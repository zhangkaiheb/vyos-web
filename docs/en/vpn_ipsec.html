IPsec Overview

IPsec is the framework used to secure data. IPsec achieves this by providing authentication, IP network packet encryption, key exchange, and key management. VyOS uses the Strongswan package to implement IPsec.

Authentication Header (AH) is defined in RFC 4302. It uses the IP header and data payload to create a hash, which is then appended to the packet. This hash is used to verify that the data has not been altered during network transmission.

Encapsulating Security Payload (ESP) is defined in RFC 4303. It provides both encryption and authentication of the data.

There are two IPsec modes:

IPsec Transport Mode: In transport mode, the IPsec header (AH or ESP) is inserted between the IP header and the upper-layer protocol header.

IPsec Tunnel Mode: In tunnel mode, the original IP packet is encapsulated within another IP datagram, with the IPsec header (AH or ESP) inserted between the outer and inner headers.

IKE (Internet Key Exchange)

The IKE protocol is the default method for IPsec secure key negotiation. IKE is designed to provide mutual authentication of IKE peers and establish shared keys to create IPsec Security Associations (SA). A Security Association (SA) includes all relevant attributes of the connection, including the encryption algorithms used, IPsec mode, encryption keys, and other parameters related to data transmission through the VPN connection.

IKEv1

IKEv1 is the older version, still in use today. Most manufacturers now recommend using the IKEv2 protocol.

IKEv1 is described in the following RFCs: RFC 2409 (IKE), RFC 3407 (IPsec DOI), RFC 3947 (NAT-T), RFC 3948 (UDP Encapsulation of ESP Packets), RFC 3706 (DPD)

IKEv1 operates in two phases to establish IKE and IPsec SAs:

  • Phase 1 provides mutual authentication of IKE peers and establishment of session keys. This phase uses DH exchange, cookies, and ID exchange to create the IKE SA. Once the IKE SA is established, all IKE communication between the initiator and responder is protected by encryption and authentication integrity checks. IKE Phase 1 provides two modes: Main mode and Aggressive mode.
    • Main Mode is used for site-to-site VPN connections.
    • Aggressive Mode is used for remote access VPN connections.
  • Phase 2 provides the negotiation and establishment of IPsec SAs that secure IP data traffic using ESP or AH.

IKEv2

IKEv2 is described in RFC 7296. The biggest difference between IKEv1 and IKEv2 is that IKEv2 is simpler and more reliable than IKEv1, with fewer messages exchanged during VPN establishment and additional security features.

IKE Authentication

VyOS supports 3 authentication methods:

  • Pre-shared Key: In this method, both peers of the IPsec tunnel must have the same pre-shared key.
  • Digital Certificates: PKI is used in this method.
  • RSA Keys: If the RSA key method is used in the IKE policy, ensure that each peer has the other peer's public key.

DPD (Dead Peer Detection)

This is a mechanism used to detect when a VPN peer is no longer active. This mechanism has different algorithms for IKEv1 and IKEv2 in VyOS. DPD requests are sent as ISAKMP R-U-THERE messages, and DPD responses are sent as ISAKMP R-U-THERE-ACK messages. In IKEv1, DPD sends messages at configured intervals. If no response to these packets is received within the DPD timeout, the remote peer is considered unreachable. In IKEv2, DPD sends messages at configured intervals. If one request goes unanswered, Strongswan will execute its retransmission algorithm with its timers.

Post-Quantum Pre-Shared Key (PPK)

Post-quantum pre-shared keys help provide some quantum resistance to IPsec tunnels when post-quantum key exchange algorithms like ML-KEM are not available. The use of PPK in IKEv2 is described in RFC 8784.

PPK can be configured in VyOS under vpn ipsec authentication ppk. PPK requires an ID and a secret value. If PPK is required for a successful IPsec connection, both the ID and secret must match. The secret can be plain text, a hexadecimal value, or a Base64 value. The default is plain text. If using other value types, the secret type must be defined.

IKE Configuration

IKE Attributes

VyOS IKE groups have the following options:

set vpn ipsec ike-group <name> close-action <action>

Defines the action to take when the remote peer unexpectedly closes a CHILD_SA:

  • none - Set to none (default)
  • trap - Install a trap policy for the CHILD_SA; traffic matching these policies will trigger an acquire event, causing the daemon to establish the required IKE/IPsec SA.
  • start - Attempt to immediately recreate the CHILD_SA.

set vpn ipsec ike-group <name> ikev2-reauth

Whether rekeying the IKE_SA should also reauthenticate the peer. In IKEv1, reauthentication is always performed. Setting this parameter enables remote host reauthentication during IKE rekeying.

set vpn ipsec ike-group <name> key-exchange

Which protocol should be used to initiate the connection. If not set, both protocols are handled, and the connection uses IKEv2 when initiating but accepts any protocol version when responding:

  • ikev1 - Use IKEv1 for key exchange.
  • ikev2 - Use IKEv2 for key exchange.

set vpn ipsec ike-group <name> lifetime

IKE lifetime (seconds) <0-86400> (default 28800).

set vpn ipsec ike-group <name> mode

IKEv1 Phase 1 mode selection:

  • main - Use main mode for key exchange in the IKEv1 protocol (recommended default).
  • aggressive - Use aggressive mode for key exchange in the IKEv1 protocol; aggressive mode is less secure than main mode.

set vpn ipsec ike-group <name> proposal <number> dh-group <dh-group number>

DH group. The default value is 2.

set vpn ipsec ike-group <name> proposal <number> encryption <encryption>

Encryption algorithm. The default value is aes128.

set vpn ipsec ike-group <name> proposal <number> hash <hash>

Hash algorithm. The default value is sha1.

set vpn ipsec ike-group <name> proposal <number> prf <prf>

Pseudo-random function.

DPD Configuration

set vpn ipsec ike-group <name> dead-peer-detection action <action>

Action to perform on this CHILD_SA when DPD times out:

  • trap - Install a trap policy that will capture matching traffic and attempt to renegotiate the tunnel on demand.
  • clear - Close the CHILD_SA without further action (default).
  • restart - Immediately attempt to renegotiate the CHILD_SA under a new IKE_SA.

set vpn ipsec ike-group <name> dead-peer-detection interval <interval>

Keepalive interval (seconds) <2-86400> (default 30).

set vpn ipsec ike-group <name> dead-peer-detection timeout <timeout>

Keepalive timeout (seconds) <2-86400> (default 120) IKEv1 only

ESP Attributes

In VyOS, ESP attributes are specified through ESP groups. Multiple proposals can be specified within a single group.

set vpn ipsec esp-group <name> compression

Enable the IPComp (IP Payload Compression) protocol, allowing compression of IP packet contents.

set vpn ipsec esp-group <name> disable-rekey

Do not initiate rekeying of SAs locally; the remote peer must rekey before expiration.

set vpn ipsec esp-group <name> life-bytes <bytes>

ESP lifetime (bytes) <1024-26843545600000>. Number of bytes transmitted before the IPsec SA expires.

set vpn ipsec esp-group <name> life-packets <packets>

ESP lifetime (packets) <1000-26843545600000>. Number of packets transmitted before the IPsec SA expires.

set vpn ipsec esp-group <name> lifetime <timeout>

ESP lifetime (seconds) <30-86400> (default 3600). How long a specific instance of the connection (the set of encryption/authentication keys for user data packets) should last, from successful negotiation to expiration.

set vpn ipsec esp-group <name> mode <mode>

Connection type:

  • tunnel - Tunnel mode (default).
  • transport - Transport mode.

set vpn ipsec esp-group <name> pfs <dh-group>

Whether Perfect Forward Secrecy is required on the connection's key channel, and defines the Diffie-Hellman group for PFS:

  • enable - Inherit the Diffie-Hellman group from the IKE group (default).
  • disable - Disable PFS.
  • <dh-group> - Define the Diffie-Hellman group for PFS.

set vpn ipsec esp-group <name> proposal <number> encryption <encryption>

Encryption algorithm. The default value is aes128.

set vpn ipsec esp-group <name> proposal <number> hash <hash>

Hash algorithm. The default value is sha1.

Global IPsec Settings

set vpn ipsec interface <name>

Interface name used to restrict outbound IPsec policies. Multiple interfaces can be specified. If no interface is specified, IPsec policies apply to all interfaces.

set vpn ipsec log level <number>

Log level. The default value is 0.

set vpn ipsec log subsystem <name>

Daemon subsystem.

Options

set vpn ipsec options disable-route-autoinstall

Do not automatically install routes to remote networks.

set vpn ipsec options flexvpn

Allow FlexVPN vendor ID payload (IKEv2 only). Sends the Cisco FlexVPN vendor ID payload (IKEv2 only), which is required to allow Cisco-branded devices to negotiate local traffic selectors.

set vpn ipsec options interface <name>

Interface name to use. The interface name on which virtual IP addresses should be installed. If not specified, addresses are installed on the outbound interface.

set vpn ipsec options virtual-ip

Allow installation of virtual IP addresses.

IKEv2 Retransmission

If the peer does not respond to DPD packets, the router will initiate a retransmission procedure. The timeout is calculated using the following formula:

relative timeout = timeout * base ^ (attempts-1)

set vpn ipsec options retransmission attempts

Number of attempts before considering the peer down. The default value is 5.

set vpn ipsec options retransmission base

Base for exponential backoff. The default value is 1.8.

set vpn ipsec options retransmission timeout

Timeout before first retransmission (seconds). The default value is 4.

Using the default values, packets are retransmitted as follows:

IPsec Site-to-Site VPN Types

VyOS supports two types of IPsec VPN: policy-based IPsec VPN and route-based IPsec VPN.

Policy-based VPN

Policy-based VPN is based on statically configured policies. Each policy creates an independent IPSec SA. Traffic matching these SAs will be encrypted and directed to the remote peer.

Route-based VPN

Route-based VPN is based on secure traffic passing through a Virtual Tunnel Interface (VTI). This type of IPsec VPN allows the use of routing protocols.

Site-to-Site VPN Configuration

Requirements and Prerequisites for Site-to-Site VPN

Negotiation Parameters That Must Match

Phase 1
  • IKE Version
  • Authentication
  • Encryption
  • Hash
  • PRF
  • Lifetime
Note: Strongswan recommends using the same lifetime values on both peers
Phase 2
  • Encryption
  • Hash
  • PFS
  • Mode (tunnel or transport)
  • Lifetime
Note: Strongswan recommends using the same lifetime values on both peers
  • Remote and local networks in the SA must be compatible on both peers

Configuration Steps for Site-to-Site VPN

The following example shows the configuration for one router participating in an IPsec VPN.

Tunnel Information:

  • Phase 1:
    • Encryption: AES256
    • Hash: SHA256
    • PRF: SHA256
    • DH: 14
    • Lifetime: 28800
  • Phase 2:
    • IPsec Mode: Tunnel
    • Encryption: AES256
    • Hash: SHA256
    • PFS: Inherited from DH Phase 1
    • Lifetime: 3600
  • If using policy-based VPN
    • Remote network is 192.168.50.0/24. Local network is 192.168.10.0/24
  • If using route-based VPN
    • VTI interface IP is 10.0.0.1/30
Note: We do not recommend using both policy-based and route-based VPN configurations for the same peer simultaneously.

1. Configure ike-group (IKE Phase 1)

set vpn ipsec ike-group IKE close-action 'start'
set vpn ipsec ike-group IKE key-exchange 'ikev1'
set vpn ipsec ike-group IKE lifetime '28800'
set vpn ipsec ike-group IKE proposal 10 dh-group '14'
set vpn ipsec ike-group IKE proposal 10 encryption 'aes256'
set vpn ipsec ike-group IKE proposal 10 hash 'sha256'
set vpn ipsec ike-group IKE proposal 10 prf 'prfsha256'

2. Configure ESP-group (IKE Phase 2)

set vpn ipsec esp-group ESP lifetime '3600'
set vpn ipsec esp-group ESP mode 'tunnel'
set vpn ipsec esp-group ESP pfs 'enable'
set vpn ipsec esp-group ESP proposal 10 encryption 'aes256'
set vpn ipsec esp-group ESP proposal 10 hash 'sha256'

3. Specify the public IP address of interface eth0

set vpn ipsec ipsec-interfaces interface eth0

4. Configure site-to-site peer

Policy-based VPN configuration:

set vpn ipsec site-to-site peer 203.0.113.2 authentication mode 'pre-shared-secret'
set vpn ipsec site-to-site peer 203.0.113.2 authentication id '192.0.2.1'
set vpn ipsec site-to-site peer 203.0.113.2 authentication remote-id '203.0.113.2'
set vpn ipsec site-to-site peer 203.0.113.2 connection-type 'respond'
set vpn ipsec site-to-site peer 203.0.113.2 default-esp-group 'ESP'
set vpn ipsec site-to-site peer 203.0.113.2 ike-group 'IKE'
set vpn ipsec site-to-site peer 203.0.113.2 local-address '192.0.2.1'
set vpn ipsec site-to-site peer 203.0.113.2 tunnel 1 local prefix '192.168.10.0/24'
set vpn ipsec site-to-site peer 203.0.113.2 tunnel 1 remote prefix '192.168.50.0/24'

Route-based VPN configuration:

set interfaces vti vti0 address '10.0.0.1/30'
set interfaces vti vti0 description 'VPN VTI interface'

set vpn ipsec site-to-site peer 203.0.113.2 authentication mode 'pre-shared-secret'
set vpn ipsec site-to-site peer 203.0.113.2 authentication id '192.0.2.1'
set vpn ipsec site-to-site peer 203.0.113.2 authentication remote-id '203.0.113.2'
set vpn ipsec site-to-site peer 203.0.113.2 connection-type 'respond'
set vpn ipsec site-to-site peer 203.0.113.2 default-esp-group 'ESP'
set vpn ipsec site-to-site peer 203.0.113.2 ike-group 'IKE'
set vpn ipsec site-to-site peer 203.0.113.2 local-address '192.0.2.1'
set vpn ipsec site-to-site peer 203.0.113.2 vti bind to 'vti0'
set vpn ipsec site-to-site peer 203.0.113.2 vti esp-group 'ESP'

Remote Access VPN Overview

Remote access VPN allows remote users to securely connect to a corporate network through an IPsec tunnel. VyOS supports multiple remote access VPN configuration methods, including pre-shared key, certificate, and EAP-based authentication.

Remote Access VPN Types

Pre-shared Key-based Remote Access

The simplest remote access configuration method, where each remote user authenticates using the same pre-shared key. Suitable for small deployments or test environments.

Certificate-based Remote Access

Uses X.509 certificates for authentication, providing higher security. Each user can have their own certificate, making management and revocation easier.

EAP-based Remote Access

Extensible Authentication Protocol (EAP) allows user authentication using a RADIUS server. Supports multiple EAP methods such as EAP-MSCHAPv2, EAP-TLS, etc.

Configuring Remote Access VPN

Basic Configuration Steps

1. Configure IKE and ESP groups

set vpn ipsec ike-group IKE-RA lifetime '28800'
set vpn ipsec ike-group IKE-RA proposal 1 encryption 'aes256'
set vpn ipsec ike-group IKE-RA proposal 1 hash 'sha256'
set vpn ipsec ike-group IKE-RA proposal 1 dh-group '14'

set vpn ipsec esp-group ESP-RA lifetime '3600'
set vpn ipsec esp-group ESP-RA proposal 1 encryption 'aes256'
set vpn ipsec esp-group ESP-RA proposal 1 hash 'sha256'

2. Configure IP address pool

set vpn ipsec remote-access connection RA pool 'RA-POOL'
set vpn ipsec remote-access connection RA pool RA-POOL prefix '100.64.0.0/24'
set vpn ipsec remote-access connection RA pool RA-POOL name-server '192.0.2.53'

3. Configure remote access connection

set vpn ipsec remote-access connection RA authentication local-id '192.0.2.1'
set vpn ipsec remote-access connection RA authentication server-mode 'x509'
set vpn ipsec remote-access connection RA authentication x509 certificate 'ipsec-cert'

set vpn ipsec remote-access connection RA remote-access-interface 'ppp0'
set vpn ipsec remote-access connection RA ike-group 'IKE-RA'
set vpn ipsec remote-access connection RA default-esp-group 'ESP-RA'

EAP-RADIUS-based Configuration

Using a RADIUS server for user authentication:

set vpn ipsec remote-access connection RA authentication client-mode 'eap-radius'
set vpn ipsec remote-access connection RA eap-radius server 1 address '192.0.2.100'
set vpn ipsec remote-access connection RA eap-radius server 1 key 'testing123'

set vpn ipsec remote-access connection RA pool RA-POOL name-server '192.0.2.53'
set vpn ipsec remote-access connection RA pool RA-POOL prefix '100.64.0.0/24'

Pre-shared Key-based Configuration

Suitable for simple remote access scenarios:

set vpn ipsec remote-access connection RA authentication mode 'pre-shared-secret'
set vpn ipsec remote-access connection RA authentication id '192.0.2.1'
set vpn ipsec remote-access connection RA authentication local-id '192.0.2.1'

set vpn ipsec remote-access connection RA remote-access-interface 'ppp0'
set vpn ipsec remote-access connection RA ike-group 'IKE-RA'
set vpn ipsec remote-access connection RA default-esp-group 'ESP-RA'

set vpn ipsec remote-access connection RA pool RA-POOL prefix '100.64.0.0/24'

Remote Access Interface Configuration

Remote access VPN uses virtual PPP interfaces. The remote access interface must be specified:

set interfaces ppp ppp0 description 'Remote Access VPN Interface'
set vpn ipsec remote-access connection RA remote-access-interface 'ppp0'

Client Configuration Examples

Windows Client

Windows built-in VPN client supports IKEv2 and L2TP/IPsec. Configuration steps:

  1. Open "Settings" > "Network & Internet" > "VPN"
  2. Click "Add a VPN connection"
  3. Fill in VPN provider name, server name or address
  4. Select VPN type (IKEv2 or L2TP/IPsec)
  5. Enter authentication information (username/password or certificate)

Linux Client

Linux users can configure IPsec VPN using NetworkManager or command-line tools:

# Using strongswan client
sudo apt install strongswan strongswan-pki libcharon-extra-plugins

# Configure /etc/ipsec.conf
conn vyos-ra
    right=192.0.2.1
    rightid=@192.0.2.1
    rightsubnet=0.0.0.0/0
    left=%defaultroute
    leftid=user@example.com
    eap_identity=user@example.com
    auto=start

macOS Client

macOS has built-in support for IKEv2 VPN:

  1. Open "System Preferences" > "Network"
  2. Click "+" to add a new connection
  3. Select Interface as "VPN", Type as "IKEv2"
  4. Fill in server address and remote ID
  5. Configure authentication method

Mobile Devices

iOS and Android devices both have built-in support for IKEv2 VPN:

  • iOS: Settings > General > VPN & Network > Add VPN Configuration
  • Android: Settings > Network & Internet > VPN > Add VPN Profile

Troubleshooting

Common Issues

  • Connection failure: Check if IKE and ESP parameters match, verify pre-shared key or certificate is correct
  • Authentication failure: Confirm RADIUS server configuration is correct, check user credentials
  • Unable to obtain IP address: Verify IP address pool configuration, ensure sufficient available addresses
  • Unstable connection: Check DPD settings, adjust lifetime parameters

This document provides troubleshooting methods and diagnostic steps for common IPsec VPN issues.

Basic Diagnostic Commands

VyOS provides a series of commands to help diagnose IPsec issues:

View IPsec Status

View the current status of IPsec tunnels and security associations:

show vpn ipsec status

This command displays the current status of all IPsec tunnels, including whether connections are established, whether SAs (Security Associations) are active, etc.

View Security Associations

View detailed IKE and Child SA information:

show vpn ipsec sa

The output includes the following information:

  • IKE SA: IKE Phase 1 Security Associations
  • Child SA: IKE Phase 2 Security Associations (data tunnels)
  • Status: ESTABLISHED, INSTALLED, etc.
  • Encryption Algorithms: Encryption and authentication algorithms used
  • Traffic Statistics: Number of packets and bytes through the tunnel

View IPsec Configuration

View the currently running IPsec configuration:

show vpn ipsec detail

Common Issues and Solutions

Tunnel Won't Establish

Symptoms: IPsec tunnel status shows "down" or "connecting".

Possible Causes and Solutions:

  1. Pre-shared Key Mismatch

    Ensure the pre-shared keys on both ends are exactly the same, including case and spaces.

    show vpn ipsec site-to-site peer <peer-address>

  2. IKE Proposal Mismatch

    Check if the IKE group configurations on both ends are compatible. Encryption algorithm, hash algorithm, and Diffie-Hellman group must match.

    show vpn ipsec ike-group

  3. ESP Proposal Mismatch

    Verify that ESP group configurations are consistent.

    show vpn ipsec esp-group

  4. Firewall Blocking

    Ensure the firewall allows the following ports to pass through:

    • UDP 500 (IKE)
    • UDP 4500 (NAT-T)
    • Protocol 50 (ESP)

  5. Local/Remote Subnet Configuration Errors

    Check that local and remote subnet configurations are correct for site-to-site VPN.

Tunnel Up but No Data

Symptoms: IPsec tunnel shows "up", but data cannot be transmitted through the tunnel.

Possible Causes and Solutions:

  1. Child SA Not Installed

    Check if Child SA has been successfully installed:

    show vpn ipsec sa

    If Child SA is not displayed, it may be due to ESP proposal mismatch.

  2. Routing Issues

    Verify the routing table is correct, ensuring traffic can pass through the tunnel interface:

    show ip route

  3. MTU Problems

    IPsec adds packet overhead. If packets are too large, they may be dropped. Try adjusting MTU:

    set interfaces ethernet <interface> mtu 1400

  4. Asymmetric Routing

    Ensure return traffic also goes through the IPsec tunnel; check policy routing configuration.

Tunnel Drops Frequently

Symptoms: IPsec tunnel repeatedly establishes and disconnects.

Possible Causes and Solutions:

  1. DPD (Dead Peer Detection) Configuration

    Check if DPD settings are too aggressive:

    show vpn ipsec site-to-site peer <peer-address> dead-peer-detection

    Recommended DPD settings:

    • interval: 15-30 seconds
    • timeout: 30-60 seconds
    • action: restart

  2. IKE Rekey Failure

    Check IKE lifetime settings to ensure compatibility on both ends.

  3. NAT Issues

    If either end is behind NAT, ensure NAT Traversal (NAT-T) is enabled.

Authentication Failures

Symptoms: Logs show authentication errors.

Possible Causes and Solutions:

  1. Pre-shared Key Error

    Reconfigure the pre-shared key, ensuring an exact match on both ends.

  2. Certificate Issues

    If using certificate authentication:

    • Verify certificate has not expired
    • Check certificate chain is complete
    • Confirm certificate subject names match
    • Verify CA certificate is properly installed

Logs and Debugging

View IPsec Logs

View IPsec-related information in system logs:

show log | match charon

Or view more detailed logs:

tail -f /var/log/syslog | grep charon

Enable Detailed Logging

For more detailed debugging information, you can enable IPsec debug logging:

set vpn ipsec logging log-level 3

Log level descriptions:

  • 0: Errors only
  • 1: Warnings
  • 2: Information (default)
  • 3: Debug
  • 4: Verbose debug
Warning: High log levels can generate large amounts of log output and may affect system performance. Only enable temporarily during troubleshooting.

Network Packet Capture

When other methods cannot resolve the issue, you can use tcpdump for network packet capture:

Capture IKE Traffic

tcpdump -i any -n port 500 or port 4500

Capture ESP Traffic

tcpdump -i any -n proto 50

Save Packet Capture File

tcpdump -i any -n -w /tmp/ipsec.pcap port 500 or port 4500 or proto 50

You can use Wireshark to analyze the saved pcap file.

Reset and Restart

Reset IPsec Tunnel

Reset the IPsec tunnel for a specific site:

reset vpn ipsec site-to-site peer <peer-address>

Restart IPsec Service

To restart the entire IPsec service:

restart vpn ipsec
Warning: Restarting the IPsec service will interrupt all active VPN connections.

show vpn ipsec performance
