Webproxy

Der Proxy-Dienst in VyOS basiert auf Squid und einigen verwandten Modulen.

Squid ist ein Caching- und Weiterleitungs-HTTP-Webproxy. Es hat eine breite Vielfalt an Verwendungen, einschließlich der Beschleunigung eines Web-Servers durch Caching wiederholter Anfragen, Caching von Web-, DNS- und anderen Computernetzwerkabfragen für eine Gruppe von Personen, die Netzwerkressourcen teilen, und Unterstützung der Sicherheit durch Filtern von Verkehr. Obwohl primär für HTTP und FTP verwendet, umfasst Squid begrenzte Unterstützung für mehrere andere Protokolle, einschließlich Internet Gopher, SSL,[6] TLS und HTTPS. Squid unterstützt das SOCKS-Protokoll nicht.

URL-Filterung wird durch SquidGuard bereitgestellt.

Konfiguration

set service webproxy append-domain <domain>

Verwenden Sie diesen Befehl, um einen Domänennamen anzugeben, der an Domänennamen in URLs angehängt wird, die keinen Punkt . enthalten. Die Domäne wird angehängt.

Beispiel: Wenn „vyos.net“ als anzuhängende Domäne festgelegt wird und die empfangene URL www/foo.html ist, verwendet das System die generierte End-URL von www.vyos.net/foo.html.

set service webproxy append-domain vyos.net
set service webproxy cache-size <size>

Die Größe des auf der Festplatte befindlichen Proxy-Caches ist vom Benutzer konfigurierbar. Der Standardcache-Größe des Proxys ist auf 100 MB eingestellt.

Die Einheit dieses Befehls ist MB.

set service webproxy cache-size 1024
set service webproxy default-port <port>

Geben Sie den Port an, auf dem der Proxy-Dienst Anfragen abhört. Dieser Port ist der Standardport, der für den angegebenen Listen-Adresse verwendet wird.

Der Standardport ist 3128.

set service webproxy default-port 8080
set service webproxy domain-block <domain>

Wird verwendet, um bestimmte Domänen durch den Proxy zu blockieren. Das Angeben von „vyos.net“ blockiert alle Zugriffe auf vyos.net, und das Angeben von „.xxx“ blockiert alle Zugriffe auf URLs, die mit .xxx enden.

set service webproxy domain-block vyos.net
set service webproxy domain-noncache <domain>

Ermöglicht den Zugriff auf Seiten in einer Domäne, ohne sie aus dem Proxy-Cache abzurufen. Das Angeben von „vyos.net“ ermöglicht den Zugriff auf vyos.net, aber die aufgerufenen Seiten werden nicht gecacht. Dies ist nützlich, um Probleme mit der „If-Modified-Since“-Prüfung an bestimmten Standorten zu umgehen.

set service webproxy domain-noncache vyos.net
set service webproxy listen-address <address>

Gibt den Proxy-Dienst-Listen-Adresse an. Die Listenadresse ist die IP-Adresse, auf der der Web-Proxy-Dienst Client-Anfragen abhört.

Für Sicherheit sollte die Listen-Adresse nur auf internen/vertrauenswürdigen Netzwerken verwendet werden!

set service webproxy listen-address 192.0.2.1
set service webproxy listen-address <address> disable-transparent

Deaktiviert den transparenten Web-Proxy-Modus an einer Listen-Adresse.

Im transparenten Proxy-Modus wird jeder Verkehr, der auf Port 80 und für das Internet bestimmt ist, automatisch über den Proxy weitergeleitet. Dies ermöglicht sofortige Proxy-Weiterleitung ohne Konfiguration der Browser-Einstellungen der Clients.

Bei nicht-transparentem Proxying müssen die Browser der Clients vor der Weiterleitung der Anfragen mit den Proxy-Einstellungen konfiguriert werden. Der Vorteil davon ist, dass der Client-Webbrowser erkennen kann, dass ein Proxy verwendet wird und entsprechend handeln kann. Darüber hinaus können manchmal Web-Malware durch einen nicht-transparenten Web-Proxy blockiert werden, da sie nicht von den Proxy-Einstellungen wissen.

set service webproxy listen-address 192.0.2.1 disable-transparent
set service webproxy listen-address <address> port <port>

Legt den Hörport für eine Listen-Adresse fest. Dies überschreibt den Standardport von 3128 auf der spezifischen Listen-Adresse.

set service webproxy listen-address 192.0.2.1 port 8080
set service webproxy reply-block-mime <mime>

Wird verwendet, um einen bestimmten MIME-Typ zu blockieren.

# Blockiere alle PDFs
set service webproxy reply-block-mime application/pdf
set service webproxy reply-body-max-size <size>

Gibt die maximale Größe eines Antwortkörpers in KB an, um die Antwortgröße zu begrenzen.

Alle Antwortgrößen werden standardmäßig akzeptiert.

set service webproxy reply-body-max-size 2048
set service webproxy safe-ports <port>

Fügt einen neuen Port zur Safe-Ports ACL hinzu. Ports, die standardmäßig in der Safe-Ports ACL enthalten sind: 21, 70, 80, 210, 280, 443, 488, 591, 777, 873, 1025-65535

set service webproxy ssl-safe-ports <port>

Fügt einen neuen Port zur SSL-Ports ACL hinzu. Ports, die standardmäßig in der SSL-Ports ACL enthalten sind: 443

Authentifizierung

Der eingebaute Squid-Proxy kann LDAP verwenden, um Benutzer gegen ein Unternehmensverzeichnis zu authentifizieren. Die folgende Konfiguration ist ein Beispiel dafür, wie Active Directory als Authentifizierungsbackend verwendet werden kann. Abfragen werden über LDAP durchgeführt.

set service webproxy authentication children <number>

Maximale Anzahl der zu startenden Authentifizierungsprozesse. Wenn Sie zu wenige starten, muss Squid auf sie warten, um eine Rückstandshaltung von Kredenzvalidierungen zu verarbeiten, was es verlangsamt. Wenn die Passwortvalidierung über ein (langsame) Netzwerk erfolgt, benötigen Sie wahrscheinlich viele Authentifizierungsprozesse.

Dies ist standardmäßig auf 5 eingestellt.

set service webproxy authentication children 10
set service webproxy authentication credentials-ttl <time>

Gibt an, wie lange Squid annimmt, dass ein extern validierter Benutzername:Passwort-Paar gültig ist – also wie oft das Hilfsprogramm für diesen Benutzer aufgerufen wird. Setzen Sie dies niedrig, um erneute Validierung mit kurzlebigen Passwörtern zu erzwingen.

Die Zeit ist in Minuten und standardmäßig 60.

set service webproxy authentication credentials-ttl 120
set service webproxy authentication method <ldap>

Proxy-Authentifizierungsmethode, derzeit wird nur LDAP unterstützt.

set service webproxy authentication method ldap
set service webproxy authentication realm

Gibt den Schutzbereich (auch Realm-Name genannt) an, der an den Client für das Authentifizierungsschema gemeldet wird. Es ist häufig Teil des Textes, den der Benutzer sieht, wenn nach seinem Benutzernamen und Passwort gefragt wird.

set service webproxy authentication realm "VyOS proxy auth"

LDAP

set service webproxy authentication ldap base-dn <base-dn>

Gibt den Basis-DN an, unter dem die Benutzer sich befinden.

set service webproxy authentication ldap base-dn DC=vyos,DC=net
set service webproxy authentication ldap bind-dn <bind-dn>

DN und Passwort, mit denen während der Suche verbunden wird.

set service webproxy authentication ldap bind-dn CN=proxyuser,CN=Users,DC=vyos,DC=net
set service webproxy authentication ldap filter-expression <expr>

LDAP-Suchfilter, um den Benutzer-DN zu lokalisieren. Erforderlich, wenn die Benutzer unter dem Basis-DN hierarchisch sind oder wenn der Login-Name nicht der Teil des Benutzer-DN ist.

Der Suchfilter kann bis zu 15 Vorkommen von %s enthalten, die durch den Benutzernamen ersetzt werden, wie z.B. „uid=%s“ für RFC 2037 Verzeichnisse. Für eine detaillierte Beschreibung der LDAP-Suche Filter Syntax siehe RFC 2254.

set service webproxy authentication ldap filter-expression (cn=%s)
set service webproxy authentication ldap password <password>

DN und Passwort, mit denen während der Suche verbunden wird. Da das Passwort in Klartext in Ihrer Squid-Konfigurationsdatei gedruckt werden muss, wird dringend empfohlen, ein Konto mit minimalen zugehörigen Berechtigungen zu verwenden. Dies dient dazu, den Schaden zu begrenzen, falls jemand eine Kopie Ihrer Squid-Konfigurationsdatei erhalten könnte.

set service webproxy authentication ldap password vyos
set service webproxy authentication ldap persistent-connection

Verwenden Sie eine persistente LDAP-Verbindung. Normalerweise ist die LDAP-Verbindung nur geöffnet, während die Validierung eines Benutzernamens durchgeführt wird, um Ressourcen am LDAP-Server zu sparen. Diese Option veranlasst die LDAP-Verbindung, geöffnet zu bleiben, sodass sie für weitere Benutzervalidierungen wiederverwendet werden kann.

Empfohlen für größere Installationen.

set service webproxy authentication ldap persistent-connection
set service webproxy authentication ldap port <port>

Gibt einen alternativen TCP-Port an, auf dem der LDAP-Server lauscht, wenn nicht der Standard-LDAP-Port 389.

set service webproxy authentication ldap port 389
set service webproxy authentication ldap server <server>

Gibt den LDAP-Server an, mit dem verbunden werden soll.

set service webproxy authentication ldap server ldap.vyos.net
set service webproxy authentication ldap use-ssl

Verwenden Sie TLS-Verschlüsselung.

set service webproxy authentication ldap use-ssl
set service webproxy authentication ldap username-attribute <attr>

Gibt den Namen des DN-Attributs an, das den Benutzernamen/Anmeldung enthält. In Verbindung mit dem Basis-DN, um den Benutzer-DN zu konstruieren, wenn kein Suchfilter angegeben ist (filter-expression).

Standardwert ist 'uid'

Hinweis

Dies kann nur durchgeführt werden, wenn alle Ihre Benutzer direkt unter dem gleichen Ort im LDAP-Baum liegen und der Anmeldename für die Namensgebung jedes Benutzerobjekts verwendet wird. Wenn Ihr LDAP-Baum diese Kriterien nicht erfüllt oder Sie möchten, wer gültige Benutzer ist, dann müssen Sie einen Suchfilter verwenden, um Ihren Benutzer-DN zu suchen (filter-expression).

set service webproxy authentication ldap username-attribute uid
set service webproxy authentication ldap version <2 | 3>

LDAP-Protokollversion. Standardmäßig ist 3, wenn nicht angegeben.

set service webproxy authentication ldap version 2

Einige Dienste funktionieren nicht korrekt, wenn sie über einen Webproxy behandelt werden. Daher kann es manchmal nützlich sein, einen transparenten Proxy zu umgehen:

  • Um den Proxy für jede Anfrage zu umgehen, die an einen bestimmten Zielort gerichtet ist:

    set service webproxy whitelist destination-address 198.51.100.33

    set service webproxy whitelist destination-address 192.0.2.0/24

  • Um den Proxy für jede Anfrage zu umgehen, die von einem bestimmten Quellort stammt:

    set service webproxy whitelist source-address 192.168.1.2

    set service webproxy whitelist source-address 192.168.2.0/24

    (Dies kann nützlich sein, wenn ein aufgerufener Dienst viele und/oder häufig wechselnde Zieladressen hat - z.B. Netflix.)

Beispiele

vyos@vyos# show service webproxy
 authentication {
     children 5
     credentials-ttl 60
     ldap {
         base-dn DC=example,DC=local
         bind-dn CN=proxyuser,CN=Users,DC=example,DC=local
         filter-expression (cn=%s)
         password Qwert1234
         server ldap.example.local
         username-attribute cn
     }
     method ldap
     realm "VyOS Webproxy"
 }
 cache-size 100
 default-port 3128
 listen-address 192.168.188.103 {
     disable-transparent
 }
