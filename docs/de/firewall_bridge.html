Weitere Informationen zur Brücken-Firewall-Konfiguration und zu den zugehörigen Op-Modus-Befehlen.

Die folgenden Befehle werden in diesem Abschnitt behandelt:

set firewall bridge <options>

Aus der Hauptstruktur, die in Firewall-Übersicht in diesem Abschnitt können Sie detaillierte Informationen nur für den nächsten Teil der allgemeinen Struktur finden:

- set firewall

Der Datenverkehr, der vom Router auf einer Schnittstelle empfangen wird, die Mitglied eines Bridge-Netzwerks ist, wird auf der Brückenebene verarbeitet. Bevor die Brücke entscheidet, werden alle Pakete im Prerouting analysiert. Hier können zunächst Filter angewendet werden, und auch Regeln zum Ignorieren des Verfolgungssystems für Verbindungen können konfiguriert werden. Die relevante Konfiguration, die in prerouting wirkt, ist:

  • set firewall bridge prerouting filter ....

Für den Datenverkehr, der intern von der Brücke weitergeleitet werden muss, ist die Basiskette forward, und ihr Basisbefehl für die Filterung ist set firewall bridge forward filter ..., der im Stadium 4 stattfindet, rot markiert.

Für den Datenverkehr, der an den Router selbst oder der weitergeleitet werden muss (vorausgesetzt, eine Layer3-Brücke ist konfiguriert), ist die Basiskette input, und der Basisbefehl ist set firewall bridge input filter ... und der Pfad ist:

Wenn das Paket nicht abgewiesen wird, wird es an die IP-Ebene gesendet und dort vom IP-Ebenen-Firewall: IPv4 oder IPv6-Regelset verarbeitet. Prüfen Sie bei Bedarf erneut das allgemeine Paketflussdiagramm.

Für den Datenverkehr, der von der Brücke selbst stammt, ist die Basiskette output, und der Basisbefehl ist set firewall bridge output filter ..., und der Pfad ist:

Benutzerdefinierte Brücken-Firewall-Ketten können mit dem Befehl set firewall bridge name <name> ... erstellt werden. Um eine solche benutzerdefinierte Kette zu verwenden, muss in einer Basiskette eine Regel mit Aktion jump und dem entsprechenden Ziel definiert werden.

Brücken-Regeln

Für die Firewall-Filterung müssen Firewall-Regeln erstellt werden. Jede Regel ist nummeriert, hat eine Aktion, die ausgeführt wird, wenn die Regel übereinstimmt, und die Fähigkeit, mehrere Übereinstimmungskriterien anzugeben. Datenpakete durchlaufen die Regeln von 1 bis 999999, daher ist die Reihenfolge entscheidend. Bei der ersten Übereinstimmung wird die Aktion der Regel ausgeführt.

Aktionen

Wenn eine Regel definiert ist, muss auch eine Aktion für sie definiert werden. Dies gibt dem Firewall an, was zu tun ist, wenn alle Übereinstimmungskriterien in der Regel erfüllt sind.

In Brücken-Firewall-Regeln kann die Aktion sein:

  • accept: Akzeptiere das Paket.

  • continue: Weiter mit der nächsten Regel parse.

  • drop: Das Paket wird verworfen.

  • jump: Springe zu einer anderen benutzerdefinierten Kette.

  • return: Rückkehr aus der aktuellen Kette und Fortsetzung bei der nächsten Regel der letzten Kette.

  • queue: Paket in den Benutzerbereich einreihen.

  • notrack: Ignoriere das Verfolgungssystem für Verbindungen. Diese Aktion ist nur in der prerouting-Kette verfügbar.

set firewall bridge forward filter rule <1-999999> action [accept | continue | drop | jump | queue | return]
set firewall bridge input filter rule <1-999999> action [accept | continue | drop | jump | queue | return]
set firewall bridge output filter rule <1-999999> action [accept | continue | drop | jump | queue | return]
set firewall bridge prerouting filter rule <1-999999> action [accept | continue | drop | jump | notrack | queue | return]
set firewall bridge name <name> rule <1-999999> action [accept | continue | drop | jump | queue | return]

Diese erforderliche Einstellung definiert die Aktion der aktuellen Regel. Wenn die Aktion auf jump gesetzt ist, ist auch jump-target erforderlich.

set firewall bridge forward filter rule <1-999999> jump-target <text>
set firewall bridge input filter rule <1-999999> jump-target <text>
set firewall bridge output filter rule <1-999999> jump-target <text>
set firewall bridge prerouting filter rule <1-999999> jump-target <text>
set firewall bridge name <name> rule <1-999999> jump-target <text>

Wenn die Aktion auf queue gesetzt ist, verwenden Sie den folgenden Befehl, um das Queue-Ziel zu spezifizieren. Bereich ist ebenfalls unterstützt:

set firewall bridge forward filter rule <1-999999> queue <0-65535>
set firewall bridge input filter rule <1-999999> queue <0-65535>
set firewall bridge output filter rule <1-999999> queue <0-65535>
set firewall bridge prerouting filter rule <1-999999> queue <0-65535>
set firewall bridge name <name> rule <1-999999> queue <0-65535>

Außerdem, wenn die Aktion auf queue gesetzt ist, verwenden Sie den folgenden Befehl, um das Queue-Ziel zu spezifizieren. Mögliche Optionen sind bypass und fanout:

set firewall bridge forward filter rule <1-999999> queue-options bypass
set firewall bridge input filter rule <1-999999> queue-options bypass
set firewall bridge output filter rule <1-999999> queue-options bypass
set firewall bridge prerouting filter rule <1-999999> queue-options bypass
set firewall bridge name <name> rule <1-999999> queue-options bypass
set firewall bridge forward filter rule <1-999999> queue-options fanout
set firewall bridge input filter rule <1-999999> queue-options fanout
set firewall bridge output filter rule <1-999999> queue-options fanout
set firewall bridge prerouting filter rule <1-999999> queue-options fanout
set firewall bridge name <name> rule <1-999999> queue-options fanout

Außerdem ist default-action eine Aktion, die jedes Mal ausgeführt wird, wenn ein Paket keine Regel in seiner Kette trifft. Für Basisketten sind mögliche Optionen für default-action accept oder drop.

set firewall bridge forward filter default-action [accept | drop]
set firewall bridge input filter default-action [accept | drop]
set firewall bridge output filter default-action [accept | drop]
set firewall bridge prerouting filter default-action [accept | drop]
set firewall bridge name <name> default-action [accept | continue | drop | jump | reject | return]

Dies legt die Standardaktion der Regelmenge fest, wenn ein Paket keine der Regeln in dieser Kette trifft. Wenn default-action auf jump gesetzt ist, dann ist auch default-jump-target erforderlich. Beachten Sie, dass für Basisketten die Standardaktion nur auf accept oder drop gesetzt werden kann, während bei benutzerdefinierten Ketten mehr Aktionen verfügbar sind.

set firewall bridge name <name> default-jump-target <text>

Nur verwendet, wenn default-action auf jump gesetzt ist. Verwenden Sie diesen Befehl, um das Sprungziel für die Standardregel anzugeben.

Hinweis

Wichtiger Hinweis zu Default-Aktionen: Wenn für keine Basiskette die Default-Aktion definiert ist, wird die Default-Aktion für diese Kette auf accept gesetzt. Für benutzerdefinierte Ketten, wenn die Default-Aktion nicht definiert ist, wird die Default-Aktion auf drop gesetzt.

Firewall-Protokolle

Sie können Protokollierung für jede Firewall-Regel aktivieren. Wenn aktiviert, können andere Protokollierungsoptionen konfiguriert werden.

set firewall bridge forward filter rule <1-999999> log
set firewall bridge input filter rule <1-999999> log
set firewall bridge output filter rule <1-999999> log
set firewall bridge prerouting filter rule <1-999999> log
set firewall bridge name <name> rule <1-999999> log

Protokollierung für das übereinstimmende Paket aktivieren. Wenn dieser Konfigurationsbefehl nicht vorhanden ist, ist die Protokollierung nicht aktiviert.

set firewall bridge forward filter default-log
set firewall bridge input filter default-log
set firewall bridge output filter default-log
set firewall bridge prerouting filter default-log
set firewall bridge name <name> default-log

Verwenden Sie diesen Befehl, um die Protokollierung der Standardaktion auf der angegebenen Kette zu aktivieren.

set firewall bridge forward filter rule <1-999999> log-options level [emerg | alert | crit | err | warn | notice | info | debug]
set firewall bridge input filter rule <1-999999> log-options level [emerg | alert | crit | err | warn | notice | info | debug]
set firewall bridge output filter rule <1-999999> log-options level [emerg | alert | crit | err | warn | notice | info | debug]
set firewall bridge prerouting filter rule <1-999999> log-options level [emerg | alert | crit | err | warn | notice | info | debug]
set firewall bridge name <name> rule <1-999999> log-options level [emerg | alert | crit | err | warn | notice | info | debug]

Definieren Sie den Protokolllevel. Nur anwendbar, wenn die Regelprotokollierung aktiviert ist.

set firewall bridge forward filter rule <1-999999> log-options group <0-65535>
set firewall bridge input filter rule <1-999999> log-options group <0-65535>
set firewall bridge output filter rule <1-999999> log-options group <0-65535>
set firewall bridge prerouting filter rule <1-999999> log-options group <0-65535>
set firewall bridge name <name> rule <1-999999> log-options group <0-65535>

Definieren Sie die Protokollgruppe, an die Nachrichten gesendet werden. Nur anwendbar, wenn die Regelprotokollierung aktiviert ist.

set firewall bridge forward filter rule <1-999999> log-options snapshot-length <0-9000>
set firewall bridge input filter rule <1-999999> log-options snapshot-length <0-9000>
set firewall bridge output filter rule <1-999999> log-options snapshot-length <0-9000>
set firewall bridge prerouting filter rule <1-999999> log-options snapshot-length <0-9000>
set firewall bridge name <name> rule <1-999999> log-options snapshot-length <0-9000>

Definieren Sie die Länge des Paketpayloads, die in das Netlink-Nachrichten enthalten wird. Nur anwendbar, wenn die Regelprotokollierung aktiviert ist und die Protokollgruppe definiert ist.

set firewall bridge forward filter rule <1-999999> log-options queue-threshold <0-65535>
set firewall bridge input filter rule <1-999999> log-options queue-threshold <0-65535>
set firewall bridge output filter rule <1-999999> log-options queue-threshold <0-65535>
set firewall bridge prerouting filter rule <1-999999> log-options queue-threshold <0-65535>
set firewall bridge name <name> rule <1-999999> log-options queue-threshold <0-65535>

Definieren Sie die Anzahl der Pakete, die im Kernel vor dem Senden an den Benutzerbereich gepuffert werden. Nur anwendbar, wenn die Regelprotokollierung aktiviert ist und die Protokollgruppe definiert ist.

Firewall-Beschreibung

Sie können eine Beschreibung für jede benutzerdefinierte Kette definieren, um sie für Referenzzwecke zu kennzeichnen.

set firewall bridge name <name> description <text>

Geben Sie eine Regelmenge-Beschreibung einer benutzerdefinierten Firewall-Kette an.

set firewall bridge forward filter rule <1-999999> description <text>
set firewall bridge input filter rule <1-999999> description <text>
set firewall bridge output filter rule <1-999999> description <text>
set firewall bridge prerouting filter rule <1-999999> description <text>
set firewall bridge name <name> rule <1-999999> description <text>

Geben Sie eine Beschreibung für jede Regel an.

Regelstatus

Standardmäßig ist eine Regel, sobald sie definiert ist, aktiviert. In einigen Fällen ist es nützlich, die Regel zu deaktivieren, anstatt sie zu löschen.

set firewall bridge forward filter rule <1-999999> disable
set firewall bridge input filter rule <1-999999> disable
set firewall bridge output filter rule <1-999999> disable
set firewall bridge prerouting filter rule <1-999999> disable
set firewall bridge name <name> rule <1-999999> disable

Befehl zum Deaktivieren einer Regel, aber sie im Konfigurationsdatei behalten.

Übereinstimmungskriterien

Es gibt viele Übereinstimmungskriterien, anhand derer ein Paket getestet werden kann. Siehe IPv4 und IPv6 Übereinstimmungskriterien für weitere Details.

Da Brücken auf Ebene 2 arbeiten, werden sowohl Matcher für IPv4 als auch IPv6 in der Brücken-Firewall-Konfiguration unterstützt. Das gleiche gilt für Firewall-Gruppen.

Die gleichen spezifischen Übereinstimmungskriterien, die in der Brücken-Firewall verwendet werden können, sind in diesem Abschnitt beschrieben:

set firewall bridge forward filter rule <1-999999> ethernet-type [802.1q | 802.1ad | arp | ipv4 | ipv6]
set firewall bridge input filter rule <1-999999> ethernet-type [802.1q | 802.1ad | arp | ipv4 | ipv6]
set firewall bridge output filter rule <1-999999> ethernet-type [802.1q | 802.1ad | arp | ipv4 | ipv6]
set firewall bridge prerouting filter rule <1-999999> ethernet-type [802.1q | 802.1ad | arp | ipv4 | ipv6]
set firewall bridge name <name> rule <1-999999> ethernet-type [802.1q | 802.1ad | arp | ipv4 | ipv6]

Übereinstimmung basierend auf dem Ethernet-Typ des Pakets.

set firewall bridge forward filter rule <1-999999> vlan ethernet-type [802.1q | 802.1ad | arp | ipv4 | ipv6]
set firewall bridge input filter rule <1-999999> vlan ethernet-type [802.1q | 802.1ad | arp | ipv4 | ipv6]
set firewall bridge output filter rule <1-999999> vlan ethernet-type [802.1q | 802.1ad | arp | ipv4 | ipv6]
set firewall bridge prerouting filter rule <1-999999> vlan ethernet-type [802.1q | 802.1ad | arp | ipv4 | ipv6]
set firewall bridge name <name> rule <1-999999> vlan ethernet-type [802.1q | 802.1ad | arp | ipv4 | ipv6]

Übereinstimmung basierend auf dem Ethernet-Typ des Pakets, wenn es VLAN-markiert ist.

set firewall bridge forward filter rule <1-999999> vlan id <0-4096>
set firewall bridge input filter rule <1-999999> vlan id <0-4096>
set firewall bridge output filter rule <1-999999> vlan id <0-4096>
set firewall bridge prerouting filter rule <1-999999> vlan id <0-4096>
set firewall bridge name <name> rule <1-999999> vlan id <0-4096>

Übereinstimmung basierend auf der VLAN-Identifikator. Bereich ist auch unterstützt.

set firewall bridge forward filter rule <1-999999> vlan priority <0-7>
set firewall bridge input filter rule <1-999999> vlan priority <0-7>
set firewall bridge output filter rule <1-999999> vlan priority <0-7>
set firewall bridge prerouting filter rule <1-999999> vlan priority <0-7>
set firewall bridge name <name> rule <1-999999> vlan priority <0-7>

Übereinstimmung basierend auf der VLAN-Priorität (Priority Code Point - PCP). Bereich ist auch unterstützt.

Paketmodifikationen

Ab VyOS-1.5-rolling-202410060007 kann die Firewall Pakete modifizieren, bevor sie gesendet werden. Diese Funktion bietet mehr Flexibilität bei der Paketverarbeitung.

set firewall bridge [prerouting | forward | output] filter rule <1-999999> set dscp <0-63>

Legen Sie einen bestimmten Wert des Differentiated Services Codepoint (DSCP) fest.

set firewall bridge [prerouting | forward | output] filter rule <1-999999> set mark <1-2147483647>

Legen Sie einen bestimmten Paketmarkierungswert fest.

set firewall bridge [prerouting | forward | output] filter rule <1-999999> set tcp-mss <500-1460>

Legen Sie den TCP-MSS (TCP maximum segment size) für die Verbindung fest.

set firewall bridge [prerouting | forward | output] filter rule <1-999999> set ttl <0-255>

Legen Sie den TTL-Wert (Time to Live) fest.

set firewall bridge [prerouting | forward | output] filter rule <1-999999> set hop-limit <0-255>

Legen Sie den Hop-Limit-Wert fest.

set firewall bridge [forward | output] filter rule <1-999999> set connection-mark <0-2147483647>

Legen Sie den Verbindungsmarkierungswert fest.

IP-Firewall verwenden

Standardmäßig werden für den verarbeiteten Datenverkehr nur die Regeln angewandt, die unter set firewall bridge definiert sind. Es gibt zwei globale Optionen, die konfiguriert werden können, um eine tiefere Analyse des Pakets auf der IP-Ebene zu erzwingen. Diese Optionen sind:

set firewall global-options apply-to-bridged-traffic ipv4

Dieser Befehl aktiviert das IPv4-Firewall für bridged traffic. Wenn diese Option verwendet wird, werden Pakete auch von den Regeln definiert in set firewall ipv4 ... verarbeitet

set firewall global-options apply-to-bridged-traffic ipv6

Dieser Befehl aktiviert das IPv6-Firewall für bridged traffic. Wenn diese Option verwendet wird, werden Pakete auch von den Regeln definiert in set firewall ipv6 ... verarbeitet
