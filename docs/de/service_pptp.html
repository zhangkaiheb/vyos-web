PPPoE Server

VyOS verwendet accel-ppp, um PPPoE-Server-Funktionen bereitzustellen. Es kann mit lokaler Authentifizierung oder einem verbundenen RADIUS-Server verwendet werden.

Hinweis

Bitte beachten Sie, aufgrund eines Upstream-Bugs, werden Konfigurationsänderungen/Commit's den ppp-Dienst neu starten und bestehende PPPoE-Verbindungen von verbundenen Benutzern zurücksetzen, um wirksam zu werden.

Einrichtung des PPPoE-Servers

set service pppoe-server access-concentrator PPPoE-Server
set service pppoe-server authentication mode local
set service pppoe-server authentication local-users username test password 'test'
set service pppoe-server client-ip-pool PPPOE-POOL range 192.168.255.2-192.168.255.254
set service pppoe-server default-pool 'PPPOE-POOL'
set service pppoe-server gateway-address 192.168.255.1
set service pppoe-server interface eth0
set service pppoe-server access-concentrator <name>

Verwenden Sie diesen Befehl, um einen Namen für diesen PPPoE-Server Access Concentrator zu setzen.

set service pppoe-server authentication mode <local | radius>

Legen Sie den Authentifizierungsbackend fest. Der konfigurierte Authentifizierungsbackend wird für alle Abfragen verwendet.

  • radius: Alle Authentifizierungsanfragen werden durch einen konfigurierten RADIUS-Server verarbeitet.

  • local: Alle Authentifizierungsanfragen werden lokal verarbeitet.

  • noauth: Authentifizierung deaktiviert.

set service pppoe-server authentication local-users username <name> password <password>

Erstellen Sie einen <Benutzer> für die lokale Authentifizierung auf diesem System. Das Passwort des Benutzers wird auf <Passwort> gesetzt.

set service pppoe-server client-ip-pool <POOL-NAME> range <x.x.x.x-x.x.x.x | x.x.x.x/x>

Verwenden Sie diesen Befehl, um das erste IP-Adressen-Pool-Adresse für eine Gruppe von Adressen zu definieren, die an PPPoE-Clients vergeben werden. Wenn die Notation x.x.x.x-x.x.x.x verwendet wird, muss sie innerhalb eines /24-Subnetzes liegen. Wenn die Notation x.x.x.x/x verwendet wird, besteht die Möglichkeit, Host/Netzmaske zu setzen.

set service pppoe-server default-pool <POOL-NAME>

Verwenden Sie diesen Befehl, um den Namen des Standard-IP-Adressen-Pools zu definieren.

set service pppoe-server interface <interface>

Verwenden Sie diesen Befehl, um die Schnittstelle zu definieren, die der PPPoE-Server verwenden wird, um nach PPPoE-Clients zu suchen.

set service pppoe-server gateway-address <address>

Gibt eine einzelne <Gateway> IP-Adresse an, die als lokale Adresse der PPP-Schnittstellen verwendet werden soll.

Einrichtung der RADIUS-Authentifizierung

Um RADIUS-basierte Authentifizierung zu aktivieren, muss der Authentifizierungsmodus innerhalb der Konfiguration geändert werden. Vorherige Einstellungen wie lokale Benutzer existieren weiterhin in der Konfiguration, jedoch werden sie nicht verwendet, wenn der Modus von lokal auf radius geändert wurde. Sobald er wieder auf lokal geändert wird, wird erneut alle lokalen Konten verwendet.

set service pppoe-server authentication mode radius
set service pppoe-server authentication radius server <server> key <secret>

Konfigurieren Sie RADIUS <Server> und seinen erforderlichen gemeinsamen <Secret> für die Kommunikation mit dem RADIUS-Server.

Da der RADIUS-Server ein einziger Ausfallpunkt ist, können mehrere RADIUS-Server eingerichtet werden und werden anschließend nacheinander verwendet. Zum Beispiel:

set service pppoe-server authentication radius server 10.0.0.1 key 'foo'
set service pppoe-server authentication radius server 10.0.0.2 key 'foo'

Hinweis

Einige RADIUS-Server verwenden eine Zugriffssteuerungsliste, die Anfragen erlaubt oder ablehnt, stellen Sie sicher, dass Ihr VyOS-Router zur Liste der zugelassenen Client-Listen hinzugefügt wird.

RADIUS Quelladresse

Wenn Sie OSPF als IGP verwenden, wird immer die nächstgelegene Schnittstelle, die mit dem RADIUS-Server verbunden ist, verwendet. Mit VyOS 1.2 können Sie alle ausgehenden RADIUS-Anfragen an eine einzelne Quell-IP binden, z. B. die Loopback-Schnittstelle.

set service pppoe-server authentication radius source-address <address>

Quell-IPv4-Adresse, die in allen RADIUS-Server-Abfragen verwendet wird.

Hinweis

Die source-address muss auf einer der VyOS-Schnittstellen konfiguriert sein. Best Practice wäre eine Loopback- oder Dummy-Schnittstelle.

Erweiterte RADIUS-Optionen

set service pppoe-server authentication radius server <server> port <port>

Konfigurieren Sie RADIUS <Server> und seinen erforderlichen Port für Authentifizierungsanfragen.

set service pppoe-server authentication radius server <server> fail-time <time>

Markieren Sie den RADIUS-Server für diese gegebene <Time> Sekunden als offline.

set service pppoe-server authentication radius server <server> disable

Temporär deaktivieren Sie diesen RADIUS-Server.

set service pppoe-server authentication radius acct-timeout <timeout>

Zeitlimit, um Antwort auf Interim-Update-Pakete zu warten. (Standard 3 Sekunden)

set service pppoe-server authentication radius dynamic-author server <address>

Gibt die IP-Adresse für den Dynamic Authorization Extension Server (DM/CoA) an. Diese IP muss auf einer beliebigen VyOS-Schnittstelle existieren oder es kann 0.0.0.0 sein.

set service pppoe-server authentication radius dynamic-author port <port>

UDP-Port für Dynamic Authorization Extension Server (DM/CoA)

set service pppoe-server authentication radius dynamic-author key <secret>

Geheimnis für Dynamic Authorization Extension Server (DM/CoA)

set service pppoe-server authentication radius max-try <number>

Maximale Anzahl von Versuchen, um Access-Request/Accounting-Request-Anfragen zu senden

set service pppoe-server authentication radius timeout <timeout>

Zeitlimit, um Antwort vom Server zu warten (Sekunden)

set service pppoe-server authentication radius nas-identifier <identifier>

Wert, der an den RADIUS-Server im NAS-Identifier-Attribut gesendet wird und in DM/CoA-Anfragen übereinstimmt.

set service pppoe-server authentication radius nas-ip-address <address>

Wert, der an den RADIUS-Server im NAS-IP-Address-Attribut gesendet wird und in DM/CoA-Anfragen übereinstimmt. Auch DM/CoA-Server bindet sich an diese Adresse.

set service pppoe-server authentication radius source-address <address>

Quell-IPv4-Adresse, die in allen RADIUS-Server-Abfragen verwendet wird.

set service pppoe-server authentication radius rate-limit attribute <attribute>

Legt fest, welches RADIUS-Server-Attribut die Rate-Limit-Information enthält. Das Standardattribut ist Filter-Id.

Hinweis

Wenn Sie ein benutzerdefiniertes RADIUS-Attribut festlegen, müssen Sie es sowohl auf dem RADIUS-Server als auch auf dem Client definieren.

set service pppoe-server authentication radius rate-limit enable

Ermöglicht Bandbreitenbegrenzung über RADIUS.

set service pppoe-server authentication radius rate-limit vendor

Gibt den Hersteller-Dictionary an, das Dictionary muss in /usr/share/accel-ppp/radius sein.

Empfangene RADIUS-Attribute haben eine höhere Priorität als Parameter, die innerhalb der CLI-Konfiguration definiert sind, siehe Erklärung unten.

Client-IP-Adressen durch RADIUS zuweisen

Wenn der RADIUS-Server das Attribut Framed-IP-Address sendet, wird diese IP-Adresse dem Client zugewiesen und das Option default-pool innerhalb der CLI-Konfiguration wird ignoriert.

Wenn der RADIUS-Server das Attribut Framed-Pool sendet, wird die IP-Adresse aus einem vordefinierten IP-Pool zugewiesen, dessen Name dem Attributwert entspricht.

Wenn der RADIUS-Server das Attribut Stateful-IPv6-Address-Pool sendet, wird die IPv6-Adresse aus einem vordefinierten IPv6-Pool prefix zugewiesen, dessen Name dem Attributwert entspricht.

Wenn der RADIUS-Server das Attribut Delegated-IPv6-Prefix-Pool sendet, wird die IPv6-Delegationspräfix-Adresse aus einem vordefinierten IPv6-Pool delegate zugewiesen, dessen Name dem Attributwert entspricht.

Hinweis

Stateful-IPv6-Address-Pool und Delegated-IPv6-Prefix-Pool sind in RFC6911 definiert. Wenn sie in Ihrem RADIUS-Server nicht definiert sind, fügen Sie neue Dictionary hinzu.

Der Benutzer-Interface kann über RADIUS Access-Accept-Paket in VRF-Kontext gesetzt werden oder über RADIUS CoA geändert werden. Accel-VRF-Name wird für diese Zwecke verwendet. Es ist ein benutzerdefiniertes ACCEL-PPP-Attribut. Definieren Sie es in Ihrem RADIUS-Server.

Client-Schnittstellen durch RADIUS umbenennen

Wenn der RADIUS-Server das Attribut NAS-Port-Id verwendet, werden die PPP-Tunnel umbenannt.

Hinweis

Der Wert des Attributs NAS-Port-Id muss weniger als 16 Zeichen sein, andernfalls wird die Schnittstelle nicht umbenannt.

Automatische VLAN-Erstellung

set service pppoe-server interface <interface> vlan <id | range>

VLANs können durch Accel-ppp auf Anforderung via Kernel-Modul namens vlan_mon erstellt werden, das eingehende VLANs überwacht und erstellt die notwendigen VLANs, falls erforderlich und erlaubt. VyOS unterstützt die Verwendung von entweder VLAN-ID oder ganzen Bereichen, beide Werte können gleichzeitig für eine Schnittstelle definiert werden.

Bei Konfiguration werden PPPoE die notwendigen VLANs erstellen, wenn erforderlich. Sobald die Benutzersession beendet und das VLAN nicht mehr benötigt wird, entfernt VyOS es wieder.

set service pppoe-server interface eth3 vlan 100
set service pppoe-server interface eth3 vlan 200
set service pppoe-server interface eth3 vlan 500-1000
set service pppoe-server interface eth3 vlan 2000-3000

Bandbreitenbegrenzung

Bandbreiten-Ratenlimits können für lokale Benutzer oder RADIUS-basierte Attribute festgelegt werden.

Für lokale Benutzer

set service pppoe-server authentication local-users username <user> rate-limit download <bandwidth>

Download-Bandbreitenbegrenzung in kbit/s für <User>.

set service pppoe-server authentication local-users username <user> rate-limit upload <bandwidth>

Upload-Bandbreitenbegrenzung in kbit/s für <User>.

set service pppoe-server access-concentrator 'ACN'
set service pppoe-server authentication local-users username foo password 'bar'
set service pppoe-server authentication local-users username foo rate-limit download '20480'
set service pppoe-server authentication local-users username foo rate-limit upload '10240'
set service pppoe-server authentication mode 'local'
set service pppoe-server client-ip-pool IP-POOL range '10.1.1.100/24'
set service pppoe-server default-pool 'IP-POOL'
set service pppoe-server name-server '10.100.100.1'
set service pppoe-server name-server '10.100.200.1'
set service pppoe-server interface 'eth1'
set service pppoe-server gateway-address '10.1.1.2'

Wenn der Benutzer verbunden ist, verwendet die Benutzersession die festgelegten Grenzwerte und kann über show pppoe-server sessions angezeigt werden.

show pppoe-server sessions
ifname | username |     ip     |    calling-sid    | rate-limit  | state  |  uptime  | rx-bytes | tx-bytes
-------+----------+------------+-------------------+-------------+--------+----------+----------+----------
ppp0   | foo      | 10.1.1.100 | 00:53:00:ba:db:15 | 20480/10240 | active | 00:00:11 | 214 B    | 76 B

Für RADIUS-Benutzer

Das aktuelle Attribut Filter-Id wird als Standard verwendet und kann innerhalb von RADIUS konfiguriert werden:

Filter-Id=2000/3000 (bedeutet 2000 Kbit Downstream-Rate und 3000 Kbit Upstream-Rate)

Der folgende Befehl aktiviert es, vorausgesetzt, die RADIUS-Verbindung wurde eingerichtet und funktioniert.

set service pppoe-server authentication radius rate-limit enable

Verwenden Sie diesen Befehl, um Bandbreitenbegrenzung über RADIUS zu aktivieren.

Weitere Attribute können verwendet werden, müssen aber in einem der Dictionaries in /usr/share/accel-ppp/radius sein.

Lastverteilung

set service pppoe-server pado-delay <number-of-ms> sessions <number-of-sessions>

Verwenden Sie diesen Befehl, um die Verzögerung von PADO (PPPoE Active Discovery Offer) Paketen zu aktivieren, die als Sitzungsbalancierungsmethode mit anderen PPPoE-Servern verwendet werden können.

set service pppoe-server pado-delay 50 sessions '500'
set service pppoe-server pado-delay 100 sessions '1000'
set service pppoe-server pado-delay 300 sessions '3000'

Im obigen Beispiel verbinden sich die ersten 499 Sitzungen ohne Verzögerung. PADO-Pakete werden für Verbindungen von 500 bis 999 um 50 ms verzögert, was es anderen PPPoE-Servern ermöglicht, PADO schneller zu senden und Clients werden zu anderen Servern verbinden. Der letzte Befehl sagt, dass dieser PPPoE-Server nur 3000 Clients bedienen kann.

IPv6

set service pppoe-server ppp-options ipv6 <require | prefer | allow | deny>

Gibt die Präferenz für die IPv6-Verhandlung an.

  • require - IPv6-Verhandlung erfordern

  • prefer - Client nach IPv6-Verhandlung fragen, fehlschlagen, wenn er ablehnt

  • allow - IPv6 nur dann verhandeln, wenn der Client darum bittet

  • deny - IPv6 nicht verhandeln (Standardwert)

set service pppoe-server client-ipv6-pool <IPv6-POOL-NAME> prefix <address> mask <number-of-bits>

Verwenden Sie diesen Befehl, um den IPv6-Adresspool zu setzen, aus dem ein PPPoE-Client eine IPv6-Präfix von Ihrer definierten Länge (Maske) erhält, um das PPPoE-Endgerät auf ihrer Seite zu beenden. Die Maske kann von 48 bis 128 Bit lang sein, der Standardwert ist 64.

set service pppoe-server client-ipv6-pool <IPv6-POOL-NAME> delegate <address> delegation-prefix <number-of-bits>

Verwenden Sie diesen Befehl, um DHCPv6 Prefix Delegation (RFC3633) auf PPPoE zu konfigurieren. Sie müssen Ihren IPv6-Pool und die Länge des Delegationspräfixes festlegen. Aus dem definierten IPv6-Pool geben Sie Netzwerke der definierten Länge (Delegationspräfix) aus. Die Länge des Delegationspräfixes kann von 32 bis 64 Bit lang sein.

set service pppoe-server default-ipv6-pool <IPv6-POOL-NAME>

Verwenden Sie diesen Befehl, um den Namen des Standard-IPv6-Adresspools zu definieren.

set service pppoe-server ppp-options ipv6 allow
set service pppoe-server client-ipv6-pool IPv6-POOL delegate '2001:db8:8003::/48' delegation-prefix '56'
set service pppoe-server client-ipv6-pool IPv6-POOL prefix '2001:db8:8002::/48' mask '64'
set service pppoe-server default-ipv6-pool IPv6-POOL

Erweiterte IPv6-Optionen

set service pppoe-server ppp-options ipv6-accept-peer-interface-id

Peer-Interface-Identifier akzeptieren. Standardmäßig ist dies nicht definiert.

set service pppoe-server ppp-options ipv6-interface-id <random | x:x:x:x>

Gibt einen festen oder zufälligen Interface-Identifier für IPv6 an. Standardmäßig ist es fest.

  • random - Zufälliger Interface-Identifier für IPv6

  • x:x:x:x - Geben Sie den Interface-Identifier für IPv6 an

set service pppoe-server ppp-options ipv6-interface-id <random | x:x:x:x>

Gibt den Peer-Interface-Identifier für IPv6 an. Standardmäßig ist es fest.

  • random - Zufälliger Interface-Identifier für IPv6

  • x:x:x:x - Geben Sie den Interface-Identifier für IPv6 an

  • ipv4-addr - Berechnen Sie den Interface-Identifier aus der IPv4-Adresse.

  • calling-sid - Berechnen Sie den Interface-Identifier aus dem Calling-Station-ID.

Erweiterte Optionen

Erweiterte Authentifizierungs-Optionen

set service pppoe-server authentication local-users username <user> disable

Deaktivieren Sie das <User> Konto.

set service pppoe-server authentication local-users username <user> static-ip <address>

Weisen Sie dem <User> Konto eine statische IP-Adresse zu.

set service pppoe-server authentication protocols <pap | chap | mschap | mschap-v2>

Erfordert, dass der Peer sich mit einem der folgenden Protokolle authentifiziert: pap, chap, mschap, mschap-v2.

Erweiterte Client-IP-Pool-Optionen

set service pppoe-server client-ip-pool <POOL-NAME> next-pool <NEXT-POOL-NAME>

Verwenden Sie diesen Befehl, um den Namen des nächsten Adresspools zu definieren.

Erweiterte PPP-Optionen

set service pppoe-server ppp-options disable-ccp

Deaktivieren Sie das Compression Control Protocol (CCP). CCP ist standardmäßig aktiviert.

set service pppoe-server ppp-options interface-cache <number>

Gibt die Anzahl der Schnittstellen an, die im Cache gehalten werden. Das bedeutet, dass die Schnittstelle nachdem die entsprechende Sitzung zerstört wurde, nicht zerstört wird, sondern in den Cache platziert und später für neue Sitzungen wieder verwendet wird. Dies sollte die Rate der Erstellung/Löschung von Schnittstellen auf Kernel-Ebene reduzieren. Der Standardwert ist 0.

set service pppoe-server ppp-options ipv4 <require | prefer | allow | deny>

Gibt die Präferenz für die IPv4-Verhandlung an.

  • require - IPv4-Verhandlung erfordern

  • prefer - Client nach IPv4-Verhandlung fragen, nicht fehlschlagen, wenn er ablehnt

  • allow - IPv4 nur dann verhandeln, wenn der Client darum bittet (Standardwert)

  • deny - IPv4 nicht verhandeln

set service pppoe-server ppp-options lcp-echo-failure <number>

Definiert die maximale Anzahl <number> unbeantworteter Echo-Anfragen. Bei Erreichen des Werts <number> wird die Sitzung zurückgesetzt. Der Standardwert ist 3.

set service pppoe-server ppp-options lcp-echo-interval <interval>

Wenn dieser Option spezifiziert und größer als 0 ist, sendet das PPP-Modul LCP-Pings der Echo-Anfrage alle <interval> Sekunden. Der Standardwert ist 30.

set service pppoe-server ppp-options lcp-echo-timeout

Gibt die Zeit in Sekunden an, um auf irgendeine Peer-Aktivität zu warten. Wenn diese Option spezifiziert ist, schaltet sie die adaptive LCP Echo-Funktion ein und „lcp-echo-failure“ wird nicht verwendet. Der Standardwert ist 0.

set service pppoe-server ppp-options min-mtu <number>

Definiert die minimale akzeptable MTU. Wenn der Client versucht, weniger als die angegebene MTU zu verhandeln, wird es NAKed oder bei Ablehnung größerer MTU getrennt. Der Standardwert ist 100.

set service pppoe-server ppp-options mppe <require | prefer | deny>

Gibt die MPPE-Verhandlungspräferenz an.

  • require - Client nach MPPE fragen, wenn er ablehnt, Verbindung trennen

  • prefer - Client nach MPPE fragen, wenn er ablehnt, nicht fehlschlagen. (Standardwert)

  • deny - MPPE ablehnen

Standardverhalten - Client nach MPPE fragen, aber erlauben, wenn der Client möchte. Bitte beachten Sie, dass RADIUS dieses Option über MS-MPPE-Encryption-Policy-Attribut überschreiben kann.

set service pppoe-server ppp-options mru <number>

Definiert die bevorzugte MRU. Standardmäßig ist sie nicht definiert.

set service pppoe-server description <description>

set service pppoe-server limits burst <value>

Burst-Zahl

set service pppoe-server limits connection-limit <value>

Akzeptierbare Verbindungsraten (z. B. 1/min, 60/sec)

Timeout in Sekunden

set service pppoe-server mtu

set service pppoe-server max-concurrent-sessions

Maximale Anzahl gleichzeitiger Sitzungsstartversuche

set service pppoe-server name-server <address>

Der verbundene Client sollte <address> als DNS-Server verwenden. Dieser Befehl akzeptiert sowohl IPv4- als auch IPv6-Adressen. Bis zu zwei Nameserver können für IPv4, bis zu drei für IPv6 konfiguriert werden.

set service pppoe-server service-name <names>

Gibt den Service-Name an, um zu antworten. Wenn fehlend, ist jeder Service-Name akzeptabel und der Client’s Service-Name wird zurückgesendet. Auch möglich, mehrere Service-Names zu setzen: sn1,sn2,sn3

Standardmäßig wird die Benutzersitzung ersetzt, wenn eine zweite Authentifizierungsanfrage erfolgreich ist. Solche Sitzungsanfragen können entweder abgelehnt oder vollständig erlaubt werden, was es ermöglicht, mehrere Sitzungen für einen Benutzer im letzteren Fall zu ermöglichen. Wenn es abgelehnt wird, wird die zweite Sitzung sogar abgelehnt, wenn die Authentifizierung erfolgreich ist, der Benutzer muss seine erste Sitzung beenden und kann dann erneut authentifizieren.

set service pppoe-server session-control

  • disable: Deaktiviert die Sitzungssteuerung.

  • deny: Leitet zweite Sitzungszertifizierung ab.

  • replace: Beendet die erste Sitzung, wenn die zweite autorisiert wird (Standard)

set service pppoe-server shaper fwmark <1-2147483647>

Beispiele

IPv4

Das folgende Beispiel verwendet ACN als Access-Concentrator-Name, weist eine Adresse aus dem Pool 10.1.1.100-111 zu, beendet am lokalen Endpunkt 10.1.1.1 und dient nur auf eth1.

set service pppoe-server access-concentrator 'ACN'
set service pppoe-server authentication local-users username foo password 'bar'
set service pppoe-server authentication mode 'local'
set service pppoe-server client-ip-pool IP-POOL range '10.1.1.100-10.1.1.111'
set service pppoe-server default-pool 'IP-POOL'
set service pppoe-server interface eth1
set service pppoe-server gateway-address '10.1.1.2'
set service pppoe-server name-server '10.100.100.1'
set service pppoe-server name-server '10.100.200.1'

Dual-Stack IPv4/IPv6-Bereitstellung mit Präfixdelegation

Das folgende Beispiel umfasst eine Dual-Stack-Konfiguration.

set service pppoe-server authentication local-users username test password 'test'
set service pppoe-server authentication mode 'local'
set service pppoe-server client-ip-pool IP-POOL range '192.168.0.1/24'
set service pppoe-server default-pool 'IP-POOL'
set service pppoe-server client-ipv6-pool IPv6-POOL delegate '2001:db8:8003::/48' delegation-prefix '56'
set service pppoe-server client-ipv6-pool IPV6-POOL prefix '2001:db8:8002::/48' mask '64'
set service pppoe-server default-ipv6-pool IPv6-POOL
set service pppoe-server ppp-options ipv6 allow
set service pppoe-server name-server '10.1.1.1'
set service pppoe-server name-server '2001:db8:4860::8888'
set service pppoe-server interface 'eth2'
set service pppoe-server gateway-address '10.100.100.1'

Der Client erhält nach erfolgreicher Authentifizierung eine IPv4- und eine IPv6-/64-Adresse, um das PPPoE-Endgerät auf der Clientseite zu beenden, sowie ein /56-Subnetz für die interne Nutzung des Clients.

vyos@pppoe-server:~$ sh pppoe-server sessions
 ifname | username |     ip      |            ip6           |       ip6-dp        |    calling-sid    | rate-limit | state  |  uptime  | rx-bytes | tx-bytes
--------+----------+-------------+--------------------------+---------------------+-------------------+------------+--------+----------+----------+----------
 ppp0   | test     | 192.168.0.1 | 2001:db8:8002:0:200::/64 | 2001:db8:8003::1/56 | 00:53:00:12:42:eb |            | active | 00:00:49 | 875 B    | 2.1 KiB
