Geneve

Geneve Schnittstellen fungieren als virtuelle Netzwerkports. Administratoren können Standardnetzwerkkonfigurationen darauf anwenden, wie z. B. IP-Adressierung, Brücken oder Firewall-Regeln, genauso wie auf physische Ethernet-Ports.

Das Geneve-Protokoll kapselt Layer-2-Ethernet-Frames, die von Endpunkten wie virtuellen Maschinen, Containern oder physischen Servern stammen, in UDP-Pakete. Es vereint die Funktionen früherer Kapselungsprotokolle, einschließlich VXLAN, NVGRE und STT, und behebt deren Einschränkungen, wie z. B. feste Header-Strukturen und fehlende Metadatenunterstützung. Aufgrund seiner Erweiterbarkeit kann Geneve möglicherweise diese älteren Protokolle ersetzen.

Geneve-Tunnels werden verwendet, um virtuelle Switches zu verbinden, die sich innerhalb von Hypervisoren, physischen Switches, Middleboxes und anderen Netzwerkgeräten befinden.

Geneve-Tunnels laufen über jedes standardmäßige IP-Netzwerk. In größeren Umgebungen wird das zugrunde liegende Netzwerk (Underlay) oft mit einer Clos-Topologie, auch bekannt als Leaf-and-Spine oder Fat-Tree-Topologie, gebaut.

Konfiguration

Gemeinsame Schnittstellenkonfiguration

set interfaces geneve <interface> address <address>

Konfigurieren Sie eine oder mehrere Schnittstellen-IP-Adressen.

<address> unterstützt IPv4 und IPv6 in CIDR-Schreibweise. Verwenden Sie z. B. 192.0.2.1/24 für IPv4 oder 2001:db8::1/64 für IPv6.

Beispiel:

set interfaces geneve gnv0 address 192.0.2.1/24
set interfaces geneve gnv0 address 2001:db8::1/64
set interfaces geneve <interface> description <description>

Konfigurieren Sie einen klaren, beschreibenden Alias für die Schnittstelle.

Dieser Alias erscheint im Befehl show interfaces und in SNMP-basierten Überwachungstools.

Beispiel:

set interfaces geneve gnv0 description 'This is an interface running on VyOS.'
set interfaces geneve <interface> disable

Deaktivieren Sie die Schnittstelle.

Die Schnittstelle wird auf den administrativ heruntergefahrenen (A/D) Zustand gesetzt.

Beispiel:

set interfaces geneve gnv0 disable
set interfaces geneve <interface> mac <xx:xx:xx:xx:xx:xx>

Konfigurieren Sie eine benutzerdefinierte MAC-Adresse für die Schnittstelle.

Beispiel:

set interfaces geneve gnv0 mac '00:53:01:02:03:04'
set interfaces geneve <interface> mtu <mtu>

Konfigurieren Sie das MTU der Schnittstelle.

Dieser Wert definiert die größte Paketgröße in Bytes, die die Schnittstelle ohne Fragmentierung überträgt.

Beispiel:

set interfaces geneve gnv0 mtu 1600
set interfaces geneve <interface> ip adjust-mss <mss | clamp-mss-to-pmtu>

Konfigurieren Sie die MSS , die in ausgehenden TCP SYN-Paketen auf der angegebenen Schnittstelle angegeben wird.

Durch das Erschweren des MSS-Werts in TCP SYN-Paketen informieren Sie explizit das Remote-Gerät, dass keine Pakete größer als dieser Wert gesendet werden sollen. Dies verhindert Verbindungsprobleme, die auftreten, wenn die Pfad-MTU-Entdeckung (PMTUD) fehlschlägt.

Die folgenden Optionen sind verfügbar:

  • mss: Legt die MSS auf einen bestimmten Wert in Bytes fest. Nutzen Sie diese Option, wenn Sie eine bestimmte MSS erzwingen müssen, z. B. um Verbindungsprobleme zu beheben oder spezifische Netzwerkanforderungen zu berücksichtigen.

  • clamp-mss-to-pmtu: Der Router berechnet die MSS automatisch als das MTU der Schnittstelle minus 40 Bytes für IPv4-Datenverkehr (20 Bytes für den IPv4-Header und 20 Bytes für den TCP-Header). Diese Option wird empfohlen, um den richtigen Wert automatisch zu setzen.

set interfaces geneve <interface> ip arp-cache-timeout

Konfigurieren Sie, wie lange ein ARP-Eintrag gültig bleibt, nachdem eine IP-zu-MAC-Zuordnung auf dieser Schnittstelle erlernt wurde.

Die Standarddauer beträgt 30 Sekunden.

Ein ARP-Eintrag bleibt gültig, wenn er positive Rückmeldungen von höheren Protokollen erhält.

Beispiel:

set interfaces geneve gnv0 ip arp-cache-timeout 180
set interfaces geneve <interface> ip disable-arp-filter

Konfigurieren Sie das ARP-Filtern auf dieser Schnittstelle.

Standardverhalten: Das Kernel antwortet auf ARP-Anfragen auf dieser Schnittstelle nur dann, wenn der Datenverkehr über diese spezifische Schnittstelle zurück zum ARP-Absender weitergeleitet wird.

Wenn konfiguriert: Das Kernel antwortet auf ARP-Anfragen auf dieser Schnittstelle für jede IP-Adresse, die auf dem lokalen Host konfiguriert ist, unabhängig davon, welche spezifische Schnittstelle diese IP-Adresse zugewiesen ist, und unabhängig vom Routing-Tabellen. Dies spiegelt das Linux-Konzept wider, dass IP-Adressen dem Host gehören, nicht einzelnen Schnittstellen.

Beispiel:

set interfaces geneve gnv0 ip disable-arp-filter
set interfaces geneve <interface> ip disable-forwarding

Konfigurieren Sie das Verhalten der Schnittstelle als Host oder Router.

Wenn konfiguriert, wechselt die Schnittstelle in den Host-Modus, und IPv4-Weiterleitung wird auf ihr deaktiviert.

Beispiel:

set interfaces geneve gnv0 ip disable-forwarding
set interfaces geneve <interface> ip enable-directed-broadcast

Konfigurieren Sie, ob IP-gerichtete Broadcast-Pakete, die auf dieser Schnittstelle empfangen werden, weitergeleitet werden.

Standardverhalten: IP-gerichtete Broadcast-Pakete werden verworfen.

Wenn konfiguriert: IP-gerichtete Broadcast-Pakete werden an alle Hosts auf dem Ziel-Subnetz weitergeleitet, wie in RFC 1812 und RFC 2644 definiert.

Beispiel:

set interfaces geneve gnv0 ip enable-directed-broadcast
set interfaces geneve <interface> ip enable-arp-accept

Konfigurieren Sie, wie Gratuitous ARPs auf dieser Schnittstelle verarbeitet werden.

Wenn konfiguriert, wird eine IP-zu-MAC-Zuordnung in der ARP-Tabelle basierend auf Gratuitous ARP-Anfragen oder Antworten hinzugefügt.

Hinweis

Wenn die ARP-Tabelle bereits einen IP-Adress-Eintrag aus einem Gratuitous ARP enthält, wird dieser Eintrag aktualisiert, unabhängig davon, ob diese Einstellung konfiguriert ist.

Beispiel:

set interfaces geneve gnv0 ip enable-arp-accept
set interfaces geneve <interface> ip enable-arp-announce

Konfigurieren Sie die Quell-IP-Auswahl für ARP-Anfragen auf dieser Schnittstelle.

Standardverhalten: Das Kernel kann jede IP-Adresse verwenden, die der Host besitzt, als Quell-IP-Adresse in ARP-Anfragen auf dieser Schnittstelle.

Wenn konfiguriert: Das Kernel versucht zunächst, eine Quell-IP-Adresse auszuwählen, die auf der Schnittstelle konfiguriert ist und mit dem Ziel-IP-Adress-Subnetz übereinstimmt. Wenn kein solches Subnetz vorhanden ist, wählt das Kernel die IP-Adresse aus, die es normalerweise verwenden würde (basierend auf der Routing-Tabelle, um das Zielziel zu erreichen).

Beispiel:

set interfaces geneve gnv0 ip enable-arp-announce
set interfaces geneve <interface> ip enable-arp-ignore

Konfigurieren Sie, welche ARP-Anfragen auf dieser Schnittstelle ignoriert werden.

Standardverhalten: Das Kernel antwortet auf ARP-Anfragen für beliebige lokale IP-Adressen, unabhängig davon, welcher Schnittstelle sie zugewiesen sind.

Wenn konfiguriert: Das Kernel antwortet nur auf ARP-Anfragen, wenn die Ziel-IP-Adresse dieser spezifischen Schnittstelle zugewiesen ist.

Beispiel:

set interfaces geneve gnv0 ip enable-arp-ignore
set interfaces geneve <interface> ip enable-proxy-arp

Konfigurieren Sie Proxy-ARP auf dieser Schnittstelle.

Wenn konfiguriert, greift der Router (Kernel) auf ARP-Anfragen für nicht lokale IP-Adressen ein und antwortet mit der MAC-Adresse der Schnittstelle, die die Anfrage empfangen hat. Danach werden Pakete, die an diese IP-Adressen gerichtet sind, an ihre tatsächlichen Ziele auf entfernten Subnetzen weitergeleitet.

Beispiel:

set interfaces geneve gnv0 ip enable-proxy-arp
set interfaces geneve <interface> ip proxy-arp-pvlan

Konfigurieren Sie lokales Proxy-ARP auf der Schnittstelle.

Wenn konfiguriert, antwortet der Router (Kernel) auf ARP-Anfragen auf dieser VLAN-Schnittstelle, auch wenn die Ziel-IP-Adresse auf dem gleichen Subnetz und der gleichen Schnittstelle liegt.

Dies wird verwendet, um Netzwerkisolationsanforderungen (RFC 3069) für private VLANs (PVLANs) zu unterstützen. In PVLAN-Konfigurationen dürfen Hosts auf isolierten Ports nicht direkt miteinander kommunizieren, aber sie können mit dem Upstream-Router kommunizieren.

Durch die Antwort auf inter-host ARP-Anfragen mit ihrer eigenen MAC-Adresse leitet der Router den inter-host-Datenverkehr durch sich selbst anstatt direkt zwischen Hosts.

Hinweis

Dieser Befehl funktioniert unabhängig und erfordert nicht, dass das Standard-Proxy-ARP auf der Schnittstelle aktiviert wird.

Lokales Proxy-ARP wird auch als bezeichnet:

  • VLAN-Aggregation (RFC 3069).

  • Private VLAN (Cisco, Allied Telesyn).

  • Quellport-Filterung oder Port-Isolation (Hewlett-Packard).

  • MAC-Forced Forwarding (Ericsson).

set interfaces geneve <interface> ip source-validation <strict | loose | disable>

Konfigurieren Sie die Quell-IP-Adressen-Validierung mit RPF auf dieser Schnittstelle, wie in RFC 3704 angegeben.

Die folgenden Optionen sind verfügbar:

  • strict: Jeder eingehende Paket-Quell-IP-Adresse wird gegen die Forwarding Information Base (FIB) geprüft. Wenn die Schnittstelle nicht der beste Weg zur Quelle ist, schlägt die Validierung fehl, und das Paket wird gelöscht.

  • loose: Jeder eingehende Paket-Quell-IP-Adresse wird gegen die Forwarding Information Base (FIB) geprüft. Wenn die Quell-IP-Adresse über irgendeine Schnittstelle nicht erreichbar ist, schlägt die Validierung fehl.

  • disable: Keine Quell-IP-Adressen-Validierung wird durchgeführt. Alle eingehenden Pakete werden akzeptiert.

RFC 3704 empfiehlt, den strengen Modus zu aktivieren, um IP-Spoofing, wie z. B. DDoS-Angriffe, zu verhindern. Für asynchrone oder andere komplexe Routing-Szenarien verwenden Sie den lockeren Modus.

set interfaces geneve <interface> ipv6 address autoconf

Konfigurieren Sie die Schnittstelle, um automatisch eine IPv6-Adresse mit SLAAC, zu erhalten, wie in RFC 4862 festgelegt.

IPv6-Hosts können sich automatisch konfigurieren, wenn sie sich einem IPv6-Netzwerk anschließen, indem sie das Neighbor Discovery Protocol über ICMPv6-Router-Discovery-Nachrichten verwenden. Bei der ersten Verbindung zu einem Netzwerk sendet ein Host eine Link-Local-Router-Solicitation-Multicast-Anfrage für seine Konfigurationsparameter. Der Router antwortet mit einer Router-Advertisement-Paket, das Internet-Layer-Konfigurationsparameter enthält.

Hinweis

Diese Methode deaktiviert automatisch die IPv6-Verkehrsweiterleitung auf der Schnittstelle.

Beispiel:

set interfaces geneve gnv0 ipv6 address autoconf
set interfaces geneve <interface> ipv6 address eui64 <prefix>

Konfigurieren Sie die Schnittstelle, um sich selbst eine IPv6-Adresse mit dem EUI-64 -Methode zu weisen, wie in RFC 4291 festgelegt.

Beispiel:

set interfaces geneve gnv0 ipv6 address eui64 2001:db8:beef::/64
set interfaces geneve <interface> ipv6 address no-default-link-local

Deaktivieren Sie die automatische Zuweisung einer Link-Local-IPv6-Adresse für diese Schnittstelle.

Beispiel:

set interfaces geneve gnv0 ipv6 address no-default-link-local
set interfaces geneve <interface> ipv6 disable-forwarding

Konfigurieren Sie das Verhalten der Schnittstelle als Host oder Router.

Wenn konfiguriert, wechselt die Schnittstelle in den Host-Modus, und IPv6-Weiterleitung wird auf ihr deaktiviert.

Beispiel:

set interfaces geneve gnv0 ipv6 disable-forwarding
set interfaces geneve <interface> ipv6 adjust-mss <mss | clamp-mss-to-pmtu>

Konfigurieren Sie die MSS , die in ausgehenden TCP SYN-Paketen auf der angegebenen Schnittstelle angegeben wird.

Durch das Erschweren des MSS-Werts in TCP SYN-Paketen informieren Sie explizit das Remote-Gerät, dass keine Pakete größer als dieser Wert gesendet werden sollen. Dies verhindert Verbindungsprobleme, wenn die Pfad-MTU-Entdeckung (PMTUD) fehlschlägt.

Die folgenden Optionen sind verfügbar:

  • mss: Setzt die MSS auf einen bestimmten Wert in Bytes. Nutzen Sie diese Option, um eine bestimmte MSS zu erzwingen, z. B. um Verbindungsprobleme zu beheben oder spezifische Netzwerkanforderungen zu berücksichtigen.

  • clamp-mss-to-pmtu: Der Router berechnet die MSS als das MTU der Schnittstelle minus 60 Bytes für IPv6-Datenverkehr (40 Bytes für den IPv6-Header und 20 Bytes für den TCP-Header). Diese Option wird empfohlen, um den richtigen Wert automatisch zu setzen.

set interfaces geneve <interface> ipv6 accept-dad <0 | 1 | 2>

Konfigurieren Sie IPv6 DAD auf der Schnittstelle.

Die folgenden Optionen sind verfügbar:

  • 0: Deaktiviert DAD. Es wird keine Duplicate Address Detection durchgeführt.

  • 1: Aktiviert DAD (Standard). Duplicate Addresses werden erkannt. Die IPv6-Operation der Schnittstelle wird für gültige IPv6-Adressen fortgesetzt.

  • 2: Aktiviert DAD und, falls eine MAC-basierte duplicate link-local Adresse gefunden wird, deaktiviert die IPv6-Operation auf dieser Schnittstelle.

Beispiel:

set interfaces geneve gnv0 ipv6 accept-dad 2
set interfaces geneve gnv0 remote <address>

Konfigurieren Sie die Remote-Endpunkt-IP-Adresse für den Geneve-Tunnel.

set interfaces geneve gnv0 vni <vni>

Konfigurieren Sie VNI für die Geneve Schnittstelle.

Der VNI ist ein virtueller Netzwerk-Identifikator. Er ermöglicht es, mehrere virtuelle Netzwerke, die dieselbe physische Infrastruktur teilen, zu isolieren.

Der VNI wird auch verwendet, um den Datenverkehr nach dem Verlassen des Tunnels zu verteilen, z. B. um Pakete mit überlappenden IP-Adressen zu spezifischen Routing-Tabellen zu mappen.

set interfaces gnv0 <interface> port <port>

Konfigurieren Sie den Ziel-UDP-Port für das entfernte Geneve-Tunnel-Endgerät. Stellen Sie sicher, dass das entfernte Gerät so konfiguriert ist, dass es auf diesem spezifischen Port wartet.
