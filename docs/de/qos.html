Verkehrsrichtlinie

QoS

Der allgemeine Name für Quality of Service oder Verkehrssteuerung umfasst Dinge wie das Formen des Verkehrs, das Planen oder das Löschen von Paketen, was die Art von Dingen ist, mit denen Sie spielen können, wenn Sie beispielsweise einen Bandbreitenengpass auf einer Verbindung haben und möchten, dass einige Arten von Verkehr über andere priorisiert werden.

tc ist ein leistungsstarker Werkzeug für Verkehrssteuerung, der im Linux-Kernel gefunden wird. Seine Konfiguration wird jedoch oft als mühsame Aufgabe betrachtet. Glücklicherweise erleichtert VyOS diese Arbeit durch seine CLI, während es tc als Backend verwendet.

Wie funktioniert es

Um sicherzustellen, dass VyOS-Verkehrssteuerung funktioniert, müssen Sie zwei Schritte befolgen:

  1. Eine Verkehrsrichtlinie erstellen.

  2. Die Verkehrsrichtlinie auf eine Schnittstelle eingangs oder ausgehend anwenden.

Bevor Sie lernen, Ihre Richtlinie zu konfigurieren, warnen wir Sie über die verschiedenen Einheiten, die Sie verwenden können, und zeigen Ihnen auch, was Klassen sind und wie sie funktionieren, da einige Richtlinien möglicherweise erforderlich sind, um sie zu konfigurieren.

Einheiten

Bei der Konfiguration Ihrer Verkehrsrichtlinie müssen Sie Datenratenwerte festlegen, achten Sie auf die Einheiten, mit denen Sie arbeiten, es ist leicht, sich mit den verschiedenen Präfixen und Suffixen zu verwirren, die Sie verwenden können. VyOS zeigt Ihnen immer die verschiedenen Einheiten an, die Sie verwenden können.

Präfixe

Sie können dezimale Präfixe verwenden.

kbit  (10^3)    Kilobit pro Sekunde
mbit  (10^6)    Megabit pro Sekunde
gbit  (10^9)    Gigabit pro Sekunde
tbit  (10^12)   Terabit pro Sekunde

kbps  (8*10^3)  Kilobyte pro Sekunde
mbps  (8*10^6)  Megabyte pro Sekunde
gbps  (8*10^9)  Gigabyte pro Sekunde
tbps  (8*10^12) Terabyte pro Sekunde

Oder binäre Präfixe.

kibit (2^10 = 1024)    Kibibit pro Sekunde
mibit (2^20 = 1024^2)  Mebibit pro Sekunde
gibit (2^30 = 1024^3)  Gibibit pro Sekunde
tbit  (2^40 = 1024^4)  Tebibit pro Sekunde

kibps (1024*8)         Kibibyte (KiB) pro Sekunde
mibps (1024^2*8)       Mebibyte (MiB) pro Sekunde
gibps (1024^3*8)       Gibibyte (GiB) pro Sekunde
tibps (1024^4*8)       Tebibyte (TiB) pro Sekunde

Suffixe

Ein Bit wird als bit geschrieben,

kbit (Kilobit pro Sekunde)
mbit (Megabit pro Sekunde)
gbit (Gigabit pro Sekunde)
tbit (Terabit pro Sekunde)

während ein Byte als einzelner b geschrieben wird.

kbps (Kilobytes pro Sekunde)
mbps (Megabytes pro Sekunde)
gbps (Gigabytes pro Sekunde)

Klassen

In dem Abschnitt zur Erstellung einer Verkehrsrichtlinie sehen Sie, dass einige der Richtlinien Klassen verwenden. Diese Richtlinien ermöglichen es Ihnen, den Verkehr gemäß verschiedenen Parametern zu verteilen, die Sie wählen können. Eine Klasse ist also einfach eine spezifische Art von Verkehr, den Sie auswählen.

Das endgültige Ziel der Verkehrsclassifizierung ist es, jeder Klasse eine unterschiedliche Behandlung zu geben.

Verkehr abgleichen

Um zu definieren, welcher Verkehr in welche Klasse geht, definieren Sie Filter (das heißt, die Übereinstimmungskriterien). Pakete durchlaufen diese Übereinstimmungsregeln (wie die Regeln eines Feuerwalls) und, wenn ein Paket mit dem Filter übereinstimmt, wird es dieser Klasse zugewiesen.

In VyOS wird eine Klasse durch eine Nummer identifiziert, die Sie bei der Konfiguration wählen können.

Hinweis

Die Bedeutung der Klasse-ID ist nicht für jede Art von Richtlinie gleich. Normalerweise benötigen Richtlinien nur eine sinnlose Zahl, um eine Klasse (Klasse-ID) zu identifizieren, aber dies gilt nicht für jede Richtlinie. Die Nummer einer Klasse in einer Prioritätswarteschlange identifiziert sie nicht nur, sondern definiert auch ihre Priorität.

set qos policy <policy> <policy-name> class <class-ID> match <class-matching-rule-name>

Im obigen Befehl legen wir den Typ der Richtlinie fest, mit der wir arbeiten, und den Namen, den wir dafür wählen; eine Klasse (damit wir bestimmten Verkehr unterscheiden können) und eine identifizierbare Nummer für diese Klasse; dann konfigurieren wir eine Übereinstimmungsregel (oder Filter) und einen Namen dafür.

Eine Klasse kann mehrere Übereinstimmungsfilter haben:

set qos policy shaper MY-SHAPER class 30 match HTTP
set qos policy shaper MY-SHAPER class 30 match HTTPs

Eine Übereinstimmungsregel kann mehrere Kriterien enthalten und passt zum Verkehr, wenn alle diese Kriterien wahr sind.

Zum Beispiel:

set qos policy shaper MY-SHAPER class 30 match HTTP ip protocol tcp
set qos policy shaper MY-SHAPER class 30 match HTTP ip source port 80

Dies passt TCP-Verkehr mit Quellport 80.

Es gibt viele Parameter, mit denen Sie den Verkehr abgleichen können, den Sie für eine Klasse auswählen:

  • Ethernet (Protokoll, Zieladresse oder Quelladresse)

  • Schnittstellenname

  • IPv4 (DSCP-Wert, maximale Paketlänge, Protokoll, Quelladresse, Zieladresse, Quellport, Zielport oder TCP-Flags)

  • IPv6 (DSCP-Wert, maximale Nutzlastlänge, Protokoll, Quelladresse, Zieladresse, Quellport, Zielport oder TCP-Flags)

  • Firewall-Markierung

  • VLAN-ID

Beim Konfigurieren Ihres Filters können Sie die Tab-Taste verwenden, um die vielen verschiedenen Parameter anzuzeigen, die Sie konfigurieren können.

vyos@vyos# set qos policy shaper MY-SHAPER class 30 match MY-FIRST-FILTER 
Possible completions:
   description  Description
 > ether        Ethernet header match
   interface    Interface to use
 > ip           Match IP protocol header
 > ipv6         Match IPV6 protocol header
   mark         Match on mark applied by firewall
   vif          Virtual Local Area Network (VLAN) ID for this match

Wie in dem Beispiel oben gezeigt, ist eines der Möglichkeiten, Pakete zu matchen, basierend auf Markierungen, die vom Firewall durchgeführt werden, was Ihnen eine große Flexibilität geben kann.

Sie können auch eine Beschreibung für einen Filter schreiben:

set qos policy shaper MY-SHAPER class 30 match MY-FIRST-FILTER description "My filter description"

Hinweis

Eine IPv4 TCP-Filter wird nur Pakete mit einer IPv4-Header-Länge von 20 Bytes matchen (was die meisten IPv4-Pakete ist).

Hinweis

IPv6 TCP-Filter passen nur IPv6-Pakete ohne Header-Erweiterung an, siehe https://en.wikipedia.org/wiki/IPv6_packet#Extension_headers

Verkehrsabgleichsgruppe

In einigen Fällen, in denen wir eine Organisation unserer Abgleichsauswahl benötigen, um flexibler zu sein und unsere Filterdefinition zu organisieren, können wir Verkehrsabgleichsgruppen anwenden, um uns zu ermöglichen, verschiedene Filtergruppen innerhalb unserer Richtlinie zu erstellen und für jede Gruppe verschiedene Parameter zu definieren:

set qos traffic-match-group <group_name> match <match_name>
Possible completions:
   description          Description
 > ip                   Match IP protocol header
 > ipv6                 Match IPv6 protocol header
   mark                 Match on mark applied by firewall
   vif                  Virtual Local Area Network (VLAN) ID for this match

Erben Sie Matches aus einer anderen Gruppe

set qos traffic-match-group <group_name> match-group <match_group_name>

Eine Match-Gruppe kann mehrere Kriterien enthalten und diese in derselben Richtlinie erben.

Zum Beispiel:

set qos traffic-match-group Mission-Critical match AF31 ip dscp 'AF31'
set qos traffic-match-group Mission-Critical match AF32 ip dscp 'AF42'
set qos traffic-match-group Mission-Critical match CS3 ip dscp 'CS3'
set qos traffic-match-group Streaming-Video match AF11 ip dscp 'AF11'
set qos traffic-match-group Streaming-Video match AF41 ip dscp 'AF41'
set qos traffic-match-group Streaming-Video match AF43 ip dscp 'AF43'
set qos policy shaper VyOS-HTB class 10 bandwidth '30%'
set qos policy shaper VyOS-HTB class 10 description 'Multimedia'
set qos policy shaper VyOS-HTB class 10 match CS4 ip dscp 'CS4'
set qos policy shaper VyOS-HTB class 10 match-group 'Streaming-Video'
set qos policy shaper VyOS-HTB class 10 priority '1'
set qos policy shaper VyOS-HTB class 10 queue-type 'fair-queue'
set qos policy shaper VyOS-HTB class 20 description 'MC'
set qos policy shaper VyOS-HTB class 20 match-group 'Mission-Critical'
set qos policy shaper VyOS-HTB class 20 priority '2'
set qos policy shaper VyOS-HTB class 20 queue-type 'fair-queue'
set qos policy shaper VyOS-HTB default bandwidth '20%'
set qos policy shaper VyOS-HTB default queue-type 'fq-codel'

In diesem Beispiel können wir beobachten, dass verschiedene DSCP-Kriterien basierend auf unserer QoS-Konfiguration innerhalb der gleichen Richtliniengruppe definiert werden.

Standard

Oft müssen Sie auch Ihren Standard-Verkehr auf die gleiche Weise konfigurieren wie eine Klasse. Standard kann als Klasse betrachtet werden, da es sich so verhält. Es enthält jeden Verkehr, der keine der definierten Klassen getroffen hat, also ist es wie eine offene Klasse, eine Klasse ohne Übereinstimmungsfilter.

Klassenbehandlung

Wenn eine Klasse eine Filterkonfiguration hat, müssen Sie auch definieren, was Sie mit dem Verkehr dieser Klasse tun möchten, welche spezifische Verkehrssteuerung behandlung Sie ihr geben möchten. Sie haben unterschiedliche Möglichkeiten, je nachdem, welche Verkehrsrichtlinie Sie konfigurieren.

Eine Richtlinie in eine andere einbetten

Oft müssen wir eine Richtlinie in eine andere einbetten. Es ist möglich, dies auf klassenbasierten Richtlinien durch Anhängen einer neuen Richtlinie an eine Klasse zu tun. Zum Beispiel möchten Sie möglicherweise verschiedene Richtlinien auf die verschiedenen Klassen einer Round-Robin-Richtlinie anwenden, die Sie konfiguriert haben.

Ein häufiges Beispiel ist der Fall, bei dem einige Richtlinien, um effektiv zu sein, auf eine Schnittstelle angewandt werden müssen, die direkt mit dem Engpass verbunden ist. Wenn Ihr Router nicht direkt mit dem Engpass verbunden ist, sondern ein Hop vorher, können Sie den Engpass simulieren, indem Sie Ihre nicht-formende Richtlinie in eine klassenbasierte formende Richtlinie einbetten, damit sie wirkt.

Sie können eine Richtlinie in eine Klasse durch die queue-type-Einstellung konfigurieren.

set qos policy shaper FQ-SHAPER bandwidth 4gbit
set qos policy shaper FQ-SHAPER default bandwidth 100%
set qos policy shaper FQ-SHAPER default queue-type fq-codel

Wie in dem letzten Befehl des Beispiels oben gezeigt, ermöglicht die queue-type-Einstellung diese Kombinationen. Sie können sie in vielen Richtlinien verwenden.

Hinweis

Einige Richtlinien enthalten bereits andere eingebettete Richtlinien. Das ist der Fall bei Shaper: Jede seiner Klassen verwendet fair-queue, es sei denn, Sie ändern es.

Erstellung einer Verkehrsrichtlinie

VyOS ermöglicht es Ihnen, den Verkehr auf viele verschiedene Weisen zu steuern, hier werden wir jede Möglichkeit behandeln. Sie können so viele Richtlinien wie Sie wollen konfigurieren, aber Sie können nur eine Richtlinie pro Schnittstelle und Richtung (eingehend oder ausgehend) anwenden.

Einige Richtlinien können kombiniert werden, Sie können eine andere Richtlinie konfigurieren, die auf eine Klasse der Hauptrichtlinie angewandt wird.

Hinweis

Wenn Sie nach einer Richtlinie für Ihren ausgehenden Verkehr suchen aber Sie wissen nicht, welche Sie benötigen und Sie möchten nicht durch jede mögliche Richtlinie gehen, die hier gezeigt wird, unsere Wette ist, dass Sie wahrscheinlich eine Shaper Richtlinie suchen und Sie möchten Ihre Warteschlangen auf FQ-CoDel einstellen haben.

Drop Tail

Warteschlange: PFIFO (Packet First In First Out).
Gilt für: Ausgehender Verkehr.

Dies ist die einfachste Warteschlange, die Sie auf Ihren Verkehr anwenden können. Der Verkehr muss eine endliche Warteschlange durchlaufen, bevor er tatsächlich gesendet wird. Sie müssen definieren, wie viele Pakete diese Warteschlange enthalten kann.

Wenn ein Paket gesendet werden soll, muss es durch diese Warteschlange gehen, also wird das Paket am Ende platziert. Wenn das Paket vollständig durch sie gegangen ist, wird es aus der Warteschlange entfernt und schließlich an die NIC weitergegeben, um gesendet zu werden.

Obwohl die Drop-Tail-Richtlinie keine Pakete verlangsamt, können viele Pakete abgewiesen werden, wenn sie versuchen, am Ende der Warteschlange eingeordnet zu werden. Dies kann geschehen, wenn die Warteschlange noch nicht in der Lage war, genug Pakete aus ihrem Kopf zu entfernen.

Dies ist die Richtlinie, die die geringsten Ressourcen für denselben Verkehr benötigt. Aber sehr wahrscheinlich benötigen Sie es nicht, da Sie nicht viel daraus gewinnen können. Manchmal wird es nur zum Aktivieren von Logging verwendet.

set qos policy drop-tail <policy-name> queue-limit <number-of-packets>

Verwenden Sie diesen Befehl, um eine Drop-Tail-Richtlinie (PFIFO) zu konfigurieren. Wählen Sie einen eindeutigen Namen für diese Richtlinie und die Größe der Warteschlange, indem Sie die Anzahl der Pakete festlegen, die sie enthalten kann (maximal 4294967295).

Fair Queue

Warteschlange: SFQ (Stochastic Fairness Queuing).
Gilt für: Ausgehender Verkehr.

Fair Queue ist ein work-conserving Scheduler, der die Übertragung von Paketen basierend auf Flows plant, das heißt, es balanciert den Verkehr, indem es ihn durch verschiedene Unterklassen verteilt, um Fairness sicherzustellen, sodass jeder Flow in der Lage ist, Daten abwechselnd zu senden, wodurch kein einzelner Flow den Rest übertönt.

set qos policy fair-queue <policy-name>

Verwenden Sie diesen Befehl, um eine Fair-Queue-Richtlinie zu erstellen und ihr einen Namen zu geben. Sie basiert auf dem Stochastic Fairness Queueing und kann auf ausgehenden Verkehr angewandt werden.

Um den Verkehr zu trennen, verwendet Fair Queue einen Klassifizierer basierend auf Quelladresse, Zieladresse und Quellport. Der Algorithmus fügt Pakete basierend auf diesen drei Parametern in Hash-Buckets ein. Jeder dieser Buckets sollte einen eindeutigen Fluss darstellen. Da mehrere Flüsse in denselben Bucket hashen können, wird das Hashingalgorithmus zu konfigurierbaren Intervallen gestört, sodass die Unfairness nur kurz besteht. Die Störung kann jedoch zu unabsichtlicher Paketumordnung führen. Ein empfehlender Wert könnte 10 Sekunden sein.

Eine der Verwendungen von Fair Queue könnte die Minderung von Denial-of-Service-Angriffen sein.

set qos policy fair-queue <policy-name> hash-interval <seconds>

Verwenden Sie diesen Befehl, um eine Fair-Queue-Richtlinie zu definieren, die auf dem Stochastic Fairness Queueing basiert, und setzen Sie die Anzahl der Sekunden, in denen ein neuer Warteschlange-Algorithmus-Störung stattfindet (maximal 4294967295).

Beim Entnehmen wird jede Hash-Bucket mit Daten in einem Round-Robin-Verfahren abgefragt. Sie können die Länge der Warteschlange konfigurieren.

set qos policy fair-queue <policy-name> queue-limit <limit>

Verwenden Sie diesen Befehl, um eine Fair-Queue-Richtlinie zu definieren, die auf dem Stochastic Fairness Queueing basiert, und setzen Sie die maximale Anzahl der Pakete, die in der Warteschlange warten dürfen. Alle anderen Pakete werden abgewiesen.

Hinweis

Fair Queue ist eine nicht-formende (work-conserving) Richtlinie, daher ist sie nur dann nützlich, wenn Ihr ausgehender Schnittstellenanschluss wirklich voll ist. Wenn nicht, wird VyOS die Warteschlange nicht besitzen und Fair Queue wird keine Auswirkung haben. Wenn es Bandbreite auf dem physischen Link gibt, können Sie Fair-Queue in eine klassenbasierte formende Richtlinie einbetten, um sicherzustellen, dass sie die Warteschlange besitzt.

FQ-CoDel

Warteschlange: Fair/Flow Queue CoDel.
Gilt für: Ausgehender Verkehr.

Die FQ-CoDel-Richtlinie verteilt den Verkehr auf 1024 FIFO-Warteschlangen und versucht, gute Dienste für alle zu bieten. Sie versucht auch, die Länge aller Warteschlangen kurz zu halten.

FQ-CoDel kämpft gegen Bufferbloat und reduziert die Latenz ohne das Bedürfnis komplexer Konfigurationen. Es ist zur neuen Standard-Warteschlange für die Schnittstellen einiger GNU/Linux-Distributionen geworden.

Es verwendet ein stochastisches Modell, um ankommende Pakete in verschiedene Flüsse einzuteilen und bietet allen Flüssen, die die Warteschlange nutzen, eine faire Bandbreitenverteilung. Jeder Fluss wird von der CoDel-Warteschlange verwaltet. Paketumordnung innerhalb eines Flusses wird vermieden, da Codel intern eine FIFO-Warteschlange verwendet.

FQ-CoDel basiert auf einem modifizierten Deficit Round Robin (DRR)-Warteschlange-Scheduler mit dem CoDel Active Queue Management (AQM)-Algorithmus, der auf jeder Warteschlange operiert.

Hinweis

FQ-Codel ist eine nicht-formende (work-conserving) Richtlinie, daher ist sie nur dann nützlich, wenn Ihr ausgehender Schnittstellenanschluss wirklich voll ist. Wenn nicht, wird VyOS die Warteschlange nicht besitzen und FQ-Codel wird keine Auswirkung haben. Wenn es Bandbreite auf dem physischen Link gibt, können Sie FQ-Codel in eine klassenbasierte formende Richtlinie einbetten, um sicherzustellen, dass es die Warteschlange besitzt. Wenn Sie sich nicht sicher sind, ob Sie Ihre FQ-CoDel-Richtlinie in einen Shaper einbetten müssen, tun Sie es.

FQ-CoDel ist für 10Gbit-Geschwindigkeiten mit seinen Standardparametern gut geeignet. Es könnte auch bei anderen Geschwindigkeiten ohne Konfiguration gut funktionieren, aber hier erklären wir einige Fälle, in denen Sie seine Parameter anpassen könnten.

Wenn Sie es bei 1Gbit und niedrigerer Geschwindigkeit laufen lassen, möchten Sie möglicherweise die queue-limit auf 1000 Pakete oder weniger reduzieren. Bei Geschwindigkeiten wie 10Mbit möchten Sie sie auf 600 Pakete setzen.

Wenn Sie FQ-CoDel in Shaper einbetten und große Geschwindigkeiten (100Mbit und höher) haben, können Sie den quantum auf 8000 oder höher erhöhen, damit der Scheduler CPU spart.

Auf niedrigen Geschwindigkeiten (unter 40Mbit) möchten Sie den quantum auf etwas wie 300 Bytes heruntersetzen.

Bei sehr niedrigen Geschwindigkeiten (unter 3Mbit) möchten Sie neben der Anpassung von quantum (300 bleibt gut) auch den target auf etwas wie 15ms erhöhen und den interval auf etwa 150 ms erhöhen.

set qos policy fq-codel <policy name> codel-quantum <bytes>

Verwenden Sie diesen Befehl, um eine fq-codel-Richtlinie zu konfigurieren, ihren Namen festzulegen und die maximale Anzahl von Bytes (Standard: 1514) festzulegen, die aus einer Warteschlange gleichzeitig dekodiert werden.

set qos policy fq-codel <policy name> flows <number-of-flows>

Verwenden Sie diesen Befehl, um eine fq-codel-Richtlinie zu konfigurieren, ihren Namen festzulegen und die Anzahl der Unterklassen (Standard: 1024), in die Pakete eingeteilt werden.

set qos policy fq-codel <policy name> interval <milliseconds>

Verwenden Sie diesen Befehl, um eine fq-codel-Richtlinie zu konfigurieren, ihren Namen festzulegen und den Zeitraum zu setzen, der vom CoDel-Control-Loop verwendet wird, um zu erkennen, wann ein persistenter Warteschlange entwickelt wird, und sicherzustellen, dass die gemessene minimale Verzögerung nicht zu alt wird (Standard: 100ms).

set qos policy fq-codel <policy-name> queue-limit <number-of-packets>

Verwenden Sie diesen Befehl, um eine fq-codel-Richtlinie zu konfigurieren, ihren Namen festzulegen und eine feste Grenze für die tatsächliche Warteschlange festzulegen. Wenn diese Grenze erreicht wird, werden neue Pakete abgewiesen (Standard: 10240 Pakete).

set qos policy fq-codel <policy-name> target <milliseconds>

Verwenden Sie diesen Befehl, um eine fq-codel-Richtlinie zu konfigurieren, ihren Namen festzulegen und die akzeptable minimale stehende/persistente Warteschlange festzulegen. Diese minimale Verzögerung wird identifiziert, indem der lokale minimale Warteschlange-Verzögerung verfolgt wird, die Pakete erfahren (Standard: 5ms).

Beispiel

Ein einfaches Beispiel für eine FQ-CoDel-Richtlinie, die innerhalb einer Shaper-Richtlinie funktioniert.

set qos policy shaper FQ-CODEL-SHAPER bandwidth 2gbit
set qos policy shaper FQ-CODEL-SHAPER default bandwidth 100%
set qos policy shaper FQ-CODEL-SHAPER default queue-type fq-codel

Limiter

Warteschlange: Eingangspolicer.
Gilt für: Eingehender Verkehr.

Limiter ist eine dieser Richtlinien, die Klassen verwendet (Eingangswarteschlange ist eigentlich eine klassenlose Richtlinie, aber Filter funktionieren darin).

Der Limiter führt eine grundlegende Eingangspolizei für Verkehrsflüsse durch. Mehrere Klassen von Verkehr können definiert werden und Verkehrsbeschränkungen können auf jede Klasse angewandt werden. Obwohl der Policer ein Token-Bucket-Mechanismus intern verwendet, hat er nicht die Fähigkeit, ein Paket zu verzögern, wie ein Formungsmechanismus es tut. Verkehr, der die definierten Bandbreitenbegrenzungen überschreitet, wird direkt abgewiesen. Auch eine maximale zulässige Burst kann konfiguriert werden.

Sie können Klassen (bis zu 4090) mit verschiedenen Einstellungen und eine Standardrichtlinie konfigurieren, die auf jeden Verkehr angewandt wird, der keine der konfigurierten Klassen trifft.

Hinweis

Wenn Sie eine Formung für Ihren eingehenden Verkehr anwenden möchten, prüfen Sie den Abschnitt zu Eingangsschaltung.

set qos policy limiter <policy-name> class <class ID> match <match-name> description <description>

Verwenden Sie diesen Befehl, um einen Eingangspolicer zu konfigurieren, dessen Namen, eine Klassen-ID (1-4090), einen Namen der Klassenübereinstimmungsregel und deren Beschreibung festzulegen.

Wenn die Übereinstimmungsregeln für eine Klasse festgelegt sind, können Sie beginnen, wie Sie das übereinstimmende Verkehr verhalten möchten.

set qos policy limiter <policy-name> class <class-ID> bandwidth <rate>

Verwenden Sie diesen Befehl, um einen Eingangspolicer zu konfigurieren, dessen Namen, eine Klassen-ID (1-4090) und die maximale erlaubte Bandbreite für diese Klasse festzulegen.

set qos policy limiter <policy-name> class <class-ID> burst <burst-size>
