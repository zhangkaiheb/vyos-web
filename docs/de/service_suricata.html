Suricata

Suricata ist ein Open-Source-Netzwerkbedrohungs-Erkennungsmotor, der Intrusion Detection (IDS), Inline-Intrusion Prävention (IPS) und Netzwerksicherheits-Monitoring (NSM) durch Vergleich des Live-Verkehrs mit einer Reihe von Regeln, auch als Signaturen bezeichnet. Jedes Ereignis wird im EVE-Ereignisprotokoll im JSON-Format protokolliert.

VyOS integriert Suricata als verwaltete Dienstleistung, die unter service suricata konfigurierbar ist. Wenn die Konfiguration committet wird, generiert VyOS die Suricata-Konfiguration aus diesen Einstellungen und startet den Dienst.

Unter service suricata können Sie folgendes konfigurieren:

  • Überwachte Schnittstellen: Eine oder mehrere Schnittstellen, auf denen Suricata den Verkehr erfasst.

  • Adressgruppen: Benannte Listen von IPv4/IPv6-Adressen oder Präfixen, die anstelle von Literal-IP-Adressen in Suricata-Regeln verwendet werden.

  • Portgruppen: Benannte Listen von Ports oder Portbereichen, die anstelle von Literal-Ports in Suricata-Regeln verwendet werden.

  • EVE-Protokoll: Ziel (regulärer Datei oder Syslog), Dateiname oder Pfad sowie die Ereignistypen, die protokolliert werden.

Regeln werden separat durch Ausführen von update suricata im Betriebsmodus abgerufen. Bis dieser Befehl ausgeführt wird, hat der Dienst keine Regeln, um sie zu matchen.

Hinweis

Eine Suricata-Konfiguration kann nur committet werden, wenn mindestens eine Schnittstelle, eine Adressgruppe und eine Portgruppe definiert sind. Andernfalls schlägt das Commit fehl.

Konfiguration

Überwachte Schnittstellen

Verwenden Sie den folgenden Befehl, um die Schnittstellen zu konfigurieren, die Suricata überwacht.

set service suricata interface <interface>

Konfigurieren Sie eine Schnittstelle, auf der Suricata den Verkehr erfasst und analysiert.

Wiederholen Sie den Befehl, um mehrere Schnittstellen zu überwachen. Mindestens eine Schnittstelle muss konfiguriert sein, um einen erfolgreichen Commit zu ermöglichen.

Beispiel:

set service suricata interface eth1

Adressgruppen

Verwenden Sie die folgenden Befehle, um Adressgruppen zu konfigurieren.

Hinweis

Gruppennamen müssen Kleinbuchstaben, Ziffern oder Bindestriche sein.

Hinweis

Suricata-Regeln verweisen auf eine konventionelle Menge von Gruppennamen, wie home-net, external-net, http-servers und andere. Die Definition einer Gruppe mit einem nicht-standardmäßigen Namen ist erlaubt, aber keine gelieferten Regeln werden darauf verweisen. Typische Adressgruppen beinhalten:

  • home-net: die Netzwerke, die Suricata als intern behandeln soll (z. B. 192.0.2.0/24 und 2001:db8::/32).

  • external-net: alles, was nicht in home-net ist.

  • http-servers, sql-servers, dns-servers: Hosts, die die entsprechenden Dienste laufen lassen.

set service suricata address-group <name> address <address>

Konfigurieren Sie eine IPv4- oder IPv6-Adresse oder ein Präfix als Mitglied der angegebenen Adressgruppe.

<address> akzeptiert eine IPv4- oder IPv6-Adresse, ein IPv4- oder IPv6-Präfix, oder eines davon mit dem Präfix !, um es aus den Matches auszuschließen.

Wiederholen Sie den Befehl, um weitere Adressen oder Präfixe zur gleichen Gruppe hinzuzufügen.

Beispiel:

set service suricata address-group home-net address 192.0.2.0/24
set service suricata address-group home-net address 2001:db8::/32
set service suricata address-group home-net address !192.0.2.5
set service suricata address-group <name> group <name>

Konfigurieren Sie eine andere Adressgruppe als Mitglied der angegebenen Adressgruppe.

Präfixieren Sie den referenzierten Namen mit !, um die Mitglieder dieser Gruppe aus den Matches auszuschließen. Die referenzierte Gruppe muss zum Zeitpunkt des Commits definiert sein, und zyklische Referenzen zwischen Gruppen werden abgelehnt.

Wiederholen Sie den Befehl, um weitere Gruppen zur gleichen Elterngruppe hinzuzufügen.

Beispiel:

set service suricata address-group home-net address 192.0.2.0/24
set service suricata address-group external-net group !home-net

Portgruppen

Verwenden Sie die folgenden Befehle, um Portgruppen zu konfigurieren.

Hinweis

Gruppennamen müssen Kleinbuchstaben, Ziffern oder Bindestriche sein.

Hinweis

Suricata-Regeln verweisen auf eine konventionelle Menge von Portgruppennamen, wie http-ports, ssh-ports, oracle-ports, shellcode-ports und andere. Die Definition einer Portgruppe mit einem nicht-standardmäßigen Namen ist erlaubt, aber keine gelieferten Regeln werden darauf verweisen. Typische Portgruppen beinhalten:

  • http-ports: Ports, auf denen HTTP-Dienste laufen.

  • ssh-ports: Ports, auf denen SSH-Dienste lauschen.

  • oracle-ports: Ports, die von Oracle-Datenbankdiensten verwendet werden.

  • shellcode-ports: Ports, die von Shellcode-Erkennungsregeln überprüft werden.

set service suricata port-group <name> port <port>

Konfigurieren Sie einen Port oder einen Portbereich als Mitglied der angegebenen Portgruppe.

<port> akzeptiert einen einzelnen Port (1–65535), einen numerischen Bereich in start-end-Form (z. B. 1001-1005), oder entweder Form mit dem Präfix !, um ihn aus den Matches auszuschließen.

Wiederholen Sie den Befehl, um weitere Ports oder Portbereiche zur gleichen Gruppe hinzuzufügen.

Beispiel:

set service suricata port-group http-ports port 80
set service suricata port-group http-ports port 443
set service suricata port-group http-ports port 8000-8999
set service suricata port-group http-ports port !8080
set service suricata port-group <name> group <name>

Konfigurieren Sie eine andere Portgruppe als Mitglied der angegebenen Portgruppe.

Präfixieren Sie den referenzierten Namen mit !, um die Mitglieder dieser Gruppe aus den Matches auszuschließen. Die referenzierte Gruppe muss zum Zeitpunkt des Commits definiert sein, und zyklische Referenzen zwischen Gruppen werden abgelehnt.

Wiederholen Sie den Befehl, um mehrere Gruppen zur gleichen Elterngruppe hinzuzufügen.

Beispiel:

set service suricata port-group http-ports port 80
set service suricata port-group shellcode-ports group !http-ports

EVE-Protokoll

Verwenden Sie die folgenden Befehle, um das EVE-Protokoll zu konfigurieren.

set service suricata log eve filename <filename>

Konfigurieren Sie den Dateinamen oder Pfad für das Suricata EVE-Protokoll.

Eine bloße Datei (z. B. eve.json) platziert das Protokoll im Standard-Protokolldir von Suricata, /var/log/suricata/. Ein absoluter Pfad wird unverändert verwendet.

Der Standardwert ist eve.json.

Beispiel:

set service suricata log eve filename eve.json
set service suricata log eve filename /var/log/custom/suricata-eve.json
set service suricata log eve filetype <regular | syslog>

Konfigurieren Sie das Ziel für das Suricata EVE-Protokoll:

  • regular: Schreibt das EVE-Protokoll in die Datei, die durch set service suricata log eve filename angegeben wird.

  • syslog: Sendet das EVE-Protokoll an syslog.

Der Standardwert ist regular.

Beispiel:

set service suricata log eve filetype syslog
set service suricata log eve type <type>

Konfigurieren Sie, welche EVE-Ereignistypen protokolliert werden.

Akzeptierte Werte:

  • Allgemeine Ereignistypen: alert, anomaly, drop, files, flow, netflow.

  • Ereignistypen pro Protokoll: http, http2, dns, tls, smtp, ftp, smb, ssh, dhcp, tftp, nfs, rdp, sip, snmp, ikev2, krb5, dcerpc, dnp3, rfb, mqtt.

Wiederholen Sie den Befehl, um mehrere Ereignistypen zu protokollieren.

Beispiel:

set service suricata log eve type alert
set service suricata log eve type flow
set service suricata log eve type http

Betrieb

update suricata

Rufen Sie die aktuelle Regelmenge mit suricata-update ab und starten Sie den Suricata-Dienst neu, um sie zu laden.

Wenn service suricata nicht konfiguriert ist, gibt der Befehl eine Fehlermeldung aus und beendet sich.

Beispiel:

update suricata
restart suricata

Neustarten des Suricata-Diensts.

Wenn der Dienst nicht konfiguriert ist (keine service suricata-Konfiguration vorhanden), oder ein Konfigurationscommit läuft, druckt der Befehl eine Fehlermeldung aus und beendet sich.

Beispiel:

restart suricata
