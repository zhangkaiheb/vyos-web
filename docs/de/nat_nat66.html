NPTv6 ist eine Adressübersetzungstechnologie, die auf IPv6-Netzwerken basiert und verwendet, um ein IPv6-Adresspräfix in einer IPv6-Nachricht in ein anderes IPv6-Adresspräfix zu konvertieren. Wir nennen diese Adressübersetzungsmethode NAT66. Geräte, die die NAT66-Funktion unterstützen, werden als NAT66-Geräte bezeichnet, die NAT66-Quell- und Zieladressübersetzungsfunktionen bereitstellen können.

Übersicht

Verschiedene NAT-Typen

SNAT66

SNPTv6 Die Konvertierungsfunktion wird hauptsächlich in folgenden Szenarien verwendet:

  • Eines internen Netzwerks und eines externen Netzwerks. Verwenden Sie das NAT66-Gerät, um ein einzelnes internes Netzwerk und ein öffentliches Netzwerk zu verbinden, wobei die Hosts im internen Netzwerk IPv6-Adresspräfixe verwenden, die nur innerhalb des lokalen Bereichs routbar sind. Wenn ein Host im internen Netzwerk auf das externe Netzwerk zugreift, wird das Quell-IPv6-Adresspräfix in der Nachricht durch das NAT66-Gerät in ein globales Unicast-IPv6-Adresspräfix konvertiert.

  • Redundanz und Lastverteilung. Es gibt mehrere NAT66-Geräte am Rand eines IPv6-Netzwerks zu einem anderen IPv6-Netzwerk. Der Weg durch das NAT66-Gerät zu einem anderen IPv6-Netzwerk bildet einen äquivalenten Pfad, und der Datenverkehr kann auf diesen NAT66-Geräten lastverteilten. In diesem Fall können Sie dieselben Quelladressübersetzungsvorschriften auf diesen NAT66-Geräten konfigurieren, sodass jedes NAT66-Gerät den IPv6-Datenverkehr zwischen verschiedenen Standorten verarbeiten kann.

  • Mehrfachanschluss. In einer mehrfachen Anschlussnetzwerkumgebung verbindet das NAT66-Gerät ein internes Netzwerk und gleichzeitig verschiedene externe Netzwerke. Auf der Schnittstelle des externen Netzwerks des NAT66-Geräts können Adressübersetzungen konfiguriert werden, um dasselbe interne Netzwerkadresse in verschiedene externe Netzwerkadressen zu konvertieren und die Zuordnung derselben internen Adresse zu mehreren externen Adressen zu realisieren.

DNAT66

Die DNPTv6 Zieladressübersetzungsfunktion wird in Szenarien verwendet, in denen der Server im internen Netzwerk Dienste für das externe Netzwerk anbietet, z. B. Web-Dienste oder FTP-Dienste für das externe Netzwerk. Durch die Konfiguration der Zuordnungsbeziehung zwischen der internen Serveradresse und der externen Netzwerkadresse auf der externen Netzwerkkarte des NAT66-Geräts können externe Netzwerkbenutzer über die festgelegte externe Netzwerkadresse auf den internen Netzwerkserver zugreifen.

Präfixkonvertierung

Quellpräfix

Jede SNAT66-Regel hat einen Übersetzungsbefehl definiert. Das für die Übersetzung definierte Präfix ist das Präfix, das verwendet wird, wenn die Adressinformationen in einem Paket ersetzt werden.

Die SNAT66-Regel ersetzt die Quelladresse des Pakets und berechnet die konvertierte Adresse unter Verwendung des im Regelsatz angegebenen Präfixes.

Beispiel:

  • Konvertieren des Adresspräfixes eines einzelnen fc01::/64-Netzwerks in fc00::/64

  • Ausgabe aus dem Netzwerkinterface eth0

set nat66 source rule 1 outbound-interface name 'eth0'
set nat66 source rule 1 source prefix 'fc01::/64'
set nat66 source rule 1 translation address 'fc00::/64'

Zielpräfix

Für die DNAT66-Regel wird die Zieladresse des Pakets durch die von der im translation address-Befehl angegebenen Adresse oder Präfix berechnete Adresse ersetzt.

Beispiel:

  • Konvertieren des Adresspräfixes eines einzelnen fc00::/64-Netzwerks in fc01::/64

  • Eingang über das Netzwerkinterface eth0

set nat66 destination rule 1 inbound-interface name 'eth0'
set nat66 destination rule 1 destination address 'fc00::/64'
set nat66 destination rule 1 translation address 'fc01::/64'

Für das Ziel können auch Gruppen anstelle einer Adresse verwendet werden.

Beispiel:

set firewall group ipv6-address-group ADR-INSIDE-v6 address fc00::1

set nat66 destination rule 1 inbound-interface name 'eth0'
set nat66 destination rule 1 destination group address-group ADR-INSIDE-v6
set nat66 destination rule 1 translation address 'fc01::/64'

Konfigurationsbeispiele

Verwenden Sie die folgende Topologie, um ein mit NAT66 basiertes isoliertes Netzwerk zwischen internem und externem Netzwerk zu erstellen (dynamisches Präfix wird nicht unterstützt):

R1:

set interfaces ethernet eth0 ipv6 address autoconf
set interfaces ethernet eth1 address 'fc01::1/64'
set nat66 destination rule 1 destination address 'fc00:470:f1cd:101::/64'
set nat66 destination rule 1 inbound-interface name 'eth0'
set nat66 destination rule 1 translation address 'fc01::/64'
set nat66 source rule 1 outbound-interface name 'eth0'
set nat66 source rule 1 source prefix 'fc01::/64'
set nat66 source rule 1 translation address 'fc00:470:f1cd:101::/64'

R2:

set interfaces bridge br1 address 'fc01::2/64'
set interfaces bridge br1 member interface eth0
set interfaces bridge br1 member interface eth1
set protocols static route6 ::/0 next-hop fc01::1
set service router-advert interface br1 prefix ::/0

Verwenden Sie die folgende Topologie, um lokale Adressen von internen Benutzern (fc::/7) in vom ISP bereitgestellte Präfixe bei einem VyOS HA-Paar zu übersetzen:

Konfigurieren Sie beide Router (a und b) für DHCPv6-PD über Dummy-Schnittstelle:

set interfaces dummy dum1 description 'DHCPv6-PD NPT Dummy'
set interfaces bonding bond0 vif 20 dhcpv6-options pd 0 interface dum1 address '0'
set interfaces bonding bond0 vif 20 dhcpv6-options pd 1 interface dum1 address '0'
set interfaces bonding bond0 vif 20 dhcpv6-options pd 2 interface dum1 address '0'
set interfaces bonding bond0 vif 20 dhcpv6-options pd 3 interface dum1 address '0'
set interfaces bonding bond0 vif 20 dhcpv6-options rapid-commit
commit
