VXLAN

VXLAN ist eine Netzwerk-Virtualisierungstechnologie, die Skalierbarkeitsprobleme in großen Cloud-Rechenumgebungen löst. Sie kapselt Ethernet-Frames (Schicht 2) innerhalb von UDP-Datagrammen (Schicht 4), die dann über den UDP-Port 4789 gesendet werden, wie von IANA zugewiesen. VXLAN-Endpunkte, die als VTEPs bezeichnet werden, beenden VXLAN-Tunnel und können entweder virtuelle oder physische Switch-Ports sein.

VXLAN unterstützt bis zu 16 Millionen logische Netzwerke und ermöglicht die Schicht-2-Nähe über Schicht-3-IP-Netzwerke. Es verwendet Multicast oder Unicast mit Head-End-Replikation (HER), um Broadcast-, Unicast- und Multicast (BUM)-Datenverkehr zu verbreiten.

Die VXLAN-Spezifikation wurde ursprünglich von VMware, Arista Networks und Cisco entwickelt. Weitere Unterstützer sind Huawei, Broadcom, Citrix, Pica8, Big Switch Networks, Cumulus Networks, Dell EMC, Ericsson, Mellanox, FreeBSD, OpenBSD, Red Hat, Joyent und Juniper Networks.

VXLAN ist offiziell im RFC 7348 dokumentiert.

Beim Konfigurieren von VXLAN in einer VyOS-Virtualisierung muss sichergestellt werden, dass MAC-Spoofing (Hyper-V) oder Forged Transmits (ESX) erlaubt sind. Andernfalls kann der Hypervisor weitergeleitete Frames blockieren.

Hinweis

Obwohl der von IANA zugewiesene VXLAN-Port 4789 ist, verwendet VyOS den Linux-Standard-UDP-Port 8472 für VXLAN-Schnittstellen. Um Kompatibilität mit anderen Herstellern sicherzustellen, setzen Sie den Port auf den IANA-Standard 4789.

Konfiguration

Gemeinsame Schnittstellenkonfiguration

set interfaces vxlan <interface> address <address>

Konfigurieren Sie eine oder mehrere Schnittstellen-IP-Adressen.

<address> unterstützt IPv4 und IPv6 in CIDR-Schreibweise. Beispielsweise verwenden Sie 192.0.2.1/24 für IPv4 oder 2001:db8::1/64 für IPv6.

Beispiel:

set interfaces vxlan vxlan0 address 192.0.2.1/24
set interfaces vxlan vxlan0 address 2001:db8::1/64
set interfaces vxlan <interface> description <description>

Konfigurieren Sie eine klare, beschreibende Aliasbezeichnung für die Schnittstelle.

Diese Aliasbezeichnung erscheint im Befehl show interfaces und in SNMP-basierten Überwachungstools.

Beispiel:

set interfaces vxlan vxlan0 description 'This is an interface running on VyOS.'
set interfaces vxlan <interface> disable

Deaktivieren Sie die Schnittstelle.

Die Schnittstelle wird auf den administrativ heruntergefahrenen (A/D) Zustand gesetzt.

Beispiel:

set interfaces vxlan vxlan0 disable
set interfaces vxlan <interface> disable-flow-control

Deaktivieren Sie die Ethernet-Flusssteuerung (IEEE 802.3x Pause-Frames) auf der Schnittstelle.

Die Ethernet-Flusssteuerung, definiert durch den IEEE 802.3x-Standard, unterbricht vorübergehend die Datenübertragung, um Paketverluste während der Netzwerkbelastung zu vermeiden. Zum Beispiel, wenn ein Sender Daten schneller überträgt, als der Empfänger verarbeiten kann.

Das Deaktivieren der Ethernet-Flusssteuerung bedeutet, dass die Schnittstelle nicht signalisiert, dass das angeschlossene Gerät die Übertragung pausieren soll, und Pakete abwirft, falls überlastet.

Beispiel:

set interfaces vxlan vxlan0 disable-flow-control
set interfaces vxlan <interface> disable-link-detect

Deaktivieren Sie die Erkennung physischer Link-Zustandsänderungen auf der Schnittstelle, z.B. wenn ein Kabel entfernt wird.

Standardmäßig erkennt die Schnittstelle physische Link-Zustandsänderungen.

Beispiel:

set interfaces vxlan vxlan0 disable-link-detect
set interfaces vxlan <interface> mac <xx:xx:xx:xx:xx:xx>

Konfigurieren Sie eine benutzerdefinierte MAC-Adresse auf der Schnittstelle.

Beispiel:

set interfaces vxlan vxlan0 mac '00:53:01:02:03:04'
set interfaces vxlan <interface> mtu <mtu>

Konfigurieren Sie das MTU auf der Schnittstelle.

Der Wert definiert die größte Paketgröße in Bytes, die die Schnittstelle ohne Fragmentierung überträgt.

Beispiel:

set interfaces vxlan vxlan0 mtu 1600
set interfaces vxlan <interface> ip adjust-mss <mss | clamp-mss-to-pmtu>

Konfigurieren Sie die MSS die in ausgehenden TCP SYN-Paketen auf der angegebenen Schnittstelle angezeigt wird.

Durch das Begrenzen des MSS-Werts in TCP SYN-Paketen informieren Sie den Remote-Partner explizit, dass keine Pakete größer als dieser Wert gesendet werden sollen. Dies verhindert Verbindungsprobleme, die auftreten können, wenn die Pfad-MTU-Erkennung (PMTUD) fehlschlägt.

Die folgenden Optionen sind verfügbar:

  • mss: Legt die MSS auf einen bestimmten Wert in Bytes fest. Verwenden Sie diese Option, wenn Sie eine spezifische MSS erzwingen müssen, z.B. zur Fehlerbehebung von Verbindungsproblemen oder zur Anpassung an spezifische Netzwerkanforderungen.

  • clamp-mss-to-pmtu: Der Router berechnet die MSS automatisch als den MTU der Schnittstelle minus 40 Bytes für IPv4-Datenverkehr (20 Bytes für den IPv4-Header und 20 Bytes für den TCP-Header). Diese Option wird empfohlen, um den richtigen Wert automatisch zu setzen.

set interfaces vxlan <interface> ip arp-cache-timeout

Konfigurieren Sie, wie lange ein ARP-Eintrag gültig bleibt, nachdem auf dieser Schnittstelle eine IP-zu-MAC-Adresszuordnung gelernt wurde.

Die Standarddauer beträgt 30 Sekunden.

Ein ARP-Eintrag bleibt gültig, wenn er positive Rückmeldungen von höheren Protokollen erhält.

Beispiel:

set interfaces vxlan vxlan0 ip arp-cache-timeout 180
set interfaces vxlan <interface> ip disable-arp-filter

Konfigurieren Sie die ARP-Filterung auf dieser Schnittstelle.

Standardverhalten: Das Kernel antwortet auf ARP-Anfragen auf dieser Schnittstelle nur, wenn der Datenverkehr über diese spezifische Schnittstelle zurück zum ARP-Sender geroutet wird.

Wenn konfiguriert: Das Kernel antwortet auf ARP-Anfragen auf dieser Schnittstelle für jede IP-Adresse, die auf dem lokalen Host konfiguriert ist, unabhängig davon, welche spezifische Schnittstelle diese IP-Adresse zugewiesen ist, und unabhängig vom Routing-Tabellen. Dies spiegelt das Linux-Konzept wider, dass IP-Adressen dem Host gehören, nicht individuellen Schnittstellen.

Beispiel:

set interfaces vxlan vxlan0 ip disable-arp-filter
set interfaces vxlan <interface> ip disable-forwarding

Konfigurieren Sie die Schnittstelle für Host- oder Router-Verhalten.

Wenn konfiguriert, wechselt die Schnittstelle in den Hostmodus und wird IPv4-Weiterleitung deaktiviert.

Beispiel:

set interfaces vxlan vxlan0 ip disable-forwarding
set interfaces vxlan <interface> ip enable-directed-broadcast

Konfigurieren Sie, ob IP-gerichtete Broadcast-Pakete, die auf dieser Schnittstelle empfangen werden, weitergeleitet werden.

Standardverhalten: IP-gerichtete Broadcast-Pakete werden verworfen.

Wenn konfiguriert: IP-gerichtete Broadcast-Pakete werden an alle Hosts auf dem Ziel-Subnetz weitergeleitet, wie in RFC 1812 und RFC 2644 definiert.

Beispiel:

set interfaces vxlan vxlan0 ip enable-directed-broadcast
set interfaces vxlan <interface> ip enable-arp-accept

Konfigurieren Sie, wie auf kostenlose ARPs auf dieser Schnittstelle reagiert wird.

Wenn konfiguriert, wird eine IP-zu-MAC-Adresszuordnung basierend auf kostenlosen ARP-Anfragen oder Antworten in die ARP-Tabelle eingefügt.

Hinweis

Wenn die ARP-Tabelle bereits eine IP-Adresse aus einem kostenlosen ARP enthält, wird deren Eintrag aktualisiert, unabhängig davon, ob diese Einstellung konfiguriert ist.

Beispiel:

set interfaces vxlan vxlan0 ip enable-arp-accept
set interfaces vxlan <interface> ip enable-arp-announce

Konfigurieren Sie die Quell-IP-Auswahl für ARP-Anfragen auf dieser Schnittstelle.

Standardverhalten: Das Kernel kann jede IP-Adresse verwenden, die der Host besitzt, als Quell-IP-Adresse in ARP-Anfragen auf dieser Schnittstelle.

Wenn konfiguriert: Das Kernel versucht zunächst, eine Quell-IP-Adresse auszuwählen, die auf der Schnittstelle konfiguriert ist und eine gemeinsame Subnetz mit der Ziel-IP-Adresse hat. Wenn es kein solches Subnetz gibt, wählt das Kernel die IP-Adresse aus, die es normalerweise verwenden würde (basierend auf dem Routing-Tabellen, um das Zielziel zu erreichen).

Beispiel:

set interfaces vxlan vxlan0 ip enable-arp-announce
set interfaces vxlan <interface> ip enable-arp-ignore

Konfigurieren Sie, welche ARP-Anfragen auf dieser Schnittstelle ignoriert werden.

Standardverhalten: Das Kernel antwortet auf ARP-Anfragen für beliebige lokale IP-Adressen, unabhängig davon, welcher Schnittstelle sie zugeordnet sind.

Wenn konfiguriert: Das Kernel antwortet nur auf ARP-Anfragen, wenn die Ziel-IP-Adresse dieser spezifischen Schnittstelle zugeordnet ist.

Beispiel:

set interfaces vxlan vxlan0 ip enable-arp-ignore
set interfaces vxlan <interface> ip enable-proxy-arp

Konfigurieren Sie Proxy-ARP auf dieser Schnittstelle.

Wenn konfiguriert, greift der Router (Kernel) auf ARP-Anfragen für nicht-lokale IP-Adressen ein und antwortet mit der MAC-Adresse der Schnittstelle, die die Anfrage empfangen hat. Danach werden Pakete, die an diese IP-Adressen gerichtet sind, an ihre tatsächlichen Ziele auf entfernten Subnetzen weitergeleitet.

Beispiel:

set interfaces vxlan vxlan0 ip enable-proxy-arp
set interfaces vxlan <interface> ip proxy-arp-pvlan

Konfigurieren Sie lokale Proxy-ARP auf der Schnittstelle.

Wenn konfiguriert, antwortet der Router (Kernel) auf ARP-Anfragen auf dieser VLAN-Schnittstelle, auch wenn die Ziel-IP-Adresse auf dem gleichen Subnetz und der gleichen Schnittstelle liegt.

Dies wird verwendet, um Netzwerkisolierungsanforderungen (RFC 3069) für private VLANs (PVLANs) zu unterstützen. In PVLAN-Konfigurationen dürfen Hosts auf isolierten Ports nicht direkt miteinander kommunizieren, aber sie können mit dem Upstream-Router kommunizieren.

Durch die Antwort auf inter-host ARP-Anfragen mit seiner eigenen MAC-Adresse leitet der Router den inter-host-Datenverkehr über sich selbst anstatt direkt zwischen Hosts weiter.

Hinweis

Dieser Befehl funktioniert unabhängig und erfordert nicht die Aktivierung des standardmäßigen Proxy-ARP auf der Schnittstelle.

Lokales Proxy-ARP ist auch bekannt als:

  • VLAN-Aggregation (RFC 3069).

  • Private VLAN (Cisco, Allied Telesyn).

  • Quellport-Filterung oder Port-Isolation (Hewlett-Packard).

  • MAC-Forced Forwarding (Ericsson).

set interfaces vxlan <interface> ip source-validation <strict | loose | disable>

Konfigurieren Sie die Quell-IP-Adressen-Validierung mit RPF auf dieser Schnittstelle, wie in RFC 3704 festgelegt.

Die folgenden Optionen sind verfügbar:

  • strict: Jedes eingehende Paket wird anhand der Forwarding Information Base (FIB) überprüft. Wenn die Schnittstelle nicht der beste Weg zurück zu dieser Quelle ist, schlägt die Validierung fehl und das Paket wird gelöscht.

  • loose: Jedes eingehende Paket wird anhand der Forwarding Information Base (FIB) überprüft. Wenn die Quell-IP-Adresse durch irgendeine Schnittstelle nicht erreichbar ist, schlägt die Validierung fehl.

  • disable: Keine Quell-IP-Adressen-Validierung wird durchgeführt. Alle eingehenden Pakete werden akzeptiert.

RFC 3704 empfiehlt, den strengen Modus zu aktivieren, um IP-Spoofing, wie z.B. DDoS-Angriffe, zu verhindern. Für asynchrone oder andere komplexe Routing-Szenarien verwenden Sie den losen Modus.

set interfaces vxlan <interface> ipv6 address autoconf

Konfigurieren Sie die Schnittstelle, um eine IPv6-Adresse automatisch mit SLAAC, zu erhalten, wie in RFC 4862 festgelegt.

IPv6-Hosts können sich automatisch konfigurieren, wenn sie sich mit einem IPv6-Netzwerk verbinden, indem sie den Neighbor Discovery Protocol über ICMPv6 Router Discovery Nachrichten verwenden. Wenn ein Host sich zum ersten Mal mit einem Netzwerk verbindet, sendet er eine Link-Local Router Solicitation Multicast-Anfrage für seine Konfigurationsparameter. Der Router antwortet mit einer Router Advertisement-Paket, das Internet Layer Konfigurationsparameter enthält.

Hinweis

Diese Methode deaktiviert automatisch IPv6-Verkehr Weiterleitung auf der Schnittstelle.

Beispiel:

set interfaces vxlan vxlan0 ipv6 address autoconf
set interfaces vxlan <interface> ipv6 address eui64 <prefix>

Konfigurieren Sie die Schnittstelle, um sich selbst eine IPv6-Adresse mit der EUI-64 Methode zu weisen, wie in RFC 4291 festgelegt.

Beispiel:

set interfaces vxlan vxlan0 ipv6 address eui64 2001:db8:beef::/64
set interfaces vxlan <interface> ipv6 address no-default-link-local

Deaktivieren Sie die automatische Zuweisung einer link-local IPv6-Adresse zu dieser Schnittstelle.

Beispiel:

set interfaces vxlan vxlan0 ipv6 address no-default-link-local
set interfaces vxlan <interface> ipv6 disable-forwarding

Konfigurieren Sie die Schnittstelle für Host- oder Router-Verhalten.

Wenn konfiguriert, wechselt die Schnittstelle in den Hostmodus und wird IPv6-Weiterleitung deaktiviert.

Beispiel:

set interfaces vxlan vxlan0 ipv6 disable-forwarding
set interfaces vxlan <interface> ipv6 adjust-mss <mss | clamp-mss-to-pmtu>

Konfigurieren Sie die MSS die in ausgehenden TCP SYN-Paketen auf der angegebenen Schnittstelle angezeigt wird.

Durch das Begrenzen des MSS-Werts in TCP SYN-Paketen informieren Sie den Remote-Partner explizit, dass keine Pakete größer als dieser Wert gesendet werden sollen. Dies verhindert Verbindungsprobleme, wenn die Pfad-MTU-Erkennung (PMTUD) fehlschlägt.

Die folgenden Optionen sind verfügbar:

  • mss: Setzt die MSS auf einen bestimmten Wert in Bytes. Verwenden Sie diese Option, um eine spezifische MSS zu erzwingen, z.B. zur Fehlerbehebung von Verbindungsproblemen oder zur Anpassung an spezifische Netzwerkbedürfnisse.

  • clamp-mss-to-pmtu: Der Router berechnet die MSS als den MTU der Schnittstelle minus 60 Bytes für IPv6-Datenverkehr (40 Bytes für den IPv6-Header und 20 Bytes für den TCP-Header). Diese Option wird empfohlen, um den richtigen Wert automatisch zu setzen.

set interfaces vxlan <interface> ipv6 accept-dad <0 | 1 | 2>

Konfigurieren Sie IPv6 DAD auf der Schnittstelle.

Die folgenden Optionen sind verfügbar:

  • 0: Deaktiviert DAD. Es wird keine Duplicate Address Detection durchgeführt.

  • 1: Aktiviert DAD (Standard). Duplicate Addresses werden erkannt. Die Schnittstelle's IPv6-Betrieb wird für gültige IPv6-Adressen fortgesetzt.

  • 2: Aktiviert DAD und, falls eine MAC-basierte Duplicate Link-Local-Adresse gefunden wird, deaktiviert IPv6-Betrieb auf dieser Schnittstelle.

Beispiel:

set interfaces vxlan vxlan0 ipv6 accept-dad 2
set interfaces vxlan <interface> ipv6 dup-addr-detect-transmits <n>

Konfigurieren Sie die Anzahl der DAD Nachrichten, die der Router (Kernel) während der IPv6-Adresszuordnung auf dieser Schnittstelle sendet.

Der Standardwert ist 1.

Beispiel:

set interfaces vxlan vxlan0 ipv6 dup-addr-detect-transmits 5
set interfaces vxlan <interface> vrf <vrf>

Weisen Sie die Schnittstelle einem bestimmten VRF Instanz zu.

Siehe auch

Für Informationen zur Konfiguration eines VRF, siehe den VRF Abschnitt.

Beispiel:

set interfaces vxlan vxlan0 vrf red

VXLAN-spezifische Optionen

set interfaces vxlan <interface> vni <number>

Konfigurieren Sie einen VNI für die VXLAN Schnittstelle.

Jeder VXLAN-Segment wird durch diesen 24-Bit-VNI identifiziert, was bis zu 16 Millionen Segmente ermöglicht, die innerhalb desselben Administrationsbereichs koexistieren.

set interfaces vxlan <interface> port <port>

Konfigurieren Sie den UDP-Port des remote VXLAN-Endpunkts.

Hinweis

Obwohl der von IANA zugewiesene VXLAN-Port 4789 ist, verwendet VyOS den Linux-Standard-UDP-Port 8472 für VXLAN-Schnittstellen.

set interfaces vxlan <interface> source-address <address>

Konfigurieren Sie die Quell-IP-Adresse für das VXLAN-Unterlay.

Warnung

Diese Einstellung ist erforderlich, wenn VXLAN über L2VPN/EVPN bereitgestellt wird.

set interfaces vxlan <interface> gpe

Enable the GPE for the VXLAN interface.

Zum Verwenden dieses Features müssen Sie die Schnittstelle mit dem Parameter external konfigurieren.

set interfaces vxlan <interface> parameters external

Konfigurieren Sie die VXLAN-Schnittstelle, um einen externen Steuerungsplan, wie BGP L2VPN/EVPN, für die Entdeckung von Remote-Endpunkten zu verwenden.

Wenn nicht konfiguriert, wird der interne FDB verwendet.

set interfaces vxlan <interface> parameters neighbor-suppress

Aktivieren Sie ARP- und ND-Unterdrückung auf der VXLAN-Schnittstelle.

Dies reduziert das Flooding von ARP- und ND-Nachrichten über das VXLAN-Netzwerk. Wie in RFC 7432#section-10 definiert, verwenden Teilnehmende VTEPs bekannte MAC-zu-IP-Bindungen, um lokale Anfragen im Namen entfernter Hosts zu beantworten.

set interfaces vxlan <interface> parameters nolearning

Deaktivieren Sie SLLA und IP-Adressenlernen auf der VXLAN-Schnittstelle.

set interfaces vxlan <interface> parameters vni-filter

Aktivieren Sie VNI Filterung auf der VXLAN Schnittstelle.

Wenn aktiviert, empfängt die Schnittstelle nur Pakete mit VNIs, die in ihrer VNI-Filtertabelle konfiguriert sind.

Hinweis

VNI-Filterung funktioniert nur, wenn die Schnittstelle mit dem external Parameter konfiguriert ist.

Unicast

set interfaces vxlan <interface> remote <address>

Konfigurieren Sie die IPv4- oder IPv6-Adresse des remote VTEP.

Im Gegensatz zu Multicast-Setup ermöglicht dieser Befehl Ihnen, die IPv4- oder IPv6-Adresse direkt zu konfigurieren.

Multicast

set interfaces vxlan <interface> source-interface <interface>

Konfigurieren Sie die Quell-Schnittstelle für das VXLAN-Unterlay.

Alle VXLAN-Datenverkehr wird über die angegebene Schnittstelle gesendet und empfangen. Diese Einstellung ist erforderlich, wenn VXLAN über ein Multicast-Netzwerk bereitgestellt wird.

set interfaces vxlan <interface> group <address>

Konfigurieren Sie die IPv4- oder IPv6-Multicast-Gruppenadresse für die VXLAN-Schnittstelle.

VXLAN-Tunnel können mit entweder Multicast-Gruppe oder Unicast-IP-Adressen gebaut werden.

Multicast VXLAN

Topologie: PC4 - Leaf2 - Spine1 - Leaf3 - PC5

PC4 verwendet die IP-Adresse 10.0.0.4/24, und PC5 verwendet die IP-Adresse 10.0.0.5/24. Beide Geräte gehen davon aus, dass sie sich im selben Broadcast-Bereich befinden.

Angenommen, PC4 auf Leaf2 pingt PC5 auf Leaf3. Anstatt Leaf3 manuell als Remote-Endpunkt zu spezifizieren, kapselt Leaf2 das Paket in ein UDP-Datagramm und sendet es über Spine1 an die angegebene Multicast-Adresse. Spine1 leitet das Paket an alle Leaves in der gleichen Multicast-Gruppe, einschließlich Leaf3. Bei Empfang des Datagrams leitet Leaf3 es an PC5 weiter und lernt, dass PC4 über Leaf2 erreichbar ist, indem es die Quell-IP im kapselten Datagramm untersucht.

PC5 erhält den Ping und antwortet mit einem Echo-Reply. Leaf3, nun bewusst, wo PC4 sich befindet, leitet die Antwort direkt an Leaf2's Unicast-Adresse weiter. Bei Empfang des Echo-Replies lernt Leaf2, dass PC5 über Leaf3 erreichbar ist.

Nach dieser Entdeckung verwenden nachfolgende Kommunikation zwischen PC4 und PC5 nicht mehr den Multicast-Adresse zwischen den Leaves, da beide Leaves die Position der PCs gelernt haben. Dies reduziert den Multicast-Verkehr und den Netzwerklast, wodurch die Skalierbarkeit verbessert wird, wenn weitere Leaves hinzugefügt werden.

Single VXLAN device (SVD)

In VyOS können Sie mehrere VLAN-to-VNI-Mappings für EVPN-VXLAN auf einer einzigen Container-Schnittstelle konfigurieren, die als Single VXLAN Device (SVD) bekannt ist. Dies ermöglicht eine erhebliche VNI-Skalierung, da keine separate VXLAN-Schnittstelle für jeden VNI erforderlich ist.

set interfaces vxlan <interface> vlan-to-vni <vlan> vni <vni>

Mappen Sie eine VLAN-ID auf einen VNI auf der angegebenen VXLAN-Schnittstelle.

Die VXLAN-Schnittstelle kann zu einem Bridge hinzugefügt werden.

Das folgende Beispiel zeigt eine SVD-Konfiguration mit mehreren VLAN-to-VNI-Mappings.

set interfaces bridge br0 member interface vxlan0
set interfaces vxlan vxlan0 parameters external
set interfaces vxlan vxlan0 source-interface 'dum0'
set interfaces vxlan vxlan0 vlan-to-vni 10 vni '10010'
set interfaces vxlan vxlan0 vlan-to-vni 11 vni '10011'
set interfaces vxlan vxlan0 vlan-to-vni 30 vni '10030'
set interfaces vxlan vxlan0 vlan-to-vni 31 vni '10031'

Beispiel

Das folgende Beispiel demonstriert eine Multicast-VXLAN-Bereitstellung.

Die Einrichtung besteht aus drei Routern: Spine1, einem Cisco IOS-Router und Leaf2 und Leaf3, die VyOS-Routern sind.

Topologie: Leaf2 - Spine1 - Leaf3.

Die Topologie wurde mit GNS3 erstellt.

Spine1:
fa0/2 towards Leaf2, IP-address: 10.1.2.1/24
fa0/3 towards Leaf3, IP-address: 10.1.3.1/24

Leaf2:
Eth0 towards Spine1, IP-address: 10.1.2.2/24
Eth1 towards a VLAN-aware switch

Leaf3:
Eth0 towards Spine1, IP-address 10.1.3.3/24
Eth1 towards a VLAN-aware switch

Spine1-Konfiguration:

conf t
ip multicast-routing
!
interface fastethernet0/2
 ip address 10.1.2.1 255.255.255.0
 ip pim sparse-dense-mode
!
interface fastethernet0/3
 ip address 10.1.3.1 255.255.255.0
 ip pim sparse-dense-mode
!
router ospf 1
 network 10.0.0.0 0.255.255.255 area 0

Multicast-Routing ist erforderlich für skalierbare Datenverkehrsförderung zwischen Leaves. PIM muss aktiviert werden, um den Spine zu ermöglichen, zu lernen, aus welchen Multicast-Gruppen jeder Leaf Verkehr erwartet.

Leaf2-Konfiguration:

set interfaces ethernet eth0 address '10.1.2.2/24'
set protocols ospf area 0 network '10.0.0.0/8'

! First VXLAN interface
set interfaces bridge br241 address '172.16.241.1/24'
set interfaces bridge br241 member interface 'eth1.241'
set interfaces bridge br241 member interface 'vxlan241'

set interfaces vxlan vxlan241 group '239.0.0.241'
set interfaces vxlan vxlan241 source-interface 'eth0'
set interfaces vxlan vxlan241 vni '241'

! Second VXLAN interface
set interfaces bridge br242 address '172.16.242.1/24'
set interfaces bridge br242 member interface 'eth1.242'
set interfaces bridge br242 member interface 'vxlan242'

set interfaces vxlan vxlan242 group '239.0.0.242'
set interfaces vxlan vxlan242 source-interface 'eth0'
set interfaces vxlan vxlan242 vni '242'

Leaf3-Konfiguration:

set interfaces ethernet eth0 address '10.1.3.3/24'
set protocols ospf area 0 network '10.0.0.0/8'

! First VXLAN interface
set interfaces bridge br241 address '172.16.241.1/24'
set interfaces bridge br241 member interface 'eth1.241'
set interfaces bridge br241 member interface 'vxlan241'

set interfaces vxlan vxlan241 group '239.0.0.241'
set interfaces vxlan vxlan241 source-interface 'eth0'
set interfaces vxlan vxlan241 vni '241'

! Second VXLAN interface
set interfaces bridge br242 address '172.16.242.1/24'
set interfaces bridge br242 member interface 'eth1.242'
set interfaces bridge br242 member interface 'vxlan242'

set interfaces vxlan vxlan242 group '239.0.0.242'
set interfaces vxlan vxlan242 source-interface 'eth0'
set interfaces vxlan vxlan242 vni '242'

Die Konfigurationen für Leaf2 und Leaf3 sind fast identisch. Detaillierte Erklärungen für jeden Befehl finden Sie unten.

set interfaces bridge br241 address '172.16.241.1/24'

Dieser Befehl erstellt eine Brücke, um den Verkehr auf eth1 VLAN 241 mit der vxlan241 Schnittstelle zu binden. Die IP-Adresse ist optional. Falls konfiguriert, kann sie als Standard-Gateway für jedes Leaf dienen, sodass Geräte auf dem VLAN andere Subnetze erreichen können. Subnetze müssen durch OSPF weitergeleitet werden, damit der Spine weiß, wie sie erreicht werden können. Um 172.16/12 Netzwerke zu werben, ändern Sie den OSPF Netzwerk von 10.0.0.0/8 auf 0.0.0.0/0.

set interfaces bridge br241 member interface 'eth1.241'
set interfaces bridge br241 member interface 'vxlan241'

Diese Befehle binden eth1.241 und vxlan241 als Mitgliedsschnittstellen der gleichen Brücke.

set interfaces vxlan vxlan241 group '239.0.0.241'

Dieser Befehl konfiguriert die Multicast-Gruppe, die alle Leaves für diesen VLAN-Erweiterung verwenden. Es muss dieselbe sein auf allen Leaves, die diese Schnittstelle haben.

set interfaces vxlan vxlan241 source-interface 'eth0'

Dieser Befehl konfiguriert die Schnittstelle, die Multicast-Pakete hört. Es kann auch eine Loopback-Schnittstelle sein.

set interfaces vxlan vxlan241 vni '241'

Dieser Befehl konfiguriert die eindeutige ID für die VXLAN-Schnittstelle.

set interfaces vxlan vxlan241 port 12345

VyOS verwendet den Linux-Standard-UDP-Port 8472 für VXLAN-Schnittstellen. Dieser Befehl ermöglicht es Ihnen, einen anderen UDP-Port zu konfigurieren.

Unicast VXLAN

Als Alternative zu Multicast können Sie den VXLAN-Tunnel konfigurieren, indem Sie die Remote-IPv4-Adresse direkt angeben. Das folgende aktualisiert das vorherige Multicast-Beispiel:

# leaf2 and leaf3
delete interfaces vxlan vxlan241 group '239.0.0.241'
delete interfaces vxlan vxlan241 source-interface 'eth0'

# leaf2
set interfaces vxlan vxlan241 remote 10.1.3.3

# leaf3
set interfaces vxlan vxlan241 remote 10.1.2.2

Der Standard-UDP-Port ist 8472. Um einen anderen Port zu konfigurieren, verwenden Sie set interfaces vxlan <vxlanN> port <port>.
