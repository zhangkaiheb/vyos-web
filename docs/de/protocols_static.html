Statisch

Statische Routen sind manuell konfigurierte Einträge im Routing-Informationen-Basis (RIB) des Routers, die definieren, wie der Datenverkehr zu spezifischen Zielen geleitet werden soll. Im Gegensatz zu dynamischen Routing-Protokollen werden statische Routen nicht automatisch aktualisiert, wenn sich die Netzwerktopologie ändert.

Statische Routen eignen sich am besten für einfache Netzwerktopologien oder um das Verhalten dynamischer Routing-Protokolle für eine begrenzte Anzahl von Routen zu überschreiben.

Der Routing-Informationen-Basis (RIB) speichert alle Routing-Informationen, einschließlich manuell konfigurierter statischer Routen und jeder dynamisch erlernten Route. Aus dem RIB leitet der Router unicast-Routen ab, um die Forwarding-Informationen-Basis (FIB) zu erstellen.

IPv4 Unicast-Routen

IPv4 Unicast-Routen leiten den Datenverkehr, der auf ein einzelnes IPv4-Host oder Subnetz gerichtet ist, zu einem bestimmten nächsten Hop. Verwenden Sie die folgenden Befehle, um IPv4 Unicast-Routen für ein bestimmtes entferntes Subnetz zu konfigurieren.

set protocols static route <subnet> next-hop <address>

Konfigurieren Sie die nächste Hop-IP-Adresse für das angegebene Subnetz.

Sie können mehrere nächste Hop-IP-Adressen für dasselbe Ziel-Subnetz konfigurieren.

Beispiel:

set protocols static route 192.0.2.0/24 next-hop 10.0.0.254
set protocols static route <subnet> next-hop <address> disable

Deaktivieren Sie die Route über die angegebene nächste Hop-IP-Adresse.

Dieser Befehl deaktiviert vorübergehend die Route, während die konfigurierten Subnetz-, nächste Hop- und Distanzparameter erhalten bleiben.

Beispiel:

set protocols static route 192.0.2.0/24 next-hop 10.0.0.254 disable
set protocols static route <subnet> next-hop <address> distance <distance>

Konfigurieren Sie die administrative Distanz für die Route über die angegebene nächste Hop-IP-Adresse.

Routen mit einer niedrigeren administrativen Distanz haben Vorrang vor Routen mit einer höheren Distanz.

Der zulässige Bereich beträgt 1 bis 255. Die Standarddistanz beträgt 1.

Hinweis

Routen mit einer Distanz von 255 sind deaktiviert und werden nicht für die Paketweiterleitung verwendet.

Beispiel:

set protocols static route 192.0.2.0/24 next-hop 10.0.0.254 distance 10

IPv4 Schnittstellenrouten leiten den Datenverkehr, der auf ein einzelnes IPv4-Host oder Subnetz gerichtet ist, über eine bestimmte lokale Schnittstelle. Verwenden Sie die folgenden Befehle, um IPv4 Schnittstellenrouten für ein bestimmtes entferntes Subnetz zu konfigurieren.

set protocols static route <subnet> interface <interface> disable

Beispiel:

set protocols static route 192.0.2.0/24 interface eth0 disable

Konfigurieren Sie die administrative Distanz für die Route über die angegebene nächste Hop-Schnittstelle.

Routen mit einer niedrigeren administrativen Distanz haben Vorrang vor Routen mit einer höheren Distanz.

Der zulässige Bereich beträgt 1 bis 255. Die Standarddistanz beträgt 1.

Beispiel:

set protocols static route 192.0.2.0/24 interface eth0 distance 10

IPv4 BFD

BFD überwacht die Erreichbarkeit der nächsten Hop-IP-Adresse einer statischen Route. Verwenden Sie die folgenden Befehle, um BFD-Parameter für Ihre IPv4 statischen Routen zu konfigurieren.

set protocols static route <subnet> next-hop <address> bfd

Enable BFD monitoring for the route via the specified next-hop IP address.

The system uses the next-hop IP address as the BFD peer destination.

Example:

set protocols static route 192.0.2.0/24 next-hop 10.0.0.254 bfd
set protocols static route <subnet> next-hop <address> bfd profile <profile>

Apply the settings from a designated BFD profile to the BFD session that monitors the specified next-hop IP address.

Example:

set protocols static route 192.0.2.0/24 next-hop 10.0.0.254 bfd profile custom-profile
set protocols static route <subnet> next-hop <address> bfd multi-hop source-address <source-address>

Enable a multi-hop BFD session to monitor the reachability of the specified next-hop IP address.

The system initiates the BFD session from the specified local source IPv4 address.

Example:

set protocols static route 192.0.2.0/24 next-hop 10.0.0.254 bfd multi-hop source-address 172.16.1.1

DHCP Schnittstellenrouten

DHCP Schnittstellenrouten leiten den Datenverkehr, der auf ein einzelnes IPv4-Host oder Subnetz gerichtet ist, zu einem nächsten Hop-Gateway, das aus einer DHCP-fähigen Schnittstelle abgerufen wird. Verwenden Sie den folgenden Befehl, um DHCP Schnittstellenrouten zu konfigurieren.

set protocols static route <subnet> dhcp-interface <interface>

Konfigurieren Sie eine statische Route, die ihre nächste Hop-IP-Adresse aus der angegebenen DHCP-fähigen Schnittstelle ableitet.

Beispiel:

set protocols static route 192.0.2.0/24 dhcp-interface eth0

IPv4 Ablehnungsrichtlinien

IPv4 Ablehnungsrichtlinien leiten den Datenverkehr, der auf ein einzelnes IPv4-Host oder Subnetz gerichtet ist, explizit ab und senden eine ICMP-unreachable Nachricht an das sendende Gerät. Verwenden Sie die folgenden Befehle, um IPv4 Ablehnungsrichtlinien zu konfigurieren.

set protocols static route <subnet> reject

Konfigurieren Sie eine Ablehnungsroute für das angegebene Subnetz.

Das System verwirft den Datenverkehr, der für dieses Subnetz bestimmt ist, und sendet eine ICMP-Zielunreachable-Nachricht an das sendende Gerät.

Beispiel:

set protocols static route 192.0.2.0/24 reject
set protocols static route <subnet> reject distance <distance>

Konfigurieren Sie die administrative Distanz für die Ablehnungsroute.

Routen mit einer niedrigeren administrativen Distanz haben Vorrang vor Routen mit einer höheren Distanz.

Der zulässige Bereich beträgt 1 bis 255.

Beispiel:

set protocols static route 192.0.2.0/24 reject distance 200
set protocols static route <subnet> reject tag <tag>

Konfigurieren Sie eine numerische Kennung für die Ablehnungsroute.

Der zulässige Bereich beträgt 1 bis 4294967295.

Beispiel:

set protocols static route 192.0.2.0/24 reject tag 100

IPv4 Blackhole-Routen

Blackhole-Routen werfen den Datenverkehr, der auf ein bestimmtes Subnetz gerichtet ist, stillschweigend weg. Im Gegensatz zu einer Ablehnungsroute, die dem Sender eine ICMP-Zielunreachable-Nachricht sendet, wirft eine Blackhole-Route die Pakete ohne jegliche Antwort weg.

set protocols static route <subnet> blackhole

Konfigurieren Sie eine Blackhole-Route für das angegebene Subnetz.

Das System wirft entsprechende Pakete stillschweigend weg, ohne eine ICMP-Antwort an den Quellort zu senden.

Beispiel:

set protocols static route 10.0.0.0/8 blackhole
set protocols static route <subnet> blackhole distance <distance>

Konfigurieren Sie die administrative Distanz für die Blackhole-Route.

Routen mit einer niedrigeren administrativen Distanz haben Vorrang vor Routen mit einer höheren Distanz.

Der zulässige Bereich beträgt 1 bis 255.

Beispiel:

set protocols static route 10.0.0.0/8 blackhole distance 200
set protocols static route <subnet> blackhole tag <tag>

Konfigurieren Sie eine numerische Kennung für die Blackhole-Route.

Der zulässige Bereich beträgt 1 bis 4294967295.

Beispiel:

set protocols static route 10.0.0.0/8 blackhole tag 100

Dieser Befehl deaktiviert vorübergehend die Route, während die konfigurierten Subnetz-, nächste Hop- und Distanzparameter erhalten bleiben.

Routen mit einer niedrigeren administrativen Distanz haben Vorrang vor Routen mit einer höheren Distanz.

Der zulässige Bereich beträgt 1 bis 255. Die Standarddistanz beträgt 1.

Hinweis

Routen mit einer Distanz von 255 sind deaktiviert und werden nicht für die Paketweiterleitung verwendet.

Beispiel:

set protocols static route6 2001:db8:1::/64 next-hop 2001:db8:100::1 distance 10
set protocols static route6 <subnet> next-hop <address> segments <segments>

Konfigurieren Sie eine IPv6 Unicast-Route, die Segment Routing over IPv6 (SRv6) verwendet, um das Ziel-Subnetz zu erreichen.

Verwenden Sie einen Schrägstrich (/), um mehrere IPv6 Segment-Identifikatoren (SIDs) in Ihrer Sequenz zu trennen.

Beispiel:

set protocols static route6 2001:db8:1000::/36 next-hop 2001:db8:201::ffff segments '2001:db8:aaaa::7/2002::4/2002::3/2002::2'
