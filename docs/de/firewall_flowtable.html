Übersicht

Dieser Abschnitt bietet Informationen zur Firewall-Konfiguration für Flowtables.

set firewall flowtable …

Weitere Informationen über den allgemeinen Datenverkehr in VyOS Firewalls finden Sie unter Firewall.

- set firewall
    * flowtable
         - custom_flow_table
            + ...

Flowtables ermöglichen es Ihnen, einen schnellen Pfad durch den Flowtable-Datapfad zu definieren. Flowtables unterstützen Layer 3 (IPv4 und IPv6) und Layer 4 (TCP und UDP) Protokolle.

Nachdem das erste Paket den IP-Weiterleitungs-Pfad erfolgreich durchläuft (schwarzer Kreis-Pfad), können Sie nachfolgende Pakete über Ihre Regelsammlung an den Flowtable weiterleiten. Sie bestimmen, wann ein Fluss dem Flowtable hinzugefügt wird während der Weiterleitungsfilterung (roter Kreisnummer 6).

Wenn ein Paket einen passenden Eintrag im Flowtable findet (Flowtable-Hit), sendet das System es an das Ausgangs-Netzgerät. Dies bedeutet, dass Pakete den klassischen IP-Weiterleitungs-Pfad umgehen und den Schnellpfad (orangener Kreis-Pfad) verwenden. Als Ergebnis sehen Sie diese Pakete nicht mehr von irgendeinem Netfilter-Hook nach Eingang. Wenn kein passender Eintrag im Flowtable existiert (Flowtable-Miss), durchläuft das Paket den klassischen IP-Weiterleitungs-Pfad.

Hinweis

Flowtable Referenz: https://docs.kernel.org/networking/nf_flowtable.html

Flowtable-Konfiguration

Um Flowtables zu verwenden, müssen Sie Folgendes konfigurieren:

  • Erstellen Sie einen Flowtable, der die Schnittstellen enthält, die für den Flowtable verwendet werden sollen.

  • Erstellen Sie eine Firewall-Regel. Legen Sie die Aktion auf offload fest und verwenden Sie Ihren gewünschten Flowtable als offload-target.

Erstellen eines Flow Tables:

set firewall flowtable <flow_table_name> interface <iface> Geben Sie die Schnittstellen an, die im Flowtable verwendet werden sollen.
set firewall flowtable <flow_table_name> description <text>

Geben Sie eine Beschreibung für den Flowtable an.

set firewall flowtable <flow_table_name> offload <hardware | software>

Geben Sie den Offload-Typ an, den der Flowtable verwendet: hardware oder software. Der Standard ist software Offload.

Hinweis

Hardware-Offload: Stellen Sie sicher, dass Ihr Netzwerk-Interface-Controller (NIC) Hardware-Offload unterstützt und dass Sie die erforderlichen Treiber installiert haben, bevor Sie diese Option aktivieren.

Erstellen von Regeln für die Verwendung von Flowtables:

set firewall [ipv4 | ipv6] forward filter rule <1-999999> action offload

Erstellen Sie eine Firewall-Regel in der Forward-Kette mit der Aktion auf offload gesetzt.

set firewall [ipv4 | ipv6] forward filter rule <1-999999> offload-target <flowtable>

Erstellen Sie eine Firewall-Regel in der Forward-Kette und geben Sie an, welchen Flowtable zu verwenden. Nur anwendbar, wenn die Aktion offload ist.

Schnittstellenauswahl

Wichtig

Konfigurieren Sie immer den Flowtable mit der Schnittstelle, die VyOS am Forward-Hook beobachtet – was nicht unbedingt die physische Schnittstelle ist. Wenn Traffic über eine logische Schnittstelle empfangen oder übertragen wird, verfolgt VyOS diese logische Schnittstelle, nicht das zugrunde liegende physische Gerät. Das Registrieren der falschen Schnittstelle im Flowtable führt dazu, dass jeder Fluss-Suche fehlschlägt, zurückfällt auf den klassischen Weiterleitungs-Pfad und somit das Ziel des Fast-Path-Offloads vereitelt.

Konfigurationsbeispiel

Betrachten Sie folgendes in dieser Einrichtung:

  • Dieses Beispiel verwendet zwei Schnittstellen in den Flowtables: eth0 und eth1.

  • Das Beispiel bietet eine minimale Firewall-Regelsammlung mit Filterregeln und Regeln für die Nutzung von Flowtable-Offload-Fähigkeiten.

Das erste Paket wird vom Firewall-Pfad bewertet, also sollte eine gewünschte Verbindung explizit akzeptiert werden. Das gleiche sollte für den umgekehrten Verkehr gelten. In den meisten Fällen werden Zustandsrichtlinien verwendet, um eine Verbindung im umgekehrten Pfad zu akzeptieren.

In folgendem Beispiel wird nur Traffic, der von der Schnittstelle eth0, TCP-Protokoll und Zielport 1122 kommt, akzeptiert. Alle anderen Traffic an den Router wird abgelehnt.

Befehle

set firewall flowtable FT01 interface 'eth0'
set firewall flowtable FT01 interface 'eth1'
set firewall ipv4 forward filter default-action 'drop'
set firewall ipv4 forward filter rule 10 action 'offload'
set firewall ipv4 forward filter rule 10 offload-target 'FT01'
set firewall ipv4 forward filter rule 10 state 'established'
set firewall ipv4 forward filter rule 20 action 'accept'
set firewall ipv4 forward filter rule 20 state 'established'
set firewall ipv4 forward filter rule 20 state 'related'
set firewall ipv4 forward filter rule 110 action 'accept'
set firewall ipv4 forward filter rule 110 destination address '192.0.2.100'
set firewall ipv4 forward filter rule 110 destination port '1122'
set firewall ipv4 forward filter rule 110 inbound-interface name 'eth0'
set firewall ipv4 forward filter rule 110 protocol 'tcp'

Erläuterung

Was passiert bei einer gewünschten Verbindung:

  1. Ein Paket kommt auf eth0 mit Zieladresse 192.0.2.100, TCP Protokoll und Zielport 1122. Nehmen wir an, diese Adresse ist über die Schnittstelle eth1 erreichbar.

  2. Für dieses erste Paket ist der Verbindungsstatus neu. Weder Regel 10 noch Regel 20 gilt.

  3. Regel 110 passt, daher wird die Verbindung akzeptiert.

  4. Wenn der Server 192.0.2.100 antwortet, wird der Verbindungsstatus etabliert, und Regel 20 akzeptiert die Antwort.

  5. Der Router erhält das zweite Paket für diese Verbindung. Da der Verbindungsstatus etabliert ist, passt Regel 10 und fügt einen neuen Eintrag in den Flowtable FT01 für diese Verbindung hinzu.

  6. Spätere Pakete überspringen den traditionellen Weg und verwenden den Schnellpfad für das Offloaden.

Flowtable-Konfiguration auf logischen und Unter-Schnittstellen

Konfigurieren Sie den Flowtable mit dem Namen der Schnittstelle, den Sie in der VyOS-Konfiguration verwendet haben. Wenn VLANs, Bonds oder Bridges beteiligt sind, ist dies die logische Schnittstelle (bond0, br0, eth0.10) – nicht die zugrunde liegende physische Schnittstelle.

Zum Beispiel:

  • Wenn bond0 konfiguriert ist, sieht VyOS bond0 – nicht eth0 oder eth1

  • Wenn br0 konfiguriert ist, sieht VyOS br0 – nicht seine Mitgliedsschnittstellen

  • Der Flowtable muss den gleichen Schnittstellennamen referenzieren, den VyOS beobachtet

Zwei Formate werden akzeptiert, aber das Registrieren des Elterns wird empfohlen:

  • Das Registrieren von bond1 lädt den Elternschnittstellen und alle ihre VLAN-Unterschnittstellen (bond1.10, bond1.20, etc.) – das Kernel automatisch entdeckt sie durch das Parsen der L2-Headers (Linux 5.13+).

  • Das direkte Registrieren von bond1.10 lädt nur VLAN 10 Traffic. Aber die Unterschnittstelle muss zum Commit-Zeitpunkt vorhanden sein; wenn sie noch nicht vorhanden ist, wenn die Regelsammlung geladen wird, kann die Konfiguration fehlschlagen.

# Offload bond1 und alle Sub-Interfaces (bond1.10, bond1.20, ...)
set firewall flowtable FT01 interface 'bond1'

# Offload VLAN 10 nur: registrieren Sie die Sub-Interface direkt
set firewall flowtable FT01 interface 'bond1.10'

Beispiel: Gemischte Eltern- und Sub-Interface-Offload

Stellen Sie sich eine Einrichtung vor, in der:

  • Der Traffic eingeht auf bond1.10 (VLAN 10)

  • Der Traffic ausgeht auf bond2.20 (VLAN 20)

set firewall flowtable FT01 interface 'bond1'
set firewall flowtable FT01 interface 'bond2.20'
set firewall ipv4 forward filter default-action 'drop'
set firewall ipv4 forward filter rule 10 action 'offload'
set firewall ipv4 forward filter rule 10 offload-target 'FT01'
set firewall ipv4 forward filter rule 10 state 'established'
set firewall ipv4 forward filter rule 20 action 'accept'
set firewall ipv4 forward filter rule 20 state 'established'
set firewall ipv4 forward filter rule 20 state 'related'
set firewall ipv4 forward filter rule 200 action 'accept'
set firewall ipv4 forward filter rule 200 inbound-interface name 'bond*'

In dieser Konfiguration:

  • bond1 deckt den Eingang aus bond1.10 und allen anderen bond1 Sub-Interfaces ab.

  • bond2.20 lädt nur VLAN 20 – andere bond2 Sub-Interfaces bleiben auf der Standard-Weiterleitungspfad. Dies zeigt, wie man ein einzelnes VLAN selektiv offloadet, während andere auf dem langsamen Pfad bleiben.

  • Regel 200 verwendet einen Wildcard, um jeden Traffic anzunehmen, der auf irgendeiner Bond-Schnittstelle oder Sub-Schnittstelle vor dem Fluss etabliert ist und für das Offload berechtigt ist

  • Einmal, wenn ein Fluss etabliert ist, fügt Regel 10 ihn dem Flowtable hinzu und nachfolgende Pakete überspringen den Forward-Hook vollständig über den Schnellpfad

Hinweis

Die Schnittstellenrichtungen in diesem Beispiel sind aus der Perspektive von Client-zu-Server-Verkehr. In der Praxis verarbeitet jede Schnittstelle den Verkehr in beiden Richtungen, und der Flowtable verwaltet das Offloaden symmetrisch, sobald der Fluss etabliert ist. Um die Eingangs- und Ausgangsschnittstellen zu bestätigen, aktivieren Sie log auf einer Regel im Forward-Hook und prüfen Sie die Firewall-Logs – siehe den Firewall Abschnitt für die Konfiguration.

Schnittstellenidentifikation

Um zu überprüfen, dass VyOS den Verkehr anhand seiner logischen Sub-Schnittstelle und nicht des zugrunde liegenden physischen Geräts identifiziert, inspizieren Sie das Firewall-Log:

vyos@FlowTables:~$ show log firewall
Jun 18 22:22:00 kernel: [ipv4-FWD-filter-200-A] IN=bond1.10 OUT=bond2.20 \
  MAC=00:53:00:00:00:02:00:53:00:00:00:01:08:00 SRC=192.168.10.2 \
  DST=192.168.20.2 LEN=84 PROTO=ICMP TYPE=8 CODE=0 ID=3572 SEQ=1

Die Felder IN und OUT zeigen bond1.10 und bond2.20 – die logischen Sub-Schnittstellen – nicht das zugrunde liegende physische oder Bond-Gerät.

Flowtable-Offload

Führen Sie den folgenden Befehl aus, um zu überprüfen, ob die Verbindungen an den Flowtable-Schnellpfad weitergeleitet wurden:

vyos@FlowTables:~$ show conntrack table ipv4
Original src        Original dst       Reply src          Reply dst           Protocol    State    Timeout    Mark    Zone
------------------  -----------------  -----------------  ------------------  ----------  -------  ---------  ------  ------
192.168.10.2:45140  192.168.20.2:5201  192.168.20.2:5201  192.168.10.2:45140  tcp                  n/a        0
192.168.10.2:45124  192.168.20.2:5201  192.168.20.2:5201  192.168.10.2:45124  tcp                  n/a        0


vyos@FlowTables:~$ show conntrack table ipv4
Original src        Original dst       Reply src          Reply dst           Protocol    State      Timeout    Mark    Zone
------------------  -----------------  -----------------  ------------------  ----------  ---------  ---------  ------  ------
192.168.10.2:45124  192.168.20.2:5201  192.168.20.2:5201  192.168.10.2:45124  tcp         TIME_WAIT  105        0

Einträge mit Timeout als n/a und einem leeren State bestätigen, dass die Flüsse an den Flowtable-Schnellpfad weitergeleitet wurden – nachfolgende Pakete überspringen die Firewall vollständig. Sobald die TCP-Verbindung geschlossen wird, wechselt der Eintrag in TIME_WAIT und der Timeout-Zähler setzt wieder ein.
