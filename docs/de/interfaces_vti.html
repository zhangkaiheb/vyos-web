VTI (virtueller Tunnel-Schnittstelle)

VTIs ermöglichen es, sichere, verschlüsselte Tunnel zwischen privaten Netzwerken oder Hosts über öffentliche Infrastruktur, wie z. B. das Internet, zu erstellen. Sie arbeiten neben einem zugrunde liegenden IPsec-Tunnel, der die Verpackung und Verschlüsselung übernimmt, während VTIs ausschließlich als Routing- Schnittstelle fungieren.

Konfiguration

Gemeinsame Schnittstellenkonfiguration

set interfaces vti <interface> address <address>

Konfigurieren Sie eine oder mehrere Schnittstellen-IP-Adressen.

<address> unterstützt IPv4 und IPv6 in CIDR-Schreibweise. Zum Beispiel verwenden Sie 192.0.2.1/24 für IPv4 oder 2001:db8::1/64 für IPv6.

Beispiel:

set interfaces vti vti0 address 192.0.2.1/24
set interfaces vti vti0 address 2001:db8::1/64
set interfaces vti <interface> description <description>

Konfigurieren Sie einen klaren, beschreibenden Alias für die Schnittstelle.

Dieser Alias erscheint im Befehl show interfaces und in SNMP-basierten Überwachungstools.

Beispiel:

set interfaces vti vti0 description 'This is an interface running on VyOS.'
set interfaces vti <interface> disable

Deaktivieren Sie die Schnittstelle.

Die Schnittstelle wird auf den administrativ down-Zustand (A/D) gesetzt.

Beispiel:

set interfaces vti vti0 disable
set interfaces vti <interface> ip adjust-mss <mss | clamp-mss-to-pmtu>

Konfigurieren Sie die MSS , die in ausgehenden TCP SYN-Paketen auf der angegebenen Schnittstelle angegeben werden.

Durch das Begrenzen des MSS-Werts in TCP SYN-Paketen informieren Sie den entfernten Teilnehmer explizit nicht, Pakete größer als diese Größe zu senden. Dies verhindert Verbindungsprobleme, die auftreten, wenn die Pfad-MTU-Entdeckung (PMTUD) fehlschlägt.

Die folgenden Optionen sind verfügbar:

  • mss: Legt die MSS auf einen bestimmten Wert in Bytes fest. Nutzen Sie diese Option, falls Sie eine spezifische MSS erzwingen müssen, beispielsweise um Verbindungsschwierigkeiten zu beheben oder spezifische Netzwerkanforderungen zu berücksichtigen.

  • clamp-mss-to-pmtu: Der Router berechnet die MSS automatisch als MTU der Schnittstelle minus 40 Bytes für IPv4-Datenverkehr (20 Bytes für den IPv4-Header und 20 Bytes für den TCP-Header). Diese Option wird empfohlen, um den richtigen Wert automatisch einzustellen.

set interfaces vti <interface> ip arp-cache-timeout

Konfigurieren Sie, wie lange ein ARP-Eintrag gültig bleibt, nachdem eine IP-zu-MAC-Adresse-Zuordnung auf dieser Schnittstelle gelernt wurde.

Die Standarddauer beträgt 30 Sekunden.

Ein ARP-Eintrag bleibt gültig, wenn er positive Rückmeldungen von höheren Protokollen erhält.

Beispiel:

set interfaces vti vti0 ip arp-cache-timeout 180
set interfaces vti <interface> ip disable-arp-filter

Konfigurieren Sie die ARP-Filterung auf dieser Schnittstelle.

Standardverhalten: Das Kernel antwortet auf ARP-Anfragen auf dieser Schnittstelle nur dann, wenn der Datenverkehr über diese spezifische Schnittstelle zurück zum ARP-Sender geroutet wird.

Wenn konfiguriert: Das Kernel antwortet auf ARP-Anfragen auf dieser Schnittstelle für jede IP-Adresse, die auf dem lokalen Host konfiguriert ist, unabhängig davon, welche spezifische Schnittstelle diese IP-Adresse zugewiesen ist, und unabhängig vom Routing-Tabellen. Dies spiegelt das Linux-Konzept wider, dass IP-Adressen dem Host gehören, nicht einzelnen Schnittstellen.

Beispiel:

set interfaces vti vti0 ip disable-arp-filter
set interfaces vti <interface> ip disable-forwarding

Konfigurieren Sie die Schnittstelle für Host- oder Router-Verhalten.

Wenn konfiguriert, wechselt die Schnittstelle in Hostmodus und wird IPv4-Weiterleitung deaktiviert.

Beispiel:

set interfaces vti vti0 ip disable-forwarding
set interfaces vti <interface> ip enable-directed-broadcast

Konfigurieren Sie, ob IP-gerichtete Broadcast-Pakete, die auf dieser Schnittstelle empfangen werden, weitergeleitet werden.

Standardverhalten: IP-gerichtete Broadcast-Pakete werden verworfen.

Wenn konfiguriert: IP-gerichtete Broadcast-Pakete werden an alle Hosts auf dem Ziel-Subnetz weitergeleitet, wie in RFC 1812 und RFC 2644 definiert.

Beispiel:

set interfaces vti vti0 ip enable-directed-broadcast
set interfaces vti <interface> ip enable-arp-accept

Konfigurieren Sie, wie mit kostenlosen ARPs auf dieser Schnittstelle umgegangen wird.

Wenn konfiguriert, wird eine IP-zu-MAC-Adresse-Zuordnung in der ARP-Tabelle basierend auf kostenlosen ARP-Anfragen oder Antworten hinzugefügt.

Hinweis

Wenn die ARP-Tabelle bereits die IP-Adresse aus einem kostenlosen ARP enthält, wird deren Eintrag aktualisiert, unabhängig davon, ob diese Einstellung konfiguriert ist.

Beispiel:

set interfaces vti vti0 ip enable-arp-accept
set interfaces vti <interface> ip enable-arp-announce

Konfigurieren Sie die Quell-IP-Auswahl für ARP-Anfragen auf dieser Schnittstelle.

Standardverhalten: Das Kernel kann jede IP-Adresse verwenden, die der Host besitzt, als Quell-IP-Adresse in ARP-Anfragen auf dieser Schnittstelle.

Wenn konfiguriert: Das Kernel versucht zunächst, eine Quell-IP-Adresse auszuwählen, die auf der Schnittstelle konfiguriert ist und mit dem Ziel-IP-Adress-Subnetz übereinstimmt. Wenn kein solches Subnetz vorhanden ist, wählt das Kernel die IP-Adresse aus, die es normalerweise verwendet (basierend auf der Routing-Tabelle, um das Zielziel zu erreichen).

Beispiel:

set interfaces vti vti0 ip enable-arp-announce
set interfaces vti <interface> ip enable-arp-ignore

Konfigurieren Sie, welche ARP-Anfragen auf dieser Schnittstelle ignoriert werden.

Standardverhalten: Das Kernel antwortet auf ARP-Anfragen für beliebige lokale IP-Adressen, unabhängig davon, welcher Schnittstelle sie zugewiesen sind.

Wenn konfiguriert: Das Kernel antwortet nur auf ARP-Anfragen, wenn die Ziel-IP-Adresse dieser spezifischen Schnittstelle zugewiesen ist.

Beispiel:

set interfaces vti vti0 ip enable-arp-ignore
set interfaces vti <interface> ip enable-proxy-arp

Konfigurieren Sie Proxy-ARP auf dieser Schnittstelle.

Wenn konfiguriert, greift der Router (Kernel) auf ARP-Anfragen für nicht-lokale IP-Adressen zu und antwortet mit der MAC-Adresse der Schnittstelle, die die Anfrage empfangen hat. Danach werden Pakete, die an diese IP-Adressen gerichtet sind, an ihre tatsächlichen Ziele auf entfernten Subnetzen weitergeleitet.

Beispiel:

set interfaces vti vti0 ip enable-proxy-arp
set interfaces vti <interface> ip proxy-arp-pvlan

Konfigurieren Sie lokales Proxy-ARP auf der Schnittstelle.

Wenn konfiguriert, antwortet der Router (Kernel) auf ARP-Anfragen auf dieser VLAN-Schnittstelle, auch wenn die Ziel-IP-Adresse auf dem gleichen Subnetz und der gleichen Schnittstelle liegt.

Dies wird verwendet, um Netzwerkisolationsanforderungen (RFC 3069) für private VLANs (PVLANs) zu unterstützen. In PVLAN-Konfigurationen dürfen Hosts auf isolierten Ports nicht direkt miteinander kommunizieren, aber sie können mit dem Upstream-Router kommunizieren.

Durch die Antwort auf interne ARP-Anfragen mit seiner eigenen MAC-Adresse leitet der Router den inter-HOST-Datenverkehr durch sich selbst anstatt direkt zwischen den Hosts.

Hinweis

Dieser Befehl funktioniert unabhängig und erfordert nicht, dass das normale Proxy-ARP auf der Schnittstelle aktiviert wird.

Lokales Proxy-ARP wird auch bezeichnet als:

  • VLAN-Aggregation (RFC 3069).

  • Private VLAN (Cisco, Allied Telesyn).

  • Quellport-Filterung oder Port-Isolation (Hewlett-Packard).

  • MAC-Forced Forwarding (Ericsson).

set interfaces vti <interface> ip source-validation <strict | loose | disable>

Konfigurieren Sie die Quell-IP-Adressen-Validierung mit RPF auf dieser Schnittstelle, wie in RFC 3704 beschrieben.

Die folgenden Optionen sind verfügbar:

  • strict: Die Quell-IP-Adresse jedes eingehenden Pakets wird gegen die Forwarding Information Base (FIB) geprüft. Wenn die Schnittstelle nicht der beste Weg zur Quelle ist, schlägt die Validierung fehl und das Paket wird verworfen.

  • loose: Die Quell-IP-Adresse jedes eingehenden Pakets wird gegen die FIB geprüft. Wenn die Quell-IP-Adresse über keine Schnittstelle erreichbar ist, schlägt die Validierung fehl.

  • disable: Es wird keine Quell-IP-Adressen-Validierung durchgeführt. Alle eingehenden Pakete werden akzeptiert.

RFC 3704 empfiehlt, den strengen Modus zu aktivieren, um IP-Spoofing, wie DDoS-Angriffe, zu verhindern. Für asynchrone oder komplexe Routing-Szenarien verwenden Sie den lockeren Modus.

set interfaces vti <interface> ipv6 address autoconf

Konfigurieren Sie die Schnittstelle, um automatisch eine IPv6-Adresse mit SLAAC, zu erhalten, wie in RFC 4862 beschrieben.

IPv6-Hosts können sich automatisch konfigurieren, wenn sie sich einem IPv6-Netzwerk anschließen, indem sie das Neighbor Discovery Protocol über ICMPv6-Router-Bekanntmachungen verwenden. Bei der ersten Verbindung zu einem Netzwerk sendet ein Host eine Link-Local-Router-Solicitation-Multicast-Anfrage für seine Konfigurationsparameter. Der Router antwortet mit einem Router-Advertisement-Paket, das Internet-Layer-Konfigurationsparameter enthält.

Hinweis

Diese Methode deaktiviert automatisch die IPv6-Verkehrsweiterleitung auf der Schnittstelle.

Beispiel:

set interfaces vti vti0 ipv6 address autoconf
set interfaces vti <interface> ipv6 address eui64 <prefix>

Konfigurieren Sie die Schnittstelle, um sich selbst eine IPv6-Adresse mit der EUI-64 -Methode zu zuweisen, wie in RFC 4291 beschrieben.

Beispiel:

set interfaces vti vti0 ipv6 address eui64 2001:db8:beef::/64
set interfaces vti <interface> ipv6 address no-default-link-local

Deaktivieren Sie die automatische Zuweisung einer link-lokalen IPv6-Adresse zu dieser Schnittstelle.

Beispiel:

set interfaces vti vti0 ipv6 address no-default-link-local
set interfaces vti <interface> ipv6 disable-forwarding

Konfigurieren Sie die Schnittstelle für Host- oder Router-Verhalten.

Wenn konfiguriert, wechselt die Schnittstelle in Hostmodus und wird IPv6-Weiterleitung deaktiviert.

Beispiel:

set interfaces vti vti0 ipv6 disable-forwarding
set interfaces vti <interface> ipv6 adjust-mss <mss | clamp-mss-to-pmtu>

Konfigurieren Sie die MSS , die in ausgehenden TCP SYN-Paketen auf der angegebenen Schnittstelle angegeben werden.

Durch das Begrenzen des MSS-Werts in TCP SYN-Paketen informieren Sie den entfernten Teilnehmer explizit nicht, Pakete größer als diese Größe zu senden. Dies verhindert Verbindungsprobleme, wenn die Pfad-MTU-Entdeckung (PMTUD) fehlschlägt.

Die folgenden Optionen sind verfügbar:

  • mss: Setzt die MSS auf einen bestimmten Wert in Bytes. Nutzen Sie diese Option, um eine spezifische MSS zu erzwingen, beispielsweise um Verbindungsschwierigkeiten zu beheben oder spezifische Netzwerkanforderungen zu berücksichtigen.

  • clamp-mss-to-pmtu: Der Router berechnet die MSS als MTU der Schnittstelle minus 60 Bytes für IPv6-Datenverkehr (40 Bytes für den IPv6-Header und 20 Bytes für den TCP-Header). Diese Option wird empfohlen, um den richtigen Wert automatisch einzustellen.

set interfaces vti <interface> ipv6 accept-dad <0 | 1 | 2>

Konfigurieren Sie IPv6 DAD auf der Schnittstelle.

Die folgenden Optionen sind verfügbar:

  • 0: Deaktiviert DAD. Es wird keine Duplicate Address Detection durchgeführt.

  • 1: Aktiviert DAD (Standard). Duplicate Addresses werden erkannt. Die IPv6-Operation der Schnittstelle wird fortgesetzt für gültige IPv6-Adressen.

  • 2: Aktiviert DAD und, falls eine MAC-basierte doppelte Link-Local-Adresse gefunden wird, deaktiviert die IPv6-Operation auf dieser Schnittstelle.

Beispiel:

set interfaces vti vti0 ipv6 accept-dad 2
set interfaces vti <interface> ipv6 dup-addr-detect-transmits <n>

Konfigurieren Sie die Anzahl der DAD -Nachrichten, die der Router (Kernel) während der IPv6-Adresszuweisung auf dieser Schnittstelle sendet.

Der Standardwert ist 1.

Beispiel:

set interfaces vti vti0 ipv6 dup-addr-detect-transmits 5
set interfaces vti <interface> mtu <mtu>

Konfigurieren Sie die MTU auf der Schnittstelle.

Dieser Wert definiert die größte Paketgröße in Bytes, die die Schnittstelle ohne Fragmentierung überträgt.

Beispiel:

set interfaces vti vti0 mtu 1600
set interfaces vti <interface> mirror egress <monitor-interface>

Konfigurieren Sie die Spiegelung des ausgehenden Verkehrs von der angegebenen VTI auf die bezeichnete Monitor-Schnittstelle.

set interfaces vti <interface> mirror ingress <monitor-interface>

Konfigurieren Sie die Spiegelung des eingehenden Verkehrs von der angegebenen VTI auf die bezeichnete Monitor-Schnittstelle.

set interfaces vti <interface> redirect <interface>

Enable redirection of incoming packets to the specified interface.

set interfaces vti <interface> vrf <vrf>

Weisen Sie die Schnittstelle einem spezifischen VRF -Instanz zu.

Warnung

Bei der Konfiguration von Site-to-Site-IPsec mit VTIs stellen Sie sicher, dass die Route-Autoinstall-Funktion deaktiviert ist.

set vpn ipsec options disable-route-autoinstall

Weitere Informationen zum IPsec- und VTI-Problem sowie zur Option disable-route-autoinstall, finden Sie unter: https://blog.vyos.io/vyos-1-dot-2-0-development-news-in-july.

Der Grund für das Problem ist, dass VTI-Tunnel ihre Traffic-Selektoren auf 0.0.0.0/0 setzen müssen, damit der Datenverkehr den Tunnel trifft, auch wenn Routing-Entscheidungen auf Netfilter-Marks basieren. Ausgenommen, wenn die Route-Einfügung explizit deaktiviert wird, fügt StrongSWAN fälschlicherweise eine Standardroute über die VTI-Partner-Adresse ein, was dazu führt, dass der gesamte Datenverkehr falsch umgeleitet wird.
