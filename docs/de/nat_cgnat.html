CGNAT

CGNAT, auch bekannt als Large-Scale NAT (LSN), ist ein Typ von Netzwerkadressübersetzung, der von Internetdienstleistern (ISPs) verwendet wird, um mehrere private IP-Adressen zu ermöglichen, um eine einzelne öffentliche IP-Adresse zu teilen. Dieses Verfahren hilft dabei, den begrenzten IPv4-Adressraum zu schonen. Der Adressblock 100.64.0.0/10 ist für die Verwendung in Carrier-Grade NAT reserviert

Übersicht

CGNAT funktioniert, indem ein NAT-Gerät innerhalb des Netzwerks des ISP platziert wird. Dieses Gerät übersetzt private IP-Adressen aus Kundennetzen in einen begrenzten Pool öffentlicher IP-Adressen, die dem ISP zugewiesen sind. Dies ermöglicht es vielen Kunden, eine kleinere Anzahl öffentlicher IP-Adressen zu teilen.

Nicht alle RFC 6888 Anforderungen werden in CGNAT implementiert.

Implementierte folgende RFC 6888 Anforderungen:

  • REQ 2: Ein CGN muss ein Standardverhalten „IP-Adressenpool“ von „Paired“ haben. CGN muss dieselbe externe IP-Adressenzuordnung für alle Sitzungen verwenden, die mit der gleichen internen IP-Adresse verbunden sind, seien sie TCP, UDP, ICMP, etwas anderes oder eine Mischung verschiedener Protokolle.

  • REQ 3: Das CGN-Funktionsverhalten sollte keine Einschränkungen bezüglich der Größe oder Kontinuität des externen Adresspools haben.

  • REQ 4: Ein CGN muss die Anzahl der externen Ports (oder, gleichbedeutend, „Identifikatoren“ für ICMP) beschränken, die pro Abonnent zugewiesen werden.

Vorteile von CGNAT

  • IPv4-Adressen-Sparung: CGNAT hilft, die Erschöpfung von IPv4-Adressen zu vermeiden, indem mehrere Kunden eine einzelne öffentliche IP-Adresse teilen.

  • Skalierbarkeit: ISPs können mehr Kunden unterstützen, ohne dass die Anzahl der öffentlichen IP-Adressen proportional zunehmen muss.

  • Kosteneffizient: Reduziert die Kosten, die mit der Beschaffung zusätzlicher öffentlicher IPv4-Adressen verbunden sind.

Überlegungen

  • Spurprobleme: Da mehrere Benutzer die gleiche öffentliche IP-Adresse teilen, kann es schwierig sein, individuelle Benutzer für Sicherheits- und rechtliche Zwecke zu verfolgen.

  • Leistungsüberhängen: Der Übersetzungsprozess kann Latenz und potenzielle Leistungsengpässe einbringen, insbesondere unter hoher Last.

  • Anwendungs-Kompatibilität: Einige Anwendungen und Protokolle funktionieren möglicherweise nicht gut mit CGNAT, da sie auf eindeutige öffentliche IP-Adressen angewiesen sind.

  • Port-Zuweisungs-Limits: Jede öffentliche IP-Adresse hat eine begrenzte Anzahl an Ports, die erschöpft werden können und die Fähigkeit beeinträchtigen, neue Verbindungen herzustellen.

  • Port-Control-Protokoll: PCP wird nicht implementiert.

Port-Berechnung

Beim Implementieren von CGNAT ist es entscheidend, sicherzustellen, dass genug Ports pro Abonnent zugewiesen werden. Im Folgenden ist eine Zusammenfassung basierend auf RFC 6888.

  1. Gesamte verfügbare Ports:

    • Gesamte Ports: 65536 (0 bis 65535)

    • Reservierte Ports: Angenommen, 1024 Ports sind für bekannte Dienste und administrative Zwecke reserviert.

    • Nutzbare Ports: 65536 - 1024 = 64512

  2. Schätzung der benötigten Ports pro Abonnent:

    • Beispiel: Ein Haushalt könnte 1000 Ports benötigen, um eine reibungslose Funktion für mehrere Geräte und Anwendungen zu gewährleisten.

  3. Berechnung der Anzahl der Abonnenten pro öffentliche IP:

    • Nutzbare Ports / Ports pro Abonnent

    • 64512 / 1000 ≈ 64 Abonnenten pro öffentliche IP

Konfiguration

set nat cgnat pool external <pool-name> external-port-range <port-range>

Legt einen externen Portbereich für den externen Pool fest, der Standardbereich ist 1024-65535. Mehrere Einträge können demselben Pool hinzugefügt werden.

set nat cgnat pool external <pool-name> per-user-limit port <num>

Legt externe Quellportbegrenzungen fest, die jedem Abonnenten individuell zugewiesen werden. Der Standardwert ist 2000.

set nat cgnat pool external <pool-name> range [address | address range | network] [seq]

Legt den Bereich der externen IP-Adressen für den CGNAT-Pool fest. Die Sequenz ist optional; wenn gesetzt, bedeutet ein niedrigerer Wert eine höhere Priorität.

set nat cgnat pool internal <pool-name> range [address range | network]

Legt den Bereich der internen IP-Adressen für den CGNAT-Pool fest.

set nat cgnat rule <num> source pool <internal-pool-name>

Legt die Regel für den Quellpool fest.

set nat cgnat rule <num> translation pool <external-pool-name>

Legt die Regel für den Übersetzungs-Pool fest.

set nat cgnat log-allocation

Enable logging of IP address and ports allocations.

Konfigurationsbeispiele

Eine externe Adresse

Beispiel für die Einrichtung einer grundlegenden CGNAT-Konfiguration: Im folgenden Beispiel definieren wir einen externen Pool mit dem Namen ext-1 mit einer externen IP-Adresse.

Jeder Abonnent erhält maximal 2000 Ports aus dem externen Pool.

set nat cgnat pool external ext1 external-port-range '1024-65535'
set nat cgnat pool external ext1 per-user-limit port '2000'
set nat cgnat pool external ext1 range '192.0.2.222/32'
set nat cgnat pool internal int1 range '100.64.0.0/28'
set nat cgnat rule 10 source pool 'int1'
set nat cgnat rule 10 translation pool 'ext1'

Mehrere externe Adressen

set nat cgnat pool external ext1 external-port-range '1024-65535'
set nat cgnat pool external ext1 per-user-limit port '8000'
set nat cgnat pool external ext1 range '192.0.2.1-192.0.2.2'
set nat cgnat pool external ext1 range '203.0.113.253-203.0.113.254'
set nat cgnat pool internal int1 range '100.64.0.1-100.64.0.32'
set nat cgnat rule 10 source pool 'int1'
set nat cgnat rule 10 translation pool 'ext1'

Externe Adresssequenzen

set nat cgnat pool external ext-01 per-user-limit port '16000'
set nat cgnat pool external ext-01 range 203.0.113.1/32 seq '10'
set nat cgnat pool external ext-01 range 192.0.2.1/32 seq '20'
set nat cgnat pool internal int-01 range '100.64.0.0/29'
set nat cgnat rule 10 source pool 'int-01'
set nat cgnat rule 10 translation pool 'ext-01'
