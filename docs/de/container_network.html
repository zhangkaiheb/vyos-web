Container

Die VyOS-Containerimplementierung basiert auf Podman als daemonloser Container-Engine.

Konfiguration

set container name <name> image

Legt den Image-Namen im Hub-Registry fest

set container name mysql-server image mysql:8.0

Wenn kein Registry angegeben wird, wird Docker.io als Container-Registry verwendet, es sei denn, ein alternativer Registry wird mit set container registry <name> oder der Registry ist in dem Image-Name enthalten.

set container name mysql-server image quay.io/mysql:8.0
set container name <name> entrypoint <entrypoint>

Überschreibt den Standard-Entrypoint des Images für einen Container.

set container name <name> command <command>

Überschreibt den Standard-Befehl des Images für einen Container.

set container name <name> arguments <arguments>

Setzt die Befehlsargumente für einen Container.

set container name <name> host-name <hostname>

Setzt den Hostnamen für einen Container.

set container name <name> allow-host-pid

Der Container und der Host teilen sich dasselbe Prozessnamespace. Das bedeutet, dass Prozesse, die auf dem Host laufen, im Container sichtbar sind, und Prozesse im Container sind auf dem Host sichtbar.

Der Befehl übersetzt sich zu „–pid host“ beim Erstellen des Containers.

set container name <name> allow-host-networks

Erlaubt Netzwerkzugriff des Hosts in einem Container. Der Netzwerkspeicher des Containers ist nicht von dem des Hosts isoliert und verwendet die IP des Hosts.

Der Befehl übersetzt sich zu „–net host“ beim Erstellen des Containers.

Hinweis

allow-host-networks kann nicht mit network verwendet werden

set container name <name> network <networkname>

Hängt ein benutzerdefiniertes Netzwerk an einen Container an. Es muss nur ein Netzwerk angegeben werden und muss bereits existieren.

set container name <name> network <networkname> address <address>

Legt optional eine spezifische statische IPv4- oder IPv6-Adresse für den Container fest. Diese Adresse muss innerhalb des benannten Netzwerkpräfixes liegen.

Hinweis

Die erste IP im Container-Netzwerk wird vom Engine reserviert und kann nicht verwendet werden

set container name <name> name-server <address>

Legt optional einen benutzerdefinierten Namenserver fest. Wenn ein Container-Netzwerk mit aktiviertem DNS verwendet wird, wirkt sich diese Einstellung nicht aus.

set container name <name> description <text>

Setzt eine Container-Beschreibung

set container name <name> environment <key> value <value>

Fügt benutzerdefinierte Umgebungsvariablen hinzu. Mehrere Umgebungsvariablen sind erlaubt. Die folgenden Befehle übersetzen sich zu „-e key=value“ beim Erstellen des Containers.

set container name mysql-server environment MYSQL_DATABASE value 'zabbix'
set container name mysql-server environment MYSQL_USER value 'zabbix'
set container name mysql-server environment MYSQL_PASSWORD value 'zabbix_pwd'
set container name mysql-server environment MYSQL_ROOT_PASSWORD value 'root_pwd'
set container name <name> port <portname> source <portnumber>
set container name <name> port <portname> destination <portnumber>
set container name <name> port <portname> protocol <tcp | udp>

Veröffentlicht einen Port für den Container.

set container name zabbix-web-nginx-mysql port http source 80
set container name zabbix-web-nginx-mysql port http destination 8080
set container name zabbix-web-nginx-mysql port http protocol tcp

Hinweis

Portveröffentlichung kann nicht mit network verwendet werden. Für diesen Zweck ist ein Workaround verfügbar, der Destination NAT und statische IP-Zuweisung für den Container verwendet.

set container name <name> volume <volumename> source <path>
set container name <name> volume <volumename> destination <path>

Mountet ein Volume in den Container

set container name coredns volume 'corefile' source /config/coredns/Corefile
set container name coredns volume 'corefile' destination /etc/Corefile
set container name <name> volume <volumename> mode <ro | rw>

Das Volume wird entweder als rw (read-write - Standard) oder ro (read-only) gemountet

set container name <name> tmpfs <tmpfsname> destination <path>

Mountet ein tmpfs (RAM-Disk) Dateisystem an den gegebenen Pfad innerhalb des Containers.

set container name <name> tmpfs <tmpfsname> size <MB>

Größe in MB für das tmpfs-Dateisystem, maximale Größe ist 64 GB oder 50 % des verfügbaren Systemspeichers.

set container name <name> uid <number>
set container name <name> gid <number>

Setzt die User ID oder Group ID des Containers

set container name <name> restart [no | on-failure | always]

Setzt das Wiederstartverhalten des Containers.

  • no: Startet Container nicht neu bei Beendigung

  • on-failure: Startet Container neu, wenn sie mit einem nicht-null Exit-Code beendet werden, unendlich oft wiederholen (Standard)

  • always: Startet Container neu, wenn sie beendet werden, unabhängig vom Status, unendlich oft wiederholen

set container name <name> cpu-quota <num>

Dies gibt die Anzahl der CPU-Ressourcen an, die der Container verwenden kann.

Standardwert ist 0 für unbegrenzt. Zum Beispiel 1.25 begrenzt den Container auf bis zu 1.25 Kerne Wert der CPU-Zeit. Dies kann eine Dezimalzahl mit bis zu drei Dezimalstellen sein.

Der Befehl übersetzt sich zu „–cpus=<num>“ beim Erstellen des Containers.

set container name <name> memory <MB>

Beschränkt den Speicher, der dem Container zur Verfügung steht.

Standardwert ist 512 MB. Verwenden Sie 0 MB für unbegrenzten Speicher.

set container name <name> device <devicename> source <path>
set container name <name> device <devicename> destination <path>

Fügt ein Hostgerät dem Container hinzu.

set container name <name> capability <text>

Setzt Container-Fähigkeiten oder Berechtigungen.

  • net-admin: Netzwerkoperationen (Schnittstelle, Firewall, Routing-Tabellen)

  • net-bind-service: Binden eines Sockets an privilegierte Ports (Nummern kleiner als 1024)

  • net-raw: Berechtigung zum Erstellen von Roh-Netzwerk-Sockets

  • setpcap: Fähigkeits-Sets (aus eingeschränktem oder geerbtem Set)

  • sys-admin: Administrationsoperationen (quotactl, mount, sethostname, setdomainame)

  • sys-time: Berechtigung, den Systemuhrzeit zu setzen

set container name <name> sysctl parameter <parameter> value <value>

Setzt Container-Sysctl-Werte.

Die Teilmenge möglicher Parameter sind:

  • Kernel-Parameter: kernel.msgmax, kernel.msgmnb, kernel.msgmni, kernel.sem, kernel.shmall, kernel.shmmax, kernel.shmmni, kernel.shm_rmid_forced

  • Parameter, die mit fs.mqueue.* beginnen

  • Parameter, die mit net.* beginnen (nur wenn ein benutzerdefiniertes Netzwerk verwendet wird)

set container name <name> label <label> value <value>

Fügt Metadaten-Label für diesen Container hinzu.

set container name <name> disable

Deaktiviert einen Container.

Container Gesundheitschecks

Standardmäßig werden keine Gesundheitschecks ausgeführt, selbst wenn sie durch das Bild definiert sind.

set container name <name> health-check

Standardgesundheitscheck wird für den Container ausgeführt, falls durch das Bild definiert.

set container name <name> health-check command <command>

Überschreibt den Standard-Gesundheitscheck-Befehl des Bildes für einen Container.

set container name <name> health-check interval <interval>

Überschreibt das Standard-Gesundheitscheck-Intervall. Zum Beispiel: 60

set container name <name> health-check timeout <timeout>

Überschreibt das Standard-Gesundheitscheck-Timeout. Zum Beispiel: 10

set container name <name> health-check retries <retries>

Anzahl der Gesundheitscheck-Wiederholungen, bevor der Container als ungesund betrachtet wird. Zum Beispiel: 1

Container Netzwerke

set container network <name>

Erstellt ein benanntes Container-Netzwerk

set container network <name> description

Eine kurze Beschreibung, was dieses Netzwerk alles umfasst.

set container network <name> prefix <ipv4|ipv6>

Definiert IPv4 und/oder IPv6 Präfix für einen bestimmten Netzwerknamen. Beide IPv4 und IPv6 können parallel verwendet werden.

set container network <name> mtu <number>

Konfiguriert MTU für ein bestimmtes Netzwerk. Es ist die Größe (in Bytes) des größten Ethernet-Frames, der auf diesem Link gesendet wird.

set container network <name> no-name-server

Deaktiviert den Domain Name System (DNS)-Plugin für dieses Netzwerk.

set container network <name> vrf <name>

Bindet das Container-Netzwerk an eine bestimmte VRF-Instanz.

Container Registry

set container registry <name>

Fügt Registry zur Liste der unqualifizierten Such-Registries hinzu. Standardmäßig verwendet VyOS für jedes Bild, das den Registry in dem Bildnamen nicht enthält, docker.io und quay.io als Container-Registry.

set container registry <name> disable

Deaktiviert einen bestimmten Container-Registry

set container registry <name> authentication username
set container registry <name> authentication password

Einige Container-Registries benötigen Anmeldeinformationen, um verwendet zu werden.

Anmeldeinformationen können hier definiert werden und werden nur verwendet, wenn ein Container-Bild dem System hinzugefügt wird.

set container registry <name> insecure

Erlaubt den Zugriff auf Registry über unverschlüsselte HTTP- oder TLS-Verbindungen mit unvertrauten Zertifikaten.

set container registry <name> mirror address <address>
set container registry <name> mirror host-name <host-name>
set container registry <name> mirror port <port>
set container registry <name> mirror path <path>

Registry-Mirror, verwende (host-name|address)[:port][/path].

Wenn du einen Mirror http://192.168.1.1:8080 für docker.io hast, kannst du docker.io/some/repo oder podman pull docker.io/some/repo ausführen

set container registry docker.io mirror address 192.168.1.1
set container registry docker.io mirror port 8080
set container registry docker.io insecure

Wenn http://192.168.1.1:8080 dein eigenes Registry ist, kannst du 192.168.1.1:8080/some/repo oder podman pull 192.168.1.1:8080/some/repo ausführen

set container registry 192.168.1.1:8080 insecure

Log-Konfiguration

set container name <name> log-driver [k8s-file | journald | none]

Setzt den Standard-Log-Treiber für Container.

  • k8s-file: Loggt in eine Textdatei im Kubernetes-Stil.

  • journald: Loggt in das Systemjournal

  • none: Deaktiviert das Logging für den Container

Der aktuelle Standard ist journald.

Betriebsbefehle

add container image <containername>

Downloadet ein neues Image für den Container

show container

Listet alle aktiven Container auf.

show container image

Listet lokale Container-Images auf.

show container log <containername>

Listet Logs aus einem gegebenen Container

show container network

Listet verfügbare Container-Netzwerke auf

restart container <containername>

Neustart eines gegebenen Containers

update container image <containername>

Aktualisiert Container-Image

delete container image <image id|all> [force]

Löscht ein bestimmtes Container-Image basierend auf seiner Image-ID. Sie können auch alle Container-Images gleichzeitig löschen.

Sie können ein Container-Image nicht löschen, wenn es mehr als ein Tag hat, daher gibt es eine force-Option, um diese Bilder auch zu entfernen.
