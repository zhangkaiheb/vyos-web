L2TPv3

L2TPv3 Schnittstellen ermöglichen es Ihnen, L2TPv3-Tunnel zu erstellen, um Layer-2-Datenverkehr über IP-Netzwerke zu transportieren.

Das L2TPv3-Protokoll (gemäß RFC 3931) umschließt Layer-2-Frames (z. B. Ethernet, Frame Relay, HDLC) innerhalb von IP-Paketen, wodurch sie den zugrunde liegenden IP-Infrastruktur durchqueren können.

Im Gegensatz zu L2TPv2, das strikt UDP-Encapsulation erfordert, ist das L2TPv3-Protokoll flexibler und unterstützt zwei Encapsulation-Typen:

  • Direktes IP: Tunnel-Daten werden direkt in IP-Pakete (Protokoll 115) eingepackt, um Overhead zu reduzieren.

  • UDP: Tunnel-Daten werden in ein UDP-Datagramm eingepackt. Dies ermöglicht es dem Tunnel, leichter durch NAT zu gelangen.

L2TPv3-Tunnel verbinden geografisch getrennte Standorte und dienen als einfachere Alternative zu MPLS, indem sie über grundlegende IP-Konnektivität statt über eine vollständige MPLS-Infrastruktur funktionieren.

L2TPv3-Tunnel können über sowohl IPv4- als auch IPv6-Untergrundnetze eingerichtet werden.

Konfiguration

Gemeinsame Schnittstellenkonfiguration

set interfaces l2tpv3 <interface> address <address>

Konfigurieren Sie eine oder mehrere Schnittstellen-IP-Adressen.

<address> unterstützt IPv4 und IPv6 in CIDR-Schreibweise. Beispiel: Verwenden Sie 192.0.2.1/24 für IPv4 oder 2001:db8::1/64 für IPv6.

Beispiel:

set interfaces l2tpv3 l2tpeth0 address 192.0.2.1/24
set interfaces l2tpv3 l2tpeth0 address 2001:db8::1/64
set interfaces l2tpv3 <interface> description <description>

Konfigurieren Sie einen klaren, beschreibenden Alias für die Schnittstelle.

Dieser Alias erscheint im Befehl show interfaces und in SNMP-basierten Überwachungstools.

Beispiel:

set interfaces l2tpv3 l2tpeth0 description 'This is an interface running on VyOS.'
set interfaces l2tpv3 <interface> disable

Deaktivieren Sie die Schnittstelle.

Die Schnittstelle wird auf den administrativ heruntergefahrenen Zustand (A/D) gesetzt.

Beispiel:

set interfaces l2tpv3 l2tpeth0 disable
set interfaces l2tpv3 <interface> disable-flow-control

Deaktivieren Sie die Ethernet-Flow-Control (IEEE 802.3x Pause Frames) auf der Schnittstelle.

Ethernet-Flow-Control, definiert durch den IEEE 802.3x-Standard, stoppt vorübergehend die Datenübertragung, um Paketverluste während Netzwerkengpässe zu vermeiden. Zum Beispiel, wenn ein Sender Daten schneller überträgt, als der Empfänger verarbeiten kann.

Das Deaktivieren der Ethernet-Flow-Control bedeutet, dass die Schnittstelle nicht signalisiert, dass das angeschlossene Gerät die Übertragung pausieren soll, und Pakete abwirft, wenn sie überfordert sind.

Beispiel:

set interfaces l2tpv3 l2tpeth0 disable-flow-control
set interfaces l2tpv3 <interface> disable-link-detect

Deaktivieren Sie die Erkennung physischer Link-Zustandsänderungen auf der Schnittstelle, z. B. wenn ein Kabel gezogen wird.

Standardmäßig erkennt die Schnittstelle physische Link-Zustandsänderungen.

Beispiel:

set interfaces l2tpv3 l2tpeth0 disable-link-detect
set interfaces l2tpv3 <interface> mac <xx:xx:xx:xx:xx:xx>

Konfigurieren Sie eine benutzerdefinierte MAC-Adresse auf der Schnittstelle.

Beispiel:

set interfaces l2tpv3 l2tpeth0 mac '00:53:01:02:03:04'
set interfaces l2tpv3 <interface> mtu <mtu>

Konfigurieren Sie das MTU auf der Schnittstelle.

Der Wert definiert die größte Paketgröße in Bytes, die die Schnittstelle ohne Fragmentierung überträgt.

Beispiel:

set interfaces l2tpv3 l2tpeth0 mtu 1600
set interfaces l2tpv3 <interface> ip adjust-mss <mss | clamp-mss-to-pmtu>

Konfigurieren Sie die MSS die in ausgehenden TCP SYN-Paketen auf der angegebenen Schnittstelle angezeigt wird.

Durch das Erschweren des MSS-Werts in TCP SYN-Paketen informieren Sie den Remote-Partner explizit, dass keine Pakete größer als diese Größe gesendet werden sollen. Dies verhindert Verbindungsprobleme, die auftreten, wenn die Pfad-MTU-Entdeckung (PMTUD) fehlschlägt.

Die folgenden Optionen stehen zur Verfügung:

  • mss: Legt die MSS auf einen bestimmten Wert in Bytes fest. Verwenden Sie diese Option, wenn Sie eine spezifische MSS erzwingen möchten, z. B. um Verbindungsprobleme zu beheben oder spezifische Netzwerkbedürfnisse zu berücksichtigen.

  • clamp-mss-to-pmtu: Der Router berechnet den MSS automatisch als den MTU der Schnittstelle minus 40 Bytes für IPv4-Datenverkehr (20 Bytes für den IPv4-Header und 20 Bytes für den TCP-Header). Diese Option wird empfohlen, um den richtigen Wert automatisch zu setzen.

set interfaces l2tpv3 <interface> ip arp-cache-timeout

Konfigurieren Sie, wie lange ein ARP-Eintrag gültig bleibt, nachdem eine IP-zu-MAC-Adresse-Zuordnung auf dieser Schnittstelle gelernt wurde.

Die Standarddauer beträgt 30 Sekunden.

Ein ARP-Eintrag bleibt gültig, wenn er positives Feedback von höheren Protokollen erhält.

Beispiel:

set interfaces l2tpv3 l2tpeth0 ip arp-cache-timeout 180
set interfaces l2tpv3 <interface> ip disable-arp-filter

Konfigurieren Sie die ARP-Filterung auf dieser Schnittstelle.

Standardverhalten: Das Kernel antwortet auf ARP-Anfragen auf dieser Schnittstelle nur, wenn der Datenverkehr über diese spezifische Schnittstelle zurück zum ARP-Sender geroutet wird.

Wenn konfiguriert: Das Kernel antwortet auf ARP-Anfragen auf dieser Schnittstelle für jede IP-Adresse, die auf dem lokalen Host konfiguriert ist, unabhängig davon, welche spezifische Schnittstelle diese IP-Adresse zugewiesen ist, und unabhängig vom Routing-Tabellen. Dies spiegelt das Linux-Konzept wider, dass IP-Adressen dem Host gehören, nicht individuellen Schnittstellen.

Beispiel:

set interfaces l2tpv3 l2tpeth0 ip disable-arp-filter
set interfaces l2tpv3 <interface> ip disable-forwarding

Konfigurieren Sie das Verhalten der Schnittstelle als Host oder Router.

Wenn konfiguriert, wechselt die Schnittstelle in den Host-Modus und wird IPv4-Weiterleitung deaktiviert.

Beispiel:

set interfaces l2tpv3 l2tpeth0 ip disable-forwarding
set interfaces l2tpv3 <interface> ip enable-directed-broadcast

Konfigurieren Sie, ob IP-gerichtete Broadcast-Pakete, die auf dieser Schnittstelle empfangen werden, weitergeleitet werden.

Standardverhalten: IP-gerichtete Broadcast-Pakete werden abgelehnt.

Wenn konfiguriert: IP-gerichtete Broadcast-Pakete werden an alle Hosts auf dem Ziel-Subnetz weitergeleitet, gemäß RFC 1812 und RFC 2644.

Beispiel:

set interfaces l2tpv3 l2tpeth0 ip enable-directed-broadcast
set interfaces l2tpv3 <interface> ip enable-arp-accept

Konfigurieren Sie, wie mit kostenlosen ARPs auf dieser Schnittstelle umgegangen wird.

Wenn konfiguriert, wird eine IP-zu-MAC-Zuordnung in die ARP-Tabelle basierend auf kostenlosen ARP-Anfragen oder Antworten hinzugefügt.

Hinweis

Wenn die ARP-Tabelle bereits eine IP-Adresse aus einem kostenlosen ARP enthält, wird deren Eintrag aktualisiert, unabhängig davon, ob diese Einstellung konfiguriert ist.

Beispiel:

set interfaces l2tpv3 l2tpeth0 ip enable-arp-accept
set interfaces l2tpv3 <interface> ip enable-arp-announce

Konfigurieren Sie die Quell-IP-Auswahl für ARP-Anfragen auf dieser Schnittstelle.

Standardverhalten: Das Kernel kann jede IP-Adresse verwenden, die der Host besitzt, als Quell-IP-Adresse in ARP-Anfragen auf dieser Schnittstelle.

Wenn konfiguriert: Das Kernel versucht zunächst, eine Quell-IP-Adresse auszuwählen, die auf der Schnittstelle konfiguriert ist und mit dem Ziel-IP-Adress-Subnetz übereinstimmt. Wenn kein solches Subnetz vorhanden ist, wählt das Kernel die IP-Adresse aus, die es normalerweise verwenden würde (basierend auf der Routing-Tabelle, um das Zielziel zu erreichen).

Beispiel:

set interfaces l2tpv3 l2tpeth0 ip enable-arp-announce
set interfaces l2tpv3 <interface> ip enable-arp-ignore

Konfigurieren Sie, welche ARP-Anfragen auf dieser Schnittstelle ignoriert werden.

Standardverhalten: Das Kernel antwortet auf ARP-Anfragen für beliebige lokale IP-Adressen, unabhängig davon, welcher Schnittstelle sie zugewiesen sind.

Wenn konfiguriert: Das Kernel antwortet nur auf ARP-Anfragen, wenn die Ziel-IP-Adresse dieser spezifischen Schnittstelle zugewiesen ist.

Beispiel:

set interfaces l2tpv3 l2tpeth0 ip enable-arp-ignore
set interfaces l2tpv3 <interface> ip enable-proxy-arp

Konfigurieren Sie Proxy ARP auf dieser Schnittstelle.

Wenn konfiguriert, empfängt der Router (Kernel) ARP-Anfragen für nicht lokale IP-Adressen und antwortet mit der MAC-Adresse der Schnittstelle, die die Anfrage empfangen hat. Danach werden Pakete, die an diese IP-Adressen gerichtet sind, an ihre tatsächlichen Ziele auf entfernten Subnetzen weitergeleitet.

Beispiel:

set interfaces l2tpv3 l2tpeth0 ip enable-proxy-arp
set interfaces l2tpv3 <interface> ip proxy-arp-pvlan

Konfigurieren Sie lokales Proxy ARP auf der Schnittstelle.

Wenn konfiguriert, antwortet der Router (Kernel) auf ARP-Anfragen auf dieser VLAN-Schnittstelle, selbst wenn die Ziel-IP-Adresse auf dem gleichen Subnetz und der gleichen Schnittstelle liegt.

Dies wird verwendet, um Netzwerkisolationsanforderungen (RFC 3069) für private VLANs (PVLANs) zu unterstützen. In PVLAN-Konfigurationen dürfen Geräte auf isolierten Ports nicht direkt miteinander kommunizieren, aber sie können mit dem Upstream-Router kommunizieren.

Durch die Antwort auf inter-host ARP-Anfragen mit seiner eigenen MAC-Adresse leitet der Router (Kernel) den inter-host-Datenverkehr durch sich selbst anstatt direkt zwischen Hosts.

Hinweis

Dieser Befehl funktioniert unabhängig und erfordert nicht, dass der Standard-Proxy ARP auf der Schnittstelle aktiviert ist.

Lokales Proxy ARP ist auch bekannt als:

  • VLAN-Aggregation (RFC 3069).

  • Private VLAN (Cisco, Allied Telesyn).

  • Source-port filtering oder Port-Isolation (Hewlett-Packard).

  • MAC-Forced Forwarding (Ericsson).

set interfaces l2tpv3 <interface> ip source-validation <strict | loose | disable>

Konfigurieren Sie die Quell-IP-Adressen-Überprüfung mit RPF auf dieser Schnittstelle, wie in RFC 3704 angegeben.

Die folgenden Optionen sind verfügbar:

  • strict: Die Quell-IP-Adresse jedes eingehenden Pakets wird gegen die Forwarding Information Base (FIB) überprüft. Wenn die Schnittstelle nicht der beste Weg zurück zu dieser Quelle ist, schlägt die Validierung fehl und das Paket wird verworfen.

  • loose: Die Quell-IP-Adresse jedes eingehenden Pakets wird gegen die FIB überprüft. Wenn die Quell-IP-Adresse durch irgendeine Schnittstelle nicht erreichbar ist, schlägt die Validierung fehl.

  • disable: Es wird keine Quell-IP-Adressen-Überprüfung durchgeführt. Alle eingehenden Pakete werden akzeptiert.

RFC 3704 empfiehlt, den strengen Modus zu aktivieren, um IP-Spoofing, wie DDoS-Angriffe, zu verhindern. Für asynchrone oder komplexe Routing-Szenarien verwenden Sie den lockeren Modus.

set interfaces l2tpv3 <interface> ipv6 address autoconf

Konfigurieren Sie die Schnittstelle, um automatisch eine IPv6-Adresse mit SLAAC, zu erhalten, wie in RFC 4862 festgelegt.

IPv6-Hosts können sich automatisch konfigurieren, wenn sie mit einem IPv6-Netzwerk verbunden sind, unter Verwendung des Neighbor Discovery Protocols via ICMPv6 Router Discovery Nachrichten. Bei der ersten Verbindung zu einem Netzwerk sendet ein Host eine link-local Router Solicitation Multicast Anfrage für seine Konfigurationsparameter. Der Router antwortet mit einer Router Advertisement Paket, das Internet Layer Konfigurationsparameter enthält.

Hinweis

Diese Methode deaktiviert automatisch IPv6 Traffic Forwarding auf der Schnittstelle.

Beispiel:

set interfaces l2tpv3 l2tpeth0 ipv6 address autoconf
set interfaces l2tpv3 <interface> ipv6 address eui64 <prefix>

Konfigurieren Sie die Schnittstelle, um sich selbst eine IPv6-Adresse mit dem EUI-64 Verfahren zu geben, wie in RFC 4291 festgelegt.

Beispiel:

set interfaces l2tpv3 l2tpeth0 ipv6 address eui64 2001:db8:beef::/64
set interfaces l2tpv3 <interface> ipv6 address no-default-link-local

Deaktivieren Sie die automatische Zuweisung einer link-local IPv6-Adresse zu dieser Schnittstelle.

Beispiel:

set interfaces l2tpv3 l2tpeth0 ipv6 address no-default-link-local
set interfaces l2tpv3 <interface> ipv6 disable-forwarding

Konfigurieren Sie das Verhalten der Schnittstelle als Host oder Router.

Wenn konfiguriert, wechselt die Schnittstelle in den Host-Modus und wird IPv6-Weiterleitung deaktiviert.

Beispiel:

set interfaces l2tpv3 l2tpeth0 ipv6 disable-forwarding
set interfaces l2tpv3 <interface> ipv6 adjust-mss <mss | clamp-mss-to-pmtu>

Konfigurieren Sie die MSS die in ausgehenden TCP SYN-Paketen auf der angegebenen Schnittstelle angezeigt wird.

Durch das Erschweren des MSS-Werts in TCP SYN-Paketen informieren Sie den Remote-Partner explizit, dass keine Pakete größer als diese Größe gesendet werden sollen. Dies verhindert Verbindungsprobleme, wenn die Pfad-MTU-Entdeckung (PMTUD) fehlschlägt.

Die folgenden Optionen sind verfügbar:

  • mss: Setzt die MSS auf einen bestimmten Wert in Bytes. Verwenden Sie diese Option, um eine spezifische MSS zu erzwingen, z. B. um Verbindungsprobleme zu beheben oder spezifische Netzwerkbedürfnisse zu berücksichtigen.

  • clamp-mss-to-pmtu: Der Router berechnet die MSS als den MTU der Schnittstelle minus 60 Bytes für IPv6-Datenverkehr (40 Bytes für den IPv6-Header und 20 Bytes für den TCP-Header). Diese Option wird empfohlen, um den richtigen Wert automatisch zu setzen.

set interfaces l2tpv3 <interface> ipv6 accept-dad <0 | 1 | 2>

Konfigurieren Sie IPv6 DAD auf der Schnittstelle.

Die folgenden Optionen sind verfügbar:

  • 0: Deaktiviert DAD. Es wird keine Duplicate Address Detection durchgeführt.

  • 1: Aktiviert DAD (Standard). Duplicate Addresses werden erkannt. Die IPv6-Operation der Schnittstelle geht weiter für gültige IPv6-Adressen.

  • 2: Aktiviert DAD und, falls eine MAC-basierte duplicate link-local Adresse gefunden wird, deaktiviert IPv6-Operation auf dieser Schnittstelle.

Beispiel:

set interfaces l2tpv3 l2tpeth0 ipv6 accept-dad 2
set interfaces l2tpv3 <interface> ipv6 dup-addr-detect-transmits <n>

Konfigurieren Sie die Anzahl der DAD Nachrichten, die der Router (Kernel) während der IPv6-Adresszuweisung auf dieser Schnittstelle sendet.

Der Standardwert ist 1.

Beispiel:

set interfaces l2tpv3 l2tpeth0 ipv6 dup-addr-detect-transmits 5
set interfaces l2tpv3 <interface> vrf <vrf>

Weisen Sie die Schnittstelle einem bestimmten VRF Instanz zu.

Siehe auch

Informationen zur Konfiguration eines VRF finden Sie im Abschnitt VRF.

Beispiel:

set interfaces l2tpv3 l2tpeth0 vrf red

L2TPv3-Optionen

Verwenden Sie die folgenden Befehle, um die spezifischen Parameter des L2TPv3-Tunnels zu konfigurieren.

set interfaces l2tpv3 <interface> encapsulation <udp | ip>

Konfigurieren Sie den Encapsulation-Typ für den L2TPv3-Tunnel.

Gültige Werte sind udp und ip.

Der Standard-Encapsulation-Typ ist udp.

Hinweis

Der Encapsulation-Typ muss auf beiden lokalen und remote Peers übereinstimmen, damit der Tunnel eingerichtet werden kann.

set interfaces l2tpv3 <interface> source-address <address>

Konfigurieren Sie die Quell-IP-Adresse des L2TPv3-Tunnels.

Die angegebene Adresse muss eine lokale Schnittstellen-IP-Adresse sein und kann entweder IPv4 oder IPv6 sein.

set interfaces l2tpv3 <interface> remote <address>

Konfigurieren Sie die Ziel-IP-Adresse des L2TPv3-Tunnels.

Die angegebene Adresse muss eine IP-Adresse des Remote-Peers sein und kann entweder IPv4 oder IPv6 sein.

set interfaces l2tpv3 <interface> session-id <id>

Konfigurieren Sie die lokale Session-ID innerhalb des L2TPv3-Tunnels.

Die session-id ist ein 32-Bit-Wert, der eine eingehende Tunnel-Session auf dem lokalen Peer identifiziert.

Die peer-session-id, die diese Session auf dem Remote-Peer identifiziert, muss denselben Wert haben.

set interfaces l2tpv3 <interface> peer-session-id <id>

Konfigurieren Sie die Peer-Session-ID innerhalb des L2TPv3-Tunnels.

Die peer-session-id ist ein 32-Bit-Wert, der eine ausgehende Tunnel-Session vom lokalen Peer identifiziert.

Die peer-session-id muss mit der session-id übereinstimmen, die für diese Session auf dem Remote-Peer konfiguriert ist.

set interfaces l2tpv3 <interface> tunnel-id <id>

Konfigurieren Sie den lokalen Bezeichner des L2TPv3-Tunnels.

Die tunnel-id ist ein 32-Bit-Wert, der den L2TPv3-Tunnel auf dem lokalen Peer identifiziert.

Die peer-tunnel-id, die diesen Tunnel auf dem Remote-Peer identifiziert, muss denselben Wert haben.

set interfaces l2tpv3 <interface> peer-tunnel-id <id>

Konfigurieren Sie den Peer-Bezeichner des L2TPv3-Tunnels.

Die peer-tunnel-id ist ein 32-Bit-Wert, der den L2TPv3-Tunnel auf dem Remote-Peer identifiziert und muss mit der tunnel-id übereinstimmen, die für diesen Tunnel auf diesem Peer konfiguriert ist.

Die peer-tunnel-id muss mit der tunnel-id übereinstimmen, die diesen Tunnel auf dem Remote-Peer identifiziert.

Beispiel

L2TPv3-Tunnel mit IP-Encapsulation

Das folgende Beispiel zeigt die Konfiguration eines L2TPv3-Tunnels mit direkter IP-Encapsulation:

# show interfaces l2tpv3
l2tpv3 l2tpeth10 {
    address 192.168.37.1/27
    encapsulation ip
    source-address 192.0.2.1
    peer-session-id 100
    peer-tunnel-id 200
    remote 203.0.113.24
    session-id 100
    tunnel-id 200
}

Die inverse Konfiguration muss auf dem Remote-Peer angewandt werden.

L2TPv3-Tunnel mit UDP-Encapsulation

Das folgende Beispiel zeigt die Konfiguration eines L2TPv3-Tunnels mit UDP-Encapsulation.

Diese Einrichtung wird empfohlen, wenn der Tunnel NAT-Geräte durchläuft.

Konfigurationsnotizen:

  • Verwenden Sie eine lokale LAN-IP-Adresse als source-address.

  • Konfigurieren Sie eine Weiterleitungsregel, um Tunnelverkehr auf dem angegebenen UDP-Port auf dem upstream NAT-Gerät zu erlauben.

  • Verwenden Sie einen unterschiedlichen UDP-Port für jeden einzelnen Tunnel.

# show interfaces l2tpv3
l2tpv3 l2tpeth10 {
    address 192.168.37.1/27
    destination-port 9001
    encapsulation udp
    source-address 192.0.2.1
    peer-session-id 100
    peer-tunnel-id 200
    remote 203.0.113.24
    session-id 100
    source-port 9000
    tunnel-id 200
}
