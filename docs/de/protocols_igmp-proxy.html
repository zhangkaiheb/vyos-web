IGMP Proxy

Der IGMP-Proxy ermöglicht es Routern, Multicast-Datenverkehr, wie IPTV oder Video-Streams, zwischen verschiedenen Netzwerken, wie Heimnetzwerken und ISP's, zu übertragen. Der IGMP-Proxy verlässt sich auf eine Upstream-Schnittstelle, die gegenüber Upstream-Multicast-Quellen liegt, und eine oder mehrere Downstream-Schnittstellen, die gegenüber lokalen Netzwerken oder Hosts liegen und den Datenverkehr an anfragende Clients weiterleiten.

Die IGMP-Proxy-Konfiguration erfordert genau eine Upstream-Schnittstelle und mindestens eine Downstream-Schnittstelle.

Konfiguration

set protocols igmp-proxy interface <interface> role <upstream | downstream>

Konfigurieren Sie den Betriebsmodus für die angegebene IGMP-Proxy-Schnittstelle.

  • upstream: Kommuniziert mit Upstream-Multicast-Quellen, um den Multicast-Datenverkehr abzufragen. Eine gültige Konfiguration erfordert genau eine Upstream-Schnittstelle.

  • downstream: Kommuniziert mit Downstream-Lokalnetzen oder Hosts, um den angeforderten Datenverkehr zu verteilen. Eine gültige Konfiguration erfordert mindestens eine Downstream-Schnittstelle.

Beispiel:

set protocols igmp-proxy interface eth0 role upstream
set protocols igmp-proxy interface eth1 role downstream
set protocols igmp-proxy interface <interface> alt-subnet <network>

Konfigurieren Sie ein erlaubtes Remote-Subnetz für eingehenden Multicast-Datenverkehr auf der angegebenen IGMP-Proxy-Schnittstelle

Standardmäßig akzeptiert der IGMP-Proxy Multicast-Datenverkehr nur von direkt angeschlossenen Subnetzen. Wenn eine Multicast-Quelle auf einem entfernten Netzwerk liegt, müssen Sie das erlaubte Remote-Subnetz explizit definieren, um den Datenverkehr zu erlauben.

Sie können mehrere Remote-Subnetze für eine Upstream-IGMP-Proxy-Schnittstelle konfigurieren.

Upstream-Schnittstellen benötigen häufig diese Konfiguration, da Multicast-Quellen typischerweise auf externen Subnetzen liegen.

Beispiel:

set protocols igmp-proxy interface eth0 alt-subnet 10.0.0.0/8
set protocols igmp-proxy interface <interface> whitelist <network>

Konfigurieren Sie ein erlaubtes Zielnetzwerk für Multicast-Datenverkehrsanfragen auf der angegebenen IGMP-Proxy-Schnittstelle.

Standardmäßig akzeptiert der IGMP-Proxy Anfragen für alle Multicast-Zielnetze. Wenn Sie eine Whitelist definieren, leitet der IGMP-Proxy Anfragen nur für die angegebenen Multicast-Netze weiter.

Sie können pro Downstream-IGMP-Proxy-Schnittstelle mehrere Whitelist-Einträge konfigurieren.

Beispiel:

set protocols igmp-proxy interface eth1 whitelist 239.0.0.0/8
set protocols igmp-proxy interface <interface> threshold <1-255>

Konfigurieren Sie den TTL-Schwellwert für die angegebene IGMP-Proxy-Schnittstelle.

Der IGMP-Proxy verwirft jedes Multicast-Paket mit einem TTL-Wert unter dem konfigurierten Schwellwert.

Beispiel:

set protocols igmp-proxy interface eth0 threshold 5
set protocols igmp-proxy disable-quickleave

Deaktivieren Sie den Quickleave-Modus für den IGMP-Proxy.

Wenn deaktiviert, sendet der IGMP-Proxy kein Upstream-Leave-Nachricht, wenn eine Downstream-Leave-Nachricht empfangen wird, wodurch die sofortige Beendigung des Upstream-Multicast-Datenverkehrs verhindert wird. Der IGMP-Proxy hört auch auf, Downstream-Schnittstellen nach Mitgliedschaftsberichten zu fragen. Wenn ein Downstream-Klient einen neuen Bericht sendet, verwirft der IGMP-Proxy die Nachricht und nimmt den Datenverkehr nicht wieder auf.

Hinweis

Das Deaktivieren des Quickleave-Modus führt dazu, dass der IGMP-Proxy sich exakt wie ein standardmäßiger Multicast-Client auf der Upstream-Schnittstelle verhält.

Hinweis

Das Deaktivieren des Quickleave-Modus erhöht das Risiko einer Bandbreitenüberlastung im Netzwerk.

Beispiel:

set protocols igmp-proxy disable-quickleave
set protocols igmp-proxy disable

Deaktivieren Sie den IGMP-Proxy auf dem Router.

Beispiel:

set protocols igmp-proxy disable

Betrieb

restart igmp-proxy

Starten Sie den IGMP-Proxy-Prozess neu.

Beispiel

In diesem Beispiel betreibt die lokale LAN-Schnittstelle eth1 hinter NAT. Um den lokalen Clients zu ermöglichen, Multicast-Datenverkehr zu empfangen, der aus dem Quellnetzwerk 198.51.100.0/24 auf der WAN-Schnittstelle (eth0) stammt, konfigurieren Sie den IGMP-Proxy wie folgt:

set protocols igmp-proxy interface eth0 role upstream
set protocols igmp-proxy interface eth0 alt-subnet 198.51.100.0/24
set protocols igmp-proxy interface eth1 role downstream
