OSPF

OSPF ist ein Routingprotokoll für Internet-Protokoll (IP)-Netzwerke. Es verwendet ein Link-State-Routing (LSR)-Algorithmus und gehört zur Gruppe der Interior Gateway Protocols (IGPs), das innerhalb eines einzelnen autonomen Systems (AS) operiert. Es ist als OSPF Version 2 in RFC 2328 (1998) für IPv4 definiert. Updates für IPv6 sind als OSPF Version 3 in RFC 5340 (2008) spezifiziert. OSPF unterstützt das CIDR-Adressmodell.

OSPF wird in großen Unternehmensnetzwerken häufig als IGP verwendet.

OSPFv2 (IPv4)

Konfiguration

Allgemeines

VyOS hat kein spezielles Kommando, um den OSPF-Prozess zu starten. Der OSPF-Prozess startet, wenn die erste ospf-funktionale Schnittstelle konfiguriert wird.

set protocols ospf area <number> network <A.B.C.D/M>

Dieses Kommando gibt die OSPF-funktionale Schnittstelle(n) an. Wenn die Schnittstelle eine Adresse aus dem definierten Bereich hat, aktiviert das Kommando OSPF auf dieser Schnittstelle, sodass der Router Netzwerkinformationen über diese Schnittstelle an andere OSPF-Routern weitergeben kann.

Dieses Kommando wird auch verwendet, um den OSPF-Prozess zu aktivieren. Die Bereichsnummer kann im Dezimalsystem im Bereich von 0 bis 4294967295 angegeben werden. Oder sie kann im Punktdesimalformat ähnlich wie IP-Adressen angegeben werden.

Die Präfixlänge in der Schnittstelle muss gleich oder größer (d.h. kleinerer Netzwerk) sein als die Präfixlänge in der Netzwerkangabe. Zum Beispiel aktiviert die obige Anweisung keine OSPF auf einer Schnittstelle mit der Adresse 192.168.1.1/23, aber es tut auf einer Schnittstelle mit der Adresse 192.168.1.129/25.

In einigen Fällen kann es bequemer sein, OSPF pro Schnittstelle/Unternetz zu aktivieren set protocols ospf interface <interface> area <x.x.x.x | x>

set protocols ospf auto-cost reference-bandwidth <number>

Dieses Kommando legt die Referenzbandbreite für Kostenberechnungen fest, wobei die Bandbreite im Bereich von 1 bis 4294967 in Mbits/s angegeben werden kann. Der Standardwert ist 100 Mbit/s (d.h. eine Verbindung mit einer Bandbreite von 100 Mbit/s oder höher hat einen Kostenwert von 1. Kosten niedrigerer Bandbreiten werden entsprechend diesem Wert skaliert).

set protocols ospf parameters router-id <rid>

Dieses Kommando legt die Router-ID des OSPF-Prozesses fest. Die Router-ID kann eine IP-Adresse des Routers sein, muss aber nicht – sie kann eine beliebige 32-Bit-Zahl sein. Sie muss jedoch innerhalb des gesamten OSPF-Bereichs eindeutig sein, andernfalls können schlechte Dinge passieren, wenn mehrere OSPF-Sprecher mit derselben Router-ID konfiguriert werden!

Optional

set protocols ospf default-information originate [always] [metric <number>] [metric-type <1|2>] [route-map <name>]

Erzeugt eine AS-External (Typ-5) LSA, die eine Standardroute in alle externen Routing-fähigen Bereichen beschreibt, mit der angegebenen Metrik und Metrikart. Wenn das Schlüsselwort always angegeben wird, wird die Standardroute immer beworben, auch wenn keine Standardroute in der Routing-Tabelle vorhanden ist. Das Argument route-map gibt an, dass die Standardroute beworben wird, wenn die Route-Map erfüllt ist.

set protocols ospf distance global <distance>

Dieses Kommando ändert den Abstandswert von OSPF global. Der Abstandsbereich ist 1 bis 255.

set protocols ospf distance ospf <external|inter-area|intra-area> <distance>

Dieses Kommando ändert den Abstandswert von OSPF. Die Argumente sind die Abstands-Werte für externe Routen, inter-areale Routen und intra-areale Routen jeweils. Der Abstandsbereich ist 1 bis 255.

Hinweis

Route mit einem Abstand von 255 sind effektiv deaktiviert und werden nicht in den Kernel installiert.

set protocols ospf log-adjacency-changes [detail]

Dieses Kommando ermöglicht das Protokollieren von Änderungen in der Nachbarschaft. Mit dem optionalen Argument detail werden alle Änderungen in der Nachbarschaftsstatus angezeigt. Ohne detail werden nur Änderungen zu vollständigen oder Regressionen angezeigt.

set protocols ospf max-metric router-lsa <administrative|on-shutdown <seconds>|on-startup <seconds>>

Dies aktiviert RFC 3137 Unterstützung, bei der der OSPF-Prozess seine Transit-Verbindungen in seiner Router-LSA als unendlichen Abstand beschreibt, so dass andere Router währenddessen Transitschritte durch den Router vermeiden, aber dennoch Netzwerke durch den Router erreichen können.

Diese Unterstützung kann administrativ (und unbegrenzt) mit dem Befehl administrative aktiviert werden. Sie kann auch bedingt aktiviert werden. Bedingte Aktivierung von Max-Metric Router-LSAs kann für eine Periode von Sekunden nach dem Start mit dem Befehl on-startup <seconds> und/oder für eine Periode von Sekunden vor dem Shutdown mit dem Befehl on-shutdown <seconds> erfolgen. Der Zeitbereich ist 5 bis 86400.

set protocols ospf parameters abr-type <cisco|ibm|shortcut|standard>

Dieses Kommando wählt das ABR-Modell aus. OSPF-Router unterstützt vier ABR-Modelle:

cisco – ein Router wird als ABR betrachtet, wenn er mehrere konfigurierte Links zu Netzwerken in verschiedenen Bereichen hat, wobei einer davon ein Backbone-Bereich ist. Darüber hinaus sollte der Link zum Backbone-Bereich aktiv (arbeiten) sein. ibm – identisch mit „cisco“-Modell, aber in diesem Fall kann der Backbone-Bereich-Link nicht aktiv sein. standard – Router hat mehrere aktive Links zu verschiedenen Bereichen. shortcut – identisch mit „standard“-Modell, aber in diesem Modell darf der Router eine verbundene Bereichs-Topologie ohne Einbeziehung eines Backbone-Bereichs für inter-areale Verbindungen verwenden.

Weitere Informationen über Unterschiede zwischen „cisco“ und „ibm“-Modellen finden Sie in RFC 3509. Ein „shortcut“-Modell ermöglicht ABR, Routen zwischen Bereichen basierend auf der Topologie der an diesen Router angeschlossenen Bereiche zu erstellen, aber nicht unter Verwendung eines Backbone-Bereichs, falls ein nicht-Backbone-Route billiger ist. Für weitere Informationen über das „shortcut“-Modell siehe ospf-shortcut-abr-02.txt

set protocols ospf parameters rfc1583-compatibility

RFC 2328, der Nachfolger von RFC 1583, schlägt gemäß Abschnitt G.2 (Änderungen) im Abschnitt 16.4.1 eine Änderung des Pfadpräferenzalgorithmus vor, die mögliche Routing-Loops verhindert, die in der alten Version von OSPFv2 möglich waren. Genauer gesagt verlangt es, dass inter-areale Pfade und intra-areale Backbone-Pfade nun gleichermaßen bevorzugt werden, aber immer noch bevorzugter als externe Pfade.

Dieses Kommando sollte normalerweise nicht gesetzt werden.

set protocols ospf interface <interface> passive [disable]

Dieses Kommando gibt die Schnittstelle als passiv an. Eine passive Schnittstelle bewirbt ihre Adresse, läuft aber nicht das OSPF-Protokoll (Nachbarschaften werden nicht gebildet und Hello-Pakete werden nicht generiert).

Das optionale Disable-Argument ermöglicht es, die Schnittstelle aus dem passiven Zustand auszuschließen. Dieses Kommando wird verwendet, wenn das Kommando passive-interface default konfiguriert wurde.

set protocols ospf passive-interface default

Dieses Kommando gibt alle Schnittstellen standardmäßig als passiv an. Da dieses Kommando die Konfigurationslogik auf einen Standardpassiv ändert, müssen Schnittstellen, auf denen Router-Nachbarschaften erwartet werden, mit dem Kommando passive-interface-exclude konfiguriert werden.

set protocols ospf maximum-paths <1-64>

Verwenden Sie dieses Kommando, um die maximale Anzahl gleichwertiger Pfade zu einem bestimmten Ziel zu steuern. Der obere Grenzwert kann sich unterscheiden, wenn Sie den Wert von MULTIPATH_NUM während der Kompilierung ändern. Der Standardwert ist MULTIPATH_NUM (64).

set protocols ospf refresh timers <seconds>

Der Router aktualisiert automatisch die Link-State-Informationen mit seinen Nachbarn. Nur veraltete Informationen werden aktualisiert, deren Alter einen bestimmten Schwellwert überschritten hat. Dieses Parameter ändert den Schwellwert, der standardmäßig 1800 Sekunden (30 Minuten) beträgt. Der Wert wird auf den ganzen OSPF-Router angewendet. Der Timerbereich ist 10 bis 1800.

set protocols ospf timers throttle spf <delay|initial-holdtime|max-holdtime> <seconds>

Dieses Kommando legt die Anfangsverzögerung, die Anfangs-Holdzeit und die maximale Holdzeit zwischen der Berechnung des SPF und dem Ereignis fest, das die Berechnung ausgelöst hat. Die Zeiten werden in Millisekunden angegeben und müssen im Bereich von 0 bis 600000 Millisekunden liegen. delay legt die Anfangs-SPF-Planungsverzögerung in Millisekunden fest. Der Standardwert ist 200 ms. initial-holdtime legt die minimale Haltezeit zwischen zwei aufeinanderfolgenden SPF-Berechnungen fest. Der Standardwert ist 1000 ms. max-holdtime legt die maximale Wartezeit zwischen zwei aufeinanderfolgenden SPF-Berechnungen fest. Der Standardwert ist 10000 ms.

set protocols ospf ldp-sync

Dieses Kommando aktiviert IGP-LDP-Synchronisation global für OSPF. Dies erfordert, dass LDP funktionsfähig ist. Dies wird in RFC 5443 beschrieben. Standardmäßig sind alle Interfaces, die im OSPF betrieben werden, für die Synchronisation aktiviert. Loopbacks sind ausgenommen.

set protocols ospf ldp-sync holddown <seconds>

Dieses Kommando ändert den Haltezeitwert global für IGP-LDP-Synchronisation während der Konvergenz/Interface-Flap-Ereignisse.

set protocols ospf capability opaque

ospfd unterstützt Opaque LSA RFC 2370 als Teil der Unterstützung für MPLS Traffic Engineering LSAs. Die Opaque-LSA-Fähigkeit muss in der Konfiguration aktiviert werden.

Eine alternative Anweisung könnte „mpls-te on“ (Traffic Engineering) sein

Hinweis

FRR bietet nur eine teilweise Unterstützung für einige Routingprotokoll-Erweiterungen, die mit MPLS-TE verwendet werden; es unterstützt nicht eine vollständige RSVP-TE-Lösung.

Bereichskonfiguration

set protocols ospf area <number> area-type stub

Dieses Kommando gibt den Bereich als Stub-Bereich an. Das bedeutet, dass kein Router externe Routen außerhalb von OSPF startet und daher ein Bereich, in dem alle externen Routen über den ABR(s) erfolgen. Daher benötigen ABRs für solche Bereiche nicht, um AS-External LSAs (Typ-5) oder ASBR-Summary LSAs (Typ-4) in den Bereich einzufügen. Sie müssen nur Network-Summary (Typ-3) LSAs in solche Bereiche einfügen, zusammen mit einer Standardroute-Zusammenfassung.

set protocols ospf area <number> area-type stub no-summary
