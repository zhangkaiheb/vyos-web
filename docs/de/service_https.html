HTTP API

VyOS bietet eine HTTP API an. Sie können sie verwenden, um Betriebsmodus-Befehle auszuführen oder Konfigurationen zu ändern oder zu löschen. Die API ist sowohl als REST API als auch als GraphQL API verfügbar.

Für REST API-Anfragesbeispiele, Endpunkte und Authentifizierungsdetails siehe VyOS API.

Hinweis

Wenn kein PKI-Zertifikat für den Dienst konfiguriert ist, generiert VyOS automatisch ein selbstsigniertes Zertifikat. Dies wird für die Produktion nicht empfohlen.

Konfiguration

HTTPS-Listener

set service https listen-address <address>

Konfigurieren Sie eine lokale IPv4- oder IPv6-Adresse, auf der der HTTPS-Listener eingehende Verbindungen akzeptiert.

Die IP-Adresse muss bereits einem lokalen Interface zugewiesen sein. Wiederholen Sie den Befehl, um mehrere IP-Adressen zu konfigurieren.

Wenn nicht gesetzt, akzeptiert der Listener eingehende Verbindungen auf allen lokalen IP-Adressen.

Beispiel:

set service https listen-address 192.0.2.1
set service https listen-address 2001:db8::1
set service https port <1-65535>

Konfigurieren Sie den TCP-Port, auf dem der HTTPS-Listener eingehende Verbindungen akzeptiert.

Der Standardwert ist 443.

Hinweis

Wenn der gewählte Port bereits von einem anderen Dienst verwendet wird, schlägt der Commit fehl.

Beispiel:

set service https port 8443
set service https vrf <name>

Binden Sie den HTTPS-Listener an die angegebene VRF-Instanz.

Die VRF muss bereits unter set vrf name <name> konfiguriert sein.

Beispiel:

set service https vrf mgmt
set service https allow-client address <address>

Beschränken Sie den Zugriff auf die HTTPS-API-Endpunkte auf die angegebene IPv4- oder IPv6-Adresse oder Präfix.

Wiederholen Sie den Befehl, um mehrere IP-Adressen oder Präfixe zu erlauben.

Wenn nicht gesetzt, akzeptiert die API Verbindungen von jeder IP-Adresse.

Beispiel:

set service https allow-client address 192.0.2.0/24
set service https allow-client address 2001:db8::/32
set service https enable-http-redirect

Enable redirection of incoming HTTP requests (port 80) to HTTPS.

The redirect sends traffic to the default HTTPS port (443). If you have changed the HTTPS port, the redirect will not work.

Beispiel:

set service https enable-http-redirect
set service https request-body-size-limit <1-256>

Konfigurieren Sie die maximale Größe, in Megabytes, eines HTTP-Anfragetextes, den der Listener akzeptiert.

Anfragen, die diese Grenze überschreiten, werden abgelehnt.

Der Standardwert ist 1.

Beispiel:

set service https request-body-size-limit 10

TLS

set service https tls-version <1.2 | 1.3>

Enable a specific TLS protocol version for the HTTPS listener.

Repeat the command to enable multiple protocol versions.

By default, both TLS 1.2 and TLS 1.3 are enabled.

Beispiel:

set service https tls-version 1.3
set service https certificates certificate <name>

Binden Sie ein TLS-Zertifikat aus dem PKI-Untersystem an den HTTPS-Listener.

Das Zertifikat muss bereits unter set pki certificate <name> definiert sein, mit einem Zertifikat und einem privaten Schlüssel.

Beispiel:

set service https certificates certificate my-server-cert
set service https certificates ca-certificate <name>

Binden Sie ein CA-Zertifikat aus dem PKI-Untersystem an den HTTPS-Listener.

Die CA muss bereits unter set pki ca <name> definiert sein. Das CA-Zertifikat wird dem TLS-Zertifikat angehängt, um eine vollständige Kette zu bilden, die während des TLS-Handshakes an Clients übermittelt wird.

Beispiel:

set service https certificates ca-certificate my-internal-ca
set service https certificates dh-params <name>

Wählen Sie Diffie-Hellman-Parameter aus dem PKI-Untersystem für den HTTPS-Listener aus.

Die Parameter müssen bereits unter set pki dh <name> definiert sein, mit einer Schlüsselgröße von mindestens 2048 Bit. Die Parameter werden von DHE-Verschlüsselungssuiten in TLS 1.2 verwendet. TLS 1.3 verwendet sie nicht.

Beispiel:

set service https certificates dh-params my-dh-2048

API-Authentifizierung

set service https api keys id <name> key <apikey>

Konfigurieren Sie einen HTTP-API-Schlüssel zur Authentifizierung von REST-Anfragen und GraphQL-Anfragen, es sei denn, GraphQL wechselt zu JWT-Token-Authentifizierung.

Der Schlüssel wird im Klartext angegeben und gewährt volle Zugriffsrechte auf die API.

Mindestens ein Schlüssel muss konfiguriert sein, um die REST-API zu verwenden. GraphQL kann ohne Schlüssel laufen, wenn JWT-Token-Authentifizierung aktiviert ist.

Beispiel:

set service https api keys id MY-HTTPS-API-ID key 'MY-HTTPS-API-PLAINTEXT-KEY'

REST

set service https api rest

Enable the REST API for managing VyOS over HTTPS.

Beispiel:

set service https api rest
set service https api rest strict

Verwerfen Sie Löschanfragen auf dem /configure-Endpunkt, wenn der Zielkonfigurationspfad nicht existiert.

Ohne diesen Flag erfolgen solche Anfragen still.

Beispiel:

set service https api rest strict
set service https api rest debug

Protokollieren Sie detaillierte Fehlermeldungen in der systemd-Journal, wenn API-Konfigurationsanfragen fehlschlagen.

Ohne diesen Flag werden nur kurze Fehlermeldungen protokolliert.

Beispiel:

set service https api rest debug

GraphQL

set service https api graphql introspection

Enable GraphQL schema introspection.

Authenticated clients can then query the endpoint for the full schema. Disabled by default, and typically kept disabled in production due to security concerns.

Beispiel:

set service https api graphql introspection
set service https api graphql authentication type <key | token>

Konfigurieren Sie den Authentifizierungstyp für GraphQL-Anfragen:

  • key: Verwendet die in service https api keys konfigurierten API-Schlüssel.

  • token: Verwendet JWT-Tokens.

Der Standardwert ist key.

Beispiel:

set service https api graphql authentication type token
set service https api graphql authentication expiration <60-31536000>

Konfigurieren Sie die Lebensdauer, in Sekunden, von JWT-Tokens.

Der Standardwert ist 3600.

Beispiel:

set service https api graphql authentication expiration 86400
set service https api graphql authentication secret-length <16-65535>

Konfigurieren Sie die Länge, in Bytes, des gemeinsamen Geheimnisses, das zum Signieren von JWT-Tokens verwendet wird.

Der Standardwert ist 32.

Beispiel:

set service https api graphql authentication secret-length 64
set service https api graphql cors allow-origin <origin>

Konfigurieren Sie, welche Websites (Origins) im Browser responses vom GraphQL API lesen können, mithilfe von CORS.

Wiederholen Sie den Befehl, um mehrere Origins zu erlauben.

Beispiel:

set service https api graphql cors allow-origin https://app.example.com

Beispiel

Die minimale Konfiguration für eine funktionierende REST API erfordert die Aktivierung von REST und die Konfiguration von mindestens einem API-Schlüssel:

set service https api keys id MY-HTTPS-API-ID key MY-HTTPS-API-PLAINTEXT-KEY
set service https api rest
