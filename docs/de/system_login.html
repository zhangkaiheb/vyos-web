Anmeldung/Benutzerverwaltung

Das Standard-VyOS-Benutzerkonto (vyos), sowie neu erstellte Benutzerkonten, verfügen über vollständige Systemkonfigurationsrechte. Diese Konten erhalten sudo-Rechte, wodurch sie Befehle als Root-Benutzer ausführen können.

VyOS unterstützt sowohl lokale als auch Remote-Authentifizierung über RADIUS/ TACACS+.

Lokale Authentifizierung

set system login user <name> full-name “<string>”

Konfigurieren Sie den echten Namen oder die Beschreibung für einen Systembenutzer.

Wenn die Beschreibung Leerzeichen enthält, setzen Sie <string> in Anführungszeichen.

Wenn der Benutzer <name> bereits existiert, aktualisiert der Befehl die aktuelle Beschreibung. Wenn nicht, wird ein neuer Benutzer mit der angegebenen Beschreibung erstellt.

set system login user <name> authentication plaintext-password <password>

Konfigurieren Sie ein Passwort für einen Systembenutzer.

Geben Sie das Passwort im Klartext ein. Bei commit hashiert VyOS das Passwort für sichere Speicherung und entfernt den Klartext-Wert.

Wenn der Benutzer <name> bereits existiert, aktualisiert der Befehl das aktuelle Passwort. Wenn nicht, wird ein neuer Benutzer mit dem angegebenen Klartext-Passwort erstellt.

set system login user <name> authentication encrypted-password <password>

Konfigurieren Sie ein vorher gehashtes Passwort für einen Systembenutzer.

Geben Sie das Passwort im gehashten Format ein. Bei commit speichert VyOS diesen Wert direkt ohne Änderung.

Wenn der Benutzer <name> bereits existiert, aktualisiert der Befehl das aktuelle Passwort. Wenn nicht, wird ein neuer Benutzer mit dem angegebenen vorher gehashten Passwort erstellt.

set system login user <name> authentication principal <principal>

Konfigurieren Sie einen SSH-Zertifikatsprinzipal für einen Systembenutzer.

Geben Sie den Prinzipal (einen String, der im Benutzer-Signatur-SSH-Zertifikat enthalten ist). Bei commit speichert VyOS diese Zuordnung, sodass der Benutzer sich anmelden kann, wenn das Zertifikat, das er präsentiert, diesen Prinzipal enthält.

Wenn der Benutzer <name> bereits existiert, aktualisiert der Befehl den Prinzipal. Wenn nicht, wird ein neuer Benutzer mit dem angegebenen Prinzipal erstellt.

Wenn nicht konfiguriert, ist der Prinzipal standardmäßig <name>.

set system login user <name> disable

Deaktivieren Sie ein Systembenutzerkonto.

VyOS sperrt das Konto, wodurch der Benutzer nicht mehr anmelden kann.

Schlüsselbasierte Authentifizierung

Die schlüsselbasierte Authentifizierung ist die empfohlene Methode, um den SSH-Zugriff in VyOS zu sichern. Sie verwendet ein öffentliches/geheimes Schlüsselpaar, um die Benutzeridentität zu überprüfen, ohne dass ein Passwort erforderlich ist. Um den Zugriff zu autorisieren, weisen Sie SSH-Öffentlichkeitschlüssel zu Benutzerkonten auf dem Router zu, während die SSH-Privatschlüssel auf lokalen Geräten verbleiben. VyOS ermöglicht es, mehrere SSH-Öffentlichkeitschlüssel einem einzelnen Benutzerkonto zuzuweisen, was nützlich ist, um von verschiedenen Geräten auf einen Router zuzugreifen.

Generieren Sie das Schlüsselpaar

Generieren Sie ein SSH-Schlüsselpaar auf Ihrem lokalen Rechner mit dem ssh-keygen Befehl. Dies erstellt zwei Dateien:

  • Privatschlüssel (z. B. id_rsa): Verbleibt auf Ihrem lokalen Rechner und muss niemals geteilt werden.

  • Öffentlicher Schlüssel (z. B. id_rsa.pub): Wird verwendet, um das VyOS-Benutzerkonto zu konfigurieren. Standardmäßig wird er in ~/.ssh/id_rsa.pub gespeichert.

Jeder SSH-Öffentlichkeitschlüssel besteht aus drei Teilen, durch Leerzeichen getrennt:

  • Art des Verschlüsselungsalgorithmus: ssh-rsa, ssh-ed25519, usw.

  • Schlüssel: Die tatsächlichen Daten (ein langer String, der mit AAAA... beginnt).

  • Kommentar: Ein Identifier für Ihre Referenz (z. B. user@host).

Nur der Algorithmustyp und der Schlüssel sind erforderlich, um den Autorisierungseintrag in VyOS zu konfigurieren. Der Kommentarteil ist optional.

Warnung

SSH-Schlüsselstrings sind lang. Beim Kopieren und Einfügen stellen Sie sicher, dass Ihr Terminal keine Zeilenumbrüche einfügt. Der Schlüssel muss als eine einzelne Zeile eingegeben werden, um korrekt zu funktionieren.

Router konfigurieren

Um die SSH-Öffentlichkeitschlüsselauthentifizierung für ein Benutzerkonto zu konfigurieren, führen Sie die folgenden beiden Befehle mit dem gleichen <identifier> aus:

set system login user <username> authentication public-keys <identifier> key <key>

Konfigurieren Sie den SSH-Öffentlichkeitschlüssel für das Benutzerkonto.

  • <identifier>: Ein eindeutiger Bezeichner, der diesen spezifischen Schlüssel einträgt.

  • <key>: Der tatsächliche Zeichenstring aus Ihrem öffentlichen Schlüssel.

set system login user <username> authentication public-keys <identifier> type <type>

Konfigurieren Sie den Verschlüsselungstyp des SSH-Schlüssels.

Folgende Verschlüsselungsalgorithmustypen sind verfügbar:

  • ecdsa-sha2-nistp256

  • ecdsa-sha2-nistp384

  • ecdsa-sha2-nistp521

  • ssh-dss

  • ssh-ed25519

  • ssh-rsa

Hinweis

Um mehrere SSH-Öffentlichkeitschlüssel einem Benutzerkonto zuzuweisen, wiederholen Sie die obigen Befehle mit einem eindeutigen Bezeichner für jeden Schlüssel.

set system login user <username> authentication public-keys <identifier> options <options>

Konfigurieren Sie spezifische Einschränkungen oder Verhaltensweisen für einen SSH-Öffentlichkeitschlüssel.

<options>: Eine Zeichenkette mit Komma-getrennten Werten, die Berechtigungen oder Einschränkungen für diesen Schlüssel definieren.

Der Befehl akzeptiert die standardmäßigen OpenSSH-Optionen, die in der Datei des Routers ~/.ssh/authorized_keys aufgelistet sind.

Um ein "-Zeichen in der Optionszeichenkette zu verwenden, verwenden Sie &quot;.

Zum Beispiel, um erlaubte Quell-IP-Adressen für einen SSH-Öffentlichkeitschlüssel zu beschränken, verwenden Sie: from=&quot;10.0.0.0/24&quot;.

OTP-basierte MFA

VyOS ermöglicht es Ihnen, die Sicherheit der Benutzerzugriffe zu verbessern, indem Sie OTP-basierte MFA für einzelne Benutzer aktivieren. Benutzer mit OTP-basiertem MFA müssen bei der Anmeldung ein gültiges OTP zusammen mit ihrem Passwort eingeben. Benutzer ohne OTP-basiertes MFA verwenden Standardauthentifizierung.

set system login user <username> authentication otp key <key>

Konfigurieren Sie OTP-basiertes MFA für einen Benutzer.

<key>: Ein Base32-codierter geheimer Schlüssel. Dieser Schlüssel muss in die Authenticator-App des Benutzers eingefügt werden, um gültige OTPs zu generieren.

Wenn konfiguriert, muss der Benutzer bei allen nachfolgenden Anmeldungen sein Passwort gefolgt von einem gültigen OTP eingeben.

OTP-Einstellungen

set system login user <username> authentication otp rate-limit <limit>

Konfigurieren Sie die Anzahl der OTP Authentifizierungsversuche, die innerhalb eines bestimmten Zeitraums erlaubt sind.

Wenn dieser Limit überschritten wird, wird der Benutzer vorübergehend blockiert.

Der Standardwert ist 3 Versuche. Der gültige Bereich liegt zwischen 1 und 10 Versuchen.

set system login user <username> authentication otp rate-time <seconds>

Konfigurieren Sie die Zeitspanne, in Sekunden, für die OTP Authentifizierungsversuche verfolgt werden.

Der Standardwert ist 30 Sekunden. Der gültige Bereich liegt zwischen 1 und 600 Sekunden.

set system login user <username> authentication otp window-size <size>

Konfigurieren Sie das OTP Window-Size für einen Benutzer.

Das OTP Window-Size definiert die Anzahl der gleichzeitig gültigen OTPs, die der Authentifizierungsserver akzeptiert. Diese Einstellung geht davon aus, dass ein neuer Token alle 30 Sekunden generiert wird.

Der Standardwert ist 3. Dies erlaubt 3 gleichzeitige Codes: den Code für das aktuelle 30-Sekunden-Intervall, den vorherigen Code und den folgenden Code. Dies erlaubt bis zu 30 Sekunden Zeitverschiebung zwischen dem Authentifizierungsserver und dem Client.

Wenn die Fenstergröße auf 17 erhöht wird, erlaubt das System 17 gleichzeitige Codes (den aktuellen Code, die 8 vorherigen Codes und die 8 folgenden Codes). Dies erlaubt eine Zeitverschiebung von bis zu 4 Minuten.

Der gültige Bereich liegt zwischen 1 und 21.

RADIUS-Authentifizierung

Für große Implementierungen ist es ineffizient, individuelle Benutzerkonten auf mehreren VyOS-Instanzen zu verwalten. VyOS unterstützt zentrale Authentifizierung über RADIUS, wodurch die Benutzerkontoverwaltung auf einem einzigen Backend-Server zusammengefasst wird.

Konfiguration

set system login radius server <address> key <secret>

Konfigurieren Sie die IP-Adresse und den gemeinsamen Geheimnisschlüssel des RADIUS Servers.

Der gemeinsame Geheimnisschlüssel wird verwendet, um die Identität des Routers zu überprüfen und Benutzerpasswörter während der Authentifizierung zu verschlüsseln.

Sie können mehrere RADIUS Server konfigurieren.

set system login radius server <address> port <port>

Konfigurieren Sie den UDP-Port für die Kommunikation mit dem RADIUS Server.

Der Standardport ist 1812.

set system login radius server <address> disable

Deaktivieren Sie einen RADIUS Server aus dem Authentifizierungsprozess.

Das Deaktivieren eines bestimmten RADIUS Servers entfernt nicht dessen Konfigurationsparameter (die IP-Adresse des Servers und den gemeinsamen Geheimnisschlüssel).

set system login radius server <address> timeout <timeout>

Konfigurieren Sie die Dauer, in Sekunden, die der VyOS-Router auf eine Antwort vom RADIUS Server wartet, nachdem ein Authentifizierungsantrag gesendet wurde.

Wenn der Server innerhalb dieses Zeitrahmens nicht antwortet, versucht der VyOS-Router, sich mit einem anderen konfigurierten Server zu verbinden oder fällt zurück auf lokale Authentifizierung.

set system login radius source-address <address>

Konfigurieren Sie die Quell-IP-Adresse, die der Router für RADIUS Authentifizierungsanträge verwendet.

Es wird empfohlen, eine konsistente Quell-IP-Adresse zu verwenden, da RADIUS-Server in der Regel Anträge nur von bekannten, vertrauenswürdigen IP-Adressen akzeptieren.

Wenn nicht explizit definiert, verwendet der Router die aktuelle Ausgangschnittstellenadresse, die sich ändern kann (z. B. aufgrund eines Linkausfalls), was zu Authentifizierungsfehlern führen kann.

set system login radius vrf <name>

Konfigurieren Sie den Router, um alle RADIUS Authentifizierungsanträge über einen bestimmten VRF zu senden.

Standardmäßig werden RADIUS Authentifizierungsanträge über das globale Routing-Table gesendet.

Konfigurationsbeispiel

set system login radius server 192.168.0.2 key 'test-vyos'
set system login radius server 192.168.0.2 port '1812'
set system login radius server 192.168.0.2 timeout '5'
set system login radius source-address '192.168.0.1'

Wenn die Kommunikation mit dem RADIUS Server fehlschlägt, fällt der Router auf lokale Benutzer-Authentifizierung zurück. Während dieses Prozesses können Benutzer eine Anmeldeverzögerung erleben, während das System auf den RADIUS Antrag wartet und abläuft. Diese Verzögerung hängt vom konfigurierten Timeout-Wert ab.

Hinweis

Um Administrationsrechte für RADIUS-authentifizierte Benutzer zu gewähren, muss der Server das Cisco-AV-Pair Attribut auf shell:priv-lvl=15 zurückgeben. Andernfalls erhalten Benutzer Standardrechte und können keine Konfigurationsaufgaben ausführen.

TACACS+ Authentifizierung

Im Gegensatz zu RADIUS, unterstützt VyOS TACACS+, das häufig in großen Unternehmensumgebungen verwendet wird.

Im Gegensatz zu RADIUS, trennt TACACS+ die Authentifizierung, Autorisierung und Abrechnung (AAA) in unabhängige Prozesse und verschlüsselt den gesamten Paketinhalt für eine erhöhte Sicherheit.

TACACS+ ist definiert in RFC 8907.

Konfiguration

set system login tacacs server <address> key <secret>

Konfigurieren Sie die IP-Adresse und den gemeinsamen Geheimnisschlüssel des TACACS+ Servers.

Im Gegensatz zu RADIUS, das nur Passwörter verschlüsselt, verschlüsselt TACACS+ den gesamten Paketinhalt für eine erhöhte Sicherheit.

Sie können mehrere TACACS+ Server konfigurieren.

set system login tacacs server <address> port <port>

Konfigurieren Sie den TCP-Port für die Kommunikation mit dem TACACS+ Server.

Der Standardport ist 49.

set system login tacacs server <address> disable

Deaktivieren Sie einen TACACS+ Server aus dem Authentifizierungsprozess.

Das Deaktivieren eines bestimmten TACACS+ Servers entfernt nicht dessen Konfigurationsparameter (die IP-Adresse des Servers und den gemeinsamen Geheimnisschlüssel).

set system login tacacs server <address> timeout <timeout>

Konfigurieren Sie die Dauer, in Sekunden, die der VyOS-Router auf eine Antwort vom TACACS+ Server wartet, nachdem ein Authentifizierungsantrag gesendet wurde.

Wenn der Server innerhalb dieses Zeitrahmens nicht antwortet, versucht der VyOS-Router, sich mit einem anderen konfigurierten Server zu verbinden oder fällt zurück auf lokale Authentifizierung.

set system login tacacs source-address <address>

Konfigurieren Sie die Quell-IP-Adresse, die der Router für TACACS+ Authentifizierungsanträge verwendet.

Es wird empfohlen, eine konsistente Quell-IP-Adresse zu verwenden, da TACACS+ Server in der Regel Anträge nur von bekannten, vertrauenswürdigen IP-Adressen akzeptieren.

Wenn nicht explizit definiert, verwendet der Router die aktuelle Ausgangschnittstellenadresse, die sich ändern kann (z. B. aufgrund eines Linkausfalls), was zu Authentifizierungsfehlern führen kann.

set system login tacacs vrf <name>

Konfigurieren Sie den Router, um alle TACACS+ Authentifizierungsanträge über einen bestimmten VRF zu senden.

Standardmäßig werden TACACS+ Authentifizierungsanträge über das globale Routing-Table gesendet.

Konfigurationsbeispiel

set system login tacacs server 192.168.0.2 key 'test-vyos'
set system login tacacs server 192.168.0.2 port '49'
set system login tacacs source-address '192.168.0.1'

Wenn die Kommunikation mit dem TACACS+ Server fehlschlägt, fällt der Router auf lokale Benutzer-Authentifizierung zurück.

Anmeldebanner

VyOS ermöglicht es Ihnen, vor der Anmeldung und nach der Anmeldung Banner zu konfigurieren. Vor der Anmeldung werden Banner typischerweise für Systemidentifikation, rechtliche Haftungsausschlüsse oder Sicherheitswarnungen verwendet, die vor der Authentifizierung angezeigt werden, während nach der Anmeldung Banner Systeminformationen oder Betriebsnotizen für Benutzer nach der Anmeldung bereitstellen.

set system login banner pre-login <message>

Konfigurieren Sie eine Nachricht, die Benutzern vor dem Auftreten der username und password Eingaben angezeigt wird.

set system login banner post-login <message>

Konfigurieren Sie eine Nachricht, die Benutzern nach erfolgreicher Authentifizierung angezeigt wird.

Hinweis

Verwenden Sie \\n, um Zeilenumbrüche in Multi-Line-Banner-Nachrichten einzufügen.

Anmelde-Sessions-Limits

set system login max-login-session <number>

Konfigurieren Sie die maximale Anzahl gleichzeitiger Anmelde-Session.

Hinweis

Wenn Sie gleichzeitige Anmelde-Session begrenzen, müssen Sie auch eine Session <timeout> konfigurieren. Dies löscht inaktive Sessions und verhindert Blockierung neuer Anmeldeversuche.

set system login timeout <timeout>

Konfigurieren Sie die Anmelde-Session-Timeout, in Sekunden.

Inaktive Anmelde-Session werden nach dieser Periode beendet.

Konfigurationsbeispiele

Beispiel 1: Mehrschlüssel-SSH mit MFA und Quellbeschränkungen

In dieser Konfiguration verwenden User1 und User2 beide das vyos-Benutzerkonto, jeder mit einem eindeutigen SSH-Schlüssel. User1 ist auf die Authentifizierung von einer einzelnen IP-Adresse beschränkt.

Für beide Benutzer erfordert die Passwort-basierte Anmeldung OTP -basierte MFA.

set system login user vyos authentication public-keys 'User1' key "AAAAB3Nz...KwEW"
set system login user vyos authentication public-keys 'User1' type ssh-rsa
set system login user vyos authentication public-keys 'User1' options "from=&quot;192.168.0.100&quot;"

set system login user vyos authentication public-keys 'User2' key "AAAAQ39x...fbV3"
set system login user vyos authentication public-keys 'User2' type ssh-rsa

set system login user vyos authentication otp key OHZ3OJ7U2N25BK4G7SOFFJTZDTCFUUE2
set system login user vyos authentication plaintext-password vyos

Beispiel 2: Containerisierte TACACS+ Deployment mit Redundanz.

In dieser Konfiguration hostet der VyOS-Router seine eigene Authentifizierungsinfrastruktur mit zwei containerisierten TACACS+ Servern (tacacs1 und tacacs2) auf einem privaten Netzwerk für Redundanz.

Systemanmeldungen werden gegen Anmeldeinformationen authentifiziert, die innerhalb dieser internen Container gespeichert sind, anstatt das lokale Benutzerdatenbank des Routers.

Zuerst laden Sie das Image im Betriebsmodus herunter:

add container image lfkeitel/tacacs_plus:latest

Dann konfigurieren Sie die Container im Konfigurationsmodus:

set container network tac-test prefix '100.64.0.0/24'

set container name tacacs1 image 'lfkeitel/tacacs_plus:latest'
set container name tacacs1 network tac-test address '100.64.0.11'

set container name tacacs2 image 'lfkeitel/tacacs_plus:latest'
set container name tacacs2 network tac-test address '100.64.0.12'

set system login tacacs server 100.64.0.11 key 'tac_plus_key'
set system login tacacs server 100.64.0.12 key 'tac_plus_key'

commit

Sie können sich nun per SSH oder Konsole mit admin/admin Anmeldeinformationen, die von dem Container-Image bereitgestellt werden, anmelden.
