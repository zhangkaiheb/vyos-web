NTP

NTP (Network Time Protocol) ist ein Netzwerkprotokoll zur Synchronisierung von Uhren zwischen Computern über paketvermittelte, variabel-latente Datennetze. Es wird seit vor 1985 betrieben und ist eines der ältesten Internet-Protokolle, die heute verwendet werden.

NTP soll alle teilnehmenden Computer innerhalb von wenigen Millisekunden von UTC synchronisieren. Es verwendet den Schnittalgorithmus, eine modifizierte Version des Marzullo-Algorithmus, um genaue Zeitserver auszuwählen und ist darauf ausgelegt, die Auswirkungen variabler Netzwerklatenz zu verringern. NTP kann normalerweise die Zeit im öffentlichen Internet auf einige Zehntel Millisekunden genau halten und unter idealen Bedingungen in lokalen Netzwerken eine Genauigkeit von besser als einer Millisekunde erreichen. Asymmetrische Routen und Netzwerkbelastung können Fehler von 100 ms oder mehr verursachen.

Das Protokoll wird üblicherweise im Sinne eines Client-Server-Modells beschrieben, kann aber ebenso in Peer-to-Peer-Beziehungen verwendet werden, bei denen beide Peers den anderen als potenziellen Zeitsource betrachten. Implementierungen senden und empfangen Timestamps mit Hilfe von UDP auf Portnummer 123.

NTP gibt eine Warnung für jede bevorstehende Schaltsekunde bekannt, aber keine Informationen über lokale Zeitzone oder Sommerzeit werden übertragen.

Das aktuelle Protokoll ist Version 4 (NTPv4), das als vorgeschlagenes Standarddokumentiert in RFC 5905. Es ist rückwärtskompatibel mit Version 3, die in RFC 1305 spezifiziert ist.

Hinweis

VyOS 1.4 verwendet chrony anstelle von ntpd (siehe T3008), was keine anonymen NTP-Anfragen mehr akzeptiert wie in VyOS 1.3. Alle Konfigurationen werden migriert, um die anonyme Funktionalität beizubehalten. Für neue Einrichtungen müssen Sie bei Clients, die Ihr VyOS-System als NTP-Server verwenden, den allow-client-Befehl angeben.

Konfiguration

set service ntp server <address>

Konfigurieren Sie einen oder mehrere Server für die Synchronisation. Der Servername kann entweder eine IP-Adresse oder ein FQDN sein.

Drei Standard-NTP-Server sind festgelegt. Sie können sie ändern.

  • time1.vyos.net

  • time2.vyos.net

  • time3.vyos.net

set service ntp server <address> <noselect | nts | pool | prefer | ptp | interleave>

Konfigurieren Sie ein oder mehrere Attribute für den gegebenen NTP-Server.

  • noselect markiert den Server als nicht verwendbar, außer für Anzeigepurposes. Der Server wird durch den Auswahlalgorithmus verworfen.

  • nts aktiviert Network Time Security (NTS) für den Server gemäß RFC 8915

  • pool mobilisiert den dauerhaften Client-Modus mit einer Anzahl von entfernten Servern.

  • prefer markiert den Server als bevorzugt. Bei gleichen Bedingungen wird dieser Host für die Synchronisation unter einer Gruppe korrekt arbeitender Hosts gewählt.

  • ptp aktiviert den PTP-Transport für diesen Server (siehe PTP-Transport von NTP-Paketen).

  • interleave aktiviert den NTP-Interleaved-Modus (siehe draft-ntp-interleaved-modes), der die Synchronisationsgenauigkeit und Stabilität verbessern kann, wenn beide Seiten dies unterstützen.

set service ntp listen-address <address>

Der NTP-Prozess wird nur auf der angegebenen IP-Adresse lauschen. Sie müssen den <address> angeben und optional die erlaubten Clients. Mehrere Listenadressen für dieselbe IP-Familie werden nicht mehr unterstützt. Nur eine IPv4- und eine IPv6-Adresse können konfiguriert werden, wobei separate Befehle für jede verwendet werden.

set service ntp allow-client address <address>

Liste von Netzwerken oder Client-Adressen, die Zugriff auf diesen NTP-Server haben dürfen.

Mehrere Netzwerke/Client-IP-Adressen können konfiguriert werden.

set service ntp vrf <name>

Geben Sie den Namen der VRF-Instanz an.

set service ntp leap-second [ignore|smear|system|timezone]

Definiere, wie mit Schaltsekunden umgegangen werden soll.

  • ignore: Keine Korrektur wird für die Schaltsekunde auf die Uhr angewandt. Die Uhr wird später während der normalen Operation korrigiert, wenn neue Messungen gemacht werden und der geschätzte Offset die eine Sekunde Fehler enthält.

  • smear: Wenn eine Schaltsekunde verschmiert wird, wird der Schaltstatus auf dem Server unterdrückt und die gesendete Zeit wird langsam durch Schwingen korrigiert, anstatt zu springen. Die Clients benötigen keine besondere Konfiguration, da sie nicht wissen, dass es eine Schaltsekunde gibt und sie der Serverzeit folgen, die sie schließlich wieder in UTC bringt. Es muss darauf geachtet werden, sicherzustellen, dass sie nur NTP-Server verwenden, die die Schaltsekunde genau gleich verschmieren, um sich zu synchronisieren.

  • system: Beim Einfügen einer Schaltsekunde, springt der Kernel die Systemuhr rückwärts um eine Sekunde, wenn die Uhr 00:00:00 UTC erreicht. Beim Löschen einer Schaltsekunde, springt er vorwärts um eine Sekunde, wenn die Uhr 23:59:59 UTC erreicht.

  • timezone: Dieser Befehl gibt eine Zeitzone in der System-Zeitzone-Datenbank an, die chronyd verwenden kann, um zu bestimmen, wann die nächste Schaltsekunde stattfindet und welcher aktuelle Offset zwischen TAI und UTC ist. Es wird periodisch überprüft, ob 23:59:59 und 23:59:60 gültige Zeiten in der Zeitzone sind. Dies funktioniert normalerweise mit der richtigen/UTC-Zeitzone, die die Standardeinstellung ist.

Hardware-Timestamping von NTP-Paketen

Der chrony-Daemon auf VyOS kann die Fähigkeiten der Netzwerkkarten nutzen, um den exakten Zeitpunkt zu erfassen, zu dem Pakete auf der Schnittstelle empfangen wurden, sowie den Zeitpunkt, zu dem die Pakete tatsächlich übertragen wurden. Dies bietet eine verbesserte Genauigkeit und Stabilität, wenn das System unter Last steht, da Warteschlangen und OS-Kontextwechsel eine variable Verzögerung zwischen dem Zeitpunkt des Empfangs der Pakete auf dem Netzwerk und dem Zeitpunkt ihrer tatsächlichen Verarbeitung durch den NTP-Daemon verursachen können.

Das Hardware-Timestamping hängt von der Unterstützung der Netzwerkkarte ab. Einige Netzwerkkarten können so konfiguriert werden, dass sie Timestamps auf beliebige eingehende Pakete anwenden, während andere nur Timestamps für bestimmte Protokolle (z. B. PTP) unterstützen.

Wenn das Timestamping auf einer Schnittstelle aktiviert ist, versucht chrony standardmäßig, die Schnittstelle so zu konfigurieren, dass nur NTP-Pakete timestamped werden. Wenn dieses Modus nicht unterstützt wird, versucht chrony, es auf Timestamping aller Pakete zu setzen. Wenn keiner dieser Optionen unterstützt wird (z. B. wenn die Netzwerkkarte nur Timestamps für empfangene PTP-Pakete unterstützt), nutzt chrony nur das Timestamping von gesendeten Paketen, was immer noch einige Vorteile bietet.

set service ntp timestamp interface <interface>

Konfiguriert das Hardware-Timestamping auf der Schnittstelle <interface>. Der besondere Wert all kann auch angegeben werden, um Timestamping auf allen Schnittstellen zu aktivieren, die dies unterstützen.

Konfigurieren Sie das Timestamping-Verhalten mit folgender Option:

  • receive-filter [all|ntp|ptp|none] wählt den Empfangsfiltermodus aus, der steuert, welche eingehenden Pakete die Netzwerkkarte timestamped. Der gewählte Modus muss von der Netzwerkkarte unterstützt werden, sonst wird das Timestamping für die Schnittstelle deaktiviert.

Die folgenden receive-filter-Modi können ausgewählt werden:

  • all: Alle empfangenen Pakete werden timestamped.

  • ntp: Nur empfangene NTP-Protokollpakete werden timestamped.

  • ptp: Nur empfangene PTP-Protokollpakete werden timestamped. In Verbindung mit dem PTP-Transport für NTP-Pakete kann dies genutzt werden, um von Hardware-Timestamping auf Netzwerkkarten zu profitieren, die nur den ptp-Filtermodus unterstützen.

  • none: Keine empfangenen Pakete werden timestamped. Das Timestamping von gesendeten Paketen wird weiterhin genutzt, sofern von der Netzwerkkarte unterstützt.

PTP-Transport von NTP-Paketen

Das Precision Time Protocol (IEEE 1588) ist ein lokales Netzwerk-Zeitsynchronisationsprotokoll, das eine hohe Präzision der Zeitsynchronisation ermöglicht, indem es Hardwareuhren in Netzwerkkarten und anderen Netzwerkelementen nutzt. VyOS unterstützt derzeit kein standardspezifisches PTP, das unabhängig von NTP eingesetzt werden kann.

Für Netzwerke, die aus VyOS und anderen Linux-Systemen bestehen, die relativ aktuelle Versionen des chrony-Daemons laufen, können NTP-Pakete „tunneln“ über PTP. NTP über PTP bietet das Beste aus beiden Welten, indem es die Hardwareunterstützung für das Timestamping von PTP-Paketen nutzt, während die Konfigurationsflexibilität und Fehlertoleranz von NTP beibehalten werden.

set service ntp ptp

Activiert den PTP-Transport des NTP-Daemons. Der NTP-Daemon wird auf dem konfigurierten PTP-Port lauschen. Beachten Sie, dass einem oder mehreren Servern vor dem Synchronisieren über den Transport individuell PTP aktiviert werden muss.

set service ntp ptp port <port>

Konfiguriert den PTP-Port. Standardmäßig wird der Standardport 319 verwendet.
