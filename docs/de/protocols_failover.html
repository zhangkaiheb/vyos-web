Fehlerschutz

Fehlerschutzrouten sind manuell konfigurierte Netzwerkwege, die nur verwendet werden, während ihre Gesundheitsüberprüfungziele erreichbar sind. Wenn das Ziel nicht mehr antwortet, entfernt VyOS die Route aus der Routing-Tabelle und installiert sie erneut, sobald das Ziel wieder verfügbar ist.

Konfiguration

Verwenden Sie die folgenden Befehle, um Fehlerschutzrouten für ein bestimmtes entferntes <subnet> zu konfigurieren, das über den nächsten Hop <address> erreichbar ist.

set protocols failover route <subnet> next-hop <address> check target <target-address>

Konfigurieren Sie die IP-Adresse des Gesundheitsüberprüfungziels.

Dies ist normalerweise ein hochverfügbares Host, entweder innerhalb des Ziel-Subnets oder im öffentlichen Internet.

Beispiel:

set protocols failover route 203.0.113.1/32 next-hop 10.217.37.254 check target 8.8.8.8
set protocols failover route <subnet> next-hop <address> check timeout <timeout>

Konfigurieren Sie das Timeout-Intervall in Sekunden zwischen den Zielgesundheitsprüfungen.

Der gültige Bereich beträgt 1 bis 300 Sekunden. Der Standardwert beträgt 10 Sekunden.

Beispiel:

set protocols failover route 203.0.113.1/32 next-hop 10.217.37.254 check timeout 2
set protocols failover route <subnet> next-hop <address> check type <protocol>

Konfigurieren Sie das Protokoll, das für die Gesundheitsprüfung verwendet wird.

Folgende Protokolle sind verfügbar:

  • icmp: VyOS sendet zwei ICMP Echo Request-Pakete mit einem Antworttimeout von 1 Sekunde. Die Gesundheitsprüfung ist erfolgreich, wenn mindestens eine Antwort empfangen wird.

  • arp: VyOS sendet zwei ARP-Anfragen mit einem Antworttimeout von 1 Sekunde. Die Gesundheitsprüfung ist erfolgreich, wenn mindestens eine Antwort empfangen wird.

  • tcp: VyOS prüft, ob der Ziel-TCP-Port geöffnet ist. Die Gesundheitsprüfung ist erfolgreich, wenn eine TCP-Verbindung zum Zielport hergestellt wird.

Das Standardprotokoll ist icmp.

Hinweis

Wenn der Prüftyp auf tcp gesetzt wird, müssen Sie auch den Ziel-TCP-Port definieren.

Beispiel:

set protocols failover route 203.0.113.1/32 next-hop 10.217.37.254 check type tcp
set protocols failover route <subnet> next-hop <address> check port <port>

Konfigurieren Sie den Ziel-TCP-Port des Gesundheitsüberprüfungziels.

Dieser Parameter gilt nur, wenn der Prüftyp als tcp konfiguriert ist.

Der gültige Portbereich beträgt 1 bis 65535.

Beispiel:

set protocols failover route 203.0.113.1/32 next-hop 10.217.37.254 check port 443
set protocols failover route <subnet> next-hop <address> check policy <policy>

Konfigurieren Sie die Erfolgspolitik der Gesundheitsprüfung für mehrere Ziele.

Folgende Politiken sind verfügbar:

  • any-available: Die Gesundheitsprüfung ist erfolgreich, wenn mindestens eines der konfigurierten Ziele erfolgreich antwortet.

  • all-available: Die Gesundheitsprüfung ist nur erfolgreich, wenn jedes konfigurierte Ziel erfolgreich antwortet.

Die Standardpolitik ist any-available.

Beispiel:

set protocols failover route 203.0.113.1/32 next-hop 10.217.37.254 check policy all-available
set protocols failover route <subnet> next-hop <address> interface <interface>

Konfigurieren Sie die lokale Schnittstelle, die zum Erreichen des nächsten Hops verwendet wird.

Dieser Parameter ist obligatorisch.

Beispiel:

set protocols failover route 203.0.113.1/32 next-hop 10.217.37.254 interface eth0
set protocols failover route <subnet> next-hop <address> metric <1-255>

Konfigurieren Sie die Metrik (Kosten) für die Fehlerschutzroute.

Die Metrik definiert die Routenpriorität. Ein niedrigerer Metrik-Wert zeigt eine vorgezogene Route an.

Der Standardwert ist 1.

Beispiel:

set protocols failover route 203.0.113.1/32 next-hop 10.217.37.254 metric 50
set protocols failover route <subnet> next-hop <address> onlink

Konfigurieren Sie den nächsten Hop, um über die zugewiesene Schnittstelle erreichbar zu sein, selbst wenn <address> außerhalb eines auf dieser Schnittstelle konfigurierten Subnets liegt.

Beispiel:

set protocols failover route 203.0.113.1/32 next-hop 10.217.37.254 onlink

Beispiele

Fehlerschutzroute mit einem einzelnen nächsten Hop und ICMP-Gesundheitsprüfung

Das folgende Beispiel konfiguriert eine Fehlerschutzroute zu 203.0.113.1/32 über den nächsten Hop 192.0.2.1 auf eth0. Der nächste Hop wird mit ICMP-Proben zu 192.0.2.1 alle 5 Sekunden überwacht, und die Route wird mit einer Metrik von 10 installiert.

set protocols failover route 203.0.113.1/32 next-hop 192.0.2.1 check target '192.0.2.1'
set protocols failover route 203.0.113.1/32 next-hop 192.0.2.1 check timeout '5'
set protocols failover route 203.0.113.1/32 next-hop 192.0.2.1 check type 'icmp'
set protocols failover route 203.0.113.1/32 next-hop 192.0.2.1 interface 'eth0'
set protocols failover route 203.0.113.1/32 next-hop 192.0.2.1 metric '10'

Überprüfen Sie die Route:

vyos@vyos:~$ show ip route 203.0.113.1
Routing entry for 203.0.113.1/32
  Known via "kernel", distance 0, metric 10, best
  Last update 00:00:39 ago
  Flags: Selected
  Status: Installed
  * 192.0.2.1, via eth0, weight 1

Zwei Fehlerschutzrouten mit unterschiedlichen Metriken

Das folgende Beispiel konfiguriert zwei Fehlerschutzrouten zu 203.0.113.1/32, jeweils über einen anderen nächsten Hop. Der primäre nächste Hop 192.0.2.1 wird auf eth0 mit einer Metrik von 10 erreicht, und der Backup-Nächste Hop 198.51.100.1 wird auf eth2 mit einer Metrik von 20 erreicht. Beide nächste Hops werden mit ICMP Proben alle 5 Sekunden überwacht.

Während beide Gesundheitsprüfungen erfolgreich sind, wird die Route durch eth0 bevorzugt. Wenn das primäre Ziel nicht mehr antwortet, wird seine Route aus der Routing-Tabelle entfernt, und der Datenverkehr fällt auf 198.51.100.1 über eth2.

set protocols failover route 203.0.113.1/32 next-hop 192.0.2.1 check target '192.0.2.1'
set protocols failover route 203.0.113.1/32 next-hop 192.0.2.1 check timeout '5'
set protocols failover route 203.0.113.1/32 next-hop 192.0.2.1 check type 'icmp'
set protocols failover route 203.0.113.1/32 next-hop 192.0.2.1 interface 'eth0'
set protocols failover route 203.0.113.1/32 next-hop 192.0.2.1 metric '10'

set protocols failover route 203.0.113.1/32 next-hop 198.51.100.1 check target '198.51.100.99'
set protocols failover route 203.0.113.1/32 next-hop 198.51.100.1 check timeout '5'
set protocols failover route 203.0.113.1/32 next-hop 198.51.100.1 check type 'icmp'
set protocols failover route 203.0.113.1/32 next-hop 198.51.100.1 interface 'eth2'
set protocols failover route 203.0.113.1/32 next-hop 198.51.100.1 metric '20'

Überprüfen Sie die Routen:

vyos@vyos:~$ show ip route 203.0.113.1
Routing entry for 203.0.113.1/32
  Known via "kernel", distance 0, metric 10, best
  Last update 00:08:06 ago
  Flags: Selected
  Status: Installed
  * 192.0.2.1, via eth0, weight 1

Routing entry for 203.0.113.1/32
  Known via "kernel", distance 0, metric 20
  Last update 00:08:14 ago
  Flags: None
  Status: Installed
  * 198.51.100.1, via eth2, weight 1
