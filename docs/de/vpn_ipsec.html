IPsec-Übersicht

IPsec ist das Framework zur Sicherung von Daten. IPsec erreicht dies durch Bereitstellung von Authentifizierung, Verschlüsselung von IP-Netzwerkpaketen, Schlüsselaustausch und Schlüsselverwaltung. VyOS verwendet das Strongswan-Paket zur Implementierung von IPsec.

Authentication Header (AH) ist in RFC 4302 definiert. Er verwendet den IP-Header und die Daten-Nutzlast, um einen Hash zu erstellen, der dann an das Paket angehängt wird. Dieser Hash wird verwendet, um zu überprüfen, dass die Daten während der Netzwerkübertragung nicht verändert wurden.

Encapsulating Security Payload (ESP) ist in RFC 4303 definiert. Es bietet sowohl Verschlüsselung als auch Authentifizierung der Daten.

Es gibt zwei IPsec-Modi:

IPsec-Transportmodus: Im Transportmodus wird der IPsec-Header (AH oder ESP) zwischen den IP-Header und den Protokoll-Header der höheren Schicht eingefügt.

IPsec-Tunnelmodus: Im Tunnelmodus wird das ursprüngliche IP-Paket in ein anderes IP-Datagramm gekapselt, wobei der IPsec-Header (AH oder ESP) zwischen den äußeren und inneren Header eingefügt wird.

IKE (Internet Key Exchange)

Das IKE-Protokoll ist die Standardmethode für die sichere IPsec-Schlüsselverhandlung. IKE wurde entwickelt, um gegenseitige Authentifizierung von IKE-Peers bereitzustellen und gemeinsame Schlüssel zur Erstellung von IPsec Security Associations (SA) zu etablieren. Eine Security Association (SA) umfasst alle relevanten Attribute der Verbindung, einschließlich der verwendeten Verschlüsselungsalgorithmen, des IPsec-Modus, der Verschlüsselungsschlüssel und anderer Parameter, die mit der Datenübertragung durch die VPN-Verbindung zusammenhängen.

IKEv1

IKEv1 ist die ältere Version, die heute noch verwendet wird. Die meisten Hersteller empfehlen jetzt die Verwendung des IKEv2-Protokolls.

IKEv1 ist in den folgenden RFCs beschrieben: RFC 2409 (IKE), RFC 3407 (IPsec DOI), RFC 3947 (NAT-T), RFC 3948 (UDP-Kapselung von ESP-Paketen), RFC 3706 (DPD)

IKEv1 arbeitet in zwei Phasen zur establishment von IKE- und IPsec-SAs:

  • Phase 1 bietet gegenseitige Authentifizierung von IKE-Peers und establishment von Sitzungsschlüsseln. Diese Phase verwendet DH-Austausch, Cookies und ID-Austausch, um die IKE-SA zu erstellen. Sobald die IKE-SA etabliert ist, wird die gesamte IKE-Kommunikation zwischen Initiator und Responder durch Verschlüsselung und Authentifizierungs-Integritätsprüfungen geschützt. IKE Phase 1 bietet zwei Modi: Hauptmodus und Aggressiver Modus.
    • Hauptmodus wird für Site-to-Site-VPN-Verbindungen verwendet.
    • Aggressiver Modus wird für Fernzugriffs-VPN-Verbindungen verwendet.
  • Phase 2 bietet die Verhandlung und establishment von IPsec-SAs, die IP-Datenverkehr mit ESP oder AH sichern.

IKEv2

IKEv2 ist in RFC 7296 beschrieben. Der größte Unterschied zwischen IKEv1 und IKEv2 besteht darin, dass IKEv2 einfacher und zuverlässiger als IKEv1 ist, mit weniger Nachrichten, die während der VPN-Einrichtung ausgetauscht werden, und zusätzlichen Sicherheitsfunktionen.

IKE-Authentifizierung

VyOS unterstützt 3 Authentifizierungsmethoden:

  • Pre-shared Key: Bei dieser Methode müssen beide Peers des IPsec-Tunnels den gleichen Pre-shared Key haben.
  • Digitale Zertifikate: Bei dieser Methode wird PKI verwendet.
  • RSA-Schlüssel: Wenn die RSA-Schlüsselmethode in der IKE-Richtlinie verwendet wird, stellen Sie sicher, dass jeder Peer den öffentlichen Schlüssel des anderen Peers hat.

DPD (Dead Peer Detection)

Dies ist ein Mechanismus, der verwendet wird, um zu erkennen, wann ein VPN-Peer nicht mehr aktiv ist. Dieser Mechanismus hat unterschiedliche Algorithmen für IKEv1 und IKEv2 in VyOS. DPD-Anfragen werden als ISAKMP R-U-THERE-Nachrichten gesendet, und DPD-Antworten werden als ISAKMP R-U-THERE-ACK-Nachrichten gesendet. In IKEv1 sendet DPD Nachrichten in konfigurierten Intervallen. Wenn innerhalb des DPD-Timeouts keine Antwort auf diese Pakete empfangen wird, wird der Remote-Peer als nicht erreichbar betrachtet. In IKEv2 sendet DPD Nachrichten in konfigurierten Intervallen. Wenn eine Anfrage unbeantwortet bleibt, führt Strongswan seinen Retransmissionsalgorithmus mit seinen Timern aus.

Post-Quantum Pre-Shared Key (PPK)

Post-Quantum-Pre-Shared-Keys helfen, eine gewisse Quantenresistenz für IPsec-Tunnel bereitzustellen, wenn Post-Quantum-Schlüsselaustauschalgorithmen wie ML-KEM nicht verfügbar sind. Die Verwendung von PPK in IKEv2 ist in RFC 8784 beschrieben.

PPK kann in VyOS unter vpn ipsec authentication ppk konfiguriert werden. PPK erfordert eine ID und einen geheimen Wert. Wenn PPK für eine erfolgreiche IPsec-Verbindung erforderlich ist, müssen sowohl die ID als auch der geheime Wert übereinstimmen. Der geheime Wert kann Klartext, ein Hexadezimalwert oder ein Base64-Wert sein. Der Standard ist Klartext. Bei Verwendung anderer Werttypen muss der geheime Werttyp definiert werden.

IKE-Konfiguration

IKE-Attribute

VyOS-IKE-Gruppen haben die folgenden Optionen:

set vpn ipsec ike-group <name> close-action <action>

Definiert die Aktion, die ausgeführt werden soll, wenn der Remote-Peer unerwartet eine CHILD_SA schließt:

  • none - Auf none setzen (Standard)
  • trap - Eine Trap-Richtlinie für die CHILD_SA installieren; Verkehr, der diesen Richtlinien entspricht, löst ein Acquire-Ereignis aus, wodurch der Daemon die erforderliche IKE/IPsec-SA etabliert.
  • start - Versuchen, die CHILD_SA sofort neu zu erstellen.

set vpn ipsec ike-group <name> ikev2-reauth

Ob das Rekeying der IKE_SA auch eine erneute Authentifizierung des Peers bewirken soll. In IKEv1 wird die Authentifizierung immer durchgeführt. Das Setzen dieses Parameters ermöglicht die erneute Authentifizierung des Remote-Hosts während des IKE-Rekeyings.

set vpn ipsec ike-group <name> key-exchange

Welches Protokoll zur Initiierung der Verbindung verwendet werden soll. Wenn nicht gesetzt, werden beide Protokolle verarbeitet, und die Verbindung verwendet IKEv2 beim Initiieren, akzeptiert jedoch jede Protokollversion beim Antworten:

  • ikev1 - IKEv1 für den Schlüsselaustausch verwenden.
  • ikev2 - IKEv2 für den Schlüsselaustausch verwenden.

set vpn ipsec ike-group <name> lifetime

IKE-Lebensdauer (Sekunden) <0-86400> (Standard 28800).

set vpn ipsec ike-group <name> mode

IKEv1 Phase 1 Modusauswahl:

  • main - Hauptmodus für den Schlüsselaustausch im IKEv1-Protokoll verwenden (empfohlener Standard).
  • aggressive - Aggressiver Modus für den Schlüsselaustausch im IKEv1-Protokoll; der aggressive Modus ist weniger sicher als der Hauptmodus.

set vpn ipsec ike-group <name> proposal <number> dh-group <dh-group number>

DH-Gruppe. Der Standardwert ist 2.

set vpn ipsec ike-group <name> proposal <number> encryption <encryption>

Verschlüsselungsalgorithmus. Der Standardwert ist aes128.

set vpn ipsec ike-group <name> proposal <number> hash <hash>

Hash-Algorithmus. Der Standardwert ist sha1.

set vpn ipsec ike-group <name> proposal <number> prf <prf>

Pseudozufallsfunktion.

DPD-Konfiguration

set vpn ipsec ike-group <name> dead-peer-detection action <action>

Aktion, die bei DPD-Timeout für diese CHILD_SA ausgeführt werden soll:

  • trap - Eine Trap-Richtlinie installieren, die übereinstimmenden Verkehr erfasst und versucht, den Tunnel bei Bedarf neu zu verhandeln.
  • clear - Die CHILD_SA ohne weitere Aktion schließen (Standard).
  • restart - Sofort versuchen, die CHILD_SA unter einer neuen IKE_SA neu zu verhandeln.

set vpn ipsec ike-group <name> dead-peer-detection interval <interval>

Keepalive-Intervall (Sekunden) <2-86400> (Standard 30).

set vpn ipsec ike-group <name> dead-peer-detection timeout <timeout>

Keepalive-Timeout (Sekunden) <2-86400> (Standard 120) nur IKEv1

ESP-Attribute

In VyOS werden ESP-Attribute durch ESP-Gruppen angegeben. Mehrere Vorschläge können innerhalb einer einzelnen Gruppe angegeben werden.

set vpn ipsec esp-group <name> compression

Das IPComp-Protokoll (IP Payload Compression) aktivieren, das die Komprimierung von IP-Paketinhalten ermöglicht.

set vpn ipsec esp-group <name> disable-rekey

Rekeying von SAs lokal nicht initiieren; der Remote-Peer muss vor dem Ablauf rekeyen.

set vpn ipsec esp-group <name> life-bytes <bytes>

ESP-Lebensdauer (Bytes) <1024-26843545600000>. Anzahl der übertragenen Bytes, bevor die IPsec-SA abläuft.

set vpn ipsec esp-group <name> life-packets <packets>

ESP-Lebensdauer (Pakete) <1000-26843545600000>. Anzahl der übertragenen Pakete, bevor die IPsec-SA abläuft.

set vpn ipsec esp-group <name> lifetime <timeout>

ESP-Lebensdauer (Sekunden) <30-86400> (Standard 3600). Wie lange eine bestimmte Instanz der Verbindung (die Menge der Verschlüsselungs-/Authentifizierungsschlüssel für Benutzerdatenpakete) von der erfolgreichen Verhandlung bis zum Ablauf bestehen soll.

set vpn ipsec esp-group <name> mode <mode>

Verbindungstyp:

  • tunnel - Tunnelmodus (Standard).
  • transport - Transportmodus.

set vpn ipsec esp-group <name> pfs <dh-group>

Ob Perfect Forward Secrecy auf dem Schlüsselkanal der Verbindung erforderlich ist, und definiert die Diffie-Hellman-Gruppe für PFS:

  • enable - Die Diffie-Hellman-Gruppe von der IKE-Gruppe erben (Standard).
  • disable - PFS deaktivieren.
  • <dh-group> - Die Diffie-Hellman-Gruppe für PFS definieren.

set vpn ipsec esp-group <name> proposal <number> encryption <encryption>

Verschlüsselungsalgorithmus. Der Standardwert ist aes128.

set vpn ipsec esp-group <name> proposal <number> hash <hash>

Hash-Algorithmus. Der Standardwert ist sha1.

Globale IPsec-Einstellungen

set vpn ipsec interface <name>

Schnittstellenname, der zur Einschränkung ausgehender IPsec-Richtlinien verwendet wird. Mehrere Schnittstellen können angegeben werden. Wenn keine Schnittstelle angegeben ist, gelten IPsec-Richtlinien für alle Schnittstellen.

set vpn ipsec log level <number>

Protokollstufe. Der Standardwert ist 0.

set vpn ipsec log subsystem <name>

Daemon-Subsystem.

Optionen

set vpn ipsec options disable-route-autoinstall

Routen zu Remote-Netzwerken nicht automatisch installieren.

set vpn ipsec options flexvpn

FlexVPN- vendor ID-Payload erlauben (nur IKEv2). Sendet das Cisco FlexVPN vendor ID-Payload (nur IKEv2), das erforderlich ist, um Cisco-geräten zu ermöglichen, lokale Verkehrsselektoren zu verhandeln.

set vpn ipsec options interface <name>

Zu verwendender Schnittstellenname. Der Schnittstellenname, auf dem virtuelle IP-Adressen installiert werden sollen. Wenn nicht angegeben, werden Adressen auf der ausgehenden Schnittstelle installiert.

set vpn ipsec options virtual-ip

Installation virtueller IP-Adressen erlauben.

IKEv2-Retransmission

Wenn der Peer nicht auf DPD-Pakete antwortet, initiiert der Router ein Retransmissionsverfahren. Das Timeout wird mit der folgenden Formel berechnet:

relative timeout = timeout * base ^ (attempts-1)

set vpn ipsec options retransmission attempts

Anzahl der Versuche, bevor der Peer als ausgefallen betrachtet wird. Der Standardwert ist 5.

set vpn ipsec options retransmission base

Basis für exponentielles Backoff. Der Standardwert ist 1.8.

set vpn ipsec options retransmission timeout

Timeout vor der ersten Retransmission (Sekunden). Der Standardwert ist 4.

Mit den Standardwerten werden Pakete wie folgt retransmittiert:

IPsec-Site-to-Site-VPN-Typen

VyOS unterstützt zwei Arten von IPsec-VPN: richtlinienbasiertes IPsec-VPN und routenbasiertes IPsec-VPN.

Richtlinienbasiertes VPN

Das richtlinienbasierte VPN basiert auf statisch konfigurierten Richtlinien. Jede Richtlinie erstellt eine unabhängige IPSec-SA. Verkehr, der diesen SAs entspricht, wird verschlüsselt und an den Remote-Peer geleitet.

Routenbasiertes VPN

Das routenbasierte VPN basiert auf sicherem Verkehr, der durch eine Virtual Tunnel Interface (VTI) geleitet wird. Diese Art von IPsec-VPN ermöglicht die Verwendung von Routing-Protokollen.

Site-to-Site-VPN-Konfiguration

Anforderungen und Voraussetzungen für Site-to-Site-VPN

Verhandlungsparameter, die übereinstimmen müssen

Phase 1
  • IKE-Version
  • Authentifizierung
  • Verschlüsselung
  • Hash
  • PRF
  • Lebensdauer
Hinweis: Strongswan empfiehlt die Verwendung der gleichen Lebensdauerwerte auf beiden Peers
Phase 2
  • Verschlüsselung
  • Hash
  • PFS
  • Modus (Tunnel oder Transport)
  • Lebensdauer
Hinweis: Strongswan empfiehlt die Verwendung der gleichen Lebensdauerwerte auf beiden Peers
  • Remote- und lokale Netzwerke in der SA müssen auf beiden Peers kompatibel sein

Konfigurationsschritte für Site-to-Site-VPN

Das folgende Beispiel zeigt die Konfiguration für einen Router, der an einem IPsec-VPN teilnimmt.

Tunnelinformationen:

  • Phase 1:
    • Verschlüsselung: AES256
    • Hash: SHA256
    • PRF: SHA256
    • DH: 14
    • Lebensdauer: 28800
  • Phase 2:
    • IPsec-Modus: Tunnel
    • Verschlüsselung: AES256
    • Hash: SHA256
    • PFS: Von DH Phase 1 geerbt
    • Lebensdauer: 3600
  • Bei Verwendung von richtlinienbasiertem VPN
    • Remote-Netzwerk ist 192.168.50.0/24. Lokales Netzwerk ist 192.168.10.0/24
  • Bei Verwendung von routenbasiertem VPN
    • VTI-Schnittstellen-IP ist 10.0.0.1/30
Hinweis: Wir empfehlen nicht, gleichzeitig sowohl richtlinienbasierte als auch routenbasierte VPN-Konfigurationen für denselben Peer zu verwenden.

1. ike-group konfigurieren (IKE Phase 1)

set vpn ipsec ike-group IKE close-action 'start'
set vpn ipsec ike-group IKE key-exchange 'ikev1'
set vpn ipsec ike-group IKE lifetime '28800'
set vpn ipsec ike-group IKE proposal 10 dh-group '14'
set vpn ipsec ike-group IKE proposal 10 encryption 'aes256'
set vpn ipsec ike-group IKE proposal 10 hash 'sha256'
set vpn ipsec ike-group IKE proposal 10 prf 'prfsha256'

2. ESP-group konfigurieren (IKE Phase 2)

set vpn ipsec esp-group ESP lifetime '3600'
set vpn ipsec esp-group ESP mode 'tunnel'
set vpn ipsec esp-group ESP pfs 'enable'
set vpn ipsec esp-group ESP proposal 10 encryption 'aes256'
set vpn ipsec esp-group ESP proposal 10 hash 'sha256'

3. Öffentliche IP-Adresse der Schnittstelle eth0 angeben

set vpn ipsec ipsec-interfaces interface eth0

4. Site-to-Site-Peer konfigurieren

Konfiguration für richtlinienbasiertes VPN:

set vpn ipsec site-to-site peer 203.0.113.2 authentication mode 'pre-shared-secret'
set vpn ipsec site-to-site peer 203.0.113.2 authentication id '192.0.2.1'
set vpn ipsec site-to-site peer 203.0.113.2 authentication remote-id '203.0.113.2'
set vpn ipsec site-to-site peer 203.0.113.2 connection-type 'respond'
set vpn ipsec site-to-site peer 203.0.113.2 default-esp-group 'ESP'
set vpn ipsec site-to-site peer 203.0.113.2 ike-group 'IKE'
set vpn ipsec site-to-site peer 203.0.113.2 local-address '192.0.2.1'
set vpn ipsec site-to-site peer 203.0.113.2 tunnel 1 local prefix '192.168.10.0/24'
set vpn ipsec site-to-site peer 203.0.113.2 tunnel 1 remote prefix '192.168.50.0/24'

Konfiguration für routenbasiertes VPN:

set interfaces vti vti0 address '10.0.0.1/30'
set interfaces vti vti0 description 'VPN VTI interface'

set vpn ipsec site-to-site peer 203.0.113.2 authentication mode 'pre-shared-secret'
set vpn ipsec site-to-site peer 203.0.113.2 authentication id '192.0.2.1'
set vpn ipsec site-to-site peer 203.0.113.2 authentication remote-id '203.0.113.2'
set vpn ipsec site-to-site peer 203.0.113.2 connection-type 'respond'
set vpn ipsec site-to-site peer 203.0.113.2 default-esp-group 'ESP'
set vpn ipsec site-to-site peer 203.0.113.2 ike-group 'IKE'
set vpn ipsec site-to-site peer 203.0.113.2 local-address '192.0.2.1'
set vpn ipsec site-to-site peer 203.0.113.2 vti bind to 'vti0'
set vpn ipsec site-to-site peer 203.0.113.2 vti esp-group 'ESP'

Übersicht über Fernzugriffs-VPN

Das Fernzugriffs-VPN ermöglicht es Remote-Benutzern, sich sicher über einen IPsec-Tunnel mit einem Unternehmensnetzwerk zu verbinden. VyOS unterstützt mehrere Konfigurationsmethoden für Fernzugriffs-VPN, einschließlich Pre-shared Key, Zertifikat und EAP-basierter Authentifizierung.

Typen von Fernzugriffs-VPN

Pre-shared Key-basierter Fernzugriff

Die einfachste Konfigurationsmethode für Fernzugriff, bei der sich jeder Remote-Benutzer mit demselben Pre-shared Key authentifiziert. Geeignet für kleine Bereitstellungen oder Testumgebungen.

Zertifikat-basierter Fernzugriff

Verwendet X.509-Zertifikate zur Authentifizierung und bietet höhere Sicherheit. Jeder Benutzer kann sein eigenes Zertifikat haben, was die Verwaltung und Sperrung erleichtert.

EAP-basierter Fernzugriff

Das Extensible Authentication Protocol (EAP) ermöglicht die Benutzerauthentifizierung über einen RADIUS-Server. Unterstützt mehrere EAP-Methoden wie EAP-MSCHAPv2, EAP-TLS usw.

Konfiguration des Fernzugriffs-VPN

Grundlegende Konfigurationsschritte

1. IKE- und ESP-Gruppen konfigurieren

set vpn ipsec ike-group IKE-RA lifetime '28800'
set vpn ipsec ike-group IKE-RA proposal 1 encryption 'aes256'
set vpn ipsec ike-group IKE-RA proposal 1 hash 'sha256'
set vpn ipsec ike-group IKE-RA proposal 1 dh-group '14'

set vpn ipsec esp-group ESP-RA lifetime '3600'
set vpn ipsec esp-group ESP-RA proposal 1 encryption 'aes256'
set vpn ipsec esp-group ESP-RA proposal 1 hash 'sha256'

2. IP-Adresspool konfigurieren

set vpn ipsec remote-access connection RA pool 'RA-POOL'
set vpn ipsec remote-access connection RA pool RA-POOL prefix '100.64.0.0/24'
set vpn ipsec remote-access connection RA pool RA-POOL name-server '192.0.2.53'

3. Fernzugriffsverbindung konfigurieren

set vpn ipsec remote-access connection RA authentication local-id '192.0.2.1'
set vpn ipsec remote-access connection RA authentication server-mode 'x509'
set vpn ipsec remote-access connection RA authentication x509 certificate 'ipsec-cert'

set vpn ipsec remote-access connection RA remote-access-interface 'ppp0'
set vpn ipsec remote-access connection RA ike-group 'IKE-RA'
set vpn ipsec remote-access connection RA default-esp-group 'ESP-RA'

EAP-RADIUS-basierte Konfiguration

Verwendung eines RADIUS-Servers zur Benutzerauthentifizierung:

set vpn ipsec remote-access connection RA authentication client-mode 'eap-radius'
set vpn ipsec remote-access connection RA eap-radius server 1 address '192.0.2.100'
set vpn ipsec remote-access connection RA eap-radius server 1 key 'testing123'

set vpn ipsec remote-access connection RA pool RA-POOL name-server '192.0.2.53'
set vpn ipsec remote-access connection RA pool RA-POOL prefix '100.64.0.0/24'

Pre-shared Key-basierte Konfiguration

Geeignet für einfache Fernzugriffsszenarien:

set vpn ipsec remote-access connection RA authentication mode 'pre-shared-secret'
set vpn ipsec remote-access connection RA authentication id '192.0.2.1'
set vpn ipsec remote-access connection RA authentication local-id '192.0.2.1'

set vpn ipsec remote-access connection RA remote-access-interface 'ppp0'
set vpn ipsec remote-access connection RA ike-group 'IKE-RA'
set vpn ipsec remote-access connection RA default-esp-group 'ESP-RA'

set vpn ipsec remote-access connection RA pool RA-POOL prefix '100.64.0.0/24'

Konfiguration der Fernzugriffs-Schnittstelle

Das Fernzugriffs-VPN verwendet virtuelle PPP-Schnittstellen. Die Fernzugriffs-Schnittstelle muss angegeben werden:

set interfaces ppp ppp0 description 'Remote Access VPN Interface'
set vpn ipsec remote-access connection RA remote-access-interface 'ppp0'

Client-Konfigurationsbeispiele

Windows-Client

Der integrierte Windows-VPN-Client unterstützt IKEv2 und L2TP/IPsec. Konfigurationsschritte:

  1. "Einstellungen" > "Netzwerk & Internet" > "VPN" öffnen
  2. Auf "VPN-Verbindung hinzufügen" klicken
  3. VPN-Anbietername, Servername oder Adresse eingeben
  4. VPN-Typ auswählen (IKEv2 oder L2TP/IPsec)
  5. Authentifizierungsinformationen eingeben (Benutzername/Passwort oder Zertifikat)

Linux-Client

Linux-Benutzer können IPsec-VPN mit NetworkManager oder Befehlszeilentools konfigurieren:

# Verwendung des strongswan-Clients
sudo apt install strongswan strongswan-pki libcharon-extra-plugins

# /etc/ipsec.conf konfigurieren
conn vyos-ra
    right=192.0.2.1
    rightid=@192.0.2.1
    rightsubnet=0.0.0.0/0
    left=%defaultroute
    leftid=user@example.com
    eap_identity=user@example.com
    auto=start

macOS-Client

macOS hat integrierte Unterstützung für IKEv2-VPN:

  1. "Systemeinstellungen" > "Netzwerk" öffnen
  2. Auf "+" klicken, um eine neue Verbindung hinzuzufügen
  3. Schnittstelle als "VPN" und Typ als "IKEv2" auswählen
  4. Serveradresse und Remote-ID eingeben
  5. Authentifizierungsmethode konfigurieren

Mobile Geräte

iOS- und Android-Geräte haben beide integrierte Unterstützung für IKEv2-VPN:

  • iOS: Einstellungen > Allgemein > VPN & Netzwerk > VPN-Konfiguration hinzufügen
  • Android: Einstellungen > Netzwerk & Internet > VPN > VPN-Profil hinzufügen

Fehlerbehebung

Häufige Probleme

  • Verbindungsfehler: Prüfen Sie, ob IKE- und ESP-Parameter übereinstimmen, überprüfen Sie, ob Pre-shared Key oder Zertifikat korrekt ist
  • Authentifizierungsfehler: Bestätigen Sie, dass die RADIUS-Server-Konfiguration korrekt ist, überprüfen Sie die Benutzeranmeldeinformationen
  • IP-Adresse kann nicht abgerufen werden: Überprüfen Sie die IP-Adresspool-Konfiguration, stellen Sie sicher, dass genügend verfügbare Adressen vorhanden sind
  • Instabile Verbindung: Überprüfen Sie die DPD-Einstellungen, passen Sie die Lebensdauerparameter an

Grundlegende Diagnosebefehle

VyOS bietet eine Reihe von Befehlen zur Diagnose von IPsec-Problemen:

IPsec-Status anzeigen

Zeigt den aktuellen Status von IPsec-Tunneln und Security Associations an:

show vpn ipsec status

Dieser Befehl zeigt den aktuellen Status aller IPsec-Tunnel an, einschließlich ob Verbindungen etabliert sind, ob SAs (Security Associations) aktiv sind usw.

Security Associations anzeigen

Zeigt detaillierte IKE- und Child-SA-Informationen an:

show vpn ipsec sa

Die Ausgabe enthält die folgenden Informationen:

  • IKE-SA: IKE Phase 1 Security Associations
  • Child-SA: IKE Phase 2 Security Associations (Datentunnel)
  • Status: ESTABLISHED, INSTALLED usw.
  • Verschlüsselungsalgorithmen: Verwendete Verschlüsselungs- und Authentifizierungsalgorithmen
  • Verkehrsstatistiken: Anzahl der Pakete und Bytes durch den Tunnel

IPsec-Konfiguration anzeigen

Zeigt die aktuell laufende IPsec-Konfiguration an:

show vpn ipsec detail

Häufige Probleme und Lösungen

Tunnel wird nicht etabliert

Symptome: IPsec-Tunnelstatus zeigt "down" oder "connecting".

Mögliche Ursachen und Lösungen:

  1. Pre-shared Key stimmt nicht überein

    Stellen Sie sicher, dass die Pre-shared Keys auf beiden Seiten genau identisch sind, einschließlich Groß-/Kleinschreibung und Leerzeichen.

    show vpn ipsec site-to-site peer <peer-address>

  2. IKE-Vorschlag stimmt nicht überein

    Überprüfen Sie, ob die IKE-Gruppenkonfigurationen auf beiden Seiten kompatibel sind. Verschlüsselungsalgorithmus, Hash-Algorithmus und Diffie-Hellman-Gruppe müssen übereinstimmen.

    show vpn ipsec ike-group

  3. ESP-Vorschlag stimmt nicht überein

    Überprüfen Sie, ob die ESP-Gruppenkonfigurationen konsistent sind.

    show vpn ipsec esp-group

  4. Firewall blockiert

    Stellen Sie sicher, dass die Firewall die folgenden Ports durchlässt:

    • UDP 500 (IKE)
    • UDP 4500 (NAT-T)
    • Protokoll 50 (ESP)

  5. Fehlerhafte Konfiguration des lokalen/Remote-Subnetzes

    Überprüfen Sie, ob die Konfiguration des lokalen und Remote-Subnetzes für das Site-to-Site-VPN korrekt ist.

Tunnel ist aktiv, aber keine Daten

Symptome: IPsec-Tunnel zeigt "up", aber Daten können nicht durch den Tunnel übertragen werden.

Mögliche Ursachen und Lösungen:

  1. Child-SA nicht installiert

    Überprüfen Sie, ob die Child-SA erfolgreich installiert wurde:

    show vpn ipsec sa

    Wenn die Child-SA nicht angezeigt wird, kann dies auf einen ESP-Vorschlagskonflikt zurückzuführen sein.

  2. Routing-Probleme

    Überprüfen Sie, ob die Routing-Tabelle korrekt ist, und stellen Sie sicher, dass der Verkehr durch die Tunnelschnittstelle geleitet werden kann:

    show ip route

  3. MTU-Probleme

    IPsec fügt Paket-Overhead hinzu. Wenn Pakete zu groß sind, können sie verworfen werden. Versuchen Sie, die MTU anzupassen:

    set interfaces ethernet <interface> mtu 1400

  4. Asymmetrisches Routing

    Stellen Sie sicher, dass der Rückverkehr auch durch den IPsec-Tunnel geleitet wird; überprüfen Sie die Konfiguration des Policy-Routings.

Tunnel bricht häufig ab

Symptome: IPsec-Tunnel wird wiederholt etabliert und getrennt.

Mögliche Ursachen und Lösungen:

  1. DPD-Konfiguration (Dead Peer Detection)

    Überprüfen Sie, ob die DPD-Einstellungen zu aggressiv sind:

    show vpn ipsec site-to-site peer <peer-address> dead-peer-detection

    Empfohlene DPD-Einstellungen:

    • interval: 15-30 Sekunden
    • timeout: 30-60 Sekunden
    • action: restart

  2. IKE-Rekey-Fehler

    Überprüfen Sie die IKE-Lebensdauereinstellungen, um sicherzustellen, dass sie auf beiden Seiten kompatibel sind.

  3. NAT-Probleme

    Wenn sich eine der Seiten hinter NAT befindet, stellen Sie sicher, dass NAT Traversal (NAT-T) aktiviert ist.

Authentifizierungsfehler

Symptome: Protokolle zeigen Authentifizierungsfehler an.

Mögliche Ursachen und Lösungen:

  1. Pre-shared Key-Fehler

    Konfigurieren Sie den Pre-shared Key neu und stellen Sie sicher, dass er auf beiden Seiten genau übereinstimmt.

  2. Zertifikatprobleme

    Bei Verwendung der Zertifikatauthentifizierung:

      Überprüfen Sie, ob das Zertifikat nicht abgelaufen ist

      Überprüfen Sie, ob die Zertifikatkette vollständig ist

      Bestätigen Sie, dass die Zertifikat-Betreffernamen übereinstimmen

      Überprüfen Sie, ob das CA-Zertifikat ordnungsgemäß installiert ist

Protokolle und Debugging

IPsec-Protokolle anzeigen

Zeigt IPsec-bezogene Informationen in den Systemprotokollen an:

show log | match charon

Oder zeigen Sie detailliertere Protokolle an:

tail -f /var/log/syslog | grep charon

Detaillierte Protokollierung aktivieren

Für detailliertere Debugging-Informationen können Sie die IPsec-Debug-Protokollierung aktivieren:

set vpn ipsec logging log-level 3

Beschreibungen der Protokollstufen:

  • 0: Nur Fehler
  • 1: Warnungen
  • 2: Informationen (Standard)
  • 3: Debug
  • 4: Ausführliches Debugging
Warnung: Hohe Protokollstufen können große Mengen an Protokollausgaben erzeugen und die Systemleistung beeinträchtigen. Aktivieren Sie diese nur vorübergehend während der Fehlerbehebung.

Netzwerkpaket-Erfassung

Wenn andere Methoden das Problem nicht lösen können, können Sie tcpdump zur Netzwerkpaket-Erfassung verwenden:

IKE-Verkehr erfassen

tcpdump -i any -n port 500 or port 4500

ESP-Verkehr erfassen

tcpdump -i any -n proto 50

Paket-Erfassungsdatei speichern

tcpdump -i any -n -w /tmp/ipsec.pcap port 500 or port 4500 or proto 50

Sie können Wireshark verwenden, um die gespeicherte pcap-Datei zu analysieren.

Zurücksetzen und Neustart

IPsec-Tunnel zurücksetzen

Setzen Sie den IPsec-Tunnel für eine bestimmte Site zurück:

reset vpn ipsec site-to-site peer <peer-address>

IPsec-Dienst neu starten

Um den gesamten IPsec-Dienst neu zu starten:

restart vpn ipsec
Warnung: Das Neustarten des IPsec-Dienstes unterbricht alle aktiven VPN-Verbindungen.

Leistungsprobleme

Verschlüsselungsleistungstest

Testen Sie die Verschlüsselungsleistung des Systems:

show vpn ipsec performance

Hardwarebeschleunigung

Wenn Hardware-Verschlüsselungsbeschleunigung unterstützt wird, stellen Sie sicher, dass sie aktiviert ist:

show vpn ipsec hardware-acceleration
Tipp: Einige CPUs unterstützen den AES-NI-Befehlssatz, der die IPsec-Leistung erheblich verbessern kann. Verwenden Sie lscpu | grep aes, um die Unterstützung zu überprüfen.

Support kontaktieren

Wenn die oben genannten Schritte das Problem nicht lösen können, sammeln Sie bitte die folgenden Informationen und kontaktieren Sie den technischen Support:

  1. Vollständiger Konfigurationsexport: show configuration commands | match vpn
  2. IPsec-Statusausgabe: show vpn ipsec status
  3. Security Association-Informationen: show vpn ipsec sa
  4. Systemprotokolle: show log | match charon
  5. Netzwerkpaket-Erfassungsdatei (falls zutreffend)
