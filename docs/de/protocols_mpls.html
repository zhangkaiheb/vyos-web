MPLS

MPLS ist ein Paketweiterleitungsverfahren, das sich von der traditionellen IP-Weiterleitung unterscheidet. Anstatt IP-Adressen zu suchen, leiten MPLS-Router den Datenverkehr unter Verwendung von exakten Suchvorgängen nach MPLS-Labels ein, die zwischen dem Layer 2 (Ethernet) und Layer 3 (IP) Header eingefügt werden.

MPLS-Labels können statisch oder dynamisch zugewiesen werden. Dieser Abschnitt konzentriert sich auf die dynamische Label-Zuweisung mit Label-Verteilungsprotokollen wie dem LDP und RSVP-TE, oder über SR Erweiterungen zu OSPF oder IS-IS.

Diese Protokolle etablieren einen einseitigen Pfad, der als LSP bezeichnet wird, durch das Netzwerk. Wenn ein Paket das MPLS-Netzwerk betritt, fügt der Eingangsrouter ein MPLS-Label basierend auf dem Ziel hinzu und leitet das Paket entlang des LSP weiter. Jeder Zwischenrouter verwendet das ankommende Label, um die Ausgangsschnittstelle und das nächste Label-Wert zu suchen, wechselt das Label und leitet das Paket an dieser Schnittstelle weiter. Der Ausgangsrouter entfernt das Label und leitet das ursprüngliche Paket mit normaler IP-Routing weiter.

MPLS-Unterstützung in VyOS

Die MPLS-Unterstützung in VyOS befindet sich in Entwicklung, daher ist das Funktionsumfang aktuell begrenzt. Die grundlegende MPLS-Weiterleitung funktioniert, da der zugrunde liegende FRR-Routing-Stack RFC 3031 unterstützt.

Unterstützte Funktionen:

  • LDP: Gemäß RFC 5036 implementiert.

Hinweis

Weitere verwandte LDP-Standards umfassen RFCs 6720, 6667, 5919, 5561 und 7552.

Aktuelle Einschränkungen:

  • MPLS-VPNs: Noch keine Unterstützung für MPLS-fähige VPN-Dienste, wie z.B. L2VPNs und mVPNs.

  • RSVP-TE: Nicht unterstützt, da der zugrunde liegende FRR-Stack es derzeit nicht implementiert.

Labelverteilungsprotokoll (LDP)

MPLS unterstützt verschiedene Protokolle für die Pfaderstellung. VyOS implementiert LDP über den zugrunde liegenden FRR-Routing-Stack, gemäß RFC 5036.

LDP ist ein TCP-basiertes MPLS-Signalisierungsprotokoll, das Labels dynamisch verteilt, um label-switched paths zu erstellen. Es ist kein Routing-Protokoll und verlässt sich auf bestehende Routing-Protokolle für Weiterleitungsentscheidungen und Kommunikation mit anderen LDP-fähigen Routern.

Um Labelwerbung auszutauschen, stellt LDP TCP-Sessions mit automatisch entdeckten oder statisch konfigurierten Nachbarn her. Jede Session wird mit dem Transport-Adresse des Peers gebildet, die im Routing-Tabell vorhanden und kontinuierlich erreichbar sein muss.

Hinweis

Es wird empfohlen, dieselbe Adresse für den LDP-Router-ID und den Entdeckungs-Transport-Adresse zu verwenden. Für die Funktion von MPLS LDP in VyOS müssen beide Parameter explizit konfiguriert werden.

Hinweis

LDP hat kein Mechanismus zur Aktualisierung einer bestehenden Sitzung. Um eine Konfigurationsänderung oder eine Änderung der vereinbarten Sitzungsfähigkeiten anzuwenden, muss der LDP-Nachbar auf dem lokalen Router zurückgesetzt werden.

Konfiguration

set protocols mpls interface <interface>

MPLS auf dem angegebenen Interface aktivieren.

Beispiel:

set protocols mpls interface eth1
set protocols mpls parameters no-propagate-ttl

Verhindern Sie die Weitergabe des IP TTL in den MPLS-Header bei Label-Einschub.

Beispiel:

set protocols mpls parameters no-propagate-ttl
set protocols mpls parameters maximum-ttl <1-255>

Konfigurieren Sie den maximalen TTL-Wert für MPLS-Pakete.

Dieser Wert wird verwendet, wenn der TTL nicht aus dem IP-Header übernommen wird. Der Standardwert ist 255.

Beispiel:

set protocols mpls parameters maximum-ttl 15
set protocols mpls ldp interface <interface>

LDP auf dem angegebenen Interface aktivieren.

Beispiel:

set protocols mpls ldp interface eth1
set protocols mpls ldp interface <interface> disable-establish-hello

Deaktivieren Sie das ausgelöste Hello, das der Router auf dem angegebenen Interface sendet, in Reaktion auf das Empfangen eines LDP Hello von einem Peer.

Beispiel:

set protocols mpls ldp interface eth0 disable-establish-hello
set protocols mpls ldp router-id <address>

Konfigurieren Sie die IP-Adresse, die als LDP-Router-ID für das lokale Gerät verwendet wird.

Beispiel:

set protocols mpls ldp router-id 192.0.2.1
set protocols mpls ldp discovery transport-ipv4-address <address>

Konfigurieren Sie die IPv4-Transportadresse für IPv4-LDP-Verbindungen.

Beispiel:

set protocols mpls ldp discovery transport-ipv4-address 192.0.2.1
set protocols mpls ldp discovery transport-ipv6-address <address>

Konfigurieren Sie die IPv6-Transportadresse für IPv6-LDP-Verbindungen.

Beispiel:

set protocols mpls ldp discovery transport-ipv6-address 2001:db8::1
set protocols mpls ldp neighbor <ipv4-address> password <password>

Konfigurieren Sie die Authentifizierung für die LDP-Sitzung mit dem angegebenen Nachbarn.

Hinweis

Um eine erfolgreiche Sitzung zu ermöglichen, müssen beide Peers mit dem gleichen Passwort konfiguriert sein.

Beispiel:

set protocols mpls ldp neighbor 192.0.2.2 password mysharedsecret
set protocols mpls ldp neighbor <ipv4-address> session-holdtime <15-65535>

Konfigurieren Sie die LDP-Sitzungsholdzeit, in Sekunden, die an den angegebenen Nachbarn übermittelt wird.

Der Nachbar muss zurückgesetzt werden, damit diese Änderung wirksam wird.

Beispiel:

set protocols mpls ldp neighbor 192.0.2.2 session-holdtime 180
set protocols mpls ldp neighbor <ipv4-address> ttl-security <disable | 1-254>

Konfigurieren Sie TTL-Sicherheit (GTSM) für die LDP-Sitzung mit dem angegebenen Nachbarn.

Verwenden Sie disable, um die TTL-Sicherheit zu deaktivieren, oder setzen Sie einen Hop-Zählwert (1-254), um einzuschränken, welche eingehenden Pakete akzeptiert werden, basierend auf ihrem TTL.

Beispiel:

set protocols mpls ldp neighbor 192.0.2.2 ttl-security 5
set protocols mpls ldp discovery hello-ipv4-interval <1-65535>

Konfigurieren Sie das Intervall, in Sekunden, mit dem der Router IPv4 LDP Hello-Nachrichten sendet.

Beispiel:

set protocols mpls ldp discovery hello-ipv4-interval 5
set protocols mpls ldp discovery hello-ipv4-holdtime <1-65535>

Konfigurieren Sie die Holdzeit, in Sekunden, die in IPv4 LDP Hello Nachrichten angegeben wird.

Beispiel:

set protocols mpls ldp discovery hello-ipv4-holdtime 15
set protocols mpls ldp discovery hello-ipv6-interval <1-65535>

Konfigurieren Sie das Intervall, in Sekunden, mit dem der Router IPv6 LDP Hello-Nachrichten sendet.

Beispiel:

set protocols mpls ldp discovery hello-ipv6-interval 5
set protocols mpls ldp discovery hello-ipv6-holdtime <1-65535>

Konfigurieren Sie die Holdzeit, in Sekunden, die in IPv6 LDP Hello Nachrichten angegeben wird.

Beispiel:

set protocols mpls ldp discovery hello-ipv6-holdtime 15
set protocols mpls ldp discovery session-ipv4-holdtime <15-65535>

Konfigurieren Sie die LDP-Sitzungsholdzeit, in Sekunden, die in IPv4 LDP Initialisierungsnachrichten angegeben wird.

Beispiel:

set protocols mpls ldp discovery session-ipv4-holdtime 180
set protocols mpls ldp discovery session-ipv6-holdtime <15-65535>

Konfigurieren Sie die LDP-Sitzungsholdzeit, in Sekunden, die in IPv6 LDP Initialisierungsnachrichten angegeben wird.

Beispiel:

set protocols mpls ldp discovery session-ipv6-holdtime 180
set protocols mpls ldp import ipv4 import-filter filter-access-list <1-2699>

Filtern Sie die IPv4-Label-Bindungen (Zuordnung zwischen einem IPv4-Präfix und einem MPLS-Label) von LDP-Partnern mit dem angegebenen Zugriffslisten.

Nur Label-Bindungen, deren Präfix von der Zugriffsliste erlaubt wird, werden akzeptiert.

Beispiel:

set protocols mpls ldp import ipv4 import-filter filter-access-list 10
set protocols mpls ldp import ipv4 import-filter neighbor-access-list <1-2699>

Filtern Sie die IPv4-Label-Bindungen (Zuordnung zwischen einem IPv4-Präfix und einem MPLS-Label) von LDP-Partnern mit der angegebenen Zugriffsliste.

Nur Label-Bindungen, die von einem Peer stammen, dessen IPv4-Adresse von der Zugriffsliste erlaubt wird, werden akzeptiert.

Beispiel:

set protocols mpls ldp import ipv4 import-filter neighbor-access-list 20
set protocols mpls ldp import ipv6 import-filter filter-access-list6 <1-2699>

Filtern Sie die IPv6-Label-Bindungen (Zuordnung zwischen einem IPv6-Präfix und einem MPLS-Label) von LDP-Partnern mit der angegebenen Zugriffsliste.

Nur Label-Bindungen, deren Präfix von der Zugriffsliste erlaubt wird, werden akzeptiert.

Beispiel:

set protocols mpls ldp import ipv6 import-filter filter-access-list6 10
set protocols mpls ldp import ipv6 import-filter neighbor-access-list6 <1-2699>

Filtern Sie die IPv6-Label-Bindungen (Zuordnung zwischen einem IPv6-Präfix und einem MPLS-Label) von LDP-Partnern mit der angegebenen Zugriffsliste.

Nur Label-Bindungen, die von einem Peer stammen, dessen IPv6-Adresse von der Zugriffsliste erlaubt wird, werden akzeptiert.

Beispiel:

set protocols mpls ldp import ipv6 import-filter neighbor-access-list6 20
set protocols mpls ldp export ipv4 export-filter filter-access-list <1-2699>

Filtern Sie die IPv4-Label-Bindungen (Zuordnung zwischen einem IPv4-Präfix und einem MPLS-Label) die an LDP-Partner übermittelt werden, mit der angegebenen Zugriffsliste.

Nur Label-Bindungen, deren Präfix von der Zugriffsliste erlaubt wird, werden übermittelt.

Beispiel:

set protocols mpls ldp export ipv4 export-filter filter-access-list 10
set protocols mpls ldp export ipv4 export-filter neighbor-access-list <1-2699>

Filtern Sie die IPv4-Label-Bindungen (Zuordnung zwischen einem IPv4-Präfix und einem MPLS-Label) die an LDP-Partner übermittelt werden, mit der angegebenen Zugriffsliste.

Label-Bindungen werden nur an Peers übermittelt, deren IPv4-Adresse von der Zugriffsliste erlaubt wird.

Beispiel:

set protocols mpls ldp export ipv4 export-filter neighbor-access-list 20
set protocols mpls ldp export ipv6 export-filter filter-access-list6 <1-2699>

Filtern Sie die IPv6-Label-Bindungen (Zuordnung zwischen einem IPv6-Präfix und einem MPLS-Label) die an LDP-Partner übermittelt werden, mit der angegebenen Zugriffsliste.

Nur Label-Bindungen, deren Präfix von der Zugriffsliste erlaubt wird, werden übermittelt.

Beispiel:

set protocols mpls ldp export ipv6 export-filter filter-access-list6 10
set protocols mpls ldp export ipv6 export-filter neighbor-access-list6 <1-2699>

Filtern Sie die IPv6-Label-Bindungen (Zuordnung zwischen einem IPv6-Präfix und einem MPLS-Label) die an LDP-Partner übermittelt werden, mit der angegebenen Zugriffsliste.

Label-Bindungen werden nur an Peers übermittelt, deren IPv6-Adresse von der Zugriffsliste erlaubt wird.

Beispiel:

set protocols mpls ldp export ipv6 export-filter neighbor-access-list6 20
set protocols mpls ldp export ipv4 explicit-null

Konfigurieren Sie den Router, um das Explicit Null-Label für seine direkt verbundenen IPv4-Präfixe an LDP-Nachbarn zu bewerben.

Dies weist den penultimate-hop Router an, die markierten Pakete unverändert weiterzuleiten, ohne das MPLS-Label zu entfernen.

Beispiel:

set protocols mpls ldp export ipv4 explicit-null
set protocols mpls ldp export ipv6 explicit-null

Konfigurieren Sie den Router, um das Explicit Null-Label für seine direkt verbundenen IPv6-Präfixe an LDP-Nachbarn zu bewerben.

Dies weist den penultimate-hop Router an, die markierten Pakete unverändert weiterzuleiten, ohne das MPLS-Label zu entfernen.

Beispiel:

set protocols mpls ldp export ipv6 explicit-null
set protocols mpls ldp allocation ipv4 access-list <1-2699>

Begrenzen Sie die MPLS-Label-Zuweisung auf IPv4-Präfixe, die von der angegebenen Zugriffsliste erlaubt werden.

Standardmäßig weist LDP ein Label für jeden IPv4-Präfix im Routing-Tabell zu. Ein gängiges Best Practice ist es, die Zuweisung auf Loopback-Adressen zu beschränken.

Beispiel:

set protocols mpls ldp allocation ipv4 access-list 10
set protocols mpls ldp allocation ipv6 access-list6 <1-2699>

Begrenzen Sie die MPLS-Label-Zuweisung auf IPv6-Präfixe, die von der angegebenen Zugriffsliste erlaubt werden.

Standardmäßig weist LDP ein Label für jeden IPv6-Präfix im Routing-Tabell zu. Ein gängiges Best Practice ist es, die Zuweisung auf Loopback-Adressen zu beschränken.

Beispiel:

set protocols mpls ldp parameters cisco-interop-tlv

Konfigurieren Sie den Router, um die Dual-Stack-Fähigkeit TLV (RFC 7552) mit einem Cisco-nicht-kompatiblen Format für Dual-Stack-LDP-Sitzungen zu verhandeln.

Beispiel:

set protocols mpls ldp parameters cisco-interop-tlv
set protocols mpls ldp parameters ordered-control

Enable LDP Ordered Label Distribution Control mode (RFC 5036) für den Router.

Standardmäßig arbeitet der Router im Independent Label Distribution Control Mode.

Beispiel:

set protocols mpls ldp parameters ordered-control

Konfigurieren Sie den Router, um eine IPv4 TCP-Transportverbindung für LDP Peering vorzuziehen, wenn LDP für Dual-Stack-Betrieb konfiguriert ist (beide IPv4 und IPv6-Adressfamilien sind aktiviert).

Beispiel:

set protocols mpls ldp parameters transport-prefer-ipv4
set protocols mpls ldp targeted-neighbor ipv4 enable

Enable den Router, um gezielte IPv4 LDP-Sitzungen zu akzeptieren.

Dies ermöglicht dem Router, LDP-Adjazenz mit nicht direkt verbundenen Partnern zu etablieren, indem auf eingehende gezielte (Unicast) LDP Hello Nachrichten reagiert wird.

Beispiel:

set protocols mpls ldp targeted-neighbor ipv4 enable

Dies ermöglicht dem Router, LDP-Adjazenz mit nicht direkt verbundenen Partnern zu etablieren, indem auf eingehende gezielte (Unicast) LDP Hello Nachrichten reagiert wird.

Beispiel:

Konfigurieren Sie den Router, um eine gezielte IPv4 LDP-Sitzung mit dem angegebenen Remote LSR zu initiieren.

Beispiel:

set protocols mpls ldp targeted-neighbor ipv4 address 192.0.2.5

Betrieb

Wenn LDP eingerichtet ist, können Sie Labelzuweisungen direkt innerhalb der show ip route oder show ipv6 route Ausgaben ansehen. Um LDP Betriebszustände zu inspektionieren, verwenden Sie folgende Befehle.

Show

show mpls ldp binding

Zeigen Sie die LIB an.

show mpls ldp binding <prefix>

Zeigen Sie LDP Label-Bindungen für den angegebenen Präfix an.

Der <prefix> Parameter akzeptiert einen IPv4-Präfix (x.x.x.x/x) oder IPv6 Präfix (h:h:h:h:h:h:h:h/h).

show mpls ldp binding detail

Zeigen Sie detaillierte LDP Label Information Base (LIB) Einträge an.

show mpls ldp binding neighbor <address>

Zeigen Sie LDP Label-Bindungen an, die vom angegebenen Peer gelernt wurden.

Der <address> Parameter akzeptiert eine IPv4- oder IPv6-Adresse.

show mpls ldp binding local-label <label>

Zeigen Sie LDP Label-Bindungen an, die mit dem angegebenen lokal zugewiesenen Label-Wert assoziiert sind.

show mpls ldp binding remote-label <label>

Zeigen Sie LDP Label-Bindungen an, die mit dem angegebenen fern zugewiesenen Label-Wert assoziiert sind.

show mpls ldp discovery

Zeigen Sie LDP Discovery Hello Informationen an.

show mpls ldp discovery detail

Zeigen Sie detaillierte LDP Discovery Hello Informationen an.

show mpls ldp interface

Zeigen Sie LDP Interface Informationen an.

show mpls ldp neighbor

Zeigen Sie grundlegende LDP Nachbarn Informationen an.

show mpls ldp neighbor detail

Zeigen Sie detaillierte LDP Nachbarn Informationen an.

show mpls ldp neighbor capabilities

Zeigen Sie die LDP-Fähigkeiten an, die während der Sitzungserstellung mit jedem Peer vereinbart wurden.

show mpls ldp neighbor <address>

Zeigen Sie LDP Nachbarn Informationen für den angegebenen Peer an.

Der <address> Parameter akzeptiert eine IPv4- oder IPv6-Adresse.

show mpls ldp neighbor <address> detail

Zeigen Sie detaillierte LDP Sitzungsinformationen für den angegebenen Peer an.

show mpls ldp neighbor <address> capabilities

Zeigen Sie die LDP-Fähigkeiten an, die mit dem angegebenen Peer vereinbart wurden.

show mpls table

Zeigen Sie die MPLS-Tabelle an.

show mpls pseudowire

Zeigen Sie MPLS Pseudowire Schnittstellen an.

Zurücksetzen

reset mpls ldp neighbor <address>

Setzen Sie die etablierte LDP-Sitzung mit dem angegebenen Nachbarn zurück.

Der <address> Parameter akzeptiert eine IPv4- oder IPv6-Adresse.

Beispiel

Die folgende Konfiguration richtet einen grundlegenden MPLS LDP-fähigen Router ein. OSPF wird als zugrunde liegender IGP verwendet, um die Erreichbarkeit zwischen den LDP Peers' Loopback-Adressen bereitzustellen, die dann als LDP-Transport-Adressen und Router-IDs verwendet werden. MPLS-Weiterleitung und LDP sind auf dem Interface aktiviert, das mit dem Netzwerk verbunden ist.

set protocols ospf area 0 network '192.0.2.1/32'
set protocols ospf area 0 network '192.0.2.4/31'
set protocols ospf parameters router-id '192.0.2.1'
set protocols mpls interface 'eth1'
set protocols mpls ldp discovery transport-ipv4-address '192.0.2.1'
set protocols mpls ldp interface 'eth1'
set protocols mpls ldp interface 'lo'
set protocols mpls ldp router-id '192.0.2.1'
set interfaces ethernet eth1 address '192.0.2.5/31'
set interfaces loopback lo address '192.0.2.1/32'

Hinweis

Dieses Beispiel setzt eine Transit (P-Router)-Rolle voraus: MPLS-Weiterleitung ist nur auf der Transit-Schnittstelle aktiviert, nicht auf der Loopback. Wenn der Router MPLS-encapsulated Traffic auf seiner Loopback terminieren muss (PE-Router-Rolle), konfigurieren Sie auch set protocols mpls interface 'lo'.

Wenden Sie die gleiche Konfiguration auf den LDP-Partner (mit eigenen Loopback- und Transit-Schnittstellen-Adressen) an, um eine grundlegende LDP-Sitzung zu etablieren.
