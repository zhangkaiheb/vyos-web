SSH

SSH ist ein kryptografisches Netzwerkprotokoll für den sicheren Betrieb von Netzwerkdiensten über ein unsicheres Netzwerk. Der Standard-TCP-Port für SSH ist 22. Das bekannteste Beispiel ist die Fernanmeldung an Computer-Systeme durch Benutzer.

SSH bietet einen sicheren Kanal über ein unsicheres Netzwerk in einer Client-Server-Architektur, der eine SSH-Client-Anwendung mit einem SSH-Server verbindet. Häufige Anwendungen umfassen Fern-Befehlszeilen-Login und Fern-Befehlsausführung, aber jeder Netzwerkdienst kann mit SSH gesichert werden. Das Protokoll unterscheidet zwischen zwei Hauptversionen, die als SSH-1 und SSH-2 bezeichnet werden.

Die sichtbarste Anwendung des Protokolls ist der Zugriff auf Shell-Konten auf Unix-artigen Betriebssystemen, aber es wird auch auf Windows eingesetzt. Im Jahr 2015 kündigte Microsoft an, dass sie native Unterstützung für SSH in einer zukünftigen Version integrieren werden.

SSH wurde als Ersatz für Telnet und ungesicherte Remote-Shell-Protokolle wie das Berkeley rlogin, rsh und rexec-Protokoll entworfen. Diese Protokolle senden Informationen, insbesondere Passwörter, im Klartext, was sie anfällig für Abhörung und Offenlegung mittels Paketanalyse macht. Die von SSH verwendete Verschlüsselung dient dazu, Vertraulichkeit und Integrität von Daten über ein unsicheres Netzwerk, wie das Internet, zu gewährleisten.

Hinweis

VyOS 1.1 unterstützte die Anmeldung als Benutzer root. Dies wurde aufgrund der stärkeren Sicherheit in VyOS 1.2 entfernt.

SSH Schlüsselbasierte Authentifizierung

Konfiguration

set service ssh port <port>

Das Aktivieren von SSH erfordert nur die Angabe des Ports <port>, auf dem SSH lauschen soll. Standardmäßig läuft SSH auf Port 22.

set service ssh listen-address <address>

Geben Sie die IPv4/IPv6-Adresse des SSH-Servers an. Mehrere Adressen können definiert werden.

set service ssh cipher <cipher>

Definieren Sie die für die SSH-Verbindung verwendeten erlaubten Verschlüsselungsalgorithmen. Mehrere erlaubte Verschlüsselungsalgorithmen können angegeben werden, verwenden Sie mehrfach, um mehrere Algorithmen zu erlauben.

Liste der unterstützten Verschlüsselungen: 3des-cbc, aes128-cbc, aes192-cbc, aes256-cbc, aes128-ctr, aes192-ctr, aes256-ctr, aes128-gcm@openssh.com, aes256-gcm@openssh.com, chacha20-poly1305@openssh.com

set service ssh disable-password-authentication

Deaktivieren Sie die Authentifizierung basierend auf Passwörtern. Nur Anmeldung über SSH-Schlüssel. Dies erhöht die Sicherheit!

set service ssh fido pin-required

Benötigt FIDO2-Schlüssel, um zu attestieren, dass ein Benutzer verifiziert wurde (z. B. über eine PIN).

set service ssh fido touch-required

Benötigt FIDO2-Schlüssel, um zu attestieren, dass ein Benutzer physisch vorhanden ist.

VyOS unterstützt die SSH-Authentifizierung mit FIDO2-basierten Schlüsseln, die von OpenSSH generiert wurden. Zwei FIDO2-Schlüsseltypen werden von OpenSSH unterstützt: ed25519-sk, ecdsa-sk

Beispiel für die Generierung eines allgemeinen FIDO2-basierten SSH-Schlüssels:

ssh-keygen -t ecdsa-sk -O verify-required -C "fido2-ssh-key"
Während der Schlüsselerzeugung führt OpenSSH folgendes aus:

  • Anforderung der Benutzerpräsenz (z. B. physischer Berührung oder Bestätigung)

  • Optionale Anforderung der Benutzerverifikation (PIN), falls vom Authenticator unterstützt

  • Erstellung einer lokalen Schlüsseldatei und eines entsprechenden öffentlichen Schlüssels (.pub)

Der private Schlüssel verlässt das Authenticator-Gerät nie.

VyOS-Konfigurationsbeispiel:

# Generieren Sie einen FIDO2 SSH-Schlüssel auf dem Client-System
# Kopieren Sie den öffentlichen Schlüssel auf das VyOS-System
set system login user vyos authentication public-keys fido key '<public-key>'
set system login user vyos authentication public-keys fido type '[email protected]'
set service ssh fido touch-required

Sie können sich nun mit: ssh -i ~/.ssh/id_fido_key vyos@192.0.2.1 anmelden.

set service ssh disable-host-validation

Deaktivieren Sie die Host-Validierung durch umgekehrte DNS-Abfragen – kann die Anmeldezeit beschleunigen, wenn eine umgekehrte Abfrage nicht möglich ist.

set service ssh mac <mac>

Gibt die verfügbaren MAC-Algorithmen an. Der MAC-Algorithmus wird in Protokollversion 2 für Schutz der Datenintegrität verwendet. Mehrere Algorithmen können durch Verwendung mehrerer Befehle angegeben werden, wobei pro Befehl ein Algorithmus definiert wird.

Liste der unterstützten MACs: hmac-md5, hmac-md5-96, hmac-ripemd160, hmac-sha1, hmac-sha1-96, hmac-sha2-256, hmac-sha2-512, umac-64@openssh.com, umac-128@openssh.com, hmac-md5-etm@openssh.com, hmac-md5-96-etm@openssh.com, hmac-ripemd160-etm@openssh.com, hmac-sha1-etm@openssh.com, hmac-sha1-96-etm@openssh.com, hmac-sha2-256-etm@openssh.com, hmac-sha2-512-etm@openssh.com, umac-64-etm@openssh.com, umac-128-etm@openssh.com

set service ssh access-control <allow | deny> <group | user> <name>

Fügen Sie eine Zugriffssteuerungsrichtlinie hinzu, um Benutzer und Gruppen zuzulassen oder abzulehnen. Richtlinien werden in folgender Reihenfolge verarbeitet: deny-users, allow-users, deny-groups und allow-groups.

set service ssh client-keepalive-interval <interval>

Legen Sie das Zeitintervall für Keepalive-Nachrichten in Sekunden fest.

set service ssh key-exchange <kex>

Geben Sie die erlaubten KEX-Algorithmen an.

Liste der unterstützten Algorithmen: diffie-hellman-group1-sha1, diffie-hellman-group14-sha1, diffie-hellman-group14-sha256, diffie-hellman-group16-sha512, diffie-hellman-group18-sha512, diffie-hellman-group-exchange-sha1, diffie-hellman-group-exchange-sha256, ecdh-sha2-nistp256, ecdh-sha2-nistp384, ecdh-sha2-nistp521, curve25519-sha256 und curve25519-sha256@libssh.org.

set service ssh loglevel <quiet | fatal | error | info | verbose>

Legen Sie das sshd-Protokollniveau fest. Der Standardwert ist info.

set service ssh vrf <name>

Geben Sie den Namen des VRF-Instanz an.

set service ssh pubkey-accepted-algorithm <name>

Gibt die Signaturalgorithmen an, die für die Public-Key-Authentifizierung akzeptiert werden

Liste der unterstützten Algorithmen: ssh-ed25519, ssh-ed25519-cert-v01@openssh.com, sk-ssh-ed25519@openssh.com, sk-ssh-ed25519-cert-v01@openssh.com, ecdsa-sha2-nistp256, ecdsa-sha2-nistp256-cert-v01@openssh.com, ecdsa-sha2-nistp384, ecdsa-sha2-nistp384-cert-v01@openssh.com, ecdsa-sha2-nistp521, ecdsa-sha2-nistp521-cert-v01@openssh.com, sk-ecdsa-sha2-nistp256@openssh.com, sk-ecdsa-sha2-nistp256-cert-v01@openssh.com, webauthn-sk-ecdsa-sha2-nistp256@openssh.com, ssh-dss, ssh-dss-cert-v01@openssh.com, ssh-rsa, ssh-rsa-cert-v01@openssh.com, rsa-sha2-256, rsa-sha2-256-cert-v01@openssh.com, rsa-sha2-512, rsa-sha2-512-cert-v01@openssh.com

set service ssh trusted-user-ca <name>

Geben Sie den Namen des OpenSSH-Schlüsselpaars an, das als Zertifikatsbehörde fungiert und zur Überprüfung von Benutzerzertifikaten verwendet wird.

Sie können es verwenden, indem Sie das OpenSSH-Schlüsselpaar unter dem PKI-Untersystem hinzufügen.

Beispiel:

# Generieren Sie ein Schlüsselpaar, das als CA fungiert
$ ssh-keygen -f vyos-ssh-ca.key

# Generieren Sie ein Schlüsselpaar für den Benutzer: vyos_testca
$ ssh-keygen -f vyos_testca  -C "[email protected]"

# Signieren Sie den öffentlichen Schlüssel des Benutzers vyos_testca und fügen Sie Principal-Names hinzu: vyos, vyos_testca
# mit einer Schlüssel-Lebensdauer von zwei Wochen – nach Ablauf ist der Schlüssel nicht mehr nutzbar
$ ssh-keygen -s vyos-ssh-ca.key -I [email protected] -n vyos,vyos_testca -V +2w vyos_testca.pub

$ set system login user vyos_testca
$ set pki openssh test_ca public key AAAAB3N.....
$ set pki openssh test_ca public type ssh-rsa
$ set service ssh trusted-user-ca test_ca

Sie können sich nun mit: ssh -i vyos_testca vyos_testca@vyos.test.com anmelden.

Dynamischer Schutz

Schützt den Host vor Brute-Force-Angriffen gegen SSH. Logmeldungen werden Zeile für Zeile auf erkannte Muster geprüft. Wenn ein Angriff, wie mehrere Anmeldefehler innerhalb weniger Sekunden, erkannt wird, wird die angreifende IP blockiert. Die Blockierung wird nach einer festgelegten Zeitspanne aufgehoben.

set service ssh dynamic-protection

Erlaubt ssh dynamischen Schutz.

set service ssh dynamic-protection allow-from <address | prefix>

Weißliste von Adressen und Netzwerken. Erlaubt immer eingehende Verbindungen von diesen Systemen.

set service ssh dynamic-protection block-time <sec>

Blockiert die Quell-IP in Sekunden. Nachfolgende Blöcke erhöhen sich um einen Faktor von 1,5 Der Standardwert ist 120.

set service ssh dynamic-protection detect-time <sec>

Behält die Quell-IP in Sekunden vor dem Zurücksetzen ihres Scores. Der Standardwert ist 1800.

set service ssh dynamic-protection threshold <sec>

Blockiert die Quell-IP, wenn ihr kumulativer Angriffsscore den Schwellwert überschreitet. Der Standardwert ist 30.

Betrieb

restart ssh

Neustarten des SSH-Daemon-Prozesses, die aktuelle Sitzung wird nicht beeinflusst, nur der Hintergrund-Daemon wird neu gestartet.

generate ssh server-key

Erneut generiert den öffentlichen/geheimen Schlüsselteil, den SSH verwendet, um Verbindungen zu sichern.

Hinweis

Die bereits gelernten known_hosts-Dateien der Clients müssen aktualisiert werden, da der öffentliche Schlüssel sich ändern wird.

generate ssh client-key /path/to/private_key

Erneut generiert einen bekannten öffentlichen/geheimen Schlüsseldatei, der verwendet werden kann, um sich mit anderen Diensten (z. B. RPKI-Cache) zu verbinden.

Beispiel:

generate public-key-command user <username> path <location>

Generiert die Konfigurationsmodus-Befehle, um einen öffentlichen Schlüssel für Schlüsselbasierte Authentifizierung hinzuzufügen. <location> kann ein lokaler Pfad oder eine URL sein, die auf eine remote Datei verweist.

Unterstützte Remote-Protokolle sind FTP, FTPS, HTTP, HTTPS, SCP/SFTP und TFTP.

Beispiel:

alyssa@vyos:~$ generate public-key-command user alyssa path sftp://example.net/home/alyssa/.ssh/id_rsa.pub
# Um diesen Schlüssel als eingebetteten Schlüssel hinzuzufügen, führen Sie die folgenden Befehle aus:
configure
set system login user alyssa authentication public-keys [email protected] key AAA...
set system login user alyssa authentication public-keys [email protected] type ssh-rsa
commit
save
exit

ben@vyos:~$ generate public-key-command user ben path ~/.ssh/id_rsa.pub
# Um diesen Schlüssel als eingebetteten Schlüssel hinzuzufügen, führen Sie die folgenden Befehle aus:
configure
set system login user ben authentication public-keys ben@vyos key AAA...
set system login user ben authentication public-keys ben@vyos type ssh-dss
commit
save
exit
show log ssh

Zeigt den SSH-Server-Log an.

monitor log ssh

Folgt dem SSH-Server-Log.

show log ssh dynamic-protection

Zeigt den SSH-Dynamikschutz-Log an.

monitor log ssh dynamic-protection

Folgt dem SSH-Dynamikschutz-Log.

show ssh dynamic-protection

Zeigt die Liste der IPs an, die derzeit durch SSH-Dynamikschutz blockiert sind.

show ssh fingerprints

Zeigt die Fingerabdrücke des öffentlichen Schlüssels des SSH-Servers an.

show ssh fingerprints ascii

Zeigt die Fingerabdrücke des öffentlichen Schlüssels des SSH-Servers an, einschließlich einer visuellen ASCII-Kunstdarstellung.
