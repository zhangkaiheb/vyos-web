BFD

BFD ist ein Netzwerkprotokoll, das Kommunikationsfehler zwischen zwei verbundenen Routing-Geräten in nur Millisekunden erkennt – weit schneller als traditionelle Routing-Protokolle. BFD leitet den Datenverkehr selbst nicht weiter. Stattdessen bietet es eine schnelle Fehlererkennung für andere Protokolle, wie z. B. BGP, OSPF und statische Routen.

BFD wird durch folgende RFCs beschrieben und erweitert: RFC 5880, RFC 5881 und RFC 5883.

Wie BFD funktioniert

BFD stellt eine Sitzung zwischen zwei Peers her und tauscht schnelle UDP-Steuerpakete zu einem vereinbarten Intervall (z. B. 300 ms zwischen aufeinanderfolgenden Paketen) aus. Wenn ein Peer diese Pakete innerhalb der Erkennungszeit (das vereinbarte Intervall multipliziert mit einem Erkennungsmultiplikator) nicht empfängt, geht BFD von einem Verbindungsfehler aus und informiert die Routing-Protokolle.

Konfiguration

set protocols bfd peer <address>

Konfigurieren Sie die IPv4- oder IPv6-Adresse des BFD-Peers.

Sie können mehrere BFD-Peers konfigurieren, indem Sie für jeden Nachbarn, den Sie überwachen möchten, eine unterschiedliche IP-Adresse angeben.

Hinweis

Für IPv6-Peers müssen Sie eine Quell-IP-Adresse oder einen Schnittstellenname konfigurieren.

Beispiel:

set protocols bfd peer 198.51.100.33
set protocols bfd peer <address> echo-mode

Das Echo-Übertragungsmodus für den Peer an der angegebenen IP-Adresse aktivieren.

Beispiel:

set protocols bfd peer 198.51.100.33 echo-mode
set protocols bfd peer <address> multihop

Konfigurieren Sie den Peer an der angegebenen IP-Adresse als Multi-Hop-Nachbarn.

Hinweis

Für BFD-Multi-Hop-Peers müssen Sie eine lokale Quell-IP-Adresse konfigurieren.

Beispiel:

set protocols bfd peer 198.51.100.33 multihop
set protocols bfd peer 198.51.100.33 source address 198.51.100.1
set protocols bfd peer <address> source address <address>

Konfigurieren Sie die Quell-IP-Adresse für die BFD-Sitzung mit dem Peer an der angegebenen IP-Adresse.

Hinweis

Die Konfiguration einer Quell-IP-Adresse oder eines Schnittstellennamens ist für IPv6-BFD-Peers obligatorisch.

Beispiel:

set protocols bfd peer 198.51.100.33 source address 198.51.100.1
set protocols bfd peer <address> source interface <interface>

Konfigurieren Sie die Quellschnittstelle für die BFD-Sitzung mit dem Peer an der angegebenen IP-Adresse.

Hinweis

Die Konfiguration einer Quell-IP-Adresse oder eines Schnittstellennamens ist für IPv6-BFD-Peers obligatorisch.

Beispiel:

set protocols bfd peer 2001:db8::2 source interface eth0
set protocols bfd peer <address> interval echo-interval <10-60000>

Konfigurieren Sie das minimale Intervall, in Millisekunden, mit dem das lokale System Echo-Pakete vom Peer an der angegebenen IP-Adresse empfangen kann.

Beispiel:

set protocols bfd peer 198.51.100.33 interval echo-interval 50
set protocols bfd peer <address> interval multiplier <2-255>

Konfigurieren Sie den Erkennungsmultiplikator für den Peer an der angegebenen IP-Adresse.

BFD multipliziert das vereinbarte Intervall mit diesem Wert, um die Erkennungszeit zu berechnen – den Zeitraum nach dem, wenn es die Sitzung als beendet erklärt, falls keine Steuerpakete eintreffen.

Beispiel:

set protocols bfd peer 192.0.2.1 interval multiplier 3
set protocols bfd peer <address> interval receive <10-60000>

Konfigurieren Sie das Intervall, in Millisekunden, mit dem das lokale System BFD-Steuerpakete vom Peer an der angegebenen IP-Adresse empfangen kann.

Beispiel:

set protocols bfd peer 192.0.2.1 interval receive 300
set protocols bfd peer <address> interval transmit <10-60000>

Konfigurieren Sie das Intervall, in Millisekunden, mit dem Sie das lokale System BFD-Steuerpakete an den Peer an der angegebenen IP-Adresse senden möchten.

Beispiel:

set protocols bfd peer 192.0.2.1 interval transmit 300
set protocols bfd peer <address> shutdown

Deaktivieren Sie die BFD-Sitzung mit dem Peer an der angegebenen IP-Adresse.

Beispiel:

set protocols bfd peer 198.51.100.33 shutdown
set protocols bfd peer <address> minimum-ttl <1-254>

Konfigurieren Sie den minimalen TTL-Wert, den eingehende BFD Steuerpakete haben müssen, um von dem Peer an der angegebenen IP-Adresse akzeptiert zu werden.

BFD verwirft jedes Paket, dessen TTL unter diesem Schwellwert liegt.

Hinweis

Diese Einstellung gilt nur für Multi-Hop-Sitzungen.

Beispiel:

set protocols bfd peer 192.0.2.1 minimum-ttl 250
set protocols bfd peer <address> passive

Konfigurieren Sie die BFD-Sitzung mit dem Peer an der angegebenen IP-Adresse, um im passiven Modus zu arbeiten.

Im passiven Modus initiert das lokale System keine BFD-Sitzung. Stattdessen wartet es darauf, das erste BFD-Steuerpaket vom entfernten Peer zu empfangen.

Hinweis

Mindestens einer der beiden Peers muss im aktiven Modus verbleiben, damit die Sitzung hergestellt werden kann. Wenn beide Peers im passiven Modus sind, initiieren sie nicht, und die Sitzung wird nie hergestellt.

Beispiel:

set protocols bfd peer 198.51.100.33 passive
set protocols bfd peer <address> profile <profile>

Wenden Sie Einstellungen aus einem bestimmten BFD-Profil auf den Peer an der angegebenen IP-Adresse an.

Beispiel:

set protocols bfd peer 192.0.2.1 profile datacenter-fast
set protocols bfd peer <address> vrf <vrf>

Binden Sie die BFD-Sitzung mit dem Peer an der angegebenen IP-Adresse an eine spezifische VRF-Instanz.

Beispiel:

set protocols bfd peer 192.0.2.1 vrf customer-a

BFD in BGP aktivieren

set protocols bgp neighbor <neighbor> bfd

BFD-Fehlererkennung für die BGP-Sitzung mit dem Nachbarn an der angegebenen IP-Adresse aktivieren.

Beispiel:

set protocols bgp neighbor 192.0.2.1 bfd
set protocols bgp peer-group <neighbor> bfd

BFD-Fehlererkennung für alle Nachbarn in der angegebenen BGP-Peergruppe aktivieren.

Beispiel:

set protocols bgp peer-group INTERNAL-PEERS bfd

BFD in OSPF aktivieren

set protocols ospf interface <interface> bfd

BFD-Fehlererkennung für OSPF-Nachbarn aktivieren, die auf dem angegebenen Interface gefunden wurden.

Wenn OSPF eine Adjazenz mit einem Nachbarn auf diesem Interface bildet, fordert es BFD auf, eine Sitzung mit diesem Nachbarn zu erstellen.

Beispiel:

set protocols ospf interface eth0 bfd
set protocols ospfv3 interface <interface> bfd

BFD-Fehlererkennung für OSPFv3-Nachbarn aktivieren, die auf dem angegebenen Interface gefunden wurden.

Wenn OSPFv3 eine Adjazenz mit einem Nachbarn auf diesem Interface bildet, fordert es BFD auf, eine Sitzung mit diesem Nachbarn zu erstellen.

Beispiel:

set protocols ospfv3 interface eth0 bfd

BFD in IS-IS aktivieren

set protocols isis interface <interface> bfd

BFD-Fehlererkennung für IS-IS-Nachbarn aktivieren, die auf dem angegebenen Interface gefunden wurden.

Wenn IS-IS eine Adjazenz mit einem Nachbarn auf diesem Interface bildet, fordert es BFD auf, eine Sitzung mit diesem Nachbarn zu erstellen.

Beispiel:

set protocols isis interface eth0 bfd

BFD statische Routenüberwachung

Eine überwachte statische Route ist nur dann in der RIB, wenn die BFD-Sitzung aktiv ist. Wenn die Sitzung abbricht, wird die Route entfernt.

set protocols static route <subnet> next-hop <address> bfd profile <profile>

BFD-Fehlererkennung für eine Einhoppe-Statikroute konfigurieren.

BFD verwendet die Next-Hop-IP-Adresse als BFD-Peer-IP-Adresse und wendet Einstellungen aus dem angegebenen BFD-Profil an.

Beispiel:

set protocols static route 10.0.0.0/24 next-hop 192.0.2.1 bfd profile datacenter-fast
set protocols static route <subnet> next-hop <address> bfd multi-hop source-address <address>

BFD-Fehlererkennung für eine Mehrhop-Statikroute konfigurieren.

BFD verwendet die Next-Hop-IP-Adresse als BFD-Peer-IP-Adresse und die Mehrhop-Quell-IP-Adresse als lokale Quell-IP für ausgehende BFD-Pakete.

Beispiel:

set protocols static route 10.0.0.0/24 next-hop 198.51.100.33 bfd multi-hop source-address 198.51.100.1
set protocols static route6 <subnet> next-hop <address> bfd profile <profile>

BFD-Fehlererkennung für eine Einhoppe-IPv6-Statikroute konfigurieren.

BFD verwendet die Next-Hop-IPv6-Adresse als BFD-Peer-IPv6-Adresse und wendet Einstellungen aus dem angegebenen BFD-Profil an.

Beispiel:

set protocols static route6 2001:db8:1::/64 next-hop 2001:db8::1 bfd profile datacenter-fast
set protocols static route6 <subnet> next-hop <address> bfd multi-hop source-address <address>

BFD-Fehlererkennung für eine Mehrhop-IPv6-Statikroute konfigurieren.

BFD verwendet die Next-Hop-IPv6-Adresse als BFD-Peer-IPv6-Adresse und die Mehrhop-Quell-IPv6-Adresse als lokale Quell-IPv6-Adresse für ausgehende BFD-Pakete.

Beispiel:

set protocols static route6 2001:db8:1::/64 next-hop 2001:db8:100::33 bfd multi-hop source-address 2001:db8::1
