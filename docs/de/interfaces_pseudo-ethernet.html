MACVLAN (Pseudoethernet)

MACVLAN, oder Pseudoethernet-Schnittstellen, funktionieren als logische Unterschnittstellen von Standard-Ethernet-Schnittstellen. Jede Unterschnittstelle hat eine eindeutige MAC-Adresse, teilt sich aber einen einzigen physischen Ethernet-Port. Das ermöglicht dem Benutzer, Pakete mit unterschiedlichen Quell-IPv4- oder IPv6-Adressen über eine unterschiedliche MAC-Adresse zu senden.

Pseudoethernet-Schnittstellen verhalten sich wie physische Ethernet-Schnittstellen. Sie unterstützen IPv4 und IPv6-Adressierung, können IP-Adressen über DHCP oder DHCPv6 erhalten und werden einer physischen Ethernet-Schnittstelle zugeordnet. Sie erben Eigenschaften wie Geschwindigkeit und Duplex von ihrer Elternschnittstelle und können wie gewöhnliche Ethernet-Schnittstellen verwiesen werden, sobald sie erstellt wurden.

Pseudoethernet-Schnittstellen können in Umgebungen nicht funktionieren, die eine

NIC erfordern, die nur eine MAC-Adresse hat. Dies beinhaltet:

  • VMware-Maschinen mit Standardeinstellungen.

  • Netzwerkswitches, die nur eine einzelne MAC-Adresse erlauben.

  • xDSL-Modems, die die MAC-Adresse der NIC lernen.

Konfiguration

Gemeinsame Schnittstellenkonfiguration

set interfaces pseudo-ethernet <interface> address <address | dhcp | dhcpv6>

Konfigurieren Sie die Schnittstelle mit einer oder mehreren IP-Adressen.

Die folgenden Optionen sind verfügbar:

  • address: Weisen Sie der Schnittstelle eine oder mehrere IPv4- oder IPv6-Adressen zu. Zum Beispiel verwenden Sie 192.0.2.1/24 für IPv4 oder 2001:db8::1/64 für IPv6.

  • dhcp: Die Schnittstelle erhält eine IPv4-Adresse von einem DHCP-Server im gleichen Netzwerksegment.

  • dhcpv6: Die Schnittstelle erhält eine IPv6-Adresse von einem DHCPv6-Server im gleichen Netzwerksegment.

Hinweis

Wenn die Schnittstelle eine IPv4-Adresse über DHCP erhält und spezielle Anpassungen vor oder nach der Erhaltung der IP-Adresse erforderlich sind, verwenden Sie die bereitgestellten Hook-Skripte:

  • /config/scripts/dhcp-client/pre-hooks.d/

  • /config/scripts/dhcp-client/post-hooks.d/

Beispiel:

set interfaces pseudo-ethernet peth0 address 192.0.2.1/24
set interfaces pseudo-ethernet peth0 address 2001:db8::1/64
set interfaces pseudo-ethernet peth0 address dhcp
set interfaces pseudo-ethernet peth0 address dhcpv6
set interfaces pseudo-ethernet <interface> description <description>

Konfigurieren Sie eine klare, beschreibende Aliasbezeichnung für die Schnittstelle.

Diese Bezeichnung erscheint im Befehl show interfaces und in SNMP-basierten Überwachungstools.

Beispiel:

set interfaces pseudo-ethernet peth0 description 'This is an interface running on VyOS.'
set interfaces pseudo-ethernet <interface> disable

Deaktivieren Sie die Schnittstelle.

Die Schnittstelle wird auf den administrativ heruntergefahrenen Zustand (A/D) gesetzt.

Beispiel:

set interfaces pseudo-ethernet peth0 disable
set interfaces pseudo-ethernet <interface> disable-flow-control

Deaktivieren Sie das Ethernet-Flow-Control (IEEE 802.3x-Pause-Frames) auf der Schnittstelle.

Ethernet-Flow-Control, definiert durch den IEEE 802.3x-Standard, stoppt temporär die Datenübertragung, um Paketverluste während Netzwerkengpässe zu verhindern. Zum Beispiel, wenn ein Sender Daten schneller überträgt, als der Empfänger verarbeiten kann.

Das Deaktivieren des Ethernet-Flow-Controls bedeutet, dass die Schnittstelle keine Signale sendet, um die Übertragung zu pausieren, und Pakete abwirft, wenn sie überfordert ist.

Beispiel:

set interfaces pseudo-ethernet peth0 disable-flow-control
set interfaces pseudo-ethernet <interface> disable-link-detect

Deaktivieren Sie die physische Link-State-Änderungserkennung auf der Schnittstelle, z. B. bei einem Kabelentfernen.

Standardmäßig erkennt die Schnittstelle physische Link-State-Änderungen.

Beispiel:

set interfaces pseudo-ethernet peth0 disable-link-detect
set interfaces pseudo-ethernet <interface> mac <xx:xx:xx:xx:xx:xx>

Konfigurieren Sie eine benutzerdefinierte MAC-Adresse auf der Schnittstelle.

Beispiel:

set interfaces pseudo-ethernet peth0 mac '00:53:01:02:03:04'
set interfaces pseudo-ethernet <interface> mtu <mtu>

Konfigurieren Sie das MTU auf der Schnittstelle.

Dieser Wert definiert die größte Paketgröße in Bytes, die die Schnittstelle ohne Fragmentierung überträgt.

Beispiel:

set interfaces pseudo-ethernet peth0 mtu 1600
set interfaces pseudo-ethernet <interface> ip adjust-mss <mss | clamp-mss-to-pmtu>

Konfigurieren Sie das MSS , das in ausgehenden TCP SYN-Paketen auf der angegebenen Schnittstelle angegeben wird.

Durch das Einklemmen des MSS-Werts in TCP SYN-Paketen informieren Sie den Remote-Partner explizit, dass keine Pakete größer als dieser Wert gesendet werden sollen. Dies verhindert Verbindungsprobleme, die auftreten, wenn die Pfad-MTU-Entdeckung (PMTUD) fehlschlägt.

Die folgenden Optionen sind verfügbar:

  • mss: Legt das MSS auf einen bestimmten Wert in Bytes fest. Verwenden Sie diese Option, wenn Sie ein bestimmtes MSS erzwingen müssen, z. B. zur Fehlerbehebung von Verbindungsproblemen oder zur Erfüllung spezifischer Netzwerkanforderungen.

  • clamp-mss-to-pmtu: Der Router berechnet das MSS automatisch als das MTU der Schnittstelle minus 40 Bytes für IPv4-Datenverkehr (20 Bytes für den IPv4-Header und 20 Bytes für den TCP-Header). Diese Option wird empfohlen, um den richtigen Wert automatisch zu setzen.

set interfaces pseudo-ethernet <interface> ip arp-cache-timeout

Konfigurieren Sie, wie lange ein ARP-Eintrag gültig bleibt, nachdem eine IP-zu-MAC-Zuordnung auf dieser Schnittstelle gelernt wurde.

Der Standardzeitraum beträgt 30 Sekunden.

Ein ARP-Eintrag bleibt gültig, wenn er positive Rückmeldungen von höheren Protokollen erhält.

Beispiel:

set interfaces pseudo-ethernet peth0 ip arp-cache-timeout 180
set interfaces pseudo-ethernet <interface> ip disable-arp-filter

Konfigurieren Sie ARP-Filterung auf dieser Schnittstelle.

Standardverhalten: Das Kernel antwortet auf ARP-Anfragen auf dieser Schnittstelle nur, wenn der Verkehr zurück zum ARP-Sender über diese spezifische Schnittstelle geroutet wird.

Wenn konfiguriert: Das Kernel antwortet auf ARP-Anfragen auf dieser Schnittstelle für jede IP-Adresse, die auf dem lokalen Host konfiguriert ist, unabhängig davon, welche spezifische Schnittstelle diese IP-Adresse zugewiesen ist, und unabhängig vom Routing-Tabellen. Dies spiegelt den Linux-Konzept wider, dass IP-Adressen dem Host gehören, nicht den individuellen Schnittstellen.

Beispiel:

set interfaces pseudo-ethernet peth0 ip disable-arp-filter
set interfaces pseudo-ethernet <interface> ip disable-forwarding

Konfigurieren Sie die Schnittstelle für Host- oder Router-Verhalten.

Wenn konfiguriert, wechselt die Schnittstelle in den Host-Modus und deaktiviert die IPv4-Weiterleitung darauf.

Beispiel:

set interfaces pseudo-ethernet peth0 ip disable-forwarding
set interfaces pseudo-ethernet <interface> ip enable-directed-broadcast

Konfigurieren Sie, ob IP-gerichtete Broadcast-Pakete, die auf dieser Schnittstelle empfangen werden, weitergeleitet werden.

Standardverhalten: IP-gerichtete Broadcast-Pakete werden abgeworfen.

Wenn konfiguriert: IP-gerichtete Broadcast-Pakete werden an alle Hosts im Ziel-Subnetz weitergeleitet, wie in RFC 1812 und RFC 2644 definiert.

Beispiel:

set interfaces pseudo-ethernet peth0 ip enable-directed-broadcast
set interfaces pseudo-ethernet <interface> ip enable-arp-accept

Konfigurieren Sie, wie mit kostenlosen ARPs auf dieser Schnittstelle umgegangen wird.

Wenn konfiguriert, wird ein IP-zu-MAC-Zuordnungseintrag in die ARP-Tabelle basierend auf kostenlosen ARP-Anfragen oder Antworten hinzugefügt.

Hinweis

Wenn die ARP-Tabelle bereits eine IP-Adresse aus einem kostenlosen ARP enthält, wird der Eintrag aktualisiert, unabhängig davon, ob diese Einstellung konfiguriert ist.

Beispiel:

set interfaces pseudo-ethernet peth0 ip enable-arp-accept
set interfaces pseudo-ethernet <interface> ip enable-arp-announce

Konfigurieren Sie die Quell-IP-Auswahl für ARP-Anfragen auf dieser Schnittstelle.

Standardverhalten: Das Kernel kann jede IP-Adresse verwenden, die der Host besitzt, als Quell-IP-Adresse in ARP-Anfragen auf dieser Schnittstelle.

Wenn konfiguriert: Das Kernel versucht zunächst, eine Quell-IP-Adresse zu wählen, die auf der Schnittstelle konfiguriert ist und mit dem Ziel-IP-Adress-Subnetz übereinstimmt. Wenn kein solches Subnetz vorhanden ist, wählt das Kernel die IP-Adresse aus, die es normalerweise verwendet (basierend auf dem Routing-Tabellen, um das Zielziel zu erreichen).

Beispiel:

set interfaces pseudo-ethernet peth0 ip enable-arp-announce
set interfaces pseudo-ethernet <interface> ip enable-arp-ignore

Konfigurieren Sie, welche ARP-Anfragen auf dieser Schnittstelle ignoriert werden.

Standardverhalten: Das Kernel antwortet auf ARP-Anfragen für beliebige lokale IP-Adressen, unabhängig davon, welcher Schnittstelle diese IP-Adresse zugewiesen ist.

Wenn konfiguriert: Das Kernel antwortet nur dann auf ARP-Anfragen, wenn die Ziel-IP-Adresse auf dieser spezifischen Schnittstelle zugewiesen ist.

Beispiel:

set interfaces pseudo-ethernet peth0 ip enable-arp-ignore
set interfaces pseudo-ethernet <interface> ip enable-proxy-arp

Konfigurieren Sie Proxy-ARP auf dieser Schnittstelle.

Wenn konfiguriert, greift der Router (Kernel) ARP-Anfragen für nicht-lokale IP-Adressen ab und antwortet mit der MAC-Adresse der Schnittstelle, die die Anfrage empfangen hat. Danach werden Pakete, die an diese IP-Adressen gerichtet sind, an ihre tatsächlichen Ziele auf entfernten Subnetzen weitergeleitet.

Beispiel:

set interfaces pseudo-ethernet peth0 ip enable-proxy-arp
set interfaces pseudo-ethernet <interface> ip proxy-arp-pvlan

Konfigurieren Sie lokales Proxy-ARP auf der Schnittstelle.

Wenn konfiguriert, antwortet der Router (Kernel) auf ARP-Anfragen auf dieser VLAN-Schnittstelle, auch wenn die Ziel-IP-Adresse auf dem gleichen Subnetz und der gleichen Schnittstelle liegt.

Dies wird verwendet, um Netzwerkisolierungsanforderungen (RFC 3069) für private VLANs (PVLANs) zu unterstützen. In PVLAN-Konfigurationen dürfen Hosts auf isolierten Ports nicht direkt miteinander kommunizieren, jedoch können sie mit dem Upstream-Router kommunizieren.

Durch die Antwort auf inter-host ARP-Anfragen mit seiner eigenen MAC-Adresse leitet der Router den inter-host Traffic über sich selbst statt direkt zwischen Hosts.

Hinweis

Dieser Befehl funktioniert unabhängig und erfordert nicht, dass der Standard-Proxy-ARP auf der Schnittstelle aktiviert ist.

Lokales Proxy-ARP wird auch bezeichnet als:

  • VLAN-Aggregation (RFC 3069).

  • Private VLAN (Cisco, Allied Telesyn).

  • Source-port filtering oder Port-Isolation (Hewlett-Packard).

  • MAC-Forced Forwarding (Ericsson).

set interfaces pseudo-ethernet <interface> ip source-validation <strict | loose | disable>

Konfigurieren Sie die Quell-IP-Adressen-Überprüfung mit RPF auf dieser Schnittstelle, wie in RFC 3704 spezifiziert.

Die folgenden Optionen sind verfügbar:

  • strict: Jedes eingehende Paket wird anhand der Forwarding Information Base (FIB) überprüft. Wenn die Schnittstelle nicht der beste Weg zurück zur Quelle ist, schlägt die Überprüfung fehl und das Paket wird gelöscht.

  • loose: Jedes eingehende Paket wird anhand der FIB überprüft. Wenn die Quell-IP-Adresse über keine Schnittstelle erreichbar ist, schlägt die Überprüfung fehl.

  • disable: Keine Quell-IP-Adressen-Überprüfung wird durchgeführt. Alle eingehenden Pakete werden akzeptiert.

RFC 3704 empfiehlt, strengen Modus zu aktivieren, um IP-Spoofing, wie DDoS-Angriffe, zu verhindern. Für asynchrone oder andere komplexe Routing-Szenarien verwenden Sie den losen Modus.

set interfaces pseudo-ethernet <interface> ipv6 address autoconf

Konfigurieren Sie die Schnittstelle, um eine IPv6-Adresse automatisch unter Verwendung von SLAAC, wie in RFC 4862 spezifiziert, zu erhalten.

IPv6-Hosts können sich automatisch konfigurieren, wenn sie sich einem IPv6-Netzwerk anschließen, indem sie den Neighbor Discovery Protocol via ICMPv6 Router Discovery Nachrichten verwenden. Bei der ersten Verbindung zu einem Netzwerk sendet ein Host eine link-local Router Solicitation Multicast Anfrage für seine Konfigurationsparameter. Der Router antwortet mit einer Router Advertisement Packet, das Internet Layer Konfigurationsparameter enthält.
