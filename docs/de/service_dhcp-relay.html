DHCP-Relay

Eine DHCP-Relay-Agent ermöglicht es einem einzelnen DHCP-Server, Clients auf fernen Subnetzen zu bedienen, wodurch kein separater Server auf jedem Subnetz erforderlich ist.

Der DHCP-Relay-Agent empfängt Client-Anfragen auf einer Schnittstelle, weiterleitet sie als Unicast an den angegebenen Server auf einem anderen Netzwerk und liefert die Antworten des Servers zurück an die ursprünglichen Clients.

VyOS bietet zwei unabhängige DHCP-Relay-Dienste:

  • service dhcp-relay: Weiterleiten von Nachrichten zwischen IPv4-Clients und Servern.

  • service dhcpv6-relay: Weiterleiten von Nachrichten zwischen IPv6-Clients und Servern.

Die beiden Dienste werden separat konfiguriert und teilen keine Einstellungen. Auf einem Dual-Stack-Netzwerk, bei dem Clients beider Adressfamilien DHCP benötigen, müssen beide konfiguriert werden.

IPv4-Relay

Konfiguration

set service dhcp-relay listen-interface <interface>

Konfigurieren Sie eine Schnittstelle, auf der der DHCPv4-Relay Client-Broadcast-Anfragen empfängt.

Wiederholen Sie den Befehl, um mehrere Listen-Schnittstellen zu konfigurieren.

Hinweis

Mindestens ein listen-interface und ein upstream-interface müssen für einen erfolgreichen Commit konfiguriert sein.

Beispiel:

set service dhcp-relay listen-interface eth1
set service dhcp-relay upstream-interface <interface>

Konfigurieren Sie eine Upstream-Schnittstelle, über die der DHCPv4-Relay Client-Anfragen an den DHCP-Server weiterleitet.

Wiederholen Sie den Befehl, um mehrere Upstream-Schnittstellen zu konfigurieren.

Hinweis

Mindestens ein listen-interface und ein upstream-interface müssen für einen erfolgreichen Commit konfiguriert sein.

Beispiel:

set service dhcp-relay upstream-interface eth2
set service dhcp-relay server <ipv4-address>

Konfigurieren Sie die IPv4-Adresse eines DHCPv4-Servers, an den der Relay Client-Anfragen weiterleitet.

Wiederholen Sie den Befehl, um Client-Anfragen an mehrere DHCPv4-Server weiterzuleiten.

Hinweis

Mindestens ein DHCPv4-Server muss für einen erfolgreichen Commit konfiguriert sein.

Beispiel:

set service dhcp-relay server 203.0.113.4
set service dhcp-relay interface <interface>

Konfigurieren Sie eine Schnittstelle, die an der DHCPv4-Relay-Beteiligung teilnimmt.

Schnittstellen, die unter diesem veralteten Befehl konfiguriert sind, arbeiten bidirektional, empfangen DHCPv4-Client-Broadcasts und leiten Anfragen an den Server weiter.

Warnung

Dieser Befehl ist veraltet und bleibt nur zum Unterstützung bestehender Konfigurationen verfügbar. Neue Bereitstellungen sollten listen-interface und upstream-interface verwenden, die mit diesem Befehl nicht kombiniert werden können. Bei Commit erscheint eine Veraltungs-Warnung.

Hinweis

Die Loopback-Schnittstelle (lo) wird nicht als gültiger Wert für diesen Befehl akzeptiert.

Beispiel:

set service dhcp-relay interface eth1
set service dhcp-relay interface eth2
set service dhcp-relay disable

Verwaltet deaktivieren Sie den DHCPv4-Relay-Dienst, ohne dessen Konfiguration zu entfernen.

Beispiel:

set service dhcp-relay disable

Relay-Optionen

set service dhcp-relay relay-options hop-count <1-255>

Konfigurieren Sie den DHCPv4-Hop-Zähler, bei dem weitergeleitete Pakete gelöscht werden.

Eine DHCPv4-Relay, die eine Clientmeldung empfängt, setzt den Hop-Zähler auf 0. Jeder nachfolgende DHCPv4-Relay entlang des Paketweges erhöht ihn. Pakete, deren Hop-Zähler den festgelegten Wert erreicht hat, werden stillgelöscht.

Der Standardwert ist 10.

Beispiel:

set service dhcp-relay relay-options hop-count 4
set service dhcp-relay relay-options max-size <64-1400>

Konfigurieren Sie die maximale Größe, in Bytes, die ein DHCPv4-Paket mit der Relay Agent Information-Option erreichen darf.

Wenn das Paket mit der angefügten Option diese Größe überschreitet, wird die Option weggelassen und das Paket wird ohne sie weitergeleitet.

Der Standardwert ist 576.

Beispiel:

set service dhcp-relay relay-options max-size 1400
set service dhcp-relay relay-options relay-agents-packets <append | discard | forward | replace>

Konfigurieren Sie die Richtlinie, die auf eingehende DHCPv4-Pakete angewandt wird, die bereits eine Relay Agent Information-Option tragen:

  • append: Fügt die lokale Relay Agent Information-Option hinzu, während die vorhandene Relay Agent Information-Option erhalten bleibt.

  • discard: Löscht Pakete, die eine Relay Agent Information-Option tragen.

  • forward: Weiterleiten von Paketen mit ihrer vorhandenen Relay Agent Information-Option unverändert.

  • replace: Entfernt die vorhandene Relay Agent Information-Option und fügt die lokale Relay Agent Information-Option ein.

Der Standardwert ist forward.

Beispiel:

set service dhcp-relay relay-options relay-agents-packets discard

Betrieb

restart dhcp relay-agent

Neustarten des DHCPv4-Relay-Dienstes.

Beispiel

Die folgende Konfiguration leitet DHCP-Client-Anfragen, die auf eth1 (die clientseitige Schnittstelle) empfangen werden, über eth2 (die serverseitige Schnittstelle) an einen DHCP-Server unter 203.0.113.4 weiter. Pakete, die bereits eine Relay Agent Information enthalten, werden gelöscht, sodass nur Anfragen, die direkt von Clients stammen, weitergeleitet werden.

set interfaces ethernet eth1 address '192.0.2.1/24'
set interfaces ethernet eth2 address '198.51.100.1/24'
set service dhcp-relay listen-interface 'eth1'
set service dhcp-relay upstream-interface 'eth2'
set service dhcp-relay server '203.0.113.4'
set service dhcp-relay relay-options relay-agents-packets discard

Die äquivalente Konfiguration mit der veralteten interface-Syntax, die nur aus Kompatibilitätsgründen beibehalten wird, lautet:

set interfaces ethernet eth1 address '192.0.2.1/24'
set interfaces ethernet eth2 address '198.51.100.1/24'
set service dhcp-relay interface 'eth1'
set service dhcp-relay interface 'eth2'
set service dhcp-relay server '203.0.113.4'
set service dhcp-relay relay-options relay-agents-packets discard

IPv6-Relay

Konfiguration

set service dhcpv6-relay listen-interface <interface>

Konfigurieren Sie eine Schnittstelle, auf der der DHCPv6-Relay Client-Multicast-Anfragen empfängt.

Die Schnittstelle muss bereits eine globale unicast IPv6-Adresse haben.

Wiederholen Sie den Befehl, um mehrere Listen-Schnittstellen zu konfigurieren.

Hinweis

Mindestens ein listen-interface und ein upstream-interface müssen für einen erfolgreichen Commit konfiguriert sein.

Beispiel:

set service dhcpv6-relay listen-interface eth1
set service dhcpv6-relay listen-interface <interface> address <ipv6-address>

Konfigurieren Sie die IPv6-Adresse, die der DHCPv6-Relay verwendet, um das clientseitige Netzwerk für den DHCPv6-Server zu identifizieren.

Die Adresse muss eine nicht-link-local IPv6-Adresse sein, die bereits der angegebenen Listen-Schnittstelle zugewiesen wurde.

Wenn die Adresse nicht gesetzt ist, verwendet der DHCPv6-Relay die erste nicht-link-local IPv6-Adresse, die auf dieser Listen-Schnittstelle gefunden wird.

Beispiel:

set service dhcpv6-relay listen-interface eth1 address 2001:db8:1::1
set service dhcpv6-relay upstream-interface <interface> address <ipv6-address>

Konfigurieren Sie die IPv6-Adresse eines DHCPv6-Servers (oder eines anderen Relays), an den der DHCPv6-Relay Client-Nachrichten über die angegebene Upstream-Schnittstelle weiterleitet.

Wiederholen Sie den Befehl, um Client-Nachrichten an mehrere Server (oder Relays) weiterzuleiten.

Hinweis

Es muss mindestens eine Server-(oder Relay)-Adresse für jedes Upstream-Interface konfiguriert sein, um einen erfolgreichen Commit zu gewährleisten.

Beispiel:

set service dhcpv6-relay upstream-interface eth2 address 2001:db8:2::4
set service dhcpv6-relay disable

Verwaltet deaktivieren Sie den DHCPv6-Relay-Dienst, ohne dessen Konfiguration zu entfernen.

Beispiel:

set service dhcpv6-relay disable

Relay-Optionen

set service dhcpv6-relay max-hop-count <1-255>

Konfigurieren Sie den DHCPv6-Hop-Zähler, bei dem weitergeleitete Pakete gelöscht werden.

Eine DHCPv6-Relay, die eine Clientmeldung empfängt, setzt den Hop-Zähler auf 0. Jeder nachfolgende DHCPv6-Relay entlang des Paketweges erhöht ihn. Pakete, deren Hop-Zähler den festgelegten Wert erreicht hat, werden stillgelöscht.

Der Standardwert ist 10.

Beispiel:

set service dhcpv6-relay max-hop-count 4
set service dhcpv6-relay use-interface-id-option

Das Einfügen der Interface-ID-Option in jede Relay-forward-Nachricht aktivieren.

Die Interface-ID-Option wird automatisch eingefügt, wenn mehr als eine Listen-Schnittstelle auf einem Relay konfiguriert ist, unabhängig von dieser Einstellung.

Beispiel:

set service dhcpv6-relay use-interface-id-option

Betrieb

restart dhcpv6 relay-agent

Neustarten des DHCPv6-Relay-Dienstes.

Beispiel

Die folgende Konfiguration leitet DHCPv6-Client-Anfragen, die auf eth1 (die clientseitige Schnittstelle) empfangen werden, über eth2 (die serverseitige Schnittstelle) an einen DHCPv6-Server unter 2001:db8:2::4 weiter.

set interfaces ethernet eth1 address '2001:db8:1::1/64'
set interfaces ethernet eth2 address '2001:db8:2::1/64'
set service dhcpv6-relay listen-interface 'eth1'
set service dhcpv6-relay upstream-interface 'eth2' address '2001:db8:2::4'
