Segment Routing

SR ist eine Netzwerkarchitektur, die der Quellrouting-Technik ähnelt. Der Eingangsrouter fügt bei jedem Paket, das das Netzwerk betritt, eine Liste von Segmenten, sogenannte SIDs, hinzu.

Die SID-Liste definiert explizit den Weg, den das Paket folgen wird. Bei jedem Knoten liest der Router das erste SID, führt die zugehörige Weiterleitungsanweisung aus und entfernt es in der Regel, damit der nächste Knoten das folgende SID verarbeiten kann.

SR beruht auf IGPs, wie IS-IS oder OSPF, um SIDs im gesamten Netzwerk zu verbreiten.

Hinweis

SR definiert eine Steuerungsplane-Architektur und kann auf bestehende MPLS-basierte Datenpläne angewandt werden. In MPLS-Netzwerken werden Segmente als MPLS-Labels kodiert und am Eingangsrouter angewandt. Diese Labels werden dann durch IGPs wie IS-IS (wie in RFC 8667 beschrieben) oder OSPF im Routing-Bereich verteilt.

SR für den MPLS-Datenplan unterstützt IPv4, IPv6 und ECMP und wurde mit Cisco- und Juniper-Routern getestet. Dieses Deployment ist jedoch weiterhin experimentell für FRR.

IS-IS SR-Konfiguration

Verwenden Sie die folgenden Befehle, um SR auf IS-IS zu aktivieren.

Bekannte Einschränkungen:

  • Keine Unterstützung für Level-Redistribution (L1 zu L2 oder L2 zu L1).

  • Keine Unterstützung für BSID.

  • Nur ein einzelnes SRGB und der Standard-SPF-Algorithmus werden unterstützt.

set protocols isis segment-routing global-block high-label-value <16-1048575>

Konfigurieren Sie die obere Grenze des Segment Routing Global Blocks (SRGB).

Der SRGB definiert den Bereich der MPLS-Labels, die für das Zuordnen globaler Segmente, wie Prefix-SIDs, zu FIB-Einträgen reserviert sind.

Der Bereich darf nicht mehr als 65535 Labels überschreiten.

Beispiel:

set protocols isis segment-routing global-block high-label-value 23999
set protocols isis segment-routing global-block low-label-value <16-1048575>

Konfigurieren Sie die untere Grenze des Segment Routing Global Blocks (SRGB).

Der SRGB definiert den Bereich der MPLS-Labels, die für das Zuordnen globaler Segmente, wie Prefix-SIDs, zu FIB-Einträgen reserviert sind.

Der Bereich darf nicht mehr als 65535 Labels überschreiten.

Beispiel:

set protocols isis segment-routing global-block low-label-value 16000
set protocols isis segment-routing local-block high-label-value <16-1048575>

Konfigurieren Sie die obere Grenze des Segment Routing Local Blocks (SRLB).

Der SRLB definiert den Bereich der MPLS-Labels, die ein Router für seine lokalen Segmente, wie Adjacency-SIDs, reserviert.

Der Bereich darf nicht mehr als 65535 Labels überschreiten.

Beispiel:

set protocols isis segment-routing local-block high-label-value 15999
set protocols isis segment-routing local-block low-label-value <16-1048575>

Konfigurieren Sie die untere Grenze des Segment Routing Local Blocks (SRLB).

Der SRLB definiert den Bereich der MPLS-Labels, die ein Router für seine lokalen Segmente, wie Adjacency-SIDs, reserviert.

Der Bereich darf nicht mehr als 65535 Labels überschreiten.

Beispiel:

set protocols isis segment-routing local-block low-label-value 15000

Hinweis

SR-Labelblöcke haben folgende Konfigurationsbeschränkungen:

  • Beide Grenzen (high-label-value und low-label-value) müssen konfiguriert werden. Das Entfernen einer Grenze entfernt auch die andere.

  • local-block erfordert, dass global-block konfiguriert ist.

  • Die SRGB- und SRLB-Bereiche dürfen sich nicht überlappen.

Verstöße gegen diese Regeln führen dazu, dass das Commit fehlschlägt.

set protocols isis segment-routing maximum-label-depth <1-16>

Konfigurieren Sie die vom Router unterstützte MSD.

Der Wert hängt vom MPLS-Datenplane ab.

Beispiel:

set protocols isis segment-routing maximum-label-depth 10
set protocols isis segment-routing prefix <address> index value <0-65535>

Konfigurieren Sie einen Prefix-SID mit einem Indexwert für den angegebenen IP-Präfix.

Ein Prefix-SID ist ein Segment-Identifier, der mit einem IP-Präfix assoziiert ist und vom IGP (IS-IS) verteilt wird.

Beispiel:

set protocols isis segment-routing prefix 192.0.2.1/32 index value 1
set protocols isis segment-routing prefix <address> index <no-php-flag | explicit-null>

Konfigurieren Sie einen Label-Verarbeitungs-Flag für den indizierten Prefix-SID, der mit dem angegebenen IP-Präfix assoziiert ist:

  • no-php-flag: Fordert den Upstream-Neighbor an, das Prefix-SID-Label vor dem Weiterleiten des Pakets nicht zu entfernen.

  • explicit-null: Fordert den Upstream-Neighbor an, das Paket mit dem Explicit-Null-Label weiterzuleiten.

Beispiel:

set protocols isis segment-routing prefix 192.0.2.1/32 index no-php-flag
set protocols isis segment-routing prefix <address> absolute value <16-1048575>

Konfigurieren Sie einen Prefix-SID mit absolutem Wert für den angegebenen IP-Präfix

Ein Prefix-SID ist ein Segment-Identifier, der mit einem IP-Präfix assoziiert ist und vom IGP (IS-IS) verteilt wird.

Beispiel:

set protocols isis segment-routing prefix 192.0.2.1/32 absolute value 16001
set protocols isis segment-routing prefix <address> absolute <no-php-flag | explicit-null>

Konfigurieren Sie einen Label-Verarbeitungs-Flag für den absoluten Prefix-SID, der mit dem angegebenen IP-Präfix assoziiert ist:

  • no-php-flag: Fordert den Upstream-Neighbor an, das Prefix-SID-Label vor dem Weiterleiten des Pakets nicht zu entfernen.

  • explicit-null: Fordert den Upstream-Neighbor an, das Paket mit dem Explicit-Null-Label weiterzuleiten.

Beispiel:

set protocols isis segment-routing prefix 192.0.2.1/32 absolute no-php-flag

Betriebsbefehle

show isis segment-routing node

Zeigen Sie alle gelernten SR-Knoten an.

show isis route prefix-sid

Zeigen Sie alle gelernten Prefix-SIDs und deren MPLS-Labels an.

Hinweis

Weitere Informationen finden Sie unter IS-IS.

OSPF SR-Konfiguration

Verwenden Sie die folgenden Befehle, um SR auf OSPF zu aktivieren.

set protocols ospf parameters opaque-lsa

Enable Opaque LSA (RFC 2370) in OSPF.

Opaque LSAs sind erforderlich, um MPLS-Labels über OSPF zu transportieren.

Beispiel:

set protocols ospf parameters opaque-lsa
set protocols ospf segment-routing global-block high-label-value <16-1048575>

Beispiele

SR auf IS-IS aktivieren (experimentell)

Das folgende Beispiel zeigt ein grundlegendes zwei-Knoten SR-Topologie mit IS-IS.

Knoten 1:

set interfaces loopback lo address '198.51.100.1/32'
set interfaces ethernet eth1 address '192.0.2.1/24'

set protocols isis interface eth1
set protocols isis interface lo
set protocols isis net '49.0001.1980.5110.0001.00'
set protocols isis segment-routing global-block high-label-value '599'
set protocols isis segment-routing global-block low-label-value '550'
set protocols isis segment-routing prefix 198.51.100.1/32 index value '1'
set protocols isis segment-routing prefix 198.51.100.1/32 index explicit-null
set protocols mpls interface 'eth1'

Knoten 2:

set interfaces loopback lo address '198.51.100.2/32'
set interfaces ethernet eth1 address '192.0.2.2/24'

set protocols isis interface eth1
set protocols isis interface lo
set protocols isis net '49.0001.1980.5110.0002.00'
set protocols isis segment-routing global-block high-label-value '599'
set protocols isis segment-routing global-block low-label-value '550'
set protocols isis segment-routing prefix 198.51.100.2/32 index value '2'
set protocols isis segment-routing prefix 198.51.100.2/32 index explicit-null
set protocols mpls interface 'eth1'

SR auf OSPF aktivieren (experimentell)

Das folgende Beispiel zeigt ein grundlegendes zwei-Knoten SR-Topologie mit OSPF.

Knoten 1:

set interfaces ethernet eth0 address 192.0.2.1/24
set protocols ospf area 0 network '192.0.2.0/24'
set protocols ospf area 0 network '198.51.100.1/32'
set protocols ospf parameters opaque-lsa
set protocols ospf parameters router-id '198.51.100.1'
