Babel

Das Babel-Protokoll bietet zuverlässige und effiziente Routing für kabelgebundene und drahtlose Mesh-Netzwerke. Standardmäßig verwendet Babel Hop-Zählungsmetriken auf kabelgebundenen Verbindungen und eine Variante des erwarteten Übertragungszaus (ETX) auf drahtlosen Verbindungen. Administratoren können Babel konfigurieren, um die Radiodiversität zu berücksichtigen, die Link-Latenz automatisch zu berechnen und diese Latenz in die Routing-Metrik einzubeziehen. RFC 8966 definiert das Babel-Protokoll.

Babel ist ein Dual-Stack-Protokoll. Ein einzelnes Babel-Exemplar routet gleichzeitig IPv4- und IPv6-Datenverkehr.

Allgemeine Konfiguration

VyOS benötigt keinen spezifischen Befehl, um den Babel-Prozess zu starten. Das System startet den Routing-Prozess automatisch, wenn Sie die erste Babel-fähige Schnittstelle konfigurieren.

set protocols babel interface <interface>

Die Babel-Routing auf der angegebenen Schnittstelle aktivieren.

Das System beginnt sofort mit dem Senden und Empfangen von Babel-Paketen auf dieser Schnittstelle.

Optionale Konfiguration

set protocols babel parameters diversity

Radio-Frequenz-Diversität für den Babel-Prozess aktivieren.

Diese Funktion wird für Netzwerke mit vielen drahtlosen Knoten dringend empfohlen.

Hinweis

Wenn Sie die Diversitätsrouting-Funktion aktivieren, sollten Sie auch die Parameter diversity-factor und channel konfigurieren.

set protocols babel parameters diversity-factor <1-256>

Konfigurieren Sie den Multiplikationsfaktor für das Diversitätsrouting in Einheiten von 1/256.

Niedrigere Multiplikationsfaktoren geben einer Diversität bei der Routenauswahl größere Gewichtung. Der Standardwert ist 256, was das Diversitätsrouting deaktiviert. Bei Knoten mit mehreren unabhängigen Radios sollten Sie einen Wert von 128 oder weniger konfigurieren.

set protocols babel parameters resend-delay <20-655340>

Konfigurieren Sie die Verzögerung in Millisekunden, bevor das System eine wichtige Anfrage oder Aktualisierung erneut sendet.

Der Standardwert beträgt 2000 ms.

set protocols babel parameters smoothing-half-life <0-65534>

Konfigurieren Sie die Zeitkonstante in Sekunden für den Glättungsalgorithmus, der zur Implementierung der Hysterese verwendet wird.

Höhere Werte reduzieren die Routenschwankungen, erhöhen aber leicht die Konvergenzzeit. Ein Wert von 0 deaktiviert die Hysterese und ist für kabelgebundene Netzwerke geeignet. Der Standardwert beträgt 4 Sekunden.

Schnittstellen-Konfiguration

set protocols babel interface <interface> type <auto|wired|wireless>

Konfigurieren Sie den Netzwerktyp für die Babel-fähige Schnittstelle.

Wählen Sie aus folgenden Optionen:

  • auto: Babel erkennt automatisch, ob eine Schnittstelle kabelgebunden oder drahtlos ist.

  • wired: Babel aktiviert Optimierungen für kabelgebundene Schnittstellen.

  • wireless: Babel deaktiviert Optimierungen, die nur für kabelgebundene Schnittstellen geeignet sind. Die Angabe von wireless ist immer korrekt, kann aber zu langsamerer Konvergenz und erhöhtem Routing-Verkehr führen.

set protocols babel interface <interface> split-horizon <default|disable|enable>

Konfigurieren Sie das Split-Horizon-Routing-Verhalten für die angegebene Schnittstelle.

Verwenden Sie eine der folgenden Optionen:

  • default: Babel aktiviert automatisch Split-Horizon auf kabelgebundenen Schnittstellen und deaktiviert es auf drahtlosen Schnittstellen.

  • enable: Babel aktiviert Split-Horizon auf der Schnittstelle. Diese Optimierung sollte nur auf symmetrischen, transitiven (kabelgebundenen) Netzwerken verwendet werden.

  • disable: Babel deaktiviert Split-Horizon auf der Schnittstelle. Das Deaktivieren von Split-Horizon ist immer sicher und korrekt.

set protocols babel interface <interface> hello-interval <20-655340>

Konfigurieren Sie das Intervall in Millisekunden zwischen geplanten Hello-Nachrichten auf der angegebenen Schnittstelle.

Auf kabelgebundenen Verbindungen erkennt Babel innerhalb von zwei Hello-Intervallen Verbindungsfehler. Auf drahtlosen Verbindungen wird die Verbindungsqualität jedes Intervalls neu geschätzt. Der Standardwert beträgt 4000 ms.

set protocols babel interface <interface> update-interval <20-655340>

Konfigurieren Sie das Intervall in Millisekunden zwischen geplanten Routing-Updates auf der angegebenen Schnittstelle.

Weil Babel Trigger-Updates stark verwendet, können Sie diesen Wert auf zuverlässigen Verbindungen mit geringer Paketverlustrate erhöhen. Der Standardwert beträgt 20000 ms.

set protocols babel interface <interface> rxcost <1-65534>

Konfigurieren Sie die Basis-Empfangskosten für die angegebene Schnittstelle.

Babel wendet diesen Wert basierend auf dem konfigurierten Netzwerktyp an:

  • wired: Der Wert ist die Routing-Kosten, die an benachbarte Router weitergegeben werden.

  • wireless: Der Wert ist ein Multiplikator, der zur Berechnung der ETX (Expected Transmission Count)-Empfangskosten verwendet wird.

Der Standardwert beträgt 256.

set protocols babel interface <interface> rtt-decay <1-256>

Konfigurieren Sie den Zerfallsfaktor für den exponentiellen gleitenden Durchschnitt von RTT-Proben in Einheiten von 1/256.

Höhere Werte werfen ältere Proben schneller weg. Der Standardwert ist 42.

set protocols babel interface <interface> rtt-min <1-65535>

Konfigurieren Sie die minimale RTT in Millisekunden, ab der die Kosten zu einem Nachbarn ansteigen.

Die zusätzlichen Kosten sind linear in (rtt - rtt-min). Der Standardwert beträgt 10 ms.

set protocols babel interface <interface> rtt-max <1-65535>

Konfigurieren Sie die maximale RTT in Millisekunden, über die die Kosten zu einem Nachbarn nicht mehr ansteigen.

Der Standardwert beträgt 120 ms.

set protocols babel interface <interface> max-rtt-penalty <0-65535>

Konfigurieren Sie die maximale Kosten, die zu einem Nachbarn hinzugefügt werden, wenn RTT den Wert rtt-max erreicht oder überschreitet.

Wenn Sie diesen Wert auf 0 setzen, werden RTT-basierte Kosten deaktiviert. Der Standardwert beträgt 150.

set protocols babel interface <interface> enable-timestamps

Konfigurieren Sie das Hinzufügen von Zeitspeichern zu jeder Hello- und IHU-Nachricht, um RTT-Werte zu berechnen.

Das Aktivieren von Zeitspeichern wird für Tunnel-Schnittstellen empfohlen.

set protocols babel interface <interface> channel <1-254|interfering|noninterfering>

Konfigurieren Sie den Kanal-Identifikator, den das Diversitätsrouting für die angegebene Schnittstelle verwendet.

Schnittstellen beeinflussen sich gegenseitig basierend auf dem zugewiesenen Kanal-Identifikator:

  • 1–254: Die Schnittstelle beeinflusst andere Schnittstellen mit demselben Kanalnummer und Schnittstellen, die als interfering konfiguriert sind.

  • interfering: Die Schnittstelle beeinflusst alle anderen außer denen, die als noninterfering konfiguriert sind.

  • noninterfering: Die Schnittstelle beeinflusst nur sich selbst.

Redistribution-Konfiguration

set protocols babel redistribute <ipv4|ipv6> <route source>

Konfigurieren Sie die Redistribution von Routing-Informationen aus dem angegebenen Route-Quelle in den Babel-Prozess.

Folgende Route-Quellen sind verfügbar:

  • ipv4: bgp, connected, eigrp, isis, kernel, nhrp, ospf, rip, static

  • ipv6: bgp, connected, eigrp, isis, kernel, nhrp, ospfv3, ripng, static

set protocols babel distribute-list <ipv4|ipv6> access-list <in|out> <number>

Konfigurieren Sie globale Babel-Routenfilterung mit einer Zugriffsliste.

Geben Sie die Richtung an, in der die Zugriffsliste angewandt wird:

  • in: Filtert eingehende Routen.

  • out: Filtert ausgehende Routen.

set protocols babel distribute-list <ipv4|ipv6> interface <interface> access-list <in|out> <number>

Konfigurieren Sie Babel-Routenfilterung auf der angegebenen Schnittstelle mit einer Zugriffsliste.

Geben Sie die Richtung an, in der die Zugriffsliste angewandt wird:

  • in: Filtert eingehende Routen.

  • out: Filtert ausgehende Routen.

set protocols babel distribute-list <ipv4|ipv6> prefix-list <in|out> <name>

Konfigurieren Sie globale Babel-Routenfilterung mit einer Präfixliste.

Geben Sie die Richtung an, in der die Präfixliste angewandt wird:

  • in: Filtert eingehende Routen.

  • out: Filtert ausgehende Routen.

set protocols babel distribute-list <ipv4|ipv6> interface <interface> prefix-list <in|out> <name>

Konfigurieren Sie Babel-Routenfilterung auf der angegebenen Schnittstelle mit einer Präfixliste.

Geben Sie die Richtung an, in der die Präfixliste angewandt wird:

  • in: Filtert eingehende Routen.

  • out: Filtert ausgehende Routen.

Konfigurationsbeispiel

Grundlegendes zweiknotiges Babel-Netzwerk

Ziel: Das folgende Beispiel verbindet zwei Router (Knoten 1 und Knoten 2) über ihre eth0-Schnittstellen und verwendet das Babel-Routing-Protokoll, um die lokal konfigurierten Netzwerke jedes Routers (dargestellt durch Loopback-Adressen) gegenseitig zu bewerben (redistribute).

Knoten 1:

# Konfigurieren Sie die Loopback-(lokale Netzwerke) und physische (eth0) Adressen
set interfaces loopback lo address 10.1.1.1/32
set interfaces loopback lo address fd12:3456:dead:beef::1/128
set interfaces ethernet eth0 address 192.168.1.1/24

# Babel auf der physischen Verbindung aktivieren
set protocols babel interface eth0 type wired

# Weisen Sie Babel an, die lokal konfigurierten Netzwerke zu bewerben (redistribute)
set protocols babel redistribute ipv4 connected
set protocols babel redistribute ipv6 connected

Knoten 2:

# Konfigurieren Sie die Loopback-(lokale Netzwerke) und physische (eth0) Adressen
set interfaces loopback lo address 10.2.2.2/32
set interfaces loopback lo address fd12:3456:beef:dead::2/128
set interfaces ethernet eth0 address 192.168.1.2/24

# Babel auf der physischen Verbindung aktivieren
set protocols babel interface eth0 type wired

# Teilen Sie Babel mit, die lokal konfigurierten Netzwerke zu bewerben (redistribute)
set protocols babel redistribute ipv4 connected
set protocols babel redistribute ipv6 connected
