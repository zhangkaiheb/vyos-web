Syslog

Übersicht

Standardmäßig bietet VyOS eine minimale Logging-Konfiguration mit lokaler Speicherung und Log-Rotation. Alle Fehler, einschließlich der local7-Meldungen, werden in eine lokale Datei gespeichert. Notfallmeldungen werden an die Konsole gesendet.

Um diese Einstellungen zu ändern, geben Sie den Konfigurationsmodus ein.

Syslog-Konfiguration

Syslog unterstützt das Protokollieren in mehrere Ziele: eine lokale Datei, eine Konsole oder einen entfernten Syslog-Server über UDP oder TCP.

Die Syslog-Konfiguration ist in folgende Kategorien unterteilt:

  • Allgemeine Einstellungen

  • Lokales Protokollieren

  • Konsole-Protokollieren

  • Entferntes Protokollieren

  • TLS-verschlüsseltes entferntes Protokollieren

Allgemeine Einstellungen

Konfigurieren Sie das allgemeine Verhalten des Syslog-Dienstes.

set system syslog marker interval <number>

Konfigurieren Sie das Intervall in Sekunden für das Senden von Syslog-Markenmeldungen.

Syslog-Markenmeldungen bestätigen, dass der Logging-Dienst funktioniert.

Standard: 1200 Sekunden.

set system syslog marker disable

Deaktivieren Sie das Senden von Syslog-Markenmeldungen.

set system syslog preserve-fqdn

Konfigurieren Sie, wie der Hostname des Logging-Geräts in den Protokollmeldungen erscheint, die an einen entfernten Syslog-Server gesendet werden.

Wenn konfiguriert, enthält das Gerät seine FQDN in den Protokollmeldungen, auch wenn der Syslog-Server im selben Domänenbereich ist.

Lokales Protokollieren

Konfigurieren Sie, welche Protokollmeldungen in eine lokale Protokolldatei gespeichert werden.

set system syslog local <filename> facility <keyword> level <keyword>

Konfigurieren Sie Syslog, um Protokollmeldungen für eine bestimmte Facility und Schweregrad auf ``/var/log/messages`` zu speichern.

Referenzieren Sie die unten stehenden Tabellen für gültige Facility- und Schweregradoptionen.

Konsole-Protokollieren

Konfigurieren Sie, welche Protokollmeldungen an /dev/console gesendet werden.

set system syslog console facility <keyword> level <keyword>

Konfigurieren Sie Syslog, um Protokollmeldungen für eine bestimmte Facility und Schweregrad an die Konsole des Geräts zu senden.

Referenzieren Sie die unten stehenden Tabellen für gültige Facility- und Schweregradoptionen.

Entferntes Protokollieren

Konfigurieren Sie entferntes Protokollieren, um Protokollmeldungen an einen entfernten Syslog-Server zu senden.

Entferntes Protokollieren beeinflusst weder lokales noch Konsole-Protokollieren und läuft parallel dazu. Entferntes Protokollieren unterstützt das Senden von Protokollmeldungen an mehrere Hosts.

set system syslog remote <address> facility <keyword> level <keyword>

Konfigurieren Sie die Übertragung von Protokollen an den entfernten Syslog-Server für eine bestimmte Facility und Schweregrad.

Die Adresse des Servers kann entweder mit einem FQDN oder einer IP-Adresse angegeben werden.

Referenzieren Sie die unten stehenden Tabellen für gültige Facility- und Schweregradoptionen.

set system syslog remote <address> protocol <udp | tcp>

Konfigurieren Sie das Protokoll für die Protokollübertragung.

Das Protokoll kann entweder UDP oder TCP sein. Standardmäßig werden Protokollmeldungen über UDP gesendet.

set system syslog remote <address> port <port>

Konfigurieren Sie den Port für die Protokollübertragung.

Standardmäßig wird der Standardport 514 verwendet.

set system syslog remote <address> format include-timezone

Konfigurieren Sie die Protokollübertragung im RFC 5424-Format.

Das RFC 5424-Format enthält die Zeitzone in dem Zeitstempel. Zum Beispiel:

<34>1 2003-10-11T22:14:15.003-07:00 mymachine.example.com su - ID47 - BOM’su root’ failed for lonvick on /dev/pts/8.

Standardmäßig werden Protokollmeldungen im RFC 3164-Format gesendet. Zum Beispiel:

<34>Oct 11 22:14:15 mymachine su: ‘su root’ failed for lonvick on /dev/pts/8
set system syslog remote <address> format octet-counted

Enable octet-counted framing for log transmission.

When enabled, multi-line log messages are sent without splitting. Ensure the remote server supports octet-counted framing to avoid parsing errors.

Octet-counted framing is not available for the UDP protocol.

set system syslog remote <address> vrf <name>

Konfigurieren Sie die VRF-Instanz für die Protokollübertragung.

set system syslog remote <address> source-address <address>

Konfigurieren Sie die Quell-IP-Adresse (IPv4 oder IPv6) für die Protokollübertragung.

TLS-verschlüsseltes entferntes Protokollieren

VyOS unterstützt TLS-verschlüsseltes entferntes Protokollieren über TCP, um sichere Übertragung von Syslog-Daten an entfernte Syslog-Server sicherzustellen.

Voraussetzungen: Bevor Sie TLS-verschlüsseltes entferntes Protokollieren konfigurieren, stellen Sie sicher, dass Sie haben:

  • Eine gültige Adresse eines entfernten Syslog-Servers.

  • Gültige CA- und Client-Zertifikate, die in den lokalen PKI-Speicher hochgeladen wurden.

  • Der entfernte Syslog-Transport-Protokoll ist auf TCP gesetzt:

    set system syslog remote <address> protocol tcp

Hinweis

TLS-verschlüsseltes entferntes Protokollieren ist nicht unterstützt über UDP.

set system syslog remote <address> tls

Enable TLS-encrypted remote logging.

set system syslog remote <address> tls ca-certificate <ca_name>

Konfigurieren Sie das CA Zertifikat.

Das Syslog-Client verwendet das CA-Zertifikat, um die Identität des entfernten Syslog-Servers zu verifizieren.

Das CA-Zertifikat ist erforderlich für alle Authentifizierungsmodi außer anon.

set system syslog remote <address> tls certificate <cert_name>

Konfigurieren Sie das Client-Zertifikat.

Der entfernte Syslog-Server verwendet das Client-Zertifikat, um die Identität des Syslog-Clients zu verifizieren.

Das Client-Zertifikat ist erforderlich, wenn der entfernte Syslog-Server Client-Zertifikatsverifikation erzwingt.

set system syslog remote <address> tls auth-mode <anon | fingerprint | certvalid | name>

Konfigurieren Sie den Authentifizierungsmodus.

Der Authentifizierungsmodus definiert, wie der Syslog-Client die Identität des Syslog-Servers verifiziert.

Die folgenden Authentifizierungsmodi sind verfügbar:

  • anon (Standard): Erlaubt verschlüsselte Verbindungen ohne die Verifizierung der Identität des Syslog-Servers. Dieser Modus ist nicht empfohlen, da er anfällig für MITM-Angriffe ist.

  • fingerprint: Verifiziert das Zertifikat des Servers gegen den vorher konfigurierten Wert mit:

    set system syslog remote <address> tls permitted-peer <peer>

  • certvalid: Verifiziert, dass das Serverzertifikat von einer vertrauenswürdigen CA signiert wurde, wobei der CN-Check übersprungen wird.

  • name: Verifiziert, dass:

    • Das Serverzertifikat von einer vertrauenswürdigen CA signiert ist.

    • Der CN im Zertifikat mit dem Wert übereinstimmt, der mit:

    set system syslog remote <address> tls permitted-peer <peer>

    Dies ist ein empfohlener sicherer Modus für Produktionsumgebungen.

set system syslog remote <address> tls permitted-peer <peer>

Konfigurieren Sie die Zertifikat-Identifikatoren des Peers.

Das Format des Zertifikat-Identifikators hängt vom Authentifizierungsmodus ab:

  • fingerprint: Geben Sie die erwarteten Zertifikat-Fingerprints (SHA-1 oder SHA-256) ein.

  • name: Geben Sie die erwarteten Zertifikat-CNs ein.

Für anon und certvalid Authentifizierungsmodi sind Zertifikat-Identifikatoren nicht erforderlich.

Beispiele:

# Beispiel für den 'anon'-Authentifizierungsmodus
set system syslog remote 10.10.2.3 facility all level debug
set system syslog remote 10.10.2.3 port 6514
set system syslog remote 10.10.2.3 protocol tcp
set system syslog remote 10.10.2.3 tls auth-mode anon
# oder einfach 'set system syslog remote 10.10.2.3 tls'

# Beispiel für den 'certvalid'-Authentifizierungsmodus
set system syslog remote elk.example.com facility all level debug
set system syslog remote elk.example.com port 6514
set system syslog remote elk.example.com protocol tcp
set system syslog remote elk.example.com tls ca-certificate my-ca
set system syslog remote elk.example.com tls auth-mode certvalid

# Beispiel für den 'fingerprint'-Authentifizierungsmodus
set system syslog remote syslog.example.com facility all level debug
set system syslog remote syslog.example.com port 6514
set system syslog remote syslog.example.com protocol tcp
set system syslog remote syslog.example.com tls ca-certificate my-ca
set system syslog remote syslog.example.com tls auth-mode fingerprint
set system syslog remote syslog.example.com tls permitted-peers 'SHA1:10:C4:26:...,SHA256:7B:4B:10:...'

# Beispiel für den 'name'-Authentifizierungsmodus
set system syslog remote graylog.example.com facility all level debug
set system syslog remote graylog.example.com port 6514
set system syslog remote graylog.example.com protocol tcp
set system syslog remote graylog.example.com tls ca-certificate my-ca
set system syslog remote graylog.example.com tls certificate syslog-client
set system syslog remote graylog.example.com tls auth-mode name
set system syslog remote graylog.example.com tls permitted-peers 'graylog.example.com'

Sicherheitsempfehlungen

  • Für sichere Bereitstellungen sollten Sie immer den name-Authentifizierungsmodus verwenden. Er stellt sicher, dass der Server durch eine vertrauenswürdige CA validiert wird und dass der Hostname mit dem Zertifikat übereinstimmt.

  • Verwenden Sie den anon-Authentifizierungsmodus nur in Testumgebungen, da er keine Server-Authentifizierung bietet.

  • Stellen Sie sicher, dass private Schlüssel ausschließlich innerhalb des PKI-Systems generiert, gespeichert und gewartet werden.

Syslog-Facilities

Dieser Abschnitt listet Facilities auf, die von Syslog verwendet werden. Die meisten Facility-Namen sind selbst erklärend. Die Facilities local0–local7 werden für benutzerdefinierte Zwecke verwendet, z. B. zum Protokollieren von Netzwerkknoten und Geräten. Die Zuordnung von Facilities ist flexibel und sollte an Ihre Unternehmensbedürfnisse angepasst werden. Betrachten Sie Facilities als Kategorisierungstools, nicht als strenge Anweisungen.

Protokolle anzeigen

show log [all | authorization | cluster | conntrack-sync | …]

Protokolle für eine bestimmte Kategorie auf der Konsole anzeigen.

Verwenden Sie die Tab-Completions, um eine Liste der verfügbaren Kategorien anzuzeigen.

Wenn keine Kategorie angegeben wird, werden alle Protokolle angezeigt.

show log image <name> [all | authorization | directory | file <file name> | tail <lines>]

Protokolle für ein bestimmtes Bild auf der Konsole anzeigen.

Verfügbare Protokollkategorien:

all

Zeigt den Inhalt der Systemprotokolldateien des angegebenen Bildes an.

authorization

Zeigt Versuche der Autorisierung des angegebenen Bildes an.

directory

Zeigt benutzerdefinierte Protokolldateien des angegebenen Bildes an.

file <file name>

Zeigt den Inhalt einer bestimmten benutzerdefinierten Protokolldatei des angegebenen Bildes an.

tail

Zeigt die letzten Zeilen des Systemprotokolls des angegebenen Bildes an.

<lines>

Anzahl der anzuzeigenden Zeilen, Standardwert 10.

Wenn keine Kategorie angegeben wird, werden der Inhalt der Haupt-Systemprotokolldatei angezeigt.

Hinweis

Verwenden Sie show log | strip-private, um private Daten zu verbergen, wenn Sie Ihre Protokolle ansehen.
