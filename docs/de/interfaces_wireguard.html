WireGuard

WireGuard ist ein äußerst einfaches, schnelles und modernes VPN, das zustandsorientierte Verschlüsselungstechnologie verwendet. Weitere Informationen finden Sie unter https://www.wireguard.com.

Schlüsselpaare

WireGuard benötigt ein Schlüsselpaar, das einen privaten Schlüssel enthält, um eingehenden Datenverkehr zu entschlüsseln, und einen öffentlichen Schlüssel für Peers, um ausgehenden Datenverkehr zu verschlüsseln.

Schlüsselpaar generieren

generate pki wireguard key-pair

Generiert ein Schlüsselpaar: einen öffentlichen und einen privaten Schlüssel.

Hinweis

Dieser Befehl gibt nur die Schlüssel auf Ihrem Bildschirm aus. Er speichert sie nicht im System und wendet sie auch nicht auf die Systemkonfiguration an.

vyos@vyos:~$ generate pki wireguard key-pair
Privater Schlüssel: iJJyEARGK52Ls1GYRCcFvPuTj7WyWYDo//BknoDU0XY=
Öffentlicher Schlüssel: EKY0dxRrSD98QHjfHOK13mZ5PJ7hnddRZt5woB3szyw=
generate pki wireguard key-pair install interface <interface>

Generiert ein Schlüsselpaar und gibt den Befehl zur Zuordnung des privaten Schlüssels für den angegebenen Schnittstellen an.

vyos@vyos:~$ generate pki wireguard key-pair install interface wg10
"generate" CLI-Befehl wurde vom Betriebslevel ausgeführt.
Der generierte private Schlüssel wird nicht automatisch zur VyOS-Konfiguration hinzugefügt, verwenden Sie die folgenden Konfigurationsmodus-Befehle, um den Schlüssel zu installieren:

set interfaces wireguard wg10 private-key '4Krkv8h6NkAYMMaBWI957yYDJDMvj9URTHstdlOcDU0='

Der entsprechende öffentliche Schlüssel, der auf dem Peer-System verwendet werden soll, lautet: 'UxDsYT6EnpTIOKUzvMlw2p0sNOKQvFxEdSVrnNrX1Ro='

Hinweis

Wenn Sie diesen Befehl im Konfigurationsmodus mit dem Präfix run aufrufen, wird der generierte private Schlüssel automatisch der angegebenen Schnittstelle zugewiesen.

vyos@vyos# run generate pki wireguard key-pair install interface wg10
"generate" CLI-Befehl wurde von einer Konfigurations-Sitzung ausgeführt.
Der generierte private-Key wurde in die CLI importiert!

Verwenden Sie den folgenden Befehl, um dies zu überprüfen: show interfaces wireguard wg10
Der entsprechende öffentliche Schlüssel, der auf dem Peer-System verwendet werden soll, lautet: '7d9KwabjLhHpJiEJeIGd0CBlao/eTwFOh6xyCovTfG8='

vyos@vyos# compare
[edit interfaces]
+wireguard wg10 {
+    private-key CJweb8FC6BU3Loj4PC2pn5V82cDjIPs7G1saW0ZfLWc=
+}
show interfaces wireguard <interface> public-key

Anzeigen des öffentlichen Schlüssels, der der Schnittstelle zugewiesen wurde.

vyos@vyos:~$ show interfaces wireguard wg01 public-key
EKY0dxRrSD98QHjfHOK13mZ5PJ7hnddRZt5woB3szyw=

Optional

generate pki wireguard preshared-key

Generiert einen vorher vereinbarten Schlüssel.

Der vorher vereinbarte Schlüssel ist optional. Er fügt eine zusätzliche Schicht der symmetrischen Kryptografie über die asymmetrische Kryptografie hinzu.

vyos@vyos:~$ generate pki wireguard preshared-key
Vorher vereinbarter Schlüssel: OHH2EwZfMNK+1L6BXbYw3bKCtMrfjpR4mCAEeBlFnRs=
generate pki wireguard preshared-key install interface <interface> peer <peer>

Generiert einen vorher vereinbarten Schlüssel und gibt den Befehl zur Zuordnung des Schlüssels für den angegebenen Peer an.

vyos@vyos:~$ generate pki wireguard preshared-key install interface wg10 peer foo
"generate" CLI-Befehl wurde vom Betriebslevel ausgeführt.
Der generierte vorher vereinbarte Schlüssel wird nicht in die CLI gespeichert, verwenden Sie Konfigurationsmodus-Befehle, um den Schlüssel zu installieren:

set interfaces wireguard wg10 peer foo preshared-key '32vQ1w1yFKTna8n7Gu7EimubSe2Y63m8bafz55EG3Ro='

Vorher vereinbarter Schlüssel: +LuaZ8W6DjsDFJFX3jJzoNqrsXHhvq08JztM9z8LHCs=

Hinweis

Wenn Sie diesen Befehl im Konfigurationsmodus mit dem Präfix run aufrufen, wird der generierte Schlüssel automatisch dem angegebenen Peer zugewiesen.

Schnittstellenkonfiguration

Der nächste Schritt besteht darin, Ihre lokale WireGuard-Schnittstelle zu konfigurieren und die Netzwerke zu definieren, die Sie tunneln möchten (allowed-ips).

Wenn Ihr System nur Verbindungen initiieren muss, ist das Angeben des Laufzeitsports optional. Wenn Ihr System eingehende Verbindungen akzeptiert, müssen Sie einen Port definieren, den Peers verwenden können, um sich zu verbinden. Andernfalls wählt WireGuard bei jedem Neustart einen zufälligen Port aus, und das kann dazu führen, dass die Fähigkeit Ihrer Peers, sich zu verbinden, gestört wird, wenn dieser Port nicht in Ihren Firewall-Regeln aktiviert ist.

Um einen WireGuard-Tunnel zu konfigurieren, benötigen Sie auch den öffentlichen Schlüssel Ihres Peers.

Hinweis

Der in der Peer-Konfigurationsblock angegebene öffentliche Schlüssel ist immer der ferne Peer's öffentliche Schlüssel, nie Ihr lokaler.

Lokale Konfiguration

Die lokale Seite wird mit folgenden Parametern konfiguriert:

  • Lokale WireGuard-Schnittstellen-IP: 10.1.0.1/30

  • Lokaler Laufzeitport: 51820

  • Remote-Peer-Name: to-wg02

  • Remote-Peer-Endpunkt: 192.0.2.1 auf Port 51820

  • Remote-Peer-öffentlicher Schlüssel: XMrlPykaxhdAAiSjhtPlvi30NVkvLQliQuKP7AI7CyI=

  • Erlaubte Netzwerke: 192.168.2.0/24

set interfaces wireguard wg01 address '10.1.0.1/30'
set interfaces wireguard wg01 description 'VPN-to-wg02'
set interfaces wireguard wg01 peer to-wg02 allowed-ips '192.168.2.0/24'
set interfaces wireguard wg01 peer to-wg02 address '192.0.2.1'
set interfaces wireguard wg01 peer to-wg02 port '51820'
set interfaces wireguard wg01 peer to-wg02 public-key 'XMrlPykaxhdAAiSjhtPlvi30NVkvLQliQuKP7AI7CyI='
set interfaces wireguard wg01 port '51820'

set protocols static route 192.168.2.0/24 interface wg01

Um den Datenverkehr, der für 192.168.2.0/24 bestimmt ist, durch die WireGuard-Schnittstelle (wg01) zu senden, konfigurieren Sie eine statische Route. Mehrere IP-Adressen oder Netzwerke können definiert und geroutet werden. Die letzte Prüfung erfolgt gegen allowed-ips, was den Datenverkehr entweder erlaubt oder ablehnt.

Warnung

Sie können dem gleichen allowed-ips nicht mehreren WireGuard Peers zuweisen. Dies ist eine strenge Designbeschränkung. Weitere Informationen finden Sie im WireGuard-Mailing-Liste.

set interfaces wireguard <interface> private-key <private-key>

Weisen Sie einen privaten Schlüssel der angegebenen WireGuard-Schnittstelle zu.

Beispiel:

set interfaces wireguard wg01 private-key 'iJJyEARGK52Ls1GYRCcFvPuTj7WyWYDo//BknoDU0XY='

Zum Generieren eines privaten Schlüssels verwenden Sie den folgenden Befehl: generate pki wireguard key-pair.

Zum Anzeigen des öffentlichen Schlüssels, der der Schnittstelle zugewiesen wurde, damit Sie ihn mit einem Peer teilen können, verwenden Sie den folgenden Befehl: show interfaces wireguard wg01 public-key.

set interfaces wireguard <interface> per-client-thread

Thread-Modus für alle NAPI-Instanzen der angegebenen Netzwerkgeräts aktivieren.

Das Aktivieren des Thread-Modus beeinflusst die Geräteoperation nicht und kann während des Betriebs des Geräts durchgeführt werden.

Dieser Modus ist standardmäßig deaktiviert.

Beispiel:

set interfaces wireguard wg01 per-client-thread

Entfernte Seitenkonfiguration

set interfaces wireguard wg01 address '10.1.0.2/30'
set interfaces wireguard wg01 description 'VPN-to-wg01'
set interfaces wireguard wg01 peer to-wg01 allowed-ips '192.168.1.0/24'
set interfaces wireguard wg01 peer to-wg01 address '192.0.2.2'
set interfaces wireguard wg01 peer to-wg01 port '51820'
set interfaces wireguard wg01 peer to-wg01 public-key 'EKY0dxRrSD98QHjfHOK13mZ5PJ7hnddRZt5woB3szyw='
set interfaces wireguard wg01 port '51820'
set interfaces wireguard wg01 private-key 'OLTQY3HuK5qWDgVs6fJR093SwPgOmCKkDI1+vJLGoFU='

Firewall-Ausnahmen

Um WireGuard-Datenverkehr durch die WAN-Schnittstelle zu ermöglichen, erstellen Sie eine Firewall-Ausnahme:

set firewall ipv4 name OUTSIDE_LOCAL rule 10 action accept
set firewall ipv4 name OUTSIDE_LOCAL rule 10 description 'Allow established/related'
set firewall ipv4 name OUTSIDE_LOCAL rule 10 state established enable
set firewall ipv4 name OUTSIDE_LOCAL rule 10 state related enable
set firewall ipv4 name OUTSIDE_LOCAL rule 20 action accept
set firewall ipv4 name OUTSIDE_LOCAL rule 20 description WireGuard_IN
set firewall ipv4 name OUTSIDE_LOCAL rule 20 destination port 51820
set firewall ipv4 name OUTSIDE_LOCAL rule 20 log enable
set firewall ipv4 name OUTSIDE_LOCAL rule 20 protocol udp

Vergewissern Sie sich, dass die OUTSIDE_LOCAL-Firewallgruppe an die WAN-Schnittstelle angewandt wird und in einer Eingabe-(lokalen) Richtung.

set firewall ipv4 input filter rule 10 action jump
set firewall ipv4 input filter rule 10 jump-target 'OUTSIDE_LOCAL'
set firewall ipv4 input filter rule 10 inbound-interface name 'eth0'

Überprüfen Sie, ob Ihre Firewallregeln den Datenverkehr erlauben. Wenn ja, sollte Ihr WireGuard-VPN funktionieren.

wg01# ping 192.168.1.1
PING 192.168.1.1 (192.168.1.1) 56(84) bytes of data.
64 bytes from 192.168.1.1: icmp_seq=1 ttl=64 time=1.16 ms
64 bytes from 192.168.1.1: icmp_seq=2 ttl=64 time=1.77 ms

wg02# ping 192.168.2.1
PING 192.168.2.1 (192.168.2.1) 56(84) bytes of data.
64 bytes from 192.168.2.1: icmp_seq=1 ttl=64 time=4.40 ms
64 bytes from 192.168.2.1: icmp_seq=2 ttl=64 time=1.02 ms

Ein zusätzlicher Schicht der symmetrischen Kryptografie kann über die asymmetrische Kryptografie hinzugefügt werden. Dies ist optional.

vyos@vyos:~$ generate pki wireguard preshared-key
Vorher vereinbarter Schlüssel: rvVDOoc2IYEnV+k5p7TNAmHBMEGTHbPU8Qqg8c/sUqc=

Kopieren Sie den Schlüssel, da er nicht lokal gespeichert wird. Da es sich um einen symmetrischen Schlüssel handelt, sollten nur Sie und Ihr Peer dessen Inhalt kennen. Verteilen Sie den Schlüssel sicher.

wg01# set interfaces wireguard wg01 peer to-wg02 preshared-key 'rvVDOoc2IYEnV+k5p7TNAmHBMEGTHbPU8Qqg8c/sUqc='
wg02# set interfaces wireguard wg01 peer to-wg01 preshared-key 'rvVDOoc2IYEnV+k5p7TNAmHBMEGTHbPU8Qqg8c/sUqc='

Remote-Zugriff (Road Warrior)

Mit WireGuard ist eine Road Warrior-VPN-Konfiguration ähnlich wie eine Standort-zu-Standort-VPN. Es fehlen einfach die address und port Anweisungen.

In dem folgenden Beispiel werden die IP-Adressen für entfernte Clients innerhalb jeder Peer-Konfiguration definiert. Dies ermöglicht es Peers, miteinander zu kommunizieren.

Zusätzlich verwendet diese Konfiguration ein persistent-keepalive Flag, das auf 15 Sekunden gesetzt ist, um die Verbindung am Leben zu halten. Dieses Einstellung ist besonders relevant, wenn ein Peer hinter NAT ist und nicht erreicht werden kann, wenn die Verbindung verloren geht. Für Effektivität sollte der Wert niedriger sein als der UDP-Timeout.

wireguard wg01 {
    address 10.172.24.1/24
    address 2001:db8:470:22::1/64
    description RoadWarrior
    peer MacBook {
        allowed-ips 10.172.24.30/32
        allowed-ips 2001:db8:470:22::30/128
        persistent-keepalive 15
        pubkey F5MbW7ye7DsoxdOaixjdrudshjjxN5UdNV+pGFHqehc=
    }
    peer iPhone {
        allowed-ips 10.172.24.20/32
        allowed-ips 2001:db8:470:22::20/128
        persistent-keepalive 15
        pubkey BknHcLFo8nOo8Dwq2CjaC/TedchKQ0ebxC7GYn7Al00=
    }
    port 2224
    private-key OLTQY3HuK5qWDgVs6fJR093SwPgOmCKkDI1+vJLGoFU=
}

Unten ist die Konfiguration für den iPhone-Peer. Der AllowedIPs-Wildcard-Eintrag leitet den gesamten IPv4- und IPv6-Datenverkehr über die VPN-Verbindung.

[Interface]
PrivateKey = ARAKLSDJsadlkfjasdfiowqeruriowqeuasdf=
Address = 10.172.24.20/24, 2001:db8:470:22::20/64
DNS = 10.0.0.53, 10.0.0.54

[Peer]
PublicKey = RIbtUTCfgzNjnLNPQ/ulkGnnB2vMWHm7l2H/xUfbyjc=
AllowedIPs = 0.0.0.0/0, ::/0
Endpoint = 192.0.2.1:2224
PersistentKeepalive = 15

Um Split-Tunneling zu ermöglichen, geben Sie die entfernten Subnetze an. Dies stellt sicher, dass nur der Datenverkehr, der für das entfernte Ziel bestimmt ist, durch den Tunnel gesendet wird, während der restliche Datenverkehr unbeeinflusst bleibt.

[Interface]
PrivateKey = 8Iasdfweirousd1EVGUk5XsT+wYFZ9mhPnQhmjzaJE6Go=
Address = 10.172.24.30/24, 2001:db8:470:22::30/64

[Peer]
PublicKey = RIbtUTCfgzNjnLNPQ/ulkGnnB2vMWHm7l2H/xUfbyjc=
AllowedIPs = 10.172.24.30/24, 2001:db8:470:22::/64
Endpoint = 192.0.2.1:2224
PersistentKeepalive = 15

Remote-Zugriff (Road Warrior) Clients

Einige Benutzer verbinden mobile Geräte mit ihrem VyOS-Router über WireGuard. Um die Bereitstellung zu vereinfachen, generieren Sie eine pro-mobil-Konfiguration aus der VyOS CLI.

Warnung

Aus Sicherheitsperspektive wird es nicht empfohlen, einem Dritten zu erlauben, den privaten Schlüssel für eine sichere Verbindung zu erstellen und zu teilen. Sie sollten den privaten Teil selbst erstellen und nur den öffentlichen Schlüssel weitergeben.

generate wireguard client-config <name> interface <interface> server <ip|fqdn> address <client-ip>

Generiert eine Client-Konfigurationsdatei, die eine Verbindung mit der angegebenen Schnittstelle herstellt.

Der öffentliche Schlüssel aus der angegebenen Schnittstelle wird automatisch in die Konfigurationsdatei eingefügt.

Der Befehl generiert auch ein Konfigurations-Snippet, das in die VyOS CLI kopiert werden kann. Der <name>, den Sie angeben, wird als Peer-Name im Snippet verwendet.

Sie müssen auch die IP-Adresse oder FQDN des Servers angeben, mit dem der Client verbunden wird. Der Parameter Adresse kann zweimal verwendet werden, um sowohl eine IPv4 (/32) als auch eine IPv6 (/128) Adresse dem Client zuzuweisen.
