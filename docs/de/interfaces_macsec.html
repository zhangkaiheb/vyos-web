MACsec

MACsec ist ein IEEE-Standard (IEEE 802.1AE) für MAC-Sicherheit, der im Jahr 2006 eingeführt wurde. Er ermöglicht die protokollunabhängige Verbindung zwischen zwei Hosts und bietet Datenvertraulichkeit, Authentizität und Integrität mit GCM-AES-Chiffren. MACsec arbeitet auf der Ethernet-Ebene als Layer-2-Protokoll und schützt den Datenverkehr innerhalb Layer-2-Netzwerke, einschließlich DHCP- und ARP-Anfragen. Es konkurriert nicht mit anderen Sicherheitslösungen wie IPsec (Layer 3) oder TLS (Layer 4), da jedes unterschiedliche Anwendungsfälle abdeckt.

Konfiguration

Gemeinsame Schnittstellenkonfiguration

set interfaces macsec <interface> address <address | dhcp | dhcpv6>

Konfigurieren Sie die Schnittstelle mit einer oder mehreren IP-Adressen.

Die folgenden Optionen sind verfügbar:

  • address: Weisen Sie der Schnittstelle eine oder mehrere IPv4- oder IPv6-Adressen zu. Zum Beispiel verwenden Sie 192.0.2.1/24 für IPv4 oder 2001:db8::1/64 für IPv6.

  • dhcp: Die Schnittstelle erhält eine IPv4-Adresse von einem DHCP-Server im gleichen Netzwerksegment.

  • dhcpv6: Die Schnittstelle erhält eine IPv6-Adresse von einem DHCPv6-Server im gleichen Netzwerksegment.

Hinweis

Wenn die Schnittstelle eine IPv4-Adresse über DHCP erhält und spezifische Anpassungen vor oder nach dem Erhalt der IP-Adresse erforderlich sind, verwenden Sie die bereitgestellten Skripte:

  • /config/scripts/dhcp-client/pre-hooks.d/

  • /config/scripts/dhcp-client/post-hooks.d/

Beispiel:

set interfaces macsec macsec0 address 192.0.2.1/24
set interfaces macsec macsec0 address 2001:db8::1/64
set interfaces macsec macsec0 address dhcp
set interfaces macsec macsec0 address dhcpv6
set interfaces macsec <interface> description <description>

Konfigurieren Sie eine klare, beschreibende Alias für die Schnittstelle.

Dieser Alias erscheint im Befehl show interfaces und in SNMP-basierten Überwachungstools.

Beispiel:

set interfaces macsec macsec0 description 'This is an interface running on VyOS.'
set interfaces macsec <interface> disable

Schalten Sie die Schnittstelle aus.

Die Schnittstelle wird auf den administrativ heruntergefahrenen (A/D) Zustand gesetzt.

Beispiel:

set interfaces macsec macsec0 disable
set interfaces macsec <interface> disable-flow-control

Deaktivieren Sie die Ethernet-Flusssteuerung (IEEE 802.3x Pause Frames) auf der Schnittstelle.

Ethernet-Flusssteuerung, definiert durch den IEEE 802.3x-Standard, unterbricht temporär die Datenübertragung, um Paketverluste während Netzwerkengpässe zu vermeiden. Zum Beispiel, wenn ein Sender Daten schneller überträgt, als der Empfänger verarbeiten kann.

Das Deaktivieren der Ethernet-Flusssteuerung bedeutet, dass die Schnittstelle nicht signalisiert, dass das verbundene Gerät die Übertragung anhalten soll, und verwirft Pakete, falls überlastet.

Beispiel:

set interfaces macsec macsec0 disable-flow-control
set interfaces macsec <interface> disable-link-detect

Deaktivieren Sie die physische Link-State-Änderungserkennung auf der Schnittstelle, z.B. wenn ein Kabel entfernt wird.

Standardmäßig erkennt die Schnittstelle physische Link-State-Änderungen.

Beispiel:

set interfaces macsec macsec0 disable-link-detect
set interfaces macsec <interface> mac <xx:xx:xx:xx:xx:xx>

Konfigurieren Sie eine benutzerdefinierte MAC-Adresse auf der Schnittstelle.

Beispiel:

set interfaces macsec macsec0 mac '00:53:01:02:03:04'
set interfaces macsec <interface> mtu <mtu>

Konfigurieren Sie den MTU auf der Schnittstelle.

Dieser Wert definiert die größte Paketgröße in Bytes, die die Schnittstelle ohne Fragmentierung überträgt.

Beispiel:

set interfaces macsec macsec0 mtu 1600
set interfaces macsec <interface> ip adjust-mss <mss | clamp-mss-to-pmtu>

Konfigurieren Sie die MSS im ausgehenden TCP SYN-Paketen auf der angegebenen Schnittstelle.

Durch das Erschweren des MSS-Werts in TCP SYN-Paketen informieren Sie explizit den fernen Teil, nicht größer als diese Größe zu senden. Dies verhindert Verbindungsprobleme, die auftreten, wenn die Pfad-MTU-Entdeckung (PMTUD) fehlschlägt.

Die folgenden Optionen sind verfügbar:

  • mss: Legt die MSS auf einen bestimmten Wert in Bytes fest. Nutzen Sie diese Option, wenn Sie eine spezifische MSS erzwingen müssen, z.B. zur Behebung von Verbindungsproblemen oder zur Anpassung an spezifische Netzwerkanforderungen.

  • clamp-mss-to-pmtu: Der Router berechnet die MSS automatisch als die MTU der Schnittstelle minus 40 Bytes für IPv4-Datenverkehr (20 Bytes für die IPv4-Header und 20 Bytes für den TCP-Header). Diese Option wird empfohlen, um den richtigen Wert automatisch einzustellen.

set interfaces macsec <interface> ip arp-cache-timeout

Konfigurieren Sie, wie lange ein ARP-Eintrag gültig bleibt, nachdem eine IP-zu-MAC-Adresse-Zuordnung auf dieser Schnittstelle gelernt wurde.

Der Standardzeitraum beträgt 30 Sekunden.

Ein ARP-Eintrag bleibt gültig, wenn er positive Rückmeldungen von höheren Protokollen erhält.

Beispiel:

set interfaces macsec macsec0 ip arp-cache-timeout 180
set interfaces macsec <interface> ip disable-arp-filter

Konfigurieren Sie die ARP-Filterung auf dieser Schnittstelle.

Standardverhalten: Das Kernel antwortet auf ARP-Anfragen auf dieser Schnittstelle nur, wenn der Datenverkehr zurück zum ARP-Sender über diese spezifische Schnittstelle geroutet wird.

Wenn konfiguriert: Das Kernel antwortet auf ARP-Anfragen auf dieser Schnittstelle für jede IP-Adresse, die auf dem lokalen Host konfiguriert ist, unabhängig davon, welche spezifische Schnittstelle diese IP-Adresse zugewiesen ist, und unabhängig vom Routing-Tabellen. Dies spiegelt das Linux-Konzept wider, dass IP-Adressen dem Host gehören, nicht individuellen Schnittstellen.

Beispiel:

set interfaces macsec macsec0 ip disable-arp-filter
set interfaces macsec <interface> ip disable-forwarding

Konfigurieren Sie das Verhalten der Schnittstelle als Host oder Router.

Wenn konfiguriert, wechselt die Schnittstelle in Hostmodus und wird IPv4-Weiterleitung deaktiviert.

Beispiel:

set interfaces macsec macsec0 ip disable-forwarding
set interfaces macsec <interface> ip enable-directed-broadcast

Konfigurieren Sie, ob IP-gerichtete Broadcast-Pakete, die auf dieser Schnittstelle empfangen werden, weitergeleitet werden.

Standardverhalten: IP-gerichtete Broadcast-Pakete werden abgelehnt.

Wenn konfiguriert: IP-gerichtete Broadcast-Pakete werden an alle Hosts auf dem Ziel-Subnetz weitergeleitet, wie in RFC 1812 und RFC 2644 definiert.

Beispiel:

set interfaces macsec macsec0 ip enable-directed-broadcast
set interfaces macsec <interface> ip enable-arp-accept

Konfigurieren Sie, wie gratis ARPs auf dieser Schnittstelle verarbeitet werden.

Wenn konfiguriert, wird eine IP-zu-MAC-Adresse-Zuordnung in die ARP-Tabelle basierend auf gratis ARP-Anfragen oder Antworten hinzugefügt.

Hinweis

Wenn die ARP-Tabelle bereits die IP-Adresse aus einem gratis ARP enthält, wird der Eintrag aktualisiert, unabhängig davon, ob diese Einstellung konfiguriert ist.

Beispiel:

set interfaces macsec macsec0 ip enable-arp-accept
set interfaces macsec <interface> ip enable-arp-announce

Konfigurieren Sie die Quell-IP-Auswahl für ARP-Anfragen auf dieser Schnittstelle.

Standardverhalten: Das Kernel kann jede IP-Adresse, die der Host besitzt, als Quell-IP-Adresse in ARP-Anfragen auf dieser Schnittstelle verwenden.

Wenn konfiguriert: Das Kernel versucht zunächst, eine Quell-IP-Adresse auszuwählen, die auf der Schnittstelle konfiguriert ist und mit dem Ziel-IP-Adress-Subnetz übereinstimmt. Wenn kein solches Subnetz vorhanden ist, wählt das Kernel die IP-Adresse aus, die es normalerweise verwendet (basierend auf der Routing-Tabelle, um das Zielziel zu erreichen).

Beispiel:

set interfaces macsec macsec0 ip enable-arp-announce
set interfaces macsec <interface> ip enable-arp-ignore

Konfigurieren Sie, welche ARP-Anfragen auf dieser Schnittstelle ignoriert werden.

Standardverhalten: Das Kernel antwortet auf ARP-Anfragen für beliebige lokale IP-Adressen, unabhängig davon, welcher Schnittstelle sie zugewiesen sind.

Wenn konfiguriert: Das Kernel antwortet nur auf ARP-Anfragen, wenn die Ziel-IP-Adresse auf dieser spezifischen Schnittstelle zugewiesen ist.

Beispiel:

set interfaces macsec macsec0 ip enable-arp-ignore
set interfaces macsec <interface> ip enable-proxy-arp

Konfigurieren Sie Proxy ARP auf dieser Schnittstelle.

Wenn konfiguriert, empfängt der Router (Kernel) ARP-Anfragen für nicht lokale IP-Adressen und antwortet mit der MAC-Adresse der Schnittstelle, die die Anfrage empfangen hat. Danach werden Pakete, die an diese IP-Adressen gerichtet sind, an ihre tatsächlichen Ziele auf entfernten Subnetzen weitergeleitet.

Beispiel:

set interfaces macsec macsec0 ip enable-proxy-arp
set interfaces macsec <interface> ip proxy-arp-pvlan

Konfigurieren Sie lokale Proxy ARP auf der Schnittstelle.

Wenn konfiguriert, antwortet der Router (Kernel) auf ARP-Anfragen auf dieser VLAN-Schnittstelle, auch wenn die Ziel-IP-Adresse auf dem gleichen Subnetz und der Schnittstelle liegt.

Dies wird verwendet, um Netzwerkisolationsanforderungen (RFC 3069) für private VLANs (PVLANs) zu unterstützen. In PVLAN-Konfigurationen können Hosts auf isolierten Ports nicht direkt miteinander kommunizieren, aber sie können mit dem Upstream-Router kommunizieren.

Durch die Antwort auf inter-Host-ARP-Anfragen mit seiner eigenen MAC-Adresse leitet der Router den inter-Host-Datenverkehr durch sich selbst statt direkt zwischen Hosts.

Hinweis

Dieser Befehl funktioniert unabhängig und erfordert nicht, dass der Standard-Proxy ARP auf der Schnittstelle aktiviert ist.

Lokaler Proxy ARP ist auch bekannt als:

  • VLAN Aggregation (RFC 3069).

  • Private VLAN (Cisco, Allied Telesyn).

  • Source-port filtering oder Port-Isolation (Hewlett-Packard).

  • MAC-Forced Forwarding (Ericsson).

set interfaces macsec <interface> ip source-validation <strict | loose | disable>

Konfigurieren Sie die Quell-IP-Adressen-Validierung mit RPF auf dieser Schnittstelle, wie in RFC 3704 beschrieben.

Die folgenden Optionen sind verfügbar:

  • strict: Jedes eingehende Paket wird auf seine Quell-IP-Adresse gegen den Forwarding Information Base (FIB) geprüft. Wenn die Schnittstelle nicht die beste Route für diesen Quellort ist, schlägt die Validierung fehl und das Paket wird gelöscht.

  • loose: Jedes eingehende Paket wird auf seine Quell-IP-Adresse gegen den FIB geprüft. Wenn die Quell-IP-Adresse über keine Schnittstelle erreichbar ist, schlägt die Validierung fehl.

  • disable: Keine Quell-IP-Adressen-Validierung wird durchgeführt. Alle eingehenden Pakete werden akzeptiert.

RFC 3704 empfiehlt, den strengen Modus zu aktivieren, um IP-Spoofing, wie DDoS-Angriffe, zu verhindern. Für asynchrone oder andere komplexe Routing-Szenarien verwenden Sie den lockeren Modus.

set interfaces macsec <interface> ipv6 address autoconf

Konfigurieren Sie die Schnittstelle, um eine IPv6-Adresse automatisch mit SLAAC, zu erhalten, wie in RFC 4862 beschrieben.

IPv6-Hosts können sich automatisch konfigurieren, wenn sie sich einem IPv6-Netzwerk anschließen, indem sie den Neighbor Discovery Protocol über ICMPv6 Router Discovery Nachrichten verwenden. Bei erstmaliger Verbindung zu einem Netzwerk sendet ein Host eine link-local Router Solicitation Multicast Anfrage für seine Konfigurationsparameter. Der Router antwortet mit einer Router Advertisement Packet, das Internet Layer Konfigurationsparameter enthält.

Hinweis

Diese Methode deaktiviert automatisch die IPv6-Verkehr Weiterleitung auf der Schnittstelle.

Beispiel:

set interfaces macsec macsec0 ipv6 address autoconf
set interfaces macsec <interface> ipv6 address eui64 <prefix>

Konfigurieren Sie die Schnittstelle, um eine IPv6-Adresse mit dem EUI-64 Verfahren zu vergeben, wie in RFC 4291 beschrieben.

Beispiel:

set interfaces macsec macsec0 ipv6 address eui64 2001:db8:beef::/64
set interfaces macsec <interface> ipv6 address no-default-link-local

Deaktivieren Sie die automatische Zuweisung einer link-local IPv6-Adresse zu dieser Schnittstelle.

Beispiel:

set interfaces macsec macsec0 ipv6 address no-default-link-local
set interfaces macsec <interface> ipv6 disable-forwarding

Konfigurieren Sie das Verhalten der Schnittstelle als Host oder Router.

Wenn konfiguriert, wechselt die Schnittstelle in Hostmodus und wird IPv6-Weiterleitung deaktiviert.

Beispiel:

set interfaces macsec macsec0 ipv6 disable-forwarding
set interfaces macsec <interface> ipv6 adjust-mss <mss | clamp-mss-to-pmtu>

Konfigurieren Sie die MSS im ausgehenden TCP SYN-Paketen auf der angegebenen Schnittstelle.

Durch das Erschweren des MSS-Werts in TCP SYN-Paketen informieren Sie explizit den fernen Teil, nicht größer als diese Größe zu senden. Dies verhindert Verbindungsprobleme, die auftreten, wenn die Pfad-MTU-Entdeckung (PMTUD) fehlschlägt.

Die folgenden Optionen sind verfügbar:

  • mss: Legt die MSS auf einen bestimmten Wert in Bytes fest. Nutzen Sie diese Option, wenn Sie eine spezifische MSS erzwingen müssen, z.B. zur Behebung von Verbindungsproblemen oder zur Anpassung an spezifische Netzwerkanforderungen.

  • clamp-mss-to-pmtu: Der Router berechnet die MSS automatisch als die MTU der Schnittstelle minus 60 Bytes für IPv6-Datenverkehr (40 Bytes für den IPv6-Header und 20 Bytes für den TCP-Header). Diese Option wird empfohlen, um den richtigen Wert automatisch einzustellen.

set interfaces macsec <interface> ipv6 accept-dad <0 | 1 | 2>

Konfigurieren Sie IPv6 DAD auf der Schnittstelle.

Die folgenden Optionen sind verfügbar:

  • 0: Deaktiviert DAD. Es wird keine Duplikatadresse erkannt.

  • 1: Aktiviert DAD (Standard). Duplikatadressen werden erkannt. Die Schnittstelle läuft weiter für gültige IPv6-Adressen.

  • 2: Aktiviert DAD und, falls eine MAC-basierte duplizierte link-local Adresse gefunden wird, deaktiviert IPv6-Betrieb auf dieser Schnittstelle.

Beispiel:

set interfaces macsec macsec0 ipv6 accept-dad 2
set interfaces macsec <interface> ipv6 dup-addr-detect-transmits <n>

Konfigurieren Sie die Anzahl der DAD Nachrichten, die der Router (Kernel) während der IPv6-Adresszuweisung auf dieser Schnittstelle sendet.

Der Standardwert ist 1.

Beispiel:

set interfaces macsec macsec0 ipv6 dup-addr-detect-transmits 5
set interfaces macsec <interface> vrf <vrf>

Weisen Sie die Schnittstelle einer spezifischen VRF Instanz zu.

Siehe auch

Für Informationen zur Konfiguration einer VRF, siehe den Abschnitt VRF.

Beispiel:

set interfaces macsec macsec0 vrf red

DHCP(v6)

set interfaces macsec <interface> dhcp-options client-id <description>

Konfigurieren Sie einen DHCP-Clientschlüssel für die Schnittstelle, wie in RFC 2131 beschrieben.

Der client-id ist ein Identifikator, den der DHCP-Client an den DHCP-Server sendet, um sich eindeutig für die IP-Adresszuweisung zu identifizieren. Standardmäßig verwendet der Client seine MAC-Adresse. Der <description> ist eine vom Benutzer definierte Zeichenkette, die an den DHCP-Server als DHCP-Clientschlüssel gesendet wird.

Beispiel:

set interfaces macsec macsec0 dhcp-options client-id 'foo-bar'
set interfaces macsec <interface> dhcp-options host-name <hostname>

Konfigurieren Sie einen spezifischen Hostnamen für die Schnittstelle.

Statt des echten Hostnamens sendet der DHCP-Client den spezifischen Hostnamen an den DHCP-Server, wenn eine IP-Adresse angefordert wird.

Beispiel:

set interfaces macsec macsec0 dhcp-options host-name 'VyOS'
set interfaces macsec <interface> dhcp-options vendor-class-id <vendor-id>

Konfigurieren Sie den DHCP-Client, um einen Vendor-Class-Identifier in seinen DHCP-Anfragen auf dieser Schnittstelle einzuschließen.

Der Vendor-Class-Identifier ist ein herstellerspezifischer Byte-String, der es dem DHCP-Server ermöglicht, das Gerät zu identifizieren und in einigen Fällen Konfigurationsoptionen bereitzustellen.

Beispiel:

set interfaces macsec macsec0 dhcp-options vendor-class-id 'VyOS'
set interfaces macsec <interface> dhcp-options no-default-route

Konfigurieren Sie den DHCP-Client, eine IP-Adresse zu erhalten, aber jegliche Standardroute, die vom DHCP-Server auf dieser Schnittstelle bereitgestellt wird, zu ignorieren.

Beispiel:

set interfaces macsec macsec0 dhcp-options no-default-route
set interfaces macsec <interface> dhcp-options default-route-distance <distance>

Konfigurieren Sie die Entfernung für die Standardroute, die vom DHCP-Server auf dieser Schnittstelle erhalten wird.

Beispiel:

set interfaces macsec macsec0 dhcp-options default-route-distance 220
set interfaces macsec <interface> dhcp-options reject <address>

Konfigurieren Sie den DHCP-Client, um die spezifische IP-Adresse oder IP-Adressbereich von dem DHCP-Server auf dieser Schnittstelle abzulehnen.

Dies ist nützlich, wenn ein Modem bei Start eine lokale IP-Adresse zuweist. Um mehrere Adressen abzulehnen, führen Sie diesen Befehl mehrmals mit unterschiedlichen Werten aus. Sie können einzelne Adressen (192.168.100.1) oder ganze Subnetze (192.168.100.0/24) ablehnen.

Beispiel:

set interfaces macsec macsec0 dhcp-options reject 192.168.100.0/24
set interfaces macsec <interface> dhcp-options user-class <string>

Konfigurieren Sie den DHCP-Client, um einen spezifischen User-Class-Identifier in seinen DHCP-Anfragen auf dieser Schnittstelle zu senden.

Der DHCP-Server kann diesen Identifier interpretieren und basierend darauf spezifische Konfigurationsoptionen bereitstellen (z.B. Standardrouten). Der User-Class-Wert gruppiert typischerweise DHCP-Clients mit ähnlichen Konfigurationsbedürfnissen (z.B. Mitarbeiter, Gäste oder Drucker).

Beispiel:

set interfaces macsec macsec0 dhcp-options user-class VyOS
set interfaces macsec <interface> dhcpv6-options duid <duid>

Konfigurieren Sie eine spezifische DUID für den DHCPv6-Client auf dieser Schnittstelle.

Die DUID ist ein Identifikator, der von einem DHCPv6-Client verwendet wird, um eine IPv6-Adresse von einem DHCPv6-Server zu erhalten. Sie besteht aus einem 2-byte-Typfeld, gefolgt von einem variablen Länge-Identifikator bis zu 128 bytes. Das Format des Identifikator-Teils hängt vom DUID-Typ ab:

  • DUID-LLT: Der häufigste Typ, der eine Hardwareart, einen Zeitstempel und eine MAC-Adresse enthält.

  • DUID-EN: Basierend auf einer Unternehmensnummer des Herstellers und einem eindeutigen Identifikator, der vom Hersteller zugewiesen wird.

  • DUID-LL: Enthält nur eine MAC-Adresse.

Der DHCP-Server vergleicht die DUID mit seinem Datenbank und liefert Konfigurationsdaten (z.B. Adresse, Leihzeit, DNS-Server usw.) an den DHCP-Client.

Beispiel:

set interfaces macsec macsec0 duid '0e:00:00:01:00:01:27:71:db:f0:00:50:56:bf:c5:6d'
set interfaces macsec <interface> dhcpv6-options no-release

Konfigurieren Sie den DHCP-Client, dass er keine Release-Nachricht sendet, wenn er auf dieser Schnittstelle stoppt.

Dies hilft, die zugewiesene Adresse oder Präfix zu behalten.

Beispiel:

set interfaces macsec macsec0 dhcpv6-options no-release
set interfaces macsec <interface> dhcpv6-options parameters-only

Enable a stateless DHCPv6 client mode on this interface.

In stateless mode, the DHCPv6 client requests only stateless configuration parameters from the DHCP server (for example, DNS server addresses). It doesn’t request a stateful configuration, such as IPv6 addresses or prefixes.

Example:

set interfaces macsec macsec0 dhcpv6-options parameters-only
set interfaces macsec <interface> dhcpv6-options rapid-commit

Enable DHCPv6 rapid commit on this interface.

When enabled, the DHCP client and server skip the negotiation steps (Advertise and Request), completing the DHCPv6 configuration process in just two messages (Solicit and final Reply).

Example:

set interfaces macsec macsec0 dhcpv6-options rapid-commit
set interfaces macsec <interface> dhcpv6-options temporary

Konfigurieren Sie den DHCPv6-Client, um eine temporäre IPv6-Adresse auf dieser Schnittstelle zu beantragen.

Wenn konfiguriert, bildet der DHCP-Client keine Identity Association for Non-temporary Addresses (IA_NA) Partnerschaft. Folglich erhält er nur eine temporäre IPv6-Adresse und keine permanente.

Beispiel:

set interfaces macsec macsec0 dhcpv6-options temporary

DHCPv6 Prefix Delegation (PD)

VyOS unterstützt DHCPv6 Prefix Delegation (DHCPv6-PD) gemäß RFC 3633. DHCPv6-PD wird von den meisten ISPs unterstützt, die native IPv6 für Verbraucher auf festen Netzwerken bieten.

set interfaces macsec <interface> dhcpv6-options pd <id> length <length>

Konfigurieren Sie eine spezifische Präfixlänge für DHCPv6-PD-Anfragen auf dieser Schnittstelle.

Einige ISPs stellen standardmäßig nur ein /64-Präfix bereit. Verwenden Sie diesen Befehl, um eine andere Präfixlänge für eine spezifische DHCPv6-PD-Anfrage anzufordern, wobei der Bereich von /32 (falls von Ihrem ISP erlaubt) bis /64 reicht. <id> ist ein einzigartiger Bezeichner für die DHCPv6-PD-Anfrage.

Der Standardwert ist 64.

Um ein /56-Präfix von Ihrem ISP anzufordern, verwenden Sie:

set interfaces macsec macsec0 dhcpv6-options pd 0 length 56
set interfaces macsec <interface> dhcpv6-options pd <id> interface <delegatee> address <address>

Konfigurieren Sie den IPv6-Interface-Identifier (Host-Anteil) für die delegatee Schnittstelle.

Der Wert muss eine Dezimalzahl sein. Er wird dem delegierten Präfix und dem konfigurierten SLA ID angehängt, um die Endgültige IPv6-Adresse zu bilden.

Standardmäßig wird der Host-Anteil basierend auf der MAC-Adresse der Elternschnittstelle (EUI-64-Format) generiert.

Beispiel:

Wenn ein /64-Präfix an die Schnittstelle eth8 delegiert wird und Sie den Host-Anteil als 65535 konfigurieren, wird die resultierende IPv6-Adresse mit ::ffff enden, da 65535 hexadezimal ffff entspricht.

set interfaces macsec macsec0 dhcpv6-options pd 0 interface eth8 address 65534
set interfaces macsec <interface> dhcpv6-options pd <id> interface <delegatee> sla-id <id>

Konfigurieren Sie die SLA ID für die Delegatee-Schnittstelle.

Der Wert muss eine Dezimalzahl > 0 sein und in die Länge der SLA IDs passen. Er wird in Hexadezimal umgewandelt und an das delegierte Präfix angehängt, um das spezifische Subnetzpräfix für die Delegatee-Schnittstelle zu bilden.

Beispiel:

Wenn SLA ID 1 ist und das delegierte Präfix 2001:db8:ffff::/48 ist, wird das resultierende Subnetzpräfix für die Delegatee-Schnittstelle 2001:db8:ffff:1::/64 sein.

set interfaces macsec macsec0 dhcpv6-options pd 0 interface eth8 sla-id 1

MACsec-Optionen

set interfaces macsec <interface> security cipher <gcm-aes-128|gcm-aes-256>

Konfigurieren Sie den Cipher-Suite für die MACsec-Schnittstelle.

Dieser Konfigurationsparameter ist obligatorisch.

set interfaces macsec <interface> security encrypt

Enable encryption on the MACsec interface.

Standardmäßig bietet MACsec nur Authentifizierung; Verschlüsselung ist optional. Wenn aktiviert, werden ausgehende Pakete mit der konfigurierten Cipher-Suite verschlüsselt.
