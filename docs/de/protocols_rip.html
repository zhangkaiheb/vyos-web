RIP

Im 1970er Jahren bei Xerox Labs entwickelt, ist RIP ein Distanzvektor-Routingprotokoll, das auf dem Bellman-Ford-Algorithmus basiert.

RIP bestimmt den besten Weg anhand der Anzahl der Hop (Anzahl der durchquerten Router). RIP-fähige Router geben periodisch ihre gesamte Routing-Tabelle mit dem Metrik (Hop-Zahl) für jedes Ziel an Nachbarn weiter.

Unterstützte Versionen:

  • RIPv1: Wie in RFC 1058 beschrieben

  • RIPv2: Wie in RFC 2453 beschrieben

Allgemeine Konfiguration

set protocols rip network <A.B.C.D/M>

RIP auf allen Schnittstellen aktivieren, deren IP-Adressen im angegebenen Netzwerk liegen.

Beispiel:

set protocols rip network 192.0.2.0/24
set protocols rip interface <interface>

RIP auf der angegebenen Schnittstelle aktivieren.

Wenn angewandt, sendet die Schnittstelle und empfängt RIP-Pakete.

Beispiel:

set protocols rip interface eth0
set protocols rip neighbor <A.B.C.D>

Einen RIP-Nachbarn mit seiner IP-Adresse konfigurieren.

Verwenden Sie diesen Befehl, wenn ein Nachbar keine Multicast-RIP-Updates verarbeiten kann. Sobald konfiguriert, sendet der lokale Router Updates direkt an den angegebenen Nachbarn als Unicast-Pakete.

Beispiel:

set protocols rip neighbor 192.0.2.2
set protocols rip passive-interface <interface>

Passiven Modus für die angegebene Schnittstelle aktivieren.

Dies verhindert, dass der Router ausgehende RIP-Updates auf der Schnittstelle sendet, außer an explizit konfigurierte Nachbarn. Eingehende RIP-Updates werden immer noch akzeptiert und verarbeitet.

Beispiel:

set protocols rip passive-interface eth0
set protocols rip passive-interface default

Passiven Modus für alle Schnittstellen aktivieren.

Dies verhindert, dass der Router ausgehende RIP-Updates auf allen Schnittstellen sendet, außer an explizit konfigurierte Nachbarn. Der Router empfängt und verarbeitet eingehende RIP-Updates normal weiter.

Beispiel:

set protocols rip passive-interface default

Optionale Konfiguration

set protocols rip default-distance <1-255>

Administrative Distanz für alle RIP-gelernten Routen konfigurieren.

Die administrative Distanz bestimmt, wie RIP-gelernte Routen gegenüber Routen, die aus anderen Quellen (wie BGP, OSPF oder statischen Routen) gelernt wurden, priorisiert werden, wenn mehrere Wege zu demselben Ziel existieren.

Hinweis

Routen mit einer Distanz von 255 sind deaktiviert und werden nicht in die Kernel-Weiterschaltungstabelle installiert.

Beispiel:

set protocols rip default-distance 100
set protocols rip network-distance <A.B.C.D/M> distance <1-255>

Administrative Distanz für RIP-Routen konfigurieren, deren Quell-IP-Adresse im angegebenen Netzwerk liegt.

Beispiel:

set protocols rip network-distance 192.0.2.0/24 distance 80
set protocols rip network-distance <A.B.C.D/M> access-list <name>

Administrative Distanzzuweisungen auf RIP-Routen beschränken, deren Quell-IP-Adresse mit dem angegebenen Netzwerk übereinstimmt und die Route selbst mit dem angegebenen Zugriffslisten übereinstimmt.

Beispiel:

set protocols rip network-distance 192.0.2.0/24 distance 80
set protocols rip network-distance 192.0.2.0/24 access-list 10
set protocols rip default-information originate

Erzeugen und Werben eines Standardweges (0.0.0.0/0) an alle RIP-Nachbarn.

Beispiel:

set protocols rip default-information originate
set protocols rip distribute-list access-list <in|out> <0-4294967295>

Eine Zugriffsliste anwenden, um RIP-Routen in Richtung ein- oder ausgehend zu filtern.

  • in: Filtert Routen, die von RIP-Nachbarn empfangen werden.

  • out: Filtert Routen, die an RIP-Nachbarn weitergegeben werden.

Beispiel:

set protocols rip distribute-list access-list in 20
set protocols rip distribute-list interface <interface> access-list <in|out> <0-4294967295>

Eine Zugriffsliste anwenden, um RIP-Routen in Richtung ein- oder ausgehend auf der angegebenen Schnittstelle zu filtern.

  • in: Filtert Routen, die von RIP-Nachbarn auf dieser Schnittstelle empfangen werden.

  • out: Filtert Routen, die an RIP-Nachbarn auf dieser Schnittstelle weitergegeben werden.

Beispiel:

set protocols rip distribute-list interface eth0 access-list in 20
set protocols rip distribute-list prefix-list <in|out> <name>

Eine Präfixliste anwenden, um RIP-Routen in Richtung ein- oder ausgehend zu filtern.

  • in: Filtert Routen, die von RIP-Nachbarn empfangen werden.

  • out: Filtert Routen, die an RIP-Nachbarn weitergegeben werden.

Beispiel:

set protocols rip distribute-list prefix-list in INBOUND-FILTER
set protocols rip distribute-list interface <interface> prefix-list <in|out> <name>

Eine Präfixliste anwenden, um RIP-Routen auf der angegebenen Schnittstelle in Richtung ein- oder ausgehend zu filtern.

  • in: Filtert Routen, die von RIP-Nachbarn auf dieser Schnittstelle empfangen werden.

  • out: Filtert Routen, die an RIP-Nachbarn auf dieser Schnittstelle weitergegeben werden.

Beispiel:

set protocols rip distribute-list interface eth0 prefix-list in RIP-IN
set protocols rip route <A.B.C.D/M>

Einen statischen Weg zum RIP-Weiterschaltprozess hinzufügen.

Der Weg wird nur innerhalb von RIP erstellt.

Dieser Befehl ist spezifisch für FRR und VyOS und sollte nur von fortgeschrittenen Benutzern mit starkem Verständnis des RIP-Protokolls verwendet werden.

Für die meisten Bereitstellungen ist der empfohlene Ansatz, einen standardmäßigen statischen Weg zu erstellen und ihn über set protocols rip redistribute static in RIP zu verteilen.

Beispiel:

set protocols rip route 192.0.2.0/24
set protocols rip timers update <5-2147483647>

Den RIP-Update-Timer in Sekunden konfigurieren.

Der Update-Timer definiert, wie oft der Router unangeforderte Antwortmeldungen an seine RIP-Nachbarn sendet. Jede Antwort enthält die vollständige RIP-Weiterschaltungstabelle.

Der Standardwert beträgt 30 Sekunden.

Beispiel:

set protocols rip timers update 60
set protocols rip timers timeout <5-2147483647>

Den RIP-Routen-Timeout in Sekunden konfigurieren.

Wenn eine Route innerhalb dieses Intervalls nicht durch eine eingehende Aktualisierung aktualisiert wird, wird sie ungültig. Der Router behält die ungültige Route vorübergehend in der RIP-Weiterschaltungstabelle, damit die Nachbarn lernen, dass der Weg entfernt wurde.

Der Standardwert beträgt 180 Sekunden.

Beispiel:

set protocols rip timers timeout 300
set protocols rip timers garbage-collection <5-2147483647>

Den RIP-Garbage-Collection-Timer in Sekunden konfigurieren.

Dieser Timer startet, wenn eine Route ungültig wird. Wenn der Timer abläuft, wird die Route aus der Weiterschaltungstabelle entfernt.

Der Standardwert beträgt 120 Sekunden.

Beispiel:

set protocols rip timers garbage-collection 60

Redistribution-Konfiguration

set protocols rip redistribute <babel|bgp|connected|isis|kernel|nhrp|ospf|static>

Routen aus der angegebenen Quelle in RIP umleiten.

Routen, die aus der gewählten Quelle gelernt wurden, werden in die RIP-Weiterschaltungstabelle importiert und an RIP-Nachbarn weitergegeben, als wären sie durch RIP selbst gelernt worden.

Die unterstützten Quellen sind:

  • babel: Routen, die über Babel gelernt wurden.

  • bgp: Routen, die über BGP gelernt wurden.

  • connected: Direkt verbundene Routen.

  • isis: Routen, die über IS-IS gelernt wurden.

  • kernel: Routen, die in die Kernel-Weiterschaltungstabelle installiert wurden.

  • nhrp: Routen, die über NHRP gelernt wurden.

  • ospf: Routen, die über OSPF gelernt wurden.

  • static: Statistisch konfigurierte Routen.

Beispiel:

set protocols rip redistribute static
set protocols rip redistribute <babel|bgp|connected|isis|kernel|nhrp|ospf|static> metric <1-16>

Das Metrik für Routen konfigurieren, die aus der angegebenen Quelle umgeleitet werden.

Beispiel:

set protocols rip redistribute static metric 5
set protocols rip redistribute <babel|bgp|connected|isis|kernel|nhrp|ospf|static> route-map <name>

Eine Route-Map anwenden, um Routen zu filtern, die aus der angegebenen Quelle umgeleitet werden.

Beispiel:

set protocols rip redistribute static route-map RIP-REDISTRIBUTE
set protocols rip default-metric <1-16>

Das Standardmetrik (Hop-Zahl) für umgeleitete Routen konfigurieren.

Der Standardwert ist 1.

Hinweis

Dieser Befehl wirkt sich nicht auf direkt verbundene Routen aus, die über set protocols rip redistribute connected umgeleitet werden. Um das Metrik für direkt verbundene Routen zu konfigurieren, verwenden Sie set protocols rip redistribute connected metric explizit.

Beispiel:

set protocols rip default-metric 5

Schnittstellen-Konfiguration

set protocols rip interface <interface> authentication plaintext-password <text>

Einfache Passwort-Authentifizierung für RIPv2 auf der angegebenen Schnittstelle aktivieren und ein Passwort festlegen.

Das Passwort darf nicht länger als 16 Zeichen sein.

Beispiel:

set protocols rip interface eth0 authentication plaintext-password vyos-secret
set protocols rip interface <interface> authentication md5 <id> password <text>

MD5-Authentifizierung für RIPv2 auf der angegebenen Schnittstelle aktivieren und den MD5-Schlüssel festlegen.

Der MD5-Schlüssel darf nicht länger als 16 Zeichen sein.

Beispiel:

set protocols rip interface eth0 authentication md5 1 password vyos-secret
set protocols rip interface <interface> split-horizon disable

Split-Horizon auf der angegebenen Schnittstelle deaktivieren.

Standardmäßig gibt VyOS keine RIP-Routen zurück durch die Schnittstelle, auf der sie gelernt wurden (Split Horizon). Dieser Befehl schaltet dies ab.

Beispiel:

set protocols rip interface eth0 split-horizon disable
set protocols rip interface <interface> split-horizon poison-reverse

Split Horizon mit Poison Reverse auf der angegebenen Schnittstelle aktivieren.

Wenn aktiviert, gibt der Router die gelernten Routen als unerreichbar auf der Schnittstelle, auf der sie gelernt wurden, weiter.

Beispiel:

set protocols rip interface eth0 split-horizon poison-reverse

Beispiel

Das folgende Beispiel zeigt eine grundlegende RIP-Konfiguration zwischen zwei Routern, bei der direkt verbundene Netzwerke in RIP umgeleitet werden.

Knoten 1:

set interfaces ethernet eth0 address '198.51.100.1/24'
set interfaces loopback lo address '192.0.2.1/32'
set protocols rip network 198.51.100.0/24
set protocols rip redistribute connected

Knoten 2:

set interfaces ethernet eth0 address '198.51.100.2/24'
set interfaces loopback lo address '192.0.2.2/32'
set protocols rip network 198.51.100.0/24
set protocols rip redistribute connected
