Hochverfügbarkeit

VRRP (Virtual Router Redundancy Protocol) bietet aktive/backup-Redundanz für Router. Jeder VRRP-Router hat eine physische IP-/IPv6-Adresse und eine virtuelle Adresse. Bei Start wählen die Router den Master aus, und der Router mit der höchsten Priorität wird zum Master und weist die virtuelle Adresse seinem Schnittstellen zu. Alle Router mit niedrigerer Priorität werden Backup-Router. Der Master sendet dann Keepalive-Pakete, um andere Router zu benachrichtigen, dass er verfügbar ist. Wenn der Master fehlschlägt und die Keepalive-Pakete nicht mehr sendet, wird der Router mit der nächsten höchsten Priorität zum neuen Master und übernimmt die virtuelle Adresse.

VRRP-Keepalive-Pakete verwenden Multicast, und VRRP-Einrichtungen sind auf einen einzelnen Datalink-Segment begrenzt. Sie können mehrere VRRP-Gruppen (auch als virtuelle Router bezeichnet) einrichten. Virtuelle Router werden durch eine VRID (Virtual Router IDentifier) identifiziert. Wenn Sie mehrere Gruppen auf derselben Schnittstelle einrichten, müssen ihre VRIDs eindeutig sein, wenn sie das gleiche Adressfamilie verwenden, aber es ist möglich (selbst wenn es nicht empfohlen wird, aus Lesbarkeitsgründen), duplicate VRIDs auf unterschiedlichen Schnittstellen zu verwenden.

Basisinstallation

VRRP-Gruppen werden mit dem Befehl set high-availability vrrp group $GROUP_NAME erstellt. Die erforderlichen Parameter sind Schnittstelle, VRID und Adresse.

Minimale Konfiguration

set high-availability vrrp group Foo vrid 10
set high-availability vrrp group Foo interface eth0
set high-availability vrrp group Foo address 192.0.2.1/24

Sie können den Status Ihrer VRRP-Gruppe mit dem Betriebsmodus-Befehl run show vrrp überprüfen:

vyos@vyos# run show vrrp
Name        Interface      VRID  State    Last Transition
----------  -----------  ------  -------  -----------------
Foo         eth1             10  MASTER   2s

IPv6-Unterstützung

Der address-Parameter kann entweder eine IPv4- oder IPv6-Adresse sein, aber Sie können IPv4 und IPv6 nicht in derselben Gruppe kombinieren und müssen Gruppen mit verschiedenen VRIDs speziell für IPv4 und IPv6 erstellen. Wenn Sie IPv4 + IPv6-Adressen verwenden möchten, können Sie den Parameter excluded-address verwenden

Adresse

Die address kann entweder auf der VRRP-Schnittstelle oder nicht auf der VRRP-Schnittstelle konfiguriert werden.

set high-availability vrrp group Foo address 192.0.2.1/24
set high-availability vrrp group Foo address 203.0.113.22/24 interface eth2
set high-availability vrrp group Foo address 198.51.100.33/24 interface eth3

Deaktivieren einer VRRP-Gruppe

Sie können eine VRRP-Gruppe mit dem disable-Option deaktivieren:

set high-availability vrrp group Foo disable

Eine deaktivierte Gruppe wird aus dem VRRP-Prozess entfernt und Ihr Router nimmt nicht an VRRP für diesen VRID teil. Sie verschwindet aus dem Betriebsmodus-Befehlsergebnis, anstatt den Backup-Zustand zu betreten.

Ausschlussadresse

Ausschluss von IP-Adressen aus VRRP-Paketen. Diese Option excluded-address wird verwendet, wenn Sie IPv4 + IPv6-Adressen auf derselben virtuellen Schnittstelle festlegen möchten oder wenn mehr als 20 IP-Adressen verwendet werden.

set high-availability vrrp group Foo excluded-address '203.0.113.254/24'
set high-availability vrrp group Foo excluded-address '2001:db8:aa::1/64'
set high-availability vrrp group Foo excluded-address '2001:db8:22::1/64'

Einrichtung der VRRP-Gruppenpriorität

Die VRRP-Priorität kann mit der priority-Option eingestellt werden:

set high-availability vrrp group Foo priority 200

Die Priorität muss eine ganze Zahl zwischen 1 und 255 sein. Ein höherer Prioritätswert erhöht die Präzedenz des Routers bei der Wahl des Masters.

Synchronisierungsgruppen

Eine Synchronisierungsgruppe ermöglicht es, VRRP-Gruppen zusammen zu übertragen.

edit high-availability vrrp
set sync-group MAIN member VLAN9
set sync-group MAIN member VLAN20

In folgendem Beispiel wird VLAN9 überschritten, wodurch auch VLAN20 überschritten wird:

vrrp {
    group VLAN9 {
        interface eth0.9
        address 10.9.1.1/24
        priority 200
        vrid 9
    }
    group VLAN20 {
        interface eth0.20
        priority 200
        address 10.20.20.1/24
        vrid 20
    }
    sync-group MAIN {
        member VLAN20
        member VLAN9
    }
}

Warnung

Alle Elemente in einer Synchronisierungsgruppe sollten gleich konfiguriert sein. Wenn eine VRRP-Gruppe eine andere Vorabzeitszeit oder Priorität hat, kann dies zu einem unendlichen Übergangsloop führen.

Präemption

VRRP kann zwei Modi verwenden: präemptiv und nicht-präemptiv. Im präemptiven Modus, wenn ein Router mit höherer Priorität ausfällt und wieder zurückkehrt, geben Router mit niedrigerer Priorität ihren Master-Status ab. Im nicht-präemptiven Modus behält der neu gewählte Master den Master-Status und die virtuelle Adresse für immer.

Standardmäßig verwendet VRRP Präemption. Sie können es mit dem „no-preempt“-Option deaktivieren:

set high-availability vrrp group Foo no-preempt

Sie können auch das Zeitintervall für die Präemption mit der „preempt-delay“-Option konfigurieren. Zum Beispiel, um den Router mit höherer Priorität nach 180 Sekunden zu übernehmen, verwenden Sie:

set high-availability vrrp group Foo preempt-delay 180

Track

Track-Option zur Überwachung von Nicht-VRRP-Schnittstellenzuständen. VRRP ändert den Zustand in FAULT, wenn einer der Track-Schnittstellen im Zustand down ist.

set high-availability vrrp group Foo track interface eth0
set high-availability vrrp group Foo track interface eth1

Ignorieren Sie VRRP-Haupt-Schnittstellenfehler

set high-availability vrrp group Foo track exclude-vrrp-interface

Unicast VRRP

Standardmäßig verwendet VRRP Multicast-Pakete. Wenn Ihr Netzwerk aus irgendeinem Grund kein Multicast unterstützt, können Sie VRRP stattdessen unicast-Kommunikation verwenden.

set high-availability vrrp group Foo peer-address 192.0.2.10
set high-availability vrrp group Foo hello-source-address 192.0.2.15

rfc3768-kompatibilität

RFC 3768 definiert eine virtuelle MAC-Adresse für jeden VRRP-Virtuellen Router. Diese virtuelle Router-MAC-Adresse wird als Quelle in allen periodischen VRRP-Nachrichten verwendet, die vom aktiven Knoten gesendet werden. Wenn die rfc3768-kompatibilitätsoption aktiviert ist, wird eine neue VRRP-Schnittstelle erstellt, der die MAC-Adresse und die virtuelle IP-Adresse automatisch zugewiesen wird.

set high-availability vrrp group Foo rfc3768-compatibility

Überprüfung

$show interfaces ethernet eth0v10
eth0v10@eth0: <BROADCAST,MULTICAST,UP,LOWER_UP> mtu 1500 qdisc noqueue
state UP group default qlen 1000
link/ether 00:00:5e:00:01:0a brd ff:ff:ff:ff:ff:ff
inet 172.25.0.247/16 scope global eth0v10
valid_lft forever preferred_lft forever

Warnung

RFC 3768 erstellt eine virtuelle Schnittstelle. Wenn Sie eine Ziel-NAT-Regel auf den Verkehr anwenden möchten, der an die virtuelle MAC-Adresse geht, setzen Sie die erstellte virtuelle Schnittstelle als inbound-interface.

Globale Optionen

In den meisten Szenarien ist es nicht notwendig, spezifische Parameter zu ändern, und die Standardkonfiguration reicht aus. Aber es gibt Fälle, in denen zusätzliche Konfiguration erforderlich ist.

set high-availability vrrp global-parameters startup_delay <1-600>

Diese Option gibt eine Verzögerung in Sekunden an, bevor die VRRP-Instanzen nach dem Start von keepalived starten.

Gratuitous ARP

Diese Konfiguration ist nicht obligatorisch und in den meisten Fällen ist keine Konfiguration erforderlich. Falls erforderlich, kann Gratuitous ARP in global-parameters und/oder in group-Abschnitt konfiguriert werden.

set high-availability vrrp global-parameters garp interval <0.000-1000>
set high-availability vrrp group <name> garp interval <0.000-1000>

Legt die Verzögerung zwischen kostenlosen ARP-Nachrichten fest, die auf einer Schnittstelle gesendet werden.

0, falls nicht definiert.

set high-availability vrrp global-parameters garp master-delay <1-255>
set high-availability vrrp group <name> garp master-delay <1-255>

Legt die Verzögerung für die zweite Reihe von kostenlosen ARPs nach dem Übergang zum MASTER fest.

5, falls nicht definiert.

set high-availability vrrp global-parameters garp master-refresh <1-600>
set high-availability vrrp group <name> garp master-refresh <1-600>

Legt das minimale Zeitintervall für die Aktualisierung von kostenlosen ARPs fest, während MASTER.

0, falls nicht definiert, was bedeutet, dass keine Aktualisierung stattfindet.

set high-availability vrrp global-parameters garp master-refresh-repeat <1-600>
set high-availability vrrp group <name> garp master-refresh-repeat <1-600>

Legt die Anzahl der kostenlosen ARP-Nachrichten fest, die gleichzeitig während MASTER gesendet werden.

1, falls nicht definiert.

set high-availability vrrp global-parameters garp master-repeat <1-600>
set high-availability vrrp group <name> garp master-repeat <1-600>

Legt die Anzahl der kostenlosen ARP-Nachrichten fest, die gleichzeitig nach dem Übergang zu MASTER gesendet werden.

5, falls nicht definiert.

Version

set high-availability vrrp global-parameters version 2|3

Legt die Standard-VRRP-Version fest. Dies ist standardmäßig 2, aber IPv6-Instanzen verwenden immer Version 3.

Skripte

VRRP-Funktionen können durch Skripte erweitert werden. VyOS unterstützt zwei Arten von Skripten: Gesundheitschecks und Übergangsskripte. Gesundheitscheck-Skripte führen benutzerdefinierte Checks zusätzlich zur Erreichbarkeit des Master-Routers aus. Übergangsskripte werden ausgeführt, wenn sich der VRRP-Zustand von Master zu Backup oder Fehler ändert und können verwendet werden, um bestimmte Dienste zu aktivieren oder zu deaktivieren, z. B.

Hinweis

Das Platzieren von Skriptdateien in /config/scripts/ bedeutet nicht, dass das System sie ausführen kann. Um benutzerdefinierte Skripte ausführbar zu machen, gewähren Sie ihnen Ausführungsrechte. Verwenden Sie den folgenden Befehl:

chmod +x /config/scripts/script-name.sh

Warnung

Es wird nicht empfohlen, VRRP-Konfigurationen innerhalb von Gesundheitscheck- und Übergangsskripten zu ändern.

Gesundheitscheck-Skripte

Es ist möglich, ein beliebiges Skript gemäß den Gesundheitscheck-Parametern in regelmäßigen Abständen auszuführen. Wenn ein Skript 0 zurückgibt, zeigt es Erfolg an. Wenn ein Skript etwas anderes zurückgibt, zeigt es an, dass die VRRP-Instanz in den FAULT-Zustand wechseln soll.

Diese Einrichtung führt das VRRP-Programm aus /config/scripts/vrrp-check.sh script alle 60 Sekunden aus und wechselt die Gruppe in den Fehlerzustand, wenn sie fehlschlägt (dh mit nicht-null-Status verlässt):

set high-availability vrrp group Foo health-check script /config/scripts/vrrp-check.sh
set high-availability vrrp group Foo health-check interval 60
set high-availability vrrp group Foo health-check failure-count 3

Ein optionaler timeout kann festgelegt werden, um die maximale Anzahl Sekunden festzulegen, die das Skript laufen darf. Dies ist nützlich für Skripte, die hängen oder länger dauern als erwartet – das Setzen des Timeouts höher als das Intervall ermöglicht längeren laufenden Skripten, um vor dem Versuch, als fehlgeschlagen betrachtet zu werden, abzuschließen.

set high-availability vrrp group Foo health-check script /config/scripts/vrrp-check.sh
set high-availability vrrp group Foo health-check interval 20
set high-availability vrrp group Foo health-check failure-count 3
set high-availability vrrp group Foo health-check timeout 40

Wenn die VRRP-Gruppe Mitglied der Sync-Gruppe ist, wird nur die Sync-Gruppe Gesundheitscheck-Skript verwenden. Dieses Beispiel zeigt, wie es für die Sync-Gruppe konfiguriert wird:

set high-availability vrrp sync-group Bar health-check script /config/scripts/vrrp-check.sh
set high-availability vrrp sync-group Bar health-check interval 60
set high-availability vrrp sync-group Bar health-check failure-count 3

Übergangsskripte

Übergangsskripte können Ihnen helfen, verschiedene Fixups umzusetzen, wie z. B. Starten und Beenden von Diensten oder sogar Ändern der VyOS-Konfiguration bei VRRP-Übergang. Diese Einrichtung führt das VRRP-Programm aus /config/scripts/vrrp-fail.sh mit Argument Foo aus, wenn VRRP fehlschlägt, und das /config/scripts/vrrp-master.sh , wenn der Router zum Master wird:

set high-availability vrrp group Foo transition-script backup "/config/scripts/vrrp-fail.sh Foo"
set high-availability vrrp group Foo transition-script fault "/config/scripts/vrrp-fail.sh Foo"
set high-availability vrrp group Foo transition-script master "/config/scripts/vrrp-master.sh Foo"

Weitere Informationen zu Skripten finden Sie im Command scripting-Abschnitt.

Virtueller Server

Virtueller Server ermöglicht die Lastverteilung des Verkehrs Ziel virtueller Adresse:Port zwischen mehreren realen Servern.

Algorithmus

Lastverteilungsscheduling-Algorithmus:

  • round-robin

  • weighted-round-robin

  • least-connection

  • weighted-least-connection

  • source-hashing

  • destination-hashing

  • locality-based-least-connection

set high-availability virtual-server 203.0.113.1 algorithm 'least-connection'

Forward-Methode

  • NAT

  • direct

  • tunnel

set high-availability virtual-server 203.0.113.1 forward-method 'nat'

Persistenz-Timeout

Zeit in Sekunden für persistente Verbindungen. IPVS wird alle Verbindungen von demselben Quell-IP-Adressen an denselben echten Server weiterleiten, für die Dauer des Timeout. Der Standardwert beträgt 300 Sekunden.

Setzen Sie auf 0, um Persistenz zu deaktivieren und die Lastverteilungsalgorithmus jede Verbindung unabhängig zu verteilen.

set high-availability virtual-server 203.0.113.1 persistence-timeout '180'

Gesundheitscheck

Benutzerdefiniertes Gesundheitscheck-Skript ermöglicht die Prüfung der Echtheit des Server-Verfügbarkeit

set high-availability virtual-server 203.0.113.1 real-server 192.0.2.11 health-check script <path-to-script>

Fwmark

Firewall-Mark. Es ist möglich, den Traffic basierend auf fwmark-Wert zu lasten.

set high-availability virtual-server 203.0.113.1 fwmark '111'

Real Server

Real Server IP-Adresse und Port

set high-availability virtual-server 203.0.113.1 real-server 192.0.2.11 port '80'

Beispiel

Virtueller Server kann mit VRRP virtuelle Adresse oder ohne VRRP konfiguriert werden.

In dem nächsten Beispiel wird der gesamte Verkehr, der an 203.0.113.1 und Port 8280 Protokoll TCP zwischen 2 echten Servern 192.0.2.11 und 192.0.2.12 an Port 80 balanciert

Real Server wird automatisch ausgeschlossen, wenn die Port-Prüfung mit diesem Server fehlschlägt.

set interfaces ethernet eth0 address '203.0.113.11/24'
set interfaces ethernet eth1 address '192.0.2.1/24'
set high-availability vrrp group FOO interface 'eth0'
set high-availability vrrp group FOO no-preempt
set high-availability vrrp group FOO priority '150'
set high-availability vrrp group FOO address '203.0.113.1/24'
set high-availability vrrp group FOO vrid '10'

set high-availability virtual-server 203.0.113.1 algorithm 'source-hashing'
set high-availability virtual-server 203.0.113.1 delay-loop '10'
set high-availability virtual-server 203.0.113.1 forward-method 'nat'
set high-availability virtual-server 203.0.113.1 persistence-timeout '180'
set high-availability virtual-server 203.0.113.1 port '8280'
set high-availability virtual-server 203.0.113.1 protocol 'tcp'
set high-availability virtual-server 203.0.113.1 real-server 192.0.2.11 port '80'
set high-availability virtual-server 203.0.113.1 real-server 192.0.2.12 port '80'

Ein Firewall-Mark fwmark ermöglicht es, mehrere Ports für hochverfügbare virtuelle Server zu verwenden. Es verwendet fwmark-Wert.

In diesem Beispiel wird der gesamte Verkehr, der an Ports „80, 2222, 8888“ Protokoll TCP markiert, um fwmark „111“ und zwischen 2 echten Servern balanciert. Port „0“ ist erforderlich, wenn mehrere Ports verwendet werden.

set interfaces ethernet eth0 address 'dhcp'
set interfaces ethernet eth0 description 'WAN'
set interfaces ethernet eth1 address '192.0.2.1/24'
set interfaces ethernet eth1 description 'LAN'

set policy route PR interface 'eth0'
set policy route PR rule 10 destination port '80,2222,8888'
set policy route PR rule 10 protocol 'tcp'
set policy route PR rule 10 set mark '111'

set high-availability virtual-server vyos fwmark '111'
set high-availability virtual-server vyos protocol 'tcp'
set high-availability virtual-server vyos real-server 192.0.2.11 health-check script '/config/scripts/check-real-server-first.sh'
set high-availability virtual-server vyos real-server 192.0.2.11 port '0'
set high-availability virtual-server vyos real-server 192.0.2.12 health-check script '/config/scripts/check-real-server-second.sh'
set high-availability virtual-server vyos real-server 192.0.2.12 port '0'

set nat source rule 100 outbound-interface name 'eth0'
set nat source rule 100 source address '192.0.2.0/24'
set nat source rule 100 translation address 'masquerade'
