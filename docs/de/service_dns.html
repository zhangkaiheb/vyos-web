DNS-Weiterleitung

VyOS bietet DNS-Infrastruktur für kleine Netzwerke, die leichtgewichtig und für ressourcenbeschränkte Router und Firewalls geeignet ist.

Verbundene Clients werden über die DNS-Weiterleitungs-Dienstleistung bedient, die unter service dns forwarding konfiguriert wird. Sie kann entweder Abfragen an konfigurierbare obere DNS-Server weiterleiten oder als vollständiger rekursiver DNS-Server ohne erforderliche obere DNS-Server betreiben. Der Betrieb ohne obere Server vermeidet, dass Client-Abfragen einem oberen DNS-Betreiber ausgesetzt sind.

Konfiguration

Hinweis

Eine DNS-Weiterleitungs-Konfiguration kann nur dann committet werden, wenn sowohl listen-address als auch allow-from gesetzt sind. Andernfalls scheitert das Commit.

Listener

set service dns forwarding listen-address <address>

Konfigurieren Sie eine lokale IPv4- oder IPv6-Adresse, auf der die DNS-Weiterleitung eingehende Abfragen empfängt.

Die Adresse muss bereits einer lokalen Schnittstelle zugewiesen sein. Wiederholen Sie den Befehl, um mehrere Anmeldeadressen zu konfigurieren. Mindestens eine Anmeldeadresse ist für ein erfolgreiches Commit erforderlich.

Beispiel:

set service dns forwarding listen-address 192.0.2.1
set service dns forwarding listen-address 2001:db8::1
set service dns forwarding port <1-65535>

Konfigurieren Sie den Port, auf dem die DNS-Weiterleitung eingehende Abfragen empfängt.

Der Standardwert ist 53.

Beispiel:

set service dns forwarding port 5353
set service dns forwarding allow-from <prefix>

Begrenzen Sie eingehende Abfragen auf Clients, deren Quell-IP innerhalb des angegebenen IPv4- oder IPv6-Präfixes liegt.

Wiederholen Sie den Befehl, um mehrere Präfixe zu erlauben. Mindestens ein Präfix ist für ein erfolgreiches Commit erforderlich.

Hinweis

Begrenzen Sie allow-from auf vertraute Netzwerke. Verwenden Sie nicht 0.0.0.0/0 oder ::/0, wenn der Dienst vom öffentlichen Internet erreichbar ist.

Beispiel:

set service dns forwarding allow-from 192.0.2.0/24
set service dns forwarding allow-from 2001:db8::/32
set service dns forwarding exclude-throttle-address <address>

Verhindern Sie die Drosselung autoritativer Server, die mit der angegebenen IPv4- oder IPv6-Adresse oder Präfix übereinstimmen.

DNS-Weiterleitung drosselt autoritative Server, die eine Abfrage nicht beantworten oder Antworten ablehnen, die DNS-Weiterleitung ablehnt. Dieser Befehl exmpt die angegebenen Adressen von der Drosselung. Wiederholen Sie den Befehl, um mehrere Adressen hinzuzufügen.

Beispiel:

set service dns forwarding exclude-throttle-address 192.0.2.53
set service dns forwarding exclude-throttle-address 2001:db8::53

Upstream-Weiterleitung

set service dns forwarding name-server <address>

Weiterleiten Sie Abfragen an den angegebenen IPv4- oder IPv6-Obere DNS-Server.

Die obere Server werden direkt unter DNS-Weiterleitung konfiguriert. Wiederholen Sie den Befehl, um mehrere obere Server zu konfigurieren.

Beispiel:

set service dns forwarding name-server 192.0.2.53
set service dns forwarding name-server 2001:db8::53
set service dns forwarding name-server <address> port <1-65535>

Konfigurieren Sie den Zielport, der bei der Weiterleitung von Abfragen an den angegebenen obere DNS-Server verwendet wird.

Der Standardwert ist 53.

Beispiel:

set service dns forwarding name-server 192.0.2.53 port 853
set service dns forwarding system

Weiterleiten Sie Abfragen an die obere DNS-Server, die unter system name-server konfiguriert sind.

Die obere Server werden von system name-server geerbt.

Beispiel:

set service dns forwarding system
set service dns forwarding dhcp <interface>

Weiterleiten Sie Abfragen an die DNS-Server, die über den DHCPv4- oder DHCPv6-Client auf der angegebenen Schnittstelle gelernt wurden.

Wiederholen Sie den Befehl, um Abfragen an DHCP-gelernte Server von mehreren Schnittstellen weiterzuleiten.

Beispiel:

set service dns forwarding dhcp eth0
set service dns forwarding source-address <address>

Konfigurieren Sie die lokale IPv4- oder IPv6-Adresse, die bei der Initiation von Ausgangsabfragen durch die DNS-Weiterleitung als Quelle verwendet wird.

Der Standardwert ist 0.0.0.0 und ::, was bedeutet, dass die Quelladresse pro ausgehende Abfrage ausgewählt wird. Wiederholen Sie den Befehl, um mehrere Quelladressen zu konfigurieren.

Beispiel:

set service dns forwarding source-address 192.0.2.1
set service dns forwarding source-address 2001:db8::1
set service dns forwarding no-serve-rfc1918

Deaktivieren Sie die autoritative Beantwortung von Abfragen für 10.in-addr.arpa, 168.192.in-addr.arpa und 16-31.172.in-addr.arpa Zonen.

Diese sind die umgekehrten Suchzonen für die RFC 1918 privaten Adressbereiche. Abfragen für diese Zonen werden dann an die konfigurierten obere Server weitergeleitet.

Beispiel:

set service dns forwarding no-serve-rfc1918
set service dns forwarding ignore-hosts-file

Verwenden Sie die lokale /etc/hosts Datei bei der Namensauflösung nicht.

Standardmäßig antwortet die DNS-Weiterleitung auf Abfragen mithilfe von /etc/hosts vor der Rekursion oder Weiterleitung.

Beispiel:

set service dns forwarding ignore-hosts-file

Cach und Timer

set service dns forwarding cache-size <0-2147483647>

Konfigurieren Sie die maximale Anzahl von DNS-Cache-Einträgen.

Der Standardwert ist 10000. Ein Wert von 0 deaktiviert den Cache.

Beispiel:

set service dns forwarding cache-size 1000000
set service dns forwarding negative-ttl <0-7200>

Konfigurieren Sie die maximale Zeit, in Sekunden, die negative Antworten (NXDOMAIN und NODATA) im Cache gespeichert werden.

Der Standardwert ist 3600.

Beispiel:

set service dns forwarding negative-ttl 60
set service dns forwarding minimum-ttl-override <0-2147483647>

Konfigurieren Sie den minimalen TTL, in Sekunden, der auf zwischengespeicherte Datensätze angewandt wird, unabhängig davon, welchen TTL die autoritative Server zurückgeben.

Datensätze mit einem TTL unter diesem Wert werden mit diesem minimalen TTL zwischengespeichert. Der Standardwert ist 1.

Hinweis

Ändern Sie dies nur, wenn Sie einen spezifischen Grund haben, kurze TTLs zu erhöhen, da höhere Werte die Caching-Zeit über den autoritativen TTL hinaus verlängern. Wenn sich der Datensatz oben ändert, erhalten Clients den veralteten zwischengespeicherten Wert, bis der Überschreitung abläuft.

Beispiel:

set service dns forwarding minimum-ttl-override 30
set service dns forwarding timeout <10-60000>

Konfigurieren Sie die Zeit, in Millisekunden, die DNS-Weiterleitung auf eine Antwort eines entfernten autoritativen Servers wartet.

Der Standardwert ist 1500.

Beispiel:

set service dns forwarding timeout 2000
set service dns forwarding ttl-percent <0-100>

Erneuern Sie zwischengespeicherte Datensätze im Hintergrund, wenn der verbleibende TTL unter diesem Prozentsatz des ursprünglichen TTLs fällt.

Die Clients erhalten während der Aktualisierung weiterhin die vorhandenen zwischengespeicherten Antworten. Der Standardwert ist 0, was das Hintergrund-Refresh deaktiviert.

Beispiel:

set service dns forwarding ttl-percent 10
set service dns forwarding serve-stale-extension <0-65535>

Konfigurieren Sie, wie oft der TTL eines abgelaufenen Datensatzes um 30 Sekunden verlängert werden kann, wenn der Datensatz nicht aktualisiert werden kann.

Der Standardwert ist 0, was das Bereitstellen veralteter Datensätze deaktiviert.

Beispiel:

set service dns forwarding serve-stale-extension 30

DNSSEC und NXDOMAIN-Verhalten

set service dns forwarding dnssec <off | process-no-validate | process | log-fail | validate>

Konfigurieren Sie den DNSSEC-Verarbeitungsmodus für ausgehende Abfragen und Antworten:

  • off: Keine DNSSEC-Verarbeitung. DO-Bits in Client-Abfragen werden ignoriert, und keine DNSSEC-Records werden von autoritativen Servern angefordert.

  • process-no-validate: Gibt DNSSEC-Records (RRSIG, NSEC) an Clients zurück, die sie anfordern, aber validiert sie nicht.

  • process: Validiert Antworten nur, wenn der Klient es anfordert (DO oder AD-Bit gesetzt). Gibt SERVFAIL bei falschen Daten zurück.

  • log-fail: Validiert alle Antworten unabhängig von der Client-Anfrage, protokolliert falsche Antworten, gibt aber die gleichen Antworten wie im process-Modus zurück.

  • validate: Validiert alle Antworten und gibt SERVFAIL bei falschen Daten zurück, unabhängig von der Client-Anfrage.

Der Standardwert ist process-no-validate.

Beispiel:

set service dns forwarding dnssec validate
set service dns forwarding nothing-below-nxdomain <no | dnssec | yes>

Konfigurieren Sie, wie DNS-Weiterleitung den NXDOMAIN-Schnitt behandelt.

Wenn DNS-Weiterleitung einen zwischengespeicherten NXDOMAIN hat, kann es auch NXDOMAIN für jeden Namen unter dem verweigerten Namen zurückgeben, ohne nach oben zu fragen. Dieses Einstellung steuert, wann dieses Verhalten gilt:

  • no: Wenden Sie den NXDOMAIN-Schnitt nie an.

  • dnssec: Wenden Sie den NXDOMAIN-Schnitt nur für DNSSEC-validierte NXDOMAIN-Einträge an.

  • yes: Wenden Sie den NXDOMAIN-Schnitt für jeden zwischengespeicherten NXDOMAIN an, der nicht falsch ist.

Der Standardwert ist dnssec.

Beispiel:

set service dns forwarding nothing-below-nxdomain yes

DNS64

set service dns forwarding dns64-prefix <prefix>

Synthesizieren Sie AAAA-Records aus A-Records für Namen, die keine AAAA-Records haben, unter Verwendung des angegebenen NAT64-IPv6-Prefixes.

Die Präfixlänge muss genau /96 sein.

Beispiel:

set service dns forwarding dns64-prefix 2001:db8:64::/96

EDNS Client Subnet

set service dns forwarding options ecs-add-for <prefix>

Konfigurieren Sie, welche Client-Quelladresse als ECS Wert in ausgehenden Abfragen gesendet wird.

Für Clients, deren Quelladresse mit dem angegebenen Präfix übereinstimmt, wird die echte Adresse des Clients gesendet. Für nicht übereinstimmende Clients wird stattdessen eine Platzhalteradresse gesendet, damit keine client-spezifische Subnetzinformation offengelegt wird.

ECS wird nur für Abfragen gesendet, die edns-subnet-allow-list entsprechen. Diese Option kontrolliert nur den Wert, nicht, ob ECS gesendet wird.

Stellen Sie ein ! voran, um ein Präfix auszuschließen. Wiederholen Sie den Befehl für mehrere Einträge.

Beispiel:

set service dns forwarding options ecs-add-for 192.0.2.0/24
set service dns forwarding options ecs-add-for !192.0.2.128/25
set service dns forwarding options ecs-ipv4-bits <0-32>

Konfigurieren Sie die Anzahl der Bits der IPv4-Adresse des Clients, die im ECS-Option, die an autoritative Server gesendet wird, enthalten sind.

Gilt nur für Abfragen, bei denen ECS gesendet wird (diejenigen, die edns-subnet-allow-list entsprechen).

Beispiel:

set service dns forwarding options ecs-ipv4-bits 24
set service dns forwarding options edns-subnet-allow-list <value>

Einschalten von ECS in ausgehenden Abfragen, wenn die Zielserver-Adresse innerhalb des angegebenen Netzmasks liegt oder wenn die Abfragename unter dem angegebenen Domänenname liegt.

Wiederholen Sie den Befehl, um mehrere Einträge hinzuzufügen.

Beispiel:

set service dns forwarding options edns-subnet-allow-list example.com
set service dns forwarding options edns-subnet-allow-list 192.0.2.0/24

Pro-Domänen-Weiterleitung

set service dns forwarding domain <domain-name> name-server <address>

Weiterleiten Sie Abfragen für die angegebene Domäne an den angegebenen IPv4- oder IPv6-Obere DNS-Server.

Wiederholen Sie den Befehl, um mehrere Nameserver für dieselbe Domäne zu konfigurieren. Verwenden Sie diese Option, um Split-Horizon-DNS zu implementieren. Die Domäne kann auch eine umgekehrte Suche Zone wie 2.0.192.in-addr.arpa sein.

Beispiel:

set service dns forwarding domain example.com name-server 192.0.2.53
set service dns forwarding domain example.com name-server 2001:db8::53
set service dns forwarding domain <domain-name> name-server <address> port <1-65535>

Konfigurieren Sie den Port des angegebenen obere DNS-Servers, an den Abfragen für die angegebene Domäne weitergeleitet werden.

Der Standardwert ist 53.

Beispiel:

set service dns forwarding domain example.com name-server 192.0.2.53 port 853
set service dns forwarding domain <domain-name> addnta

Konfigurieren Sie die angegebene Domäne als NTA, wodurch DNSSEC-Validierung für sie deaktiviert wird.

Konfigurieren Sie dies, wenn Abfragen für eine DNSSEC-beschädigte Domäne SERVFAIL zurückgeben, sodass die Domäne wieder erreichbar wird.

Beispiel:

set service dns forwarding domain example.com addnta
set service dns forwarding domain <domain-name> recursion-desired

Setzen Sie das RD Bit in Abfragen, die an den obere DNS-Server für diese Domäne gesendet werden.

Beispiel:

set service dns forwarding domain example.com recursion-desired

Authoritative Zonen

DNS-Weiterleitung kann autoritative Einträge für eine Domäne hosten und direkt statt weiterleiten oder rekursiv Abfragen beantworten.

set service dns forwarding authoritative-domain <domain-name> disable

Verhindern Sie, dass DNS-Weiterleitung die angegebene autoritative Zone bedient, ohne sie aus der Konfiguration zu entfernen.

Abfragen für Namen in der Zone werden stattdessen weitergeleitet oder rekursiv beantwortet.

Beispiel:

set service dns forwarding authoritative-domain example.com disable
set service dns forwarding authoritative-domain <domain-name> records <type> <name> disable

Verhindern Sie, dass DNS-Weiterleitung einen bestimmten Eintrag innerhalb der autoritativen Zone bedient, ohne ihn aus der Konfiguration zu entfernen.

Abfragen, die mit dem Eintrag übereinstimmen, werden stattdessen weitergeleitet oder rekursiv beantwortet.

Beispiel:

set service dns forwarding authoritative-domain example.com records a www disable
set service dns forwarding authoritative-domain <domain-name> records <type> <name> ttl <0-2147483647>

Konfigurieren Sie den TTL, in Sekunden, für den angegebenen Eintrag.

Der Standardwert ist 300.

Beispiel:

set service dns forwarding authoritative-domain example.com records a www ttl 600

Eintragstypen

Die Befehle für Eintragstypen in diesem Abschnitt akzeptieren folgende Schlüsselwörter für den Eintrag:

  • @: Stellt eine Zone-Apex dar, z. B. example.com. Akzeptiert jedes Eintragstyp.

  • any: Stellt einen Wildcard-Eintrag dar, z. B. *.example.com, der jede Unterdomain unter dem Apex abdeckt. Akzeptiert nur a und aaaa Einträge.

set service dns forwarding authoritative-domain <domain-name> records a <name> address <ipv4-address>

Konfigurieren Sie einen A Eintrag in der angegebenen autoritativen Zone.

Unterstützt @ und any als <name>. Wiederholen Sie den Befehl, um mehrere IPv4-Adressen zum selben Eintrag hinzuzufügen.

Beispiel:

set service dns forwarding authoritative-domain example.com records a www address 192.0.2.10
set service dns forwarding authoritative-domain <domain-name> records aaaa <name> address <ipv6-address>

Konfigurieren Sie einen AAAA Eintrag in der angegebenen autoritativen Zone.

Unterstützt @ und any als <name>. Wiederholen Sie den Befehl, um mehrere IPv6-Adressen zum selben Eintrag hinzuzufügen.

Beispiel:

set service dns forwarding authoritative-domain example.com records aaaa www address 2001:db8::10
set service dns forwarding authoritative-domain <domain-name> records cname <name> target <target-domain-name>

Konfigurieren Sie einen CNAME Eintrag in der angegebenen autoritativen Zone.

Unterstützt @ als <name>.

Beispiel:

set service dns forwarding authoritative-domain example.com records cname www target host.example.com
set service dns forwarding authoritative-domain <domain-name> records mx <name> server <server>

Konfigurieren Sie einen MX Eintrag in der angegebenen autoritativen Zone.

Unterstützt @ als <name>. Wiederholen Sie den Befehl, um mehrere Mailserver zum selben Eintrag hinzuzufügen.

Beispiel:

set service dns forwarding authoritative-domain example.com records mx @ server mail.example.com
set service dns forwarding authoritative-domain <domain-name> records mx <name> server <server> priority <1-999>

Konfigurieren Sie die Priorität des angegebenen MX-Eintrags.

Niedrigere Werte sind bevorzugt. Der Standardwert ist 10.

Beispiel:

set service dns forwarding authoritative-domain example.com records mx @ server mail.example.com priority 20
set service dns forwarding authoritative-domain <domain-name> records ns <name> target <target-name>

Konfigurieren Sie einen NS Eintrag in der angegebenen autoritativen Zone.

Unterstützt @ als <name>. Wiederholen Sie den Befehl, um mehrere Nameserver zum selben Eintrag hinzuzufügen.

Beispiel:

set service dns forwarding authoritative-domain example.com records ns @ target ns1.example.com
set service dns forwarding authoritative-domain <domain-name> records ptr <name> target <target-name>

Konfigurieren Sie einen PTR Eintrag in der angegebenen autoritativen Zone.

Unterstützt @ als <name>.

Beispiel:

set service dns forwarding authoritative-domain 2.0.192.in-addr.arpa records ptr 10 target host.example.com
set service dns forwarding authoritative-domain <domain-name> records txt <name> value <value>

Konfigurieren Sie einen TXT Eintrag in der angegebenen autoritativen Zone.

Unterstützt @ als <name>. Wiederholen Sie den Befehl, um mehrere TXT-Strings zum selben Eintrag hinzuzufügen.

Beispiel:

set service dns forwarding authoritative-domain example.com records txt @ value 'v=spf1 -all'
set service dns forwarding authoritative-domain <domain-name> records spf <name> value <value>

Konfigurieren Sie einen SPF Eintrag in der angegebenen autoritativen Zone.

Unterstützt @ als <name>.

Hinweis

SPF-Einträge werden im Hinblick auf neue Implementierungen durch TXT-Einträge ersetzt. Nutzen Sie TXT-Einträge für neue Deployment.

Beispiel:

set service dns forwarding authoritative-domain example.com records spf @ value 'v=spf1 -all'
set service dns forwarding authoritative-domain <domain-name> records srv <name> entry <0-65535> hostname <name>

Konfigurieren Sie das Zielhostname eines SRV-Eintrags in der angegebenen autoritativen Zone.

Unterstützt @ als <name>.

Beispiel:

set service dns forwarding authoritative-domain example.com records srv _sip._tcp entry 0 hostname sip.example.com
set service dns forwarding authoritative-domain <domain-name> records srv <name> entry <0-65535> port <0-65535>

Konfigurieren Sie den Port eines SRV-Eintrags in der angegebenen autoritativen Zone.

Beispiel:

set service dns forwarding authoritative-domain example.com records srv _sip._tcp entry 0 port 5060
set service dns forwarding authoritative-domain <domain-name> records srv <name> entry <0-65535> priority <0-65535>

Konfigurieren Sie die Priorität eines SRV-Eintrags in der angegebenen autoritativen Zone.

Niedrigere Werte sind bevorzugt. Der Standardwert ist 10.

Beispiel:

set service dns forwarding authoritative-domain example.com records srv _sip._tcp entry 0 priority 20
set service dns forwarding authoritative-domain <domain-name> records srv <name> entry <0-65535> weight <0-65535>

Konfigurieren Sie das Gewicht eines SRV-Eintrags in der angegebenen autoritativen Zone.

Das Gewicht wird verwendet, um Last zwischen Einträgen mit gleicher Priorität zu verteilen. Der Standardwert ist 0.

Beispiel:

set service dns forwarding authoritative-domain example.com records srv _sip._tcp entry 0 weight 50
set service dns forwarding authoritative-domain <domain-name> records naptr <name> rule <0-65535> order <0-65535>

Konfigurieren Sie das Order-Feld eines NAPTR-Regels in der angegebenen autoritativen Zone.

Unterstützt @ als <name>. Regeln mit niedrigerem Order werden zuerst bewertet.

Beispiel:

set service dns forwarding authoritative-domain example.com records naptr @ rule 100 order 10
set service dns forwarding authoritative-domain <domain-name> records naptr <name> rule <0-65535> preference <0-65535>

Konfigurieren Sie das Preference-Feld einer NAPTR-Regel in der angegebenen autoritativen Zone.

Unterstützt @ als <name>. Der Standardwert ist 0.

Beispiel:

set service dns forwarding authoritative-domain example.com records naptr @ rule 100 preference 50
set service dns forwarding authoritative-domain <domain-name> records naptr <name> rule <0-65535> lookup-a

Setzen Sie das A-Flag einer NAPTR-Regel in der angegebenen autoritativen Zone.

Wenn gesetzt, behandelt DNS-Weiterleitung die Ausgabe der Regel als Domainname und sucht dessen A- oder AAAA-Record. Es folgen keine weiteren NAPTR-Suchen.

Hinweis

Legen Sie maximal eines von lookup-a, lookup-srv, resolve-uri und protocol-specific auf derselben NAPTR-Regel fest. Diese Flags definieren gegenseitig ausschließende nächste Aktionen im DNS-Auflösungsprozess.

Beispiel:

set service dns forwarding authoritative-domain example.com records naptr @ rule 100 lookup-a
set service dns forwarding authoritative-domain <domain-name> records naptr <name> rule <0-65535> lookup-srv

Setzen Sie das S-Flag einer NAPTR-Regel in der angegebenen autoritativen Zone.

Wenn gesetzt, behandelt DNS-Weiterleitung die Ausgabe der Regel als Domainname und sucht dessen SRV-Record. Es folgen keine weiteren NAPTR-Suchen.

Beispiel:

set service dns forwarding authoritative-domain example.com records naptr @ rule 100 lookup-srv
set service dns forwarding authoritative-domain <domain-name> records naptr <name> rule <0-65535> resolve-uri

Setzen Sie das U-Flag einer NAPTR-Regel in der angegebenen autoritativen Zone.

Wenn gesetzt, behandelt DNS-Weiterleitung die Ausgabe der Regel als URI und verwendet sie direkt. Es folgen keine weiteren DNS-Suchen.

Beispiel:

set service dns forwarding authoritative-domain example.com records naptr @ rule 100 resolve-uri
set service dns forwarding authoritative-domain <domain-name> records naptr <name> rule <0-65535> protocol-specific

Setzen Sie das P-Flag einer NAPTR-Regel in der angegebenen autoritativen Zone.

Wenn gesetzt, behandelt DNS-Weiterleitung die Ausgabe der Regel gemäß dem zugehörigen Anwendungsprotokoll. Es folgen keine weiteren DNS-Suchen.

Beispiel:

set service dns forwarding authoritative-domain example.com records naptr @ rule 100 protocol-specific
