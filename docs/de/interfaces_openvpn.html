OpenVPN

Traditionell verwenden Hardware-Routern IPsec allein, da es einfach in der Hardware umzusetzen ist und ihre CPUs nicht über ausreichende Leistung für Software-basierte Verschlüsselung verfügen. Diese Einschränkung ist für VyOS weniger relevant, da es sich um eine Software-Router handelt.

OpenVPN wird bereits seit langer Zeit auf UNIX-Plattformen verwendet und ist eine beliebte Wahl für Remote-Access-VPNs. Es unterstützt auch Site-to-Site-Verbindungen.

OpenVPN bietet folgende Vorteile:

  • Es verwendet eine einzelne TCP- oder UDP-Verbindung und verlässt sich nicht auf Paket-Quelladressen, wodurch es auch durch doppelte NAT funktioniert. Dies macht es gut für öffentliche Hotspots geeignet.

  • Es ist einfach einzurichten und bietet sehr flexible Split-Tunneling.

  • Verschiedene Client-GUI-Frontends sind für jede Plattform verfügbar.

Nachteile beinhalten:

  • Es ist langsamer als IPsec, aufgrund höherer Protokollüberhead und weil es im Nutzermodus läuft, während IPsec auf Linux im Kernelmodus läuft.

  • Kein Betriebssystem enthält standardmäßig OpenVPN-Clientsoftware.

In der VyOS CLI wird OpenVPN als Netzwerkinterface konfiguriert, mit set interfaces openvpn, anstatt set vpn, was oft übersehen wird.

Konfiguration

set interfaces openvpn <interface> authentication password <text>

Konfigurieren Sie das Passwort für die auth-user-pass Authentifizierungsmethode.

Diese Option gilt nur für OpenVPN-Clients.

set interfaces openvpn <interface> authentication username <text>

Konfigurieren Sie den Benutzernamen für die auth-user-pass Authentifizierungsmethode.

Diese Option gilt nur für OpenVPN-Clients.

set interfaces openvpn <interface> description <description>

Konfigurieren Sie die Beschreibung für das OpenVPN-Interface.

set interfaces openvpn <interface> device-type <tap | tun>

Konfigurieren Sie den virtuellen Netzwerkgeräte-Typ für das OpenVPN-Interface:

  • tun (Standard): Funktioniert auf Ebene 3, kapselt IPv4- oder IPv6-Pakete.

  • tap: Funktioniert auf Ebene 2, kapselt Ethernet 802.3-Frames.

set interfaces openvpn <interface> disable

Deaktivieren Sie das spezifische OpenVPN-Interface.

set interfaces openvpn <interface> encryption cipher < 3des | aes128 | aes128gcm | aes192 | aes192gcm | aes256 | aes256gcm | none >

Konfigurieren Sie den statischen Verschlüsselungsalgorithmus für den OpenVPN-Tunnel.

Die cipher-Option entspricht dem OpenVPN-Befehl --cipher und gibt den symmetrischen Verschlüsselungsalgorithmus für Steuer- und Datenkanäle an.

Dies war zuvor die Standardverschlüsselungsmethode in allen OpenVPN-Modi. In neueren OpenVPN-Versionen wird der --cipher-Befehl als veraltet betrachtet und sollte nur in Kompatibilitätsszenarien verwendet werden.

set interfaces openvpn <interface> encryption data-ciphers < 3des | aes128 | aes128gcm | aes192 | aes192gcm | aes256 | aes256gcm | none >

Konfigurieren Sie eine priorisierte Liste der vereinbarten Chiffren für OpenVPN in client oder server Modus.

Die data-ciphers-Option stellt eine Liste unterstützter Verschlüsselungsalgorithmen dar. Sie entspricht dem OpenVPN-Befehl --data-ciphers und ermöglicht die Chiffrenvereinbarung, bei der beide Peers automatisch eine gemeinsam unterstützte Chiffre während des Sitzungsstarts vereinbaren.

Hinweis

Diese Option ist nicht kompatibel mit site-to-site Modus.

set interfaces openvpn <interface> encryption data-ciphers-fallback < 3des | aes128 | aes128gcm | aes192 | aes192gcm | aes256 | aes256gcm | none >

Konfigurieren Sie die Fallback-Chiffre für site-to-site Modus.

Die data-ciphers-fallback-Option entspricht dem OpenVPN-Befehl --data-ciphers- fallback. Sie definiert die Chiffre, die verwendet wird, wenn die Vereinbarung nicht unterstützt wird.

Hinweis

Diese Option stellt sicher, dass die Verschlüsselung zwischen zwei statischen Peers konsistent bleibt, ohne Fähigkeit zur Chiffrenvereinbarung.

set interfaces openvpn <interface> hash <md5 | sha1 | sha256 | …>

Konfigurieren Sie den Hash-Algorithmus für das OpenVPN-Interface.

set interfaces openvpn <interface> ip adjust-mss <mss | clamp-mss-to-pmtu>

Konfigurieren Sie die MSS im ausgehenden TCP SYN-Paket auf dem angegebenen Interface.

Durch das Klammern des MSS-Werts in TCP SYN-Paketen informieren Sie explizit das entfernte Ende, dass keine Pakete größer als diese Größe gesendet werden sollen. Dies verhindert Verbindungsprobleme, die auftreten, wenn die Pfad-MTU-Entdeckung (PMTUD) fehlschlägt.

Die folgenden Optionen sind verfügbar:

  • mss: Legt die MSS auf einen bestimmten Wert in Bytes fest. Verwenden Sie diese Option, wenn Sie eine bestimmte MSS erzwingen müssen, z. B. um Verbindungsprobleme zu beheben oder spezifische Netzwerkanforderungen zu erfüllen.

  • clamp-mss-to-pmtu: Der Router berechnet die MSS automatisch als MTU des Interfaces minus 40 Bytes für IPv4-Datenverkehr (20 Bytes für das IPv4-Header und 20 Bytes für das TCP-Header). Diese Option wird empfohlen, um den richtigen Wert automatisch zu setzen.

set interfaces openvpn <interface> ip arp-cache-timeout

Konfigurieren Sie, wie lange ein ARP-Eintrag gültig bleibt, nachdem ein IP-zu-MAC-Adressen-Zuordnung auf diesem Interface gelernt wurde.

Der Standardzeitraum beträgt 30 Sekunden.

Ein ARP-Eintrag bleibt gültig, wenn er positive Rückmeldungen von höheren Protokollen erhält.

Beispiel:

set interfaces openvpn vtun0 ip arp-cache-timeout 180
set interfaces openvpn <interface> ip disable-arp-filter

Konfigurieren Sie das ARP-Filtering auf diesem Interface.

Standardverhalten: Der Kernel antwortet auf ARP-Anfragen auf diesem Interface nur, wenn der Verkehr zurück zum ARP-Sender über dieses spezifische Interface geroutet wird.

Wenn konfiguriert: Der Kernel antwortet auf ARP-Anfragen auf diesem Interface für jede IP-Adresse, die auf dem lokalen Host konfiguriert ist, unabhängig davon, welches spezifische Interface diese IP-Adresse zugewiesen ist, und unabhängig vom Routing-Tabellen. Dies spiegelt den Linux-Konzept wider, dass IP-Adressen dem Host gehören, nicht individuellen Schnittstellen.

Beispiel:

set interfaces openvpn vtun0 ip disable-arp-filter
set interfaces openvpn <interface> ip disable-forwarding

Konfigurieren Sie das Interface für Host- oder Router-Verhalten.

Wenn konfiguriert, wechselt das Interface in Host-Modus, und IPv4-Weiterleitung wird auf ihm deaktiviert.

Beispiel:

set interfaces openvpn vtun0 ip disable-forwarding
set interfaces openvpn <interface> ip enable-directed-broadcast

Konfigurieren Sie, ob IP-gerichtete Broadcast-Pakete, die auf diesem Interface empfangen werden, weitergeleitet werden.

Standardverhalten: IP-gerichtete Broadcast-Pakete werden abgeworfen.

Wenn konfiguriert: IP-gerichtete Broadcast-Pakete werden an alle Hosts auf dem Ziel-Subnetz weitergeleitet, wie in RFC 1812 und RFC 2644 definiert.

Beispiel:

set interfaces openvpn vtun0 ip enable-directed-broadcast
set interfaces openvpn <interface> ip enable-arp-accept

Konfigurieren Sie, wie man Gratuitous ARPs auf diesem Interface verarbeitet.

Wenn konfiguriert, wird eine IP-zu-MAC-Adressenzuordnung basierend auf Gratuitous ARP-Anfragen oder Antworten in die ARP-Tabelle eingefügt.

Hinweis

Wenn die ARP-Tabelle bereits die IP-Adresse aus einem Gratuitous ARP enthält, wird deren Eintrag aktualisiert, unabhängig davon, ob diese Einstellung konfiguriert ist.

Beispiel:

set interfaces openvpn vtun0 ip enable-arp-accept
set interfaces openvpn <interface> ip enable-arp-announce

Konfigurieren Sie die Quell-IP-Auswahl für ARP-Anfragen auf diesem Interface.

Standardverhalten: Der Kernel kann jede IP-Adresse verwenden, die der Host besitzt, als Quell-IP-Adresse in ARP-Anfragen auf diesem Interface.

Wenn konfiguriert: Der Kernel versucht zunächst, eine Quell-IP-Adresse zu wählen, die auf dem Interface konfiguriert ist und mit dem Ziel-IP-Adress-Subnetz übereinstimmt. Wenn kein solches Subnetz vorhanden ist, wählt der Kernel die IP-Adresse, die er normalerweise verwenden würde (basierend auf der Routing-Tabelle, um das Zielziel zu erreichen).

Beispiel:

set interfaces openvpn vtun0 ip enable-arp-announce
set interfaces openvpn <interface> ip enable-arp-ignore

Konfigurieren Sie, welche ARP-Anfragen auf diesem Interface ignoriert werden.

Standardverhalten: Der Kernel antwortet auf ARP-Anfragen für beliebige lokale IP-Adressen, unabhängig davon, welchem Interface sie zugewiesen sind.

Wenn konfiguriert: Der Kernel antwortet nur auf ARP-Anfragen, wenn die Ziel-IP-Adresse diesem spezifischen Interface zugewiesen ist.

Beispiel:

set interfaces openvpn vtun0 ip enable-arp-ignore
set interfaces openvpn <interface> ip enable-proxy-arp

Konfigurieren Sie Proxy ARP auf diesem Interface.

Wenn konfiguriert, greift der Router (Kernel) ARP-Anfragen für nicht lokale IP-Adressen ab und antwortet mit der MAC -Adresse des Interfaces, das die Anfrage empfangen hat. Danach werden Pakete, die an diese IP-Adressen gerichtet sind, an ihre tatsächlichen Ziele auf entfernten Subnetzen weitergeleitet.

Beispiel:

set interfaces openvpn vtun0 ip enable-proxy-arp
set interfaces openvpn <interface> ip proxy-arp-pvlan

Konfigurieren Sie lokales Proxy ARP auf dem Interface.

Wenn konfiguriert, antwortet der Router (Kernel) auf ARP-Anfragen auf diesem VLAN-Interface, selbst wenn die Ziel-IP-Adresse auf dem gleichen Subnetz und Interface liegt.

Dies wird verwendet, um Netzwerkisolationsanforderungen (RFC 3069) für private VLANs (PVLANs) zu unterstützen. In PVLAN-Konfigurationen dürfen Hosts auf isolierten Ports nicht direkt miteinander kommunizieren, aber sie können mit dem Upstream-Router kommunizieren.

Indem er inter-host ARP-Anfragen mit seiner eigenen MAC -Adresse beantwortet, leitet der Router (Kernel) inter-host Traffic durch sich selbst statt direkt zwischen Hosts.

Hinweis

Dieser Befehl funktioniert unabhängig und erfordert nicht die Aktivierung des Standard-Proxy ARP auf dem Interface.

Lokales Proxy ARP ist auch bekannt als:

  • VLAN Aggregation (RFC 3069).

  • Private VLAN (Cisco, Allied Telesyn).

  • Source-port filtering oder Port-Isolation (Hewlett-Packard).

  • MAC-Forced Forwarding (Ericsson).

set interfaces openvpn <interface> ip source-validation <strict | loose | disable>

Konfigurieren Sie die Quell-IP-Adressen-Überprüfung mit RPF auf diesem Interface, wie in RFC 3704 spezifiziert.

Die folgenden Optionen sind verfügbar:

  • strict: Jedes eingehende Paket wird auf seine Quell-IP-Adresse gegen die Forwarding Information Base (FIB) geprüft. Wenn das Interface nicht der beste Weg zurück zu dieser Quelle ist, schlägt die Validierung fehl und das Paket wird gelöscht.

  • loose: Jedes eingehende Paket wird auf seine Quell-IP-Adresse gegen die Forwarding Information Base (FIB) geprüft. Wenn die Quell-IP-Adresse über kein Interface erreichbar ist, schlägt die Validierung fehl.

  • disable: Keine Quell-IP-Adressen-Überprüfung wird durchgeführt. Alle eingehenden Pakete werden akzeptiert.

RFC 3704 empfiehlt, den strengen Modus zu aktivieren, um IP-Spoofing, wie DDoS-Angriffe, zu verhindern. Für asynchrone oder andere komplexe Routing-Szenarien verwenden Sie den lockeren Modus.

set interfaces openvpn <interface> ipv6 address autoconf

Konfigurieren Sie das Interface, um eine IPv6-Adresse automatisch mit SLAAC, zu erhalten, wie in RFC 4862 spezifiziert.

IPv6-Hosts können sich automatisch konfigurieren, wenn sie sich mit einem IPv6-Netzwerk verbinden, indem sie den Neighbor Discovery Protocol über ICMPv6 Router Discovery Nachrichten verwenden. Wenn ein Host sich zum ersten Mal mit einem Netzwerk verbindet, sendet er eine Link-Local Router Solicitation Multicast Anfrage für seine Konfigurationsparameter. Der Router antwortet mit einer Router Advertisement Packet, das Internet Layer Konfigurationsparameter enthält.

Hinweis

Diese Methode deaktiviert automatisch die IPv6-Traffik-Weiterleitung auf dem Interface.

Beispiel:

set interfaces openvpn vtun0 ipv6 address autoconf
set interfaces openvpn <interface> ipv6 address eui64 <prefix>

Konfigurieren Sie das Interface, um eine IPv6-Adresse mit dem EUI-64 Verfahren zu zuweisen, wie in RFC 4291 spezifiziert.

Beispiel:

set interfaces openvpn vtun0 ipv6 address eui64 2001:db8:beef::/64
set interfaces openvpn <interface> ipv6 address no-default-link-local

Deaktivieren Sie die automatische Zuweisung einer link-local IPv6-Adresse zu diesem Interface.

Beispiel:

set interfaces openvpn vtun0 ipv6 address no-default-link-local
set interfaces openvpn <interface> ipv6 disable-forwarding

Konfigurieren Sie das Interface für Host- oder Router-Verhalten.

Wenn konfiguriert, wechselt das Interface in Host-Modus, und IPv6-Weiterleitung wird auf ihm deaktiviert.

Beispiel:

set interfaces openvpn vtun0 ipv6 disable-forwarding
set interfaces openvpn <interface> ipv6 adjust-mss <mss | clamp-mss-to-pmtu>

Konfigurieren Sie die MSS im ausgehenden TCP SYN-Paket auf dem angegebenen Interface.

Durch das Klammern des MSS-Werts in TCP SYN-Paketen informieren Sie explizit das entfernte Ende, dass keine Pakete größer als diese Größe gesendet werden sollen. Dies verhindert Verbindungsprobleme, wenn die Pfad-MTU-Entdeckung (PMTUD) fehlschlägt.

Die folgenden Optionen sind verfügbar:

  • mss: Setzt die MSS auf einen bestimmten Wert in Bytes. Verwenden Sie diese Option, um eine bestimmte MSS zu erzwingen, z. B. um Verbindungsprobleme zu beheben oder spezifische Netzwerkanforderungen zu erfüllen.

  • clamp-mss-to-pmtu: Der Router berechnet die MSS als MTU des Interfaces minus 60 Bytes für IPv6-Datenverkehr (40 Bytes für das IPv6-Header und 20 Bytes für das TCP-Header). Diese Option wird empfohlen, um den richtigen Wert automatisch zu setzen.

set interfaces openvpn <interface> ipv6 accept-dad <0 | 1 | 2>

Konfigurieren Sie IPv6 DAD auf dem Interface.

Die folgenden Optionen sind verfügbar:

  • 0: Deaktiviert DAD. Es wird keine Duplikatadresse erkannt.

  • 1: Aktiviert DAD (Standard). Duplikatadressen werden erkannt. Die IPv6-Operation des Interfaces wird für gültige IPv6-Adressen fortgesetzt.

  • 2: Aktiviert DAD und, falls eine MAC-basierte duplizierte Link-Local-Adresse gefunden wird, deaktiviert es die IPv6-Operation auf diesem Interface.

Beispiel:

set interfaces openvpn vtun0 ipv6 accept-dad 2
set interfaces openvpn <interface> ipv6 dup-addr-detect-transmits <n>

Konfigurieren Sie die Anzahl der DAD Nachrichten, die der Router (Kernel) während der IPv6-Adresszuweisung auf diesem Interface sendet.

Der Standardwert ist 1.

Beispiel:

set interfaces openvpn vtun0 ipv6 dup-addr-detect-transmits 5
set interfaces openvpn <interface> keep-alive failure-count <value>

Konfigurieren Sie die Anzahl tolerierter Keepalive-Paketfehler.

Standard: 60 aufeinanderfolgende Fehler.

set interfaces openvpn <interface> keep-alive interval <value>

Konfigurieren Sie die Frequenz, in Sekunden, mit der Keepalive-Pakete gesendet werden.

Standard: 10 Sekunden.

set interfaces openvpn <interface> local-address <address>

set interfaces openvpn <interface> local-host <address>

Konfigurieren Sie die lokale IP-Adresse, um Verbindungen zu akzeptieren.

Wenn konfiguriert, bindet OpenVPN nur an diese IP-Adresse.

Standardmäßig bindet OpenVPN an alle Schnittstellen.

set interfaces openvpn <interface> local-port <port>

Konfigurieren Sie den lokalen Port, um Verbindungen zu akzeptieren.

set interfaces openvpn <interface> mirror egress <monitor-interface>

Konfigurieren Sie die Spiegelung ausgehenden Verkehrs von diesem OpenVPN-Interface auf das angegebene Monitor-Interface.

set interfaces openvpn <interface> mirror ingress <monitor-interface>

Konfigurieren Sie die Spiegelung eingehenden Verkehrs von diesem OpenVPN-Interface auf das angegebene Monitor-Interface.

set interfaces openvpn <interface> mode <site-to-site | server | client>

Konfigurieren Sie den OpenVPN-Betriebsmodus:

  • client: Funktioniert als Client im Server-Client-Modus.

  • server: Funktioniert als Server im Server-Client-Modus.

OpenVPN Data Channel Offload (DCO)

OpenVPN DCO verbessert die Leistung der verschlüsselten OpenVPN-Datenverarbeitung, indem es die meiste Datenverarbeitung im Kernel hält und häufige Kontextwechsel zwischen Kernel und Benutzermodus vermeidet.

Dadurch wird die Paketverarbeitung effizienter und kann möglicherweise Hardware-Verschlüsselungs-Offload-Unterstützung im Kernel nutzen.

Hinweis

  • DCO ist ein experimentelles, nicht vollständig unterstütztes OpenVPN-Feature. Einige OpenVPN-Funktionen und Deployment-Szenarien sind nicht kompatibel mit DCO.

    Für eine vollständige Liste der unterstützten Features besuchen Sie: https://community.openvpn.net/openvpn/wiki/DataChannelOffload/Features

  • DCO wird pro Tunnel konfiguriert und ist standardmäßig deaktiviert. Bestehende Tunnel laufen ohne DCO, es sei denn, es wird explizit aktiviert.

  • Das Aktivieren von DCO setzt das Interface zurück.

Bester Praxis: Erstellen Sie einen neuen Tunnel mit DCO aktiviert, um Kompatibilitätsprobleme mit bestehenden Clients zu vermeiden.

set interfaces openvpn <interface> offload dco

Enable DCO für das angegebene OpenVPN-Interface.

Beispiel:

set interfaces openvpn vtun0 offload dco

Dieser Befehl aktiviert DCO und lädt das erforderliche Kernel-Modul.

set interfaces openvpn <interface> openvpn-option <text>

Fügen Sie rohe OpenVPN-Konfigurationsoptionen zur openvpn.conf-Datei hinzu.

OpenVPN bietet viele Konfigurationsoptionen, aber nicht alle sind in der VyOS CLI verfügbar.

Wenn eine erforderliche Option fehlt, können Sie eine Funktionsanfrage bei Phabricator einreichen, damit alle Benutzer davon profitieren (siehe Contributing/Issues and Features).

Alternativ können Sie openvpn-option verwenden, um rohe OpenVPN-Konfigurationsoptionen an die openvpn.conf-Datei zu übergeben.

Warnung

Verwenden Sie diese Option nur als letzte Möglichkeit. Ungültige Optionen oder Syntax können dazu führen, dass OpenVPN nicht startet. Überprüfen Sie nach dem Anwenden der Änderungen die Systemprotokolle auf Fehler.

Beispiel:

set interfaces openvpn vtun0 openvpn-option 'persist-key'

Dieser Befehl fügt persist-key zur Konfigurationsdatei hinzu. Dies löst das Problem, indem Schlüssel über Neustarts hinweg beibehalten werden, sodass sie nicht neu gelesen werden müssen.

set interfaces openvpn vtun0 openvpn-option 'route-up &quot;/config/auth/tun_up.sh arg1&quot;'

Dieser Befehl fügt route-up "/config/auth/tun_up.sh arg1" zur Konfigurationsdatei hinzu. Diese Option wird nach der Authentifizierung der Verbindung ausgeführt, entweder sofort oder nach kurzer Verzögerung, wie definiert.

Achten Sie darauf, dass der Pfad und die Argumente in einfachen oder doppelten Anführungszeichen eingeschlossen sind.
