SNMP

SNMP ist ein Internet-Standardprotokoll zur Erfassung und Organisation von Informationen über verwaltete Geräte auf IP-Netzwerken und zur Änderung dieser Informationen, um das Verhalten der Geräte zu verändern. Geräte, die typischerweise SNMP unterstützen, umfassen Kabelmodems, Router, Switches, Server, Workstations, Drucker und vieles mehr.

SNMP wird weit verbreitet in der Netzwerkverwaltung für Netzwerküberwachung verwendet. SNMP stellt Verwaltungsdaten in Form von Variablen auf den verwalteten Systemen bereit, die in einer Verwaltungsinformationsbasis (MIB) organisiert sind, die den Systemstatus und die Konfiguration beschreiben. Diese Variablen können dann von Verwaltungsanwendungen ferngesteuert abgefragt (und in einigen Fällen auch manipuliert) werden.

Drei bedeutende Versionen des SNMP wurden entwickelt und eingesetzt. SNMPv1 ist die ursprüngliche Version des Protokolls. Neuere Versionen, SNMPv2c und SNMPv3, bieten Verbesserungen in Leistung, Flexibilität und Sicherheit.

SNMP ist ein Bestandteil des Internet-Protokollstapels, wie vom Internet Engineering Task Force (IETF) definiert. Es besteht aus einem Satz von Standards für Netzwerkverwaltung, einschließlich eines Anwendungsprotokolls, eines Datenbank-Schemas und eines Satzes von Datenobjekten.

Übersicht und grundlegende Konzepte

In typischen Anwendungen des SNMP hat ein oder mehrere administrative Computer, die als Manager bezeichnet werden, die Aufgabe, eine Gruppe von Hosts oder Geräten auf einem Computernetzwerk zu überwachen oder zu verwalten. Jedes verwaltete System führt ein Softwarekomponente namens Agent aus, der Informationen über SNMP an den Manager meldet.

Ein SNMP-verwaltetes Netzwerk besteht aus drei Schlüsselkomponenten:

  • Verwaltete Geräte

  • Agent – Software, die auf verwalteten Geräten läuft

  • Netzwerkverwaltungsstation (NMS) – Software, die auf dem Manager läuft

Eine verwaltete Einheit ist ein Netzwerk-Knoten, der ein SNMP-Schnittstelle implementiert, das unidirektionale (nur Lesen) oder bidirektionale (Lesen und Schreiben) Zugriff auf knotenspezifische Informationen ermöglicht. Verwaltete Geräte tauschen knotenspezifische Informationen mit NMSs aus. Manchmal auch als Netzwerkelemente bezeichnet, können verwaltete Geräte jedes Gerät sein, einschließlich, aber nicht beschränkt auf Router, Zugangsserver, Switches, Kabelmodems, Brücken, Hub, IP-Telefon, IP-Videokamera, Computerhost und Drucker.

Ein Agent ist ein Netzwerkmanagement-Softwaremodul, das auf einem verwalteten Gerät residieren. Ein Agent hat lokale Kenntnisse über Verwaltungsinformationen und übersetzt diese Information in oder aus einem SNMP-spezifischen Format.

Eine Netzwerkverwaltungsstation führt Anwendungen aus, die verwaltete Geräte überwachen und steuern. NMSs stellen den Großteil der erforderlichen Verarbeitungs- und Speicherressourcen für die Netzwerkverwaltung bereit. Eine oder mehrere NMSs können auf jedem verwalteten Netzwerk existieren.

Hinweis

VyOS SNMP unterstützt sowohl IPv4 als auch IPv6.

SNMP-Protokollversionen

VyOS selbst unterstützt SNMPv2 (Version 2) und SNMPv3 (Version 3), wobei die letztere aufgrund verbesserten Sicherheit (optionaler Authentifizierung und Verschlüsselung) empfohlen wird.

SNMPv2

SNMPv2 ist die ursprüngliche und am häufigsten verwendete Version. Für die Autorisierung von Clients verwendet SNMP das Konzept von Communities. Communities können autorisierter auf Lesezugriff (das ist am häufigsten) oder auf Lese- und Schreibzugriff (diese Option wird in VyOS nicht aktiv verwendet) gesetzt werden.

SNMP kann synchron oder asynchron arbeiten. Bei synchroner Kommunikation fragt das Überwachungssystem den Router periodisch ab. Bei asynchroner Kommunikation sendet der Router eine Benachrichtigung an den „Trap“ (die Überwachungsstation).

SNMPv2 unterstützt keine Authentifizierungsmechanismen, außer dem Client-Quelladresse, daher sollten Sie Adressen der Clients angeben, die den Router überwachen dürfen. Beachten Sie, dass SNMPv2 auch keine Verschlüsselung unterstützt und immer Daten im Klartext sendet.

Beispiel

# Definieren einer Community
set service snmp community routers authorization ro

# Ermöglichen des Monitoring-Zugriffs aus dem gesamten Netzwerk
set service snmp community routers network 192.0.2.0/24
set service snmp community routers network 2001::db8:ffff:eeee::/64

# Ermöglichen des Monitoring-Zugriffs von spezifischen Adressen
set service snmp community routers client 203.0.113.10
set service snmp community routers client 203.0.113.20

# Definieren optionaler Router-Informationen
set service snmp location "UK, London"
set service snmp contact "[email protected]"

# Trap-Ziel, falls asynchrone Kommunikation gewünscht ist
set service snmp trap-target 203.0.113.10

# Nur auf bestimmten IP-Adressen lauschen (Port standardmäßig 161)
set service snmp listen-address 172.16.254.36 port 161
set service snmp listen-address 2001:db8::f00::1

SNMPv3

SNMPv3 (Version 3 des SNMP-Protokolls) führte eine ganze Menge neuer sicherheitsbezogener Funktionen ein, die in den vorherigen Versionen fehlten. Sicherheit war eines der größten Schwächen von SNMP bis hin zu v3. Die Authentifizierung in SNMP-Versionen 1 und 2 besteht lediglich darin, ein Passwort (Community-String) in Klartext zwischen Manager und Agent zu senden. Jede SNMPv3-Nachricht enthält Sicherheitsparameter, die als Oktettstring codiert sind. Die Bedeutung dieser Sicherheitsparameter hängt vom verwendeten Sicherheitsmodell ab.

Der Sicherheitsansatz in SNMPv3 zielt auf:

  • Vertraulichkeit – Verschlüsselung von Paketen, um Spionage durch einen unbefugten Quelle zu verhindern.

  • Integrität – Nachrichtenintegrität, um sicherzustellen, dass ein Paket während der Übertragung nicht manipuliert wurde, einschließlich eines optionalen Mechanismus zur Paket-Wiederholungsschutz.

  • Authentifizierung – um sicherzustellen, dass die Nachricht von einer gültigen Quelle stammt.

Beispiel

  • Lassen Sie den SNMP-Dienst nur auf der IP-Adresse 192.0.2.1 lauschen

  • Konfigurieren Sie einen neuen SNMP-Benutzer mit dem Namen „vyos“ mit dem Passwort „vyos12345678“

  • Der neue Benutzer verwendet SHA/AES für Authentifizierung und Privatsphäre

set service snmp listen-address 192.0.2.1
set service snmp location 'VyOS Datacenter'
set service snmp v3 engineid '000000000000000000000002'
set service snmp v3 group default mode 'ro'
set service snmp v3 group default view 'default'
set service snmp v3 user vyos auth plaintext-password 'vyos12345678'
set service snmp v3 user vyos auth type 'sha'
set service snmp v3 user vyos group 'default'
set service snmp v3 user vyos privacy plaintext-password 'vyos12345678'
set service snmp v3 user vyos privacy type 'aes'
set service snmp v3 view default oid 1

Nach dem Commit werden die Klartext-Passwörter gehasht und in Ihrer Konfiguration gespeichert. Der resultierende CLI-Konfigurationsbefehl sieht wie folgt aus:

vyos@vyos# show service snmp
 listen-address 192.0.2.1 {
 }
 location "VyOS Datacenter"
 v3 {
     engineid 000000000000000000000002
     group default {
         mode ro
         view default
     }
     user vyos {
         auth {
             encrypted-password 4e52fe55fd011c9c51ae2c65f4b78ca93dcafdfe
             type sha
         }
         group default
         privacy {
             encrypted-password 4e52fe55fd011c9c51ae2c65f4b78ca93dcafdfe
             type aes
         }
     }
     view default {
         oid 1 {
         }
     }
 }

Sie können die SNMPv3-Funktionen von jedem Linux-basierten System aus testen, indem Sie einfach den folgenden Befehl ausführen: snmpwalk -v 3 -u vyos -a SHA -A vyos12345678 -x AES -X vyos12345678 -l authPriv 192.0.2.1 .1

VyOS MIBs

Alle SNMP-MIBs befinden sich in jedem VyOS-Image hier: /usr/share/snmp/mibs/

Sie können die Dateien mit SCP herunterladen, sobald der SSH-Dienst aktiviert wurde, so wie folgt

scp -r vyos@your_router:/usr/share/snmp/mibs /your_folder/mibs

SNMP-Erweiterungen

Um die Funktionalität des SNMP-Agents zu erweitern, können benutzerdefinierte Skripte ausgeführt werden, sobald der Agent aufgerufen wird. Dies kann erreicht werden, indem man arbitrary extensioncommands verwendet. Der erste Schritt ist selbstverständlich, ein funktionales Skript zu erstellen, danach muss es über den Befehl scp your_script.sh vyos@your_router:/config/user-data auf Ihr VyOS-System hochgeladen werden. Sobald das Skript hochgeladen wurde, muss es mit dem folgenden Befehl konfiguriert werden.

set service snmp script-extensions extension-name my-extension script your_script.sh
commit

Die OID .1.3.6.1.4.1.8072.1.3.2.3.1.1.4.116.101.115.116, sobald sie aufgerufen wird, enthält die Ausgabe der Erweiterung.

root@vyos:/home/vyos# snmpwalk -v2c  -c public 127.0.0.1 nsExtendOutput1
NET-SNMP-EXTEND-MIB::nsExtendOutput1Line."my-extension" = STRING: hello
NET-SNMP-EXTEND-MIB::nsExtendOutputFull."my-extension" = STRING: hello
NET-SNMP-EXTEND-MIB::nsExtendOutNumLines."my-extension" = INTEGER: 1
NET-SNMP-EXTEND-MIB::nsExtendResult."my-extension" = INTEGER: 0

SolarWinds

Wenn Sie SolarWinds Orion als NMS verwenden, können Sie auch das Device Templates Management nutzen. Ein Template für VyOS kann leicht importiert werden.

Erstellen Sie eine Datei mit dem Namen VyOS-1.3.6.1.4.1.44641.ConfigMgmt-Commands mit dem folgenden Inhalt:

<Configuration-Management Device="VyOS" SystemOID="1.3.6.1.4.1.44641">
    <Commands>
        <Command Name="Reset" Value="set terminal width 0${CRLF}set terminal length 0"/>
        <Command Name="Reboot" Value="reboot${CRLF}Yes"/>
        <Command Name="EnterConfigMode" Value="configure"/>
        <Command Name="ExitConfigMode" Value="commit${CRLF}exit"/>
        <Command Name="DownloadConfig" Value="show configuration commands"/>
        <Command Name="SaveConfig" Value="commit${CRLF}save"/>
        <Command Name="Version" Value="show version"/>
        <Command Name="MenuBased" Value="False"/>
        <Command Name="VirtualPrompt" Value=":~"/>
    </Commands>
</Configuration-Management>
