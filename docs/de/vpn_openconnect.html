Die OpenConnect-kompatible Serverfunktion ist seit Equuleus (1.3) verfügbar. Openconnect VPN unterstützt SSL-Verbindungen und bietet volle Netzwerkzugriff. SSL-VPN-Netzwerk-Erweiterung verbindet das Endgerätesystem mit dem Unternehmensnetzwerk mit Zugriffssteuerung nur auf der Netzwerkschichtinformation, wie Ziel-IP-Adresse und Portnummer. So bietet es sichere Kommunikation für alle Arten von Geräteverkehr über öffentliche und private Netzwerke und verschlüsselt den Verkehr mit dem SSL-Protokoll.

Der Remote-Benutzer wird den openconnect-Client verwenden, um sich mit dem Router zu verbinden und eine IP-Adresse aus einem VPN-Pool erhalten, was den vollen Zugriff auf das Netzwerk ermöglicht.

Konfiguration

SSL-Zertifikate

Wir müssen das Zertifikat generieren, das Benutzer authentifiziert, die versuchen, auf die Netzwerkressource über SSL-VPN-Tunnel zuzugreifen. Die folgenden Befehle werden ein selbstsigniertes Zertifikat erstellen und in der Konfiguration speichern:

run generate pki ca install <CA name>
run generate pki certificate sign <CA name> install <Server name>

Wir können auch Zertifikate mit Certbot erstellen, welches ein einfach zu verwendender Client ist, der ein Zertifikat von Let’s Encrypt, einer offenen Zertifizierungsstelle, die von EFF, Mozilla und anderen gestartet wurde, abruft und es auf einen Webserver deployt.

sudo certbot certonly --standalone --preferred-challenges http -d <domain name>

Server-Konfiguration

set vpn openconnect authentication local-users username <user> password <pass>
set vpn openconnect authentication mode <local password|radius|certificate>
set vpn openconnect network-settings client-ip-settings subnet <subnet>
set vpn openconnect network-settings name-server <address>
set vpn openconnect network-settings name-server <address>
set vpn openconnect ssl ca-certificate <pki-ca-name>
set vpn openconnect ssl certificate <pki-cert-name>
set vpn openconnect ssl passphrase <pki-password>

2FA OTP Unterstützung

Anstelle der Passwort-Authentifizierung kann 2FA-Passwort Authentifizierung + OTP-Schlüssel verwendet werden. Alternativ kann auch nur OTP-Authentifizierung ohne Passwort verwendet werden. Um dies zu tun, muss eine OTP-Konfiguration zur obigen Konfiguration hinzugefügt werden:

set vpn openconnect authentication mode local <password-otp|otp>
set vpn openconnect authentication local-users username <user> otp <key>
set vpn openconnect authentication local-users username <user> interval <interval (optional)>
set vpn openconnect authentication local-users username <user> otp-length <otp-length (optional)>
set vpn openconnect authentication local-users username <user> token-type <token-type (optional)>

Zum Generieren eines OTP-Schlüssels in VyOS können Sie den CLI-Befehl (operational mode):

generate openconnect username <user> otp-key hotp-time

User-Zertifikat-Authentifizierung

Sie können Benutzer so konfigurieren, dass sie durch Zertifikat authentifiziert werden, indem Sie den Authentifizierungsmodus auf Zertifikat setzen und definieren, welches Feld (nach OID) im Zertifikat verwendet werden soll, um den Benutzernamen zu identifizieren. Zwei vordefinierte

Abkürzungen für Common Name (OID 2.5.4.3) und User ID (OID 0.9.2342.19200300.100.1.1) wurden als cn oder uid bereitgestellt.

Andernfalls muss ein spezifischer OID-Wert angegeben werden.

Das Zertifikat des Benutzers muss von der in der Konfiguration definierten Zertifizierungsstelle signiert sein, damit es für die Authentifizierung validiert werden kann.

set vpn openconnect authentication mode certificate
set vpn openconnect authentication mode certificate user-identifier-field cn
set vpn openconnect ssl ca-certificate <cert>

OpenConnect-Konfiguration

Einfache Einrichtung mit einem Benutzer und Passwort-Authentifizierung:

set vpn openconnect authentication local-users username tst password 'OC_bad_Secret'
set vpn openconnect authentication mode local password
set vpn openconnect network-settings client-ip-settings subnet '172.20.20.0/24'
set vpn openconnect network-settings name-server '10.1.1.1'
set vpn openconnect network-settings name-server '10.1.1.2'
set vpn openconnect ssl ca-certificate 'ca-ocserv'
set vpn openconnect ssl certificate 'srv-ocserv'

Um die HTTP-Sicherheitsheader in der Konfigurationsdatei zu aktivieren, verwenden Sie den Befehl:

set vpn openconnect http-security-headers

Identitätsbasierte Konfiguration

OpenConnect unterstützt eine Teilmenge seiner Konfigurationsoptionen, die auf Basis von Benutzer/Gruppe angewandt werden können, für Konfigurationszwecke beziehen wir uns auf diese Funktion als „Identitätsbasierte Konfiguration“. Der folgende OpenConnect Server Manual listet die Menge der Konfigurationsoptionen auf, die erlaubt sind. Dies kann genutzt werden, um verschiedene Mengen von Konfigurationen für verschiedene Benutzer oder Gruppen von Benutzern anzuwenden.

sudo mkdir -p /config/auth/ocserv/config-per-user
sudo touch /config/auth/ocserv/default-user.conf

set vpn openconnect authentication identity-based-config mode user
set vpn openconnect authentication identity-based-config directory /config/auth/ocserv/config-per-user
set vpn openconnect authentication identity-based-config default-config /config/auth/ocserv/default-user.conf

Warnung

Der oben genannte Ordner und default-config müssen ein Unterverzeichnis von /config/auth sein, da Dateien außerhalb dieses Verzeichnisses nach einem Bildupgrade nicht persistiert werden.

Sobald Sie die oben genannten Änderungen committen, können Sie eine Konfigurationsdatei im /config/auth/ocserv/config-per-user-Ordner erstellen, die einem Benutzernamen entspricht, den Sie erstellt haben, z. B. „tst“. Wenn Sie sich mit dem „tst“-Benutzer anmelden, werden die von Ihnen in dieser Datei festgelegten Konfigurationsoptionen geladen.

Vergewissern Sie sich, dass Sie in der Standardkonfigurationsdatei eine sinnvolle Standardkonfiguration einrichten, die geladen wird, falls ein Benutzer authentifiziert wird und keine Datei im konfigurierten Verzeichnis mit dem Benutzernamen/der Gruppe gefunden wird.

sudo nano /config/auth/ocserv/config-per-user/tst

Die gleichen Konfigurationsoptionen gelten, wenn Identitätsbasierte Konfiguration im Gruppenmodus konfiguriert wird, mit der Ausnahme, dass Gruppenmodus nur mit RADIUS-Authentifizierung verwendet werden kann.

Warnung

OpenConnect Server passt den Dateinamen in einer casesensitiven Weise an, stellen Sie sicher, dass der Benutzername/Gruppenname, den Sie konfigurieren, genau mit dem Dateinamen übereinstimmt.

Radius-Accounting konfigurieren

OpenConnect kann so konfiguriert werden, dass es Accounting-Informationen an einen RADIUS-Server sendet, um Benutzer-Sessions-Daten wie Zeit von Verbindung/Trennung, übertragenen Daten usw. zu erfassen.

Konfigurieren Sie einen Accounting-Server und aktivieren Sie Accounting mit:

set vpn openconnect accounting mode radius
set vpn openconnect accounting radius server 172.20.20.10
set vpn openconnect accounting radius server 172.20.20.10 port 1813
set vpn openconnect accounting radius server 172.20.20.10 key your_radius_secret

Warnung

Das Radius-Accounting-Feature muss mit dem OpenConnect Authentifizierungsmodus Radius verwendet werden. Es kann nicht mit lokaler Authentifizierung verwendet werden. Sie müssen den OpenConnect-Authentifizierungsmodus auf „radius“ konfigurieren.

Ein Beispiel für die Daten, die von einem FREERADIUS-Server mit sql-Accounting erfasst werden:
