Failover

Les routes de failover sont des chemins réseau configurés manuellement utilisés uniquement pendant que leurs cibles de vérification de santé sont accessibles. Si la cible ne répond plus, VyOS supprime la route du tableau de routage et la réinstalle une fois que la cible est à nouveau accessible.

Configuration

Utilisez les commandes suivantes pour configurer les routes de failover pour un sous-réseau spécifique <subnet> accessible via le prochain saut <address>.

set protocols failover route <subnet> next-hop <address> check target <target-address>

Configurez l'adresse IP de la cible de vérification de santé.

Cela correspond généralement à un hôte hautement disponible, soit dans le sous-réseau de destination, soit sur Internet public.

Exemple :

set protocols failover route 203.0.113.1/32 next-hop 10.217.37.254 check target 8.8.8.8
set protocols failover route <subnet> next-hop <address> check timeout <timeout>

Configurez l'intervalle de temporisation, en secondes, entre les vérifications de santé.

La plage valide est de 1 à 300 secondes. La valeur par défaut est de 10 secondes.

Exemple :

set protocols failover route 203.0.113.1/32 next-hop 10.217.37.254 check timeout 2
set protocols failover route <subnet> next-hop <address> check type <protocol>

Configurez le protocole à utiliser pour les vérifications de santé.

Les protocoles suivants sont disponibles :

  • icmp : VyOS envoie deux paquets de requête d'écho ICMP avec un délai de réponse de 1 seconde. La vérification de santé réussit si au moins une réponse est reçue.

  • arp : VyOS envoie deux requêtes ARP avec un délai de réponse de 1 seconde. La vérification de santé réussit si au moins une réponse est reçue.

  • tcp : VyOS vérifie si le port TCP de destination est ouvert. La vérification de santé réussit si une connexion TCP est établie avec succès avec le port cible.

Le protocole par défaut est icmp.

Remarque

Lorsque le type de vérification est défini sur tcp, vous devez également définir le port TCP cible.

Exemple :

set protocols failover route 203.0.113.1/32 next-hop 10.217.37.254 check type tcp
set protocols failover route <subnet> next-hop <address> check port <port>

Configurez le port TCP de destination sur la cible de vérification de santé.

Ce paramètre s'applique uniquement lorsque le type de vérification est configuré comme tcp.

La plage de ports valide est de 1 à 65535.

Exemple :

set protocols failover route 203.0.113.1/32 next-hop 10.217.37.254 check port 443
set protocols failover route <subnet> next-hop <address> check policy <policy>

Configurez la politique de réussite de la vérification de santé pour plusieurs cibles.

Les politiques suivantes sont disponibles :

  • any-available : La vérification de santé réussit si au moins une des cibles configurées répond correctement.

  • all-available : La vérification de santé réussit uniquement si toutes les cibles configurées répondent correctement.

La politique par défaut est any-available.

Exemple :

set protocols failover route 203.0.113.1/32 next-hop 10.217.37.254 check policy all-available
set protocols failover route <subnet> next-hop <address> interface <interface>

Configurez l'interface locale utilisée pour atteindre l'adresse de prochain saut.

Ce paramètre est obligatoire.

Exemple :

set protocols failover route 203.0.113.1/32 next-hop 10.217.37.254 interface eth0
set protocols failover route <subnet> next-hop <address> metric <1-255>

Configurez la métrique (coût) pour la route de failover.

La métrique définit la priorité de la route. Une valeur de métrique plus faible indique une route plus préférée.

La valeur par défaut est 1.

Exemple :

set protocols failover route 203.0.113.1/32 next-hop 10.217.37.254 metric 50
set protocols failover route <subnet> next-hop <address> onlink

Configurez le prochain saut comme étant accessible via l'interface assignée, même lorsque <address> est en dehors de tout sous-réseau configuré sur cette interface.

Exemple :

set protocols failover route 203.0.113.1/32 next-hop 10.217.37.254 onlink

Exemples

Route de failover avec un seul prochain saut et vérification de santé ICMP

L'exemple suivant configure une route de failover vers 203.0.113.1/32 via le prochain saut 192.0.2.1 sur eth0. Le prochain saut est surveillé avec des sondes ICMP vers 192.0.2.1 toutes les 5 secondes, et la route est installée avec une métrique de 10.

set protocols failover route 203.0.113.1/32 next-hop 192.0.2.1 check target '192.0.2.1'
set protocols failover route 203.0.113.1/32 next-hop 192.0.2.1 check timeout '5'
set protocols failover route 203.0.113.1/32 next-hop 192.0.2.1 check type 'icmp'
set protocols failover route 203.0.113.1/32 next-hop 192.0.2.1 interface 'eth0'
set protocols failover route 203.0.113.1/32 next-hop 192.0.2.1 metric '10'

Vérifiez la route :

vyos@vyos:~$ show ip route 203.0.113.1
Routing entry for 203.0.113.1/32
  Known via "kernel", distance 0, metric 10, best
  Last update 00:00:39 ago
  Flags: Selected
  Status: Installed
  * 192.0.2.1, via eth0, weight 1

Deux routes de failover avec des métriques différentes

L'exemple suivant configure deux routes de failover vers 203.0.113.1/32, chacune via un prochain saut différent. Le prochain saut principal 192.0.2.1 est atteint sur eth0 avec une métrique de 10, et le prochain saut de secours 198.51.100.1 est atteint sur eth2 avec une métrique de 20. Les deux prochains sauts sont surveillés avec des sondes ICMP toutes les 5 secondes.

Tant que les deux vérifications de santé réussissent, la route avec la métrique inférieure via eth0 est privilégiée. Si la cible principale ne répond plus, sa route est supprimée du tableau de routage, et le trafic passe à 198.51.100.1 via eth2.

set protocols failover route 203.0.113.1/32 next-hop 192.0.2.1 check target '192.0.2.1'
set protocols failover route 203.0.113.1/32 next-hop 192.0.2.1 check timeout '5'
set protocols failover route 203.0.113.1/32 next-hop 192.0.2.1 check type 'icmp'
set protocols failover route 203.0.113.1/32 next-hop 192.0.2.1 interface 'eth0'
set protocols failover route 203.0.113.1/32 next-hop 192.0.2.1 metric '10'

set protocols failover route 203.0.113.1/32 next-hop 198.51.100.1 check target '198.51.100.99'
set protocols failover route 203.0.113.1/32 next-hop 198.51.100.1 check timeout '5'
set protocols failover route 203.0.113.1/32 next-hop 198.51.100.1 check type 'icmp'
set protocols failover route 203.0.113.1/32 next-hop 198.51.100.1 interface 'eth2'
set protocols failover route 203.0.113.1/32 next-hop 198.51.100.1 metric '20'

Vérifiez les routes :

vyos@vyos:~$ show ip route 203.0.113.1
Routing entry for 203.0.113.1/32
  Known via "kernel", distance 0, metric 10, best
  Last update 00:08:06 ago
  Flags: Selected
  Status: Installed
  * 192.0.2.1, via eth0, weight 1

Routing entry for 203.0.113.1/32
  Known via "kernel", distance 0, metric 20
  Last update 00:08:14 ago
  Flags: None
  Status: Installed
  * 198.51.100.1, via eth2, weight 1
