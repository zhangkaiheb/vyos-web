NPTv6 est une technologie de traduction d'adresse basée sur les réseaux IPv6, utilisée pour convertir un préfixe d'adresse IPv6 dans un message IPv6 en un autre préfixe d'adresse IPv6. Nous appelons cette méthode de traduction d'adresse NAT66. Les appareils qui prennent en charge la fonction NAT66 sont appelés appareils NAT66, qui peuvent fournir des fonctions de traduction d'adresse source et de destination NAT66.

Aperçu

Types de NAT différents

SNAT66

SNPTv6 La fonction de conversion est principalement utilisée dans les scénarios suivants :

  • Un seul réseau interne et externe. Utilisez l'appareil NAT66 pour connecter un seul réseau interne et un réseau public, et les hôtes du réseau interne utilisent des préfixes d'adresses IPv6 qui ne prennent en charge que le routage dans la portée locale. Lorsqu'un hôte du réseau interne accède au réseau externe, le préfixe d'adresse IPv6 source dans le message sera converti par l'appareil NAT66 en un préfixe d'adresse IPv6 unicast global.

  • Réplication et partage de charge. Il y a plusieurs appareils NAT66 à la périphérie d'un réseau IPv6 vers un autre réseau IPv6. Le chemin via l'appareil NAT66 vers un autre réseau IPv6 forme un itinéraire équivalent, et le trafic peut être partagé en charge sur ces appareils NAT66. Dans ce cas, vous pouvez configurer les mêmes règles de traduction d'adresse source sur ces appareils NAT66, afin qu'un appareil NAT66 puisse gérer le trafic IPv6 entre différents sites.

  • Multihomed. Dans un environnement réseau multihomed, l'appareil NAT66 se connecte à un réseau interne et se connecte simultanément à différents réseaux externes. Une traduction d'adresse peut être configurée sur chaque interface du côté du réseau externe de l'appareil NAT66 pour convertir la même adresse du réseau interne en différentes adresses du réseau externe, et réaliser la correspondance de la même adresse interne vers plusieurs adresses externes.

DNAT66

La fonction de traduction d'adresse de destination DNPTv6 est utilisée dans les scénarios où le serveur du réseau interne fournit des services au réseau externe, tels que la fourniture de services Web ou FTP au réseau externe. En configurant la relation de mappage entre l'adresse du serveur interne et l'adresse du réseau externe sur l'interface du côté du réseau externe de l'appareil NAT66, les utilisateurs du réseau externe peuvent accéder au serveur du réseau interne via l'adresse externe désignée.

Conversion de préfixe

Préfixe source

Chaque règle SNAT66 a une commande de traduction définie. Le préfixe défini pour la traduction est le préfixe utilisé lors de la substitution des informations d'adresse dans un paquet.

La règle SNAT66 remplace l'adresse source du paquet et calcule l'adresse convertie à l'aide du préfixe spécifié dans la règle.

Exemple :

  • Convertir le préfixe d'adresse d'un seul réseau fc01::/64 en fc00::/64

  • Sortie depuis l'interface réseau eth0

set nat66 source rule 1 outbound-interface name 'eth0'
set nat66 source rule 1 source prefix 'fc01::/64'
set nat66 source rule 1 translation address 'fc00::/64'

Préfixe de destination

Pour la règle DNAT66, l'adresse de destination du paquet est remplacée par l'adresse calculée à partir de l'adresse ou du préfixe spécifié dans la commande translation address.

Exemple :

  • Convertir le préfixe d'adresse d'un seul réseau fc00::/64 en fc01::/64

  • Entrée depuis l'interface réseau eth0

set nat66 destination rule 1 inbound-interface name 'eth0'
set nat66 destination rule 1 destination address 'fc00::/64'
set nat66 destination rule 1 translation address 'fc01::/64'

Pour la destination, des groupes peuvent également être utilisés au lieu d'une adresse.

Exemple :

set firewall group ipv6-address-group ADR-INSIDE-v6 address fc00::1

set nat66 destination rule 1 inbound-interface name 'eth0'
set nat66 destination rule 1 destination group address-group ADR-INSIDE-v6
set nat66 destination rule 1 translation address 'fc01::/64'

Exemples de configuration

Utilisez la topologie suivante pour créer un réseau isolé basé sur NAT66 entre les réseaux internes et externes (le préfixe dynamique n'est pas pris en charge) :

R1 :

set interfaces ethernet eth0 ipv6 address autoconf
set interfaces ethernet eth1 address 'fc01::1/64'
set nat66 destination rule 1 destination address 'fc00:470:f1cd:101::/64'
set nat66 destination rule 1 inbound-interface name 'eth0'
set nat66 destination rule 1 translation address 'fc01::/64'
set nat66 source rule 1 outbound-interface name 'eth0'
set nat66 source rule 1 source prefix 'fc01::/64'
set nat66 source rule 1 translation address 'fc00:470:f1cd:101::/64'

R2 :

set interfaces bridge br1 address 'fc01::2/64'
set interfaces bridge br1 member interface eth0
set interfaces bridge br1 member interface eth1
set protocols static route6 ::/0 next-hop fc01::1
set service router-advert interface br1 prefix ::/0

Utilisez la topologie suivante pour traduire les adresses locales des utilisateurs internes (fc::/7) en préfixes fournis par un FAI via DHCPv6-PD connecté à un couple HA VyOS.

Configurer les deux routeurs (a et b) pour DHCPv6-PD via une interface dummy :

set interfaces dummy dum1 description 'DHCPv6-PD NPT dummy'
set interfaces bonding bond0 vif 20 dhcpv6-options pd 0 interface dum1 address '0'
set interfaces bonding bond0 vif 20 dhcpv6-options pd 1 interface dum1 address '0'
set interfaces bonding bond0 vif 20 dhcpv6-options pd 2 interface dum1 address '0'
set interfaces bonding bond0 vif 20 dhcpv6-options pd 3 interface dum1 address '0'
set interfaces bonding bond0 vif 20 dhcpv6-options rapid-commit
commit
