Babel

Le protocole Babel fournit un routage robuste et efficace pour les réseaux maillés filaires et sans fil. Par défaut, Babel utilise des métriques basées sur le nombre de sauts sur les liaisons filaires et une variante du Compteur de Transmission Attendu (ETX) sur les liaisons sans fil. Les administrateurs peuvent configurer Babel pour tenir compte de la diversité radio, calculer automatiquement la latence des liaisons et inclure cette latence dans la métrique de routage. RFC 8966 définit le protocole Babel.

Babel est un protocole à double pile. Une instance Babel unique route les trafics IPv4 et IPv6 simultanément.

Configuration générale

VyOS n'a pas besoin d'une commande spécifique pour démarrer le processus Babel. Le système démarre automatiquement le processus de routage lorsque vous configurez la première interface activée en Babel.

set protocols babel interface <interface>

Activer le routage Babel sur l'interface spécifiée.

Le système commence immédiatement à envoyer et recevoir des paquets Babel sur cette interface.

Configuration facultative

set protocols babel parameters diversity

Activer le routage avec diversité de fréquence radio pour le processus Babel.

L'activation de cette fonctionnalité est fortement recommandée pour les réseaux avec de nombreux nœuds sans fil.

Note

Lorsque vous activez le routage avec diversité, vous devriez également configurer les paramètres diversity-factor et channel.

set protocols babel parameters diversity-factor <1-256>

Configurer le facteur multiplicatif pour le routage avec diversité, en unités de 1/256.

Les facteurs multiplicatifs plus faibles donnent plus de poids à la diversité lors de la sélection des routes. La valeur par défaut est 256, ce qui désactive le routage avec diversité. Sur les nœuds avec plusieurs radios indépendantes, configurez une valeur inférieure ou égale à 128.

set protocols babel parameters resend-delay <20-655340>

Configurer le délai en millisecondes avant que le système ne renvoie une demande ou une mise à jour importante.

La valeur par défaut est de 2000 ms.

set protocols babel parameters smoothing-half-life <0-65534>

Configurer la constante de temps, en secondes, pour l'algorithme de lissage utilisé pour implémenter l'hystérésis.

Des valeurs plus élevées réduisent les oscillations des routes mais augmentent légèrement le temps de convergence. Une valeur de 0 désactive l'hystérésis et convient aux réseaux filaires. La valeur par défaut est de 4 secondes.

Configuration des interfaces

set protocols babel interface <interface> type <auto|wired|wireless>

Configurer le type de réseau pour l'interface activée en Babel.

Choisissez parmi les suivants :

  • auto : Babel détecte automatiquement si une interface est filaire ou sans fil.

  • wired : Babel active les optimisations pour les interfaces filaires.

  • wireless : Babel désactive les optimisations adaptées uniquement aux interfaces filaires. Spécifier wireless est toujours correct, mais peut entraîner une convergence plus lente et un trafic de routage accru.

set protocols babel interface <interface> split-horizon <default|disable|enable>

Configurer le comportement de routage split-horizon pour l'interface spécifiée.

Utilisez l'une des options suivantes :

  • default : Babel active automatiquement le split-horizon sur les interfaces filaires et le désactive sur les interfaces sans fil.

  • enable : Babel active le split-horizon sur l'interface. Cette optimisation doit être utilisée uniquement sur des réseaux symétriques et transitifs (filaires).

  • disable : Babel désactive le split-horizon sur l'interface. Désactiver le split-horizon est toujours sûr et correct.

set protocols babel interface <interface> hello-interval <20-655340>

Configurer l'intervalle, en millisecondes, entre les messages hello programmés sur l'interface spécifiée.

Sur les liaisons filaires, Babel détecte les pannes de liaison dans deux intervalles de hello. Sur les liaisons sans fil, la qualité de la liaison est recalculée à chaque intervalle. La valeur par défaut est de 4000 ms.

set protocols babel interface <interface> update-interval <20-655340>

Configurer l'intervalle, en millisecondes, entre les mises à jour de routage programmées sur l'interface spécifiée.

Comme Babel utilise largement les mises à jour déclenchées, vous pouvez augmenter cette valeur sur les liaisons fiables avec une perte de paquets minimale. La valeur par défaut est de 20000 ms.

set protocols babel interface <interface> rxcost <1-65534>

Configurer le coût de réception de base pour l'interface spécifiée.

Babel applique cette valeur en fonction du type de réseau configuré :

  • wired : La valeur est le coût de routage annoncé aux routeurs voisins.

  • wireless : La valeur est un multiplicateur utilisé pour calculer le coût de réception ETX (Expected Transmission Count).

La valeur par défaut est de 256.

set protocols babel interface <interface> rtt-decay <1-256>

Configurer le facteur de décroissance pour la moyenne exponentielle des échantillons RTT, en unités de 1/256.

Les valeurs plus élevées éliminent plus rapidement les anciens échantillons. La valeur par défaut est de 42.

set protocols babel interface <interface> rtt-min <1-65535>

Configurer le RTT minimum, en millisecondes, à partir duquel le coût vers un voisin commence à augmenter.

Le coût supplémentaire est linéaire en (rtt - rtt-min). La valeur par défaut est de 10 ms.

set protocols babel interface <interface> rtt-max <1-65535>

Configurer le RTT maximum, en millisecondes, au-delà duquel le coût vers un voisin cesse d'augmenter.

La valeur par défaut est de 120 ms.

set protocols babel interface <interface> max-rtt-penalty <0-65535>

Configurer le coût maximum ajouté à un voisin lorsqu'un RTT atteint ou dépasse rtt-max.

En réglant cette valeur à 0, on désactive les coûts basés sur le RTT. La valeur par défaut est de 150.

set protocols babel interface <interface> enable-timestamps

Configurer l'ajout de horodatages à chaque message Hello et IHU pour calculer les valeurs RTT.

L'activation des horodatages est recommandée pour les interfaces tunnel.

set protocols babel interface <interface> channel <1-254|interfering|noninterfering>

Configurer l'identifiant de canal utilisé par le routage avec diversité pour l'interface spécifiée.

Les interfaces s'interfèrent mutuellement en fonction de l'identifiant de canal attribué :

  • 1–254 : L'interface s'interfère avec les interfaces partageant le même numéro de canal et avec les interfaces configurées comme interfering.

  • interfering : L'interface s'interfère avec toutes les autres sauf celles configurées comme noninterfering.

  • noninterfering : L'interface s'interfère uniquement avec elle-même.

Configuration de redistribution

set protocols babel redistribute <ipv4|ipv6> <route source>

Configurer la redistribution de l'information de routage provenant de la source de route spécifiée vers le processus Babel.

Les sources de route suivantes sont disponibles :

  • ipv4: bgp, connected, eigrp, isis, kernel, nhrp, ospf, rip, static

  • ipv6: bgp, connected, eigrp, isis, kernel, nhrp, ospfv3, ripng, static

set protocols babel distribute-list <ipv4|ipv6> access-list <in|out> <number>

Configurer le filtrage global des routes Babel à l'aide d'une liste d'accès.

Spécifiez le sens dans lequel la liste d'accès est appliquée :

  • in : Filtre les routes entrantes.

  • out : Filtre les routes sortantes.

set protocols babel distribute-list <ipv4|ipv6> interface <interface> access-list <in|out> <number>

Configurer le filtrage des routes Babel sur l'interface spécifiée à l'aide d'une liste d'accès.

Spécifiez le sens dans lequel la liste d'accès est appliquée :

  • in : Filtre les routes entrantes.

  • out : Filtre les routes sortantes.

set protocols babel distribute-list <ipv4|ipv6> prefix-list <in|out> <name>

Configurer le filtrage global des routes Babel à l'aide d'une liste de préfixes.

Spécifiez le sens dans lequel la liste de préfixes est appliquée :

  • in : Filtre les routes entrantes.

  • out : Filtre les routes sortantes.

set protocols babel distribute-list <ipv4|ipv6> interface <interface> prefix-list <in|out> <name>

Configurer le filtrage des routes Babel sur l'interface spécifiée à l'aide d'une liste de préfixes.

Spécifiez le sens dans lequel la liste de préfixes est appliquée :

  • in : Filtre les routes entrantes.

  • out : Filtre les routes sortantes.

Exemple de configuration

Réseau Babel à deux nœuds de base

Objectif : L'exemple suivant connecte deux routeurs (Nœud 1 et Nœud 2) via leurs interfaces eth0 et utilise le protocole de routage Babel pour publier (redistribuer) les réseaux localement configurés de chaque routeur (représentés par des adresses de boucle) à l'autre.

Nœud 1 :

# Configurer les adresses de boucle (réseaux locaux) et physiques (eth0)
set interfaces loopback lo address 10.1.1.1/32
set interfaces loopback lo address fd12:3456:dead:beef::1/128
set interfaces ethernet eth0 address 192.168.1.1/24

# Activer Babel sur la liaison physique
set protocols babel interface eth0 type wired

# Instruire Babel de publier (redistribuer) les réseaux localement configurés
set protocols babel redistribute ipv4 connected
set protocols babel redistribute ipv6 connected

Nœud 2 :

# Configurer les adresses de boucle (réseaux locaux) et physiques (eth0)
set interfaces loopback lo address 10.2.2.2/32
set interfaces loopback lo address fd12:3456:beef:dead::2/128
set interfaces ethernet eth0 address 192.168.1.2/24

# Activer Babel sur la liaison physique
set protocols babel interface eth0 type wired

# Dire à Babel de publier (redistribuer) les réseaux localement configurés
set protocols babel redistribute ipv4 connected
set protocols babel redistribute ipv6 connected
