PIM

PIM route le trafic multicast entre les routeurs en utilisant le tableau de routage unicast existant pour les décisions de chemin. VyOS prend en charge PIM Sparse Mode (PIM-SM) et les versions 2 et 3 d'IGMP.

Dans le PIM-SM, le trafic provenant des sources multicast est transmis vers le RP. Les récepteurs multicast utilisent IGMP pour signaler à leur routeur local les groupes qu'ils souhaitent recevoir, et le routeur utilise PIM pour tirer ce trafic du RP via un arbre partagé.

Une déployment fonctionnel de PIM-SM nécessite :

  • PIM activé sur chaque interface le long du chemin multicast.

  • La localisation du RP déclarée de manière identique sur chaque routeur dans le domaine PIM.

  • IGMP activé sur les interfaces face aux récepteurs multicast.

Configuration

PIM-SM

set protocols pim ecmp

Activer le routage ECMP (Equal-Cost Multipath) pour le trafic multicast.

Lorsqu'une recherche RPF (Reverse Path Forwarding) spécifique retourne plusieurs prochains sauts à coût égal, l'activation de cette fonction distribue les flux (S,G) multicast sur tous ceux-ci.

Si ECMP n'est pas activé, PIM utilise par défaut uniquement le premier prochain saut retourné par la recherche RPF.

Exemple :

set protocols pim ecmp
set protocols pim ecmp rebalance

Activer le rééquilibrage automatique de tous les flux (S,G) PIM lorsqu'une interface de prochain saut ECMP tombe en panne.

Lorsque ECMP est activé, et qu'une des interfaces utilisées par PIM tombe en panne, cette fonction force PIM à redistribuer tous les flux (S,G) existants sur les interfaces restantes à coût égal.

Si le rééquilibrage n'est pas configuré, PIM ne redirige que les flux spécifiques qui utilisaient activement l'interface défaillante.

Exemple :

set protocols pim ecmp rebalance
set protocols pim join-prune-interval <1-65535>

Configurer l'intervalle, en secondes, à partir duquel PIM envoie des messages Join/Prune aux voisins en amont.

L'intervalle par défaut est de 60 secondes. Définir une valeur inférieure à 60 secondes peut avoir un impact négatif sur la convergence à grande échelle.

Exemple :

set protocols pim join-prune-interval 120
set protocols pim keep-alive-timer <1-65535>

Configurer l'intervalle de temporisation de maintien de connexion, en secondes, pour l'état des flux multicast (S,G).

Note

Certains matériels ne peuvent pas détecter le trafic circulant à intervalles inférieurs à 30 secondes. Pour ces matériels, assurez-vous que la valeur est fixée à 31 secondes ou plus.

Exemple :

set protocols pim keep-alive-timer 60
set protocols pim packets <1-255>

Configurer le nombre de paquets PIM entrants traités consécutivement d'un voisin avant que le système ne passe à la tâche suivante.

La valeur par défaut est de 3 paquets. Cette commande n'est utile que dans les déploiements avec un grand nombre de paquets de contrôle PIM.

Exemple :

set protocols pim packets 10
set protocols pim register-accept-list prefix-list <prefix-list>

Configurer une liste de préfixes pour filtrer les messages PIM Register entrants.

Lorsque PIM reçoit un paquet Register, l'adresse IP de la source multicast est évaluée contre la liste de préfixes spécifiée. Si l'adresse IP de la source est autorisée, le traitement normal PIM continue. Si l'adresse IP de la source est refusée, un message Register-Stop est envoyé à l'expéditeur.

Exemple :

set protocols pim register-accept-list prefix-list MULTICAST-SOURCES
set protocols pim register-suppress-time <1-65535>

Configurer la durée, en secondes, pendant laquelle un FHR (First-Hop Router) supprime l'envoi de messages PIM Register.

Exemple :

set protocols pim register-suppress-time 60
set protocols pim rp address <ip-address> group <prefix>

Configurer un point de rendez-vous (RP) pour la plage de groupe multicast spécifiée.

Pour utiliser PIM, vous devez configurer un RP pour recevoir les messages Join. VyOS prend actuellement en charge uniquement la configuration statique du RP.

Le paramètre <address> définit l'adresse IP du RP, et le paramètre <group> définit le préfixe de la plage de groupe multicast servie par ce RP.

Un seul RP peut servir plusieurs plages de groupe. Répétez la commande avec différents préfixes <group> pour mapper plusieurs plages au même RP.

Exemple :

set protocols pim rp address 192.0.2.1 group 239.0.0.0/8
set protocols pim rp keep-alive-timer <1-65535>

Configurer l'intervalle de temporisation de maintien de connexion, en secondes, pour l'état des flux multicast (S,G) au point de rendez-vous (RP).

Cette valeur doit être au moins égale à la register-suppression-time ; sinon, le RP peut expirer l'état (S,G) avant l'arrivée du prochain message Null-Register depuis le FHR.

Lorsqu'un Register-Stop est envoyé, le KAT(S,G) au niveau du RP est défini à la valeur maximale de Keepalive_Period global et de RP_Keepalive_Period.

La valeur par défaut est de 210 secondes.

Voir RFC 7761, Section 4.1 pour les détails.

Note

Comme certains plateformes matérielles ne peuvent pas détecter le trafic circulant à intervalles inférieurs à 30 secondes, assurez-vous que la valeur est fixée à 31 secondes ou plus.

Exemple :

set protocols pim rp keep-alive-timer 300
set protocols pim no-v6-secondary

Désactiver l'envoi d'adresses secondaires IPv6 dans les messages PIM Hello.

Par défaut, les messages PIM Hello incluent toutes les adresses secondaires IPv6 configurées sur l'interface, permettant aux voisins PIM d'utiliser ces adresses comme prochains sauts IPv6 pour les recherches RPF.

Exemple :

set protocols pim no-v6-secondary
set protocols pim spt-switchover infinity-and-beyond prefix-list <list>

Au niveau du LHR, supprimer le basculement du arbre partagé (*,G) vers l'arbre spécifique à la source (S,G) SPT.

La liste de préfixes optionnelle contrôle les groupes affectés : les groupes correspondant à une entrée permit restent sur l'arbre partagé, les groupes correspondant à une entrée deny basculent normalement. Sans liste de préfixes, la suppression s'applique à tous les groupes.

Exemple :

set protocols pim spt-switchover infinity-and-beyond
set protocols pim spt-switchover infinity-and-beyond prefix-list SHARED-TREE-GROUPS
set protocols pim ssm prefix-list <list>

Configurer une liste de préfixes avec la plage d'adresses IP de groupe multicast qui fonctionnent en mode SSM.

Exemple :

set protocols pim ssm prefix-list SSM-RANGE

Commandes spécifiques à l'interface

set protocols pim interface <interface> bfd

Activer le BFD (Bidirectional Forwarding Detection) pour chaque voisin PIM découvert sur l'interface spécifiée.

Lorsque le BFD détecte une panne de lien, la relation de voisinage PIM est rompue, et tous les enregistrements (S,G) multicast associés sont supprimés.

Exemple :

set protocols pim interface eth0 bfd
set protocols pim interface <interface> bfd profile <name>

Appliquer le profil BFD spécifié aux sessions BFD sur cette interface PIM.

Exemple :

set protocols pim interface eth0 bfd profile fast-failover
set protocols pim interface <interface> dr-priority <1-4294967295>

Configurer la priorité du routeur désigné (DR) pour l'interface spécifiée.

Le routeur avec la priorité d'interface la plus élevée est élu DR pour un segment LAN.

Exemple :

set protocols pim interface eth0 dr-priority 100
set protocols pim interface <interface> hello <1-180>

Configurer l'intervalle PIM Hello, en secondes, pour l'interface spécifiée.

Les messages PIM Hello sont envoyés périodiquement sur l'interface pour découvrir et maintenir les relations de voisinage PIM. Le temps d'attente (la durée après laquelle un voisin est considéré comme mort si aucun Hello n'est reçu) est calculé en fonction de l'intervalle Hello.

Exemple :

set protocols pim interface eth0 hello 10
set protocols pim interface <interface> no-bsm

Désactiver le traitement des messages PIM BSMs sur l'interface spécifiée.

Exemple :

set protocols pim interface eth0 no-bsm
set protocols pim interface <interface> no-unicast-bsm

Désactiver le traitement des BSMs PIM unicast sur cette interface.

Exemple :

set protocols pim interface eth0 no-unicast-bsm
set protocols pim interface <interface> passive

Désactiver l'envoi et la réception de paquets de contrôle PIM sur cette interface.

Exemple :

set protocols pim interface eth0 passive
set protocols pim interface <interface> source-address <ip-address>

Configurer l'adresse IP source PIM utilisée pour les messages de contrôle envoyés sur l'interface spécifiée.

Cette commande est utile lorsque plusieurs adresses IP sont configurées sur une seule interface.

Exemple :

set protocols pim interface eth0 source-address 192.0.2.10

IGMP

set protocols pim igmp watermark-warning <1-65535>

Configurer la génération d'avertissements de seuil en fonction du nombre de groupes IGMP joints.

Lorsque le nombre total de groupes IGMP joints atteint cette limite spécifiée, le routeur génère un avertissement.

Exemple :

set protocols pim igmp watermark-warning 500

Commandes spécifiques à l'interface

set protocols pim interface <interface> igmp

Activer IGMP sur l'interface spécifiée.

Exemple :

set protocols pim interface eth0 igmp
set protocols pim interface <interface> igmp disable

Désactiver administrativement IGMP sur l'interface spécifiée sans supprimer la configuration IGMP existante.

Exemple :

set protocols pim interface eth0 igmp disable
set protocols pim interface <interface> igmp join <multicast-address> source-address <IP-address>

Configurer l'interface pour rejoindre un canal (S,G) spécifique.

Spécifiez à la fois l'adresse IP multicast (G) et l'adresse IP source (S). Chaque commande rejoint un canal (S,G). Pour rejoindre plusieurs canaux partageant le même groupe, répétez la commande avec différentes valeurs de source-address.

Exemple :

set protocols pim interface eth0 igmp join 232.1.1.100 source-address 192.0.2.50
set protocols pim interface eth0 igmp join 232.1.1.100 source-address 192.0.2.51
set protocols pim interface <interface> igmp query-interval <1-1800>

Configurer l'intervalle de requête Hôte IGMP, en secondes, sur l'interface spécifiée.

Cette configuration détermine l'intervalle entre les requêtes IGMP envoyées par le routeur pour découvrir quels groupes multicast ont des auditeurs actifs sur le réseau connecté.

Exemple :

set protocols pim interface eth1 igmp query-interval 125
set protocols pim interface <interface> igmp query-max-response-time <10-250>

Configurer le temps maximum de réponse de requête IGMP, en décisecondes, sur l'interface spécifiée.

Cette valeur est insérée dans les requêtes IGMP et spécifie le temps maximum dont les hôtes disposent pour répondre avec un rapport de membre. Si aucun rapport n'est reçu dans la fenêtre spécifiée, PIM suppose qu'il n'y a plus d'auditeurs locaux actifs et peut expirer l'état associé (*,G) ou (S,G) (voir RFC 7761, Section 4.1).

Exemple :

set protocols pim interface eth0 igmp query-max-response-time 50
set protocols pim interface <interface> igmp version <2-3>

Configurer la version IGMP sur l'interface spécifiée.

La version par défaut est la version 3.

Exemple :

set protocols pim interface eth0 igmp version 2

Exemple

L'exemple suivant illustre un déploiement de multicast PIM Sparse Mode (PIM-SM) de base sur trois routeurs, montrant comment configurer le rôle de chaque routeur dans un domaine multicast. Ensemble, les trois routeurs forment un chemin complet de distribution multicast depuis les sources vers les récepteurs, avec un routeur agissant comme point de rendez-vous (RP).

Topologie et rôles

  • Router 1 est le LHR.

  • Router 3 est le RP.

  • Router 2 est le FHR.

Router 1 :

set interfaces ethernet eth2 address '198.51.100.1/30'
set interfaces ethernet eth1 address '192.0.2.1/24'
set protocols ospf area 0 network '198.51.100.0/30'
set protocols ospf area 0 network '192.0.2.0/24'
set protocols pim interface eth1
set protocols pim interface eth1 igmp
set protocols pim interface eth2
set protocols pim rp address 203.0.113.1 group '224.0.0.0/4'

Router 3 :

set interfaces dummy dum0 address '203.0.113.1/32'
set interfaces ethernet eth0 address '198.51.100.2/30'
set interfaces ethernet eth1 address '198.51.100.5/30'
set protocols ospf area 0 network '198.51.100.0/30'
set protocols ospf area 0 network '203.0.113.1/32'
set protocols ospf area 0 network '198.51.100.4/30'
set protocols pim interface dum0
set protocols pim interface eth0
set protocols pim interface eth1
set protocols pim rp address 203.0.113.1 group '224.0.0.0/4'

Router 2 :

set interfaces ethernet eth1 address '203.0.113.129/25'
set interfaces ethernet eth2 address '198.51.100.6/30'
set protocols ospf area 0 network '203.0.113.128/25'
set protocols ospf area 0 network '198.51.100.4/30'
set protocols pim interface eth1
set protocols pim interface eth2
set protocols pim rp address 203.0.113.1 group '224.0.0.0/4'
