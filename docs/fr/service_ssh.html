SSH

SSH est un protocole réseau cryptographique pour exécuter des services réseau de manière sécurisée sur un réseau non sécurisé. Le port TCP standard pour SSH est le 22. L'exemple le plus connu d'application est pour la connexion distante à des systèmes informatiques par les utilisateurs.

SSH fournit un canal sécurisé sur un réseau non sécurisé dans une architecture client-serveur, connectant une application cliente SSH avec un serveur SSH. Les applications courantes incluent la connexion distante en ligne de commande et l'exécution distante de commandes, mais tout service réseau peut être sécurisé avec SSH. La spécification du protocole distingue deux grandes versions, appelées SSH-1 et SSH-2.

L'application la plus visible du protocole est pour l'accès aux comptes de shell sur les systèmes Unix-like, mais il est utilisé de manière limitée sur Windows également. En 2015, Microsoft a annoncé qu'ils incluraient un support natif pour SSH dans une future version.

SSH a été conçu comme remplacement de Telnet et des protocoles de shell non sécurisés tels que les protocoles Berkeley rlogin, rsh et rexec. Ces protocoles transmettent des informations, notamment les mots de passe, en clair, ce qui les rend vulnérables à l'interception et à la divulgation à l'aide de l'analyse de paquets. La cryptographie utilisée par SSH vise à fournir la confidentialité et l'intégrité des données sur un réseau non sécurisé, tel qu'Internet.

Remarque

VyOS 1.1 permettait la connexion en tant qu'utilisateur root. Cela a été supprimé en raison d'une sécurité plus stricte dans VyOS 1.2.

SSH Authentification basée sur les clés

Configuration

set service ssh port <port>

Activer SSH ne nécessite que vous spécifiez le port <port> que vous souhaitez que SSH écoute. Par défaut, SSH fonctionne sur le port 22.

set service ssh listen-address <address>

Spécifier l'adresse IPv4/IPv6 d'écoute du serveur SSH. Plusieurs adresses peuvent être définies.

set service ssh cipher <cipher>

Définir les chiffrements autorisés utilisés pour la connexion SSH. Un nombre de chiffrements autorisés peut être spécifié, utiliser plusieurs occurrences pour autoriser plusieurs chiffrements.

Liste des chiffrements pris en charge : 3des-cbc, aes128-cbc, aes192-cbc, aes256-cbc, aes128-ctr, aes192-ctr, aes256-ctr, aes128-gcm@openssh.com, aes256-gcm@openssh.com, chacha20-poly1305@openssh.com

set service ssh disable-password-authentication

Désactiver l'authentification basée sur le mot de passe. Connexion uniquement via les clés SSH. Cela renforce la sécurité !

set service ssh fido pin-required

Exiger des clés FIDO2 pour attester qu'un utilisateur a été vérifié (par exemple, via un code PIN).

set service ssh fido touch-required

Exiger des clés FIDO2 pour attester qu'un utilisateur est physiquement présent.

VyOS prend en charge l'authentification SSH à l'aide de clés FIDO2 générées par OpenSSH. Deux types de clés FIDO2 sont pris en charge par OpenSSH : ed25519-sk, ecdsa-sk

Exemple de génération de clé SSH FIDO2 générique :

ssh-keygen -t ecdsa-sk -O verify-required -C "fido2-ssh-key"
Pendant la génération de la clé, OpenSSH fera :

  • Demander la présence de l'utilisateur (par exemple, un contact physique ou une confirmation)

  • Optionnellement demander la vérification de l'utilisateur (code PIN), si prise en charge par l'authentificateur

  • Créer un fichier de gestion de clé local et une clé publique correspondante (.pub)

Les données privées de la clé ne quittent jamais l'appareil authentificateur.

Exemple de configuration VyOS :

# Générer une clé SSH FIDO2 sur le système client
# Copier la clé publique vers l'instance VyOS
set system login user vyos authentication public-keys fido key '<public-key>'
set system login user vyos authentication public-keys fido type '[email protected]'
set service ssh fido touch-required

Vous pouvez maintenant vous connecter au système en utilisant : ssh -i ~/.ssh/id_fido_key vyos@192.0.2.1

set service ssh disable-host-validation

Désactiver la validation de l'hôte via des recherches DNS inverses - peut accélérer le temps de connexion lorsque la recherche inverse n'est pas possible.

set service ssh mac <mac>

Spécifie les algorithmes de codes d'authentification de message (MAC) disponibles. L'algorithme MAC est utilisé dans la version 2 du protocole pour la protection de l'intégrité des données. Plusieurs algorithmes peuvent être fournis en utilisant plusieurs commandes, en définissant un algorithme par commande.

Liste des MACs prises en charge : hmac-md5, hmac-md5-96, hmac-ripemd160, hmac-sha1, hmac-sha1-96, hmac-sha2-256, hmac-sha2-512, umac-64@openssh.com, umac-128@openssh.com, hmac-md5-etm@openssh.com, hmac-md5-96-etm@openssh.com, hmac-ripemd160-etm@openssh.com, hmac-sha1-etm@openssh.com, hmac-sha1-96-etm@openssh.com, hmac-sha2-256-etm@openssh.com, hmac-sha2-512-etm@openssh.com, umac-64-etm@openssh.com, umac-128-etm@openssh.com

set service ssh access-control <allow | deny> <group | user> <name>

Ajouter une directive de contrôle d'accès pour autoriser ou interdire des utilisateurs et des groupes. Les directives sont traitées dans l'ordre de priorité suivant : deny-users, allow-users, deny-groups et allow-groups.

set service ssh client-keepalive-interval <interval>

Spécifier l'intervalle de temporisation pour le message de keepalive en secondes.

set service ssh key-exchange <kex>

Spécifier les algorithmes d'échange de clés autorisés.

Liste des algorithmes pris en charge : diffie-hellman-group1-sha1, diffie-hellman-group14-sha1, diffie-hellman-group14-sha256, diffie-hellman-group16-sha512, diffie-hellman-group18-sha512, diffie-hellman-group-exchange-sha1, diffie-hellman-group-exchange-sha256, ecdh-sha2-nistp256, ecdh-sha2-nistp384, ecdh-sha2-nistp521, curve25519-sha256 et curve25519-sha256@libssh.org.

set service ssh loglevel <quiet | fatal | error | info | verbose>

Définir le niveau de journalisation sshd. La valeur par défaut est info.

set service ssh vrf <name>

Spécifier le nom de l'instance de VRF.

set service ssh pubkey-accepted-algorithm <name>

Spécifie les algorithmes de signature qui seront acceptés pour l'authentification par clé publique

Liste des algorithmes pris en charge : ssh-ed25519, ssh-ed25519-cert-v01@openssh.com, sk-ssh-ed25519@openssh.com, sk-ssh-ed25519-cert-v01@openssh.com, ecdsa-sha2-nistp256, ecdsa-sha2-nistp256-cert-v01@openssh.com, ecdsa-sha2-nistp384, ecdsa-sha2-nistp384-cert-v01@openssh.com, ecdsa-sha2-nistp521, ecdsa-sha2-nistp521-cert-v01@openssh.com, sk-ecdsa-sha2-nistp256@openssh.com, sk-ecdsa-sha2-nistp256-cert-v01@openssh.com, webauthn-sk-ecdsa-sha2-nistp256@openssh.com, ssh-dss, ssh-dss-cert-v01@openssh.com, ssh-rsa, ssh-rsa-cert-v01@openssh.com, rsa-sha2-256, rsa-sha2-256-cert-v01@openssh.com, rsa-sha2-512, rsa-sha2-512-cert-v01@openssh.com

set service ssh trusted-user-ca <name>

Spécifier le nom de la paire de clés OpenSSH qui agit comme autorité de certification et sera utilisée pour vérifier les certificats d'utilisateurs.

Vous pouvez l'utiliser en ajoutant la paire de clés OpenSSH sous le sous-système PKI.

Exemple :

# Générer une paire de clés agissant comme CA
$ ssh-keygen -f vyos-ssh-ca.key

# Générer une clé pour l'utilisateur : vyos_testca
$ ssh-keygen -f vyos_testca  -C "[email protected]"

# Signer la clé publique de l'utilisateur vyos_testca et insérer les noms principaux : vyos, vyos_testca
# avec une durée de vie de deux semaines - après quoi la clé n'est plus utilisable
$ ssh-keygen -s vyos-ssh-ca.key -I [email protected] -n vyos,vyos_testca -V +2w vyos_testca.pub

$ set system login user vyos_testca
$ set pki openssh test_ca public key AAAAB3N.....
$ set pki openssh test_ca public type ssh-rsa
$ set service ssh trusted-user-ca test_ca

Vous pouvez maintenant vous connecter au système en utilisant : ssh -i vyos_testca vyos_testca@vyos.test.com

Protection dynamique

Protège l'hôte contre les attaques de force brute contre SSH. Les messages d'enregistrement sont analysés ligne par ligne, pour des modèles reconnus. Si une attaque, telle que plusieurs échecs de connexion en quelques secondes, est détectée, l'IP offensive est bloquée. Les auteurs sont débloqués après un intervalle défini.

set service ssh dynamic-protection

Autoriser la protection dynamique ssh.

set service ssh dynamic-protection allow-from <address | prefix>

Liste blanche d'adresses et de réseaux. Toujours autoriser les connexions entrantes depuis ces systèmes.

set service ssh dynamic-protection block-time <sec>

Bloquer l'IP source en secondes. Les blocages ultérieurs augmentent d'un facteur de 1,5 La valeur par défaut est de 120.

set service ssh dynamic-protection detect-time <sec>

Enregistrer l'IP source pendant un certain temps avant de réinitialiser leur score. La valeur par défaut est de 1800.

set service ssh dynamic-protection threshold <sec>

Bloquer l'IP source lorsqu'un score cumulatif d'attaque dépasse le seuil. La valeur par défaut est de 30.

Opération

restart ssh

Redémarrer le processus daemon SSH, la session actuelle n'est pas affectée, seul le daemon en arrière-plan est redémarré.

generate ssh server-key

Régénérer la partie clé publique/priveé que SSH utilise pour sécuriser les connexions.

Remarque

Les fichiers known_hosts déjà appris des clients doivent être mis à jour car la clé publique changera.

generate ssh client-key /path/to/private_key

Régénérer un fichier de clé publique/priveé connu qui peut être utilisé pour se connecter à d'autres services (par exemple, cache RPKI).

generate public-key-command user <username> path <location>

Générer les commandes du mode configuration pour ajouter une clé publique pour Authentification basée sur les clés. <location> peut être un chemin local ou une URL pointant vers un fichier distant.

Les protocoles distants pris en charge sont FTP, FTPS, HTTP, HTTPS, SCP/SFTP et TFTP.

Exemple :

alyssa@vyos:~$ generate public-key-command user alyssa path sftp://example.net/home/alyssa/.ssh/id_rsa.pub
# Pour ajouter cette clé en tant que clé intégrée, exécutez les commandes suivantes :
configure
set system login user alyssa authentication public-keys [email protected] key AAA...
set system login user alyssa authentication public-keys [email protected] type ssh-rsa
commit
save
exit

ben@vyos:~$ generate public-key-command user ben path ~/.ssh/id_rsa.pub
# Pour ajouter cette clé en tant que clé intégrée, exécutez les commandes suivantes :
configure
set system login user ben authentication public-keys ben@vyos key AAA...
set system login user ben authentication public-keys ben@vyos type ssh-dss
commit
save
exit
