WireGuard

WireGuard est un VPN extrêmement simple, rapide et moderne qui utilise la cryptographie de pointe. Consultez https://www.wireguard.com pour plus d'informations.

Clés

WireGuard nécessite une paire de clés, comprenant une clé privée pour décrypter le trafic entrant, et une clé publique pour les pairs afin d'encrypter le trafic sortant.

Générer une paire de clés

generate pki wireguard key-pair

Générer une paire de clés : une clé publique et une clé privée.

Note

Cette commande n'affiche que les clés dans votre console. Elle ne les stocke pas dans le système ni ne les applique à la configuration du système.

vyos@vyos:~$ generate pki wireguard key-pair
Clé privée : iJJyEARGK52Ls1GYRCcFvPuTj7WyWYDo//BknoDU0XY=
Clé publique : EKY0dxRrSD98QHjfHOK13mZ5PJ7hnddRZt5woB3szyw=
generate pki wireguard key-pair install interface <interface>

Générer une paire de clés et afficher la commande d'attribution de la clé privée pour l'interface spécifiée.

vyos@vyos:~$ generate pki wireguard key-pair install interface wg10
"generate" commande CLI exécutée depuis le niveau opérationnel.
La clé privée générée n'est pas automatiquement ajoutée à la configuration VyOS, utilisez les commandes suivantes en mode configuration pour installer la clé :

set interfaces wireguard wg10 private-key '4Krkv8h6NkAYMMaBWI957yYDJDMvj9URTHstdlOcDU0='

La clé publique correspondante à utiliser sur le système pair est : 'UxDsYT6EnpTIOKUzvMlw2p0sNOKQvFxEdSVrnNrX1Ro='

Note

Si vous invoquez cette commande depuis le mode configuration avec le préfixe run, la clé privée générée est automatiquement assignée à l'interface spécifiée.

vyos@vyos# run generate pki wireguard key-pair install interface wg10
"generate" commande CLI exécutée depuis une session de configuration.
La clé privée générée a été importée dans le CLI !

Utilisez la commande suivante pour vérifier : show interfaces wireguard wg10
La clé publique correspondante à utiliser sur le système pair est : '7d9KwabjLhHpJiEJeIGd0CBlao/eTwFOh6xyCovTfG8='

Optionnel

generate pki wireguard preshared-key

Générer une clé prédéfinie.

La clé prédéfinie est optionnelle. Elle ajoute une couche supplémentaire de cryptographie symétrique au-dessus de la cryptographie asymétrique.

vyos@vyos:~$ generate pki wireguard preshared-key
Clé prédéfinie : OHH2EwZfMNK+1L6BXbYw3bKCtMrfjpR4mCAEeBlFnRs=
generate pki wireguard preshared-key install interface <interface> peer <peer>

Générer une clé prédéfinie et afficher la commande d'attribution de la clé pour le pair spécifié.

vyos@vyos:~$ generate pki wireguard preshared-key install interface wg10 peer foo
"generate" commande CLI exécutée depuis le niveau opérationnel.
La clé prédéfinie générée n'est pas stockée dans le CLI, utilisez les commandes en mode configuration pour installer la clé :

set interfaces wireguard wg10 peer foo preshared-key '32vQ1w1yFKTna8n7Gu7EimubSe2Y63m8bafz55EG3Ro='

Clé prédéfinie : +LuaZ8W6DjsDFJFX3jJzoNqrsXHhvq08JztM9z8LHCs=

Note

Si vous invoquez cette commande depuis le mode configuration avec le préfixe run, la clé générée est automatiquement assignée au pair spécifié.

Configuration de l'interface

La prochaine étape consiste à configurer votre interface WireGuard locale et à définir les réseaux que vous souhaitez tunneliser (allowed-ips).

Si votre système n'initie que des connexions, spécifier le port d'écoute est optionnel. Si votre système accepte des connexions entrantes, vous devez définir un port pour que les pairs puissent se connecter. Sinon, WireGuard sélectionne un port aléatoire à chaque redémarrage, ce qui peut empêcher vos pairs de se connecter si ce port n'est pas autorisé dans vos règles de pare-feu.

Pour configurer un tunnel WireGuard, vous avez également besoin de la clé publique de votre pair.

Note

La clé publique spécifiée dans le bloc de configuration du pair est toujours celle du pair distant, jamais celle de votre propre système.

Configuration côté local

Le côté local est configuré avec les paramètres suivants :

  • Adresse IP de l'interface WireGuard locale : 10.1.0.1/30

  • Port d'écoute local : 51820

  • Nom du pair distant : to-wg02

  • Point de terminaison du pair distant : 192.0.2.1 sur le port 51820

  • Clé publique du pair distant : XMrlPykaxhdAAiSjhtPlvi30NVkvLQliQuKP7AI7CyI=

  • Réseaux autorisés : 192.168.2.0/24

set interfaces wireguard wg01 address '10.1.0.1/30'
set interfaces wireguard wg01 description 'VPN-to-wg02'
set interfaces wireguard wg01 peer to-wg02 allowed-ips '192.168.2.0/24'
set interfaces wireguard wg01 peer to-wg02 address '192.0.2.1'
set interfaces wireguard wg01 peer to-wg02 port '51820'
set interfaces wireguard wg01 peer to-wg02 public-key 'XMrlPykaxhdAAiSjhtPlvi30NVkvLQliQuKP7AI7CyI='
set interfaces wireguard wg01 port '51820'

set protocols static route 192.168.2.0/24 interface wg01

Pour envoyer le trafic destiné à 192.168.2.0/24 via l'interface WireGuard (wg01), configurez une route statique. Plusieurs adresses IP ou réseaux peuvent être définis et routés. Le dernier contrôle est effectué contre allowed-ips, qui permet ou rejette le trafic.

Avertissement

Vous ne pouvez pas attribuer le même allowed-ips à plusieurs pairs WireGuard. C'est une restriction de conception stricte. Pour plus d'informations, consultez le liste de diffusion WireGuard.

set interfaces wireguard <interface> private-key <private-key>

Assigner une clé privée à l'interface WireGuard spécifiée.

Exemple :

set interfaces wireguard wg01 private-key 'iJJyEARGK52Ls1GYRCcFvPuTj7WyWYDo//BknoDU0XY='

Pour générer une clé privée, utilisez la commande suivante : generate pki wireguard key-pair.

Pour afficher la clé publique assignée à l'interface afin de la partager avec un pair, utilisez la commande suivante : show interfaces wireguard wg01 public-key.

set interfaces wireguard <interface> per-client-thread

Activer le mode thread pour toutes les instances NAPI de l'appareil réseau spécifié.

L'activation du mode thread n'affecte pas l'opération de l'appareil et peut être effectuée pendant que l'appareil est actif.

Ce mode est désactivé par défaut.

Exemple :

set interfaces wireguard wg01 per-client-thread

Exceptions de pare-feu

Pour permettre le trafic WireGuard à travers l'interface WAN, créez une exception de pare-feu :

set firewall ipv4 name OUTSIDE_LOCAL rule 10 action accept
set firewall ipv4 name OUTSIDE_LOCAL rule 10 description 'Allow established/related'
set firewall ipv4 name OUTSIDE_LOCAL rule 10 state established enable
set firewall ipv4 name OUTSIDE_LOCAL rule 10 state related enable
set firewall ipv4 name OUTSIDE_LOCAL rule 20 action accept
set firewall ipv4 name OUTSIDE_LOCAL rule 20 description WireGuard_IN
set firewall ipv4 name OUTSIDE_LOCAL rule 20 destination port 51820
set firewall ipv4 name OUTSIDE_LOCAL rule 20 log enable
set firewall ipv4 name OUTSIDE_LOCAL rule 20 protocol udp

Vérifiez que le groupe de pare-feu OUTSIDE_LOCAL est appliqué à l'interface WAN et dans une direction d'entrée (locale).

set firewall ipv4 input filter rule 10 action jump
set firewall ipv4 input filter rule 10 jump-target 'OUTSIDE_LOCAL'
set firewall ipv4 input filter rule 10 inbound-interface name 'eth0'

Vérifiez que vos règles de pare-feu autorisent le trafic. Si c'est le cas, votre VPN WireGuard devrait fonctionner.

wg01# ping 192.168.1.1
PING 192.168.1.1 (192.168.1.1) 56(84) bytes of data.
64 bytes from 192.168.1.1: icmp_seq=1 ttl=64 time=1.16 ms
64 bytes from 192.168.1.1: icmp_seq=2 ttl=64 time=1.77 ms

wg02# ping 192.168.2.1
PING 192.168.2.1 (192.168.2.1) 56(84) bytes of data.
64 bytes from 192.168.2.1: icmp_seq=1 ttl=64 time=4.40 ms

Une couche supplémentaire de cryptographie symétrique peut être utilisée au-dessus de la cryptographie asymétrique. Cela est optionnel.

vyos@vyos:~$ generate pki wireguard preshared-key
Clé prédéfinie : rvVDOoc2IYEnV+k5p7TNAmHBMEGTHbPU8Qqg8c/sUqc=

Copiez la clé, car elle n'est pas stockée localement. Étant donné qu'il s'agit d'une clé symétrique, seul vous et votre pair devriez connaître son contenu. Distribuez la clé en toute sécurité.

wg01# set interfaces wireguard wg01 peer to-wg02 preshared-key 'rvVDOoc2IYEnV+k5p7TNAmHBMEGTHbPU8Qqg8c/sUqc='
wg02# set interfaces wireguard wg01 peer to-wg01 preshared-key 'rvVDOoc2IYEnV+k5p7TNAmHBMEGTHbPU8Qqg8c/sUqc='

Accès à distance (road warrior)

Avec WireGuard, une configuration de VPN road warrior est similaire à un VPN site à site. Elle omet simplement les déclarations address et port.

Dans l'exemple suivant, les adresses IP des clients distants sont définies dans chaque configuration de pair. Cela permet aux pairs de communiquer entre eux.

De plus, cette configuration utilise un indicateur persistent-keepalive défini à 15 secondes pour maintenir la connexion active. Cette configuration est principalement pertinente si un pair est derrière un NAT et ne peut pas être atteint si la connexion est perdue. Pour une efficacité, la valeur doit être inférieure au délai d'expiration UDP.

wireguard wg01 {
    address 10.172.24.1/24
    address 2001:db8:470:22::1/64
    description RoadWarrior
    peer MacBook {
        allowed-ips 10.172.24.30/32
        allowed-ips 2001:db8:470:22::30/128
        persistent-keepalive 15
        pubkey F5MbW7ye7DsoxdOaixjdrudshjjxN5UdNV+pGFHqehc=
    }
    peer iPhone {
        allowed-ips 10.172.24.20/32
        allowed-ips 2001:db8:470:22::20/128
        persistent-keepalive 15
        pubkey BknHcLFo8nOo8Dwq2CjaC/TedchKQ0ebxC7GYn7Al00=
    }
    port 2224
    private-key OLTQY3HuK5qWDgVs6fJR093SwPgOmCKkDI1+vJLGoFU=
}

Voici la configuration du pair iPhone. Le paramètre AllowedIPs wildcard indique tout le trafic IPv4 et IPv6 via la connexion VPN.

[Interface]
PrivateKey = ARAKLSDJsadlkfjasdfiowqeruriowqeuasdf=
Address = 10.172.24.20/24, 2001:db8:470:22::20/64
DNS = 10.0.0.53, 10.0.0.54

[Peer]
PublicKey = RIbtUTCfgzNjnLNPQ/ulkGnnB2vMWHm7l2H/xUfbyjc=
AllowedIPs = 0.0.0.0/0, ::/0
Endpoint = 192.0.2.1:2224
PersistentKeepalive = 15

Pour activer le tunnel partagé, spécifiez les sous-réseaux distants. Cela garantit que seul le trafic destiné au site distant est envoyé via le tunnel, tandis que tout le reste du trafic reste inchangé.

[Interface]
PrivateKey = 8Iasdfweirousd1EVGUk5XsT+wYFZ9mhPnQhmjzaJE6Go=
Address = 10.172.24.30/24, 2001:db8:470:22::30/64

[Peer]
PublicKey = RIbtUTCfgzNjnLNPQ/ulkGnnB2vMWHm7l2H/xUfbyjc=
AllowedIPs = 10.172.24.30/24, 2001:db8:470:22::/64
Endpoint = 192.0.2.1:2224
PersistentKeepalive = 15

Clients d'accès à distance (road warrior)

Certaines personnes connectent leurs appareils mobiles à leur routeur VyOS à l'aide de WireGuard. Pour simplifier le déploiement, générez une configuration par appareil mobile à partir du CLI VyOS.

Avertissement

En termes de sécurité, il n'est pas recommandé de permettre à un tiers de créer et de partager la clé privée pour une connexion sécurisée. Vous devriez créer la partie privée vous-même et ne distribuer que la clé publique.

generate wireguard client-config <name> interface <interface> server <ip|fqdn> address <client-ip>

Générer un fichier de configuration client qui établit une connexion à l'interface spécifiée.

La clé publique de l'interface spécifiée est automatiquement incluse dans le fichier de configuration.

La commande génère également un fragment de configuration pouvant être copié dans le CLI VyOS. Le <name> que vous fournissez sera utilisé comme nom de pair dans le fragment.

Vous devez également spécifier l'adresse IP ou le FQDN du serveur auquel le client se connecte. Le paramètre address peut être utilisé deux fois pour attribuer à la fois une adresse IPv4 (/32) et une adresse IPv6 (/128) au client.
