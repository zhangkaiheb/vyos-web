MACsec

MACsec est une norme IEEE (IEEE 802.1AE) pour la sécurité MAC, introduite en 2006. Elle permet une connectivité protocol-independent entre deux hôtes, fournissant la confidentialité des données, l'authenticité et l'intégrité à l'aide de chiffrements GCM-AES. MACsec fonctionne au niveau Ethernet comme un protocole de couche 2 et sécurise le trafic dans les réseaux de couche 2, y compris les demandes DHCP et ARP. Elle ne compete pas avec d'autres solutions de sécurité, telles que IPsec (couche 3) ou TLS (couche 4), car chacune traite des cas d'utilisation distincts.

Configuration

Configuration commune de l'interface

set interfaces macsec <interface> address <address | dhcp | dhcpv6>

Configurez l'interface avec une ou plusieurs adresses IP.

Les options suivantes sont disponibles :

  • address: Attribuez une ou plusieurs adresses IPv4 ou IPv6 à l'interface. Par exemple, utilisez 192.0.2.1/24 pour IPv4 ou 2001:db8::1/64 pour IPv6.

  • dhcp: L'interface obtient une adresse IPv4 d'un serveur DHCP sur le même segment réseau.

  • dhcpv6: L'interface obtient une adresse IPv6 d'un serveur DHCPv6 sur le même segment réseau.

Remarque

Si l'interface obtient une adresse IPv4 via DHCP, et qu'il faut apporter des ajustements spécifiques avant/après l'obtention de l'adresse IP, utilisez les scripts de raccordement :

  • /config/scripts/dhcp-client/pre-hooks.d/

  • /config/scripts/dhcp-client/post-hooks.d/

Exemple :

set interfaces macsec macsec0 address 192.0.2.1/24
set interfaces macsec macsec0 address 2001:db8::1/64
set interfaces macsec macsec0 address dhcp
set interfaces macsec macsec0 address dhcpv6
set interfaces macsec <interface> description <description>

Configurez un alias clair et descriptif pour l'interface.

Cet alias apparaît dans la commande show interfaces et les outils de surveillance basés sur SNMP.

Exemple :

set interfaces macsec macsec0 description 'This is an interface running on VyOS.'
set interfaces macsec <interface> disable

Désactivez l'interface.

L'interface sera définie à l'état administrativement down (A/D).

Exemple :

set interfaces macsec macsec0 disable
set interfaces macsec <interface> disable-flow-control

Désactivez le contrôle de flux Ethernet (IEEE 802.3x frames de pause) sur l'interface.

Le contrôle de flux Ethernet, défini par la norme IEEE 802.3x, temporairement arrête la transmission des données pour éviter la perte de paquets pendant la congestion du réseau. Par exemple, lorsqu'un émetteur transmet des données plus rapidement que le récepteur ne peut les traiter.

La désactivation du contrôle de flux Ethernet signifie que l'interface ne signalera pas à l'appareil connecté de suspendre la transmission et supprimera les paquets si elle est submergée.

Exemple :

set interfaces macsec macsec0 disable-flow-control
set interfaces macsec <interface> disable-link-detect

Désactivez la détection d'état de lien physique sur l'interface, telle que lorsqu'un câble est débranché.

Par défaut, l'interface détecte les changements d'état de lien physique.

Exemple :

set interfaces macsec macsec0 disable-link-detect
set interfaces macsec <interface> mac <xx:xx:xx:xx:xx:xx>

Configurez une adresse MAC personnalisée sur l'interface.

Exemple :

set interfaces macsec macsec0 mac '00:53:01:02:03:04'
set interfaces macsec <interface> mtu <mtu>

Configurez le MTU sur l'interface.

Cette valeur définit la taille maximale des paquets, en octets, que l'interface transmet sans fragmentation.

Exemple :

set interfaces macsec macsec0 mtu 1600
set interfaces macsec <interface> ip adjust-mss <mss | clamp-mss-to-pmtu>

Configurez la MSS annoncée dans les paquets TCP SYN sortants sur l'interface spécifiée.

En limitant la valeur MSS dans les paquets TCP SYN, vous informez explicitement l'autre côté qu'il ne doit pas envoyer des paquets plus grands que cette taille. Cela empêche les problèmes de connexion qui surviennent lorsque la découverte du MTU de chemin (PMTUD) échoue.

Les options suivantes sont disponibles :

  • mss: Définissez la MSS à une valeur spécifique, en octets. Utilisez cette option si vous avez besoin d'imposer une MSS spécifique, par exemple pour résoudre des problèmes de connectivité ou satisfaire des exigences réseau spécifiques.

  • clamp-mss-to-pmtu: Le routeur calcule automatiquement la MSS à être la MTU de l'interface moins 40 octets pour le trafic IPv4 (20 octets pour l'en-tête IPv4 et 20 octets pour l'en-tête TCP). Cette option est recommandée pour configurer automatiquement la bonne valeur.

set interfaces macsec <interface> ip arp-cache-timeout

Configurez pendant combien de temps une entrée ARP reste valide après avoir appris une correspondance entre une adresse IP et une adresse MAC sur cette interface.

La durée par défaut est de 30 secondes.

Une entrée ARP reste valide si elle reçoit un feedback positif des protocoles de niveau supérieur.

Exemple :

set interfaces macsec macsec0 ip arp-cache-timeout 180
set interfaces macsec <interface> ip disable-arp-filter

Configurez le filtrage ARP sur cette interface.

Comportement par défaut : Le noyau répond aux demandes ARP sur cette interface seulement si le trafic serait routé de retour à l'expéditeur ARP via cette interface spécifique.

Si configuré : Le noyau répond aux demandes ARP sur cette interface pour toute adresse IP configurée sur l'hôte local, indépendamment de l'interface spécifique à laquelle cette adresse IP est assignée, et indépendamment de la table de routage. Cela reflète le concept Linux selon lequel les adresses IP appartiennent à l'hôte, et non à des interfaces individuelles.

Exemple :

set interfaces macsec macsec0 ip disable-arp-filter
set interfaces macsec <interface> ip disable-forwarding

Configurez le comportement de l'interface en tant qu'hôte ou routeur.

Si configuré, l'interface passe en mode hôte, et le transfert IPv4 est désactivé sur celle-ci.

Exemple :

set interfaces macsec macsec0 ip disable-forwarding
set interfaces macsec <interface> ip enable-directed-broadcast

Configurez si les paquets broadcast directs IP reçus sur cette interface doivent être transmis.

Comportement par défaut : Les paquets broadcast directs IP sont supprimés.

Si configuré : Les paquets broadcast directs IP sont transmis à tous les hôtes sur le sous-réseau de destination, conformément à RFC 1812 et RFC 2644.

Exemple :

set interfaces macsec macsec0 ip enable-directed-broadcast
set interfaces macsec <interface> ip enable-arp-accept

Configurez comment traiter les ARPs gratuits sur cette interface.

Si configuré, une correspondance IP-MAC est ajoutée au tableau ARP en fonction des demandes ou réponses ARP gratuit.

Note

Si le tableau ARP contient déjà l'adresse IP provenant d'un ARP gratuit, son entrée est mise à jour, indépendamment du fait que cette configuration soit activée.

Exemple :

set interfaces macsec macsec0 ip enable-arp-accept
set interfaces macsec <interface> ip enable-arp-announce

Configurez la sélection de l'adresse IP source pour les demandes ARP sur cette interface.

Comportement par défaut : Le noyau peut utiliser n'importe quelle adresse IP possédée par l'hôte comme adresse IP source dans les demandes ARP sur cette interface.

Si configuré : Le noyau essaie d'abord de sélectionner une adresse IP source configurée sur l'interface partageant un sous-réseau commun avec l'adresse IP cible. Si aucun tel sous-réseau n'existe, le noyau sélectionne l'adresse IP qu'il utiliserait normalement (en fonction de la table de routage pour atteindre la destination cible).

Exemple :

set interfaces macsec macsec0 ip enable-arp-announce
set interfaces macsec <interface> ip enable-arp-ignore

Configurez quelles demandes ARP seront ignorées sur cette interface.

Comportement par défaut : Le noyau répond aux demandes ARP pour toutes les adresses IP locales, indépendamment de l'interface à laquelle elles sont assignées.

Si configuré : Le noyau répond aux demandes ARP uniquement si l'adresse IP cible est assignée à cette interface spécifique.

Exemple :

set interfaces macsec macsec0 ip enable-arp-ignore
set interfaces macsec <interface> ip enable-proxy-arp

Configurez le proxy ARP sur cette interface.

Si configuré, le routeur (noyau) intercepte les demandes ARP pour des adresses IP non locales et répond avec l'MAC de l'interface qui a reçu la demande. Les paquets ultérieurs destinés à ces adresses IP sont acheminés vers leurs destinations réelles sur les sous-réseaux distants.

Exemple :

set interfaces macsec macsec0 ip enable-proxy-arp
set interfaces macsec <interface> ip proxy-arp-pvlan

Configurez le proxy ARP local sur l'interface.

Si configuré, le routeur (noyau) répond aux demandes ARP sur cette interface VLAN même si l'adresse IP cible se trouve sur le même sous-réseau et interface.

Cela est utilisé pour soutenir les exigences de isolation réseau (RFC 3069) pour les VLAN privés (PVLANs). Dans les configurations PVLAN, les hôtes sur les ports isolés ne sont PAS autorisés à communiquer directement entre eux au niveau 2, mais ils peuvent communiquer avec le routeur upstream.

En répondant aux demandes ARP inter-hôtes avec sa propre adresse MAC, le routeur (noyau) dirige le trafic inter-hôtes via lui-même plutôt que directement entre les hôtes.

Note

Cette commande fonctionne indépendamment et ne nécessite pas l'activation du proxy ARP standard sur l'interface.

Le proxy ARP local est également connu sous les noms suivants :

  • VLAN agrégé (RFC 3069).

  • VLAN privé (Cisco, Allied Telesyn).

  • Filtrage de port source ou isolation de port (Hewlett-Packard).

  • Transfert forcé MAC (Ericsson).

set interfaces macsec <interface> ip source-validation <strict | loose | disable>

Configurez la validation de l'adresse IP source à l'aide de RPF sur cette interface, comme spécifié dans RFC 3704.

Les options suivantes sont disponibles :

  • strict : Chaque paquet entrant est vérifié contre la base de données de routage (FIB). Si l'interface n'est pas le meilleur chemin de retour vers cette source, la validation échoue et le paquet est supprimé.

  • loose : Chaque paquet entrant est vérifié contre la base de données de routage (FIB). Si l'adresse IP source est inatteignable via n'importe quelle interface, la validation échoue.

  • disable : Aucune validation de l'adresse IP source n'est effectuée. Tous les paquets entrants sont acceptés.

Le RFC 3704 recommande d'activer le mode strict pour empêcher le spoofing d'IP, comme les attaques DDoS. Pour des scénarios de routage asymétrique ou autres complexes, utilisez le mode loose.

set interfaces macsec <interface> ipv6 address autoconf

Configurez l'interface pour obtenir automatiquement une adresse IPv6 à l'aide de SLAAC, comme spécifié dans RFC 4862.

Les hôtes IPv6 peuvent se configurer automatiquement lorsqu'ils sont connectés à un réseau IPv6 en utilisant le protocole de découverte des voisins via ICMPv6. Lorsqu'ils se connectent pour la première fois à un réseau, un hôte envoie une requête multicast de sollicitation de routeur pour ses paramètres de configuration. Le routeur répond avec un paquet d'annonce de routeur contenant les paramètres de configuration du niveau Internet.

Note

Cette méthode désactive automatiquement le transfert de trafic IPv6 sur l'interface.

Exemple :

set interfaces macsec macsec0 ipv6 address autoconf
set interfaces macsec <interface> ipv6 address eui64 <prefix>

Configurez l'interface pour lui attribuer une adresse IPv6 à l'aide de la méthode EUI-64 , comme spécifié dans RFC 4291.

Exemple :

set interfaces macsec macsec0 ipv6 address eui64 2001:db8:beef::/64
set interfaces macsec <interface> ipv6 address no-default-link-local

Désactivez l'attribution automatique d'une adresse IPv6 link-local à cette interface.

Exemple :

set interfaces macsec macsec0 ipv6 address no-default-link-local
set interfaces macsec <interface> ipv6 disable-forwarding

Configurez l'interface pour un comportement d'hôte ou de routeur.

Si configuré, l'interface passe en mode hôte, et le transfert IPv6 est désactivé sur celle-ci.

Exemple :

set interfaces macsec macsec0 ipv6 disable-forwarding
set interfaces macsec <interface> ipv6 adjust-mss <mss | clamp-mss-to-pmtu>

Configurez la MSS annoncée dans les paquets TCP SYN sortants sur l'interface spécifiée.

En limitant la valeur MSS dans les paquets TCP SYN, vous informez explicitement l'autre côté qu'il ne doit pas envoyer des paquets plus grands que cette taille. Cela empêche les problèmes de connexion lorsqu'une découverte de MTU de chemin (PMTUD) échoue.

Les options suivantes sont disponibles :

  • mss : Définissez la MSS à une valeur spécifique, en octets. Utilisez cette option pour forcer une MSS spécifique, par exemple, pour résoudre des problèmes de connectivité ou satisfaire des exigences réseau spécifiques.

  • clamp-mss-to-pmtu : Le routeur calcule la MSS à être la MTU de l'interface moins 60 octets pour le trafic IPv6 (40 octets pour l'en-tête IPv6 et 20 octets pour l'en-tête TCP). Cette option est recommandée pour configurer automatiquement la bonne valeur.

set interfaces macsec <interface> ipv6 accept-dad <0 | 1 | 2>

Configurez le DAD IPv6 sur l' interface.

Les options suivantes sont disponibles :

  • 0 : Désactive le DAD. Aucune détection de duplication d'adresse n'est effectuée.

  • 1 : Active le DAD (par défaut). Les adresses dupliquées sont détectées. L' opération IPv6 de l'interface continue pour les adresses IPv6 valides.

  • 2 : Active le DAD et, si une adresse link-local dupliquée basée sur la MAC est trouvée, désactive l'opération IPv6 sur cette interface.

Exemple :

set interfaces macsec macsec0 ipv6 accept-dad 2
set interfaces macsec <interface> ipv6 dup-addr-detect-transmits <n>

Configurez le nombre de DAD messages que le routeur (noyau) envoie pendant l'attribution d'adresse IPv6 sur cette interface.

La valeur par défaut est 1.

Exemple :

set interfaces macsec macsec0 ipv6 dup-addr-detect-transmits 5
set interfaces macsec <interface> vrf <vrf>

Affectez l'interface à une instance spécifique de VRF .

Voir aussi

Pour plus d'informations sur la configuration d'un VRF, consultez la section VRF.

Exemple :

set interfaces macsec macsec0 vrf red

DHCP(v6)

set interfaces macsec <interface> dhcp-options client-id <description>

Configurez un identifiant client DHCP pour l'interface, comme spécifié dans RFC 2131.

Le client-id est un identifiant que le client DHCP envoie au serveur DHCP pour identifier uniquement son propre appareil pour l'attribution d'adresse IP. Par défaut, le client utilise son adresse MAC. La chaîne <description> est un identifiant utilisateur qui sera envoyé au serveur DHCP comme identifiant client DHCP.

Exemple :

set interfaces macsec macsec0 dhcp-options client-id 'foo-bar'
set interfaces macsec <interface> dhcp-options host-name <hostname>

Configurez un nom d'hôte spécifique pour l'interface.

À la place du vrai nom d'hôte, le client DHCP enverra le nom d'hôte spécifique au serveur DHCP lors de la demande d'une adresse IP.

Exemple :

set interfaces macsec macsec0 dhcp-options host-name 'VyOS'
set interfaces macsec <interface> dhcp-options vendor-class-id <vendor-id>

Configurez le client DHCP pour inclure un identifiant de classe de fabricant dans ses demandes DHCP sur cette interface.

L'identifiant de classe de fabricant est une chaîne de bytes spécifique au fabricant qui permet au serveur DHCP d'identifier l'appareil et, dans certains cas, de fournir des options de configuration.

Exemple :

set interfaces macsec macsec0 dhcp-options vendor-class-id 'VyOS'
set interfaces macsec <interface> dhcp-options no-default-route

Configurez le client DHCP pour obtenir une adresse IP, mais ignorer toute passerelle par défaut fournie par le serveur DHCP sur cette interface.

Exemple :

set interfaces macsec macsec0 dhcp-options no-default-route
set interfaces macsec <interface> dhcp-options default-route-distance <distance>

Configurez la distance pour la route par défaut obtenue du serveur DHCP sur cette interface.

Exemple :

set interfaces macsec macsec0 dhcp-options default-route-distance 220
set interfaces macsec <interface> dhcp-options reject <address>

Configurez le client DHCP pour rejeter l'adresse IP spécifique ou la plage d'adresses IP du serveur DHCP sur cette interface.

Cela est utile lorsqu'un modem attribue une adresse IP locale au démarrage. Pour rejeter plusieurs adresses, exécutez cette commande plusieurs fois avec différentes valeurs. Vous pouvez rejeter des adresses individuelles (192.168.100.1) ou des sous-réseaux entiers (192.168.100.0/24).

Exemple :

set interfaces macsec macsec0 dhcp-options reject 192.168.100.0/24
set interfaces macsec <interface> dhcp-options user-class <string>

Configurez le client DHCP pour envoyer un identifiant de classe d'utilisateur spécifique dans ses demandes DHCP sur cette interface.

Le serveur DHCP peut interpréter cet identifiant et fournir des options de configuration spécifiques en fonction de celui-ci (par exemple, des routes par défaut). La valeur de la classe d'utilisateur regroupe généralement les clients DHCP ayant des besoins de configuration similaires (par exemple, employés, invités ou imprimantes).

Exemple :

set interfaces macsec macsec0 dhcp-options user-class VyOS
set interfaces macsec <interface> dhcpv6-options duid <duid>

Configurez un DUID spécifique pour le client DHCPv6 sur cette interface.

Le DUID est un identifiant utilisé par un client DHCPv6 pour obtenir une adresse IPv6 d'un serveur DHCPv6. Il se compose d'un champ de type de 2 octets, suivi d'un champ d'identifiant variable de longueur allant jusqu'à 128 octets. Le format de la partie identifiant dépend du type de DUID :

  • DUID-LLT : Le type le plus courant, qui inclut un type matériel, une horodatage et une adresse MAC.

  • DUID-EN : Basé sur un numéro d'entreprise d'un fabricant et un identifiant unique attribué par le fabricant.

  • DUID-LL : Inclut uniquement une adresse MAC.

Le serveur DHCP compare le DUID à sa base de données et fournit des données de configuration (telles que l'adresse, les durées de bail, les serveurs DNS, etc.) au client DHCP.

Exemple :

set interfaces macsec macsec0 duid '0e:00:00:01:00:01:27:71:db:f0:00:50:56:bf:c5:6d'
set interfaces macsec <interface> dhcpv6-options no-release

Configurez le client DHCP pour ne pas envoyer un message de libération lorsqu'il s'arrête sur cette interface.

Cela aide à conserver l'adresse ou le préfixe assigné.

Exemple :

set interfaces macsec macsec0 dhcpv6-options no-release
set interfaces macsec <interface> dhcpv6-options parameters-only

Activez un mode client DHCPv6 sans état sur cette interface.

En mode sans état, le client DHCPv6 demande uniquement des paramètres de configuration sans état au serveur DHCP (par exemple, les adresses des serveurs DNS). Il ne demande pas de configuration avec état, telle que des adresses IPv6 ou des préfixes.

Exemple :

set interfaces macsec macsec0 dhcpv6-options parameters-only
set interfaces macsec <interface> dhcpv6-options rapid-commit

Activez le commit rapide DHCPv6 sur cette interface.

Lorsqu'elle est activée, le client DHCP et le serveur sautent les étapes de négociation (Advertise et Request), terminant le processus de configuration DHCPv6 en seulement deux messages (Solicit et réponse finale).

Exemple :

set interfaces macsec macsec0 dhcpv6-options rapid-commit
set interfaces macsec <interface> dhcpv6-options temporary

Configurez le client DHCPv6 pour demander une adresse IPv6 temporaire sur cette interface.

Lorsqu'elle est configurée, le client DHCP ne forme pas une association d'identité pour les adresses non temporaires (IA_NA). En conséquence, il n'obtient qu'une adresse IPv6 temporaire et n'obtient pas une adresse permanente.

Exemple :

set interfaces macsec macsec0 dhcpv6-options temporary

DHCPv6 Prefix Delegation (PD)

VyOS prend en charge la délégation de préfixe DHCPv6 (DHCPv6-PD) comme décrit dans RFC 3633. La délégation de préfixe DHCPv6-PD est prise en charge par la plupart des FAI qui fournissent IPv6 natif aux consommateurs sur des réseaux fixes.

set interfaces macsec <interface> dhcpv6-options pd <id> length <length>

Configurez une longueur de préfixe spécifique pour les demandes DHCPv6-PD sur cette interface.

Certaines FAI fournissent uniquement un préfixe /64 par défaut. Utilisez cette commande pour demander une autre longueur de préfixe pour une demande DHCPv6-PD spécifique, allant de /32 (si autorisé par votre FAI) à /64. <id> est un identifiant unique pour la demande DHCPv6-PD.

La valeur par défaut est 64.

Pour demander un préfixe /56 à votre FAI, utilisez :

set interfaces macsec macsec0 dhcpv6-options pd 0 length 56
set interfaces macsec <interface> dhcpv6-options pd <id> interface <delegatee> address <address>

Configurez l'identifiant d'interface IPv6 (partie hôte) pour l'interface déléguée.

La valeur doit être un entier décimal. Elle est ajoutée au préfixe délégué et à l'ID SLA pour former l'adresse IPv6 finale.

Par défaut, la partie hôte est générée en fonction de l'adresse MAC de l'interface parente (en format EUI-64).

Exemple :

Si un préfixe /64 est délégué à l'interface eth8 et que vous configurez la partie hôte à 65535, l'adresse IPv6 résultante se terminera par ::ffff, car 65535 correspond à ffff en notation hexadécimale.

set interfaces macsec macsec0 dhcpv6-options pd 0 interface eth8 address 65534
set interfaces macsec <interface> dhcpv6-options pd <id> interface <delegatee> sla-id <id>

Configurez l' SLA ID pour l' interface déléguée.

La valeur doit être un entier décimal supérieur à 0 et convenir à la longueur des IDs SLA. Elle est convertie en hexadécimal et ajoutée au préfixe délégué pour former le préfixe de sous-réseau spécifique pour l'interface déléguée.

Exemple :

Si l'ID SLA est 1 et que le préfixe délégué est 2001:db8:ffff::/48, le préfixe de sous-réseau résultant pour l'interface déléguée sera 2001:db8:ffff:1::/64.

set interfaces macsec macsec0 dhcpv6-options pd 0 interface eth8 sla-id 1

Options MACsec

set interfaces macsec <interface> security cipher <gcm-aes-128|gcm-aes-256>

Configurez le suite de chiffrement pour l'interface MACsec.

Ce paramètre de configuration est obligatoire.

set interfaces macsec <interface> security encrypt

Activer le chiffrement sur l'interface MACsec.

Par défaut, les interfaces MACsec ne fournissent que l'authentification ; le chiffrement est optionnel. Lorsqu'il est activé, les paquets sortants sont chiffrés à l'aide de la suite de chiffrement configurée.

set interfaces macsec <interface> source-interface <physical-source>

Configurez une interface source physique pour l'interface MACsec.

Le trafic transmis à travers cette interface est authentifié et, si configuré, chiffré.

Gestion des clés MACsec

Mode SAK statique

Dans le mode SAK statique, les administrateurs doivent configurer manuellement et mettre à jour les SAKs sur chaque pair MACsec. Le protocole MKA ne peut pas être utilisé dans ce mode.

set interfaces macsec <interface> security static key <key>

Configurez la clé TX (SAK) pour l'interface MACsec.

La clé doit être une chaîne hexadécimale de 16 octets (GCM-AES-128) ou 64 octets (GCM-AES-256).

set interfaces macsec <interface> security static peer <peer> mac <mac address>

Configurez l'adresse MAC associée au pair MACsec.

set interfaces macsec <interface> security static peer <peer> key <key>
