API HTTP

VyOS fournit une API HTTP. Vous pouvez l'utiliser pour exécuter des commandes en mode opérationnel ou pour modifier ou supprimer la configuration. L'API est disponible sous forme d'une API REST et d'une API GraphQL.

Pour les exemples de requêtes API REST, les points de terminaison et les détails d'authentification, voir VyOS API.

Remarque

S'il aucun certificat PKI n'est configuré pour le service, VyOS génère automatiquement un certificat auto-signé. Cela n'est pas recommandé pour une utilisation en production.

Configuration

Écouteur HTTPS

set service https listen-address <address>

Configurez une adresse IPv4 ou IPv6 locale sur laquelle l'écouteur HTTPS accepte les connexions entrantes.

L'adresse IP doit déjà être attribuée à une interface locale. Répétez la commande pour configurer plusieurs adresses IP.

Lorsqu'elle n'est pas définie, l'écouteur accepte les connexions entrantes sur toutes les adresses IP locales.

Exemple :

set service https listen-address 192.0.2.1
set service https listen-address 2001:db8::1
set service https port <1-65535>

Configurez le port TCP sur lequel l'écouteur HTTPS accepte les connexions entrantes.

La valeur par défaut est 443.

Note

Si le port choisi est déjà utilisé par un autre service, la validation échoue.

Exemple :

set service https port 8443
set service https vrf <name>

Lier l'écouteur HTTPS à l'instance VRF spécifiée.

Le VRF doit déjà être configuré sous set vrf name <name>.

Exemple :

set service https vrf mgmt
set service https allow-client address <address>

Restreindre l'accès aux points de terminaison de l'API HTTPS à l'adresse IPv4 ou IPv6 ou au préfixe spécifié.

Répétez la commande pour autoriser plusieurs adresses IP ou préfixes.

Lorsqu'elle n'est pas définie, l'API accepte les connexions depuis toute adresse IP.

Exemple :

set service https allow-client address 192.0.2.0/24
set service https allow-client address 2001:db8::/32
set service https enable-http-redirect

Activer la redirection des requêtes HTTP entrantes (port 80) vers HTTPS.

La redirection envoie le trafic vers le port HTTPS par défaut (443). Si vous avez modifié le port HTTPS, la redirection ne fonctionnera pas.

Exemple :

set service https enable-http-redirect
set service https request-body-size-limit <1-256>

Configurer la taille maximale, en mégaoctets, du corps d'une requête HTTP accepté par l'écouteur.

Les requêtes dépassant cette limite sont rejetées.

La valeur par défaut est 1.

Exemple :

set service https request-body-size-limit 10

TLS

set service https tls-version <1.2 | 1.3>

Activer une version spécifique du protocole TLS pour l'écouteur HTTPS.

Répétez la commande pour activer plusieurs versions de protocole.

Par défaut, les versions TLS 1.2 et TLS 1.3 sont activées.

Exemple :

set service https tls-version 1.3
set service https certificates certificate <name>

Lier un certificat TLS du sous-système PKI à l'écouteur HTTPS.

Le certificat doit déjà être défini sous set pki certificate <name> avec à la fois un certificat et une clé privée.

Exemple :

set service https certificates certificate my-server-cert
set service https certificates ca-certificate <name>

Lier un certificat CA du sous-système PKI à l'écouteur HTTPS.

La CA doit déjà être définie sous set pki ca <name>. Le certificat CA est ajouté au certificat TLS pour former une chaîne complète présentée aux clients pendant l'échange TLS.

Exemple :

set service https certificates ca-certificate my-internal-ca
set service https certificates dh-params <name>

Choisir des paramètres Diffie-Hellman du sous-système PKI pour l'écouteur HTTPS.

Les paramètres doivent déjà être définis sous set pki dh <name> avec une taille de clé d'au moins 2048 bits. Les paramètres sont utilisés par les suites de chiffrement DHE dans TLS 1.2. TLS 1.3 n'en utilise pas.

Exemple :

set service https certificates dh-params my-dh-2048

Authentification de l'API

set service https api keys id <name> key <apikey>

Configurer une clé d'API HTTP pour authentifier les requêtes REST, et les requêtes GraphQL sauf si GraphQL passe à l'authentification avec un jeton JWT.

La clé est spécifiée en texte brut et accorde un accès complet à l'API.

Au moins une clé doit être configurée pour utiliser l'API REST. GraphQL peut fonctionner sans clés si l'authentification avec un jeton JWT est activée.

Exemple :

set service https api keys id MY-HTTPS-API-ID key 'MY-HTTPS-API-PLAINTEXT-KEY'

REST

set service https api rest

Activer l'API REST pour gérer VyOS via HTTPS.

Exemple :

set service https api rest
set service https api rest strict

Rejeter les requêtes de suppression sur le point de terminaison /configure lorsqu'il n'existe pas de chemin de configuration cible.

Sans ce drapeau, ces requêtes réussissent silencieusement.

Exemple :

set service https api rest strict
set service https api rest debug

Enregistrer des messages d'erreur détaillés dans le journal systemd lorsqu'une demande de configuration d'API échoue.

Sans ce drapeau, seuls les messages d'erreur courts sont enregistrés.

Exemple :

set service https api rest debug

GraphQL

set service https api graphql introspection

Activer l'introspection du schéma GraphQL.

Les clients authentifiés peuvent alors interroger le point de terminaison pour obtenir le schéma complet. Désactivé par défaut, et généralement maintenu désactivé en production en raison de des préoccupations de sécurité.

Exemple :

set service https api graphql introspection
set service https api graphql authentication type <key | token>

Configurer le type d'authentification pour les requêtes GraphQL :

  • key : Utilise les clés d'API configurées dans service https api keys.

  • token : Utilise des jetons JWT.

La valeur par défaut est key.

Exemple :

set service https api graphql authentication type token
set service https api graphql authentication expiration <60-31536000>

Configurer la durée de vie, en secondes, des jetons JWT.

La valeur par défaut est 3600.

Exemple :

set service https api graphql authentication expiration 86400
set service https api graphql authentication secret-length <16-65535>

Configurer la longueur, en octets, du secret partagé utilisé pour signer les jetons JWT.

La valeur par défaut est 32.

Exemple :

set service https api graphql authentication secret-length 64
set service https api graphql cors allow-origin <origin>

Configurer quels sites (origines) peuvent lire les réponses de l'API GraphQL dans un navigateur, en utilisant CORS.

Répétez la commande pour autoriser plusieurs origines.

Exemple :

set service https api graphql cors allow-origin https://app.example.com

Exemple

La configuration minimale pour une API REST fonctionnelle nécessite l'activation de REST et la configuration d'au moins une clé d'API :

set service https api keys id MY-HTTPS-API-ID key MY-HTTPS-API-PLAINTEXT-KEY
set service https api rest
