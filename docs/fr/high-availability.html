Haute disponibilité

VRRP (Virtual Router Redundancy Protocol) fournit une redondance active/backup pour les routeurs. Chaque routeur VRRP dispose d'une adresse IP/IPv6 physique, et d'une adresse virtuelle. Au démarrage, les routeurs élisent le maître, et le routeur avec la plus haute priorité devient le maître et attribue l'adresse virtuelle à son interface. Tous les routeurs avec une priorité inférieure deviennent des routeurs de secours. Le maître commence ensuite à envoyer des paquets keepalive pour informer les autres routeurs qu'il est disponible. Si le maître échoue et arrête d'envoyer les paquets keepalive, le routeur avec la priorité suivante la plus élevée devient le nouveau maître et prend en charge l'adresse virtuelle.

Les paquets keepalive VRRP utilisent le multicast, et les configurations VRRP sont limitées à un seul segment de couche datalink. Vous pouvez configurer plusieurs groupes VRRP (également appelés routeurs virtuels). Les routeurs virtuels sont identifiés par un VRID (Virtual Router IDentifier). Si vous configurez plusieurs groupes sur la même interface, leurs VRIDs doivent être uniques si ils utilisent la même famille d'adresses, mais il est possible (même si ce n'est pas recommandé pour des raisons de lisibilité) d'utiliser des VRIDs dupliqués sur des interfaces différentes.

Configuration de base

Les groupes VRRP sont créés avec la commande set high-availability vrrp group $GROUP_NAME. Les paramètres requis sont interface, vrid et address.

configuration minimale

set high-availability vrrp group Foo vrid 10
set high-availability vrrp group Foo interface eth0
set high-availability vrrp group Foo address 192.0.2.1/24

Vous pouvez vérifier l'état de votre groupe VRRP avec la commande opérationnelle run show vrrp :

vyos@vyos# run show vrrp
Name        Interface      VRID  State    Last Transition
----------  -----------  ------  -------  -----------------
Foo         eth1             10  MASTER   2s

Prise en charge IPv6

Le paramètre address peut être soit une adresse IPv4 ou IPv6, mais vous ne pouvez pas mélanger IPv4 et IPv6 dans le même groupe, et vous devrez créer des groupes avec des VRIDs différents spécialement pour IPv4 et IPv6. Si vous souhaitez utiliser une adresse IPv4 + IPv6, vous pouvez utiliser l'option excluded-address

Adresse

La address peut être configurée soit sur l'interface VRRP, soit sur une interface non VRRP.

set high-availability vrrp group Foo address 192.0.2.1/24
set high-availability vrrp group Foo address 203.0.113.22/24 interface eth2
set high-availability vrrp group Foo address 198.51.100.33/24 interface eth3

Désactivation d'un groupe VRRP

Vous pouvez désactiver un groupe VRRP avec l'option disable :

set high-availability vrrp group Foo disable

Un groupe désactivé sera supprimé du processus VRRP et votre routeur ne participera pas au VRRP pour ce VRID. Il disparaîtra des sorties des commandes en mode opérationnel, plutôt que d'entrer dans l'état de sauvegarde.

Exclure une adresse

Exclure les adresses IP des paquets VRRP. Cette option excluded-address est utilisée lorsque vous souhaitez définir des adresses IPv4 + IPv6 sur la même interface virtuelle ou lorsqu'elle est utilisée avec plus de 20 adresses IP.

set high-availability vrrp group Foo excluded-address '203.0.113.254/24'
set high-availability vrrp group Foo excluded-address '2001:db8:aa::1/64'
set high-availability vrrp group Foo excluded-address '2001:db8:22::1/64'

Définir la priorité d'un groupe VRRP

La priorité VRRP peut être définie avec l'option priority :

set high-availability vrrp group Foo priority 200

La priorité doit être un nombre entier compris entre 1 et 255. Une valeur de priorité plus élevée augmente la préférence du routeur dans les élections du maître.

Groupes de synchronisation

Un groupe de synchronisation permet aux groupes VRRP de basculer ensemble.

edit high-availability vrrp
set sync-group MAIN member VLAN9
set sync-group MAIN member VLAN20

Dans l'exemple suivant, lorsque VLAN9 change d'état, VLAN20 changera également :

vrrp {
    group VLAN9 {
        interface eth0.9
        address 10.9.1.1/24
        priority 200
        vrid 9
    }
    group VLAN20 {
        interface eth0.20
        priority 200
        address 10.20.20.1/24
        vrid 20
    }
    sync-group MAIN {
        member VLAN20
        member VLAN9
    }
}

Avertissement

Tous les éléments d'un groupe de synchronisation doivent être configurés de manière similaire. Si un groupe VRRP est configuré avec un délai de préemption différent ou une priorité, cela entraînera une boucle de transition infinie.

Préemption

VRRP peut utiliser deux modes : préemptif et non préemptif. Dans le mode préemptif, si un routeur avec une priorité plus élevée échoue puis revient, les routeurs avec une priorité plus faible abandonneront leur statut de maître. Dans le mode non préemptif, le nouveau maître restera en tant que maître et conservera l'adresse virtuelle indéfiniment.

Par défaut, VRRP utilise la préemption. Vous pouvez la désactiver avec l'option « no-preempt » :

set high-availability vrrp group Foo no-preempt

Vous pouvez également configurer l'intervalle de temps pour la préemption avec l'option « preempt-delay ». Par exemple, pour que le routeur à haute priorité prenne le contrôle après 180 secondes, utilisez :

set high-availability vrrp group Foo preempt-delay 180

Suivi

Option de suivi des états des interfaces non VRRP. VRRP passe à l'état FAULT si l'une des interfaces de suivi est en état down.

set high-availability vrrp group Foo track interface eth0
set high-availability vrrp group Foo track interface eth1

Ignorer les pannes de l'interface principale VRRP

set high-availability vrrp group Foo track exclude-vrrp-interface

VRRP unicast

Par défaut, VRRP utilise des paquets multicast. Si votre réseau ne prend pas en charge le multicast pour quelque raison que ce soit, vous pouvez faire en sorte que VRRP utilise la communication unicast au lieu.

set high-availability vrrp group Foo peer-address 192.0.2.10
set high-availability vrrp group Foo hello-source-address 192.0.2.15

Compatibilité rfc3768

Le RFC 3768 définit une adresse MAC virtuelle pour chaque routeur virtuel VRRP. Cette adresse MAC de routeur virtuel sera utilisée comme source dans tous les messages VRRP périodiques envoyés par le nœud actif. Lorsque l'option rfc3768-compatibility est activée, un nouvel interface VRRP est créé, auquel l'adresse MAC et l'adresse IP virtuelle sont automatiquement attribuées.

set high-availability vrrp group Foo rfc3768-compatibility

Vérification

$show interfaces ethernet eth0v10
eth0v10@eth0: <BROADCAST,MULTICAST,UP,LOWER_UP> mtu 1500 qdisc noqueue
state UP group default qlen 1000
link/ether 00:00:5e:00:01:0a brd ff:ff:ff:ff:ff:ff

Avertissement

Le RFC 3768 crée une interface virtuelle. Si vous souhaitez appliquer la règle de NAT de destination au trafic envoyé à la MAC virtuelle, définissez l'interface virtuelle créée comme inbound-interface.

Options globales

Dans la plupart des scénarios, il n'est pas nécessaire de modifier des paramètres spécifiques, et une configuration par défaut suffit. Mais il y a des cas où une configuration supplémentaire est nécessaire.

set high-availability vrrp global-parameters startup_delay <1-600>

Cette option spécifie un délai en secondes avant que les instances vrrp ne démarrent après le démarrage de keepalived.

ARP gratuit

Cette configuration n'est pas obligatoire et dans la plupart des cas, il n'y a pas besoin de la configurer. Mais si nécessaire, l'ARP gratuit peut être configuré dans global-parameters et/ou dans la section group.

set high-availability vrrp global-parameters garp interval <0.000-1000>
set high-availability vrrp group <name> garp interval <0.000-1000>

Définir le délai entre les messages ARP gratuits envoyés sur une interface.

0 si non défini.

set high-availability vrrp global-parameters garp master-delay <1-255>
set high-availability vrrp group <name> garp master-delay <1-255>

Définir le délai pour le deuxième ensemble d'ARP gratuits après le passage à MAÎTRE.

5 si non défini.

set high-availability vrrp global-parameters garp master-refresh <1-600>
set high-availability vrrp group <name> garp master-refresh <1-600>

Définir l'intervalle minimum pour rafraîchir les ARP gratuits pendant le mode MAÎTRE.

0 si non défini, ce qui signifie qu'il n'y a pas de rafraîchissement.

set high-availability vrrp global-parameters garp master-refresh-repeat <1-600>
set high-availability vrrp group <name> garp master-refresh-repeat <1-600>

Définir le nombre de messages ARP gratuits à envoyer à la fois pendant le mode MAÎTRE.

1 si non défini.

set high-availability vrrp global-parameters garp master-repeat <1-600>
set high-availability vrrp group <name> garp master-repeat <1-600>

Définir le nombre de messages ARP gratuits à envoyer à la fois après le passage à MAÎTRE.

5 si non défini.

Version

set high-availability vrrp global-parameters version 2|3

Définir la version VRRP par défaut à utiliser. Cela par défaut à 2, mais les instances IPv6 utiliseront toujours la version 3.

Scripting

La fonctionnalité VRRP peut être étendue avec des scripts. VyOS prend en charge deux types de scripts : scripts de vérification de santé et scripts de transition. Les scripts de vérification de santé exécutent des vérifications personnalisées en plus de la faisabilité du routeur principal. Les scripts de transition s'exécutent lorsqu'il y a un changement d'état VRRP du maître vers le sauvegarde ou le défaut et vice versa et peuvent être utilisés pour activer ou désactiver certains services, par exemple.

Note

Placer simplement les fichiers de script dans /config/scripts/ ne signifie pas que le système peut les exécuter. Pour rendre les scripts personnalisés exécutables, accordez-leur les permissions d'exécution. Utilisez la commande suivante :

chmod +x /config/scripts/script-name.sh

Avertissement

Il n'est pas recommandé de modifier la configuration VRRP dans les scripts de vérification de santé et de transition.

Scripts de vérification de santé

Il est possible d'exécuter un script arbitraire à intervalles réguliers selon les paramètres de vérification de santé. Si un script retourne 0, cela indique un succès. Si un script retourne autre chose, cela indiquera que l'instance VRRP doit entrer dans l'état FAULT.

Cette configuration fera exécuter le processus VRRP le /config/scripts/vrrp-check.sh script toutes les 60 secondes, et transitera le groupe vers l'état de panne s'il échoue (c'est-à-dire qu'il quitte avec un statut non nul) trois fois :

set high-availability vrrp group Foo health-check script /config/scripts/vrrp-check.sh
set high-availability vrrp group Foo health-check interval 60
set high-availability vrrp group Foo health-check failure-count 3

Un timeout optionnel peut être défini pour définir le nombre maximum de secondes pendant lesquelles le script est autorisé à s'exécuter. Cela est utile pour les scripts qui peuvent se bloquer ou prendre plus longtemps que prévu — définir le timeout supérieur à l'intervalle permet aux scripts plus longs de terminer avant d'être considérés comme échoués.

set high-availability vrrp group Foo health-check script /config/scripts/vrrp-check.sh
set high-availability vrrp group Foo health-check interval 20
set high-availability vrrp group Foo health-check failure-count 3
set high-availability vrrp group Foo health-check timeout 40

Lorsque le groupe vrrp est membre d'un groupe de synchronisation, il utilisera uniquement le script de vérification de santé du groupe de synchronisation. Cet exemple montre comment le configurer pour le groupe de synchronisation :

set high-availability vrrp sync-group Bar health-check script /config/scripts/vrrp-check.sh
set high-availability vrrp sync-group Bar health-check interval 60
set high-availability vrrp sync-group Bar health-check failure-count 3

Scripts de transition

Les scripts de transition peuvent vous aider à implémenter divers correctifs, tels que le démarrage et l'arrêt de services, ou même la modification de la configuration VyOS lors d'une transition VRRP. Cette configuration fera exécuter le processus VRRP le /config/scripts/vrrp-fail.sh avec l'argument Foo lorsqu'il y a un échec VRRP, et le /config/scripts/vrrp-master.sh lorsqu'il devient maître :

set high-availability vrrp group Foo transition-script backup "/config/scripts/vrrp-fail.sh Foo"
set high-availability vrrp group Foo transition-script fault "/config/scripts/vrrp-fail.sh Foo"
set high-availability vrrp group Foo transition-script master "/config/scripts/vrrp-master.sh Foo"

Pour en savoir plus sur le scripting, consultez la section Command scripting.

Serveur virtuel

Virtual Server permet de charger-balançer le trafic vers l'adresse virtuelle:port entre plusieurs serveurs réels.

Algorithme

Algorithme de planification de charge équilibrée :

  • round-robin

  • weighted-round-robin

  • least-connection

  • weighted-least-connection

  • source-hashing

  • destination-hashing

  • locality-based-least-connection

set high-availability virtual-server 203.0.113.1 algorithm 'least-connection'

Méthode de transfert

  • NAT

  • direct

  • tunnel

set high-availability virtual-server 203.0.113.1 forward-method 'nat'

Timeout de persistance

Temps d'attente en secondes pour les connexions persistantes. IPVS transmettra toutes les connexions provenant de la même adresse IP source au même serveur réel pendant la durée du timeout. La valeur par défaut est de 300 secondes.

Définir sur 0 pour désactiver la persistance et permettre à l'algorithme de charge équilibrée de distribuer chaque connexion indépendamment.

set high-availability virtual-server 203.0.113.1 persistence-timeout '180'

Vérification de santé

Le script de vérification de santé personnalisé permet de vérifier la disponibilité des serveurs réels

set high-availability virtual-server 203.0.113.1 real-server 192.0.2.11 health-check script <path-to-script>

Fwmark

Marque de pare-feu. Il est possible de loadbalancer le trafic en fonction de la valeur fwmark

set high-availability virtual-server 203.0.113.1 fwmark '111'

Serveur réel

Adresse IP et port du serveur réel

set high-availability virtual-server 203.0.113.1 real-server 192.0.2.11 port '80'

Exemple

Le serveur virtuel peut être configuré avec une adresse virtuelle VRRP ou sans VRRP.

Dans l'exemple suivant, tout le trafic destiné à 203.0.113.1 et au port 8280 protocole TCP est équilibré entre 2 serveurs réels 192.0.2.11 et 192.0.2.12 au port 80

Le serveur réel est exclu automatiquement si le test de port avec ce serveur échoue.

set interfaces ethernet eth0 address '203.0.113.11/24'
set interfaces ethernet eth1 address '192.0.2.1/24'
set high-availability vrrp group FOO interface 'eth0'
set high-availability vrrp group FOO no-preempt
set high-availability vrrp group FOO priority '150'
set high-availability vrrp group FOO address '203.0.113.1/24'
set high-availability vrrp group FOO vrid '10'

set high-availability virtual-server 203.0.113.1 algorithm 'source-hashing'
set high-availability virtual-server 203.0.113.1 delay-loop '10'
set high-availability virtual-server 203.0.113.1 forward-method 'nat'
set high-availability virtual-server 203.0.113.1 persistence-timeout '180'
set high-availability virtual-server 203.0.113.1 port '8280'
set high-availability virtual-server 203.0.113.1 protocol 'tcp'
set high-availability virtual-server 203.0.113.1 real-server 192.0.2.11 port '80'
set high-availability virtual-server 203.0.113.1 real-server 192.0.2.12 port '80'

Une marque de pare-feu fwmark permet d'utiliser plusieurs ports pour le serveur virtuel haute disponibilité. Il utilise la valeur fwmark.

Dans cet exemple, tout le trafic destiné aux ports «80, 2222, 8888» protocole TCP marque à fwmark «111» et est équilibré entre 2 serveurs réels. Le port «0» est requis si plusieurs ports sont utilisés.

set interfaces ethernet eth0 address 'dhcp'
set interfaces ethernet eth0 description 'WAN'
set interfaces ethernet eth1 address '192.0.2.1/24'
set interfaces ethernet eth1 description 'LAN'

set policy route PR interface 'eth0'
set policy route PR rule 10 destination port '80,2222,8888'
set policy route PR rule 10 protocol 'tcp'
set policy route PR rule 10 set mark '111'

set high-availability virtual-server vyos fwmark '111'
set high-availability virtual-server vyos protocol 'tcp'
set high-availability virtual-server vyos real-server 192.0.2.11 health-check script '/config/scripts/check-real-server-first.sh'
set high-availability virtual-server vyos real-server 192.0.2.11 port '0'
set high-availability virtual-server vyos real-server 192.0.2.12 health-check script '/config/scripts/check-real-server-second.sh'
set high-availability virtual-server vyos real-server 192.0.2.12 port '0'

set nat source rule 100 outbound-interface name 'eth0'
set nat source rule 100 source address '192.0.2.0/24'
set nat source rule 100 translation address 'masquerade'
