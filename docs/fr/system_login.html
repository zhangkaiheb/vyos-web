Gestion des connexions/utilisateurs

Le compte utilisateur par défaut de VyOS (vyos), ainsi que les comptes d'utilisateurs nouvellement créés, possèdent des privilèges complets pour la configuration du système. Ces comptes bénéficient des privilèges sudo, leur permettant d'exécuter des commandes en tant qu'utilisateur root.

VyOS prend en charge l'authentification locale et l'authentification distante via RADIUS/ TACACS+.

Authentification locale

set system login user <name> full-name “<string>”

Configurez le nom réel ou la description d'un utilisateur système.

Si la description contient des espaces, placez <string> entre guillemets doubles.

Si l'utilisateur <name> existe déjà, la commande met à jour la description actuelle. Si ce n'est pas le cas, elle crée un nouvel utilisateur avec la description spécifiée.

set system login user <name> authentication plaintext-password <password>

Configurez un mot de passe pour un utilisateur système.

Saisissez le mot de passe en clair. Lors de la validation commit, VyOS hache le mot de passe pour une conservation sécurisée et supprime la valeur en clair.

Si l'utilisateur <name> existe déjà, la commande met à jour le mot de passe actuel. Si ce n'est pas le cas, elle crée un nouvel utilisateur avec le mot de passe en clair spécifié.

set system login user <name> authentication encrypted-password <password>

Configurez un mot de passe pré-chiffré pour un utilisateur système.

Saisissez le mot de passe au format haché. Lors de la validation commit, VyOS stocke cette valeur directement sans modification.

Si l'utilisateur <name> existe déjà, la commande met à jour le mot de passe actuel. Si ce n'est pas le cas, elle crée un nouvel utilisateur lié au mot de passe pré-chiffré spécifié.

set system login user <name> authentication principal <principal>

Configurez un principal SSH pour un utilisateur système.

Saisissez le principal (une chaîne incluse dans le certificat SSH signé de l'utilisateur). Lors de la validation commit, VyOS stocke cette association, permettant à l'utilisateur de se connecter s'il présente un certificat contenant ce principal.

Si l'utilisateur <name> existe déjà, la commande met à jour le principal. Si ce n'est pas le cas, elle crée un nouvel utilisateur lié au principal spécifié.

Si non configuré, le principal est par défaut <name>.

set system login user <name> disable

Désactivez un compte utilisateur système.

VyOS verrouille le compte, empêchant l'utilisateur de se connecter.

Authentification basée sur des clés

L'authentification basée sur des clés est la méthode recommandée pour sécuriser l'accès SSH dans VyOS. Elle utilise une paire de clés publique/prive pour vérifier l'identité de l'utilisateur sans nécessiter de mot de passe. Pour autoriser l'accès, vous attribuez des clés publiques SSH aux comptes d'utilisateurs sur le routeur, tandis que les clés privées SSH restent sur les appareils locaux. VyOS permet d'attribuer plusieurs clés publiques SSH à un seul compte d'utilisateur, ce qui est utile pour accéder à un routeur depuis différents appareils.

Générer la paire de clés

Générez une paire de clés SSH sur votre ordinateur local en utilisant la commande ssh-keygen. Cela crée deux fichiers :

  • Clé privée (par exemple, id_rsa) : Reste sur votre ordinateur local et ne doit jamais être partagée.

  • Clé publique (par exemple, id_rsa.pub) : Est utilisée pour configurer le compte utilisateur VyOS. Par défaut, elle est sauvegardée dans ~/.ssh/id_rsa.pub.

Chaque clé publique SSH se compose de trois parties, séparées par des espaces :

  • Type d'algorithme de chiffrement : ssh-rsa, ssh-ed25519, etc.

  • Clé : Les données réelles (une longue chaîne commençant par AAAA...).

  • Commentaire : Un identifiant pour votre référence (par exemple, user@host).

Seulement le type d'algorithme de chiffrement et la clé sont requis pour configurer l'entrée d'autorisation dans VyOS. La partie commentaire est facultative.

Opération SSH

Avertissement

Les chaînes de clés SSH sont longues. Lors de la copie et de la collation, assurez-vous que votre terminal n'insère pas de sauts de ligne. La clé doit être saisie comme une ligne unique pour fonctionner correctement.

Configurer le routeur

Pour configurer l'authentification par clé publique SSH pour un compte utilisateur, exécutez les deux commandes suivantes en utilisant le même <identifier> :

set system login user <username> authentication public-keys <identifier> key <key>

Configurez la clé publique SSH pour le compte utilisateur.

  • <identifier> : Un étiquette unique qui identifie cette entrée de clé spécifique.

  • <key> : La chaîne réelle de caractères provenant de votre clé publique.

set system login user <username> authentication public-keys <identifier> type <type>

Configurez le type de chiffrement de la clé SSH.

Les types d'algorithmes de chiffrement suivants sont disponibles :

  • ecdsa-sha2-nistp256

  • ecdsa-sha2-nistp384

  • ecdsa-sha2-nistp521

  • ssh-dss

  • ssh-ed25519

  • ssh-rsa

Note

Pour assigner plusieurs clés publiques SSH à un compte utilisateur, répétez les commandes ci-dessus avec un identifiant unique pour chaque clé.

set system login user <username> authentication public-keys <identifier> options <options>

Configurez des restrictions ou comportements spécifiques pour une clé publique SSH.

<options> : Une chaîne de valeurs séparées par des virgules définissant les permissions ou restrictions pour cette clé.

La commande accepte les options standard OpenSSH listées dans le fichier ~/.ssh/authorized_keys du routeur.

Pour inclure un caractère " dans la chaîne d'options, utilisez &quot;.

Par exemple, pour limiter les adresses IP sources autorisées pour une clé publique SSH, utilisez : from=&quot;10.0.0.0/24&quot;.

MFA basé sur OTP

VyOS permet d'améliorer la sécurité de l'accès utilisateur en activant le OTP-based MFA pour des utilisateurs individuels. Les utilisateurs avec OTP-based MFA doivent entrer un OTP valide ainsi qu'un mot de passe lors de la connexion. Les utilisateurs sans OTP-based MFA utilisent une authentification standard.

set system login user <username> authentication otp key <key>

Configurez OTP-based MFA pour un utilisateur.

<key> : Une clé secrète encodée en Base32. Cette clé doit être ajoutée à l'application d'authentification de l'utilisateur pour générer des OTPs valides.

Lorsqu'elle est configurée, l'utilisateur doit entrer son mot de passe suivi d'un OTP valide pour toutes les connexions ultérieures.

Paramètres OTP

set system login user <username> authentication otp rate-limit <limit>

Configurez le nombre de OTP tentatives d'authentification autorisées pendant une période spécifiée.

Si cette limite est dépassée, l'utilisateur est temporairement bloqué.

La valeur par défaut est de 3 tentatives. La plage valide est de 1 à 10 tentatives.

set system login user <username> authentication otp rate-time <seconds>

Configurez la durée, en secondes, pour le suivi des OTP tentatives d'authentification.

La valeur par défaut est de 30 secondes. La plage valide est de 1 à 600 secondes.

set system login user <username> authentication otp window-size <size>

Configurez la taille de fenêtre OTP pour un utilisateur.

La taille de fenêtre OTP définit le nombre de OTPs valides simultanément que le serveur d'authentification accepte. Ce paramètre suppose qu'un nouveau jeton est généré toutes les 30 secondes.

La valeur par défaut est de 3. Cela permet 3 codes simultanés : le code pour l'intervalle de 30 secondes actuel, le code précédent et le code suivant. Cela permet jusqu'à 30 secondes de décalage temporel entre le serveur d'authentification et le client.

Si la taille de la fenêtre est augmentée à 17, le système permet 17 codes simultanés (le code actuel, les 8 codes précédents et les 8 codes suivants). Cela permet un décalage temporel de jusqu'à 4 minutes.

La plage valide est de 1 à 21.

Générer une clé OTP

Utilisez la commande suivante pour générer une clé OTP :

generate system login username <username> otp-key hotp-time rate-limit <1-10> rate-time <15-600> window-size <1-21>

Authentification RADIUS

Pour les déploiements à grande échelle, gérer individuellement les comptes d'utilisateurs sur plusieurs instances VyOS est inefficace. VyOS prend en charge l'authentification centralisée via RADIUS, regroupant la gestion des comptes utilisateurs sur un seul serveur backend.

Configuration

set system login radius server <address> key <secret>

Configurez l'adresse IP et le secret partagé du RADIUS serveur.

Le secret partagé est utilisé pour vérifier l'identité du routeur et pour chiffrer les mots de passe des utilisateurs pendant l'authentification.

Vous pouvez configurer plusieurs serveurs RADIUS.

set system login radius server <address> port <port>

Configurez le port UDP pour la communication avec le RADIUS serveur.

Le port par défaut est 1812.

set system login radius server <address> disable

Désactivez un RADIUS serveur de l'processus d'authentification.

Désactiver un serveur RADIUS spécifique ne supprime pas ses paramètres de configuration (l'adresse IP et le secret partagé du serveur).

set system login radius server <address> timeout <timeout>

Configurez la durée, en secondes, pendant laquelle le routeur VyOS attend une réponse du RADIUS serveur après avoir envoyé une demande d'authentification.

Si le serveur ne répond pas dans ce délai, le routeur VyOS tente de se connecter à un autre serveur configuré ou revient à l'authentification locale.

set system login radius source-address <address>

Configurez l'adresse IP source que le routeur utilise pour les demandes d'authentification RADIUS.

Une adresse IP source constante est recommandée car les serveurs RADIUS acceptent généralement les requêtes uniquement depuis des adresses IP connues et fiables.

Si elle n'est pas explicitement définie, le routeur utilise l'adresse de l'interface de sortie actuelle, qui peut changer (par exemple, en cas de panne de lien), entraînant des échecs d'authentification.

set system login radius vrf <name>

Configurez le routeur pour envoyer toutes les demandes d'authentification RADIUS via un VRF spécifique.

Par défaut, les demandes d'authentification RADIUS sont envoyées via le tableau de routage global.

Exemple de configuration

set system login radius server 192.168.0.2 key 'test-vyos'
set system login radius server 192.168.0.2 port '1812'
set system login radius server 192.168.0.2 timeout '5'
set system login radius source-address '192.168.0.1'

Si la communication avec le serveur RADIUS échoue, le routeur revient à l'authentification locale. Pendant ce processus, les utilisateurs peuvent subir un délai de connexion pendant que le système attend que la demande RADIUS expire. Ce délai dépend de la valeur de timeout configurée.

Conseil

Pour accorder des privilèges administratifs aux utilisateurs authentifiés par RADIUS, le serveur doit retourner l'attribut Cisco-AV-Pair défini sur shell:priv-lvl=15. Sinon, les utilisateurs reçoivent des privilèges standards et ne peuvent pas effectuer des tâches de configuration.

Authentification TACACS+

En plus de RADIUS, VyOS prend en charge TACACS+, qui est couramment utilisé dans les environnements d'entreprises.

Contrairement à RADIUS, TACACS+ sépare l'authentification, l'autorisation et la comptabilisation (AAA) en processus indépendants et chiffre l'ensemble du corps du paquet pour une sécurité renforcée.

TACACS+ est défini dans RFC 8907.

Configuration

set system login tacacs server <address> key <secret>

Configurez l'adresse IP et le secret partagé du TACACS+ serveur.

Contrairement à RADIUS, qui chiffre uniquement les mots de passe, TACACS+ chiffre l'ensemble du corps du paquet pour une sécurité renforcée.

Vous pouvez configurer plusieurs serveurs TACACS+.

set system login tacacs server <address> port <port>

Configurez le port TCP pour la communication avec le TACACS+ serveur.

Le port par défaut est 49.

set system login tacacs server <address> disable

Désactivez un TACACS+ serveur de l'processus d'authentification.

Désactiver un serveur TACACS+ spécifique ne supprime pas ses paramètres de configuration (l'adresse IP et le secret partagé du serveur).

set system login tacacs server <address> timeout <timeout>

Configurez la durée, en secondes, pendant laquelle le routeur VyOS attend une réponse du TACACS+ serveur après avoir envoyé une demande d'authentification.

Si le serveur ne répond pas dans ce délai, le routeur VyOS tente de se connecter à un autre serveur configuré ou revient à l'authentification locale.

set system login tacacs source-address <address>

Configurez l'adresse IP source que le routeur utilise pour les demandes d'authentification TACACS+.

Une adresse IP source constante est recommandée car les serveurs TACACS+ acceptent généralement les requêtes uniquement depuis des adresses IP connues et fiables.

Si elle n'est pas explicitement définie, le routeur utilise l'adresse de l'interface de sortie actuelle, qui peut changer (par exemple, en cas de panne de lien), entraînant des échecs d'authentification.

set system login tacacs vrf <name>

Configurez le routeur pour envoyer toutes les demandes d'authentification TACACS+ via un VRF spécifique.

Par défaut, les demandes d'authentification TACACS+ sont envoyées via le tableau de routage global.

Exemple de configuration

set system login tacacs server 192.168.0.2 key 'test-vyos'
set system login tacacs server 192.168.0.2 port '49'
set system login tacacs source-address '192.168.0.1'

Si la communication avec le serveur TACACS+ échoue, le routeur revient à l'authentification locale des utilisateurs.

Bannières de connexion

VyOS permet de configurer des bannières avant la connexion et après la connexion. Les bannières avant la connexion sont généralement utilisées pour l'identification du système, les dénégations juridiques ou les avertissements de sécurité affichés avant l'authentification, tandis que les bannières après la connexion fournissent des informations sur le système ou des annonces opérationnelles aux utilisateurs après la connexion.

set system login banner pre-login <message>

Configurez un message à afficher aux utilisateurs avant que les invites username et password n'apparaissent.

set system login banner post-login <message>

Configurez un message à afficher aux utilisateurs après une authentification réussie.

Note

Utilisez \\n pour insérer des sauts de ligne dans les messages de bannière multilignes.

Limites de sessions de connexion

set system login max-login-session <number>

Configurez le nombre maximum de sessions de connexion simultanées.

Note

Si vous limitez les sessions de connexion simultanées, vous devez également configurer un <timeout> de session. Cela efface les sessions inactives et évite le blocage des nouvelles tentatives de connexion.

set system login timeout <timeout>

Configurez le délai de session de connexion, en secondes.

Les sessions de connexion inactives sont terminées après cette période.

Exemple 2 : Déploiement conteneurisé de TACACS+ avec redondance.

Dans cette configuration, le routeur VyOS héberge son propre infrastructure d'authentification en utilisant deux serveurs TACACS+ conteneurisés (tacacs1 et tacacs2) sur un réseau privé pour la redondance.

Les connexions système sont authentifiées contre les identifiants stockés dans ces conteneurs internes plutôt que dans la base de données d'utilisateurs locale du routeur.

Tout d'abord, téléchargez l'image en mode opérationnel :

add container image lfkeitel/tacacs_plus:latest

Ensuite, configurez les conteneurs en mode configuration :

set container network tac-test prefix '100.64.0.0/24'

set container name tacacs1 image 'lfkeitel/tacacs_plus:latest'
set container name tacacs1 network tac-test address '100.64.0.11'

set container name tacacs2 image 'lfkeitel/tacacs_plus:latest'
set container name tacacs2 network tac-test address '100.64.0.12'

set system login tacacs server 100.64.0.11 key 'tac_plus_key'
set system login tacacs server 100.64.0.12 key 'tac_plus_key'

commit

Vous pouvez maintenant vous connecter via SSH ou console en utilisant les identifiants admin/admin fournis par l'image conteneur.
