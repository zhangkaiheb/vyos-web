Suricata

Suricata est un moteur de détection des menaces réseau open source qui effectue la détection d'intrusion (IDS), la prévention d'intrusion en ligne (IPS) et la surveillance de la sécurité réseau (NSM) en comparant le trafic en temps réel à un ensemble de règles, également appelées signatures. Chaque événement est enregistré dans le journal d'événements EVE au format JSON.

VyOS intègre Suricata en tant que service géré, configurable sous service suricata. Lorsque la configuration est validée, VyOS génère la configuration de Suricata à partir de ces paramètres et lance le service.

Sous service suricata, vous pouvez configurer les éléments suivants :

  • Interfaces surveillées : une ou plusieurs interfaces sur lesquelles Suricata capture le trafic.

  • Groupes d'adresses : listes nommées d'adresses IPv4/IPv6 ou de préfixes, utilisées à la place des adresses IP littérales dans les règles de Suricata.

  • Groupes de ports : listes nommées de ports ou de plages de ports, utilisées à la place des ports littéraux dans les règles de Suricata.

  • Journaux EVE : destination (fichier régulier ou syslog), nom ou chemin du fichier, et types d'événements à journaliser.

Les règles sont récupérées séparément en exécutant update suricata en mode opérationnel. Jusqu'à ce que cette commande soit exécutée, le service n'a pas de règles à matcher.

Remarque

Une configuration Suricata ne peut être validée que lorsqu'au moins une interface, un groupe d'adresses et un groupe de ports sont définis. Sinon, la validation échoue.

Configuration

Interfaces surveillées

Utilisez la commande suivante pour configurer les interfaces surveillées par Suricata.

set service suricata interface <interface>

Configurez une interface sur laquelle Suricata capture et inspecte le trafic.

Répétez la commande pour surveiller plusieurs interfaces. Au moins une interface doit être configurée pour une validation réussie.

Exemple :

set service suricata interface eth1

Groupes d'adresses

Utilisez les commandes suivantes pour configurer les groupes d'adresses.

Note

Les noms de groupe doivent être composés de lettres minuscules, de chiffres ou de tirets.

Note

Les règles de Suricata font référence à un ensemble conventionnel de noms de groupes, tels que home-net, external-net, http-servers, et d'autres. La définition d'un groupe avec un nom non standard est autorisée, mais aucune règle fournie ne fera référence à celui-ci. Les groupes d'adresses typiques incluent :

  • home-net : les réseaux que Suricata devrait traiter comme internes (par exemple, 192.0.2.0/24 et 2001:db8::/32).

  • external-net : tout ce qui n'est pas dans home-net.

  • http-servers, sql-servers, dns-servers : hôtes exécutant les services correspondants.

set service suricata address-group <name> address <address>

Configurez une adresse IPv4 ou IPv6 ou un préfixe comme membre du groupe d'adresses spécifié.

<address> accepte une adresse IPv4 ou IPv6, un préfixe IPv4 ou IPv6, ou l'une de ces adresses précédée de ! pour l'exclure des correspondances.

Répétez la commande pour ajouter plus d'adresses ou de préfixes au même groupe.

Exemple :

set service suricata address-group home-net address 192.0.2.0/24
set service suricata address-group home-net address 2001:db8::/32
set service suricata address-group home-net address !192.0.2.5
set service suricata address-group <name> group <name>

Configurez un autre groupe d'adresses comme membre du groupe d'adresses spécifié.

Précédé du nom référencé par ! pour exclure les membres de ce groupe des correspondances. Le groupe référencé doit être défini au moment de la validation, et les références cycliques entre les groupes sont rejetées.

Répétez la commande pour ajouter plus de groupes au même groupe parent.

Exemple :

set service suricata address-group home-net address 192.0.2.0/24
set service suricata address-group external-net group !home-net

Groupes de ports

Utilisez les commandes suivantes pour configurer les groupes de ports.

Note

Les noms de groupe doivent être composés de lettres minuscules, de chiffres ou de tirets.

Note

Les règles de Suricata font référence à un ensemble conventionnel de noms de groupes de ports, tels que http-ports, ssh-ports, oracle-ports, shellcode-ports, et d'autres. La définition d'un groupe de ports avec un nom non standard est autorisée, mais aucune règle fournie ne fera référence à celui-ci. Les groupes de ports typiques incluent :

  • http-ports : ports où les services HTTP s'exécutent.

  • ssh-ports : ports où les services SSH écoutent.

  • oracle-ports : ports utilisés par les services de base de données Oracle.

  • shellcode-ports : ports inspectés par les règles de détection de shellcode.

set service suricata port-group <name> port <port>

Configurez un port ou une plage de ports comme membre du groupe de ports spécifié.

<port> accepte un seul port (1–65535), une plage numérique au format start-end (ex. 1001-1005), ou l'une de ces formes précédée de ! pour l'exclure des correspondances.

Répétez la commande pour ajouter plus de ports ou de plages de ports au même groupe.

Exemple :

set service suricata port-group http-ports port 80
set service suricata port-group http-ports port 443
set service suricata port-group http-ports port 8000-8999
set service suricata port-group http-ports port !8080
set service suricata port-group <name> group <name>

Configurez un autre groupe de ports comme membre du groupe de ports spécifié.

Précédé du nom référencé par ! pour exclure les membres de ce groupe des correspondances. Le groupe référencé doit être défini au moment de la validation, et les références cycliques entre les groupes sont rejetées.

Répétez la commande pour ajouter plusieurs groupes au même groupe parent.

Exemple :

set service suricata port-group http-ports port 80
set service suricata port-group shellcode-ports group !http-ports

Journaux EVE

Utilisez les commandes suivantes pour configurer les journaux EVE.

set service suricata log eve filename <filename>

Configurez le nom du fichier ou le chemin pour le journal EVE de Suricata.

Un nom de fichier simple (ex. eve.json) place le journal dans le répertoire par défaut de Suricata, /var/log/suricata/. Un chemin absolu est utilisé tel quel.

La valeur par défaut est eve.json.

Exemple :

set service suricata log eve filename eve.json
set service suricata log eve filename /var/log/custom/suricata-eve.json
set service suricata log eve filetype <regular | syslog>

Configurez la destination pour le journal EVE de Suricata :

  • regular : écrit le journal EVE dans le fichier spécifié par set service suricata log eve filename.

  • syslog : envoie le journal EVE vers syslog.

La valeur par défaut est regular.

Exemple :

set service suricata log eve filetype syslog
set service suricata log eve type <type>

Configurez quels types d'événements EVE sont journalisés.

Valeurs acceptées :

  • Types d'événements généraux : alert, anomaly, drop, files, flow, netflow.

  • Types d'événements par protocole : http, http2, dns, tls, smtp, ftp, smb, ssh, dhcp, tftp, nfs, rdp, sip, snmp, ikev2, krb5, dcerpc, dnp3, rfb, mqtt.

Répétez la commande pour journaliser plusieurs types d'événements.

Exemple :

set service suricata log eve type alert
set service suricata log eve type flow
set service suricata log eve type http

Opération

update suricata

Récupérez l'ensemble de règles actuel avec suricata-update et redémarrez le service Suricata pour le charger.

Si service suricata n'est pas configuré, la commande affiche un message d'erreur et quitte.

Exemple :

update suricata
restart suricata

Redémarrez le service Suricata.

Si le service n'est pas configuré (aucune configuration service suricata n'existe), ou si une validation de configuration est en cours, la commande affiche un message d'erreur et quitte.

Exemple :

restart suricata
