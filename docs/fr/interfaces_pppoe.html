PPPoE

PPPoE est un protocole réseau qui encapsule les trames PPP dans des trames Ethernet. Il est souvent utilisé pour connecter les clients d'un FAI à un serveur d'accès à large bande.

Configuration

Configuration commune de l'interface

set interfaces pppoe <interface> description <description>

Configurez un alias clair et descriptif pour l'interface.

Cet alias apparaît dans la commande show interfaces et les outils de surveillance basés sur SNMP.

Exemple :

set interfaces pppoe pppoe0 description 'This is an interface running on VyOS.'
set interfaces pppoe <interface> disable

Désactiver l'interface.

L'interface sera définie sur l'état administrativement arrêté (A/D).

Exemple :

set interfaces pppoe pppoe0 disable
set interfaces pppoe <interface> mtu <mtu>

Configurer le MTU sur l'interface.

Cette valeur définit la taille maximale du paquet, en octets, que l'interface transmet sans fragmentation.

Exemple :

set interfaces pppoe pppoe0 mtu 1600
set interfaces pppoe <interface> vrf <vrf>

Affectez l'interface à une instance spécifique VRF .

Voir aussi

Pour plus d'informations sur la configuration d'un VRF, consultez la section VRF.

Exemple :

set interfaces pppoe pppoe0 vrf red

Options PPPoE

set interfaces pppoe <interface> access-concentrator <name>

Configurer le nom du concentrateur d'accès cible pour la session PPPoE.

Pendant le processus de découverte PPPoE, le client envoie un paquet d'initialisation PPPoE. Plusieurs concentrateurs d'accès peuvent répondre avec des paquets d'offre, et le client sélectionne l'un d'eux.

Cette configuration restreint le client à établir des sessions uniquement avec le concentrateur d'accès spécifié.

set interfaces pppoe <interface> authentication username <username>

Configurer le nom d'utilisateur pour l'authentification de session PPPoE.

Même si l'authentification est facultative dans la configuration de l'interface, la plupart des FAIs la nécessitent pour établir une connexion.

set interfaces pppoe <interface> authentication password <password>

Configurer le mot de passe pour l'authentification de session PPPoE.

Même si l'authentification est facultative dans la configuration de l'interface, la plupart des FAIs la nécessitent pour établir une connexion.

set interfaces pppoe <interface> connect-on-demand

Activer le dial-on-demand sur l'interface PPPoE.

Lorsqu'elle est activée, le système établit une connexion PPPoE uniquement lorsqu'il y a du trafic à travers l'interface. Si la connexion échoue, elle est rétablie lorsque le trafic reprend.

Pour les connexions à la demande, vous devez également configurer une période idle-timeout pour déconnecter la session après une inactivité.

Note

Si le délai d'inactivité est défini à zéro, ou s'il n'est pas configuré, la connexion reste active continuellement une fois établie.

Par défaut, la connexion PPPoE est établie au démarrage et reste active continuellement ; si la connexion échoue, elle est rétablie immédiatement.

set interfaces pppoe <interface> no-default-route

Demander une adresse IP au serveur PPPoE sans installer une route par défaut.

Exemple :

set interfaces pppoe pppoe0 no-default-route

Note

Introduit dans VyOS 1.4, cette commande inverse la logique de l'option CLI précédente default-route.

set interfaces pppoe <interface> default-route-distance <distance>

Configurer la distance pour la passerelle par défaut fournie par le serveur PPPoE.

Exemple :

set interfaces pppoe pppoe0 default-route-distance 220
set interfaces pppoe <interface> mru <mru>

Configurer le MRU pour l'interface PPPoE.

Cette configuration indique au daemon pppd de limiter le pair distant à envoyer des paquets plus grands que le MRU configuré. Les valeurs de MRU autorisées vont de 128 à 16384 octets.

Un MRU de 296 convient aux liens très lents (40 octets pour l'en-tête TCP/IP et 256 octets pour les données).

La valeur par défaut du MRU est de 1492 octets.

Note

Lors de l'utilisation du protocole IPv6, le MRU doit être d'au moins 1280 octets.

set interfaces pppoe <interface> idle-timeout <time>

Configurer le délai d'inactivité pour les sessions PPPoE à la demande.

Cette configuration définit combien de temps la connexion reste active sans aucun trafic avant d'être déconnectée.

Note

Si le délai d'inactivité est défini à zéro, ou s'il n'est pas configuré, la connexion reste active continuellement une fois établie.

set interfaces pppoe <interface> holdoff <time>

Configurer le délai de redial pour les sessions PPPoE persistantes.

Si une session persistante (avec connect-on-demand désactivé) est terminée par le pair distant ou tombe inopinément, le routeur attend l'intervalle spécifié avant d'essayer de se reconnecter.

Le délai de redial par défaut est de 30 secondes.

set interfaces pppoe <interface> local-address <address>

Configurer l'adresse IP de l'extrémité locale pour les sessions PPPoE.

Par défaut, cette adresse IP est négociée.

set interfaces pppoe <interface> no-peer-dns

Désactiver l'installation des serveurs DNS annoncés sur le système local.

set interfaces pppoe <interface> remote-address <address>

Configurer l'adresse IP de l'extrémité distante pour les sessions PPPoE.

Par défaut, cette adresse IP est négociée.

set interfaces pppoe <interface> service-name <name>

Configurer le nom du service du concentrateur d'accès cible pour la session PPPoE.

Par défaut, l'interface PPPoE se connecte à tout concentrateur d'accès disponible.

set interfaces pppoe <interface> source-interface <source-interface>

Configurer l'interface sous-jacente pour la connexion PPPoE.

Chaque connexion PPPoE est établie sur une interface sous-jacente, qui peut être une interface Ethernet, un VIF, ou une interface de regroupement.

set interfaces pppoe <interface> ip adjust-mss <mss | clamp-mss-to-pmtu>

Configurer le MSS annoncé dans les paquets TCP SYN sortants sur l'interface spécifiée.

En limitant la valeur du MSS dans les paquets TCP SYN, vous indiquez au côté distant de ne pas envoyer de paquets plus grands que la taille spécifiée. Cela aide à éviter les problèmes de connexion si PMTUD échoue.

Les options suivantes sont disponibles :

  • mss : Définit le MSS à une valeur spécifique en octets.

  • clamp-mss-to-pmtu : Définit le MSS à la taille MTU de l'interface moins 40 octets pour le trafic IPv4 (20 octets pour l'en-tête IPv4 et 20 octets pour l'en-tête TCP). Cette option est recommandée pour définir automatiquement la bonne valeur.

Note

Introduit dans VyOS 1.4, cette commande remplace la syntaxe plus ancienne set firewall options interface <name> adjust-mss <value>.

set interfaces pppoe <interface> ip disable-forwarding

Configurer l'interface pour un comportement d'hôte ou de routeur.

Si configuré, l'interface passe en mode hôte, et le transfert IPv4 est désactivé sur celle-ci.

set interfaces pppoe <interface> ip source-validation <strict | loose | disable>

Configurer la validation de l'adresse IP source à l'aide de RPF sur cette interface, comme spécifié dans RFC 3704.

Les options suivantes sont disponibles :

  • strict : Chaque paquet entrant est vérifié contre la FIB. Si l'interface n'est pas le meilleur chemin vers la source, la validation échoue et le paquet est supprimé.

  • loose : Chaque paquet entrant est vérifié contre la FIB. Si l'adresse IP source est inaccessible via n'importe quelle interface, la validation échoue.

  • disable : Aucune validation de l'adresse IP source n'est effectuée. Tous les paquets entrants sont acceptés.

RFC 3704 recommande d'activer le mode strict pour empêcher le spoofing d'IP, comme les attaques DDoS. Pour les scénarios de routage asynchrones ou autres complexes, utilisez le mode loose.

IPv6

set interfaces pppoe <interface> ipv6 address autoconf

Activer l'attribution d'adresses IPv6 via SLAAC sur cette interface.

set interfaces pppoe <interface> ipv6 adjust-mss <mss | clamp-mss-to-pmtu>

Configurer le MSS annoncé dans les paquets TCP SYN sortants sur l'interface spécifiée.

En limitant la valeur du MSS dans les paquets TCP SYN, vous indiquez au côté distant de ne pas envoyer de paquets plus grands que la taille spécifiée. Cela aide à éviter les problèmes de connexion si PMTUD échoue.

Les options suivantes sont disponibles :

  • mss : Définit le MSS à une valeur spécifique en octets.

  • clamp-mss-to-pmtu : Définit le MSS à la taille MTU de l'interface moins 60 octets pour le trafic IPv6 (40 octets pour l'en-tête IPv6 et 20 octets pour l'en-tête TCP). Cette option est recommandée pour définir automatiquement la bonne valeur.

Note

Introduit dans VyOS 1.4, cette commande remplace la syntaxe plus ancienne set firewall options interface <name> adjust-mss <value>.

set interfaces pppoe <interface> ipv6 disable-forwarding

Configurer l'interface pour un comportement d'hôte ou de routeur.

Si configuré, l'interface passe en mode hôte, et le transfert IPv6 est désactivé sur celle-ci.

DHCPv6 Prefix Delegation (PD)

VyOS prend en charge DHCPv6 Prefix Delegation (DHCPv6-PD) tel que décrit dans RFC 3633. DHCPv6-PD est pris en charge par la plupart des FAIs qui fournissent IPv6 natif pour les consommateurs sur des réseaux fixes.

set interfaces pppoe <interface> dhcpv6-options pd <id> length <length>

Configurer une longueur de préfixe spécifique pour les demandes DHCPv6-PD sur cette interface.

Certains FAIs fournissent uniquement un préfixe /64 par défaut. Utilisez cette commande pour demander une longueur de préfixe différente pour une demande DHCPv6-PD spécifique, allant de /32 (si autorisé par votre FAI) à /64. <id> est un identifiant unique pour la demande DHCPv6-PD.

La valeur par défaut est 64.

Pour demander un préfixe /56 à votre FAI, utilisez :

set interfaces pppoe pppoe0 dhcpv6-options pd 0 length 56
set interfaces pppoe <interface> dhcpv6-options pd <id> interface <delegatee> address <address>

Configurer l'identifiant d'interface IPv6 (partie hôte) pour l'interface déléguée.

La valeur doit être un entier décimal. Elle est ajoutée au préfixe délégué et à l'ID SLA configuré pour former l'adresse IPv6 finale.

Par défaut, la partie hôte est générée en fonction de l'adresse MAC de l'interface parente (format EUI-64).

Exemple :

Si un préfixe /64 est délégué à l'interface eth8 et que vous configurez la partie hôte comme 65535, l'adresse IPv6 résultante se terminera par ::ffff, car 65535 correspond à ffff en notation hexadécimale.

set interfaces pppoe pppoe0 dhcpv6-options pd 0 interface eth8 address 65534
set interfaces pppoe <interface> dhcpv6-options pd <id> interface <delegatee> sla-id <id>

Configurer le SLA ID pour l'interface déléguée.

La valeur doit être un entier décimal supérieur à 0 et convenir à la longueur des IDs SLA. Elle est convertie en hexadécimal et ajoutée au préfixe délégué pour former le préfixe de sous-réseau spécifique pour l'interface déléguée.

Exemple :

Si le SLA ID est 1 et que le préfixe délégué est 2001:db8:ffff::/48, le préfixe de sous-réseau résultant pour l'interface déléguée sera 2001:db8:ffff:1::/64.

set interfaces pppoe pppoe0 dhcpv6-options pd 0 interface eth8 sla-id 1

Connecter/déconnecter

disconnect interface <interface>

Déconnecter l'interface spécifiée.

connect interface <interface>

Initier une session sur l'interface spécifiée.

Exemple

PPPoE sur DSL

Scénario de configuration :

  • Votre modem DSL de FAI est connecté à l'interface eth0 sur votre routeur VyOS.

  • Votre FAI n'exige pas de balisage VLAN.

  • Les identifiants PPPoE sont fournis par votre FAI. Le format typique du nom d'utilisateur est name@host.net, bien que cela puisse varier.

Remarques de configuration :

  • La taille MTU maximale pour le DSL est de 1492 car de la surcharge PPPoE. Si vous passez d'un FAI basé sur DHCP (par exemple, une connexion câble standard), assurez-vous que les liens VPN ont des tailles MTU ajustées en conséquence.

  • Pour ignorer les serveurs DNS fournis par le FAI et n'utiliser que ceux que vous avez configurés manuellement, définissez l'option name-server sur none.

  • Une route par défaut est installée automatiquement une fois l'interface active. Pour changer ce comportement, utilisez l'option CLI no-default-route.

Note

La syntaxe de configuration PPPoE a changé après VyOS 1.2 (Crux) et est automatiquement migrée pendant une mise à jour.

set interfaces pppoe pppoe0 authentication username 'userid'
set interfaces pppoe pppoe0 authentication password 'secret'
set interfaces pppoe pppoe0 source-interface 'eth0'

Sécurisez votre configuration en créant des règles correspondant à l'interface pppoe0 dans les chaînes de pare-feu :

set firewall ipv4 input filter rule 10 inbound-interface name 'pppoe0'
set firewall ipv4 forward filter rule 10 inbound-interface name 'pppoe0'

PPPoE sur VLAN

Certains FAIs exigent que les connexions PPPoE soient établies sur une interface VLAN. Cette topologie spécifique est pleinement prise en charge par VyOS.

La configuration suivante établit la connexion PPPoE via le VLAN 7, qui est le VLAN par défaut pour Deutsche Telekom :

set interfaces pppoe pppoe0 authentication username 'userid'
set interfaces pppoe pppoe0 authentication password 'secret'
set interfaces pppoe pppoe0 source-interface 'eth0.7'

Délégation de préfixe DHCPv6 IPv6

Scénario de configuration :

La configuration suivante établit une session PPPoE sur l'interface eth1, demande un délégué de préfixe IPv6 /56 auprès du FAI, et attribue un sous-réseau /64 de ce délégué à l'interface eth0.

Remarques de configuration :

  • L'adresse IPv6 assignée à eth0 est <prefix>::1/64.

  • Si vous ne connaissez pas la taille de votre préfixe délégué, commencez par sla-len 0.

  • Pour annoncer le préfixe sur le lien eth0, configurez l'annonce de routeur IPv6.

set interfaces pppoe pppoe0 authentication username vyos
set interfaces pppoe pppoe0 authentication password vyos
set interfaces pppoe pppoe0 dhcpv6-options pd 0 interface eth0 address '1'
set interfaces pppoe pppoe0 dhcpv6-options pd 0 interface eth0 sla-id '0'
set interfaces pppoe pppoe0 dhcpv6-options pd 0 length '56'
set interfaces pppoe pppoe0 ipv6 address autoconf
set interfaces pppoe pppoe0 source-interface eth1

set service router-advert interface eth0 prefix ::/64
