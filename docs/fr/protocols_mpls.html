MPLS

MPLS est une méthode de transfert de paquets qui diffère du transfert IP traditionnel. Au lieu d'effectuer des recherches d'adresses IP, les routeurs MPLS transmettent le trafic en utilisant des recherches d'exact match sur les étiquettes MPLS insérées entre le niveau 2 (Ethernet) et le niveau 3 (IP).

Les étiquettes MPLS peuvent être attribuées statiquement ou dynamiquement. Cette section se concentre sur l'allocation dynamique des étiquettes à l'aide de protocoles de distribution d'étiquettes tels que le LDP et RSVP-TE, ou via les extensions SR d'OSPF ou IS-IS.

Ces protocoles établissent un chemin unidirectionnel appelé un LSP à travers le réseau. Lorsqu'un paquet entre dans le réseau MPLS, le routeur d'entrée insère une étiquette MPLS sur celui-ci en fonction de la destination et le transmet le long du LSP. Chaque routeur intermédiaire utilise l'étiquette entrante pour rechercher l'interface de sortie et la valeur de l'étiquette suivante, remplace l'étiquette et transmet le paquet sur cette interface. Le routeur de sortie supprime l'étiquette et transmet le paquet original en utilisant le routage IP normal.

Prise en charge MPLS dans VyOS

La prise en charge MPLS dans VyOS est en cours de développement, donc son ensemble de fonctionnalités est actuellement limité. Le transfert MPLS de base fonctionne, car la pile de routage FRR sous-jacente prend en charge RFC 3031.

Fonctionnalités prises en charge :

  • LDP: Implémenté conformément à RFC 5036.

Note

D'autres normes LDP connexes incluent les RFCs 6720, 6667, 5919, 5561, et 7552.

Limitations actuelles :

  • VNP MPLS: Aucune prise en charge pour les services VNP MPLS, tels que les L2VPNs et mVPNs.

  • RSVP-TE: Non pris en charge, car la pile FRR sous-jacente ne l'implémente pas actuellement.

Protocole de distribution d'étiquettes (LDP)

MPLS prend en charge plusieurs protocoles pour la création de chemins. VyOS implémente le LDP via la pile de routage FRR sous-jacente, selon RFC 5036.

Le LDP est un protocole de signalisation MPLS basé sur TCP qui distribue dynamiquement des étiquettes pour créer des chemins commutés par étiquettes. Il n'est pas un protocole de routage et dépend des protocoles de routage existants pour les décisions de transfert et la communication avec d'autres routeurs LDP.

Pour échanger les annonces d'étiquettes, le LDP établit des sessions TCP avec des pairs automatiquement découverts ou configurés statiquement. Chaque session est formée en utilisant l'adresse de transport du pair, qui doit être présente dans le tableau de routage et continuellement accessible.

Note

Il est recommandé d'utiliser la même adresse pour l'ID du routeur LDP et l'adresse de transport de la découverte. Pour que le LDP fonctionne dans VyOS, les deux paramètres doivent être configurés explicitement.

Note

Le LDP n'a aucun mécanisme pour rafraîchir une session existante. Pour appliquer une modification de configuration ou un changement dans les capacités de session négociées, il faut réinitialiser le pair LDP sur le routeur local.

Configuration

set protocols mpls interface <interface>

Activer le MPLS sur l'interface spécifiée.

Exemple :

set protocols mpls interface eth1
set protocols mpls parameters no-propagate-ttl

Désactiver la propagation de la TTL IP dans l'en-tête MPLS lors de l'imposition de l'étiquette.

Exemple :

set protocols mpls parameters no-propagate-ttl
set protocols mpls parameters maximum-ttl <1-255>

Configurer la valeur maximale de TTL pour les paquets MPLS.

Cette valeur est utilisée lorsque la TTL n'est pas propagée depuis l'en-tête IP. La valeur par défaut est 255.

Exemple :

set protocols mpls parameters maximum-ttl 15
set protocols mpls ldp interface <interface>

Activer le LDP sur l'interface spécifiée.

Exemple :

set protocols mpls ldp interface eth1
set protocols mpls ldp interface <interface> disable-establish-hello

Désactiver le Hello déclenché que le routeur envoie sur l'interface spécifiée en réponse à la réception d'un Hello LDP d'un pair.

Exemple :

set protocols mpls ldp interface eth0 disable-establish-hello
set protocols mpls ldp router-id <address>

Configurer l'adresse IP utilisée comme ID de routeur LDP pour l'appareil local.

Exemple :

set protocols mpls ldp router-id 192.0.2.1
set protocols mpls ldp discovery transport-ipv4-address <address>

Configurer l'adresse de transport IPv4 pour les connexions LDP IPv4.

Exemple :

set protocols mpls ldp discovery transport-ipv4-address 192.0.2.1
set protocols mpls ldp discovery transport-ipv6-address <address>

Configurer l'adresse de transport IPv6 pour les connexions LDP IPv6.

Exemple :

set protocols mpls ldp discovery transport-ipv6-address 2001:db8::1
set protocols mpls ldp neighbor <ipv4-address> password <password>

Configurer l'authentification pour la session LDP avec le pair spécifié.

Note

Pour que la session s'établisse correctement, les deux pairs doivent être configurés avec le même mot de passe.

Exemple :

set protocols mpls ldp neighbor 192.0.2.2 password mysharedsecret
set protocols mpls ldp neighbor <ipv4-address> session-holdtime <15-65535>

Configurer le temps d'attente de la session LDP, en secondes, annoncé au pair spécifié.

Le pair doit être réinitialisé pour que ce changement prenne effet.

Exemple :

set protocols mpls ldp neighbor 192.0.2.2 session-holdtime 180
set protocols mpls ldp neighbor <ipv4-address> ttl-security <disable | 1-254>

Configurer la sécurité TTL (GTSM) pour la session LDP avec le pair spécifié.

Utilisez disable pour désactiver la sécurité TTL, ou définissez une valeur de compteur de sauts (1-254) pour restreindre les paquets entrants acceptés en fonction de leur TTL.

Exemple :

set protocols mpls ldp neighbor 192.0.2.2 ttl-security 5
set protocols mpls ldp discovery hello-ipv4-interval <1-65535>

Configurer l'intervalle, en secondes, à partir duquel le routeur envoie des messages Hello IPv4 LDP.

Exemple :

set protocols mpls ldp discovery hello-ipv4-interval 5
set protocols mpls ldp discovery hello-ipv4-holdtime <1-65535>

Configurer le délai d'attente, en secondes, annoncé dans les messages Hello IPv4 LDP.

Exemple :

set protocols mpls ldp discovery hello-ipv4-holdtime 15
set protocols mpls ldp discovery hello-ipv6-interval <1-65535>

Configurer l'intervalle, en secondes, à partir duquel le routeur envoie des messages Hello IPv6 LDP.

Exemple :

set protocols mpls ldp discovery hello-ipv6-interval 5
set protocols mpls ldp discovery hello-ipv6-holdtime <1-65535>

Configurer le délai d'attente, en secondes, annoncé dans les messages Hello IPv6 LDP.

Exemple :

set protocols mpls ldp discovery hello-ipv6-holdtime 15
set protocols mpls ldp discovery session-ipv4-holdtime <15-65535>

Configurer le délai d'attente de la session LDP, en secondes, annoncé dans les messages d'initialisation IPv4 LDP.

Exemple :

set protocols mpls ldp discovery session-ipv4-holdtime 180
set protocols mpls ldp discovery session-ipv6-holdtime <15-65535>

Configurer le délai d'attente de la session LDP, en secondes, annoncé dans les messages d'initialisation IPv6 LDP.

Exemple :

set protocols mpls ldp discovery session-ipv6-holdtime 180
set protocols mpls ldp import ipv4 import-filter filter-access-list <1-2699>

Filtrer les liaisons d'étiquettes IPv4 (associations entre un préfixe IPv4 et une étiquette MPLS) provenant des pairs LDP à l'aide de la liste d'accès spécifiée.

Seules les liaisons d'étiquettes dont le préfixe est autorisé par la liste d'accès sont acceptées.

Exemple :

set protocols mpls ldp import ipv4 import-filter filter-access-list 10
set protocols mpls ldp import ipv4 import-filter neighbor-access-list <1-2699>

Filtrer les liaisons d'étiquettes IPv4 (associations entre un préfixe IPv4 et une étiquette MPLS) provenant des pairs LDP à l'aide de la liste d'accès spécifiée.

Seules les liaisons d'étiquettes reçues d'un pair dont l'adresse IPv4 est autorisée par la liste d'accès sont acceptées.

Exemple :

set protocols mpls ldp import ipv4 import-filter neighbor-access-list 20
set protocols mpls ldp import ipv6 import-filter filter-access-list6 <1-2699>

Filtrer les liaisons d'étiquettes IPv6 (associations entre un préfixe IPv6 et une étiquette MPLS) provenant des pairs LDP à l'aide de la liste d'accès spécifiée.

Seules les liaisons d'étiquettes dont le préfixe est autorisé par la liste d'accès sont acceptées.

Exemple :

set protocols mpls ldp import ipv6 import-filter filter-access-list6 10
set protocols mpls ldp import ipv6 import-filter neighbor-access-list6 <1-2699>

Filtrer les liaisons d'étiquettes IPv6 (associations entre un préfixe IPv6 et une étiquette MPLS) provenant des pairs LDP à l'aide de la liste d'accès spécifiée.

Seules les liaisons d'étiquettes reçues d'un pair dont l'adresse IPv6 est autorisée par la liste d'accès sont acceptées.

Exemple :

set protocols mpls ldp import ipv6 import-filter neighbor-access-list6 20
set protocols mpls ldp export ipv4 export-filter filter-access-list <1-2699>

Filtrer les liaisons d'étiquettes IPv4 (associations entre un préfixe IPv4 et une étiquette MPLS) annoncées aux pairs LDP à l'aide de la liste d'accès spécifiée.

Seules les liaisons d'étiquettes dont le préfixe est autorisé par la liste d'accès sont annoncées.

Exemple :

set protocols mpls ldp export ipv4 export-filter filter-access-list 10
set protocols mpls ldp export ipv4 export-filter neighbor-access-list <1-2699>

Filtrer les liaisons d'étiquettes IPv4 (associations entre un préfixe IPv4 et une étiquette MPLS) annoncées aux pairs LDP à l'aide de la liste d'accès spécifiée.

Les liaisons d'étiquettes sont annoncées uniquement aux pairs dont l'adresse IPv4 est autorisée par la liste d'accès.

Exemple :

set protocols mpls ldp export ipv4 export-filter neighbor-access-list 20
set protocols mpls ldp export ipv6 export-filter filter-access-list6 <1-2699>

Filtrer les liaisons d'étiquettes IPv6 (associations entre un préfixe IPv6 et une étiquette MPLS) annoncées aux pairs LDP à l'aide de la liste d'accès spécifiée.

Seules les liaisons d'étiquettes dont le préfixe est autorisé par la liste d'accès sont annoncées.

Exemple :

set protocols mpls ldp export ipv6 export-filter filter-access-list6 10
set protocols mpls ldp export ipv6 export-filter neighbor-access-list6 <1-2699>

Filtrer les liaisons d'étiquettes IPv6 (associations entre un préfixe IPv6 et une étiquette MPLS) annoncées aux pairs LDP à l'aide de la liste d'accès spécifiée.

Les liaisons d'étiquettes sont annoncées uniquement aux pairs dont l'adresse IPv6 est autorisée par la liste d'accès.

Exemple :

set protocols mpls ldp export ipv6 export-filter neighbor-access-list6 20
set protocols mpls ldp export ipv4 explicit-null

Configurer le routeur pour annoncer l'étiquette Explicit Null pour ses préfixes IPv4 directement connectés aux pairs LDP.

Cela indique au routeur de la dernière étape de saut de transmettre les paquets étiquetés sans les modifier et sans supprimer l'étiquette MPLS.

Exemple :

set protocols mpls ldp export ipv4 explicit-null
set protocols mpls ldp export ipv6 explicit-null

Configurer le routeur pour annoncer l'étiquette Explicit Null pour ses préfixes IPv6 directement connectés aux pairs LDP.

Cela indique au routeur de la dernière étape de saut de transmettre les paquets étiquetés sans les modifier et sans supprimer l'étiquette MPLS.

Exemple :

set protocols mpls ldp export ipv6 explicit-null
set protocols mpls ldp allocation ipv4 access-list <1-2699>

Restreindre l'allocation d'étiquettes MPLS aux préfixes IPv4 autorisés par la liste d'accès spécifiée.

Par défaut, le LDP alloue une étiquette pour chaque préfixe IPv4 dans le tableau de routage. Une pratique courante est de limiter l'allocation aux adresses de boucle.

Exemple :

set protocols mpls ldp allocation ipv4 access-list 10
set protocols mpls ldp allocation ipv6 access-list6 <1-2699>

Restreindre l'allocation d'étiquettes MPLS aux préfixes IPv6 autorisés par la liste d'accès spécifiée.

Par défaut, le LDP alloue une étiquette pour chaque préfixe IPv6 dans le tableau de routage. Une pratique courante est de limiter l'allocation aux adresses de boucle.

Exemple :

set protocols mpls ldp allocation ipv6 access-list6 10
set protocols mpls ldp parameters cisco-interop-tlv

Configurer le routeur pour négocier la capacité Dual-Stack TLV (RFC 7552) en utilisant un format non conforme Cisco pour les sessions LDP dual-stack.

Exemple :

set protocols mpls ldp parameters cisco-interop-tlv
set protocols mpls ldp parameters ordered-control

Activer le mode de contrôle de distribution d'étiquettes LDP ordonné (RFC 5036) pour le routeur.

Par défaut, le routeur fonctionne en mode de contrôle de distribution d'étiquettes indépendant.

Exemple :

set protocols mpls ldp parameters ordered-control
set protocols mpls ldp parameters transport-prefer-ipv4

Configurer le routeur pour privilégier une connexion TCP IPv4 pour le peering LDP lorsqu'il est configuré pour une opération dual-stack (les familles d'adresses IPv4 et IPv6 sont activées).

Exemple :

set protocols mpls ldp parameters transport-prefer-ipv4
set protocols mpls ldp targeted-neighbor ipv4 enable

Activer le routeur pour accepter les sessions IPv4 LDP ciblées.

Cela permet au routeur d'établir des adjacences LDP avec des pairs non directement connectés en répondant aux messages Hello LDP ciblés (unicast).

Exemple :

set protocols mpls ldp targeted-neighbor ipv4 enable
set protocols mpls ldp targeted-neighbor ipv6 enable

Activer le routeur pour accepter les sessions IPv6 LDP ciblées.

Cela permet au routeur d'établir des adjacences LDP avec des pairs non directement connectés en répondant aux messages Hello LDP ciblés (unicast).

Exemple :

set protocols mpls ldp targeted-neighbor ipv6 enable
set protocols mpls ldp targeted-neighbor ipv4 address <address>

Configurer le routeur pour initier une session IPv4 LDP ciblée avec le LSR distant spécifié.

Exemple :

set protocols mpls ldp targeted-neighbor ipv4 address 192.0.2.5
set protocols mpls ldp targeted-neighbor ipv6 address <address>

Configurer le routeur pour initier une session IPv6 LDP ciblée avec le LSR distant spécifié.

Exemple :

set protocols mpls ldp targeted-neighbor ipv6 address 2001:db8::5
set protocols mpls ldp targeted-neighbor ipv4 hello-holdtime <1-65535>

Configurer le délai d'attente, en secondes, annoncé dans les messages Hello IPv4 LDP ciblés.

Exemple :

set protocols mpls ldp targeted-neighbor ipv4 hello-holdtime 45
set protocols mpls ldp targeted-neighbor ipv4 hello-interval <1-65535>

Configurer l'intervalle, en secondes, entre les messages Hello IPv4 LDP ciblés envoyés aux LSR distants.

Exemple :

set protocols mpls ldp targeted-neighbor ipv4 hello-interval 15
set protocols mpls ldp targeted-neighbor ipv6 hello-holdtime <1-65535>

Configurer le délai d'attente, en secondes, annoncé dans les messages Hello IPv6 LDP ciblés.

Exemple :

set protocols mpls ldp targeted-neighbor ipv6 hello-holdtime 45
set protocols mpls ldp targeted-neighbor ipv6 hello-interval <1-65535>

Configurer l'intervalle, en secondes, entre les messages Hello IPv6 LDP ciblés envoyés aux LSR distants.

Exemple :

set protocols mpls ldp targeted-neighbor ipv6 hello-interval 15

Opération

Lorsque le LDP est établi, vous pouvez visualiser les affectations d'étiquettes directement dans les sorties de show ip route ou show ipv6 route. Pour inspecter les états opérationnels du LDP, utilisez les commandes suivantes.

Afficher

show mpls ldp binding

Afficher la LIB.

show mpls ldp binding <prefix>

Afficher les liaisons d'étiquettes LDP pour le préfixe spécifié.

Le paramètre <prefix> accepte un préfixe IPv4 (x.x.x.x/x) ou un préfixe IPv6 (h:h:h:h:h:h:h:h/h).

show mpls ldp binding detail

Afficher les entrées détaillées de la base d'informations d'étiquettes LDP (LIB).

show mpls ldp binding neighbor <address>

Afficher les liaisons d'étiquettes LDP apprises du pair spécifié.

Le paramètre <address> accepte une adresse IPv4 ou IPv6.

show mpls ldp binding local-label <label>

Afficher les liaisons d'étiquettes LDP associées à une valeur d'étiquette localement assignée.

show mpls ldp binding remote-label <label>

Afficher les liaisons d'étiquettes LDP associées à une valeur d'étiquette assignée à distance.

show mpls ldp discovery

Afficher les informations de découverte Hello LDP.

show mpls ldp discovery detail

Afficher les informations détaillées de découverte Hello LDP.

show mpls ldp interface

Afficher les informations d'interface LDP.

show mpls ldp neighbor

Afficher les informations de base sur les pairs LDP.

show mpls ldp neighbor detail

Afficher les informations détaillées sur les pairs LDP.

show mpls ldp neighbor capabilities

Afficher les capacités LDP négociées avec chaque pair pendant l'initialisation de la session.

show mpls ldp neighbor <address>

Afficher les informations de pair LDP pour le pair spécifié.

Le paramètre <address> accepte une adresse IPv4 ou IPv6.

show mpls ldp neighbor <address> detail

Afficher les informations détaillées sur la session LDP pour le pair spécifié.

show mpls ldp neighbor <address> capabilities

Afficher les capacités LDP négociées avec le pair spécifié.

show mpls table

Afficher le tableau MPLS.

show mpls pseudowire

Afficher les interfaces pseudowire MPLS.

Réinitialiser

reset mpls ldp neighbor <address>

Réinitialiser la session LDP établie avec le pair spécifié.

Le paramètre <address> accepte une adresse IPv4 ou IPv6.

Exemple

La configuration suivante met en place un routeur MPLS LDP de base. OSPF est utilisé comme IGP sous-jacent pour fournir la connectivité entre les adresses de boucle des pairs LDP, qui sont ensuite utilisées comme adresses de transport LDP et IDs de routeur. Le transfert MPLS et le LDP sont activés sur l'interface connectée au réseau.

set protocols ospf area 0 network '192.0.2.1/32'
set protocols ospf area 0 network '192.0.2.4/31'
set protocols ospf parameters router-id '192.0.2.1'
set protocols mpls interface 'eth1'
set protocols mpls ldp discovery transport-ipv4-address '192.0.2.1'
set protocols mpls ldp interface 'eth1'
set protocols mpls ldp interface 'lo'
set protocols mpls ldp router-id '192.0.2.1'
set interfaces ethernet eth1 address '192.0.2.5/31'
set interfaces loopback lo address '192.0.2.1/32'

Note

Cet exemple suppose un rôle de routeur transit (P-router) : le transfert MPLS est activé uniquement sur l'interface de transit, pas sur la boucle. Si le routeur doit terminer le trafic encapsulé MPLS sur sa boucle (rôle PE-router), configurez également set protocols mpls interface 'lo'.

Appliquez la même configuration au pair LDP (en utilisant ses propres adresses de boucle et d'interface de transit) pour établir une session LDP de base.
