Aperçu d'IPsec

IPsec est le framework utilisé pour sécuriser les données. IPsec y parvient en fournissant l'authentification, le chiffrement des paquets réseau IP, l'échange de clés et la gestion des clés. VyOS utilise le package Strongswan pour implémenter IPsec.

Authentication Header (AH) est défini dans RFC 4302. Il utilise l'en-tête IP et la charge utile des données pour créer un hachage, qui est ensuite ajouté au paquet. Ce hachage est utilisé pour vérifier que les données n'ont pas été modifiées pendant la transmission réseau.

Encapsulating Security Payload (ESP) est défini dans RFC 4303. Il fournit à la fois le chiffrement et l'authentification des données.

Il existe deux modes IPsec :

Mode Transport IPsec : En mode transport, l'en-tête IPsec (AH ou ESP) est inséré entre l'en-tête IP et l'en-tête du protocole de couche supérieure.

Mode Tunnel IPsec : En mode tunnel, le paquet IP original est encapsulé dans un autre datagramme IP, avec l'en-tête IPsec (AH ou ESP) inséré entre les en-têtes externe et interne.

IKE (Internet Key Exchange)

Le protocole IKE est la méthode par défaut pour la négociation sécurisée des clés IPsec. IKE est conçu pour fournir l'authentification mutuelle des pairs IKE et établir des clés partagées pour créer des associations de sécurité IPsec (SA). Une association de sécurité (SA) inclut tous les attributs pertinents de la connexion, y compris les algorithmes de chiffrement utilisés, le mode IPsec, les clés de chiffrement et d'autres paramètres liés à la transmission des données via la connexion VPN.

IKEv1

IKEv1 est l'ancienne version, encore utilisée aujourd'hui. La plupart des fabricants recommandent désormais d'utiliser le protocole IKEv2.

IKEv1 est décrit dans les RFC suivants : RFC 2409 (IKE), RFC 3407 (IPsec DOI), RFC 3947 (NAT-T), RFC 3948 (Encapsulation UDP des paquets ESP), RFC 3706 (DPD)

IKEv1 fonctionne en deux phases pour établir les SA IKE et IPsec :

  • Phase 1 fournit l'authentification mutuelle des pairs IKE et l'établissement des clés de session. Cette phase utilise l'échange DH, les cookies et l'échange d'ID pour créer la SA IKE. Une fois la SA IKE établie, toutes les communications IKE entre l'initiateur et le répondeur sont protégées par des vérifications d'intégrité de chiffrement et d'authentification. La phase 1 IKE fournit deux modes : Mode principal et Mode agressif.
    • Mode Principal est utilisé pour les connexions VPN site-à-site.
    • Mode Agressif est utilisé pour les connexions VPN d'accès à distance.
  • Phase 2 fournit la négociation et l'établissement des SA IPsec qui sécurisent le trafic de données IP en utilisant ESP ou AH.

IKEv2

IKEv2 est décrit dans RFC 7296. La plus grande différence entre IKEv1 et IKEv2 est qu'IKEv2 est plus simple et plus fiable qu'IKEv1, avec moins de messages échangés lors de l'établissement du VPN et des fonctionnalités de sécurité supplémentaires.

Authentification IKE

VyOS prend en charge 3 méthodes d'authentification :

  • Clé Pré-partagée : Dans cette méthode, les deux pairs du tunnel IPsec doivent avoir la même clé pré-partagée.
  • Certificats Numériques : PKI est utilisé dans cette méthode.
  • Clés RSA : Si la méthode de clé RSA est utilisée dans la politique IKE, assurez-vous que chaque pair possède la clé publique de l'autre pair.

DPD (Dead Peer Detection)

C'est un mécanisme utilisé pour détecter quand un pair VPN n'est plus actif. Ce mécanisme a différents algorithmes pour IKEv1 et IKEv2 dans VyOS. Les requêtes DPD sont envoyées sous forme de messages ISAKMP R-U-THERE, et les réponses DPD sont envoyées sous forme de messages ISAKMP R-U-THERE-ACK. Dans IKEv1, DPD envoie des messages à des intervalles configurés. Si aucune réponse à ces paquets n'est reçue dans le délai d'expiration DPD, le pair distant est considéré comme injoignable. Dans IKEv2, DPD envoie des messages à des intervalles configurés. Si une requête reste sans réponse, Strongswan exécutera son algorithme de retransmission avec ses temporisateurs.

Clé Pré-partagée Post-Quantique (PPK)

Les clés pré-partagées post-quantiques aident à fournir une certaine résistance quantique aux tunnels IPsec lorsque les algorithmes d'échange de clés post-quantiques comme ML-KEM ne sont pas disponibles. L'utilisation de PPK dans IKEv2 est décrite dans RFC 8784.

PPK peut être configuré dans VyOS sous vpn ipsec authentication ppk. PPK nécessite un ID et une valeur secrète. Si PPK est requis pour une connexion IPsec réussie, l'ID et le secret doivent correspondre. Le secret peut être en texte brut, une valeur hexadécimale ou une valeur Base64. La valeur par défaut est le texte brut. Si vous utilisez d'autres types de valeurs, le type de secret doit être défini.

Configuration IKE

Attributs IKE

Les groupes IKE de VyOS ont les options suivantes :

set vpn ipsec ike-group <name> close-action <action>

Définit l'action à entreprendre lorsque le pair distant ferme de manière inattendue un CHILD_SA :

  • none - Définir sur none (par défaut)
  • trap - Installer une politique de trap pour le CHILD_SA ; le trafic correspondant à ces politiques déclenchera un événement d'acquisition, amenant le démon à établir la SA IKE/IPsec requise.
  • start - Tenter de recréer immédiatement le CHILD_SA.

set vpn ipsec ike-group <name> ikev2-reauth

Indique si le rekeying de l'IKE_SA doit également réauthentifier le pair. Dans IKEv1, la réauthentification est toujours effectuée. La définition de ce paramètre active la réauthentification de l'hôte distant lors du rekeying IKE.

set vpn ipsec ike-group <name> key-exchange

Quel protocole doit être utilisé pour initier la connexion. Si non défini, les deux protocoles sont gérés, et la connexion utilise IKEv2 lors de l'initiation mais accepte n'importe quelle version du protocole lors de la réponse :

  • ikev1 - Utiliser IKEv1 pour l'échange de clés.
  • ikev2 - Utiliser IKEv2 pour l'échange de clés.

set vpn ipsec ike-group <name> lifetime

Durée de vie IKE (secondes) <0-86400> (par défaut 28800).

set vpn ipsec ike-group <name> mode

Sélection du mode de phase 1 IKEv1 :

  • main - Utiliser le mode principal pour l'échange de clés dans le protocole IKEv1 (par défaut recommandé).
  • aggressive - Utiliser le mode agressif pour l'échange de clés dans le protocole IKEv1 ; le mode agressif est moins sécurisé que le mode principal.

set vpn ipsec ike-group <name> proposal <number> dh-group <dh-group number>

Groupe DH. La valeur par défaut est 2.

set vpn ipsec ike-group <name> proposal <number> encryption <encryption>

Algorithme de chiffrement. La valeur par défaut est aes128.

set vpn ipsec ike-group <name> proposal <number> hash <hash>

Algorithme de hachage. La valeur par défaut est sha1.

set vpn ipsec ike-group <name> proposal <number> prf <prf>

Fonction pseudo-aléatoire.

Configuration DPD

set vpn ipsec ike-group <name> dead-peer-detection action <action>

Action à effectuer sur ce CHILD_SA lorsque le DPD expire :

  • trap - Installer une politique de trap qui capturera le trafic correspondant et tentera de renégocier le tunnel à la demande.
  • clear - Fermer le CHILD_SA sans action supplémentaire (par défaut).
  • restart - Tenter immédiatement de renégocier le CHILD_SA sous une nouvelle IKE_SA.

set vpn ipsec ike-group <name> dead-peer-detection interval <interval>

Intervalle de keepalive (secondes) <2-86400> (par défaut 30).

set vpn ipsec ike-group <name> dead-peer-detection timeout <timeout>

Délai d'expiration du keepalive (secondes) <2-86400> (par défaut 120) IKEv1 uniquement

Attributs ESP

Dans VyOS, les attributs ESP sont spécifiés via des groupes ESP. Plusieurs propositions peuvent être spécifiées dans un seul groupe.

set vpn ipsec esp-group <name> compression

Activer le protocole IPComp (IP Payload Compression), permettant la compression du contenu des paquets IP.

set vpn ipsec esp-group <name> disable-rekey

Ne pas initier le rekeying des SA localement ; le pair distant doit effectuer le rekeying avant l'expiration.

set vpn ipsec esp-group <name> life-bytes <bytes>

Durée de vie ESP (octets) <1024-26843545600000>. Nombre d'octets transmis avant l'expiration de la SA IPsec.

set vpn ipsec esp-group <name> life-packets <packets>

Durée de vie ESP (paquets) <1000-26843545600000>. Nombre de paquets transmis avant l'expiration de la SA IPsec.

set vpn ipsec esp-group <name> lifetime <timeout>

Durée de vie ESP (secondes) <30-86400> (par défaut 3600). Durée pendant laquelle une instance spécifique de la connexion (l'ensemble des clés de chiffrement/authentification pour les paquets de données utilisateur) doit durer, de la négociation réussie à l'expiration.

set vpn ipsec esp-group <name> mode <mode>

Type de connexion :

  • tunnel - Mode tunnel (par défaut).
  • transport - Mode transport.

set vpn ipsec esp-group <name> pfs <dh-group>

Indique si la confidentialité persistante parfaite (PFS) est requise sur le canal de clés de la connexion, et définit le groupe Diffie-Hellman pour PFS :

  • enable - Hériter du groupe Diffie-Hellman du groupe IKE (par défaut).
  • disable - Désactiver PFS.
  • <dh-group> - Définir le groupe Diffie-Hellman pour PFS.

set vpn ipsec esp-group <name> proposal <number> encryption <encryption>

Algorithme de chiffrement. La valeur par défaut est aes128.

set vpn ipsec esp-group <name> proposal <number> hash <hash>

Algorithme de hachage. La valeur par défaut est sha1.

Paramètres IPsec Globaux

set vpn ipsec interface <name>

Nom de l'interface utilisé pour restreindre les politiques IPsec sortantes. Plusieurs interfaces peuvent être spécifiées. Si aucune interface n'est spécifiée, les politiques IPsec s'appliquent à toutes les interfaces.

set vpn ipsec log level <number>

Niveau de journalisation. La valeur par défaut est 0.

set vpn ipsec log subsystem <name>

Sous-système du démon.

Options

set vpn ipsec options disable-route-autoinstall

Ne pas installer automatiquement les routes vers les réseaux distants.

set vpn ipsec options flexvpn

Autoriser la charge utile d'ID vendeur FlexVPN (IKEv2 uniquement). Envoie la charge utile d'ID vendeur Cisco FlexVPN (IKEv2 uniquement), qui est requise pour permettre aux appareils de marque Cisco de négocier les sélecteurs de trafic local.

set vpn ipsec options interface <name>

Nom de l'interface à utiliser. Le nom de l'interface sur lequel les adresses IP virtuelles doivent être installées. Si non spécifié, les adresses sont installées sur l'interface sortante.

set vpn ipsec options virtual-ip

Autoriser l'installation d'adresses IP virtuelles.

Retransmission IKEv2

Si le pair ne répond pas aux paquets DPD, le routeur initiera une procédure de retransmission. Le délai d'expiration est calculé en utilisant la formule suivante :

relative timeout = timeout * base ^ (attempts-1)

set vpn ipsec options retransmission attempts

Nombre de tentatives avant de considérer le pair comme hors service. La valeur par défaut est 5.

set vpn ipsec options retransmission base

Base pour le backoff exponentiel. La valeur par défaut est 1.8.

set vpn ipsec options retransmission timeout

Délai d'expiration avant la première retransmission (secondes). La valeur par défaut est 4.

En utilisant les valeurs par défaut, les paquets sont retransmis comme suit :

Types de VPN IPsec Site-à-Site

VyOS prend en charge deux types de VPN IPsec : le VPN IPsec basé sur des politiques et le VPN IPsec basé sur des routes.

VPN Basé sur des Politiques

Le VPN basé sur des politiques est basé sur des politiques configurées statiquement. Chaque politique crée une SA IPSec indépendante. Le trafic correspondant à ces SA sera chiffré et dirigé vers le pair distant.

VPN Basé sur des Routes

Le VPN basé sur des routes est basé sur le passage sécurisé du trafic via une interface de tunnel virtuel (VTI). Ce type de VPN IPsec permet l'utilisation de protocoles de routage.

Étapes de Configuration pour le VPN Site-à-Site

L'exemple suivant montre la configuration pour un routeur participant à un VPN IPsec.

Informations sur le Tunnel :

  • Phase 1 :
    • Chiffrement : AES256
    • Hachage : SHA256
    • PRF : SHA256
    • DH : 14
    • Durée de vie : 28800
  • Phase 2 :
    • Mode IPsec : Tunnel
    • Chiffrement : AES256
    • Hachage : SHA256
    • PFS : Hérité du DH de la Phase 1
    • Durée de vie : 3600
  • Si vous utilisez un VPN basé sur des politiques
    • Le réseau distant est 192.168.50.0/24. Le réseau local est 192.168.10.0/24
  • Si vous utilisez un VPN basé sur des routes
    • L'IP de l'interface VTI est 10.0.0.1/30
Note : Nous ne recommandons pas d'utiliser simultanément des configurations VPN basées sur des politiques et basées sur des routes pour le même pair.

1. Configurer ike-group (Phase 1 IKE)

set vpn ipsec ike-group IKE close-action 'start'
set vpn ipsec ike-group IKE key-exchange 'ikev1'
set vpn ipsec ike-group IKE lifetime '28800'
set vpn ipsec ike-group IKE proposal 10 dh-group '14'
set vpn ipsec ike-group IKE proposal 10 encryption 'aes256'
set vpn ipsec ike-group IKE proposal 10 hash 'sha256'
set vpn ipsec ike-group IKE proposal 10 prf 'prfsha256'

2. Configurer ESP-group (Phase 2 IKE)

set vpn ipsec esp-group ESP lifetime '3600'
set vpn ipsec esp-group ESP mode 'tunnel'
set vpn ipsec esp-group ESP pfs 'enable'
set vpn ipsec esp-group ESP proposal 10 encryption 'aes256'
set vpn ipsec esp-group ESP proposal 10 hash 'sha256'

3. Spécifier l'adresse IP publique de l'interface eth0

set vpn ipsec ipsec-interfaces interface eth0

4. Configurer le pair site-à-site

Configuration VPN basée sur des politiques :

set vpn ipsec site-to-site peer 203.0.113.2 authentication mode 'pre-shared-secret'
set vpn ipsec site-to-site peer 203.0.113.2 authentication id '192.0.2.1'
set vpn ipsec site-to-site peer 203.0.113.2 authentication remote-id '203.0.113.2'
set vpn ipsec site-to-site peer 203.0.113.2 connection-type 'respond'
set vpn ipsec site-to-site peer 203.0.113.2 default-esp-group 'ESP'
set vpn ipsec site-to-site peer 203.0.113.2 ike-group 'IKE'
set vpn ipsec site-to-site peer 203.0.113.2 local-address '192.0.2.1'
set vpn ipsec site-to-site peer 203.0.113.2 tunnel 1 local prefix '192.168.10.0/24'
set vpn ipsec site-to-site peer 203.0.113.2 tunnel 1 remote prefix '192.168.50.0/24'

Configuration VPN basée sur des routes :

set interfaces vti vti0 address '10.0.0.1/30'
set interfaces vti vti0 description 'VPN VTI interface'

set vpn ipsec site-to-site peer 203.0.113.2 authentication mode 'pre-shared-secret'
set vpn ipsec site-to-site peer 203.0.113.2 authentication id '192.0.2.1'
set vpn ipsec site-to-site peer 203.0.113.2 authentication remote-id '203.0.113.2'
set vpn ipsec site-to-site peer 203.0.113.2 connection-type 'respond'
set vpn ipsec site-to-site peer 203.0.113.2 default-esp-group 'ESP'
set vpn ipsec site-to-site peer 203.0.113.2 ike-group 'IKE'
set vpn ipsec site-to-site peer 203.0.113.2 local-address '192.0.2.1'
set vpn ipsec site-to-site peer 203.0.113.2 vti bind to 'vti0'
set vpn ipsec site-to-site peer 203.0.113.2 vti esp-group 'ESP'

Aperçu du VPN d'Accès à Distance

Le VPN d'accès à distance permet aux utilisateurs distants de se connecter en toute sécurité à un réseau d'entreprise via un tunnel IPsec. VyOS prend en charge plusieurs méthodes de configuration de VPN d'accès à distance, y compris l'authentification par clé pré-partagée, par certificat et basée sur EAP.

Types de VPN d'Accès à Distance

Accès à Distance Basé sur Clé Pré-partagée

La méthode de configuration d'accès à distance la plus simple, où chaque utilisateur distant s'authentifie en utilisant la même clé pré-partagée. Convient aux petits déploiements ou aux environnements de test.

Accès à Distance Basé sur Certificat

Utilise des certificats X.509 pour l'authentification, offrant une sécurité plus élevée. Chaque utilisateur peut avoir son propre certificat, ce qui facilite la gestion et la révocation.

Accès à Distance Basé sur EAP

Le protocole d'authentification extensible (EAP) permet l'authentification des utilisateurs en utilisant un serveur RADIUS. Prend en charge plusieurs méthodes EAP telles que EAP-MSCHAPv2, EAP-TLS, etc.

Configuration du VPN d'Accès à Distance

Étapes de Configuration de Base

1. Configurer les groupes IKE et ESP

set vpn ipsec ike-group IKE-RA lifetime '28800'
set vpn ipsec ike-group IKE-RA proposal 1 encryption 'aes256'
set vpn ipsec ike-group IKE-RA proposal 1 hash 'sha256'
set vpn ipsec ike-group IKE-RA proposal 1 dh-group '14'

set vpn ipsec esp-group ESP-RA lifetime '3600'
set vpn ipsec esp-group ESP-RA proposal 1 encryption 'aes256'
set vpn ipsec esp-group ESP-RA proposal 1 hash 'sha256'

2. Configurer le pool d'adresses IP

set vpn ipsec remote-access connection RA pool 'RA-POOL'
set vpn ipsec remote-access connection RA pool RA-POOL prefix '100.64.0.0/24'
set vpn ipsec remote-access connection RA pool RA-POOL name-server '192.0.2.53'

3. Configurer la connexion d'accès à distance

set vpn ipsec remote-access connection RA authentication local-id '192.0.2.1'
set vpn ipsec remote-access connection RA authentication server-mode 'x509'
set vpn ipsec remote-access connection RA authentication x509 certificate 'ipsec-cert'

set vpn ipsec remote-access connection RA remote-access-interface 'ppp0'
set vpn ipsec remote-access connection RA ike-group 'IKE-RA'
set vpn ipsec remote-access connection RA default-esp-group 'ESP-RA'

Configuration Basée sur EAP-RADIUS

Utilisation d'un serveur RADIUS pour l'authentification des utilisateurs :

set vpn ipsec remote-access connection RA authentication client-mode 'eap-radius'
set vpn ipsec remote-access connection RA eap-radius server 1 address '192.0.2.100'
set vpn ipsec remote-access connection RA eap-radius server 1 key 'testing123'

set vpn ipsec remote-access connection RA pool RA-POOL name-server '192.0.2.53'
set vpn ipsec remote-access connection RA pool RA-POOL prefix '100.64.0.0/24'

Configuration Basée sur Clé Pré-partagée

Convient aux scénarios d'accès à distance simples :

set vpn ipsec remote-access connection RA authentication mode 'pre-shared-secret'
set vpn ipsec remote-access connection RA authentication id '192.0.2.1'
set vpn ipsec remote-access connection RA authentication local-id '192.0.2.1'

set vpn ipsec remote-access connection RA remote-access-interface 'ppp0'
set vpn ipsec remote-access connection RA ike-group 'IKE-RA'
set vpn ipsec remote-access connection RA default-esp-group 'ESP-RA'

set vpn ipsec remote-access connection RA pool RA-POOL prefix '100.64.0.0/24'

Configuration de l'Interface d'Accès à Distance

Le VPN d'accès à distance utilise des interfaces PPP virtuelles. L'interface d'accès à distance doit être spécifiée :

set interfaces ppp ppp0 description 'Remote Access VPN Interface'
set vpn ipsec remote-access connection RA remote-access-interface 'ppp0'

Exemples de Configuration Client

Client Windows

Le client VPN intégré de Windows prend en charge IKEv2 et L2TP/IPsec. Étapes de configuration :

  1. Ouvrir "Paramètres" > "Réseau et Internet" > "VPN"
  2. Cliquer sur "Ajouter une connexion VPN"
  3. Remplir le nom du fournisseur VPN, le nom du serveur ou l'adresse
  4. Sélectionner le type de VPN (IKEv2 ou L2TP/IPsec)
  5. Entrer les informations d'authentification (nom d'utilisateur/mot de passe ou certificat)

Client Linux

Les utilisateurs Linux peuvent configurer le VPN IPsec en utilisant NetworkManager ou des outils en ligne de commande :

# Utilisation du client strongswan
sudo apt install strongswan strongswan-pki libcharon-extra-plugins

# Configurer /etc/ipsec.conf
conn vyos-ra
    right=192.0.2.1
    rightid=@192.0.2.1
    rightsubnet=0.0.0.0/0
    left=%defaultroute
    leftid=user@example.com
    eap_identity=user@example.com
    auto=start

Client macOS

macOS prend en charge nativement le VPN IKEv2 :

  1. Ouvrir "Préférences Système" > "Réseau"
  2. Cliquer sur "+" pour ajouter une nouvelle connexion
  3. Sélectionner l'interface comme "VPN", le type comme "IKEv2"
  4. Remplir l'adresse du serveur et l'ID distant
  5. Configurer la méthode d'authentification

Appareils Mobiles

Les appareils iOS et Android prennent tous deux en charge nativement le VPN IKEv2 :

  • iOS : Réglages > Général > VPN et réseau > Ajouter une configuration VPN
  • Android : Paramètres > Réseau et Internet > VPN > Ajouter un profil VPN

Dépannage

Problèmes Courants

  • Échec de connexion : Vérifier si les paramètres IKE et ESP correspondent, vérifier que la clé pré-partagée ou le certificat est correct
  • Échec d'authentification : Confirmer que la configuration du serveur RADIUS est correcte, vérifier les identifiants utilisateur
  • Impossible d'obtenir une adresse IP : Vérifier la configuration du pool d'adresses IP, s'assurer qu'il y a suffisamment d'adresses disponibles
  • Connexion instable : Vérifier les paramètres DPD, ajuster les paramètres de durée de vie

Problèmes Courants et Solutions

Le Tunnel Ne S'établit Pas

Symptômes : L'état du tunnel IPsec affiche "down" ou "connecting".

Causes Possibles et Solutions :

  1. Non-correspondance de Clé Pré-partagée

    S'assurer que les clés pré-partagées aux deux extrémités sont exactement identiques, y compris la casse et les espaces.

    show vpn ipsec site-to-site peer <peer-address>

  2. Non-correspondance de Proposition IKE

    Vérifier si les configurations de groupe IKE aux deux extrémités sont compatibles. L'algorithme de chiffrement, l'algorithme de hachage et le groupe Diffie-Hellman doivent correspondre.

    show vpn ipsec ike-group

  3. Non-correspondance de Proposition ESP

    Vérifier que les configurations de groupe ESP sont cohérentes.

    show vpn ipsec esp-group

  4. Blocage par Pare-feu

    S'assurer que le pare-feu autorise le passage des ports suivants :

    • UDP 500 (IKE)
    • UDP 4500 (NAT-T)
    • Protocole 50 (ESP)

  5. Erreurs de Configuration de Sous-réseau Local/Distant

    Vérifier que les configurations de sous-réseau local et distant sont correctes pour le VPN site-à-site.

Tunnel Actif Mais Pas de Données

Symptômes : Le tunnel IPsec affiche "up", mais les données ne peuvent pas être transmises via le tunnel.

Causes Possibles et Solutions :

  1. Child SA Non Installé

    Vérifier si le Child SA a été installé avec succès :

    show vpn ipsec sa

    Si le Child SA n'est pas affiché, cela peut être dû à une non-correspondance de proposition ESP.

  2. Problèmes de Routage

    Vérifier que la table de routage est correcte, en s'assurant que le trafic peut passer par l'interface de tunnel :

    show ip route

  3. Problèmes de MTU

    IPsec ajoute une surcharge aux paquets. Si les paquets sont trop volumineux, ils peuvent être supprimés. Essayer d'ajuster le MTU :

    set interfaces ethernet <interface> mtu 1400

  4. Routage Asymétrique

    S'assurer que le trafic de retour passe également par le tunnel IPsec ; vérifier la configuration de routage stratégique.

Le Tunnel Se Déconnecte Fréquemment

Symptômes : Le tunnel IPsec s'établit et se déconnecte de manière répétée.

Causes Possibles et Solutions :

  1. Configuration DPD (Dead Peer Detection)

    Vérifier si les paramètres DPD sont trop agressifs :

    show vpn ipsec site-to-site peer <peer-address> dead-peer-detection

    Paramètres DPD recommandés :

    • interval : 15-30 secondes
    • timeout : 30-60 secondes
    • action : restart

  2. Échec de Rekey IKE

    Vérifier les paramètres de durée de vie IKE pour s'assurer de la compatibilité aux deux extrémités.

  3. Problèmes NAT

    Si l'une des extrémités est derrière un NAT, s'assurer que NAT Traversal (NAT-T) est activé.

Échecs d'Authentification

Symptômes : Les journaux affichent des erreurs d'authentification.

Causes Possibles et Solutions :

  1. Erreur de Clé Pré-partagée

    Reconfigurer la clé pré-partagée, en s'assurant d'une correspondance exacte aux deux extrémités.

  2. Problèmes de Certificat

    Si vous utilisez l'authentification par certificat :

    • Vérifier que le certificat n'a pas expiré
    • Vérifier que la chaîne de certificats est complète
    • Confirmer que les noms de sujet du certificat correspondent
    • Vérifier que le certificat CA est correctement installé

Journaux et Débogage

Voir les Journaux IPsec

Voir les informations relatives à IPsec dans les journaux système :

show log | match charon

Ou voir des journaux plus détaillés :

tail -f /var/log/syslog | grep charon

Activer la Journalisation Détaillée

Pour des informations de débogage plus détaillées, vous pouvez activer la journalisation de débogage IPsec :

set vpn ipsec logging log-level 3

Descriptions des niveaux de journalisation :

  • 0 : Erreurs uniquement
  • 1 : Avertissements
  • 2 : Informations (par défaut)
  • 3 : Débogage
  • 4 : Débogage verbeux
Avertissement : Des niveaux de journalisation élevés peuvent générer de grandes quantités de sorties de journal et peuvent affecter les performances du système. À activer temporairement uniquement pendant le dépannage.

Messages de Journal Courants

Message de Journal Signification Solution
received INVALID_ID_INFORMATION Non-correspondance d'identité Vérifier la configuration d'identité locale et distante
no matching proposal found Non-correspondance de proposition Vérifier la configuration du groupe IKE/ESP
authentication failed Échec d'authentification Vérifier la clé pré-partagée ou le certificat
peer not responding Le pair ne répond pas Vérifier la connectivité réseau et le pare-feu
SA lifetime expired Durée de vie SA expirée Phénomène normal, vérifier la configuration de rekey

Capture de Paquets Réseau

Lorsque d'autres méthodes ne peuvent pas résoudre le problème, vous pouvez utiliser tcpdump pour la capture de paquets réseau :

Capturer le Trafic IKE

tcpdump -i any -n port 500 or port 4500

Capturer le Trafic ESP

tcpdump -i any -n proto 50

Enregistrer le Fichier de Capture de Paquets

tcpdump -i any -n -w /tmp/ipsec.pcap port 500 or port 4500 or proto 50

Vous pouvez utiliser Wireshark pour analyser le fichier pcap enregistré.

Réinitialisation et Redémarrage

Réinitialiser le Tunnel IPsec

Réinitialiser le tunnel IPsec pour un site spécifique :

reset vpn ipsec site-to-site peer <peer-address>

Redémarrer le Service IPsec

Pour redémarrer l'ensemble du service IPsec :

restart vpn ipsec
Avertissement : Le redémarrage du service IPsec interrompra toutes les connexions VPN actives.

Problèmes de Performance

Test de Performance de Chiffrement

Tester les performances de chiffrement du système :

show vpn ipsec performance

Accélération Matérielle

Si l'accélération matérielle de chiffrement est prise en charge, s'assurer qu'elle est activée :

show vpn ipsec hardware-acceleration
Astuce : Certains processeurs prennent en charge le jeu d'instructions AES-NI, ce qui peut améliorer considérablement les performances IPsec. Utiliser lscpu | grep aes pour vérifier la prise en charge.

Contacter le Support

Si les étapes ci-dessus ne peuvent pas résoudre le problème, veuillez collecter les informations suivantes et contacter le support technique :

  1. Exportation complète de la configuration : show configuration commands | match vpn
  2. Sortie de l'état IPsec : show vpn ipsec status
  3. Informations sur les associations de sécurité : show vpn ipsec sa
  4. Journaux système : show log | match charon
  5. Fichier de capture de paquets réseau (le cas échéant)
