OSPF

OSPF est un protocole de routage pour les réseaux de protocole Internet (IP). Il utilise un algorithme de routage d'état de lien (LSR) et appartient au groupe des protocoles de passerelle intérieure (IGP), fonctionnant dans un seul système autonome (AS). Il est défini comme OSPF Version 2 dans RFC 2328 (1998) pour IPv4. Les mises à jour pour IPv6 sont spécifiées comme OSPF Version 3 dans RFC 5340 (2008). OSPF prend en charge le modèle d'adressage CIDR.

OSPF est un IGP largement utilisé dans les réseaux d'entreprises de grande taille.

OSPFv2 (IPv4)

Configuration

Général

VyOS n'a pas de commande spécifique pour démarrer le processus OSPF. Le processus OSPF démarre lorsqu'une interface OSPF activée est configurée.

set protocols ospf area <number> network <A.B.C.D/M>

Cette commande spécifie l'interface OSPF activée. Si l'interface a une adresse provenant de la plage définie, alors la commande active OSPF sur cette interface, afin que le routeur puisse fournir les informations de réseau aux autres routeurs OSPF via cette interface.

Cette commande est également utilisée pour activer le processus OSPF. Le numéro de zone peut être spécifié en notation décimale dans la plage de 0 à 4294967295. Ou il peut être spécifié en notation décimale pointée similaire à une adresse IP.

La longueur du préfixe dans l'interface doit être égale ou supérieure (c'est-à-dire plus petit réseau) à la longueur du préfixe dans l'instruction réseau. Par exemple, l'instruction ci-dessus ne permet pas d'activer OSPF sur une interface avec l'adresse 192.168.1.1/23, mais elle le fait sur une interface avec l'adresse 192.168.1.129/25.

Dans certains cas, il peut être plus pratique d'activer OSPF par interface/sous-réseau set protocols ospf interface <interface> area <x.x.x.x | x>

set protocols ospf auto-cost reference-bandwidth <number>

Cette commande définit la bande passante de référence pour les calculs de coût, où la bande passante peut être comprise entre 1 et 4294967, spécifiée en Mbits/s. La valeur par défaut est 100 Mbit/s (c'est-à-dire qu'un lien avec une bande passante de 100 Mbit/s ou plus aura un coût de 1. Le coût des liens avec une bande passante inférieure sera mis à l'échelle par rapport à ce coût).

set protocols ospf parameters router-id <rid>

Cette commande définit l'identifiant de routeur du processus OSPF. L'identifiant de routeur peut être une adresse IP du routeur, mais il n'en est pas obligatoirement. Il peut être n'importe quel nombre de 32 bits arbitraire. Cependant, il doit être unique dans tout le domaine OSPF pour le speaker OSPF – des choses mauvaises se produiront si plusieurs speakers OSPF sont configurés avec le même identifiant de routeur !

Optionnel

set protocols ospf default-information originate [always] [metric <number>] [metric-type <1|2>] [route-map <name>]

Origine d'une LSA AS-External (type-5) décrivant une route par défaut dans toutes les zones capables de routage externe, avec la métrique et le type de métrique spécifiés. Si le mot-clé always est donné, alors la route par défaut est toujours annoncée, même lorsqu'il n'y a pas de route par défaut présente dans le tableau de routage. L'argument route-map spécifie d'annoncer la route par défaut si la route-map est satisfaite.

set protocols ospf distance global <distance>

Cette commande modifie la valeur de distance d'OSPF globalement. La plage de distance est de 1 à 255.

set protocols ospf distance ospf <external|inter-area|intra-area> <distance>

Cette commande modifie la valeur de distance d'OSPF. Les arguments sont les valeurs de distance pour les routes externes, les routes inter-zone et les routes intra-zone respectivement. La plage de distance est de 1 à 255.

Note

Les routes avec une distance de 255 sont effectivement désactivées et ne sont pas installées dans le noyau.

set protocols ospf log-adjacency-changes [detail]

Cette commande permet d'enregistrer les changements d'adjacence. Avec l'argument detail optionnel, tous les changements d'état d'adjacence sont affichés. Sans detail, seuls les changements vers un état complet ou des régressions sont affichés.

set protocols ospf max-metric router-lsa <administrative|on-shutdown <seconds>|on-startup <seconds>>

Cela active le support de RFC 3137, où le processus OSPF décrit ses liens de transit dans son router-LSA comme ayant une distance infinie afin que les autres routeurs évitent de calculer des chemins de transit à travers le routeur pendant qu'ils peuvent encore atteindre les réseaux à travers le routeur.

Ce support peut être activé administrativement (et indéfiniment) avec la commande administrative. Il peut également être activé de manière conditionnelle. L'activation conditionnelle des router-lsas de métrique maximale peut être effectuée pendant une période de secondes après le démarrage avec la commande on-startup <seconds> et/ou pendant une période de secondes avant l'arrêt avec la commande on-shutdown <seconds>. La plage de temps est de 5 à 86400.

set protocols ospf parameters abr-type <cisco|ibm|shortcut|standard>

Cette commande sélectionne le modèle ABR. Le routeur OSPF prend en charge quatre modèles ABR :

cisco – un routeur sera considéré comme ABR s'il a plusieurs interfaces configurées vers des réseaux dans différentes zones, dont l'une est une zone principale. De plus, le lien vers la zone principale doit être actif (en fonctionnement). ibm – identique au modèle « cisco » mais dans ce cas, le lien vers la zone principale peut ne pas être actif. standard – le routeur a plusieurs liens actifs vers différentes zones. shortcut – identique au modèle « standard », mais dans ce modèle, un routeur est autorisé à utiliser une topologie de zones connectées sans impliquer une zone principale pour les connexions inter-zones.

Des informations détaillées sur les différences entre les modèles « cisco » et « ibm » peuvent être trouvées dans RFC 3509. Un modèle « shortcut » permet aux ABR de créer des routes entre des zones basées sur la topologie des zones connectées à ce routeur mais sans utiliser une zone principale si le chemin non principal est moins coûteux. Pour plus d'informations sur le modèle « shortcut », voir ospf-shortcut-abr-02.txt

set protocols ospf parameters rfc1583-compatibility

RFC 2328, successeur de RFC 1583, suggère selon la section G.2 (changements) dans la section 16.4.1 un changement dans l'algorithme de préférence des chemins qui empêche les boucles de routage possibles dans la version ancienne d'OSPFv2. Plus précisément, il exige que les chemins inter-zone et les chemins de la zone principale intra-zone soient maintenant de préférence égale mais toujours préférés aux chemins externes.

Cette commande ne doit pas normalement être configurée.

set protocols ospf interface <interface> passive [disable]

Cette commande spécifie l'interface comme passive. Une interface passive publie son adresse, mais ne lance pas le protocole OSPF (les adjacences ne sont pas formées et les paquets Hello ne sont pas générés).

L'option disable permet d'exclure l'interface de l'état passif. Cette commande est utilisée si la commande passive-interface default a été configurée.

set protocols ospf passive-interface default

Cette commande spécifie toutes les interfaces comme passives par défaut. Comme cette commande change la logique de configuration vers une interface passive par défaut ; donc, les interfaces où des adjacences de routeurs sont attendues doivent être configurées avec la commande passive-interface-exclude.

set protocols ospf maximum-paths <1-64>

Utilisez cette commande pour contrôler le nombre maximum de chemins de même coût pour atteindre une destination spécifique. La limite supérieure peut différer si vous modifiez la valeur de MULTIPATH_NUM pendant la compilation. La valeur par défaut est MULTIPATH_NUM (64).

set protocols ospf refresh timers <seconds>

Le routeur met à jour automatiquement les informations d'état de lien avec ses voisins. Seules les informations obsolètes sont mises à jour, qui ont dépassé une certaine limite. Cette paramètre change la valeur de seuil, qui par défaut est de 1800 secondes (demi-heure). La valeur est appliquée à tout le routeur OSPF. La plage des compteurs est de 10 à 1800.

set protocols ospf timers throttle spf <delay|initial-holdtime|max-holdtime> <seconds>

Cette commande définit le délai initial, le délai initial et le délai maximal entre le moment où SPF est calculé et l'événement qui a déclenché le calcul. Les temps sont spécifiés en millisecondes et doivent être dans la plage de 0 à 600000 millisecondes. delay définit le délai initial de planification SPF en millisecondes. La valeur par défaut est de 200 ms. initial-holdtime définit le délai minimum entre deux calculs consécutifs de SPF. La valeur par défaut est de 1000 ms. max-holdtime définit le délai maximum entre deux calculs consécutifs de SPF. La valeur par défaut est de 10000 ms.

set protocols ospf ldp-sync

Cette commande activera la synchronisation IGP-LDP globalement pour OSPF. Cela nécessite que LDP soit fonctionnel. Cela est décrit dans RFC 5443. Par défaut, toutes les interfaces opérationnelles en OSPF sont activées pour la synchronisation. Les boucles sont exclues.

set protocols ospf ldp-sync holddown <seconds>

Cette commande modifiera la valeur de délai d'attente globalement pour la synchronisation IGP-LDP pendant les événements de convergence/flash d'interface.

set protocols ospf capability opaque

ospfd prend en charge les LSAs Opaque RFC 2370 en tant que support partiel pour les LSAs de Ingénierie de trafic MPLS. La capacité opaque-lsa doit être activée dans la configuration.

Une autre commande pourrait être « mpls-te on » (Ingénierie de trafic)

Note

FRR propose uniquement un support partiel pour certaines extensions de protocole de routage utilisées avec MPLS-TE ; il ne prend pas en charge une solution complète RSVP-TE.

Configuration de zone

set protocols ospf area <number> area-type stub

Cette commande spécifie la zone comme étant une zone Stub. C'est-à-dire, une zone où aucun routeur ne génère des routes externes à OSPF et donc une zone où toutes les routes externes sont via les ABR(s). Ainsi, les ABR pour une telle zone n'ont pas besoin de transmettre des LSAs AS-External (type-5) ou des LSAs ASBR-Summary (type-4) dans la zone. Ils doivent seulement transmettre des LSAs Network-Summary (type-3) dans une telle zone, ainsi qu'une route par défaut.

set protocols ospf area <number> area-type stub no-summary

Cette commande spécifie la zone comme étant une zone Totally Stub. En plus des limites de zone Stub, cette zone empêche un ABR de transmettre des LSAs Network-Summary (type-3) dans la zone Stub spécifiée. Seule la route par défaut est autorisée.

set protocols ospf area <number> area-type stub default-cost <number>

Cette commande spécifie la zone comme étant une zone Stub. C'est-à-dire, une zone où aucun routeur ne génère de routes externes à OSPF et donc une zone où toutes les routes externes sont via les ABR (Routeurs de bord de zone). Ainsi, les ABR de cette zone n'ont pas besoin de transmettre des LSAs de type 5 ou 4 dans la zone. Ils doivent transmettre des LSAs de type 3, ainsi qu'une route par défaut.
