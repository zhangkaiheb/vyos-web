Conteneur

L'implémentation des conteneurs VyOS repose sur Podman en tant qu'engine de conteneurs sans daemon.

Configuration

set container name <name> image

Définit le nom de l'image dans le registre

set container name mysql-server image mysql:8.0

Si aucun registre n'est spécifié, Docker.io sera utilisé comme registre de conteneurs à moins qu'un registre alternatif ne soit spécifié à l'aide de set container registry <name> ou que le registre ne soit inclus dans le nom de l'image

set container name mysql-server image quay.io/mysql:8.0
set container name <name> entrypoint <entrypoint>

Remplace le point d'entrée par défaut de l'image pour un conteneur.

set container name <name> command <command>

Remplace la commande par défaut de l'image pour un conteneur.

set container name <name> arguments <arguments>

Définit les arguments de commande pour un conteneur.

set container name <name> host-name <hostname>

Définit le nom d'hôte pour un conteneur.

set container name <name> allow-host-pid

Le conteneur et l'hôte partagent le même espace de noms de processus. Cela signifie que les processus en cours d'exécution sur l'hôte sont visibles à l'intérieur du conteneur, et les processus présents dans le conteneur sont visibles sur l'hôte.

La commande se traduit par « –pid host » lors de la création du conteneur.

set container name <name> allow-host-networks

Autorise le réseau hôte dans un conteneur. La pile réseau du conteneur n'est pas isolée de l'hôte et utilisera l'adresse IP de l'hôte.

La commande se traduit par « –net host » lors de la création du conteneur.

Note

allow-host-networks ne peut pas être utilisé avec network

set container name <name> network <networkname>

Attache un réseau défini par l'utilisateur à un conteneur. Un seul réseau doit être spécifié et doit déjà exister.

set container name <name> network <networkname> address <address>

Spécifiez éventuellement une adresse IPv4 ou IPv6 statique pour le conteneur. Cette adresse doit être dans le préfixe du réseau nommé.

Note

La première adresse IP du réseau du conteneur est réservée par le moteur et ne peut pas être utilisée

set container name <name> name-server <address>

Spécifiez éventuellement un serveur de noms personnalisé. Si un réseau de conteneur est utilisé avec le DNS activé, ce paramètre n'aura aucun effet.

set container name <name> description <text>

Définit une description du conteneur

set container name <name> environment <key> value <value>

Ajoute des variables d'environnement personnalisées. Plusieurs variables d'environnement sont autorisées. Les commandes suivantes se traduisent par « -e key=value » lors de la création du conteneur.

set container name mysql-server environment MYSQL_DATABASE value 'zabbix'
set container name mysql-server environment MYSQL_USER value 'zabbix'
set container name mysql-server environment MYSQL_PASSWORD value 'zabbix_pwd'
set container name mysql-server environment MYSQL_ROOT_PASSWORD value 'root_pwd'
set container name <name> port <portname> source <portnumber>
set container name <name> port <portname> destination <portnumber>
set container name <name> port <portname> protocol <tcp | udp>

Publie un port pour le conteneur.

set container name zabbix-web-nginx-mysql port http source 80
set container name zabbix-web-nginx-mysql port http destination 8080
set container name zabbix-web-nginx-mysql port http protocol tcp

Note

La publication de ports ne peut pas être utilisée avec network. Pour cette raison, un travail d'adaptation utilisant NAT de destination et une attribution d'IP statique au conteneur est disponible.

set container name <name> volume <volumename> source <path>
set container name <name> volume <volumename> destination <path>

Monte un volume dans le conteneur

set container name coredns volume 'corefile' source /config/coredns/Corefile
set container name coredns volume 'corefile' destination /etc/Corefile
set container name <name> volume <volumename> mode <ro | rw>

Le volume est monté en lecture-écriture (par défaut) ou en lecture seule

set container name <name> tmpfs <tmpfsname> destination <path>

Monte un système de fichiers tmpfs (disque RAM) vers le chemin donné dans le conteneur.

set container name <name> tmpfs <tmpfsname> size <MB>

Taille en MB pour le système de fichiers tmpfs, la taille maximale est de 64 Go ou de 50 % de la mémoire totale disponible du système.

set container name <name> uid <number>
set container name <name> gid <number>

Définit l'ID utilisateur ou l'ID de groupe du conteneur

set container name <name> restart [no | on-failure | always]

Définit le comportement de redémarrage du conteneur.

  • no: Ne redémarrez pas les conteneurs à la sortie

  • on-failure: Redémarrez les conteneurs lorsqu'ils sortent avec un code de sortie non nul, en réessayant indéfiniment (défaut)

  • always: Redémarrez les conteneurs lorsqu'ils sortent, indépendamment de l'état, en réessayant indéfiniment

set container name <name> cpu-quota <num>

Cela spécifie le nombre de ressources CPU que le conteneur peut utiliser.

La valeur par défaut est 0 pour illimité. Par exemple, 1.25 limite le conteneur à utiliser jusqu'à 1.25 cœurs de temps CPU. Cela peut être un nombre décimal avec jusqu'à trois chiffres après la virgule.

La commande se traduit par « –cpus=<num> » lors de la création du conteneur.

set container name <name> memory <MB>

Limite la mémoire disponible pour le conteneur.

La valeur par défaut est de 512 Mo. Utilisez 0 Mo pour une mémoire illimitée.

set container name <name> device <devicename> source <path>
set container name <name> device <devicename> destination <path>

Ajoute un périphérique hôte au conteneur.

set container name <name> capability <text>

Définit les capacités ou permissions du conteneur.

  • net-admin: Opérations réseau (interface, pare-feu, tables de routage)

  • net-bind-service: Lier un socket à des ports privilégiés (numéros de port inférieurs à 1024)

  • net-raw: Permission de créer des sockets réseau bruts

  • setpcap: Ensembles de capacités (à partir d'un ensemble borné ou hérité)

  • sys-admin: Opérations d'administration (quotactl, montage, sethostname, setdomainame)

  • sys-time: Permission de définir l'horloge système

set container name <name> sysctl parameter <parameter> value <value>

Définit les valeurs sysctl du conteneur.

Les paramètres possibles sont :

  • Paramètres du noyau : kernel.msgmax, kernel.msgmnb, kernel.msgmni, kernel.sem, kernel.shmall, kernel.shmmax, kernel.shmmni, kernel.shm_rmid_forced

  • Paramètres commençant par fs.mqueue.*

  • Paramètres commençant par net.* (seulement si un réseau défini par l'utilisateur est utilisé)

set container name <name> label <label> value <value>

Ajoute une étiquette de métadonnées pour ce conteneur.

set container name <name> disable

Désactive un conteneur.

Vérifications de santé des conteneurs

Par défaut, aucune vérification de santé n'est effectuée, même si elle est définie par l'image.

set container name <name> health-check

La vérification de santé par défaut est exécutée pour le conteneur si elle est définie par l'image.

set container name <name> health-check command <command>

Remplace la commande de vérification de santé par défaut de l'image pour un conteneur.

set container name <name> health-check interval <interval>

Remplace l'intervalle de vérification de santé par défaut. Par exemple : 60

set container name <name> health-check timeout <timeout>

Remplace le délai de vérification de santé par défaut. Par exemple : 10

set container name <name> health-check retries <retries>

Nombre de tentatives de vérification de santé avant que le conteneur ne soit considéré comme instable. Par exemple : 1

Réseaux de conteneurs

set container network <name>

Crée un réseau de conteneur nommé

set container network <name> description

Une brève description de ce que ce réseau concerne.

set container network <name> prefix <ipv4|ipv6>

Définit le préfixe IPv4 et/ou IPv6 pour un nom de réseau donné. Les IPv4 et IPv6 peuvent être utilisés en parallèle.

set container network <name> mtu <number>

Configurez le MTU pour un réseau donné. C'est la taille (en octets) du plus grand cadre Ethernet envoyé sur ce lien.

set container network <name> no-name-server

Désactive le plugin Domain Name System (DNS) pour ce réseau.

set container network <name> vrf <name>

Lie le réseau de conteneur à une instance VRF donnée.

Référentiel de conteneurs

set container registry <name>

Ajoute le référentiel à la liste des registries sans qualification. Par défaut, pour toute image qui ne comprend pas le référentiel dans le nom de l'image, VyOS utilisera docker.io et quay.io comme référentiel de conteneurs.

set container registry <name> disable

Désactive un référentiel de conteneur donné

set container registry <name> authentication username
set container registry <name> authentication password

Certains référentiels de conteneurs nécessitent des identifiants pour être utilisés.

Les identifiants peuvent être définis ici et seront uniquement utilisés lors de l'ajout d'une image de conteneur au système.

set container registry <name> insecure

Permet l'accès au référentiel via des connexions HTTP non chiffrées ou TLS avec des certificats non fiables.

set container registry <name> mirror address <address>
set container registry <name> mirror host-name <host-name>
set container registry <name> mirror port <port>
set container registry <name> mirror path <path>

Miroir de référentiel, utilisez (host-name|address)[:port][/path].

Si vous avez un miroir http://192.168.1.1:8080 pour docker.io, vous pouvez utiliser docker.io/some/repo ou exécuter podman pull docker.io/some/repo

set container registry docker.io mirror address 192.168.1.1
set container registry docker.io mirror port 8080
set container registry docker.io insecure

Si http://192.168.1.1:8080 est votre propre registre, vous pouvez utiliser 192.168.1.1:8080/some/repo ou exécuter podman pull 192.168.1.1:8080/some/repo

set container registry 192.168.1.1:8080 insecure

Configuration des journaux

set container name <name> log-driver [k8s-file | journald | none]

Définit le pilote de journal par défaut pour les conteneurs.

  • k8s-file: Journaliser dans un fichier texte au format Kubernetes.

  • journald: Journaliser dans le journal système

  • none: Désactiver le journalisation pour le conteneur

Le pilote par défaut est journald.

Commandes d'opération

add container image <containername>

Télécharge une nouvelle image pour le conteneur

show container

Affiche la liste de tous les conteneurs actifs.

show container image

Affiche les images de conteneurs locales.

show container log <containername>

Affiche les journaux d'un conteneur donné

show container network

Affiche la liste des réseaux de conteneurs disponibles

restart container <containername>

Redémarre un conteneur donné

update container image <containername>

Mettre à jour l'image du conteneur

delete container image <image id|all> [force]

Supprime une image de conteneur particulière en fonction de son ID d'image. Vous pouvez également supprimer toutes les images de conteneurs en une seule fois.

Vous ne pouvez pas supprimer une image de conteneur si elle a plus d'un tag assigné, c'est pourquoi il y a une option force pour transmettre à l'image de conteneur afin de supprimer également ces images.

Configuration d'exemple

Pour l'exemple, exemple #1 dans la documentation officielle à la syntaxe déclarative du CLI VyOS.

set container network zabbix prefix 172.20.0.0/16
set container network zabbix description 'Network for Zabbix component containers'

set container name mysql-server image mysql:8.0
set container name mysql-server network zabbix

set container name mysql-server environment 'MYSQL_DATABASE' value 'zabbix'
set container name mysql-server environment 'MYSQL_USER' value 'zabbix'
set container name mysql-server environment 'MYSQL_PASSWORD' value 'zabbix_pwd'
set container name mysql-server environment 'MYSQL_ROOT_PASSWORD' value 'root_pwd'

set container name zabbix-java-gateway image zabbix/zabbix-java-gateway:alpine-5.2-latest
set container name zabbix-java-gateway network zabbix

set container name zabbix-server-mysql image zabbix/zabbix-server-mysql:alpine-5.2-latest
set container name zabbix-server-mysql network zabbix

set container name zabbix-server-mysql environment 'DB_SERVER_HOST' value 'mysql-server'
set container name zabbix-server-mysql environment 'MYSQL_DATABASE' value 'zabbix'
set container name zabbix-server-mysql environment 'MYSQL_USER' value 'zabbix'
set container name zabbix-server-mysql environment 'MYSQL_PASSWORD' value 'zabbix_pwd'
set container name zabbix-server-mysql environment 'MYSQL_ROOT_PASSWORD' value 'root_pwd'
set container name zabbix-server-mysql environment 'ZBX_JAVAGATEWAY' value 'zabbix-java-gateway'

set container name zabbix-server-mysql port zabbix source 10051
set container name zabbix-server-mysql port zabbix destination 10051

set container name zabbix-web-nginx-mysql image zabbix/zabbix-web-nginx-mysql:alpine-5.2-latest
set container name zabbix-web-nginx-mysql network zabbix

set container name zabbix-web-nginx-mysql environment 'MYSQL_DATABASE' value 'zabbix'
set container name zabbix-web-nginx-mysql environment 'ZBX_SERVER_HOST' value 'zabbix-server-mysql'
set container name zabbix-web-nginx-mysql environment 'DB_SERVER_HOST' value 'mysql-server'
set container name zabbix-web-nginx-mysql environment 'MYSQL_USER' value 'zabbix'
set container name zabbix-web-nginx-mysql environment 'MYSQL_PASSWORD' value 'zabbix_pwd'
set container name zabbix-web-nginx-mysql environment 'MYSQL_ROOT_PASSWORD' value 'root_pwd'

set container name zabbix-web-nginx-mysql port http source 80
set container name zabbix-web-nginx-mysql port http destination 8080
