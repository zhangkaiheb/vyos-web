Forwarding DNS

VyOS fournit une infrastructure DNS pour les réseaux de petite taille, conçue pour être légère et adaptée aux routeurs et pare-feux à ressources limitées.

Les clients connectés sont servis par le service de forwarding DNS, configuré sous service dns forwarding. Il peut soit transférer les requêtes vers des serveurs DNS upstream configurables, soit fonctionner en tant que serveur DNS récursif complet sans nécessiter de serveurs DNS upstream. Fonctionner sans serveurs upstream évite d'exposer les requêtes des clients à un opérateur de DNS upstream.

Configuration

Note

Une configuration de forwarding DNS ne peut être validée que lorsqu'listen-address et allow-from sont définis. Sinon, la validation échoue.

Écouteur

set service dns forwarding listen-address <address>

Configurez une adresse IPv4 ou IPv6 locale sur laquelle le forwarding DNS écoute les requêtes entrantes.

L'adresse doit déjà être assignée à une interface locale. Répétez la commande pour configurer plusieurs adresses d'écoute. Au moins une adresse d'écoute est nécessaire pour une validation réussie.

Exemple :

set service dns forwarding listen-address 192.0.2.1
set service dns forwarding listen-address 2001:db8::1
set service dns forwarding port <1-65535>

Configurez le port sur lequel le forwarding DNS écoute les requêtes entrantes.

La valeur par défaut est 53.

Exemple :

set service dns forwarding port 5353
set service dns forwarding allow-from <prefix>

Restreindre les requêtes entrantes aux clients dont l'IP source se trouve dans le préfixe IPv4 ou IPv6 spécifié.

Répétez la commande pour autoriser plusieurs préfixes. Au moins un préfixe est requis pour une validation réussie.

Note

Limitez allow-from aux réseaux fiables. N'utilisez pas 0.0.0.0/0 ou ::/0 si le service est accessible depuis Internet public.

Exemple :

set service dns forwarding allow-from 192.0.2.0/24
set service dns forwarding allow-from 2001:db8::/32
set service dns forwarding exclude-throttle-address <address>

Empêchez le throttling des serveurs autoritatifs correspondant à l'adresse IPv4 ou IPv6 ou au préfixe spécifié.

Le forwarding DNS throttle les serveurs autoritatifs qui ne répondent pas à une requête ou retournent des réponses que le forwarding DNS rejette. Cette commande exempte les adresses spécifiées du throttling. Répétez la commande pour ajouter plusieurs adresses.

Exemple :

set service dns forwarding exclude-throttle-address 192.0.2.53
set service dns forwarding exclude-throttle-address 2001:db8::53

Forwarding en amont

set service dns forwarding name-server <address>

Transférer les requêtes vers le serveur DNS upstream IPv4 ou IPv6 spécifié.

Les serveurs upstream sont configurés directement sous le forwarding DNS. Répétez la commande pour configurer plusieurs serveurs upstream.

Exemple :

set service dns forwarding name-server 192.0.2.53
set service dns forwarding name-server 2001:db8::53
set service dns forwarding name-server <address> port <1-65535>

Configurez le port de destination utilisé lors du transfert des requêtes vers le serveur DNS upstream spécifié.

La valeur par défaut est 53.

Exemple :

set service dns forwarding name-server 192.0.2.53 port 853
set service dns forwarding system

Transférer les requêtes vers les serveurs DNS upstream configurés sous system name-server.

Les serveurs upstream sont hérités de system name-server.

Exemple :

set service dns forwarding system
set service dns forwarding dhcp <interface>

Transférer les requêtes vers les serveurs DNS appris via le client DHCPv4 ou DHCPv6 sur l'interface spécifiée.

Répétez la commande pour transférer les requêtes vers des serveurs appris via DHCP sur plusieurs interfaces.

Exemple :

set service dns forwarding dhcp eth0
set service dns forwarding source-address <address>

Configurez l'adresse IPv4 ou IPv6 locale utilisée comme source lorsqu'le forwarding DNS initie des requêtes sortantes.

La valeur par défaut est 0.0.0.0 et ::, ce qui signifie que l'adresse source est sélectionnée pour chaque requête sortante. Répétez la commande pour configurer plusieurs adresses sources.

Exemple :

set service dns forwarding source-address 192.0.2.1
set service dns forwarding source-address 2001:db8::1
set service dns forwarding no-serve-rfc1918

Désactiver la réponse autoritaire aux requêtes pour les zones 10.in-addr.arpa, 168.192.in-addr.arpa et 16-31.172.in-addr.arpa.

Ces sont les zones de recherche inverse pour les plages d'adresses privées RFC 1918. Les requêtes pour ces zones sont ensuite transférées vers les serveurs upstream configurés.

Exemple :

set service dns forwarding no-serve-rfc1918
set service dns forwarding ignore-hosts-file

Ne pas utiliser le fichier local /etc/hosts dans la résolution de noms.

Par défaut, le forwarding DNS répond aux requêtes en utilisant /etc/hosts avant d'effectuer une récursion ou un transfert.

Exemple :

set service dns forwarding ignore-hosts-file

Cache et temporisations

set service dns forwarding cache-size <0-2147483647>

Configurez le nombre maximum d'entrées de cache DNS.

La valeur par défaut est 10000. Une valeur de 0 désactive le cache.

Exemple :

set service dns forwarding cache-size 1000000
set service dns forwarding negative-ttl <0-7200>

Configurez le temps maximum, en secondes, pendant lequel les réponses négatives (NXDOMAIN et NODATA) sont mises en cache.

La valeur par défaut est 3600.

Exemple :

set service dns forwarding negative-ttl 60
set service dns forwarding minimum-ttl-override <0-2147483647>

Configurez la durée minimale TTL, en secondes, appliquée aux enregistrements mis en cache, indépendamment du TTL reçu du serveur autoritatif.

Les enregistrements avec un TTL inférieur à cette valeur sont mis en cache avec ce TTL minimal. La valeur par défaut est 1.

Note

Modifiez uniquement si vous avez une raison spécifique d'augmenter les TTL courts, car cela prolonge le cache au-delà du TTL autoritatif. Si l'enregistrement change en amont, les clients reçoivent la valeur mise en cache obsolète jusqu'à ce que l'override expire.

Exemple :

set service dns forwarding minimum-ttl-override 30
set service dns forwarding timeout <10-60000>

Configurez le temps, en millisecondes, pendant lequel le forwarding DNS attend une réponse du serveur autoritatif distant à une requête sortante.

La valeur par défaut est 1500.

Exemple :

set service dns forwarding timeout 2000
set service dns forwarding ttl-percent <0-100>

Actualisez les enregistrements en cache en arrière-plan lorsque le TTL restant tombe en dessous de ce pourcentage du TTL original.

Les clients continuent de recevoir la réponse existante pendant la mise à jour. La valeur par défaut est 0, ce qui désactive la mise à jour en arrière-plan.

Exemple :

set service dns forwarding ttl-percent 10
set service dns forwarding serve-stale-extension <0-65535>

Configurez combien de fois le TTL d'un enregistrement expiré peut être étendu de 30 secondes lorsque l'enregistrement ne peut pas être actualisé.

La valeur par défaut est 0, ce qui désactive le service des enregistrements périmés.

Exemple :

set service dns forwarding serve-stale-extension 30

DNSSEC et comportement NXDOMAIN

set service dns forwarding dnssec <off | process-no-validate | process | log-fail | validate>

Configurez le mode de traitement DNSSEC pour les requêtes et réponses sortantes :

  • off : Aucun traitement DNSSEC. Les bits DO des requêtes clients sont ignorés, et aucun enregistrement DNSSEC n'est demandé aux serveurs autoritatifs.

  • process-no-validate : Retourne les enregistrements DNSSEC (RRSIG, NSEC) aux clients qui les demandent, mais ne valide pas.

  • process : Valide les réponses uniquement lorsqu'un client les demande (bit DO ou AD). Retourne SERVFAIL en cas de données frauduleuses.

  • log-fail : Valide toutes les réponses, indépendamment de la demande du client, enregistre les réponses frauduleuses, mais retourne les mêmes réponses qu'en mode process.

  • validate : Valide toutes les réponses et retourne SERVFAIL en cas de données frauduleuses, indépendamment de la demande du client.

La valeur par défaut est process-no-validate.

Exemple :

set service dns forwarding dnssec validate
set service dns forwarding nothing-below-nxdomain <no | dnssec | yes>

Configurez comment le forwarding DNS gère la coupure NXDOMAIN.

Lorsque le forwarding DNS a un NXDOMAIN en cache, il peut également retourner NXDOMAIN pour tout nom sous le nom refusé, sans interroger en amont. Ce paramètre contrôle quand ce comportement s'applique :

  • no : Ne jamais appliquer la coupure NXDOMAIN.

  • dnssec : Appliquer la coupure NXDOMAIN uniquement pour les entrées NXDOMAIN validées par DNSSEC.

  • yes : Appliquer la coupure NXDOMAIN pour tout NXDOMAIN en cache qui n'est pas frauduleux.

La valeur par défaut est dnssec.

Exemple :

set service dns forwarding nothing-below-nxdomain yes

DNS64

set service dns forwarding dns64-prefix <prefix>

Synthétisez les enregistrements AAAA à partir des enregistrements A pour les noms qui n'ont pas d'enregistrements AAAA, en utilisant le préfixe IPv6 NAT64 spécifié.

La longueur du préfixe doit être exactement /96.

Exemple :

set service dns forwarding dns64-prefix 2001:db8:64::/96

Sous-réseau client EDNS

set service dns forwarding options ecs-add-for <prefix>

Configurez quelle adresse source de client est envoyée en tant que valeur ECS dans les requêtes sortantes.

Pour les clients dont l'adresse source correspond au préfixe spécifié, l'adresse réelle du client est envoyée. Pour les clients non correspondants, une adresse de substitution est envoyée afin qu'aucun sous-réseau spécifique au client ne soit exposé.

ECS n'est envoyé que pour les requêtes correspondant à edns-subnet-allow-list. Cette option contrôle uniquement la valeur, pas si ECS est envoyé.

Précédé de ! pour exclure un préfixe. Répétez la commande pour plusieurs entrées.

Exemple :

set service dns forwarding options ecs-add-for 192.0.2.0/24
set service dns forwarding options ecs-add-for !192.0.2.128/25
set service dns forwarding options ecs-ipv4-bits <0-32>

Configurez le nombre de bits de l'adresse IPv4 du client inclus dans l'option ECS envoyée aux serveurs autoritatifs.

S'applique uniquement aux requêtes où ECS est envoyé (celles correspondant à edns-subnet-allow-list).

Exemple :

set service dns forwarding options ecs-ipv4-bits 24
set service dns forwarding options edns-subnet-allow-list <value>

Activer ECS dans les requêtes sortantes lorsque l'adresse du serveur de destination est dans le masque réseau spécifié, ou lorsque le nom de la requête est sous le domaine spécifié.

Répétez la commande pour ajouter plusieurs entrées.

Exemple :

set service dns forwarding options edns-subnet-allow-list example.com
set service dns forwarding options edns-subnet-allow-list 192.0.2.0/24

Forwarding par domaine

set service dns forwarding domain <domain-name> name-server <address>

Transférer les requêtes pour le domaine spécifié vers le serveur DNS upstream IPv4 ou IPv6 spécifié.

Répétez la commande pour configurer plusieurs noms de serveurs pour le même domaine. Utilisez cette option pour implémenter un DNS split-horizon. Le domaine peut également être une zone de recherche inverse telle que 2.0.192.in-addr.arpa.

Exemple :

set service dns forwarding domain example.com name-server 192.0.2.53
set service dns forwarding domain example.com name-server 2001:db8::53
set service dns forwarding domain <domain-name> name-server <address> port <1-65535>

Configurez le port du serveur DNS upstream vers lequel les requêtes pour le domaine spécifié sont transférées.

La valeur par défaut est 53.

Exemple :

set service dns forwarding domain example.com name-server 192.0.2.53 port 853
set service dns forwarding domain <domain-name> addnta

Configurez le domaine spécifié comme un NTA, désactivant la validation DNSSEC pour celui-ci.

Configurez cela lorsque les requêtes pour un domaine cassé DNSSEC retournent SERVFAIL, afin que le domaine devienne à nouveau accessible.

Exemple :

set service dns forwarding domain example.com addnta
set service dns forwarding domain <domain-name> recursion-desired

Définissez le bit RD dans les requêtes envoyées au serveur DNS upstream pour ce domaine.

Exemple :

set service dns forwarding domain example.com recursion-desired

Zones autoritatives

Le forwarding DNS peut héberger des enregistrements autoritatifs pour un domaine, répondant directement plutôt que de transférer ou de rechercher.

set service dns forwarding authoritative-domain <domain-name> disable

Empêche le forwarding DNS de servir la zone autoritaire spécifiée, sans la supprimer de la configuration.

Les requêtes pour les noms dans la zone sont transférées ou recherchées au lieu d'être servies.

Exemple :

set service dns forwarding authoritative-domain example.com disable
set service dns forwarding authoritative-domain <domain-name> records <type> <name> disable

Empêche le forwarding DNS de servir un enregistrement spécifique dans la zone autoritaire, sans le supprimer de la configuration.

Les requêtes correspondant à l'enregistrement sont transférées ou recherchées au lieu d'être servies.

Exemple :

set service dns forwarding authoritative-domain example.com records a www disable
set service dns forwarding authoritative-domain <domain-name> records <type> <name> ttl <0-2147483647>

Configurez le TTL, en secondes, pour l'enregistrement spécifié.

La valeur par défaut est 300.

Exemple :

set service dns forwarding authoritative-domain example.com records a www ttl 600

Types de registres

Les commandes de type de registre de cette section acceptent les mots-clés suivants pour le nom de registre :

  • @ : Représente une zone apex, par exemple example.com. Accepté par tous les types de registre.

  • any : Représente un enregistrement wildcard, par exemple *.example.com, qui correspond à tous les sous-domaines sous l'apex. Accepté par les enregistrements a et aaaa uniquement.

set service dns forwarding authoritative-domain <domain-name> records a <name> address <ipv4-address>

Configurez un enregistrement A dans la zone autoritaire spécifiée.

Accepte @ et any comme <name>. Répétez la commande pour ajouter plusieurs adresses IPv4 au même enregistrement.

Exemple :

set service dns forwarding authoritative-domain example.com records a www address 192.0.2.10
set service dns forwarding authoritative-domain <domain-name> records aaaa <name> address <ipv6-address>

Configurez un enregistrement AAAA dans la zone autoritaire spécifiée.

Accepte @ et any comme <name>. Répétez la commande pour ajouter plusieurs adresses IPv6 au même enregistrement.

Exemple :

set service dns forwarding authoritative-domain example.com records aaaa www address 2001:db8::10
set service dns forwarding authoritative-domain <domain-name> records cname <name> target <target-domain-name>

Configurez un enregistrement CNAME dans la zone autoritaire spécifiée.

Accepte @ comme <name>.

Exemple :

set service dns forwarding authoritative-domain example.com records cname www target host.example.com
set service dns forwarding authoritative-domain <domain-name> records mx <name> server <server>

Configurez un enregistrement MX dans la zone autoritaire spécifiée.

Accepte @ comme <name>. Répétez la commande pour ajouter plusieurs serveurs de messagerie au même enregistrement.

Exemple :

set service dns forwarding authoritative-domain example.com records mx @ server mail.example.com
set service dns forwarding authoritative-domain <domain-name> records mx <name> server <server> priority <1-999>

Configurez la priorité de l'enregistrement MX spécifié.

Les valeurs plus basses sont prioritaires. La valeur par défaut est 10.

Exemple :

set service dns forwarding authoritative-domain example.com records mx @ server mail.example.com priority 20
set service dns forwarding authoritative-domain <domain-name> records ns <name> target <target-name>

Configurez un enregistrement NS dans la zone autoritaire spécifiée.

Accepte @ comme <name>. Répétez la commande pour ajouter plusieurs serveurs de noms au même enregistrement.

Exemple :

set service dns forwarding authoritative-domain example.com records ns @ target ns1.example.com
set service dns forwarding authoritative-domain <domain-name> records ptr <name> target <target-name>

Configurez un enregistrement PTR dans la zone autoritaire spécifiée.

Accepte @ comme <name>.

Exemple :

set service dns forwarding authoritative-domain 2.0.192.in-addr.arpa records ptr 10 target host.example.com
set service dns forwarding authoritative-domain <domain-name> records txt <name> value <value>

Configurez un enregistrement TXT dans la zone autoritaire spécifiée.

Accepte @ comme <name>. Répétez la commande pour ajouter plusieurs chaînes TXT au même enregistrement.

Exemple :

set service dns forwarding authoritative-domain example.com records txt @ value 'v=spf1 -all'
set service dns forwarding authoritative-domain <domain-name> records spf <name> value <value>

Configurez un enregistrement SPF dans la zone autoritaire spécifiée.

Accepte @ comme <name>.

Note

Les enregistrements SPF sont dépréciés au profit des enregistrements TXT. Privilégiez les enregistrements TXT pour les nouvelles implantations.

Exemple :

set service dns forwarding authoritative-domain example.com records spf @ value 'v=spf1 -all'
set service dns forwarding authoritative-domain <domain-name> records srv <name> entry <0-65535> hostname <name>

Configurez l'hôte cible d'une entrée d'enregistrement SRV dans la zone autoritaire spécifiée.

Accepte @ comme <name>.

Exemple :

set service dns forwarding authoritative-domain example.com records srv _sip._tcp entry 0 hostname sip.example.com
set service dns forwarding authoritative-domain <domain-name> records srv <name> entry <0-65535> port <0-65535>

Configurez le port d'une entrée d'enregistrement SRV dans la zone autoritaire spécifiée.

Exemple :

set service dns forwarding authoritative-domain example.com records srv _sip._tcp entry 0 port 5060
set service dns forwarding authoritative-domain <domain-name> records srv <name> entry <0-65535> priority <0-65535>

Configurez la priorité d'une entrée d'enregistrement SRV dans la zone autoritaire spécifiée.

Les valeurs plus basses sont prioritaires. La valeur par défaut est 10.

Exemple :

set service dns forwarding authoritative-domain example.com records srv _sip._tcp entry 0 priority 20
set service dns forwarding authoritative-domain <domain-name> records srv <name> entry <0-65535> weight <0-65535>

Configurez le poids d'une entrée d'enregistrement SRV dans la zone autoritaire spécifiée.

Le poids est utilisé pour distribuer la charge entre les entrées ayant la même priorité. La valeur par défaut est 0.

Exemple :

set service dns forwarding authoritative-domain example.com records srv _sip._tcp entry 0 weight 50
set service dns forwarding authoritative-domain <domain-name> records naptr <name> rule <0-65535> order <0-65535>

Configurez le champ d'ordre d'une règle NAPTR dans la zone autoritaire spécifiée.

Accepte @ comme <name>. Les règles avec un ordre plus bas sont évaluées en premier.

Exemple :

set service dns forwarding authoritative-domain example.com records naptr @ rule 100 order 10
set service dns forwarding authoritative-domain <domain-name> records naptr <name> rule <0-65535> preference <0-65535>

Configurez le champ de préférence d'une règle NAPTR dans la zone autoritaire spécifiée.

Accepte @ comme <name>. La valeur par défaut est 0.

Exemple :

set service dns forwarding authoritative-domain example.com records naptr @ rule 100 preference 50
set service dns forwarding authoritative-domain <domain-name> records naptr <name> rule <0-65535> lookup-a

Définissez le bit A sur une règle NAPTR dans la zone autoritaire spécifiée.

Lorsqu'il est activé, le forwarding DNS traite la sortie de la règle comme un nom de domaine et cherche son enregistrement A ou AAAA. Aucune autre recherche NAPTR ne suit.

Note

Définissez au plus un des champs lookup-a, lookup-srv, resolve-uri et protocol-specific sur la même règle NAPTR. Ces indicateurs définissent des actions suivantes mutuellement exclusives dans la résolution DNS.

Exemple :

set service dns forwarding authoritative-domain example.com records naptr @ rule 100 lookup-a
set service dns forwarding authoritative-domain <domain-name> records naptr <name> rule <0-65535> lookup-srv

Définissez le bit S sur une règle NAPTR dans la zone autoritaire spécifiée.

Lorsqu'il est activé, le forwarding DNS traite la sortie de la règle comme un nom de domaine et cherche son enregistrement SRV. Aucune autre recherche NAPTR ne suit.

Exemple :

set service dns forwarding authoritative-domain example.com records naptr @ rule 100 lookup-srv
set service dns forwarding authoritative-domain <domain-name> records naptr <name> rule <0-65535> resolve-uri

Définissez le bit U sur une règle NAPTR dans la zone autoritaire spécifiée.

Lorsqu'il est activé, le forwarding DNS traite la sortie de la règle comme un URI et l'utilise directement. Aucune autre recherche DNS ne suit.

Exemple :

set service dns forwarding authoritative-domain example.com records naptr @ rule 100 resolve-uri
set service dns forwarding authoritative-domain <domain-name> records naptr <name> rule <0-65535> protocol-specific

Définissez le bit P sur une règle NAPTR dans la zone autoritaire spécifiée.

Lorsqu'il est activé, le forwarding DNS traite la sortie de la règle selon le protocole d'application associé. Aucune autre recherche DNS ne suit.

Exemple :

set service dns forwarding authoritative-domain example.com records naptr @ rule 100 protocol-specific
set service dns forwarding authoritative-domain <domain-name> records naptr <name> rule <0-65535> service <service>

Configurez le champ Service d'une règle NAPTR dans la zone autoritaire spécifiée.

Définit le protocole et le service de résolution que cette règle propose dans le format Protocol+ResolutionService (par exemple, SIP sur TCP → SIP+D2T).

Exemple :

set service dns forwarding authoritative-domain example.com records naptr @ rule 100 service SIP+D2T
set service dns forwarding authoritative-domain <domain-name> records naptr <name> rule <0-65535> regexp <expression>

Configurez le champ Regexp d'une règle NAPTR dans la zone autoritaire spécifiée.

Une expression de substitution au format !ere!replacement!, appliquée au nom de la requête pour produire la cible de la prochaine recherche ou URI.

Note

Une règle utilise soit regexp soit replacement, pas les deux. Définir les deux produit un enregistrement NAPTR mal formé.

Exemple :

set service dns forwarding authoritative-domain example.com records naptr @ rule 100 regexp !^.*$!sip:[email protected]!
set service dns forwarding authoritative-domain <domain-name> records naptr <name> rule <0-65535> replacement <target-name>

Configurez le champ Replacement d'une règle NAPTR dans la zone autoritaire spécifiée.

Un nom DNS absolu utilisé comme cible de la prochaine recherche, dont le type dépend du drapeau de la règle.

Exemple :

set service dns forwarding authoritative-domain example.com records naptr @ rule 100 replacement sip.example.com

Mise en cache de zone

Le forwarding DNS peut charger une zone directement dans son cache via AXFR ou à partir d'un fichier de zone à une URL. La mise en cache de zone est configurée sous service dns forwarding zone-cache <domain-name>.

set service dns forwarding zone-cache <domain-name> source axfr <address>

Configurez le forwarding DNS pour charger la zone spécifiée via AXFR depuis le serveur DNS IPv4 ou IPv6 spécifié.

Exemple :

set service dns forwarding zone-cache example.com source axfr 192.0.2.53
set service dns forwarding zone-cache <domain-name> source url <url>

Configurez le forwarding DNS pour charger la zone spécifiée à partir de l'URL HTTP(S) pointant vers un fichier de zone.

Exemple :

set service dns forwarding zone-cache example.com source url https://zones.example.com/example.com.zone
set service dns forwarding zone-cache <domain-name> options timeout <1-3600>

Configurez pendant combien de secondes le forwarding DNS attend la récupération de la zone avant d'abandonner l'essai.

La valeur par défaut est 20.

Exemple :

set service dns forwarding zone-cache example.com
