SNMP

SNMP est un protocole standard d'Internet pour collecter et organiser des informations sur les appareils gérés sur des réseaux IP et pour modifier ces informations afin de changer le comportement des appareils. Les appareils qui supportent généralement SNMP incluent les modems câble, les routeurs, les commutateurs, les serveurs, les postes de travail, les imprimantes, et bien d'autres.

Le SNMP est largement utilisé dans la gestion réseau pour la surveillance du réseau. Le SNMP expose les données de gestion sous forme de variables sur les systèmes gérés organisées dans une base d'information de gestion (MIB) qui décrivent l'état et la configuration du système. Ces variables peuvent ensuite être interrogées à distance (et, dans certains cas, manipulées) par les applications de gestion.

Trois versions importantes du SNMP ont été développées et déployées. SNMPv1 est la version originale du protocole. Les versions plus récentes, SNMPv2c et SNMPv3, offrent des améliorations en termes de performance, de flexibilité et de sécurité.

Le SNMP est un composant du jeu de protocoles Internet tel que défini par le groupe de travail d'ingénierie Internet (IETF). Il se compose d'un ensemble de normes pour la gestion réseau, comprenant un protocole de couche application, un schéma de base de données et un ensemble d'objets de données.

Aperçu et concepts de base

Dans les utilisations typiques du SNMP, un ou plusieurs ordinateurs administratifs appelés gestionnaires ont la tâche de surveiller ou de gérer un groupe d'hôtes ou d'appareils sur un réseau informatique. Chaque système géré exécute un composant logiciel appelé agent qui transmet des informations via le SNMP au gestionnaire.

Un réseau géré par le SNMP comporte trois composants clés :

  • Appareils gérés

  • Agent - logiciel qui s'exécute sur les appareils gérés

  • Station de gestion réseau (NMS) - logiciel qui s'exécute sur le gestionnaire

Un appareil géré est un nœud de réseau qui implémente une interface SNMP qui permet un accès unidirectionnel (lecture seule) ou bidirectionnel (lecture et écriture) aux informations spécifiques au nœud. Les appareils gérés échangent des informations spécifiques au nœud avec les NMS. Parfois appelés éléments réseau, les appareils gérés peuvent être tout type d'appareil, y compris, mais sans s'y limiter, des routeurs, des serveurs d'accès, des commutateurs, des modems câble, des ponts, des hubs, des téléphones IP, des caméras vidéo IP, des hôtes informatiques et des imprimantes.

Un agent est un module de logiciel de gestion réseau qui réside sur un appareil géré. Un agent possède une connaissance locale des informations de gestion et traduit ces informations vers ou depuis une forme spécifique au SNMP.

Une station de gestion réseau exécute des applications qui surveillent et contrôlent les appareils gérés. Les NMS fournissent la majorité des ressources de traitement et de mémoire nécessaires pour la gestion réseau. Un ou plusieurs NMS peuvent exister sur n'importe quel réseau géré.

Note

VyOS SNMP prend en charge à la fois IPv4 et IPv6.

Versions du protocole SNMP

VyOS prend en charge SNMPv2 (version 2) et SNMPv3 (version 3), où la dernière est recommandée en raison d'une meilleure sécurité (authentification et chiffrement optionnels).

SNMPv2

SNMPv2 est la version originale et la plus couramment utilisée. Pour autoriser les clients, SNMP utilise le concept de communautés. Les communautés peuvent avoir une autorisation définie sur lecture seule (ce qui est le plus courant) ou sur lecture et écriture (cette option n'est pas activement utilisée dans VyOS).

SNMP peut fonctionner de manière synchrone ou asynchrone. Dans la communication synchrone, le système de surveillance interroge périodiquement le routeur. Dans le cas asynchrone, le routeur envoie une notification au « trap » (hôte de surveillance).

SNMPv2 ne prend en charge aucun mécanisme d'authentification, à part l'adresse source du client, donc vous devez spécifier les adresses des clients autorisés à surveiller le routeur. Notez que SNMPv2 ne prend également en charge aucun chiffrement et envoie toujours les données en texte clair.

Exemple

# Définir une communauté
set service snmp community routers authorization ro

# Autoriser l'accès de surveillance depuis l'ensemble du réseau
set service snmp community routers network 192.0.2.0/24
set service snmp community routers network 2001::db8:ffff:eeee::/64

# Autoriser l'accès de surveillance depuis des adresses spécifiques
set service snmp community routers client 203.0.113.10
set service snmp community routers client 203.0.113.20

# Définir des informations supplémentaires sur le routeur
set service snmp location "UK, London"
set service snmp contact "[email protected]"

# Cible de trap si vous voulez une communication asynchrone
set service snmp trap-target 203.0.113.10

# Écouter uniquement sur des adresses IP spécifiques (le port par défaut est 161)
set service snmp listen-address 172.16.254.36 port 161
set service snmp listen-address 2001:db8::f00::1

SNMPv3

SNMPv3 (version 3 du protocole SNMP) a introduit un ensemble complet de nouvelles fonctionnalités de sécurité qui manquaient aux versions précédentes. La sécurité était l'une des faiblesses les plus importantes du SNMP jusqu'à la version 3. L'authentification dans les versions 1 et 2 du SNMP se limite à rien de plus qu'un mot de passe (chaîne de communauté) envoyé en clair entre un gestionnaire et un agent. Chaque message SNMPv3 contient des paramètres de sécurité qui sont codés en tant que chaîne d'octets. Le sens de ces paramètres de sécurité dépend du modèle de sécurité utilisé.

L'approche de sécurité dans SNMPv3 vise :

  • Confidentialité – Chiffrement des paquets pour empêcher l'espionnage par une source non autorisée.

  • Intégrité – Intégrité des messages pour s'assurer qu'un paquet n'a pas été altéré pendant le transit, y compris un mécanisme de protection contre la reprise de paquet optionnel.

  • Authentification – pour vérifier que le message provient d'une source valide.

Exemple

  • Faire écouter le daemon SNMP uniquement sur l'adresse IP 192.0.2.1

  • Configurer un nouvel utilisateur SNMP nommé « vyos » avec le mot de passe « vyos12345678 »

  • Nouvel utilisateur utilisera SHA/AES pour l'authentification et la confidentialité

set service snmp listen-address 192.0.2.1
set service snmp location 'VyOS Datacenter'
set service snmp v3 engineid '000000000000000000000002'
set service snmp v3 group default mode 'ro'
set service snmp v3 group default view 'default'
set service snmp v3 user vyos auth plaintext-password 'vyos12345678'
set service snmp v3 user vyos auth type 'sha'
set service snmp v3 user vyos group 'default'
set service snmp v3 user vyos privacy plaintext-password 'vyos12345678'
set service snmp v3 user vyos privacy type 'aes'
set service snmp v3 view default oid 1

Après validation, les mots de passe en clair seront hachés et stockés dans votre configuration. La configuration CLI résultante ressemblera à ceci :

vyos@vyos# show service snmp

Vous pouvez tester la fonctionnalité SNMPv3 depuis n'importe quel système basé sur Linux, il suffit d'exécuter la commande suivante : snmpwalk -v 3 -u vyos -a SHA -A vyos12345678 -x AES -X vyos12345678 -l authPriv 192.0.2.1 .1

MIBs de VyOS

Tous les MIBs SNMP sont situés dans chaque image de VyOS ici : /usr/share/snmp/mibs/

Vous pouvez télécharger les fichiers à l'aide de SCP, une fois que le service SSH a été activé comme suit

scp -r vyos@your_router:/usr/share/snmp/mibs /your_folder/mibs

Extensions SNMP

Pour étendre la fonctionnalité de l'agent SNMP, des scripts personnalisés peuvent être exécutés à chaque fois que l'agent est appelé. Cela peut être réalisé en utilisant arbitrary extensioncommands. La première étape est bien sûr de créer un script fonctionnel, puis de le télécharger sur votre instance VyOS via la commande scp your_script.sh vyos@your_router:/config/user-data. Une fois le script téléchargé, il doit être configuré via la commande ci-dessous.

set service snmp script-extensions extension-name my-extension script your_script.sh
commit

L'OID .1.3.6.1.4.1.8072.1.3.2.3.1.1.4.116.101.115.116, une fois appelé, contiendra la sortie de l'extension.

root@vyos:/home/vyos# snmpwalk -v2c  -c public 127.0.0.1 nsExtendOutput1
NET-SNMP-EXTEND-MIB::nsExtendOutput1Line."my-extension" = STRING: hello
NET-SNMP-EXTEND-MIB::nsExtendOutputFull."my-extension" = STRING: hello
NET-SNMP-EXTEND-MIB::nsExtendOutNumLines."my-extension" = INTEGER: 1
NET-SNMP-EXTEND-MIB::nsExtendResult."my-extension" = INTEGER: 0

SolarWinds

Si vous utilisez Orion de SolarWinds comme NMS, vous pouvez également utiliser la Gestion des Modèles de Dispositif. Un modèle pour VyOS peut être facilement importé.

Créez un fichier nommé VyOS-1.3.6.1.4.1.44641.ConfigMgmt-Commands en utilisant le contenu suivant :

<Configuration-Management Device="VyOS" SystemOID="1.3.6.1.4.1.44641">
    <Commands>
        <Command Name="Reset" Value="set terminal width 0${CRLF}set terminal length 0"/>
        <Command Name="Reboot" Value="reboot${CRLF}Yes"/>
        <Command Name="EnterConfigMode" Value="configure"/>
        <Command Name="ExitConfigMode" Value="commit${CRLF}exit"/>
        <Command Name="DownloadConfig" Value="show configuration commands"/>
        <Command Name="SaveConfig" Value="commit${CRLF}save"/>
        <Command Name="Version" Value="show version"/>
        <Command Name="MenuBased" Value="False"/>
        <Command Name="VirtualPrompt" Value=":~"/>
    </Commands>
</Configuration-Management>
