L2TPv3

L2TPv3 interfaces vous permettent d'établir des tunnels L2TPv3 pour transporter le trafic de la couche 2 sur des réseaux IP.

Le protocole L2TPv3 (défini dans le RFC 3931) encapsule les trames de la couche 2 (par exemple, Ethernet, Frame Relay, HDLC) dans des paquets IP, permettant ainsi de traverser l'infrastructure IP sous-jacente.

Contrairement à L2TPv2, qui nécessite strictement l'encapsulation UDP, le protocole L2TPv3 est plus flexible et prend en charge deux types d'encapsulation :

  • IP direct : Les données du tunnel sont encapsulées directement dans des paquets IP (Protocole 115) pour un surcoût plus faible.

  • UDP : Les données du tunnel sont encapsulées dans un datagramme UDP. Cela permet au tunnel de traverser plus facilement le NAT.

Les tunnels L2TPv3 relient des sites géographiquement séparés, servant d'alternative plus simple à MPLS en fonctionnant sur une connectivité IP basique plutôt qu'en nécessitant une infrastructure MPLS complète.

Les tunnels L2TPv3 peuvent être établis sur des réseaux sous-jacents IPv4 et IPv6.

Configuration

Configuration commune de l'interface

set interfaces l2tpv3 <interface> address <address>

Configurez une ou plusieurs adresses IP d'interface.

<address> prend en charge IPv4 et IPv6 en notation CIDR. Par exemple, utilisez 192.0.2.1/24 pour IPv4 ou 2001:db8::1/64 pour IPv6.

Exemple :

set interfaces l2tpv3 l2tpeth0 address 192.0.2.1/24
set interfaces l2tpv3 l2tpeth0 address 2001:db8::1/64
set interfaces l2tpv3 <interface> description <description>

Configurez un alias clair et descriptif pour l'interface.

Cet alias apparaît dans la commande show interfaces et dans les outils de surveillance basés sur SNMP.

Exemple :

set interfaces l2tpv3 l2tpeth0 description 'This is an interface running on VyOS.'
set interfaces l2tpv3 <interface> disable

Désactivez l'interface.

L'interface sera définie sur l'état administrativement down (A/D).

Exemple :

set interfaces l2tpv3 l2tpeth0 disable
set interfaces l2tpv3 <interface> disable-flow-control

Désactivez le contrôle de flux Ethernet (trame pause IEEE 802.3x) sur l'interface.

Le contrôle de flux Ethernet, défini par la norme IEEE 802.3x, arrête temporairement la transmission des données pour éviter la perte de paquets pendant la congestion du réseau. Par exemple, lorsqu'un émetteur transmet des données plus rapidement que le récepteur ne peut les traiter.

La désactivation du contrôle de flux Ethernet signifie que l'interface ne signalera pas à l'appareil connecté de suspendre la transmission et supprimera les paquets si elle est submergée.

Exemple :

set interfaces l2tpv3 l2tpeth0 disable-flow-control
set interfaces l2tpv3 <interface> disable-link-detect

Désactivez la détection des changements d'état physique de l'interface, tels que lorsque un câble est débranché.

Par défaut, l'interface détecte les changements d'état physique.

Exemple :

set interfaces l2tpv3 l2tpeth0 disable-link-detect
set interfaces l2tpv3 <interface> mac <xx:xx:xx:xx:xx:xx>

Configurez une adresse MAC personnalisée sur l'interface.

Exemple :

set interfaces l2tpv3 l2tpeth0 mac '00:53:01:02:03:04'
set interfaces l2tpv3 <interface> mtu <mtu>

Configurez le MTU sur l'interface.

Cette valeur définit la taille maximale du paquet, en octets, que l'interface transmet sans fragmentation.

Exemple :

set interfaces l2tpv3 l2tpeth0 mtu 1600
set interfaces l2tpv3 <interface> ip adjust-mss <mss | clamp-mss-to-pmtu>

Configurez la MSS annoncée dans les paquets TCP SYN sortants sur l'interface spécifiée.

En limitant la valeur de MSS dans les paquets TCP SYN, vous informez explicitement l'extrémité distante qu'elle ne doit pas envoyer de paquets plus grands que cette taille. Cela empêche les problèmes de connexion qui surviennent lorsque la découverte du MTU du chemin (PMTUD) échoue.

Les options suivantes sont disponibles :

  • mss : Définit la MSS à une valeur spécifique, en octets. Utilisez cette option si vous avez besoin d'imposer une MSS spécifique, par exemple pour résoudre des problèmes de connectivité ou répondre à des exigences réseau spécifiques.

  • clamp-mss-to-pmtu : Le routeur calcule automatiquement la MSS à être la MTU de l'interface moins 40 octets pour le trafic IPv4 (20 octets pour l'en-tête IPv4 et 20 octets pour l'en-tête TCP). Cette option est recommandée pour définir automatiquement la bonne valeur.

set interfaces l2tpv3 <interface> ip arp-cache-timeout

Configurez la durée pendant laquelle une entrée ARP reste valide après avoir appris une correspondance entre une adresse IP et une adresse MAC sur cette interface.

La durée par défaut est de 30 secondes.

Une entrée ARP reste valide s'il reçoit un feedback positif des protocoles de niveau supérieur.

Exemple :

set interfaces l2tpv3 l2tpeth0 ip arp-cache-timeout 180
set interfaces l2tpv3 <interface> ip disable-arp-filter

Configurez le filtrage ARP sur cette interface.

Comportement par défaut : Le noyau répond aux demandes ARP sur cette interface uniquement si le trafic serait routé de retour à l'expéditeur ARP via cette interface spécifique.

Si configuré : Le noyau répond aux demandes ARP sur cette interface pour toute adresse IP configurée sur l'hôte local, indépendamment de l'interface spécifique à laquelle cette adresse IP est assignée, et indépendamment de la table de routage. Cela reflète le concept Linux selon lequel les adresses IP appartiennent à l'hôte, et non à des interfaces individuelles.

Exemple :

set interfaces l2tpv3 l2tpeth0 ip disable-arp-filter
set interfaces l2tpv3 <interface> ip disable-forwarding

Configurez l'interface pour un comportement d'hôte ou de routeur.

Si configuré, l'interface passe en mode hôte, et le transfert IPv4 est désactivé sur celle-ci.

Exemple :

set interfaces l2tpv3 l2tpeth0 ip disable-forwarding
set interfaces l2tpv3 <interface> ip enable-directed-broadcast

Configurez si les paquets broadcast directs IP reçus sur cette interface doivent être transmis.

Comportement par défaut : Les paquets broadcast directs IP sont supprimés.

Si configuré : Les paquets broadcast directs IP sont transmis à tous les hôtes sur le sous-réseau de destination, conformément au RFC 1812 et au RFC 2644.

Exemple :

set interfaces l2tpv3 l2tpeth0 ip enable-directed-broadcast
set interfaces l2tpv3 <interface> ip enable-arp-accept

Configurez comment traiter les ARP gratuit sur cette interface.

Si configuré, une correspondance IP-MAC est ajoutée au tableau ARP en fonction des demandes ou réponses ARP gratuit.

Note

Si le tableau ARP contient déjà l'adresse IP provenant d'un ARP gratuit, son entrée est mise à jour indépendamment de la configuration de ce paramètre.

Exemple :

set interfaces l2tpv3 l2tpeth0 ip enable-arp-accept
set interfaces l2tpv3 <interface> ip enable-arp-announce

Configurez la sélection de l'adresse IP source pour les demandes ARP sur cette interface.

Comportement par défaut : Le noyau peut utiliser n'importe quelle adresse IP possédée par l'hôte comme adresse IP source dans les demandes ARP sur cette interface.

Si configuré : Le noyau essaie d'abord de sélectionner une adresse IP configurée sur l'interface partageant un sous-réseau commun avec l'adresse IP cible. Si aucun tel sous-réseau n'existe, le noyau sélectionne l'adresse IP qu'il utiliserait normalement (en se basant sur la table de routage pour atteindre la destination cible).

Exemple :

set interfaces l2tpv3 l2tpeth0 ip enable-arp-announce
set interfaces l2tpv3 <interface> ip enable-arp-ignore

Configurez les demandes ARP qui seront ignorées sur cette interface.

Comportement par défaut : Le noyau répond aux demandes ARP pour toutes les adresses IP locales, indépendamment de l'interface à laquelle elles sont assignées.

Si configuré : Le noyau répond aux demandes ARP uniquement si l'adresse IP cible est assignée à cette interface spécifique.

Exemple :

set interfaces l2tpv3 l2tpeth0 ip enable-arp-ignore
set interfaces l2tpv3 <interface> ip enable-proxy-arp

Configurez le proxy ARP sur cette interface.

Si configuré, le routeur (noyau) intercepte les demandes ARP pour des adresses IP non locales et répond avec l'adresse MAC de l'interface qui a reçu la demande. Les paquets suivants destinés à ces adresses IP sont ensuite transmis vers leurs destinations réelles sur les sous-réseaux distants.

Exemple :

set interfaces l2tpv3 l2tpeth0 ip enable-proxy-arp
set interfaces l2tpv3 <interface> ip proxy-arp-pvlan

Configurez le proxy ARP local sur l'interface.

Si configuré, le routeur (noyau) répond aux demandes ARP sur cette interface VLAN même si l'adresse IP cible se trouve sur le même sous-réseau et interface.

Cela est utilisé pour soutenir les exigences d'isolation réseau (RFC 3069) pour les VLAN privés (PVLAN). Dans les configurations PVLAN, les hôtes sur les ports isolés ne sont PAS autorisés à communiquer directement entre eux au niveau 2, mais ils peuvent communiquer avec le routeur supérieur.

En répondant aux demandes ARP inter-hôtes avec sa propre adresse MAC, le routeur (noyau) dirige le trafic inter-hôtes à travers lui-même au lieu de directement entre les hôtes.

Note

Cette commande fonctionne indépendamment et ne nécessite pas l'activation du proxy ARP standard sur l'interface.

Le proxy ARP local est également connu sous les noms suivants :

  • Aggregation VLAN (RFC 3069).

  • VLAN privé (Cisco, Allied Telesyn).

  • Filtrage de port source ou isolation de port (Hewlett-Packard).

  • Transfert forcé MAC (Ericsson).

set interfaces l2tpv3 <interface> ip source-validation <strict | loose | disable>

Configurez la validation de l'adresse IP source à l'aide de RPF sur cette interface, comme spécifié dans RFC 3704.

Les options suivantes sont disponibles :

  • strict : Chaque adresse IP source des paquets entrants est vérifiée contre la base d'informations de routage (FIB). Si l'interface n'est pas le meilleur chemin de retour vers cette source, la validation échoue et le paquet est supprimé.

  • loose : Chaque adresse IP source des paquets entrants est vérifiée contre la FIB. Si l'adresse IP source est inatteignable à travers n'importe quelle interface, la validation échoue.

  • disable : Aucune validation de l'adresse IP source n'est effectuée. Tous les paquets entrants sont acceptés.

Le RFC 3704 recommande d'activer le mode strict pour empêcher la falsification d'IP, telle que les attaques DDoS. Pour les scénarios de routage asymétrique ou autres complexes, utilisez le mode loose.

set interfaces l2tpv3 <interface> ipv6 address autoconf

Configurez l'interface pour obtenir automatiquement une adresse IPv6 à l'aide de SLAAC, comme spécifié dans RFC 4862.

Les hôtes IPv6 peuvent se configurer automatiquement lorsqu'ils sont connectés à un réseau IPv6 en utilisant le protocole de découverte des voisins via les messages ICMPv6 de découverte de routeur. Lorsqu'ils se connectent pour la première fois à un réseau, un hôte envoie une demande multicast de routeur de lien local pour ses paramètres de configuration. Le routeur répond avec un paquet d'annonce de routeur contenant les paramètres de configuration de la couche Internet.

Note

Cette méthode désactive automatiquement le transfert de trafic IPv6 sur l'interface.

Exemple :

set interfaces l2tpv3 l2tpeth0 ipv6 address autoconf
set interfaces l2tpv3 <interface> ipv6 address eui64 <prefix>

Configurez l'interface pour lui attribuer une adresse IPv6 à l'aide de la méthode EUI-64 , comme spécifié dans RFC 4291.

Exemple :

set interfaces l2tpv3 l2tpeth0 ipv6 address eui64 2001:db8:beef::/64
set interfaces l2tpv3 <interface> ipv6 address no-default-link-local

Désactivez l'attribution automatique d'une adresse IPv6 de lien local à cette interface.

Exemple :

set interfaces l2tpv3 l2tpeth0 ipv6 address no-default-link-local
set interfaces l2tpv3 <interface> ipv6 disable-forwarding

Configurez l'interface pour un comportement d'hôte ou de routeur.

Si configuré, l'interface passe en mode hôte, et le transfert IPv6 est désactivé sur celle-ci.

Exemple :

set interfaces l2tpv3 l2tpeth0 ipv6 disable-forwarding
set interfaces l2tpv3 <interface> ipv6 adjust-mss <mss | clamp-mss-to-pmtu>

Configurez la MSS annoncée dans les paquets TCP SYN sortants sur l'interface spécifiée.

En limitant la valeur de MSS dans les paquets TCP SYN, vous informez explicitement l'extrémité distante qu'elle ne doit pas envoyer de paquets plus grands que cette taille. Cela empêche les problèmes de connexion lorsqu'il y a un échec de la découverte du MTU du chemin (PMTUD).

Les options suivantes sont disponibles :

  • mss : Définit la MSS à une valeur spécifique, en octets. Utilisez cette option pour imposer une MSS spécifique, par exemple pour résoudre des problèmes de connectivité ou répondre à des exigences réseau spécifiques.

  • clamp-mss-to-pmtu : Le routeur calcule la MSS comme étant la MTU de l'interface moins 60 octets pour le trafic IPv6 (40 octets pour l'en-tête IPv6 et 20 octets pour l'en-tête TCP). Cette option est recommandée pour définir automatiquement la bonne valeur.

set interfaces l2tpv3 <interface> ipv6 accept-dad <0 | 1 | 2>

Configurez le DAD IPv6 sur l'interface.

Les options suivantes sont disponibles :

  • 0 : Désactive le DAD. Aucune détection de duplication d'adresse n'est effectuée.

  • 1 : Active le DAD (par défaut). Les adresses dupliquées sont détectées. L'opération IPv6 de l'interface continue pour les adresses IPv6 valides.

  • 2 : Active le DAD et, si une adresse de lien local dupliquée basée sur la MAC est trouvée, désactive l'opération IPv6 sur cette interface.

Exemple :

set interfaces l2tpv3 l2tpeth0 ipv6 accept-dad 2
set interfaces l2tpv3 <interface> ipv6 dup-addr-detect-transmits <n>

Configurez le nombre de DAD messages que le routeur (noyau) envoie pendant l'attribution d'adresse IPv6 sur cette interface.

La valeur par défaut est 1.

Exemple :

set interfaces l2tpv3 l2tpeth0 ipv6 dup-addr-detect-transmits 5
set interfaces l2tpv3 <interface> vrf <vrf>

Attribuez l'interface à une instance spécifique de VRF .

Voir aussi

Pour plus d'informations sur la configuration d'un VRF, consultez la section VRF.

Exemple :

set interfaces l2tpv3 l2tpeth0 vrf red

Options L2TPv3

Utilisez les commandes suivantes pour configurer les paramètres spécifiques du tunnel L2TPv3.

set interfaces l2tpv3 <interface> encapsulation <udp | ip>

Configurez le type d'encapsulation pour le tunnel L2TPv3.

Les valeurs valides sont udp et ip.

Le type d'encapsulation par défaut est udp.

Note

Le type d'encapsulation doit être identique sur les pairs locaux et distants pour que le tunnel puisse être établi.

set interfaces l2tpv3 <interface> source-address <address>

Configurez l'adresse IP source du tunnel L2TPv3.

L'adresse spécifiée doit être une adresse IP d'interface locale et peut être soit IPv4, soit IPv6.

set interfaces l2tpv3 <interface> remote <address>

Configurez l'adresse IP de destination du tunnel L2TPv3.

L'adresse spécifiée doit être une adresse IP d'interface d'un pair distant et peut être soit IPv4, soit IPv6.

set interfaces l2tpv3 <interface> session-id <id>

Configurez l'identifiant de session local dans le tunnel L2TPv3.

Le session-id est une valeur de 32 bits qui identifie une session de tunnel entrante sur le pair local.

Le peer-session-id qui identifie cette session sur le pair distant doit être configuré avec la même valeur.

set interfaces l2tpv3 <interface> peer-session-id <id>

Configurez l'identifiant de session du pair dans le tunnel L2TPv3.

Le peer-session-id est une valeur de 32 bits qui identifie une session de tunnel sortante depuis le pair local.

Le peer-session-id doit correspondre au session-id configuré pour cette session sur le pair distant.

set interfaces l2tpv3 <interface> tunnel-id <id>

Configurez l'identifiant local du tunnel L2TPv3.

Le tunnel-id est une valeur de 32 bits qui identifie le tunnel L2TPv3 sur le pair local.

Le peer-tunnel-id qui identifie ce tunnel sur le pair distant doit être configuré avec la même valeur.

set interfaces l2tpv3 <interface> peer-tunnel-id <id>

Configurez l'identifiant du pair pour le tunnel L2TPv3.

Le peer-tunnel-id est une valeur de 32 bits qui identifie le tunnel L2TPv3 sur le pair distant et doit correspondre au tunnel-id configuré pour ce tunnel sur ce pair.

Le peer-tunnel-id doit correspondre au tunnel-id qui identifie ce tunnel sur le pair distant.

Exemple

Tunnel L2TPv3 avec encapsulation IP

L'exemple suivant montre la configuration d'un tunnel L2TPv3 utilisant l'encapsulation IP directe :

# show interfaces l2tpv3
l2tpv3 l2tpeth10 {
    address 192.168.37.1/27
    encapsulation ip
    source-address 192.0.2.1
    peer-session-id 100
    peer-tunnel-id 200
    remote 203.0.113.24
    session-id 100
    tunnel-id 200
}

La configuration inverse doit être appliquée au pair distant.

Tunnel L2TPv3 avec encapsulation UDP

L'exemple suivant montre la configuration d'un tunnel L2TPv3 utilisant l'encapsulation UDP.

Cette configuration est recommandée lorsque le tunnel traverse des dispositifs NAT.

Remarques concernant la configuration :

  • Utilisez une adresse IP LAN locale comme source-address.

  • Configurez une règle de transfert pour autoriser le trafic de tunnel sur le port UDP spécifié sur le dispositif NAT amont.

  • Utilisez un port UDP distinct pour chaque tunnel individuel.

# show interfaces l2tpv3
l2tpv3 l2tpeth10 {
    address 192.168.37.1/27
    destination-port 9001
    encapsulation udp
    source-address 192.0.2.1
    peer-session-id 100
    peer-tunnel-id 200
    remote 203.0.113.24
    session-id 100
    source-port 9000
    tunnel-id 200
}
