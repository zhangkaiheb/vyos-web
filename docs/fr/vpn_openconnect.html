OpenConnect

À faire

Convertir les blocs de commandes brutes dans ce fichier en directives cfgcmd/opcmd pour le suivi de la couverture des commandes.

La fonctionnalité du serveur compatible OpenConnect est disponible depuis Equuleus (1.3). Le VPN OpenConnect prend en charge la connexion SSL et offre un accès complet au réseau. L'extension de réseau SSL connecte le système utilisateur à l'entreprise avec des contrôles d'accès basés uniquement sur des informations de couche réseau, comme l'adresse IP de destination et le numéro de port. Ainsi, il fournit une communication sécurisée pour tous les types de trafic d'appareil sur les réseaux publics et privés, et chiffre également le trafic avec le protocole SSL.

L'utilisateur distant utilisera le client openconnect pour se connecter au routeur et recevra une adresse IP d'une plage de VPN, permettant un accès complet au réseau.

Configuration

Certificats SSL

Nous devons générer le certificat qui authentifie les utilisateurs qui tentent d'accéder aux ressources réseau via les tunnels SSL. Les commandes suivantes créeront des certificats auto-signés et seront stockées dans la configuration :

run generate pki ca install <CA name>
run generate pki certificate sign <CA name> install <Server name>

Nous pouvons également créer les certificats en utilisant Certbot, un client facile à utiliser qui obtient un certificat de Let’s Encrypt, une autorité de certification ouverte lancée par l'EFF, Mozilla et d'autres, et le déploie sur un serveur web.

sudo certbot certonly --standalone --preferred-challenges http -d <domain name>

Configuration du serveur

set vpn openconnect authentication local-users username <user> password <pass>
set vpn openconnect authentication mode <local password|radius|certificate>
set vpn openconnect network-settings client-ip-settings subnet <subnet>
set vpn openconnect network-settings name-server <address>
set vpn openconnect network-settings name-server <address>
set vpn openconnect ssl ca-certificate <pki-ca-name>
set vpn openconnect ssl certificate <pki-cert-name>
set vpn openconnect ssl passphrase <pki-password>

Prise en charge du 2FA OTP

Au lieu de l'authentification par mot de passe uniquement, l'authentification par mot de passe + clé OTP peut être utilisée. Alternativement, l'authentification par OTP seule, sans mot de passe, peut être utilisée. Pour cela, une configuration OTP doit être ajoutée à la configuration ci-dessus :

set vpn openconnect authentication mode local <password-otp|otp>
set vpn openconnect authentication local-users username <user> otp <key>
set vpn openconnect authentication local-users username <user> interval <interval (optional)>
set vpn openconnect authentication local-users username <user> otp-length <otp-length (optional)>
set vpn openconnect authentication local-users username <user> token-type <token-type (optional)>

Pour générer une clé OTP dans VyOS, vous pouvez utiliser la commande CLI (mode opérationnel) :

generate openconnect username <user> otp-key hotp-time

Authentification par certificat utilisateur

Vous pouvez configurer les utilisateurs pour qu'ils soient authentifiés par certificat en définissant le mode d'authentification sur certificat, et en définissant quel champ (par OID) du certificat sera utilisé pour identifier le nom d'utilisateur. Deux raccourcis prédéfinis pour le Common Name (OID 2.5.4.3) et le User ID (OID 0.9.2342.19200300.100.1.1) ont été fournis sous les noms cn ou uid.

Autrement dit, une valeur OID spécifique doit être fournie.

Le certificat de l'utilisateur doit être signé par l'autorité de certification définie dans la configuration pour qu'il soit validé pour l'authentification.

set vpn openconnect authentication mode certificate
set vpn openconnect authentication mode certificate user-identifier-field cn
set vpn openconnect ssl ca-certificate <cert>

Configuration Openconnect

Configuration simple avec un utilisateur ajouté et authentification par mot de passe :

set vpn openconnect authentication local-users username tst password 'OC_bad_Secret'
set vpn openconnect authentication mode local password
set vpn openconnect network-settings client-ip-settings subnet '172.20.20.0/24'
set vpn openconnect network-settings name-server '10.1.1.1'
set vpn openconnect network-settings name-server '10.1.1.2'
set vpn openconnect ssl ca-certificate 'ca-ocserv'
set vpn openconnect ssl certificate 'srv-ocserv'

Pour activer les en-têtes de sécurité HTTP dans le fichier de configuration, utilisez la commande :

set vpn openconnect http-security-headers

Configuration basée sur l'identité

OpenConnect prend en charge un sous-ensemble de ses options de configuration pour être appliqué par utilisateur/groupe, pour des raisons de configuration, nous faisons référence à cette fonctionnalité comme « configuration basée sur l'identité ». Le manuel suivant d'OpenConnect Server ouvre la liste des options de configuration autorisées. Cela peut être utilisé pour appliquer différents ensembles de configurations à différents utilisateurs ou groupes d'utilisateurs.

sudo mkdir -p /config/auth/ocserv/config-per-user
sudo touch /config/auth/ocserv/default-user.conf

set vpn openconnect authentication identity-based-config mode user
set vpn openconnect authentication identity-based-config directory /config/auth/ocserv/config-per-user
set vpn openconnect authentication identity-based-config default-config /config/auth/ocserv/default-user.conf

Avertissement

Le répertoire ci-dessus et le default-config doivent être un sous-répertoire de /config/auth, car les fichiers en dehors de ce répertoire ne sont pas persistants après une mise à jour d'image.

Une fois que vous avez validé les modifications ci-dessus, vous pouvez créer un fichier de configuration dans le répertoire /config/auth/ocserv/config-per-user qui correspond à un nom d'utilisateur que vous avez créé, par exemple « tst ». Maintenant, lors de la connexion avec l'utilisateur « tst », les options de configuration que vous avez définies dans ce fichier seront chargées.

Assurez-vous de définir une configuration par défaut raisonnable dans le fichier de configuration par défaut, celle-ci sera chargée dans le cas où un utilisateur s'authentifie et qu'aucun fichier ne se trouve dans le répertoire configuré correspondant au nom d'utilisateur/groupe.

sudo nano /config/auth/ocserv/config-per-user/tst

Les mêmes options de configuration s'appliquent lorsque la configuration basée sur l'identité est configurée en mode groupe, sauf que le mode groupe ne peut être utilisé qu'avec l'authentification RADIUS.

Avertissement

Le serveur OpenConnect correspond au nom de fichier de manière sensible à la casse, assurez-vous que le nom d'utilisateur/groupe que vous configurez correspond exactement au nom de fichier.

Configuration de la comptabilité RADIUS

OpenConnect peut être configuré pour envoyer des informations de comptabilité à un serveur RADIUS afin de capturer les données de session utilisateur telles que le moment de connexion/déconnexion, les données transférées, etc.

Configurez un serveur de comptabilité et activez la comptabilité avec :

set vpn openconnect accounting mode radius
set vpn openconnect accounting radius server 172.20.20.10
set vpn openconnect accounting radius server 172.20.20.10 port 1813
set vpn openconnect accounting radius server 172.20.20.10 key your_radius_secret

Avertissement

La fonctionnalité de comptabilité RADIUS doit être utilisée avec le mode d'authentification OpenConnect RADIUS. Elle ne peut pas être utilisée avec l'authentification locale. Vous devez configurer le mode d'authentification OpenConnect en « radius ».
