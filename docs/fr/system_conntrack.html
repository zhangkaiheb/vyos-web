Conntrack

VyOS peut être configuré pour suivre les connexions à l'aide du sous-système de suivi des connexions. Le suivi des connexions devient opérationnel une fois que soit un pare-feu stateful, soit le NAT est configuré.

Configurer

set system conntrack table-size <1-50000000>

Le tableau de suivi des connexions contient une entrée pour chaque connexion suivie par le système.

set system conntrack expect-table-size <1-50000000>

Le tableau de suivi des connexions attendues contient une entrée pour chaque connexion attendue liée à une connexion existante. Ces connexions sont généralement utilisées par les modules « helper de suivi de connexion » tels que FTP. La taille par défaut du tableau d'attente est de 2048 entrées.

set system conntrack hash-size <1-50000000>

Définir la taille du tableau de hachage. Le tableau de hachage de suivi des connexions accélère la recherche dans le tableau de suivi des connexions. Le tableau de hachage utilise des « buckets » pour enregistrer les entrées dans le tableau de suivi des connexions.

set system conntrack modules ftp
set system conntrack modules h323
set system conntrack modules nfs
set system conntrack modules pptp
set system conntrack modules sip
set system conntrack modules sqlnet
set system conntrack modules tftp

Configurez les modules de gestion des protocoles de suivi des connexions. Tous les modules sont activés par défaut.

Utilisez delete system conntrack modules pour désactiver tous les modules.
Ou, par exemple pour ftp, delete system conntrack modules ftp.
set system conntrack tcp half-open-connections <1-21474836>

Définir le nombre maximum de connexions TCP demi-ouvertes.

set system conntrack tcp loose <enable | disable>

Politique pour suivre les connexions précédemment établies.

set system conntrack tcp max-retrans <1-2147483647>

Définir le nombre maximal de tentatives de rétransmission TCP.

Timeouts Conntrack

Vous pouvez définir des valeurs de timeout personnalisées à appliquer à un sous-ensemble spécifique de connexions, en fonction d'un sélecteur de paquet et de flux. Pour cela, vous devez créer une règle définissant le sélecteur de paquet et de flux.

set system conntrack timeout custom [ipv4 | ipv6] rule <1-999999> description <test>

Définir une description de règle.

set system conntrack timeout custom [ipv4 | ipv6] rule <1-999999> destination address <ip-address>
set system conntrack timeout custom [ipv4 | ipv6] rule <1-999999> source address <ip-address>

Définir une adresse de destination et/ou source. Entrée acceptée pour ipv4 :

set system conntrack timeout custom ipv4 rule <1-999999> [source | destination] address
Complétions possibles :
   <x.x.x.x>            Adresse IPv4 à correspondre
   <x.x.x.x/x>          Préfixe IPv4 à correspondre
   <x.x.x.x>-<x.x.x.x>  Plage d'adresses IPv4 à correspondre
   !<x.x.x.x>           Correspondre à tout sauf l'adresse spécifiée
   !<x.x.x.x/x>         Correspondre à tout sauf le préfixe spécifié
   !<x.x.x.x>-<x.x.x.x> Correspondre à tout sauf la plage spécifiée

set system conntrack timeout custom ipv6 rule <1-999999> [source | destination] address
Complétions possibles :
   <h:h:h:h:h:h:h:h>    Adresse IP à correspondre
   <h:h:h:h:h:h:h:h/x>  Sous-réseau à correspondre
   <h:h:h:h:h:h:h:h>-<h:h:h:h:h:h:h:h>
                        Plage d'adresses IP à correspondre
   !<h:h:h:h:h:h:h:h>   Correspondre à tout sauf l'adresse spécifiée
   !<h:h:h:h:h:h:h:h/x> Correspondre à tout sauf le préfixe spécifié
   !<h:h:h:h:h:h:h:h>-<h:h:h:h:h:h:h:h>
                        Correspondre à tout sauf la plage spécifiée
set system conntrack timeout custom [ipv4 | ipv6] rule <1-999999> destination port <value>
set system conntrack timeout custom [ipv4 | ipv6] rule <1-999999> source port <value>

Définir une destination et/ou une porte source. Entrée acceptée :

<nom de port>    Port nommé (n'importe quel nom dans /etc/services, par exemple http)
<1-65535>        Numéro de port
<start>-<end>  Plage de numéros de port (par exemple 1001-1005)

Plusieurs ports de destination peuvent être spécifiés sous forme d'une liste séparée par des virgules. L'ensemble de la liste peut également être « négatif » en utilisant « ! ». Par exemple : !22,telnet,http,123,1001-1005`

set system conntrack timeout custom [ipv4 | ipv6] rule <1-999999> protocol tcp close <1-21474836>
set system conntrack timeout custom [ipv4 | ipv6] rule <1-999999> protocol tcp close-wait <1-21474836>
set system conntrack timeout custom [ipv4 | ipv6] rule <1-999999> protocol tcp established <1-21474836>
set system conntrack timeout custom [ipv4 | ipv6] rule <1-999999> protocol tcp fin-wait <1-21474836>
set system conntrack timeout custom [ipv4 | ipv6] rule <1-999999> protocol tcp last-ack <1-21474836>
set system conntrack timeout custom [ipv4 | ipv6] rule <1-999999> protocol tcp syn-recv <1-21474836>
set system conntrack timeout custom [ipv4 | ipv6] rule <1-999999> protocol tcp syn-sent <1-21474836>
set system conntrack timeout custom [ipv4 | ipv6] rule <1-999999> protocol tcp time-wait <1-21474836>
set system conntrack timeout custom [ipv4 | ipv6] rule <1-999999> protocol udp replied <1-21474836>
set system conntrack timeout custom [ipv4 | ipv6] rule <1-999999> protocol udp unreplied <1-21474836>

Définir le délai d'attente en secondes pour un protocole ou un état dans une règle personnalisée.

Règles d'ignorance Conntrack

Remarque

Important sur les règles d'ignorance Conntrack : À partir de vyos-1.5-rolling-202406120020, les règles d'ignorance peuvent être définies dans set firewall [ipv4 | ipv6] prerouting raw .... Il est prévu que dans le futur, les règles d'ignorance Conntrack seront supprimées.

Règles d'ignorance personnalisées, basées sur un sélecteur de paquet et de flux.

set system conntrack ignore [ipv4 | ipv6] rule <1-999999> description <text>
set system conntrack ignore [ipv4 | ipv6] rule <1-999999> destination address <ip-address>
set system conntrack ignore [ipv4 | ipv6] rule <1-999999> destination port <port>
set system conntrack ignore [ipv4 | ipv6] rule <1-999999> inbound-interface <interface>
set system conntrack ignore [ipv4 | ipv6] rule <1-999999> protocol <protocol>
set system conntrack ignore [ipv4 | ipv6] rule <1-999999> source address <ip-address>
set system conntrack ignore [ipv4 | ipv6] rule <1-999999> source port <port>
set system conntrack ignore [ipv4 | ipv6] rule <1-999999> tcp flags [not] <text>

Valeurs autorisées pour les drapeaux TCP : ack, cwr, ecn, fin, psh, rst, syn et urg. Des valeurs multiples sont prises en charge, et pour une sélection inversée, utiliser not, comme indiqué dans l'exemple.

Journal Conntrack

set system conntrack log event destroy
set system conntrack log event new
set system conntrack log event update

Enregistrer les événements de suivi des connexions par type.

set system conntrack log event destroy icmp
set system conntrack log event destroy other
set system conntrack log event destroy tcp
set system conntrack log event destroy udp
set system conntrack log event new icmp
set system conntrack log event new other
set system conntrack log event new tcp
set system conntrack log event new udp
set system conntrack log event update icmp
set system conntrack log event update other
set system conntrack log event update tcp
set system conntrack log event update udp

Enregistrer les événements de suivi des connexions par protocole.

set system conntrack log timestamp

Activer l'extension de l'horodatage basée sur le flux.

set system conntrack log queue-size <100-999999>

Gérer la taille de la file d'attente interne, la taille par défaut est de 4096 événements.

set system conntrack log log-level <info | debug>

Gérer le niveau de journalisation
