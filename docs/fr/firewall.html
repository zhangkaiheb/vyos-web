Firewall

Avertissement

En raison d'une condition de concurrence au démarrage, toutes les interfaces s'initialisent avant le firewall. Cela laisse temporairement le système ouvert à tout le trafic et représente un risque de sécurité.

VyOS utilise Netfilter. Le projet Netfilter a développé iptables et son successeur nftables pour le noyau Linux pour traiter les flux de données des paquets directement. Cela étend le concept de sécurité par zone pour vous permettre de manipuler les données à plusieurs étapes après que l'interface réseau et le pilote l'aient acceptée, et avant de l'envoyer à sa destination (par exemple, un serveur web ou un autre appareil).

Le diagramme suivant est un schéma simplifié du flux de paquets basé sur Netfilter. Ce diagramme donne un aperçu de la manière dont les paquets sont traités et des chemins possibles que peut prendre le trafic.

Les points principaux concernant le flux des paquets et la terminologie dans le firewall VyOS sont :

  • Port de pont ?: Choisissez le chemin approprié en fonction de savoir si l'interface où le paquet a été reçu fait partie d'un pont.

Si l'interface où le paquet a été reçu ne fait pas partie d'un pont, le paquet est traité au niveau de la couche IP :

  • Pré-routing: Le routeur traite tous les paquets à cette étape, indépendamment de la destination. Vous pouvez effectuer plusieurs actions à cette étape, et ces actions sont également définies dans différentes parties de la configuration VyOS. L'ordre est important. La configuration pertinente qui s'applique à cette étape inclut :

    • Firewall pré-routing: Les règles que vous définissez sous set firewall [ipv4 | ipv6] prerouting raw.... Le système traite toutes les règles de cette section avant le sous-système de suivi des connexions.

    • Ignorer le suivi de connexion: Les règles que vous définissez sous set system conntrack ignore [ipv4 | ipv6] .... Vous pouvez configurer cette section avec firewall [ipv4 | ipv6] prerouting .... Pour des raisons de compatibilité, cette fonctionnalité est prise en charge, mais elle sera dépréciée à l'avenir.

    • Route poli: Les règles que vous définissez sous set policy [route | route6] ....

    • NAT de destination: Les règles que vous définissez sous set [nat | nat66] destination....

  • La destination est le routeur ?: Choisissez le chemin approprié en fonction de l'adresse IP de destination. Le trafic transit continue vers forward, tandis que le trafic destiné au routeur continue vers input.

  • Input: L'étape où vous filtrez et contrôlez le trafic destiné au routeur lui-même. C'est là que vous appliquez toutes les règles pour sécuriser le routeur. Cela inclut les règles de filtrage IPv4 et IPv6, définies dans :

    • set firewall ipv4 input filter ....

    • set firewall ipv6 input filter ....

  • Forward: L'étape où vous filtrez et contrôlez le trafic transit. Cela inclut les règles de filtrage IPv4 et IPv6, définies dans :

    • set firewall ipv4 forward filter ....

    • set firewall ipv6 forward filter ....

  • Output: L'étape où vous filtrez et contrôlez le trafic que le routeur génère. Notez que ce trafic provient soit d'une nouvelle connexion initiée par un processus interne sur le routeur VyOS (comme NTP), soit d'une réponse au trafic reçu par le routeur via input (par exemple, une réponse à une tentative de connexion SSH). Cela inclut les règles IPv4 et IPv6, et deux sections différentes s'appliquent :

    • Output Prerouting: set firewall [ipv4 | ipv6] output raw .... Comme décrit dans Prerouting, le système traite les règles de cette section avant le sous-système de suivi des connexions.

    • Output Filter: set firewall [ipv4 | ipv6] output filter ....

  • Postrouting: Comme dans Prerouting, vous pouvez effectuer plusieurs actions définies dans différentes parties de la configuration VyOS à cette étape. Cela inclut :

    • NAT source: Les règles que vous définissez sous set [nat | nat66] source....

Si l'interface où le paquet a été reçu fait partie d'un pont, le paquet est traité au niveau de la couche pont :

  • Pré-routing (Pont): Le pont traite tous les paquets qu'il reçoit à cette étape, indépendamment de la destination. Tout d'abord, vous pouvez appliquer des filtres ici, ou configurer des règles qui ignorent le système de suivi des connexions. La configuration pertinente qui s'applique :

    • set firewall bridge prerouting filter ....

  • Forward (Pont): L'étape où vous filtrez et contrôlez le trafic qui passe à travers le pont :

    • set firewall bridge forward filter ....

  • Input (Pont): L'étape où vous filtrez et contrôlez le trafic destiné au pont lui-même :

    • set firewall bridge input filter ....

  • Output (Pont): L'étape où vous filtrez et contrôlez le trafic que le pont génère :

    • set firewall bridge output filter ....

Voici une liste des sous-commandes de la CLI du firewall VyOS et leurs pages correspondantes dans la documentation :

set firewall bridge …

Configurer les règles de pare-feu de pont pour le trafic au niveau de la couche pont. Voir la page Configuration du pare-feu de pont pour plus d'informations détaillées.

set firewall flowtable …

Configurer les flowtables de pare-feu pour le suivi des connexions étatiques et les règles. Voir la page Configuration des flowtables de pare-feu pour plus d'informations détaillées.

set firewall global-options …

Configurer les options globales du pare-feu telles que all-ping, broadcast-ping, syn-cookies et autres paramètres système du pare-feu. Voir la page Options globales du pare-feu pour plus d'informations détaillées.

set firewall group …

Organiser les règles de pare-feu en créant des groupes d'adresses, de réseaux, d'interfaces, de MAC, de ports et de domaines réutilisables. Utilisez des groupes dans plusieurs règles pour simplifier la configuration et la maintenance. Voir la page Groupes de pare-feu pour plus d'informations détaillées.

set firewall ipv4 …

Configurer les règles de pare-feu spécifiques à IPv4. Voir la page Configuration du pare-feu IPv4 pour plus d'informations détaillées.

set firewall ipv6 …

Configurer les règles de pare-feu spécifiques à IPv6. Voir la page Configuration du pare-feu IPv6 pour plus d'informations détaillées.

set firewall zone …

Configurer les politiques de pare-feu basées sur les zones pour contrôler le trafic entre différentes zones réseau. Voir la page Configuration du pare-feu basé sur les zones pour plus d'informations détaillées.

Pour plus d'informations sur la configuration du pare-feu, voir les pages suivantes :

Pare-feu basé sur les zones

  • Pare-feu basé sur les zones

Avec les pare-feux basés sur les zones, un nouveau concept s'applique. En plus des flux de trafic entrant et sortant standards, un flux local permet le trafic provenant et destiné au routeur lui-même. Cela signifie que vous devez configurer des règles supplémentaires pour sécuriser le pare-feu par rapport au réseau, en plus des règles existantes entrantes et sortantes.

Pour configurer VyOS avec un pare-feu basé sur les zones, voir Configuration du pare-feu basé sur les zones.
