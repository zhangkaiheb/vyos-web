Serveur PPPoE

VyOS utilise accel-ppp pour fournir la fonctionnalité de serveur PPPoE. Il peut être utilisé avec une authentification locale ou un serveur RADIUS connecté.

Remarque

Veuillez noter, en raison d'un bug upstream, les changements/de commits de configuration redémarreront le démon ppp et réinitialiseront les connexions PPPoE existantes des utilisateurs connectés, afin de devenir effectifs.

Configuration du serveur PPPoE

set service pppoe-server access-concentrator PPPoE-Server
set service pppoe-server authentication mode local
set service pppoe-server authentication local-users username test password 'test'
set service pppoe-server client-ip-pool PPPOE-POOL range 192.168.255.2-192.168.255.254
set service pppoe-server default-pool 'PPPOE-POOL'
set service pppoe-server gateway-address 192.168.255.1
set service pppoe-server interface eth0
set service pppoe-server access-concentrator <name>

Utilisez cette commande pour définir un nom pour ce concentrateur PPPoE.

set service pppoe-server authentication mode <local | radius>

Définir le backend d'authentification. Le backend d'authentification configuré est utilisé pour toutes les requêtes.

  • radius: Toutes les requêtes d'authentification sont gérées par un serveur RADIUS configuré.

  • local: Toutes les requêtes d'authentification sont gérées localement.

  • noauth: L'authentification est désactivée.

set service pppoe-server authentication local-users username <name> password <password>

Créer <user> pour l'authentification locale sur ce système. Le mot de passe de l'utilisateur sera défini à <pass>.

set service pppoe-server client-ip-pool <POOL-NAME> range <x.x.x.x-x.x.x.x | x.x.x.x/x>

Utilisez cette commande pour définir la première adresse IP d'un pool d'adresses à attribuer aux clients PPPoE. Si la notation x.x.x.x-x.x.x.x, elle doit se trouver dans un sous-réseau /24. Si la notation x.x.x.x/x est utilisée, il est possible de définir un hôte/réseau masque.

set service pppoe-server default-pool <POOL-NAME>

Utilisez cette commande pour définir le nom du pool d'adresses par défaut.

set service pppoe-server interface <interface>

Utilisez cette commande pour définir l'interface que le serveur PPPoE utilisera pour écouter les clients PPPoE.

set service pppoe-server gateway-address <address>

Spécifie une seule adresse <gateway> IP à utiliser comme adresse locale des interfaces PPP.

Configuration de l'authentification RADIUS

Pour activer l'authentification basée sur RADIUS, le mode d'authentification doit être modifié dans la configuration. Les paramètres précédents comme les utilisateurs locaux, existent toujours dans la configuration, cependant ils ne sont pas utilisés si le mode a été changé de local à radius. Une fois changé en local, il utilisera à nouveau tous les comptes locaux.

set service pppoe-server authentication mode radius
set service pppoe-server authentication radius server <server> key <secret>

Configurer le serveur RADIUS <server> et sa clé partagée nécessaire <secret> pour communiquer avec le serveur RADIUS.

Comme le serveur RADIUS serait un point de défaillance unique, plusieurs serveurs RADIUS peuvent être configurés et seront utilisés séquentiellement. Par exemple :

set service pppoe-server authentication radius server 10.0.0.1 key 'foo'
set service pppoe-server authentication radius server 10.0.0.2 key 'foo'

Note

Certains serveurs RADIUS utilisent une liste d'accès qui permet ou refuse les requêtes, assurez-vous d'ajouter votre routeur VyOS à la liste des clients autorisés.

Adresse source RADIUS

Si vous utilisez OSPF comme IGP, l'interface la plus proche connectée au serveur RADIUS est toujours utilisée. Avec VyOS 1.2, vous pouvez lier toutes les demandes sortantes RADIUS à une adresse IP source unique, par exemple l'interface boucle.

set service pppoe-server authentication radius source-address <address>

Adresse IPv4 source utilisée dans toutes les requêtes du serveur RADIUS.

Note

La source-address doit être configurée sur une interface VyOS. La pratique recommandée serait une interface boucle ou dummy.

Options avancées RADIUS

set service pppoe-server authentication radius server <server> port <port>

Configurer le serveur RADIUS <server> et son port requis pour les requêtes d'authentification.

set service pppoe-server authentication radius server <server> fail-time <time>

Marquer le serveur RADIUS comme hors ligne pendant ce temps donné <time> en secondes.

set service pppoe-server authentication radius server <server> disable

Désactiver temporairement ce serveur RADIUS.

set service pppoe-server authentication radius acct-timeout <timeout>

Délai d'attente pour répondre aux paquets Interim-Update. (défaut 3 secondes)

set service pppoe-server authentication radius dynamic-author server <address>

Spécifie l'adresse IP pour le serveur d'extension d'autorisation dynamique (DM/CoA). Cette adresse doit exister sur n'importe quelle interface VyOS ou elle peut être 0.0.0.0.

set service pppoe-server authentication radius dynamic-author port <port>

Port UDP pour le serveur d'extension d'autorisation dynamique (DM/CoA)

set service pppoe-server authentication radius dynamic-author key <secret>

Clé pour le serveur d'extension d'autorisation dynamique (DM/CoA)

set service pppoe-server authentication radius max-try <number>

Nombre maximum de tentatives pour envoyer les requêtes Access-Request/Accounting-Request

set service pppoe-server authentication radius timeout <timeout>

Délai d'attente pour attendre une réponse du serveur (secondes)

set service pppoe-server authentication radius nas-identifier <identifier>

Valeur à envoyer au serveur RADIUS dans l'attribut NAS-Identifier et à correspondre dans les requêtes DM/CoA.

set service pppoe-server authentication radius nas-ip-address <address>

Valeur à envoyer au serveur RADIUS dans l'attribut NAS-IP-Address et à correspondre dans les requêtes DM/CoA. Le serveur DM/CoA s'attachera à cette adresse.

set service pppoe-server authentication radius source-address <address>

Adresse IPv4 source utilisée dans toutes les requêtes du serveur RADIUS.

set service pppoe-server authentication radius rate-limit attribute <attribute>

Spécifie quel attribut du serveur RADIUS contient les informations de limite de débit. L'attribut par défaut est Filter-Id.

Note

Si vous définissez un attribut RADIUS personnalisé, vous devez le définir sur les deux dictionnaires sur le serveur RADIUS et le client.

set service pppoe-server authentication radius rate-limit enable

Active le contrôle de débit via RADIUS.

set service pppoe-server authentication radius rate-limit vendor

Spécifie le dictionnaire fournisseur, le dictionnaire doit être dans /usr/share/accel-ppp/radius.

Les attributs RADIUS reçus ont une priorité supérieure aux paramètres définis dans la configuration CLI, se référer à l'explication ci-dessous.

Allouer des adresses IP clients par RADIUS

Si le serveur RADIUS envoie l'attribut Framed-IP-Address, cette adresse IP sera allouée au client et l'option default-pool dans la configuration CLI est ignorée.

Si le serveur RADIUS envoie l'attribut Framed-Pool, l'adresse IP sera allouée à partir d'un pool d'adresses prédéfini dont le nom correspond à la valeur de l'attribut.

Si le serveur RADIUS envoie l'attribut Stateful-IPv6-Address-Pool, l'adresse IPv6 sera allouée à partir d'un pool IPv6 prédéfini prefix dont le nom correspond à la valeur de l'attribut.

Si le serveur RADIUS envoie l'attribut Delegated-IPv6-Prefix-Pool, le préfixe de délégation IPv6 sera alloué à partir d'un pool IPv6 prédéfini delegate dont le nom correspond à la valeur de l'attribut.

Note

Stateful-IPv6-Address-Pool et Delegated-IPv6-Prefix-Pool sont définis dans le RFC6911. Si ces attributs ne sont pas définis sur votre serveur RADIUS, ajoutez un nouveau dictionnaire.

Le réseau utilisateur peut être placé dans un contexte VRF via un paquet Access-Accept RADIUS, ou changer via RADIUS CoA. Accel-VRF-Name est utilisé à ces fins. Il s'agit d'un attribut ACCEL-PPP personnalisé. Définissez-le sur votre serveur RADIUS.

Renommer les interfaces clients par RADIUS

Si le serveur RADIUS utilise l'attribut NAS-Port-Id, les tunnels PPP seront renommés.

Note

La valeur de l'attribut NAS-Port-Id doit être inférieure à 16 caractères, sinon l'interface ne sera pas renommée.

Création automatique de VLAN

set service pppoe-server interface <interface> vlan <id | range>

Les VLAN peuvent être créés par Accel-ppp en temps réel via l'utilisation d'un module noyau nommé vlan_mon, qui surveille les VLAN entrants et crée le VLAN nécessaire si nécessaire et autorisé. VyOS prend en charge l'utilisation de soit ID de VLAN ou des plages entières, les deux valeurs peuvent être définies en même temps pour une interface.

Lorsqu'elle est configurée, PPPoE créera les VLAN nécessaires lorsqu'ils sont requis. Une fois la session utilisateur annulée et le VLAN n'étant plus nécessaire, VyOS le supprimera à nouveau.

set service pppoe-server interface eth3 vlan 100
set service pppoe-server interface eth3 vlan 200
set service pppoe-server interface eth3 vlan 500-1000
set service pppoe-server interface eth3 vlan 2000-3000

Formage de bande passante

Les limites de débit peuvent être définies pour les utilisateurs locaux ou les attributs RADIUS.

Pour les utilisateurs locaux

set service pppoe-server authentication local-users username <user> rate-limit download <bandwidth>

Limite de bande passante de téléchargement en kbit/s pour <user>.

set service pppoe-server authentication local-users username <user> rate-limit upload <bandwidth>

Limite de bande passante de téléchargement en kbit/s pour <user>.

set service pppoe-server access-concentrator 'ACN'
set service pppoe-server authentication local-users username foo password 'bar'
set service pppoe-server authentication local-users username foo rate-limit download '20480'
set service pppoe-server authentication local-users username foo rate-limit upload '10240'
set service pppoe-server authentication mode 'local'
set service pppoe-server client-ip-pool IP-POOL range '10.1.1.100/24'
set service pppoe-server default-pool 'IP-POOL'
set service pppoe-server name-server '10.100.100.1'
set service pppoe-server name-server '10.100.200.1'
set service pppoe-server interface 'eth1'
set service pppoe-server gateway-address '10.1.1.2'

Une fois que l'utilisateur est connecté, la session utilisateur utilise les limites définies et peut être affichée via show pppoe-server sessions.

show pppoe-server sessions
ifname | username |     ip     |    calling-sid    | rate-limit  | state  |  uptime  | rx-bytes | tx-bytes
-------+----------+------------+-------------------+-------------+--------+----------+----------+----------
ppp0   | foo      | 10.1.1.100 | 00:53:00:ba:db:15 | 20480/10240 | active | 00:00:11 | 214 B    | 76 B

Pour les utilisateurs RADIUS

L'attribut actuel Filter-Id est utilisé par défaut et peut être configuré dans RADIUS :

Filter-Id=2000/3000 (signifie 2000Kbit down-stream rate et 3000Kbit up-stream rate)

La commande ci-dessous l'active, en supposant que la connexion RADIUS a été configurée et fonctionne.

set service pppoe-server authentication radius rate-limit enable

Utilisez cette commande pour activer le formage de bande passante via RADIUS.

D'autres attributs peuvent être utilisés, mais ils doivent être dans l'un des dictionnaires dans /usr/share/accel-ppp/radius.

Équilibrage de charge

set service pppoe-server pado-delay <number-of-ms> sessions <number-of-sessions>

Utilisez cette commande pour activer le délai des paquets PADO (PPPoE Active Discovery Offer), qui peut être utilisé comme mécanisme d'équilibrage de session avec d'autres serveurs PPPoE.

set service pppoe-server pado-delay 50 sessions '500'
set service pppoe-server pado-delay 100 sessions '1000'
set service pppoe-server pado-delay 300 sessions '3000'

Dans l'exemple ci-dessus, les premières 499 sessions se connectent sans délai. Les paquets PADO seront retardés de 50 ms pour les connexions de 500 à 999, cette astuce permet aux autres serveurs PPPoE d'envoyer des PADO plus rapidement et les clients se connecteront à d'autres serveurs. La dernière commande indique que ce serveur PPPoE ne peut servir que 3000 clients.

IPv6

set service pppoe-server ppp-options ipv6 <require | prefer | allow | deny>

Spécifie la préférence de négociation IPv6.

  • require - Exiger la négociation IPv6

  • prefer - Demander au client la négociation IPv6, ne pas échouer si il la rejette

  • allow - Négocier IPv6 uniquement si le client le demande (valeur par défaut)

  • deny - Ne pas négocier IPv6 (valeur par défaut)

set service pppoe-server client-ipv6-pool <IPv6-POOL-NAME> prefix <address> mask <number-of-bits>

Utilisez cette commande pour définir le pool d'adresses IPv6 à partir duquel un client PPPoE obtiendra un préfixe IPv6 de longueur définie (masque) pour terminer le point de terminaison PPPoE côté client. La longueur du masque peut être définie de 48 à 128 bits, la valeur par défaut est 64.

set service pppoe-server client-ipv6-pool <IPv6-POOL-NAME> delegate <address> delegation-prefix <number-of-bits>

Utilisez cette commande pour configurer la délégation de préfixe DHCPv6 (RFC3633) sur PPPoE. Vous devrez définir votre pool IPv6 et la longueur du préfixe de délégation. À partir du pool IPv6 défini, vous distribuerez des réseaux de la longueur définie (préfixe de délégation). La longueur du préfixe de délégation peut être définie de 32 à 64 bits de long.

set service pppoe-server default-ipv6-pool <IPv6-POOL-NAME>

Utilisez cette commande pour définir le nom du pool d'adresses IPv6 par défaut.

set service pppoe-server ppp-options ipv6 allow
set service pppoe-server client-ipv6-pool IPv6-POOL delegate '2001:db8:8003::/48' delegation-prefix '56'
set service pppoe-server client-ipv6-pool IPv6-POOL prefix '2001:db8:8002::/48' mask '64'
set service pppoe-server default-ipv6-pool IPv6-POOL

Options avancées IPv6

set service pppoe-server ppp-options ipv6-accept-peer-interface-id

Accepter l'identifiant d'interface du pair. Par défaut, il n'est pas défini.

set service pppoe-server ppp-options ipv6-interface-id <random | x:x:x:x>

Spécifie l'identifiant d'interface fixe ou aléatoire pour IPv6. Par défaut, il est fixe.

  • random - Identifiant d'interface aléatoire pour IPv6

  • x:x:x:x - Spécifier l'identifiant d'interface pour IPv6

set service pppoe-server ppp-options ipv6-interface-id <random | x:x:x:x>

Spécifie l'identifiant d'interface du pair pour IPv6. Par défaut, il est fixe.

  • random - Identifiant d'interface aléatoire pour IPv6

  • x:x:x:x - Spécifier l'identifiant d'interface pour IPv6

  • ipv4-addr - Calculer l'identifiant d'interface à partir de l'adresse IPv4.

  • calling-sid - Calculer l'identifiant d'interface à partir de calling-station-id.

Options avancées d'authentification

set service pppoe-server authentication local-users username <user> disable

Désactiver le compte <user>.

Attribuer une adresse IP statique au compte <user>.

Exiger que le pair s'authentifie à l'aide d'un des protocoles suivants : pap, chap, mschap, mschap-v2.

set service pppoe-server client-ip-pool <POOL-NAME> next-pool <NEXT-POOL-NAME>

Options avancées PPP

set service pppoe-server ppp-options disable-ccp

Désactiver le protocole de contrôle de compression (CCP). CCP est activé par défaut.

set service pppoe-server ppp-options interface-cache <number>

Spécifie le nombre d'interfaces à garder en cache. Cela signifie que l'interface ne sera pas détruite après la destruction de la session correspondante, mais placée dans le cache et utilisée ultérieurement pour les nouvelles sessions. Cela devrait réduire le taux de création/suppression d'interfaces au niveau du noyau. La valeur par défaut est 0.

set service pppoe-server ppp-options ipv4 <require | prefer | allow | deny>

Spécifie la préférence de négociation IPv4.

  • require - Exiger la négociation IPv4

  • prefer - Demander au client la négociation IPv4, ne pas échouer si il la rejette

  • allow - Négocier IPv4 uniquement si le client le demande (valeur par défaut)

  • deny - Ne pas négocier IPv4

set service pppoe-server ppp-options lcp-echo-failure <number>

Définit le nombre maximum <number> de demandes d'écho non répondues. Lorsque la valeur <number> est atteinte, la session sera réinitialisée. La valeur par défaut est 3.

set service pppoe-server ppp-options lcp-echo-interval <interval>

Si cette option est spécifiée et supérieure à 0, le module PPP enverra des pings LCP d'écho toutes les <interval> secondes. La valeur par défaut est 30.

set service pppoe-server ppp-options lcp-echo-timeout

Spécifie le délai en secondes pour attendre toute activité du pair. Si cette option est spécifiée, elle active la fonctionnalité d'écho LCP adaptatif et « lcp-echo-failure » n'est pas utilisé. La valeur par défaut est 0.

set service pppoe-server ppp-options min-mtu <number>

Définit la MTU minimale acceptable. Si le client tente de négocier une MTU inférieure à celle spécifiée, elle sera NAKée ou déconnectée si elle rejette une MTU plus grande. La valeur par défaut est 100.

set service pppoe-server ppp-options mppe <require | prefer | deny>

Spécifie la préférence de négociation MPPE.

  • require - demander au client MPPE, si il le rejette, la connexion est coupée

  • prefer - demander au client MPPE, si il le rejette, ne pas échouer. (valeur par défaut)

  • deny - refuser MPPE

Comportement par défaut - ne pas demander au client MPPE, mais permettre s'il veut. Veuillez noter que RADIUS peut remplacer cette option par l'attribut MS-MPPE-Encryption-Policy.

set service pppoe-server ppp-options mru <number>

Définit la MRU préférée. Par défaut, elle n'est pas définie.

Options avancées globales

set service pppoe-server description <description>

Définir la description.

set service pppoe-server limits burst <value>

Nombre de pics

set service pppoe-server limits connection-limit <value>

Rate d'acceptation des connexions (par exemple 1/min, 60/sec)

set service pppoe-server limits timeout <value>

Délai en secondes

set service pppoe-server mtu

Unité de transmission maximale (MTU) (valeur par défaut : 1492)

set service pppoe-server max-concurrent-sessions

Nombre maximum de tentatives de démarrage de sessions concurrentes

set service pppoe-server name-server <address>

Le client connecté devrait utiliser <address> comme serveur DNS. Cette commande accepte les adresses IPv4 et IPv6. Jusqu'à deux serveurs DNS peuvent être configurés pour IPv4, jusqu'à trois pour IPv6.

set service pppoe-server service-name <names>

Spécifie le Service-Name à répondre. Si absent, tout Service-Name est acceptable et le Service-Name du client sera envoyé en retour. Il est également possible de définir plusieurs service-names : sn1,sn2,sn3

Par défaut, la session utilisateur est remplacée si une deuxième requête d'authentification réussit. Ces requêtes de session peuvent être soit refusées ou autorisées entièrement, ce qui permettra à plusieurs sessions pour un utilisateur dans le dernier cas. Si elle est refusée, la deuxième session est rejetée même si l'authentification réussit, l'utilisateur doit terminer sa première session et puis peut s'authentifier à nouveau.

set service pppoe-server session-control

  • disable: Désactive le contrôle de session.

  • deny: Refuse l'autorisation de la deuxième session.

  • replace: Termine la première session lorsqu'une deuxième est autorisée (valeur par défaut)

set service pppoe-server shaper fwmark <1-2147483647>

Valeur de marqueur de pare-feu à matcher

set service pppoe-server snmp master-agent

Activer SNMP

set service pppoe-server wins-server <address>

Serveurs Windows Internet Name Service (WINS) propagés au client

Exemples

IPv4

L'exemple ci-dessous utilise ACN comme nom de concentrateur, attribue une adresse depuis le pool 10.1.1.100-111, termine à l'extrémité locale 10.1.1.1 et sert les requêtes uniquement sur eth1.

set service pppoe-server access-concentrator 'ACN'
set service pppoe-server authentication local-users username foo password 'bar'
set service pppoe-server authentication mode 'local'
set service pppoe-server client-ip-pool IP-POOL range '10.1.1.100-10.1.1.111'
set service pppoe-server default-pool 'IP-POOL'
set service pppoe-server interface eth1
set service pppoe-server gateway-address '10.1.1.2'
set service pppoe-server name-server '10.100.100.1'
set service pppoe-server name-server '10.100.200.1'

Provisionnement dual-stack IPv4/IPv6 avec délégation de préfixe

L'exemple ci-dessous couvre une configuration dual-stack.

set service pppoe-server authentication local-users username test password 'test'
set service pppoe-server authentication mode 'local'
set service pppoe-server client-ip-pool IP-POOL range '192.168.0.1/24'
set service pppoe-server default-pool 'IP-POOL'
set service pppoe-server client-ipv6-pool IPv6-POOL delegate '2001:db8:8003::/48' delegation-prefix '56'
set service pppoe-server client-ipv6-pool IPV6-POOL prefix '2001:db8:8002::/48' mask '64'
set service pppoe-server default-ipv6-pool IPv6-POOL
set service pppoe-server ppp-options ipv6 allow
set service pppoe-server name-server '10.1.1.1'
set service pppoe-server name-server '2001:db8:4860::8888'
set service pppoe-server interface 'eth2'
set service pppoe-server gateway-address '10.100.100.1'

Une fois authentifié avec succès, le client recevra une adresse IPv4 et une adresse IPv6 /64 pour terminer le point de terminaison PPPoE côté client et un préfixe /56 pour l'utilisation interne des clients.

vyos@pppoe-server:~$ sh pppoe-server sessions
 ifname | username |     ip      |            ip6           |       ip6-dp        |    calling-sid    | rate-limit | state  |  uptime  | rx-bytes | tx-bytes
--------+----------+-------------+--------------------------+---------------------+-------------------+------------+--------+----------+----------+----------
 ppp0   | test     | 192.168.0.1 | 2001:db8:8002:0:200::/64 | 2001:db8:8003::1/56 | 00:53:00:12:42:eb |            | active | 00:00:49 | 875 B    | 2.1 KiB
