Webproxy

Le service de proxy dans VyOS est basé sur Squid et quelques modules associés.

Squid est un proxy web de cache et de transfert HTTP. Il a une grande variété d'usages, notamment pour accélérer un serveur web en stockant les requêtes répétées, pour le cache des recherches web, DNS et autres ressources réseau pour un groupe de personnes partageant des ressources réseau, et pour aider la sécurité en filtrant le trafic. Bien qu'il soit principalement utilisé pour HTTP et FTP, Squid inclut un support limité pour plusieurs autres protocoles, y compris Internet Gopher, SSL,[6] TLS et HTTPS. Squid ne prend pas en charge le protocole SOCKS.

Le filtrage des URL est fourni par SquidGuard.

Configuration

set service webproxy append-domain <domain>

Utilisez cette commande pour spécifier un nom de domaine à ajouter aux noms de domaines dans les URLs qui n'incluent pas un point . le domaine est ajouté.

Exemple : si le domaine à ajouter est défini sur vyos.net et que l'URL reçue est www/foo.html, le système utilisera l'URL finale générée de www.vyos.net/foo.html.

set service webproxy append-domain vyos.net
set service webproxy cache-size <size>

La taille du cache sur disque du proxy est configurable par l'utilisateur. La taille par défaut du cache du proxy est configurée à 100 Mo.

L'unité de cette commande est en Mo.

set service webproxy cache-size 1024
set service webproxy default-port <port>

Spécifie le port utilisé sur lequel le service de proxy écoute les demandes. Ce port est le port par défaut utilisé pour l'adresse d'écoute spécifiée.

Le port par défaut est 3128.

set service webproxy default-port 8080
set service webproxy domain-block <domain>

Utilisé pour bloquer des domaines spécifiques par le Proxy. Spécifier « vyos.net » bloquera tout l'accès à vyos.net, et spécifier « .xxx » bloquera tout l'accès aux URLs ayant une fin .xxx.

set service webproxy domain-block vyos.net
set service webproxy domain-noncache <domain>

Permet l'accès aux sites d'un domaine sans les récupérer depuis le cache du proxy. Spécifier « vyos.net » permettra l'accès à vyos.net mais les pages consultées ne seront pas mises en cache. Cela est utile pour contourner les problèmes avec le contrôle « If-Modified-Since » sur certains sites.

set service webproxy domain-noncache vyos.net
set service webproxy listen-address <address>

Spécifie l'adresse d'écoute du service de proxy. L'adresse d'écoute est l'adresse IP sur laquelle le service de proxy web écoute les requêtes clients.

Pour des raisons de sécurité, l'adresse d'écoute doit être utilisée uniquement sur des réseaux internes/validés !

set service webproxy listen-address 192.0.2.1
set service webproxy listen-address <address> disable-transparent

Désactive le mode transparent du proxy web à une adresse d'écoute.

En mode transparent, tout le trafic arrivant sur le port 80 et destiné à Internet est automatiquement redirigé via le proxy. Cela permet une redirection immédiate du proxy sans configurer les navigateurs clients.

Le proxy non transparent nécessite que les navigateurs clients soient configurés avec les paramètres de proxy avant que les requêtes ne soient redirigées. L'avantage de cela est que le navigateur web client peut détecter qu'un proxy est en cours d'utilisation et se comporter en conséquence. De plus, le malware transmis via le web peut parfois être bloqué par un proxy web non transparent, car ils ne sont pas conscients des paramètres de proxy.

set service webproxy listen-address 192.0.2.1 disable-transparent
set service webproxy listen-address <address> port <port>

Définit le port d'écoute pour une adresse d'écoute. Cela remplace le port par défaut de 3128 sur l'adresse d'écoute spécifique.

set service webproxy listen-address 192.0.2.1 port 8080
set service webproxy reply-block-mime <mime>

Utilisé pour bloquer un type mime spécifique.

# bloquer tous les PDFs
set service webproxy reply-block-mime application/pdf
set service webproxy reply-body-max-size <size>

Spécifie la taille maximale d'un corps de réponse en KB, utilisée pour limiter la taille de la réponse.

Toutes les tailles de réponse sont acceptées par défaut.

set service webproxy reply-body-max-size 2048
set service webproxy safe-ports <port>

Ajoute un nouveau port à l'acl Safe-ports. Ports inclus par défaut dans l'acl Safe-ports : 21, 70, 80, 210, 280, 443, 488, 591, 777, 873, 1025-65535

set service webproxy ssl-safe-ports <port>

Ajoute un nouveau port à l'acl SSL-ports. Ports inclus par défaut dans l'acl SSL-ports : 443

Authentification

Le proxy Squid intégré peut utiliser LDAP pour authentifier les utilisateurs contre un annuaire d'entreprise. La configuration suivante est un exemple de la manière d'utiliser Active Directory comme backend d'authentification. Les requêtes sont effectuées via LDAP.

set service webproxy authentication children <number>

Nombre maximum de processus d'authentification à lancer. Si vous en lancez trop peu, Squid devra attendre qu'ils traitent une liste d'attente de vérifications de crédentials, ce qui ralentira le processus. Quand les vérifications de mot de passe sont effectuées via un réseau (lent), vous aurez probablement besoin de nombreux processus d'authentification.

Cela est par défaut à 5.

set service webproxy authentication children 10
set service webproxy authentication credentials-ttl <time>

Spécifie pendant combien de temps Squid suppose qu'une paire utilisateur/mot de passe validée externement est valide - autrement dit, à quelle fréquence le programme d'aide est appelé pour cet utilisateur. Définissez-le faible pour forcer une nouvelle validation avec des mots de passe à courte durée de vie.

Le temps est en minutes et par défaut à 60.

set service webproxy authentication credentials-ttl 120
set service webproxy authentication method <ldap>

Méthode d'authentification du proxy, actuellement seul LDAP est pris en charge.

set service webproxy authentication method ldap
set service webproxy authentication realm

Spécifie la portée de protection (nom de domaine) qui est rapportée au client pour le schéma d'authentification. C'est généralement partie du texte que l'utilisateur verra lorsqu'on lui demandera son nom d'utilisateur et son mot de passe.

set service webproxy authentication realm "VyOS proxy auth"

LDAP

set service webproxy authentication ldap base-dn <base-dn>

Spécifie le DN de base sous lequel les utilisateurs se trouvent.

set service webproxy authentication ldap base-dn DC=vyos,DC=net
set service webproxy authentication ldap bind-dn <bind-dn>

Le DN et le mot de passe pour se connecter pendant les recherches.

set service webproxy authentication ldap bind-dn CN=proxyuser,CN=Users,DC=vyos,DC=net
set service webproxy authentication ldap filter-expression <expr>

Filtre de recherche LDAP pour localiser le DN utilisateur. Requis si les utilisateurs sont dans une hiérarchie en dessous du DN de base, ou si le nom d'utilisateur n'est pas ce qui construit la partie spécifique de DN des utilisateurs.

Le filtre de recherche peut contenir jusqu'à 15 occurrences de %s qui seront remplacées par le nom d'utilisateur, comme dans « uid=%s » pour RFC 2037 des répertoires. Pour une description détaillée de la syntaxe du filtre de recherche LDAP, voir RFC 2254.

set service webproxy authentication ldap filter-expression (cn=%s)
set service webproxy authentication ldap password <password>

Le DN et le mot de passe pour se connecter pendant les recherches. Comme le mot de passe doit être imprimé en clair dans votre configuration Squid, il est fortement recommandé d'utiliser un compte avec des privilèges minimaux. Cela limite les dommages en cas où quelqu'un pourrait obtenir une copie de votre fichier de configuration Squid.

set service webproxy authentication ldap password vyos
set service webproxy authentication ldap persistent-connection

Utilise une connexion LDAP persistante. Normalement, la connexion LDAP n'est ouverte que pendant la validation d'un nom d'utilisateur afin de préserver les ressources du serveur LDAP. Cette option fait en sorte que la connexion LDAP reste ouverte, permettant ainsi de la réutiliser pour d'autres validations d'utilisateurs.

Recommandé pour les installations plus importantes.

set service webproxy authentication ldap persistent-connection
set service webproxy authentication ldap port <port>

Spécifie un port TCP alternatif où le serveur LDAP écoute s'il n'est pas le port LDAP par défaut 389.

set service webproxy authentication ldap port 389
set service webproxy authentication ldap server <server>

Spécifie le serveur LDAP auquel se connecter.

set service webproxy authentication ldap server ldap.vyos.net
set service webproxy authentication ldap use-ssl

Utilise l'encryption TLS.

set service webproxy authentication ldap use-ssl
set service webproxy authentication ldap username-attribute <attr>

Spécifie le nom de l'attribut DN qui contient le nom d'utilisateur/connexion. Combiné avec le DN de base pour construire le DN des utilisateurs lorsqu'aucun filtre de recherche n'est spécifié (filter-expression).

Par défaut, c'est 'uid'

Note

Cela ne peut être fait que si tous vos utilisateurs se trouvent directement sous la même position dans l'arbre LDAP et que le nom d'utilisateur est utilisé pour nommer chaque objet utilisateur. Si votre arbre LDAP ne correspond pas à ces critères ou si vous souhaitez filtrer qui sont les utilisateurs valides, vous devez utiliser un filtre de recherche pour chercher le DN des utilisateurs (filter-expression).

set service webproxy authentication ldap username-attribute uid
set service webproxy authentication ldap version <2 | 3>

Version du protocole LDAP. Par défaut, c'est 3 si non spécifié.

set service webproxy authentication ldap version 2

Certaines services ne fonctionnent pas correctement lorsqu'ils sont gérés via un proxy web. Parfois, il est utile de contourner un proxy transparent :

  • Pour contourner le proxy pour chaque demande dirigée vers une destination spécifique :

    set service webproxy whitelist destination-address 198.51.100.33

    set service webproxy whitelist destination-address 192.0.2.0/24

  • Pour contourner le proxy pour chaque demande provenant d'une source spécifique :

    set service webproxy whitelist source-address 192.168.1.2

    set service webproxy whitelist source-address 192.168.2.0/24

    (Cela peut être utile lorsque un service appelé a de nombreuses adresses de destination et/ou souvent changeantes - par exemple Netflix.)

Exemples

vyos@vyos# show service webproxy
 authentication {
     children 5
     credentials-ttl 60
     ldap {
         base-dn DC=example,DC=local
         bind-dn CN=proxyuser,CN=Users,DC=example,DC=local
         filter-expression (cn=%s)
         password Qwert1234
         server ldap.example.local
         username-attribute cn
     }
     method ldap
     realm "VyOS Webproxy"
 }
 cache-size 100
 default-port 3128
 listen-address 192.168.188.103 {
     disable-transparent
 }
