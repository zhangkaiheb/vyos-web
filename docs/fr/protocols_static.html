Statique

Les routes statiques sont des entrées configurées manuellement dans la base d'information de routage (RIB) du routeur qui définissent comment le trafic doit atteindre des destinations spécifiques. Contrairement aux protocoles de routage dynamique, les routes statiques ne sont pas mises à jour automatiquement lorsque la topologie réseau change.

Les routes statiques conviennent mieux aux topologies réseau simples ou pour remplacer le comportement des protocoles de routage dynamique pour un petit nombre de routes.

La RIB stocke toutes les informations de routage, y compris les routes statiques configurées manuellement et les routes apprises dynamiquement. À partir de la RIB, le routeur dérive les routes unicast pour construire la FIB.

Routes unicast IPv4

Les routes unicast IPv4 dirigent le trafic destiné à un seul hôte IPv4 ou sous-réseau vers un prochain saut spécifique. Utilisez les commandes suivantes pour configurer les routes unicast IPv4 pour un sous-réseau distant spécifique.

set protocols static route <subnet> next-hop <address>

Configurez l'adresse IP du prochain saut pour le sous-réseau spécifié.

Vous pouvez configurer plusieurs adresses IP de prochain saut pour le même sous-réseau destinataire.

Exemple :

set protocols static route 192.0.2.0/24 next-hop 10.0.0.254
set protocols static route <subnet> next-hop <address> disable

Désactivez la route via l'adresse IP du prochain saut spécifiée.

Cette commande désactive temporairement la route tout en préservant les paramètres de sous-réseau, d'adresse de prochain saut et de distance configurés.

Exemple :

set protocols static route 192.0.2.0/24 next-hop 10.0.0.254 disable
set protocols static route <subnet> next-hop <address> distance <distance>

Configurez la distance administrative pour la route via l'adresse IP du prochain saut spécifiée.

Les routes avec une distance administrative plus faible sont prioritaires par rapport aux routes avec une distance plus élevée.

La plage autorisée est de 1 à 255. La distance par défaut est de 1.

Remarque

Les routes avec une distance de 255 sont désactivées et ne sont pas utilisées pour le transfert de paquets.

Exemple :

set protocols static route 192.0.2.0/24 next-hop 10.0.0.254 distance 10

Cette commande désactive temporairement la route tout en préservant les paramètres de sous-réseau, d'interface et de distance configurés.

Exemple :

set protocols static route 192.0.2.0/24 interface eth0 disable
set protocols static route <subnet> interface <interface> distance <distance>

Configurez la distance administrative pour la route via l'interface de prochain saut spécifiée.

Les routes avec une distance administrative plus faible sont prioritaires par rapport aux routes avec une distance plus élevée.

La plage autorisée est de 1 à 255. La distance par défaut est de 1.

Exemple :

set protocols static route 192.0.2.0/24 interface eth0 distance 10

IPv4 BFD

BFD surveille la disponibilité de l'adresse IP du prochain saut d'une route statique. Utilisez les commandes suivantes pour configurer les paramètres BFD pour vos routes statiques IPv4.

set protocols static route <subnet> next-hop <address> bfd

Activez la surveillance BFD pour la route via l'adresse IP du prochain saut spécifiée.

Le système utilise l'adresse IP du prochain saut comme destination du pair BFD.

Exemple :

set protocols static route 192.0.2.0/24 next-hop 10.0.0.254 bfd
set protocols static route <subnet> next-hop <address> bfd profile <profile>

Appliquez les paramètres d'un profil BFD désigné à la session BFD qui surveille l'adresse IP du prochain saut spécifiée.

Exemple :

set protocols static route 192.0.2.0/24 next-hop 10.0.0.254 bfd profile custom-profile
set protocols static route <subnet> next-hop <address> bfd multi-hop source-address <source-address>

Activez une session BFD à plusieurs sauts pour surveiller la disponibilité de l'adresse IP du prochain saut spécifiée.

Le système lance la session BFD à partir de l'adresse IPv4 source locale spécifiée.

Exemple :

set protocols static route 192.0.2.0/24 next-hop 10.0.0.254 bfd multi-hop source-address 172.16.1.1

Routes d'interface DHCP

Les routes d'interface DHCP dirigent le trafic destiné à un seul hôte IPv4 ou sous-réseau vers une passerelle obtenue à partir d'une interface DHCP. Utilisez la commande suivante pour configurer les routes d'interface DHCP.

set protocols static route <subnet> dhcp-interface <interface>

Configurez une route statique qui obtient son adresse IP de prochain saut à partir de l'interface DHCP spécifiée.

Exemple :

set protocols static route 192.0.2.0/24 dhcp-interface eth0

Routes IPv4 rejetées

Les routes IPv4 rejetées suppriment explicitement le trafic destiné à un seul hôte IPv4 ou sous-réseau et renvoient un message ICMP indiquant qu'il n'est pas accessible au dispositif émetteur. Utilisez les commandes suivantes pour configurer les routes IPv4 rejetées.

set protocols static route <subnet> reject

Configurez une route de rejet pour le sous-réseau spécifié.

Le système supprime le trafic destiné à ce sous-réseau et renvoie un message ICMP indiquant que la destination n'est pas accessible au dispositif émetteur.

Exemple :

set protocols static route 192.0.2.0/24 reject
set protocols static route <subnet> reject distance <distance>

Configurez la distance administrative pour la route de rejet.

Les routes avec une distance administrative plus faible sont prioritaires par rapport aux routes avec une distance plus élevée.

La plage autorisée est de 1 à 255.

Exemple :

set protocols static route 192.0.2.0/24 reject distance 200
set protocols static route <subnet> reject tag <tag>

Configurez une balise numérique pour la route de rejet.

La plage autorisée est de 1 à 4294967295.

Exemple :

set protocols static route 192.0.2.0/24 reject tag 100

Routes IPv4 vers le néant

Les routes vers le néant suppriment silencieusement le trafic destiné à un sous-réseau spécifique. Contrairement à une route de rejet, qui informe l'expéditeur avec un message ICMP indiquant que la destination n'est pas accessible, une route vers le néant jette les paquets sans générer aucune réponse.

set protocols static route <subnet> blackhole

Configurez une route vers le néant pour le sous-réseau spécifié.

Le système supprime silencieusement les paquets correspondants sans envoyer de réponse ICMP au source.

Exemple :

set protocols static route 10.0.0.0/8 blackhole
set protocols static route <subnet> blackhole distance <distance>

Configurez la distance administrative pour la route vers le néant.

Les routes avec une distance administrative plus faible sont prioritaires par rapport aux routes avec une distance plus élevée.

La plage autorisée est de 1 à 255.

Exemple :

set protocols static route 10.0.0.0/8 blackhole distance 200
set protocols static route <subnet> blackhole tag <tag>

Configurez une balise numérique pour la route vers le néant.

La plage autorisée est de 1 à 4294967295.

Exemple :

set protocols static route 10.0.0.0/8 blackhole tag 100

Exemple :

set protocols static route6 <subnet> next-hop <address> disable

Désactivez la route via l'adresse IPv6 du prochain saut spécifiée.

Cette commande désactive temporairement la route tout en préservant les paramètres de sous-réseau, d'adresse de prochain saut et de distance configurés.

Configurez la distance administrative pour la route via l'adresse IPv6 du prochain saut spécifiée.

Les routes avec une distance administrative plus faible sont prioritaires par rapport aux routes avec une distance plus élevée.

La plage autorisée est de 1 à 255. La distance par défaut est de 1.

Note

Les routes avec une distance de 255 sont désactivées et ne sont pas utilisées pour le transfert de paquets.

Exemple :

set protocols static route6 2001:db8:1::/64 next-hop 2001:db8:100::1 distance 10
set protocols static route6 <subnet> next-hop <address> segments <segments>

Configurez une route unicast IPv6 qui utilise le routage par segment sur IPv6 (SRv6) pour atteindre le sous-réseau de destination.

Utilisez une barre oblique (/) pour séparer plusieurs identifiants de segment IPv6 (SID) dans votre séquence.

Exemple :

set protocols static route6 2001:db8:1000::/36 next-hop 2001:db8:201::ffff segments '2001:db8:aaaa::7/2002::4/2002::3/2002::2'
