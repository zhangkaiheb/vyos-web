Configuration du pare-feu de pont

Aperçu

Découvrez-en plus sur la configuration du pare-feu de pont et les commandes op-mode associées.

Les commandes suivantes sont abordées dans cette section :

set firewall bridge <options>

À partir de la structure principale définie dans Aperçu du pare-feu dans cette section, vous pouvez trouver des informations détaillées uniquement pour la prochaine partie de la structure générale :

- set firewall

Le trafic reçu par le routeur sur une interface qui est membre d'un pont est traité sur le Niveau Pont. Avant que la décision du pont ne soit prise, tous les paquets sont analysés au Prerouting. Des filtres peuvent être appliqués ici, ainsi que des règles pour ignorer le système de suivi des connexions.

  • set firewall bridge prerouting filter ....

Pour le trafic qui doit être commuté internement par le pont, la chaîne de base est forward, et sa commande de base pour le filtrage est set firewall bridge forward filter ..., qui se produit à l'étape 4, surlignée en rouge.

Pour le trafic destiné au routeur lui-même ou qui doit être routé (à supposer qu'un pont de couche 3 soit configuré), la chaîne de base est input, et la commande de base est set firewall bridge input filter ... et le chemin est :

Si ce n'est pas supprimé, le paquet est envoyé au Niveau IP, et sera traité par le pare-feu du Niveau IP : ensemble de règles IPv4 ou IPv6. Vérifiez à nouveau le diagramme du flux de paquet général si nécessaire.

Pour le trafic provenant du pont lui-même, la chaîne de base est output, et la commande de base est set firewall bridge output filter ..., et le chemin est :

Des chaînes de pare-feu de pont personnalisées peuvent être créées avec la commande set firewall bridge name <name> .... Pour utiliser une telle chaîne personnalisée, une règle avec une action jump et la cible appropriée doit être définie dans une chaîne de base.

Règles de pont

Pour le filtrage du pare-feu, des règles de pare-feu doivent être créées. Chaque règle est numérotée, a une action à appliquer si la règle est matchée, et la possibilité de spécifier plusieurs critères de correspondance. Les paquets passent par les règles de 1 à 999999, donc l'ordre est crucial. À la première correspondance, l'action de la règle sera exécutée.

Actions

Si une règle est définie, une action doit également être définie pour celle-ci. Cela indique au pare-feu quoi faire si tous les critères de correspondance de la règle sont remplis.

Dans les règles de pare-feu de pont, l'action peut être :

  • accept : accepter le paquet.

  • continue : continuer à analyser la règle suivante.

  • drop : supprimer le paquet.

  • jump : passer à une autre chaîne personnalisée.

  • return : retourner depuis la chaîne actuelle et continuer à la règle suivante de la dernière chaîne.

  • queue : mettre en file d'attente le paquet vers l'espace utilisateur.

  • notrack : ignorer le système de suivi des connexions. Cette action est disponible uniquement dans la chaîne prerouting.

set firewall bridge forward filter rule <1-999999> action [accept | continue | drop | jump | queue | return]
set firewall bridge input filter rule <1-999999> action [accept | continue | drop | jump | queue | return]
set firewall bridge output filter rule <1-999999> action [accept | continue | drop | jump | queue | return]
set firewall bridge prerouting filter rule <1-999999> action [accept | continue | drop | jump | notrack | queue | return]
set firewall bridge name <name> rule <1-999999> action [accept | continue | drop | jump | queue | return]

Cette configuration requise définit l'action de la règle actuelle. Si l'action est définie sur jump, alors jump-target est également nécessaire.

set firewall bridge forward filter rule <1-999999> jump-target <text>
set firewall bridge input filter rule <1-999999> jump-target <text>
set firewall bridge output filter rule <1-999999> jump-target <text>
set firewall bridge prerouting filter rule <1-999999> jump-target <text>
set firewall bridge name <name> rule <1-999999> jump-target <text>

Si l'action est définie sur queue, utilisez la commande suivante pour spécifier la cible de la file d'attente. La plage est également prise en charge :

set firewall bridge forward filter rule <1-999999> queue <0-65535>
set firewall bridge input filter rule <1-999999> queue <0-65535>
set firewall bridge output filter rule <1-999999> queue <0-65535>
set firewall bridge prerouting filter rule <1-999999> queue <0-65535>
set firewall bridge name <name> rule <1-999999> queue <0-65535>

De plus, si l'action est définie sur queue, utilisez la commande suivante pour spécifier la file d'attente options. Les options possibles sont bypass et fanout :

set firewall bridge forward filter rule <1-999999> queue-options bypass
set firewall bridge input filter rule <1-999999> queue-options bypass
set firewall bridge output filter rule <1-999999> queue-options bypass
set firewall bridge prerouting filter rule <1-999999> queue-options bypass
set firewall bridge name <name> rule <1-999999> queue-options bypass
set firewall bridge forward filter rule <1-999999> queue-options fanout
set firewall bridge input filter rule <1-999999> queue-options fanout
set firewall bridge output filter rule <1-999999> queue-options fanout
set firewall bridge prerouting filter rule <1-999999> queue-options fanout
set firewall bridge name <name> rule <1-999999> queue-options fanout

De plus, default-action est une action qui s'exécute lorsque un paquet ne correspond à aucune règle dans sa chaîne. Pour les chaînes de base, les options possibles pour default-action sont accept ou drop.

set firewall bridge forward filter default-action [accept | drop]
set firewall bridge input filter default-action [accept | drop]
set firewall bridge output filter default-action [accept | drop]
set firewall bridge prerouting filter default-action [accept | drop]
set firewall bridge name <name> default-action [accept | continue | drop | jump | reject | return]

Cela définit l'action par défaut de l'ensemble de règles si un paquet ne correspond à aucune des règles de cette chaîne. Si default-action est défini sur jump, alors default-jump-target est également nécessaire. Notez que pour les chaînes de base, l'action par défaut ne peut être définie que sur accept ou drop, tandis que sur les chaînes personnalisées, davantage d'actions sont disponibles.

set firewall bridge name <name> default-jump-target <text>

À utiliser uniquement lorsqu'default-action est défini sur jump. Utilisez cette commande pour spécifier la cible de saut pour la règle par défaut.

Note

Remarque importante sur les actions par défaut : Si l'action par défaut pour toute chaîne de base n'est pas définie, alors l'action par défaut est définie sur accept pour cette chaîne. Pour les chaînes personnalisées, si l'action par défaut n'est pas définie, alors l'action par défaut est définie sur drop.

Journaux du pare-feu

Vous pouvez activer le journalisation pour chaque règle du pare-feu. Si activé, d'autres options de journalisation peuvent être configurées.

set firewall bridge forward filter rule <1-999999> log
set firewall bridge input filter rule <1-999999> log
set firewall bridge output filter rule <1-999999> log
set firewall bridge prerouting filter rule <1-999999> log
set firewall bridge name <name> rule <1-999999> log

Activez la journalisation du paquet correspondant. Si cette commande de configuration n'est pas présente, alors le journal n'est pas activé.

set firewall bridge forward filter default-log
set firewall bridge input filter default-log
set firewall bridge output filter default-log
set firewall bridge prerouting filter default-log
set firewall bridge name <name> default-log

Utilisez cette commande pour activer la journalisation de l'action par défaut sur la chaîne spécifiée.

set firewall bridge forward filter rule <1-999999> log-options level [emerg | alert | crit | err | warn | notice | info | debug]
set firewall bridge input filter rule <1-999999> log-options level [emerg | alert | crit | err | warn | notice | info | debug]
set firewall bridge output filter rule <1-999999> log-options level [emerg | alert | crit | err | warn | notice | info | debug]
set firewall bridge prerouting filter rule <1-999999> log-options level [emerg | alert | crit | err | warn | notice | info | debug]
set firewall bridge name <name> rule <1-999999> log-options level [emerg | alert | crit | err | warn | notice | info | debug]

Définir le niveau de journalisation. N'applicable que si la règle log est activée.

set firewall bridge forward filter rule <1-999999> log-options group <0-65535>
set firewall bridge input filter rule <1-999999> log-options group <0-65535>
set firewall bridge output filter rule <1-999999> log-options group <0-65535>
set firewall bridge prerouting filter rule <1-999999> log-options group <0-65535>
set firewall bridge name <name> rule <1-999999> log-options group <0-65535>

Définir le groupe de journalisation à envoyer aux messages. N'applicable que si la règle log est activée.

set firewall bridge forward filter rule <1-999999> log-options snapshot-length <0-9000>
set firewall bridge input filter rule <1-999999> log-options snapshot-length <0-9000>
set firewall bridge output filter rule <1-999999> log-options snapshot-length <0-9000>
set firewall bridge prerouting filter rule <1-999999> log-options snapshot-length <0-9000>
set firewall bridge name <name> rule <1-999999> log-options snapshot-length <0-9000>

Définir la longueur du payload du paquet à inclure dans le message netlink. N'est applicable que si la règle log est activée et que le groupe de journalisation est défini.

set firewall bridge forward filter rule <1-999999> log-options queue-threshold <0-65535>
set firewall bridge input filter rule <1-999999> log-options queue-threshold <0-65535>
set firewall bridge output filter rule <1-999999> log-options queue-threshold <0-65535>
set firewall bridge prerouting filter rule <1-999999> log-options queue-threshold <0-65535>
set firewall bridge name <name> rule <1-999999> log-options queue-threshold <0-65535>

Définir le nombre de paquets à mettre en file d'attente dans le noyau avant de les envoyer à l'espace utilisateur. N'est applicable que si la règle log est activée et que le groupe de journalisation est défini.

Description du pare-feu

Vous pouvez définir une description pour référence pour chaque chaîne personnalisée.

set firewall bridge name <name> description <text>

Fournir une description de l'ensemble de règles à une chaîne de pare-feu personnalisée.

set firewall bridge forward filter rule <1-999999> description <text>
set firewall bridge input filter rule <1-999999> description <text>
set firewall bridge output filter rule <1-999999> description <text>
set firewall bridge prerouting filter rule <1-999999> description <text>
set firewall bridge name <name> rule <1-999999> description <text>

Fournir une description pour chaque règle.

Statut de la règle

Par défaut, lorsqu'une règle est définie, elle est activée. Dans certains cas, il est utile de désactiver la règle au lieu de la supprimer.

set firewall bridge forward filter rule <1-999999> disable
set firewall bridge input filter rule <1-999999> disable
set firewall bridge output filter rule <1-999999> disable
set firewall bridge prerouting filter rule <1-999999> disable
set firewall bridge name <name> rule <1-999999> disable

Commande pour désactiver une règle mais la garder dans la configuration.

Critères de correspondance

Il existe de nombreux critères de correspondance contre lesquels un paquet peut être testé. Se référer à IPv4 et IPv6 pour plus de détails.

Comme les ponts fonctionnent au niveau 2, les deux matchers pour IPv4 et IPv6 sont pris en charge dans la configuration du pare-feu de pont. La même chose s'applique aux groupes de pare-feu.

Les critères de correspondance spécifiques qui peuvent être utilisés dans le pare-feu de pont sont décrits dans cette section :

set firewall bridge forward filter rule <1-999999> ethernet-type [802.1q | 802.1ad | arp | ipv4 | ipv6]
set firewall bridge input filter rule <1-999999> ethernet-type [802.1q | 802.1ad | arp | ipv4 | ipv6]
set firewall bridge output filter rule <1-999999> ethernet-type [802.1q | 802.1ad | arp | ipv4 | ipv6]
set firewall bridge prerouting filter rule <1-999999> ethernet-type [802.1q | 802.1ad | arp | ipv4 | ipv6]
set firewall bridge name <name> rule <1-999999> ethernet-type [802.1q | 802.1ad | arp | ipv4 | ipv6]

Correspondre en fonction du type Ethernet du paquet.

set firewall bridge forward filter rule <1-999999> vlan ethernet-type [802.1q | 802.1ad | arp | ipv4 | ipv6]
set firewall bridge input filter rule <1-999999> vlan ethernet-type [802.1q | 802.1ad | arp | ipv4 | ipv6]
set firewall bridge output filter rule <1-999999> vlan ethernet-type [802.1q | 802.1ad | arp | ipv4 | ipv6]
set firewall bridge prerouting filter rule <1-999999> vlan ethernet-type [802.1q | 802.1ad | arp | ipv4 | ipv6]
set firewall bridge name <name> rule <1-999999> vlan ethernet-type [802.1q | 802.1ad | arp | ipv4 | ipv6]

Correspondre en fonction du type Ethernet du paquet lorsqu'il est étiqueté VLAN.

set firewall bridge forward filter rule <1-999999> vlan id <0-4096>
set firewall bridge input filter rule <1-999999> vlan id <0-4096>
set firewall bridge output filter rule <1-999999> vlan id <0-4096>
set firewall bridge prerouting filter rule <1-999999> vlan id <0-4096>
set firewall bridge name <name> rule <1-999999> vlan id <0-4096>

Correspondre en fonction de l'identifiant VLAN. La plage est également prise en charge.

set firewall bridge forward filter rule <1-999999> vlan priority <0-7>
set firewall bridge input filter rule <1-999999> vlan priority <0-7>
set firewall bridge output filter rule <1-999999> vlan priority <0-7>
set firewall bridge prerouting filter rule <1-999999> vlan priority <0-7>
set firewall bridge name <name> rule <1-999999> vlan priority <0-7>

Correspondre en fonction de la priorité VLAN (Code Point de Priorité - PCP). La plage est également prise en charge.

Modifications des paquets

À partir de VyOS-1.5-rolling-202410060007, le pare-feu peut modifier les paquets avant qu'ils ne soient envoyés. Cette fonctionnalité offre plus de flexibilité dans la gestion des paquets.

set firewall bridge [prerouting | forward | output] filter rule <1-999999> set dscp <0-63>

Définir une valeur spécifique du Differentiated Services Codepoint (DSCP).

set firewall bridge [prerouting | forward | output] filter rule <1-999999> set mark <1-2147483647>

Définir une valeur spécifique de marque de paquet.

set firewall bridge [prerouting | forward | output] filter rule <1-999999> set tcp-mss <500-1460>

Définir la taille maximale de segment TCP (TCP-MSS) pour la connexion.

set firewall bridge [prerouting | forward | output] filter rule <1-999999> set ttl <0-255>

Définir la valeur TTL (Time to Live).

set firewall bridge [prerouting | forward | output] filter rule <1-999999> set hop-limit <0-255>

Définir la valeur de limite de saut.

set firewall bridge [forward | output] filter rule <1-999999> set connection-mark <0-2147483647>

Définir la valeur de marque de connexion.

Utiliser le pare-feu IP

Par défaut, pour le trafic commuté, seules les règles définies sous set firewall bridge sont appliquées. Il y a deux options globales qui peuvent être configurées afin de forcer une analyse plus approfondie du paquet au niveau IP. Ces options sont :

set firewall global-options apply-to-bridged-traffic ipv4

Cette commande active le pare-feu IPv4 pour le trafic bridgé. Si cette option est utilisée, les paquets sont également analysés par les règles définies dans set firewall ipv4 ...

set firewall global-options apply-to-bridged-traffic ipv6

Cette commande active le pare-feu IPv6 pour le trafic bridgé. Si cette option est utilisée, les paquets sont également analysés par les règles définies dans set firewall ipv6 ...
