OpenVPN

Traditionnellement, les routeurs matériels utilisent exclusivement IPsec car il est facile à implémenter en matériel, et leurs processeurs n'ont pas assez de puissance pour le chiffrement logiciel. Cette limitation est moins pertinente pour VyOS, car c'est un routeur logiciel.

OpenVPN a été largement utilisé sur les plateformes UNIX depuis longtemps et est une option populaire pour les réseaux privés virtuels (VPN) à accès distant. Il prend également en charge les connexions site à site.

OpenVPN offre les avantages suivants :

  • Il utilise une seule connexion TCP ou UDP et ne dépend pas des adresses sources des paquets, donc il fonctionne même à travers un double NAT. Cela le rend bien adapté aux hotspots publics.

  • Il est facile à configurer et offre une très grande flexibilité en matière de tunnel partagé.

  • Un grand nombre d'interfaces graphiques clients sont disponibles pour toute plateforme.

Les inconvénients incluent :

  • Il est plus lent que IPsec en raison d'une surcharge de protocole plus importante et du fait qu'il s'exécute en mode utilisateur, tandis que IPsec sous Linux s'exécute en mode noyau.

  • Aucun système d'exploitation n'inclut par défaut le logiciel client OpenVPN.

Dans l'interface CLI de VyOS, OpenVPN est configuré comme une interface réseau à l'aide de set interfaces openvpn plutôt que set vpn, ce qui est souvent négligé.

Configuration

set interfaces openvpn <interface> authentication password <text>

Configurez le mot de passe pour la méthode d'authentification auth-user-pass .

Cette option s'applique uniquement aux clients OpenVPN.

set interfaces openvpn <interface> authentication username <text>

Configurez le nom d'utilisateur pour la méthode d'authentification auth-user-pass .

Cette option s'applique uniquement aux clients OpenVPN.

set interfaces openvpn <interface> description <description>

Configurez la description de l'interface OpenVPN.

set interfaces openvpn <interface> device-type <tap | tun>

Configurez le type de dispositif réseau virtuel pour l'interface OpenVPN :

  • tun (par défaut) : Fonctionne au niveau 3, encapsulant les paquets IPv4 ou IPv6.

  • tap : Fonctionne au niveau 2, encapsulant les trames Ethernet 802.3.

set interfaces openvpn <interface> disable

Désactivez l'interface OpenVPN spécifique.

set interfaces openvpn <interface> encryption cipher < 3des | aes128 | aes128gcm | aes192 | aes192gcm | aes256 | aes256gcm | none >

Configurez le chiffrement statique pour le tunnel OpenVPN.

L'option cipher correspond à la directive --cipher d'OpenVPN et spécifie l'algorithme de chiffrement symétrique pour les canaux de contrôle et de données.

C'était précédemment la méthode de chiffrement par défaut dans tous les modes OpenVPN. Dans les versions plus récentes d'OpenVPN, la directive --cipher est considérée comme obsolète et doit être utilisée uniquement dans des scénarios de compatibilité.

set interfaces openvpn <interface> encryption data-ciphers < 3des | aes128 | aes128gcm | aes192 | aes192gcm | aes256 | aes256gcm | none >

Configurez une liste priorisée de chiffrements négociés pour OpenVPN en mode client ou server .

L'option data-ciphers représente une liste d'algorithmes de chiffrement pris en charge. Elle correspond à la directive --data-ciphers d'OpenVPN et permet la négociation de chiffrement, où les deux pairs s'accordent automatiquement sur un chiffrement mutuellement supporté lors du démarrage de la session.

Note

Cette option n'est pas compatible avec le mode site-to-site.

set interfaces openvpn <interface> encryption data-ciphers-fallback < 3des | aes128 | aes128gcm | aes192 | aes192gcm | aes256 | aes256gcm | none >

Configurez le chiffrement de secours pour le mode site-to-site .

L'option data-ciphers-fallback correspond à la directive --data-ciphers- fallback d'OpenVPN. Elle définit le chiffrement à utiliser si la négociation est non prise en charge.

Note

Cette option assure une chiffrement cohérent entre deux pairs statiques sans capacité de négociation de chiffrement.

set interfaces openvpn <interface> hash <md5 | sha1 | sha256 | …>

Configurez l'algorithme de hachage pour l'interface OpenVPN.

set interfaces openvpn <interface> ip adjust-mss <mss | clamp-mss-to-pmtu>

Configurez la taille maximale de segment (MSS) annoncée dans les paquets TCP SYN sortants sur l'interface spécifiée.

En limitant la valeur de MSS dans les paquets TCP SYN, vous informez explicitement l'autre côté qu'il ne doit pas envoyer de paquets plus grands que cette taille. Cela empêche les problèmes de connexion qui surviennent lorsque la découverte de MTU de chemin (PMTUD) échoue.

Les options suivantes sont disponibles :

  • mss : Définit la taille MSS à une valeur spécifique, en octets. Utilisez cette option si vous avez besoin d'imposer une taille MSS spécifique, par exemple pour résoudre des problèmes de connectivité ou répondre à des exigences réseau spécifiques.

  • clamp-mss-to-pmtu : Le routeur calcule automatiquement la taille MSS à être la taille MTU de l'interface moins 40 octets pour le trafic IPv4 (20 octets pour l'en-tête IPv4 et 20 octets pour l'en-tête TCP). Cette option est recommandée pour définir automatiquement la bonne valeur.

set interfaces openvpn <interface> ip arp-cache-timeout

Configurez pendant combien de temps un enregistrement ARP reste valide après avoir appris une association d'adresse IP à adresse MAC sur cette interface.

La durée par défaut est de 30 secondes.

Un enregistrement ARP reste valide s'il reçoit un feedback positif des protocoles de niveau supérieur.

Exemple :

set interfaces openvpn vtun0 ip arp-cache-timeout 180
set interfaces openvpn <interface> ip disable-arp-filter

Configurez le filtrage ARP sur cette interface.

Comportement par défaut : Le noyau répond aux demandes ARP sur cette interface uniquement si le trafic serait routé de retour à l'expéditeur ARP via cette interface spécifique.

Si configuré : Le noyau répond aux demandes ARP sur cette interface pour toute adresse IP configurée sur l'hôte local, indépendamment de l'interface spécifique à laquelle cette adresse IP est assignée, et indépendamment de la table de routage. Cela reflète le concept Linux selon lequel les adresses IP appartiennent à l'hôte, et non à des interfaces individuelles.

Exemple :

set interfaces openvpn vtun0 ip disable-arp-filter
set interfaces openvpn <interface> ip disable-forwarding

Configurez l'interface pour le comportement hôte ou routeur.

Si configuré, l'interface passe en mode hôte, et le transfert IPv4 est désactivé sur celle-ci.

Exemple :

set interfaces openvpn vtun0 ip disable-forwarding
set interfaces openvpn <interface> ip enable-directed-broadcast

Configurez si les paquets broadcast directs IP reçus sur cette interface doivent être transmis.

Comportement par défaut : Les paquets broadcast directs IP sont supprimés.

Si configuré : Les paquets broadcast directs IP sont transmis à tous les hôtes sur le sous-réseau de destination, conformément à RFC 1812 et RFC 2644.

Exemple :

set interfaces openvpn vtun0 ip enable-directed-broadcast
set interfaces openvpn <interface> ip enable-arp-accept

Configurez comment traiter les ARPs gratuit sur cette interface.

Si configuré, une association IP-MAC est ajoutée au tableau ARP en fonction des demandes ou réponses ARP gratuit.

Note

Si le tableau ARP contient déjà l'adresse IP provenant d'un ARP gratuit, son entrée est mise à jour, indépendamment de la configuration de cette option.

Exemple :

set interfaces openvpn vtun0 ip enable-arp-accept
set interfaces openvpn <interface> ip enable-arp-announce

Configurez la sélection de l'adresse source pour les demandes ARP sur cette interface.

Comportement par défaut : Le noyau peut utiliser n'importe quelle adresse IP possédée par l'hôte comme adresse source dans les demandes ARP sur cette interface.

Si configuré : Le noyau tente d'abord de sélectionner une adresse IP configurée sur l'interface qui partage un sous-réseau commun avec l'adresse IP cible. Si aucun tel sous-réseau n'existe, le noyau sélectionne l'adresse IP qu'il utiliserait normalement (en fonction de la table de routage pour atteindre la destination cible).

Exemple :

set interfaces openvpn vtun0 ip enable-arp-announce
set interfaces openvpn <interface> ip enable-arp-ignore

Configurez quels requêtes ARP seront ignorées sur cette interface.

Comportement par défaut : Le noyau répond aux requêtes ARP pour toutes les adresses IP locales, indépendamment de l'interface à laquelle elles sont assignées.

Si configuré : Le noyau répond aux requêtes ARP uniquement si l'adresse IP cible est assignée à cette interface spécifique.

Exemple :

set interfaces openvpn vtun0 ip enable-arp-ignore
set interfaces openvpn <interface> ip enable-proxy-arp

Configurez le proxy ARP sur cette interface.

Si configuré, le routeur (noyau) intercepte les requêtes ARP pour des adresses IP non locales et répond avec l'adresse MAC de l'interface qui a reçu la requête. Les paquets suivants destinés à ces adresses IP sont ensuite transmis vers leurs destinations réelles sur les sous-réseaux distants.

Exemple :

set interfaces openvpn vtun0 ip enable-proxy-arp
set interfaces openvpn <interface> ip proxy-arp-pvlan

Configurez le proxy ARP local sur l'interface.

Si configuré, le routeur (noyau) répond aux requêtes ARP sur cette interface VLAN même si l'adresse IP cible se trouve sur le même sous-réseau et l'interface.

Cela est utilisé pour soutenir les exigences d'isolation réseau (RFC 3069) pour les VLAN privés (PVLAN). Dans les configurations PVLAN, les hôtes sur des ports isolés ne sont pas autorisés à communiquer directement entre eux au niveau 2, mais ils peuvent communiquer avec le routeur supérieur.

En répondant aux requêtes ARP inter-hôtes avec sa propre adresse MAC, le routeur (noyau) dirige le trafic inter-hôtes via lui-même au lieu de directement entre les hôtes.

Note

Cette commande fonctionne indépendamment et n'a pas besoin d'activer le proxy ARP standard sur l'interface.

Le proxy ARP local est également connu sous les noms suivants :

  • Aggrégation de VLAN (RFC 3069).

  • VLAN privé (Cisco, Allied Telesyn).

  • Filtrage de port source ou isolation de port (Hewlett-Packard).

  • Transfert forcé MAC (Ericsson).

set interfaces openvpn <interface> ip source-validation <strict | loose | disable>

Configurez la validation de l'adresse IP source à l'aide de RPF sur cette interface, comme spécifié dans RFC 3704.

Les options suivantes sont disponibles :

  • strict : Chaque paquet entrant est vérifié contre la base d'informations de routage (FIB). Si l'interface n'est pas le meilleur chemin de retour vers cette source, la validation échoue et le paquet est supprimé.

  • loose : Chaque paquet entrant est vérifié contre la FIB. Si l'adresse IP source est inatteignable via n'importe quelle interface, la validation échoue.

  • disable : Aucune validation de l'adresse IP source n'est effectuée. Tous les paquets entrants sont acceptés.

Le RFC 3704 recommande d'activer le mode strict pour prévenir le spoofing d'IP, comme les attaques DDoS. Pour les scénarios de routage asymétrique ou autres scénarios complexes, utilisez le mode loose.

set interfaces openvpn <interface> ipv6 address autoconf

Configurez l'interface pour obtenir automatiquement une adresse IPv6 à l'aide de SLAAC, comme spécifié dans RFC 4862.

Les hôtes IPv6 peuvent se configurer automatiquement lorsqu'ils sont connectés à un réseau IPv6 en utilisant le protocole de découverte des voisins via les messages ICMPv6 de découverte de routeur. Lorsqu'ils se connectent pour la première fois à un réseau, un hôte envoie une demande multicast de demande de routeur link-local pour ses paramètres de configuration. Le routeur répond avec un paquet de publication de routeur contenant les paramètres de configuration du niveau Internet.

Note

Cette méthode désactive automatiquement le transfert de trafic IPv6 sur l'interface.

Exemple :

set interfaces openvpn vtun0 ipv6 address autoconf
set interfaces openvpn <interface> ipv6 address eui64 <prefix>

Configurez l'interface pour lui attribuer une adresse IPv6 à l'aide de la méthode EUI-64 , comme spécifié dans RFC 4291.

Exemple :

set interfaces openvpn vtun0 ipv6 address eui64 2001:db8:beef::/64
set interfaces openvpn <interface> ipv6 address no-default-link-local

Désactivez l'attribution automatique d'une adresse IPv6 link-local à cette interface.

Exemple :

set interfaces openvpn vtun0 ipv6 address no-default-link-local
set interfaces openvpn <interface> ipv6 disable-forwarding

Configurez l'interface pour le comportement hôte ou routeur.

Si configuré, l'interface passe en mode hôte, et le transfert IPv6 est désactivé sur celle-ci.

Exemple :

set interfaces openvpn vtun0 ipv6 disable-forwarding
set interfaces openvpn <interface> ipv6 adjust-mss <mss | clamp-mss-to-pmtu>

Configurez la taille maximale de segment (MSS) annoncée dans les paquets TCP SYN sortants sur l'interface spécifiée.

En limitant la valeur de MSS dans les paquets TCP SYN, vous informez explicitement l'autre côté qu'il ne doit pas envoyer de paquets plus grands que cette taille. Cela empêche les problèmes de connexion lorsque la découverte de MTU de chemin (PMTUD) échoue.

Les options suivantes sont disponibles :

  • mss : Définit la taille MSS à une valeur spécifique, en octets. Utilisez cette option pour imposer une taille MSS spécifique, par exemple pour résoudre des problèmes de connectivité ou répondre à des exigences réseau spécifiques.

  • clamp-mss-to-pmtu : Le routeur calcule la taille MSS à être la taille MTU de l'interface moins 60 octets pour le trafic IPv6 (40 octets pour l'en-tête IPv6 et 20 octets pour l'en-tête TCP). Cette option est recommandée pour définir automatiquement la bonne valeur.

set interfaces openvpn <interface> ipv6 accept-dad <0 | 1 | 2>

Configurez le DAD IPv6 sur l'interface.

Les options suivantes sont disponibles :

  • 0 : Désactive le DAD. Aucune détection d'adresse dupliquée n'est effectuée.

  • 1 : Active le DAD (par défaut). Les adresses dupliquées sont détectées. L'opération IPv6 de l'interface continue pour les adresses IPv6 valides.

  • 2 : Active le DAD et, si une adresse link-local dupliquée basée sur le MAC est trouvée, désactive l'opération IPv6 sur cette interface.

Exemple :

set interfaces openvpn vtun0 ipv6 accept-dad 2
set interfaces openvpn <interface> ipv6 dup-addr-detect-transmits <n>

Configurez le nombre de messages DAD que le routeur (noyau) envoie pendant l'attribution d'adresse IPv6 sur cette interface.

La valeur par défaut est 1.

Exemple :

set interfaces openvpn vtun0 ipv6 dup-addr-detect-transmits 5
set interfaces openvpn <interface> keep-alive failure-count <value>

Configurez le nombre de pannes de paquets keepalive tolérés.

Défaut : 60 pannes consécutives.

set interfaces openvpn <interface> keep-alive interval <value>

Configurez la fréquence, en secondes, à laquelle les paquets keepalive sont envoyés.

Défaut : 10 secondes.

set interfaces openvpn <interface> local-address <address>

Configurez l'adresse IP du tunnel local pour le mode site-to-site.

set interfaces openvpn <interface> local-host <address>

Configurez l'adresse IP locale pour accepter les connexions.

Si configuré, OpenVPN s'attache à cette adresse IP uniquement.

Par défaut, OpenVPN s'attache à toutes les interfaces.

set interfaces openvpn <interface> local-port <port>

Configurez le port local pour accepter les connexions.

set interfaces openvpn <interface> mirror egress <monitor-interface>

Configurez le miroir du trafic sortant de cette interface OpenVPN vers l'interface de surveillance désignée.

set interfaces openvpn <interface> mirror ingress <monitor-interface>

Configurez le miroir du trafic entrant de cette interface OpenVPN vers l'interface de surveillance désignée.

set interfaces openvpn <interface> mode <site-to-site | server | client>

Configurez le mode d'exploitation d'OpenVPN :

  • site-to-site : Établit une connexion VPN site à site.

  • client : Fonctionne en tant que client en mode serveur-client.

  • server : Fonctionne en tant que serveur en mode serveur-client.

OpenVPN Data Channel Offload (DCO)

OpenVPN DCO améliore les performances du traitement des données chiffrées OpenVPN en maintenant la plupart du traitement des données dans le noyau et en évitant les commutations contextuelles fréquentes entre le noyau et l'espace utilisateur.

En conséquence, le traitement des paquets devient plus efficace et peut utiliser le support de déchargement de chiffrement matériel disponible dans le noyau.

Note

  • DCO est une fonctionnalité expérimentale, non pleinement prise en charge d'OpenVPN. Certaines fonctionnalités d'OpenVPN et certains scénarios de déploiement sont non compatibles avec DCO.

    Pour une liste complète des fonctionnalités prises en charge, visitez : https://community.openvpn.net/openvpn/wiki/DataChannelOffload/Features

  • DCO est configuré par tunnel et désactivé par défaut. Les tunnels existants fonctionnent sans DCO à moins qu'il ne soit activé explicitement.

  • L'activation de DCO réinitialise l'interface.

Bonne pratique : Créez un nouveau tunnel avec DCO activé pour éviter les problèmes de compatibilité avec les clients existants.

set interfaces openvpn <interface> offload dco

Activez DCO pour l'interface OpenVPN spécifiée.

Exemple :

set interfaces openvpn vtun0 offload dco

Cette commande active DCO et charge le module noyau requis.

set interfaces openvpn <interface> openvpn-option <text>

Ajoutez des options de configuration OpenVPN brutes au fichier openvpn.conf.

OpenVPN propose de nombreuses options de configuration, mais pas toutes sont disponibles dans la CLI VyOS.

Si une option requise est absente, vous pouvez soumettre une demande de fonctionnalité à Phabricator afin que tous les utilisateurs en bénéficient (voir Contributing/Issues and Features).

Alternativement, utilisez openvpn-option pour passer des options de configuration OpenVPN brutes au fichier openvpn.conf.

Avertissement

Utilisez cette option uniquement en dernier recours. Des options ou une syntaxe incorrectes peuvent empêcher OpenVPN de démarrer. Vérifiez les journaux du système après l'application des modifications.

Exemple :

set interfaces openvpn vtun0 openvpn-option 'persist-key'

Cette commande ajoute persist-key au fichier de configuration. Cela résout le problème en conservant les clés après les redémarrages, afin qu'elles n'aient pas à être relues.

set interfaces openvpn vtun0 openvpn-option 'route-up &quot;/config/auth/tun_up.sh arg1&quot;'

Cette commande ajoute route-up "/config/auth/tun_up.sh arg1" au fichier de configuration. Cette option est exécutée après l'authentification de la connexion, soit immédiatement, soit après un court délai, selon la définition.

Assurez-vous que le chemin et les arguments sont encadrés par des guillemets simples ou doubles.

Note

Certaines options de configuration brutes nécessitent des guillemets. Pour les inclure, utilisez la « déclaration ».

set interfaces openvpn <interface> persistent-tunnel

Activez le mode toujours actif pour le périphérique TUN/TAP.

Lorsqu'elle est activée, le périphérique TUN/TAP reste actif après les redémarrages ou les rechargements du daemon.

set interfaces openvpn <interface> protocol <udp | tcp-passive | tcp-active >

Configurez le protocole pour la communication OpenVPN avec un hôte distant :

  • udp (par défaut) : Utilise le protocole UDP.

  • tcp-passive : Utilise le protocole TCP et accepte les connexions passivement.

  • tcp-active : Utilise le protocole TCP et initie les connexions activement.

set interfaces openvpn <interface> server topology < net30 | point-to-point | subnet>

Configurez la topologie d'adressage virtuelle pour le mode tun .

Cette commande n'affecte pas le mode tap, qui utilise toujours la topologie subnet.

  • subnet (par défaut) : Alloue une adresse IP unique à chaque client connecté. C'est la topologie recommandée.

  • net30 : Alloue un sous-réseau /30 à chaque client connecté. C'est une topologie héritée utilisée pour supporter les clients Windows. Elle est désormais effectivement obsolète.

  • point-to-point : Crée une topologie point à point où l'extrémité distante de l'interface tun du client pointe toujours vers l'extrémité locale de l'interface tun du serveur.

Comme subnet, cette topologie alloue une adresse IP par client. Utilisez-la uniquement si aucun client ne tourne sous Windows.
