Syslog

Aperçu

Par défaut, VyOS fournit une configuration de journalisation minimale avec un stockage local et une rotation des journaux. Tous les erreurs, y compris les messages local7, sont enregistrés dans un fichier local. Les alertes d'urgence sont envoyées au terminal.

Pour modifier ces paramètres, entrez le mode de configuration.

Configuration du syslog

Le syslog prend en charge la journalisation vers plusieurs destinations : un fichier local, un terminal ou un serveur syslog distant via UDP ou TCP.

La configuration du syslog est organisée en catégories suivantes :

  • Paramètres globaux

  • Journalisation locale

  • Journalisation sur le terminal

  • Journalisation distante

  • Journalisation distante chiffrée avec TLS

Paramètres globaux

Configurez le comportement général du service syslog.

set system syslog marker interval <number>

Configurez l'intervalle, en secondes, pour l'envoi des messages de marque syslog.

Les messages de marque syslog confirment que le service de journalisation est opérationnel.

Par défaut : 1200 secondes.

set system syslog marker disable

Désactiver l'envoi des messages de marque syslog.

set system syslog preserve-fqdn

Configurez comment le nom d'hôte de l'appareil de journalisation apparaît dans les messages de journal envoyés à un serveur syslog distant.

Si configuré, l'appareil inclut son FQDN dans les messages de journal, même si le serveur syslog se trouve dans le même domaine.

Journalisation locale

Configurez quels messages de journal à enregistrer dans un fichier de journal local.

set system syslog local <filename> facility <keyword> level <keyword>

Configurez le syslog pour enregistrer les messages de journal pour une installation et un niveau de gravité spécifiques dans ``/var/log/messages``.

Référez-vous aux tableaux ci-dessous pour les options valides d'installation et de niveau de gravité.

Journalisation sur le terminal

Configurez quels messages de journal à envoyer à /dev/console.

set system syslog console facility <keyword> level <keyword>

Configurez le syslog pour envoyer les messages de journal pour une installation et une gravité spécifiques au terminal de l'appareil.

Référez-vous aux tableaux ci-dessous pour les options valides d'installation et de niveau de gravité.

Journalisation distante

Configurez la journalisation distante pour envoyer les messages de journal à un serveur syslog distant.

La journalisation distante n'affecte ni la journalisation locale ni la journalisation sur le terminal et s'exécute en parallèle avec elles. La journalisation distante permet d'envoyer les messages de journal à plusieurs hôtes.

set system syslog remote <address> facility <keyword> level <keyword>

Configurez l'envoi des messages de journal vers le serveur syslog distant pour une installation et un niveau de gravité spécifiques.

L'adresse du serveur peut être spécifiée à l'aide d'un FQDN ou d'une adresse IP.

Référez-vous aux tableaux ci-dessous pour les options valides d'installation et de niveau de gravité.

set system syslog remote <address> protocol <udp | tcp>

Configurez le protocole pour l'envoi des messages de journal.

Le protocole peut être UDP ou TCP. Par défaut, les messages de journal sont envoyés via UDP.

set system syslog remote <address> port <port>

Configurez le port pour l'envoi des messages de journal.

Par défaut, le port standard 514 est utilisé.

set system syslog remote <address> format include-timezone

Configurez l'envoi des messages de journal au format RFC 5424.

Le format RFC 5424 inclut la zone horaire dans l'horodatage. Par exemple :

<34>1 2003-10-11T22:14:15.003-07:00 mymachine.example.com su - ID47 - BOM’su root’ failed for lonvick on /dev/pts/8.

Par défaut, les messages de journal sont envoyés au format RFC 3164. Par exemple :

<34>Oct 11 22:14:15 mymachine su: ‘su root’ failed for lonvick on /dev/pts/8
set system syslog remote <address> format octet-counted

Activez le format d'encapsulation octet-compté pour l'envoi des messages de journal.

Lorsqu'elle est activée, les messages de journal multilignes sont envoyés sans séparation. Assurez-vous que le serveur distant prend en charge le format d'encapsulation octet-compté pour éviter les erreurs de parsing.

Le format d'encapsulation octet-compté n'est pas disponible pour le protocole UDP.

set system syslog remote <address> vrf <name>

Configurez l'instance VRF pour l'envoi des messages de journal.

set system syslog remote <address> source-address <address>

Configurez l'adresse IP source (IPv4 ou IPv6) pour l'envoi des messages de journal.

TLS-journalisation distante chiffrée

VyOS prend en charge la TLS-journalisation distante chiffrée sur TCP pour assurer une transmission sécurisée des données syslog vers les serveurs syslog distants.

Prérequis : Avant de configurer la TLS-journalisation distante chiffrée, assurez-vous que vous avez :

  • Une adresse de serveur syslog distant valide.

  • Des certificats CA et client valides chargés dans le stockage PKI local.

  • Le protocole de transport syslog distant est défini sur TCP :

    set system syslog remote <address> protocol tcp

Note

La journalisation distante chiffrée avec TLS n'est pas prise en charge sur UDP.

set system syslog remote <address> tls

Activer la journalisation distante chiffrée avec TLS.

set system syslog remote <address> tls ca-certificate <ca_name>

Configurez le certificat CA .

Le client syslog utilise le certificat CA pour vérifier l'identité du serveur syslog distant.

Le certificat CA est requis pour tous les modes d'authentification sauf anon.

set system syslog remote <address> tls certificate <cert_name>

Configurez le certificat client.

Le serveur syslog distant utilise le certificat client pour vérifier l'identité du client syslog.

Le certificat client est requis si le serveur syslog distant impose la vérification du certificat client.

set system syslog remote <address> tls auth-mode <anon | fingerprint | certvalid | name>

Configurez le mode d'authentification.

Le mode d'authentification définit comment le client syslog vérifie l'identité du serveur syslog.

Les modes d'authentification suivants sont disponibles :

  • anon (par défaut) : Permet des connexions chiffrées sans vérifier l'identité du serveur syslog. Ce mode n'est pas recommandé, car il est vulnérable aux attaques MITM.

  • fingerprint : Vérifie la empreinte digitale du certificat du serveur contre la valeur prédéfinie avec :

    set system syslog remote <address> tls permitted-peer <peer>

  • certvalid : Vérifie que le certificat du serveur est signé par une CA de confiance, en ignorant le contrôle CN.

  • name : Vérifie que :

    • Le certificat du serveur est signé par une CA de confiance.

    • Le CN du certificat correspond à la valeur prédéfinie avec :

    set system syslog remote <address> tls permitted-peer <peer>

    Ce mode est recommandé pour les environnements de production.

set system syslog remote <address> tls permitted-peer <peer>

Configurez les identifiants de certificat du pair.

Le format de l'identifiant du certificat dépend du mode d'authentification :

  • fingerprint : Entrez les empreintes digitales de certificat attendues (SHA-1 ou SHA-256).

  • name : Entrez les noms CNs de certificat attendus.

Pour les modes d'authentification anon et certvalid, les identifiants de certificat ne sont pas requis.

Exemples :

# Exemple de mode d'authentification 'anon'
set system syslog remote 10.10.2.3 facility all level debug
set system syslog remote 10.10.2.3 port 6514
set system syslog remote 10.10.2.3 protocol tcp
set system syslog remote 10.10.2.3 tls auth-mode anon
# ou utiliser simplement 'set system syslog remote 10.10.2.3 tls'

# Exemple de mode d'authentification 'certvalid'
set system syslog remote elk.example.com facility all level debug
set system syslog remote elk.example.com port 6514
set system syslog remote elk.example.com protocol tcp
set system syslog remote elk.example.com tls ca-certificate my-ca
set system syslog remote elk.example.com tls auth-mode certvalid

# Exemple de mode d'authentification 'fingerprint'
set system syslog remote syslog.example.com facility all level debug
set system syslog remote syslog.example.com port 6514
set system syslog remote syslog.example.com protocol tcp
set system syslog remote syslog.example.com tls ca-certificate my-ca
set system syslog remote syslog.example.com tls auth-mode fingerprint
set system syslog remote syslog.example.com tls permitted-peers 'SHA1:10:C4:26:...,SHA256:7B:4B:10:...'

# Exemple de mode d'authentification 'name'
set system syslog remote graylog.example.com facility all level debug
set system syslog remote graylog.example.com port 6514
set system syslog remote graylog.example.com protocol tcp
set system syslog remote graylog.example.com tls ca-certificate my-ca
set system syslog remote graylog.example.com tls certificate syslog-client
set system syslog remote graylog.example.com tls auth-mode name
set system syslog remote graylog.example.com tls permitted-peers 'graylog.example.com'

Recommandations de sécurité

  • Pour les déploiements sécurisés, utilisez toujours le mode d'authentification name. Cela assure que le serveur est validé par une CA de confiance et que le nom d'hôte correspond au certificat.

  • Utilisez le mode d'authentification anon uniquement dans les environnements de test, car il ne fournit pas d'authentification du serveur.

  • Assurez-vous que les clés privées sont générées, stockées et maintenues exclusivement dans le système PKI.

Cette section liste les facilités utilisées par syslog. La plupart des noms de facilité sont auto-expliquants. Les facilités local0–local7 sont utilisées à des fins personnalisées, comme la journalisation provenant des nœuds réseau et équipements. L'attribution de facilité est flexible et doit être adaptée aux besoins de votre entreprise. Considérez les facilités comme des outils de catégorisation, plutôt que des directives strictes.

Afficher les journaux

show log [all | authorization | cluster | conntrack-sync | …]

Afficher les journaux pour une catégorie spécifique sur le terminal.

Utilisez la complétion tabulaire pour afficher la liste des catégories disponibles.

Si aucune catégorie n'est spécifiée, tous les journaux sont affichés.

show log image <name> [all | authorization | directory | file <file name> | tail <lines>]

Afficher les journaux pour une image spécifique sur le terminal.

Les catégories de journal disponibles :

all

Affiche le contenu des fichiers de journal du système de l'image spécifiée.

authorization

Affiche les tentatives d'autorisation de l'image spécifiée.

directory

Affiche les fichiers de journal définis par l'utilisateur de l'image spécifiée.

file <file name>

Affiche le contenu d'un fichier de journal défini par l'utilisateur de l'image spécifiée.

tail

Affiche les dernières lignes du journal système de l'image spécifiée.

<lines>

Nombre de lignes à afficher, par défaut 10.

Si aucune catégorie n'est spécifiée, le contenu du fichier syslog principal est affiché.

Conseil

Utilisez show log | strip-private pour masquer les données privées lors de l'affichage de vos journaux.
