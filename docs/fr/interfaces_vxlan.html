VXLAN

VXLAN est une technologie de virtualisation réseau qui répond aux défis d'évolutivité dans les environnements informatiques cloud de grande taille. Il encapsule les trames Ethernet (couche 2) dans des datagrammes UDP (couche 4), qui sont ensuite transmis via le port UDP 4789, comme assigné par l'IANA. Les extrémités VXLAN, appelées VTEPs, terminent les tunnels VXLAN et peuvent être soit des ports de commutateur virtuel ou physique.

VXLAN prend en charge jusqu'à 16 millions de réseaux logiques et permet la connectivité au niveau 2 à travers des réseaux IP au niveau 3. Il utilise le multicast ou le unicast avec la réplication de tête (HER) pour diffuser le trafic de diffusion, de broadcast inconnu et multicast (BUM).

La spécification VXLAN a été initialement développée par VMware, Arista Networks et Cisco. D'autres soutiens incluent Huawei, Broadcom, Citrix, Pica8, Big Switch Networks, Cumulus Networks, Dell EMC, Ericsson, Mellanox, FreeBSD, OpenBSD, Red Hat, Joyent et Juniper Networks.

VXLAN est officiellement documenté par l'IETF dans RFC 7348.

Lors de la configuration du VXLAN dans une machine virtuelle VyOS, assurez-vous que le spoofing MAC (Hyper-V) ou les transmissions falsifiées (ESX) sont autorisés. Sinon, l'hyperviseur peut bloquer les trames transmises.

Remarque

Même si le port VXLAN attribué par l'IANA est 4789, VyOS utilise le port UDP par défaut de Linux 8472 pour les interfaces VXLAN. Pour garantir la compatibilité avec d'autres fournisseurs, définissez le port sur la norme IANA 4789.

Configuration

Configuration commune de l'interface

set interfaces vxlan <interface> address <address>

Configurez une ou plusieurs adresses IP d'interface.

<address> prend en charge IPv4 et IPv6 en notation CIDR. Par exemple, utilisez 192.0.2.1/24 pour IPv4 ou 2001:db8::1/64 pour IPv6.

Exemple :

set interfaces vxlan vxlan0 address 192.0.2.1/24
set interfaces vxlan vxlan0 address 2001:db8::1/64
set interfaces vxlan <interface> description <description>

Configurez un alias clair et descriptif pour l'interface.

Cet alias apparaît dans la commande show interfaces et les outils de surveillance basés sur SNMP.

Exemple :

set interfaces vxlan vxlan0 description 'This is an interface running on VyOS.'
set interfaces vxlan <interface> disable

Désactivez l'interface.

L'interface sera configurée en état administrativement down (A/D).

Exemple :

set interfaces vxlan vxlan0 disable
set interfaces vxlan <interface> disable-flow-control

Désactivez le contrôle de flux Ethernet (trames pause IEEE 802.3x) sur l'interface.

Le contrôle de flux Ethernet, défini par la norme IEEE 802.3x, temporairement arrête la transmission de données pour éviter la perte de paquets pendant la congestion réseau. Par exemple, lorsqu'un émetteur transmet des données plus rapidement que le récepteur ne peut les traiter.

La désactivation du contrôle de flux Ethernet signifie que l'interface ne signalera pas à l'appareil connecté de suspendre la transmission et supprimera les paquets s'il est submergé.

Exemple :

set interfaces vxlan vxlan0 disable-flow-control
set interfaces vxlan <interface> disable-link-detect

Désactivez la détection des changements d'état physique de l'interface, tels que lorsqu'un câble est débranché.

Par défaut, l'interface détecte les changements d'état physique.

Exemple :

set interfaces vxlan vxlan0 disable-link-detect
set interfaces vxlan <interface> mac <xx:xx:xx:xx:xx:xx>

Configurez une adresse MAC personnalisée sur l'interface.

Exemple :

set interfaces vxlan vxlan0 mac '00:53:01:02:03:04'
set interfaces vxlan <interface> mtu <mtu>

Configurez le MTU sur l'interface.

Cette valeur définit la taille maximale du paquet, en octets, que l'interface transmet sans fragmentation.

Exemple :

set interfaces vxlan vxlan0 mtu 1600
set interfaces vxlan <interface> ip adjust-mss <mss | clamp-mss-to-pmtu>

Configurez la MSS annoncée dans les paquets TCP SYN sortants sur l'interface spécifiée.

En limitant la valeur MSS dans les paquets TCP SYN, vous informez explicitement l'autre partie qu'elle ne doit pas envoyer de paquets plus grands que cette taille. Cela empêche les problèmes de connexion qui surviennent lorsque la découverte du MTU de chemin (PMTUD) échoue.

Les options suivantes sont disponibles :

  • mss : Définit la MSS à une valeur spécifique, en octets. Utilisez cette option si vous avez besoin d'imposer une MSS spécifique, par exemple pour résoudre des problèmes de connectivité ou pour satisfaire des exigences réseau spécifiques.

  • clamp-mss-to-pmtu : Le routeur calcule automatiquement la MSS à être la MTU de l'interface moins 40 octets pour le trafic IPv4 (20 octets pour l'en-tête IPv4 et 20 octets pour l'en-tête TCP). Cette option est recommandée pour configurer automatiquement la bonne valeur.

set interfaces vxlan <interface> ip arp-cache-timeout

Configurez la durée pendant laquelle une entrée ARP reste valide après avoir appris une correspondance entre une adresse IP et une adresse MAC sur cette interface.

La durée par défaut est de 30 secondes.

Une entrée ARP reste valide si elle reçoit un feedback positif des protocoles de niveau supérieur.

Exemple :

set interfaces vxlan vxlan0 ip arp-cache-timeout 180
set interfaces vxlan <interface> ip disable-arp-filter

Configurez le filtrage ARP sur cette interface.

Comportement par défaut : Le noyau répond aux demandes ARP sur cette interface uniquement si le trafic serait routé de retour à l'expéditeur ARP via cette interface spécifique.

Si configuré : Le noyau répond aux demandes ARP sur cette interface pour toute adresse IP configurée sur l'hôte local, indépendamment de l'interface spécifique à laquelle cette adresse IP est assignée, et indépendamment de la table de routage. Cela reflète le concept Linux selon lequel les adresses IP appartiennent à l'hôte, et non aux interfaces individuelles.

Exemple :

set interfaces vxlan vxlan0 ip disable-arp-filter
set interfaces vxlan <interface> ip disable-forwarding

Configurez l'interface pour un comportement d'hôte ou de routeur.

Si configuré, l'interface passe en mode hôte, et le transfert IPv4 est désactivé dessus.

Exemple :

set interfaces vxlan vxlan0 ip disable-forwarding
set interfaces vxlan <interface> ip enable-directed-broadcast

Configurez si les paquets broadcast directs IP reçus sur cette interface doivent être transmis.

Comportement par défaut : Les paquets broadcast directs IP sont supprimés.

Si configuré : Les paquets broadcast directs IP sont transmis à tous les hôtes sur le sous-réseau de destination, conformément à RFC 1812 et RFC 2644.

Exemple :

set interfaces vxlan vxlan0 ip enable-directed-broadcast
set interfaces vxlan <interface> ip enable-arp-accept

Configurez comment traiter les ARPs gratuit sur cette interface.

Si configuré, une correspondance IP-MAC est ajoutée au tableau ARP en fonction des demandes ou réponses ARP gratuit.

Note

Si le tableau ARP contient déjà l'adresse IP provenant d'un ARP gratuit, son entrée est mise à jour, indépendamment de la configuration de ce paramètre.

Exemple :

set interfaces vxlan vxlan0 ip enable-arp-accept
set interfaces vxlan <interface> ip enable-arp-announce

Configurez la sélection de l'adresse IP source pour les demandes ARP sur cette interface.

Comportement par défaut : Le noyau peut utiliser n'importe quelle adresse IP possédée par l'hôte comme adresse IP source dans les demandes ARP sur cette interface.

Si configuré : Le noyau tente d'abord de sélectionner une adresse IP source configurée sur l'interface partageant un sous-réseau commun avec l'adresse IP cible. Si aucun tel sous-réseau n'existe, le noyau sélectionne l'adresse IP qu'il utiliserait normalement (en fonction de la table de routage pour atteindre la destination cible).

Exemple :

set interfaces vxlan vxlan0 ip enable-arp-announce
set interfaces vxlan <interface> ip enable-arp-ignore

Configurez les demandes ARP qui seront ignorées sur cette interface.

Comportement par défaut : Le noyau répond aux demandes ARP pour toutes les adresses IP locales, indépendamment de l'interface à laquelle elles sont assignées.

Si configuré : Le noyau répond aux demandes ARP uniquement si l'adresse IP cible est assignée à cette interface spécifique.

Exemple :

set interfaces vxlan vxlan0 ip enable-arp-ignore
set interfaces vxlan <interface> ip enable-proxy-arp

Configurez le proxy ARP sur cette interface.

Si configuré, le routeur (noyau) intercepte les demandes ARP pour des adresses IP non locales et répond avec l'adresse MAC de l'interface qui a reçu la demande. Les paquets suivants destinés à ces adresses IP sont acheminés vers leurs destinations réelles sur des sous-réseaux distants.

Exemple :

set interfaces vxlan vxlan0 ip enable-proxy-arp
set interfaces vxlan <interface> ip proxy-arp-pvlan

Configurez le proxy ARP local sur l'interface.

Si configuré, le routeur (noyau) répond aux demandes ARP sur cette interface VLAN même si l'adresse IP cible se trouve sur le même sous-réseau et interface.

Cela est utilisé pour soutenir les exigences de séparation réseau (RFC 3069) pour les VLAN privés (PVLANs). Dans les configurations PVLAN, les hôtes sur les ports isolés ne sont PAS autorisés à communiquer directement entre eux au niveau 2, mais ils peuvent communiquer avec le routeur supérieur.

Avec une réponse aux demandes ARP inter-hôtes avec sa propre adresse MAC, le routeur (noyau) dirige le trafic inter-hôtes à travers lui-même au lieu de directement entre les hôtes.

Note

Cette commande fonctionne indépendamment et ne nécessite pas l'activation du proxy ARP standard sur l'interface.

Le proxy ARP local est également connu sous les noms suivants :

  • Aggrégation de VLAN (RFC 3069).

  • VLAN privé (Cisco, Allied Telesyn).

  • Filtrage de port source ou isolation de port (Hewlett-Packard).

  • Transfert forcé MAC (Ericsson).

set interfaces vxlan <interface> ip source-validation <strict | loose | disable>

Configurez la validation de l'adresse IP source à l'aide de RPF sur cette interface, comme spécifié dans RFC 3704.

Les options suivantes sont disponibles :

  • strict : Chaque adresse IP source des paquets entrants est vérifiée contre la base d'informations de routage (FIB). Si l'interface n'est pas le meilleur chemin de retour à cette source, la validation échoue et le paquet est supprimé.

  • loose : Chaque adresse IP source des paquets entrants est vérifiée contre la FIB. Si l'adresse IP source est inatteignable via n'importe quelle interface, la validation échoue.

  • disable : Aucune validation d'adresse IP source n'est effectuée. Tous les paquets entrants sont acceptés.

Le RFC 3704 recommande d'activer le mode strict pour empêcher le piratage d'IP, comme les attaques DDoS. Pour les scénarios de routage asymétrique ou autres scénarios complexes, utilisez le mode loose.

set interfaces vxlan <interface> ipv6 address autoconf

Configurez l'interface pour obtenir automatiquement une adresse IPv6 à l'aide de SLAAC, comme spécifié dans RFC 4862.

Les hôtes IPv6 peuvent se configurer automatiquement lorsqu'ils sont connectés à un réseau IPv6 en utilisant le protocole de découverte de voisins via les messages de découverte de routeur ICMPv6. Lorsqu'ils se connectent pour la première fois à un réseau, un hôte envoie une requête de diffusion de routeur link-local pour ses paramètres de configuration. Le routeur répond avec un paquet de publication de routeur contenant les paramètres de configuration du niveau Internet.

Note

Cette méthode désactive automatiquement le transfert de trafic IPv6 sur l'interface.

Exemple :

set interfaces vxlan vxlan0 ipv6 address autoconf
set interfaces vxlan <interface> ipv6 address eui64 <prefix>

Configurez l'interface pour lui attribuer une adresse IPv6 à l'aide de la méthode EUI-64 , comme spécifié dans RFC 4291.

Exemple :

set interfaces vxlan vxlan0 ipv6 address eui64 2001:db8:beef::/64
set interfaces vxlan <interface> ipv6 address no-default-link-local

Désactivez l'attribution automatique d'une adresse IPv6 link-local à cette interface.

Exemple :

set interfaces vxlan vxlan0 ipv6 address no-default-link-local
set interfaces vxlan <interface> ipv6 disable-forwarding

Configurez l'interface pour un comportement d'hôte ou de routeur.

Si configuré, l'interface passe en mode hôte, et le transfert IPv6 est désactivé dessus.

Exemple :

set interfaces vxlan vxlan0 ipv6 disable-forwarding
set interfaces vxlan <interface> ipv6 adjust-mss <mss | clamp-mss-to-pmtu>

Configurez la MSS annoncée dans les paquets TCP SYN sortants sur l'interface spécifiée.

En limitant la valeur MSS dans les paquets TCP SYN, vous informez explicitement l'autre partie qu'elle ne doit pas envoyer de paquets plus grands que cette taille. Cela empêche les problèmes de connexion lorsqu'il y a un échec de la découverte du MTU de chemin (PMTUD).

Les options suivantes sont disponibles :

  • mss : Définissez la MSS à une valeur spécifique, en octets. Utilisez cette option pour imposer une MSS spécifique, par exemple pour résoudre des problèmes de connectivité ou pour satisfaire des exigences réseau spécifiques.

  • clamp-mss-to-pmtu : Le routeur calcule la MSS à être la MTU de l'interface moins 60 octets pour le trafic IPv6 (40 octets pour l'en-tête IPv6 et 20 octets pour l'en-tête TCP). Cette option est recommandée pour configurer automatiquement la bonne valeur.

set interfaces vxlan <interface> ipv6 accept-dad <0 | 1 | 2>

Configurez le DAD IPv6 sur l'interface.

Les options suivantes sont disponibles :

  • 0 : Désactive le DAD. Aucune détection de duplication d'adresse n'est effectuée.

  • 1 : Active le DAD (par défaut). Les adresses dupliquées sont détectées. L'opération IPv6 de l'interface continue pour les adresses IPv6 valides.

  • 2 : Active le DAD et, si une adresse link-local dupliquée basée sur la MAC est trouvée, désactive l'opération IPv6 sur cette interface.

Exemple :

set interfaces vxlan vxlan0 ipv6 accept-dad 2
set interfaces vxlan <interface> ipv6 dup-addr-detect-transmits <n>

Configurez le nombre de DAD messages que le routeur (noyau) envoie pendant l'attribution d'adresse IPv6 sur cette interface.

La valeur par défaut est 1.

Exemple :

set interfaces vxlan vxlan0 ipv6 dup-addr-detect-transmits 5
set interfaces vxlan <interface> vrf <vrf>

Attribuez l'interface à une instance spécifique VRF .

Voir aussi

Pour plus d'informations sur la configuration d'un VRF, consultez la section VRF.

Exemple :

set interfaces vxlan vxlan0 vrf red

Options spécifiques à VXLAN

set interfaces vxlan <interface> vni <number>

Configurez un VNI pour l'interface VXLAN.

Chaque segment VXLAN est identifié par ce VNI de 24 bits, permettant jusqu'à 16 millions de segments de coexister dans le même domaine administratif.

set interfaces vxlan <interface> port <port>

Configurez le port UDP de l'extrémité VXLAN distante.

Note

Même si le port VXLAN attribué par l'IANA est 4789, VyOS utilise le port UDP par défaut de Linux 8472 pour les interfaces VXLAN.

set interfaces vxlan <interface> source-address <address>

Configurez l'adresse IP source pour le sous-réseau VXLAN.

Avertissement

Cette configuration est obligatoire lors de la déploiement de VXLAN via L2VPN/EVPN.

set interfaces vxlan <interface> gpe

Activez le GPE pour l'interface VXLAN.

Pour utiliser cette fonctionnalité, vous devez configurer l'interface avec le paramètre external.

set interfaces vxlan <interface> parameters external

Configurez l'interface VXLAN pour utiliser un plan de contrôle externe, comme BGP L2VPN/EVPN, pour la découverte des points d'extrémité distants.

Si non configuré, la base de données de transfert interne (FDB) est utilisée.

set interfaces vxlan <interface> parameters neighbor-suppress

Activez la suppression ARP et ND sur l'interface VXLAN.

Cela réduit la diffusion de messages ARP et ND sur le réseau VXLAN. Comme défini dans RFC 7432#section-10, les VTEPs participants utilisent des liaisons MAC-IP connues pour répondre aux demandes locales au nom des hôtes distants.

set interfaces vxlan <interface> parameters nolearning

Désactivez l'apprentissage de l'adresse MAC et de l'adresse IP sur l'interface VXLAN.

set interfaces vxlan <interface> parameters vni-filter

Activez le filtrage de VNI sur l'interface VXLAN.

Lorsqu'elle est activée, l'interface ne reçoit que les paquets avec des VNIs configurés dans sa table de filtrage VNI.

Note

Le filtrage VNI fonctionne uniquement si l'interface est configurée avec le paramètre external.

Unicast

set interfaces vxlan <interface> remote <address>

Configurez l'adresse IPv4 ou IPv6 de l'extrémité VTEP distante.

Contrairement aux configurations multicast, cette commande vous permet de configurer directement l'adresse IPv4 ou IPv6 distante.

Multicast

set interfaces vxlan <interface> source-interface <interface>

Configurez l'interface source pour le sous-réseau VXLAN.

Tout le trafic VXLAN est envoyé et reçu via l'interface spécifiée. Cette configuration est obligatoire lors du déploiement de VXLAN sur un réseau multicast.

set interfaces vxlan <interface> group <address>

Configurez l'adresse de groupe multicast IPv4 ou IPv6 pour l'interface VXLAN.

Les tunnels VXLAN peuvent être construits à l'aide d'une adresse de groupe multicast ou d'une adresse IP unicast.

VXLAN multicast

Topologie : PC4 - Leaf2 - Spine1 - Leaf3 - PC5

PC4 utilise l'adresse IP 10.0.0.4/24, et PC5 utilise l'adresse IP 10.0.0.5/24. Les deux appareils supposent qu'ils résident dans le même domaine de diffusion.

Supposons que PC4 sur Leaf2 ping PC5 sur Leaf3. Au lieu de spécifier manuellement Leaf3 comme point d'extrémité distant, Leaf2 encapsule le paquet dans un datagramme UDP et l'envoie à l'adresse multicast désignée via Spine1. Spine1 transmet le paquet à tous les leafs du même groupe multicast, y compris Leaf3. Lorsque Leaf3 reçoit le datagramme, il le transmet à PC5 et apprend que PC4 est accessible via Leaf2 en examinant l'adresse IP source dans le datagramme encapsulé.

PC5 reçoit le ping et répond avec une réponse d'écho. Leaf3, maintenant conscient de la localisation de PC4, transmet la réponse directement à l'adresse unicast de Leaf2. Lorsque Leaf2 reçoit la réponse d'écho, il apprend que PC5 est accessible via Leaf3.

Après cette découverte, le trafic ultérieur entre PC4 et PC5 ne fera pas usage de l'adresse multicast entre les leafs, car les leafs ont appris la localisation des ordinateurs. Cela réduit le trafic multicast et la charge réseau, améliorant ainsi l'évolutivité lorsque davantage de leafs sont ajoutés.

Appareil VXLAN unique (SVD)

Dans VyOS, vous pouvez configurer plusieurs mappages VLAN-VNI pour EVPN-VXLAN sur une seule interface conteneur, appelée un seul appareil VXLAN (SVD). Cela permet une grande évolutivité VNI car une interface VXLAN distincte n'est pas nécessaire pour chaque VNI.

set interfaces vxlan <interface> vlan-to-vni <vlan> vni <vni>

Mappez un ID VLAN à un VNI sur l'interface VXLAN spécifiée.

L'interface VXLAN peut être ajoutée à un pont.

L'exemple suivant montre une configuration SVD avec plusieurs mappages VLAN-VNI.

set interfaces bridge br0 member interface vxlan0
set interfaces vxlan vxlan0 parameters external
set interfaces vxlan vxlan0 source-interface 'dum0'
set interfaces vxlan vxlan0 vlan-to-vni 10 vni '10010'
set interfaces vxlan vxlan0 vlan-to-vni 11 vni '10011'
set interfaces vxlan vxlan0 vlan-to-vni 30 vni '10030'
set interfaces vxlan vxlan0 vlan-to-vni 31 vni '10031'

Exemple

L'exemple suivant illustre un déploiement VXLAN multicast.

La configuration comprend trois routeurs : Spine1, un routeur Cisco IOS, et Leaf2 et Leaf3, qui sont des routeurs VyOS.

Topologie : Leaf2 - Spine1 - Leaf3.

La topologie est construite à l'aide de GNS3.

Spine1:
fa0/2 vers Leaf2, adresse IP : 10.1.2.1/24
fa0/3 vers Leaf3, adresse IP : 10.1.3.1/24

Leaf2:
Eth0 vers Spine1, adresse IP : 10.1.2.2/24
Eth1 vers un commutateur compatible VLAN

Leaf3:
Eth0 vers Spine1, adresse IP 10.1.3.3/24
Eth1 vers un commutateur compatible VLAN

Configuration de Spine1 :

conf t
ip multicast-routing
!
interface fastethernet0/2
 ip address 10.1.2.1 255.255.255.0
 ip pim sparse-dense-mode
!
interface fastethernet0/3
 ip address 10.1.3.1 255.255.255.0
 ip pim sparse-dense-mode
!
router ospf 1
 network 10.0.0.0 0.255.255.255 area 0

Le routage multicast est requis pour le transfert de trafic évolutif entre les leafs. PIM doit être activé vers les leafs afin que le spine puisse apprendre de quel groupe multicast chaque leaf attend du trafic.

Configuration de Leaf2 :

set interfaces ethernet eth0 address '10.1.2.2/24'
set protocols ospf area 0 network '10.0.0.0/8'

! Première interface VXLAN
set interfaces bridge br241 address '172.16.241.1/24'
set interfaces bridge br241 member interface 'eth1.241'
set interfaces bridge br241 member interface 'vxlan241'

set interfaces vxlan vxlan241 group '239.0.0.241'
set interfaces vxlan vxlan241 source-interface 'eth0'
set interfaces vxlan vxlan241 vni '241'

! Deuxième interface VXLAN
set interfaces bridge br242 address '172.16.242.1/24'
set interfaces bridge br242 member interface 'eth1.242'
set interfaces bridge br242 member interface 'vxlan242'

set interfaces vxlan vxlan242 group '239.0.0.242'
set interfaces vxlan vxlan242 source-interface 'eth0'
set interfaces vxlan vxlan242 vni '242'

Configuration de Leaf3 :

set interfaces ethernet eth0 address '10.1.3.3/24'
set protocols ospf area 0 network '10.0.0.0/8'

! Première interface VXLAN
set interfaces bridge br241 address '172.16.241.1/24'
set interfaces bridge br241 member interface 'eth1.241'
set interfaces bridge br241 member interface 'vxlan241'

set interfaces vxlan vxlan241 group '239.0.0.241'
set interfaces vxlan vxlan241 source-interface 'eth0'
set interfaces vxlan vxlan241 vni '241'

! Deuxième interface VXLAN
set interfaces bridge br242 address '172.16.242.1/24'
set interfaces bridge br242 member interface 'eth1.242'
set interfaces bridge br242 member interface 'vxlan242'

set interfaces vxlan vxlan242 group '239.0.0.242'
set interfaces vxlan vxlan242 source-interface 'eth0'
set interfaces vxlan vxlan242 vni '242'

Les configurations de Leaf2 et Leaf3 sont presque identiques. Des explications détaillées pour chaque commande sont fournies ci-dessous.

set interfaces bridge br241 address '172.16.241.1/24'

Cette commande crée un pont pour lier le trafic sur eth1 VLAN 241 avec l'interface vxlan241. L'adresse IP est facultative. Si configurée, elle peut servir de passerelle par défaut pour chaque leaf, permettant aux appareils sur le VLAN d'accéder à d'autres sous-réseaux. Les sous-réseaux doivent être redistribués par OSPF afin que le spine puisse apprendre comment les atteindre. Pour annoncer les réseaux 172.16/12, changez le réseau OSPF de 10.0.0.0/8 en 0.0.0.0/0.

set interfaces bridge br241 member interface 'eth1.241'
set interfaces bridge br241 member interface 'vxlan241'

Ces commandes lient eth1.241 et vxlan241 en tant qu'interfaces membres du même pont.

set interfaces vxlan vxlan241 group '239.0.0.241'

Cette commande configure le groupe multicast utilisé par tous les leafs pour cette extension VLAN. Elle doit être la même sur tous les leafs ayant cette interface.

set interfaces vxlan vxlan241 source-interface 'eth0'

Cette commande configure l'interface qui écoute les paquets multicast. Cela peut également être une interface boucle.

set interfaces vxlan vxlan241 vni '241'

Cette commande configure l'ID unique pour l'interface VXLAN.

set interfaces vxlan vxlan241 port 12345

VyOS utilise le port UDP par défaut de Linux 8472 pour les interfaces VXLAN. Cette commande vous permet de configurer un port UDP différent.

VXLAN unicast

En alternative au multicast, vous pouvez configurer le tunnel VXLAN en spécifiant directement l'adresse IPv4 distante. La mise à jour suivante met à jour l'exemple multicast précédent :

# leaf2 et leaf3
delete interfaces vxlan vxlan241 group '239.0.0.241'
delete interfaces vxlan vxlan241 source-interface 'eth0'

# leaf2
set interfaces vxlan vxlan241 remote 10.1.3.3

# leaf3
set interfaces vxlan vxlan241 remote 10.1.2.2

Le port UDP par défaut est 8472. Pour configurer un port différent, utilisez set interfaces vxlan <vxlanN> port <port>.
