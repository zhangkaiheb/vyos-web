NTP

NTP (Network Time Protocol) est un protocole réseau pour la synchronisation des horloges entre les systèmes informatiques sur des réseaux de données à commutation de paquets et à latence variable. En fonctionnement depuis avant 1985, le NTP est l'un des protocoles Internet les plus anciens en usage actuel.

Le NTP vise à synchroniser tous les ordinateurs participants à quelques millisecondes près de UTC. Il utilise l'algorithme d'intersection, une version modifiée de l'algorithme de Marzullo, pour sélectionner des serveurs de temps précis et est conçu pour atténuer les effets de la latence réseau variable. Le NTP peut généralement maintenir le temps à quelques dizaines de millisecondes près sur Internet public, et peut atteindre une précision supérieure à une milliseconde dans les réseaux locaux sous conditions idéales. Les itinéraires asymétriques et la congestion du réseau peuvent causer des erreurs de 100 ms ou plus.

Le protocole est généralement décrit en termes d'un modèle client-serveur, mais peut également être utilisé facilement dans des relations pair à pair où chaque pair considère l'autre comme une source potentielle de temps. Les implémentations envoient et reçoivent des horodatages en utilisant UDP sur le numéro de port 123.

Le NTP fournit un avertissement en cas de correction d'une seconde intercalaire imminente, mais ne transmet aucune information sur les fuseaux horaires locaux ou l'heure d'été.

Le protocole actuel est la version 4 (NTPv4), qui est une norme proposée telle qu'elle est documentée dans RFC 5905. Il est compatible avec la version 3, spécifiée dans RFC 1305.

Remarque

VyOS 1.4 utilise chrony au lieu de ntpd (voir T3008) qui ne prendra plus en charge les demandes anonymes NTP comme dans VyOS 1.3. Toutes les configurations seront migrées pour conserver la fonctionnalité anonyme. Pour les nouveaux déploiements, si vous avez des clients utilisant votre installation VyOS comme serveur NTP, vous devez spécifier la directive allow-client.

Configuration

set service ntp server <address>

Configurez un ou plusieurs serveurs pour la synchronisation. Le nom du serveur peut être soit une adresse IP, soit un FQDN.

Il y a 3 serveurs NTP par défaut configurés. Vous pouvez les modifier.

  • time1.vyos.net

  • time2.vyos.net

  • time3.vyos.net

set service ntp server <address> <noselect | nts | pool | prefer | ptp | interleave>

Configurez un ou plusieurs attributs pour le serveur NTP donné.

  • noselect marque le serveur comme non utilisé, sauf pour des raisons d'affichage. Le serveur est écarté par l'algorithme de sélection.

  • nts active la sécurité du temps réseau (NTS) pour le serveur tel que spécifié dans RFC 8915

  • pool mobilise le mode client persistant avec un nombre de serveurs distants.

  • prefer marque le serveur comme préféré. Toutes choses étant égales par ailleurs, cet hôte sera choisi pour la synchronisation parmi un ensemble d'hôtes correctement opérationnels.

  • ptp active le transport PTP pour ce serveur (voir Transport PTP des paquets NTP).

  • interleave active le mode NTP intercalé (voir draft-ntp-interleaved-modes), ce qui peut améliorer la précision et la stabilité de la synchronisation lorsqu'elle est prise en charge par les deux parties.

set service ntp listen-address <address>

Le processus NTP n'écoute que sur l'adresse IP spécifiée. Vous devez spécifier <address> et éventuellement les clients autorisés. Plusieurs adresses d'écoute pour la même famille IP ne sont plus prises en charge. Une seule adresse IPv4 et une seule adresse IPv6 peuvent être configurées, en utilisant des commandes séparées pour chacune.

set service ntp allow-client address <address>

Liste des réseaux ou adresses de clients autorisés à contacter ce serveur NTP.

Plusieurs réseaux/adresses IP de clients peuvent être configurés.

set service ntp vrf <name>

Spécifiez le nom de l'instance VRF.

set service ntp leap-second [ignore|smear|system|timezone]

Définissez comment gérer les secondes intercalaires.

  • ignore: Aucune correction n'est appliquée à l'horloge pour la seconde intercalaire. L'horloge sera corrigée ultérieurement pendant l'exploitation normale lorsque de nouvelles mesures seront effectuées et que l'écart estimé inclura l'erreur d'une seconde.

  • smear: Lors de la mise en œuvre d'une seconde intercalaire, le statut de la seconde intercalaire est supprimé sur le serveur et le temps servi est corrigé lentement par glissement au lieu de saut. Les clients n'ont pas besoin de configuration particulière car ils ne savent pas qu'il y a une seconde intercalaire et suivent le temps du serveur qui finit par les ramener à UTC. Il faut faire attention à s'assurer qu'ils utilisent uniquement des serveurs NTP qui mettent en œuvre la seconde intercalaire exactement de la même manière pour la synchronisation.

  • system: Lors de l'insertion d'une seconde intercalaire, le noyau fait reculer l'horloge système de une seconde lorsqu'elle atteint 00:00:00 UTC. Lors de la suppression d'une seconde intercalaire, il fait avancer l'horloge de une seconde lorsqu'elle atteint 23:59:59 UTC.

  • timezone: Cette directive spécifie un fuseau horaire dans la base de données de fuseaux horaires du système que chronyd peut utiliser pour déterminer quand aura lieu la prochaine seconde intercalaire et quel est le décalage actuel entre TAI et UTC. Il vérifiera périodiquement si 23:59:59 et 23:59:60 sont des heures valides dans le fuseau horaire. Cela fonctionne normalement avec le fuseau horaire right/UTC qui est le par défaut

Horodatage matériel des paquets NTP

Le démon chrony sur VyOS peut exploiter les capacités matérielles des cartes réseau pour enregistrer le moment exact où les paquets sont reçus sur l'interface, ainsi que le moment où les paquets ont été réellement transmis. Cela offre une meilleure précision et stabilité lorsque le système est chargé, car la file d'attente et le changement de contexte du système d'exploitation peuvent introduire un délai variable entre le moment où le paquet est reçu sur le réseau et le moment où il est traité par le démon NTP.

L'horodatage matériel dépend du support de la carte réseau. Certaines cartes réseau peuvent être configurées pour appliquer des horodatages à tout paquet entrant, tandis que d'autres ne prennent en charge que l'application d'horodatages à des protocoles spécifiques (par exemple, PTP).

Lorsque l'horodatage est activé sur une interface, le comportement par défaut de chrony est d'essayer de configurer l'interface pour n'horodater que les paquets NTP. Si ce mode n'est pas pris en charge, chrony essaiera de le configurer pour horodater tous les paquets. Si aucun des deux modes n'est pris en charge (par exemple, si la carte réseau ne peut horodater que les paquets PTP reçus), chrony utilisera uniquement l'horodatage des paquets transmis, ce qui apporte encore certains bénéfices.

set service ntp timestamp interface <interface>

Configure l'horodatage matériel sur l'interface <interface>. La valeur spéciale all peut également être spécifiée pour activer l'horodatage sur toutes les interfaces qui le supportent.

Configurez le comportement de l'horodatage avec l'option suivante :

  • receive-filter [all|ntp|ptp|none] sélectionne le mode de filtre d'entrée, qui contrôle quels paquets entrants la carte réseau applique des horodatages. Le mode sélectionné doit être pris en charge par la carte réseau, sinon l'horodatage sera désactivé pour l'interface.

Les modes suivants de receive-filter peuvent être sélectionnés :

  • all: Tous les paquets reçus seront horodatés.

  • ntp: Seuls les paquets du protocole NTP seront horodatés.

  • ptp: Seuls les paquets du protocole PTP seront horodatés. Combiné avec le transport PTP pour les paquets NTP, cela peut être utilisé pour tirer parti de l'horodatage matériel sur les cartes réseau qui ne prennent en charge que le mode de filtre PTP.

  • none: Aucun paquet reçu ne sera horodaté. L'horodatage des paquets transmis sera toujours utilisé, si la carte réseau le supporte.

Transport PTP des paquets NTP

Le protocole de temps précis (IEEE 1588) est un protocole de synchronisation de l'heure sur un réseau local qui fournit une synchronisation haute précision de l'heure en exploitant les horloges matérielles des cartes réseau et d'autres éléments réseau. VyOS ne prend pas en charge actuellement le PTP basé sur les normes, qui peut être déployé indépendamment du NTP.

Pour les réseaux composés de VyOS et d'autres systèmes Linux exécutant des versions récentes du démon chrony, les paquets NTP peuvent être « tunnélisés » via PTP. Le NTP sur PTP offre le meilleur des deux mondes, en exploitant le support matériel pour l'horodatage des paquets PTP tout en conservant la flexibilité de configuration et la tolérance aux pannes du NTP.

set service ntp ptp

Active le transport PTP du démon NTP. Le démon NTP écoutera sur le port PTP configuré. Notez qu'un ou plusieurs serveurs doivent être individuellement activés pour PTP avant que le démon ne puisse synchroniser via le transport.

set service ntp ptp port <port>

Configure le port PTP. Par défaut, le port standard 319 est utilisé.
