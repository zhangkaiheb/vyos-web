CGNAT

CGNAT, également connu sous le nom de NAT à grande échelle (LSN), est un type de traduction d'adresses réseau utilisé par les fournisseurs d'accès à Internet (FAI) pour permettre à plusieurs adresses IP privées de partager une seule adresse IP publique. Cette technique aide à économiser l'espace d'adressage IPv4 limité. Le bloc d'adresses 100.64.0.0/10 est réservé à l'utilisation dans le CGNAT

Aperçu

Le CGNAT fonctionne en plaçant un dispositif NAT au sein du réseau du FAI. Ce dispositif traduit les adresses IP privées des réseaux clients vers un petit ensemble d'adresses IP publiques attribuées au FAI. Cela permet à plusieurs clients de partager un plus petit nombre d'adresses IP publiques.

Pas toutes les exigences RFC 6888 sont implémentées dans le CGNAT.

Implémentation des exigences suivantes RFC 6888 :

  • REQ 2 : Un CGN doit avoir un comportement par défaut « pooling d'adresses IP » de « Paired ». Le CGN doit utiliser la même carte d'adresse IP externe pour toutes les sessions associées à la même adresse IP interne, qu'elles soient TCP, UDP, ICMP, autre chose ou une combinaison de différents protocoles.

  • REQ 3 : La fonction CGN ne doit pas avoir de limitations sur la taille ou la continuité du pool d'adresses externes.

  • REQ 4 : Un CGN doit prendre en charge la limitation du nombre de ports externes (ou, de manière équivalente, « identifiants » pour ICMP) qui sont attribués par abonné

Avantages du CGNAT

  • Économie d'adresses IPv4 : Le CGNAT aide à atténuer l'épuisement des adresses IPv4 en permettant à plusieurs clients de partager une seule adresse IP publique.

  • Évolutivité : Les FAI peuvent soutenir plus de clients sans avoir besoin d'une augmentation proportionnelle des adresses IP publiques.

  • Économie de coûts : Réduit les coûts liés à l'acquisition d'adresses IPv4 publiques supplémentaires.

Considérations

  • Problèmes de traçabilité : Étant donné que plusieurs utilisateurs partagent la même adresse IP publique, il peut être difficile de traquer des utilisateurs individuels à des fins de sécurité et légales.

  • Surcharge de performance : Le processus de traduction peut introduire une latence et des goulots d'étranglement de performance, surtout sous haute charge.

  • Compatibilité des applications : Certaines applications et protocoles peuvent ne pas fonctionner correctement avec le CGNAT en raison de leur dépendance aux adresses IP publiques uniques.

  • Limits d'allocation de ports : Chaque adresse IP publique a un nombre limité de ports, ce qui peut être épuisé, affectant la capacité à établir de nouvelles connexions.

  • Protocole de contrôle de port : PCP n'est pas implémenté.

Calcul des ports

Lors de la mise en œuvre du CGNAT, il est crucial de s'assurer qu'il y a suffisamment de ports alloués par abonné. Ci-dessous se trouve un résumé basé sur le RFC 6888.

  1. Ports disponibles totaux :

    • Total des ports : 65536 (0 à 65535)

    • Ports réservés : On suppose que 1024 ports sont réservés pour les services bien connus et les objectifs administratifs.

    • Ports utilisables : 65536 - 1024 = 64512

  2. Estimation des ports nécessaires par abonné :

    • Exemple : Une maison pourrait avoir besoin de 1000 ports pour assurer un fonctionnement fluide pour plusieurs appareils et applications.

  3. Calcul du nombre d'abonnés par adresse IP publique :

    • Ports utilisables / Ports par abonné

    • 64512 / 1000 ≈ 64 abonnés par adresse IP publique

Configuration

set nat cgnat pool external <pool-name> external-port-range <port-range>

Définir une plage de ports externes pour le pool externe, la plage par défaut est 1024-65535. Plusieurs entrées peuvent être ajoutées au même pool.

set nat cgnat pool external <pool-name> per-user-limit port <num>

Définir les limites de ports source externes qui seront alloués à chaque abonné individuellement. La valeur par défaut est de 2000.

set nat cgnat pool external <pool-name> range [address | address range | network] [seq]

Définir la plage d'adresses IP externes pour le pool CGNAT. La séquence est facultative ; si elle est définie, une valeur plus faible signifie une priorité plus élevée.

set nat cgnat pool internal <pool-name> range [address range | network]

Définir la plage d'adresses IP internes pour le pool CGNAT.

set nat cgnat rule <num> source pool <internal-pool-name>

Définir la règle pour le pool source.

set nat cgnat rule <num> translation pool <external-pool-name>

Définir la règle pour le pool de traduction.

set nat cgnat log-allocation

Activer le journalisation de l'allocation des adresses IP et des ports.

Exemples de configuration

Adresse externe unique

Exemple de configuration de base CGNAT : Dans l'exemple suivant, nous définissons un pool externe nommé ext-1 avec une adresse IP externe.

Chaque abonné sera alloué un maximum de 2000 ports du pool externe.

set nat cgnat pool external ext1 external-port-range '1024-65535'
set nat cgnat pool external ext1 per-user-limit port '2000'
set nat cgnat pool external ext1 range '192.0.2.222/32'
set nat cgnat pool internal int1 range '100.64.0.0/28'
set nat cgnat rule 10 source pool 'int1'
set nat cgnat rule 10 translation pool 'ext1'

Plusieurs adresses externes

set nat cgnat pool external ext1 external-port-range '1024-65535'
set nat cgnat pool external ext1 per-user-limit port '8000'
set nat cgnat pool external ext1 range '192.0.2.1-192.0.2.2'
set nat cgnat pool external ext1 range '203.0.113.253-203.0.113.254'
set nat cgnat pool internal int1 range '100.64.0.1-100.64.0.32'
set nat cgnat rule 10 source pool 'int1'
set nat cgnat rule 10 translation pool 'ext1'

Séquences d'adresses externes

set nat cgnat pool external ext-01 per-user-limit port '16000'
set nat cgnat pool external ext-01 range 203.0.113.1/32 seq '10'
set nat cgnat pool external ext-01 range 192.0.2.1/32 seq '20'
set nat cgnat pool internal int-01 range '100.64.0.0/29'
set nat cgnat rule 10 source pool 'int-01'
set nat cgnat rule 10 translation pool 'ext-01'

show nat cgnat allocation

show nat cgnat allocation external-address <address>

Afficher toutes les allocations pour une adresse IP publique

show nat cgnat allocation internal-address <address>
