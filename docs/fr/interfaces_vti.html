VTI (interface virtuelle de tunnel)

VTIs vous permettent de créer des tunnels sécurisés et chiffrés entre des réseaux privés ou des hôtes via une infrastructure publique, telle qu'Internet. Elles fonctionnent en parallèle avec un tunnel IPsec sous-jacent, qui gère l'encapsulation et le chiffrement, tandis que les VTIs agissent exclusivement comme interfaces de routage.

Configuration

Configuration commune de l'interface

set interfaces vti <interface> address <address>

Configurez une ou plusieurs adresses IP d'interface.

<address> prend en charge IPv4 et IPv6 en notation CIDR. Par exemple, utilisez 192.0.2.1/24 pour IPv4 ou 2001:db8::1/64 pour IPv6.

Exemple :

set interfaces vti vti0 address 192.0.2.1/24
set interfaces vti vti0 address 2001:db8::1/64
set interfaces vti <interface> description <description>

Configurez un alias clair et descriptif pour l'interface.

Cet alias apparaît dans la commande show interfaces et les outils de surveillance basés sur SNMP.

Exemple :

set interfaces vti vti0 description 'This is an interface running on VyOS.'
set interfaces vti <interface> disable

Désactivez l'interface.

L'interface sera définie à l'état administrativement arrêté (A/D).

Exemple :

set interfaces vti vti0 disable
set interfaces vti <interface> ip adjust-mss <mss | clamp-mss-to-pmtu>

Configurez la taille maximale de segment (MSS) annoncée dans les paquets TCP SYN sortants sur l'interface spécifiée.

En limitant la valeur MSS dans les paquets TCP SYN, vous informez explicitement l'autre extrémité qu'elle ne doit pas envoyer des paquets plus grands que cette taille. Cela évite les problèmes de connexion qui surviennent lorsque la découverte du MTU du chemin (PMTUD) échoue.

Les options suivantes sont disponibles :

  • mss : Définit la MSS à une valeur spécifique, en octets. Utilisez cette option si vous avez besoin d'imposer une MSS spécifique, par exemple pour résoudre des problèmes de connectivité ou satisfaire des exigences réseau spécifiques.

  • clamp-mss-to-pmtu : Le routeur calcule automatiquement la MSS à être la MTU de l'interface moins 40 octets pour le trafic IPv4 (20 octets pour l'en-tête IPv4 et 20 octets pour l'en-tête TCP). Cette option est recommandée pour définir automatiquement la bonne valeur.

set interfaces vti <interface> ip arp-cache-timeout

Configurez pendant combien de temps un enregistrement ARP reste valide après avoir appris une correspondance IP-MAC sur cette interface.

La durée par défaut est de 30 secondes.

Un enregistrement ARP reste valide s'il reçoit un feedback positif des protocoles de niveau supérieur.

Exemple :

set interfaces vti vti0 ip arp-cache-timeout 180
set interfaces vti <interface> ip disable-arp-filter

Configurez le filtrage ARP sur cette interface.

Comportement par défaut : Le noyau répond aux demandes ARP sur cette interface uniquement si le trafic serait routé de retour à l'expéditeur ARP via cette interface spécifique.

Si configuré : Le noyau répond aux demandes ARP sur cette interface pour toute adresse IP configurée sur l'hôte local, indépendamment de l'interface spécifique à laquelle cette adresse IP est assignée, et indépendamment de la table de routage. Cela reflète le concept Linux selon lequel les adresses IP appartiennent à l'hôte, et non à des interfaces individuelles.

Exemple :

set interfaces vti vti0 ip disable-arp-filter
set interfaces vti <interface> ip disable-forwarding

Configurez le comportement de l'interface en tant qu'hôte ou routeur.

Si configuré, l'interface passe en mode hôte, et le transfert IPv4 est désactivé sur celle-ci.

Exemple :

set interfaces vti vti0 ip disable-forwarding
set interfaces vti <interface> ip enable-directed-broadcast

Configurez si les paquets broadcast directs IP reçus sur cette interface doivent être transmis.

Comportement par défaut : Les paquets broadcast directs IP sont supprimés.

Si configuré : Les paquets broadcast directs IP sont transmis à tous les hôtes du sous-réseau de destination, conformément à RFC 1812 et RFC 2644.

Exemple :

set interfaces vti vti0 ip enable-directed-broadcast
set interfaces vti <interface> ip enable-arp-accept

Configurez comment traiter les ARPs gratuit sur cette interface.

Si configuré, une correspondance IP-MAC est ajoutée au tableau ARP en fonction des demandes ou réponses ARP gratuit.

Note

Si le tableau ARP contient déjà l'adresse IP provenant d'un ARP gratuit, son entrée est mise à jour, indépendamment de la configuration de ce paramètre.

Exemple :

set interfaces vti vti0 ip enable-arp-accept
set interfaces vti <interface> ip enable-arp-announce

Configurez la sélection de l'adresse IP source pour les demandes ARP sur cette interface.

Comportement par défaut : Le noyau peut utiliser n'importe quelle adresse IP possédée par l'hôte comme adresse IP source dans les demandes ARP sur cette interface.

Si configuré : Le noyau essaie d'abord de sélectionner une adresse IP source configurée sur l'interface partageant un sous-réseau commun avec l'adresse IP cible. Si aucun tel sous-réseau n'existe, le noyau sélectionne l'adresse IP qu'il utiliserait normalement (basée sur la table de routage pour atteindre la destination cible).

Exemple :

set interfaces vti vti0 ip enable-arp-announce
set interfaces vti <interface> ip enable-arp-ignore

Configurez quels types de demandes ARP seront ignorées sur cette interface.

Comportement par défaut : Le noyau répond aux demandes ARP pour toutes les adresses IP locales, indépendamment de l'interface à laquelle elles sont assignées.

Si configuré : Le noyau répond aux demandes ARP uniquement si l'adresse IP cible est assignée à cette interface spécifique.

Exemple :

set interfaces vti vti0 ip enable-arp-ignore
set interfaces vti <interface> ip enable-proxy-arp

Configurez le proxy ARP sur cette interface.

Si configuré, le routeur (noyau) intercepte les demandes ARP pour des adresses IP non locales et répond avec l'adresse MAC de l'interface qui a reçu la demande. Les paquets suivants destinés à ces adresses IP sont ensuite transmis vers leurs destinations réelles sur des sous-réseaux distants.

Exemple :

set interfaces vti vti0 ip enable-proxy-arp
set interfaces vti <interface> ip proxy-arp-pvlan

Configurez le proxy ARP local sur l'interface.

Si configuré, le routeur (noyau) répond aux demandes ARP sur cette interface VLAN même si l'adresse IP cible se trouve sur le même sous-réseau et interface.

Cela est utilisé pour soutenir les exigences d'isolation réseau (RFC 3069) pour les VLAN privés (PVLANs). Dans les configurations PVLAN, les hôtes sur des ports isolés ne sont PAS autorisés à communiquer directement entre eux au niveau 2, mais ils peuvent communiquer avec le routeur supérieur.

En répondant aux demandes ARP inter-hôtes avec sa propre adresse MAC, le routeur (noyau) dirige le trafic inter-hôtes à travers lui-même plutôt que directement entre les hôtes.

Note

Cette commande fonctionne indépendamment et n'a pas besoin d'activer le proxy ARP standard sur l'interface.

Le proxy ARP local est également connu sous les noms suivants :

  • Aggrégation de VLAN (RFC 3069).

  • VLAN privé (Cisco, Allied Telesyn).

  • Filtrage de port source ou isolation de port (Hewlett-Packard).

  • Transfert forcé MAC (Ericsson).

set interfaces vti <interface> ip source-validation <strict | loose | disable>

Configurez la validation de l'adresse IP source à l'aide de RPF sur cette interface, comme spécifié dans RFC 3704.

Les options suivantes sont disponibles :

  • strict : Chaque paquet entrant est vérifié pour son adresse IP source contre la base de données de routage (FIB). Si l'interface n'est pas le meilleur chemin de retour vers cette source, la validation échoue et le paquet est supprimé.

  • loose : Chaque paquet entrant est vérifié pour son adresse IP source contre la base de données de routage (FIB). Si l'adresse IP source est inatteignable via n'importe quelle interface, la validation échoue.

  • disable : Aucune validation d'adresse IP source n'est effectuée. Tous les paquets entrants sont acceptés.

Le RFC 3704 recommande d'activer le mode strict pour empêcher le spoofing d'IP, comme les attaques DDoS. Pour les scénarios de routage asymétrique ou autres scénarios complexes, utilisez le mode loose.

set interfaces vti <interface> ipv6 address autoconf

Configurez l'interface pour obtenir automatiquement une adresse IPv6 à l'aide de SLAAC, comme spécifié dans RFC 4862.

Les hôtes IPv6 peuvent se configurer automatiquement lorsqu'ils sont connectés à un réseau IPv6 à l'aide du protocole de découverte des voisins via les messages ICMPv6 de découverte de routeur. Lorsqu'ils se connectent pour la première fois à un réseau, un hôte envoie une requête multicast de sollicitation de routeur link-local pour ses paramètres de configuration. Le routeur répond avec un paquet d'annonce de routeur contenant les paramètres de configuration du niveau Internet.

Note

Cette méthode désactive automatiquement le transfert de trafic IPv6 sur l'interface.

Exemple :

set interfaces vti vti0 ipv6 address autoconf
set interfaces vti <interface> ipv6 address eui64 <prefix>

Configurez l'interface pour lui attribuer une adresse IPv6 à l'aide de la méthode EUI-64 , comme spécifié dans RFC 4291.

Exemple :

set interfaces vti vti0 ipv6 address eui64 2001:db8:beef::/64
set interfaces vti <interface> ipv6 address no-default-link-local

Désactivez l'attribution automatique d'une adresse IPv6 link-local à cette interface.

Exemple :

set interfaces vti vti0 ipv6 address no-default-link-local
set interfaces vti <interface> ipv6 disable-forwarding

Configurez le comportement de l'interface en tant qu'hôte ou routeur.

Si configuré, l'interface passe en mode hôte, et le transfert IPv6 est désactivé sur celle-ci.

Exemple :

set interfaces vti vti0 ipv6 disable-forwarding
set interfaces vti <interface> ipv6 adjust-mss <mss | clamp-mss-to-pmtu>

Configurez la taille maximale de segment (MSS) annoncée dans les paquets TCP SYN sortants sur l'interface spécifiée.

En limitant la valeur MSS dans les paquets TCP SYN, vous informez explicitement l'autre extrémité qu'elle ne doit pas envoyer des paquets plus grands que cette taille. Cela évite les problèmes de connexion lorsque la découverte du MTU du chemin (PMTUD) échoue.

Les options suivantes sont disponibles :

  • mss : Définissez la MSS à une valeur spécifique, en octets. Utilisez cette option pour imposer une MSS spécifique, par exemple pour résoudre des problèmes de connectivité ou satisfaire des exigences réseau spécifiques.

  • clamp-mss-to-pmtu : Le routeur calcule la MSS à être la MTU de l'interface moins 60 octets pour le trafic IPv6 (40 octets pour l'en-tête IPv6 et 20 octets pour l'en-tête TCP). Cette option est recommandée pour définir automatiquement la bonne valeur.

set interfaces vti <interface> ipv6 accept-dad <0 | 1 | 2>

Configurez le DAD IPv6 sur l'interface.

Les options suivantes sont disponibles :

  • 0 : Désactive le DAD. Aucune détection d'adresse dupliquée n'est effectuée.

  • 1 : Active le DAD (par défaut). Les adresses dupliquées sont détectées. L'opération IPv6 de l'interface continue pour les adresses IPv6 valides.

  • 2 : Active le DAD et, si une adresse link-local dupliquée basée sur le MAC est trouvée, désactive l'opération IPv6 sur cette interface.

Exemple :

set interfaces vti vti0 ipv6 accept-dad 2
set interfaces vti <interface> ipv6 dup-addr-detect-transmits <n>

Configurez le nombre de messages DAD que le routeur (noyau) envoie pendant l'attribution d'adresse IPv6 sur cette interface.

La valeur par défaut est 1.

Exemple :

set interfaces vti vti0 ipv6 dup-addr-detect-transmits 5
set interfaces vti <interface> mtu <mtu>

Configurez le MTU sur l'interface.

Cette valeur définit la taille maximale de paquet, en octets, que l'interface transmet sans fragmentation.

Exemple :

set interfaces vti vti0 mtu 1600
set interfaces vti <interface> mirror egress <monitor-interface>

Configurez le miroir du trafic sortant depuis l'interface VTI spécifiée vers l'interface de surveillance désignée.

set interfaces vti <interface> mirror ingress <monitor-interface>

Configurez le miroir du trafic entrant depuis l'interface VTI spécifiée vers l'interface de surveillance désignée.

set interfaces vti <interface> redirect <interface>

Activez le redimensionnement des paquets entrants vers l'interface spécifiée.

set interfaces vti <interface> vrf <vrf>

Affectez l'interface à une instance spécifique de VRF .

Voir aussi

Pour plus d'informations sur la configuration d'un VRF, consultez la section VRF.

Exemple :

set interfaces vti vti0 vrf red

Opération

show interfaces vti <vtiX>

Affichez l'état opérationnel et les statistiques de trafic pour le VTI spécifié.

show interfaces vti <vtiX> brief

Affichez un résumé de l'état opérationnel pour le VTI spécifié.

Exemple

Configurer un VTI

Affectez des adresses IPv4 et IPv6 au VTI, ainsi qu'une brève description :

set interfaces vti vti0 address 192.168.2.249/30
set interfaces vti vti0 address 2001:db8:2::249/64
set interfaces vti vti0 description "Description"

Résultat de la configuration :

vyos@vyos# show interfaces vti
vti vti0 {
    address 192.168.2.249/30
    address 2001:db8:2::249/64
    description "Description"
}

Avertissement

Lors de la configuration d'un IPsec site-to-site avec des VTIs, assurez-vous que l'installation automatique de route est désactivée.

set vpn ipsec options disable-route-autoinstall

Pour plus d'informations sur le problème IPsec et VTI, ainsi que sur l'option disable-route-autoinstall, voir : https://blog.vyos.io/vyos-1-dot-2-0-development-news-in-july.

La cause principale du problème est que les tunnels VTI nécessitent que leurs sélecteurs de trafic soient définis sur 0.0.0.0/0 pour que le trafic corresponde au tunnel, même si les décisions de routage sont basées sur les marques netfilter. À moins que l'insertion de route ne soit explicitement désactivée, strongSWAN insère incorrectement une route par défaut via l'adresse du pair VTI, entraînant un routage erroné de tout le trafic.
