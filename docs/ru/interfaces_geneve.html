Geneve

Geneve интерфейсы работают как виртуальные сетевые порты. Администраторы могут применять стандартные сетевые настройки к ним, такие как IP-адресация, мосты или правила брандмауэра, так же, как и на физических Ethernet-портах.

Протокол Geneve инкапсулирует слои 2 Ethernet-фреймов, исходящих от конечных точек, таких как виртуальные машины, контейнеры или физические серверы, внутри UDP-пакетов. Он объединяет функции более ранних протоколов инкапсуляции, включая VXLAN, NVGRE и STT, и решает их ограничения, такие как фиксированные структуры заголовков и отсутствие поддержки метаданных. Благодаря своей расширяемости Geneve может в будущем заменить эти более старые протоколы.

Geneve-туннели используются для соединения виртуальных коммутаторов, находящихся внутри гипервизоров, физических коммутаторов, промежуточных устройств и других сетевых устройств.

Geneve-туннели работают над любыми стандартными IP-сетями. В крупных развертываниях подложная сеть (underlay) часто строится с использованием топологии Clos, также известной как leaf-and-spine или fat-tree топология.

Конфигурация

Общая конфигурация интерфейса

set interfaces geneve <interface> address <address>

Настройте один или несколько IP-адресов интерфейса.

<address> поддерживает IPv4 и IPv6 в формате CIDR. Например, используйте 192.0.2.1/24 для IPv4 или 2001:db8::1/64 для IPv6.

Пример:

set interfaces geneve gnv0 address 192.0.2.1/24
set interfaces geneve gnv0 address 2001:db8::1/64
set interfaces geneve <interface> description <description>

Настройте ясное и описательное имя для интерфейса.

Это имя появляется в команде show interfaces и средствах мониторинга на основе SNMP.

Пример:

set interfaces geneve gnv0 description 'This is an interface running on VyOS.'
set interfaces geneve <interface> disable

Отключите интерфейс.

Интерфейс будет установлен в состояние административно выключенное (A/D).

Пример:

set interfaces geneve gnv0 disable
set interfaces geneve <interface> mac <xx:xx:xx:xx:xx:xx>

Настройте пользовательский MAC-адрес на интерфейсе.

Пример:

set interfaces geneve gnv0 mac '00:53:01:02:03:04'
set interfaces geneve <interface> mtu <mtu>

Настройте MTU на интерфейсе.

Это значение определяет максимальный размер пакета, в байтах, который интерфейс передает без фрагментации.

Пример:

set interfaces geneve gnv0 mtu 1600
set interfaces geneve <interface> ip adjust-mss <mss | clamp-mss-to-pmtu>

Настройте MSS , объявляемый в исходящих TCP SYN-пакетах на указанном интерфейсе.

При ограничении значения MSS в TCP SYN-пакетах вы явно информируете удаленную сторону не отправлять пакеты большего размера. Это предотвращает проблемы с подключением, которые возникают при сбое обнаружения PMTUD.

Доступны следующие варианты:

  • mss: Устанавливает MSS в конкретное значение, в байтах. Используйте этот вариант, если вам нужно принудительно установить конкретное значение MSS, например, для устранения проблем с подключением или соответствия требованиям сети.

  • clamp-mss-to-pmtu: Роутер автоматически рассчитывает MSS, равный MTU интерфейса минус 40 байтов для IPv4 (20 байтов для заголовка IPv4 и 20 байтов для заголовка TCP). Этот вариант рекомендуется для автоматической установки правильного значения.

set interfaces geneve <interface> ip arp-cache-timeout

Настройте, как долго ARP-запись остается действительной после получения сопоставления IP-адреса и MAC-адреса на этом интерфейсе.

По умолчанию длительность составляет 30 секунд.

ARP-запись остается действительной, если она получает положительный ответ от вышеуказанных протоколов.

Пример:

set interfaces geneve gnv0 ip arp-cache-timeout 180
set interfaces geneve <interface> ip disable-arp-filter

Настройте фильтрацию ARP на этом интерфейсе.

Поведение по умолчанию: Ядро отвечает на запросы ARP на этом интерфейсе только в том случае, если трафик будет маршрутизирован обратно к отправителю ARP через этот конкретный интерфейс.

Если настроено: Ядро отвечает на запросы ARP на этом интерфейсе для любого IP-адреса, настроенного на локальном хосте, независимо от того, какой конкретный интерфейс этот IP-адрес назначен, и независимо от таблицы маршрутизации. Это отражает концепцию Linux, что IP-адреса принадлежат хосту, а не отдельным интерфейсам.

Пример:

set interfaces geneve gnv0 ip disable-arp-filter
set interfaces geneve <interface> ip disable-forwarding

Настройте интерфейс на работу в режиме хоста или роутера.

Если настроено, интерфейс переключается в режим хоста, и IPv4-маршрутизация отключается на нем.

Пример:

set interfaces geneve gnv0 ip disable-forwarding
set interfaces geneve <interface> ip enable-directed-broadcast

Настройте, будут ли передаваться IP-направленные широковещательные пакеты, полученные на этом интерфейсе.

Поведение по умолчанию: IP-направленные широковещательные пакеты отбрасываются.

Если настроено: IP-направленные широковещательные пакеты передаются всем хостам на подсети назначения, как определено в RFC 1812 и RFC 2644.

Пример:

set interfaces geneve gnv0 ip enable-directed-broadcast
set interfaces geneve <interface> ip enable-arp-accept

Настройте, как обрабатывать бесплатные ARP на этом интерфейсе.

Если настроено, сопоставление IP-адреса и MAC-адреса добавляется в таблицу ARP на основе бесплатных ARP-запросов или ответов.

Примечание

Если таблица ARP уже содержит IP-адрес из бесплатного ARP, его запись обновляется независимо от того, настроено ли это настройство.

Пример:

set interfaces geneve gnv0 ip enable-arp-accept
set interfaces geneve <interface> ip enable-arp-announce

Настройте выбор источника IP-адреса для ARP-запросов на этом интерфейсе.

Поведение по умолчанию: Ядро может использовать любой IP-адрес, которым владеет хост, как источник IP-адреса в ARP-запросах на этом интерфейсе.

Если настроено: Ядро сначала пытается выбрать источник IP-адреса, настроенный на интерфейсе, который имеет общую подсеть с целевым IP-адресом. Если такой подсети нет, ядро выбирает IP-адрес, который оно обычно использует (на основе таблицы маршрутизации для достижения целевой цели).

Пример:

set interfaces geneve gnv0 ip enable-arp-announce
set interfaces geneve <interface> ip enable-arp-ignore

Настройте, какие ARP-запросы будут игнорироваться на этом интерфейсе.

Поведение по умолчанию: Ядро отвечает на ARP-запросы для любых локальных IP-адресов, независимо от того, к какому интерфейсу они относятся.

Если настроено: Ядро отвечает на ARP-запросы только в том случае, если целевой IP-адрес назначен этому конкретному интерфейсу.

Пример:

set interfaces geneve gnv0 ip enable-arp-ignore
set interfaces geneve <interface> ip enable-proxy-arp

Настройте proxy ARP на этом интерфейсе.

Если настроено, роутер (ядро) перехватывает ARP-запросы для нелокальных IP-адресов и отвечает MAC-адресом интерфейса, получившего запрос. Последующие пакеты, предназначенные этим IP-адресам, передаются на их фактические цели на удаленных подсетях.

Пример:

set interfaces geneve gnv0 ip enable-proxy-arp
set interfaces geneve <interface> ip proxy-arp-pvlan

Настройте локальный proxy ARP на интерфейсе.

Если настроено, роутер (ядро) отвечает на ARP-запросы на этом VLAN-интерфейсе даже если целевой IP-адрес находится на той же подсети и интерфейсе.

Это используется для поддержки требований к изоляции сети (RFC 3069) для частных VLAN (PVLAN). В конфигурациях PVLAN, хосты на изолированных портах НЕ разрешены к прямой коммуникации между собой на уровне 2, но они могут общаться с верхним роутером.

Посредством ответа на ARP-запросы между хостами своим собственным MAC адресом, роутер (ядро) направляет трафик между хостами через себя вместо прямой передачи между хостами.

Примечание

Эта команда работает независимо и не требует включения стандартного proxy ARP на интерфейсе.

Локальный proxy ARP также известен как:

  • VLAN-агрегация (RFC 3069).

  • Частный VLAN (Cisco, Allied Telesyn).

  • Фильтрация по порту или изоляция порта (Hewlett-Packard).

  • Перенаправление MAC (Ericsson).

set interfaces geneve <interface> ip source-validation <strict | loose | disable>

Настройте проверку исходного IP-адреса с помощью RPF на этом интерфейсе, как указано в RFC 3704.

Доступны следующие варианты:

  • strict: Каждый входящий пакет проверяется на соответствие FIB (Forwarding Information Base). Если интерфейс не является лучшим маршрутом обратно к этому источнику, проверка не проходит, и пакет удаляется.

  • loose: Каждый входящий пакет проверяется на соответствие FIB. Если исходный IP-адрес недоступен через любой интерфейс, проверка не проходит.

  • disable: Проверка исходного IP-адреса не выполняется. Все входящие пакеты принимаются.

RFC 3704 рекомендует включить строгий режим для предотвращения подделки IP-адресов, например, DDoS-атак. Для асимметричных или других сложных сценариев маршрутизации используйте режим loose.

set interfaces geneve <interface> ipv6 address autoconf

Настройте интерфейс для автоматического получения IPv6-адреса с помощью SLAAC, как указано в RFC 4862.

Хосты IPv6 могут автоматически настраивать себя, когда подключены к IPv6-сети с помощью протокола Neighbor Discovery через ICMPv6 сообщения о маршрутизаторе. При первом подключении к сети хост отправляет многоадресный запрос на маршрутизатор для получения параметров конфигурации. Маршрутизатор отвечает пакетом рекламы маршрутизатора, содержащим параметры конфигурации уровня интернета.

Примечание

Этот метод автоматически отключает передачу IPv6 на интерфейсе.

Пример:

set interfaces geneve gnv0 ipv6 address autoconf
set interfaces geneve <interface> ipv6 address eui64 <prefix>

Настройте интерфейс для присвоения себе IPv6-адреса с помощью метода EUI-64 , как указано в RFC 4291.

Пример:

set interfaces geneve gnv0 ipv6 address eui64 2001:db8:beef::/64
set interfaces geneve <interface> ipv6 address no-default-link-local

Отключите автоматическое присвоение ссылочного IPv6-адреса этому интерфейсу.

Пример:

set interfaces geneve gnv0 ipv6 address no-default-link-local
set interfaces geneve <interface> ipv6 disable-forwarding

Настройте интерфейс на работу в режиме хоста или роутера.

Если настроено, интерфейс переключается в режим хоста, и IPv6-маршрутизация отключается на нем.

Пример:

set interfaces geneve gnv0 ipv6 disable-forwarding
set interfaces geneve <interface> ipv6 adjust-mss <mss | clamp-mss-to-pmtu>

Настройте MSS , объявляемый в исходящих TCP SYN-пакетах на указанном интерфейсе.

При ограничении значения MSS в TCP SYN-пакетах вы явно информируете удаленную сторону не отправлять пакеты большего размера. Это предотвращает проблемы с подключением, когда обнаружение PMTUD не удается.

Доступны следующие варианты:

  • mss: Установите MSS в конкретное значение, в байтах. Используйте этот вариант, чтобы принудительно установить конкретное значение MSS, например, для устранения проблем с подключением или соответствия требованиям сети.

  • clamp-mss-to-pmtu: Роутер рассчитывает MSS, равный MTU интерфейса минус 60 байтов для IPv6 (40 байтов для заголовка IPv6 и 20 байтов для заголовка TCP). Этот вариант рекомендуется для автоматической установки правильного значения.

set interfaces geneve <interface> ipv6 accept-dad <0 | 1 | 2>

Настройте IPv6 DAD на интерфейсе.

Доступны следующие варианты:

  • 0: Отключает DAD. Не производится обнаружение дублирующих адресов.

  • 1: Включает DAD (по умолчанию). Обнаруживаются дублирующиеся адреса. Операция IPv6 интерфейса продолжается для корректных IPv6-адресов.

  • 2: Включает DAD и, если найден дублирующийся MAC-адрес локальной подсети, отключает операцию IPv6 на этом интерфейсе.

Пример:

set interfaces geneve gnv0 ipv6 accept-dad 2
set interfaces geneve gnv0 remote <address>

Настройте IP-адрес удаленной точки для Geneve-туннеля.

set interfaces geneve gnv0 vni <vni>

Настройте VNI для Geneve интерфейса.

VNI — это идентификатор виртуальной сети. Он позволяет нескольким виртуальным сетям разделять одну физическую инфраструктуру и оставаться изолированными.

VNI также используется для распределения трафика после выхода из туннеля, например, для сопоставления пакетов с перекрывающимися IP-адресами с конкретными таблицами маршрутизации.

set interfaces gnv0 <interface> port <port>

Настройте порт UDP назначения для удаленного конца Geneve-туннеля. Убедитесь, что удаленный узел настроен на прослушивание этого конкретного порта.
