RIP

Разработан в 1970-х годах в лаборатории Xerox, RIP — это протокол маршрутизации на основе вектора расстояния, основанный на алгоритме Беллмана-Форда.

RIP определяет лучший маршрут на основе количества промежуточных узлов (количества маршрутизаторов, через которые проходит путь). Маршрутизаторы, поддерживающие RIP, периодически объявляют свою всю таблицу маршрутизации соседям, а также метрику (количество промежуточных узлов) для каждого назначения.

Поддерживаемые версии:

  • RIPv1: как описано в RFC 1058

  • RIPv2: как описано в RFC 2453

Общая конфигурация

set protocols rip network <A.B.C.D/M>

Включить RIP на всех интерфейсах, IP-адреса которых находятся в указанной сети.

Пример:

set protocols rip network 192.0.2.0/24
set protocols rip interface <interface>

Включить RIP на указанном интерфейсе.

После применения интерфейс отправляет и получает пакеты RIP.

Пример:

set protocols rip interface eth0
set protocols rip neighbor <A.B.C.D>

Настроить соседа RIP с использованием его IP-адреса.

Используйте эту команду, когда сосед не может обрабатывать многоадресные обновления RIP. После настройки локальный маршрутизатор отправляет обновления напрямую указанному соседу в виде одноадресных пакетов.

Пример:

set protocols rip neighbor 192.0.2.2
set protocols rip passive-interface <interface>

Включить пассивный режим для указанного интерфейса.

Это предотвращает отправку исходящих обновлений RIP на интерфейсе, за исключением явно настроенных соседей. Входящие обновления RIP все еще принимаются и обрабатываются.

Пример:

set protocols rip passive-interface eth0
set protocols rip passive-interface default

Включить пассивный режим для всех интерфейсов.

Это предотвращает отправку исходящих обновлений RIP на всех интерфейсах, за исключением явно настроенных соседей. Маршрутизатор по-прежнему получает и обрабатывает входящие обновления RIP в обычном порядке.

Пример:

set protocols rip passive-interface default

Дополнительная конфигурация

set protocols rip default-distance <1-255>

Настроить административное расстояние для всех маршрутов, изученных через RIP.

Административное расстояние определяет, как маршруты, изученные через RIP, приоритизируются относительно маршрутов, изученных из других источников (например, BGP, OSPF или статических маршрутов), когда существует несколько путей к одному и тому же назначению.

Примечание

Маршруты, которым присвоено расстояние 255, отключены и не будут установлены в таблице маршрутизации ядра.

Пример:

set protocols rip default-distance 100
set protocols rip network-distance <A.B.C.D/M> distance <1-255>

Настроить административное расстояние для маршрутов RIP, чей адрес источника находится в указанной сети.

Пример:

set protocols rip network-distance 192.0.2.0/24 distance 80
set protocols rip network-distance <A.B.C.D/M> access-list <name>

Ограничить назначение административных расстояний для маршрутов RIP, чей адрес источника соответствует указанной сети и сам маршрут соответствует указанному списку доступа.

Пример:

set protocols rip network-distance 192.0.2.0/24 distance 80
set protocols rip network-distance 192.0.2.0/24 access-list 10
set protocols rip default-information originate

Создать и объявить маршрут по умолчанию (0.0.0.0/0) всем соседям RIP.

Пример:

set protocols rip default-information originate
set protocols rip distribute-list access-list <in|out> <0-4294967295>

Применить список доступа для фильтрации маршрутов RIP в направлении входящего или исходящего.

  • in: Фильтрует маршруты, полученные от соседей RIP.

  • out: Фильтрует маршруты, объявленные соседям RIP.

Пример:

set protocols rip distribute-list access-list in 20
set protocols rip distribute-list interface <interface> access-list <in|out> <0-4294967295>

Применить список доступа для фильтрации маршрутов RIP в направлении входящего или исходящего на указанном интерфейсе.

  • in: Фильтрует маршруты, полученные от соседей RIP на этом интерфейсе.

  • out: Фильтрует маршруты, объявленные соседям RIP на этом интерфейсе.

Пример:

set protocols rip distribute-list interface eth0 access-list in 20
set protocols rip distribute-list prefix-list <in|out> <name>

Применить префикс-лист для фильтрации маршрутов RIP в направлении входящего или исходящего.

  • in: Фильтрует маршруты, полученные от соседей RIP.

  • out: Фильтрует маршруты, объявленные соседям RIP.

Пример:

set protocols rip distribute-list prefix-list in INBOUND-FILTER
set protocols rip distribute-list interface <interface> prefix-list <in|out> <name>

Применить префикс-лист для фильтрации маршрутов RIP на указанном интерфейсе в направлении входящего или исходящего.

  • in: Фильтрует маршруты, полученные от соседей RIP на этом интерфейсе.

  • out: Фильтрует маршруты, объявленные соседям RIP на этом интерфейсе.

Пример:

set protocols rip distribute-list interface eth0 prefix-list in RIP-IN
set protocols rip route <A.B.C.D/M>

Добавить статический маршрут в процесс маршрутизации RIP.

Маршрут создается только внутри RIP.

Эта команда специфична для FRR и VyOS и должна использоваться только продвинутыми пользователями, имеющими глубокое понимание протокола RIP.

Для большинства развертываний рекомендуется создать обычный статический маршрут и перераспределить его в RIP с помощью set protocols rip redistribute static.

Пример:

set protocols rip route 192.0.2.0/24
set protocols rip timers update <5-2147483647>

Настроить таймер обновления RIP, в секундах.

Таймер обновления определяет, как часто маршрутизатор отправляет неожиданные сообщения ответа своим соседям RIP. Каждый ответ содержит полную таблицу маршрутизации RIP.

Значение по умолчанию — 30 секунд.

Пример:

set protocols rip timers update 60
set protocols rip timers timeout <5-2147483647>

Настроить таймер истечения времени действия маршрута RIP, в секундах.

Если маршрут не обновляется входящим обновлением в течение этого интервала, он становится недействительным. Маршрутизатор временно сохраняет недействительный маршрут в таблице маршрутизации RIP, чтобы соседи узнали, что маршрут был удален.

Значение по умолчанию — 180 секунд.

Пример:

set protocols rip timers timeout 300
set protocols rip timers garbage-collection <5-2147483647>

Настроить таймер сбора мусора RIP, в секундах.

Этот таймер начинает работать, когда маршрут становится недействительным. Когда таймер истекает, маршрут удаляется из таблицы маршрутизации.

Значение по умолчанию — 120 секунд.

Пример:

set protocols rip timers garbage-collection 60

Конфигурация перераспределения

set protocols rip redistribute <babel|bgp|connected|isis|kernel|nhrp|ospf|static>

Перераспределить маршруты из указанного источника в RIP.

Маршруты, изученные из выбранного источника, импортируются в таблицу маршрутизации RIP и объявляются соседям RIP, как если бы они были изучены через RIP.

Поддерживаемые источники:

  • babel: Маршруты, изученные через Babel.

  • bgp: Маршруты, изученные через BGP.

  • connected: Непосредственно подключенные маршруты.

  • isis: Маршруты, изученные через IS-IS.

  • kernel: Маршруты, установленные в таблице маршрутизации ядра.

  • nhrp: Маршруты, изученные через NHRP.

  • ospf: Маршруты, изученные через OSPF.

  • static: Статические маршруты.

Пример:

set protocols rip redistribute static
set protocols rip redistribute <babel|bgp|connected|isis|kernel|nhrp|ospf|static> metric <1-16>

Настроить метрику для маршрутов, перераспределенных из указанного источника.

Пример:

set protocols rip redistribute static metric 5
set protocols rip redistribute <babel|bgp|connected|isis|kernel|nhrp|ospf|static> route-map <name>

Применить маршрут-карту для фильтрации маршрутов, перераспределенных из указанного источника.

Пример:

set protocols rip redistribute static route-map RIP-REDISTRIBUTE
set protocols rip default-metric <1-16>

Настроить значение метрики по умолчанию (количество промежуточных узлов) для перераспределенных маршрутов.

Значение по умолчанию — 1.

Примечание

Эта команда не влияет на прямые маршруты, перераспределенные через set protocols rip redistribute connected. Чтобы настроить метрику для прямых маршрутов, используйте set protocols rip redistribute connected metric явно.

Пример:

set protocols rip default-metric 5

Конфигурация интерфейсов

set protocols rip interface <interface> authentication plaintext-password <text>

Включить простую аутентификацию паролем для RIPv2 на указанном интерфейсе и установить пароль.

Пароль не должен превышать 16 символов.

Пример:

set protocols rip interface eth0 authentication plaintext-password vyos-secret
set protocols rip interface <interface> authentication md5 <id> password <text>

Включить аутентификацию MD5 для RIPv2 на указанном интерфейсе и установить ключ MD5.

Ключ MD5 не должен превышать 16 символов.

Пример:

set protocols rip interface eth0 authentication md5 1 password vyos-secret
set protocols rip interface <interface> split-horizon disable

Отключить разделение горизонта на указанном интерфейсе.

По умолчанию VyOS не объявляет маршруты RIP обратно через интерфейс, на котором они были изучены (разделение горизонта). Эта команда отключает это поведение по умолчанию.

Пример:

set protocols rip interface eth0 split-horizon disable
set protocols rip interface <interface> split-horizon poison-reverse

Включить разделение горизонта с обратной помойкой на указанном интерфейсе.

Если включено, маршрутизатор объявляет изученные маршруты как недоступные на интерфейсе, на котором они были изучены.

Пример:

set protocols rip interface eth0 split-horizon poison-reverse

Пример

Следующий пример демонстрирует базовую конфигурацию RIP между двумя маршрутизаторами, где непосредственно подключенные сети перераспределяются в RIP.

Узел 1:

set interfaces ethernet eth0 address '198.51.100.1/24'
set interfaces loopback lo address '192.0.2.1/32'
set protocols rip network 198.51.100.0/24
set protocols rip redistribute connected

Узел 2:

set interfaces ethernet eth0 address '198.51.100.2/24'
set interfaces loopback lo address '192.0.2.2/32'
set protocols rip network 198.51.100.0/24
set protocols rip redistribute connected
