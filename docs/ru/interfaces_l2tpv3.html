L2TPv3

L2TPv3 интерфейсы позволяют установить L2TPv3 туннели для передачи сетевого уровня 2 через IP сети.

Протокол L2TPv3 (определён в RFC 3931) оборачивает кадры уровня 2 (например, Ethernet, Frame Relay, HDLC) внутри IP пакетов, позволяя им проходить через базовую IP инфраструктуру.

В отличие от L2TPv2, который строго требует обертки UDP, протокол L2TPv3 более гибкий и поддерживает два типа обертки:

  • Прямой IP: Данные туннеля упаковываются непосредственно внутри IP пакетов (Протокол 115) для меньшего объема данных.

  • UDP: Данные туннеля упаковываются внутри UDP датаграммы. Это позволяет туннелю легче проходить через NAT.

L2TPv3 туннели соединяют географически разнесенные сайты, служа более простым альтернативным решением по сравнению с MPLS, работая на основе обычного IP соединения вместо требования полной MPLS инфраструктуры.

L2TPv3 туннели могут быть установлены как на IPv4, так и на IPv6 основных сетях.

Конфигурация

Общая конфигурация интерфейса

set interfaces l2tpv3 <interface> address <address>

Настройте одно или несколько IP-адресов интерфейса.

<address> поддерживает IPv4 и IPv6 в формате CIDR. Например, используйте 192.0.2.1/24 для IPv4 или 2001:db8::1/64 для IPv6.

Пример:

set interfaces l2tpv3 l2tpeth0 address 192.0.2.1/24
set interfaces l2tpv3 l2tpeth0 address 2001:db8::1/64
set interfaces l2tpv3 <interface> description <description>

Настройте понятное, описательное имя для интерфейса.

Это имя появляется в команде show interfaces и инструментах мониторинга на основе SNMP.

Пример:

set interfaces l2tpv3 l2tpeth0 description 'Это интерфейс, работающий на VyOS.'
set interfaces l2tpv3 <interface> disable

Отключите интерфейс.

Интерфейс будет установлен в состояние административно выключенное (A/D).

Пример:

set interfaces l2tpv3 l2tpeth0 disable
set interfaces l2tpv3 <interface> disable-flow-control

Отключите управление потоком Ethernet (стандарт IEEE 802.3x pause frames) на интерфейсе.

Управление потоком Ethernet, определенное стандартом IEEE 802.3x, временно прекращает передачу данных, чтобы предотвратить потерю пакетов при перегрузке сети. Например, когда отправитель передает данные быстрее, чем получатель может их обработать.

Отключение управления потоком Ethernet означает, что интерфейс не будет сигнализировать подключенному устройству о паузе передачи и будет отбрасывать пакеты, если перегружен.

Пример:

set interfaces l2tpv3 l2tpeth0 disable-flow-control
set interfaces l2tpv3 <interface> disable-link-detect

Отключите обнаружение изменений состояния физического соединения на интерфейсе, например, когда кабель отсоединен.

По умолчанию интерфейс обнаруживает изменения состояния физического соединения.

Пример:

set interfaces l2tpv3 l2tpeth0 disable-link-detect
set interfaces l2tpv3 <interface> mac <xx:xx:xx:xx:xx:xx>

Настройте пользовательский MAC-адрес на интерфейсе.

Пример:

set interfaces l2tpv3 l2tpeth0 mac '00:53:01:02:03:04'
set interfaces l2tpv3 <interface> mtu <mtu>

Настройте MTU на интерфейсе.

Это значение определяет максимальный размер пакета, в байтах, который интерфейс передает без фрагментации.

Пример:

set interfaces l2tpv3 l2tpeth0 mtu 1600
set interfaces l2tpv3 <interface> ip adjust-mss <mss | clamp-mss-to-pmtu>

Настройте MSS , объявляемый в исходящих TCP SYN пакетах на указанном интерфейсе.

Путем ограничения значения MSS в TCP SYN пакетах, вы явно информируете удаленную сторону, что она не должна отправлять пакеты большего размера. Это предотвращает проблемы с соединением, которые возникают, когда Path MTU Discovery (PMTUD) не работает.

Доступны следующие варианты:

  • mss: Устанавливает MSS на конкретное значение, в байтах. Используйте этот вариант, если необходимо принудительно установить конкретное значение MSS, например, для устранения проблем с подключением или соответствия специфическим требованиям сети.

  • clamp-mss-to-pmtu: Роутер автоматически рассчитывает MSS, равный MTU интерфейса минус 40 байт для IPv4 (20 байт для заголовка IPv4 и 20 байт для заголовка TCP). Этот вариант рекомендуется для автоматической установки правильного значения.

set interfaces l2tpv3 <interface> ip arp-cache-timeout

Настройте, как долго ARP-запись остается действительной после изучения сопоставления IP-адреса и MAC-адреса на этом интерфейсе.

По умолчанию длительность составляет 30 секунд.

ARP-запись остается действительной, если получает положительный ответ от вышеуказанных протоколов.

Пример:

set interfaces l2tpv3 l2tpeth0 ip arp-cache-timeout 180
set interfaces l2tpv3 <interface> ip disable-arp-filter

Настройте фильтрацию ARP на этом интерфейсе.

Стандартное поведение: Ядро отвечает на запросы ARP на этом интерфейсе только в том случае, если трафик будет маршрутизирован обратно к отправителю ARP через этот конкретный интерфейс.

Если настроено: Ядро отвечает на запросы ARP на этом интерфейсе для любого IP-адреса, настроенного на локальном хосте, независимо от того, какой конкретный интерфейс этот IP-адрес назначен, и независимо от таблицы маршрутизации. Это отражает концепцию Linux, согласно которой IP-адреса принадлежат хосту, а не отдельным интерфейсам.

Пример:

set interfaces l2tpv3 l2tpeth0 ip disable-arp-filter
set interfaces l2tpv3 <interface> ip disable-forwarding

Настройте интерфейс для работы в режиме хоста или роутера.

Если настроено, интерфейс переключается в режим хоста, и IPv4-пересылка отключена на нем.

Пример:

set interfaces l2tpv3 l2tpeth0 ip disable-forwarding
set interfaces l2tpv3 <interface> ip enable-directed-broadcast

Настройте, будут ли передаваться IP-направленные широковещательные пакеты, полученные на этом интерфейсе.

Стандартное поведение: IP-направленные широковещательные пакеты отбрасываются.

Если настроено: IP-направленные широковещательные пакеты передаются всем хостам на подсети назначения, как определено в RFC 1812 и RFC 2644.

Пример:

set interfaces l2tpv3 l2tpeth0 ip enable-directed-broadcast
set interfaces l2tpv3 <interface> ip enable-arp-accept

Настройте, как обрабатывать бесплатные ARP на этом интерфейсе.

Если настроено, IP-адрес и MAC-адрес сопоставляются в таблице ARP на основе бесплатных ARP-запросов или ответов.

Примечание

Если в таблице ARP уже есть IP-адрес из бесплатного ARP, его запись обновляется независимо от того, настроено ли это настройка.

Пример:

set interfaces l2tpv3 l2tpeth0 ip enable-arp-accept
set interfaces l2tpv3 <interface> ip enable-arp-announce

Настройте выбор источника IP-адреса для ARP-запросов на этом интерфейсе.

Стандартное поведение: Ядро может использовать любой IP-адрес, который имеет хост, как источник IP-адреса в ARP-запросах на этом интерфейсе.

Если настроено: Ядро сначала пытается выбрать источник IP-адреса, настроенный на интерфейсе, который совпадает с подсетью целевого IP-адреса. Если такой подсети нет, ядро выбирает IP-адрес, который обычно используется (на основе таблицы маршрутизации для достижения целевой цели).

Пример:

set interfaces l2tpv3 l2tpeth0 ip enable-arp-announce
set interfaces l2tpv3 <interface> ip enable-arp-ignore

Настройте, какие ARP-запросы будут игнорироваться на этом интерфейсе.

Стандартное поведение: Ядро отвечает на ARP-запросы для любых локальных IP-адресов, независимо от того, к какому интерфейсу они привязаны.

Если настроено: Ядро отвечает на ARP-запросы только в том случае, если целевой IP-адрес назначен этому конкретному интерфейсу.

Пример:

set interfaces l2tpv3 l2tpeth0 ip enable-arp-ignore
set interfaces l2tpv3 <interface> ip enable-proxy-arp

Настройте прокси ARP на этом интерфейсе.

Если настроено, роутер (ядро) перехватывает ARP-запросы для нелокальных IP-адресов и отвечает с MAC-адресом интерфейса, который получил запрос. Последующие пакеты, предназначенные этим IP-адресам, перенаправляются на их фактические цели на удаленных подсетях.

Пример:

set interfaces l2tpv3 l2tpeth0 ip enable-proxy-arp
set interfaces l2tpv3 <interface> ip proxy-arp-pvlan

Настройте локальный прокси ARP на интерфейсе.

Если настроено, роутер (ядро) отвечает на ARP-запросы на этом VLAN-интерфейсе даже если целевой IP-адрес находится на той же подсети и интерфейсе.

Это используется для поддержки требований изоляции сети (RFC 3069) для частных VLAN (PVLAN). В конфигурациях PVLAN, хосты на изолированных портах НЕ разрешены общаться напрямую друг с другом на уровне 2, но могут общаться с верхним роутером.

Посредством ответа на ARP-запросы между хостами своим собственным MAC адресом, роутер (ядро) направляет трафик между хостами через себя, а не напрямую между хостами.

Примечание

Эта команда работает независимо и не требует включения обычного прокси ARP на интерфейсе.

Локальный прокси ARP также известен как:

  • VLAN агрегация (RFC 3069).

  • Частная VLAN (Cisco, Allied Telesyn).

  • Фильтрация по источнику или изоляция порта (Hewlett-Packard).

  • Перенаправление по MAC-адресу (Ericsson).

set interfaces l2tpv3 <interface> ip source-validation <strict | loose | disable>

Настройте проверку исходного IP-адреса с использованием RPF на этом интерфейсе, как указано в RFC 3704.

Доступны следующие варианты:

  • strict: Каждый входящий пакет проверяет исходный IP-адрес против Базы информации о маршрутизации (FIB). Если интерфейс не является лучшим маршрутом обратно к этому источнику, проверка не удается, и пакет удаляется.

  • loose: Каждый входящий пакет проверяет исходный IP-адрес против FIB. Если исходный IP-адрес недоступен через любой интерфейс, проверка не удается.

  • disable: Проверка исходного IP-адреса не выполняется. Все входящие пакеты принимаются.

RFC 3704 рекомендует включить строгий режим для предотвращения подделки IP-адресов, таких как DDoS-атаки. Для асимметричных или других сложных сценариев маршрутизации используйте режим loose.

set interfaces l2tpv3 <interface> ipv6 address autoconf

Настройте интерфейс для автоматического получения IPv6-адреса с помощью SLAAC, как указано в RFC 4862.

Хосты IPv6 могут настраивать себя автоматически при подключении к IPv6-сети с помощью протокола обнаружения соседей через ICMPv6 сообщения о маршрутизации. При первом подключении к сети, хост отправляет многоадресный запрос для своей конфигурации параметров. Роутер отвечает пакетом объявлений маршрутизатора, содержащим параметры конфигурации уровня интернета.

Примечание

Этот метод автоматически отключает передачу IPv6 на интерфейсе.

Пример:

set interfaces l2tpv3 l2tpeth0 ipv6 address autoconf
set interfaces l2tpv3 <interface> ipv6 address eui64 <prefix>

Настройте интерфейс для присвоения себе IPv6-адреса с помощью метода EUI-64 , как указано в RFC 4291.

Пример:

set interfaces l2tpv3 l2tpeth0 ipv6 address eui64 2001:db8:beef::/64
set interfaces l2tpv3 <interface> ipv6 address no-default-link-local

Отключите автоматическое присвоение link-local IPv6-адреса этому интерфейсу.

Пример:

set interfaces l2tpv3 l2tpeth0 ipv6 address no-default-link-local
set interfaces l2tpv3 <interface> ipv6 disable-forwarding

Настройте интерфейс для работы в режиме хоста или роутера.

Если настроено, интерфейс переключается в режим хоста, и IPv6-пересылка отключена на нем.

Пример:

set interfaces l2tpv3 l2tpeth0 ipv6 disable-forwarding
set interfaces l2tpv3 <interface> ipv6 adjust-mss <mss | clamp-mss-to-pmtu>

Настройте MSS , объявляемый в исходящих TCP SYN пакетах на указанном интерфейсе.

Путем ограничения значения MSS в TCP SYN пакетах, вы явно информируете удаленную сторону, что она не должна отправлять пакеты большего размера. Это предотвращает проблемы с соединением, когда Path MTU Discovery (PMTUD) не работает.

Доступны следующие варианты:

  • mss: Установите MSS на конкретное значение, в байтах. Используйте этот вариант, чтобы принудительно установить конкретное значение MSS, например, для устранения проблем с подключением или соответствия специфическим требованиям сети.

  • clamp-mss-to-pmtu: Роутер рассчитывает MSS, равный MTU интерфейса минус 60 байт для IPv6 (40 байт для заголовка IPv6 и 20 байт для заголовка TCP). Этот вариант рекомендуется для автоматической установки правильного значения.

set interfaces l2tpv3 <interface> ipv6 accept-dad <0 | 1 | 2>

Настройте IPv6 DAD на интерфейсе.

Доступны следующие варианты:

  • 0: Отключает DAD. Не производится проверка дублирования адреса.

  • 1: Включает DAD (по умолчанию). Обнаруживаются дублирующиеся адреса. Интерфейс продолжает работу с допустимыми IPv6-адресами.

  • 2: Включает DAD и, если найден дублирующийся локальный адрес, отключает работу IPv6 на этом интерфейсе.

Пример:

set interfaces l2tpv3 l2tpeth0 ipv6 accept-dad 2
set interfaces l2tpv3 <interface> ipv6 dup-addr-detect-transmits <n>

Настройте количество DAD сообщений, которые отправляет роутер (ядро) во время назначения IPv6-адреса на этом интерфейсе.

Значение по умолчанию — 1.

Пример:

set interfaces l2tpv3 l2tpeth0 ipv6 dup-addr-detect-transmits 5
set interfaces l2tpv3 <interface> vrf <vrf>

Назначьте интерфейс определенному экземпляру VRF .

См. также

Для информации о настройке VRF см. раздел VRF.

Пример:

set interfaces l2tpv3 l2tpeth0 vrf red

Параметры L2TPv3

Используйте следующие команды для настройки конкретных параметров туннеля L2TPv3.

set interfaces l2tpv3 <interface> encapsulation <udp | ip>

Настройте тип обертки для туннеля L2TPv3.

Допустимые значения: udp и ip.

Тип обертки по умолчанию — udp.

Примечание

Тип обертки должен совпадать на локальном и удаленном узлах для установления туннеля.

set interfaces l2tpv3 <interface> source-address <address>

Настройте исходный IP-адрес туннеля L2TPv3.

Указанный адрес должен быть локальным IP-адресом интерфейса и может быть как IPv4, так и IPv6.

set interfaces l2tpv3 <interface> remote <address>

Настройте конечный IP-адрес туннеля L2TPv3.

Указанный адрес должен быть IP-адресом интерфейса удаленного узла и может быть как IPv4, так и IPv6.

set interfaces l2tpv3 <interface> session-id <id>

Настройте локальный идентификатор сессии в туннеле L2TPv3.

session-id — 32-битное значение, которое идентифицирует входящую сессию туннеля на локальном узле.

peer-session-id, который идентифицирует эту сессию на удаленном узле, должен быть установлен в то же значение.

set interfaces l2tpv3 <interface> peer-session-id <id>

Настройте идентификатор сессии на удаленном узле в туннеле L2TPv3.

peer-session-id — 32-битное значение, которое идентифицирует исходящую сессию туннеля с локального узла.

peer-session-id должен совпадать с session-id, настроенным для этой сессии на удаленном узле.

set interfaces l2tpv3 <interface> tunnel-id <id>

Настройте локальный идентификатор туннеля L2TPv3.

tunnel-id — 32-битное значение, которое идентифицирует туннель L2TPv3 на локальном узле.

peer-tunnel-id, который идентифицирует этот туннель на удаленном узле, должен быть установлен в то же значение.

set interfaces l2tpv3 <interface> peer-tunnel-id <id>

Настройте идентификатор туннеля на удаленном узле в туннеле L2TPv3.

peer-tunnel-id — 32-битное значение, которое идентифицирует туннель L2TPv3 на удаленном узле и должно соответствовать tunnel-id, настроенному для этого туннеля на этом узле.

peer-tunnel-id должен совпадать с tunnel-id, который идентифицирует этот туннель на удаленном узле.

Пример

Туннель L2TPv3 с IP-оберткой

В следующем примере показана настройка туннеля L2TPv3 с прямой IP-оберткой:

# show interfaces l2tpv3
l2tpv3 l2tpeth10 {
    address 192.168.37.1/27
    encapsulation ip
    source-address 192.0.2.1
    peer-session-id 100
    peer-tunnel-id 200
    remote 203.0.113.24
    session-id 100
    tunnel-id 200
}

Обратная конфигурация должна быть применена к удаленному узлу.

Туннель L2TPv3 с UDP-оберткой

В следующем примере показана настройка туннеля L2TPv3 с UDP-оберткой.

Эта настройка рекомендуется, когда туннель проходит через устройства NAT.

Примечания по настройке:

  • Используйте локальный IP-адрес сети в качестве source-address.

  • Настройте правило пересылки, чтобы разрешить трафик туннеля на указанном порту UDP на внешнем устройстве NAT.

  • Используйте отдельный порт UDP для каждого отдельного туннеля.

# show interfaces l2tpv3
l2tpv3 l2tpeth10 {
    address 192.168.37.1/27
    destination-port 9001
    encapsulation udp
    source-address 192.0.2.1
    peer-session-id 100
    peer-tunnel-id 200
    remote 203.0.113.24
    session-id 100
    source-port 9000
    tunnel-id 200
}
