Высокая доступность

VRRP (Протокол резервирования маршрутизаторов) обеспечивает активно-резервную избыточность для маршрутизаторов. Каждый маршрутизатор VRRP имеет физический IP/IPv6 адрес и виртуальный адрес. При запуске маршрутизаторы выбирают мастера, и маршрутизатор с наибольшим приоритетом становится мастером и назначает виртуальный адрес своему интерфейсу. Все маршрутизаторы с меньшим приоритетом становятся резервными. Мастер затем начинает отправлять пакеты keepalive, чтобы сообщить другим маршрутизаторам, что он доступен. Если мастер выходит из строя и перестаёт отправлять пакеты keepalive, маршрутизатор с следующим наибольшим приоритетом становится новым мастером и берёт на себя виртуальный адрес.

Пакеты keepalive VRRP используют многоадресную передачу, и настройки VRRP ограничены одним сегментом уровня данных. Вы можете настроить несколько групп VRRP (также называемых виртуальными маршрутизаторами). Виртуальные маршрутизаторы идентифицируются идентификатором виртуального маршрутизатора (VRID). Если вы настраиваете несколько групп на одном интерфейсе, их VRID должны быть уникальными, если они используют один и тот же семейство адресов, но возможно (даже если это не рекомендуется по причинам читаемости) использовать дублирующиеся VRID на разных интерфейсах.

Базовая настройка

Группы VRRP создаются с помощью команды set high-availability vrrp group $GROUP_NAME. Необходимые параметры — интерфейс, vrid и address.

минимальная конфигурация

set high-availability vrrp group Foo vrid 10
set high-availability vrrp group Foo interface eth0
set high-availability vrrp group Foo address 192.0.2.1/24

Вы можете проверить статус группы VRRP в режиме операционной системы командой run show vrrp:

vyos@vyos# run show vrrp
Name        Interface      VRID  State    Last Transition
----------  -----------  ------  -------  -----------------
Foo         eth1             10  MASTER   2s

Поддержка IPv6

Параметр address может быть как IPv4, так и IPv6 адресом, но вы не можете смешивать IPv4 и IPv6 в одной группе, и вам нужно создать группы с разными VRID специально для IPv4 и IPv6. Если вы хотите использовать IPv4 + IPv6 адрес, вы можете использовать опцию excluded-address

Адрес

Параметр address можно настроить либо на интерфейсе VRRP, либо на не VRRP интерфейсе.

set high-availability vrrp group Foo address 192.0.2.1/24
set high-availability vrrp group Foo address 203.0.113.22/24 interface eth2
set high-availability vrrp group Foo address 198.51.100.33/24 interface eth3

Отключение группы VRRP

Вы можете отключить группу VRRP с помощью опции disable:

set high-availability vrrp group Foo disable

Отключенная группа будет удалена из процесса VRRP, и ваш роутер не будет участвовать в VRRP для этого VRID. Она исчезнет из вывода команд режима операционной системы, а не войдет в состояние резервного.

Исключить адрес

Исключить IP-адреса из пакетов VRRP. Эта опция excluded-address используется, когда вы хотите установить IPv4 + IPv6 адреса на том же виртуальном интерфейсе или когда используется более 20 IP-адресов.

set high-availability vrrp group Foo excluded-address '203.0.113.254/24'
set high-availability vrrp group Foo excluded-address '2001:db8:aa::1/64'
set high-availability vrrp group Foo excluded-address '2001:db8:22::1/64'

Настройка приоритета группы VRRP

Приоритет VRRP можно установить с помощью опции priority:

set high-availability vrrp group Foo priority 200

Приоритет должен быть целым числом от 1 до 255. Более высокое значение приоритета увеличивает приоритет маршрутизатора в выборе мастера.

Синхронные группы

Синхронная группа позволяет группам VRRP переходить вместе.

edit high-availability vrrp
set sync-group MAIN member VLAN9
set sync-group MAIN member VLAN20

В следующем примере, когда VLAN9 изменяется, VLAN20 также изменится:

vrrp {
    group VLAN9 {
        interface eth0.9
        address 10.9.1.1/24
        priority 200
        vrid 9
    }
    group VLAN20 {
        interface eth0.20
        priority 200
        address 10.20.20.1/24
        vrid 20
    }
    sync-group MAIN {
        member VLAN20
        member VLAN9
    }
}

Предупреждение

Все элементы в синхронной группе должны быть одинаково настроены. Если одна группа VRRP настроена с другим временем предварительного отключения или приоритетом, это приведет к бесконечному циклу перехода.

Предварительное отключение

VRRP может использовать два режима: предварительное отключение и непредварительное отключение. В режиме предварительного отключения, если маршрутизатор с более высоким приоритетом выходит из строя и затем возвращается, маршрутизаторы с более низким приоритетом отказываются от своего статуса мастера. В непредварительном режиме новый выбранный мастер сохраняет статус мастера и виртуальный адрес неограниченно.

По умолчанию VRRP использует предварительное отключение. Вы можете отключить его с помощью опции «no-preempt»:

set high-availability vrrp group Foo no-preempt

Вы также можете настроить временной интервал для предварительного отключения с помощью опции «preempt-delay». Например, чтобы установить, что высокоприоритетный маршрутизатор возьмет контроль через 180 секунд, используйте:

set high-availability vrrp group Foo preempt-delay 180

Отслеживание

Опция track для отслеживания состояний не VRRP интерфейсов. VRRP меняет состояние на FAULT, если один из отслеживаемых интерфейсов находится в состоянии down.

set high-availability vrrp group Foo track interface eth0
set high-availability vrrp group Foo track interface eth1

Игнорировать ошибки основного интерфейса VRRP

set high-availability vrrp group Foo track exclude-vrrp-interface

Unicast VRRP

По умолчанию VRRP использует многоадресные пакеты. Если ваша сеть не поддерживает многоадресную передачу по какой-либо причине, вы можете заставить VRRP использовать одноадресную связь вместо.

set high-availability vrrp group Foo peer-address 192.0.2.10
set high-availability vrrp group Foo hello-source-address 192.0.2.15

rfc3768-совместимость

RFC 3768 определяет виртуальный MAC-адрес для каждого виртуального маршрутизатора VRRP. Этот виртуальный MAC-адрес будет использоваться как источник во всех периодических VRRP сообщениях, отправляемых активным узлом. Когда установлена опция rfc3768-совместимость, создается новый интерфейс VRRP, к которому автоматически присваивается MAC-адрес и виртуальный IP-адрес.

set high-availability vrrp group Foo rfc3768-compatibility

Проверка

$show interfaces ethernet eth0v10
eth0v10@eth0: <BROADCAST,MULTICAST,UP,LOWER_UP> mtu 1500 qdisc noqueue
state UP group default qlen 1000
link/ether 00:00:5e:00:01:0a brd ff:ff:ff:ff:ff:ff
inet 172.25.0.247/16 scope global eth0v10
valid_lft forever preferred_lft forever

Предупреждение

RFC 3768 создает виртуальный интерфейс. Если вы хотите применить правило NAT назначения к трафику, направленному на виртуальный MAC, установите созданный виртуальный интерфейс как inbound-interface.

Глобальные параметры

В большинстве случаев нет необходимости менять конкретные параметры, и использование по умолчанию достаточно. Но есть случаи, когда требуется дополнительная настройка.

set high-availability vrrp global-parameters startup_delay <1-600>

Эта опция указывает задержку в секундах перед запуском экземпляров vrrp после запуска keepalived.

Gratuitous ARP

Эта конфигурация не обязательна, и в большинстве случаев нет необходимости ее настраивать. Но если необходимо, Gratuitous ARP можно настроить в global-parameters и/или в разделе group.

set high-availability vrrp global-parameters garp interval <0.000-1000>
set high-availability vrrp group <name> garp interval <0.000-1000>

Установите задержку между пакетами Gratuitous ARP, отправляемыми на интерфейсе.

0, если не определено.

set high-availability vrrp global-parameters garp master-delay <1-255>
set high-availability vrrp group <name> garp master-delay <1-255>

Установите задержку для второй серии Gratuitous ARPs после перехода в MASTER.

5, если не определено.

set high-availability vrrp global-parameters garp master-refresh <1-600>
set high-availability vrrp group <name> garp master-refresh <1-600>

Установите минимальный временной интервал для обновления Gratuitous ARPs, пока MASTER.

0, если не определено, что означает отсутствие обновления.

set high-availability vrrp global-parameters garp master-refresh-repeat <1-600>
set high-availability vrrp group <name> garp master-refresh-repeat <1-600>

Установите количество пакетов Gratuitous ARP, которые нужно отправить одновременно, пока MASTER.

1, если не определено.

set high-availability vrrp global-parameters garp master-repeat <1-600>
set high-availability vrrp group <name> garp master-repeat <1-600>

Установите количество пакетов Gratuitous ARP, которые нужно отправить одновременно после перехода в MASTER.

5, если не определено.

Версия

set high-availability vrrp global-parameters version 2|3

Установите версию VRRP по умолчанию. По умолчанию это 2, но экземпляры IPv6 всегда будут использовать версию 3.

Скрипты

Функциональность VRRP можно расширить с помощью скриптов. VyOS поддерживает два типа скриптов: скрипты проверки работоспособности и скрипты перехода. Скрипты проверки работоспособности выполняют пользовательские проверки дополнительно к достижимости главного маршрутизатора. Скрипты перехода выполняются, когда состояние VRRP изменяется с мастера на резервное или аварийное и наоборот, и могут быть использованы для включения или отключения определенных служб, например.

Примечание

Просто размещение скриптов в /config/scripts/ не означает, что система может их выполнять. Чтобы сделать пользовательские скрипты исполняемыми, предоставьте им права на выполнение. Используйте следующую команду:

chmod +x /config/scripts/script-name.sh

Предупреждение

Не рекомендуется изменять конфигурацию VRRP в скриптах проверки работоспособности и перехода.

Скрипты проверки работоспособности

Возможно запуск произвольного скрипта через регулярные интервалы в соответствии с параметрами проверки работоспособности. Если скрипт возвращает 0, это означает успех. Если скрипт возвращает любое другое значение, это означает, что экземпляр VRRP должен перейти в состояние FAULT.

Эта настройка позволит VRRP запустить /config/scripts/vrrp-check.sh script каждые 60 секунд, и перейти в состояние сбоев, если он неудачно завершится (то есть завершится с ненулевым статусом) три раза:

set high-availability vrrp group Foo health-check script /config/scripts/vrrp-check.sh
set high-availability vrrp group Foo health-check interval 60
set high-availability vrrp group Foo health-check failure-count 3

Дополнительно можно установить timeout, чтобы определить максимальное количество секунд, в течение которых скрипт может выполняться. Это полезно для скриптов, которые могут зависнуть или занять больше времени, чем ожидалось — установка таймаута выше, чем интервал, позволяет длинно выполняющимся скриптам завершиться до того, как они будут считаться неудачными.

set high-availability vrrp group Foo health-check script /config/scripts/vrrp-check.sh
set high-availability vrrp group Foo health-check interval 20
set high-availability vrrp group Foo health-check failure-count 3
set high-availability vrrp group Foo health-check timeout 40

Когда группа VRRP является членом синхронной группы, будет использоваться только скрипт проверки работоспособности синхронной группы. Этот пример показывает, как настроить его для синхронной группы:

set high-availability vrrp sync-group Bar health-check script /config/scripts/vrrp-check.sh
set high-availability vrrp sync-group Bar health-check interval 60
set high-availability vrrp sync-group Bar health-check failure-count 3

Скрипты перехода

Скрипты перехода помогут реализовать различные исправления, такие как запуск и остановка служб, или даже модификация конфигурации VyOS при переходе VRRP. Эта настройка позволит VRRP запустить /config/scripts/vrrp-fail.sh с аргументом Foo, когда VRRP не работает, и /config/scripts/vrrp-master.sh, когда роутер становится мастером:

set high-availability vrrp group Foo transition-script backup "/config/scripts/vrrp-fail.sh Foo"
set high-availability vrrp group Foo transition-script fault "/config/scripts/vrrp-fail.sh Foo"
set high-availability vrrp group Foo transition-script master "/config/scripts/vrrp-master.sh Foo"

Для получения дополнительной информации о скриптировании, обратитесь к разделу Скрипты команд.

Виртуальный сервер позволяет балансировать нагрузку трафика на виртуальный адрес:порт между несколькими реальными серверами.

Алгоритм

Алгоритм распределения нагрузки:

  • round-robin

  • weighted-round-robin

  • least-connection

  • weighted-least-connection

  • source-hashing

  • destination-hashing

  • locality-based-least-connection

set high-availability virtual-server 203.0.113.1 algorithm 'least-connection'

Метод передачи

  • NAT

  • direct

  • tunnel

set high-availability virtual-server 203.0.113.1 forward-method 'nat'

Время ожидания постоянства

Время в секундах для постоянных соединений. IPVS будет направлять все соединения от одного и того же источника IP на один и тот же реальный сервер в течение времени ожидания. Значение по умолчанию — 300 секунд.

Установите 0, чтобы отключить постоянство и позволить алгоритму балансировки распределять каждое соединение независимо.

set high-availability virtual-server 203.0.113.1 persistence-timeout '180'

Проверка работоспособности

Пользовательский скрипт проверки работоспособности позволяет проверить доступность реального сервера

set high-availability virtual-server 203.0.113.1 real-server 192.0.2.11 health-check script <path-to-script>

Fwmark

Пометка брандмауэра. Возможна балансировка трафика на основе значения fwmark

set high-availability virtual-server 203.0.113.1 fwmark '111'

Реальный сервер

IP-адрес и порт реального сервера

set high-availability virtual-server 203.0.113.1 real-server 192.0.2.11 port '80'

Пример

Виртуальный сервер может быть настроен с использованием виртуального адреса VRRP или без.

В следующем примере весь трафик, предназначенный для 203.0.113.1 и порта 8280 протокола TCP, распределяется между двумя реальными серверами 192.0.2.11 и 192.0.2.12 на порт 80

Реальный сервер автоматически исключается, если проверка порта с этим сервером неудачна.

set interfaces ethernet eth0 address '203.0.113.11/24'
set interfaces ethernet eth1 address '192.0.2.1/24'
set high-availability vrrp group FOO interface 'eth0'
set high-availability vrrp group FOO no-preempt
set high-availability vrrp group FOO priority '150'
set high-availability vrrp group FOO address '203.0.113.1/24'
set high-availability vrrp group FOO vrid '10'

set high-availability virtual-server 203.0.113.1 algorithm 'source-hashing'
set high-availability virtual-server 203.0.113.1 delay-loop '10'
set high-availability virtual-server 203.0.113.1 forward-method 'nat'
set high-availability virtual-server 203.0.113.1 persistence-timeout '180'
set high-availability virtual-server 203.0.113.1 port '8280'
set high-availability virtual-server 203.0.113.1 protocol 'tcp'
set high-availability virtual-server 203.0.113.1 real-server 192.0.2.11 port '80'
set high-availability virtual-server 203.0.113.1 real-server 192.0.2.12 port '80'

Пометка брандмауэра fwmark позволяет использовать несколько портов для высокодоступного виртуального сервера. Он использует значение fwmark.

В этом примере весь трафик, предназначенный для портов “80, 2222, 8888” протокола TCP отмечается как fwmark “111” и распределяется между двумя реальными серверами. Порт “0” необходим, если используются несколько портов.

set interfaces ethernet eth0 address 'dhcp'
set interfaces ethernet eth0 description 'WAN'
set interfaces ethernet eth1 address '192.0.2.1/24'
set interfaces ethernet eth1 description 'LAN'

set policy route PR interface 'eth0'
set policy route PR rule 10 destination port '80,2222,8888'
set policy route PR rule 10 protocol 'tcp'
set policy route PR rule 10 set mark '111'

set high-availability virtual-server vyos fwmark '111'
set high-availability virtual-server vyos protocol 'tcp'
set high-availability virtual-server vyos real-server 192.0.2.11 health-check script '/config/scripts/check-real-server-first.sh'
set high-availability virtual-server vyos real-server 192.0.2.11 port '0'
set high-availability virtual-server vyos real-server 192.0.2.12 health-check script '/config/scripts/check-real-server-second.sh'
set high-availability virtual-server vyos real-server 192.0.2.12 port '0'

set nat source rule 100 outbound-interface name 'eth0'
set nat source rule 100 source address '192.0.2.0/24'
set nat source rule 100 translation address 'masquerade'
