Политика трафика

QoS

Общее название Quality of Service или Control трафика включает в себя такие вещи, как формирование трафика, расписание или удаление пакетов, что является тем, с чем вы можете играть, когда у вас, например, есть ограничение пропускной способности на линии и вы хотите каким-то образом приоритизировать определенный тип трафика по сравнению с другим.

tc — мощный инструмент для контроля трафика, найденный в ядре Linux. Однако его настройка часто считается трудоемкой задачей. К счастью, VyOS облегчает работу через свою CLI, используя tc как бэкенд.

Как это работает

Чтобы VyOS-контроль трафика работал, вам нужно выполнить 2 шага:

  1. Создайте политику трафика.

  2. Примените политику трафика к интерфейсу входящего или исходящего трафика.

Но прежде чем учиться настраивать вашу политику, мы предупредим вас о различных единицах, которые вы можете использовать, а также покажем, что такое классы и как они работают, так как некоторые политики могут потребовать от вас настройки их.

Единицы

При настройке вашей политики трафика, вам придется задавать значения скорости передачи данных, обратите внимание на единицы, которые вы управляете, легко запутаться с разными префиксами и суффиксами, которые вы можете использовать. VyOS всегда покажет вам различные единицы, которые вы можете использовать.

tibps (1024^4*8)       тебибайт (TiB) в секунду

Классы

В разделе Создание политики трафика вы увидите, что некоторые политики используют классы. Эти политики позволяют распределять трафик по разным классам в зависимости от различных параметров, которые вы можете выбрать. Таким образом, класс — это просто определенный тип трафика, который вы выбираете.

Конечная цель классификации трафика — дать каждому классу разное обращение.

Сопоставление трафика

Чтобы определить, какой трафик попадает в какой класс, вы определяете фильтры (то есть критерии сопоставления). Пакеты проходят через эти правила сопоставления (как в правилах фаервола), и если пакет соответствует фильтру, он присваивается этому классу.

В VyOS класс идентифицируется числом, которое вы можете выбрать при настройке.

Примечание

Значение идентификатора класса не одинаково для каждой политики. Обычно политики нуждаются только в бесполезном числе для идентификации класса (ID класса), но это не относится ко всем политикам. Число класса в очереди приоритетов не только идентифицирует его, но и определяет его приоритет.

set qos policy <policy> <policy-name> class <class-ID> match <class-matching-rule-name>

В команде выше мы устанавливаем тип политики, с которой мы собираемся работать, и имя, которое мы выбрали для нее; класс (чтобы различать определенный трафик) и уникальное число для этого класса; затем мы настраиваем правило сопоставления (или фильтр) и имя для него.

Класс может иметь несколько правил сопоставления:

set qos policy shaper MY-SHAPER class 30 match HTTP
set qos policy shaper MY-SHAPER class 30 match HTTPs

Правило сопоставления может содержать несколько критериев и будет соответствовать трафику, если все эти критерии истинны.

Например:

set qos policy shaper MY-SHAPER class 30 match HTTP ip protocol tcp
set qos policy shaper MY-SHAPER class 30 match HTTP ip source port 80

Это будет соответствовать TCP-трафику с портом источника 80.

Есть много параметров, которыми вы сможете воспользоваться, чтобы сопоставить трафик для класса:

  • Ethernet (protocol, destination address or source address)

  • Interface name

  • IPv4 (DSCP value, maximum packet length, protocol, source address, destination address, source port, destination port or TCP flags)

  • IPv6 (DSCP value, maximum payload length, protocol, source address, destination address, source port, destination port or TCP flags)

  • Firewall mark

  • VLAN ID

При настройке вашего фильтра вы можете использовать клавишу Tab, чтобы увидеть множество различных параметров, которые вы можете настроить.

vyos@vyos# set qos policy shaper MY-SHAPER class 30 match MY-FIRST-FILTER 
Possible completions:
   description  Description
 > ether        Ethernet header match
   interface    Interface to use
 > ip           Match IP protocol header
 > ipv6         Match IPV6 protocol header
   mark         Match on mark applied by firewall
   vif          Virtual Local Area Network (VLAN) ID for this match

Как показано в приведенном выше примере, одним из возможных способов сопоставления пакетов является использование отметок, сделанных фаерволом, что может дать вам большое количество гибкости.

Вы также можете написать описание для фильтра:

set qos policy shaper MY-SHAPER class 30 match MY-FIRST-FILTER description "My filter description"

Примечание

IPv4 TCP-фильтр будет соответствовать только пакетам с заголовком IPv4 длиной 20 байтов (это большинство пакетов IPv4).

Примечание

IPv6 TCP-фильтры будут соответствовать только пакетам IPv6 без расширений заголовка, см. https://en.wikipedia.org/wiki/IPv6_packet#Extension_headers

Группа сопоставления трафика

В некоторых случаях, когда нам нужно организовать наш выбор сопоставления, чтобы быть более гибким и организовать с нашим определением фильтра. Мы можем применять группы сопоставления трафика, позволяющие создавать отдельные группы фильтров внутри нашей политики и определять различные параметры для каждой группы:

set qos traffic-match-group <group_name> match <match_name>
Possible completions:
   description          Description
 > ip                   Match IP protocol header
 > ipv6                 Match IPv6 protocol header
   mark                 Match on mark applied by firewall
   vif                  Virtual Local Area Network (VLAN) ID for this match

наследовать совпадения из другой группы

set qos traffic-match-group <group_name> match-group <match_group_name>

Группа совпадений может содержать несколько критериев и наследовать их в той же политике.

Например:

set qos traffic-match-group Mission-Critical match AF31 ip dscp 'AF31'
set qos traffic-match-group Mission-Critical match AF32 ip dscp 'AF42'
set qos traffic-match-group Mission-Critical match CS3 ip dscp 'CS3'
set qos traffic-match-group Streaming-Video match AF11 ip dscp 'AF11'
set qos traffic-match-group Streaming-Video match AF41 ip dscp 'AF41'
set qos traffic-match-group Streaming-Video match AF43 ip dscp 'AF43'
set qos policy shaper VyOS-HTB class 10 bandwidth '30%'
set qos policy shaper VyOS-HTB class 10 description 'Multimedia'
set qos policy shaper VyOS-HTB class 10 match CS4 ip dscp 'CS4'
set qos policy shaper VyOS-HTB class 10 match-group 'Streaming-Video'
set qos policy shaper VyOS-HTB class 10 priority '1'
set qos policy shaper VyOS-HTB class 10 queue-type 'fair-queue'
set qos policy shaper VyOS-HTB class 20 description 'MC'
set qos policy shaper VyOS-HTB class 20 match-group 'Mission-Critical'
set qos policy shaper VyOS-HTB class 20 priority '2'
set qos policy shaper VyOS-HTB class 20 queue-type 'fair-queue'
set qos policy shaper VyOS-HTB default bandwidth '20%'
set qos policy shaper VyOS-HTB default queue-type 'fq-codel'

В этом примере мы можем наблюдать, что разные критерии DSCP определяются на основе нашей конфигурации QoS в рамках одной группы политики.

По умолчанию

Часто вам также придется настраивать ваш по умолчанию трафик таким же образом, как и класс. По умолчанию можно рассматривать как класс, так как он ведет себя как такой. Он содержит любой трафик, который не соответствовал ни одному из определенных классов, поэтому это как открытый класс, класс без правил сопоставления.

Обработка класса

После настройки фильтра для класса, вы также должны определить, что вы хотите сделать с трафиком этого класса, какую конкретную обработку трафика вы хотите предоставить. Вы будете иметь разные возможности в зависимости от политики трафика, которую вы настраиваете.

Вложение одной политики в другую

Часто нам нужно вложить одну политику в другую. Это возможно сделать на классовых политиках, прикрепляя новую политику к классу. Например, вы можете хотеть применить разные политики к разным классам кругового алгоритма, который вы настроили.

Обычный пример — это случай, когда некоторые политики, чтобы быть эффективными, им нужно применить к интерфейсу, который непосредственно подключен, где находится узкое место. Если ваш роутер не подключен напрямую к узкому месту, но находится на хопе до него, вы можете имитировать узкое место, вложив вашу политику без формирования в классовую политику формирования, чтобы она вступила в силу.

Вы можете настроить политику в классе через параметр queue-type.

set qos policy shaper FQ-SHAPER bandwidth 4gbit
set qos policy shaper FQ-SHAPER default bandwidth 100%
set qos policy shaper FQ-SHAPER default queue-type fq-codel

Как показано в последней команде примера выше, параметр queue-type позволяет комбинировать эти варианты. Вы сможете использовать его во многих политиках.

Примечание

Некоторые политики уже включают другие встроенные политики внутри. Это случай шейпера: каждый из его классов использует fair-queue, если вы не измените его.

Создание политики трафика

VyOS позволяет контролировать трафик многими различными способами, здесь мы рассмотрим каждую возможность. Вы можете настроить столько политик, сколько хотите, но вы сможете применить только одну политику на интерфейс и направление (входящий или исходящий).

Некоторые политики можно комбинировать, вы сможете вложить другую политику, которая будет применена к классу основной политики.

Совет

Если вы ищете политику для своего исходящего трафика но вы не знаете, какую именно вам нужно, и не хотите проходить через все возможные политики, представленные здесь, наше предположение заключается в том, что вы, вероятно, ищете Shaper политику и хотите установить очереди как FQ-CoDel.

Drop Tail

Дисциплина очереди: PFIFO (Пакет First In First Out).
Применяется к: Исходящий трафик.

Это самая простая очередь, которую вы можете применить к своему трафику. Трафик должен пройти через конечную очередь перед тем, как он будет фактически отправлен. Вам нужно определить, сколько пакетов эта очередь может содержать.

Когда пакет должен быть отправлен, он должен пройти через эту очередь, поэтому пакет будет помещен в хвост. Когда пакет полностью пройдет через нее, он будет удален, освободив место в очереди и в конечном итоге будет передан NIC для фактической отправки.

Несмотря на то, что политика Drop-Tail не замедляет пакеты, если много пакетов должно быть отправлено, они могут быть потеряны при попытке добавить их в хвост. Это может произойти, если очередь еще не смогла освободить достаточно пакетов с головы.

Это политика, которая требует наименьших ресурсов для одного и того же объема трафика. Но очень вероятно, что вам не нужно это, так как вы не получите много от этого. Иногда он используется просто для включения журналирования.

set qos policy drop-tail <policy-name> queue-limit <number-of-packets>

Используйте эту команду для настройки политики Drop-Tail (PFIFO). Выберите уникальное имя для этой политики и размер очереди, установив количество пакетов, которые она может содержать (максимум 4294967295).

Fair Queue

Дисциплина очереди: SFQ (Stochastic Fairness Queuing).
Применяется к: Исходящий трафик.

Fair Queue — это работающий консервирующий планировщик, который планирует передачу пакетов на основе потоков, то есть он распределяет трафик по разным подочередям, чтобы обеспечить справедливость, так что каждый поток может отправлять данные по очереди, предотвращая любую единственную, которая затопит остальные.

set qos policy fair-queue <policy-name>

Используйте эту команду для создания политики Fair-Queue и присвойте ей имя. Она основана на Stochastic Fairness Queueing и может быть применена к исходящему трафику.

Для разделения трафика Fair Queue использует классификатор на основе адреса источника, адреса назначения и порта источника. Алгоритм помещает пакеты в хэш-буфера на основе этих трех параметров. Каждый из этих буферов должен представлять уникальный поток. Поскольку несколько потоков могут попасть в один и тот же буфер, алгоритм хэширования возмущается в установленные интервалы, чтобы несправедливость длилась только короткое время. Возмущение может, однако, вызвать непреднамеренное перемешивание пакетов. Рекомендуемое значение может быть 10 секунд.

Одним из применений Fair Queue может быть снижение атак типа «отказ в обслуживании».

set qos policy fair-queue <policy-name> hash-interval <seconds>

Используйте эту команду для определения политики Fair-Queue, основанной на Stochastic Fairness Queueing, и установите количество секунд, через которое произойдет новая перестройка алгоритма очереди (максимум 4294967295).

При деэнуации каждая хэш-буферная очередь с данными опрашивается циклическим образом. Вы можете настроить длину очереди.

set qos policy fair-queue <policy-name> queue-limit <limit>

Используйте эту команду для определения политики Fair-Queue, основанной на Stochastic Fairness Queueing, и установите максимальное количество пакетов, допустимых для ожидания в очереди. Любые другие пакеты будут отброшены.

Примечание

Fair Queue — это политика без формирования (работающая консервирующая), поэтому она будет полезна только в том случае, если ваш исходящий интерфейс действительно полный. Если нет, то VyOS не владеет очередью, и Fair Queue не будет иметь эффекта. Если на физическом канале есть свободная пропускная способность, вы можете вложить Fair-Queue в классовую политику формирования, чтобы убедиться, что он владеет очередью.

FQ-CoDel

Дисциплина очереди: Fair/Flow Queue CoDel.
Применяется к: Исходящий трафик.

Политика FQ-CoDel распределяет трафик по 1024 FIFO-очередям и пытается обеспечить хорошее обслуживание всех них. Он также пытается сохранить короткую длину всех очередей.

FQ-CoDel борется с буферблатом и уменьшает задержку без необходимости сложных настроек. Он стал новым стандартным дисциплиной очереди для интерфейсов некоторых дистрибутивов GNU/Linux.

Он использует статистическую модель для классификации входящих пакетов в разные потоки и используется для предоставления справедливого количества пропускной способности всем потокам, использующим очередь. Каждый поток управляется дисциплиной очереди CoDel. Перемешивание внутри потока избегается, поскольку CoDel внутренне использует FIFO-очередь.

FQ-CoDel основан на модифицированном алгоритме планирования Deficit Round Robin (DRR) с алгоритмом активного управления очередью (AQM) CoDel, работающим на каждой очереди.

Примечание

FQ-Codel — это политика без формирования (работающая консервирующая), поэтому она будет полезна только в том случае, если ваш исходящий интерфейс действительно полный. Если нет, то VyOS не владеет очередью, и FQ-Codel не будет иметь эффекта. Если на физическом канале есть свободная пропускная способность, вы можете вложить FQ-Codel в классовую политику формирования, чтобы убедиться, что он владеет очередью. Если вы не уверены, нужно ли вам вкладывать политику FQ-CoDel в Шейпер, сделайте это.

FQ-CoDel настроен на работу с его базовыми параметрами на скорости 10 Гбит/с. Он может работать нормально и на других скоростях без настройки, но здесь мы объясним некоторые случаи, когда вы можете настроить его параметры.

При работе на скорости 1 Гбит/с и ниже, вы можете уменьшить queue-limit до 1000 пакетов или меньше. На скоростях, таких как 10 Мбит/с, вы можете установить его на 600 пакетов.

Если вы используете FQ-CoDel, вложенный в Шейпер, и у вас большие скорости (100 Мбит/с и выше), вы можете рассмотреть увеличение quantum до 8000 или выше, чтобы экономить ЦП.

На низких скоростях (ниже 40 Мбит/с) вы можете настроить quantum до 300 байт.

На очень низких скоростях (ниже 3 Мбит/с) помимо настройки quantum (300 остается в порядке) вы также можете увеличить target до около 15 мс и увеличить interval до около 150 мс.

set qos policy fq-codel <policy name> codel-quantum <bytes>

Используйте эту команду для настройки политики fq-codel, установите ее имя и максимальное количество байтов (по умолчанию: 1514), которые будут извлечены из очереди за один раз.

set qos policy fq-codel <policy name> flows <number-of-flows>

Используйте эту команду для настройки политики fq-codel, установите ее имя и количество подочередей (по умолчанию: 1024), в которые будут классифицированы пакеты.

set qos policy fq-codel <policy name> interval <milliseconds>

Используйте эту команду для настройки политики fq-codel, установите ее имя и период времени, используемый циклом управления CoDel для обнаружения развития постоянной очереди, обеспечивая, чтобы измеренное минимальное время задержки не стало слишком старым (по умолчанию: 100 мс).

set qos policy fq-codel <policy name> queue-limit <number-of-packets>

Используйте эту команду для настройки политики fq-codel, установите ее имя и определите жесткий предел реального размера очереди. Когда этот предел достигнут, новые пакеты будут отброшены (по умолчанию: 10240 пакетов).

set qos policy fq-codel <policy name> target <milliseconds>

Используйте эту команду для настройки политики fq-codel, установите ее имя и определите допустимое минимальное стоячее/постоянное время задержки очереди. Это минимальное время задержки определяется путем отслеживания локального минимального времени задержки, которое испытывают пакеты (по умолчанию: 5 мс).

Пример

Простой пример политики FQ-CoDel, работающей внутри политики Шейпера.

set qos policy shaper FQ-CODEL-SHAPER bandwidth 2gbit
set qos policy shaper FQ-CODEL-SHAPER default bandwidth 100%
set qos policy shaper FQ-CODEL-SHAPER default queue-type fq-codel

Limiter

Дисциплина очереди: Входной регулятор.
Применяется к: Входящий трафик.

Limiter — одна из тех политик, которые используют классы (входная дисциплина очереди на самом деле является классовой политикой, но фильтры работают в ней).

Limiter выполняет базовое входное регулирование трафика. Можно определить несколько классов трафика и применить ограничения на трафик к каждому классу. Хотя регулятор использует механизм токен-бакета внутренне, он не имеет возможности задерживать пакет, как делает механизм формирования. Трафик, превышающий определенные лимиты пропускной способности, сразу отбрасывается. Также можно настроить максимальный допустимый пакет.

Вы можете настроить классы (до 4090) с разными настройками и политику по умолчанию, которая будет применяться к любому трафику, не соответствующему каким-либо настроенным классам.

Примечание

Если вы хотите применить какое-то формирование к вашему входящему трафику, проверьте раздел входящего формирования.

set qos policy limiter <policy-name> class <class ID> match <match-name> description <description>

Используйте эту команду для настройки входного регулятора, определив его имя, идентификатор класса (1-4090), имя правила сопоставления класса и его описание.

После того, как правила сопоставления установлены для класса, вы можете начать настраивать, как вы хотите, чтобы соответствующий трафик вел себя.

set qos policy limiter <policy-name> class <class-ID> bandwidth <rate>

Используйте эту команду для настройки входного регулятора, определив его имя, идентификатор класса (1-4090) и максимальную допустимую пропускную способность для этого класса.

set qos policy limiter <policy-name> class <class-ID> burst <burst-size>
