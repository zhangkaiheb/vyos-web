Брандмауэр

Предупреждение

Из-за гонки при запуске, все интерфейсы инициализируются до брандмауэра. Это временно оставляет систему открытым для всего трафика и представляет угрозу безопасности.

VyOS использует Netfilter. Проект Netfilter разработал iptables и его преемник nftables для ядра Linux, чтобы обрабатывать потоки пакетов напрямую. Это расширяет понятие базовой безопасности зоны, позволяя вам манипулировать данными на нескольких этапах после того, как сетевой интерфейс и драйвер принимают их, и перед тем, как отправить их в цель (например, веб-сервер или другое устройство).

Ниже приведена упрощенная схема потока трафика на основе Netfilter пакетного потока. Эта диаграмма предоставляет обзор того, как обрабатываются пакеты и возможные пути, которые может принять трафик.

Основные моменты относительно потока пакетов и терминологии в брандмауэре VyOS следующие:

  • Мост?: Выберите соответствующий путь в зависимости от того, является ли интерфейс, на котором был принят пакет, частью моста.

Если интерфейс, на котором был принят пакет, не является частью моста, пакет обрабатывается на уровне IP:

  • Prerouting: Роутер обрабатывает все пакеты на этом этапе, независимо от назначения. Вы можете выполнить несколько действий на этом этапе, и эти действия также определены в разных частях конфигурации VyOS. Порядок важен. Конфигурация, которая применяется на этом этапе, включает:

    • Правила prerouting брандмауэра: Правила, которые вы определяете под set firewall [ipv4 | ipv6] prerouting raw.... Система обрабатывает все правила в этом разделе до подсистемы отслеживания соединений.

    • Игнорировать conntrack: Правила, которые вы определяете под set system conntrack ignore [ipv4 | ipv6] .... Вы можете настроить этот раздел с помощью firewall [ipv4 | ipv6] prerouting .... По причинам совместимости, эта функция поддерживается, но будет устаревшей в будущем.

    • Политика маршрутизации: Правила, которые вы определяете под set policy [route | route6] ....

    • Destination NAT: Правила, которые вы определяете под set [nat | nat66] destination....

  • Назначение — роутер?: Выберите соответствующий путь в зависимости от адреса назначения. Транзитный трафик продолжает forward, а трафик, предназначенный для роутера, продолжает input.

  • Input: Этап, на котором вы фильтруете и контролируете трафик, предназначенный для самого роутера. Это место, где вы применяете все правила для обеспечения безопасности роутера. Это включает в себя правила фильтрации IPv4 и IPv6, определенные в:

    • set firewall ipv4 input filter ....

    • set firewall ipv6 input filter ....

  • Forward: Этап, на котором вы фильтруете и контролируете транзитный трафик. Это включает в себя правила фильтрации IPv4 и IPv6, определенные в:

    • set firewall ipv4 forward filter ....

    • set firewall ipv6 forward filter ....

  • Output: Этап, на котором вы фильтруете и контролируете трафик, исходящий из роутера. Обратите внимание, что этот трафик поступает либо от нового соединения, которое запускает внутренний процесс на роутере VyOS (например, NTP), либо от ответа на трафик, который роутер получает внешним образом через input (например, ответ на попытку входа по SSH). Это включает правила IPv4 и IPv6, и применяются два различных раздела:

    • Output Prerouting: set firewall [ipv4 | ipv6] output raw .... Как описано в Prerouting, система обрабатывает правила в этом разделе до подсистемы отслеживания соединений.

    • Output Filter: set firewall [ipv4 | ipv6] output filter ....

  • Postrouting: Как и в случае Prerouting, вы можете выполнять несколько действий в определенных частях конфигурации VyOS на этом этапе. Это включает:

    • Source NAT: Правила, которые вы определяете под set [nat | nat66] source....

Если интерфейс, на котором был принят пакет, является частью моста, то пакет обрабатывается на уровне Bridge:

  • Prerouting (Bridge): Мост обрабатывает все пакеты, которые он получает на этом этапе, независимо от назначения. Сначала вы можете применить фильтры здесь, или вы можете настроить правила, которые игнорируют систему отслеживания соединений. Применяемая конфигурация:

    • set firewall bridge prerouting filter ....

  • Forward (Bridge): Этап, на котором вы фильтруете и контролируете трафик, проходящий через мост:

    • set firewall bridge forward filter ....

  • Input (Bridge): Этап, на котором вы фильтруете и контролируете трафик, направленный в сам мост:

    • set firewall bridge input filter ....

  • Output (Bridge): Этап, на котором вы фильтруете и контролируете трафик, который исходит из моста:

    • set firewall bridge output filter ....

    * flowtable

            + ...

         + all-ping
         + broadcast-ping
         + ...
    * group

         - interface-group
         - mac-group
         - port-group
         - domain-group
    * ipv4

            + filter

            + filter
         - output
            + filter

         - prerouting
            + raw

            + custom_name
    * ipv6

            + filter
         - input
            + filter
         - output
            + filter
            + raw
         - prerouting
            + raw
         - ipv6-name
            + custom_name
    * zone
         - custom_zone_name
            + ...

set firewall bridge …

Настройте таблицы потоков брандмауэра для отслеживания состояния соединений и правил. См. страницу «Конфигурация брандмауэра Flowtables» для получения подробной информации.

set firewall global-options …

Настройте глобальные параметры брандмауэра, такие как all-ping, broadcast-ping, syn-cookies и другие системные настройки брандмауэра. См. страницу «Глобальные параметры брандмауэра» для получения подробной информации.

set firewall group …

Организуйте правила брандмауэра, создавая повторно используемые группы адресов, сетей, интерфейсов, MAC-адресов, портов и доменов. Используйте группы в нескольких правилах, чтобы упростить конфигурацию и обслуживание. См. страницу «Группы брандмауэра» для получения подробной информации.

set firewall ipv4 …

Настройте специфичные для IPv4 правила брандмауэра. См. страницу «Конфигурация брандмауэра IPv4» для получения подробной информации.

set firewall ipv6 …

Настройте специфичные для IPv6 правила брандмауэра. См. страницу «Конфигурация брандмауэра IPv6» для получения подробной информации.

set firewall zone …

Настройте политики брандмауэра на основе зон для контроля трафика между разными сетевыми зонами. См. страницу «Конфигурация зонного брандмауэра» для получения подробной информации.

Зонный брандмауэр

  • Зонный брандмауэр

С зонным брандмауэром применяется новая концепция. Помимо стандартных потоков входящего и исходящего трафика, существует локальный поток, который позволяет трафику, исходящему из и предназначенным для самого роутера. Это означает, что вам нужно настроить дополнительные правила, чтобы защитить брандмауэр от сети, помимо существующих входящих и исходящих правил.

Чтобы настроить VyOS с зонным брандмауэром, см. Конфигурация зонного брандмауэра.

Как показывает следующее примерное изображение, необходимо настроить правила, чтобы разрешить или заблокировать трафик, идущий к или от служб, работающих на устройстве, имеющих открытые соединения на этом интерфейсе.
