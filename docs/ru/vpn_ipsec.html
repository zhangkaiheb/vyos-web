Общие сведения об IPsec

IPsec — это фреймворк, используемый для защиты данных. IPsec обеспечивает это за счёт аутентификации, шифрования IP-пакетов, обмена ключами и управления ключами. VyOS использует пакет Strongswan для реализации IPsec.

Заголовок аутентификации (AH) определён в RFC 4302. Он использует IP-заголовок и полезную нагрузку данных для создания хеша, который затем добавляется к пакету. Этот хеш используется для проверки того, что данные не были изменены во время передачи по сети.

Инкапсулирующая полезная нагрузка безопасности (ESP) определена в RFC 4303. Она обеспечивает как шифрование, так и аутентификацию данных.

Существует два режима IPsec:

Транспортный режим IPsec: В транспортном режиме заголовок IPsec (AH или ESP) вставляется между IP-заголовком и заголовком протокола верхнего уровня.

Режим туннеля IPsec: В режиме туннеля исходный IP-пакет инкапсулируется в другую IP-датаграмму, при этом заголовок IPsec (AH или ESP) вставляется между внешним и внутренним заголовками.

IKE (Internet Key Exchange)

Протокол IKE является стандартным методом безопасного согласования ключей IPsec. IKE предназначен для обеспечения взаимной аутентификации узлов IKE и установления общих ключей для создания ассоциаций безопасности IPsec (SA). Ассоциация безопасности (SA) включает все соответствующие атрибуты соединения, включая используемые алгоритмы шифрования, режим IPsec, ключи шифрования и другие параметры, связанные с передачей данных через VPN-соединение.

IKEv1

IKEv1 — это более старая версия, которая до сих пор используется. Большинство производителей теперь рекомендуют использовать протокол IKEv2.

IKEv1 описан в следующих RFC: RFC 2409 (IKE), RFC 3407 (IPsec DOI), RFC 3947 (NAT-T), RFC 3948 (UDP-инкапсуляция пакетов ESP), RFC 3706 (DPD)

IKEv1 работает в две фазы для установления IKE и IPsec SA:

  • Фаза 1 обеспечивает взаимную аутентификацию узлов IKE и установление сеансовых ключей. Эта фаза использует обмен DH, куки и обмен идентификаторами для создания IKE SA. После установления IKE SA вся коммуникация IKE между инициатором и респондентом защищена шифрованием и проверками целостности аутентификации. IKE Фаза 1 предоставляет два режима: основной режим и агрессивный режим.
    • Основной режим используется для VPN-соединений сайт-сайт.
    • Агрессивный режим используется для VPN-соединений удалённого доступа.
  • Фаза 2 обеспечивает согласование и установление IPsec SA, которые защищают IP-трафик данных с использованием ESP или AH.

IKEv2

IKEv2 описан в RFC 7296. Основное отличие между IKEv1 и IKEv2 заключается в том, что IKEv2 проще и надёжнее, чем IKEv1, с меньшим количеством сообщений, обмениваемых при установлении VPN, и дополнительными функциями безопасности.

Аутентификация IKE

VyOS поддерживает 3 метода аутентификации:

  • Предварительно распределённый ключ: при этом методе оба узла туннеля IPsec должны иметь одинаковый предварительно распределённый ключ.
  • Цифровые сертификаты: при этом методе используется PKI.
  • Ключи RSA: если в политике IKE используется метод ключей RSA, убедитесь, что каждый узел имеет открытый ключ другого узла.

DPD (Dead Peer Detection)

Это механизм, используемый для обнаружения случаев, когда узел VPN больше не активен. Этот механизм имеет различные алгоритмы для IKEv1 и IKEv2 в VyOS. Запросы DPD отправляются как сообщения ISAKMP R-U-THERE, а ответы DPD отправляются как сообщения ISAKMP R-U-THERE-ACK. В IKEv1 DPD отправляет сообщения через настроенные интервалы. Если в течение тайм-аута DPD не получен ответ на эти пакеты, удалённый узел считается недоступным. В IKEv2 DPD отправляет сообщения через настроенные интервалы. Если один запрос остаётся без ответа, Strongswan выполнит свой алгоритм повторной передачи со своими таймерами.

Постквантовый предварительно распределённый ключ (PPK)

Постквантовые предварительно распределённые ключи помогают обеспечить некоторую квантовую устойчивость туннелей IPsec, когда постквантовые алгоритмы обмена ключами, такие как ML-KEM, недоступны. Использование PPK в IKEv2 описано в RFC 8784.

PPK может быть настроен в VyOS в разделе vpn ipsec authentication ppk. PPK требует идентификатор и секретное значение. Если PPK необходим для успешного соединения IPsec, оба значения — идентификатор и секрет — должны совпадать. Секрет может быть открытым текстом, шестнадцатеричным значением или значением Base64. По умолчанию используется открытый текст. При использовании других типов значений необходимо определить тип секрета.

Конфигурация IKE

Атрибуты IKE

Группы IKE в VyOS имеют следующие параметры:

set vpn ipsec ike-group <name> close-action <action>

Определяет действие, которое необходимо предпринять, когда удалённый узел неожиданно закрывает CHILD_SA:

  • none — не выполнять никаких действий (по умолчанию)
  • trap — установить политику-ловушку для CHILD_SA; трафик, соответствующий этим политикам, вызовет событие acquire, что заставит демон установить необходимую IKE/IPsec SA.
  • start — немедленно попытаться пересоздать CHILD_SA.

set vpn ipsec ike-group <name> ikev2-reauth

Должна ли повторная генерация ключей IKE_SA также повторно аутентифицировать узел. В IKEv1 повторная аутентификация выполняется всегда. Установка этого параметра включает повторную аутентификацию удалённого узла во время обновления ключей IKE.

set vpn ipsec ike-group <name> key-exchange

Какой протокол должен использоваться для инициирования соединения. Если не задано, обрабатываются оба протокола, и соединение использует IKEv2 при инициировании, но принимает любую версию протокола при ответе:

  • ikev1 — использовать IKEv1 для обмена ключами.
  • ikev2 — использовать IKEv2 для обмена ключами.

set vpn ipsec ike-group <name> lifetime

Время жизни IKE (секунды) <0-86400> (по умолчанию 28800).

set vpn ipsec ike-group <name> mode

Выбор режима Фазы 1 IKEv1:

  • main — использовать основной режим для обмена ключами в протоколе IKEv1 (рекомендуемый по умолчанию).
  • aggressive — использовать агрессивный режим для обмена ключами в протоколе IKEv1; агрессивный режим менее безопасен, чем основной режим.

set vpn ipsec ike-group <name> proposal <number> dh-group <dh-group number>

Группа DH. Значение по умолчанию — 2.

set vpn ipsec ike-group <name> proposal <number> encryption <encryption>

Алгоритм шифрования. Значение по умолчанию — aes128.

set vpn ipsec ike-group <name> proposal <number> hash <hash>

Алгоритм хеширования. Значение по умолчанию — sha1.

set vpn ipsec ike-group <name> proposal <number> prf <prf>

Псевдослучайная функция.

Конфигурация DPD

set vpn ipsec ike-group <name> dead-peer-detection action <action>

Действие, выполняемое для данного CHILD_SA при истечении времени ожидания DPD:

  • trap — установить политику-ловушку, которая будет перехватывать соответствующий трафик и пытаться пересогласовать туннель по требованию.
  • clear — закрыть CHILD_SA без дальнейших действий (по умолчанию).
  • restart — немедленно попытаться пересогласовать CHILD_SA под новой IKE_SA.

set vpn ipsec ike-group <name> dead-peer-detection interval <interval>

Интервал проверки активности (секунды) <2-86400> (по умолчанию 30).

set vpn ipsec ike-group <name> dead-peer-detection timeout <timeout>

Тайм-аут проверки активности (секунды) <2-86400> (по умолчанию 120) только IKEv1

Атрибуты ESP

В VyOS атрибуты ESP задаются через группы ESP. В рамках одной группы может быть указано несколько предложений.

set vpn ipsec esp-group <name> compression

Включить протокол IPComp (сжатие полезной нагрузки IP), позволяющий сжимать содержимое IP-пакетов.

set vpn ipsec esp-group <name> disable-rekey

Не инициировать повторную генерацию ключей SA локально; удалённый узел должен выполнить повторную генерацию до истечения срока.

set vpn ipsec esp-group <name> life-bytes <bytes>

Время жизни ESP (байты) <1024-26843545600000>. Количество переданных байт до истечения срока IPsec SA.

set vpn ipsec esp-group <name> life-packets <packets>

Время жизни ESP (пакеты) <1000-26843545600000>. Количество переданных пакетов до истечения срока IPsec SA.

set vpn ipsec esp-group <name> lifetime <timeout>

Время жизни ESP (секунды) <30-86400> (по умолчанию 3600). Как долго должен существовать конкретный экземпляр соединения (набор ключей шифрования/аутентификации для пакетов пользовательских данных) от успешного согласования до истечения срока.

set vpn ipsec esp-group <name> mode <mode>

Тип соединения:

  • tunnel — режим туннеля (по умолчанию).
  • transport — транспортный режим.

set vpn ipsec esp-group <name> pfs <dh-group>

Требуется ли совершенная прямая секретность (PFS) для ключевого канала соединения, и определяет группу Диффи-Хеллмана для PFS:

  • enable — наследовать группу Диффи-Хеллмана из группы IKE (по умолчанию).
  • disable — отключить PFS.
  • <dh-group> — определить группу Диффи-Хеллмана для PFS.

set vpn ipsec esp-group <name> proposal <number> encryption <encryption>

Алгоритм шифрования. Значение по умолчанию — aes128.

set vpn ipsec esp-group <name> proposal <number> hash <hash>

Алгоритм хеширования. Значение по умолчанию — sha1.

Глобальные настройки IPsec

set vpn ipsec interface <name>

Имя интерфейса, используемое для ограничения исходящих политик IPsec. Может быть указано несколько интерфейсов. Если интерфейс не задан, политики IPsec применяются ко всем интерфейсам.

set vpn ipsec log level <number>

Уровень логирования. Значение по умолчанию — 0.

set vpn ipsec log subsystem <name>

Подсистема демона.

Параметры

set vpn ipsec options disable-route-autoinstall

Не устанавливать маршруты к удалённым сетям автоматически.

set vpn ipsec options flexvpn

Разрешить загрузку идентификатора поставщика FlexVPN (только IKEv2). Отправляет загрузку идентификатора поставщика Cisco FlexVPN (только IKEv2), которая необходима для разрешения устройствам с маркой Cisco согласовывать селекторы локального трафика.

set vpn ipsec options interface <name>

Имя используемого интерфейса. Имя интерфейса, на котором должны быть установлены виртуальные IP-адреса. Если не задано, адреса устанавливаются на исходящем интерфейсе.

set vpn ipsec options virtual-ip

Разрешить установку виртуальных IP-адресов.

Повторная передача IKEv2

Если узел не отвечает на пакеты DPD, маршрутизатор инициирует процедуру повторной передачи. Тайм-аут рассчитывается по следующей формуле:

relative timeout = timeout * base ^ (attempts-1)

set vpn ipsec options retransmission attempts

Количество попыток перед тем, как считать узел недоступным. Значение по умолчанию — 5.

set vpn ipsec options retransmission base

Основание для экспоненциальной задержки. Значение по умолчанию — 1.8.

set vpn ipsec options retransmission timeout

Тайм-аут перед первой повторной передачей (секунды). Значение по умолчанию — 4.

При использовании значений по умолчанию пакеты повторно передаются следующим образом:

ПопыткаФормулаОтносительный тайм-аутАбсолютный тайм-аут
14 * 1.8 ^ 04с4с
24 * 1.8 ^ 17с11с
34 * 1.8 ^ 213с24с
44 * 1.8 ^ 323с47с
54 * 1.8 ^ 442с89с
Узел недоступен4 * 1.8 ^ 576с165с

Типы VPN IPsec сайт-сайт

VyOS поддерживает два типа VPN IPsec: VPN на основе политик и VPN на основе маршрутов.

VPN на основе политик

VPN на основе политик опирается на статически настроенные политики. Каждая политика создаёт независимую IPSec SA. Трафик, соответствующий этим SA, будет зашифрован и направлен удалённому узлу.

VPN на основе маршрутов

VPN на основе маршрутов основано на безопасном прохождении трафика через виртуальный туннельный интерфейс (VTI). Этот тип VPN IPsec позволяет использовать протоколы маршрутизации.

Этапы конфигурации VPN сайт-сайт

Следующий пример показывает конфигурацию для одного маршрутизатора, участвующего в VPN IPsec.

Информация о туннеле:

  • Фаза 1:
    • Шифрование: AES256
    • Хеширование: SHA256
    • PRF: SHA256
    • DH: 14
    • Время жизни: 28800
  • Фаза 2:
    • Режим IPsec: Туннель
    • Шифрование: AES256
    • Хеширование: SHA256
    • PFS: наследуется от DH Фазы 1
    • Время жизни: 3600
  • При использовании VPN на основе политик
    • Удалённая сеть — 192.168.50.0/24. Локальная сеть — 192.168.10.0/24
  • При использовании VPN на основе маршрутов
    • IP-адрес интерфейса VTI — 10.0.0.1/30
Примечание: Не рекомендуется одновременно использовать конфигурации VPN на основе политик и на основе маршрутов для одного и того же узла.

1. Настройка ike-group (Фаза 1 IKE)

set vpn ipsec ike-group IKE close-action 'start'
set vpn ipsec ike-group IKE key-exchange 'ikev1'
set vpn ipsec ike-group IKE lifetime '28800'
set vpn ipsec ike-group IKE proposal 10 dh-group '14'
set vpn ipsec ike-group IKE proposal 10 encryption 'aes256'
set vpn ipsec ike-group IKE proposal 10 hash 'sha256'
set vpn ipsec ike-group IKE proposal 10 prf 'prfsha256'

2. Настройка ESP-group (Фаза 2 IKE)

set vpn ipsec esp-group ESP lifetime '3600'
set vpn ipsec esp-group ESP mode 'tunnel'
set vpn ipsec esp-group ESP pfs 'enable'
set vpn ipsec esp-group ESP proposal 10 encryption 'aes256'
set vpn ipsec esp-group ESP proposal 10 hash 'sha256'

3. Указание публичного IP-адреса интерфейса eth0

set vpn ipsec ipsec-interfaces interface eth0

4. Настройка узла сайт-сайт

Общие сведения о VPN удалённого доступа

VPN удалённого доступа позволяет удалённым пользователям безопасно подключаться к корпоративной сети через туннель IPsec. VyOS поддерживает несколько методов конфигурации VPN удалённого доступа, включая аутентификацию на основе предварительно распределённого ключа, сертификатов и EAP.

Типы VPN удалённого доступа

Удалённый доступ на основе предварительно распределённого ключа

Простейший метод конфигурации удалённого доступа, при котором каждый удалённый пользователь аутентифицируется с использованием одного и того же предварительно распределённого ключа. Подходит для небольших развёртываний или тестовых сред.

Удалённый доступ на основе сертификатов

Использует сертификаты X.509 для аутентификации, обеспечивая более высокий уровень безопасности. Каждый пользователь может иметь свой собственный сертификат, что упрощает управление и отзыв.

Удалённый доступ на основе EAP

Расширяемый протокол аутентификации (EAP) позволяет аутентифицировать пользователей с помощью сервера RADIUS. Поддерживает несколько методов EAP, таких как EAP-MSCHAPv2, EAP-TLS и другие.

Конфигурация VPN удалённого доступа

Основные этапы конфигурации

1. Настройка групп IKE и ESP

set vpn ipsec ike-group IKE-RA lifetime '28800'
set vpn ipsec ike-group IKE-RA proposal 1 encryption 'aes256'
set vpn ipsec ike-group IKE-RA proposal 1 hash 'sha256'
set vpn ipsec ike-group IKE-RA proposal 1 dh-group '14'

set vpn ipsec esp-group ESP-RA lifetime '3600'
set vpn ipsec esp-group ESP-RA proposal 1 encryption 'aes256'
set vpn ipsec esp-group ESP-RA proposal 1 hash 'sha256'

2. Настройка пула IP-адресов

set vpn ipsec remote-access connection RA pool 'RA-POOL'
set vpn ipsec remote-access connection RA pool RA-POOL prefix '100.64.0.0/24'
set vpn ipsec remote-access connection RA pool RA-POOL name-server '192.0.2.53'

3. Настройка соединения удалённого доступа

set vpn ipsec remote-access connection RA authentication local-id '192.0.2.1'
set vpn ipsec remote-access connection RA authentication server-mode 'x509'
set vpn ipsec remote-access connection RA authentication x509 certificate 'ipsec-cert'

set vpn ipsec remote-access connection RA remote-access-interface 'ppp0'
set vpn ipsec remote-access connection RA ike-group 'IKE-RA'
set vpn ipsec remote-access connection RA default-esp-group 'ESP-RA'

Конфигурация на основе EAP-RADIUS

Использование сервера RADIUS для аутентификации пользователей:

set vpn ipsec remote-access connection RA authentication client-mode 'eap-radius'
set vpn ipsec remote-access connection RA eap-radius server 1 address '192.0.2.100'
set vpn ipsec remote-access connection RA eap-radius server 1 key 'testing123'

set vpn ipsec remote-access connection RA pool RA-POOL name-server '192.0.2.53'
set vpn ipsec remote-access connection RA pool RA-POOL prefix '100.64.0.0/24'

Конфигурация на основе предварительно распределённого ключа

Подходит для простых сценариев удалённого доступа:

set vpn ipsec remote-access connection RA authentication mode 'pre-shared-secret'
set vpn ipsec remote-access connection RA authentication id '192.0.2.1'
set vpn ipsec remote-access connection RA authentication local-id '192.0.2.1'

set vpn ipsec remote-access connection RA remote-access-interface 'ppp0'
set vpn ipsec remote-access connection RA ike-group 'IKE-RA'
set vpn ipsec remote-access connection RA default-esp-group 'ESP-RA'

set vpn ipsec remote-access connection RA pool RA-POOL prefix '100.64.0.0/24'

Конфигурация интерфейса удалённого доступа

VPN удалённого доступа использует виртуальные интерфейсы PPP. Необходимо указать интерфейс удалённого доступа:

set interfaces ppp ppp0 description 'Remote Access VPN Interface'
set vpn ipsec remote-access connection RA remote-access-interface 'ppp0'

Устранение неполадок

Типичные проблемы

  • Сбой подключения: проверьте совпадение параметров IKE и ESP, убедитесь, что предварительно распределённый ключ или сертификат верны
  • Сбой аутентификации: убедитесь, что конфигурация сервера RADIUS корректна, проверьте учётные данные пользователя
  • Невозможно получить IP-адрес: проверьте конфигурацию пула IP-адресов, убедитесь, что достаточно доступных адресов
  • Нестабильное соединение: проверьте настройки DPD, скорректируйте параметры времени жизни

Основные диагностические команды

VyOS предоставляет ряд команд для диагностики проблем IPsec:

Просмотр состояния IPsec

Просмотр текущего состояния туннелей IPsec и ассоциаций безопасности:

show vpn ipsec status

Эта команда отображает текущее состояние всех туннелей IPsec, включая информацию о том, установлены ли соединения, активны ли SA (ассоциации безопасности) и т.д.

Просмотр ассоциаций безопасности

Просмотр подробной информации об IKE SA и Child SA:

show vpn ipsec sa

Вывод включает следующую информацию:

  • IKE SA: ассоциации безопасности Фазы 1 IKE
  • Child Sa: ассоциации безопасности Фазы 2 IKE (туннели данных)
  • Состояние: ESTABLISHED, INSTALLED и т.д.
  • Алгоритмы шифрования: используемые алгоритмы шифрования и аутентификации
  • Статистика трафика: количество пакетов и байт, прошедших через туннель

Просмотр конфигурации IPsec

Просмотр текущей действующей конфигурации IPsec:

show vpn ipsec detail

Типичные проблемы и решения

Туннель не устанавливается

Симптомы: состояние туннеля IPsec отображается как «down» или «connecting».

Возможные причины и решения:

  1. Несовпадение предварительно распределённого ключа

    Убедитесь, что предварительно распределённые ключи на обоих концах абсолютно одинаковы, включая регистр и пробелы.

    show vpn ipsec site-to-site peer <peer-address>

  2. Несовпадение предложений IKE

    Проверьте, совместимы ли конфигурации групп IKE на обоих концах. Алгоритм шифрования, алгоритм хеширования и группа Диффи-Хеллмана должны совпадать.

    show vpn ipsec ike-group

  3. Несовпадение предложений ESP

    Убедитесь, что конфигурации групп ESP согласованы.

    show vpn ipsec esp-group

  4. Блокировка межсетевым экраном

    Убедитесь, что межсетевой экран разрешает прохождение следующих портов:

    • UDP 500 (IKE)
    • UDP 4500 (NAT-T)
    • Протокол 50 (ESP)

  5. Ошибки в конфигурации локальной/удалённой подсети

    Проверьте правильность конфигурации локальной и удалённой подсетей для VPN сайт-сайт.

Туннель поднят, но данных нет

Симптомы: туннель IPsec отображается как «up», но данные не могут передаваться через туннель.

Возможные причины и решения:

  1. Child SA не установлена

    Проверьте, была ли Child SA успешно установлена:

    show vpn ipsec sa

    Если Child SA не отображается, это может быть вызвано несовпадением предложений ESP.

  2. Проблемы с маршрутизацией

    Проверьте корректность таблицы маршрутизации, убедившись, что трафик может проходить через туннельный интерфейс:

    show ip route

  3. Проблемы с MTU

    IPsec добавляет накладные расходы на пакет. Если пакеты слишком велики, они могут быть отброшены. Попробуйте настроить MTU:

    set interfaces ethernet <interface> mtu 1400

  4. Асимметричная маршрутизация

    Убедитесь, что обратный трафик также проходит через туннель IPsec; проверьте конфигурацию маршрутизации по политикам.

Туннель часто обрывается

Симптомы: туннель IPsec повторно устанавливается и отключается.

Возможные причины и решения:

  1. Конфигурация DPD (Dead Peer Detection)

    Проверьте, не слишком ли агрессивны настройки DPD:

    show vpn ipsec site-to-site peer <peer-address> dead-peer-detection

    Рекомендуемые настройки DPD:

    • interval: 15-30 секунд
    • timeout: 30-60 секунд
    • action: restart

  2. Сбой повторной генерации ключей IKE

    Проверьте настройки времени жизни IKE, убедившись в совместимости на обоих концах.

  3. Проблемы с NAT

    Если один из концов находится за NAT, убедитесь, что NAT Traversal (NAT-T) включён.

Сбои аутентификации

Симптомы: в логах отображаются ошибки аутентификации.

Возможные причины и решения:

  1. Ошибка предварительно распределённого ключа

    Перенастройте предварительно распределённый ключ, убедившись в точном совпадении на обоих концах.

  2. Проблемы с сертификатами

    При использовании аутентификации на основе сертификатов:

    • Убедитесь, что срок действия сертификата не истёк
    • Проверьте полноту цепочки сертификатов
    • Подтвердите совпадение имён субъектов сертификатов
    • Убедитесь, что сертификат CA правильно установлен

Логи и отладка

Просмотр логов IPsec

Просмотр информации, связанной с IPsec, в системных логах:

show log | match charon

Или просмотр более подробных логов:

tail -f /var/log/syslog | grep charon

Включение подробного логирования

Для получения более подробной отладочной информации можно включить подробное логирование IPsec:

set vpn ipsec logging log-level 3

Описание уровней логирования:

  • 0: только ошибки
  • 1: предупреждения
  • 2: информация (по умолчанию)
  • 3: отладка
  • 4: подробная отладка
Предупреждение: Высокие уровни логирования могут генерировать большой объём записей в логе и влиять на производительность системы. Включайте временно только на время устранения неполадок.

Типичные сообщения в логах

Сообщение лога Значение Решение
received INVALID_ID_INFORMATION Несовпадение идентификатора Проверьте конфигурацию локального и удалённого идентификатора
no matching proposal found Несовпадение предложений Проверьте конфигурацию групп IKE/ESP
authentication failed Сбой аутентификации Проверьте предварительно распределённый ключ или сертификат
peer not responding Узел не отвечает Проверьте сетевое подключение и межсетевой экран
SA lifetime expired Время жизни SA истекло Нормальное явление, проверьте конфигурацию повторной генерации ключей

Захват сетевых пакетов

Когда другие методы не позволяют решить проблему, можно использовать tcpdump для захвата сетевых пакетов:

Захват трафика IKE

tcpdump -i any -n port 500 or port 4500

Захват трафика ESP

tcpdump -i any -n proto 50

Сохранение файла захвата пакетов

tcpdump -i any -n -w /tmp/ipsec.pcap port 500 or port 4500 or proto 50

Для анализа сохранённого файла pcap можно использовать Wireshark.

Сброс и перезапуск

Сброс туннеля IPsec

Сброс туннеля IPsec для конкретного узла:

reset vpn ipsec site-to-site peer <peer-address>

Перезапуск службы IPsec

Для перезапуска всей службы IPsec:

restart vpn ipsec
Предупреждение: Перезапуск службы IPsec прервёт все активные VPN-соединения.

Проблемы производительности

Тест производительности шифрования

Тестирование производительности шифрования системы:

show vpn ipsec performance

Аппаратное ускорение

Если поддерживается аппаратное ускорение шифрования, убедитесь, что оно включено:

show vpn ipsec hardware-acceleration
Совет: Некоторые процессоры поддерживают набор инструкций AES-NI, который может значительно повысить производительность IPsec. Используйте lscpu | grep aes для проверки поддержки.

Обращение в поддержку

Если указанные выше шаги не позволяют решить проблему, соберите следующую информацию и обратитесь в техническую поддержку:

  1. Полный экспорт конфигурации: show configuration commands | match vpn
  2. Вывод состояния IPsec: show vpn ipsec status
  3. Информация об ассоциациях безопасности: show vpn ipsec sa
  4. Системные логи: show log | match charon
  5. Файл захвата сетевых пакетов (при наличии)
