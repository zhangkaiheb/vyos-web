Прокси IGMP

Прокси IGMP позволяет роутерам передавать трафик multicast, такой как IPTV или потоковое видео, между разными сетями, такими как домашние сети и провайдеры. Прокси IGMP зависит от верхнего интерфейса, который обращается к источникам multicast сверху, и одного или нескольких нижних интерфейсов, которые обращаются к локальным сетям или хостам и передают трафик запрашивающим клиентам.

Конфигурация прокси IGMP требует точно один верхний интерфейс и по крайней мере один нижний интерфейс.

Конфигурация

set protocols igmp-proxy interface <interface> role <upstream | downstream>

Настройте операционную роль для указанного интерфейса прокси IGMP.

  • upstream: Обменивается с источниками multicast сверху, чтобы получить multicast-трафик. Для корректной конфигурации требуется ровно один верхний интерфейс.

  • downstream: Обменивается с локальными подсетями или хостами внизу, чтобы распределить запрошенный трафик. Для корректной конфигурации требуется по крайней мере один нижний интерфейс.

Пример:

set protocols igmp-proxy interface eth0 role upstream
set protocols igmp-proxy interface eth1 role downstream
set protocols igmp-proxy interface <interface> alt-subnet <network>

Настройте разрешенную удаленную подсеть для входящего multicast-трафика на указанном интерфейсе прокси IGMP

По умолчанию прокси IGMP принимает multicast-трафик только с непосредственно подключенных подсетей. Если источник multicast находится на удаленной сети, вы должны явно определить разрешенную удаленную подсеть, чтобы разрешить трафик.

Вы можете настроить несколько удаленных подсетей для интерфейса upstream прокси IGMP.

Интерфейсы upstream часто требуют этой конфигурации, потому что источники multicast обычно находятся на внешних подсетях.

Пример:

set protocols igmp-proxy interface eth0 alt-subnet 10.0.0.0/8
set protocols igmp-proxy interface <interface> whitelist <network>

Настройте разрешенную целевую сеть для запросов multicast-трафика на указанном интерфейсе прокси IGMP.

По умолчанию прокси IGMP принимает запросы для всех multicast-целевых сетей. При определении белого списка прокси IGMP пересылает запросы только для указанных multicast-сетей.

Вы можете настроить несколько записей белого списка для интерфейса downstream прокси IGMP.

Пример:

set protocols igmp-proxy interface eth1 whitelist 239.0.0.0/8
set protocols igmp-proxy interface <interface> threshold <1-255>

Настройте порог значения Time-to-Live (TTL) для указанного интерфейса прокси IGMP.

Прокси IGMP удаляет любой пакет multicast с значением TTL ниже, чем настроенное значение порога.

Пример:

set protocols igmp-proxy interface eth0 threshold 5
set protocols igmp-proxy disable-quickleave

Отключите режим quickleave для прокси IGMP.

Если отключен, прокси IGMP не отправляет сообщение Leave вверх по цепи при получении сообщения Leave вниз по цепи, предотвращая немедленное завершение трафика multicast сверху. Прокси IGMP также прекращает проверку нижних интерфейсов на сообщения о членстве. Если клиент внизу отправляет новое сообщение, прокси IGMP игнорирует его и не возобновляет доставку запрошенного трафика.

Примечание

Отключение режима quickleave заставляет прокси IGMP действовать точно так же, как стандартный клиент multicast на верхнем интерфейсе.

Примечание

Отключение режима quickleave увеличивает риск перегрузки пропускной способности сети.

Пример:

set protocols igmp-proxy disable-quickleave
set protocols igmp-proxy disable

Отключите прокси IGMP на маршрутизаторе.

Пример:

set protocols igmp-proxy disable

Работа

restart igmp-proxy

Перезапустите процесс прокси IGMP.

Пример

В этом примере локальная ЛАН на интерфейсе eth1 работает за NAT. Чтобы разрешить локальным клиентам получать multicast-трафик, исходящий из сети источника 198.51.100.0/24 на интерфейсе WAN (eth0), настройте прокси IGMP следующим образом:

set protocols igmp-proxy interface eth0 role upstream
set protocols igmp-proxy interface eth0 alt-subnet 198.51.100.0/24
set protocols igmp-proxy interface eth1 role downstream
