Синхронизация конфигурации

Служба синхронизации конфигурации (config-sync) в VyOS реплицирует выбранные разделы конфигурации одного маршрутизатора на другой. Это устраняет необходимость вручную отражать изменения конфигурации с основного маршрутизатора на резервный.

Синхронизация выполняется посредством хука post-commit на основном маршрутизаторе. Хук наблюдает за разделами, выбранными для синхронизации. При изменении любого из них при коммите хук вызывает HTTPS API на резервном маршрутизаторе и отправляет текущее состояние всех выбранных разделов в одном из следующих режимов:

  • load: Заменяет выбранные разделы на резервном маршрутизаторе версией с основного. Все, что существует только на резервном внутри этих разделов, удаляется.

  • set: Объединяет версию выбранных разделов с основного маршрутизатора на резервном. Конфликтующие значения перезаписываются основным. Записи, существующие только на резервном, сохраняются.

Синхронизация строго односторонняя от основного к резервному; изменения, сделанные на резервном, не отправляются обратно.

Оба маршрутизатора должны быть онлайн во время коммита на основном, который модифицирует настроенный раздел. Если резервный недоступен, коммит на основном успешно завершается, но конфигурация не синхронизируется, и ошибка записывается в системный журнал.

Конфигурация

Параметры резервного маршрутизатора

set service config-sync secondary address <address>

Настройте адрес резервного маршрутизатора.

Основной маршрутизатор отправляет синхронизированную конфигурацию по HTTPS API резервного маршрутизатора. Значение может быть IPv4-адресом, IPv6-адресом или FQDN. Это значение обязательно.

Примечание

Адрес должен быть установлен каждый раз, когда настраивается service config-sync. В противном случае коммит будет отклонен.

Пример:

set service config-sync secondary address 192.0.2.112
set service config-sync secondary port <1-65535>

Настройте TCP-порт, на котором HTTPS API резервного маршрутизатора слушает.

Значение должно совпадать с портом, настроенным под service https port на резервном маршрутизаторе. Если они отличаются, коммит на основном маршрутизаторе успешен, но синхронизация после коммита не удалась. Резервный маршрутизатор не обновляется, и основной маршрутизатор записывает ошибку в системный журнал.

По умолчанию 443, соответствует значению по умолчанию service https port.

Пример:

set service config-sync secondary port 8443
set service config-sync secondary key <key>

Настройте ключ HTTPS API, который основной маршрутизатор использует для аутентификации на HTTPS API резервного маршрутизатора.

Значение должно совпадать с ключом, настроенным под service https api keys id <ID> key на резервном маршрутизаторе. Если на резервном маршрутизаторе нет соответствующего ключа, коммит на основном маршрутизаторе все равно успешен, но синхронизация после коммита не удалась. Резервный маршрутизатор не обновляется, и основной маршрутизатор записывает ошибку в системный журнал.

Примечание

Это значение должно быть установлено каждый раз, когда настраивается service config-sync. В противном случае коммит будет отклонен.

Пример:

set service config-sync secondary key 'foo'
set service config-sync secondary timeout <1-3600>

Настройте, сколько секунд основной маршрутизатор ждет ответа HTTPS от резервного маршрутизатора после отправки конфигурации.

По умолчанию 60 секунд.

Пример:

set service config-sync secondary timeout 120

Режим синхронизации

set service config-sync mode <load | set>

Настройте, как резервный маршрутизатор применяет конфигурацию, отправленную основным:

  • load: Заменяет выбранные разделы на резервном маршрутизаторе версией с основного. Все, что существует только на резервном внутри этих разделов, удаляется.

  • set: Объединяет версию выбранных разделов с основного маршрутизатора на резервном. Конфликтующие значения перезаписываются основным. Записи, существующие только на резервном, сохраняются.

Примечание

Это значение должно быть установлено каждый раз, когда настраивается service config-sync. В противном случае коммит будет отклонен.

Пример:

set service config-sync mode load

Разделы для синхронизации

set service config-sync section <section>

Настройте один или несколько разделов конфигурации, которые будут синхронизироваться с основного на резервный маршрутизатор.

Повторите команду, чтобы добавить дополнительные разделы. Если какой-либо настроенный раздел был изменен при коммите на основном маршрутизаторе, хук отправляет текущее состояние всех настроенных разделов на резервный. Если ни один из настроенных разделов не был изменен, хук ничего не делает.

Поддерживаемые разделы:

  • firewall

  • interfaces <bonding | bridge | dummy | ethernet | geneve | input | l2tpv3 | loopback | macsec | openvpn | pppoe | pseudo-ethernet | sstpc | tunnel | virtual-ethernet | vti | vxlan | wireguard | wireless | wwan>

  • nat

  • nat66

  • pki

  • policy

  • protocols <babel | bfd | bgp | failover | igmp-proxy | isis | mpls | nhrp | ospf | ospfv3 | pim | pim6 | rip | ripng | rpki | segment-routing | static>

  • qos <interface | policy>

  • service <console-server | dhcp-relay | dhcp-server | dhcpv6-relay | dhcpv6-server | dns | lldp | mdns | monitoring | ndp-proxy | ntp | snmp | tftp-server | webproxy>

  • system <conntrack | flow-accounting | login | option | sflow | static-host-mapping | sysctl | time-zone>

  • vpn

  • vrf

Примечание

Должен быть установлен хотя бы один раздел каждый раз, когда настраивается service config-sync. В противном случае коммит будет отклонен.

Пример:

set service config-sync section protocols ospf
set service config-sync section system time-zone

Работа

show configuration secondary sync [commands] [running | candidate | saved [<config-node-path>]]

Показать различие между локальной конфигурацией на основном и текущей конфигурацией на резервном.

Команда получает текущую конфигурацию резервного маршрутизатора через HTTPS API, поэтому резервный маршрутизатор должен быть доступен.

Локальная конфигурация по умолчанию — running и может быть установлена в candidate (незафиксированные изменения) или saved (последняя сохраненная конфигурация). Сторона удаленного — всегда текущая конфигурация резервного маршрутизатора.

По умолчанию различие показывается в формате конфигурации со скобками, где строки, существующие только на резервном, предваряются символом -, а строки, существующие только на основном, предваряются символом +. Опциональное слово commands отображает то же самое различие в виде последовательности команд set и delete конфигурации, где set перечисляет пути, присутствующие только на основном, а delete перечисляет пути, присутствующие только на резервном.

Опциональный аргумент <config-node-path> ограничивает различие одним разделом и должен быть одним из разделов, уже настроенных под set service config-sync section. Если опущен, различие охватывает все настроенные разделы.

Примеры:

# Сравнить полную текущую конфигурацию с резервным
show configuration secondary sync

# Сравнить только конфигурацию протокола OSPF с резервным
show configuration secondary sync running protocols ospf

# Сравнить кандидатскую конфигурацию с резервным,
# отобразить как команды
show configuration secondary sync commands candidate

Пример

В следующем примере синхронизируются разделы system time-zone и protocols ospf с маршрутизатора A (основной, 192.0.2.1) на маршрутизатор B (резервный, 192.0.2.112). HTTPS API маршрутизатора B слушает на TCP-порту 8443.

Включите и настройте службу HTTPS API на маршрутизаторе B:

set service https listen-address '192.0.2.112'
set service https port '8443'
set service https api keys id primary key 'foo'
set service https api rest

Настройте службу config-sync на маршрутизаторе A:

set service config-sync mode 'load'
set service config-sync secondary address '192.0.2.112'
set service config-sync secondary port '8443'
set service config-sync secondary key 'foo'
set service config-sync section protocols 'ospf'
set service config-sync section system 'time-zone'

Внесите изменения на маршрутизаторе A, которые попадают под один из синхронизированных разделов. Хук post-commit автоматически запускается при коммите:

vyos@vyos-A# set system time-zone 'America/Los_Angeles'
vyos@vyos-A# commit
INFO:vyos_config_sync:Config synchronization: Mode=load, Secondary=192.0.2.112
vyos@vyos-A# save

vyos@vyos-A# set protocols ospf area 0 network '198.51.100.0/30'
vyos@vyos-A# commit
INFO:vyos_config_sync:Config synchronization: Mode=load, Secondary=192.0.2.112
vyos@vyos-A# save

Каждый коммит на маршрутизаторе A модифицирует один раздел, но так как хук отправляет все настроенные разделы, когда любой из них изменяется, оба коммита заменяют полное состояние system и protocols ospf на маршрутизаторе B.

Проверьте, были ли изменения применены на маршрутизаторе B:

vyos@vyos-B:~$ show configuration commands | match time-zone
set system time-zone 'America/Los_Angeles'

vyos@vyos-B:~$ show configuration commands | match ospf
set protocols ospf area 0 network '198.51.100.0/30'
