Babel

Протокол Babel обеспечивает надежный и эффективный маршрут как для проводных, так и для беспроводных сетей в виде решетки. По умолчанию Babel использует метрику количества переходов на проводных связях и вариант ожидаемого количества передач (ETX) на беспроводных связях. Администраторы могут настроить Babel с учетом разнообразия радиочастот, автоматически вычислять задержку на линии связи и включать эту задержку в маршрутную метрику. RFC 8966 определяет протокол Babel.

Babel — это двойной протокол. Одна инстанция Babel одновременно маршрутизирует трафик IPv4 и IPv6.

Общая конфигурация

VyOS не требует специальной команды для запуска процесса Babel. Система автоматически запускает процесс маршрутизации, когда вы настраиваете первый интерфейс, поддерживающий Babel.

set protocols babel interface <interface>

Включить маршрутизацию Babel на указанном интерфейсе.

Система немедленно начинает отправку и получение пакетов Babel на этом интерфейсе.

Дополнительная конфигурация

set protocols babel parameters diversity

Включить маршрутизацию с учетом разнообразия радиочастот для процесса Babel.

Рекомендуется включить эту функцию для сетей с большим количеством беспроводных узлов.

Примечание

При включении маршрутизации с учетом разнообразия, также следует настроить параметры diversity-factor и channel.

set protocols babel parameters diversity-factor <1-256>

Настроить множитель для маршрутизации с учетом разнообразия, в единицах 1/256.

Меньшие множители дают большее значение разнообразию при выборе маршрута. Значение по умолчанию равно 256, что отключает маршрутизацию с учетом разнообразия. На узлах с несколькими независимыми радио, настройте значение 128 или меньше.

set protocols babel parameters resend-delay <20-655340>

Настроить задержку в миллисекундах до повторной отправки важного запроса или обновления.

Значение по умолчанию составляет 2000 мс.

set protocols babel parameters smoothing-half-life <0-65534>

Настроить постоянную времени, в секундах, для алгоритма сглаживания, используемого для реализации гистерезиса.

Большие значения уменьшают колебания маршрутов, но немного увеличивают время сходимости. Значение 0 отключает гистерезис и подходит для проводных сетей. Значение по умолчанию — 4 секунды.

Конфигурация интерфейсов

set protocols babel interface <interface> type <auto|wired|wireless>

Настроить тип сети для интерфейса, поддерживающего Babel.

Выберите из следующих:

  • auto: Babel автоматически определяет, является ли интерфейс проводным или беспроводным.

  • wired: Babel включает оптимизации для проводных интерфейсов.

  • wireless: Babel отключает оптимизации, подходящие только для проводных интерфейсов. Указание wireless всегда верно, но может привести к более медленной сходимости и увеличению трафика маршрутизации.

set protocols babel interface <interface> split-horizon <default|disable|enable>

Настроить поведение маршрутизации split-horizon для указанного интерфейса.

Используйте один из следующих вариантов:

  • default: Babel автоматически включает split-horizon на проводных интерфейсах и отключает его на беспроводных интерфейсах.

  • enable: Babel включает split-horizon на интерфейсе. Эта оптимизация должна использоваться только на симметричных, транзитивных (проводных) сетях.

  • disable: Babel отключает split-horizon на интерфейсе. Отключение split-horizon всегда безопасно и правильно.

set protocols babel interface <interface> hello-interval <20-655340>

Настроить интервал, в миллисекундах, между запланированными сообщениями hello на указанном интерфейсе.

На проводных связях Babel обнаруживает сбои в соединении в течение двух интервалов hello. На беспроводных связях качество связи пересчитывается каждый интервал. Значение по умолчанию — 4000 мс.

set protocols babel interface <interface> update-interval <20-655340>

Настроить интервал, в миллисекундах, между запланированными обновлениями маршрутизации на указанном интерфейсе.

Поскольку Babel широко использует триггерные обновления, вы можете увеличить это значение на надежных связях с минимальным количеством потери пакетов. Значение по умолчанию — 20000 мс.

set protocols babel interface <interface> rxcost <1-65534>

Настроить базовую стоимость приема для указанного интерфейса.

Babel применяет это значение в зависимости от настроенного типа сети:

  • wired: Значение — это стоимость маршрутизации,advertised соседними роутерами.

  • wireless: Значение — это множитель, используемый для вычисления стоимости приема ETX (Expected Transmission Count).

Значение по умолчанию — 256.

set protocols babel interface <interface> rtt-decay <1-256>

Настроить коэффициент затухания для экспоненциального скользящего среднего образцов RTT, в единицах 1/256.

Большие значения быстрее отбрасывают старые образцы. Значение по умолчанию — 42.

set protocols babel interface <interface> rtt-min <1-65535>

Настроить минимальное RTT, в миллисекундах, при котором стоимость до соседа начинает увеличиваться.

Дополнительная стоимость линейна в (rtt - rtt-min). Значение по умолчанию — 10 мс.

set protocols babel interface <interface> rtt-max <1-65535>

Настроить максимальное RTT, в миллисекундах, выше которого стоимость до соседа перестает увеличиваться.

Значение по умолчанию — 120 мс.

set protocols babel interface <interface> max-rtt-penalty <0-65535>

Настроить максимальную стоимость, добавляемую к соседу, когда RTT соответствует или превышает rtt-max.

Установка этого значения в 0 отключает стоимость, основанную на RTT. Значение по умолчанию — 150.

set protocols babel interface <interface> enable-timestamps

Настроить добавление временных меток в каждое сообщение Hello и IHU для расчета значений RTT.

Рекомендуется включить временные метки для туннельных интерфейсов.

set protocols babel interface <interface> channel <1-254|interfering|noninterfering>

Настроить идентификатор канала, который использует маршрутизация с учетом разнообразия для указанного интерфейса.

Интерфейсы взаимодействуют друг с другом на основе назначенного идентификатора канала:

  • 1–254: Интерфейс взаимодействует с интерфейсами, которые делят тот же номер канала и с интерфейсами, настроенными как interfering.

  • interfering: Интерфейс взаимодействует со всеми остальными, кроме тех, которые настроены как noninterfering.

  • noninterfering: Интерфейс взаимодействует только с самим собой.

Конфигурация перераспределения

set protocols babel redistribute <ipv4|ipv6> <route source>

Настроить перераспределение информации о маршрутизации из указанного источника маршрута в процесс Babel.

Доступны следующие источники маршрутов:

  • ipv4: bgp, connected, eigrp, isis, kernel, nhrp, ospf, rip, static

  • ipv6: bgp, connected, eigrp, isis, kernel, nhrp, ospfv3, ripng, static

set protocols babel distribute-list <ipv4|ipv6> access-list <in|out> <number>

Настроить глобальное фильтрование маршрутов Babel с помощью списка доступа.

Укажите направление, в котором применяется список доступа:

  • in: Фильтрует входящие маршруты.

  • out: Фильтрует исходящие маршруты.

set protocols babel distribute-list <ipv4|ipv6> interface <interface> access-list <in|out> <number>

Настроить фильтрование маршрутов Babel на указанном интерфейсе с помощью списка доступа.

Укажите направление, в котором применяется список доступа:

  • in: Фильтрует входящие маршруты.

  • out: Фильтрует исходящие маршруты.

set protocols babel distribute-list <ipv4|ipv6> prefix-list <in|out> <name>

Настроить глобальное фильтрование маршрутов Babel с помощью списка префиксов.

Укажите направление, в котором применяется список префиксов:

  • in: Фильтрует входящие маршруты.

  • out: Фильтрует исходящие маршруты.

set protocols babel distribute-list <ipv4|ipv6> interface <interface> prefix-list <in|out> <name>

Настроить фильтрование маршрутов Babel на указанном интерфейсе с помощью списка префиксов.

Укажите направление, в котором применяется список префиксов:

  • in: Фильтрует входящие маршруты.

  • out: Фильтрует исходящие маршруты.

Пример конфигурации

Базовая двухузловая сеть Babel

Цель: В следующем примере два маршрутизатора (узел 1 и узел 2) соединяются через их интерфейсы eth0 и используют протокол маршрутизации Babel для рекламы (перераспределения) локально настроенных сетей каждого маршрутизатора (представленных адресами loopback) друг другу.

Узел 1:

# Настройте адреса loopback (локальные сети) и физические (eth0)
set interfaces loopback lo address 10.1.1.1/32
set interfaces loopback lo address fd12:3456:dead:beef::1/128
set interfaces ethernet eth0 address 192.168.1.1/24

# Включите Babel на физической связи
set protocols babel interface eth0 type wired

# Сообщите Babel, чтобы он рекламировал (перераспределял) локально настроенные сети
set protocols babel redistribute ipv4 connected
set protocols babel redistribute ipv6 connected

Узел 2:

# Настройте адреса loopback (локальные сети) и физические (eth0)
set interfaces loopback lo address 10.2.2.2/32
set interfaces loopback lo address fd12:3456:beef:dead::2/128
set interfaces ethernet eth0 address 192.168.1.2/24

# Включите Babel на физической связи
set protocols babel interface eth0 type wired

# Сообщите Babel, чтобы он рекламировал (перераспределял) локально настроенные сети
set protocols babel redistribute ipv4 connected
set protocols babel redistribute ipv6 connected
