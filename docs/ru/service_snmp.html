SNMP

SNMP — это интернет-стандартный протокол для сбора и организации информации о управляемых устройствах на IP-сетях и для изменения этой информации, чтобы изменить поведение устройств. Устройства, которые обычно поддерживают SNMP, включают кабельные модемы, маршрутизаторы, коммутаторы, серверы, рабочие станции, принтеры и т. д.

SNMP широко используется в управлении сетью для мониторинга сети. SNMP предоставляет управляющую информацию в виде переменных на управляемых системах, организованных в базе данных управляющей информации (MIB), которая описывает статус и конфигурацию системы. Эти переменные затем могут быть удаленно запрошены (и, в некоторых случаях, изменены) управляющими приложениями.

Было разработано и внедрено три значимые версии SNMP. SNMPv1 — оригинальная версия протокола. Более новые версии, SNMPv2c и SNMPv3, предлагают улучшения в производительности, гибкости и безопасности.

SNMP является компонентом набора протоколов Интернета, как определено Инженерной задачей по интернету (IETF). Он состоит из набора стандартов для управления сетью, включая протокол прикладного уровня, схему базы данных и набор объектов данных.

Обзор и основные понятия

В типичном использовании SNMP, одно или несколько административных компьютеров, называемых менеджерами, имеют задачу мониторинга или управления группой хостов или устройств на компьютерной сети. Каждое управляемое устройство выполняет программный компонент, называемый агентом, который сообщает информацию через SNMP менеджеру.

Сеть, управляемая SNMP, состоит из трех ключевых компонентов:

  • Управляемые устройства

  • Агент — программное обеспечение, работающее на управляемых устройствах

  • Станция управления сетью (NMS) — программное обеспечение, работающее на менеджере

Управляемое устройство — это узел сети, реализующий интерфейс SNMP, который позволяет односторонний (только чтение) или двусторонний (чтение и запись) доступ к специфическим данным узла. Управляемые устройства обмениваются информацией о конкретных узлах с NMS. Иногда их называют элементами сети, управляемые устройства могут быть любым типом устройства, включая, но не ограничиваясь, маршрутизаторами, серверами доступа, коммутаторами, кабельными модемами, мостами, концентраторами, IP-телефонами, IP-видеокамерами, компьютерными хостами и принтерами.

Агент — это модуль программного обеспечения для управления сетью, находящийся на управляемом устройстве. Агент имеет локальное знание о управляющей информации и переводит эту информацию в или из формата SNMP.

Станция управления сетью выполняет приложения, которые мониторят и управляют управляемыми устройствами. NMS обеспечивают основную часть процессорных ресурсов и памяти, необходимых для управления сетью. На любой управляемой сети может существовать одно или несколько NMS.

Примечание

VyOS поддерживает как IPv4, так и IPv6.

Версии протокола SNMP

VyOS сам поддерживает SNMPv2 (версия 2) и SNMPv3 (версия 3), где последняя рекомендуется из-за улучшенной безопасности (опциональная аутентификация и шифрование).

SNMPv2

SNMPv2 — это оригинальная и наиболее часто используемая версия. Для авторизации клиентов SNMP использует понятие сообществ. Сообщества могут иметь авторизацию только для чтения (это наиболее часто), или для чтения и записи (этот вариант не активно используется в VyOS).

SNMP может работать синхронно или асинхронно. В синхронной коммуникации система мониторинга периодически запрашивает маршрутизатор. В асинхронном случае маршрутизатор отправляет уведомление на «trap» (управляющий хост).

SNMPv2 не поддерживает никаких механизмов аутентификации, кроме адреса источника клиента, поэтому вы должны указать адреса клиентов, разрешенных для мониторинга маршрутизатора. Обратите внимание, что SNMPv2 также не поддерживает шифрования и всегда отправляет данные в открытом виде.

Пример

# Определить сообщество
set service snmp community routers authorization ro

# Разрешить доступ к мониторингу со всей сети
set service snmp community routers network 192.0.2.0/24
set service snmp community routers network 2001::db8:ffff:eeee::/64

# Разрешить доступ к мониторингу с конкретных адресов
set service snmp community routers client 203.0.113.10
set service snmp community routers client 203.0.113.20

# Определить дополнительную информацию о маршрутизаторе
set service snmp location "UK, London"
set service snmp contact "[email protected]"

# Цель тревоги, если вы хотите асинхронную связь
set service snmp trap-target 203.0.113.10

# Слушать только на определенных IP-адресах (порт по умолчанию 161)
set service snmp listen-address 172.16.254.36 port 161
set service snmp listen-address 2001:db8::f00::1

SNMPv3

SNMPv3 (третья версия протокола SNMP) ввёл целый ряд новых функций безопасности, которых не было в предыдущих версиях. Безопасность была одной из самых больших слабостей SNMP до версии 3. Аутентификация в SNMP-версиях 1 и 2 сводится к простому паролю (строке сообщества), передаваемому в открытом виде между менеджером и агентом. Каждое сообщение SNMPv3 содержит параметры безопасности, закодированные как октетная строка. Значение этих параметров зависит от используемой модели безопасности.

Подход к безопасности в SNMPv3 направлен на:

  • Конфиденциальность — шифрование пакетов, чтобы предотвратить прослушивание неавторизованным источником.

  • Целостность — целостность сообщений, чтобы убедиться, что пакет не был изменён во время передачи, включая опциональный механизм защиты от повторного использования пакета.

  • Аутентификацию — чтобы проверить, что сообщение исходит от действительного источника.

Пример

  • Пусть демон SNMP слушает только на IP-адресе 192.0.2.1

  • Настроить нового пользователя SNMP с именем «vyos» и паролем «vyos12345678»

  • Новый пользователь будет использовать SHA/AES для аутентификации и конфиденциальности

set service snmp listen-address 192.0.2.1
set service snmp location 'VyOS Datacenter'
set service snmp v3 engineid '000000000000000000000002'
set service snmp v3 group default mode 'ro'
set service snmp v3 group default view 'default'
set service snmp v3 user vyos auth plaintext-password 'vyos12345678'
set service snmp v3 user vyos auth type 'sha'
set service snmp v3 user vyos group 'default'
set service snmp v3 user vyos privacy plaintext-password 'vyos12345678'
set service snmp v3 user vyos privacy type 'aes'
set service snmp v3 view default oid 1

После выполнения commit, текстовые пароли будут хешироваться и храниться в вашей конфигурации. Результирующая конфигурация CLI будет выглядеть следующим образом:

vyos@vyos# show service snmp
 listen-address 192.0.2.1 {
 }
 location "VyOS Datacenter"
 v3 {
     engineid 000000000000000000000002
     group default {
         mode ro
         view default
     }
     user vyos {
         auth {
             encrypted-password 4e52fe55fd011c9c51ae2c65f4b78ca93dcafdfe
             type sha
         }
         group default
         privacy {
             encrypted-password 4e52fe55fd011c9c51ae2c65f4b78ca93dcafdfe
             type aes
         }
     }
     view default {
         oid 1 {
         }
     }
 }

Вы можете протестировать функциональность SNMPv3 с любого Linux-системы, просто запустив следующую команду: snmpwalk -v 3 -u vyos -a SHA -A vyos12345678 -x AES -X vyos12345678 -l authPriv 192.0.2.1 .1

MIBs VyOS

Все MIBs SNMP находятся в каждом образе VyOS здесь: /usr/share/snmp/mibs/

Вы сможете загрузить файлы с помощью SCP, после того как сервис SSH будет активирован, например:

scp -r vyos@your_router:/usr/share/snmp/mibs /your_folder/mibs

Расширения SNMP

Чтобы расширить функциональность агента SNMP, можно запускать пользовательские скрипты каждый раз, когда вызывается агент. Это можно достичь, используя произвольные команды расширения. Первым шагом является создание рабочего скрипта, затем загрузка его на ваш экземпляр VyOS через команду scp your_script.sh vyos@your_router:/config/user-data. После загрузки скрипта, он должен быть настроен с помощью команды ниже.

set service snmp script-extensions extension-name my-extension script your_script.sh
commit

OID .1.3.6.1.4.1.8072.1.3.2.3.1.1.4.116.101.115.116, при вызове, будет содержать вывод расширения.

root@vyos:/home/vyos# snmpwalk -v2c  -c public 127.0.0.1 nsExtendOutput1
NET-SNMP-EXTEND-MIB::nsExtendOutput1Line."my-extension" = STRING: hello
NET-SNMP-EXTEND-MIB::nsExtendOutputFull."my-extension" = STRING: hello
NET-SNMP-EXTEND-MIB::nsExtendOutNumLines."my-extension" = INTEGER: 1
NET-SNMP-EXTEND-MIB::nsExtendResult."my-extension" = INTEGER: 0

SolarWinds

Если вы используете SolarWinds Orion как NMS, вы также можете использовать Управление шаблонами устройств. Шаблон для VyOS можно легко импортировать.

Создайте файл с именем VyOS-1.3.6.1.4.1.44641.ConfigMgmt-Commands с следующим содержанием:

<Configuration-Management Device="VyOS" SystemOID="1.3.6.1.4.1.44641">
    <Commands>
        <Command Name="Reset" Value="set terminal width 0${CRLF}set terminal length 0"/>
        <Command Name="Reboot" Value="reboot${CRLF}Yes"/>
        <Command Name="EnterConfigMode" Value="configure"/>
        <Command Name="ExitConfigMode" Value="commit${CRLF}exit"/>
        <Command Name="DownloadConfig" Value="show configuration commands"/>
        <Command Name="SaveConfig" Value="commit${CRLF}save"/>
        <Command Name="Version" Value="show version"/>
        <Command Name="MenuBased" Value="False"/>
        <Command Name="VirtualPrompt" Value=":~"/>
    </Commands>
</Configuration-Management>
