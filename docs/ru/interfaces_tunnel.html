Туннель

Интерфейсы туннелей — это виртуальные связи, которые передают инкапсулированный трафик между частными сетями или хостами через общественную инфраструктуру, например, интернет. Они работают с использованием протоколов инкапсуляции для упаковки исходного трафика для транспортировки. Поддерживаемые протоколы включают GRE, IPIP, IPIP6, IP6IP6 и 6in4 (SIT).

Хотя GRE часто является предпочтительным универсальным решением благодаря своей гибкости, другие протоколы инкапсуляции могут быть более подходящими для конкретных случаев.

VyOS использует один тип интерфейса туннеля для всех этих протоколов. Нет отдельных интерфейсов GRE, IPIP или IP6IP6; вместо этого выбирается нужный протокол инкапсуляции в конфигурации set interfaces tunnel.

Опции конфигурации для каждого протокола описаны ниже.

Предупреждение

Не изменяйте тип инкапсуляции уже настроенных интерфейсов туннеля, так как это может нарушить их зависимые настройки.

Общая конфигурация интерфейса

set interfaces tunnel <interface> address <address>

Настройте одно или несколько IP-адресов интерфейса.

<address> поддерживает IPv4 и IPv6 в формате CIDR. Например, используйте 192.0.2.1/24 для IPv4 или 2001:db8::1/64 для IPv6.

Пример:

set interfaces tunnel tun0 address 192.0.2.1/24
set interfaces tunnel tun0 address 2001:db8::1/64
set interfaces tunnel <interface> description <description>

Настройте ясное и описательное имя для интерфейса.

Это имя появляется в команде show interfaces и инструментах мониторинга на основе SNMP.

Пример:

set interfaces tunnel tun0 description 'This is an interface running on VyOS.'
set interfaces tunnel <interface> disable

Отключите интерфейс.

Интерфейс будет установлен в состояние административно выключенное (A/D).

Пример:

set interfaces tunnel tun0 disable
set interfaces tunnel <interface> disable-flow-control

Отключите управление потоком Ethernet (IEEE 802.3x pause frames) на интерфейсе.

Управление потоком Ethernet, определенное стандартом IEEE 802.3x, временно прекращает передачу данных, чтобы предотвратить потерю пакетов при перегрузке сети. Например, когда отправитель передает данные быстрее, чем получатель может их обработать.

Отключение управления потоком Ethernet означает, что интерфейс не будет сигнализировать подключенному устройству о приостановке передачи и будет удалять пакеты, если он перегружен.

Пример:

set interfaces tunnel tun0 disable-flow-control
set interfaces tunnel <interface> disable-link-detect

Отключите обнаружение изменения состояния физической линии на интерфейсе, например, когда кабель отсоединен.

По умолчанию интерфейс обнаруживает изменения состояния физической линии.

Пример:

set interfaces tunnel tun0 disable-link-detect
set interfaces tunnel <interface> mtu <mtu>

Настройте MTU на интерфейсе.

Это значение определяет максимальный размер пакета в байтах, который интерфейс передает без фрагментации.

Пример:

set interfaces tunnel tun0 mtu 1600
set interfaces tunnel <interface> ip adjust-mss <mss | clamp-mss-to-pmtu>

Настройте MSS , объявляемый в исходящих пакетах TCP SYN на указанном интерфейсе.

Путем ограничения значения MSS в пакетах TCP SYN, вы явно информируете удаленный сторону не отправлять пакеты большего размера, чем этот. Это предотвращает проблемы с соединением, возникающие при неудачной проверке PMTUD.

Доступны следующие варианты:

  • mss: Устанавливает MSS в определенное значение, в байтах. Используйте этот вариант, если нужно зафиксировать определенный MSS, например, для устранения проблем с доступностью или соответствия специфическим требованиям сети.

  • clamp-mss-to-pmtu: Рouters автоматически рассчитывает MSS, равный MTU интерфейса минус 40 байт для IPv4 (20 байт для заголовка IPv4 и 20 байт для заголовка TCP). Этот вариант рекомендуется для автоматического установления правильного значения.

set interfaces tunnel <interface> ip arp-cache-timeout

Настройте, как долго ARP-запись остается действительной после изучения сопоставления IP-адреса и MAC-адреса на этом интерфейсе.

По умолчанию длительность составляет 30 секунд.

ARP-запись остается действительной, если она получает положительный ответ от верхних уровней протоколов.

Пример:

set interfaces tunnel tun0 ip arp-cache-timeout 180
set interfaces tunnel <interface> ip disable-arp-filter

Настройте фильтрацию ARP на этом интерфейсе.

Стандартное поведение: Ядро отвечает на запросы ARP на этом интерфейсе только в том случае, если трафик будет маршрутизирован обратно к отправителю ARP через этот конкретный интерфейс.

Если настроено: Ядро отвечает на запросы ARP на этом интерфейсе для любого IP-адреса, настроенного на локальном хосте, независимо от того, какой конкретный интерфейс этому IP-адресу принадлежит, и независимо от таблицы маршрутизации. Это отражает концепцию Linux, согласно которой IP-адреса принадлежат хосту, а не отдельным интерфейсам.

Пример:

set interfaces tunnel tun0 ip disable-arp-filter
set interfaces tunnel <interface> ip disable-forwarding

Настройте интерфейс на работу в режиме хоста или роутера.

Если настроено, интерфейс переключается в режим хоста, и IPv4-пересылка отключается на нем.

Пример:

set interfaces tunnel tun0 ip disable-forwarding
set interfaces tunnel <interface> ip enable-directed-broadcast

Настройте, будут ли передаваться пакеты IP-направленного широковещания, полученные на этом интерфейсе.

Стандартное поведение: Пакеты IP-направленного широковещания отбрасываются.

Если настроено: Пакеты IP-направленного широковещания передаются всем хостам на подсети назначения, как определено в RFC 1812 и RFC 2644.

Пример:

set interfaces tunnel tun0 ip enable-directed-broadcast
set interfaces tunnel <interface> ip enable-arp-accept

Настройте, как обрабатывать бесплатные ARP на этом интерфейсе.

Если настроено, сопоставление IP-адреса и MAC-адреса добавляется в таблицу ARP на основе бесплатных ARP-запросов или ответов.

Примечание

Если в таблице ARP уже есть IP-адрес из бесплатного ARP, его запись обновляется независимо от того, настроено ли это настройка.

Пример:

set interfaces tunnel tun0 ip enable-arp-accept
set interfaces tunnel <interface> ip enable-arp-announce

Настройте выбор источника IP-адреса для ARP-запросов на этом интерфейсе.

Стандартное поведение: Ядро может использовать любой IP-адрес, которым владеет хост, в качестве исходного IP-адреса в ARP-запросах на этом интерфейсе.

Если настроено: Ядро сначала пытается выбрать исходный IP-адрес, настроенный на интерфейсе, который имеет общую подсеть с целевым IP-адресом. Если такой подсети нет, ядро выбирает IP-адрес, который обычно используется (на основе таблицы маршрутизации для достижения целевой цели).

Пример:

set interfaces tunnel tun0 ip enable-arp-announce
set interfaces tunnel <interface> ip enable-arp-ignore

Настройте, какие ARP-запросы будут игнорироваться на этом интерфейсе.

Стандартное поведение: Ядро отвечает на ARP-запросы для любых локальных IP-адресов, независимо от того, к какому интерфейсу они привязаны.

Если настроено: Ядро отвечает на ARP-запросы только в том случае, если целевой IP-адрес привязан к этому конкретному интерфейсу.

Пример:

set interfaces tunnel tun0 ip enable-arp-ignore
set interfaces tunnel <interface> ip enable-proxy-arp

Настройте proxy ARP на этом интерфейсе.

Если настроено, роутер (ядро) перехватывает ARP-запросы для нелокальных IP-адресов и отвечает с MAC-адресом интерфейса, который получил запрос. Последующие пакеты, предназначенные для этих IP-адресов, перенаправляются на их фактические цели на удаленных подсетях.

Пример:

set interfaces tunnel tun0 ip enable-proxy-arp
set interfaces tunnel <interface> ip proxy-arp-pvlan

Настройте локальный proxy ARP на интерфейсе.

Если настроено, роутер (ядро) отвечает на ARP-запросы на этом VLAN-интерфейсе, даже если целевой IP-адрес находится на той же подсети и интерфейсе.

Это используется для поддержки требований изоляции сети (RFC 3069) для частных VLAN (PVLAN). В конфигурациях PVLAN хосты на изолированных портах НЕ разрешены к прямой коммуникации друг с другом на уровне 2, но они могут общаться с верхним роутером.

Путем ответа на ARP-запросы между хостами своим собственным MAC-адресом, роутер (ядро) направляет трафик между хостами через себя вместо прямой передачи между хостами.

Примечание

Эта команда работает независимо и не требует включения обычного proxy ARP на интерфейсе.

Локальный proxy ARP также известен как:

  • Агрегация VLAN (RFC 3069).

  • Частная VLAN (Cisco, Allied Telesyn).

  • Фильтрация по источнику или изоляция порта (Hewlett-Packard).

  • Перенаправление по MAC-адресу (Ericsson).

set interfaces tunnel <interface> ip source-validation <strict | loose | disable>

Настройте проверку исходного IP-адреса с использованием RPF на этом интерфейсе, как указано в RFC 3704.

Доступны следующие варианты:

  • strict: Каждый входящий пакет проверяет исходный IP-адрес против FIB. Если интерфейс не является лучшим маршрутом обратно к этому источнику, проверка не проходит, и пакет удаляется.

  • loose: Каждый входящий пакет проверяет исходный IP-адрес против FIB. Если исходный IP-адрес недоступен через любой интерфейс, проверка не проходит.

  • disable: Не производится проверка исходного IP-адреса. Все входящие пакеты принимаются.

RFC 3704 рекомендует включить строгий режим для предотвращения подделки IP-адресов, таких как DDoS-атаки. Для асимметричных или других сложных сценариев маршрутизации используйте режим loose.

set interfaces tunnel <interface> ipv6 address autoconf

Настройте интерфейс для автоматического получения IPv6-адреса с использованием SLAAC, как указано в RFC 4862.

Хосты IPv6 могут самостоятельно настраивать себя, когда подключены к IPv6-сети с помощью протокола обнаружения соседей через ICMPv6 сообщения о маршрутизаторе. При первом подключении к сети хост отправляет многоадресный запрос на маршрутизатор для получения параметров своей конфигурации. Маршрутизатор отвечает пакетом объявлений маршрутизатора, содержащим параметры конфигурации уровня Интернета.

Примечание

Этот метод автоматически отключает передачу IPv6-трафика на интерфейсе.

Пример:

set interfaces tunnel tun0 ipv6 address autoconf
set interfaces tunnel <interface> ipv6 address eui64 <prefix>

Настройте интерфейс для присвоения себе IPv6-адреса с использованием метода EUI-64 , как указано в RFC 4291.

Пример:

set interfaces tunnel tun0 ipv6 address eui64 2001:db8:beef::/64
set interfaces tunnel <interface> ipv6 address no-default-link-local

Отключите автоматическое присвоение ссылочного IPv6-адреса этому интерфейсу.

Пример:

set interfaces tunnel tun0 ipv6 address no-default-link-local
set interfaces tunnel <interface> ipv6 disable-forwarding

Настройте интерфейс на работу в режиме хоста или роутера.

Если настроено, интерфейс переключается в режим хоста, и IPv6-передача отключается на нем.

Пример:

set interfaces tunnel tun0 ipv6 disable-forwarding
set interfaces tunnel <interface> ipv6 adjust-mss <mss | clamp-mss-to-pmtu>

Настройте MSS , объявляемый в исходящих пакетах TCP SYN на указанном интерфейсе.

Путем ограничения значения MSS в пакетах TCP SYN, вы явно информируете удаленный сторону не отправлять пакеты большего размера, чем этот. Это предотвращает проблемы с соединением, возникающие при неудачной проверке PMTUD.

Доступны следующие варианты:

  • mss: Установите MSS в определенное значение, в байтах. Используйте этот вариант, чтобы зафиксировать определенный MSS, например, для устранения проблем с доступностью или соответствия специфическим требованиям сети.

  • clamp-mss-to-pmtu: Роутер рассчитывает MSS, равный MTU интерфейса минус 60 байт для IPv6 (40 байт для заголовка IPv6 и 20 байт для заголовка TCP). Этот вариант рекомендуется для автоматического установления правильного значения.

set interfaces tunnel <interface> ipv6 accept-dad <0 | 1 | 2>

Настройте IPv6 DAD на интерфейсе.

Доступны следующие варианты:

  • 0: Отключает DAD. Не выполняется обнаружение дублирующих адресов.

  • 1: Включает DAD (по умолчанию). Обнаруживаются дублирующиеся адреса. Работа интерфейса с IPv6 продолжается для действительных IPv6-адресов.

  • 2: Включает DAD и, если найден дублирующийся локальный адрес, связанный с MAC-адресом, отключает работу IPv6 на этом интерфейсе.

Пример:

set interfaces tunnel tun0 ipv6 accept-dad 2
set interfaces tunnel <interface> ipv6 dup-addr-detect-transmits <n>

Настройте количество DAD сообщений, которые роутер (ядро) отправляет во время назначения IPv6-адреса на этом интерфейсе.

Значение по умолчанию равно 1.

Пример:

set interfaces tunnel tun0 ipv6 dup-addr-detect-transmits 5
set interfaces tunnel <interface> vrf <vrf>

Назначьте интерфейс определенному экземпляру VRF .

См. также

Для информации о настройке VRF см. раздел VRF.

Пример:

set interfaces tunnel tun0 vrf red

IPIP

IPIP — это простой протокол инкапсуляции, определенный в RFC 2003. Он инкапсулирует один пакет IPv4 внутри другого пакета IPv4.

Туннели с инкапсуляцией IPIP не имеют специфичных для протокола опций конфигурации, кроме явного указания типа инкапсуляции как IPIP (см. пример ниже).

Пример:

set interfaces tunnel tun0 encapsulation ipip
set interfaces tunnel tun0 source-address 192.0.2.10
set interfaces tunnel tun0 remote 203.0.113.20
set interfaces tunnel tun0 address 192.168.100.200/24

IP6IP6

IP6IP6 — это IPv6-аналог IPIP. Он инкапсулирует один пакет IPv6 внутри другого пакета IPv6.

Подобно их IPIP-аналогам, туннели с инкапсуляцией IP6IP6 не имеют специфичных для протокола опций конфигурации, кроме явного указания типа инкапсуляции как IP6IP6.

Пример:

set interfaces tunnel tun0 encapsulation ip6ip6
set interfaces tunnel tun0 source-address 2001:db8:aa::1
set interfaces tunnel tun0 remote 2001:db8:aa::2
set interfaces tunnel tun0 address 2001:db8:bb::1/64

IPIP6

IPIP6 — это протокол инкапсуляции, который оборачивает пакеты IPv4 в пакеты IPv6.

Подобно IPIP и IP6IP6, специфичные для протокола настройки для туннелей с инкапсуляцией IPIP6 требуют только указания типа инкапсуляции как IP6IP6.

Пример:

set interfaces tunnel tun0 encapsulation ipip6
set interfaces tunnel tun0 source-address 2001:db8:aa::1
set interfaces tunnel tun0 remote 2001:db8:aa::2
set interfaces tunnel tun0 address 192.168.70.80/24

6in4 (SIT)

6in4, также известный как SIT, — это протокол инкапсуляции, определенный в RFC 4213, который оборачивает пакеты IPv6 в пакеты IPv4. Инкапсулирующие заголовки IPv4 используют номер протокола IP 41, который зарезервирован исключительно для инкапсуляции IPv6.

Процесс инкапсуляции добавляет 20-байтовый заголовок IPv4 к каждому пакету IPv6. Следовательно, интерфейсы туннелей 6in4 могут передавать пакеты IPv6 до 1480 байт через базовую сеть с обычным MTU 1500 байт без фрагментации.

Интерфейсы туннелей 6in4 часто используются IPv6-брокерами туннелей (например, Hurricane Electric) для подключения изолированных IPv6-сетей или отдельных хостов к IPv6-интернету.

Пример:

set interfaces tunnel tun0 encapsulation sit
set interfaces tunnel tun0 source-address 192.0.2.10
set interfaces tunnel tun0 remote 192.0.2.20
set interfaces tunnel tun0 address 2001:db8:bb::1/64

Для практического примера конфигурации см. раздел Tunnelbroker.net (IPv6).

Общий маршрутный протокол инкапсуляции (GRE)

GRE — это универсальный протокол инкапсуляции, определенный в RFC 2784. В отличие от более простых протоколов, таких как IPIP, он позволяет транспортировать как IPv4, так и IPv6 через один и тот же туннель.

GRE инкапсулирует исходные пакеты данных, добавляя заголовок GRE, за которым следует IP-заголовок (доставочный заголовок). Доставочный заголовок использует номер протокола IP 47 для идентификации трафика, инкапсулированного в GRE.

В VyOS туннели GRE могут быть установлены как над IPv4 (инкапсуляция gre), так и над IPv6 (инкапсуляция ip6gre).

Конфигурация

Для настройки туннеля GRE необходимо определить IP-адрес источника туннеля, IP-адрес назначения туннеля, тип инкапсуляции (GRE) и IP-адрес интерфейса туннеля.

Пример:

В следующем примере показано, как настроить IPv4/IPv6-туннель GRE между роутером VyOS и хостом Linux, работающим с systemd-networkd.

Роутер VyOS:

set interfaces tunnel tun101 address '2001:db8:feed:beef::1/126'
set interfaces tunnel tun101 address '192.168.5.1/30'
set interfaces tunnel tun101 encapsulation 'ip6gre'
set interfaces tunnel tun101 source-address '2001:db8:babe:face::3afe:3'
set interfaces tunnel tun101 remote '2001:db8:9bb:3ce::5'

Linux systemd-networkd:

Настройка systemd-networkd требует двух файлов конфигурации: xxx.netdev для создания интерфейса туннеля GRE, и xxx.network для присвоения IP-адресов ему.

# cat /etc/systemd/network/gre-example.netdev
[NetDev]
Name=gre-example
Kind=ip6gre
MTUBytes=14180

[Tunnel]
Remote=2001:db8:babe:face::3afe:3


# cat /etc/systemd/network/gre-example.network
[Match]
Name=gre-example

[Network]
Address=2001:db8:feed:beef::2/126

[Address]
Address=192.168.5.2/30

Ключи GRE

Ключ GRE — это необязательное 32-битное поле в заголовке GRE, которое позволяет нескольким туннелям GRE работать между одними и теми же точками назначения и источника. При получении пакета приемник проверяет ключ GRE, чтобы определить, какой интерфейс туннеля должен его обработать.

Хотя это звучит как безопасность, ключ GRE — это просто идентификатор и не предоставляет шифрования или защиты данных.

Пример:

set interfaces tunnel tun0 source-address 192.0.2.10
set interfaces tunnel tun0 remote 192.0.2.20
set interfaces tunnel tun0 address 10.40.50.60/24
set interfaces tunnel tun0 parameters ip key 10

set interfaces tunnel tun1 source-address 192.0.2.10
set interfaces tunnel tun1 remote 192.0.2.20
set interfaces tunnel tun1 address 172.16.17.18/24
set interfaces tunnel tun1 parameters ip key 20

GRETAP

В отличие от GRE, который инкапсулирует только трафик уровня 3 (IP), GRETAP инкапсулирует кадры уровня 2 (Ethernet).

Это означает, что интерфейсы туннелей GRETAP могут быть участниками интерфейса моста. Это позволяет двум географически удаленным сайтам соединяться, как будто они находятся на одном локальном LAN.

Туннели GRETAP могут быть установлены как над сетью IPv4, так и над сетью IPv6.

Пример:

set interfaces bridge br0 member interface eth0
set interfaces bridge br0 member interface tun0
set interfaces tunnel tun0 encapsulation gretap
set interfaces tunnel tun0 source-address 198.51.100.2
set interfaces tunnel tun0 remote 203.0.113.10

Устранение неполадок

GRE — это стандартизированный протокол туннелирования, используемый во многих сетевых средах.

Хотя настройка туннеля GRE проста, частые сбои в подключении происходят потому, что ACL или правила фаервола блокируют протокол IP 47 или препятствуют прямой коммуникации между точками назначения туннеля.

Если ваш туннель GRE не удается установить, выполните эти диагностические шаги:

1. Убедитесь, что удаленный узел достижим из настроенного source-address.

Это гарантирует, что физический путь между двумя точками назначения функционален.
