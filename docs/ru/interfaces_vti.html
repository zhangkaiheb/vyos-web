VTI (виртуальный туннельный интерфейс)

VTIs позволяют создавать защищенные, шифрованные туннели между частными сетями или хостами через общую инфраструктуру, например, Интернет. Они работают вместе с базовым IPsec-туннелем, который отвечает за кодирование и шифрование, в то время как VTIs функционируют исключительно как маршрутизирующие интерфейсы.

Конфигурация

Общая конфигурация интерфейса

set interfaces vti <interface> address <address>

Настройте один или несколько IP-адресов интерфейса.

<address> поддерживает IPv4 и IPv6 в формате CIDR. Например, используйте 192.0.2.1/24 для IPv4 или 2001:db8::1/64 для IPv6.

Пример:

set interfaces vti vti0 address 192.0.2.1/24
set interfaces vti vti0 address 2001:db8::1/64
set interfaces vti <interface> description <description>

Настройте понятное описание интерфейса.

Это описание появляется в команде show interfaces и в инструментах мониторинга на основе SNMP.

Пример:

set interfaces vti vti0 description 'This is an interface running on VyOS.'
set interfaces vti <interface> disable

Отключить интерфейс.

Интерфейс будет установлен в состояние административно выключен (A/D).

Пример:

set interfaces vti vti0 disable
set interfaces vti <interface> ip adjust-mss <mss | clamp-mss-to-pmtu>

Настройте MSS , объявляемый в исходящих TCP SYN пакетах на указанном интерфейсе.

Путем ограничения значения MSS в пакетах TCP SYN, вы явно информируете удаленную сторону о том, что она не должна отправлять пакеты большего размера. Это предотвращает проблемы с соединением, которые возникают, когда Path MTU Discovery (PMTUD) не работает.

Доступны следующие варианты:

  • mss: Устанавливает MSS в конкретное значение, в байтах. Используйте этот вариант, если необходимо принудительно установить определенное значение MSS, например, для устранения проблем с доступностью или соответствия специфическим требованиям сети.

  • clamp-mss-to-pmtu: Роутер автоматически рассчитывает MSS как MTU интерфейса минус 40 байт для IPv4 (20 байт для заголовка IPv4 и 20 байт для заголовка TCP). Этот вариант рекомендуется для автоматической установки правильного значения.

set interfaces vti <interface> ip arp-cache-timeout

Настройте, как долго ARP-запись остается действительной после получения сопоставления IP-адреса и MAC-адреса на этом интерфейсе.

По умолчанию длительность составляет 30 секунд.

ARP-запись остается действительной, если получает положительный ответ от протоколов верхнего уровня.

Пример:

set interfaces vti vti0 ip arp-cache-timeout 180
set interfaces vti <interface> ip disable-arp-filter

Настройте фильтрацию ARP на этом интерфейсе.

Стандартное поведение: Ядро отвечает на запросы ARP на этом интерфейсе только в том случае, если трафик будет направлен обратно к отправителю ARP через этот конкретный интерфейс.

Если настроено: Ядро отвечает на запросы ARP на этом интерфейсе для любого IP-адреса, настроенного на локальном хосте, независимо от того, какой конкретный интерфейс назначен этому IP-адресу, и независимо от таблицы маршрутизации. Это отражает концепцию Linux, согласно которой IP-адреса принадлежат хосту, а не отдельным интерфейсам.

Пример:

set interfaces vti vti0 ip disable-arp-filter
set interfaces vti <interface> ip disable-forwarding

Настройте интерфейс на работу в режиме хоста или роутера.

Если настроено, интерфейс переключается в режим хоста, и IPv4-пересылка отключается на нем.

Пример:

set interfaces vti vti0 ip disable-forwarding
set interfaces vti <interface> ip enable-directed-broadcast

Настройте, чтобы передавать IP-направленные широковещательные пакеты, полученные на этом интерфейсе.

Стандартное поведение: IP-направленные широковещательные пакеты удаляются.

Если настроено: IP-направленные широковещательные пакеты передаются всем хостам на целевой подсети, как определено в RFC 1812 и RFC 2644.

Пример:

set interfaces vti vti0 ip enable-directed-broadcast
set interfaces vti <interface> ip enable-arp-accept

Настройте обработку широковещательных ARP на этом интерфейсе.

Если настроено, IP-адрес-МАС-адресная связь добавляется в таблицу ARP на основе широковещательных ARP-запросов или ответов.

Примечание

Если таблица ARP уже содержит IP-адрес из широковещательного ARP, его запись обновляется независимо от того, настроено ли это настройка.

Пример:

set interfaces vti vti0 ip enable-arp-accept
set interfaces vti <interface> ip enable-arp-announce

Настройте выбор источника IP-адреса для ARP-запросов на этом интерфейсе.

Стандартное поведение: Ядро может использовать любой IP-адрес, принадлежащий хосту, в качестве источника IP-адреса в ARP-запросах на этом интерфейсе.

Если настроено: Ядро сначала пытается выбрать источник IP-адреса, настроенный на интерфейсе, который совпадает с подсетью целевого IP-адреса. Если такой подсети нет, ядро выбирает IP-адрес, который обычно используется (на основе таблицы маршрутизации для достижения целевого назначения).

Пример:

set interfaces vti vti0 ip enable-arp-announce
set interfaces vti <interface> ip enable-arp-ignore

Настройте, какие ARP-запросы будут игнорироваться на этом интерфейсе.

Стандартное поведение: Ядро отвечает на ARP-запросы для любых локальных IP-адресов, независимо от того, к какому интерфейсу они относятся.

Если настроено: Ядро отвечает на ARP-запросы только в том случае, если целевой IP-адрес назначен этому конкретному интерфейсу.

Пример:

set interfaces vti vti0 ip enable-arp-ignore
set interfaces vti <interface> ip enable-proxy-arp

Настройте прокси-ARP на этом интерфейсе.

Если настроено, маршрутизатор (ядро) перехватывает ARP-запросы для нелокальных IP-адресов и отвечает MAC-адресом интерфейса, получившего запрос. Далее пакеты, предназначенные этим IP-адресам, пересылаются на их фактические цели на удаленных подсетях.

Пример:

set interfaces vti vti0 ip enable-proxy-arp
set interfaces vti <interface> ip proxy-arp-pvlan

Настройте локальный прокси-ARP на интерфейсе.

Если настроено, маршрутизатор (ядро) отвечает на ARP-запросы на этом VLAN-интерфейсе, даже если целевой IP-адрес находится на той же подсети и интерфейсе.

Это используется для поддержки требований к изоляции сети (RFC 3069) для приватных VLAN (PVLAN). В конфигурациях PVLAN хосты на изолированных портах НЕ разрешены к прямой коммуникации друг с другом на уровне 2, но могут общаться с верхним роутером.

Путем ответа на ARP-запросы между хостами своим собственным MAC-адресом, маршрутизатор (ядро) направляет трафик между хостами через себя вместо прямой передачи между хостами.

Примечание

Эта команда работает независимо и не требует включения стандартного прокси-ARP на интерфейсе.

Локальный прокси-ARP также известен как:

  • Агрегация VLAN (RFC 3069).

  • Частная VLAN (Cisco, Allied Telesyn).

  • Фильтрация по порту или изоляция порта (Hewlett-Packard).

  • Перенаправление MAC (Ericsson).

set interfaces vti <interface> ip source-validation <strict | loose | disable>

Настройте проверку исходного IP-адреса с использованием RPF на этом интерфейсе, как указано в RFC 3704.

Доступны следующие варианты:

  • strict: Каждый входящий пакет проверяет исходный IP-адрес против FIB. Если интерфейс не является лучшим маршрутом обратно к этому источнику, проверка не проходит, и пакет удаляется.

  • loose: Каждый входящий пакет проверяет исходный IP-адрес против FIB. Если исходный IP-адрес недостижим через любой интерфейс, проверка не проходит.

  • disable: Проверка исходного IP-адреса не выполняется. Все входящие пакеты принимаются.

RFC 3704 рекомендует включить строгий режим для предотвращения подделки IP-адресов, таких как DDoS-атаки. Для асимметричных или других сложных сценариев маршрутизации используйте режим loose.

set interfaces vti <interface> ipv6 address autoconf

Настройте интерфейс для автоматического получения IPv6-адреса с помощью SLAAC, как указано в RFC 4862.

Хосты IPv6 могут самостоятельно настраивать себя, когда подключены к сети IPv6 с помощью протокола Neighbor Discovery через ICMPv6 сообщения о маршрутизаторе. При первом подключении к сети хост отправляет многоадресный запрос для своей конфигурации параметров. Маршрутизатор отвечает пакетом объявлений маршрутизатора, содержащим параметры конфигурации уровня интернета.

Примечание

Этот метод автоматически отключает передачу IPv6 на интерфейсе.

Пример:

set interfaces vti vti0 ipv6 address autoconf
set interfaces vti <interface> ipv6 address eui64 <prefix>

Настройте интерфейс для присвоения себе IPv6-адреса с помощью метода EUI-64 , как указано в RFC 4291.

Пример:

set interfaces vti vti0 ipv6 address eui64 2001:db8:beef::/64
set interfaces vti <interface> ipv6 address no-default-link-local

Отключите автоматическое присвоение ссылочного IPv6-адреса этому интерфейсу.

Пример:

set interfaces vti vti0 ipv6 address no-default-link-local
set interfaces vti <interface> ipv6 disable-forwarding

Настройте интерфейс на работу в режиме хоста или роутера.

Если настроено, интерфейс переключается в режим хоста, и IPv6-пересылка отключается на нем.

Пример:

set interfaces vti vti0 ipv6 disable-forwarding
set interfaces vti <interface> ipv6 adjust-mss <mss | clamp-mss-to-pmtu>

Настройте MSS , объявляемый в исходящих TCP SYN пакетах на указанном интерфейсе.

Путем ограничения значения MSS в пакетах TCP SYN, вы явно информируете удаленную сторону о том, что она не должна отправлять пакеты большего размера. Это предотвращает проблемы с соединением, когда Path MTU Discovery (PMTUD) не работает.

Доступны следующие варианты:

  • mss: Установите MSS в конкретное значение, в байтах. Используйте этот вариант, чтобы принудительно установить определенное значение MSS, например, для устранения проблем с доступностью или соответствия специфическим требованиям сети.

  • clamp-mss-to-pmtu: Роутер рассчитывает MSS как MTU интерфейса минус 60 байт для IPv6 (40 байт для заголовка IPv6 и 20 байт для заголовка TCP). Этот вариант рекомендуется для автоматической установки правильного значения.

set interfaces vti <interface> ipv6 accept-dad <0 | 1 | 2>

Настройте IPv6 DAD на интерфейсе.

Доступны следующие варианты:

  • 0: Отключает DAD. Не производится обнаружение дублирующих адресов.

  • 1: Включает DAD (по умолчанию). Обнаруживаются дублирующие адреса. Работа интерфейса с IPv6 продолжается для корректных IPv6-адресов.

  • 2: Включает DAD и, если найден дублирующийся локальный адрес, основанный на MAC-адресе, отключает работу IPv6 на этом интерфейсе.

Пример:

set interfaces vti vti0 ipv6 accept-dad 2
set interfaces vti <interface> ipv6 dup-addr-detect-transmits <n>

Настройте количество DAD сообщений, которые маршрутизатор (ядро) отправляет при назначении IPv6-адреса на этом интерфейсе.

Значение по умолчанию равно 1.

Пример:

set interfaces vti vti0 ipv6 dup-addr-detect-transmits 5
set interfaces vti <interface> mtu <mtu>

Настройте MTU на интерфейсе.

Это значение определяет максимальный размер пакета, в байтах, который интерфейс передает без фрагментации.

Пример:

set interfaces vti vti0 mtu 1600
set interfaces vti <interface> mirror egress <monitor-interface>

Настройте отражение исходящего трафика с указанного VTI на заданный интерфейс мониторинга.

set interfaces vti <interface> mirror ingress <monitor-interface>

Настройте отражение входящего трафика с указанного VTI на заданный интерфейс мониторинга.

set interfaces vti <interface> redirect <interface>

Включите перенаправление входящих пакетов на указанный интерфейс.

set interfaces vti <interface> vrf <vrf>

Назначьте интерфейс определенному экземпляру VRF .

Пример

Настройка VTI

Назначьте IPv4 и IPv6-адреса VTI, а также краткое описание:

set interfaces vti vti0 address 192.168.2.249/30
set interfaces vti vti0 address 2001:db8:2::249/64
set interfaces vti vti0 description "Description"

Результат конфигурации:

vyos@vyos# show interfaces vti
vti vti0 {
    address 192.168.2.249/30
    address 2001:db8:2::249/64
    description "Description"
}

Предупреждение

При настройке site-to-site IPsec с VTI убедитесь, что отключена автозагрузка маршрутов.

set vpn ipsec options disable-route-autoinstall

Для получения дополнительной информации о проблеме IPsec и VTI, а также о параметре disable-route-autoinstall, см.: https://blog.vyos.io/vyos-1-dot-2-0-development-news-in-july.

Корневая причина проблемы заключается в том, что туннели VTI требуют, чтобы их трафик был настроен на 0.0.0.0/0 для соответствия туннелю, даже если решения о маршрутизации основаны на метках netfilter. Если автовставки маршрутов не отключена, strongSWAN ошибочно вставляет маршрут по умолчанию через адрес VTI-пира, вызывая неправильную маршрутизацию всего трафика.
