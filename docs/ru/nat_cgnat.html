CGNAT

CGNAT, также известный как Large-Scale NAT (LSN), представляет собой тип трансляции сетевых адресов, используемый поставщиками интернет-услуг (ISP) для того, чтобы несколько частных IP-адресов могли разделять один публичный IP-адрес. Этот метод помогает сэкономить ограниченное пространство IPv4-адресов. Блок адресов 100.64.0.0/10 зарезервирован для использования в CGNAT

Обзор

CGNAT работает, размещая устройство NAT в сети провайдера. Это устройство переводит частные IP-адреса из сетей клиентов в ограниченный набор публичных IP-адресов, присвоенных провайдеру. Это позволяет многим клиентам делиться меньшим количеством публичных IP-адресов.

Не все RFC 6888 требования реализованы в CGNAT.

Реализованы следующие RFC 6888 требования:

  • REQ 2: CGN должен иметь поведение по умолчанию "IP-адресного пула" в виде "Пары". CGN должен использовать одно и то же сопоставление внешних IP-адресов для всех сессий, связанных с одним внутренним IP-адресом, независимо от того, являются ли они TCP, UDP, ICMP, чем-то еще или комбинацией различных протоколов.

  • REQ 3: Функция CGN не должна иметь ограничений на размер или непрерывность внешнего адресного пула.

  • REQ 4: CGN должен поддерживать ограничение количества внешних портов (или, эквивалентно, "идентификаторов" для ICMP), которые назначаются каждому абоненту

Преимущества CGNAT

  • Сохранение IPv4-адресов: CGNAT помогает снизить истощение IPv4-адресов, позволяя нескольким клиентам делиться одним публичным IP-адресом.

  • Масштабируемость: Провайдеры могут обслуживать больше клиентов без необходимости пропорционального увеличения публичных IP-адресов.

  • Экономичность: Уменьшает затраты, связанные с приобретением дополнительных публичных IPv4-адресов.

Важные моменты

  • Проблемы с трассировкой: Поскольку несколько пользователей делят один и тот же публичный IP-адрес, отслеживание отдельных пользователей для целей безопасности и законности может быть сложным.

  • Нагрузка на производительность: Процесс трансляции может вызывать задержки и потенциальные узкие места производительности, особенно при высокой нагрузке.

  • Совместимость приложений: Некоторые приложения и протоколы могут плохо работать с CGNAT из-за их зависимости от уникальных публичных IP-адресов.

  • Ограничения выделения портов: У каждого публичного IP-адреса есть ограниченное количество портов, которое может исчерпаться, влияя на возможность установления новых соединений.

  • Протокол управления портами: PCP не реализован.

Расчет портов

При реализации CGNAT важно обеспечить достаточное количество портов, выделяемых каждому абоненту. Ниже приведено краткое описание на основе RFC 6888.

  1. Общее количество доступных портов:

    • Общее количество портов: 65536 (0 до 65535)

    • Зарезервированные порты: Предположим, что 1024 порта зарезервированы для известных служб и административных целей.

    • Доступные порты: 65536 - 1024 = 64512

  2. Оценка необходимых портов на абонента:

    • Пример: В домашней сети может потребоваться 1000 портов для обеспечения бесперебойной работы нескольких устройств и приложений.

  3. Расчет количества абонентов на публичный IP-адрес:

    • Доступные порты / Порты на абонента

    • 64512 / 1000 ≈ 64 абонента на публичный IP-адрес

Конфигурация

set nat cgnat pool external <pool-name> external-port-range <port-range>

Установите диапазон внешних портов для внешнего пула, по умолчанию диапазон равен 1024-65535. Можно добавить несколько записей в один и тот же пул.

set nat cgnat pool external <pool-name> per-user-limit port <num>

Установите ограничения на внешние исходные порты, которые будут выделяться каждому абоненту индивидуально. Значение по умолчанию равно 2000.

set nat cgnat pool external <pool-name> range [address | address range | network] [seq]

Установите диапазон внешних IP-адресов для пула CGNAT. Последовательность является необязательной; если она установлена, более низкое значение означает более высокий приоритет.

set nat cgnat pool internal <pool-name> range [address range | network]

Установите диапазон внутренних IP-адресов для пула CGNAT.

set nat cgnat rule <num> source pool <internal-pool-name>

Установите правило для источника пула.

set nat cgnat rule <num> translation pool <external-pool-name>

Установите правило для пула перевода.

set nat cgnat log-allocation

Включить логирование выделения IP-адресов и портов.

Примеры конфигурации

Один внешний адрес

Пример базовой конфигурации CGNAT: В следующем примере мы определяем внешний пул с именем ext-1, содержащий один внешний IP-адрес.

Каждому абоненту будет выделяться максимум 2000 портов из внешнего пула.

set nat cgnat pool external ext1 external-port-range '1024-65535'
set nat cgnat pool external ext1 per-user-limit port '2000'
set nat cgnat pool external ext1 range '192.0.2.222/32'
set nat cgnat pool internal int1 range '100.64.0.0/28'
set nat cgnat rule 10 source pool 'int1'
set nat cgnat rule 10 translation pool 'ext1'

Несколько внешних адресов

set nat cgnat pool external ext1 external-port-range '1024-65535'
set nat cgnat pool external ext1 per-user-limit port '8000'
set nat cgnat pool external ext1 range '192.0.2.1-192.0.2.2'
set nat cgnat pool external ext1 range '203.0.113.253-203.0.113.254'
set nat cgnat pool internal int1 range '100.64.0.1-100.64.0.32'
set nat cgnat rule 10 source pool 'int1'
set nat cgnat rule 10 translation pool 'ext1'

Последовательности внешних адресов

set nat cgnat pool external ext-01 per-user-limit port '16000'
set nat cgnat pool external ext-01 range 203.0.113.1/32 seq '10'
set nat cgnat pool external ext-01 range 192.0.2.1/32 seq '20'
set nat cgnat pool internal int-01 range '100.64.0.0/29'
set nat cgnat rule 10 source pool 'int-01'
set nat cgnat rule 10 translation pool 'ext-01'
