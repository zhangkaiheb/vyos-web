WireGuard

WireGuard — это очень простой, быстрый и современный VPN, использующий современную криптографию. Посетите https://www.wireguard.com, чтобы получить больше информации.

VPN между сайтами

Следующая диаграмма иллюстрирует настройку VPN между сайтами.

Ключевые пары

WireGuard требует ключевой пары, включающей частный ключ для расшифровки входящего трафика и общественный ключ для шифрования исходящего трафика.

Создать ключевую пару

generate pki wireguard key-pair

Создать ключевую пару: публичный и приватный ключи.

Примечание

Эта команда выводит ключи только в ваш консоль. Она не сохраняет их в системе и не применяет их к системной конфигурации.

vyos@vyos:~$ generate pki wireguard key-pair
Private key: iJJyEARGK52Ls1GYRCcFvPuTj7WyWYDo//BknoDU0XY=
Public key: EKY0dxRrSD98QHjfHOK13mZ5PJ7hnddRZt5woB3szyw=
generate pki wireguard key-pair install interface <interface>

Создать ключевую пару и вывести команду назначения приватного ключа для указанного интерфейса.

vyos@vyos:~$ generate pki wireguard key-pair install interface wg10
"generate" CLI команда выполнена с операционного уровня.
Сгенерированный приватный ключ не добавляется автоматически в конфигурацию VyOS, используйте следующие команды режима конфигурации для установки ключа:

set interfaces wireguard wg10 private-key '4Krkv8h6NkAYMMaBWI957yYDJDMvj9URTHstdlOcDU0='

Соответствующий публичный ключ, который нужно использовать на системе-пире: 'UxDsYT6EnpTIOKUzvMlw2p0sNOKQvFxEdSVrnNrX1Ro='

Примечание

Если вы вызываете эту команду из режима конфигурации с префиксом run, сгенерированный приватный ключ автоматически назначается указанному интерфейсу.

vyos@vyos# run generate pki wireguard key-pair install interface wg10
"generate" CLI команда выполнена с сессии конфигурации.
Сгенерированный приватный ключ был импортирован в CLI!

Используйте следующую команду для проверки: show interfaces wireguard wg10
Соответствующий публичный ключ, который нужно использовать на системе-пире: '7d9KwabjLhHpJiEJeIGd0CBlao/eTwFOh6xyCovTfG8='

vyos@vyos# compare
[edit interfaces]
+wireguard wg10 {
+    private-key CJweb8FC6BU3Loj4PC2pn5V82cDjIPs7G1saW0ZfLWc=
+}
show interfaces wireguard <interface> public-key

Показать публичный ключ, назначенный интерфейсу.

vyos@vyos:~$ show interfaces wireguard wg01 public-key
EKY0dxRrSD98QHjfHOK13mZ5PJ7hnddRZt5woB3szyw=

Дополнительно

generate pki wireguard preshared-key

Создать предварительно общий ключ.

Предварительно общий ключ является необязательным. Он добавляет дополнительный уровень симметричной криптографии поверх асимметричной криптографии.

vyos@vyos:~$ generate pki wireguard preshared-key
Предварительно общий ключ: OHH2EwZfMNK+1L6BXbYw3bKCtMrfjpR4mCAEeBlFnRs=
generate pki wireguard preshared-key install interface <interface> peer <peer>

Создать предварительно общий ключ и вывести команду назначения ключа для указанного пира.

vyos@vyos:~$ generate pki wireguard preshared-key install interface wg10 peer foo
"generate" CLI команда выполнена с операционного уровня.
Сгенерированный предварительно общий ключ не сохраняется в CLI, используйте команды режима конфигурации для установки ключа:

set interfaces wireguard wg10 peer foo preshared-key '32vQ1w1yFKTna8n7Gu7EimubSe2Y63m8bafz55EG3Ro='

Предварительно общий ключ: +LuaZ8W6DjsDFJFX3jJzoNqrsXHhvq08JztM9z8LHCs=

Примечание

Если вы вызываете эту команду из режима конфигурации с префиксом run, сгенерированный ключ автоматически назначается указанному пиру.

Настройка интерфейса

Следующий шаг — настроить локальный интерфейс WireGuard и определить сети, которые вы хотите передавать через туннель (allowed-ips).

Если ваша система инициирует только соединения, указание порта прослушивания является необязательным. Если ваша система принимает входящие соединения, необходимо определить порт для подключения пиров. В противном случае, WireGuard выбирает случайный порт при каждом перезапуске, и это может нарушить способность пиров подключаться, если этот порт не разрешен в правилах вашего брандмауэра.

Чтобы настроить туннель WireGuard, вам также понадобится публичный ключ вашего пира.

Примечание

Публичный ключ, указанный в блоке конфигурации пира, всегда является удаленным публичным ключом, никогда не вашим локальным.

Локальная конфигурация

Локальная сторона настраивается следующими параметрами:

  • IP-адрес локального интерфейса WireGuard: 10.1.0.1/30

  • Локальный порт прослушивания: 51820

  • Имя удаленного пира: to-wg02

  • Точка подключения удаленного пира: 192.0.2.1 на порту 51820

  • Публичный ключ удаленного пира: XMrlPykaxhdAAiSjhtPlvi30NVkvLQliQuKP7AI7CyI=

  • Разрешенные сети: 192.168.2.0/24

set interfaces wireguard wg01 address '10.1.0.1/30'
set interfaces wireguard wg01 description 'VPN-to-wg02'
set interfaces wireguard wg01 peer to-wg02 allowed-ips '192.168.2.0/24'
set interfaces wireguard wg01 peer to-wg02 address '192.0.2.1'
set interfaces wireguard wg01 peer to-wg02 port '51820'
set interfaces wireguard wg01 peer to-wg02 public-key 'XMrlPykaxhdAAiSjhtPlvi30NVkvLQliQuKP7AI7CyI='
set interfaces wireguard wg01 port '51820'

set protocols static route 192.168.2.0/24 interface wg01

Чтобы отправить трафик, предназначенный для 192.168.2.0/24, через интерфейс WireGuard (wg01), настройте статический маршрут. Можно определить несколько IP-адресов или сетей и маршрутизировать их. Последняя проверка выполняется по allowed-ips, который либо разрешает, либо отбрасывает трафик.

Предупреждение

Вы не можете назначить один и тот же allowed-ips нескольким пирям WireGuard. Это строгое ограничение дизайна. Для получения дополнительной информации обратитесь к WireGuard mailing list.

set interfaces wireguard <interface> private-key <private-key>

Назначить приватный ключ указанному интерфейсу WireGuard.

Пример:

set interfaces wireguard wg01 private-key 'iJJyEARGK52Ls1GYRCcFvPuTj7WyWYDo//BknoDU0XY='

Чтобы создать приватный ключ, используйте следующую команду: generate pki wireguard key-pair.

Чтобы увидеть публичный ключ, назначенный интерфейсу, чтобы поделиться им с пиром, используйте следующую команду: show interfaces wireguard wg01 public-key.

set interfaces wireguard <interface> per-client-thread

Включить многопоточный режим для всех экземпляров NAPI указанного сетевого устройства.

Включение многопоточного режима не влияет на работу устройства и может быть выполнено, когда устройство включено.

Этот режим отключен по умолчанию.

Пример:

set interfaces wireguard wg01 per-client-thread

Конфигурация удаленной стороны

set interfaces wireguard wg01 address '10.1.0.2/30'
set interfaces wireguard wg01 description 'VPN-to-wg01'
set interfaces wireguard wg01 peer to-wg01 allowed-ips '192.168.1.0/24'
set interfaces wireguard wg01 peer to-wg01 address '192.0.2.2'
set interfaces wireguard wg01 peer to-wg01 port '51820'
set interfaces wireguard wg01 peer to-wg01 public-key 'EKY0dxRrSD98QHjfHOK13mZ5PJ7hnddRZt5woB3szyw='
set interfaces wireguard wg01 port '51820'
set interfaces wireguard wg01 private-key 'OLTQY3HuK5qWDgVs6fJR093SwPgOmCKkDI1+vJLGoFU='

set protocols static route 192.168.1.0/24 interface wg01

Исключения брандмауэра

Чтобы разрешить трафик WireGuard через WAN-интерфейс, создайте исключение брандмауэра:

set firewall ipv4 name OUTSIDE_LOCAL rule 10 action accept
set firewall ipv4 name OUTSIDE_LOCAL rule 10 description 'Allow established/related'
set firewall ipv4 name OUTSIDE_LOCAL rule 10 state established enable
set firewall ipv4 name OUTSIDE_LOCAL rule 10 state related enable
set firewall ipv4 name OUTSIDE_LOCAL rule 20 action accept
set firewall ipv4 name OUTSIDE_LOCAL rule 20 description WireGuard_IN
set firewall ipv4 name OUTSIDE_LOCAL rule 20 destination port 51820
set firewall ipv4 name OUTSIDE_LOCAL rule 20 log enable
set firewall ipv4 name OUTSIDE_LOCAL rule 20 protocol udp

Убедитесь, что группа брандмауэра OUTSIDE_LOCAL применяется к WAN-интерфейсу и в направлении входящих (локальных) данных.

set firewall ipv4 input filter rule 10 action jump
set firewall ipv4 input filter rule 10 jump-target 'OUTSIDE_LOCAL'
set firewall ipv4 input filter rule 10 inbound-interface name 'eth0'

Убедитесь, что ваши правила брандмауэра разрешают трафик. Если так, то ваша сеть WireGuard должна быть готова к работе.

wg01# ping 192.168.1.1
PING 192.168.1.1 (192.168.1.1) 56(84) bytes of data.
64 bytes from 192.168.1.1: icmp_seq=1 ttl=64 time=1.16 ms
64 bytes from 192.168.1.1: icmp_seq=2 ttl=64 time=1.77 ms

wg02# ping 192.168.2.1
PING 192.168.2.1 (192.168.2.1) 56(84) bytes of data.
64 bytes from 192.168.2.1: icmp_seq=1 ttl=64 time=4.40 ms
64 bytes from 192.168.2.1: icmp_seq=2 ttl=64 time=1.02 ms

Дополнительный уровень симметричной криптографии можно использовать поверх асимметричной криптографии. Это необязательно.

vyos@vyos:~$ generate pki wireguard preshared-key
Предварительно общий ключ: rvVDOoc2IYEnV+k5p7TNAmHBMEGTHbPU8Qqg8c/sUqc=

Скопируйте ключ, так как он не хранится локально. Поскольку это симметричный ключ, только вы и ваш пир должны знать его содержимое. Распределите ключ безопасно.

wg01# set interfaces wireguard wg01 peer to-wg02 preshared-key 'rvVDOoc2IYEnV+k5p7TNAmHBMEGTHbPU8Qqg8c/sUqc='
wg02# set interfaces wireguard wg01 peer to-wg01 preshared-key 'rvVDOoc2IYEnV+k5p7TNAmHBMEGTHbPU8Qqg8c/sUqc='

Доступ с удаленной стороны (road warrior)

С WireGuard конфигурация road warrior-VPN аналогична конфигурации site-to-site VPN. Просто опустите указания address и port.

В следующем примере IP-адреса для удаленных клиентов определяются внутри каждого конфигурационного блока пира. Это позволяет пирам общаться друг с другом.

Кроме того, эта настройка использует флаг persistent-keepalive, установленный на 15 секунд, чтобы поддерживать соединение. Это значение особенно важно, если пир находится за NAT и не может быть достигнут, если соединение потеряно. Для эффективности значение должно быть меньше, чем время ожидания UDP.

wireguard wg01 {
    address 10.172.24.1/24
    address 2001:db8:470:22::1/64
    description RoadWarrior
    peer MacBook {
        allowed-ips 10.172.24.30/32
        allowed-ips 2001:db8:470:22::30/128
        persistent-keepalive 15
        pubkey F5MbW7ye7DsoxdOaixjdrudshjjxN5UdNV+pGFHqehc=
    }
    peer iPhone {
        allowed-ips 10.172.24.20/32
        allowed-ips 2001:db8:470:22::20/128
        persistent-keepalive 15
        pubkey BknHcLFo8nOo8Dwq2CjaC/TedchKQ0ebxC7GYn7Al00=
    }
    port 2224
    private-key OLTQY3HuK5qWDgVs6fJR093SwPgOmCKkDI1+vJLGoFU=
}

Ниже представлена конфигурация для пира iPhone. Настройка AllowedIPs с подстановочным знаком направляет весь IPv4 и IPv6 трафик через соединение VPN.

[Interface]
PrivateKey = ARAKLSDJsadlkfjasdfiowqeruriowqeuasdf=
Address = 10.172.24.20/24, 2001:db8:470:22::20/64
DNS = 10.0.0.53, 10.0.0.54

[Peer]
PublicKey = RIbtUTCfgzNjnLNPQ/ulkGnnB2vMWHm7l2H/xUfbyjc=
AllowedIPs = 0.0.0.0/0, ::/0
Endpoint = 192.0.2.1:2224
PersistentKeepalive = 15

Чтобы включить разделение трафика, укажите удаленные подсети. Это гарантирует, что только трафик, предназначенный для удаленного сайта, будет отправлен через туннель, а остальной трафик останется без изменений.

[Interface]
PrivateKey = 8Iasdfweirousd1EVGUk5XsT+wYFZ9mhPnQhmjzaJE6Go=
Address = 10.172.24.30/24, 2001:db8:470:22::30/64

[Peer]
PublicKey = RIbtUTCfgzNjnLNPQ/ulkGnnB2vMWHm7l2H/xUfbyjc=
AllowedIPs = 10.172.24.30/24, 2001:db8:470:22::/64
Endpoint = 192.0.2.1:2224

Клиенты доступа с удаленной стороны (road warrior)

Некоторые пользователи подключают мобильные устройства к своему роутеру VyOS с помощью WireGuard. Чтобы упростить развертывание, сгенерируйте конфигурацию для мобильных устройств из CLI VyOS.

Предупреждение

С точки зрения безопасности, не рекомендуется позволять третьей стороне создавать и делиться приватным ключом для безопасного соединения. Вы должны создать приватную часть сами и предоставить только публичный ключ.

generate wireguard client-config <name> interface <interface> server <ip|fqdn> address <client-ip>

Создать файл конфигурации клиента, который устанавливает соединение с указанным интерфейсом.

Публичный ключ из указанного интерфейса автоматически включается в файл конфигурации.

Команда также генерирует фрагмент конфигурации, который можно скопировать в CLI VyOS. Имя, которое вы предоставляете, будет использоваться как имя пира в фрагменте.

Вам также необходимо указать IP-адрес или FQDN сервера, к которому подключается клиент. Параметр адреса можно использовать дважды, чтобы назначить как IPv4 (/32), так и IPv6 (/128) адрес клиенту.
