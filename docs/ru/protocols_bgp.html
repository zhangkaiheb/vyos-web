BGP

BGP является одним из внешних шлюзовых протоколов и де-факто стандартным междоменным маршрутизационным протоколом. Последняя версия BGP — это 4. BGP-4 описан в RFC 1771 и обновлено RFC 4271. RFC 2858 добавляет многоадресную поддержку к BGP.

VyOS использует FRR и хотим поблагодарить их за их усилия!

Основные понятия

Автономные системы

Согласно RFC 1930:

AS — это связанный набор одного или более IP префиксов, управляемых одним или несколькими сетевыми операторами, которые имеют ЕДИНЫЙ и ЧЕТКО ОПРЕДЕЛЕННЫЙ маршрутный политика.

Каждая AS имеет идентифицирующее число, связанное с ней называется ASN. Это двухбайтовое значение в диапазоне от 1 до 65535. Номера AS 64512 через 65535 определены как частные номера AS. Частные номера AS не должны быть объявлены на глобальной Интернет. Двухбайтовый диапазон номеров AS исчерпан. 4-байтовые номера AS указаны в RFC 6793, и предоставляют набор из 4294967296 номеров AS.

ASN является одним из основных элементов BGP. BGP — это протокол расстояния-вектора, и фреймворк AS-Path предоставляет метрику расстояния-вектора и обнаружение циклов для BGP.

set protocols bgp system-as <asn>

Установите локальный ASN, который представляет этот роутер. Это обязательный параметр!

Семейства адресов

Многоадресные расширения позволяют BGP передавать информацию о маршрутизации для нескольких сетевых протоколов уровней. BGP поддерживает идентификатор семейства адресов (AFI) для IPv4 и IPv6.

Выбор маршрута

Процесс выбора маршрута, используемый реализацией FRR BGP, использует следующие критерии принятия решений, начиная с верхней части списка и двигаясь вниз, пока один из факторов не будет использован.

  1. Проверка веса

    Предпочитать маршруты с более высоким локальным весом, чем с более низким.

  2. Проверка локальной предпочтительности

    Предпочитать маршруты с более высокой локальной предпочтительностью, чем с более низкой.

  3. Проверка локального маршрута

    Предпочитать локальные маршруты (статические, агрегаты, перераспределенные) по сравнению с полученными маршрутами.

  4. Проверка длины AS-пути

    Предпочитать кратчайший путь AS-пути.

  5. Проверка источника

    Предпочитать маршрут с самым низким типом источника. То есть, предпочитать маршруты IGP по сравнению с EGP, и неопределенными маршрутами.

  6. Проверка MED

    Где маршруты с MED были получены от одного и того же AS, предпочитать маршрут с самым низким MED.

  7. Проверка внешнего

    Предпочитать маршрут, полученный от внешнего, eBGP-пира, по сравнению с маршрутами, полученными от других типов пиров.

  8. Проверка стоимости IGP

    Предпочитать маршрут с более низкой стоимостью IGP.

  9. Проверка многопутевого

    Если многопутевая настройка включена, то проверьте, могут ли маршруты, еще не различаемые по предпочтению, считаться равными. Если bgp bestpath as-path multipath-relax установлен, все такие маршруты считаются равными, в противном случае маршруты, полученные через iBGP с одинаковыми AS_PATH, или маршруты, полученные от eBGP-соседей в том же AS, считаются равными.

  10. Проверка уже выбранного внешнего

    Если оба маршрута были получены от eBGP-пиров, то предпочитать маршрут, который уже был выбран. Обратите внимание, что эта проверка не применяется, если bgp bestpath compare-routerid настроен. Эта проверка может предотвратить некоторые случаи колебаний.

  11. Проверка идентификатора маршрутизатора

    Предпочитать маршрут с самым низким идентификатором маршрутизатора. Если у маршрута есть атрибут ORIGINATOR_ID, через iBGP-отражение, тогда используется этот идентификатор маршрутизатора, в противном случае используется идентификатор маршрутизатора соседа, от которого был получен маршрут.

  12. Проверка длины списка кластеров

    Используется маршрут с самой короткой длиной списка кластеров. Список кластеров отражает путь iBGP-отражения, который маршрут прошел.

  13. Адрес пир

    Предпочитать маршрут, полученный от пира с более высоким транспортным слоем адресом, как последний критерий для разрешения спора.

Согласование возможностей

При добавлении функции обмена информацией о маршрутизации IPv6 в BGP. Были некоторые предложения. IETF IDR приняла предложение, называемое Многоадресным расширением для BGP. Спецификация описана в RFC 2283. Протокол не определяет новых протоколов. Он определяет новые атрибуты для существующего BGP. Когда он используется для обмена информацией о маршрутизации IPv6, он называется BGP-4+. Когда он используется для обмена информацией о multicast-маршрутизации, он называется MBGP.

bgpd поддерживает Многоадресное расширение для BGP. Таким образом, если удаленный пир поддерживает протокол, bgpd может обмениваться информацией о маршрутизации IPv6 и/или multicast.

Традиционный BGP не имел функции для обнаружения возможностей удаленного пира, например, может ли он обрабатывать типы префиксов, отличные от маршрутов IPv4 unicast. Это было большой проблемой при использовании Многоадресного расширения для BGP в операционной сети. RFC 2842 приняло функцию, называемую Согласование возможностей. bgpd использует это Согласование возможностей для обнаружения возможностей удаленного пира. Если пир настроен только как пир IPv4 unicast, bgpd не отправляет эти пакеты согласования возможностей (по крайней мере, не если другие необязательные возможности BGP требуют согласования возможностей).

По умолчанию FRR запускает соединение с минимальными общими возможностями для обеих сторон. Например, если локальный роутер имеет возможность unicast и multicast и удаленный роутер имеет только unicast, локальный роутер установит соединение с unicast только. Когда нет общих возможностей, FRR отправляет ошибку Unsupported Capability и затем сбрасывает соединение.

Конфигурация

Конфигурация роутера BGP

Во-первых, вы должны настроить роутер BGP с помощью ASN. Номер AS является идентификатором автономной системы. Протокол BGP использует номер AS для определения, является ли соединение BGP внутренним или внешним. VyOS не имеет специальной команды для запуска процесса BGP. Процесс BGP начинается, когда первый сосед конфигурируется.

set protocols bgp system-as <asn>

Установите локальный номер автономной системы, который представляет этот роутер. Это обязательный параметр!

Конфигурация пиров

Определение пиров
set protocols bgp neighbor <address|interface> remote-as <asn>

Эта команда создает нового соседа, чей remote-as — <asn>. Адрес соседа может быть IPv4-адресом, IPv6-адресом или интерфейсом для использования для соединения. Эта команда применима для пира и группы пиров.

set protocols bgp neighbor <address|interface> remote-as internal

Создайте пир так, как вы бы сделали, указав ASN, за исключением того, что если пир ASN отличается от моего, как указано в команде protocols bgp <asn>, соединение будет отклонено.

set protocols bgp neighbor <address|interface> remote-as external

Создайте пир так, как вы бы сделали, указав ASN, за исключением того, что если пир ASN такой же, как мой, как указано в команде protocols bgp <asn>, соединение будет отклонено.

set protocols bgp neighbor <address|interface> remote-as auto

Создайте пир так, как вы бы сделали, указав ASN, за исключением того, что пир удаленный ASN определяется автоматически из сообщения OPEN.

set protocols bgp neighbor <address|interface> local-role <role> [strict]

Роли BGP определены в RFC RFC 9234 и обеспечивают простой способ добавления предотвращения, обнаружения и смягчения маршрутизации. Значение локальной роли согласуется с новой возможностью BGP Role, которая имеет встроенную проверку соответствующего значения. В случае несоответствия новое сообщение о несоответствии ролей BGP <2, 11> будет отправлено. Правильные пары ролей:

Провайдер - Клиент

Пир - Пир

RS-Server - RS-Client

Если задано strict, сеанс BGP не будет установлен до тех пор, пока BGP-пир не установит локальную роль на своей стороне. Этот параметр конфигурации определен в RFC RFC 9234 и используется для обязательного выполнения соответствующей конфигурации на стороне ваших контрагентов.

Маршруты, отправляемые провайдером, rs-server или пиром локальной роли (или если получены клиентом, rs-client или пиром локальной роли), будут отмечены новым атрибутом Only to Customer (OTC).

Маршруты с этим атрибутом могут быть отправлены только вашему соседу, если ваша локальная роль — провайдер или rs-server. Маршруты с этим атрибутом могут быть получены только если ваша локальная роль — клиент или rs-client.

В случае пир-пир отношения маршруты могут быть получены только если OTC значение равно вашему номеру AS соседа.

Все эти правила с OTC помогут обнаружить и смягчить утечки маршрутов и будут происходить автоматически, если локальная роль установлена.

set protocols bgp neighbor <address|interface> shutdown

Эта команда отключает пир или группу пиров. Чтобы снова включить пир, используйте команду delete этого.

set protocols bgp neighbor <address|interface> description <text>

Установите описание пира или группы пиров.

set protocols bgp neighbor <address|interface> update-source <address|interface>

Укажите IPv4-адрес источника для сеанса BGP с этим соседом, может быть указан как прямой IPv4-адрес, так и имя интерфейса.

Согласование возможностей
set protocols bgp neighbor <address|interface> capability dynamic

Эта команда позволит динамическое обновление возможностей во время установленного сеанса BGP.

set protocols bgp neighbor <address|interface> capability extended-nexthop

Позвольте BGP согласовать возможность extended-nexthop с его пиром. Если вы соединяетесь через IPv6 Link-Local адрес, эта возможность включается автоматически. Если вы соединяетесь через IPv6 Global Address то включение этой команды позволит BGP устанавливать маршруты IPv4 с IPv6 next-hop, если у вас не настроены IPv4 на интерфейсах.

set protocols bgp neighbor <address|interface> disable-capability-negotiation

Подавить отправку Согласования возможностей как необязательный параметр OPEN сообщения для пира. Эта команда влияет только на пир, который настроен иначе, чем IPv4 unicast конфигурация.

Когда удаленный пир не имеет функции согласования возможностей, удаленный пир не отправляет никаких возможностей вообще. В этом случае, BGP настраивает пир с настроенными возможностями.

Вы можете предпочесть локально настроенные возможности более чем согласованными возможностями, даже если удаленный пир отправляет возможности. Если пир настроен с помощью override-capability, VyOS игнорирует полученные возможности, затем заменяет согласованные возможности на настроенные значения.

Кроме того, вы должны помнить, что эта функция фундаментально отключает возможность использовать широко распространенные функции BGP. BGP без номера, поддержка хост-имен, AS4, Addpath, Обновление маршрута, ORF, Динамические возможности, и гладкий рестарт.

set protocols bgp neighbor <address|interface> override-capability

Эта команда позволяет переопределить результат согласования возможностей с локальной конфигурацией. Игнорировать значение возможностей удаленного пира.

set protocols bgp neighbor <address|interface> strict-capability-match

Эта команда строго сравнивает удаленные возможности и локальные возможности. Если возможности различаются, отправляется сообщение об ошибке Unsupported Capability, затем сбрасывается соединение.

Вы можете предпочесть отключить отправку параметра OPEN сообщения необязательного параметра для пира, когда удаленный пир не реализует функцию согласования возможностей. Используйте команду ылoбпосл code 5 . .
