PIM

PIM маршрутизирует мультикастовый трафик между маршрутизаторами, используя существующую таблицу маршрутизации для принятия решений о пути. VyOS поддерживает PIM Sparse Mode (PIM-SM) и версии IGMP 2 и 3.

В PIM-SM трафик от мультикаст-источников передается к RP. Мультикаст-приемники используют IGMP для сигнализации своего локального маршрутизатора, какие группы они хотят получать, а маршрутизатор использует PIM для получения этого трафика от RP через общее дерево.

Для работы в PIM-SM необходимо:

  • PIM должен быть включен на каждом интерфейсе по пути мультикаста.

  • Положение RP должно быть объявлено одинаково на каждом маршрутизаторе в домене PIM.

  • IGMP должен быть включен на интерфейсах, подключенных к мультикаст-приемникам.

Конфигурация

PIM-SM

set protocols pim ecmp

Включить маршрутизацию ECMP для мультикастового трафика.

Когда при поиске RPF возвращается несколько равных по стоимости следующих узлов, включение этой функции распределяет (S,G) потоки мультикаста между всеми из них.

Если ECMP не включен, PIM по умолчанию использует только первый следующий узел, возвращенный при поиске RPF.

Пример:

set protocols pim ecmp
set protocols pim ecmp rebalance

Включить автоматическое перераспределение всех потоков PIM (S,G), когда интерфейс ECMP выходит из строя.

Когда ECMP включен, и один из интерфейсов, используемых PIM, выходит из строя, эта функция заставляет PIM перераспределить все существующие потоки (S,G) по оставшимся интерфейсам с одинаковой стоимостью.

Если перераспределение не настроено, PIM перенаправляет только те потоки, которые активно использовали неисправный интерфейс.

Пример:

set protocols pim ecmp rebalance
set protocols pim join-prune-interval <1-65535>

Настройте интервал, в секундах, с которым PIM отправляет сообщения Join/Prune соседям сверху.

По умолчанию интервал составляет 60 секунд. Установка значения ниже 60 секунд может негативно повлиять на сходимость масштаба.

Пример:

set protocols pim join-prune-interval 120
set protocols pim keep-alive-timer <1-65535>

Настройте временной интервал, в секундах, для состояния потока (S,G) мультикаста.

Примечание

Некоторое оборудование не может обнаруживать трафик, поступающий с интервалом менее 30 секунд. Для такого оборудования убедитесь, что значение установлено на 31 секунду или выше.

Пример:

set protocols pim keep-alive-timer 60
set protocols pim packets <1-255>

Настройте количество последовательно обрабатываемых входящих пакетов PIM с соседа до того, как система перейдет к следующей задаче.

Значение по умолчанию — 3 пакета. Эта команда полезна только в развертываниях с большим количеством пакетов управления PIM.

Пример:

set protocols pim packets 10
set protocols pim register-accept-list prefix-list <prefix-list>

Настройте список префиксов для фильтрации входящих сообщений PIM Register.

Когда PIM получает пакет Register, IP-адрес источника мультикаста оценивается по указанному списку префиксов. Если IP-адрес источника разрешен, нормальная обработка PIM продолжается. Если IP-адрес источника запрещен, отправляется сообщение Register-Stop отправителю.

Пример:

set protocols pim register-accept-list prefix-list MULTICAST-SOURCES
set protocols pim register-suppress-time <1-65535>

Настройте продолжительность, в секундах, в течение которой FHR подавляет отправку сообщений PIM Register.

Пример:

set protocols pim register-suppress-time 60
set protocols pim rp address <ip-address> group <prefix>

Настройте точку привязки (RP) для заданного диапазона мультикаст-группы.

Чтобы использовать PIM, необходимо настроить RP для получения сообщений Join. VyOS в настоящее время поддерживает только статическую конфигурацию RP.

Параметр <address> определяет IP-адрес RP, а параметр <group> определяет префикс диапазона мультикаст-группы, обслуживаемой этим RP.

Один RP может обслуживать несколько диапазонов групп. Повторите команду с разными префиксами <group>, чтобы сопоставить несколько диапазонов с одним RP.

Пример:

set protocols pim rp address 192.0.2.1 group 239.0.0.0/8
set protocols pim rp keep-alive-timer <1-65535>

Настройте временной интервал, в секундах, для состояния (S,G) мультикаст-потока на точке привязки (RP).

Это значение должно быть не меньше, чем register-suppression-time; в противном случае RP может истечь (S,G) состояние до того, как придет следующее сообщение Null-Register от FHR.

Когда отправляется сообщение Register-Stop, KAT(S,G) на RP устанавливается в максимальное значение глобального Keepalive_Period и RP_Keepalive_Period.

Значение по умолчанию — 210 секунд.

См. RFC 7761, раздел 4.1 для деталей.

Примечание

Поскольку некоторые аппаратные платформы не могут обнаруживать данные, поступающие с интервалом менее 30 секунд, убедитесь, что значение установлено на 31 секунду или выше.

Пример:

set protocols pim rp keep-alive-timer 300
set protocols pim no-v6-secondary

Отключить отправку второстепенных адресов IPv6 в сообщениях PIM Hello.

По умолчанию сообщения PIM Hello включают все второстепенные IPv6 адреса, настроенные на интерфейсе, позволяя PIM-соседям использовать их как IPv6 следующие узлы для поиска RPF.

Пример:

set protocols pim no-v6-secondary
set protocols pim spt-switchover infinity-and-beyond prefix-list <list>

На LHR подавить переключение с общего дерева (*,G) на специфичное по источнику (S,G) SPT.

Опциональный prefix-list контролирует, какие группы затронуты: группы, соответствующие записи permit, остаются на общем дереве, группы, соответствующие записи deny, переключаются нормально. Без списка префиксов подавление применяется ко всем группам.

Пример:

set protocols pim spt-switchover infinity-and-beyond
set protocols pim spt-switchover infinity-and-beyond prefix-list SHARED-TREE-GROUPS
set protocols pim ssm prefix-list <list>

Настройте список префиксов с диапазоном IP-адресов групп мультикаста, работающих в режиме SSM.

Пример:

set protocols pim ssm prefix-list SSM-RANGE

Команды, специфичные для интерфейса

set protocols pim interface <interface> bfd

Включить BFD для каждого PIM-соседа, обнаруженного на указанном интерфейсе.

Когда BFD обнаруживает сбой связи, связь PIM-соседа разрывается, и все связанные с ней записи (S,G) мультикаста удаляются.

Пример:

set protocols pim interface eth0 bfd
set protocols pim interface <interface> bfd profile <name>

Примените указанный профиль BFD к сессиям BFD на этом интерфейсе PIM.

Пример:

set protocols pim interface eth0 bfd profile fast-failover
set protocols pim interface <interface> dr-priority <1-4294967295>

Настройте приоритет маршрутизатора-дизайнер (DR) для указанного интерфейса.

Маршрутизатор с самым высоким приоритетом интерфейса выбирается в качестве DR для сегмента LAN.

Пример:

set protocols pim interface eth0 dr-priority 100
set protocols pim interface <interface> hello <1-180>

Настройте интервал PIM Hello, в секундах, для указанного интерфейса.

Сообщения PIM Hello отправляются периодически на интерфейсе для обнаружения и поддержания отношений PIM-соседей. Время ожидания (продолжительность, после которой сосед считается мертвым, если не получено сообщение Hello) рассчитывается на основе интервала Hello.

Пример:

set protocols pim interface eth0 hello 10
set protocols pim interface <interface> no-bsm

Отключить обработку сообщений PIM BSM на указанном интерфейсе.

Пример:

set protocols pim interface eth0 no-bsm
set protocols pim interface <interface> no-unicast-bsm

Отключить обработку однократных сообщений PIM BSM на этом интерфейсе.

Пример:

set protocols pim interface eth0 no-unicast-bsm
set protocols pim interface <interface> passive

Отключить отправку и получение контрольных пакетов PIM на этом интерфейсе.

Пример:

set protocols pim interface eth0 passive
set protocols pim interface <interface> source-address <ip-address>

Настройте IP-адрес источника, который PIM использует для отправки контрольных сообщений на указанном интерфейсе.

Эта команда полезна, когда на одном интерфейсе настроено несколько IP-адресов.

Пример:

set protocols pim interface eth0 source-address 192.0.2.10

IGMP

set protocols pim igmp watermark-warning <1-65535>

Настройте генерацию предупреждения по водяным меткам на основе количества присоединенных групп IGMP.

Когда общее количество присоединенных групп IGMP достигает этого заданного предела, маршрутизатор генерирует предупреждение.

Пример:

set protocols pim igmp watermark-warning 500

Команды, специфичные для интерфейса

set protocols pim interface <interface> igmp

Включить IGMP на указанном интерфейсе.

Пример:

set protocols pim interface eth0 igmp
set protocols pim interface <interface> igmp disable

Административно отключить IGMP на указанном интерфейсе без удаления существующей конфигурации IGMP.

Пример:

set protocols pim interface eth0 igmp disable
set protocols pim interface <interface> igmp join <multicast-address> source-address <IP-address>

Настройте интерфейс для присоединения к определенному каналу (S,G).

Укажите оба IP-адреса мультикаста (G) и IP-адрес источника (S). Каждая команда присоединяет один канал (S,G). Чтобы присоединиться к нескольким каналам, имеющим одну и ту же группу, повторите команду с разными значениями source-address.

Пример:

set protocols pim interface eth0 igmp join 232.1.1.100 source-address 192.0.2.50
set protocols pim interface eth0 igmp join 232.1.1.100 source-address 192.0.2.51
set protocols pim interface <interface> igmp query-interval <1-1800>

Настройте интервал запроса IGMP, в секундах, на указанном интерфейсе.

Это настройка определяет интервал между запросами IGMP, отправляемыми маршрутизатором для обнаружения, какие группы мультикаста имеют активных слушателей на подключенной сети.

Пример:

set protocols pim interface eth1 igmp query-interval 125
set protocols pim interface <interface> igmp query-max-response-time <10-250>

Настройте максимальное время ответа запроса IGMP, в децисекундах, на указанном интерфейсе.

Это значение вставляется в запросы IGMP и указывает максимальное время, в течение которого хосты могут ответить сообщением о регистрации. Если сообщение не получено в течение указанного времени, PIM предполагает, что больше нет активных локальных получателей, и может истечь срок действия связанного с ним состояния (*,G) или (S,G) (см. RFC 7761, раздел 4.1).

Пример:

set protocols pim interface eth0 igmp query-max-response-time 50
set protocols pim interface <interface> igmp version <2-3>

Настройте версию IGMP на указанном интерфейсе.

По умолчанию версия 3.

Пример:

set protocols pim interface eth0 igmp version 2

Пример

Следующий пример демонстрирует базовую реализацию PIM Sparse Mode (PIM-SM) в трех маршрутизаторах, показывая, как настроить роль каждого маршрутизатора в мультикаст-домене. Вместе три маршрутизатора образуют полный путь распространения мультикаста от источников к получателям, один из которых действует как точка привязки (RP).

Топология и роли

  • Маршрутизатор 1 — это LHR.

  • Маршрутизатор 3 — это RP.

  • Маршрутизатор 2 — это FHR.

Маршрутизатор 1:

set interfaces ethernet eth2 address '198.51.100.1/30'
set interfaces ethernet eth1 address '192.0.2.1/24'
set protocols ospf area 0 network '198.51.100.0/30'
set protocols ospf area 0 network '192.0.2.0/24'
set protocols pim interface eth1
set protocols pim interface eth1 igmp
set protocols pim interface eth2
set protocols pim rp address 203.0.113.1 group '224.0.0.0/4'

Маршрутизатор 3:

set interfaces dummy dum0 address '203.0.113.1/32'
set interfaces ethernet eth0 address '198.51.100.2/30'
set interfaces ethernet eth1 address '198.51.100.5/30'
set protocols ospf area 0 network '198.51.100.0/30'
set protocols ospf area 0 network '203.0.113.1/32'
set protocols ospf area 0 network '198.51.100.4/30'
set protocols pim interface dum0
set protocols pim interface eth0
set protocols pim interface eth1
set protocols pim rp address 203.0.113.1 group '224.0.0.0/4'

Маршрутизатор 2:

set interfaces ethernet eth1 address '203.0.113.129/25'
set interfaces ethernet eth2 address '198.51.100.6/30'
set protocols ospf area 0 network '203.0.113.128/25'
set protocols ospf area 0 network '198.51.100.4/30'
set protocols pim interface eth1
set protocols pim interface eth2
set protocols pim rp address 203.0.113.1 group '224.0.0.0/4'
