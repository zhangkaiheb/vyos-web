OSPF

OSPF — это протокол маршрутизации для сетей Internet Protocol (IP). Он использует алгоритм маршрутизации по состоянию ссылки (LSR) и относится к группе внутренних шлюзовых протоколов (IGPs), работающих в пределах одного автономного системы (AS). Он определен как OSPF версии 2 в RFC 2328 (1998) для IPv4. Обновления для IPv6 указаны как OSPF версии 3 в RFC 5340 (2008). OSPF поддерживает модель адресации CIDR.

OSPF широко используется IGP в крупных корпоративных сетях.

Общие сведения

VyOS не имеет специальной команды для запуска процесса OSPF. Процесс OSPF начинается, когда настраивается первый интерфейс, включенный в OSPF.

set protocols ospf area <number> network <A.B.C.D/M>

Эта команда указывает интерфейсы, включенные в OSPF. Если у интерфейса есть адрес из определенного диапазона, то команда включает OSPF на этом интерфейсе, так что маршрутизатор может предоставить информацию о сети другим роутерам OSPF через этот интерфейс.

Эта команда также используется для включения процесса OSPF. Номер области можно указать в десятичной нотации в диапазоне от 0 до 4294967295. Или он может быть указан в точечной десятичной нотации, аналогичной IP-адресу.

Длина префикса на интерфейсе должна быть равна или больше (то есть меньше сети) длины префикса в объявлении сети. Например, вышеупомянутая команда не включает OSPF на интерфейсе с адресом 192.168.1.1/23, но включает его на интерфейсе с адресом 192.168.1.129/25.

В некоторых случаях может быть удобнее включить OSPF на уровне интерфейса/подсети set protocols ospf interface <interface> area <x.x.x.x | x>

set protocols ospf auto-cost reference-bandwidth <number>

Эта команда устанавливает эталонную пропускную способность для расчета стоимости, где пропускная способность может быть в диапазоне от 1 до 4294967, указанная в Мбит/с. По умолчанию это 100 Мбит/с (то есть связь с пропускной способностью 100 Мбит/с или выше будет иметь стоимость 1. Стоимость связей с меньшей пропускной способностью будет масштабироваться относительно этой стоимости).

set protocols ospf parameters router-id <rid>

Эта команда устанавливает идентификатор маршрутизатора для процесса OSPF. Идентификатор маршрутизатора может быть IP-адресом маршрутизатора, но не обязательно — это может быть любое произвольное 32-битное число. Однако он ДОЛЖЕН быть уникальным в пределах всей области OSPF для OSPF-спикера — если несколько OSPF-спикеров настроены с одинаковым идентификатором маршрутизатора, будут происходить плохие вещи!

Дополнительные параметры

set protocols ospf default-information originate [always] [metric <number>] [metric-type <1|2>] [route-map <name>]

Создание AS-External (тип-5) LSA, описывающего маршрут по умолчанию во всех областях, способных к внешней маршрутизации, с заданным типом метрики и метрикой. Если ключевое слово always задано, маршрут по умолчанию всегда объявляется, даже если его нет в таблице маршрутизации. Аргумент route-map указывает, чтобы объявлять маршрут по умолчанию, если маршрут соответствует карте маршрутизации.

set protocols ospf distance global <distance>

Эта команда изменяет значение расстояния OSPF глобально. Диапазон расстояний — 1–255.

set protocols ospf distance ospf <external|inter-area|intra-area> <distance>

Эта команда изменяет значение расстояния OSPF. Аргументы — это значения расстояния для внешних маршрутов, межобластных маршрутов и внутренних маршрутов соответственно. Диапазон расстояний — 1–255.

Примечание

Маршруты с расстоянием 255 считаются недействительными и не устанавливаются в ядро.

set protocols ospf log-adjacency-changes [detail]

Эта команда позволяет регистрировать изменения в соседстве. С необязательным аргументом detail, все изменения в состоянии соседства отображаются. Без detail, отображаются только изменения в полном состоянии или регрессиях.

set protocols ospf max-metric router-lsa <administrative|on-shutdown <seconds>|on-startup <seconds>>

Это включает поддержку RFC 3137, где процесс OSPF описывает свои транзитные ссылки в своем маршрутизирующем LSA как имеющие бесконечное расстояние, поэтому другие маршрутизаторы избегают вычисления путей через этот маршрутизатор, пока еще могут достичь сетей через этот маршрутизатор.

Эта поддержка может быть включена административно (и неограниченно) с помощью команды administrative. Она также может быть включена условно. Условное включение максимальной метрики маршрутизирующих LSA может быть выполнено на период секунд после запуска с помощью команды on-startup <seconds> и/или на период секунд перед завершением с помощью команды on-shutdown <seconds>. Диапазон времени — 5–86400.

set protocols ospf parameters abr-type <cisco|ibm|shortcut|standard>

Эта команда выбирает модель ABR. OSPF-роутер поддерживает четыре модели ABR:

cisco — маршрутизатор считается ABR, если у него несколько настроенных ссылок на сети в разных областях, одна из которых является основной областью. Кроме того, ссылка на основную область должна быть активной (работающей). ibm — идентично модели «cisco», но в этом случае ссылка на основную область может не быть активной. standard — маршрутизатор имеет несколько активных ссылок на разные области. shortcut — идентично модели «standard», но в этой модели маршрутизатор разрешает использовать топологию подключенных областей без вовлечения основной области для межобластных соединений.

Дополнительная информация о различиях между моделями «cisco» и «ibm» можно найти в RFC 3509. Модель «shortcut» позволяет ABR создавать маршруты между областями на основе топологии областей, подключенных к этому маршрутизатору, но не используя основную область, если неосновной маршрут будет дешевле. Для получения дополнительной информации о модели «shortcut», см. ospf-shortcut-abr-02.txt

set protocols ospf parameters rfc1583-compatibility

RFC 2328, заменяющий RFC 1583, предлагает согласно разделу G.2 (изменения) в разделе 16.4.1 изменение алгоритма предпочтения пути, которое предотвращает возможные циклы маршрутизации, которые были возможны в старой версии OSPFv2. Более конкретно, это требует, чтобы межобластные пути и внутренние маршруты основной области теперь имели одинаковое предпочтение, но оба по-прежнему предпочтительнее внешних путей.

Эту команду обычно НЕ следует устанавливать.

set protocols ospf interface <interface> passive [disable]

Эта команда указывает интерфейс как пассивный. Пассивный интерфейс объявляет свой адрес, но не запускает протокол OSPF (не формируются соседства и не генерируются пакеты Hello).

Опциональный параметр disable позволяет исключить интерфейс из пассивного состояния. Эта команда используется, если была настроена команда passive-interface default.

set protocols ospf passive-interface default

Эта команда по умолчанию указывает все интерфейсы как пассивные. Поскольку эта команда изменяет логику конфигурации на пассивную по умолчанию, интерфейсы, где ожидаются соседства маршрутизатора, должны быть настроены с помощью команды passive-interface-exclude.

set protocols ospf maximum-paths <1-64>

Используйте эту команду для контроля максимального количества равных маршрутов для достижения конкретной цели. Верхний предел может отличаться, если вы измените значение MULTIPATH_NUM во время компиляции. По умолчанию это MULTIPATH_NUM (64).

set protocols ospf refresh timers <seconds>

Роутер автоматически обновляет информацию о состоянии ссылки с соседями. Только устаревшая информация обновляется, которая превысила определенный порог. Эта переменная изменяет значение порога, которое по умолчанию составляет 1800 секунд (полчаса). Значение применяется ко всему маршрутизатору OSPF. Диапазон таймера — 10–1800.

set protocols ospf timers throttle spf <delay|initial-holdtime|max-holdtime> <seconds>

Эта команда устанавливает начальную задержку, начальное время ожидания и максимальное время ожидания между тем, когда рассчитывается SPF и событие, вызвавшее расчет. Время указывается в миллисекундах и должно находиться в диапазоне 0–600000 миллисекунд. delay устанавливает начальный временной интервал планирования SPF в миллисекундах. Значение по умолчанию — 200 мс. initial-holdtime устанавливает минимальное время ожидания между двумя последовательными расчетами SPF. Значение по умолчанию — 1000 мс. max-holdtime устанавливает максимальное время ожидания между двумя последовательными расчетами SPF. Значение по умолчанию — 10000 мс.

set protocols ospf ldp-sync

Эта команда включает синхронизацию IGP-LDP глобально для OSPF. Это требует, чтобы LDP был функционален. Это описано в RFC 5443. По умолчанию все интерфейсы, работающие в OSPF, включены в синхронизацию. Петли исключены.

set protocols ospf ldp-sync holddown <seconds>

Эта команда изменяет значение времени ожидания глобально для синхронизации IGP-LDP во время сходимости/событий переключения интерфейса.

set protocols ospf capability opaque

ospfd поддерживает Opaque LSA RFC 2370 как частичную поддержку LSAs для MPLS Traffic Engineering. Необходимо включить возможность Opaque-LSA в конфигурации.

Альтернативная команда — «mpls-te on» (Traffic Engineering)

Примечание

FRR предоставляет только частичную поддержку некоторых расширений протокола маршрутизации, используемых с MPLS-TE; он не поддерживает полное решение RSVP-TE.

Конфигурация области

set protocols ospf area <number> area-type stub

Эта команда указывает область как Stub Area. То есть, область, где ни один маршрутизатор не создает маршруты вне OSPF, и, следовательно, в этой области все внешние маршруты проходят через ABR. Таким образом, ABR для такой области не нужно передавать AS-External LSAs (тип-5) или ASBR-Summary LSAs (тип-4) в область. Они должны передавать только Network-Summary (тип-3) LSAs в такую область, вместе с маршрутом по умолчанию.

set protocols ospf area <number> area-type stub no-summary

Эта команда указывает область как Totally Stub Area. Помимо ограничений Stub Area, этот тип области запрещает ABR вставлять Network-Summary:span>
