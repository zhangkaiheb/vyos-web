Виртуальный Ethernet

Виртуальные интерфейсы Ethernet (veth) — это программные интерфейсы, которые работают парами, создавая туннель между собой. Трафик, переданный в один из интерфейсов пары (например, veth0), доставляется напрямую к его соседнему интерфейсу (например, veth1).

Интерфейсы veth часто используются для подключения сетевых пространств имен или VRF, но они также могут функционировать как самостоятельные виртуальные сетевые интерфейсы.

Примечание

Интерфейсы veth должны быть созданы парами, где каждый интерфейс выступает в роли соседа другого.

Конфигурация

Общая конфигурация интерфейса

set interfaces virtual-ethernet <interface> address <address | dhcp | dhcpv6>

Настройте интерфейс с одним или несколькими IP-адресами.

Доступны следующие варианты:

  • address: Назначьте один или несколько IPv4 или IPv6 адресов интерфейсу. Например, используйте 192.0.2.1/24 для IPv4 или 2001:db8::1/64 для IPv6.

  • dhcp: Интерфейс получает IPv4-адрес от сервера DHCP на том же сегменте сети.

  • dhcpv6: Интерфейс получает IPv6-адрес от сервера DHCPv6 на том же сегменте сети.

Примечание

Если интерфейс получает IPv4-адрес через DHCP, и необходимы определенные настройки до/после получения IP-адреса, используйте предоставленные скрипты-хуки:

  • /config/scripts/dhcp-client/pre-hooks.d/

  • /config/scripts/dhcp-client/post-hooks.d/

Пример:

set interfaces virtual-ethernet veth0 address 192.0.2.1/24
set interfaces virtual-ethernet veth0 address 2001:db8::1/64
set interfaces virtual-ethernet veth0 address dhcp
set interfaces virtual-ethernet veth0 address dhcpv6
set interfaces virtual-ethernet <interface> description <description>

Настройте понятное, описательное имя интерфейса.

Это имя появляется в команде show interfaces и в инструментах мониторинга на основе SNMP.

Пример:

set interfaces virtual-ethernet veth0 description 'This is an interface running on VyOS.'

VLAN

Регулярные VLANs (802.1q)

IEEE 802.1q, часто называемый Dot1q, является стандартом отрасли для реализации VLAN на Ethernet-сетях. Он определяет тегирование VLAN для кадров Ethernet и описывает процедуры для коммутаторов и мостов. Стандарт также включает приоритизацию качества обслуживания (IEEE 802.1p) и определяет протокол общих атрибутов регистрации.

Сегменты сетей, совместимые с IEEE 802.1q, используют теги VLAN. Когда кадр попадает в такой сегмент, добавляется тег для указания принадлежности к VLAN. Каждый кадр может принадлежать только одному VLAN. Если кадр приходит без тега, предполагается, что он относится к базовому VLAN.

IEEE 802.1, рабочая группа IEEE 802, разработала стандарт и продолжает его обновлять. Одним из известных обновлений является 802.1Q-2014, который включил IEEE 802.1aq (Shortest Path Bridging) и большую часть стандарта IEEE 802.1d.

В VyOS, интерфейсы VLAN 802.1q представлены как виртуальные подинтерфейсы, называемые vif.

set interfaces virtual-ethernet <interface> vif <vlan-id>

Настройте VLAN-интерфейс с уникальным идентификатором VLAN.

ID VLAN идентифицирует конкретный VLAN и находится в диапазоне от 0 до 4094.

Вы можете настроить несколько VLAN-интерфейсов на одном физическом интерфейсе.

Примечание

На Ethernet vifs принимаются только тегированные пакеты 802.1Q.

set interfaces virtual-ethernet <interface> vif <vlan-id> address <address | dhcp | dhcpv6>

Настройте интерфейс с одним или несколькими IP-адресами.

Доступны следующие варианты:

  • address: Назначьте один или несколько IPv4 или IPv6 адресов интерфейсу. Например, используйте 192.0.2.1/24 для IPv4 или 2001:db8::1/64 для IPv6.

  • dhcp: Интерфейс получает IPv4-адрес от сервера DHCP на том же сегменте сети.

  • dhcpv6: Интерфейс получает IPv6-адрес от сервера DHCPv6 на том же сегменте сети.

Примечание

Если интерфейс получает IPv4-адрес через DHCP, и необходимы определенные настройки до/после получения IP-адреса, используйте предоставленные скрипты-хуки:

  • /config/scripts/dhcp-client/pre-hooks.d/

  • /config/scripts/dhcp-client/post-hooks.d/

Пример:

set interfaces virtual-ethernet veth0 vif 10 address 192.0.2.1/24
set interfaces virtual-ethernet veth0 vif 10 address 2001:db8::1/64
set interfaces virtual-ethernet veth0 vif 10 address dhcp
set interfaces virtual-ethernet veth0 vif 10 address dhcpv6
set interfaces virtual-ethernet <interface> vif <vlan-id> description <description>

Настройте понятное, описательное имя интерфейса.

Это имя появляется в команде show interfaces и в инструментах мониторинга на основе SNMP.

Пример:

set interfaces virtual-ethernet veth0 vif 10 description 'This is an interface running on VyOS.'
set interfaces virtual-ethernet <interface> vif <vlan-id> disable

Отключите интерфейс.

Интерфейс будет установлен в состояние административно отключен (A/D).

Пример:

set interfaces virtual-ethernet veth0 vif 10 disable
set interfaces virtual-ethernet <interface> vif <vlan-id> disable-link-detect

Отключите обнаружение изменений состояния физической линии на интерфейсе, например, когда кабель отсоединен.

По умолчанию интерфейс обнаруживает изменения состояния физической линии.

Пример:

set interfaces virtual-ethernet veth0 vif 10 disable-link-detect
set interfaces virtual-ethernet <interface> vif <vlan-id> mac <xx:xx:xx:xx:xx:xx>

Настройте пользовательский MAC-адрес на интерфейсе.

Пример:

set interfaces virtual-ethernet veth0 vif 10 mac '00:53:01:02:03:04'
set interfaces virtual-ethernet <interface> vif <vlan-id> mtu <mtu>

Настройте MTU настройка интерфейса

Если настроен, интерфейс переключается в режим хоста, и IPv4-пересылка отключена на нем.

Пример:

set interfaces virtual-ethernet veth0 vif 10 ip disable-forwarding
set interfaces virtual-ethernet <interface> vif <vlan-id> ip enable-directed-broadcast

Настройте, чтобы передавать IP-направленные широковещательные пакеты, полученные на этом интерфейсе.

Стандартное поведение: IP-направленные широковещательные пакеты отбрасываются.

Если настроен: IP-направленные широковещательные пакеты передаются всем хостам на целевом подсети, как указано в RFC 1812 и RFC 2644.

Пример:

set interfaces virtual-ethernet veth0 vif 10 ip enable-directed-broadcast
set interfaces virtual-ethernet <interface> vif <vlan-id> ip enable-arp-accept
