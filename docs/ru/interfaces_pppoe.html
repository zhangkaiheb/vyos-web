PPPoE

PPPoE — это сетевой протокол, который инкапсулирует кадры PPP в кадры Ethernet. Он часто используется для подключения клиентов ISP к серверу широкополосного доступа.

Конфигурация

Общая конфигурация интерфейса

set interfaces pppoe <interface> description <description>

Настройте понятное и описательное имя интерфейса.

Это имя появляется в команде show interfaces и средствах мониторинга на основе SNMP.

Пример:

set interfaces pppoe pppoe0 description 'This is an interface running on VyOS.'
set interfaces pppoe <interface> disable

Отключить интерфейс.

Интерфейс будет установлен в состояние административно отключенного (A/D).

Пример:

set interfaces pppoe pppoe0 disable
set interfaces pppoe <interface> mtu <mtu>

Настройте MTU на интерфейсе.

Это значение определяет максимальный размер пакета, в байтах, который интерфейс отправляет без фрагментации.

Пример:

set interfaces pppoe pppoe0 mtu 1600
set interfaces pppoe <interface> vrf <vrf>

Назначьте интерфейс определенному VRF экземпляру.

См. также

Для информации о настройке VRF обратитесь к разделу VRF.

Пример:

set interfaces pppoe pppoe0 vrf red

Параметры PPPoE

set interfaces pppoe <interface> access-concentrator <name>

Настройте имя целевого концентратора доступа для сеанса PPPoE.

Во время процесса обнаружения PPPoE клиент отправляет пакет инициализации PPPoE. Может быть несколько концентраторов доступа, которые отвечают пакетами предложений, и клиент выбирает один из них.

Это настройка ограничивает клиента только установкой сеансов с указанным концентратором доступа.

set interfaces pppoe <interface> authentication username <username>

Настройте имя пользователя для аутентификации сеанса PPPoE.

Хотя аутентификация необязательна в конфигурации интерфейса, большинство провайдеров требует ее для установления соединения.

set interfaces pppoe <interface> authentication password <password>

Настройте пароль для аутентификации сеанса PPPoE.

Хотя аутентификация необязательна в конфигурации интерфейса, большинство провайдеров требует ее для установления соединения.

set interfaces pppoe <interface> connect-on-demand

Включить вызов по запросу на интерфейсе PPPoE.

При включении система устанавливает соединение PPPoE только тогда, когда через интерфейс проходит трафик. Если соединение не удается, оно восстанавливается при возобновлении трафика.

Для соединений по запросу необходимо также настроить период idle-timeout, чтобы отключить сеанс после бездействия.

Примечание

Установка idle timeout в ноль или его отсутствие сохраняет соединение активным после установки.

По умолчанию соединение PPPoE устанавливается при запуске и остается активным постоянно; если соединение не удается, оно восстанавливается немедленно.

set interfaces pppoe <interface> no-default-route

Запросите IP-адрес от сервера PPPoE без установки маршрута по умолчанию.

Пример:

set interfaces pppoe pppoe0 no-default-route

Примечание

Введен в VyOS 1.4, эта команда меняет логику прежней опции CLI default-route.

set interfaces pppoe <interface> default-route-distance <distance>

Настройте расстояние для шлюза по умолчанию, предоставляемого сервером PPPoE.

Пример:

set interfaces pppoe pppoe0 default-route-distance 220
set interfaces pppoe <interface> mru <mru>

Настройте MRU для интерфейса PPPoE.

Эта настройка instructs daemon pppd ограничить удаленный абонент от отправки пакетов, превышающих настроенный MRU. Допустимые значения MRU варьируются от 128 до 16384 байт.

MRU 296 подходит для очень медленных линий (40 байт для заголовка TCP/IP и 256 байт для данных).

По умолчанию MRU составляет 1492 байта.

Примечание

При использовании протокола IPv6 MRU должен составлять не менее 1280 байт.

set interfaces pppoe <interface> idle-timeout <time>

Настройте время бездействия для сеансов PPPoE по запросу.

Эта настройка определяет, как долго соединение остается активным без любого трафика перед отключением.

Примечание

Установка времени бездействия в ноль или его отсутствие сохраняет соединение активным после установки.

set interfaces pppoe <interface> holdoff <time>

Настройте задержку повторного подключения для постоянных сеансов PPPoE.

Если постоянный сеанс (с отключенным connect-on-demand) завершается удаленным абонентом или внезапно прерывается, роутер ждет указанное время перед попыткой переподключения.

По умолчанию задержка повторного подключения составляет 30 секунд.

set interfaces pppoe <interface> local-address <address>

Настройте локальный IP-адрес для сеансов PPPoE.

По умолчанию этот IP-адрес согласуется.

set interfaces pppoe <interface> no-peer-dns

Отключите установку объявленных DNS-серверов на локальной системе.

set interfaces pppoe <interface> remote-address <address>

Настройте удаленный IP-адрес для сеансов PPPoE.

По умолчанию этот IP-адрес согласуется.

set interfaces pppoe <interface> service-name <name>

Настройте имя службы целевого концентратора доступа для сеанса PPPoE.

По умолчанию интерфейс PPPoE подключается к любому доступному концентратору доступа.

set interfaces pppoe <interface> source-interface <source-interface>

Настройте базовый интерфейс для соединения PPPoE.

Каждое соединение PPPoE устанавливается над базовым интерфейсом, который может быть сетевым интерфейсом, VIF или интерфейсом объединения.

set interfaces pppoe <interface> ip adjust-mss <mss | clamp-mss-to-pmtu>

Настройте MSS , объявляемый в исходящих пакетах TCP SYN на указанном интерфейсе.

Путем ограничения значения MSS в пакетах TCP SYN вы instruct удаленную сторону не отправлять пакеты большего размера, чем указано. Это помогает предотвратить проблемы с соединением, если PMTUD не работает.

Доступны следующие варианты:

  • mss: Устанавливает MSS в конкретное значение в байтах.

  • clamp-mss-to-pmtu: Устанавливает MSS в размер MTU интерфейса минус 40 байт для трафика IPv4 (20 байт для заголовка IPv4 и 20 байт для заголовка TCP). Этот вариант рекомендуется для автоматической установки правильного значения.

Примечание

Введено в VyOS 1.4, эта команда заменяет более старую синтаксическую конструкцию set firewall options interface <name> adjust-mss <value>.

set interfaces pppoe <interface> ip disable-forwarding

Настройте интерфейс для работы в режиме хоста или маршрутизатора.

Если настроен, интерфейс переключается в режим хоста, и IPv4-пересылка отключается на нем.

set interfaces pppoe <interface> ip source-validation <strict | loose | disable>

Настройте проверку исходного IP-адреса с использованием RPF на этом интерфейсе, как указано в RFC 3704.

Доступны следующие варианты:

  • strict: Каждый входящий пакет проверяется на соответствие FIB. Если интерфейс не является лучшим маршрутом обратно к этому источнику, проверка неудачна, и пакет удаляется.

  • loose: Каждый входящий пакет проверяется на соответствие FIB. Если исходный IP-адрес недоступен через любой интерфейс, проверка неудачна.

  • disable: Проверка исходного IP-адреса не выполняется. Все входящие пакеты принимаются.

RFC 3704 рекомендует включать режим strict, чтобы предотвратить спуфинг IP-адресов, например, DDoS-атаки. Для асимметричных или других сложных сценариев маршрутизации используйте режим loose.

IPv6

set interfaces pppoe <interface> ipv6 address autoconf

Включить назначение IPv6-адреса через SLAAC на этом интерфейсе.

set interfaces pppoe <interface> ipv6 adjust-mss <mss | clamp-mss-to-pmtu>

Настройте MSS , объявляемый в исходящих пакетах TCP SYN на указанном интерфейсе.

Путем ограничения значения MSS в пакетах TCP SYN вы instruct удаленную сторону не отправлять пакеты большего размера, чем указано. Это помогает предотвратить проблемы с соединением, если PMTUD не работает.

Доступны следующие варианты:

  • mss: Устанавливает MSS в конкретное значение в байтах.

  • clamp-mss-to-pmtu: Устанавливает MSS в размер MTU интерфейса минус 60 байт для трафика IPv6 (40 байт для заголовка IPv6 и 20 байт для заголовка TCP). Этот вариант рекомендуется для автоматической установки правильного значения.

Примечание

Введено в VyOS 1.4, эта команда заменяет более старую синтаксическую конструкцию set firewall options interface <name> adjust-mss <value>.

set interfaces pppoe <interface> ipv6 disable-forwarding

Настройте интерфейс для работы в режиме хоста или маршрутизатора.

Если настроен, интерфейс переключается в режим хоста, и IPv6-пересылка отключается на нем.

DHCPv6 Prefix Delegation (PD)

VyOS поддерживает DHCPv6 Prefix Delegation (DHCPv6-PD), как описано в RFC 3633. DHCPv6-PD поддерживается большинством провайдеров, предоставляющих native IPv6 для потребителей на фиксированных сетях.

set interfaces pppoe <interface> dhcpv6-options pd <id> length <length>

Настройте конкретную длину префикса для запросов DHCPv6-PD на этом интерфейсе.

Некоторые провайдеры по умолчанию предоставляют только /64 префикс. Используйте эту команду, чтобы запросить другую длину префикса для конкретного запроса DHCPv6-PD, в диапазоне от /32 (если разрешено вашим провайдером) до /64. <id> — уникальный идентификатор для запроса DHCPv6-PD.

По умолчанию значение равно 64.

Чтобы запросить префикс /56 от вашего провайдера, используйте:

set interfaces pppoe pppoe0 dhcpv6-options pd 0 length 56
set interfaces pppoe <interface> dhcpv6-options pd <id> interface <delegatee> address <address>

Настройте идентификатор интерфейса IPv6 (часть хоста) для делегированного интерфейса.

Значение должно быть десятичным целым числом. Оно добавляется к делегированному префиксу и настроенному SLA ID, чтобы сформировать окончательный IPv6-адрес.

По умолчанию часть хоста генерируется на основе MAC-адреса родительского интерфейса (формат EUI-64).

Пример:

Если /64-префикс делегируется интерфейсу eth8, и вы настраиваете часть хоста как 65535, полученный IPv6-адрес будет заканчиваться на ::ffff, так как 65535 соответствует ffff в шестнадцатеричной записи.

set interfaces pppoe pppoe0 dhcpv6-options pd 0 interface eth8 address 65534
set interfaces pppoe <interface> dhcpv6-options pd <id> interface <delegatee> sla-id <id>

Настройте SLA ID для делегированного интерфейса.

Значение должно быть десятичным целым числом больше 0 и помещаться в длину SLA ID. Оно преобразуется в шестнадцатеричный формат и добавляется к делегированному префиксу, чтобы сформировать специфический префикс подсети для делегированного интерфейса.

Пример:

Если SLA ID равен 1, а делегированный префикс равен 2001:db8:ffff::/48, то результатом будет подсеть для делегированного интерфейса 2001:db8:ffff:1::/64.

set interfaces pppoe pppoe0 dhcpv6-options pd 0 interface eth8 sla-id 1

Подключение/отключение

Пример

PPPoE через DSL

Сценарий конфигурации:

  • DSL-модем вашего провайдера подключен к интерфейсу eth0 на вашем маршрутизаторе VyOS.

  • Ваш провайдер не требует таггирования VLAN.

  • Данные для входа в PPPoE предоставлены вашим провайдером. Обычный формат имени пользователя — name@host.net, хотя это может отличаться.

Примечания по конфигурации:

  • Максимальный размер MTU для DSL составляет 1492 из-за заголовка PPPoE. Если вы переключаетесь с провайдера, использующего DHCP (например, стандартное кабельное соединение), убедитесь, что размеры MTU для VPN-соединений настроены соответствующим образом.

  • Чтобы игнорировать имена серверов, предоставляемые провайдером, и использовать только ваши статически настроенные, установите параметр name-server в none.

  • Автоматически устанавливается маршрут по умолчанию, как только интерфейс становится активным. Чтобы изменить это поведение, используйте опцию CLI no-default-route.

Примечание

Синтаксис конфигурации PPPoE изменился после VyOS 1.2 (Crux) и автоматически мигрируется при обновлении.

set interfaces pppoe pppoe0 authentication username 'userid'
set interfaces pppoe pppoe0 authentication password 'secret'
set interfaces pppoe pppoe0 source-interface 'eth0'

Защитите свою настройку, создав правила, соответствующие интерфейсу pppoe0 в цепочках фаервола:

set firewall ipv4 input filter rule 10 inbound-interface name 'pppoe0'
set firewall ipv4 forward filter rule 10 inbound-interface name 'pppoe0'

PPPoE через VLAN

Некоторые провайдеры требуют, чтобы соединения PPPoE устанавливались через интерфейс VLAN. Эта конкретная топология полностью поддерживается VyOS.

Следующая конфигурация устанавливает соединение PPPoE через VLAN 7, который является стандартным VLAN для Deutsche Telekom:

set interfaces pppoe pppoe0 authentication username 'userid'
set interfaces pppoe pppoe0 authentication password 'secret'
set interfaces pppoe pppoe0 source-interface 'eth0.7'

IPv6 DHCPv6 префикс делегирования

Сценарий конфигурации:

Следующая конфигурация устанавливает сеанс PPPoE на интерфейсе eth1, запрашивает делегирование префикса IPv6 /56 от провайдера и назначает подсеть /64 из этого делегирования интерфейсу eth0.

Примечания по конфигурации:

  • IP-адрес, присвоенный eth0, это <prefix>::1/64.

  • Если вы не знаете размер делегированного префикса, начните с sla-len 0.

  • Чтобы объявить префикс на интерфейсе eth0, настройте IPv6 Router Advertisement.

set interfaces pppoe pppoe0 authentication username vyos
set interfaces pppoe pppoe0 authentication password vyos
set interfaces pppoe pppoe0 dhcpv6-options pd 0 interface eth0 address '1'
set interfaces pppoe pppoe0 dhcpv6-options pd 0 interface eth0 sla-id '0'
set interfaces pppoe pppoe0 dhcpv6-options pd 0 length '56'
set interfaces pppoe pppoe0 ipv6 address autoconf
set interfaces pppoe pppoe0 source-interface eth1

set service router-advert interface eth0 prefix ::/64
