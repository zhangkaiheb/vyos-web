VXLAN

VXLAN — это технология виртуализации сети, которая решает проблемы масштабируемости в больших средах облачных вычислений. Он инкапсулирует кадры Ethernet (уровень 2) в датаграммы UDP (уровень 4), которые затем передаются через порт UDP 4789, назначенный IANA. Конечные точки VXLAN, называемые VTEPs, завершают туннели VXLAN и могут быть либо виртуальными, либо физическими портами коммутатора.

VXLAN поддерживает до 16 миллионов логических сетей и позволяет обеспечить связь на уровне 2 через IP-сети уровня 3. Он использует multicast или unicast с репликацией на стороне головного конца (HER), чтобы распространять вещательный, неизвестный однократный и многоадресный (BUM) трафик.

Спецификация VXLAN была изначально разработана VMware, Arista Networks и Cisco. Другие участники включают Huawei, Broadcom, Citrix, Pica8, Big Switch Networks, Cumulus Networks, Dell EMC, Ericsson, Mellanox, FreeBSD, OpenBSD, Red Hat, Joyent и Juniper Networks.

VXLAN официально документирован IETF в RFC 7348.

При настройке VXLAN в виртуальной машине VyOS убедитесь, что разрешено подделывание MAC-адреса (Hyper-V) или отправка фальшивых пакетов (ESX). В противном случае гипервизор может заблокировать переданные кадры.

Примечание

Хотя порт VXLAN, назначенный IANA, равен 4789, VyOS использует стандартный порт UDP Linux 8472 для интерфейсов VXLAN. Чтобы обеспечить совместимость с другими поставщиками, установите порт в стандартное значение IANA 4789.

Конфигурация

Общая конфигурация интерфейса

set interfaces vxlan <interface> address <address>

Настройте одно или несколько IP-адресов интерфейса.

<address> поддерживает IPv4 и IPv6 в обозначении CIDR. Например, используйте 192.0.2.1/24 для IPv4 или 2001:db8::1/64 для IPv6.

Пример:

set interfaces vxlan vxlan0 address 192.0.2.1/24
set interfaces vxlan vxlan0 address 2001:db8::1/64
set interfaces vxlan <interface> description <description>

Настройте понятное, описательное имя интерфейса.

Это имя появляется в команде show interfaces и инструментах мониторинга на основе SNMP.

Пример:

set interfaces vxlan vxlan0 description 'Это интерфейс, работающий на VyOS.'
set interfaces vxlan <interface> disable

Отключите интерфейс.

Интерфейс будет установлен в состояние административно отключен (A/D).

Пример:

set interfaces vxlan vxlan0 disable
set interfaces vxlan <interface> disable-flow-control

Отключите управление потоком Ethernet (стандарт IEEE 802.3x паузные кадры) на интерфейсе.

Управление потоком Ethernet, определенное стандартом IEEE 802.3x, временно прекращает передачу данных, чтобы предотвратить потерю пакетов при перегрузке сети. Например, когда отправитель передает данные быстрее, чем получатель может их обработать.

Отключение управления потоком Ethernet означает, что интерфейс не будет сигнализировать подключенному устройству о паузе передачи и будет удалять пакеты, если перегружен.

Пример:

set interfaces vxlan vxlan0 disable-flow-control
set interfaces vxlan <interface> disable-link-detect

Отключите обнаружение изменений состояния физической линии на интерфейсе, например, при отсоединении кабеля.

По умолчанию интерфейс обнаруживает изменения состояния физической линии.

Пример:

set interfaces vxlan vxlan0 disable-link-detect
set interfaces vxlan <interface> mac <xx:xx:xx:xx:xx:xx>

Настройте пользовательский MAC-адрес на интерфейсе.

Пример:

set interfaces vxlan vxlan0 mac '00:53:01:02:03:04'
set interfaces vxlan <interface> mtu <mtu>

Настройте MTU на интерфейсе.

Это значение определяет максимальный размер пакета, в байтах, который интерфейс передает без фрагментации.

Пример:

set interfaces vxlan vxlan0 mtu 1600
set interfaces vxlan <interface> ip adjust-mss <mss | clamp-mss-to-pmtu>

Настройте MSS , объявляемый в исходящих пакетах TCP SYN на указанном интерфейсе.

Путем ограничения значения MSS в пакетах TCP SYN, вы явно информируете удаленную сторону, что она не должна отправлять пакеты большего размера, чем этот. Это предотвращает проблемы с соединением, возникающие при неудачной проверке пути MTU (PMTUD).

Доступны следующие варианты:

  • mss: Устанавливает MSS в конкретное значение, в байтах. Используйте этот вариант, если необходимо принудительно установить конкретное значение MSS, например, для устранения проблем с подключением или соответствия специфическим требованиям сети.

  • clamp-mss-to-pmtu: Роутер автоматически рассчитывает MSS как MTU интерфейса минус 40 байтов для IPv4 (20 байтов для заголовка IPv4 и 20 байтов для заголовка TCP). Этот вариант рекомендуется для автоматического установления правильного значения.

set interfaces vxlan <interface> ip arp-cache-timeout

Настройте, как долго ARP-запись остается действительной после получения карты IP-адреса в MAC-адрес на этом интерфейсе.

По умолчанию длительность составляет 30 секунд.

ARP-запись остается действительной, если она получает положительный ответ от вышеуровневых протоколов.

Пример:

set interfaces vxlan vxlan0 ip arp-cache-timeout 180
set interfaces vxlan <interface> ip disable-arp-filter

Настройте фильтрацию ARP на этом интерфейсе.

Стандартное поведение: Ядро отвечает на запросы ARP на этом интерфейсе только в том случае, если трафик будет направлен обратно к отправителю ARP через этот конкретный интерфейс.

Если настроено: Ядро отвечает на запросы ARP на этом интерфейсе для любого IP-адреса, настроенного на локальном хосте, независимо от того, какой конкретный интерфейс этот IP-адрес назначен, и независимо от таблицы маршрутизации. Это отражает концепцию Linux, согласно которой IP-адреса принадлежат хосту, а не отдельным интерфейсам.

Пример:

set interfaces vxlan vxlan0 ip disable-arp-filter
set interfaces vxlan <interface> ip disable-forwarding

Настройте интерфейс на работу в режиме хоста или маршрутизатора.

Если настроено, интерфейс переключается в режим хоста, и IPv4-пересылка отключена на нем.

Пример:

set interfaces vxlan vxlan0 ip disable-forwarding
set interfaces vxlan <interface> ip enable-directed-broadcast

Настройте, будут ли передаваться пакеты IP-направленного вещания, полученные на этом интерфейсе.

Стандартное поведение: Пакеты IP-направленного вещания удаляются.

Если настроено: Пакеты IP-направленного вещания передаются всем хостам на целевом подсети, как определено в RFC 1812 и RFC 2644.

Пример:

set interfaces vxlan vxlan0 ip enable-directed-broadcast
set interfaces vxlan <interface> ip enable-arp-accept

Настройте, как обрабатывать бесплатные ARP на этом интерфейсе.

Если настроено, IP-адрес-MAC-адресная связь добавляется в таблицу ARP на основе бесплатных ARP-запросов или ответов.

Примечание

Если в таблице ARP уже есть IP-адрес из бесплатного ARP, его запись обновляется независимо от того, настроено ли это настройка.

Пример:

set interfaces vxlan vxlan0 ip enable-arp-accept
set interfaces vxlan <interface> ip enable-arp-announce

Настройте выбор источника IP-адреса для ARP-запросов на этом интерфейсе.

Стандартное поведение: Ядро может использовать любой IP-адрес, которым владеет хост, как источник IP-адреса в ARP-запросах на этом интерфейсе.

Если настроено: Ядро сначала пытается выбрать источник IP-адреса, настроенный на интерфейсе, который имеет общую подсеть с целевым IP-адресом. Если такой подсети нет, ядро выбирает IP-адрес, который обычно используется (на основе таблицы маршрутизации для достижения целевой цели).

Пример:

set interfaces vxlan vxlan0 ip enable-arp-announce
set interfaces vxlan <interface> ip enable-arp-ignore

Настройте, какие ARP-запросы будут игнорироваться на этом интерфейсе.

Стандартное поведение: Ядро отвечает на ARP-запросы для любых локальных IP-адресов, независимо от того, к какому интерфейсу они привязаны.

Если настроено: Ядро отвечает на ARP-запросы только в том случае, если целевой IP-адрес привязан к этому конкретному интерфейсу.

Пример:

set interfaces vxlan vxlan0 ip enable-arp-ignore
set interfaces vxlan <interface> ip enable-proxy-arp

Настройте прокси-ARP на этом интерфейсе.

Если настроено, маршрутизатор (ядро) перехватывает ARP-запросы для не-локальных IP-адресов и отвечает с MAC-адресом интерфейса, который получил запрос. Последующие пакеты, предназначенные этим IP-адресам, перенаправляются на их фактические цели на удаленных подсетях.

Пример:

set interfaces vxlan vxlan0 ip enable-proxy-arp
set interfaces vxlan <interface> ip proxy-arp-pvlan

Настройте локальный прокси-ARP на интерфейсе.

Если настроено, маршрутизатор (ядро) отвечает на ARP-запросы на этом VLAN-интерфейсе даже если целевой IP-адрес находится на той же подсети и интерфейсе.

Это используется для поддержки требований к изоляции сети (RFC 3069) для частных VLAN (PVLAN). В конфигурациях PVLAN устройства на изолированных портах НЕ разрешается прямая связь между собой на уровне 2, но они могут общаться с верхним маршрутизатором.

Посредством ответа на ARP-запросы между хостами своим собственным MAC-адресом, маршрутизатор (ядро) направляет трафик между хостами через себя вместо прямой передачи между хостами.

Примечание

Эта команда работает независимо и не требует включения стандартного прокси-ARP на интерфейсе.

Локальный прокси-ARP также известен как:

  • Агрегация VLAN (RFC 3069).

  • Частный VLAN (Cisco, Allied Telesyn).

  • Фильтрация по источнику или изоляция порта (Hewlett-Packard).

  • Перенаправление MAC-адреса (Ericsson).

set interfaces vxlan <interface> ip source-validation <strict | loose | disable>

Настройте проверку исходного IP-адреса с использованием RPF на этом интерфейсе, как указано в RFC 3704.

Доступны следующие варианты:

  • strict: Каждый входящий пакет проверяется на соответствие исходному IP-адресу в таблице информации о маршрутизации (FIB). Если интерфейс не является лучшим маршрутом обратно к этому источнику, проверка не проходит, и пакет удаляется.

  • loose: Каждый входящий пакет проверяется на соответствие исходному IP-адресу в таблице информации о маршрутизации (FIB). Если исходный IP-адрес недоступен через любой интерфейс, проверка не проходит.

  • disable: Не выполняется проверка исходного IP-адреса. Все входящие пакеты принимаются.

RFC 3704 рекомендует включить строгий режим для предотвращения подделки IP-адресов, например, DDoS-атак. Для асимметричных или других сложных сценариев маршрутизации используйте режим loose.

set interfaces vxlan <interface> ipv6 address autoconf

Настройте интерфейс на автоматическое получение IPv6-адреса с помощью SLAAC, как указано в RFC 4862.

Устройства IPv6 могут самостоятельно настраивать себя, когда подключены к сети IPv6, используя протокол обнаружения соседей через сообщения ICMPv6 о маршрутизаторе. При первом подключении к сети устройство отправляет многоадресный запрос на обнаружение маршрутизатора в локальной подсети для получения параметров своей конфигурации. Маршрутизатор отвечает пакетом объявлений маршрутизатора, содержащим параметры конфигурации уровня интернета.

Примечание

Этот метод автоматически отключает передачу IPv6 на интерфейсе.

Пример:

set interfaces vxlan vxlan0 ipv6 address autoconf
set interfaces vxlan <interface> ipv6 address eui64 <prefix>

Настройте интерфейс на присвоение себе IPv6-адреса с помощью метода EUI-64 , как указано в RFC 4291.

Пример:

set interfaces vxlan vxlan0 ipv6 address eui64 2001:db8:beef::/64
set interfaces vxlan <interface> ipv6 address no-default-link-local

Отключите автоматическое присвоение ссылочного IPv6-адреса этому интерфейсу.

Пример:

set interfaces vxlan vxlan0 ipv6 address no-default-link-local
set interfaces vxlan <interface> ipv6 disable-forwarding

Настройте интерфейс на работу в режиме хоста или маршрутизатора.

Если настроено, интерфейс переключается в режим хоста, и IPv6-пересылка отключена на нем.

Пример:

set interfaces vxlan vxlan0 ipv6 disable-forwarding
set interfaces vxlan <interface> ipv6 adjust-mss <mss | clamp-mss-to-pmtu>

Настройте MSS , объявляемый в исходящих пакетах TCP SYN на указанном интерфейсе.

Путем ограничения значения MSS в пакетах TCP SYN, вы явно информируете удаленную сторону, что она не должна отправлять пакеты большего размера, чем этот. Это предотвращает проблемы с соединением, возникающие при неудачной проверке пути MTU (PMTUD).

Доступны следующие варианты:

  • mss: Устанавливает MSS в конкретное значение, в байтах. Используйте этот вариант, чтобы принудительно установить конкретное значение MSS, например, для устранения проблем с подключением или соответствия специфическим требованиям сети.

  • clamp-mss-to-pmtu: Роутер рассчитывает MSS как MTU интерфейса минус 60 байтов для IPv6 (40 байтов для заголовка IPv6 и 20 байтов для заголовка TCP). Этот вариант рекомендуется для автоматического установления правильного значения.

set interfaces vxlan <interface> ipv6 accept-dad <0 | 1 | 2>

Настройте IPv6 DAD на интерфейсе.

Доступны следующие варианты:

  • 0: Отключает DAD. Не производится обнаружение дублирующих адресов.

  • 1: Включает DAD (по умолчанию). Обнаруживаются дублирующиеся адреса. Операция IPv6 интерфейса продолжается для действительных IPv6-адресов.

  • 2: Включает DAD и, если найден дублирующийся локальный адрес на основе MAC, отключает операцию IPv6 на этом интерфейсе.

Пример:

set interfaces vxlan vxlan0 ipv6 accept-dad 2
set interfaces vxlan <interface> ipv6 dup-addr-detect-transmits <n>

Настройте количество DAD сообщений, которые отправляет роутер (ядро) во время назначения IPv6-адреса на этом интерфейсе.

Значение по умолчанию равно 1.

Пример:

set interfaces vxlan vxlan0 ipv6 dup-addr-detect-transmits 5
set interfaces vxlan <interface> vrf <vrf>

Настройте VNI для интерфейса VXLAN.

Каждый сегмент VXLAN идентифицируется этим 24-битным VNI, позволяя до 16 миллионов сегментов существовать в одной административной области.

Хотя порт VXLAN, назначенный IANA, равен 4789, VyOS использует стандартный порт UDP Linux 8472 для интерфейсов VXLAN.

set interfaces vxlan <interface> source-address <address>

Настройте исходный IP-адрес для подстилающей сети VXLAN.

Предупреждение

Это настройка обязательна при развертывании VXLAN через L2VPN/EVPN.

set interfaces vxlan <interface> gpe

Включите GPE для интерфейса VXLAN.

Чтобы использовать эту функцию, вы должны настроить интерфейс с параметром external.

set interfaces vxlan <interface> parameters external

Настройте интерфейс VXLAN на использование внешней плоскости управления, такой как BGP L2VPN/EVPN, для обнаружения удаленных точек.

Если не настроено, используется внутренняя FDB.

set interfaces vxlan <interface> parameters neighbor-suppress

Включите подавление ARP и ND на интерфейсе VXLAN.

Это уменьшает распространение сообщений ARP и ND по сети VXLAN. Как определено в RFC 7432#section-10, участвующие VTEP используют известные связи MAC-адреса и IP для ответа на локальные запросы от удаленных хостов.

set interfaces vxlan <interface> parameters nolearning

Отключите обучение SLLA и IP-адреса на интерфейсе VXLAN.

set interfaces vxlan <interface> parameters vni-filter

Включите VNI фильтрации на интерфейсе VXLAN.

При включении интерфейс получает только пакеты с VNIs, настроенными в его таблице фильтрации VNI.

Примечание

VNI-фильтрация работает только если интерфейс настроен с параметром external.

Unicast

set interfaces vxlan <interface> remote <address>

Настройте IPv4 или IPv6-адрес удаленного VTEP.

В отличие от настроек multicast, эта команда позволяет напрямую настроить IPv4 или IPv6-адрес удаленного.

Multicast

set interfaces vxlan <interface> source-interface <interface>

Настройте источник интерфейса для подстилающей сети VXLAN.

Все трафик VXLAN отправляется и получается через указанный интерфейс. Эта настройка обязательна при развертывании VXLAN над сетью multicast.

set interfaces vxlan <interface> group <address>

Настройте IPv4 или IPv6-адрес многоадресной группы для интерфейса VXLAN.

Туннели VXLAN могут быть построены с использованием многоадресной группы или одиночных IP-адресов.

Multicast VXLAN

Топология: PC4 - Leaf2 - Spine1 - Leaf3 - PC5

PC4 использует IP-адрес 10.0.0.4/24, а PC5 использует IP-адрес 10.0.0.5/24. Оба устройства предполагают, что находятся в одной широковещательной домене.

Предположим, что PC4 на Leaf2 пингует PC5 на Leaf3. Вместо того, чтобы вручную указать Leaf3 как удаленную точку, Leaf2 инкапсулирует пакет в датаграмму UDP и отправляет его в заданный многоадресный адрес через Spine1. Spine1 пересылает пакет всем листьям в той же многоадресной группе, включая Leaf3. После получения датаграммы, Leaf3 пересылает ее PC5 и узнает, что PC4 доступен через Leaf2, анализируя исходный IP-адрес в инкапсулированной датаграмме.

PC5 получает пинг и отвечает эхо-ответом. Leaf3, теперь знающий расположение PC4, пересылает ответ напрямую к одиночному адресу Leaf2. Получив эхо-ответ, Leaf2 узнает, что PC5 доступен через Leaf3.

После этого, последующий трафик между PC4 и PC5 не будет использовать многоадресный адрес между листьями, так как оба листа узнали расположение компьютеров. Это уменьшает многоадресный трафик и нагрузку на сеть, повышая масштабируемость при добавлении большего количества листьев.

Одиночное устройство VXLAN (SVD)

В VyOS вы можете настроить несколько карт VLAN-к-VNI для EVPN-VXLAN на одном контейнерном интерфейсе, известном как одиночное устройство VXLAN (SVD). Это позволяет значительному масштабированию VNI, поскольку для каждого VNI не требуется отдельный интерфейс VXLAN.

set interfaces vxlan <interface> vlan-to-vni <vlan> vni <vni>

Сопоставьте VLAN ID с VNI на указанном интерфейсе VXLAN.

Интерфейс VXLAN может быть добавлен в мост.

В следующем примере показана конфигурация SVD с несколькими картами VLAN-к-VNI.

set interfaces bridge br0 member interface vxlan0
set interfaces vxlan vxlan0 parameters external
set interfaces vxlan vxlan0 source-interface 'dum0'
set interfaces vxlan vxlan0 vlan-to-vni 10 vni '10010'
set interfaces vxlan vxlan0 vlan-to-vni 11 vni '10011'
set interfaces vxlan vxlan0 vlan-to-vni 30 vni '10030'
set interfaces vxlan vxlan0 vlan-to-vni 31 vni '10031'

Конфигурации Leaf2 и Leaf3 почти одинаковые. Подробные объяснения каждой команды приведены ниже.

set interfaces bridge br241 address '172.16.241.1/24'

Эта команда создает мост для связывания трафика на eth1 VLAN 241 с vxlan241 интерфейсом. IP-адрес является необязательным. Если настроен, он может служить шлюзом по умолчанию для каждого листа, позволяя устройствам на VLAN достигать других подсетей. Подсети должны быть рекламированы OSPF, чтобы спайн мог узнать, как к ним попасть. Чтобы рекламировать 172.16/12 сети, измените OSPF сеть с 10.0.0.0/8 на 0.0.0.0/0.

set interfaces bridge br241 member interface 'eth1.241'
set interfaces bridge br241 member interface 'vxlan241'

Эти команды связывают eth1.241 и vxlan241 как члены интерфейса одного моста.

set interfaces vxlan vxlan241 group '239.0.0.241'

Эта команда настраивает многоадресную группу, используемую всеми листьями для расширения VLAN. Он должен быть таким же на всех листьях, имеющих этот интерфейс.

set interfaces vxlan vxlan241 source-interface 'eth0'

Эта команда настраивает интерфейс, который слушает многоадресные пакеты. Это может быть также интерфейс loopback.

set interfaces vxlan vxlan241 vni '241'

Эта команда настраивает уникальный идентификатор для интерфейса VXLAN.

set interfaces vxlan vxlan241 port 12345

VyOS использует стандартный порт UDP Linux 8472 для интерфейсов VXLAN. Эта команда позволяет настроить другой порт UDP.

Unicast VXLAN

В качестве альтернативы multicast вы можете настроить туннель VXLAN, указав удаленный IPv4-адрес напрямую. Ниже приведена обновленная версия предыдущего примера multicast:

# leaf2 и leaf3
delete interfaces vxlan vxlan241 group '239.0.0.241'
delete interfaces vxlan vxlan241 source-interface 'eth0'

# leaf2
set interfaces vxlan vxlan241 remote 10.1.3.3

# leaf3
set interfaces vxlan vxlan241 remote 10.1.2.2

Порт UDP по умолчанию — 8472. Чтобы настроить другой порт, используйте set interfaces vxlan <vxlanN> port <port>.
