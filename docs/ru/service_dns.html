Перенаправление DNS

VyOS предоставляет инфраструктуру DNS для небольших сетей, предназначенную для легкого использования и подходящую для ресурсоограниченных маршрутизаторов и межсетевых экранов.

Подключенные клиенты обслуживаются через службу перенаправления DNS, настроенную под service dns forwarding. Она может либо перенаправлять запросы на настраиваемые серверы верхнего уровня DNS, либо работать как полный рекурсивный сервер DNS без необходимости наличия серверов верхнего уровня. Работа без серверов верхнего уровня избегает экспозиции запросов клиентов оператору DNS верхнего уровня.

Конфигурация

Примечание

Конфигурация перенаправления DNS может быть сохранена только в том случае, если оба listen-address и allow-from установлены. В противном случае, сохранение не удастся.

Прослушиватель

set service dns forwarding listen-address <address>

Настройте локальный IPv4 или IPv6 адрес, на котором DNS-перенаправление слушает входящие запросы.

Адрес должен уже быть назначен локальной интерфейс. Повторите команду, чтобы настроить несколько адресов прослушивания. Для успешного сохранения требуется хотя бы один listen-address.

Пример:

set service dns forwarding listen-address 192.0.2.1
set service dns forwarding listen-address 2001:db8::1
set service dns forwarding port <1-65535>

Настройте порт, на котором DNS-перенаправление слушает входящие запросы.

По умолчанию — 53.

Пример:

set service dns forwarding port 5353
set service dns forwarding allow-from <prefix>

Ограничьте входящие запросы клиентами, чей IP-адрес находится в указанном IPv4 или IPv6 префиксе.

Повторите команду, чтобы разрешить несколько префиксов. Для успешного сохранения требуется хотя бы один префикс.

Примечание

Ограничьте allow-from доверенными сетями. Не используйте 0.0.0.0/0 или ::/0, если сервис доступен из интернета.

Пример:

set service dns forwarding allow-from 192.0.2.0/24
set service dns forwarding allow-from 2001:db8::/32
set service dns forwarding exclude-throttle-address <address>

Исключите из торможения авторитетные серверы, совпадающие с указанным IPv4 или IPv6 адресом или префиксом.

DNS-перенаправление тормозит авторитетные серверы, которые не отвечают на запрос или возвращают ответы, которые DNS-перенаправление отклоняет. Эта команда исключает указанные адреса из торможения. Повторите команду, чтобы добавить несколько адресов.

Пример:

set service dns forwarding exclude-throttle-address 192.0.2.53
set service dns forwarding exclude-throttle-address 2001:db8::53

Перенаправление вверх

set service dns forwarding name-server <address>

Перенаправляйте запросы на указанный IPv4 или IPv6 сервер верхнего уровня DNS.

Серверы верхнего уровня настраиваются напрямую под DNS-перенаправлением. Повторите команду, чтобы настроить несколько серверов верхнего уровня.

Пример:

set service dns forwarding name-server 192.0.2.53
set service dns forwarding name-server 2001:db8::53
set service dns forwarding name-server <address> port <1-65535>

Настройте порт назначения, используемый при перенаправлении запросов на указанный сервер верхнего уровня DNS.

По умолчанию — 53.

Пример:

set service dns forwarding name-server 192.0.2.53 port 853
set service dns forwarding system

Перенаправляйте запросы на серверы верхнего уровня, настроенные под system name-server.

Серверы верхнего уровня наследуются от system name-server.

Пример:

set service dns forwarding system
set service dns forwarding dhcp <interface>

Перенаправляйте запросы на серверы DNS, полученные через клиент DHCPv4 или DHCPv6 на указанной интерфейсе.

Повторите команду, чтобы перенаправлять запросы на серверы, полученные через DHCP, с нескольких интерфейсов.

Пример:

set service dns forwarding dhcp eth0
set service dns forwarding source-address <address>

Настройте локальный IPv4 или IPv6 адрес, используемый как источник при отправке исходящих запросов DNS-перенаправлением.

По умолчанию — 0.0.0.0 и ::, что означает, что адрес источника выбирается для каждого исходящего запроса. Повторите команду, чтобы настроить несколько адресов источника.

Пример:

set service dns forwarding source-address 192.0.2.1
set service dns forwarding source-address 2001:db8::1
set service dns forwarding no-serve-rfc1918

Отключите авторитетный ответ на запросы для 10.in-addr.arpa, 168.192.in-addr.arpa и 16-31.172.in-addr.arpa зон.

Это обратные зоны для приватных диапазонов RFC 1918. Запросы для этих зон затем перенаправляются на настроенные серверы верхнего уровня.

Пример:

set service dns forwarding no-serve-rfc1918
set service dns forwarding ignore-hosts-file

Не используйте локальный файл /etc/hosts при разрешении имен.

По умолчанию DNS-перенаправление отвечает на запросы, используя /etc/hosts перед рекурсией или перенаправлением.

Пример:

set service dns forwarding ignore-hosts-file

Кэш и таймеры

set service dns forwarding cache-size <0-2147483647>

Настройте максимальное количество записей кэша DNS.

По умолчанию — 10000. Значение 0 отключает кэш.

Пример:

set service dns forwarding cache-size 1000000
set service dns forwarding negative-ttl <0-7200>

Настройте максимальное время, в секундах, в течение которого отрицательные ответы (NXDOMAIN и NODATA) хранятся в кэше.

По умолчанию — 3600.

Пример:

set service dns forwarding negative-ttl 60
set service dns forwarding minimum-ttl-override <0-2147483647>

Настройте минимальное значение TTL, в секундах, применяемое к кэшированным записям независимо от TTL, полученного от авторитетного сервера.

Записи с TTL ниже этого значения кэшируются с этим минимальным TTL. По умолчанию — 1.

Примечание

Изменяйте это значение только в том случае, если у вас есть конкретная причина увеличить короткие TTL, так как более высокие значения расширяют кэширование за пределами авторитетного TTL. Если запись изменится на стороне сервера, клиенты получат устаревшее значение кэша, пока не истечет время переопределения.

Пример:

set service dns forwarding minimum-ttl-override 30
set service dns forwarding timeout <10-60000>

Настройте время, в миллисекундах, которое DNS-перенаправление ждет ответа от удаленного авторитетного сервера на исходящий запрос.

По умолчанию — 1500.

Пример:

set service dns forwarding timeout 2000
set service dns forwarding ttl-percent <0-100>

Обновляйте кэшированные записи в фоновом режиме, когда оставшееся время TTL падает ниже этого процента от оригинального TTL.

Клиенты продолжают получать существующий ответ из кэша во время обновления. По умолчанию — 0, что отключает фоновое обновление.

Пример:

set service dns forwarding ttl-percent 10
set service dns forwarding serve-stale-extension <0-65535>

Настройте, сколько раз TTL истекшей записи можно продлить на 30 секунд, когда запись не может быть обновлена.

По умолчанию — 0, что отключает обслуживание устаревших записей.

Пример:

set service dns forwarding serve-stale-extension 30

DNSSEC и поведение NXDOMAIN

set service dns forwarding dnssec <off | process-no-validate | process | log-fail | validate>

Настройте режим обработки DNSSEC для исходящих запросов и ответов:

  • off: Нет обработки DNSSEC. Биты DO в запросах клиентов игнорируются, и не запрашиваются записи DNSSEC от авторитетных серверов.

  • process-no-validate: Возвращает записи DNSSEC (RRSIG, NSEC) клиентам, которые их запрашивают, но не проверяет.

  • process: Проверяет ответы только тогда, когда клиент запрашивает это (бит DO или AD). Возвращает SERVFAIL на поддельные данные.

  • log-fail: Проверяет все ответы независимо от запроса клиента, логирует поддельные ответы, но возвращает те же ответы, что и в режиме process.

  • validate: Проверяет все ответы и возвращает SERVFAIL на поддельные данные независимо от запроса клиента.

По умолчанию — process-no-validate.

Пример:

set service dns forwarding dnssec validate
set service dns forwarding nothing-below-nxdomain <no | dnssec | yes>

Настройте, как DNS-перенаправление обрабатывает вырезку NXDOMAIN.

Когда DNS-перенаправление имеет кэшированный NXDOMAIN, оно также может вернуть NXDOMAIN для любого имени ниже запрещенного имени, не спрашивая у верхнего уровня. Это настройка контролирует, когда это поведение применяется:

  • no: никогда не применять вырезку NXDOMAIN.

  • dnssec: применять вырезку NXDOMAIN только для проверенных DNSSEC NXDOMAIN записей.

  • yes: применять вырезку NXDOMAIN для любого кэшированного NXDOMAIN, который не является поддельным.

По умолчанию — dnssec.

Пример:

set service dns forwarding nothing-below-nxdomain yes

DNS64

set service dns forwarding dns64-prefix <prefix>

Синтезировать AAAA-записи из A-записей для имен, которые не имеют AAAA-записей, используя указанный префикс NAT64 IPv6.

Длина префикса должна быть точно /96.

Пример:

set service dns forwarding dns64-prefix 2001:db8:64::/96

EDNS Клиентский Подсет

set service dns forwarding options ecs-add-for <prefix>

Настройте, какой адрес клиента отправляется как значение ECS в исходящих запросах.

Для клиентов, чей адрес соответствует указанному префиксу, отправляется реальный адрес клиента. Для клиентов, не соответствующих префиксу, отправляется заменяющий адрес, чтобы не было экспозиции подсети клиента.

ECS отправляется только для запросов, соответствующих edns-subnet-allow-list. Эта опция контролирует только значение, а не то, отправляется ли ECS.

Добавьте ! перед префиксом, чтобы исключить его. Повторите команду для нескольких записей.

Пример:

set service dns forwarding options ecs-add-for 192.0.2.0/24
set service dns forwarding options ecs-add-for !192.0.2.128/25
set service dns forwarding options ecs-ipv4-bits <0-32>

Настройте количество битов IPv4-адреса клиента, включаемых в параметр ECS, отправляемый авторитетным серверам.

Применяется только к запросам, для которых отправляется ECS (те, которые соответствуют edns-subnet-allow-list).

Пример:

set service dns forwarding options ecs-ipv4-bits 24
set service dns forwarding options edns-subnet-allow-list <value>

Включить ECS в исходящих запросах, когда адрес сервера назначения находится в указанной маске сети, или когда имя запроса находится под указанным доменом.

Повторите команду, чтобы добавить несколько записей.

Пример:

set service dns forwarding options edns-subnet-allow-list example.com
set service dns forwarding options edns-subnet-allow-list 192.0.2.0/24

Перенаправление по домену

set service dns forwarding domain <domain-name> name-server <address>

Перенаправляйте запросы для указанного домена на указанный IPv4 или IPv6 сервер верхнего уровня DNS.

Повторите команду, чтобы настроить несколько серверов имен для одного и того же домена. Используйте эту опцию для реализации разделения зон DNS. Домен также может быть обратной зоной, такой как 2.0.192.in-addr.arpa.

Пример:

set service dns forwarding domain example.com name-server 192.0.2.53
set service dns forwarding domain example.com name-server 2001:db8::53
set service dns forwarding domain <domain-name> name-server <address> port <1-65535>

Настройте порт на указанном сервере верхнего уровня DNS, на который перенаправляются запросы для указанного домена.

По умолчанию — 53.

Пример:

set service dns forwarding domain example.com name-server 192.0.2.53 port 853
set service dns forwarding domain <domain-name> addnta

Настройте указанный домен как NTA, отключив проверку DNSSEC для него.

Настройте это, когда запросы для домена с поврежденным DNSSEC возвращают SERVFAIL, чтобы домен снова стал доступным.

Пример:

set service dns forwarding domain example.com addnta
set service dns forwarding domain <domain-name> recursion-desired

Установите бит RD в запросах, отправляемых на сервер верхнего уровня для этого домена.

Пример:

set service dns forwarding domain example.com recursion-desired

Авторитетные зоны

DNS-перенаправление может содержать авторитетные записи для домена, отвечая напрямую вместо перенаправления или рекурсии запросов.

set service dns forwarding authoritative-domain <domain-name> disable

Предотвратить обслуживание указанной авторитетной зоны DNS-перенаправлением, не удаляя ее из конфигурации.

Запросы для имен в зоне перенаправляются или рекурсируются вместо этого.

Пример:

set service dns forwarding authoritative-domain example.com disable
set service dns forwarding authoritative-domain <domain-name> records <type> <name> disable

Предотвратить обслуживание определенной записи в авторитетной зоне, не удаляя ее из конфигурации.

Запросы, соответствующие записи, перенаправляются или рекурсируются вместо этого.

Пример:

set service dns forwarding authoritative-domain example.com records a www disable
set service dns forwarding authoritative-domain <domain-name> records <type> <name> ttl <0-2147483647>

Настройте TTL, в секундах, для указанной записи.

По умолчанию — 300.

Пример:

set service dns forwarding authoritative-domain example.com records a www ttl 600

Типы записей

Команды типа записи в этом разделе принимают следующие ключевые слова имен записей:

  • @: Представляет вершину зоны, например, example.com. Принимается каждым типом записи.

  • any: Представляет шаблонную запись, например, *.example.com, которая совпадает со всеми поддоменами под вершиной. Принимается только для записей a и aaaa.

set service dns forwarding authoritative-domain <domain-name> records a <name> address <ipv4-address>

Настройте запись A в указанной авторитетной зоне.

Поддерживает @ и any как <name>. Повторите команду, чтобы добавить несколько IPv4 адресов в одну запись.

Пример:

set service dns forwarding authoritative-domain example.com records a www address 192.0.2.10
set service dns forwarding authoritative-domain <domain-name> records aaaa <name> address <ipv6-address>

Настройте запись AAAA в указанной авторитетной зоне.

Поддерживает @ и any как <name>. Повторите команду, чтобы добавить несколько IPv6 адресов в одну запись.

Пример:

set service dns forwarding authoritative-domain example.com records aaaa www address 2001:db8::10
set service dns forwarding authoritative-domain <domain-name> records cname <name> target <target-domain-name>

Настройте запись CNAME в указанной авторитетной зоне.

Поддерживает @ как <name>.

Пример:

set service dns forwarding authoritative-domain example.com records cname www target host.example.com
set service dns forwarding authoritative-domain <domain-name> records mx <name> server <server>

Настройте запись MX в указанной авторитетной зоне.

Поддерживает @ как <name>. Повторите команду, чтобы добавить несколько почтовых серверов в одну запись.

Пример:

set service dns forwarding authoritative-domain example.com records mx @ server mail.example.com
set service dns forwarding authoritative-domain <domain-name> records mx <name> server <server> priority <1-999>

Настройте приоритет указанной записи MX.

Меньшие значения предпочтительнее. По умолчанию — 10.

Пример:

set service dns forwarding authoritative-domain example.com records mx @ server mail.example.com priority 20
set service dns forwarding authoritative-domain <domain-name> records ns <name> target <target-name>

Настройте запись NS в указанной авторитетной зоне.

Поддерживает @ как <name>. Повторите команду, чтобы добавить несколько серверов имен в одну запись.

Пример:

set service dns forwarding authoritative-domain example.com records ns @ target ns1.example.com
set service dns forwarding authoritative-domain <domain-name> records ptr <name> target <target-name>

Настройте запись PTR в указанной авторитетной зоне.

Поддерживает @ как <name>.

Пример:

set service dns forwarding authoritative-domain 2.0.192.in-addr.arpa records ptr 10 target host.example.com
set service dns forwarding authoritative-domain <domain-name> records txt <name> value <value>

Настройте запись TXT в указанной авторитетной зоне.

Поддерживает @ как <name>. Повторите команду, чтобы добавить несколько строк TXT в одну запись.

Пример:

set service dns forwarding authoritative-domain example.com records txt @ value 'v=spf1 -all'
set service dns forwarding authoritative-domain <domain-name> records spf <name> value <value>

Настройте запись SPF в указанной авторитетной зоне.

Поддерживает @ как <name>.

Примечание

Записи SPF устарели в пользу записей TXT. Предпочитайте TXT-записи для новых развертываний.

Пример:

set service dns forwarding authoritative-domain example.com records spf @ value 'v=spf1 -all'
set service dns forwarding authoritative-domain <domain-name> records srv <name> entry <0-65535> hostname <name>

Настройте целевой хост записи SRV в указанной авторитетной зоне.

Поддерживает @ как <name>.

Пример:

set service dns forwarding authoritative-domain example.com records srv _sip._tcp entry 0 hostname sip.example.com
set service dns forwarding authoritative-domain <domain-name> records srv <name> entry <0-65535> port <0-65535>

Настройте порт записи SRV в указанной авторитетной зоне.

Пример:

set service dns forwarding authoritative-domain example.com records srv _sip._tcp entry 0 port 5060
set service dns forwarding authoritative-domain <domain-name> records srv <name> entry <0-65535> priority <0-65535>

Настройте приоритет записи SRV в указанной авторитетной зоне.

Меньшие значения предпочтительнее. По умолчанию — 10.

Пример:

set service dns forwarding authoritative-domain example.com records srv _sip._tcp entry 0 priority 20
set service dns forwarding authoritative-domain <domain-name> records srv <name> entry <0-65535> weight <0-65535>

Настройте вес записи SRV в указанной авторитетной зоне.

Вес используется для распределения нагрузки между записями с одинаковым приоритетом. По умолчанию — 0.

Пример:

set service dns forwarding authoritative-domain example.com records srv _sip._tcp entry 0 weight 50
set service dns forwarding authoritative-domain <domain-name> records naptr <name> rule <0-65535> order <0-65535>

Настройте поле порядка правила NAPTR в указанной авторитетной зоне.

Поддерживает @ как <name>. Правила с меньшим порядком оцениваются первыми.

Пример:

set service dns forwarding authoritative-domain example.com records naptr @ rule 100 order 10
set service dns forwarding authoritative-domain <domain-name> records naptr <name> rule <0-65535> preference <0-65535>

Настройте поле предпочтения правила NAPTR в указанной авторитетной зоне.

Поддерживает @ как <name>. По умолчанию — 0.

Пример:

set service dns forwarding authoritative-domain example.com records naptr @ rule 100 preference 50
set service dns forwarding authoritative-domain <domain-name> records naptr <name> rule <0-65535> lookup-a

Установите флаг A в правиле NAPTR в указанной авторитетной зоне.

Когда установлено, DNS-перенаправление рассматривает вывод правила как доменное имя и ищет его A или AAAA-запись. Дальнейших NAPTR-поисков не происходит.

Примечание

Установите не более одного из lookup-a, lookup-srv, resolve-uri и protocol-specific на одном правиле NAPTR. Эти флаги определяют взаимно исключающие действия в процессе разрешения DNS.

Пример:

set service dns forwarding authoritative-domain example.com records naptr @ rule 100 lookup-a
set service dns forwarding authoritative-domain <domain-name> records naptr <name> rule <0-65535> lookup-srv

Установите флаг S в правиле NAPTR в указанной авторитетной зоне.

Когда установлено, DNS-перенаправление рассматривает вывод правила как доменное имя и ищет его SRV-запись. Дальнейших NAPTR-поисков не происходит.

Пример:

set service dns forwarding authoritative-domain example.com records naptr @ rule 100 lookup-srv
set service dns forwarding authoritative-domain <domain-name> records naptr <name> rule <0-65535> resolve-uri

Установите флаг U в правиле NAPTR в указанной авторитетной зоне.

Когда установлено, DNS-перенаправление рассматривает вывод правила как URI и использует его напрямую. Дальнейших DNS-поисков не происходит.

Пример:

set service dns forwarding authoritative-domain example.com records naptr @ rule 100 resolve-uri
