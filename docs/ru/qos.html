Политика трафика

QoS

Общее название Quality of Service или Control трафика включает в себя такие вещи, как формирование трафика, расписание или удаление пакетов, что является тем, с чем вы можете играть, когда у вас, например, есть ограничение пропускной способности на линии и вы хотите как-то приоритизировать определенный тип трафика по сравнению с другим.

tc — мощный инструмент для контроля трафика, находящийся в ядре Linux. Однако его настройка часто считается сложной задачей. К счастью, VyOS облегчает работу через свою CLI, используя tc как задний план.

Как это работает

Чтобы иметь работающую политику контроля трафика VyOS, вам нужно выполнить 2 шага:

  1. Создайте политику трафика.

  2. Примените политику трафика к интерфейсу входящего или исходящего потока.

Но прежде чем учиться настраивать вашу политику, мы предупредим вас о различных единицах, которые вы можете использовать, а также покажем, что такое классы, и как они работают, так как некоторые политики могут потребовать от вас настройки их.

Единицы

При настройке вашей политики трафика, вам придется устанавливать значения скорости передачи данных, обратите внимание на единицы, которые вы управляете, легко запутаться с разными префиксами и суффиксами, которые вы можете использовать. VyOS всегда покажет вам различные единицы, которые вы можете использовать.

Классы

В разделе Создание политики трафика вы увидите, что некоторые из политик используют классы. Эти политики позволяют распределять трафик по разным классам в зависимости от различных параметров, которые вы можете выбрать. Таким образом, класс — это просто определенный тип трафика, который вы выбираете.

Конечная цель классификации трафика — дать каждому классу разное обращение.

Сопоставление трафика

Чтобы определить, какой трафик попадает в какой класс, вы определяете фильтры (то есть критерии сопоставления). Пакеты проходят через эти правила сопоставления (как в правилах брандмауэра) и, если пакет соответствует фильтру, он присваивается этому классу.

В VyOS класс идентифицируется числом, которое вы можете выбрать при настройке.

Примечание

Значение идентификатора класса не одинаково для каждой политики. Обычно политики просто нуждаются в бесполезном числе для идентификации класса (ID класса), но это не относится ко всем политикам. Число класса в очереди приоритета не только идентифицирует его, но и определяет его приоритет.

set qos policy <policy> <policy-name> class <class-ID> match <class-matching-rule-name>

В команде выше мы устанавливаем тип политики, с которой мы собираемся работать, и имя, которое мы выбрали для нее; класс (чтобы различать некоторый трафик) и уникальное число для этого класса; затем мы настраиваем правило сопоставления (или фильтр) и имя для него.

Класс может иметь несколько правил сопоставления:

set qos policy shaper MY-SHAPER class 30 match HTTP
set qos policy shaper MY-SHAPER class 30 match HTTPs

Правило сопоставления может содержать несколько критериев и будет сопоставлять трафик, если все эти критерии истинны.

Например:

set qos policy shaper MY-SHAPER class 30 match HTTP ip protocol tcp
set qos policy shaper MY-SHAPER class 30 match HTTP ip source port 80

Это будет сопоставлять TCP-трафик с исходным портом 80.

Есть много параметров, которыми вы сможете воспользоваться, чтобы сопоставить трафик, который вы хотите для класса:

  • Ethernet (протокол, адрес назначения или источник)

  • Имя интерфейса

  • IPv4 (значение DSCP, максимальная длина пакета, протокол, адрес источника, адрес назначения, порт источника, порт назначения или флаги TCP)

  • IPv6 (значение DSCP, максимальная длина заголовка, протокол, адрес источника, адрес назначения, порт источника, порт назначения или флаги TCP)

  • Маркер брандмауэра

  • ID VLAN

При настройке вашего фильтра вы можете использовать клавишу Tab, чтобы увидеть множество различных параметров, которые вы можете настроить.

vyos@vyos# set qos policy shaper MY-SHAPER class 30 match MY-FIRST-FILTER 
Possible completions:
   description  Description
 > ether        Ethernet header match
   interface    Interface to use
 > ip           Match IP protocol header
 > ipv6         Match IPV6 protocol header
   mark         Match on mark applied by firewall
   vif          Virtual Local Area Network (VLAN) ID for this match

Как показано в приведенном выше примере, одним из возможных способов сопоставления пакетов является использование марок, сделанных брандмауэром, что может дать вам большое количество гибкости.

Вы также можете написать описание для фильтра:

set qos policy shaper MY-SHAPER class 30 match MY-FIRST-FILTER description "My filter description"

Примечание

IPv4 TCP-фильтр будет сопоставлять только пакеты с длиной заголовка IPv4 20 байт (что является большинством пакетов IPv4 в любом случае).

Примечание

IPv6 TCP-фильтры будут сопоставлять только пакеты IPv6 без расширений заголовка, см. https://en.wikipedia.org/wiki/IPv6_packet#Extension_headers

Группа сопоставления трафика

В некоторых случаях, когда нам нужно организовать наш выбор сопоставления, чтобы быть более гибким и организовать с нашим определением фильтра. Мы можем применять группы сопоставления трафика, позволяя создавать отдельные группы фильтров внутри нашей политики и определять различные параметры для каждой группы:

set qos traffic-match-group <group_name> match <match_name>
Possible completions:
   description          Description
 > ip                   Match IP protocol header
 > ipv6                 Match IPv6 protocol header
   mark                 Match on mark applied by firewall
   vif                  Virtual Local Area Network (VLAN) ID for this match

наследовать совпадения из другой группы

set qos traffic-match-group <group_name> match-group <match_group_name>

Группа совпадений может содержать несколько критериев и наследовать их в той же политике.

Например:

set qos traffic-match-group Mission-Critical match AF31 ip dscp 'AF31'
set qos traffic-match-group Mission-Critical match AF32 ip dscp 'AF42'
set qos traffic-match-group Mission-Critical match CS3 ip dscp 'CS3'
set qos traffic-match-group Streaming-Video match AF11 ip dscp 'AF11'
set qos traffic-match-group Streaming-Video match AF41 ip dscp 'AF41'
set qos traffic-match-group Streaming-Video match AF43 ip dscp 'AF43'
set qos policy shaper VyOS-HTB class 10 bandwidth '30%'
set qos policy shaper VyOS-HTB class 10 description 'Multimedia'
set qos policy shaper VyOS-HTB class 10 match CS4 ip dscp 'CS4'
set qos policy shaper VyOS-HTB class 10 match-group 'Streaming-Video'
set qos policy shaper VyOS-HTB class 10 priority '1'
set qos policy shaper VyOS-HTB class 10 queue-type 'fair-queue'
set qos policy shaper VyOS-HTB class 20 description 'MC'
set qos policy shaper VyOS-HTB class 20 match-group 'Mission-Critical'
set qos policy shaper VyOS-HTB class 20 priority '2'
set qos policy shaper VyOS-HTB class 20 queue-type 'fair-queue'
set qos policy shaper VyOS-HTB default bandwidth '20%'
set qos policy shaper VyOS-HTB default queue-type 'fq-codel'

В этом примере мы можем увидеть, что разные критерии DSCP определяются на основе нашей конфигурации QoS внутри одной группы политики.

По умолчанию

Часто вам также придется настраивать ваш по умолчанию трафик таким же образом, как и класс. По умолчанию можно рассматривать как класс, так как он ведет себя как такой. Он содержит любой трафик, который не соответствовал ни одному из определенных классов, поэтому это как открытый класс, класс без правил сопоставления.

Обработка класса

Как только класс имеет настроенное правило сопоставления, вы также должны определить, что вы хотите сделать с трафиком этого класса, какую конкретную обработку трафика вы хотите предоставить. Вы будете иметь разные возможности в зависимости от политики трафика, которую вы настраиваете.

vyos@vyos# set qos policy shaper MY-SHAPER class 30
Possible completions:
   bandwidth    Available bandwidth for this policy (default: auto)
   burst        Burst size for this class (default: 15k)
   ceiling      Bandwidth limit for this class
   codel-quantum
                Deficit in the fair queuing algorithm (default 1514)
   description  Description
   flows        Number of flows into which the incoming packets are classified(default 1024)
   interval     Interval used to measure the delay (default 100)
+> match        Class matching rule name
   priority     Priority for rule evaluation

   queue-type   Queue type for default traffic (default: fq-codel)

Вложение одной политики в другую

Часто нам нужно вложить одну политику в другую. Это возможно сделать на классовых политиках, прикрепляя новую политику к классу. Например, вы можете хотеть применить разные политики к разным классам конфигурированной политики Round-Robin.

Обычный пример — это случай, когда некоторые политики, чтобы быть эффективными, необходимо применить к интерфейсу, который непосредственно подключен, где находится узкое место. Если ваш роутер не подключен напрямую к узкому месту, но находится на одном хопе до него, вы можете имитировать узкое место, вложив вашу политику без формирования в классовую политику формирования, чтобы она вступила в силу.

Вы можете настроить политику в классе через настройку queue-type.

set qos policy shaper FQ-SHAPER bandwidth 4gbit
set qos policy shaper FQ-SHAPER default bandwidth 100%
set qos policy shaper FQ-SHAPER default queue-type fq-codel

Как показано в последней команде примера выше, настройка queue-type позволяет эти комбинации. Вы сможете использовать ее во многих политиках.

Примечание

Некоторые политики уже включают другие встроенные политики внутри. Это случай Shaper: каждый из его классов использует fair-queue, если вы не измените его.

Создание политики трафика

VyOS позволяет контролировать трафик многими различными способами, здесь мы рассмотрим каждую возможность. Вы можете настроить столько политик, сколько хотите, но вы сможете применить только одну политику на интерфейс и направление (входящий или исходящий).

Некоторые политики можно комбинировать, вы сможете вложить другую политику, которая будет применена к классу основной политики.

Подсказка

Если вы ищете политику для своего исходящего трафика но вы не знаете, какую именно вам нужно, и не хотите проходить через каждую возможную политику, показанную здесь, наше предположение, что вы, вероятно, ищете Политика формирования и хотите настроить очереди как FQ-CoDel.

Drop Tail

Дисциплина очереди: PFIFO (Пакет Первым Пришел, Первым Ушел).
Применяется к: Исходящий трафик.

Это самый простой способ применения к вашему трафику. Трафик должен пройти через конечную очередь перед тем, как будет отправлен. Вам нужно определить, сколько пакетов может содержать эта очередь.

Когда пакет должен быть отправлен, он должен пройти через эту очередь, поэтому пакет будет помещен в хвост. Когда пакет полностью пройдет через нее, он будет удален, освободив место в очереди и в конечном итоге будет передан NIC для фактической отправки.

Несмотря на то, что политика Drop-Tail не замедляет пакеты, если много пакетов должно быть отправлено, они могут быть отброшены при попытке добавить их в хвост. Это может произойти, если очередь еще не смогла освободить достаточно пакетов с головы.

Это политика, которая требует наименьших ресурсов для одного и того же объема трафика. Но очень вероятно, что вам не нужно это, так как вы не получите много от этого. Иногда он используется просто для включения журналирования.

set qos policy drop-tail <policy-name> queue-limit <number-of-packets>

Используйте эту команду для настройки политики Drop-Tail (PFIFO). Выберите уникальное имя для этой политики и размер очереди, установив количество пакетов, которые она может содержать (максимум 4294967295).

Fair Queue

Дисциплина очереди: SFQ (Случайная справедливая очередь).
Применяется к: Исходящий трафик.

Fair Queue — это работающее распределение, которое распределяет передачу пакетов на основе потоков, то есть балансирует трафик, распределяя его через различные подочереди, чтобы обеспечить справедливость, так что каждый поток может отправлять данные по очереди, предотвращая любую единственную, которая затопит остальные.

set qos policy fair-queue <policy-name>

Используйте эту команду для создания политики Fair-Queue и присвойте ей имя. Она основана на Случайной справедливой очереди и может быть применена к исходящему трафику.

Чтобы разделить трафик, Fair Queue использует классификатор на основе адреса источника, адреса назначения и порта источника. Алгоритм помещает пакеты в хэш-буфера на основе этих трех параметров. Каждый из этих буферов должен представлять уникальный поток. Поскольку несколько потоков могут быть хэшированы в один и тот же буфер, алгоритм хэширования пертурбируется в настраиваемые интервалы, так что несправедливость длится только короткое время. Пертурбация может, однако, вызвать непреднамеренное переупорядочивание пакетов. Рекомендуемое значение может составлять 10 секунд.

Одним из использований Fair Queue может быть снижение атак типа «отказ в обслуживании».

set qos policy fair-queue <policy-name> hash-interval <seconds>

Используйте эту команду для определения политики Fair-Queue, основанной на Случайной справедливой очереди, и установите количество секунд, через которое произойдет новая пертурбация алгоритма очереди (максимум 4294967295).

При деочереди каждый хэш-буфер с данными опрашивается по циклическому порядку. Вы можете настроить длину очереди.

set qos policy fair-queue <policy-name> queue-limit <limit>

Используйте эту команду для определения политики Fair-Queue, основанной на Случайной справедливой очереди, и установите максимальное количество пакетов, допустимых для ожидания в очереди. Любой другой пакет будет отброшен.

Примечание

Fair Queue — это политика, не связанная с формированием (работающая), поэтому она будет полезна только в том случае, если ваш исходящий интерфейс действительно полный. Если он не полный, VyOS не будет владеть очередью, и Fair Queue не будет иметь эффекта. Если на физическом канале есть свободная пропускная способность, вы можете вложить Fair-Queue в классовую политику формирования, чтобы убедиться, что он владеет очередью.

FQ-CoDel

Дисциплина очереди: Fair/Flow Queue CoDel.
Применяется к: Исходящий трафик.

Политика FQ-CoDel распределяет трафик в 1024 FIFO-очереди и пытается обеспечить хорошее обслуживание всех них. Он также пытается сохранить короткую длину всех очередей.

FQ-CoDel борется с буферблатом и уменьшает задержку без необходимости сложных настроек. Он стал новой стандартной дисциплиной очереди для интерфейсов некоторых дистрибутивов GNU/Linux.

Он использует статистическую модель для классификации входящих пакетов в разные потоки и используется для предоставления справедливого количества пропускной способности всем потокам, использующим очередь. Каждый поток управляется дисциплиной очереди CoDel. Переупорядочение внутри потока избегается, поскольку CoDel внутренне использует FIFO-очередь.

FQ-CoDel основан на модифицированном алгоритме распределения дефицита (DRR) с алгоритмом управления активной очередью (AQM) CoDel, работающим на каждой очереди.

Примечание

FQ-Codel — это политика, не связанная с формированием (работающая), поэтому она будет полезна только в том случае, если ваш исходящий интерфейс действительно полный. Если он не полный, VyOS не будет владеть очередью, и FQ-Codel не будет иметь эффекта. Если на физическом канале есть свободная пропускная способность, вы можете вложить FQ-Codel в классовую политику формирования, чтобы убедиться, что он владеет очередью. Если вы не уверены, нужно ли вам вкладывать политику FQ-CoDel в Шапер, сделайте это.

FQ-CoDel настроен на работу с его стандартными параметрами на скорости 10 Гбит. Он может работать нормально и на других скоростях без настройки, но здесь мы объясним некоторые случаи, когда вы можете настроить его параметры.

При работе на скорости 1 Гбит и ниже, вы можете уменьшить queue-limit до 1000 пакетов или меньше. На скоростях, таких как 10 Мбит, вы можете установить его на 600 пакетов.

Если вы используете FQ-CoDel, вложенный в Шапер, и у вас большие скорости (100 Мбит и выше), вы можете рассмотреть увеличение quantum до 8000 или выше, чтобы сэкономить процессор.

На низких скоростях (ниже 40 Мбит) вы можете настроить quantum до 300 байт.

На очень низких скоростях (ниже 3 Мбит) помимо настройки quantum (300 остается в порядке), вы также можете увеличить target до около 15 мс и увеличить interval до около 150 мс.

set qos policy fq-codel <policy name> codel-quantum <bytes>

Используйте эту команду для настройки политики fq-codel, установки ее имени и максимального количества байтов (по умолчанию: 1514), которые будут извлечены из очереди за один раз.

set qos policy fq-codel <policy name> flows <number-of-flows>

Используйте эту команду для настройки политики fq-codel, установки ее имени и количества подочередей (по умолчанию: 1024), в которые будут классифицированы пакеты.

set qos policy fq-codel <policy name> interval <milliseconds>

Используйте эту команду для настройки политики fq-codel, установки ее имени и времени, используемого циклом управления CoDel для обнаружения развития постоянной очереди, обеспечивая, чтобы измеренное минимальное время задержки не стало слишком старым (по умолчанию: 100 мс).

set qos policy fq-codel <policy-name> queue-limit <number-of-packets>

Используйте эту команду для настройки политики fq-codel, установки ее имени и задания жесткого ограничения на реальный размер очереди. Когда это ограничение достигнуто, новые пакеты будут отброшены (по умолчанию: 10240 пакетов).

set qos policy fq-codel <policy-name> target <milliseconds>

Используйте эту команду для настройки политики fq-codel, установки ее имени и определения допустимого минимального стоячего/постоянного времени задержки очереди. Это минимальное время задержки определяется путем отслеживания локального минимального времени задержки, которое испытывают пакеты (по умолчанию: 5 мс).

Пример

Простой пример политики FQ-CoDel, работающей внутри политики Shaper.

set qos policy shaper FQ-CODEL-SHAPER bandwidth 2gbit
set qos policy shaper FQ-CODEL-SHAPER default bandwidth 100%
set qos policy shaper FQ-CODEL-SHAPER default queue-type fq-codel

Limiter

Дисциплина очереди: Входной регулятор.
Применяется к: Входящий трафик.

Limiter — одна из тех политик, которые используют классы (входная дисциплина очереди на самом деле является политикой без класса, но фильтры работают в ней).

Limiter выполняет базовое входное регулирование трафика. Можно определить несколько классов трафика и применить ограничения трафика к каждому классу. Хотя регулятор использует механизм токен-бакета внутренне, он не имеет возможности задерживать пакет, как делает механизм формирования. Трафик, превышающий определенные ограничения пропускной способности, прямо отбрасывается. Также можно настроить максимальный допустимый буфер.

Вы можете настроить классы (до 4090) с разными настройками и политику по умолчанию, которая будет применяться к любому трафику, не соответствующему каким-либо настроенным классам.

Примечание

Если вы хотите применить какое-либо формирование к вашему входящему трафику, проверьте раздел входного формирования.

set qos policy limiter <policy-name> class <class ID> match <match-name> description <description>

Используйте эту команду для настройки входного регулятора, определив его имя, идентификатор класса (1-4090), имя правила сопоставления класса и его описание.

После установки правил сопоставления для класса, вы можете начать настраивать, как вы хотите, чтобы соответствующий трафик вел себя.
