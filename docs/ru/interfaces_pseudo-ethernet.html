MACVLAN (псевдо-Ethernet)

MACVLAN, или псевдо-Ethernet интерфейсы, работают как логические подинтерфейсы стандартных Ethernet интерфейсов. Каждый подинтерфейс имеет уникальный MAC-адрес, но разделяет один физический Ethernet порт. Это позволяет пользователю отправлять пакеты с разных исходных IPv4 или IPv6 адресов с использованием другого MAC-адреса.

Псевдо-Ethernet интерфейсы ведут себя как физические Ethernet интерфейсы. Они поддерживают IPv4 и IPv6 адресацию, могут получать IP-адреса через DHCP или DHCPv6, и привязаны к физическому Ethernet порту. Они наследуют характеристики, такие как скорость и полнодуплексность, от родительского интерфейса и могут использоваться как стандартные Ethernet интерфейсы после создания.

Псевдо-Ethernet интерфейсы могут не работать в средах, где требуется, чтобы

NIC имел только один MAC-адрес. Это включает:

  • Машины VMware с настройками по умолчанию.

  • Сетевые коммутаторы, разрешающие только один MAC-адрес.

  • DSL модемы, которые запоминают MAC-адрес сетевой карты.

Конфигурация

Общая конфигурация интерфейса

set interfaces pseudo-ethernet <interface> address <address | dhcp | dhcpv6>

Настройте интерфейс с одним или несколькими IP-адресами.

Доступны следующие варианты:

  • address: Назначьте один или несколько IPv4 или IPv6 адресов интерфейсу. Например, используйте 192.0.2.1/24 для IPv4 или 2001:db8::1/64 для IPv6.

  • dhcp: Интерфейс получает IPv4 адрес от DHCP сервера на том же сетевом сегменте.

  • dhcpv6: Интерфейс получает IPv6 адрес от DHCPv6 сервера на том же сетевом сегменте.

Примечание

Если интерфейс получает IPv4 адрес через DHCP, и необходимы специальные настройки до/после получения IP-адреса, используйте предоставленные скрипты-хуки:

  • /config/scripts/dhcp-client/pre-hooks.d/

  • /config/scripts/dhcp-client/post-hooks.d/

Пример:

set interfaces pseudo-ethernet peth0 address 192.0.2.1/24
set interfaces pseudo-ethernet peth0 address 2001:db8::1/64
set interfaces pseudo-ethernet peth0 address dhcp
set interfaces pseudo-ethernet peth0 address dhcpv6
set interfaces pseudo-ethernet <interface> description <description>

Настройте ясное, описательное имя для интерфейса.

Это имя появляется в команде show interfaces и инструментах мониторинга на основе SNMP.

Пример:

set interfaces pseudo-ethernet peth0 description 'This is an interface running on VyOS.'
set interfaces pseudo-ethernet <interface> disable

Отключите интерфейс.

Интерфейс будет установлен в состояние административно выключенное (A/D).

Пример:

set interfaces pseudo-ethernet peth0 disable
set interfaces pseudo-ethernet <interface> disable-flow-control

Отключить управление потоком Ethernet (стандарт IEEE 802.3x pause frames) на интерфейсе.

Управление потоком Ethernet, определенное стандартом IEEE 802.3x, временно прекращает передачу данных, чтобы предотвратить потерю пакетов при перегрузке сети. Например, когда отправитель передает данные быстрее, чем может обработать получатель.

Отключение управления потоком Ethernet означает, что интерфейс не будет сигнализировать подключенному устройству о паузе передачи и будет отбрасывать пакеты, если перегружен.

Пример:

set interfaces pseudo-ethernet peth0 disable-flow-control
set interfaces pseudo-ethernet <interface> disable-link-detect

Отключить обнаружение изменений состояния физического соединения на интерфейсе, например, когда кабель отсоединен.

По умолчанию интерфейс обнаруживает изменения состояния физического соединения.

Пример:

set interfaces pseudo-ethernet peth0 disable-link-detect
set interfaces pseudo-ethernet <interface> mac <xx:xx:xx:xx:xx:xx>

Настройте пользовательский MAC-адрес на интерфейсе.

Пример:

set interfaces pseudo-ethernet peth0 mac '00:53:01:02:03:04'
set interfaces pseudo-ethernet <interface> mtu <mtu>

Настройте MTU на интерфейсе.

Это значение определяет максимальный размер пакета, в байтах, который интерфейс передает без фрагментации.

Пример:

set interfaces pseudo-ethernet peth0 mtu 1600
set interfaces pseudo-ethernet <interface> ip adjust-mss <mss | clamp-mss-to-pmtu>

Настройте MSS , объявляемый в исходящих пакетах TCP SYN на указанном интерфейсе.

При ограничении значения MSS в пакетах TCP SYN вы явно информируете удаленную сторону не отправлять пакеты большего размера. Это предотвращает проблемы с подключением, когда Path MTU Discovery (PMTUD) не работает.

Доступны следующие варианты:

  • mss: Устанавливает MSS в конкретное значение, в байтах. Используйте этот вариант, если необходимо задать конкретный MSS, например, для устранения проблем с подключением или соответствия специфическим требованиям сети.

  • clamp-mss-to-pmtu: Роутер автоматически рассчитывает MSS как MTU интерфейса минус 40 байт для IPv4 трафика (20 байт для заголовка IPv4 и 20 байт для заголовка TCP). Этот вариант рекомендуется для автоматической установки правильного значения.

set interfaces pseudo-ethernet <interface> ip arp-cache-timeout

Настройте, как долго ARP-запись остается действительной после изучения сопоставления IP-адреса и MAC-адреса на этом интерфейсе.

По умолчанию длительность составляет 30 секунд.

ARP-запись остается действительной, если она получает положительный ответ от вышеуровневых протоколов.

Пример:

set interfaces pseudo-ethernet peth0 ip arp-cache-timeout 180
set interfaces pseudo-ethernet <interface> ip disable-arp-filter

Настройте фильтрацию ARP на этом интерфейсе.

Поведение по умолчанию: Ядро отвечает на запросы ARP на этом интерфейсе только в том случае, если трафик будет направлен обратно к отправителю ARP через этот конкретный интерфейс.

Если настроено: Ядро отвечает на запросы ARP на этом интерфейсе для любого IP-адреса, настроенного на локальном хосте, независимо от того, какой конкретный интерфейс этот IP-адрес назначен, и независимо от таблицы маршрутизации. Это отражает концепцию Linux, что IP-адреса принадлежат хосту, а не отдельным интерфейсам.

Пример:

set interfaces pseudo-ethernet peth0 ip disable-arp-filter
set interfaces pseudo-ethernet <interface> ip disable-forwarding

Настройте интерфейс на режим работы хоста или роутера.

Если настроено, интерфейс переключается в режим хоста, и IPv4-пересылка отключена на нем.

Пример:

set interfaces pseudo-ethernet peth0 ip disable-forwarding
set interfaces pseudo-ethernet <interface> ip enable-directed-broadcast

Настройте, будут ли передаваться пакеты IP-направленного вещания, полученные на этом интерфейсе.

Поведение по умолчанию: Пакеты IP-направленного вещания отбрасываются.

Если настроено: Пакеты IP-направленного вещания передаются всем хостам на целевом подсети, как определено в RFC 1812 и RFC 2644.

Пример:

set interfaces pseudo-ethernet peth0 ip enable-directed-broadcast
set interfaces pseudo-ethernet <interface> ip enable-arp-accept

Настройте, как обрабатывать грабежные ARP на этом интерфейсе.

Если настроено, сопоставление IP-адреса и MAC-адреса добавляется в ARP-таблицу на основе гробежных ARP-запросов или ответов.

Примечание

Если ARP-таблица уже содержит IP-адрес из грабежного ARP, его запись обновляется независимо от того, настроено ли это настройство.

Пример:

set interfaces pseudo-ethernet peth0 ip enable-arp-accept
set interfaces pseudo-ethernet <interface> ip enable-arp-announce

Настройте выбор источника IP-адреса для ARP-запросов на этом интерфейсе.

Поведение по умолчанию: Ядро может использовать любой IP-адрес, которым владеет хост, как источник IP-адреса в ARP-запросах на этом интерфейсе.

Если настроено: Ядро сначала пытается выбрать источник IP-адреса, настроенный на интерфейсе, который совпадает с подсетью целевого IP-адреса. Если такой подсети нет, ядро выбирает IP-адрес, который обычно используется (на основе таблицы маршрутизации для достижения целевого назначения).

Пример:

set interfaces pseudo-ethernet peth0 ip enable-arp-announce
set interfaces pseudo-ethernet <interface> ip enable-arp-ignore

Настройте, какие запросы ARP будут игнорироваться на этом интерфейсе.

Поведение по умолчанию: Ядро отвечает на запросы ARP для любых локальных IP-адресов, независимо от того, к какому интерфейсу они привязаны.

Если настроено: Ядро отвечает на запросы ARP только в том случае, если целевой IP-адрес привязан к этому конкретному интерфейсу.

Пример:

set interfaces pseudo-ethernet peth0 ip enable-arp-ignore
set interfaces pseudo-ethernet <interface> ip enable-proxy-arp

Настройте прокси-ARP на этом интерфейсе.

Если настроено, роутер (ядро) перехватывает запросы ARP для нелокальных IP-адресов и отвечает с MAC-адресом интерфейса, который получил запрос. Последующие пакеты, предназначенные для этих IP-адресов, перенаправляются на их фактические цели на удаленных подсетях.

Пример:

set interfaces pseudo-ethernet peth0 ip enable-proxy-arp
set interfaces pseudo-ethernet <interface> ip proxy-arp-pvlan

Настройте локальный прокси-ARP на интерфейсе.

Если настроено, роутер (ядро) отвечает на запросы ARP на этом VLAN-интерфейсе даже если целевой IP-адрес находится на той же подсети и интерфейсе.

Это используется для поддержки требований к изоляции сети (RFC 3069) для частных VLAN (PVLAN). В конфигурациях PVLAN, хосты на изолированных портах НЕ разрешены прямая связь между собой на уровне 2, но они могут общаться с верхним роутером.

Посредством ответа на ARP-запросы между хостами своим собственным MAC-адресом, роутер (ядро) направляет трафик между хостами через себя вместо прямой передачи между хостами.

Примечание

Эта команда работает независимо и не требует включения обычного прокси-ARP на интерфейсе.

Локальный прокси-ARP также известен как:

  • Агрегация VLAN (RFC 3069).

  • Частный VLAN (Cisco, Allied Telesyn).

  • Фильтрация порта источника или изоляция порта (Hewlett-Packard).

  • Передача MAC-адреса (Ericsson).

set interfaces pseudo-ethernet <interface> ip source-validation <strict | loose | disable>

Настройте проверку исходного IP-адреса с помощью RPF на этом интерфейсе, как указано в RFC 3704.

Доступны следующие варианты:

  • strict: Каждый входящий пакет проверяет исходный IP-адрес против Forwarding Information Base (FIB). Если интерфейс не является лучшим маршрутом обратно к этому источнику, проверка неудачна, и пакет удаляется.

  • loose: Каждый входящий пакет проверяет исходный IP-адрес против FIB. Если исходный IP-адрес недоступен через любой интерфейс, проверка неудачна.

  • disable: Проверка исходного IP-адреса не выполняется. Все входящие пакеты принимаются.

RFC 3704 рекомендует включить строгий режим для предотвращения подделки IP-адресов, таких как DDoS-атаки. Для асимметричных или других сложных сценариев маршрутизации используйте режим loose.

set interfaces pseudo-ethernet <interface> ipv6 address autoconf
