SSH

SSH — это криптографический сетевой протокол для безопасного выполнения сетевых служб над не защищенной сетью. Стандартный TCP-порт для SSH — 22. Наиболее известным примером применения является удаленный вход в компьютерные системы пользователями.

SSH обеспечивает безопасный канал над не защищенной сетью в клиент-серверной архитектуре, соединяя приложение клиента SSH с сервером SSH. Обычные приложения включают удаленный вход в командную строку и удаленное выполнение команд, но любую сетевую службу можно защитить с помощью SSH. Спецификация протокола различает две основные версии, обозначаемые как SSH-1 и SSH-2.

Наиболее заметное применение протокола — это доступ к shell-аккаунтам на операционных системах, похожих на Unix, но он также используется ограниченным образом на Windows. В 2015 году Microsoft объявила, что они будут включать нативную поддержку SSH в будущем выпуске.

SSH был разработан как замена Telnet и не защищенным удаленным протоколам shell, таким как Berkeley rlogin, rsh и rexec протоколы. Эти протоколы передают информацию, особенно пароли, в текстовом виде, что делает их уязвимыми для перехвата и раскрытия с использованием анализа пакетов. Шифрование, используемое SSH, предназначено для обеспечения конфиденциальности и целостности данных над не защищенной сетью, такой как интернет.

Примечание

VyOS 1.1 поддерживал вход в систему как пользователь root. Это было удалено из-за более строгой безопасности в VyOS 1.2.

SSH Аутентификация на основе ключей

Конфигурация

set service ssh port <port>

Включение SSH требует только указания порта <port>, на котором SSH должен прослушивать. По умолчанию SSH работает на порту 22.

set service ssh listen-address <address>

Укажите IPv4/IPv6 адрес прослушивания сервера SSH. Можно определить несколько адресов.

set service ssh cipher <cipher>

Определите допустимые шифры, используемые для соединения SSH. Можно указать несколько допустимых шифров, используя несколько повторений для разрешения нескольких шифров.

Список поддерживаемых шифров: 3des-cbc, aes128-cbc, aes192-cbc, aes256-cbc, aes128-ctr, aes192-ctr, aes256-ctr, aes128-gcm@openssh.com, aes256-gcm@openssh.com, chacha20-poly1305@openssh.com

set service ssh disable-password-authentication

Отключить аутентификацию по паролю. Вход только через SSH-ключи. Это повышает безопасность!

set service ssh fido pin-required

Требовать FIDO2-ключи для подтверждения того, что пользователь был проверен (например, через PIN).

set service ssh fido touch-required

Требовать FIDO2-ключи для подтверждения физического присутствия пользователя.

VyOS поддерживает аутентификацию SSH с использованием FIDO2-ключей, созданных OpenSSH. Два типа FIDO2-ключей поддерживаются OpenSSH: ed25519-sk, ecdsa-sk

Пример генерации общего FIDO2-ключа SSH:

ssh-keygen -t ecdsa-sk -O verify-required -C "fido2-ssh-key"
Во время генерации ключа OpenSSH будет:

  • Запрашивать наличие пользователя (например, физическое касание или подтверждение)

  • По желанию запрашивать проверку пользователя (PIN), если это поддерживается аутентификатором

  • Создавать локальный файл ключа и соответствующий открытый ключ (.pub)

Частный ключ никогда не покидает устройство аутентификатора.

Пример конфигурации VyOS:

# Создайте FIDO2 SSH-ключ на клиентской системе
# Копируйте открытый ключ на экземпляр VyOS
set system login user vyos authentication public-keys fido key '<public-key>'
set system login user vyos authentication public-keys fido type '[email protected]'
set service ssh fido touch-required

Теперь вы можете войти в систему, используя: ssh -i ~/.ssh/id_fido_key vyos@192.0.2.1

set service ssh disable-host-validation

Отключить проверку хоста через обратные DNS-запросы — может ускорить время входа когда обратный запрос невозможен.

set service ssh mac <mac>

Указывает доступные алгоритмы MAC. Алгоритм MAC используется в версии протокола 2 для защиты целостности данных. Можно предоставить несколько алгоритмов, используя несколько команд, определяя один алгоритм на команду.

Список поддерживаемых MAC: hmac-md5, hmac-md5-96, hmac-ripemd160, hmac-sha1, hmac-sha1-96, hmac-sha2-256, hmac-sha2-512, umac-64@openssh.com, umac-128@openssh.com, hmac-md5-etm@openssh.com, hmac-md5-96-etm@openssh.com, hmac-ripemd160-etm@openssh.com, hmac-sha1-etm@openssh.com, hmac-sha1-96-etm@openssh.com, hmac-sha2-256-etm@openssh.com, hmac-sha2-512-etm@openssh.com, umac-64-etm@openssh.com, umac-128-etm@openssh.com

set service ssh access-control <allow | deny> <group | user> <name>

Добавьте директиву контроля доступа, чтобы разрешить или запретить пользователей и группы. Директивы обрабатываются в следующем порядке приоритета: deny-users, allow-users, deny-groups и allow-groups.

set service ssh client-keepalive-interval <interval>

Укажите интервал времени в секундах для сообщения о сохранении связи.

set service ssh key-exchange <kex>

Укажите допустимые алгоритмы KEX.

Список поддерживаемых алгоритмов: diffie-hellman-group1-sha1, diffie-hellman-group14-sha1, diffie-hellman-group14-sha256, diffie-hellman-group16-sha512, diffie-hellman-group18-sha512, diffie-hellman-group-exchange-sha1, diffie-hellman-group-exchange-sha256, ecdh-sha2-nistp256, ecdh-sha2-nistp384, ecdh-sha2-nistp521, curve25519-sha256 и curve25519-sha256@libssh.org.

set service ssh loglevel <quiet | fatal | error | info | verbose>

Установите уровень журналирования sshd. По умолчанию установлено значение info.

set service ssh vrf <name>

Укажите имя экземпляра VRF.

set service ssh pubkey-accepted-algorithm <name>

Указывает алгоритмы подписи, которые будут приняты для аутентификации по открытым ключам

Список поддерживаемых алгоритмов: ssh-ed25519, ssh-ed25519-cert-v01@openssh.com, sk-ssh-ed25519@openssh.com, sk-ssh-ed25519-cert-v01@openssh.com, ecdsa-sha2-nistp256, ecdsa-sha2-nistp256-cert-v01@openssh.com, ecdsa-sha2-nistp384, ecdsa-sha2-nistp384-cert-v01@openssh.com, ecdsa-sha2-nistp521, ecdsa-sha2-nistp521-cert-v01@openssh.com, sk-ecdsa-sha2-nistp256@openssh.com, sk-ecdsa-sha2-nistp256-cert-v01@openssh.com, webauthn-sk-ecdsa-sha2-nistp256@openssh.com, ssh-dss, ssh-dss-cert-v01@openssh.com, ssh-rsa, ssh-rsa-cert-v01@openssh.com, rsa-sha2-256, rsa-sha2-256-cert-v01@openssh.com, rsa-sha2-512, rsa-sha2-512-cert-v01@openssh.com

set service ssh trusted-user-ca <name>

Укажите имя ключевой пары OpenSSH, которая действует как центр сертификации и будет использоваться для проверки пользовательских сертификатов.

Вы можете использовать его, добавив ключевую пару OpenSSH в подсистему PKI.

Пример:

# Генерация ключевой пары, действующей как CA
$ ssh-keygen -f vyos-ssh-ca.key

# Генерация ключа для пользователя: vyos_testca
$ ssh-keygen -f vyos_testca  -C "[email protected]"

# Подписать открытый ключ пользователя vyos_testca и вставить имена пользователей: vyos, vyos_testca
# с сроком действия ключа два недели — после чего ключ станет непригодным
$ ssh-keygen -s vyos-ssh-ca.key -I [email protected] -n vyos,vyos_testca -V +2w vyos_testca.pub

$ set system login user vyos_testca
$ set pki openssh test_ca public key AAAAB3N.....
$ set pki openssh test_ca public type ssh-rsa
$ set service ssh trusted-user-ca test_ca

Теперь вы можете войти в систему, используя: ssh -i vyos_testca vyos_testca@vyos.test.com

Динамическая защита

Защищает хост от атак методом подбора паролей против SSH. Сообщения журнала анализируются построчно для распознаваемых шаблонов. Если обнаружена атака, например, несколько неудачных попыток входа в течение нескольких секунд, то IP-адрес злоумышленника блокируется. Злоумышленники разблокируются через заданный интервал.

set service ssh dynamic-protection

Разрешить ssh динамическую защиту.

set service ssh dynamic-protection allow-from <address | prefix>

Список доверенных адресов и сетей. Всегда разрешать входящие соединения с этих систем.

set service ssh dynamic-protection block-time <sec>

Блокировать исходный IP-адрес в секундах. Последующие блокировки увеличиваются в 1.5 раза По умолчанию 120.

set service ssh dynamic-protection detect-time <sec>

Помнить исходный IP-адрес в секундах до сброса их балла. По умолчанию 1800.

set service ssh dynamic-protection threshold <sec>

Блокировать исходный IP-адрес, когда их суммарный балл атаки превышает пороговое значение. По умолчанию 30.

Операция

restart ssh

Перезапустить процесс демона SSH, текущая сессия не затрагивается, только фоновый демон перезапускается.

generate ssh server-key

Перегенерировать часть публичного/приватного ключа, которую SSH использует для безопасного соединения.

Примечание

Already learned known_hosts files of clients need an update as the public key will change.

generate ssh client-key /path/to/private_key

Перегенерировать известный файл публичного/приватного ключа, который можно использовать для подключения к другим службам (например, кэшу RPKI).

Пример:

The key's randomart image is:

Будут созданы два новых файла /config/auth/id_rsa_rpki и /config/auth/id_rsa_rpki.pub .

generate public-key-command user <username> path <location>

Сгенерируйте команды режима конфигурации для добавления открытого ключа для Аутентификации на основе ключей. <location> может быть локальным путем или URL, указывающим на удаленный файл.

Поддерживаемые удаленные протоколы: FTP, FTPS, HTTP, HTTPS, SCP/SFTP и TFTP.

Пример:

alyssa@vyos:~$ generate public-key-command user alyssa path sftp://example.net/home/alyssa/.ssh/id_rsa.pub
# Чтобы добавить этот ключ как встроенный ключ, выполните следующие команды:
configure
set system login user alyssa authentication public-keys [email protected] key AAA...
set system login user alyssa authentication public-keys [email protected] type ssh-rsa
commit
save
exit

ben@vyos:~$ generate public-key-command user ben path ~/.ssh/id_rsa.pub
# Чтобы добавить этот ключ как встроенный ключ, выполните следующие команды:
configure
set system login user ben authentication public-keys ben@vyos key AAA...
set system login user ben authentication public-keys ben@vyos type ssh-dss
commit
save
exit
