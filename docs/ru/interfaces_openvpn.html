OpenVPN

Традиционно, аппаратные маршрутизаторы используют IPsec исключительно, потому что он легко реализуется в аппаратном обеспечении, а их процессоры не обладают достаточной мощностью для программной шифровки. Это ограничение менее актуально для VyOS, так как это программный маршрутизатор.

OpenVPN давно используется на платформах UNIX и является популярным выбором для удаленных сетевых туннелей. Он также поддерживает соединения между сайтами.

OpenVPN имеет следующие преимущества:

  • Он использует одно соединение TCP или UDP и не зависит от адресов источника пакетов, поэтому работает даже через двойной NAT. Это делает его подходящим для общественных точек доступа.

  • Он легко настраивается и предлагает очень гибкое разделение туннеля.

  • Для любой платформы доступны различные графические интерфейсы клиентов.

Недостатки включают:

  • Он медленнее, чем IPsec из-за большего объема протокола и того, что он работает в пользовательском режиме, тогда как IPsec на Linux работает в режиме ядра.

  • Ни одна операционная система не включает в себя программное обеспечение клиента OpenVPN по умолчанию.

В интерфейсе командной строки VyOS OpenVPN конфигурируется как сетевой интерфейс с помощью set interfaces openvpn, а не set vpn, что часто игнорируется.

Конфигурация

set interfaces openvpn <interface> authentication password <text>

Настройте пароль для метода аутентификации auth-user-pass .

Эта опция применяется только к клиентам OpenVPN.

set interfaces openvpn <interface> authentication username <text>

Настройте имя пользователя для метода аутентификации auth-user-pass .

Эта опция применяется только к клиентам OpenVPN.

set interfaces openvpn <interface> description <description>

Настройте описание для интерфейса OpenVPN.

set interfaces openvpn <interface> device-type <tap | tun>

Настройте тип виртуального сетевого устройства для интерфейса OpenVPN:

  • tun (по умолчанию): Работает на уровне 3, инкапсулируя пакеты IPv4 или IPv6.

  • tap: Работает на уровне 2, инкапсулируя кадры Ethernet 802.3.

set interfaces openvpn <interface> disable

Отключите конкретный интерфейс OpenVPN.

set interfaces openvpn <interface> encryption cipher < 3des | aes128 | aes128gcm | aes192 | aes192gcm | aes256 | aes256gcm | none >

Настройте статический алгоритм шифрования для туннеля OpenVPN.

Параметр cipher соответствует директиве OpenVPN --cipher и указывает симметричный алгоритм шифрования для каналов управления и данных.

Это было стандартным методом шифрования во всех режимах OpenVPN. В более новых версиях OpenVPN директива --cipher считается устаревшей и должна использоваться только в сценариях совместимости.

set interfaces openvpn <interface> encryption data-ciphers < 3des | aes128 | aes128gcm | aes192 | aes192gcm | aes256 | aes256gcm | none >

Настройте приоритетный список согласованных шифров для OpenVPN в режиме client или server .

Параметр data-ciphers представляет собой список поддерживаемых алгоритмов шифрования. Он соответствует директиве OpenVPN --data-ciphers и позволяет согласовать шифры, где оба узла автоматически соглашаются на совместно поддерживаемый шифр во время запуска сеанса.

Примечание

Эта опция несовместима с режимом site-to-site.

set interfaces openvpn <interface> encryption data-ciphers-fallback < 3des | aes128 | aes128gcm | aes192 | aes192gcm | aes256 | aes256gcm | none >

Настройте резервный шифр для режима site-to-site .

Параметр data-ciphers-fallback соответствует директиве OpenVPN --data-ciphers-fallback. Он определяет шифр, который будет использоваться, если согласование не поддерживается.

Примечание

Эта опция обеспечивает согласованное шифрование между двумя статичными узлами без возможности согласования шифров.

set interfaces openvpn <interface> hash <md5 | sha1 | sha256 | …>

Настройте алгоритм хеширования для интерфейса OpenVPN.

set interfaces openvpn <interface> ip adjust-mss <mss | clamp-mss-to-pmtu>

Настройте MSS , объявляемый в исходящих пакетах TCP SYN на указанном интерфейсе.

Путем ограничения значения MSS в пакетах TCP SYN, вы явно информируете удаленный узел о том, что он не должен отправлять пакеты большего размера. Это предотвращает проблемы с подключением, когда обнаружение MTU пути (PMTUD) не удается.

Доступны следующие варианты:

  • mss: Устанавливает MSS в определенное значение, в байтах. Используйте этот вариант, если необходимо принудительно установить определенное значение MSS, например, для устранения проблем с подключением или соответствия специфическим требованиям сети.

  • clamp-mss-to-pmtu: Роутер автоматически рассчитывает MSS, равный MTU интерфейса минус 40 байт для IPv4 (20 байт для заголовка IPv4 и 20 байт для заголовка TCP). Этот вариант рекомендуется для автоматической установки правильного значения.

set interfaces openvpn <interface> ip arp-cache-timeout

Настройте, как долго ARP-запись остается действительной после получения карты IP-адреса в MAC-адрес на этом интерфейсе.

По умолчанию длительность составляет 30 секунд.

ARP-запись остается действительной, если она получает положительный ответ от более высоких уровней протоколов.

Пример:

set interfaces openvpn vtun0 ip arp-cache-timeout 180
set interfaces openvpn <interface> ip disable-arp-filter

Настройте фильтрацию ARP на этом интерфейсе.

Стандартное поведение: Ядро отвечает на запросы ARP на этом интерфейсе только в том случае, если трафик будет направлен обратно к отправителю ARP через этот конкретный интерфейс.

Если настроено: Ядро отвечает на запросы ARP на этом интерфейсе для любого IP-адреса, настроенного на локальном хосте, независимо от того, какой конкретный интерфейс этому IP-адресу привязан, и независимо от таблицы маршрутизации. Это отражает концепцию Linux, согласно которой IP-адреса принадлежат хосту, а не отдельным интерфейсам.

Пример:

set interfaces openvpn vtun0 ip disable-arp-filter
set interfaces openvpn <interface> ip disable-forwarding

Настройте интерфейс для работы в режиме хоста или маршрутизатора.

Если настроено, интерфейс переключается в режим хоста, и IPv4-пересылка отключается на нем.

Пример:

set interfaces openvpn vtun0 ip disable-forwarding
set interfaces openvpn <interface> ip enable-directed-broadcast

Настройте, будут ли передаваться пакеты IP-направленного широковещания, полученные на этом интерфейсе.

Стандартное поведение: Пакеты IP-направленного широковещания удаляются.

Если настроено: Пакеты IP-направленного широковещания передаются всем хостам на целевом подсети, как определено в RFC 1812 и RFC 2644.

Пример:

set interfaces openvpn vtun0 ip enable-directed-broadcast
set interfaces openvpn <interface> ip enable-arp-accept

Настройте, как обрабатывать грабежные ARP на этом интерфейсе.

Если настроено, IP-адрес-МАС-адрес сопоставление добавляется в таблицу ARP на основе грабежных ARP-запросов или ответов.

Примечание

Если в таблице ARP уже есть IP-адрес из грабежного ARP, его запись обновляется независимо от того, настроено ли это настройство.

Пример:

set interfaces openvpn vtun0 ip enable-arp-accept
set interfaces openvpn <interface> ip enable-arp-announce

Настройте выбор источника IP-адреса для ARP-запросов на этом интерфейсе.

Стандартное поведение: Ядро может использовать любой IP-адрес, которым владеет хост, как источник IP-адреса в ARP-запросах на этом интерфейсе.

Если настроено: Ядро сначала пытается выбрать источник IP-адреса, настроенный на интерфейсе, который совпадает с подсетью целевого IP-адреса. Если такой подсети нет, ядро выбирает IP-адрес, который оно обычно использует (на основе таблицы маршрутизации для достижения целевого назначения).

Пример:

set interfaces openvpn vtun0 ip enable-arp-announce
set interfaces openvpn <interface> ip enable-arp-ignore

Настройте, какие ARP-запросы будут игнорироваться на этом интерфейсе.

Стандартное поведение: Ядро отвечает на ARP-запросы для любых локальных IP-адресов, независимо от того, к какому интерфейсу они привязаны.

Если настроено: Ядро отвечает на ARP-запросы только в том случае, если целевой IP-адрес привязан к этому конкретному интерфейсу.

Пример:

set interfaces openvpn vtun0 ip enable-arp-ignore
set interfaces openvpn <interface> ip enable-proxy-arp

Настройте прокси-ARP на этом интерфейсе.

Если настроено, маршрутизатор (ядро) перехватывает ARP-запросы для нелокальных IP-адресов и отвечает с MAC-адресом интерфейса, который получил запрос. Последующие пакеты, предназначенные этим IP-адресам, перенаправляются на их фактические цели на удаленных подсетях.

Пример:

set interfaces openvpn vtun0 ip enable-proxy-arp
set interfaces openvpn <interface> ip proxy-arp-pvlan

Настройте локальный прокси-ARP на интерфейсе.

Если настроено, маршрутизатор (ядро) отвечает на ARP-запросы на этом интерфейсе VLAN, даже если целевой IP-адрес находится на той же подсети и интерфейсе.

Это используется для поддержки требований изоляции сети (RFC 3069) для частных VLAN (PVLAN). В конфигурациях PVLAN хосты на изолированных портах НЕ разрешены к прямой коммуникации друг с другом на уровне 2, но могут общаться с маршрутизатором верхнего уровня.

Путем ответа на ARP-запросы между хостами своим собственным MAC-адресом, маршрутизатор (ядро) направляет трафик между хостами через себя вместо прямой передачи между хостами.

Примечание

Эта команда работает независимо и не требует включения обычного прокси-ARP на интерфейсе.

Локальный прокси-ARP также известен как:

  • Агрегация VLAN (RFC 3069).

  • Частная VLAN (Cisco, Allied Telesyn).

  • Фильтрация по источнику порта или изоляция порта (Hewlett-Packard).

  • Перенаправление по MAC-адресу (Ericsson).

set interfaces openvpn <interface> ip source-validation <strict | loose | disable>

Настройте проверку исходного IP-адреса с помощью RPF на этом интерфейсе, как указано в RFC 3704.

Доступны следующие варианты:

  • strict: Каждый входящий пакет проверяет исходный IP-адрес против FIB. Если интерфейс не является лучшим маршрутом обратно к этому источнику, проверка не проходит, и пакет удаляется.

  • loose: Каждый входящий пакет проверяет исходный IP-адрес против FIB. Если исходный IP-адрес недоступен через любой интерфейс, проверка не проходит.

  • disable: Не выполняется проверка исходного IP-адреса. Все входящие пакеты принимаются.

RFC 3704 рекомендует включить строгий режим для предотвращения подделки IP-адресов, таких как DDoS-атаки. Для асимметричных или других сложных сценариев маршрутизации используйте режим loose.

set interfaces openvpn <interface> ipv6 address autoconf

Настройте интерфейс для автоматического получения IPv6-адреса с помощью SLAAC, как указано в RFC 4862.

Хосты IPv6 могут настраивать себя автоматически при подключении к сети IPv6 с помощью протокола обнаружения соседей через ICMPv6 сообщения о маршрутизаторе. При первом подключении к сети хост отправляет многоадресный запрос на обнаружение маршрутизатора в локальной подсети для получения параметров своей конфигурации. Маршрутизатор отвечает пакетом объявления маршрутизатора, содержащим параметры конфигурации уровня интернета.

Примечание

Этот метод автоматически отключает передачу IPv6-трафика на интерфейсе.

Пример:

set interfaces openvpn vtun0 ipv6 address autoconf
set interfaces openvpn <interface> ipv6 address eui64 <prefix>

Настройте интерфейс для присвоения себе IPv6-адреса с помощью метода EUI-64 , как указано в RFC 4291.

Пример:

set interfaces openvpn vtun0 ipv6 address eui64 2001:db8:beef::/64
set interfaces openvpn <interface> ipv6 address no-default-link-local

Отключите автоматическое присвоение link-local IPv6-адреса этому интерфейсу.

Пример:

set interfaces openvpn vtun0 ipv6 address no-default-link-local
set interfaces openvpn <interface> ipv6 disable-forwarding

Настройте интерфейс для работы в режиме хоста или маршрутизатора.

Если настроено, интерфейс переключается в режим хоста, и IPv6-передача отключается на нем.

Пример:

set interfaces openvpn vtun0 ipv6 disable-forwarding
set interfaces openvpn <interface> ipv6 adjust-mss <mss | clamp-mss-to-pmtu>

Настройте MSS , объявляемый в исходящих пакетах TCP SYN на указанном интерфейсе.

Путем ограничения значения MSS в пакетах TCP SYN, вы явно информируете удаленный узел о том, что он не должен отправлять пакеты большего размера. Это предотвращает проблемы с подключением, когда обнаружение MTU пути (PMTUD) не удается.

Доступны следующие варианты:

  • mss: Установите MSS в определенное значение, в байтах. Используйте этот вариант, чтобы принудительно установить определенное значение MSS, например, для устранения проблем с подключением или соответствия специфическим требованиям сети.

  • clamp-mss-to-pmtu: Роутер рассчитывает MSS как MTU интерфейса минус 60 байт для IPv6-трафика (40 байт для заголовка IPv6 и 20 байт для заголовка TCP). Этот вариант рекомендуется для автоматической установки правильного значения.

set interfaces openvpn <interface> ipv6 accept-dad <0 | 1 | 2>

Настройте IPv6 DAD на интерфейсе.

Доступны следующие варианты:

  • 0: Отключает DAD. Не производится проверка дублирующих адресов.

  • 1: Включает DAD (по умолчанию). Обнаруживаются дублирующиеся адреса. Работа интерфейса продолжается для допустимых IPv6-адресов.

  • 2: Включает DAD и, если найден дублирующийся локальный адрес, основанный на MAC-адресе, отключает работу IPv6 на этом интерфейсе.

Пример:

set interfaces openvpn vtun0 ipv6 accept-dad 2
set interfaces openvpn <interface> ipv6 dup-addr-detect-transmits <n>

Настройте количество сообщений DAD , которые отправляет роутер (ядро) во время присвоения IPv6-адреса на этом интерфейсе.

Значение по умолчанию — 1.

Пример:

set interfaces openvpn vtun0 ipv6 dup-addr-detect-transmits 5
set interfaces openvpn <interface> keep-alive failure-count <value>

Настройте количество допустимых сбоев пакетов keepalive.

По умолчанию: 60 последовательных сбоев.

set interfaces openvpn <interface> keep-alive interval <value>

Настройте частоту, с которой отправляются пакеты keepalive, в секундах.

По умолчанию: 10 секунд.

set interfaces openvpn <interface> local-address <address>

Настройте локальный IP-адрес туннеля для режима site-to-site.

set interfaces openvpn <interface> local-host <address>

Настройте локальный IP-адрес для приема соединений.

Если настроено, OpenVPN привязывается только к этому IP-адресу.

По умолчанию OpenVPN привязывается ко всем интерфейсам.

set interfaces openvpn <interface> local-port <port>

Настройте локальный порт для приема соединений.

set interfaces openvpn <interface> mirror egress <monitor-interface>

Настройте отражение исходящего трафика с этого интерфейса OpenVPN на заданный интерфейс монитора.

set interfaces openvpn <interface> mirror ingress <monitor-interface>

Настройте отражение входящего трафика с этого интерфейса OpenVPN на заданный интерфейс монитора.

set interfaces openvpn <interface> mode <site-to-site | server | client>

Настройте режим работы OpenVPN:

  • site-to-site: Устанавливает соединение между сайтами.

  • client: Работает как клиент в режиме сервер-клиент.

  • server: Работает как сервер в режиме сервер-клиент.

OpenVPN Data Channel Offload (DCO)

OpenVPN DCO повышает производительность обработки зашифрованных данных OpenVPN, сохраняя большую часть обработки данных в ядре и избегая частых переключений контекста между ядром и пользовательским пространством.

В результате обработка пакетов становится более эффективной и может использовать аппаратную поддержку шифрования в ядре.

Примечание

  • DCO — это экспериментальная, не полностью поддерживаемая функция OpenVPN. Некоторые функции OpenVPN и сценарии развертывания несовместимы с DCO.

    Для полного списка поддерживаемых функций посетите: https://community.openvpn.net/openvpn/wiki/DataChannelOffload/Features

  • DCO настраивается для каждого туннеля и отключен по умолчанию. Существующие туннели работают без DCO, если он не включен явно.

  • Включение DCO перезапускает интерфейс.

Рекомендация: Создайте новый туннель с включенным DCO, чтобы избежать проблем совместимости с существующими клиентами.

set interfaces openvpn <interface> offload dco

Включите DCO для указанного интерфейса OpenVPN.

Пример:

set interfaces openvpn vtun0 offload dco

Эта команда включает DCO и загружает необходимый модуль ядра.

set interfaces openvpn <interface> openvpn-option <text>

Добавьте необработанные параметры конфигурации OpenVPN в файл openvpn.conf.

OpenVPN предоставляет множество параметров конфигурации, но не все доступны в CLI VyOS.

Если требуется опция, которая отсутствует, вы можете подать заявку на функцию в Phabricator, чтобы все пользователи могли воспользоваться ею (см. Contributing/Issues and Features).

Альтернативно, используйте openvpn-option, чтобы передать необработанные параметры конфигурации OpenVPN в файл openvpn.conf.

Предупреждение

Используйте эту опцию только в крайнем случае. Неправильные параметры или синтаксис могут препятствовать запуску OpenVPN. Проверьте системные журналы на наличие ошибок после применения изменений.

Пример:

set interfaces openvpn vtun0 openvpn-option 'persist-key'

Эта команда добавляет persist-key в файл конфигурации. Это решает проблему, сохраняя ключи при сбросе, поэтому их не нужно читать заново.

set interfaces openvpn vtun0 openvpn-option 'route-up &quot;/config/auth/tun_up.sh arg1&quot;'

Эта команда добавляет route-up "/config/auth/tun_up.sh arg1" в файл конфигурации. Эта опция выполняется после аутентификации соединения, сразу или после коротой задержки, как определено.

Убедитесь, что путь и аргументы заключены в одинарные или двойные кавычки.

Примечание

Некоторые необработанные параметры конфигурации требуют кавычек. Чтобы включить их, используйте «statement».

set interfaces openvpn <interface> persistent-tunnel

Включите режим всегда активного TUN/TAP-устройства.

При включении TUN/TAP-устройство остается активным при сбросе соединения или перезагрузке демона.

set interfaces openvpn <interface> protocol <udp | tcp-passive | tcp-active >

Настройте протокол для общения OpenVPN с удаленным хостом:

  • udp (по умолчанию): Использует протокол UDP.

  • tcp-passive: Использует протокол TCP и принимает соединения пассивно.

  • tcp-active: Использует протокол TCP и активно инициирует соединения.

set interfaces openvpn <interface> redirect <interface>

Включите перенаправление входящих пакетов на указанный интерфейс.

set interfaces openvpn <interface> remote-address <address>

Настройте удаленный IP-адрес туннеля для режима site-to-site.

set interfaces openvpn <interface> remote-host <address | host>

Настройте IPv4/IPv6-адрес или имя хоста для серверного устройства, если OpenVPN работает в режиме клиента.

Это настройка не используется в режиме сервера.

set interfaces openvpn <interface> remote-port <port>

Настройте удаленный порт для подключения к серверу.

set interfaces openvpn <interface> replace-default-route

Настройте туннель OpenVPN как маршрут по умолчанию.

set interfaces openvpn <interface> server bridge disable

Отключите данный экземпляр.

set interfaces openvpn <interface> server bridge gateway <ipv4 address>

Настройте IP-адрес шлюза.

set interfaces openvpn <interface> server bridge start <ipv4 address>

Настройте первый IP-адрес в пуле для выдачи подключающимся клиентам.

set interfaces openvpn <interface> server bridge stop <ipv4 address>

Настройте последний IP-адрес в пуле для выдачи подключающимся клиентам.

set interfaces openvpn <interface> server bridge subnet-mask <ipv4 subnet mask>

Настройте маску подсети, передаваемую динамическим клиентам.

set interfaces openvpn <interface> server client <name>

Настройте имя Common Name (CN), указанное в сертификате клиента.

set interfaces openvpn <interface> server client <name> disable

Отключите соединение клиента.

set interfaces openvpn <interface> server client <name> ip <address>

Настройте IPv4/IPv6-адрес клиента.

set interfaces openvpn <interface> server client <name> push-route <subnet>

Настройте маршрут, который будет передаваться конкретному клиенту.

set interfaces openvpn <interface> server client <name> subnet <subnet>

Настройте фиксированную подсеть, которая будет маршрутизироваться с сервера к указанному клиенту.

Используется как директива OpenVPN iroute.

set interfaces openvpn <interface> server client-ip-pool start <address>

Настройте первый IP-адрес в подсети IPv4-пула, который будет динамически выделяться подключающимся клиентам.

set interfaces openvpn <interface> server client-ip-pool stop <address>

Настройте последний IP-адрес в подсети IPv4-пула, который будет динамически выделяться подключающимся клиентам.

set interfaces openvpn <interface> server client-ip-pool subnet <netmask>

Настройте маску подсети, передаваемую динамическим клиентам.

Используйте эту команду только для типа интерфейса TAP. Не используйте ее для мостовых интерфейсов.

set interfaces openvpn <interface> server client-ipv6-pool base <ipv6addr/bits>

Настройте пул IPv6-адресов для динамической выдачи клиентам.

set interfaces openvpn <interface> server domain-name <name>

Настройте суффикс DNS, который будет передаваться всем клиентам.

set interfaces openvpn <interface> server max-connections <1-4096>

Настройте максимальное количество подключений клиентов.

set interfaces openvpn <interface> server mfa totp challenge <enable | disable>

Если включено, openvpn-otp ожидает пароль в результате протокола вызова/ответа.

set interfaces openvpn <interface> server mfa totp digits <1-65535>

Настройте количество цифр для TOTP хэша.

По умолчанию: 6.

set interfaces openvpn <interface> server mfa totp drift <1-65535>

Настройте допустимое смещение времени в секундах.

По умолчанию: 0.

set interfaces openvpn <interface> server mfa totp slop <1-65535>

По умолчанию: 180.
