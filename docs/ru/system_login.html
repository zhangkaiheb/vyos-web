Управление входом/пользователями

По умолчанию, учетная запись пользователя VyOS (vyos), а также новые созданные учетные записи пользователей имеют полные привилегии конфигурации системы. Эти учетные записи получают привилегии sudo, что позволяет им выполнять команды от имени пользователя root.

VyOS поддерживает локальную аутентификацию и удаленную аутентификацию через RADIUS/ TACACS+.

Локальная аутентификация

set system login user <name> full-name “<string>”

Настройте реальное имя или описание для системного пользователя.

Если описание включает пробелы, заключите <string> в двойные кавычки.

Если пользователь <name> уже существует, команда обновляет текущее описание. Если нет, она создает нового пользователя с указанным описанием.

set system login user <name> authentication plaintext-password <password>

Настройте пароль для системного пользователя.

Введите пароль в виде обычного текста. При выполнении commit, VyOS хэширует пароль для безопасного хранения и удаляет значение в исходном виде.

Если пользователь <name> уже существует, команда обновляет текущий пароль. Если нет, она создает нового пользователя с указанным паролем в открытом виде.

set system login user <name> authentication encrypted-password <password>

Настройте предварительно зашифрованный пароль для системного пользователя.

Введите пароль в его зашифрованной форме. При выполнении commit, VyOS сохраняет это значение без изменений.

Если пользователь <name> уже существует, команда обновляет текущий пароль. Если нет, она создает нового пользователя с указанным предварительно зашифрованным паролем.

set system login user <name> authentication principal <principal>

Настройте принципал SSH для системного пользователя.

Введите принципал (строка, содержащаяся в сертификате SSH пользователя). При выполнении commit, VyOS сохраняет это сопоставление, позволяя пользователю войти, если сертификат, который он представляет, содержит этот принципал.

Если пользователь <name> уже существует, команда обновляет принципал. Если нет, она создает нового пользователя, связанного с указанным принципалом.

Если не настроено, принципал по умолчанию — <name>.

set system login user <name> disable

Отключить учетную запись системного пользователя.

VyOS блокирует учетную запись, запрещая пользователю войти.

Аутентификация по ключам

Аутентификация по ключам — рекомендуемый метод обеспечения безопасности доступа по SSH в VyOS. Она использует пару открытого/закрытого ключей для проверки личности пользователя без необходимости ввода пароля. Чтобы разрешить доступ, вы назначаете открытые ключи SSH учетным записям пользователей на маршрутизаторе, тогда как закрытые ключи остаются на локальных устройствах. VyOS позволяет назначать несколько открытых ключей SSH одному учетному запись пользователя, что полезно для доступа к маршрутизатору с разных устройств.

Создание пары ключей

Создайте пару ключей SSH на вашем локальном компьютере с помощью команды ssh-keygen. Это создает два файла:

  • Закрытый ключ (например, id_rsa): Остается на вашем локальном компьютере и никогда не должен быть передан.

  • Открытый ключ (например, id_rsa.pub): Используется для настройки учетной записи пользователя VyOS. По умолчанию он сохраняется в ~/.ssh/id_rsa.pub.

Каждый открытый ключ SSH состоит из трех частей, разделенных пробелами:

  • Тип алгоритма шифрования: ssh-rsa, ssh-ed25519 и т. д.

  • Ключ: Фактические данные (длинная строка, начинающаяся с AAAA...).

  • Комментарий: Идентификатор для вашей справки (например, user@host).

Только тип алгоритма шифрования и часть ключа необходимы для настройки записи авторизации в VyOS. Часть комментария является необязательной.

Работа SSH

Предупреждение

Строки SSH-ключей длинные. При копировании и вставке убедитесь, что ваш терминал не вставляет разрывы строк. Ключ должен быть введен как одна строка, чтобы работать правильно.

Настройка маршрутизатора

Чтобы настроить аутентификацию по открытым ключам SSH для учетной записи пользователя, выполните следующие две команды, используя тот же <identifier>:

set system login user <username> authentication public-keys <identifier> key <key>

Настройте открытый ключ SSH для учетной записи пользователя.

  • <identifier>: Уникальная метка, которая идентифицирует эту конкретную запись ключа.

  • <key>: Фактическая строка символов из вашего открытого ключа.

set system login user <username> authentication public-keys <identifier> type <type>

Настройте тип шифрования SSH-ключа.

Доступны следующие типы алгоритмов шифрования:

  • ecdsa-sha2-nistp256

  • ecdsa-sha2-nistp384

  • ecdsa-sha2-nistp521

  • ssh-dss

  • ssh-ed25519

  • ssh-rsa

Примечание

Чтобы назначить несколько открытых ключей SSH учетной записи пользователя, повторите вышеуказанные команды с уникальной меткой для каждого ключа.

set system login user <username> authentication public-keys <identifier> options <options>

Настройте конкретные ограничения или поведение для открытого ключа SSH.

<options>: Строка, разделенная запятыми, определяющая разрешения или ограничения для этого ключа.

Команда принимает стандартные параметры OpenSSH, перечисленные в файле ~/.ssh/authorized_keys на маршрутизаторе.

Чтобы включить символ " в строку параметров, используйте &quot;.

Например, чтобы ограничить разрешенные IP-адреса для открытого ключа SSH, используйте: from=&quot;10.0.0.0/24&quot;.

MFA на основе OTP

VyOS позволяет повысить безопасность доступа пользователей, включив OTP-based MFA для отдельных пользователей. Пользователи с OTP-based MFA должны ввести действительный OTP вместе со своим паролем при входе. Пользователи без OTP-based MFA используют стандартную аутентификацию.

set system login user <username> authentication otp key <key>

Настройте OTP-based MFA для пользователя.

<key>: Базовый ключ, закодированный в Base32. Этот ключ должен быть добавлен в приложение-аутентификатор пользователя для генерации действительных OTPs.

После настройки, пользователь должен ввести свой пароль, за которым следует действительный OTP для всех последующих входов.

Настройки OTP

set system login user <username> authentication otp rate-limit <limit>

Настройте количество OTP попыток аутентификации, разрешенных в заданный период времени.

Если это ограничение превышено, пользователь временно заблокирован.

Значение по умолчанию — 3 попытки. Допустимый диапазон — 1–10 попыток.

set system login user <username> authentication otp rate-time <seconds>

Настройте период времени, в секундах, для отслеживания OTP попыток аутентификации.

Значение по умолчанию — 30 секунд. Допустимый диапазон — 1–600 секунд.

set system login user <username> authentication otp window-size <size>

Настройте размер окна OTP для пользователя.

Размер окна OTP определяет количество одновременно допустимых OTPs, которые сервер аутентификации принимает. Это настройка предполагает, что новый токен генерируется каждые 30 секунд.

Значение по умолчанию — 3. Это позволяет 3 одновременных кода: код для текущего интервала 30 секунд, предыдущий код и следующий код. Это позволяет до 30 секунд смещения времени между сервером аутентификации и клиентом.

Если размер окна увеличен до 17, система разрешает 17 одновременных кодов (текущий код, 8 предыдущих кодов и 8 последующих кодов). Это позволяет смещение времени до 4 минут.

Допустимый диапазон — 1–21.

Аутентификация RADIUS

Для масштабных развертываний управление индивидуальными учетными записями пользователей на нескольких экземплярах VyOS неэффективно. VyOS поддерживает централизованную аутентификацию через RADIUS, объединяющую управление учетными записями пользователей на одном сервере.

Конфигурация

set system login radius server <address> key <secret>

Настройте RADIUS IP-адрес сервера и общий секрет.

Общий секрет используется для проверки идентичности роутера и шифрования паролей пользователей во время аутентификации.

Вы можете настроить несколько RADIUS серверов.

set system login radius server <address> port <port>

Настройте UDP-порт для связи с RADIUS сервером.

Порт по умолчанию — 1812.

set system login radius server <address> disable

Отключить RADIUS сервер из процесса аутентификации.

Отключение конкретного RADIUS сервера не удаляет его настройки (IP-адрес сервера и общий секрет).

set system login radius server <address> timeout <timeout>

Настройте продолжительность, в секундах, в течение которой роутер VyOS ждет ответа от RADIUS сервера после отправки запроса на аутентификацию.

Если сервер не отвечает в течение этого времени, роутер VyOS пытается подключиться к другому настроенному серверу или возвращается к локальной аутентификации.

set system login radius source-address <address>

Настройте IP-адрес источника, который использует роутер для RADIUS запросов на аутентификацию.

Рекомендуется использовать постоянный IP-адрес источника, так как серверы RADIUS обычно принимают запросы только от известных, доверенных IP-адресов.

Если не указано явно, роутер использует адрес выходного интерфейса, который может измениться (например, из-за сбоя линии), вызывая сбои в аутентификации.

set system login radius vrf <name>

Настройте роутер на отправку всех RADIUS запросов на аутентификацию через определенный VRF.

По умолчанию, запросы на аутентификацию RADIUS отправляются через глобальную таблицу маршрутизации.

Пример конфигурации

set system login radius server 192.168.0.2 key 'test-vyos'
set system login radius server 192.168.0.2 port '1812'
set system login radius server 192.168.0.2 timeout '5'
set system login radius source-address '192.168.0.1'

Если связь с RADIUS сервером не удается, роутер возвращается к локальной аутентификации пользователя. Во время этого процесса пользователи могут испытывать задержку входа, пока система ждет ответа от RADIUS запроса. Эта задержка зависит от значения, установленного в настройках таймаута.

Подсказка

Чтобы предоставить административные привилегии пользователям, аутентифицированным через RADIUS, сервер должен возвращать атрибут Cisco-AV-Pair, установленный в shell:priv-lvl=15. В противном случае, пользователи получают стандартные привилегии и не могут выполнять задачи конфигурации.

Аутентификация TACACS+

Помимо RADIUS, VyOS поддерживает TACACS+, который часто используется в крупных корпоративных средах.

В отличие от RADIUS, TACACS+ разделяет Аутентификацию, Авторизацию и Учет (AAA) на независимые процессы и шифрует весь объем пакета для повышения безопасности.

TACACS+ определен в RFC 8907.

Конфигурация

set system login tacacs server <address> key <secret>

Настройте IP-адрес сервера TACACS+ и общий секрет.

В отличие от RADIUS, который шифрует только пароли, TACACS+ шифрует весь объем пакета для повышения безопасности.

Вы можете настроить несколько TACACS+ серверов.

set system login tacacs server <address> port <port>

Настройте TCP-порт для связи с TACACS+ сервером.

Порт по умолчанию — 49.

set system login tacacs server <address> disable

Отключить TACACS+ сервер из процесса аутентификации.

Отключение конкретного TACACS+ сервера не удаляет его настройки (IP-адрес сервера и общий секрет).

set system login tacacs server <address> timeout <timeout>

Настройте продолжительность, в секундах, в течение которой роутер VyOS ждет ответа от TACACS+ сервера после отправки запроса на аутентификацию.

Если сервер не отвечает в течение этого времени, роутер VyOS пытается подключиться к другому настроенному серверу или возвращается к локальной аутентификации.

set system login tacacs source-address <address>

Настройте IP-адрес источника, который использует роутер для TACACS+ запросов на аутентификацию.

Рекомендуется использовать постоянный IP-адрес источника, так как серверы TACACS+ обычно принимают запросы только от известных, доверенных IP-адресов.

Если не указано явно, роутер использует адрес выходного интерфейса, который может измениться (например, из-за сбоя линии), вызывая сбои в аутентификации.

set system login tacacs vrf <name>

Настройте роутер на отправку всех TACACS+ запросов на аутентификацию через определенный VRF.

По умолчанию, запросы на аутентификацию TACACS+ отправляются через глобальную таблицу маршрутизации.

Пример конфигурации

set system login tacacs server 192.168.0.2 key 'test-vyos'
set system login tacacs server 192.168.0.2 port '49'
set system login tacacs source-address '192.168.0.1'

Если связь с TACACS+ сервером не удается, роутер возвращается к локальной аутентификации пользователя.

Баннеры входа

VyOS позволяет настраивать до входа и после входа баннеры. Баннеры до входа обычно используются для идентификации системы, юридических отказов или предупреждений о безопасности отображаются до аутентификации, а баннеры после входа предоставляют информацию о системе или операционные уведомления пользователям после входа.

set system login banner pre-login <message>

Настройте сообщение, которое будет показано пользователям до появления username и password запросов.

set system login banner post-login <message>

Настройте сообщение, которое будет показано пользователям после успешной аутентификации.

Примечание

Используйте \\n, чтобы вставить разрывы строк в многострочные сообщения баннера.

Ограничения сессий входа

set system login max-login-session <number>

Настройте максимальное количество одновременных сессий входа.

Примечание

Если вы ограничиваете одновременные сессии входа, вы также должны настроить сессию <timeout>. Это очищает неактивные сессии и предотвращает блокирование новых попыток входа.

set system login timeout <timeout>

Настройте таймаут сессии входа, в секундах.

Неактивные сессии входа завершаются после этого периода.

Примеры конфигурации

Пример 1: Многоключевой SSH с MFA и ограничениями источника

В этой конфигурации User1 и User2 оба используют учетную запись пользователя vyos, каждый с уникальным SSH-ключом. User1 ограничен аутентификацией только с одного IP-адреса.

Для обоих пользователей вход по паролю требует OTP основанного MFA.

set system login user vyos authentication public-keys 'User1' key "AAAAB3Nz...KwEW"
set system login user vyos authentication public-keys 'User1' type ssh-rsa
set system login user vyos authentication public-keys 'User1' options "from=&quot;192.168.0.100&quot;"

set system login user vyos authentication public-keys 'User2' key "AAAAQ39x...fbV3"
set system login user vyos authentication public-keys 'User2' type ssh-rsa

set system login user vyos authentication otp key OHZ3OJ7U2N25BK4G7SOFFJTZDTCFUUE2
set system login user vyos authentication plaintext-password vyos

Пример 2: Контейнеризированная реализация TACACS+ с резервированием.

В этой конфигурации маршрутизатор VyOS предоставляет свою инфраструктуру аутентификации, используя два контейнеризированных TACACS+ сервера (tacacs1 и tacacs2) на частной сети для резервирования.

Системные входы аутентифицируются по учетным данным, хранящимся внутри этих внутренних контейнеров, а не в локальной базе данных маршрутизатора.

Сначала загрузите образ в режиме операции:

add container image lfkeitel/tacacs_plus:latest

Далее, настройте контейнеры в режиме конфигурации:

set container network tac-test prefix '100.64.0.0/24'

set container name tacacs1 image 'lfkeitel/tacacs_plus:latest'
set container name tacacs1 network tac-test address '100.64.0.11'

set container name tacacs2 image 'lfkeitel/tacacs_plus:latest'
set container name tacacs2 network tac-test address '100.64.0.12'

set system login tacacs server 100.64.0.11 key 'tac_plus_key'
set system login tacacs server 100.64.0.12 key 'tac_plus_key'

commit

Теперь вы можете войти через SSH или консоль, используя учетные данные admin/admin, предоставленные образом контейнера.
