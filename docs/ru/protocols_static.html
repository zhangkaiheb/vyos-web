Статические

Статические маршруты — это ручные записи в базе данных маршрутизации (RIB) маршрутизатора, которые определяют, как трафик должен доставляться к определенным пунктам назначения. В отличие от динамических протоколов маршрутизации, статические маршруты не обновляются автоматически при изменении топологии сети.

Статические маршруты лучше всего подходят для простых сетевых топологий или для переопределения поведения динамического протокола маршрутизации для ограниченного числа маршрутов.

BIB хранит всю информацию о маршрутизации, включая ручные статические маршруты и любые динамически полученные маршруты. Из BIB маршрутизатор выводит одиночные маршруты для построения таблицы пересылки (FIB).

IPv4 одиночные маршруты

IPv4 одиночные маршруты направляют трафик, предназначенный для одного IPv4 хоста или подсети, к определенному следующему узлу. Используйте следующие команды, чтобы настроить IPv4 одиночные маршруты для определенной удаленной подсети.

set protocols static route <subnet> next-hop <address>

Настройте IP-адрес следующего узла для указанной подсети.

Вы можете настроить несколько IP-адресов следующего узла для одной и той же подсети назначения.

Пример:

set protocols static route 192.0.2.0/24 next-hop 10.0.0.254
set protocols static route <subnet> next-hop <address> disable

Отключите маршрут через указанный IP-адрес следующего узла.

Эта команда временно деактивирует маршрут, сохраняя при этом настроенную подсеть, адрес следующего узла и параметры расстояния.

Пример:

set protocols static route 192.0.2.0/24 next-hop 10.0.0.254 disable
set protocols static route <subnet> next-hop <address> distance <distance>

Настройте административное расстояние для маршрута через указанный IP-адрес следующего узла.

Маршруты с меньшим административным расстоянием имеют приоритет перед маршрутами с большим расстоянием.

Допустимый диапазон: 1–255. По умолчанию расстояние равно 1.

Примечание

Маршруты с расстоянием 255 отключены и не используются для передачи пакетов.

Пример:

set protocols static route 192.0.2.0/24 next-hop 10.0.0.254 distance 10

IPv4 BFD

BFD контролирует доступность IP-адреса следующего узла статического маршрута. Используйте следующие команды, чтобы настроить параметры BFD для ваших статических IPv4 маршрутов.

set protocols static route <subnet> next-hop <address> bfd

Включите мониторинг BFD для маршрута через указанный IP-адрес следующего узла.

Система использует IP-адрес следующего узла как целевой узел BFD.

Пример:

set protocols static route 192.0.2.0/24 next-hop 10.0.0.254 bfd
set protocols static route <subnet> next-hop <address> bfd profile <profile>

Примените настройки из заданного профиля BFD к сессии BFD, которая мониторит указанный IP-адрес следующего узла.

Пример:

set protocols static route 192.0.2.0/24 next-hop 10.0.0.254 bfd profile custom-profile
set protocols static route <subnet> next-hop <address> bfd multi-hop source-address <source-address>

Включите многоходовую сессию BFD для мониторинга доступности указанного IP-адреса следующего узла.

Система запускает сессию BFD с указанного локального исходного IPv4 адреса.

Пример:

set protocols static route 192.0.2.0/24 next-hop 10.0.0.254 bfd multi-hop source-address 172.16.1.1

Маршруты интерфейса DHCP

Маршруты интерфейса DHCP направляют трафик, предназначенный для одного IPv4 хоста или подсети, к шлюзу, полученному из интерфейса, включающего DHCP. Используйте следующую команду, чтобы настроить маршруты интерфейса DHCP.

set protocols static route <subnet> dhcp-interface <interface>

Настройте статический маршрут, который получает свой IP-адрес следующего узла из указанного интерфейса, включающего DHCP.

Пример:

set protocols static route 192.0.2.0/24 dhcp-interface eth0

IPv4 маршруты отбраковки

IPv4 маршруты отбраковки явно отбрасывают трафик, предназначенный для одного IPv4 хоста или подсети, и возвращают сообщение ICMP недостижимого назначения отправителю. Используйте следующие команды, чтобы настроить IPv4 маршруты отбраковки.

set protocols static route <subnet> reject

Настройте маршрут отбраковки для указанной подсети.

Система отбрасывает трафик, предназначенный для этой подсети, и возвращает сообщение ICMP недостижимого назначения отправителю.

Пример:

set protocols static route 192.0.2.0/24 reject
set protocols static route <subnet> reject distance <distance>

Настройте административное расстояние для маршрута отбраковки.

Маршруты с меньшим административным расстоянием имеют приоритет перед маршрутами с большим расстоянием.

Допустимый диапазон: 1–255.

Пример:

set protocols static route 192.0.2.0/24 reject distance 200
set protocols static route <subnet> reject tag <tag>

Настройте числовой тег для маршрута отбраковки.

Допустимый диапазон: 1–4294967295.

Пример:

set protocols static route 192.0.2.0/24 reject tag 100

IPv4 маршруты черной дыры

Маршруты черной дыры беззвучно отбрасывают трафик, предназначенный для определенной подсети. В отличие от маршрута отбраковки, который информирует отправителя сообщением ICMP недостижимого назначения, маршрут черной дыры отбрасывает пакеты без генерации любого ответа.

set protocols static route <subnet> blackhole

Настройте маршрут черной дыры для указанной подсети.

Система беззвучно отбрасывает совпадающие пакеты без отправки ICMP-ответа источнику.

Пример:

set protocols static route 10.0.0.0/8 blackhole
set protocols static route <subnet> blackhole distance <distance>

Настройте административное расстояние для маршрута черной дыры.

Маршруты с меньшим административным расстоянием имеют приоритет перед маршрутами с большим расстоянием.

Допустимый диапазон: 1–255.

Пример:

set protocols static route 10.0.0.0/8 blackhole distance 200
set protocols static route <subnet> blackhole tag <tag>

Настройте числовой тег для маршрута черной дыры.

Допустимый диапазон: 1–4294967295.

Пример:

set protocols static route 10.0.0.0/8 blackhole tag 100

Альтернативные таблицы маршрутизации

Альтернативные таблицы маршрутизации используются для реализации как Политико-ориентированной маршрутизации (PBR), так и Виртуальной маршрутизации и пересылки (VRF).
