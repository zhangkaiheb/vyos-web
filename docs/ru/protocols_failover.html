Failover

Маршруты failover настраиваются вручную и используются только тогда, когда целевой адрес доступен. Если целевой адрес перестает отвечать, VyOS удаляет маршрут из таблицы маршрутизации и снова добавляет его, когда целевой адрес восстанавливается.

Настройка

Используйте следующие команды для настройки маршрутов failover для определенного удаленного подсети <subnet>, доступной через следующий хоп <address>.

set protocols failover route <subnet> next-hop <address> check target <target-address>

Настройте IP-адрес цели проверки работоспособности.

Обычно это высокодоступный хост, находящийся либо в подсети назначения, либо в интернете.

Пример:

set protocols failover route 203.0.113.1/32 next-hop 10.217.37.254 check target 8.8.8.8
set protocols failover route <subnet> next-hop <address> check timeout <timeout>

Настройте интервал времени ожидания, в секундах, между проверками работоспособности цели.

Допустимый диапазон — 1–300 секунд. По умолчанию — 10 секунд.

Пример:

set protocols failover route 203.0.113.1/32 next-hop 10.217.37.254 check timeout 2
set protocols failover route <subnet> next-hop <address> check type <protocol>

Настройте протокол, используемый для проверки работоспособности.

Доступные протоколы:

  • icmp: VyOS отправляет два пакета ICMP echo request с таймаутом ответа 1 секунда. Проверка работоспособности успешна, если хотя бы один ответ получен.

  • arp: VyOS отправляет два запроса ARP с таймаутом ответа 1 секунда. Проверка работоспособности успешна, если хотя бы один ответ получен.

  • tcp: VyOS проверяет, открыт ли целевой TCP-порт. Проверка работоспособности успешна, если успешно установлено TCP-соединение с целевым портом.

По умолчанию используется протокол icmp.

Примечание

Если тип проверки установлен в tcp, необходимо также указать целевой TCP-порт.

Пример:

set protocols failover route 203.0.113.1/32 next-hop 10.217.37.254 check type tcp
set protocols failover route <subnet> next-hop <address> check port <port>

Настройте целевой TCP-порт для проверки работоспособности.

Этот параметр применяется только при настройке типа проверки как tcp.

Допустимый диапазон портов — 1–65535.

Пример:

set protocols failover route 203.0.113.1/32 next-hop 10.217.37.254 check port 443
set protocols failover route <subnet> next-hop <address> check policy <policy>

Настройте политику успешной проверки работоспособности для нескольких целей.

Доступные политики:

  • any-available: Проверка работоспособности успешна, если хотя бы одна из настроенных целей отвечает успешно.

  • all-available: Проверка работоспособности успешна только в том случае, если каждая настроенная цель отвечает успешно.

По умолчанию используется политика any-available.

Пример:

set protocols failover route 203.0.113.1/32 next-hop 10.217.37.254 check policy all-available
set protocols failover route <subnet> next-hop <address> interface <interface>

Настройте локальный интерфейс, используемый для достижения следующего хопа.

Этот параметр обязателен.

Пример:

set protocols failover route 203.0.113.1/32 next-hop 10.217.37.254 interface eth0
set protocols failover route <subnet> next-hop <address> metric <1-255>

Настройте метрику (стоимость) для маршрута failover.

Метрика определяет приоритет маршрута. Чем ниже значение метрики, тем более предпочтительный маршрут.

Значение по умолчанию — 1.

Пример:

set protocols failover route 203.0.113.1/32 next-hop 10.217.37.254 metric 50
set protocols failover route <subnet> next-hop <address> onlink

Настройте следующий хоп как достижимый через назначенный интерфейс, даже если <address> находится вне любой подсети, настроенной на этом интерфейсе.

Пример:

set protocols failover route 203.0.113.1/32 next-hop 10.217.37.254 onlink

Примеры

Маршрут failover с одним следующим хопом и проверкой работоспособности ICMP

В следующем примере настраивается маршрут failover для 203.0.113.1/32 через следующий хоп 192.0.2.1 на eth0. Следующий хоп контролируется проверками ICMP к 192.0.2.1 каждые 5 секунд, а маршрут устанавливается с метрикой 10.

set protocols failover route 203.0.113.1/32 next-hop 192.0.2.1 check target '192.0.2.1'
set protocols failover route 203.0.113.1/32 next-hop 192.0.2.1 check timeout '5'
set protocols failover route 203.0.113.1/32 next-hop 192.0.2.1 check type 'icmp'
set protocols failover route 203.0.113.1/32 next-hop 192.0.2.1 interface 'eth0'
set protocols failover route 203.0.113.1/32 next-hop 192.0.2.1 metric '10'

Проверьте маршрут:

vyos@vyos:~$ show ip route 203.0.113.1
Routing entry for 203.0.113.1/32
  Known via "kernel", distance 0, metric 10, best
  Last update 00:00:39 ago
  Flags: Selected
  Status: Installed
  * 192.0.2.1, via eth0, weight 1

Два маршрута failover с разными метриками

В следующем примере настраиваются два маршрута failover для 203.0.113.1/32, каждый через другой следующий хоп. Основной следующий хоп 192.0.2.1 достигается через eth0 с метрикой 10, а резервный следующий хоп 198.51.100.1 достигается через eth2 с метрикой 20. Оба следующих хопа контролируются проверками ICMP каждые 5 секунд.

Пока обе проверки работоспособности успешны, маршрут с меньшей метрикой через eth0 предпочитается. Если основной целевой адрес перестает отвечать, его маршрут удаляется из таблицы маршрутизации, и трафик переключается на 198.51.100.1 через eth2.

set protocols failover route 203.0.113.1/32 next-hop 192.0.2.1 check target '192.0.2.1'
set protocols failover route 203.0.113.1/32 next-hop 192.0.2.1 check timeout '5'
set protocols failover route 203.0.113.1/32 next-hop 192.0.2.1 check type 'icmp'
set protocols failover route 203.0.113.1/32 next-hop 192.0.2.1 interface 'eth0'
set protocols failover route 203.0.113.1/32 next-hop 192.0.2.1 metric '10'

set protocols failover route 203.0.113.1/32 next-hop 198.51.100.1 check target '198.51.100.99'
set protocols failover route 203.0.113.1/32 next-hop 198.51.100.1 check timeout '5'
set protocols failover route 203.0.113.1/32 next-hop 198.51.100.1 check type 'icmp'
set protocols failover route 203.0.113.1/32 next-hop 198.51.100.1 interface 'eth2'
set protocols failover route 203.0.113.1/32 next-hop 198.51.100.1 metric '20'

Проверьте маршруты:

vyos@vyos:~$ show ip route 203.0.113.1
Routing entry for 203.0.113.1/32
  Known via "kernel", distance 0, metric 10, best
  Last update 00:08:06 ago
  Flags: Selected
  Status: Installed
  * 192.0.2.1, via eth0, weight 1

Routing entry for 203.0.113.1/32
  Known via "kernel", distance 0, metric 20
  Last update 00:08:14 ago
  Flags: None
  Status: Installed
  * 198.51.100.1, via eth2, weight 1
