MPLS

MPLS — это метод передачи пакетов, который отличается от традиционной передачи по IP. Вместо выполнения поиска по IP-адресам маршрутизаторы MPLS передают трафик с использованием точных совпадений при поиске по меткам MPLS, вставленным между заголовками уровня 2 (Ethernet) и уровня 3 (IP).

Метки MPLS могут быть присвоены статически или динамически. Этот раздел фокусируется на динамическом распределении меток с использованием протоколов распределения меток, таких как LDP и RSVP-TE, или через расширения SR для OSPF или IS-IS.

Эти протоколы устанавливают односторонний путь, называемый LSP в сети. Когда пакет попадает в сеть MPLS, входной маршрутизатор добавляет метку MPLS к нему на основе назначения и передает пакет по LSP. Каждый промежуточный маршрутизатор использует входную метку для поиска исходящего интерфейса и следующей значения метки, меняет метку и передает пакет на этом интерфейсе. Выходной маршрутизатор удаляет метку и передает исходный пакет с помощью обычного IP-маршрутизации.

Поддержка MPLS в VyOS

Поддержка MPLS в VyOS находится в разработке, поэтому ее функциональные возможности сейчас ограничены. Базовая передача MPLS работает, так как лежащая в основе стек маршрутизации FRR поддерживает RFC 3031.

Поддерживаемые функции:

  • LDP: Реализовано в соответствии с RFC 5036.

Примечание

Другие связанные стандарты LDP включают RFCs 6720, 6667, 5919, 5561, и 7552.

Текущие ограничения:

  • MPLS VPNs: Пока нет поддержки MPLS-активных служб VPN, таких как L2VPNs и mVPNs.

  • RSVP-TE: Не поддерживается, поскольку лежащий в основе стек FRR в настоящее время не реализует его.

Протокол распределения меток (LDP)

MPLS поддерживает различные протоколы для создания путей. VyOS реализует LDP через лежащий в основе стек маршрутизации FRR, согласно RFC 5036.

LDP — это TCP-основанный протокол сигнализации MPLS, который динамически распределяет метки для создания маршрутов с переключением меток. Это не протокол маршрутизации и зависит от существующих протоколов маршрутизации для принятия решений о передаче и общения с другими маршрутами, поддерживающими LDP.

Для обмена объявлениями о метках LDP устанавливает TCP-сессии с автоматически обнаруженными или статически настроенными соседями. Каждая сессия формируется с использованием транспортного адреса пира, который должен присутствовать в таблице маршрутизации и постоянно достижим.

Примечание

Рекомендуется использовать один и тот же адрес для идентификатора маршрутизатора LDP и транспортного адреса обнаружения. Для работы LDP в VyOS оба параметра должны быть явно настроены.

Примечание

LDP не имеет механизма для обновления существующей сессии. Чтобы применить изменение конфигурации или изменение согласованных возможностей сессии, необходимо перезапустить соседа LDP на локальном маршрутизаторе.

Конфигурация

set protocols mpls interface <interface>

Включить MPLS на указанном интерфейсе.

Пример:

set protocols mpls interface eth1
set protocols mpls parameters no-propagate-ttl

Отключить распространение TTL IP в заголовок MPLS при установке метки.

Пример:

set protocols mpls parameters no-propagate-ttl
set protocols mpls parameters maximum-ttl <1-255>

Настроить максимальное значение TTL для пакетов MPLS.

Это значение используется, когда TTL не распространяется из заголовка IP. По умолчанию 255.

Пример:

set protocols mpls parameters maximum-ttl 15
set protocols mpls ldp interface <interface>

Включить LDP на указанном интерфейсе.

Пример:

set protocols mpls ldp interface eth1
set protocols mpls ldp interface <interface> disable-establish-hello

Отключить запускаемое сообщение Hello, которое маршрутизатор отправляет на указанном интерфейсе в ответ на получение LDP Hello от пира.

Пример:

set protocols mpls ldp interface eth0 disable-establish-hello
set protocols mpls ldp router-id <address>

Настроить IP-адрес, используемый как идентификатор маршрутизатора LDP для локального устройства.

Пример:

set protocols mpls ldp router-id 192.0.2.1
set protocols mpls ldp discovery transport-ipv4-address <address>

Настроить IPv4-транспортный адрес для соединений LDP IPv4.

Пример:

set protocols mpls ldp discovery transport-ipv4-address 192.0.2.1
set protocols mpls ldp discovery transport-ipv6-address <address>

Настроить IPv6-транспортный адрес для соединений LDP IPv6.

Пример:

set protocols mpls ldp discovery transport-ipv6-address 2001:db8::1
set protocols mpls ldp neighbor <ipv4-address> password <password>

Настроить аутентификацию для сессии LDP с указанным пиром.

Примечание

Для успешной установки сессии оба пира должны быть настроены с тем же паролем.

Пример:

set protocols mpls ldp neighbor 192.0.2.2 password mysharedsecret
set protocols mpls ldp neighbor <ipv4-address> session-holdtime <15-65535>

Настроить время удержания сессии LDP, в секундах,advertised to the specified neighbor.

Пир должен быть перезагружен, чтобы это изменение вступило в силу.

Пример:

set protocols mpls ldp neighbor 192.0.2.2 session-holdtime 180
set protocols mpls ldp neighbor <ipv4-address> ttl-security <disable | 1-254>

Настроить безопасность TTL (GTSM) для сессии LDP с указанным пиром.

Используйте disable, чтобы отключить безопасность TTL, или установите значение количества хопов (1-254), чтобы ограничить принимаемые входящие пакеты на основе их TTL.

Пример:

set protocols mpls ldp neighbor 192.0.2.2 ttl-security 5
set protocols mpls ldp discovery hello-ipv4-interval <1-65535>

Настроить интервал, в секундах, с которым маршрутизатор отправляет сообщения Hello IPv4 LDP.

Пример:

set protocols mpls ldp discovery hello-ipv4-interval 5
set protocols mpls ldp discovery hello-ipv4-holdtime <1-65535>

Настроить время удержания, в секундах,advertised в сообщениях Hello IPv4 LDP.

Пример:

set protocols mpls ldp discovery hello-ipv4-holdtime 15
set protocols mpls ldp discovery hello-ipv6-interval <1-65535>

Настроить интервал, в секундах, с которым маршрутизатор отправляет сообщения Hello IPv6 LDP.

Пример:

set protocols mpls ldp discovery hello-ipv6-interval 5
set protocols mpls ldp discovery hello-ipv6-holdtime <1-65535>

Настроить время удержания, в секундах,advertised в сообщениях Hello IPv6 LDP.

Пример:

set protocols mpls ldp discovery hello-ipv6-holdtime 15
set protocols mpls ldp discovery session-ipv4-holdtime <15-65535>

Настроить время удержания сессии LDP, в секундах,advertised в сообщениях Initialization IPv4 LDP.

Пример:

set protocols mpls ldp discovery session-ipv4-holdtime 180
set protocols mpls ldp discovery session-ipv6-holdtime <15-65535>

Настроить время удержания сессии LDP, в секундах,advertised в сообщениях Initialization IPv6 LDP.

Показать LIB.

show mpls ldp binding <prefix>

Параметр <prefix> принимает IPv4-префикс (x.x.x.x/x) или IPv6 префикс (h:h:h:h:h:h:h:h/h).

Пример

Следующая конфигурация настраивает базовый маршрутизатор, поддерживающий MPLS LDP. OSPF используется как underlying IGP для обеспечения достижимости между адресами loopback LDP пиров, которые затем используются как транспортные адреса LDP и идентификаторы маршрутизаторов. Передача MPLS и LDP включены на интерфейсе, подключенном к сети.

set protocols ospf area 0 network '192.0.2.1/32'
set protocols ospf area 0 network '192.0.2.4/31'
set protocols ospf parameters router-id '192.0.2.1'
set protocols mpls interface 'eth1'
set protocols mpls ldp discovery transport-ipv4-address '192.0.2.1'
set protocols mpls ldp interface 'eth1'
set protocols mpls ldp interface 'lo'
set protocols mpls ldp router-id '192.0.2.1'
set interfaces ethernet eth1 address '192.0.2.5/31'
set interfaces loopback lo address '192.0.2.1/32'

Примечание

Этот пример предполагает роль транзитного (P-роутера): передача MPLS включена только на транзитном интерфейсе, а не на loopback. Если маршрутизатору нужно завершить трафик, закодированный в MPLS на своем loopback (роль PE-роутера), также настройте set protocols mpls interface 'lo'.

Примените ту же конфигурацию на пире LDP (используя собственные адреса loopback и транзитного интерфейса), чтобы установить базовую сессию LDP.
