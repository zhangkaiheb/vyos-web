VRF

VRF устройства, совместно с правилами ip, позволяют создавать виртуальные домены маршрутизации и пересылки (так называемые VRF, VRF-lite) в стеке сети Linux. Одним из примеров использования является проблема многопользовательского доступа, где у каждого пользователя есть свои уникальные таблицы маршрутизации и, по крайней мере, разные шлюзы по умолчанию.

Конфигурация

Создается устройство VRF с привязанной таблицей маршрутизации. Затем сетевые интерфейсы привязываются к устройству VRF.

set vrf name <name> table <id>

Создайте новый экземпляр VRF с именем <name> и <id>. Имя используется при помещении отдельных интерфейсов в VRF.

Примечание

Идентификатор таблицы маршрутизации не может быть изменен после его присвоения. Он может быть изменен только путем удаления и повторного добавления экземпляра VRF.

set vrf bind-to-all

По умолчанию диапазон привязок портов для непривязанных сокетов ограничен стандартным VRF. То есть, он не будет соответствовать пакетам, поступающим на интерфейсы, привязанные к VRF, и процессы могут привязываться к одному порту, если они привязываются к VRF.

Сервисы TCP и UDP, работающие в контексте стандартного VRF (то есть, не привязанные к какому-либо устройству VRF), могут работать во всех доменах VRF, активируя эту опцию.

Zebra/Ядро маршрутизации фильтрации

Zebra поддерживает списки префиксов и карты маршрутов для соответствия маршрутам, полученным от других компонентов FRR. Средства разрешения/запрета, предоставляемые этими командами, могут использоваться для фильтрации маршрутов, которые Zebra установит в ядре.

set vrf <name> ip protocol <protocol> route-map <route-map>

Применить фильтр карты маршрута к маршрутам для указанного протокола.

Следующие протоколы могут быть использованы: any, babel, bgp, eigrp, isis, ospf, rip, static

Примечание

Если вы выберете any в качестве параметра, это вызовет все протоколы, отправляющие маршруты в Zebra.

set vrf <name> ipv6 protocol <protocol> route-map <route-map>

Применить фильтр карты маршрута к маршрутам для указанного протокола.

Следующие протоколы могут быть использованы: any, babel, bgp, isis, ospfv3, ripng, static

Примечание

Если вы выберете any в качестве параметра, это вызовет все протоколы, отправляющие маршруты в Zebra.

Отслеживание следующего узла

По умолчанию отслеживание следующего узла решается через маршрут по умолчанию. Это включено по умолчанию для традиционного профиля FRR, который мы используем. Его можно отключить, если вы не хотите, например, позволить BGP взаимодействовать через маршрут по умолчанию.

set vrf name <name> ip nht no-resolve-via-default

Не разрешать IPv4 отслеживание следующего узла через маршрут по умолчанию. Этот параметр настраивается для каждого VRF, поэтому команда также доступна в подузле VRF.

set vrf name <name> ipv6 nht no-resolve-via-default

Не разрешать IPv6 отслеживание следующего узла через маршрут по умолчанию. Этот параметр настраивается для каждого VRF, поэтому команда также доступна в подузле VRF.

Интерфейсы

При использовании VRF необходимо не только создать VRF, но и сам VRF должен быть назначен интерфейсу.

set interfaces <dummy | ethernet | bonding | bridge | pppoe> <interface> vrf <name>

Назначьте интерфейс, идентифицированный как <interface>, VRF с именем <name>.

Маршрутизация

Примечание

VyOS 1.4 (sagitta) ввел поддержку динамической маршрутизации для VRF.

В настоящее время динамическая маршрутизация поддерживается для следующих протоколов:

  • BGP

  • routing-isis

  • OSPF

  • OSPFv3 (IPv6)

  • Static

Конфигурация CLI такая же, как упомянутая в вышеуказанных статьях. Единственное отличие заключается в том, что каждый используемый протокол маршрутизации должен быть предварен командой vrf name <name>.

Пример

Следующие команды потребуются для установки параметров для заданного динамического протокола маршрутизации внутри заданного VRF:

  • BGP: set vrf name <name> protocols bgp ...

  • routing-isis: set vrf name <name> protocols isis ...

  • OSPF: set vrf name <name> protocols ospf ...

  • OSPFv3 (IPv6): set vrf name <name> protocols ospfv3 ...

  • Static: set vrf name <name> protocols static ...

Сервисы

В настоящее время следующие сервисы могут быть созданы изолированно в VRF

  • DHCP Server

Конфигурация CLI такая же, как упомянутая в вышеуказанных статьях. Единственное отличие заключается в том, что каждый используемый сервис должен быть предварен командой vrf name <name>.

Пример

Следующие команды потребуются для установки параметров для заданного сервиса внутри заданного VRF:

  • DHCP Server: set vrf name <name> service dhcp-server ...

  • DHCP Server: set vrf name <name> service dhcpv6-server ...

ping <host> vrf <name>

Команда ping используется для тестирования того, достижим ли сетевой хост.

Ping использует обязательный пакет ECHO_REQUEST протокола ICMP, чтобы вызвать ответ ECHO_RESPONSE от хоста или шлюза. Пакеты ECHO_REQUEST (пинги) будут иметь IP и заголовок ICMP, за которым следует «struct timeval» и произвольное количество байтов заполнения, используемых для заполнения пакета.

При диагностике с помощью ping, вы должны сначала запустить его на локальном хосте, чтобы убедиться, что локальный сетевой интерфейс работает. Затем продолжите с хостами и шлюзами, которые находятся дальше по пути к вашему назначению. Рассчитываются статистика времени往返 и потери пакетов.

Дублирующиеся пакеты не включаются в расчет потери пакетов, хотя время往返 этих пакетов используется для расчета минимального/среднего/максимального времени往返.

Примечание

Отображает маршрут, который пакеты проходят к сетевому хосту, используя экземпляр VRF, идентифицированный как <name>. При использовании опции IPv4 или IPv6 отображает маршрут, который пакеты проходят к заданному адресу IP хоста. Эта опция полезна, когда хост указан как имя, а не как IP-адрес.

Присоединяется к заданному VRF. Это откроет новую подоболочку внутри указанного VRF.

Подпись изменится, чтобы отразить это изменение в режимах конфигурации и операционного режима.

Пример

Перелив маршрутов VRF

Следующая примерная топология была создана с использованием EVE-NG.

  • PC1 находится в default VRF и действует, например, как «файловый сервер»

  • PC2 находится в VRF blue, который является отделом разработки

  • PC3 и PC4 подключены к устройству моста на маршрутизаторе R1, который находится в VRF red. Допустим, это отдел кадров.

  • R1 управляется через сеть out-of-band, которая находится в VRF mgmt

Конфигурация

set interfaces bridge br10 address '10.30.0.254/24'
set interfaces bridge br10 member interface eth3
set interfaces bridge br10 member interface eth4
set interfaces bridge br10 vrf 'red'

set interfaces ethernet eth0 address 'dhcp'
set interfaces ethernet eth0 vrf 'mgmt'
set interfaces ethernet eth1 address '10.0.0.254/24'
set interfaces ethernet eth2 address '10.20.0.254/24'
set interfaces ethernet eth2 vrf 'blue'

set protocols static route 10.20.0.0/24 interface eth2 vrf 'blue'
set protocols static route 10.30.0.0/24 interface br10 vrf 'red'

set service ssh disable-host-validation
set service ssh vrf 'mgmt'

set system name-server 'eth0'

set vrf name blue protocols static route 10.0.0.0/24 interface eth1 vrf 'default'
set vrf name blue table '3000'
set vrf name mgmt table '1000'
set vrf name red protocols static route 10.0.0.0/24 interface eth1 vrf 'default'
set vrf name red table '2000'

L3VPN VRFs

L3VPN VRFs bgpd поддерживает для IPv4 RFC 4364 и IPv6 RFC 4659. L3VPN маршруты и связанные с ними метки MPLS VRF могут быть распределены в соседей VPN SAFI в обычном, то есть, не VRF, экземпляре BGP. Метки MPLS VRF достигаются с помощью основных меток MPLS, которые распределяются с помощью LDP или BGP помеченного однонаправленного передачи. bgpd также поддерживает перелив маршрутов между VRF.

Перелив маршрутов VRF

BGP маршруты могут быть скопированы (то есть, скопированы) между RIB одиночного адреса и RIB SAFI VPN для использования в L3VPNs на основе MPLS. Одиночные маршруты также могут быть скопированы между любыми VRF (включая RIB одиночного адреса обычного экземпляра BGP). Также доступен короткий синтаксис для указания перелива из одного VRF в другой VRF, используя RIB VPN обычного экземпляра как промежуточную точку. Общее применение функции VRF-VRF — соединение частной области маршрутизации клиента с услугой VPN поставщика. Перелив настраивается с точки зрения отдельного VRF: импорт относится к маршрутам, скопированным из VPN в одиночный VRF, тогда как экспорт относится к маршрутам, скопированным из одиночного VRF в VPN.

Примечание

Маршруты, экспортированные из одиночного VRF в RIB VPN, должны быть дополнены двумя параметрами:

RD / RTLIST

Конфигурация для этих экспортируемых маршрутов должна, по крайней мере, указывать эти два параметра.

Конфигурация

Конфигурация перелива маршрутов между RIB одиночного адреса и RIB SAFI VPN обычного VRF осуществляется с помощью команд в контексте VRF адресной семьи.

set vrf name <name> protocols bgp address-family <ipv4-unicast|ipv6-unicast> rd vpn export <asn:nn|address:nn>

Указывает идентификатор маршрута, который будет добавлен к маршруту, экспортируемому из текущего одиночного VRF в VPN.

set vrf name <name> protocols bgp address-family <ipv4-unicast|ipv6-unicast> route-target vpn <import|export|both> [RTLIST]

Указывает список целевых маршрутов, который будет прикреплен к маршруту (экспорт) или список целевых маршрутов, которые будут соответствовать (импорт) при экспорте/импорте между текущим одиночным VRF и VPN. RTLIST — это список разделенных пробелами целевых маршрутов, которые являются значениями расширенных сообщений BGP, описанными в Атрибуте расширенных сообщений.

set vrf name <name> protocols bgp address-family <ipv4-unicast|ipv6-unicast> label vpn export <0-1048575|auto>

Включает метку MPLS, которая будет прикреплена к маршруту, экспортируемому из текущего одиночного VRF в VPN. Если указанное значение равно auto, значение метки автоматически присваивается из пула.

set vrf name <name> protocols bgp address-family <ipv4-unicast|ipv6-unicast> label vpn allocation-mode per-nexthop

Выбирает, как метки распределяются в данном VRF. По умолчанию выбирается режим per-vrf, и одна метка используется для всех префиксов из VRF. Per-nexthop будет использовать уникальную метку для всех префиксов, доступных через один и тот же следующий узел.

set vrf name <name> protocols bgp address-family <ipv4-unicast|ipv6-unicast> route-map vpn <import|export> [route-map <name>]

Указывает необязательную карту маршрута, которая применяется к маршрутам, импортируемым или экспортируемым между текущим одиночным VRF и VPN.

set vrf name <name> protocols bgp address-family <ipv4-unicast|ipv6-unicast> <import|export> vpn

Включает импорт или экспорт маршрутов между текущим одиночным VRF и VPN.

set vrf name <name> protocols bgp address-family <ipv4-unicast|ipv6-unicast> import vrf <name>

Короткий синтаксис для указания автоматического перелива из VRF VRFNAME в текущий VRF с использованием RIB VPN как промежуточной точки. RD и RT автоматически выводятся и не должны указываться явно для исходного или целевого VRF.

set vrf name <name> protocols bgp address-family <ipv4-unicast|ipv6-unicast> route-map vrf import [route-map <name>]

Указывает необязательную карту маршрута, которая применяется к маршрутам, импортируемым из VRF.

set vrf name <name> protocols bgp interface <interface> mpls forwarding

Возможно разрешить установку VPN префиксов без транспортных меток. Эта конфигурация установит префиксы VPN, происходящие от сессии e-bgp, и с прямым следующим узлом.

Операция
