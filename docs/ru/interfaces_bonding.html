Объединение интерфейсов / агрегирование линий

Интерфейс объединения объединяет несколько сетевых интерфейсов в один логический интерфейс (называемый объединением, LAG, EtherChannel или портовым каналом).

Поведение интерфейса объединения зависит от выбранного режима. Режимы обеспечивают либо отказоустойчивость, либо комбинацию балансировки нагрузки и отказоустойчивости. Кроме того, интерфейс объединения можно настроить для мониторинга целостности соединения.

Настройка

Общая конфигурация интерфейса

set interfaces bonding <interface> address <address | dhcp | dhcpv6>

Настройте интерфейс с одним или несколькими IP-адресами.

Доступны следующие варианты:

  • address: Назначьте один или несколько IPv4 или IPv6 адресов интерфейсу. Например, используйте 192.0.2.1/24 для IPv4 или 2001:db8::1/64 для IPv6.

  • dhcp: Интерфейс получает IPv4-адрес от DHCP-сервера на той же сетевой подсети.

  • dhcpv6: Интерфейс получает IPv6-адрес от DHCPv6-сервера на той же сетевой подсети.

Примечание

Если интерфейс получает IPv4-адрес через DHCP, и необходимы специальные настройки до/после получения IP-адреса, используйте предоставленные скрипты-хуки:

  • /config/scripts/dhcp-client/pre-hooks.d/

  • /config/scripts/dhcp-client/post-hooks.d/

Пример:

set interfaces bonding bond0 address 192.0.2.1/24
set interfaces bonding bond0 address 2001:db8::1/64
set interfaces bonding bond0 address dhcp
set interfaces bonding bond0 address dhcpv6
set interfaces bonding <interface> description <description>

Настройте ясное, описательное имя интерфейса.

Это имя появляется в команде show interfaces и инструментах мониторинга на основе SNMP.

Пример:

set interfaces bonding bond0 description 'This is an interface running on VyOS.'
set interfaces bonding <interface> disable

Отключите интерфейс.

Интерфейс будет установлен в состояние административно выключенное (A/D).

Пример:

set interfaces bonding bond0 disable
set interfaces bonding <interface> disable-flow-control

Отключите управление потоком Ethernet (стандарт IEEE 802.3x pause frames) на интерфейсе.

Управление потоком Ethernet, определенное стандартом IEEE 802.3x, временно прекращает передачу данных, чтобы предотвратить потерю пакетов при перегрузке сети. Например, когда отправитель передает данные быстрее, чем получатель может их обработать.

Отключение управления потоком Ethernet означает, что интерфейс не будет сигнализировать подключенному устройству о приостановке передачи и будет удалять пакеты, если перегружен.

Пример:

set interfaces bonding bond0 disable-flow-control
set interfaces bonding <interface> disable-link-detect

Отключите обнаружение физического изменения состояния интерфейса, например, когда кабель отсоединен.

По умолчанию интерфейс обнаруживает физические изменения состояния.

Пример:

set interfaces bonding bond0 disable-link-detect
set interfaces bonding <interface> mac <xx:xx:xx:xx:xx:xx>

Настройте пользовательский MAC-адрес на интерфейсе.

Пример:

set interfaces bonding bond0 mac '00:53:01:02:03:04'
set interfaces bonding <interface> mtu <mtu>

Настройте MTU на интерфейсе.

Это значение определяет максимальный размер пакета, в байтах, который интерфейс передает без фрагментации.

Пример:

set interfaces bonding bond0 mtu 1600
set interfaces bonding <interface> ip adjust-mss <mss | clamp-mss-to-pmtu>

Настройте MSS объявленный в исходящих TCP SYN-пакетах на указанном интерфейсе.

При ограничении значения MSS в пакетах TCP SYN вы явно информируете удаленную сторону, что она не должна отправлять пакеты большего размера. Это предотвращает проблемы с соединением, когда PMTUD не работает.

Доступны следующие варианты:

  • mss: Устанавливает MSS в конкретное значение, в байтах. Используйте этот вариант, если нужно принудительно установить конкретное значение MSS, например, для устранения проблем с подключением или соответствия требованиям сети.

  • clamp-mss-to-pmtu: Роутер автоматически рассчитывает MSS как MTU интерфейса минус 40 байт для IPv4 (20 байт для заголовка IPv4 и 20 байт для заголовка TCP). Этот вариант рекомендуется для автоматической установки правильного значения.

set interfaces bonding <interface> ip arp-cache-timeout

Настройте, как долго ARP-запись остается действительной после изучения сопоставления IP-адреса и MAC-адреса на этом интерфейсе.

По умолчанию длительность составляет 30 секунд.

ARP-запись остается действительной, если она получает положительный ответ от протоколов верхнего уровня.

Пример:

set interfaces bonding bond0 ip arp-cache-timeout 180
set interfaces bonding <interface> ip disable-arp-filter

Настройте фильтрацию ARP на этом интерфейсе.

Стандартное поведение: Ядро отвечает на запросы ARP на этом интерфейсе только в том случае, если трафик будет маршрутизироваться обратно к отправителю ARP через этот конкретный интерфейс.

Если настроено: Ядро отвечает на запросы ARP на этом интерфейсе для любого IP-адреса, настроенного на локальном хосте, независимо от того, какой конкретный интерфейс этому IP-адресу назначен, и независимо от таблицы маршрутизации. Это отражает концепцию Linux, согласно которой IP-адреса принадлежат хосту, а не отдельным интерфейсам.

Пример:

set interfaces bonding bond0 ip disable-arp-filter
set interfaces bonding <interface> ip disable-forwarding

Настройте интерфейс для работы в режиме хоста или роутера.

Если настроено, интерфейс переключается в режим хоста, и IPv4-пересылка отключена на нем.

Пример:

set interfaces bonding bond0 ip disable-forwarding
set interfaces bonding <interface> ip enable-directed-broadcast

Настройте, будут ли передаваться пакеты направленной широковещательной передачи, полученные на этом интерфейсе.

Стандартное поведение: Пакеты направленной широковещательной передачи отбрасываются.

Если настроено: Пакеты направленной широковещательной передачи передаются всем хостам на подсети назначения, как определено в RFC 1812 и RFC 2644.

Пример:

set interfaces bonding bond0 ip enable-directed-broadcast
set interfaces bonding <interface> ip enable-arp-accept

Настройте, как обрабатывать бесплатные ARP на этом интерфейсе.

Если настроено, IP-адреса добавляются в таблицу ARP на основе бесплатных ARP-запросов или ответов.

Примечание

Если в таблице ARP уже есть IP-адрес из бесплатного ARP, его запись обновляется независимо от того, настроено ли это настройка.

Пример:

set interfaces bonding bond0 ip enable-arp-accept
set interfaces bonding <interface> ip enable-arp-announce

Настройте выбор источника IP-адреса для запросов ARP на этом интерфейсе.

Стандартное поведение: Ядро может использовать любой IP-адрес, которым владеет хост, в качестве источника IP-адреса в запросах ARP на этом интерфейсе.

Если настроено: Ядро сначала пытается выбрать источник IP-адреса, настроенный на интерфейсе, который совпадает с подсетью цели. Если такой подсети нет, ядро выбирает IP-адрес, который обычно используется (на основе таблицы маршрутизации для достижения цели).

Пример:

set interfaces bonding bond0 ip enable-arp-announce
set interfaces bonding <interface> ip enable-arp-ignore

Настройте, какие запросы ARP будут игнорироваться на этом интерфейсе.

Стандартное поведение: Ядро отвечает на запросы ARP для любых локальных IP-адресов, независимо от того, к какому интерфейсу они привязаны.

Если настроено: Ядро отвечает на запросы ARP только в том случае, если целевой IP-адрес привязан к этому конкретному интерфейсу.

Пример:

set interfaces bonding bond0 ip enable-arp-ignore
set interfaces bonding <interface> ip enable-proxy-arp

Настройте прокси-ARP на этом интерфейсе.

Если настроено, роутер (ядро) перехватывает запросы ARP для не локальных IP-адресов и отвечает MAC-адресом интерфейса, который получил запрос. Последующие пакеты, предназначенные этим IP-адресам, перенаправляются на их фактические цели на удаленных подсетях.

Пример:

set interfaces bonding bond0 ip enable-proxy-arp
set interfaces bonding <interface> ip proxy-arp-pvlan

Настройте локальный прокси-ARP на интерфейсе.

Если настроено, роутер (ядро) отвечает на запросы ARP на этом VLAN-интерфейсе, даже если целевой IP-адрес находится на той же подсети и интерфейсе.

Это используется для поддержки требований изоляции сети (RFC 3069) для частных VLAN (PVLAN). В конфигурациях PVLAN, хосты на изолированных портах не могут напрямую общаться друг с другом на уровне 2, но могут общаться с шлюзом.

Посредством ответа на запросы ARP между хостами своим MAC-адресом, роутер направляет трафик между хостами через себя вместо прямого взаимодействия между хостами.

Примечание

Эта команда работает самостоятельно и не требует включения стандартного прокси-ARP на интерфейсе.

Локальный прокси-ARP также известен как:

  • VLAN-агрегация (RFC 3069).

  • Частная VLAN (Cisco, Allied Telesyn).

  • Фильтрация порта или изоляция порта (Hewlett-Packard).

  • Перенаправление MAC (Ericsson).

set interfaces bonding <interface> ip source-validation <strict | loose | disable>

Настройте проверку исходного IP-адреса с использованием RPF на этом интерфейсе, как указано в RFC 3704.

Доступны следующие варианты:

  • strict: Каждый входящий пакет проверяется на соответствие FIB. Если интерфейс не является лучшим маршрутом обратно к этому источнику, проверка завершается неудачей, и пакет удаляется.

  • loose: Каждый входящий пакет проверяется на соответствие FIB. Если IP-адрес недоступен через любой интерфейс, проверка завершается неудачей.

  • disable: Не производится проверка исходного IP-адреса. Все входящие пакеты принимаются.

RFC 3704 рекомендует включить строгий режим для предотвращения спуфинга IP, такого как DDoS-атаки. Для асимметричных или других сложных сценариев маршрутизации используйте строгий режим.

set interfaces bonding <interface> ipv6 address autoconf

Настройте интерфейс для автоматического получения IPv6-адреса с использованием SLAAC, как указано в RFC 4862.

Хосты IPv6 могут настраивать себя автоматически, когда подключены к IPv6-сети с использованием протокола обнаружения соседей через ICMPv6-сообщения о маршрутизации. При первом подключении к сети хост отправляет многоадресное сообщение о запросе маршрутизации на локальной подсети для получения параметров своей конфигурации. Маршрутизатор отвечает пакетом объявления маршрутизации, содержащим параметры конфигурации сетевого уровня.

Примечание

Этот метод автоматически отключает передачу IPv6-трафика на интерфейсе.

Пример:

set interfaces bonding bond0 ipv6 address autoconf
set interfaces bonding <interface> ipv6 address eui64 <prefix>

Настройте интерфейс для назначения себе IPv6-адреса с использованием метода EUI-64 , как указано в RFC 4291.

Пример:

set interfaces bonding bond0 ipv6 address eui64 2001:db8:beef::/64
set interfaces bonding <interface> ipv6 address no-default-link-local

Отключите автоматическое назначение локального IPv6-адреса этому интерфейсу.

Пример:

set interfaces bonding bond0 ipv6 address no-default-link-local
set interfaces bonding <interface> ipv6 disable-forwarding

Настройте интерфейс для работы в режиме хоста или роутера.

Если настроено, интерфейс переключается в режим хоста, и IPv6-пересылка отключена на нем.

Пример:

set interfaces bonding bond0 ipv6 disable-forwarding
set interfaces bonding <interface> ipv6 adjust-mss <mss | clamp-mss-to-pmtu>

Настройте MSS объявляемый в исходящих TCP SYN-пакетах на указанном интерфейсе.

Ограничение значения MSS в пакетах TCP SYN позволяет явно информировать удалённую сторону, что она не должна отправлять пакеты большего размера. Это предотвращает проблемы с соединением, когда PMTUD не работает.

Доступны следующие варианты:

  • mss: Установите MSS на конкретное значение, в байтах. Используйте этот вариант, чтобы принудительно установить конкретное значение MSS, например, для устранения проблем с подключением или соответствия требованиям сети.

  • clamp-mss-to-pmtu: Роутер рассчитывает MSS как MTU интерфейса минус 60 байт для IPv6-трафика (40 байт для заголовка IPv6 и 20 байт для заголовка TCP). Этот вариант рекомендуется для автоматической установки правильного значения.

set interfaces bonding <interface> ipv6 accept-dad <0 | 1 | 2>

Настройте DAD на интерфейсе.

Доступны следующие варианты:

  • 0: Отключает DAD. Проверка дублирования адреса не выполняется.

  • 1: Включает DAD (по умолчанию). Дублирование адреса обнаруживается. Работа интерфейса IPv6 продолжается для действительных IPv6-адресов.

  • 2: Включает DAD и, если найден дублированный MAC-адрес локальной подсети, отключает работу IPv6 на этом интерфейсе.

Пример:

set interfaces bonding bond0 ipv6 accept-dad 2
set interfaces bonding <interface> ipv6 dup-addr-detect-transmits <n>

Настройте количество DAD сообщений, которые отправляет роутер (ядро) во время назначения IPv6-адреса на этом интерфейсе.

Значение по умолчанию — 1.

Пример:

set interfaces bonding bond0 ipv6 dup-addr-detect-transmits 5
set interfaces bonding <interface> vrf <vrf>

Назначьте интерфейс определённому экземпляру VRF .

Смотрите также

Для информации о настройке VRF см. раздел VRF.

Пример:

set interfaces bonding bond0 vrf red

DHCP(v6)

set interfaces bonding <interface> dhcp-options client-id <description>

Настройте идентификатор клиента DHCP для интерфейса, как указано в RFC 2131.

client-id — это идентификатор, который клиент DHCP отправляет серверу DHCP, чтобы уникально идентифицировать себя для назначения IP-адреса. По умолчанию клиент использует свой MAC-адрес. <description> — это пользовательская строка, которая будет отправлена серверу DHCP в качестве идентификатора клиента DHCP.

Пример:

set interfaces bonding bond0 dhcp-options client-id 'foo-bar'
set interfaces bonding <interface> dhcp-options host-name <hostname>

Настройте конкретное имя хоста для интерфейса.

Вместо настоящего имени хоста, клиент DHCP будет отправлять конкретное имя хоста на сервер DHCP при запросе IP-адреса.

Пример:

set interfaces bonding bond0 dhcp-options host-name 'VyOS'
set interfaces bonding <interface> dhcp-options vendor-class-id <vendor-id>

Настройте клиент DHCP, чтобы включить идентификатор класса поставщика в своих запросах DHCP на этом интерфейсе.

Идентификатор класса поставщика — это специфичная для поставщика строка байтов, позволяющая серверу DHCP идентифицировать устройство и, в некоторых случаях, предоставлять опции конфигурации.

Пример:

set interfaces bonding bond0 dhcp-options vendor-class-id 'VyOS'
set interfaces bonding <interface> dhcp-options no-default-route

Настройте клиента DHCP, чтобы получить IP-адрес, но проигнорировать любой маршрут по умолчанию, предоставляемый сервером DHCP на этом интерфейсе.

Пример:

set interfaces bonding bond0 dhcp-options no-default-route
set interfaces bonding <interface> dhcp-options default-route-distance <distance>

Настройте расстояние для маршрута по умолчанию, полученного от сервера DHCP на этом интерфейсе.

Пример:

set interfaces bonding bond0 dhcp-options default-route-distance 220
set interfaces bonding <interface> dhcp-options reject <address>

Настройте клиента DHCP, чтобы отклонить конкретный IP-адрес или диапазон IP-адресов от сервера DHCP на этом интерфейсе.

Это полезно, когда модем назначает локальный IP-адрес при запуске. Чтобы отклонить несколько адресов, выполните эту команду несколько раз с разными значениями. Вы можете отклонять отдельные адреса (192.168.100.1) или целые подсети (192.168.100.0/24).

Пример:

set interfaces bonding bond0 dhcp-options reject 192.168.100.0/24
set interfaces bonding <interface> dhcp-options user-class <string>

Настройте клиента DHCP, чтобы отправить определённый идентификатор класса пользователя в своих запросах DHCP на этом интерфейсе.

Сервер DHCP может интерпретировать этот идентификатор и предоставить специфические опции конфигурации на основе него (например, маршруты по умолчанию). Значение класса пользователя обычно группирует клиентов DHCP с похожими потребностями в конфигурации (например, сотрудники, гости или принтеры).

Пример:

set interfaces bonding bond0 dhcp-options user-class VyOS
set interfaces bonding <interface> dhcpv6-options duid <duid>

Настройте определённый DUID для клиента DHCPv6 на этом интерфейсе.

DUID — это идентификатор, используемый клиентом DHCPv6 для получения IPv6-адреса от сервера DHCPv6. Он состоит из 2-байтового поля типа, за которым следует переменная длина идентификатора до 128 байт. Формат части идентификатора зависит от типа DUID:

  • DUID-LLT: Самый распространённый тип, который включает тип оборудования, временную метку и MAC-адрес.

  • DUID-EN: Основан на номере предприятия поставщика и уникальном идентификаторе, назначенном поставщиком.

  • DUID-LL: Включает только MAC-адрес.

Сервер DHCP сопоставляет DUID с базой данных и предоставляет конфигурационные данные (например, адрес, срок аренды, серверы DNS и т.д.) клиенту DHCP.

Пример:

set interfaces bonding bond0 duid '0e:00:00:01:00:01:27:71:db:f0:00:50:56:bf:c5:6d'
set interfaces bonding <interface> dhcpv6-options no-release

Настройте клиента DHCP, чтобы не отправлять сообщение о выпуске, когда он останавливается на этом интерфейсе.

Это помогает сохранить назначенный адрес или префикс.

Пример:

set interfaces bonding bond0 dhcpv6-options no-release
set interfaces bonding <interface> dhcpv6-options parameters-only

Включите режим клиента DHCPv6 без состояния на этом интерфейсе.

В режиме без состояния клиент DHCPv6 запрашивает только параметры конфигурации без состояния от сервера DHCP (например, адреса серверов DNS). Он не запрашивает состояние, например, IPv6-адреса или префиксы.

Пример:

set interfaces bonding bond0 dhcpv6-options parameters-only
set interfaces bonding <interface> dhcpv6-options rapid-commit

Включите быструю отправку запроса DHCPv6 на этом интерфейсе.

Когда включено, клиент и сервер пропускают шаги согласования (Advertise и Request), завершая процесс конфигурации DHCPv6 всего двумя сообщениями (Solicit и окончательный Reply).

Пример:

set interfaces bonding bond0 dhcpv6-options rapid-commit
set interfaces bonding <interface> dhcpv6-options temporary

Настройте клиента DHCPv6, чтобы запросить временный IPv6-адрес на этом интерфейсе.

При настройке клиент не формирует связь Identity Association для постоянных адресов. Следовательно, он получает только временный IPv6-адрес и не получает постоянный.

Пример:

set interfaces bonding bond0 dhcpv6-options temporary

DHCPv6 Передача префикса (PD)

VyOS поддерживает DHCPv6 Передача префикса (DHCPv6-PD), как описано в RFC 3633. DHCPv6-PD поддерживается большинством провайдеров, которые предлагают native IPv6 для потребителей на фиксированных сетях.

set interfaces bonding <interface> dhcpv6-options pd <id> length <length>

Настройте определённую длину префикса для запросов DHCPv6-PD на этом интерфейсе.

Некоторые провайдеры по умолчанию предоставляют только префикс /64. Используйте эту команду, чтобы запросить другой размер префикса для определённого запроса DHCPv6-PD, варьируя от /32 (если разрешено вашим провайдером) до /64. <id> — уникальный идентификатор для запроса DHCPv6-PD.

Значение по умолчанию — 64.

Чтобы запросить префикс /56 от вашего провайдера, используйте:

set interfaces bonding bond0 dhcpv6-options pd 0 length 56
set interfaces bonding <interface> dhcpv6-options pd <id> interface <delegatee> address <address>

Настройте идентификатор интерфейса IPv6 (часть хоста) для интерфейса делегата.

Значение должно быть десятичным целым числом. Оно добавляется к делегированному префиксу и конфигурации SLA ID, чтобы создать окончательный IPv6-адрес.

По умолчанию часть хоста генерируется на основе MAC-адреса родительского интерфейса (формат EUI-64).

Пример:

Если /64-префикс делегирован интерфейсу eth8, и вы настраивает часть хоста как 65535, результат IPv6-адреса будет заканчиваться ::ffff, так как 65535 соответствует ffff в шестнадцатеричной записи.

set interfaces bonding bond0 dhcpv6-options pd 0 interface eth8 address 65534
set interfaces bonding <interface> dhcpv6-options pd <id> interface <delegatee> sla-id <id>

Настройте SLA ID для интерфейса делегата.

Значение должно быть десятичным целым числом больше 0 и помещается в длину SLA ID. Оно преобразуется в шестнадцатеричное число и добавляется к делегированному префиксу, чтобы создать конкретный подсетевой префикс для интерфейса делегата.

Пример:

Если SLA ID равен 1, а делегированный префикс равен 2001:db8:ffff::/48, подсетной префикс для интерфейса делегата будет 2001:db8:ffff:1::/64.

set interfaces bonding bond0 dhcpv6-options pd 0 interface eth8 sla-id 1

Членские интерфейсы

set interfaces bonding <interface> member interface <member>

Добавьте интерфейс в группу объединения.

Пример:

Чтобы настроить eth0 и eth1 как членов интерфейса bond0, выполните следующие команды:

set interfaces bonding bond0 member interface eth0
set interfaces bonding bond0 member interface eth1

Режимы объединения

set interfaces bonding <interface> mode <802.3ad | active-backup | broadcast | round-robin | transmit-load-balance | adaptive-load-balance | xor-hash>

Настройте режим объединения на интерфейсе. Режим по умолчанию — 802.3ad.

Доступные режимы:

  • 802.3ad

Описание:

Динамическая агрегация ссылок, основанная на стандарте IEEE 802.3ad. Группируются только члены интерфейса с одинаковой скоростью (например, 1 Гбит/с) и настройками дуплекса. Члены интерфейса с различной скоростью и настройками дуплекса не входят в активное объединение.

Предоставляет баланс нагрузки и отказоустойчивость. Использует LACP для согласования объединения с коммутатором.

Распределение трафика:

Трафик распределяется в соответствии с политикой хэширования передачи (по умолчанию: XOR).

Драйвер объединения применяет операцию XOR к определенным полям заголовка пакета, генерируя значение хэша, которое отображается на определённый член интерфейса. Это гарантирует, что один и тот же сетевой поток последовательно передаётся через один и тот же член интерфейса.

Политика хэширования передачи настраивается через опцию hash-policy.

Обработка отказа:

Если член интерфейса выходит из строя, хэш пересчитывается, чтобы распределить трафик среди оставшихся активных членов интерфейса.

Примечание

Не все политики хэширования передачи соответствуют 802.3ad, особенно раздел 43.2.4. Использование несоответствующей политики может привести к неупорядоченной доставке пакетов.

  • active-backup

Описание:

Предоставляет отказоустойчивость. Только один член интерфейса активен в течение времени. Другие члены интерфейса остаются в режиме ожидания.

Распределение трафика:

Все трафик (входящий и исходящий) направляется через один активный член интерфейса.

Обработка отказа:

Если активный член интерфейса выходит из строя, весь трафик направляется на другой член интерфейса. Драйвер объединения отправляет ARP для обновления таблицы MAC-адреса у соседа, связывая MAC-адрес объединения с другим физическим портом.

  • broadcast

Описание:

Предоставляет максимальную отказоустойчивость, дублируя трафик.

Распределение трафика:

Каждый пакет дублируется и отправляется на все члены интерфейса.

Обработка отказа:

Поток не прерывается, пока хотя бы один член интерфейса остаётся активным.

  • round-robin

Описание:

Предоставляет баланс нагрузки и отказоустойчивость.

Распределение трафика:

Пакеты передаются последовательно по членам интерфейса (например, пакет 1 > интерфейс A, пакет 2 > интерфейс B и т.д.).

Обработка отказа:

Если член интерфейса выходит из строя, последовательность пропускает неисправный член и продолжает работу с оставшимися активными членами интерфейса.

  • transmit-load-balance
