MACsec

MACsec — это стандарт IEEE (IEEE 802.1AE) для обеспечения безопасности на уровне MAC, представленный в 2006 году. Он обеспечивает протокольно-независимое соединение между двумя хостами, предоставляя конфиденциальность данных, аутентичность и целостность с использованием шифров GCM-AES. MACsec работает на уровне Ethernet как протокол уровня 2 и защищает трафик внутри сетей уровня 2, включая запросы DHCP и ARP. Он не конкурирует с другими решениями безопасности, такими как IPsec (уровень 3) или TLS (уровень 4), поскольку каждое из них решает отдельные задачи.

Конфигурация

Общая конфигурация интерфейса

set interfaces macsec <interface> address <address | dhcp | dhcpv6>

Настройте интерфейс с одним или несколькими IP-адресами.

Доступны следующие варианты:

  • address: Назначьте один или несколько IPv4 или IPv6 адресов интерфейсу. Например, используйте 192.0.2.1/24 для IPv4 или 2001:db8::1/64 для IPv6.

  • dhcp: Интерфейс получает IPv4-адрес от сервера DHCP на той же сетевой подсети.

  • dhcpv6: Интерфейс получает IPv6-адрес от сервера DHCPv6 на той же сетевой подсети.

Примечание

Если интерфейс получает IPv4-адрес через DHCP, и необходимы определенные настройки до/после получения IP-адреса, используйте предоставленные скрипты-хуки:

  • /config/scripts/dhcp-client/pre-hooks.d/

  • /config/scripts/dhcp-client/post-hooks.d/

Пример:

set interfaces macsec macsec0 address 192.0.2.1/24
set interfaces macsec macsec0 address 2001:db8::1/64
set interfaces macsec macsec0 address dhcp
set interfaces macsec macsec0 address dhcpv6
set interfaces macsec <interface> description <description>

Настройте понятное описание интерфейса.

Это описание появляется в команде show interfaces и инструментах мониторинга на основе SNMP.

Пример:

set interfaces macsec macsec0 description 'This is an interface running on VyOS.'
set interfaces macsec <interface> disable

Отключите интерфейс.

Интерфейс будет установлен в состояние административно выключен (A/D).

Пример:

set interfaces macsec macsec0 disable
set interfaces macsec <interface> disable-flow-control

Отключите управление потоком Ethernet (стандарт IEEE 802.3x pause frames) на интерфейсе.

Управление потоком Ethernet, определенное стандартом IEEE 802.3x, временно останавливает передачу данных для предотвращения потери пакетов при перегрузке сети. Например, когда отправитель передает данные быстрее, чем получатель может их обработать.

Отключение управления потоком Ethernet означает, что интерфейс не будет сигнализировать подключенному устройству о паузе передачи и будет удалять пакеты, если перегружен.

Пример:

set interfaces macsec macsec0 disable-flow-control
set interfaces macsec <interface> disable-link-detect

Отключите обнаружение изменений состояния физической линии на интерфейсе, например, когда кабель отсоединен.

По умолчанию интерфейс обнаруживает изменения состояния физической линии.

Пример:

set interfaces macsec macsec0 disable-link-detect
set interfaces macsec <interface> mac <xx:xx:xx:xx:xx:xx>

Настройте пользовательский MAC-адрес на интерфейсе.

Пример:

set interfaces macsec macsec0 mac '00:53:01:02:03:04'
set interfaces macsec <interface> mtu <mtu>

Настройте MTU на интерфейсе.

Это значение определяет максимальный размер пакета, который интерфейс передает без фрагментации.

Пример:

set interfaces macsec macsec0 mtu 1600
set interfaces macsec <interface> ip adjust-mss <mss | clamp-mss-to-pmtu>

Настройте MSS , объявляемый в исходящих пакетах TCP SYN на указанном интерфейсе.

Путем ограничения значения MSS в пакетах TCP SYN вы явно информируете удаленный сторону о том, что она не должна отправлять пакеты большего размера. Это предотвращает проблемы с соединением, которые возникают, когда Path MTU Discovery (PMTUD) не работает.

Доступны следующие варианты:

  • mss: Устанавливает MSS в конкретное значение, в байтах. Используйте этот вариант, если необходимо принудительно установить конкретное значение MSS, например, для устранения проблем с доступностью или учета специфических требований сети.

  • clamp-mss-to-pmtu: Роутер автоматически рассчитывает MSS как MTU интерфейса минус 40 байт для IPv4 (20 байт для заголовка IPv4 и 20 байт для заголовка TCP). Этот вариант рекомендуется для автоматического установления правильного значения.

set interfaces macsec <interface> ip arp-cache-timeout

Настройте, как долго ARP-запись остается действительной после того, как интерфейс узнал сопоставление IP-адреса и MAC-адреса.

По умолчанию длительность составляет 30 секунд.

ARP-запись остается действительной, если она получает положительный ответ от более высоких уровней протоколов.

Пример:

set interfaces macsec macsec0 ip arp-cache-timeout 180
set interfaces macsec <interface> ip disable-arp-filter

Настройте фильтрацию ARP на этом интерфейсе.

Поведение по умолчанию: Ядро отвечает на запросы ARP на этом интерфейсе только в том случае, если трафик будет маршрутизироваться обратно к отправителю ARP через этот конкретный интерфейс.

Если настроено: Ядро отвечает на запросы ARP на этом интерфейсе для любого IP-адреса, настроенного на локальном хосте, независимо от того, какой конкретный интерфейс этому IP-адресу назначен, и независимо от таблицы маршрутизации. Это отражает концепцию Linux, согласно которой IP-адреса принадлежат хосту, а не отдельным интерфейсам.

Пример:

set interfaces macsec macsec0 ip disable-arp-filter
set interfaces macsec <interface> ip disable-forwarding

Настройте интерфейс для работы в режиме хоста или роутера.

Если настроено, интерфейс переключается в режим хоста, и IPv4-пересылка отключена на нем.

Пример:

set interfaces macsec macsec0 ip disable-forwarding
set interfaces macsec <interface> ip enable-directed-broadcast

Настройте, чтобы передавать пакеты IP-направленного широковещания, полученные на этом интерфейсе.

Поведение по умолчанию: Пакеты IP-направленного широковещания отбрасываются.

Если настроено: Пакеты IP-направленного широковещания передаются всем хостам на подсети назначения, как определено в RFC 1812 и RFC 2644.

Пример:

set interfaces macsec macsec0 ip enable-directed-broadcast
set interfaces macsec <interface> ip enable-arp-accept

Настройте, как обрабатывать gratuitous ARPs на этом интерфейсе.

Если настроено, сопоставление IP-адреса и MAC-адреса добавляется в таблицу ARP на основе gratuitous ARP-запросов или ответов.

Примечание

Если в таблице ARP уже есть IP-адрес из gratuitous ARP, его запись обновляется независимо от того, настроено ли это настройство.

Пример:

set interfaces macsec macsec0 ip enable-arp-accept
set interfaces macsec <interface> ip enable-arp-announce

Настройте выбор источника IP-адреса для запросов ARP на этом интерфейсе.

Поведение по умолчанию: Ядро может использовать любой IP-адрес, которым владеет хост, в качестве исходного IP-адреса в запросах ARP на этом интерфейсе.

Если настроено: Ядро сначала пытается выбрать исходный IP-адрес, настроенный на интерфейсе, который совпадает с подсетью цели. Если такой подсети нет, ядро выбирает IP-адрес, который оно обычно использует (на основе таблицы маршрутизации для достижения цели).

Пример:

set interfaces macsec macsec0 ip enable-arp-announce
set interfaces macsec <interface> ip enable-arp-ignore

Настройте, какие запросы ARP будут игнорироваться на этом интерфейсе.

Поведение по умолчанию: Ядро отвечает на запросы ARP для любых локальных IP-адресов, независимо от того, к какому интерфейсу они привязаны.

Если настроено: Ядро отвечает на запросы ARP только в том случае, если целевой IP-адрес привязан к этому конкретному интерфейсу.

Пример:

set interfaces macsec macsec0 ip enable-arp-ignore
set interfaces macsec <interface> ip enable-proxy-arp

Настройте proxy ARP на этом интерфейсе.

Если настроено, роутер (ядро) перехватывает запросы ARP для не-локальных IP-адресов и отвечает с MAC-адресом интерфейса, который получил запрос. Последующие пакеты, предназначенные этим IP-адресам, перенаправляются на их фактические цели на удаленных подсетях.

Пример:

set interfaces macsec macsec0 ip enable-proxy-arp
set interfaces macsec <interface> ip proxy-arp-pvlan

Настройте локальный proxy ARP на интерфейсе.

Если настроено, роутер (ядро) отвечает на запросы ARP на этом VLAN-интерфейсе даже в том случае, если целевой IP-адрес находится на той же подсети и интерфейсе.

Это используется для поддержки требований изоляции сети (RFC 3069) для частных VLAN (PVLAN). В конфигурациях PVLAN хосты на изолированных портах НЕ разрешены к прямой коммуникации друг с другом на уровне 2, но могут общаться с верхним роутером.

Путем ответа на запросы ARP между хостами своим собственным MAC-адресом, роутер (ядро) направляет трафик между хостами через себя вместо прямой передачи между хостами.

Примечание

Эта команда работает независимо и не требует включения обычного proxy ARP на интерфейсе.

Локальный proxy ARP также известен как:

  • VLAN агрегация (RFC 3069).

  • Частная VLAN (Cisco, Allied Telesyn).

  • Фильтрация по источнику или изоляция портов (Hewlett-Packard).

  • Перенаправление MAC (Ericsson).

set interfaces macsec <interface> ip source-validation <strict | loose | disable>

Настройте проверку исходного IP-адреса с помощью RPF на этом интерфейсе, как указано в RFC 3704.

Доступны следующие варианты:

  • strict: Каждый входящий пакет проверяет исходный IP-адрес против FIB. Если интерфейс не является лучшим маршрутом обратно к этому источнику, проверка не проходит, и пакет удаляется.

  • loose: Каждый входящий пакет проверяет исходный IP-адрес против FIB. Если исходный IP-адрес недостижим через любой интерфейс, проверка не проходит.

  • disable: Не выполняется проверка исходного IP-адреса. Все входящие пакеты принимаются.

RFC 3704 рекомендует включить строгий режим для предотвращения спуфинга IP, например, DDoS-атак. Для асимметричных или других сложных сценариев маршрутизации используйте режим loose.

set interfaces macsec <interface> ipv6 address autoconf

Настройте интерфейс для автоматического получения IPv6-адреса с помощью SLAAC, как указано в RFC 4862.

Хосты IPv6 могут автоматически настраивать себя, когда подключены к IPv6-сети, используя протокол обнаружения соседей через ICMPv6 сообщения о маршрутизаторе. При первом подключении к сети хост отправляет многоадресное сообщение запроса маршрутизатора на локальной подсети для получения параметров своей конфигурации. Маршрутизатор отвечает пакетом рекламы маршрутизатора, содержащим параметры конфигурации уровня интернета.

Примечание

Этот метод автоматически отключает передачу IPv6 на интерфейсе.

Пример:

set interfaces macsec macsec0 ipv6 address autoconf
set interfaces macsec <interface> ipv6 address eui64 <prefix>

Настройте интерфейс для присвоения себе IPv6-адреса с помощью метода EUI-64 , как указано в RFC 4291.

Пример:

set interfaces macsec macsec0 ipv6 address eui64 2001:db8:beef::/64
set interfaces macsec <interface> ipv6 address no-default-link-local

Отключите автоматическое присвоение link-local IPv6-адреса этому интерфейсу.

Пример:

set interfaces macsec macsec0 ipv6 address no-default-link-local
set interfaces macsec <interface> ipv6 disable-forwarding

Настройте интерфейс для работы в режиме хоста или роутера.

Если настроено, интерфейс переключается в режим хоста, и IPv6-пересылка отключена на нем.

Пример:

set interfaces macsec macsec0 ipv6 disable-forwarding
set interfaces macsec <interface> ipv6 adjust-mss <mss | clamp-mss-to-pmtu>

Настройте MSS , объявляемый в исходящих пакетах TCP SYN на указанном интерфейсе.

Путем ограничения значения MSS в пакетах TCP SYN вы явно информируете удаленный сторону о том, что она не должна отправлять пакеты большего размера. Это предотвращает проблемы с соединением, когда Path MTU Discovery (PMTUD) не работает.

Доступны следующие варианты:

  • mss: Устанавливает MSS в конкретное значение, в байтах. Используйте этот вариант, если необходимо принудительно установить конкретное значение MSS, например, для устранения проблем с доступностью или учета специфических требований сети.

  • clamp-mss-to-pmtu: Роутер рассчитывает MSS как MTU интерфейса минус 60 байт для IPv6 (40 байт для заголовка IPv6 и 20 байт для заголовка TCP). Этот вариант рекомендуется для автоматического установления правильного значения.

set interfaces macsec <interface> ipv6 accept-dad <0 | 1 | 2>

Настройте IPv6 DAD на интерфейсе.

Доступны следующие варианты:

  • 0: Отключает DAD. Не производится обнаружение дублирующих адресов.

  • 1: Включает DAD (по умолчанию). Обнаруживаются дублирующиеся адреса. Работа интерфейса IPv6 продолжается для допустимых IPv6-адресов.

  • 2: Включает DAD и, если найден дублирующийся локальный адрес, отключает работу IPv6 на этом интерфейсе.

Пример:

set interfaces macsec macsec0 ipv6 accept-dad 2
set interfaces macsec <interface> ipv6 dup-addr-detect-transmits <n>

Настройте количество сообщений DAD , которые отправляет роутер (ядро) во время назначения IPv6-адреса на этом интерфейсе.

Значение по умолчанию — 1.

Пример:

set interfaces macsec macsec0 ipv6 dup-addr-detect-transmits 5
set interfaces macsec <interface> vrf <vrf>

Назначьте интерфейс определенному экземпляру VRF .

См. также

Для информации о настройке VRF см. раздел VRF.

Пример:

set interfaces macsec macsec0 vrf red

DHCP(v6)

set interfaces macsec <interface> dhcp-options client-id <description>

Настройте идентификатор клиента DHCP для интерфейса, как указано в RFC 2131.

client-id — это идентификатор, который клиент DHCP отправляет серверу DHCP для уникальной идентификации себя для назначения IP-адреса. По умолчанию клиент использует свой MAC-адрес. <description> — это строка, заданная пользователем, которая будет отправлена серверу DHCP как идентификатор клиента DHCP.

Пример:

set interfaces macsec macsec0 dhcp-options client-id 'foo-bar'
set interfaces macsec <interface> dhcp-options host-name <hostname>

Настройте конкретное имя хоста для интерфейса.

Вместо реального имени хоста клиент DHCP будет отправлять конкретное имя хоста серверу DHCP при запросе IP-адреса.

Пример:

set interfaces macsec macsec0 dhcp-options host-name 'VyOS'
set interfaces macsec <interface> dhcp-options vendor-class-id <vendor-id>

Настройте клиент DHCP на включение идентификатора класса поставщика в свои запросы на этом интерфейсе.

Идентификатор класса поставщика — это строка байтов, специфичная для поставщика, которая позволяет серверу DHCP идентифицировать устройство и, в некоторых случаях, предоставить опции конфигурации.

Пример:

set interfaces macsec macsec0 dhcp-options vendor-class-id 'VyOS'
set interfaces macsec <interface> dhcp-options no-default-route

Настройте клиента DHCP на получение IP-адреса, но игнорирование любого шлюза по умолчанию, предоставляемого сервером DHCP на этом интерфейсе.

Пример:

set interfaces macsec macsec0 dhcp-options no-default-route
set interfaces macsec <interface> dhcp-options default-route-distance <distance>

Настройте расстояние для маршрута по умолчанию, полученного от сервера DHCP на этом интерфейсе.

Пример:

set interfaces macsec macsec0 dhcp-options default-route-distance 220
set interfaces macsec <interface> dhcp-options reject <address>

Настройте клиента DHCP на отказ от конкретного IP-адреса или диапазона IP-адресов от сервера DHCP на этом интерфейсе.

Это полезно, когда модем назначает локальный IP-адрес при запуске. Чтобы отклонить несколько адресов, выполните эту команду несколько раз с разными значениями. Вы можете отклонять отдельные адреса (192.168.100.1) или целые подсети (192.168.100.0/24).

Пример:

set interfaces macsec macsec0 dhcp-options reject 192.168.100.0/24
set interfaces macsec <interface> dhcp-options user-class <string>

Настройте клиента DHCP на отправку определенного идентификатора класса пользователя в свои запросы на этом интерфейсе.

Сервер DHCP может интерпретировать этот идентификатор и предоставить соответствующие опции конфигурации (например, маршруты по умолчанию). Значение класса пользователя обычно группирует клиентов DHCP с похожими потребностями в конфигурации (например, сотрудники, гости или принтеры).

Пример:

set interfaces macsec macsec0 dhcp-options user-class VyOS
set interfaces macsec <interface> dhcpv6-options duid <duid>

Настройте определенный DUID для клиента DHCPv6 на этом интерфейсе.

DUID — это идентификатор, используемый клиентом DHCPv6 для получения IPv6-адреса от сервера DHCPv6. Он состоит из 2-байтового поля типа, за которым следует переменная часть идентификатора длиной до 128 байт. Формат части идентификатора зависит от типа DUID:

  • DUID-LLT: Самый распространенный тип, который включает тип оборудования, временную метку и MAC-адрес.

  • DUID-EN: Основан на номере предприятия поставщика и уникальном идентификаторе, назначенном поставщиком.

  • DUID-LL: Включает только MAC-адрес.

Сервер DHCP сопоставляет DUID с базой данных и предоставляет информацию о конфигурации (например, адрес, срок аренды, DNS-серверы и т.д.) клиенту DHCP.

Пример:

set interfaces macsec macsec0 duid '0e:00:00:01:00:01:27:71:db:f0:00:50:56:bf:c5:6d'
set interfaces macsec <interface> dhcpv6-options no-release

Настройте клиент DHCP не отправлять сообщение о выпуске, когда он прекращает работу на этом интерфейсе.

Это помогает сохранить назначенный адрес или префикс.

Пример:

set interfaces macsec macsec0 dhcpv6-options no-release
set interfaces macsec <interface> dhcpv6-options parameters-only

Включите режим состоятельного клиента DHCPv6 на этом интерфейсе.

В состоянии без состояния клиент DHCPv6 запрашивает только параметры конфигурации без состояния у сервера DHCP (например, адреса серверов DNS). Он не запрашивает состоятельную конфигурацию, например, IPv6-адреса или префиксы.

Пример:

set interfaces macsec macsec0 dhcpv6-options parameters-only
set interfaces macsec <interface> dhcpv6-options rapid-commit

Включите быстрое подтверждение DHCPv6 на этом интерфейсе.

При включении клиент и сервер пропускают шаги согласования (Advertise и Request), завершая процесс конфигурации DHCPv6 всего за два сообщения (Solicit и окончательный Reply).

Пример:

set interfaces macsec macsec0 dhcpv6-options rapid-commit
set interfaces macsec <interface> dhcpv6-options temporary

Настройте клиента DHCPv6 на запрос временного IPv6-адреса на этом интерфейсе.

При настройке клиент DHCP не формирует партнерство Identity Association for Non-temporary Addresses (IA_NA). Следовательно, он получает только временный IPv6-адрес и не получает постоянный.

Пример:

set interfaces macsec macsec0 dhcpv6-options temporary

DHCPv6 Prefix Delegation (PD)

VyOS поддерживает DHCPv6 Prefix Delegation (DHCPv6-PD), как описано в RFC 3633. DHCPv6-PD поддерживается большинством провайдеров, предоставляющих native IPv6 для потребителей на фиксированных сетях.

set interfaces macsec <interface> dhcpv6-options pd <id> length <length>

Настройте определенную длину префикса для запросов DHCPv6-PD на этом интерфейсе.

Некоторые провайдеры по умолчанию предоставляют только /64 префикс. Используйте эту команду, чтобы запросить другой размер префикса для конкретного запроса DHCPv6-PD, варьируясь от /32 (если разрешено вашим провайдером) до /64. <id> — это уникальный идентификатор для запроса DHCPv6-PD.

Значение по умолчанию — 64.

Чтобы запросить префикс /56 от вашего провайдера, используйте:

set interfaces macsec macsec0 dhcpv6-options pd 0 length 56
set interfaces macsec <interface> dhcpv6-options pd <id> interface <delegatee> address <address>

Настройте идентификатор интерфейса IPv6 (часть хоста) для делегированного интерфейса.

Значение должно быть десятичным целым числом. Оно добавляется к делегированному префиксу и конфигурируемому SLA ID, чтобы образовать окончательный IPv6-адрес.

По умолчанию часть хоста генерируется на основе MAC-адреса родительского интерфейса (в формате EUI-64).

Пример:

Если /64 префикс делегирован интерфейсу eth8, и вы настраиваете часть хоста как 65535, то результатом будет IPv6-адрес, оканчивающийся на ::ffff, так как 65535 соответствует ffff в шестнадцатеричном виде.

set interfaces macsec macsec0 dhcpv6-options pd 0 interface eth8 address 65534
set interfaces macsec <interface> dhcpv6-options pd <id> interface <delegatee> sla-id <id>

Настройте SLA ID для делегированного интерфейса.

Значение должно быть десятичным целым числом больше 0 и помещаться в длину SLA ID. Оно преобразуется в шестнадцатеричное и добавляется к делегированному префиксу, чтобы образовать конкретный подсетевой префикс для делегированного интерфейса.

Пример:

Если SLA ID равен 1, а делегированный префикс — 2001:db8:ffff::/48, то подсетевой префикс для делегированного интерфейса будет 2001:db8:ffff:1::/64.

set interfaces macsec macsec0 dhcpv6-options pd 0 interface eth8 sla-id 1

Параметры MACsec

set interfaces macsec <interface> security cipher <gcm-aes-128|gcm-aes-256>

Настройте набор шифров для интерфейса MACsec.

Этот параметр конфигурации обязателен.

set interfaces macsec <interface> security encrypt

Включите шифрование на интерфейсе MACsec.
