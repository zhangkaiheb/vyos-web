NTP

NTP (Network Time Protocol) — это сетевой протокол для синхронизации часов между компьютерными системами по пакетным сетям с переменной задержкой. Существует с до 1985 года, NTP — один из самых старых интернет-протоколов, используемых в настоящее время.

NTP предназначен для синхронизации всех участвующих компьютеров с точностью несколько миллисекунд до UTC. Он использует алгоритм пересечения, модифицированную версию алгоритма Марцулло, чтобы выбрать точные серверы времени и спроектирован так, чтобы минимизировать влияние переменной задержки сети. NTP обычно может поддерживать время с точностью до десятков миллисекунд по общественной интернет-сети, а при идеальных условиях в локальной сети может достичь точности лучше одного миллисекунды. Асимметричные маршруты и загруженность сети могут вызывать ошибки в 100 мс или больше.

Протокол обычно описывается в терминах модели клиент-сервер, но также может использоваться в отношениях типа «пир-пир», где оба пира рассматривают друг друга как потенциальный источник времени. Реализации отправляют и получают временные метки с помощью UDP на номере порта 123.

NTP предоставляет предупреждение о любом грядущем корректировке секунды, но не передает информацию о локальных часовых поясах или летнем времени.

Текущий протокол — версия 4 (NTPv4), который является предложенным стандартом, как указано в RFC 5905. Он совместим с версией 3, указанной в RFC 1305.

Примечание

VyOS 1.4 использует chrony вместо ntpd (см. T3008), который больше не будет принимать анонимные запросы NTP, как в VyOS 1.3. Все конфигурации будут переведены, чтобы сохранить функциональность анонимного доступа. Для новых установок, если у вас есть клиенты, использующие вашу установку VyOS как сервер NTP, вы должны указать директиву allow-client.

Конфигурация

set service ntp server <address>

Настройте одно или несколько серверов для синхронизации. Имя сервера может быть либо IP-адресом, либо FQDN.

По умолчанию установлены 3 сервера NTP. Вы можете изменить их.

  • time1.vyos.net

  • time2.vyos.net

  • time3.vyos.net

set service ntp server <address> <noselect | nts | pool | prefer | ptp | interleave>

Настройте одно или несколько атрибутов для заданного сервера NTP.

  • noselect помечает сервер как неприменимый, за исключением целей отображения. Сервер отбрасывается алгоритмом выбора.

  • nts включает Network Time Security (NTS) для сервера, как указано в RFC 8915

  • pool активирует постоянное соединение клиента с рядом удаленных серверов.

  • prefer помечает сервер как предпочитаемый. При прочих равных, этот хост будет выбран для синхронизации среди набора правильно работающих хостов.

  • ptp включает транспорт PTP для этого сервера (см. Транспорт PTP для пакетов NTP).

  • interleave включает режим интерлейса NTP (см. draft-ntp-interleaved-modes), что может повысить точность и стабильность синхронизации, когда обе стороны поддерживают это.

set service ntp listen-address <address>

Процесс NTP будет слушать только указанный IP-адрес. Вы должны указать <address> и, по желанию, разрешенные клиенты. Несколько адресов слушания для одной и той же семейной сети больше не поддерживаются. Можно настроить только один IPv4 и один IPv6 адрес, используя отдельные команды для каждого.

set service ntp allow-client address <address>

Список сетей или адресов клиентов, разрешенных для обращения к этому серверу NTP.

Можно настроить несколько сетей/адресов клиентов.

set service ntp vrf <name>

Укажите имя экземпляра VRF.

set service ntp leap-second [ignore|smear|system|timezone]

Определите, как обрабатывать високосные секунды.

  • ignore: Клиент не корректируется для високосной секунды. Клиент будет скорректирован позже в обычной работе, когда новые измерения будут сделаны и оцененная смещение включает одну секунду ошибки.

  • smear: При смазывании високосной секунды статус високосной секунды подавляется на сервере, а обслуживаемое время корректируется медленно путем изменения вместо шага. Клиентам не нужно никакой специальной настройки, так как они не знают о наличии високосной секунды, и они следуют времени сервера, которое в конечном итоге приводит их к UTC. Важно убедиться, что они используют только серверы NTP, которые смазывают високосную секунду точно так же для синхронизации.

  • system: При вставке високосной секунды ядро делает шаг системы назад на одну секунду, когда часы достигают 00:00:00 UTC. При удалении високосной секунды он делает шаг вперед на одну секунду, когда часы достигают 23:59:59 UTC.

  • timezone: Эта директива указывает часовой пояс в базе данных часовых поясов системы, который chronyd может использовать для определения того, когда произойдет следующая високосная секунда и каков текущий сдвиг между TAI и UTC. Он периодически проверяет, являются ли 23:59:59 и 23:59:60 допустимыми временами в часовом поясе. Это обычно работает с правильным/UTC часовым поясом, который является значением по умолчанию

Аппаратное времязадание пакетов NTP

Демон chrony в VyOS может использовать возможности сетевой карты (NIC) для записи точного времени, когда пакеты были получены на интерфейсе, а также когда пакеты были фактически переданы. Это обеспечивает повышение точности и стабильности при нагрузке на систему, так как очередь и переключение контекста ОС могут вносить переменную задержку между тем, когда пакет получен на сети и когда он фактически обработан демоном NTP.

Аппаратное времязадание зависит от поддержки NIC. Некоторые сетевые карты могут быть настроены на применение временных меток ко всем входящим пакетам, тогда как другие поддерживают применение временных меток только к определенным протоколам (например, PTP).

При включении времязадания на интерфейсе, поведение демона chrony по умолчанию — попытаться настроить интерфейс, чтобы он задавал временные метки только для пакетов NTP. Если этот режим не поддерживается, chrony попытается установить его на задание временных меток всех пакетов. Если ни один из вариантов не поддерживается (например, сетевая карта может задавать временные метки только для полученных пакетов PTP), chrony будет использовать времязадание только для переданных пакетов, что все еще дает некоторую пользу.

set service ntp timestamp interface <interface>

Настраивает аппаратное времязадание на интерфейсе <interface>. Также можно указать специальное значение all, чтобы включить времязадание на всех интерфейсах, поддерживающих это.

Настройте поведение времязадания с помощью следующего параметра:

  • receive-filter [all|ntp|ptp|none] выбирает режим фильтра приема, который контролирует, какие входящие пакеты сетевая карта применяет временные метки. Выбранный режим должен поддерживаться сетевой картой, или времязадание будет отключено для интерфейса.

Следующие режимы receive-filter могут быть выбраны:

  • all: Все полученные пакеты будут времязаданы.

  • ntp: Только полученные пакеты протокола NTP будут времязаданы.

  • ptp: Только полученные пакеты протокола PTP будут времязаданы. Комбинированный с транспортом PTP для пакетов NTP, это может быть использовано для получения преимуществ аппаратного времязадания на сетевых картах, которые поддерживают только режим фильтра ptp.

  • none: Ни один из полученных пакетов не будет времязадан. Аппаратное времязадание переданных пакетов все еще будет использоваться, если поддерживается сетевой картой.

Транспорт PTP для пакетов NTP

Протокол точного времени (IEEE 1588) — это локальный сетевой протокол синхронизации времени, предоставляющий высокую точность синхронизации времени за счет использования аппаратных часов в сетевых картах и других сетевых элементах. VyOS в настоящее время не поддерживает стандартный PTP, который может быть развернут независимо от NTP.

Для сетей, состоящих из VyOS и других систем Linux, запускающих относительно новые версии демона chrony, пакеты NTP могут быть «туннелированы» через PTP. NTP через PTP объединяет лучшее из обоих миров, используя аппаратную поддержку времязадания пакетов PTP, сохраняя при этом гибкость настройки и отказоустойчивость NTP.

set service ntp ptp

Включает транспорт NTP. Демон NTP будет слушать на настроенном порту PTP. Обратите внимание, что один или несколько серверов должны быть индивидуально включены для PTP, прежде чем демон будет синхронизироваться через транспорт.

set service ntp ptp port <port>

Настройка порта PTP. По умолчанию используется стандартный порт 319.
