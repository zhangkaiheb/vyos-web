Мост

VyOS мосты соединяют сегменты Ethernet, группируя несколько интерфейсов в один мостовой интерфейс, который действует как виртуальный программный коммутатор. В отличие от маршрутизаторов, которые передают трафик на основе адресов IPv4/IPv6, мосты работают на уровне 2 и передают трафик на основе MAC-адресов. Работая на уровне 2, мосты являются протокольно-независимыми и прозрачно передают весь Ethernet-кадрированный трафик, независимо от того, является ли он IPv4, IPv6 или специализированными промышленными протоколами.

Эта реализация использует подсистему Linux bridge для поддержки подмножества стандарта ANSI/IEEE 802.1d для прозрачного моста и обучения MAC-адресам.

Примечание

STP по умолчанию отключен в VyOS и должен быть явно включен при необходимости. См. Конфигурация STP для деталей.

Конфигурация

Общая конфигурация интерфейса

set interfaces bridge <interface> address <address | dhcp | dhcpv6>

Настройте интерфейс с одним или несколькими IP-адресами.

Доступны следующие варианты:

  • address: Назначьте один или несколько IPv4 или IPv6 адресов интерфейсу. Например, используйте 192.0.2.1/24 для IPv4 или 2001:db8::1/64 для IPv6.

  • dhcp: Интерфейс получает IPv4-адрес от DHCP-сервера на том же сетевом сегменте.

  • dhcpv6: Интерфейс получает IPv6-адрес от DHCPv6-сервера на том же сетевом сегменте.

Примечание

Если интерфейс получает IPv4-адрес через DHCP, и необходимы конкретные настройки до/после получения IP-адреса, используйте предоставленные скрипты-хуки:

  • /config/scripts/dhcp-client/pre-hooks.d/

  • /config/scripts/dhcp-client/post-hooks.d/

Пример:

set interfaces bridge br0 address 192.0.2.1/24
set interfaces bridge br0 address 2001:db8::1/64
set interfaces bridge br0 address dhcp
set interfaces bridge br0 address dhcpv6
set interfaces bridge <interface> description <description>

Настройте MSS, объявляемый в исходящих TCP SYN-пакетах на указанном интерфейсе.

При ограничении значения MSS в TCP SYN-пакетах вы явно информируете удаленную сторону о том, что она не должна отправлять пакеты большего размера, чем этот размер. Это предотвращает проблемы с соединением, когда Path MTU Discovery (PMTUD) не работает.

Доступны следующие варианты:

  • mss: Устанавливает MSS в определенное значение, в байтах. Используйте этот вариант, если необходимо настроить конкретный MSS, например, для устранения проблем с доступностью или соответствия конкретным требованиям сети.

  • clamp-mss-to-pmtu: Роутер автоматически рассчитывает MSS как MTU интерфейса минус 40 байт для IPv4 (20 байт для заголовка IPv4 и 20 байт для заголовка TCP). Этот вариант рекомендуется для автоматической установки правильного значения.

set interfaces bridge <interface> ip arp-cache-timeout

Настройте, как долго ARP-запись остается действительной после изучения сопоставления IP-адреса и MAC-адреса на этом интерфейсе.

По умолчанию длительность составляет 30 секунд.

ARP-запись остается действительной, если она получает положительный ответ от более высоких уровней протоколов.

Пример:

set interfaces bridge br0 ip arp-cache-timeout 180
set interfaces bridge <interface> ip disable-arp-filter
