Geneve

Geneve 接口作为虚拟网络端口运行。管理员可在其上应用标准网络配置，例如 IP 地址分配、网桥或防火墙规则，其方式与在物理以太网端口上操作完全相同。

Geneve 协议将来自虚拟机、容器或物理服务器等端点的第 2 层以太网帧封装在 UDP 数据包内。它统一了早期封装协议（包括 VXLAN、NVGRE 和 STT）的功能，并解决了这些协议的局限性，例如固定报头结构和缺乏元数据支持。由于 Geneve 具有高度可扩展性，未来可能最终取代这些较旧的协议。

Geneve 隧道用于连接驻留在管理程序、物理交换机、中间设备及其他网络设备内的虚拟交换机。

Geneve 隧道可在任何标准 IP 网络上运行。在大规模部署中，底层网络（underlay）通常采用 Clos 拓扑构建，也称为 叶脊（leaf-and-spine） 或 胖树（fat-tree） 拓扑。

配置

通用接口配置

set interfaces geneve <interface> address <address>

配置一个或多个接口 IP 地址。

<address> 支持 CIDR 表示法的 IPv4 和 IPv6 地址。例如，IPv4 使用 192.0.2.1/24，IPv6 使用 2001:db8::1/64。

示例：

set interfaces geneve gnv0 address 192.0.2.1/24
set interfaces geneve gnv0 address 2001:db8::1/64
set interfaces geneve <interface> description <description>

为接口配置清晰、描述性的别名。

该别名将在 show interfaces 命令及基于 SNMP 的监控工具中显示。

示例：

set interfaces geneve gnv0 description '这是一个在 VyOS 上运行的接口。'
set interfaces geneve <interface> disable

禁用该接口。

该接口将被设置为管理性关闭（A/D）状态。

示例：

set interfaces geneve gnv0 disable
set interfaces geneve <interface> mac <xx:xx:xx:xx:xx:xx>

在接口上配置自定义 MAC 地址。

示例：

set interfaces geneve gnv0 mac '00:53:01:02:03:04'
set interfaces geneve <interface> mtu <mtu>

在接口上配置 MTU。

该值定义了接口在不进行分片的情况下所能传输的最大数据包大小（字节）。

示例：

set interfaces geneve gnv0 mtu 1600
set interfaces geneve <interface> ip adjust-mss <mss | clamp-mss-to-pmtu>

配置在指定接口上发出的 TCP SYN 数据包中通告的 MSS 值。

通过限制 TCP SYN 数据包中的 MSS 值，可明确告知远端不要发送大于该尺寸的数据包。这可以防止因路径 MTU 发现（PMTUD）失败而导致的连接问题。

以下选项可用：

  • mss: 将 MSS 设置为特定字节数值。当需要强制执行特定 MSS（例如排查连通性问题或满足特定网络需求）时，请使用此选项。

  • clamp-mss-to-pmtu: 路由器自动计算 MSS 值，即接口 MTU 减去 IPv4 流量所需的 40 字节（IPv4 报头 20 字节 + TCP 报头 20 字节）。建议使用此选项以自动设置合适值。

set interfaces geneve <interface> ip arp-cache-timeout

配置 ARP 条目在学习到本接口上的 IP 到 MAC 地址映射后保持有效的时间长度。

默认持续时间为 30 秒。

如果 ARP 条目从更高级别的协议接收到正向反馈，则该条目保持有效。

示例：

set interfaces geneve gnv0 ip arp-cache-timeout 180
set interfaces geneve <interface> ip disable-arp-filter

在本接口上配置 ARP 过滤。

默认行为： 内核仅在流量将通过该特定接口路由回 ARP 请求发送方时，才响应本接口上的 ARP 请求。

若已配置： 内核将响应本接口上针对本地主机所配置的任意 IP 地址的 ARP 请求，而不论该 IP 地址实际分配给哪个具体接口，也不论路由表如何。这体现了 Linux 中“IP 地址属于主机而非单个接口”的概念。

示例：

set interfaces geneve gnv0 ip disable-arp-filter
set interfaces geneve <interface> ip disable-forwarding

配置接口为主机模式或路由器模式行为。

若已配置，接口将切换至主机模式，且在该接口上禁用 IPv4 转发功能。

示例：

set interfaces geneve gnv0 ip disable-forwarding
set interfaces geneve <interface> ip enable-directed-broadcast

配置是否转发在本接口上接收的 IP 定向广播数据包。

默认行为： IP 定向广播数据包将被丢弃。

若已配置： IP 定向广播数据包将根据 RFC 1812 和 RFC 2644 的规定，转发至目标子网内的所有主机。

示例：

set interfaces geneve gnv0 ip enable-directed-broadcast
set interfaces geneve <interface> ip enable-arp-accept

配置本接口对免费 ARP（gratuitous ARP）的处理方式。

若已配置，将根据免费 ARP 请求或应答，在 ARP 表中添加 IP 到 MAC 地址映射。

注意

如果 ARP 表中已存在来自免费 ARP 的 IP 地址，无论是否启用此设置，其条目均会被更新。

示例：

set interfaces geneve gnv0 ip enable-arp-accept
set interfaces geneve <interface> ip enable-arp-announce

配置本接口上 ARP 请求的源 IP 地址选择方式。

默认行为： 内核可使用主机拥有的任意 IP 地址作为本接口上 ARP 请求的源 IP 地址。

若已配置： 内核首先尝试选择一个配置在本接口上、且与目标 IP 地址处于同一子网的源 IP 地址；若不存在此类子网，则内核将选择其通常使用的 IP 地址（即依据路由表到达目标目的地所选的地址）。

示例：

set interfaces geneve gnv0 ip enable-arp-announce
set interfaces geneve <interface> ip enable-arp-ignore

配置本接口上将被忽略的 ARP 请求类型。

默认行为： 内核将响应针对任意本地 IP 地址的 ARP 请求，而不论这些 IP 地址分配给了哪个接口。

若已配置： 内核仅在目标 IP 地址分配给本接口时，才响应 ARP 请求。

示例：

set interfaces geneve gnv0 ip enable-arp-ignore
set interfaces geneve <interface> ip enable-proxy-arp

在本接口上配置代理 ARP。

若已配置，路由器（内核）将截获针对非本地 IP 地址的 ARP 请求，并以接收请求的接口的 MAC 地址作为应答。后续发往这些 IP 地址的数据包将被转发至远程子网上的实际目的地。

示例：

set interfaces geneve gnv0 ip enable-proxy-arp
set interfaces geneve <interface> ip proxy-arp-pvlan

在接口上配置本地代理 ARP。

若已配置，路由器（内核）即使在目标 IP 地址位于同一子网和同一接口上时，也会响应本 VLAN 接口上的 ARP 请求。

此功能用于支持私有 VLAN（PVLAN）的网络隔离要求（RFC 3069）。在 PVLAN 配置中，隔离端口上的主机在第 2 层不允许直接相互通信，但可与上游路由器通信。

通过以自身 MAC 地址应答主机间 ARP 请求，路由器（内核）将主机间流量引导至自身，而非在主机之间直接转发。

注意

此命令独立工作，无需在接口上启用标准代理 ARP。

本地代理 ARP 也称为：

  • VLAN 聚合（RFC 3069）。

  • 私有 VLAN（Cisco、Allied Telesyn）。

  • 源端口过滤或端口隔离（Hewlett-Packard）。

  • MAC 强制转发（Ericsson）。

set interfaces geneve <interface> ip source-validation <strict | loose | disable>

根据 RFC 3704 的规定，在本接口上使用 RPF 配置源 IP 地址验证。

以下选项可用：

  • strict: 对每个入站数据包的源 IP 地址检查其是否匹配转发信息库（FIB）。若该接口并非返回该源地址的最佳路径，则验证失败，数据包将被丢弃。

  • loose: 对每个入站数据包的源 IP 地址检查其是否匹配 FIB。若该源 IP 地址无法通过任何接口到达，则验证失败。

  • disable: 不执行源 IP 地址验证，接受所有入站数据包。

RFC 3704 建议启用严格模式以防止 IP 欺骗（如 DDoS 攻击）。对于非对称路由或其他复杂路由场景，请使用宽松模式。

set interfaces geneve <interface> ipv6 address autoconf

根据 RFC 4862 的规定，配置接口使用 SLAAC 自动获取 IPv6 地址。

IPv6 主机在接入 IPv6 网络时，可通过 ICMPv6 路由器发现消息利用邻居发现协议（NDP）自动配置自身。主机首次接入网络时，会发送链路本地路由器请求多播请求以获取其配置参数；路由器则以包含网络层配置参数的路由器通告数据包进行响应。

注意

此方法将自动禁用接口上的 IPv6 流量转发功能。

示例：

set interfaces geneve gnv0 ipv6 address autoconf
set interfaces geneve <interface> ipv6 address eui64 <prefix>

根据 RFC 4291 的规定，配置接口使用 EUI-64 方法为其自身分配 IPv6 地址。

示例：

set interfaces geneve gnv0 ipv6 address eui64 2001:db8:beef::/64
set interfaces geneve <interface> ipv6 address no-default-link-local

禁用为本接口自动分配链路本地 IPv6 地址的功能。

示例：

set interfaces geneve gnv0 ipv6 address no-default-link-local
set interfaces geneve <interface> ipv6 disable-forwarding

配置接口为主机模式或路由器模式行为。

若已配置，接口将切换至主机模式，且在该接口上禁用 IPv6 转发功能。

示例：

set interfaces geneve gnv0 ipv6 disable-forwarding
set interfaces geneve <interface> ipv6 adjust-mss <mss | clamp-mss-to-pmtu>

配置在指定接口上发出的 TCP SYN 数据包中通告的 MSS 值。

通过限制 TCP SYN 数据包中的 MSS 值，可明确告知远端不要发送大于该尺寸的数据包。这可以防止因路径 MTU 发现（PMTUD）失败而导致的连接问题。

以下选项可用：

  • mss: 将 MSS 设置为特定字节数值。使用此选项可强制执行特定 MSS，例如排查连通性问题或满足特定网络需求。

  • clamp-mss-to-pmtu: 路由器计算 MSS 值，即接口 MTU 减去 IPv6 流量所需的 60 字节（IPv6 报头 40 字节 + TCP 报头 20 字节）。建议使用此选项以自动设置合适值。

set interfaces geneve <interface> ipv6 accept-dad <0 | 1 | 2>

在接口上配置 IPv6 DAD 功能。

以下选项可用：

  • 0: 禁用 DAD。不执行重复地址检测。

  • 1: 启用 DAD（默认）。检测重复地址。接口的 IPv6 功能对有效的 IPv6 地址继续运行。

  • 2: 启用 DAD；若发现基于 MAC 的重复链路本地地址，则禁用本接口上的 IPv6 功能。

示例：

set interfaces geneve gnv0 ipv6 accept-dad 2
set interfaces geneve <interface> ipv6 dup-addr-detect-transmits <n>

配置路由器（内核）在本接口上执行 IPv6 地址分配期间发送的 DAD 消息数量。

默认值为 1。

示例：

set interfaces geneve gnv0 ipv6 dup-addr-detect-transmits 5

Geneve 选项

set interfaces geneve gnv0 remote <address>

配置 Geneve 隧道的远端端点 IP 地址。

set interfaces geneve gnv0 vni <vni>

为 Geneve 接口配置 VNI 。

VNI 是一个虚拟网络标识符，允许多个虚拟网络共享同一物理基础设施并保持相互隔离。

VNI 还用于隧道出口后的流量分发，例如将具有重叠 IP 地址的数据包映射到特定的路由表。

set interfaces gnv0 <interface> port <port>

配置远端 Geneve 隧道端点的目标 UDP 端口。 请确保远端对等体已配置为在此特定端口上监听。
