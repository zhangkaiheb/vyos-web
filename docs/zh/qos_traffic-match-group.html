流量策略

服务质量（QoS）

服务质量（Quality of Service，简称 QoS）或流量控制的通用名称涵盖诸如流量整形、数据包调度或丢弃等操作。当链路存在带宽瓶颈时，您可能希望对不同类型的流量进行优先级划分，此类操作正是您需要配置的内容。

tc 是 Linux 内核中一个功能强大的流量控制工具。然而，其配置通常被认为是一项繁琐的任务。幸运的是，VyOS 通过其 CLI 简化了这项工作，同时仍以 tc 作为后端实现。

如何使其生效

要使 VyOS 流量控制正常工作，您需遵循以下两个步骤：

  1. 创建流量策略。

  2. 将流量策略应用到接口的入向（ingress）或出向（egress）方向。

但在学习如何配置策略之前，我们将提醒您注意可使用的不同单位，并向您介绍什么是 类别（classes） 及其工作原理，因为某些策略可能要求您对其进行配置。

单位

配置流量策略时，您需要设置数据速率值，请注意所管理的单位，不同前缀和后缀容易造成混淆。VyOS 始终会向您显示所有可用的单位。

前缀

可以使用 十进制 前缀。

kbit  (10^3)    千比特每秒
mbit  (10^6)    兆比特每秒
gbit  (10^9)    吉比特每秒
tbit  (10^12)   太比特每秒

mbps  (8*10^6)  兆字节每秒
gbps  (8*10^9)  吉字节每秒
tbps  (8*10^12) 太字节每秒

或者使用 二进制 前缀。

kibit (2^10 = 1024)    千比特（kibibit）每秒
mibit (2^20 = 1024^2)  兆比特（mebibit）每秒
gibit (2^30 = 1024^3)  吉比特（gibibit）每秒
tbit  (2^40 = 1024^4)  太比特（tebibit）每秒

kibps (1024*8)         千字节（KiB）每秒
mibps (1024^2*8)       兆字节（MiB）每秒
gibps (1024^3*8)       吉字节（GiB）每秒
tibps (1024^4*8)       太字节（TiB）每秒

比特（bit） 的写法为 bit，

而 字节（byte） 则写作单个字母 b。

gbps (吉字节每秒)

类别（Classes）

在创建流量策略一节中，您将看到某些策略使用 类别（classes）。这些策略允许您根据可选的不同参数将流量分配至不同类别。因此，类别仅是您选定的特定类型流量。

对流量进行分类的最终目标是为每个类别提供不同的处理方式。

匹配流量

为定义哪些流量进入哪个类别，您需定义过滤器（即匹配条件）。数据包依次经过这些匹配规则（类似于防火墙规则），若某数据包匹配某个过滤器，则被分配至对应类别。

在 VyOS 中，类别由您在配置时选择的一个编号来标识。

注意

类别 ID 的含义并非在所有策略类型中都相同。通常策略仅需一个无意义的编号来标识类别（类别 ID），但该规则并不适用于所有策略。在优先级队列（Priority Queue）中，类别的编号不仅用于标识，还定义了其优先级。

set qos policy <policy> <policy-name> class <class-ID> match <class-matching-rule-name>

在上述命令中，我们设置了将要使用的策略类型及其名称；定义了一个类别（以便区分某些流量）及其可识别的编号；然后配置了一个匹配规则（或过滤器）及其名称。

一个类别可拥有多个匹配过滤器：

set qos policy shaper MY-SHAPER class 30 match HTTP
set qos policy shaper MY-SHAPER class 30 match HTTPs

一个匹配过滤器可包含多个条件，仅当所有条件均满足时才匹配流量。

例如：

set qos policy shaper MY-SHAPER class 30 match HTTP ip protocol tcp
set qos policy shaper MY-SHAPER class 30 match HTTP ip source port 80

这将匹配源端口为 80 的 TCP 流量。

您可使用多种参数来匹配特定类别的流量：

  • 以太网（协议、目的地址或源地址）

  • 接口名称

  • IPv4（DSCP 值、最大数据包长度、协议、源地址、目的地址、源端口、目的端口或 TCP 标志位）

  • IPv6（DSCP 值、最大有效载荷长度、协议、源地址、目的地址、源端口、目的端口或 TCP 标志位）

  • 防火墙标记（firewall mark）

  • VLAN ID

配置过滤器时，您可以按 Tab 键查看所有可配置的不同参数。

vyos@vyos# set qos policy shaper MY-SHAPER class 30 match MY-FIRST-FILTER 
Possible completions:
   description  描述
 > ether        以太网头部匹配
   interface    要使用的接口
 > ip           匹配 IP 协议头部
 > ipv6         匹配 IPv6 协议头部
   mark         匹配防火墙应用的标记
   vif          此匹配的虚拟局域网（VLAN）ID

如上例所示，匹配数据包的一种方法是基于防火墙所做的标记， 这能为您提供极大的灵活性。

您还可以为过滤器编写描述：

set qos policy shaper MY-SHAPER class 30 match MY-FIRST-FILTER description "我的过滤器描述"

注意

IPv4 TCP 过滤器仅匹配 IPv4 头部长度为 20 字节的数据包（这已是绝大多数 IPv4 数据包的情况）。

注意

IPv6 TCP 过滤器仅匹配无扩展头部的 IPv6 数据包，参见 https://en.wikipedia.org/wiki/IPv6_packet#Extension_headers

流量匹配组（Traffic Match Group）

在某些情况下，我们需要组织匹配选择，以提高灵活性并更好地组织过滤器定义。此时可应用流量匹配组，从而在策略内创建不同的过滤器组，并为每个组定义各种参数：

set qos traffic-match-group <group_name> match <match_name>
Possible completions:
   description          描述
 > ip                   匹配 IP 协议头部
 > ipv6                 匹配 IPv6 协议头部
   mark                 匹配防火墙应用的标记
   vif                  此匹配的虚拟局域网（VLAN）ID

从另一组继承匹配项

set qos traffic-match-group <group_name> match-group <match_group_name>

匹配组可包含多个条件，并在同一策略中继承这些条件。

例如：

set qos traffic-match-group Mission-Critical match AF31 ip dscp 'AF31'
set qos traffic-match-group Mission-Critical match AF32 ip dscp 'AF42'
set qos traffic-match-group Mission-Critical match CS3 ip dscp 'CS3'
set qos traffic-match-group Streaming-Video match AF11 ip dscp 'AF11'
set qos traffic-match-group Streaming-Video match AF41 ip dscp 'AF41'
set qos traffic-match-group Streaming-Video match AF43 ip dscp 'AF43'
set qos policy shaper VyOS-HTB class 10 bandwidth '30%'
set qos policy shaper VyOS-HTB class 10 description '多媒体'
set qos policy shaper VyOS-HTB class 10 match CS4 ip dscp 'CS4'
set qos policy shaper VyOS-HTB class 10 match-group 'Streaming-Video'
set qos policy shaper VyOS-HTB class 10 priority '1'
set qos policy shaper VyOS-HTB class 10 queue-type 'fair-queue'
set qos policy shaper VyOS-HTB class 20 description '关键任务'
set qos policy shaper VyOS-HTB class 20 match-group 'Mission-Critical'
set qos policy shaper VyOS-HTB class 20 priority '2'
set qos policy shaper VyOS-HTB class 20 queue-type 'fair-queue'
set qos policy shaper VyOS-HTB default bandwidth '20%'
set qos policy shaper VyOS-HTB default queue-type 'fq-codel'

在此示例中，我们可以观察到，基于同一策略组内的 QoS 配置，定义了不同的 DSCP 条件。

默认（Default）

通常您还需以与类别相同的方式配置 默认 流量。默认 可视为一种类别，因其行为与此类似。它包含所有未匹配任何已定义类别的流量，因此类似于一个开放类别，即无匹配过滤器的类别。

类别处理（Class treatment）

一旦为类别配置了过滤器，您还需定义对该类别流量的具体处理方式，即为其指定特定的流量控制处理方式。具体选项取决于您正在配置的流量策略类型。

vyos@vyos# set qos policy shaper MY-SHAPER class 30
Possible completions:

   burst        此类别的突发大小（默认：15k）

   codel-quantum
                公平队列算法中的赤字（默认 1514）

将一个策略嵌入另一个策略

我们常需将一个策略嵌入另一个策略。对于分层策略（classful policies），可通过将新策略附加到某个类别来实现。例如，您可能希望对已配置的轮询（Round-Robin）策略的不同类别应用不同的策略。

一个常见示例是：某些策略为生效，必须应用到瓶颈所在位置直接相连的接口上。如果您的路由器并未直接连接到瓶颈处，而是位于瓶颈之前的某个跳点，则可通过将非整形策略嵌入分层整形策略中来模拟瓶颈效果，从而使该策略生效。

您可通过 queue-type 设置在类别中配置策略。

set qos policy shaper FQ-SHAPER bandwidth 4gbit
set qos policy shaper FQ-SHAPER default bandwidth 100%
set qos policy shaper FQ-SHAPER default queue-type fq-codel

如上例最后一条命令所示，queue-type 设置支持这些组合。您可在多种策略中使用它。

注意

某些策略内部已包含其他嵌入式策略。 例如整形器（Shaper）策略：其每个类别默认使用公平队列（fair-queue），除非您另行更改。

创建流量策略

VyOS 提供多种流量控制方式，此处将涵盖所有可能性。您可以配置任意数量的策略，但每个接口及每个方向（入向或出向）仅能应用一个策略。

某些策略可组合使用，您可将不同策略嵌入主策略的某个类别中。

提示

如果您正在寻找适用于出向流量的策略， 但不确定应选择哪一种，且不想逐一查阅此处列出的所有策略， 我们建议您很可能需要的是整形器（Shaper）策略，并希望将其队列设置为 FQ-CoDel。

尾部丢弃（Drop Tail）

排队机制： PFIFO（数据包先进先出）。
适用场景： 出向流量。

这是您可应用于流量的最简单队列。流量在实际发送前必须经过一个有限队列。您必须定义该队列所能容纳的数据包数量。

当数据包准备发送时，需经过该队列，因此数据包将置于队列尾部。当数据包完全通过该队列后，将被出队，腾出队列中的位置，并最终交由网卡实际发出。

尽管尾部丢弃策略不会减慢数据包传输速度，但如果需发送大量数据包，它们在尝试加入队列尾部时可能被丢弃。这种情况可能发生在队列头部尚未释放足够数据包时。

该策略在相同流量下所需资源最少。但您很可能无需此策略，因为它提供的功能非常有限。有时仅用于启用日志记录。

set qos policy drop-tail <policy-name> queue-limit <number-of-packets>

使用此命令配置尾部丢弃策略（PFIFO）。为此策略选择唯一名称，并通过设置其可容纳的数据包数量（最大值为 4294967295）来设定队列大小。

公平队列（Fair Queue）

排队机制： SFQ（随机公平队列）。
适用场景： 出向流量。

公平队列是一种工作守恒型调度器，它基于数据流调度数据包传输，即通过将流量分配至不同子队列来平衡流量，以确保公平性，使每个数据流都能轮流发送数据，防止任一单一数据流淹没其余数据流。

set qos policy fair-queue <policy-name>

使用此命令创建公平队列策略并为其命名。该策略基于随机公平队列（Stochastic Fairness Queueing），可应用于出向流量。

为分离流量，公平队列使用基于源地址、目的地址和源端口的分类器。该算法根据这三个参数将数据包入队至哈希桶（hash buckets）。每个哈希桶应代表一个唯一的数据流。由于多个数据流可能被哈希至同一桶中，哈希算法会在可配置的时间间隔内扰动，以确保不公平性仅持续短暂时间。不过，扰动可能导致意外的数据包重排序。建议值为 10 秒。

公平队列的一种用途可能是缓解拒绝服务（DoS）攻击。

set qos policy fair-queue <policy-name> hash-interval <seconds>

使用此命令定义基于随机公平队列（Stochastic Fairness Queueing）的公平队列策略，并设置新队列算法扰动发生的时间间隔（秒数，最大值为 4294967295）。

出队时，每个有数据的哈希桶将以轮询方式查询。您可以配置队列长度。

set qos policy fair-queue <policy-name> queue-limit <limit>

使用此命令定义基于随机公平队列（Stochastic Fairness Queueing）的公平队列策略，并设置队列中允许等待的最大数据包数量。超出此数量的数据包将被丢弃。

注意

公平队列是一种非整形（工作守恒）策略，因此仅当您的出向接口真正满载时才有用。若接口未满载，VyOS 将不拥有该队列，公平队列将无效。若物理链路上尚有带宽可用，您可将公平队列嵌入分层整形策略中，以确保其拥有队列。

FQ-CoDel

排队机制： 公平/流队列 CoDel。
适用场景： 出向流量。

FQ-CoDel 策略将流量分配至 1024 个 FIFO 队列，并力求在所有队列间提供良好服务。它还力求保持所有队列长度较短。

FQ-CoDel 抵御缓冲区膨胀（bufferbloat）并降低延迟，且无需复杂配置。它已成为某些 GNU/Linux 发行版接口的新默认排队机制（Queueing Discipline）。

它使用随机模型将入站数据包分类至不同数据流，并为所有使用该队列的数据流提供公平的带宽份额。每个数据流由 CoDel 排队机制管理。由于 CoDel 内部使用 FIFO 队列，因此可避免同一数据流内的数据包重排序。

FQ-CoDel 基于经修改的亏缺轮询（Deficit Round Robin，DRR）队列调度器，每个队列上运行 CoDel 主动队列管理（AQM）算法。

注意

FQ-CoDel 是一种非整形（工作守恒）策略，因此仅当您的出向接口真正满载时才有用。若接口未满载，VyOS 将不拥有该队列，FQ-CoDel 将无效。若物理链路上尚有带宽可用，您可将 FQ-CoDel 嵌入分层整形策略中，以确保其拥有队列。若您不确定是否需要将 FQ-CoDel 策略嵌入整形器（Shaper）中，请务必执行此操作。

FQ-CoDel 经过调优，可在 10Gbit 速率下使用默认参数正常运行。在其他速率下，即使不进行任何配置也可能正常工作，但此处我们将解释一些可能需要调整其参数的情形。

在 1Gbit 及更低速率下运行时，您可能希望将 queue-limit 减少至 1000 个数据包或更少。在 10Mbit 等速率下，您可能希望将其设为 600 个数据包。

若您将 FQ-CoDel 嵌入整形器（Shaper）中且具有较高速率（100Mbit 及以上），您可考虑将 quantum 增加至 8000 或更高，以节省 CPU 资源。

在较低速率（低于 40Mbit）下，您可能希望将 quantum 调整为约 300 字节。

在极低速率（低于 3Mbit）下，除调整 quantum（300 字节仍适用）外，您还可将 target 增加至约 15ms，并将 interval 增加至约 150ms。

set qos policy fq-codel <policy name> codel-quantum <bytes>

使用此命令配置 fq-codel 策略，设置其名称及每次从队列中出队的最大字节数（默认：1514）。

set qos policy fq-codel <policy name> flows <number-of-flows>

使用此命令配置 fq-codel 策略，设置其名称及数据包被分类的子队列数量（默认：1024）。

set qos policy fq-codel <policy name> interval <milliseconds>

使用此命令配置 fq-codel 策略，设置其名称及 CoDel 控制循环用于检测持久队列形成的时间周期，确保测得的最小延迟不会过于陈旧（默认：100ms）。

set qos policy fq-codel <policy-name> queue-limit <number-of-packets>

使用此命令配置 fq-codel 策略，设置其名称，并定义真实队列大小的硬性上限。达到此上限时，新数据包将被丢弃（默认：10240 个数据包）。

set qos policy fq-codel <policy-name> target <milliseconds>

使用此命令配置 fq-codel 策略，设置其名称，并定义可接受的最小持续/持久队列延迟。此最小延迟通过跟踪数据包经历的本地最小队列延迟来识别（默认：5ms）。

示例

FQ-CoDel 策略在整形器（Shaper）策略内运行的简单示例。

set qos policy shaper FQ-CODEL-SHAPER bandwidth 2gbit
set qos policy shaper FQ-CODEL-SHAPER default bandwidth 100%
set qos policy shaper FQ-CODEL-SHAPER default queue-type fq-codel

限速器（Limiter）

排队机制： 入向（Ingress）流量监管器（policer）。
适用场景： 入向流量。

限速器是使用类别的策略之一（入向 qdisc 实际上是无类别策略，但过滤器在其内部有效）。

限速器对流量流执行基本的入向流量监管。可定义多个流量类别，并为每个类别应用流量限制。尽管监管器内部使用令牌桶机制，但它不具备整形机制所具有的延迟数据包能力。超出定义带宽限制的流量将被直接丢弃。也可配置允许的最大突发大小。

您可以配置最多 4090 个类别，各具不同设置，以及一个默认策略，该策略将应用于所有未匹配任何已配置类别的流量。

注意

若您希望对入向流量应用某种整形，请参阅入向整形（ingress-shaping）部分。

set qos policy limiter <policy-name> class <class ID> match <match-name> description <description>

使用此命令配置入向流量监管器（Ingress Policer），定义其名称、类别标识符（1-4090）、类别匹配规则名称及其描述。

为类别设置匹配规则后，您即可开始配置匹配流量的行为方式。

set qos policy limiter <policy-name> class <class-ID> bandwidth <rate>

使用此命令配置入向流量监管器（Ingress Policer），定义其名称、类别标识符（1-4090）及该类别的最大允许带宽。

set qos policy limiter <policy-name> class <class-ID> burst <burst-size>

使用此命令配置入向流量监管器（Ingress Policer），定义其名称、类别标识符（1-4090）及该类别的突发大小（字节，默认：15）。

set qos policy limiter <policy-name> default bandwidth <rate>

使用此命令配置入向流量监管器（Ingress Policer），定义其名称及默认策略的最大允许带宽。

set qos policy limiter <policy-name> default burst <burst-size>

使用此命令配置入向流量监管器（Ingress Policer），定义其名称及默认策略的突发大小（字节，默认：15）。

set qos policy limiter <policy-name> class <class ID> priority <value>

使用此命令配置入向流量监管器（Ingress Policer），定义其名称、类别标识符（1-4090）及规则评估的优先级（0-20，默认 20）（数值越小，优先级越高）。

网络仿真器（Network Emulator）

排队机制： netem（网络仿真器） + TBF（令牌桶过滤器）。
适用场景： 出向流量。

VyOS 网络仿真器策略可模拟真实网络中可能遇到的各种条件。您可配置诸如速率、突发、延迟、数据包丢失、数据包损坏或数据包重排序等功能。

若您希望测试应用程序在特定网络条件下的行为表现，此功能将非常有用。

set qos policy network-emulator <policy-name> bandwidth <rate>

使用此命令配置网络仿真器策略的最大整形速率。定义策略名称及速率。

set qos policy network-emulator <policy-name> burst <burst-size>

使用此命令配置网络仿真器策略的流量突发大小。定义网络仿真器策略名称及其流量突发大小（将通过令牌桶过滤器 qdisc 配置）。默认值：15kb。仅当您同时配置了其带宽时，该设置才生效。

set qos policy network-emulator <policy-name> delay <delay>

使用此命令配置网络仿真器策略，定义其名称及希望添加到所有出站接口数据包上的固定延迟时间。延迟将通过令牌桶过滤器 qdisc 添加。仅当您同时配置了其带宽时，该设置才生效。可使用秒（secs）、毫秒（ms）和微秒（us）。默认值：50ms。

set qos policy network-emulator <policy-name> corruption <percent>

使用此命令在网络仿真器策略中模拟噪声。设置策略名称及希望损坏的数据包百分比。将在所选百分比的数据包中随机位置引入随机错误。

set qos policy network-emulator <policy-name> loss <percent>

使用此命令在网络仿真器策略中模拟数据包丢失情况。设置策略名称及您的流量将遭受的数据包丢失百分比。

set traffic-policy network-emulator <policy-name> reordering <percent>

使用此命令在网络仿真器策略中模拟数据包重排序情况。设置策略名称及您的流量将遭受的数据包重排序百分比。

set traffic-policy network-emulator <policy-name> queue-limit <limit>

使用此命令定义网络仿真器策略的队列长度。设置策略名称及队列一次可容纳的最大数据包数量（1-4294967295）。

优先级队列（Priority Queue）

排队机制： PRIO。
适用场景： 出向流量。

优先级队列是一种分层调度策略。它不会延迟数据包（优先级队列不是整形策略），而是根据数据包的优先级顺序出队。

注意

优先级队列与其他非整形策略一样，仅当您的出向接口真正满载时才有用。若接口未满载，VyOS 将不拥有该队列，优先级队列将无效。若物理链路上尚有带宽可用，您可将优先级队列嵌入分层整形策略中，以确保其拥有队列。在这种情况下，数据包可根据 DSCP 进行优先级排序。

最多可配置七个队列（定义为具有不同优先级的类别）。数据包根据关联的匹配条件被放入相应队列。数据包按优先级顺序从队列中传输。若较高优先级的类别持续接收数据包，则较低优先级类别的数据包仅在较高优先级类别流量减少后才会被传输。

注意

在优先级队列中，我们不使用无意义的类别 ID 编号，而是使用类别优先级编号（1-7）。数值越小，优先级越高。

与其他策略一样，您可以为类别定义不同类型的匹配规则：

vyos@vyos# set qos policy priority-queue MY-PRIO class 3 match MY-MATCH-RULE 
Possible completions:
   description  描述
 > ether        以太网头部匹配
   interface    要使用的接口
 > ip           匹配 IP 协议头部
 > ipv6         匹配 IPv6 协议头部
   mark         匹配防火墙应用的标记
   vif          此匹配的虚拟局域网（VLAN）ID

与其他策略一样，您可通过 queue-type 设置将其他策略嵌入优先级队列策略的类别（及默认类别）中：

vyos@vyos# set qos policy priority-queue MY-PRIO class 3 queue-type 
Possible completions:
   drop-tail    先进先出（FIFO）（默认）
   fq-codel     公平队列 CoDel
   fair-queue   随机公平队列（SFQ）
   priority     优先级队列
   random-detect
                随机早期检测（RED）
set qos policy priority-queue <policy-name> class <class-ID> queue-limit <limit>

使用此命令配置优先级队列策略，设置其名称、设置优先级为 1 至 7 的类别，并定义真实队列大小的硬性上限。达到此上限时，新数据包将被丢弃。

随机检测（Random-Detect）

排队机制： 广义随机早期丢弃（Generalized Random Early Drop）。
适用场景： 出向流量。

简单的随机早期检测（RED）策略会在队列达到其上限之前就开始随机丢弃数据包，从而避免拥塞。这对 TCP 连接有益，因为数据包的逐步丢弃可作为信号，促使发送方降低其传输速率。

与简单 RED 不同，VyOS 的随机检测（Random-Detect）采用广义随机早期检测策略，该策略基于 IP 优先级值提供不同的虚拟队列，使得某些虚拟队列可比其他队列丢弃更多数据包。

这是通过使用 ToS（服务类型）字段的前三位来对数据流进行分类，并根据定义的优先级参数做出决策来实现的。

随机检测（Random-Detect）可能对高负载流量有用。该算法的一种用途可能是防止骨干网过载。但仅适用于 TCP（因为丢弃的数据包可被重传），不适用于 UDP。

set qos policy random-detect <policy-name> bandwidth <bandwidth>

使用此命令配置随机检测（Random-Detect）策略，设置其名称及该策略的可用带宽。它用于在空闲一段时间后计算平均队列大小。应将其设置为接口带宽。随机检测不是整形策略，此命令不会进行整形。

set qos policy random-detect <policy-name> precedence <IP-precedence-value> average-packet <bytes>

使用此命令配置随机检测（Random-Detect）策略并设置其名称，然后声明您正在配置的虚拟队列的 IP 优先级及平均数据包大小（字节，默认：1024）。

注意

配置随机检测（Random-Detect）策略时：优先级数值越大，优先级越高。

set qos policy random-detect <policy-name> precedence <IP-precedence-value> mark-probability <value>

使用此命令配置随机检测（Random-Detect）策略并设置其名称，然后声明您正在配置的虚拟队列的 IP 优先级及标记（丢弃）概率。通过给出分数 1/N 中的 N 值来设置概率（默认：10）。

set qos policy random-detect <policy-name> precedence <IP-precedence-value> maximum-threshold <packets>

使用此命令配置随机检测（Random-Detect）策略并设置其名称，然后声明您正在配置的虚拟队列的 IP 优先级及随机检测的最大阈值（0 至 4096 个数据包，默认：18）。达到此大小时，标记（丢弃）概率达到最大值。

set qos policy random-detect <policy-name> precedence <IP-precedence-value> minimum-threshold <packets>

使用此命令配置随机检测（Random-Detect）策略并设置其名称，然后声明您正在配置的虚拟队列的 IP 优先级及随机检测的最小阈值（0 至 4096 个数据包）。若超过此值，数据包将开始有资格被丢弃。

使用此命令配置随机检测（Random-Detect）策略并设置其名称，然后声明您正在配置的虚拟队列的 IP 优先级及队列的最大大小（1 至 4294967295 个数据包）。当当前队列长度达到此值时，数据包将被丢弃。

若平均队列大小低于 最小阈值（min-threshold），到达的数据包将被放入队列。

若平均队列大小介于 最小阈值（min-threshold） 和 最大阈值（max-threshold） 之间，则到达的数据包将被丢弃或放入队列，具体取决于定义的 标记概率（mark-probability）。

若当前队列大小大于 队列上限（queue-limit），则数据包将被丢弃。平均队列大小取决于其先前的平均大小和当前大小。

若设置了 最大阈值（max-threshold） 但未设置 最小阈值（min-threshold），则 最小阈值（min-threshold） 将按 最大阈值（max-threshold） 的 50% 进行缩放。

原则上，数值必须满足： min-threshold < max-threshold < queue-limit。

速率控制（Rate Control）

排队机制： 令牌桶过滤器（Token Bucket Filter）。
适用场景： 出向流量。

速率控制是一种无类别策略，它将数据包流限制在设定的速率。它是一种纯粹的整形器，不调度流量。流量基于令牌消耗进行过滤。令牌大致对应字节。

允许短时间突发超过限制。创建时，速率控制流量被预填充令牌，这些令牌对应于一次性突发的流量数量。令牌以稳定速率到达，直至桶满。

set qos policy rate-control <policy-name> bandwidth <rate>

使用此命令配置速率控制策略，设置其名称及所需的速率限制。

set qos policy rate-control <policy-name> burst <burst-size>

使用此命令配置速率控制策略，设置其名称及可用于突发的桶大小（字节）。

参考值：在 Intel 平台上，若要达到 10mbit/s 的配置速率，您可能至少需要 10k 字节的缓冲区。

缓冲区过小将很快开始丢弃数据包。

set qos policy rate-control <policy-name> latency

使用此命令配置速率控制策略，设置其名称及数据包可排队的最大时间（默认：50 毫秒）。

速率控制是一种对 CPU 友好的策略。当您仅需简单地降低流量速度时，可考虑使用它。
