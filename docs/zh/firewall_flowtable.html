概述

本节提供有关流表防火墙配置的信息。

set firewall flowtable …

如需了解 VyOS 防火墙中的一般流量流向，请参阅 防火墙。

- set firewall
    * flowtable
         - custom_flow_table
            + ...

流表允许您定义一条经由流表数据路径的快速转发路径。流表支持第 3 层（IPv4 和 IPv6）和第 4 层（TCP 和 UDP）协议。

首个数据包成功穿越 IP 转发路径（黑色圆圈路径）后，您可通过规则集将后续数据包卸载至流表。您可在转发过滤阶段（红色圆圈编号 6）指定何时向流表添加流条目。

当数据包在流表中找到匹配项（流表命中）时，系统将其直接传输至输出网络设备。这意味着数据包绕过传统 IP 转发路径，转而使用快速路径（橙色圆圈路径）。因此，在入口之后，您无法再从任何 Netfilter 钩子中看到这些数据包。若流表中不存在匹配项（流表未命中），则数据包将沿传统 IP 转发路径进行处理。

注意

流表参考： https://docs.kernel.org/networking/nf_flowtable.html

流表配置

要使用流表，您需要配置以下内容：

  • 创建一个流表，并包含将在流表中使用的接口。

  • 创建一条防火墙规则：将操作设置为 offload，并为 offload-target 指定所需的流表。

创建流表：

set firewall flowtable <flow_table_name> interface <iface> 指定流表中要使用的接口。
set firewall flowtable <flow_table_name> description <text>

为流表提供描述信息。

set firewall flowtable <flow_table_name> offload <hardware | software>

指定流表所用的卸载类型：hardware 或 software。默认为 software 卸载。

注意

硬件卸载：启用该选项前，请确保您的网卡（NIC）支持硬件卸载功能，并已安装必要的驱动程序。

创建用于使用流表的规则：

set firewall [ipv4 | ipv6] forward filter rule <1-999999> action offload

在转发链中创建一条防火墙规则，并将操作设为 offload。

set firewall [ipv4 | ipv6] forward filter rule <1-999999> offload-target <flowtable>

在转发链中创建一条防火墙规则，并指定要使用的流表。仅当操作为 offload 时适用。

接口选择

重要

始终使用 VyOS 在转发钩子（forward hook）处观察到的接口来配置流表——该接口不一定是物理接口。当流量经由逻辑接口接收或发送时，VyOS 跟踪的是该逻辑接口，而非底层物理设备。若在流表中注册了错误的接口，则每次流查找均会失败，从而回退至传统转发路径，导致快速路径卸载失去意义。

配置示例

考虑本示例中的以下设置：

  • 本示例在流表中使用两个接口：eth0 和 eth1。

  • 本示例提供了一个最小化的防火墙规则集，包括过滤规则以及利用流表卸载功能的规则。

首个数据包由防火墙路径评估，因此应显式接受所需连接。反向流量也应执行相同操作。在大多数情况下，会使用状态策略在反向路径中接受连接。

在以下示例中，仅接受来自接口 eth0、使用 TCP 协议且目标端口为 1122 的流量。所有其他发往路由器的流量均被丢弃。

命令

set firewall flowtable FT01 interface 'eth0'
set firewall flowtable FT01 interface 'eth1'
set firewall ipv4 forward filter default-action 'drop'
set firewall ipv4 forward filter rule 10 action 'offload'
set firewall ipv4 forward filter rule 10 offload-target 'FT01'
set firewall ipv4 forward filter rule 10 state 'established'
set firewall ipv4 forward filter rule 20 action 'accept'
set firewall ipv4 forward filter rule 20 state 'established'
set firewall ipv4 forward filter rule 20 state 'related'
set firewall ipv4 forward filter rule 110 action 'accept'
set firewall ipv4 forward filter rule 110 destination address '192.0.2.100'
set firewall ipv4 forward filter rule 110 destination port '1122'
set firewall ipv4 forward filter rule 110 inbound-interface name 'eth0'
set firewall ipv4 forward filter rule 110 protocol 'tcp'

说明

对于所需连接，其处理过程如下：

  1. 一个数据包经 eth0 到达，目标地址为 192.0.2.100，使用 TCP 协议，目标端口为 1122。假设该地址可通过接口 eth1 访问。

  2. 对于该首个数据包，连接状态为 new。规则 10 和规则 20 均不适用。

  3. 规则 110 匹配，因此接受该连接。

  4. 当服务器 192.0.2.100 回复时，连接状态变为 established，规则 20 接受该回复。

  5. 路由器收到该连接的第二个数据包。由于连接状态为 established，规则 10 匹配，并在流表 FT01 中为此连接添加新条目。

  6. 后续数据包跳过传统路径，使用快速路径进行卸载。

逻辑接口与子接口上的流表配置

请使用 VyOS 配置中所用的接口名称配置流表。当涉及 VLAN、bond 或桥接时，该名称即为逻辑接口（例如 bond0、br0、eth0.10），而非底层物理端口。

例如：

  • 若配置了 bond0，VyOS 观察到的是 bond0，而非 eth0 或 eth1

  • 若配置了 br0，VyOS 观察到的是 br0，而非其成员接口

  • 流表必须引用 VyOS 实际观察到的相同接口名称

支持两种形式，但推荐注册父接口：

  • 注册 bond1 可对父接口及其所有 VLAN 子接口（例如 bond1.10、bond1.20 等）执行卸载——内核会通过解析 L2 头部自动发现它们（Linux 5.13+）。

  • 直接注册 bond1.10 仅对VLAN 10 流量执行卸载。但子接口必须在提交时已存在；若在规则集加载时尚未创建该子接口，则配置可能失败。

# 卸载 bond1 及其所有子接口（bond1.10、bond1.20 等）
set firewall flowtable FT01 interface 'bond1'

# 仅卸载 VLAN 10：直接注册子接口
set firewall flowtable FT01 interface 'bond1.10'

示例：混合父接口与子接口卸载

考虑以下场景：

  • 流量经 bond1.10（VLAN 10）进入

  • 流量经 bond2.20（VLAN 20）发出

set firewall flowtable FT01 interface 'bond1'
set firewall flowtable FT01 interface 'bond2.20'
set firewall ipv4 forward filter default-action 'drop'
set firewall ipv4 forward filter rule 10 action 'offload'
set firewall ipv4 forward filter rule 10 offload-target 'FT01'
set firewall ipv4 forward filter rule 10 state 'established'
set firewall ipv4 forward filter rule 20 action 'accept'
set firewall ipv4 forward filter rule 20 state 'established'
set firewall ipv4 forward filter rule 20 state 'related'
set firewall ipv4 forward filter rule 200 action 'accept'
set firewall ipv4 forward filter rule 200 inbound-interface name 'bond*'

在此配置中：

  • bond1 覆盖来自 bond1.10 及任何其他 bond1 子接口的入站流量。

  • bond2.20 仅卸载 VLAN 20 流量——其他 bond2 子接口仍走标准转发路径。这展示了如何有选择性地卸载单个 VLAN，同时让其余 VLAN 继续走慢速路径。

  • 规则 200 使用通配符，在连接达到 established 状态并具备卸载资格之前，接受任何到达任意 bond 接口或子接口的流量。

  • 一旦流建立完成，规则 10 将其加入流表，后续数据包将完全绕过转发钩子，通过快速路径转发。

注意

本示例中的接口方向是从客户端到服务器流量的角度出发。实际上，每个接口均双向处理流量，且流表在流建立后对称管理卸载。为确认入站和出站接口，请在转发钩子中的某条规则上启用 log 并检查防火墙日志——有关配置方法，请参阅 防火墙 章节。

接口识别

为验证 VyOS 是否按逻辑子接口（而非底层物理设备）识别流量，请检查防火墙日志：

vyos@FlowTables:~$ show log firewall
Jun 18 22:22:00 kernel: [ipv4-FWD-filter-200-A] IN=bond1.10 OUT=bond2.20 \
  MAC=00:53:00:00:00:02:00:53:00:00:00:01:08:00 SRC=192.168.10.2 \
  DST=192.168.20.2 LEN=84 PROTO=ICMP TYPE=8 CODE=0 ID=3572 SEQ=1

IN 和 OUT 字段显示的是 bond1.10 和 bond2.20 —— 即逻辑子接口，而非底层物理或 bond 设备。

条目中 Timeout 显示为 n/a 且 State 为空，表明该流已卸载至流表快速路径——后续数据包将完全绕过防火墙。一旦 TCP 会话关闭，该条目将转换为 TIME_WAIT 状态，超时计数器重新开始计时。
