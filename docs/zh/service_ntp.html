NTP

NTP（网络时间协议）是一种用于在分组交换、延迟可变的数据网络上实现计算机系统之间时钟同步的网络协议。自1985年以前开始运行以来，NTP是当前仍在使用的最古老的互联网协议之一。

NTP旨在将所有参与的计算机同步到与UTC相差几毫秒以内。它采用交集算法（Marzullo算法的一种改进版本）来选择准确的时间服务器，并专门设计用于缓解可变网络延迟的影响。NTP通常可在公共互联网上将时间维持在几十毫秒精度内，在局域网中理想条件下甚至可达到优于1毫秒的精度。非对称路由和网络拥塞可能导致100毫秒或更大的误差。

该协议通常以客户端-服务器模型描述，但同样适用于对等体（peer-to-peer）关系，其中双方均将对方视为潜在的时间源。实现通过UDP在端口123上发送和接收时间戳。

NTP会发出任何即将发生的闰秒调整警告，但不传输有关本地时区或夏令时的任何信息。

当前协议为第4版（NTPv4），其作为建议标准记录在RFC 5905中。它向后兼容第3版，后者在RFC 1305中定义。

注意

VyOS 1.4使用chrony替代ntpd（参见T3008），因此将不再接受如VyOS 1.3中那样的匿名NTP请求。所有现有配置将被迁移以保留匿名功能。对于新部署，若您有客户端将您的VyOS设备用作NTP服务器，则必须指定allow-client指令。

配置

set service ntp server <address>

配置一个或多个用于同步的服务器。服务器名称可以是IP地址或FQDN。

默认预置了3个NTP服务器。您可以修改它们。

  • time1.vyos.net

  • time2.vyos.net

  • time3.vyos.net

set service ntp server <address> <noselect | nts | pool | prefer | ptp | interleave>

为指定的NTP服务器配置一个或多个属性。

  • noselect将服务器标记为未使用（仅用于显示目的）。该服务器将被选择算法丢弃。

  • nts为该服务器启用网络时间安全（NTS），具体规范见RFC 8915。

  • pool激活与多个远程服务器的持久客户端模式关联。

  • prefer将服务器标记为首选。在其他条件相同的情况下，该主机将在一组正常运行的主机中被选为同步源。

  • ptp为此服务器启用PTP传输（参见NTP数据包的PTP传输）。

  • interleave启用NTP交错模式（参见draft-ntp-interleaved-modes），当通信双方均支持该模式时，可提升同步精度和稳定性。

set service ntp listen-address <address>

NTP进程仅监听指定的IP地址。您必须指定<address>，并可选地指定允许的客户端。同一IP族的多个监听地址已不再支持。IPv4和IPv6地址各只能配置一个，需分别使用独立命令进行配置。

set service ntp allow-client address <address>

允许访问本NTP服务器的网络或客户端地址列表。

可配置多个网络/客户端IP地址。

set service ntp vrf <name>

指定VRF实例的名称。

set service ntp leap-second [ignore|smear|system|timezone]

定义如何处理闰秒。

  • ignore：不对时钟应用闰秒校正。时钟将在后续常规运行中通过新的测量值进行校正，此时估计的偏移量将包含这一秒的误差。

  • smear：在“涂抹”闰秒时，服务器将抑制闰秒状态，并通过缓慢调整（slewing）而非跳变（stepping）方式逐步校正所提供的时间。客户端无需特殊配置，因为它们并不知晓存在闰秒，而是跟随服务器时间，最终自动回归UTC。必须确保客户端仅使用以完全相同方式“涂抹”闰秒的NTP服务器进行同步。

  • system：插入闰秒时，当系统时钟到达00:00:00 UTC时，内核将系统时钟向后拨动一秒；删除闰秒时，当系统时钟到达23:59:59 UTC时，内核将系统时钟向前拨动一秒。

  • timezone：该指令指定系统时区数据库中的一个时区，chronyd可利用该时区确定下一次闰秒发生的时间以及当前TAI与UTC之间的偏移量。它将周期性检查23:59:59和23:59:60在该时区是否为有效时间。此功能通常与right/UTC时区配合工作，而right/UTC时区即为默认时区。

NTP数据包的硬件时间戳

VyOS上的chrony守护进程可利用网卡（NIC）的硬件能力，精确记录数据包在接口上接收的确切时间，以及数据包实际发送的时间。当系统负载较高时，这能显著提升精度和稳定性，因为排队和操作系统上下文切换可能在网络数据包到达与NTP守护进程实际处理之间引入可变延迟。

硬件时间戳依赖于网卡的支持能力。部分网卡可配置为对任意入站数据包打时间戳，而另一些网卡则仅支持对特定协议（例如PTP）的数据包打时间戳。

当在某个接口上启用时间戳功能时，chrony的默认行为是尝试将该接口配置为仅对NTP数据包打时间戳。若该模式不受支持，chrony将尝试设置为对所有数据包打时间戳。若两种选项均不被支持（例如网卡仅支持对接收的PTP数据包打时间戳），chrony将仅利用发送数据包的时间戳，这仍能带来一定益处。

set service ntp timestamp interface <interface>

在接口<interface>上配置硬件时间戳。特殊值all也可指定，以在所有支持该功能的接口上启用时间戳。

使用以下选项配置时间戳行为：

  • receive-filter [all|ntp|ptp|none]选择接收过滤器模式，该模式控制网卡对哪些入站数据包打时间戳。所选模式必须受网卡支持，否则该接口的时间戳功能将被禁用。

以下receive-filter模式可供选择：

  • all：对所有接收到的数据包打时间戳。

  • ntp：仅对收到的NTP协议数据包打时间戳。

  • ptp：仅对收到的PTP协议数据包打时间戳。结合NTP数据包的PTP传输，此模式可用于充分利用仅支持ptp过滤模式的网卡的硬件时间戳能力。

  • none：不对任何接收到的数据包打时间戳。若网卡支持，仍将利用发送数据包的硬件时间戳。

NTP数据包的PTP传输

精密时间协议（IEEE 1588）是一种局域网时间同步协议，通过利用网卡及其他网络设备中的硬件时钟，提供高精度时间同步。VyOS目前不支持基于标准的PTP，而标准PTP可独立于NTP单独部署。

对于由VyOS及运行较新版本chrony守护进程的其他Linux系统组成的网络，NTP数据包可通过PTP进行“隧道传输”。NTP over PTP兼具两者优势：既利用了网卡对PTP数据包的硬件时间戳支持，又保留了NTP的配置灵活性和容错能力。

set service ntp ptp

启用NTP守护进程的PTP传输功能。NTP守护进程将在配置的PTP端口上监听。请注意，在守护进程通过该传输方式进行同步前，必须单独为一个或多个服务器启用PTP。

set service ntp ptp port <port>

配置PTP端口。默认情况下使用标准端口319。
