配置同步（Config sync）

配置同步（config-sync）是 VyOS 的一项服务，用于将一台路由器（主路由器）的选定配置部分复制到另一台路由器（备路由器）。该功能消除了手动将主路由器上的配置变更同步至备路由器的需要。

同步操作由主路由器上的提交后钩子（post-commit hook）执行。该钩子监控已选定用于同步的配置部分。当其中任一部分因某次提交而被修改时，钩子将调用备路由器的 HTTPS API，并以以下任一模式向其发送所有已选配置部分的当前状态：

  • load：使用主路由器的版本替换备路由器上对应的部分；仅存在于备路由器这些部分内的内容将被移除。

  • set：将主路由器所选部分的版本合并至备路由器；冲突的值将被主路由器的值覆盖；仅存在于备路由器的条目将被保留。

同步严格为单向，即仅从主路由器到备路由器；在备路由器上所做的任何更改均不会回传。

当主路由器对已配置部分执行提交操作时，两台路由器均须在线。若备路由器不可达，则主路由器的提交仍会成功，但配置无法同步，且失败信息将记录于系统日志中。

配置

备路由器参数

set service config-sync secondary address <address>

配置备路由器的地址。

主路由器通过备路由器的 HTTPS API 将同步配置推送至该地址。该值可以是 IPv4 地址、IPv6 地址或FQDN。此值为必需项。

注意

只要配置了 service config-sync，就必须设置该地址；否则提交将被拒绝。

示例：

set service config-sync secondary address 192.0.2.112
set service config-sync secondary port <1-65535>

配置备路由器 HTTPS API 所监听的 TCP 端口。

该值必须与备路由器上 service https port 所配置的端口一致。若两者不一致，则主路由器的提交仍会成功，但提交后的同步操作将失败。备路由器不会更新，且主路由器会将错误记录至系统日志。

默认值为 443，与 service https port 的默认值一致。

示例：

set service config-sync secondary port 8443
set service config-sync secondary key <key>

配置主路由器用于向备路由器 HTTPS API 进行身份验证的 HTTPS API 密钥。

该值必须与备路由器上 service https api keys id <ID> key 所配置的密钥匹配。若备路由器上不存在匹配的密钥，则主路由器的提交仍会成功，但提交后的同步操作将失败。备路由器不会更新，且主路由器会将错误记录至系统日志。

注意

只要配置了 service config-sync，就必须设置该值；否则提交将被拒绝。

示例：

set service config-sync secondary key 'foo'
set service config-sync secondary timeout <1-3600>

配置主路由器在推送配置后等待备路由器 HTTPS 响应的最长时间（单位：秒）。

默认值为 60 秒。

示例：

set service config-sync secondary timeout 120

同步模式

set service config-sync mode <load | set>

配置备路由器如何应用主路由器推送的配置：

  • load：使用主路由器的版本替换备路由器上对应的部分；仅存在于备路由器这些部分内的内容将被移除。

  • set：将主路由器所选部分的版本合并至备路由器；冲突的值将被主路由器的值覆盖；仅存在于备路由器的条目将被保留。

注意

只要配置了 service config-sync，就必须设置该值；否则提交将被拒绝。

示例：

set service config-sync mode load

待同步的配置部分

set service config-sync section <section>

配置一个或多个需从主路由器同步至备路由器的配置部分。

重复执行该命令可添加更多部分。若主路由器的某次提交修改了任一已配置的部分，则钩子将把所有已配置部分的当前状态推送至备路由器；若本次提交未修改任何已配置的部分，则钩子不执行任何操作。

支持的配置部分包括：

  • firewall

  • interfaces <bonding | bridge | dummy | ethernet | geneve | input | l2tpv3 | loopback | macsec | openvpn | pppoe | pseudo-ethernet | sstpc | tunnel | virtual-ethernet | vti | vxlan | wireguard | wireless | wwan>

  • nat

  • nat66

  • pki

  • policy

  • protocols <babel | bfd | bgp | failover | igmp-proxy | isis | mpls | nhrp | ospf | ospfv3 | pim | pim6 | rip | ripng | rpki | segment-routing | static>

  • qos <interface | policy>

  • service <console-server | dhcp-relay | dhcp-server | dhcpv6-relay | dhcpv6-server | dns | lldp | mdns | monitoring | ndp-proxy | ntp | snmp | tftp-server | webproxy>

  • system <conntrack | flow-accounting | login | option | sflow | static-host-mapping | sysctl | time-zone>

  • vpn

  • vrf

注意

只要配置了 service config-sync，则至少需设置一个配置部分；否则提交将被拒绝。

示例：

set service config-sync section protocols ospf
set service config-sync section system time-zone

运行

show configuration secondary sync [commands] [running | candidate | saved [<config-node-path>]]

显示主路由器本地配置与备路由器当前运行配置之间的差异。

该命令通过 HTTPS API 实时获取备路由器的运行配置，因此备路由器必须可达。

本地配置默认为 running，也可设为 candidate（未提交的变更）或 saved（上次保存的配置）。远程端始终为备路由器的运行配置。

默认情况下，差异以花括号格式显示：- 表示仅存在于备路由器的行，+ 表示仅存在于主路由器的行。可选的 commands 关键字则将相同差异渲染为一系列 set 和 delete 配置命令，其中 set 列出仅存在于主路由器的路径，delete 列出仅存在于备路由器的路径。

可选参数 <config-node-path> 将差异限制于单一配置部分，且该参数必须是已在 set service config-sync section 下配置的某个部分。若省略该参数，则差异涵盖所有已配置的部分。

示例：

# 将完整运行配置与备路由器进行比较
show configuration secondary sync

# 仅将 OSPF 协议配置与备路由器进行比较
show configuration secondary sync running protocols ospf

# 将候选配置与备路由器进行比较，并以命令形式呈现
show configuration secondary sync commands candidate

示例

以下示例将路由器 A（主路由器，192.0.2.1）的 system time-zone 和 protocols ospf 部分同步至路由器 B（备路由器，192.0.2.112）。路由器 B 的 HTTPS API 监听于 TCP 端口 8443。

在路由器 B 上启用并配置 HTTPS API 服务：

set service https listen-address '192.0.2.112'
set service https port '8443'
set service https api keys id primary key 'foo'
set service https api rest

在路由器 A 上配置 config-sync 服务：

set service config-sync mode 'load'
set service config-sync secondary address '192.0.2.112'
set service config-sync secondary port '8443'
set service config-sync secondary key 'foo'
set service config-sync section protocols 'ospf'
set service config-sync section system 'time-zone'

在路由器 A 上对任一已同步部分进行修改。提交后钩子将在提交时自动触发：

vyos@vyos-A# set system time-zone 'America/Los_Angeles'
vyos@vyos-A# commit
INFO:vyos_config_sync:Config synchronization: Mode=load, Secondary=192.0.2.112
vyos@vyos-A# save

vyos@vyos-A# set protocols ospf area 0 network '198.51.100.0/30'
vyos@vyos-A# commit
INFO:vyos_config_sync:Config synchronization: Mode=load, Secondary=192.0.2.112
vyos@vyos-A# save

每次在路由器 A 上的提交仅修改一个部分，但由于钩子会在任一已配置部分被修改时推送全部已配置部分，因此这两次提交均会完全替换路由器 B 上的 system 和 protocols ospf 部分。

在路由器 B 上验证变更是否已生效：

vyos@vyos-B:~$ show configuration commands | match time-zone
set system time-zone 'America/Los_Angeles'

vyos@vyos-B:~$ show configuration commands | match ospf
set protocols ospf area 0 network '198.51.100.0/30'
