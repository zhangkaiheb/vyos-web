L2TPv3

L2TPv3 接口允许您建立 L2TPv3 隧道，以在 IP 网络上承载第二层流量。

L2TPv3 协议（定义于 RFC 3931）将第二层帧（例如以太网、帧中继、HDLC）封装在 IP 数据包内，使其能够穿越底层 IP 基础设施。

与严格要求 UDP 封装的 L2TPv2 不同，L2TPv3 协议更加灵活，支持两种封装类型：

  • 直接 IP 封装： 隧道数据直接封装在 IP 数据包内（协议号 115），开销更低。

  • UDP 封装： 隧道数据封装在 UDP 数据报内。这使得隧道更容易穿越 NAT 设备。

L2TPv3 隧道连接地理上分离的站点，通过基于基本 IP 连接运行，而非需要完整的 MPLS 基础设施，从而成为 MPLS 的一种更简单替代方案。

L2TPv3 隧道可在 IPv4 和 IPv6 底层网络上建立。

配置

通用接口配置

set interfaces l2tpv3 <interface> address <address>

配置一个或多个接口 IP 地址。

<address> 支持 CIDR 表示法的 IPv4 和 IPv6 地址。例如，IPv4 使用 192.0.2.1/24，IPv6 使用 2001:db8::1/64。

示例：

set interfaces l2tpv3 l2tpeth0 address 192.0.2.1/24
set interfaces l2tpv3 l2tpeth0 address 2001:db8::1/64
set interfaces l2tpv3 <interface> description <description>

为接口配置清晰、描述性的别名。

该别名会显示在 show interfaces 命令以及基于 SNMP 的监控工具中。

示例：

set interfaces l2tpv3 l2tpeth0 description '这是一个在 VyOS 上运行的接口。'
set interfaces l2tpv3 <interface> disable

禁用该接口。

该接口将被设置为管理性关闭（A/D）状态。

示例：

set interfaces l2tpv3 l2tpeth0 disable
set interfaces l2tpv3 <interface> disable-flow-control

在接口上禁用以太网流控（IEEE 802.3x 暂停帧）。

由 IEEE 802.3x 标准定义的以太网流控机制，在网络拥塞期间临时停止数据传输，以防止丢包。例如，当发送方传输数据的速度超过接收方处理能力时。

禁用以太网流控意味着该接口不会向相连设备发出暂停传输信号，并在过载时直接丢弃数据包。

示例：

set interfaces l2tpv3 l2tpeth0 disable-flow-control
set interfaces l2tpv3 <interface> disable-link-detect

在接口上禁用物理链路状态变化检测（例如拔掉网线时）。

默认情况下，接口会检测物理链路状态变化。

示例：

set interfaces l2tpv3 l2tpeth0 disable-link-detect
set interfaces l2tpv3 <interface> mac <xx:xx:xx:xx:xx:xx>

在接口上配置自定义 MAC 地址。

示例：

set interfaces l2tpv3 l2tpeth0 mac '00:53:01:02:03:04'
set interfaces l2tpv3 <interface> mtu <mtu>

在接口上配置 MTU。

该值定义了接口在不分片的情况下可传输的最大数据包大小（字节）。

示例：

set interfaces l2tpv3 l2tpeth0 mtu 1600
set interfaces l2tpv3 <interface> ip adjust-mss <mss | clamp-mss-to-pmtu>

配置指定接口上出站 TCP SYN 数据包中通告的 MSS 值。

通过限制 TCP SYN 数据包中的 MSS 值，可明确告知远端不要发送大于该尺寸的数据包。这可以防止路径 MTU 发现（PMTUD）失败时出现的连接问题。

以下选项可用：

  • mss： 将 MSS 设置为特定字节数值。若需强制执行特定 MSS（例如排查连通性问题或满足特定网络需求），请使用此选项。

  • clamp-mss-to-pmtu： 路由器自动计算 MSS，其值为接口 MTU 减去 IPv4 流量的 40 字节（IPv4 报头 20 字节 + TCP 报头 20 字节）。推荐使用此选项以自动设置合适值。

set interfaces l2tpv3 <interface> ip arp-cache-timeout

配置 ARP 条目在本接口学习到 IP 到 MAC 地址映射后保持有效的时间长度。

默认持续时间为 30 秒。

若 ARP 条目从更高层协议获得正向反馈，则保持有效。

示例：

set interfaces l2tpv3 l2tpeth0 ip arp-cache-timeout 180
set interfaces l2tpv3 <interface> ip disable-arp-filter

在本接口上配置 ARP 过滤。

默认行为： 内核仅当流量将通过该特定接口路由回 ARP 请求发送方时，才响应本接口上的 ARP 请求。

若已配置： 内核响应本接口上针对本地主机配置的任意 IP 地址的 ARP 请求，而不论该 IP 地址分配给哪个具体接口，也不论路由表如何。这体现了 Linux 的概念：IP 地址属于主机，而非单个接口。

示例：

set interfaces l2tpv3 l2tpeth0 ip disable-arp-filter
set interfaces l2tpv3 <interface> ip disable-forwarding

配置接口为主机模式或路由器模式行为。

若已配置，接口将切换至主机模式，且在其上禁用 IPv4 转发功能。

示例：

set interfaces l2tpv3 l2tpeth0 ip disable-forwarding
set interfaces l2tpv3 <interface> ip enable-directed-broadcast

配置是否转发在本接口上接收到的 IP 定向广播数据包。

默认行为： IP 定向广播数据包被丢弃。

若已配置： IP 定向广播数据包将根据 RFC 1812 和 RFC 2644 的定义，转发至目标子网内的所有主机。

示例：

set interfaces l2tpv3 l2tpeth0 ip enable-directed-broadcast
set interfaces l2tpv3 <interface> ip enable-arp-accept

配置本接口如何处理免费 ARP（gratuitous ARP）。

若已配置，将根据免费 ARP 请求或应答，在 ARP 表中添加 IP 到 MAC 地址映射。

注意

如果 ARP 表中已存在来自免费 ARP 的 IP 地址条目，则无论是否启用此设置，该条目均会被更新。

示例：

set interfaces l2tpv3 l2tpeth0 ip enable-arp-accept
set interfaces l2tpv3 <interface> ip enable-arp-announce

配置本接口上 ARP 请求的源 IP 地址选择方式。

默认行为： 内核可使用主机拥有的任意 IP 地址作为本接口 ARP 请求的源 IP 地址。

若已配置： 内核首先尝试选择一个配置在本接口上、且与目标 IP 地址处于同一子网的源 IP 地址。若无此类子网，则内核选择其通常使用的 IP 地址（即根据路由表到达目标目的地所选的地址）。

示例：

set interfaces l2tpv3 l2tpeth0 ip enable-arp-announce
set interfaces l2tpv3 <interface> ip enable-arp-ignore

配置本接口上将忽略哪些 ARP 请求。

默认行为： 内核响应任何本地 IP 地址的 ARP 请求，而不论这些地址分配给哪个接口。

若已配置： 内核仅当目标 IP 地址分配给本特定接口时，才响应 ARP 请求。

示例：

set interfaces l2tpv3 l2tpeth0 ip enable-arp-ignore
set interfaces l2tpv3 <interface> ip enable-proxy-arp

在本接口上配置代理 ARP。

若已配置，路由器（内核）将截获针对非本地 IP 地址的 ARP 请求，并以接收请求的接口的 MAC 地址进行应答。后续发往这些 IP 地址的数据包将被转发至远程子网的实际目的地。

示例：

set interfaces l2tpv3 l2tpeth0 ip enable-proxy-arp
set interfaces l2tpv3 <interface> ip proxy-arp-pvlan

在接口上配置本地代理 ARP。

若已配置，路由器（内核）即使目标 IP 地址位于同一子网和接口上，也会响应本 VLAN 接口上的 ARP 请求。

此功能用于支持私有 VLAN（PVLAN）的网络隔离需求（RFC 3069）。在 PVLAN 配置中，隔离端口上的主机在第二层不允许直接相互通信，但可与上游路由器通信。

通过以自身 MAC 地址应答主机间 ARP 请求，路由器（内核）将主机间流量引导至自身，而非主机之间直接通信。

注意

此命令独立工作，无需在接口上启用标准代理 ARP。

本地代理 ARP 也称为：

  • VLAN 聚合（RFC 3069）。

  • 私有 VLAN（Cisco、Allied Telesyn）。

  • 源端口过滤或端口隔离（Hewlett-Packard）。

  • MAC 强制转发（Ericsson）。

set interfaces l2tpv3 <interface> ip source-validation <strict | loose | disable>

根据 RFC 3704 的规定，在本接口上使用 RPF 配置源 IP 地址验证。

以下选项可用：

  • strict： 检查每个入站数据包的源 IP 地址是否与转发信息库（FIB）匹配。若该接口并非返回该源地址的最佳路径，则验证失败，数据包被丢弃。

  • loose： 检查每个入站数据包的源 IP 地址是否与 FIB 匹配。若源 IP 地址无法通过任何接口到达，则验证失败。

  • disable： 不执行源 IP 地址验证，接受所有入站数据包。

RFC 3704 建议启用严格模式以防止 IP 欺骗（如 DDoS 攻击）。对于非对称路由或其他复杂路由场景，请使用宽松模式。

set interfaces l2tpv3 <interface> ipv6 address autoconf

根据 RFC 4862 的规定，配置接口使用 SLAAC 自动获取 IPv6 地址。

IPv6 主机在连接到 IPv6 网络时，可通过 ICMPv6 路由器发现消息利用邻居发现协议（NDP）自动配置自身。主机首次连接到网络时，会发送链路本地路由器请求组播请求以获取配置参数。路由器则以包含网络层配置参数的路由器通告数据包进行响应。

注意

此方法将自动禁用接口上的 IPv6 流量转发功能。

示例：

set interfaces l2tpv3 l2tpeth0 ipv6 address autoconf
set interfaces l2tpv3 <interface> ipv6 address eui64 <prefix>

根据 RFC 4291 的规定，配置接口使用 EUI-64 方法为自己分配 IPv6 地址。

示例：

set interfaces l2tpv3 l2tpeth0 ipv6 address eui64 2001:db8:beef::/64
set interfaces l2tpv3 <interface> ipv6 address no-default-link-local

禁用为此接口自动分配链路本地 IPv6 地址的功能。

示例：

set interfaces l2tpv3 l2tpeth0 ipv6 address no-default-link-local
set interfaces l2tpv3 <interface> ipv6 disable-forwarding

配置接口为主机模式或路由器模式行为。

若已配置，接口将切换至主机模式，且在其上禁用 IPv6 转发功能。

示例：

set interfaces l2tpv3 l2tpeth0 ipv6 disable-forwarding
set interfaces l2tpv3 <interface> ipv6 adjust-mss <mss | clamp-mss-to-pmtu>

配置指定接口上出站 TCP SYN 数据包中通告的 MSS 值。

通过限制 TCP SYN 数据包中的 MSS 值，可明确告知远端不要发送大于该尺寸的数据包。这可以防止路径 MTU 发现（PMTUD）失败时出现的连接问题。

以下选项可用：

  • mss： 将 MSS 设置为特定字节数值。使用此选项可强制执行特定 MSS，例如用于排查连通性问题或满足特定网络需求。

  • clamp-mss-to-pmtu： 路由器计算 MSS 值为接口 MTU 减去 IPv6 流量的 60 字节（IPv6 报头 40 字节 + TCP 报头 20 字节）。推荐使用此选项以自动设置合适值。

set interfaces l2tpv3 <interface> ipv6 accept-dad <0 | 1 | 2>

在接口上配置 IPv6 DAD 功能。

以下选项可用：

  • 0： 禁用 DAD。不执行重复地址检测。

  • 1： 启用 DAD（默认）。检测重复地址。接口的 IPv6 操作对有效 IPv6 地址继续进行。

  • 2： 启用 DAD；若发现基于 MAC 的重复链路本地地址，则禁用本接口上的 IPv6 操作。

示例：

set interfaces l2tpv3 l2tpeth0 ipv6 accept-dad 2
set interfaces l2tpv3 <interface> ipv6 dup-addr-detect-transmits <n>

配置路由器（内核）在本接口上分配 IPv6 地址期间发送的 DAD 消息数量。

默认值为 1。

示例：

set interfaces l2tpv3 l2tpeth0 ipv6 dup-addr-detect-transmits 5
set interfaces l2tpv3 <interface> vrf <vrf>

将接口分配给特定的 VRF 实例。

另请参阅

有关配置 VRF 的信息，请参阅 VRF 章节。

示例：

set interfaces l2tpv3 l2tpeth0 vrf red

L2TPv3 选项

使用以下命令配置 L2TPv3 隧道的具体参数。

set interfaces l2tpv3 <interface> encapsulation <udp | ip>

配置 L2TPv3 隧道的封装类型。

有效值为 udp 和 ip。

默认封装类型为 udp。

注意

封装类型必须在本地和远端对等体上保持一致，隧道才能建立成功。

set interfaces l2tpv3 <interface> source-address <address>

配置 L2TPv3 隧道的源 IP 地址。

指定的地址必须是本地接口的 IP 地址，可以是 IPv4 或 IPv6。

set interfaces l2tpv3 <interface> remote <address>

配置 L2TPv3 隧道的目的地 IP 地址。

指定的地址必须是远端对等体接口的 IP 地址，可以是 IPv4 或 IPv6。

set interfaces l2tpv3 <interface> session-id <id>

配置 L2TPv3 隧道内的本地会话 ID。

session-id 是一个 32 位值，用于标识本地对等体上的入站隧道会话。

远端对等体上标识此会话的 peer-session-id 必须设置为相同值。

set interfaces l2tpv3 <interface> peer-session-id <id>

配置 L2TPv3 隧道内的对等体会话 ID。

peer-session-id 是一个 32 位值，用于标识本地对等体上的出站隧道会话。

peer-session-id 必须与远端对等体上为此会话配置的 session-id 相匹配。

set interfaces l2tpv3 <interface> tunnel-id <id>

配置 L2TPv3 隧道的本地标识符。

tunnel-id 是一个 32 位值，用于标识本地对等体上的 L2TPv3 隧道。

远端对等体上标识此隧道的 peer-tunnel-id 必须设置为相同值。

set interfaces l2tpv3 <interface> peer-tunnel-id <id>

配置 L2TPv3 隧道的对等体标识符。

peer-tunnel-id 是一个 32 位值，用于标识远端对等体上的 L2TPv3 隧道，且必须与该对等体上为此隧道配置的 tunnel-id 相对应。

peer-tunnel-id 必须与远端对等体上标识此隧道的 tunnel-id 相匹配。

示例

采用 IP 封装的 L2TPv3 隧道

以下示例展示了使用直接 IP 封装的 L2TPv3 隧道配置：

# show interfaces l2tpv3
l2tpv3 l2tpeth10 {
    address 192.168.37.1/27
    encapsulation ip
    source-address 192.0.2.1
    peer-session-id 100
    peer-tunnel-id 200
    remote 203.0.113.24
    session-id 100
    tunnel-id 200
}

远端对等体必须应用相反的配置。

采用 UDP 封装的 L2TPv3 隧道

以下示例展示了使用 UDP 封装的 L2TPv3 隧道配置。

当隧道穿越 NAT 设备时，建议采用此配置。

配置注意事项：

  • 将本地局域网 IP 地址用作 source-address。

  • 在上游 NAT 设备上配置转发规则，以允许指定 UDP 端口上的隧道流量。

  • 为每个单独的隧道使用不同的 UDP 端口。

# show interfaces l2tpv3
l2tpv3 l2tpeth10 {
    address 192.168.37.1/27
    destination-port 9001
    encapsulation udp
    source-address 192.0.2.1
    peer-session-id 100
    peer-tunnel-id 200
    remote 203.0.113.24
    session-id 100
    source-port 9000
    tunnel-id 200
}
