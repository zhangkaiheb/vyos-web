登录/用户管理

默认的 VyOS 用户账户（vyos）以及新创建的用户账户均拥有完整的系统配置权限。这些账户被授予 sudo 权限，允许其以 root 用户身份执行命令。

VyOS 支持本地认证和通过 RADIUS/TACACS+ 进行的远程认证。

本地认证

set system login user <name> full-name “<string>”

为系统用户配置真实姓名或描述信息。

如果描述中包含空格，请将 <string> 用双引号括起。

如果用户 <name> 已存在，则该命令会更新当前描述；否则，它将创建一个具有指定描述的新用户。

set system login user <name> authentication plaintext-password <password>

为系统用户配置密码。

以明文形式输入密码。在执行 commit 后，VyOS 将对密码进行哈希处理以实现安全存储，并移除明文值。

如果用户 <name> 已存在，则该命令会更新当前密码；否则，它将创建一个具有指定明文密码的新用户。

set system login user <name> authentication encrypted-password <password>

为系统用户配置预加密密码。

以哈希格式输入密码。在执行 commit 后，VyOS 将直接存储该值而不作任何修改。

如果用户 <name> 已存在，则该命令会更新当前密码；否则，它将创建一个具有指定预加密密码的新用户。

set system login user <name> authentication principal <principal>

为系统用户配置 SSH 证书主体（principal）。

输入主体（即用户已签名 SSH 证书中包含的字符串）。在执行 commit 后，VyOS 将存储此映射关系，当用户出示的证书包含该主体时，即可成功登录。

如果用户 <name> 已存在，则该命令会更新主体；否则，它将创建一个与指定主体关联的新用户。

若未配置，则主体默认为 <name>。

set system login user <name> disable

禁用系统用户账户。

VyOS 将锁定该账户，阻止用户登录。

基于密钥的认证

基于密钥的认证是 VyOS 中保障 SSH 访问安全的推荐方法。它使用公钥/私钥对来验证用户身份，而无需密码。要授权访问，您需将SSH 公钥分配给路由器上的用户账户，而 SSH 私钥则保留在本地设备上。VyOS 允许为单个用户账户分配多个 SSH 公钥，这对于从不同设备访问路由器非常有用。

生成密钥对

请在您的本地机器上使用 ssh-keygen 命令生成 SSH 密钥对。这将创建两个文件：

  • 私钥（例如 id_rsa）：保留在您的本地机器上，且绝不可共享。

  • 公钥（例如 id_rsa.pub）：用于配置 VyOS 用户账户。默认情况下，它保存在 ~/.ssh/id_rsa.pub 中。

每个 SSH 公钥由三部分组成，各部分之间以空格分隔：

  • 加密算法类型：ssh-rsa、ssh-ed25519 等。

  • 密钥：实际数据（以 AAAA... 开头的长字符串）。

  • 注释：供您参考的标识符（例如 user@host）。

在 VyOS 中配置授权条目时，仅需加密算法类型和密钥部分。注释部分为可选。

另请参阅

SSH 操作

警告

SSH 密钥字符串较长。复制粘贴时，请确保终端不会插入换行符。密钥必须作为单行输入才能正常工作。

配置路由器

要为用户账户配置 SSH 公钥认证，请使用相同的 <identifier> 执行以下两条命令：

set system login user <username> authentication public-keys <identifier> key <key>

为用户账户配置 SSH 公钥。

  • <identifier>：唯一标识此特定密钥条目的标签。

  • <key>：您公钥中的实际字符字符串。

set system login user <username> authentication public-keys <identifier> type <type>

配置 SSH 密钥的加密类型。

支持以下加密算法类型：

  • ecdsa-sha2-nistp256

  • ecdsa-sha2-nistp384

  • ecdsa-sha2-nistp521

  • ssh-dss

  • ssh-ed25519

  • ssh-rsa

注意

如需为用户账户分配多个 SSH 公钥，请重复上述命令，并为每个密钥指定唯一的标识符。

set system login user <username> authentication public-keys <identifier> options <options>

为 SSH 公钥配置特定的限制或行为。

<options>：定义此密钥权限或限制的逗号分隔字符串。

该命令接受路由器 ~/.ssh/authorized_keys 文件中列出的标准 OpenSSH 选项。

如需在选项字符串中包含 " 字符，请使用 &quot;。

例如，要限制 SSH 公钥允许的源 IP 地址，请使用：from=&quot;10.0.0.0/24&quot;。

基于一次性密码（OTP）的多因素认证（MFA）

VyOS 允许您通过为个别用户启用基于OTP的MFA来增强用户访问安全性。启用基于OTP的MFA的用户在登录时必须同时输入有效的OTP和密码。未启用基于OTP的MFA的用户则使用标准认证方式。

set system login user <username> authentication otp key <key>

为用户配置OTP的MFA。

<key>：Base32 编码的密钥。该密钥必须添加到用户的认证器应用程序中，以生成有效的OTP。

配置后，用户在后续所有登录过程中均需先输入密码，再输入有效的 OTP。

OTP 设置

set system login user <username> authentication otp rate-limit <limit>

配置在指定时间段内允许的OTP认证尝试次数。

若超出此限制，用户将被临时阻止登录。

默认值为 3 次。有效范围为 1 至 10 次。

set system login user <username> authentication otp rate-time <seconds>

配置跟踪OTP认证尝试的时间段（单位：秒）。

默认值为 30 秒。有效范围为 1 至 600 秒。

set system login user <username> authentication otp window-size <size>

为用户配置OTP窗口大小。

OTP 窗口大小定义了认证服务器接受的同时有效的OTP数量。此设置假设每 30 秒生成一个新令牌。

默认值为 3。这意味着允许 3 个并发代码：当前 30 秒间隔内的代码、前一个代码和后一个代码。这允许认证服务器与客户端之间最多存在 30 秒的时间偏差。

若将窗口大小增加至 17，则系统允许 17 个并发代码（当前代码、前 8 个代码和后 8 个代码），从而允许最多 4 分钟的时间偏差。

有效范围为 1 至 21。

RADIUS 认证

对于大规模部署，跨多个 VyOS 实例单独管理用户账户效率低下。VyOS 支持通过RADIUS进行集中式认证，将用户账户管理统一到单一后端服务器上。

配置

set system login radius server <address> key <secret>

配置RADIUS服务器的 IP 地址和共享密钥。

共享密钥用于验证路由器的身份，并在认证过程中加密用户密码。

您可以配置多个RADIUS服务器。

set system login radius server <address> port <port>

配置与RADIUS服务器通信所使用的 UDP 端口。

默认端口为 1812。

set system login radius server <address> disable

在认证过程中禁用某个RADIUS服务器。

禁用特定RADIUS服务器并不会删除其配置设置（服务器的 IP 地址和共享密钥）。

set system login radius server <address> timeout <timeout>

配置 VyOS 路由器在发送认证请求后等待RADIUS服务器响应的持续时间（单位：秒）。

若服务器在此时间段内无响应，VyOS 路由器将尝试连接其他已配置的服务器，或回退至本地认证。

set system login radius source-address <address>

配置路由器用于RADIUS认证请求的源 IP 地址。

建议使用一致的源 IP 地址，因为 RADIUS 服务器通常只接受来自已知可信 IP 地址的请求。

若未显式定义，路由器将使用当前出口接口地址，该地址可能发生变化（例如因链路中断），从而导致认证失败。

set system login radius vrf <name>

配置路由器通过特定 VRF 发送所有RADIUS认证请求。

默认情况下，RADIUS认证请求通过全局路由表发送。

配置示例

set system login radius server 192.168.0.2 key 'test-vyos'
set system login radius server 192.168.0.2 port '1812'
set system login radius server 192.168.0.2 timeout '5'
set system login radius source-address '192.168.0.1'

若与RADIUS服务器的通信失败，路由器将回退至本地用户认证。在此过程中，用户可能会因系统等待RADIUS请求超时而经历登录延迟。此延迟取决于所配置的超时值。

提示

要向经RADIUS认证的用户授予管理权限，服务器必须返回 Cisco-AV-Pair 属性，其值设为 shell:priv-lvl=15。否则，用户仅获得标准权限，无法执行配置任务。

TACACS+ 认证

除了RADIUS外，VyOS 还支持TACACS+，后者常用于大型企业环境中。

与RADIUS不同，TACACS+ 将认证（Authentication）、授权（Authorization）和计费（Accounting）（AAA）分离为独立流程，并对整个数据包载荷进行加密，以增强安全性。

TACACS+ 在 RFC 8907 中定义。

配置

set system login tacacs server <address> key <secret>

配置TACACS+服务器的 IP 地址和共享密钥。

与仅加密密码的RADIUS不同，TACACS+ 对整个数据包载荷进行加密，以增强安全性。

您可以配置多个TACACS+服务器。

set system login tacacs server <address> port <port>

配置与TACACS+服务器通信所使用的 TCP 端口。

默认端口为 49。

set system login tacacs server <address> disable

在认证过程中禁用某个TACACS+服务器。

禁用特定TACACS+服务器并不会删除其配置设置（服务器的 IP 地址和共享密钥）。

set system login tacacs server <address> timeout <timeout>

配置 VyOS 路由器在发送认证请求后等待TACACS+服务器响应的持续时间（单位：秒）。

若服务器在此时间段内无响应，VyOS 路由器将尝试连接其他已配置的服务器，或回退至本地认证。

set system login tacacs source-address <address>

配置路由器用于TACACS+认证请求的源 IP 地址。

建议使用一致的源 IP 地址，因为TACACS+服务器通常只接受来自已知可信 IP 地址的请求。

若未显式定义，路由器将使用当前出口接口地址，该地址可能发生变化（例如因链路中断），从而导致认证失败。

set system login tacacs vrf <name>

配置路由器通过特定 VRF 发送所有TACACS+认证请求。

默认情况下，TACACS+认证请求通过全局路由表发送。

配置示例

set system login tacacs server 192.168.0.2 key 'test-vyos'
set system login tacacs server 192.168.0.2 port '49'
set system login tacacs source-address '192.168.0.1'

若与TACACS+服务器的通信失败，路由器将回退至本地用户认证。

登录横幅

VyOS 允许您配置登录前和登录后横幅。登录前横幅通常用于系统标识、法律免责声明或安全警告，显示于认证之前；登录后横幅则在用户登录后提供系统信息或操作通知。

set system login banner pre-login <message>

配置一条消息，在出现 username 和 password 提示之前向用户显示。

set system login banner post-login <message>

配置一条消息，在成功认证后向用户显示。

注意

在多行横幅消息中使用 \\n 插入换行符。

登录会话限制

set system login max-login-session <number>

配置最大并发登录会话数。

注意

如果您限制并发登录会话数，则还必须配置会话 <timeout>。这将清除非活跃会话，防止阻塞新的登录尝试。

set system login timeout <timeout>

配置登录会话超时时间（单位：秒）。

空闲登录会话将在该时间段后终止。

配置示例

示例 1：带 MFA 和源限制的多密钥 SSH

在此配置中，User1 和 User2 均使用 vyos 用户账户，各自拥有唯一的 SSH 密钥。User1 的认证被限制为仅来自单一 IP 地址。

对于两位用户，基于密码的登录均需要基于OTP的MFA。

set system login user vyos authentication public-keys 'User1' key "AAAAB3Nz...KwEW"
set system login user vyos authentication public-keys 'User1' type ssh-rsa
set system login user vyos authentication public-keys 'User1' options "from=&quot;192.168.0.100&quot;"

set system login user vyos authentication public-keys 'User2' key "AAAAQ39x...fbV3"
set system login user vyos authentication public-keys 'User2' type ssh-rsa

set system login user vyos authentication otp key OHZ3OJ7U2N25BK4G7SOFFJTZDTCFUUE2
set system login user vyos authentication plaintext-password vyos

示例 2：具备冗余性的容器化TACACS+部署

在此配置中，VyOS 路由器通过两个容器化的TACACS+服务器（tacacs1 和 tacacs2）在私有网络上托管自身的认证基础设施，以实现冗余性。

系统登录将针对这些内部容器中存储的凭证进行认证，而非路由器的本地用户数据库。

首先，在操作模式下下载镜像：

add container image lfkeitel/tacacs_plus:latest

接下来，在配置模式下配置容器：

set container network tac-test prefix '100.64.0.0/24'

set container name tacacs1 image 'lfkeitel/tacacs_plus:latest'
set container name tacacs1 network tac-test address '100.64.0.11'

set container name tacacs2 image 'lfkeitel/tacacs_plus:latest'
set container name tacacs2 network tac-test address '100.64.0.12'

set system login tacacs server 100.64.0.11 key 'tac_plus_key'
set system login tacacs server 100.64.0.12 key 'tac_plus_key'

commit

现在，您可以使用容器镜像提供的 admin/admin 凭据通过 SSH 或控制台登录。
