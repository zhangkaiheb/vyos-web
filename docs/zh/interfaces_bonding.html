链路聚合（Bond）

聚合接口 将多个网络接口聚合为一个逻辑接口（称为聚合组、LAG、EtherChannel 或端口通道）。

聚合接口的行为取决于所选模式。这些模式可提供故障容错能力，或同时提供负载均衡与故障容错能力。此外，聚合接口还可配置链路完整性监控功能。

配置

通用接口配置

set interfaces bonding <interface> address <address | dhcp | dhcpv6>

为接口配置一个或多个 IP 地址。

可用选项如下：

  • address： 为接口分配一个或多个 IPv4 或 IPv6 地址。例如，IPv4 使用 192.0.2.1/24，IPv6 使用 2001:db8::1/64。

  • dhcp： 接口从同一网段上的 DHCP 服务器获取 IPv4 地址。

  • dhcpv6： 接口从同一网段上的 DHCPv6 服务器获取 IPv6 地址。

注意

如果接口通过 DHCP 获取 IPv4 地址，并且需要在获取 IP 地址前/后进行特定调整，请使用提供的钩子脚本：

  • /config/scripts/dhcp-client/pre-hooks.d/

  • /config/scripts/dhcp-client/post-hooks.d/

示例：

set interfaces bonding bond0 address 192.0.2.1/24
set interfaces bonding bond0 address 2001:db8::1/64
set interfaces bonding bond0 address dhcp
set interfaces bonding bond0 address dhcpv6
set interfaces bonding <interface> description <description>

为接口配置清晰、描述性的别名。

该别名将显示在 show interfaces 命令及基于 SNMP 的监控工具中。

示例：

set interfaces bonding bond0 description '这是运行于 VyOS 上的一个接口。'
set interfaces bonding <interface> disable

禁用该接口。

该接口将被设置为管理性关闭（A/D）状态。

示例：

set interfaces bonding bond0 disable
set interfaces bonding <interface> disable-flow-control

禁用该接口上的以太网流控（IEEE 802.3x 暂停帧）。

以太网流控由 IEEE 802.3x 标准定义，可在网络拥塞时临时停止数据传输，防止丢包。例如，当发送方传输数据的速度超过接收方处理能力时。

禁用以太网流控意味着该接口不会向连接设备发出暂停传输信号，而是在过载时直接丢弃数据包。

示例：

set interfaces bonding bond0 disable-flow-control
set interfaces bonding <interface> disable-link-detect

禁用该接口上的物理链路状态变更检测（例如拔掉网线时）。

默认情况下，接口会检测物理链路状态变更。

示例：

set interfaces bonding bond0 disable-link-detect
set interfaces bonding <interface> mac <xx:xx:xx:xx:xx:xx>

在接口上配置自定义 MAC 地址。

示例：

set interfaces bonding bond0 mac '00:53:01:02:03:04'
set interfaces bonding <interface> mtu <mtu>

在接口上配置 MTU。

该值定义了接口在不分片情况下可传输的最大数据包大小（字节）。

示例：

set interfaces bonding bond0 mtu 1600
set interfaces bonding <interface> ip adjust-mss <mss | clamp-mss-to-pmtu>

配置在指定接口上向外发送的 TCP SYN 数据包中通告的 MSS 值。

通过限制 TCP SYN 数据包中的 MSS 值，可明确告知远端不要发送大于该尺寸的数据包，从而避免路径 MTU 发现（PMTUD）失败导致的连接问题。

可用选项如下：

  • mss： 将 MSS 设置为特定字节数值。若需强制执行特定 MSS（例如排查连通性问题或满足特定网络需求），请使用此选项。

  • clamp-mss-to-pmtu： 路由器自动计算 MSS，使其等于接口 MTU 减去 40 字节（IPv4 头部 20 字节 + TCP 头部 20 字节）。推荐使用此选项自动设置合适值。

set interfaces bonding <interface> ip arp-cache-timeout

配置 ARP 条目在学习到 IP 到 MAC 地址映射后保持有效的时间长度。

默认持续时间为 30 秒。

若 ARP 条目收到上层协议的正向反馈，则保持有效。

示例：

set interfaces bonding bond0 ip arp-cache-timeout 180
set interfaces bonding <interface> ip disable-arp-filter

在此接口上配置 ARP 过滤。

默认行为： 内核仅在流量将通过该特定接口路由回 ARP 发送方时，才响应此接口上的 ARP 请求。

若已配置： 内核将响应此接口上针对本地主机配置的任意 IP 地址的 ARP 请求，无论该 IP 地址分配给哪个具体接口，也无论路由表如何。这体现了 Linux 中“IP 地址属于主机而非单个接口”的概念。

示例：

set interfaces bonding bond0 ip disable-arp-filter
set interfaces bonding <interface> ip disable-forwarding

配置接口为主机或路由器行为。

若已配置，接口将切换至主机模式，且禁用其 IPv4 转发功能。

示例：

set interfaces bonding bond0 ip disable-forwarding
set interfaces bonding <interface> ip enable-directed-broadcast

配置是否转发在此接口上接收到的 IP 定向广播数据包。

默认行为： IP 定向广播数据包将被丢弃。

若已配置： IP 定向广播数据包将被转发至目标子网内的所有主机，如 RFC 1812 和 RFC 2644 所定义。

示例：

set interfaces bonding bond0 ip enable-directed-broadcast
set interfaces bonding <interface> ip enable-arp-accept

配置如何在此接口上处理免费 ARP（gratuitous ARP）。

若已配置，将根据免费 ARP 请求或应答，在 ARP 表中添加 IP 到 MAC 地址映射。

注意

若 ARP 表中已存在来自免费 ARP 的 IP 地址，无论是否启用此设置，其条目均会被更新。

示例：

set interfaces bonding bond0 ip enable-arp-accept
set interfaces bonding <interface> ip enable-arp-announce

在此接口上配置 ARP 请求的源 IP 地址选择方式。

默认行为： 内核可使用主机拥有的任意 IP 地址作为此接口上 ARP 请求的源 IP 地址。

若已配置： 内核首先尝试选择一个与目标 IP 地址处于同一子网的、配置在该接口上的源 IP 地址；若不存在此类子网，则内核选择其通常使用的 IP 地址（基于路由表到达目标目的地）。

示例：

set interfaces bonding bond0 ip enable-arp-announce
set interfaces bonding <interface> ip enable-arp-ignore

在此接口上配置哪些 ARP 请求将被忽略。

默认行为： 内核响应针对任意本地 IP 地址的 ARP 请求，无论这些地址分配给哪个接口。

若已配置： 内核仅在目标 IP 地址分配给该特定接口时，才响应 ARP 请求。

示例：

set interfaces bonding bond0 ip enable-arp-ignore
set interfaces bonding <interface> ip enable-proxy-arp

在此接口上配置代理 ARP。

若已配置，路由器（内核）将截获针对非本地 IP 地址的 ARP 请求，并以接收请求的接口的 MAC 地址进行应答。后续发往这些 IP 地址的数据包将被转发至远程子网的实际目的地。

示例：

set interfaces bonding bond0 ip enable-proxy-arp
set interfaces bonding <interface> ip proxy-arp-pvlan

在接口上配置本地代理 ARP。

若已配置，路由器（内核）将响应此 VLAN 接口上的 ARP 请求，即使目标 IP 地址位于同一子网和接口上。

此功能用于支持私有 VLAN（PVLAN）的网络隔离要求（RFC 3069）。在 PVLAN 配置中，隔离端口上的主机在二层不允许直接相互通信，但可与上游路由器通信。

通过以自身 MAC 地址应答主机间 ARP 请求，路由器（内核）将主机间流量导向自身，而非主机之间直接通信。

注意

此命令独立工作，无需在接口上启用标准代理 ARP。

本地代理 ARP 亦称作：

  • VLAN 聚合（RFC 3069）。

  • 私有 VLAN（Cisco、Allied Telesyn）。

  • 源端口过滤或端口隔离（Hewlett-Packard）。

  • MAC 强制转发（Ericsson）。

set interfaces bonding <interface> ip source-validation <strict | loose | disable>

在此接口上使用 RPF 配置源 IP 地址验证，如 RFC 3704 所述。

可用选项如下：

  • strict： 检查每个入站数据包的源 IP 地址是否与转发表（FIB）匹配。若该接口并非返回该源地址的最佳路径，则验证失败，数据包被丢弃。

  • loose： 检查每个入站数据包的源 IP 地址是否与 FIB 匹配。若该源 IP 地址无法通过任何接口到达，则验证失败。

  • disable： 不执行源 IP 地址验证，接受所有入站数据包。

RFC 3704 建议启用严格模式以防止 IP 欺骗（如 DDoS 攻击）。对于非对称或其他复杂路由场景，请使用宽松模式。

set interfaces bonding <interface> ipv6 address autoconf

配置接口使用 SLAAC 自动获取 IPv6 地址，如 RFC 4862 所述。

IPv6 主机在连接到 IPv6 网络时，可通过 ICMPv6 路由器发现消息利用邻居发现协议（NDP）自动配置自身。首次连接网络时，主机会发送链路本地路由器请求多播请求以获取配置参数。路由器则以包含互联网层配置参数的路由器通告数据包进行响应。

注意

此方法将自动禁用接口上的 IPv6 流量转发功能。

示例：

set interfaces bonding bond0 ipv6 address autoconf
set interfaces bonding <interface> ipv6 address eui64 <prefix>

配置接口使用 EUI-64 方法为其自身分配 IPv6 地址，如 RFC 4291 所述。

示例：

set interfaces bonding bond0 ipv6 address eui64 2001:db8:beef::/64
set interfaces bonding <interface> ipv6 address no-default-link-local

禁用为此接口自动分配链路本地 IPv6 地址。

示例：

set interfaces bonding bond0 ipv6 address no-default-link-local
set interfaces bonding <interface> ipv6 disable-forwarding

配置接口为主机或路由器行为。

若已配置，接口将切换至主机模式，且禁用其 IPv6 转发功能。

示例：

set interfaces bonding bond0 ipv6 disable-forwarding
set interfaces bonding <interface> ipv6 adjust-mss <mss | clamp-mss-to-pmtu>

配置在指定接口上向外发送的 TCP SYN 数据包中通告的 MSS 值。

通过限制 TCP SYN 数据包中的 MSS 值，可明确告知远端不要发送大于该尺寸的数据包，从而避免路径 MTU 发现（PMTUD）失败导致的连接问题。

可用选项如下：

  • mss： 将 MSS 设置为特定字节数值。若需强制执行特定 MSS（例如排查连通性问题或满足特定网络需求），请使用此选项。

  • clamp-mss-to-pmtu： 路由器计算 MSS 为接口 MTU 减去 60 字节（IPv6 头部 40 字节 + TCP 头部 20 字节）。推荐使用此选项自动设置合适值。

set interfaces bonding <interface> ipv6 accept-dad <0 | 1 | 2>

在接口上配置 IPv6 DAD 功能。

可用选项如下：

  • 0： 禁用 DAD。不执行重复地址检测。

  • 1： 启用 DAD（默认）。检测重复地址。接口的 IPv6 操作对有效 IPv6 地址继续运行。

  • 2： 启用 DAD；若发现基于 MAC 的重复链路本地地址，则禁用该接口上的 IPv6 操作。

示例：

set interfaces bonding bond0 ipv6 accept-dad 2
set interfaces bonding <interface> ipv6 dup-addr-detect-transmits <n>

配置路由器（内核）在该接口上执行 IPv6 地址分配期间发送的 DAD 消息数量。

默认值为 1。

示例：

set interfaces bonding bond0 ipv6 dup-addr-detect-transmits 5
set interfaces bonding <interface> vrf <vrf>

将接口分配给特定的 VRF 实例。

另请参阅

有关配置 VRF 的信息，请参阅 VRF 章节。

示例：

set interfaces bonding bond0 vrf red

DHCP(v6)

set interfaces bonding <interface> dhcp-options client-id <description>

按 RFC 2131 规定为接口配置 DHCP 客户端标识符。

client-id 是 DHCP 客户端发送给 DHCP 服务器以唯一标识自身并获取 IP 地址分配的标识符。默认情况下，客户端使用其 MAC 地址。<description> 是用户定义的字符串，将作为 DHCP 客户端标识符发送给 DHCP 服务器。

示例：

set interfaces bonding bond0 dhcp-options client-id 'foo-bar'
set interfaces bonding <interface> dhcp-options host-name <hostname>

为接口配置特定主机名。

DHCP 客户端在请求 IP 地址时，将向 DHCP 服务器发送此特定主机名，而非真实主机名。

示例：

set interfaces bonding bond0 dhcp-options host-name 'VyOS'
set interfaces bonding <interface> dhcp-options vendor-class-id <vendor-id>

配置 DHCP 客户端在该接口的 DHCP 请求中包含厂商类标识符。

厂商类标识符是厂商特定的字节字符串，使 DHCP 服务器能够识别设备，并在某些情况下提供配置选项。

示例：

set interfaces bonding bond0 dhcp-options vendor-class-id 'VyOS'
set interfaces bonding <interface> dhcp-options no-default-route

配置 DHCP 客户端获取 IP 地址，但忽略 DHCP 服务器在该接口上提供的任何默认网关。

示例：

set interfaces bonding bond0 dhcp-options no-default-route
set interfaces bonding <interface> dhcp-options default-route-distance <distance>

配置从该接口上的 DHCP 服务器获取的默认路由的距离值。

示例：

set interfaces bonding bond0 dhcp-options default-route-distance 220
set interfaces bonding <interface> dhcp-options reject <address>

配置 DHCP 客户端拒绝 DHCP 服务器在该接口上提供的特定 IP 地址或 IP 地址范围。

当调制解调器启动时分配本地 IP 地址时，此功能非常有用。要拒绝多个地址，请使用不同值多次运行此命令。您可以拒绝单个地址（192.168.100.1）或整个子网（192.168.100.0/24）。

示例：

set interfaces bonding bond0 dhcp-options reject 192.168.100.0/24
set interfaces bonding <interface> dhcp-options user-class <string>

配置 DHCP 客户端在该接口的 DHCP 请求中发送特定用户类标识符。

DHCP 服务器可解释此标识符，并据此提供特定配置选项（例如默认路由）。用户类值通常将具有相似配置需求的 DHCP 客户端分组（例如员工、访客或打印机）。

示例：

set interfaces bonding bond0 dhcp-options user-class VyOS
set interfaces bonding <interface> dhcpv6-options duid <duid>

为此接口上的 DHCPv6 客户端配置特定的 DUID 。

DUID 是 DHCPv6 客户端用于从 DHCPv6 服务器获取 IPv6 地址的标识符。它由 2 字节类型字段和最多 128 字节的可变长度标识符字段组成。标识符部分的格式取决于 DUID 类型：

  • DUID-LLT： 最常见类型，包含硬件类型、时间戳和 MAC 地址。

  • DUID-EN： 基于厂商的企业编号及厂商分配的唯一标识符。

  • DUID-LL： 仅包含 MAC 地址。

DHCP 服务器将 DUID 与其数据库匹配，并向 DHCP 客户端提供配置数据（如地址、租期、DNS 服务器等）。

示例：

set interfaces bonding bond0 duid '0e:00:00:01:00:01:27:71:db:f0:00:50:56:bf:c5:6d'
set interfaces bonding <interface> dhcpv6-options no-release

配置 DHCP 客户端在该接口上停止运行时不发送释放消息。

这有助于保留已分配的地址或前缀。

示例：

set interfaces bonding bond0 dhcpv6-options no-release
set interfaces bonding <interface> dhcpv6-options parameters-only

在此接口上启用无状态 DHCPv6 客户端模式。

在无状态模式下，DHCPv6 客户端仅向 DHCP 服务器请求无状态配置参数（例如 DNS 服务器地址），而不请求有状态配置（如 IPv6 地址或前缀）。

示例：

set interfaces bonding bond0 dhcpv6-options parameters-only
set interfaces bonding <interface> dhcpv6-options rapid-commit

在此接口上启用 DHCPv6 快速提交功能。

启用后，DHCP 客户端和服务器跳过协商步骤（Advertise 和 Request），仅通过两条消息（Solicit 和最终 Reply）完成 DHCPv6 配置过程。

示例：

set interfaces bonding bond0 dhcpv6-options rapid-commit
set interfaces bonding <interface> dhcpv6-options temporary

配置 DHCPv6 客户端在此接口上请求临时 IPv6 地址。

配置后，DHCP 客户端不会建立非临时地址身份关联（IA_NA）关系。因此，它仅获取临时 IPv6 地址，而不获取永久地址。

示例：

set interfaces bonding bond0 dhcpv6-options temporary

DHCPv6 前缀委派（PD）

VyOS 支持 RFC 3633 中描述的 DHCPv6 前缀委派（DHCPv6-PD）。大多数为固定网络用户提供原生 IPv6 的 ISP 均支持 DHCPv6-PD。

set interfaces bonding <interface> dhcpv6-options pd <id> length <length>

为此接口上的 DHCPv6-PD 请求配置特定前缀长度。

某些 ISP 默认仅提供 /64 前缀。使用此命令可为特定 DHCPv6-PD 请求请求不同的前缀长度，范围从 /32（若您的 ISP 允许）至 /64。 是 DHCPv6-PD 请求的唯一标识符。

默认值为 64。

若要向您的 ISP 申请 /56 前缀，请使用：

set interfaces bonding bond0 dhcpv6-options pd 0 length 56
set interfaces bonding <interface> dhcpv6-options pd <id> interface <delegatee> address <address>

配置委派接口的 IPv6 接口标识符（主机部分）。

该值必须为十进制整数。它将附加到委派前缀和配置的 SLA ID 后，形成最终 IPv6 地址。

默认情况下，主机部分基于父接口的 MAC 地址生成（EUI-64 格式）。

示例：

若 /64 前缀委派给接口 eth8，且您将主机部分配置为 65535，则生成的 IPv6 地址将以 ::ffff 结尾，因为 65535 对应十六进制 ffff。

set interfaces bonding bond0 dhcpv6-options pd 0 interface eth8 address 65534
set interfaces bonding <interface> dhcpv6-options pd <id> interface <delegatee> sla-id <id>

配置委派接口的 SLA ID 。

该值必须为大于 0 的十进制整数，且符合 SLA ID 长度要求。它将转换为十六进制并附加到委派前缀后，形成委派接口的特定子网前缀。

示例：

若 SLA ID 为 1，且委派前缀为 2001:db8:ffff::/48，则委派接口的子网前缀为 2001:db8:ffff:1::/64。

set interfaces bonding bond0 dhcpv6-options pd 0 interface eth8 sla-id 1

成员接口

set interfaces bonding <interface> member interface <member>

将接口添加到聚合组中。

示例：

要将 eth0 和 eth1 配置为聚合接口 bond0 的成员，请执行以下命令：

set interfaces bonding bond0 member interface eth0
set interfaces bonding bond0 member interface eth1

聚合模式

set interfaces bonding <interface> mode <802.3ad | active-backup | broadcast | round-robin | transmit-load-balance | adaptive-load-balance | xor-hash>

在接口上配置聚合模式。默认模式为 802.3ad。

可用模式如下：

  • 802.3ad

说明：

IEEE 802.3ad 动态链路聚合。仅聚合具有相同速率（例如 1 Gbps）和双工设置的成员接口。具有不同速率和双工设置的成员接口不会包含在活动聚合组中。

提供负载均衡和故障容错能力。使用 LACP 与交换机协商聚合组。

流量分布：

流量根据 传输哈希策略（默认：XOR）进行分布。

聚合驱动程序对特定数据包头部字段执行 XOR 运算，生成哈希值，该值映射到特定成员接口。这确保同一网络流始终通过同一成员接口传输。

传输哈希策略通过 hash-policy 选项配置。

故障切换：

若成员接口发生故障，将重新计算哈希值，以便在剩余活动成员接口间分配流量。

注意

并非所有传输哈希策略均符合 802.3ad 标准，特别是第 43.2.4 节。使用不符合标准的策略可能导致乱序数据包交付。

  • active-backup

说明：

提供故障容错能力。一次仅有一个成员接口处于活动状态，其他成员接口保持待机模式。

流量分布：

所有流量（入站和出站）均通过一个活动成员接口路由。

故障切换：

若指定成员接口发生故障，所有流量将路由至另一成员接口。聚合驱动程序发送免费 ARP 更新对端的 MAC 地址表，将聚合组的 MAC 地址关联至另一物理端口。

  • broadcast

说明：

通过复制流量提供最大故障容错能力。

流量分布：

每个数据包均被复制并在 所有 成员接口上传输。

故障切换：

只要至少有一个成员接口保持活动状态，流量流就不会中断。

  • round-robin

说明：

提供负载均衡和故障容错能力。

流量分布：

数据包按顺序依次在成员接口间传输（例如，数据包 1 > 接口 A，数据包 2 > 接口 B，依此类推）。

故障切换：

若成员接口发生故障，序列将跳过故障接口，并在剩余活动成员接口间继续。

  • transmit-load-balance

说明：

提供自适应传输负载均衡和故障容错能力。

流量分布：

出站： 基于当前负载在所有活动成员接口间分布。

入站： 由指定成员接口（活动接收器）接收。

故障切换：

若活动接收器发生故障，另一成员接口将接管成为新的活动接收器。

  • adaptive-load-balance

说明：

提供与 transmit-load-balance 相同的自适应传输负载均衡、IPv4 流量的接收负载均衡，以及入站和出站流量的故障容错能力。

流量分布：

出站： 与 transmit-load-balance 相同。

入站： 基于 ARP 操控进行分布。对于本地和远程连接，聚合驱动程序截获 ARP 流量并将源 MAC 地址更改为负载最轻成员接口的 MAC 地址。

来自该对端的所有流量随后均路由至所选成员接口。

故障切换：

若成员接口状态变更（故障、恢复、添加或排除），流量将在所有活动成员接口间重新分配。

  • xor-hash：基于哈希公式提供负载均衡和故障容错能力。其流量分布和故障切换行为与 802.3ad 相同，但无需 LACP 即可运行。

set interfaces bonding <interface> min-links <0-16>

配置必须处于活动状态（链路开启状态）的成员接口数量，以将聚合接口标记为 UP（载波激活）。

此命令仅适用于配置为 802.3ad 模式的聚合接口，其功能类似于 Cisco EtherChannel 的 min-links 特性。它确保聚合接口仅在指定数量的成员接口处于活动状态（链路开启状态）时才被标记为 UP（载波激活）。这有助于保证依赖聚合接口的上层服务（如集群）具备最低带宽水平。

默认值为 0。这意味着只要存在活动的 LACP 聚合器，聚合接口即被标记为 UP（载波激活），而不论该聚合器中成员接口的数量。

注意

在 802.3ad 模式下，聚合组若无至少一个活动成员接口则无法激活。因此，将 min-links 设置为 0 或 1 效果相同：聚合接口被标记为 UP（载波激活）。

set interfaces bonding <interface> lacp-rate <slow|fast>

配置聚合接口在 802.3ad 模式下请求其链路伙伴发送 LACPDUs 的速率。

此命令仅适用于配置为 802.3ad 模式的聚合接口。

可用选项如下：

  • slow（默认）： 请求链路伙伴每 30 秒发送一次 LACPDUs。

  • fast： 请求链路伙伴每 1 秒发送一次 LACPDUs。

set interfaces bonding <interface> system-mac <mac address>

为聚合接口配置特定 MAC 地址。

此设置用于 802.3ad 系统 MAC 地址，该地址在与链路伙伴进行 LACPDU 交换时使用。您可以为此类 LACPDU 交换分配固定 MAC 地址或生成随机 MAC 地址。

set interfaces bonding <interface> hash-policy <policy>

配置用于在成员接口间分发流量的传输哈希策略。

可用策略如下：

  • layer2

说明： 将所有发往特定网络对端的流量通过同一成员接口路由。该策略符合 802.3ad 标准。

哈希输入： 源 MAC 地址、目的 MAC 地址和以太网数据包类型 ID。

公式：

hash = 源 MAC 地址 XOR 目的 MAC 地址 XOR 数据包类型 ID
成员接口编号 = hash 模 成员接口数量

  • layer2+3

说明： 类似于 layer2，将所有发往特定网络对端的流量通过同一成员接口路由，且符合 IEEE 802.3ad 标准。使用第 2 层和第 3 层信息提供更均衡的流量分布。

哈希输入：

  • 源 MAC 地址、目的 MAC 地址和以太网数据包类型 ID。

  • 源 IP 地址、目的 IP 地址。IPv6 地址首先使用 IPv6_addr_hash 进行哈希。

公式：

hash = 源 MAC 地址 XOR 目的 MAC 地址 XOR 数据包类型 ID
hash = hash XOR 源 IP 地址 XOR 目的 IP 地址
hash = hash XOR (hash RSHIFT 16)
hash = hash XOR (hash RSHIFT 8)
成员接口编号 = hash 模 成员接口数量

对于非 IP 流量，公式与 layer2 相同。

  • layer3+4

说明： 将发往特定网络对端的不同连接（流）通过多个成员接口路由，但确保每个单独流仅通过一个成员接口路由。

注意

此策略不完全符合 802.3ad 标准。当单个 TCP 或 UDP 流同时包含分片和未分片数据包时，算法可能将它们分发至不同成员接口，导致乱序数据包交付，违反 802.3ad 标准。
