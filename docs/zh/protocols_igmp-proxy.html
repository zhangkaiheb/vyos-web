IGMP 代理

IGMP 代理使路由器能够在不同网络（例如家庭网络与 ISP 网络）之间转发组播流量（如 IPTV 或视频流）。IGMP 代理依赖一个面向上游组播源的上游接口，以及一个或多个面向本地网络或主机、并向请求客户端转发流量的下游接口。

IGMP 代理配置要求恰好指定一个上游接口，并至少指定一个下游接口。

配置

set protocols igmp-proxy interface <interface> role <upstream | downstream>

为指定的 IGMP 代理接口配置其运行角色。

  • upstream：与上游组播源通信以获取组播流量。有效配置要求恰好一个上游接口。

  • downstream：与下游本地子网或主机通信以分发所请求的流量。有效配置要求至少一个下游接口。

示例：

set protocols igmp-proxy interface eth0 role upstream
set protocols igmp-proxy interface eth1 role downstream
set protocols igmp-proxy interface <interface> alt-subnet <network>

为指定的 IGMP 代理接口配置允许接收入向组播流量的远程子网。

默认情况下，IGMP 代理仅接受来自直连子网的组播流量。若组播源位于远程网络，则必须显式定义允许的远程子网，以放行该流量。

可为一个 上游 IGMP 代理接口配置多个远程子网。

由于组播源通常位于外部子网，因此上游接口经常需要此配置。

示例：

set protocols igmp-proxy interface eth0 alt-subnet 10.0.0.0/8
set protocols igmp-proxy interface <interface> whitelist <network>

为指定的 IGMP 代理接口配置组播流量请求所允许的目的地网络。

默认情况下，IGMP 代理接受所有组播目的网络的请求。当定义白名单后，IGMP 代理仅转发针对所指定组播网络的请求。

每个 下游 IGMP 代理接口可配置多个白名单条目。

示例：

set protocols igmp-proxy interface eth1 whitelist 239.0.0.0/8
set protocols igmp-proxy interface <interface> threshold <1-255>

为指定的 IGMP 代理接口配置生存时间（TTL）阈值。

IGMP 代理将丢弃 TTL 值低于所配置阈值的所有组播数据包。

示例：

set protocols igmp-proxy interface eth0 threshold 5
set protocols igmp-proxy disable-quickleave

禁用 IGMP 代理的快速离开（quickleave）模式。

若禁用该模式，IGMP 代理在收到下游 Leave 消息时不会向上游发送 Leave 消息，从而防止上游组播流量立即终止。IGMP 代理还将停止向下游接口查询成员报告。若下游客户端提交新的报告，IGMP 代理将丢弃该消息且不会恢复所请求流量的传输。

注意

禁用 quickleave 模式将强制 IGMP 代理在上游接口上表现得与标准组播客户端完全一致。

注意

禁用 quickleave 模式会增加网络带宽饱和的风险。

示例：

set protocols igmp-proxy disable-quickleave
set protocols igmp-proxy disable

在路由器上禁用 IGMP 代理功能。

示例：

set protocols igmp-proxy disable

运行

restart igmp-proxy

重启 IGMP 代理进程。

示例

在此示例中，接口 eth1 上的本地局域网（LAN）位于 NAT 后方。为使本地客户端能够接收来自广域网（WAN）接口（eth0）上 198.51.100.0/24 源网络的组播流量，请按如下方式配置 IGMP 代理：

set protocols igmp-proxy interface eth0 role upstream
set protocols igmp-proxy interface eth0 alt-subnet 198.51.100.0/24
set protocols igmp-proxy interface eth1 role downstream
