隧道

隧道接口是虚拟链路，用于在公共基础设施（例如互联网）上跨接私有网络或主机之间传输封装的流量。它们通过封装协议对原始流量进行封装后进行传输。支持的协议包括 GRE、IPIP、IPIP6、IP6IP6 和 6in4（SIT）。

虽然 GRE 因其多功能性而常被视为“一劳永逸”的首选方案，但其他封装协议可能更适合特定应用场景。

VyOS 对所有这些协议均使用单一类型的隧道接口。不存在单独的 GRE、IPIP 或 IP6IP6 接口类型；相反，在 set interfaces tunnel 配置中选择所需的封装协议。

以下将介绍各协议的配置选项。

警告

请勿更改已配置隧道接口的封装类型，否则可能导致其依赖的配置失效。

通用接口配置

set interfaces tunnel <interface> address <address>

配置一个或多个接口 IP 地址。

<address> 支持 CIDR 表示法的 IPv4 和 IPv6 地址。例如，IPv4 使用 192.0.2.1/24，IPv6 使用 2001:db8::1/64。

示例：

set interfaces tunnel tun0 address 192.0.2.1/24
set interfaces tunnel tun0 address 2001:db8::1/64
set interfaces tunnel <interface> description <description>

为接口配置清晰、具描述性的别名。

该别名将在 show interfaces 命令及基于 SNMP 的监控工具中显示。

示例：

set interfaces tunnel tun0 description '这是运行在 VyOS 上的一个接口。'
set interfaces tunnel <interface> disable

禁用该接口。

该接口将被设置为管理性关闭状态（A/D）。

示例：

set interfaces tunnel tun0 disable
set interfaces tunnel <interface> disable-flow-control

在接口上禁用以太网流控（IEEE 802.3x 暂停帧）。

以太网流控由 IEEE 802.3x 标准定义，可在网络拥塞时临时停止数据传输，防止丢包。例如，当发送方传输数据的速度超过接收方处理能力时。

禁用以太网流控意味着该接口不会向相连设备发出暂停传输信号，若负载过重则直接丢弃数据包。

示例：

set interfaces tunnel tun0 disable-flow-control
set interfaces tunnel <interface> disable-link-detect

禁用接口上的物理链路状态变化检测（例如拔掉网线时）。

默认情况下，接口会检测物理链路状态变化。

示例：

set interfaces tunnel tun0 disable-link-detect
set interfaces tunnel <interface> mtu <mtu>

在接口上配置 MTU。

该值定义了接口在不进行分片的情况下可传输的最大数据包大小（字节）。

示例：

set interfaces tunnel tun0 mtu 1600
set interfaces tunnel <interface> ip adjust-mss <mss | clamp-mss-to-pmtu>

在指定接口的出站 TCP SYN 数据包中配置所通告的 MSS 值。

通过限制 TCP SYN 数据包中的 MSS 值，可明确告知远端不要发送大于该尺寸的数据包。这可避免路径 MTU 发现（PMTUD）失败导致的连接问题。

可选参数如下：

  • mss：将 MSS 设置为特定字节数值。如需强制执行特定 MSS（例如排查连通性问题或满足特定网络需求），请使用此选项。

  • clamp-mss-to-pmtu：路由器自动计算 MSS 值，即接口 MTU 减去 40 字节（IPv4 流量：20 字节 IPv4 头部 + 20 字节 TCP 头部）。推荐使用此选项以自动设置合适值。

set interfaces tunnel <interface> ip arp-cache-timeout

配置 ARP 条目在学习到本接口上 IP 到 MAC 地址映射后保持有效的时间。

默认持续时间为 30 秒。

若从更高层协议收到正向反馈，则 ARP 条目保持有效。

示例：

set interfaces tunnel tun0 ip arp-cache-timeout 180
set interfaces tunnel <interface> ip disable-arp-filter

在本接口上配置 ARP 过滤。

默认行为：内核仅在该接口能将流量路由回 ARP 请求发送方时，才响应其 ARP 请求。

若启用该配置：内核将响应本接口上针对本地主机配置的任意 IP 地址的 ARP 请求，无论该 IP 地址分配给哪个具体接口，也无论路由表如何。这体现了 Linux 的概念：IP 地址属于主机而非单个接口。

示例：

set interfaces tunnel tun0 ip disable-arp-filter
set interfaces tunnel <interface> ip disable-forwarding

配置接口为主机模式或路由器模式行为。

若启用该配置，接口将切换至主机模式，并在该接口上禁用 IPv4 转发功能。

示例：

set interfaces tunnel tun0 ip disable-forwarding
set interfaces tunnel <interface> ip enable-directed-broadcast

配置是否转发在本接口上接收到的 IP 定向广播数据包。

默认行为：丢弃 IP 定向广播数据包。

若启用该配置：根据 RFC 1812 和 RFC 2644 的定义，IP 定向广播数据包将被转发至目标子网的所有主机。

示例：

set interfaces tunnel tun0 ip enable-directed-broadcast
set interfaces tunnel <interface> ip enable-arp-accept

配置本接口如何处理免费 ARP（gratuitous ARP）。

若启用该配置，将根据免费 ARP 请求或应答在 ARP 表中添加 IP 到 MAC 地址映射。

注意

如果 ARP 表中已存在来自免费 ARP 的 IP 地址条目，则无论是否启用此设置，该条目都会被更新。

示例：

set interfaces tunnel tun0 ip enable-arp-accept
set interfaces tunnel <interface> ip enable-arp-announce

配置本接口上 ARP 请求的源 IP 地址选择方式。

默认行为：内核可使用主机拥有的任意 IP 地址作为本接口 ARP 请求的源 IP 地址。

若启用该配置：内核首先尝试选择与目标 IP 地址处于同一子网的、配置在本接口上的源 IP 地址；若无此类子网，则内核选择其通常使用的 IP 地址（依据路由表到达目标目的地）。

示例：

set interfaces tunnel tun0 ip enable-arp-announce
set interfaces tunnel <interface> ip enable-arp-ignore

配置本接口忽略哪些 ARP 请求。

默认行为：内核响应任何本地 IP 地址的 ARP 请求，无论这些地址分配给哪个接口。

若启用该配置：内核仅在目标 IP 地址分配给本接口时才响应 ARP 请求。

示例：

set interfaces tunnel tun0 ip enable-arp-ignore
set interfaces tunnel <interface> ip enable-proxy-arp

在本接口上配置代理 ARP。

若启用该配置，路由器（内核）将截获针对非本地 IP 地址的 ARP 请求，并以接收请求的接口的 MAC 地址进行应答。后续发往这些 IP 地址的数据包将被转发至远程子网的实际目的地。

示例：

set interfaces tunnel tun0 ip enable-proxy-arp
set interfaces tunnel <interface> ip proxy-arp-pvlan

在接口上配置本地代理 ARP。

若启用该配置，路由器（内核）即使目标 IP 地址位于同一子网和接口上，也会响应本 VLAN 接口上的 ARP 请求。

此功能用于支持私有 VLAN（PVLAN）的网络隔离要求（RFC 3069）。在 PVLAN 配置中，隔离端口上的主机在二层不允许直接相互通信，但可与上游路由器通信。

通过以自身 MAC 地址应答主机间 ARP 请求，路由器（内核）将主机间流量导向自身，而非主机之间直接通信。

注意

该命令独立工作，无需在接口上启用标准代理 ARP。

本地代理 ARP 亦称为：

  • VLAN 聚合（RFC 3069）。

  • 私有 VLAN（Cisco、Allied Telesyn）。

  • 源端口过滤或端口隔离（Hewlett-Packard）。

  • MAC 强制转发（Ericsson）。

set interfaces tunnel <interface> ip source-validation <strict | loose | disable>

按 RFC 3704 规定，在本接口上使用 RPF 配置源 IP 地址验证。

可选参数如下：

  • strict：检查每个入站数据包的源 IP 地址是否与转发信息库（FIB）匹配。若该接口并非返回该源地址的最佳路径，则验证失败，数据包被丢弃。

  • loose：检查每个入站数据包的源 IP 地址是否与 FIB 匹配。若该源 IP 地址无法通过任意接口到达，则验证失败。

  • disable：不执行源 IP 地址验证，接受所有入站数据包。

RFC 3704 建议启用严格模式以防止 IP 欺骗（如 DDoS 攻击）。对于非对称路由或其他复杂路由场景，请使用宽松模式。

set interfaces tunnel <interface> ipv6 address autoconf

按 RFC 4862 规定，配置接口使用 SLAAC 自动获取 IPv6 地址。

IPv6 主机在接入 IPv6 网络时，可通过 ICMPv6 路由器发现消息利用邻居发现协议（NDP）自动配置自身。主机首次接入网络时，会发送链路本地路由器请求组播请求以获取配置参数；路由器则以包含网络层配置参数的路由器通告报文进行响应。

注意

此方法将自动禁用接口上的 IPv6 流量转发功能。

示例：

set interfaces tunnel tun0 ipv6 address autoconf
set interfaces tunnel <interface> ipv6 address eui64 <prefix>

按 RFC 4291 规定，配置接口使用 EUI-64 方法为自己分配 IPv6 地址。

示例：

set interfaces tunnel tun0 ipv6 address eui64 2001:db8:beef::/64
set interfaces tunnel <interface> ipv6 address no-default-link-local

禁用为此接口自动分配链路本地 IPv6 地址。

示例：

set interfaces tunnel tun0 ipv6 address no-default-link-local
set interfaces tunnel <interface> ipv6 disable-forwarding

配置接口为主机模式或路由器模式行为。

若启用该配置，接口将切换至主机模式，并在该接口上禁用 IPv6 转发功能。

示例：

set interfaces tunnel tun0 ipv6 disable-forwarding
set interfaces tunnel <interface> ipv6 adjust-mss <mss | clamp-mss-to-pmtu>

在指定接口的出站 TCP SYN 数据包中配置所通告的 MSS 值。

通过限制 TCP SYN 数据包中的 MSS 值，可明确告知远端不要发送大于该尺寸的数据包。这可避免路径 MTU 发现（PMTUD）失败导致的连接问题。

可选参数如下：

  • mss：将 MSS 设置为特定字节数值。使用此选项可强制执行特定 MSS，例如排查连通性问题或满足特定网络需求。

  • clamp-mss-to-pmtu：路由器计算 MSS 值为接口 MTU 减去 60 字节（IPv6 流量：40 字节 IPv6 头部 + 20 字节 TCP 头部）。推荐使用此选项以自动设置合适值。

set interfaces tunnel <interface> ipv6 accept-dad <0 | 1 | 2>

在接口上配置 IPv6 DAD 功能。

可选参数如下：

  • 0：禁用 DAD，不执行重复地址检测。

  • 1：启用 DAD（默认）。检测重复地址，接口的 IPv6 功能对有效 IPv6 地址继续运行。

  • 2：启用 DAD；若发现基于 MAC 的重复链路本地地址，则禁用本接口上的 IPv6 功能。

示例：

set interfaces tunnel tun0 ipv6 accept-dad 2
set interfaces tunnel <interface> ipv6 dup-addr-detect-transmits <n>

配置路由器（内核）在本接口上执行 IPv6 地址分配时发送的 DAD 消息数量。

默认值为 1。

示例：

set interfaces tunnel tun0 ipv6 dup-addr-detect-transmits 5
set interfaces tunnel <interface> vrf <vrf>

将接口分配给特定的 VRF 实例。

另请参阅

有关 VRF 配置的信息，请参阅 VRF 章节。

示例：

set interfaces tunnel tun0 vrf red

IPIP

IPIP 是 RFC 2003 中定义的一种简单封装协议，它将一个 IPv4 数据包封装在另一个 IPv4 数据包内。

采用 IPIP 封装的隧道除显式指定封装类型为 IPIP 外（见下例），无协议特定配置选项。

示例：

set interfaces tunnel tun0 encapsulation ipip
set interfaces tunnel tun0 source-address 192.0.2.10
set interfaces tunnel tun0 remote 203.0.113.20
set interfaces tunnel tun0 address 192.168.100.200/24

IP6IP6

IP6IP6 是 IPIP 的 IPv6 对应协议，它将一个 IPv6 数据包封装在另一个 IPv6 数据包内。

与 IPIP 类似，采用 IP6IP6 封装的隧道除显式指定封装类型为 IP6IP6 外，无协议特定配置选项。

示例：

set interfaces tunnel tun0 encapsulation ip6ip6
set interfaces tunnel tun0 source-address 2001:db8:aa::1
set interfaces tunnel tun0 remote 2001:db8:aa::2
set interfaces tunnel tun0 address 2001:db8:bb::1/64

IPIP6

IPIP6 是一种将 IPv4 数据包封装在 IPv6 数据包内的封装协议。

与 IPIP 和 IP6IP6 类似，采用 IPIP6 封装的隧道仅需指定封装类型为 IPIP6 即可完成协议特定配置。

示例：

set interfaces tunnel tun0 encapsulation ipip6
set interfaces tunnel tun0 source-address 2001:db8:aa::1
set interfaces tunnel tun0 remote 2001:db8:aa::2
set interfaces tunnel tun0 address 192.168.70.80/24

6in4（SIT）

6in4（又称 SIT）是一种在 RFC 4213 中定义的封装协议，它将 IPv6 数据包封装在 IPv4 数据包内。封装所用的 IPv4 头部使用 IP 协议号 41，该编号专用于 IPv6 封装。

封装过程为每个 IPv6 数据包添加一个 20 字节的 IPv4 头部。因此，在底层网络标准 MTU 为 1500 字节的情况下，6in4 隧道接口可无分片地传输最大 1480 字节的 IPv6 数据包。

6in4 隧道接口常被 IPv6 隧道代理（例如 Hurricane Electric）用于将孤立的 IPv6 网络或单个主机连接至 IPv6 互联网。

示例：

set interfaces tunnel tun0 encapsulation sit
set interfaces tunnel tun0 source-address 192.0.2.10
set interfaces tunnel tun0 remote 192.0.2.20
set interfaces tunnel tun0 address 2001:db8:bb::1/64

另请参阅

有关实际配置示例，请参阅 Tunnelbroker.net（IPv6） 章节。

通用路由封装（GRE）

GRE 是 RFC 2784 中定义的一种多功能封装协议。与 IPIP 等较简单协议不同，它允许在同一隧道中传输 IPv4 和 IPv6 流量。

GRE 通过对原始数据包添加 GRE 头部，再添加 IP 头部（传送头部）来实现封装。传送头部使用 IP 协议号 47 来标识 GRE 封装的流量。

在 VyOS 中，GRE 隧道既可在 IPv4（封装类型 gre）传输网络上建立，也可在 IPv6（封装类型 ip6gre）传输网络上建立。

配置

要配置 GRE 隧道，需定义隧道源 IP 地址、隧道目的 IP 地址、封装类型（GRE）以及隧道接口 IP 地址。

示例：

以下示例展示如何在 VyOS 路由器与运行 systemd-networkd 的 Linux 主机之间配置 IPv4/IPv6 over IPv6 GRE 隧道。

VyOS 路由器：

set interfaces tunnel tun101 address '2001:db8:feed:beef::1/126'
set interfaces tunnel tun101 address '192.168.5.1/30'
set interfaces tunnel tun101 encapsulation 'ip6gre'
set interfaces tunnel tun101 source-address '2001:db8:babe:face::3afe:3'
set interfaces tunnel tun101 remote '2001:db8:9bb:3ce::5'

Linux systemd-networkd：

systemd-networkd 配置需要两个文件：xxx.netdev 用于创建 GRE 隧道接口，xxx.network 用于为其分配 IP 地址。

# cat /etc/systemd/network/gre-example.netdev
[NetDev]
Name=gre-example
Kind=ip6gre
MTUBytes=14180

[Tunnel]
Remote=2001:db8:babe:face::3afe:3


# cat /etc/systemd/network/gre-example.network
[Match]
Name=gre-example

[Network]
Address=2001:db8:feed:beef::2/126

[Address]
Address=192.168.5.2/30

GRE 密钥

GRE 密钥是 GRE 头部中一个可选的 32 位字段，允许多个 GRE 隧道在相同源和目的端点之间共存。当数据包到达时，接收方检查 GRE 密钥以确定应由哪个隧道接口处理该数据包。

尽管名称看似与安全相关，GRE 密钥仅是一个标识符，不提供加密或数据保护功能。

示例：

set interfaces tunnel tun0 source-address 192.0.2.10
set interfaces tunnel tun0 remote 192.0.2.20
set interfaces tunnel tun0 address 10.40.50.60/24
set interfaces tunnel tun0 parameters ip key 10

set interfaces tunnel tun1 source-address 192.0.2.10
set interfaces tunnel tun1 remote 192.0.2.20
set interfaces tunnel tun1 address 172.16.17.18/24
set interfaces tunnel tun1 parameters ip key 20

GRETAP

与仅封装第 3 层（IP）流量的 GRE 不同，GRETAP 封装第 2 层（以太网）帧。

这意味着 GRETAP 隧道接口可成为桥接接口的成员。这使得两个地理上分离的站点能够如同处于同一局域网（LAN）中一样互联。

GRETAP 隧道既可在 IPv4 传输网络上建立，也可在 IPv6 传输网络上建立。

示例：

set interfaces bridge br0 member interface eth0
set interfaces bridge br0 member interface tun0
set interfaces tunnel tun0 encapsulation gretap
set interfaces tunnel tun0 source-address 198.51.100.2
set interfaces tunnel tun0 remote 203.0.113.10

故障排除

GRE 是许多网络环境中使用的标准化隧道协议。

尽管 GRE 隧道配置简单，但连接失败却频繁发生，原因通常是 ACL 或防火墙规则阻止了 IP 协议 47，或阻止了隧道端点之间的直接通信。

若您的 GRE 隧道无法建立，请执行以下诊断步骤：

1. 验证远程对等体是否可从配置的 source-address 访问。
