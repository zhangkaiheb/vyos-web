NAT44

NAT 是一种常见方法，通过在数据包穿越流量路由设备时修改其 IP 报头中的网络地址信息，将一个 IP 地址空间重新映射到另一个 IP 地址空间。该技术最初被用作一种快捷方式，以避免在网络迁移时重新为每台主机配置地址。随着 IPv4 地址枯竭问题日益严峻，NAT 已成为节约全球 IPv4 地址空间的一种流行且必不可少的工具。NAT 网关的一个可全局路由的 Internet IP 地址即可供整个私有网络使用。

IP 伪装（IP masquerading）是一种隐藏整个 IP 地址空间（通常由私有 IP 地址组成）的技术，将其隐藏在一个单一 IP 地址（通常为公有地址空间）之后。隐藏的地址在出站 IP 数据包中被更改为单一（公有）IP 地址作为源地址，从而使这些数据包看起来并非源自隐藏主机，而是源自路由设备本身。由于该技术在节约 IPv4 地址空间方面广受欢迎，“NAT”一词实际上已几乎等同于“IP 伪装”。

由于网络地址转换会修改数据包中的 IP 地址信息，不同 NAT 实现方案在各种寻址场景下的具体行为及其对网络流量的影响可能各不相同。NAT 行为的具体细节通常未被包含 NAT 实现的设备厂商所记录。

内部网络中的计算机可以使用 IANA 为私有寻址预留的任意地址（参见 RFC 1918）。这些保留的 IP 地址并未在 Internet 上使用，因此外部设备无法直接路由至这些地址。以下地址范围被保留用于私有用途：

  • 10.0.0.0 至 10.255.255.255（CIDR：10.0.0.0/8）

  • 172.16.0.0 至 172.31.255.255（CIDR：172.16.0.0/12）

  • 192.168.0.0 至 192.168.255.255（CIDR：192.168.0.0/16）

如果 ISP 部署了 CGN，并使用 RFC 1918 地址空间为用户网关编址，则当客户网络本身已使用 RFC 1918 地址空间时，就会出现地址冲突风险，进而导致路由故障。

这促使部分 ISP 在 ARIN 内制定一项政策，为 CGN 分配新的私有地址空间；但 ARIN 在实施该政策前将此事移交 IETF 处理，指出该事项并非典型的地址分配问题，而是出于技术目的而进行的地址保留（依据 RFC 2860）。

IETF 发布了 RFC 6598，详细说明了一种专用于 ISP CGN 部署的共享地址空间，可同时处理入站和出站接口上出现的相同网络前缀。ARIN 将该地址空间返还给 IANA 以供此次分配之用。

所分配的地址块为 100.64.0.0/10。

评估 IPv4 地址是否为公有地址的设备必须更新，以识别这一新地址空间。为 NAT 设备分配更多私有 IPv4 地址空间可能会延长向 IPv6 过渡的时间。

概述

不同类型的 NAT

源地址 NAT（SNAT）

SNAT 是最常见形式的 NAT，通常简称为 NAT。更准确地说，大多数人所指的 NAT 实际上是 PAT（即 NAT 过载）过程。SNAT 通常由内部用户/私有主机用于访问 Internet——源地址被转换，从而保持私密性。

目的地址 NAT（DNAT）

DNAT 会更改经过路由器的数据包的目的地址，而 SNAT 则更改数据包的源地址。DNAT 通常用于外部（公有）主机需要主动与内部（私有）主机建立会话的场景。例如，客户需访问位于路由器公有 IP 后方的私有服务。此时，客户端连接至路由器公有 IP 的知名端口，所有发往该端口的流量均被重写，指向内部（私有）主机。

双向 NAT

这是一种常见场景，即同时配置 SNAT 和 DNAT。它常用于内部（私有）主机需要与外部资源建立连接，且外部系统也需要访问内部（私有）资源的情况。

NAT 规则集

NAT 完全通过一系列所谓的 规则 进行配置。规则按编号顺序排列，并由底层操作系统按数值顺序依次评估！可通过 rename 和 copy 命令修改规则编号。

注意

NAT 系统的更改仅影响新建立的连接。已建立的连接不受影响。

提示

设计 NAT 规则集时，请在连续规则之间预留一些编号空间以便后续扩展。您的规则集可从编号 10、20、30 开始。这样您便可在现有规则之间插入新的规则。

将分别为 SNAT 和 DNAT 创建规则。

对于 双向 NAT，需同时为 SNAT 和 DNAT 创建规则。

流量过滤器

流量过滤器用于控制哪些数据包将应用已定义的 NAT 规则。可在单条 NAT 规则中应用五种不同的过滤器。

  • 出站接口（outbound-interface） —— 仅适用于 SNAT。它配置此转换规则所适用的外部流量使用的接口。支持接口组、反向选择及通配符。

    示例：

    set nat source rule 20 outbound-interface name eth0
set nat source rule 30 outbound-interface name bond1*
set nat source rule 20 outbound-interface name !vtun2
set nat source rule 20 outbound-interface group GROUP1
set nat source rule 20 outbound-interface group !GROUP2

  • 入站接口（inbound-interface） —— 仅适用于 DNAT。它配置此转换规则所适用的内部流量使用的接口。支持接口组、反向选择及通配符。

    示例：

    set nat destination rule 20 inbound-interface name eth0
set nat destination rule 30 inbound-interface name bond1*
set nat destination rule 20 inbound-interface name !vtun2
set nat destination rule 20 inbound-interface group GROUP1
set nat destination rule 20 inbound-interface group !GROUP2

  • 协议（protocol） —— 指定此转换规则适用于哪些协议类型。仅匹配指定协议的数据包才会被执行 NAT。默认情况下，该规则适用于 所有 协议。

    示例：

    • 设置 SNAT 规则 20，使其仅对 TCP 和 UDP 数据包执行 NAT

    • 设置 DNAT 规则 20，使其仅对 UDP 数据包执行 NAT

    set nat source rule 20 protocol tcp_udp
set nat destination rule 20 protocol udp

  • 源地址（source） —— 根据数据包的源 IP 地址和/或源端口指定 NAT 转换规则适用的数据包。仅匹配的数据包才考虑执行 NAT。

    示例：

    • 设置 SNAT 规则 20，使其仅对来自 192.0.2.0/24 网络的数据包执行 NAT

    • 设置 SNAT 规则 30，使其仅对来自 203.0.113.0/24 网络且源端口为 80 和 443 的数据包执行 NAT

    set nat source rule 20 source address 192.0.2.0/24
set nat source rule 30 source address 203.0.113.0/24
set nat source rule 30 source port 80,443

  • 目的地址（destination） —— 仅基于配置的目的地址和/或端口号，指定将对哪些数据包应用转换。

    注意

    若未指定目的地址，则该规则将匹配任意目的地址和端口。

    示例：

    • 配置 SNAT 规则（40），使其仅对目的地址为 192.0.2.1 的数据包执行 NAT

    set nat source rule 40 destination address 192.0.2.1

地址转换

每条 NAT 规则均定义了一个转换命令。转换命令中指定的地址即为数据包地址信息被替换时所使用的地址。

源地址

对于 SNAT 规则，数据包的源地址将被转换命令中指定的地址所替代。也可指定端口转换，该端口转换属于转换地址的一部分。

注意

转换地址必须设置为已配置的 outbound-interface 上可用的地址之一，或者设置为 masquerade（伪装），后者将使用 outbound-interface 的主 IP 地址作为其转换地址。

注意

当为大量主机系统使用 NAT 时，建议至少使用 1 个 IP 地址来转换每 256 台私有主机系统。这是因为可用于唯一转换的端口号上限为 65,000 个，且平均每台主机系统需预留约 200–300 个会话。

示例：

  • 为 SNAT 规则 20 定义离散的源 IP 地址 100.64.0.1

  • 在规则 30 上使用地址 masquerade（即接口的主地址）

  • 当大量私有机器位于 NAT 后方时，您的地址池可能需要更大。在执行转换时，SNAT 规则 40 可使用 100.64.0.10 至 100.64.0.20 范围内的任一地址

set nat source rule 20 translation address 100.64.0.1
set nat source rule 30 translation address 'masquerade'
set nat source rule 40 translation address 100.64.0.10-100.64.0.20

目的地址

对于 DNAT 规则，数据包的目的地址将被 translation address 命令中指定的地址所替代。

示例：

  • DNAT 规则 10 将入站数据包的目的地址替换为 192.0.2.10

set nat destination rule 10 translation address 192.0.2.10

此外，在 DNAT 中还支持重定向至本地回环地址（localhost）。重定向语句是一种特殊的 DNAT 形式，始终将目的地址转换为本地主机的地址。

重定向示例：

set nat destination rule 10 translation redirect port 22

NAT 负载均衡

高级配置可用于应用源地址或目的地址 NAT，并在单条规则内定义多个转换后的地址，使 NAT 在这些地址之间均衡分配转换任务。

NAT 负载均衡采用一种生成哈希值的算法，并基于该哈希值应用相应的转换。该哈希值可随机生成，也可利用 IP 报头中的数据生成：源地址、目的地址、源端口和/或目的端口。默认情况下，哈希值将随机生成。

在定义转换后的地址（称为 backends）时，必须配置 weight（权重）。这使用户能够根据自身需求定义负载均衡分布。所有后端权重之和应等于 100。换言之，为后端配置的权重即为该后端将接收的连接所占百分比。

set nat [source | destination] rule <rule> load-balance hash [source-address | destination-address | source-port | destination-port | random]
set nat [source | destination] rule <rule> load-balance backend <x.x.x.x> weight <1-100>

配置示例

要配置 SNAT，我们需要了解以下信息：

  • 需要转换的内部 IP 地址

  • 执行转换的出站接口

  • 转换至的外部 IP 地址

在上述快速入门配置示例中，我们演示了如下配置：

set nat source rule 100 outbound-interface name 'eth0'
set nat source rule 100 source address '192.168.0.0/24'
set nat source rule 100 translation address 'masquerade'

该配置生成如下结果：

rule 100 {
    outbound-interface {
        name eth0
    }
    source {
        address 192.168.0.0/24
    }
    translation {
        address masquerade
    }
}

在此示例中，我们使用 masquerade（伪装）作为转换地址，而非具体的 IP 地址。masquerade 目标实质上是一个别名，表示“使用出站接口上的任意 IP 地址”，而非静态配置的 IP 地址。当出站接口使用 DHCP 获取地址且外部地址未知时，此功能尤为有用。

当为大量主机系统使用 NAT 时，建议至少使用 1 个 IP 地址来转换每 256 台主机系统。这是因为可用于唯一转换的端口号上限为 65,000 个，且平均每台主机系统需预留约 200–300 个会话。

示例：对于约 8,000 台主机的网络，建议使用包含 32 个 IP 地址的源地址 NAT 地址池。

可通过在两个 IP 地址之间使用短横线（-）来定义地址池：

set nat source rule 100 translation address '203.0.113.32-203.0.113.63'

避免“泄漏型”NAT

Linux netfilter 不会对标记为 INVALID（无效）的数据包执行 NAT。这常常使人们误以为 Linux（或特指 VyOS）的 NAT 实现存在缺陷，因为未执行 NAT 的数据包会被观察到从外部接口发出。实际上这是预期行为，对“泄漏型”流量进行数据包捕获可揭示这些流量通常是客户端系统在 Linux netfilter 认为连接已关闭后发送的额外 TCP “RST”、“FIN,ACK” 或 “RST,ACK”。最常见的现象是某些主机实现终止连接后发送的额外 TCP RST（该行为因实现而异）。

换言之，连接跟踪机制已观测到连接已关闭，并将该流状态转换为 INVALID，以防止攻击者尝试复用该连接。

您可通过使用防火墙策略丢弃“invalid”（无效）状态的数据包来避免“泄漏型”行为。

对 INVALID 状态流量的匹配进行控制（例如，有选择地记录日志）是一项重要的故障排除工具，有助于观测协议行为异常。因此，VyOS 并不会全局丢弃 INVALID 状态的流量，而是允许操作员自行决定如何处理此类流量。

发夹式 NAT / NAT 反射

使用 NAT 并托管公有服务器时的一个典型问题是：内部系统能否使用其外部 IP 地址访问内部服务器？该问题的常规解决方案通常是使用拆分 DNS（split-DNS），在内部请求时正确将主机系统指向内部地址。由于许多小型网络缺乏 DNS 基础设施，通常会部署一种变通方案，通过对来自内部主机的请求执行 NAT，将其转换为防火墙内部接口的源地址，从而实现流量转发。

该技术通常被称为 NAT 反射（NAT Reflection）或发夹式 NAT（Hairpin NAT）。

示例：

  • 通过 DNAT 规则 100，将来自外部（WAN，外部）世界的 Microsoft RDP 流量重定向至内部私有主机 192.0.2.40。

  • 通过 DNAT 规则 110，将来自内部（LAN，私有）网络的 Microsoft RDP 流量重定向至内部私有主机 192.0.2.40。我们还需要为流量的反向路径配置一条 SNAT 规则 110。内部网络 192.0.2.0/24 通过接口 eth0.10 可达。

set nat destination rule 100 description 'Regular destination NAT from external'
set nat destination rule 100 destination port '3389'
set nat destination rule 100 inbound-interface name 'pppoe0'
set nat destination rule 100 protocol 'tcp'
set nat destination rule 100 translation address '192.0.2.40'

set nat destination rule 110 description 'NAT Reflection: INSIDE'
set nat destination rule 110 destination port '3389'
set nat destination rule 110 inbound-interface name 'eth0.10'
set nat destination rule 110 protocol 'tcp'
set nat destination rule 110 translation address '192.0.2.40'

set nat source rule 110 description 'NAT Reflection: INSIDE'
set nat source rule 110 destination address '192.0.2.0/24'
set nat source rule 110 outbound-interface name 'eth0.10'
set nat source rule 110 protocol 'tcp'
set nat source rule 110 source address '192.0.2.0/24'
set nat source rule 110 translation address 'masquerade'

该配置最终生成如下结果：

vyos@vyos# show nat

         destination {
             port 3389
         }
         inbound-interface {

             address 192.0.2.40
         }
     }

         description "NAT Reflection: INSIDE"
         destination {
             port 3389
         }
         inbound-interface {
             name eth0.10
         }
         protocol tcp
         translation {
             address 192.0.2.40
         }
     }
 }

     rule 110 {
         description "NAT Reflection: INSIDE"
         destination {
             address 192.0.2.0/24
         }
         outbound-interface {
             name eth0.10
         }
         protocol tcp
         source {
             address 192.0.2.0/24
         }

         }
     }
 }

目的地址 NAT（DNAT）

DNAT 通常被称为 端口转发（Port Forward）。当使用 VyOS 作为 NAT 路由器和防火墙时，一项常见的配置任务是将入站流量重定向至防火墙后方的系统。

在本示例中，我们将以上述快速入门配置为基础展开说明。

要配置目的地址 NAT 规则，我们需要收集以下信息：

  • 流量进入的接口；

  • 希望转发的协议和端口；

  • 希望转发流量至的内部系统的 IP 地址。

在我们的示例中，我们将把 Web 服务器流量转发至内部 Web 服务器 192.168.0.100。HTTP 流量使用 TCP 协议的 80 端口。有关其他常用端口号，请参阅：https://en.wikipedia.org/wiki/List_of_TCP_and_UDP_port_numbers

我们的配置命令如下：

set nat destination rule 10 description 'Port Forward: HTTP to 192.168.0.100'
set nat destination rule 10 destination port '80'
set nat destination rule 10 inbound-interface name 'eth0'
set nat destination rule 10 protocol 'tcp'
set nat destination rule 10 translation address '192.168.0.100'

该配置将生成如下 NAT 目的地址配置：

nat {
    destination {
        rule 10 {
            description "Port Forward: HTTP to 192.168.0.100"
            destination {
                port 80
            }
            inbound-interface {
                name eth0
            }
            protocol tcp
            translation {
                address 192.168.0.100
            }
        }
    }
}

注意

若需将流量转发至与入站端口不同的端口，还可使用 set nat destination rule [n] translation port 配置转换端口。

该配置建立了我们的端口转发规则，但如果创建了防火墙策略，则该策略很可能会阻止该流量。

目的地址 NAT 的防火墙规则

需要注意的是，在创建防火墙规则时，DNAT 转换会在流量穿越防火墙 之前 执行。换言之，目的地址已被转换为 192.168.0.100。

因此，在我们的防火墙规则集中，我们希望允许先前已匹配目的地址 NAT 规则的流量。为避免为每个目的地址 NAT 规则创建多条规则，我们可以使用 connection-status 匹配器，通过一条简单规则接受所有 ‘dnat’ 连接：

set firewall ipv4 forward filter rule 10 action accept
set firewall ipv4 forward filter rule 10 connection-status nat destination
set firewall ipv4 forward filter rule 10 state new

该配置将生成如下结果：

ipv4 {
    forward {
        filter {
            rule 10 {
                action accept
                connection-status {
                    nat destination
                }
                state new
            }
        }
    }
}

一对一 NAT（1-to-1 NAT）

DNAT 的另一种常用术语是 一对一 NAT（1-to-1 NAT）。在一对一 NAT 配置中，同时使用 DNAT 和 SNAT，将所有来自外部 IP 地址的流量转换至内部 IP 地址，反之亦然。

通常，一对一 NAT 规则会省略目的端口（即所有端口），并将协议替换为 all 或 ip。

然后创建对应的 SNAT 规则，将内部 IP 的出站流量转换为预留的外部 IP。此举将一个外部 IP 地址专门分配给一个内部 IP 地址，对于无端口概念的协议（如 GRE）尤为有用。

以下是一个简单的、含一个内部接口和一个外部接口的一对一 NAT 配置摘录：

set interfaces ethernet eth0 address '192.168.1.1/24'
set interfaces ethernet eth0 description 'Inside interface'
set interfaces ethernet eth1 address '192.0.2.30/24'
set interfaces ethernet eth1 description 'Outside interface'
set nat destination rule 2000 description '1-to-1 NAT example'
set nat destination rule 2000 destination address '192.0.2.30'
set nat destination rule 2000 inbound-interface name 'eth1'
set nat destination rule 2000 translation address '192.168.1.10'
set nat source rule 2000 description '1-to-1 NAT example'
set nat source rule 2000 outbound-interface name 'eth1'
set nat source rule 2000 source address '192.168.1.10'
set nat source rule 2000 translation address '192.0.2.30'

防火墙规则按常规编写，使用内部 IP 地址作为出站规则的源地址以及入站规则的目的地址。

VPN 前的 NAT

某些应用服务提供商（ASP）运营 VPN 网关以提供对其内部资源的访问，并要求连接组织将所有发往服务提供商网络的流量转换为 ASP 提供的源地址。

负载均衡

此处提供两个应用 NAT 负载均衡的示例。

第一种场景：对所有经由接口 eth0 进入的 HTTP 流量应用目的地址 NAT，并使用 4 个后端。第一个后端应接收 30% 的请求，第二个后端接收 20%，第三个后端接收 15%，第四个后端接收 35%。我们将使用源地址和目的地址生成哈希值。

set nat destination rule 10 inbound-interface name eth0
set nat destination rule 10 protocol tcp
set nat destination rule 10 destination port 80
set nat destination rule 10 load-balance hash source-address
set nat destination rule 10 load-balance hash destination-address
set nat destination rule 10 load-balance backend 198.51.100.101 weight 30
set nat destination rule 10 load-balance backend 198.51.100.102 weight 20
set nat destination rule 10 load-balance backend 198.51.100.103 weight 15
set nat destination rule 10 load-balance backend 198.51.100.104 weight 35

第二种场景：对来自 LAN 10.0.0.0/8 的所有出站连接应用源地址 NAT，使用 3 个公有地址并平均分配流量。我们将随机生成哈希值。

set nat source rule 10 outbound-interface name eth0
set nat source rule 10 source address 10.0.0.0/8
set nat source rule 10 load-balance hash random

示例网络

以下是一个 ASP 网络环境的示例。ASP 要求该公司所有连接均须源自 172.29.41.89 —— 此地址由 ASP 分配，客户现场并未使用。

配置

所需配置可分为四大主要部分：

  • 用于提供商分配 IP 的虚拟接口；

  • NAT（特指源地址 NAT）；

  • IPSec IKE 组和 ESP 组；

  • IPSec VPN 隧道。

虚拟接口

虚拟接口使我们能够拥有类似于 Cisco IOS Loopback 接口的功能——一种路由器内部接口，可用于承载路由器必须知晓但实际并未分配给真实网络的 IP 地址。

该接口仅需执行一个步骤：

set interfaces dummy dum0 address '172.29.41.89/32'
NAT 配置
set nat source rule 110 description 'Internal to ASP'
set nat source rule 110 destination address '172.27.1.0/24'
set nat source rule 110 source address '192.168.43.0/24'
set nat source rule 110 translation address '172.29.41.89'
set nat source rule 120 description 'Internal to ASP'
set nat source rule 120 destination address '10.125.0.0/16'
set nat source rule 120 source address '192.168.43.0/24'
set nat source rule 120 translation address '172.29.41.89'
IPSec IKE 和 ESP

ASP 已在其文档中明确了 IPSec 的要求：

  • IKE 阶段：

    • aes256 加密

    • sha256 哈希

  • ESP 阶段：

    • aes256 加密

    • sha256 哈希

    • DH 第 14 组

此外，我们希望仅在 eth1 接口（即上图中的外部接口）上使用 VPN

set vpn ipsec ike-group my-ike key-exchange 'ikev1'
set vpn ipsec ike-group my-ike lifetime '7800'
set vpn ipsec ike-group my-ike proposal 1 dh-group '14'
set vpn ipsec ike-group my-ike proposal 1 encryption 'aes256'
set vpn ipsec ike-group my-ike proposal 1 hash 'sha256'

set vpn ipsec esp-group my-esp lifetime '3600'
set vpn ipsec esp-group my-esp mode 'tunnel'
set vpn ipsec esp-group my-esp pfs 'disable'
set vpn ipsec esp-group my-esp proposal 1 encryption 'aes256'
set vpn ipsec esp-group my-esp proposal 1 hash 'sha256'

set vpn ipsec interface 'eth1'
IPSec VPN 隧道

我们将为该 VPN 使用上述创建的 IKE 和 ESP 组。由于我们需要访问远端的两个不同子网，因此需要建立两条不同的隧道。如果您在上一步中更改了 ESP 组和 IKE 组的名称，请确保此处也使用正确的名称。

set vpn ipsec authentication psk vyos id '203.0.113.46'
set vpn ipsec authentication psk vyos id '198.51.100.243'
set vpn ipsec authentication psk vyos secret 'MYSECRETPASSWORD'
set vpn ipsec site-to-site peer branch authentication local-id '203.0.113.46'
set vpn ipsec site-to-site peer branch authentication mode 'pre-shared-secret'
set vpn ipsec site-to-site peer branch authentication remote-id '198.51.100.243'
set vpn ipsec site-to-site peer branch connection-type 'initiate'
set vpn ipsec site-to-site peer branch default-esp-group 'my-esp'
set vpn ipsec site-to-site peer branch ike-group 'my-ike'
set vpn ipsec site-to-site peer branch ikev2-reauth 'inherit'
set vpn ipsec site-to-site peer branch local-address '203.0.113.46'
set vpn ipsec site-to-site peer branch remote-address '198.51.100.243'
set vpn ipsec site-to-site peer branch tunnel 0 local prefix '172.29.41.89/32'
set vpn ipsec site-to-site peer branch tunnel 0 remote prefix '172.27.1.0/24'
set vpn ipsec site-to-site peer branch tunnel 1 local prefix '172.29.41.89/32'
set vpn ipsec site-to-site peer branch tunnel 1 remote prefix '10.125.0.0/16'
