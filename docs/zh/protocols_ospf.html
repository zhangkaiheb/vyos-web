OSPF

OSPF 是一种用于 Internet 协议（IP）网络的路由协议。它采用链路状态路由（LSR）算法，属于内部网关协议（IGP）类别，运行于单个自治系统（AS）内。其 IPv4 版本定义为 OSPF 版本 2，见 RFC 2328（1998 年）。IPv6 的更新版本定义为 OSPF 版本 3，见 RFC 5340（2008 年）。OSPF 支持 CIDR 地址模型。

OSPF 是大型企业网络中广泛使用的 IGP 协议。

OSPFv2（IPv4）

配置

常规配置

VyOS 没有专门用于启动 OSPF 进程的命令。当配置第一个启用 OSPF 的接口时，OSPF 进程即自动启动。

set protocols ospf area <number> network <A.B.C.D/M>

该命令指定启用 OSPF 的接口。若接口地址位于所定义的网段范围内，则该命令将在该接口上启用 OSPF，使路由器可通过该接口向其他 OSPF 路由器通告网络信息。

该命令也用于启用 OSPF 进程。区域编号可使用十进制表示法，取值范围为 0 至 4294967295；也可使用类似 IP 地址的点分十进制表示法。

接口上的前缀长度必须等于或大于（即网络范围更小）network 语句中的前缀长度。例如，上述语句不会在地址为 192.168.1.1/23 的接口上启用 OSPF，但会在地址为 192.168.1.129/25 的接口上启用。

在某些情况下，按接口/子网逐个启用 OSPF 可能更为便捷：set protocols ospf interface <interface> area <x.x.x.x | x>

set protocols ospf auto-cost reference-bandwidth <number>

该命令设置成本计算的参考带宽，带宽取值范围为 1 至 4294967，单位为 Mbit/s。默认值为 100 Mbit/s（即带宽为 100 Mbit/s 或更高的链路成本为 1；较低带宽链路的成本将相对于该成本进行缩放）。

set protocols ospf parameters router-id <rid>

该命令设置 OSPF 进程的路由器 ID。路由器 ID 可以是路由器的 IP 地址，但并非必须如此——它可以是任意 32 位数字。然而，它在整个 OSPF 域内对 OSPF 发言者而言必须唯一！若多个 OSPF 发言者被配置了相同的路由器 ID，将导致严重问题！

可选配置

set protocols ospf default-information originate [always] [metric <number>] [metric-type <1|2>] [route-map <name>]

向所有支持外部路由功能的区域发起一个 AS-External（类型 5）LSA，用以描述一条默认路由，并指定其度量值和度量类型。若指定了 always 关键字，则无论路由表中是否存在默认路由，都将始终通告该默认路由。参数 route-map 表示仅当满足路由映射条件时才通告默认路由。

set protocols ospf distance global <distance>

该命令全局更改 OSPF 的管理距离值。距离取值范围为 1 至 255。

set protocols ospf distance ospf <external|inter-area|intra-area> <distance>

该命令更改 OSPF 的管理距离值。各参数分别对应外部路由、区域间路由和区域内路由的距离值。距离取值范围为 1 至 255。

注意

管理距离为 255 的路由将被实际禁用，且不会安装到内核中。

set protocols ospf log-adjacency-changes [detail]

该命令允许记录邻接关系的变化。若使用可选参数 detail，则显示所有邻接状态变化；若不使用 detail，则仅显示完全邻接状态（Full）或退化状态（regressions）的变化。

set protocols ospf max-metric router-lsa <administrative|on-shutdown <seconds>|on-startup <seconds>>

该命令启用 RFC 3137 支持，此时 OSPF 进程在其路由器 LSA 中将其传输链路描述为具有无限距离，从而使其他路由器在仍能通过该路由器到达网络的同时，避免计算经过该路由器的传输路径。

该支持可通过 administrative 命令以管理方式（并无限期地）启用。也可有条件地启用：可在启动后若干秒内启用最大度量值路由器 LSA（使用 on-startup <seconds> 命令），和/或在关闭前若干秒内启用（使用 on-shutdown <seconds> 命令）。时间范围为 5 至 86400 秒。

set protocols ospf parameters abr-type <cisco|ibm|shortcut|standard>

该命令选择 ABR（区域边界路由器）模型。OSPF 路由器支持四种 ABR 模型：

cisco — 若路由器在不同区域（其中至少一个为骨干区域）拥有多个已配置的网络链路，则被视为 ABR。此外，通往骨干区域的链路必须处于活动（工作）状态。
ibm — 与“cisco”模型相同，但此处通往骨干区域的链路可不必处于活动状态。
standard — 路由器在不同区域拥有多个活动链路。
shortcut — 与“standard”模型相同，但在此模型中，路由器允许使用相连区域的拓扑结构进行区域间连接，而无需涉及骨干区域。

有关“cisco”和“ibm”模型差异的详细信息，请参阅 RFC 3509。“shortcut”模型允许 ABR 基于连接至该路由器的区域拓扑创建区域间路由，但若非骨干区域路由成本更低，则无需使用骨干区域。有关“shortcut”模型的更多信息，请参阅 ospf-shortcut-abr-02.txt

set protocols ospf parameters rfc1583-compatibility

RFC 2328（RFC 1583 的后续版本）第 16.4.1 节 G.2 小节（变更）建议修改路径优选算法，以防止旧版 OSPFv2 中可能出现的路由环路。具体而言，它要求区域间路径和骨干区域内路径现在具有同等优先级，但两者均优先于外部路径。

该命令通常不应设置。

set protocols ospf interface <interface> passive [disable]

该命令将接口指定为被动接口。被动接口会通告其地址，但不运行 OSPF 协议（不建立邻接关系，也不生成 Hello 数据包）。

可选的 disable 参数允许将接口从被动状态中排除。若已配置 passive-interface default 命令，则需使用此命令。

set protocols ospf passive-interface default

该命令默认将所有接口设为被动接口。由于该命令将配置逻辑更改为默认被动模式，因此预期需建立路由器邻接关系的接口必须使用 passive-interface-exclude 命令进行配置。

set protocols ospf maximum-paths <1-64>

使用该命令控制到达特定目的地的等价路径的最大数量。若在编译期间更改 MULTIPATH_NUM 的值，则上限可能不同。默认值为 MULTIPATH_NUM（64）。

set protocols ospf refresh timers <seconds>

路由器会自动与其邻居更新链路状态信息。仅更新过期信息（其年龄已超过特定阈值）。该参数更改阈值，默认值为 1800 秒（半小时）。该定时器值应用于整个 OSPF 路由器。定时器范围为 10 至 1800 秒。

set protocols ospf timers throttle spf <delay|initial-holdtime|max-holdtime> <seconds>

该命令设置 SPF 计算与触发该计算的事件之间的时间延迟、初始保持时间和最大保持时间。时间以毫秒为单位，取值范围为 0 至 600000 毫秒。delay 设置初始 SPF 调度延迟（毫秒），默认值为 200 毫秒。initial-holdtime 设置两次连续 SPF 计算之间的最小保持时间，默认值为 1000 毫秒。max-holdtime 设置两次连续 SPF 计算之间的最大等待时间，默认值为 10000 毫秒。

set protocols ospf ldp-sync

该命令将全局启用 OSPF 的 IGP-LDP 同步功能。这要求 LDP 正常运行。详见 RFC 5443。默认情况下，所有在 OSPF 中运行的接口均启用同步功能，环回接口除外。

set protocols ospf ldp-sync holddown <seconds>

该命令将在收敛/接口抖动事件期间全局更改 IGP-LDP 同步的保持时间值。

set protocols ospf capability opaque

ospfd 支持不透明 LSA RFC 2370，作为 MPLS 流量工程 LSA 的部分支持。必须在配置中启用不透明 LSA 功能。

另一替代命令为 “mpls-te on”（流量工程）

注意

FRR 对部分与 MPLS-TE 配合使用的路由协议扩展仅提供部分支持；它不支持完整的 RSVP-TE 解决方案。

区域配置

set protocols ospf area <number> area-type stub

该命令将区域指定为存根区域（Stub Area）。即：区域内无路由器发起 OSPF 外部路由，因此所有外部路由均经由 ABR（区域边界路由器）实现。因此，此类区域的 ABR 无需向该区域传递 AS-External LSA（类型 5）或 ASBR-Summary LSA（类型 4）。它们只需向该区域传递 Network-Summary（类型 3）LSA 和一条默认路由摘要即可。

set protocols ospf area <number> area-type stub no-summary

该命令将区域指定为完全存根区域（Totally Stub Area）。除存根区域限制外，该区域类型还阻止 ABR 向指定存根区域注入 Network-Summary（类型 3）LSA。仅允许默认摘要路由。

set protocols ospf area <number> area-type stub default-cost <number>

该命令设置通告至存根区域的默认摘要 LSA 的成本。成本取值范围为 0 至 16777215。

set protocols ospf area <number> area-type nssa

该命令将区域指定为非纯存根区域（Not So Stubby Area，NSSA）。外部路由信息以类型 7 LSA 导入 NSSA。类型 7 LSA 类似于类型 5 AS-external LSA，但只能泛洪至 NSSA 内。为将 NSSA 外部信息进一步传播，类型 7 LSA 必须由 NSSA ABR 转换为类型 5 AS-external LSA。

set protocols ospf area <number> area-type nssa no-summary

该命令将区域指定为 NSSA 完全存根区域。此类区域的 ABR 无需向该区域传递 Network-Summary（类型 3）LSA（默认摘要路由除外）、ASBR-Summary LSA（类型 4）和 AS-External LSA（类型 5）。但允许在 NSSA ABR 处转换为类型 5 的类型 7 LSA。

set protocols ospf area <number> area-type nssa default-cost <number>

该命令设置通告至 NSSA 区域的 LSA 的默认成本。成本取值范围为 0 至 16777215。

set protocols ospf area <number> area-type nssa translate <always|candidate|never>

指定此 NSSA 边界路由器是否无条件地将类型 7 LSA 转换为类型 5 LSA。当角色为 Always 时，无论其它 NSSA 边界路由器的转换器状态如何，类型 7 LSA 均将被转换为类型 5 LSA。当角色为 Candidate 时，该路由器参与转换器选举以确定是否执行转换任务。当角色为 Never 时，该路由器永远不会将类型 7 LSA 转换为类型 5 LSA。

set protocols ospf area <number> authentication plaintext-password

该命令指定对给定区域使用简单密码认证。密码还必须在每个接口基础上进行配置。

set protocols ospf area <number> authentication md5

该命令指定在给定区域内，OSPF 数据包必须使用 MD5 HMAC 进行认证。密钥材料也必须在每个接口基础上进行配置。

set protocols ospf area <number> range <A.B.C.D/M> [cost <number>]

该命令将指定区域内的区域内路径汇总为一条摘要 LSA（类型 3），并通告至其它区域。该命令仅可用于 ABR，且仅可汇总路由器 LSA（类型 1）和网络 LSA（类型 2）（即作用域为区域的 LSA）。AS-external LSA（类型 5）不可汇总——其作用域为 AS。可选参数 cost 指定聚合链路度量值。度量值范围为 0 至 16777215。

set protocols ospf area <number> range <A.B.C.D/M> not-advertise

该命令不汇总区域内路径，而是过滤它们——即，来自该网段的区域内路径不会通告至其它区域。该命令仅在 ABR 上有意义。

set protocols ospf area <number> export-list <acl_number>

过滤从指定区域发起、通告至其它区域的类型 3 摘要 LSA（源自区域内路径）。该命令仅在 ABR 上有意义。

set protocols ospf area <number> import-list <acl_number>

与 export-list 相同，但适用于作为类型 3 摘要 LSA 通告至指定区域的路径。该命令仅在 ABR 上有意义。

set protocols ospf area <number> range <A.B.C.D/M> substitute <E.F.G.H/M>

若定义的区域内至少包含一个来自网段 <A.B.C.D/M> 的区域内网络（即由路由器 LSA 或网络 LSA 描述），则向骨干区域通告一条带有路由信息 <E.F.G.H/M> 的类型 3 摘要 LSA。该命令仅在 ABR 上有意义。

set protocols ospf area <number> shortcut <default|disable|enable>

该参数允许对区域间路由（非骨干区域）进行“快捷”路由。路由快捷化有三种模式：

default —— 仅当 ABR 没有通往骨干区域的链路或该链路丢失时，才使用此区域进行快捷路由。
enable —— 每当经由此区域的路由成本更低时，均使用该区域进行快捷路由。
disable —— ABR 永不使用此区域进行路由快捷化。

set protocols ospf area <number> virtual-link <A.B.C.D>

通过建立虚拟链路来保证骨干区域的一致性。

通常，OSPF 协议要求骨干区域（区域 0）具有一致性和完全连通性。即，任何骨干区域路由器都必须能够到达其它骨干区域路由器。此外，每个 ABR 都必须具有通往骨干区域的链路。然而，并非总能建立通往骨干区域的物理链路。此时，在两个 ABR（其中一个具有通往骨干区域的链路）之间（在非存根区域内）建立虚拟链路。

<number> —— 虚拟链路所经区域的标识符。
<A.B.C.D> —— 建立虚拟链路的 ABR 路由器 ID。虚拟链路必须在两台路由器上均进行配置。

形式上，虚拟链路看起来像一条连接同一区域内两个 ABR 的点对点网络，其中一端物理连接至骨干区域。该伪网络被视为属于骨干区域。

接口配置

set protocols ospf interface <interface> area <x.x.x.x | x>

在接口上启用 OSPF 并设置关联区域。

若存在大量接口和/或子网，则通过此命令启用 OSPF 可能带来轻微的性能提升。

set protocols ospf interface <interface> authentication plaintext-password <text>

该命令将 OSPF 认证密钥设置为简单密码。设置后，所有 OSPF 数据包均需认证。密钥长度最多为 8 个字符。

简单文本密码认证不安全，已弃用，推荐使用 MD5 HMAC 认证。

set protocols ospf interface <interface> authentication md5 key-id <id> md5-key <text>

该命令指定在此接口上使用 MD5 HMAC 认证。它将 OSPF 认证密钥设置为加密密码。key-id 标识用于创建消息摘要的密钥。该 ID 是协议的一部分，必须在链路上的路由器之间保持一致。密钥长度最多为 16 个字符（更长的字符串将被截断），并与给定的 key-id 关联。

set protocols ospf interface <interface> bandwidth <number>

该命令为成本计算设置接口带宽，带宽取值范围为 1 至 100000，单位为 Mbit/s。

set protocols ospf interface <interface> cost <number>

该命令为指定接口设置链路成本。成本值被设置为路由器 LSA 的度量字段，并用于 SPF 计算。成本范围为 1 至 65535。

set protocols ospf interface <interface> dead-interval <number>

设置路由器死亡间隔计时器值（用于等待计时器和非活动计时器）的秒数。该值对于连接至同一网络的所有路由器必须相同。默认值为 40 秒。间隔范围为 1 至 65535。

set protocols ospf interface <interface> hello-multiplier <number>

hello-multiplier 指定每秒发送多少个 Hello 数据包，取值范围为 1（每秒一次）至 10（每 100 毫秒一次）。因此，OSPF 可实现 1 秒的收敛时间。若指定此格式，则 Hello 数据包中通告的 hello-interval 将设为 0，且接收的 Hello 数据包中的 hello-interval 不再检查，因此 hello-multiplier 在同一链路上的多台路由器之间无需一致。

set protocols ospf interface <interface> hello-interval <number>

设置 Hello 间隔计时器值的秒数。设置该值后，Hello 数据包将在指定接口上每隔该计时器值的秒数发送一次。该值对于连接至同一网络的所有路由器必须相同。默认值为 10 秒。间隔范围为 1 至 65535。

set protocols ospf interface <interface> bfd

该命令在该 OSPF 链路接口上启用 BFD。

set protocols ospf interface <interface> mtu-ignore

该命令禁用对 OSPF DBD 数据包中 MTU 值的检查。因此，使用该命令可使 OSPF 邻接关系达到 FULL 状态，即使两台 OSPF 路由器之间的接口 MTU 不匹配。

set protocols ospf interface <interface> network <type>

该命令允许指定连接至该接口的网络的分发类型：

broadcast —— 广播 IP 地址分发。
non-broadcast —— NBMA 网络拓扑中的地址分发。
point-to-multipoint —— 点对多点网络中的地址分发。
point-to-point —— 点对点网络中的地址分发。

set protocols ospf interface <interface> priority <number>

该命令设置路由器优先级整数值。具有最高优先级的路由器更有可能成为指定路由器（DR）。将该值设为 0 会使路由器不具备成为指定路由器的资格。默认值为 1。取值范围为 0 至 255。

set protocols ospf interface <interface> retransmit-interval <number>

该命令设置重传间隔（RxmtInterval）计时器值的秒数。当未收到确认时，该值用于重传数据库描述（Database Description）和链路状态请求（Link State Request）数据包。默认值为 5 秒。间隔范围为 3 至 65535。

set protocols ospf interface <interface> transmit-delay <number>

该命令设置 InfTransDelay 值的秒数。它允许为每个接口设置和调整路由器数据库与所有邻居同步过程开始前的延迟间隔。默认值为 1 秒。间隔范围为 3 至 65535。

set protocols ospf interface <interface> ldp-sync disable

该命令为此特定接口禁用 IGP-LDP 同步功能。

set protocols ospf interface <interface> ldp-sync holddown <seconds>

该命令将在收敛/接口抖动事件期间更改 IGP-LDP 同步的保持时间值，但仅针对此接口。

外部路由汇总

该功能汇总发起的外部 LSA（类型 5 和类型 7）。汇总路由将代表所有匹配的外部 LSA 发起。

set protocols ospf aggregation timer <seconds>

配置汇总延迟定时器间隔。

仅在该延迟定时器到期后才开始汇总。

set protocols ospf summary-address x.x.x.x/y [tag (1-4294967295)]

该命令启用/禁用对已配置地址范围的汇总功能。

tag 是可选参数。若配置了 tag，则汇总路由将使用配置的 tag 发起。

set protocols ospf summary-address x.x.x.x/y no-advertise

该命令确保不为匹配的外部 LSA 通告汇总 LSA。

平滑重启

set protocols ospf graceful-restart [grace-period (1-1800)]

配置平滑重启 RFC 3623 重启支持。启用后，默认平滑重启时间为 120 秒。

执行平滑关机时，需在重启 ospfd 守护进程前发出 FRR graceful-restart prepare ip ospf EXEC 级命令。

set protocols ospf graceful-restart helper enable [router-id A.B.C.D]

配置平滑重启 RFC 3623 协助支持。默认情况下，对所有邻居禁用协助支持。此配置启用/禁用该路由器对所有邻居的协助支持。

若要为特定邻居启用/禁用协助支持，必须指定路由器 ID（A.B.C.D）。

set protocols ospf graceful-restart helper no-strict-lsa-checking

默认情况下配置了严格 LSA 检查，当影响重启路由器的 LSA 发生变化时，协助者将中止平滑重启。

该命令禁用严格 LSA 检查。

set protocols ospf graceful-restart helper supported-grace-time

作为 HELPER 支持所配置的平滑重启时间。

set protocols ospf graceful-restart helper planned-only

它仅帮助支持计划内的重启作为 HELPER。

默认情况下，它同时支持计划内和非计划内的中断。

手动邻居配置

OSPF 路由设备通常通过监听网络上的广播或组播 Hello 数据包来动态发现其邻居。由于 NBMA 网络不支持广播（或组播），设备无法动态发现其邻居，因此必须静态配置所有邻居。

set protocols ospf neighbor <A.B.C.D>

该命令指定邻居设备的 IP 地址。

set protocols ospf neighbor <A.B.C.D> poll-interval <seconds>

该命令指定路由设备在与邻居建立邻接关系之前，向接口发送 Hello 数据包的时间间隔（秒）。取值范围为 1 至 65535 秒。默认值为 60 秒。

set protocols ospf neighbor <A.B.C.D> priority <number>

该命令指定与指定 IP 地址关联的非广播邻居的路由器优先级值。默认值为 0。该关键字不适用于点对多点接口。

重分发配置

set protocols ospf redistribute <route source>

该命令将来自指定路由源的路由信息重分发至 OSPF 进程。路由源有五种模式：bgp、connected、kernel、rip、static。

set protocols ospf default-metric <number>

该命令指定重分发路由的默认度量值。度量值范围为 0 至 16777214。

set protocols ospf redistribute <route source> metric <number>

该命令为来自指定路由源的重分发路由指定度量值。路由源有五种模式：bgp、connected、kernel、rip、static。度量值范围为 1 至 16777214。

set protocols ospf redistribute <route source> metric-type <1|2>

该命令为重分发路由指定度量类型。两种度量类型的区别在于：度量类型 1 是一种与 OSPF 内部链路“可比”的度量。在计算到外部目的地的度量时，完整路径度量被计算为通告该链路的路由器路径度量之和加上链路度量。因此，将选择总度量最小的路由。若外部链路以度量类型 2 发布，则选择经由通告该链路且度量最小的路由器的路径，尽管到该路由器的内部路径更长（成本更高）。然而，若两台路由器均以度量类型 2 发布外部链路，则优先选择经由内部路径更短的路由器的路径。若两台不同的路由器向同一外部目的地发布两条链路但度量类型不同，则优先选择度量类型 1。若未指定度量类型，路由器将认为这些外部链路具有默认度量类型 2。

set protocols ospf redistribute <route source> route-map <name>

该命令允许使用路由映射来过滤来自指定路由源的重分发路由。路由源有五种模式：bgp、connected、kernel、rip、static。
